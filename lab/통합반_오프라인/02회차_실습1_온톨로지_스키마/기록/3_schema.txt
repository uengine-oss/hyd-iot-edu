`결과/schema.json`만 고쳤고, `결과/graph.json`은 손대지 않았습니다. 고친 뒤 파일을 다시 읽어 쉼표와 괄호, 칸 이름을 눈으로 확인했습니다. 터미널을 쓰지 않으므로 JSON 검사 도구로는 확인하지 못했습니다.

## 고친 것

**클래스와 속성**
- `Asset`에 `code`(`string`, 필수)를 더했습니다.
- `StateVariable`에 `limit_direction`(`enum`, 값 `upper` · `lower`, 필수 아님)을 더했습니다.
- `Supplier` 클래스(한글 이름 「공급사」)를 더했습니다. 속성은 `id`, `name`, `approved`(`boolean`, 필수)입니다.
- 클래스는 10개에서 11개가 됐습니다.

**관계**
- `SUPPLIED_BY`(`Part` → `Supplier`)를 더했습니다. `properties`는 `price`, `fail_rate`, `lead_days`이고 모두 `number`, 필수입니다.
- 관계 12개 모두에 `cardinality`를 채웠습니다.

| 관계 | `cardinality` |
|---|---|
| `HAS_COMPONENT` | `N:M` |
| `MOUNTED_ON` | `N:M` |
| `MEASURES` | `N:1` |
| `CONTROLS` | `1:1` |
| `USES_PART` | `1:N` |
| `SHOWS` | `1:1` |
| `INDICATES` | `N:1` |
| `CAUSES` | `N:M` |
| `MITIGATED_BY` | `N:M` |
| `OCCURS_IN` | `N:1` |
| `RELATED_TO` | `N:M` |
| `SUPPLIED_BY` | `N:M` |

**`conventions`**

이미 있던 문장 20개는 그대로 두고, 뒤에 9개를 더했습니다.
- 공급사의 접두사는 `sup:`이고, 뒤에 이름 맨 앞의 영문자를 소문자로 적는다.
- 공급사의 `name`은 괄호 말까지 자료 그대로 적고, 이름이 같으면 노드 하나다.
- `approved`는 「예」를 `true`, 「아니오」를 `false`로 옮긴다.
- 단가, 불량률, 납기는 `SUPPLIED_BY` 관계의 속성에 적는다.
- `price`는 만원 단위, `fail_rate`는 자료의 수 그대로, `lead_days`는 날수다.
- `code`는 설비 코드를 글자 그대로 적는다.
- `limit_direction`은 `limit`가 있는 상태 변수에만 적고, `limit_note`는 함께 둔다.
- 새 표기는 `aliases`에 더하고, 태그는 넣지 않으며, 다르게 적힌 값은 이미 든 값을 따른다.
- `cardinality`는 앞으로 있을 수 있는 연결을 기준으로 정한다.

## 알아 두실 것

- **계획에 없던 문장 둘**: 「부품과 공급사의 한 짝에는 `SUPPLIED_BY`를 하나만 둔다」와 `cardinality`의 기준을 적은 문장을 더했습니다. 앞의 것은 제 판단이고, 뒤의 것은 이번에 정해 주신 기준입니다. 빼기를 원하시면 말씀해 주세요.
- **이미 있던 문장과 겹치는 곳**: 「`limit`가 위쪽인지 아래쪽인지는 숫자만으로 알 수 없다」와 접두사를 늘어놓은 첫 문장은 규칙 6에 따라 고치지 않았습니다. 새 문장이 그 뒤를 잇는 꼴입니다.
- **지금은 두 파일이 어긋나 있음**: `code`가 필수가 됐는데 `graph.json`의 설비 세 노드에는 아직 없습니다. `graph.json`을 고치면 맞춰집니다.
