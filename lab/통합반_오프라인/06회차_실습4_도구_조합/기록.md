# 기록 — 통합반 오프라인 6회차 실습 4 (Copilot판)

실라버스: 「여러 도구를 조합해 업무 결과 완성하기」(50분). 회의록 파일 읽기 → Git으로 변경된 자료 확인 → 업무 항목 생성 · 저장까지 한 요청으로 연결한다. 실제 도구 실패 시 미완료 항목을 표시하고 수정 후 재실행한다.
덱: 오프라인 6회차 35장(간지 「여러 도구를 조합한 업무 결과의 완성」), 36장(「실습에서 잇는 도구와 완성되는 업무 항목」).

## 이 묶음의 상태
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)이다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했다.**
- `완성/`은 같은 요청을 Claude Code로 대신 돌려 만든 것이다(2026-10-13, macOS, Claude Code 2.1.296). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- **서버는 6회차 실습 2 묶음의 것을 그대로 쓴다.** `시작/서버/` · `완성/서버/`는 `06회차_실습2_MCP_서버_연결/완성/서버/`와 같은 파일이다(파이썬 표준 라이브러리만 쓰고, 설치와 네트워크가 필요 없다). 연결한 서버는 둘이다: `filesystem`(도구 5개, `--read-only`, 허용 폴더는 `회의록`과 `자료`)과 `git`(도구 4개, 저장소는 `자료`). 시간 서버의 파일도 폴더에 들어 있으나 설정에는 넣지 않았다. 도구 목록은 `기록/0_서버_도구목록.txt`다.
- 두 서버에는 쓰는 도구가 없다. **결과 파일은 서버의 도구가 아니라 AI의 파일 편집으로 `결과/`에 저장한다.** 규칙 3번과 가이드의 준비 3번에 그렇게 적었다.
- 이 묶음의 첫 판은 공개 패키지(`npx` · `uvx`)의 서버로 돌렸다. 교실에 네트워크가 없을 수 있고 학생이 실습 2의 서버를 이어 쓰는 것이 맞아, 서버를 바꾸고 처음부터 끝까지 다시 돌렸다. 아래의 기록과 `완성/`은 모두 다시 돌린 것이다.
- 시작 폴더는 6회차 실습 3의 완성본에서 `meeting-actions` 스킬과 회의록 두 편을 이어받았다. 실습 3의 결과 파일(`_작업목록`)은 가져오지 않았다.
- 자료 저장소(`자료/`)는 묶음에 들어 있지 않다. `도구/자료_준비.py`가 `도구/자료_판본/`의 판본으로 그 자리에서 만든다(변경 기록 10건, 올라가지 않은 파일 하나). 저장소 안에 저장소를 넣을 수 없어서다. 날짜, 사람, 내용을 고정해 만들므로 변경의 번호가 실행마다 같다(맨 끝 변경 `837a6f8`). 실습 2의 `업무자료/`와는 다른 자료다.
- 자료의 내용(점검표, LOTO 절차서, 예비품 목록, 생산 계획표, 점검 기록)은 이 실습을 위해 새로 썼다. 회의록에 나온 사실만 옮겼고 설비의 수치는 넣지 않았다. 사람 이름은 회의록의 지어낸 이름이며 변경 기록의 메일 칸은 비어 있다.
- 가이드에서 Copilot의 답과 VS Code 화면을 보여 주는 자리는 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 12곳).

- 가이드의 요청 글은 모두 `_prompt.txt`와 같다.

## 대신 돌리면서 본 것
- 1차: 두 서버의 도구 아홉 개와 넘길 값을 정리했고 「파일을 바꾸는 도구는 없다」고 답했다. 변경 기록 10건과 올라가지 않은 `교육/쿨러_점검_교육자료.md`를 찾았다.
- 2차: 도구를 부르는 차례 일곱 단계를 내놓았다. `git_log`를 짝 자료 파일마다 `path`를 넘겨 따로 부르겠다고 했고(한 번 실패해도 그 파일의 작업만 미완료가 된다는 까닭), `max_count`를 넘기지 않으면 10건만 돌아온다는 것을 짚었으며, `git_show`와 `git_diff`는 쓰지 않겠다고 했다. 저장은 파일 편집이라고 적었다. 되물은 것이 다섯 가지였다.
- 3차: 권한 쪽으로 정해 스킬에 적었고, 묻지 않고 정한 것 네 가지를 답에 밝혔다. 그 가운데 하나로, 올라가지 않은 파일은 `git_status`가 돌려준 경로 그대로(`교육/ (새로 생김)`) 적기로 했다.
- 4차: 회의록_1에서 작업 17건, 미결 안건 2건. 변경 있음 6 · 변경 없음 3 · 자료 없음 8 · 미완료 0. 「(담당자 아님)」이 붙은 변경 4건. 호출은 `list_allowed_directories` 1, `read_text_file` 3, `git_log` 6, `git_status` 1이었다. **회의록을 읽는 첫 호출은 실패했다**(「파일이 없다: 회의록/회의록_1.txt」). 이 서버는 상대경로를 첫째 허용 폴더(`회의록`)를 기준으로 풀기 때문이다. 경로를 바로잡아 같은 도구를 다시 불러 읽었고, 답에서 이것을 밝혔다. 가이드 4단계에 이 일을 적었다.
- 5차: 서버 둘 다 연결된 상태였고, `git_log` 2번과 `git_status` 1번이 **도구 호출의 오류**로 돌아왔다(「Git 저장소가 아니다: 회의록 폴더에 .git 이 없다. 서버의 --repository 설정을 확인한다.」). 파일을 만들었고 자료 없음 6 · 미완료 2로 적었으며, 집계 줄 아래에 세 호출의 실패를 오류 문장 그대로 적었다. 터미널의 git 명령으로 돌아가지 않았다. 그때의 결과 파일은 `기록/5_회의록_2_업무항목_미완료.md` · `.json`이다.
- **규칙 위반 요청 둘 다 멈췄다.**
  - 6-1: 결과 파일을 바꾸지 않았다. 규칙 4번과 7번, 「정해져 있는 것」의 「변경 없음」의 뜻을 들었다. 혹시 고쳐졌는지 같은 세 호출을 다시 불러 보았고(모두 같은 오류) 설정을 고친 뒤 다시 요청하는 길을 권했다.
  - 6-2: 터미널 명령을 실행하지 않았다(도구 호출 0회). 규칙 4번 · 5번 · 7번을 들었다. 사람이 직접 터미널에서 보는 것은 막지 않지만 그 값을 결과 파일에 옮겨 적는 것은 규칙 3번에 걸린다고 답했다.
  - 두 요청 뒤 회의록_2의 결과 두 파일의 해시가 보내기 전과 같았다.
- 7차: 미완료 2건이 모두 변경 있음으로 채워졌고, 「도구 실패」가 지워졌으며, 「확인하지 못함」이 `교육/ (새로 생김)`으로 바뀌었다. 바뀐 줄은 그 네 곳뿐이었다(앞뒤 파일을 견주어 확인). 6-1에서 「어차피 바뀐 게 없을 것」이라며 채우려던 두 항목이 실제로는 변경 있음이었다.
- 8차: `work-items/SKILL.md`만 고쳤고 결과 네 파일에 새 절을 더했다. 서버의 도구는 부르지 않았다. 회의록_1에 3건이 모였고, 회의록_2는 변경 없음이 없어 「없음」으로 적혔다.
- 끝난 상태를 스크립트로 대조했다: 두 결과의 근거 문장은 모두 회의록 원문에 그대로 있고, 변경기록의 날짜 · 사람 · 내용 · 파일은 저장소의 변경 기록과 같으며, 회의 전의 변경은 섞이지 않았고, 「(담당자 아님)」 표시와 집계가 맞았다(어긋남 0). 회의록 두 편, 규칙 파일, `meeting-actions` 스킬, 서버 파일, 자료 저장소는 실행 전과 같았다.
- 4차와 5차에서 AI가 폴더를 보려고 터미널 명령(`find`, `ls`)을 한 번씩 실행했고, 답에서 규칙 5번에 어긋났다고 스스로 밝혔다(읽기만 하는 명령이며 바뀐 파일은 없다). 실습 3의 기록과 같은 현상이다. Copilot에서는 터미널 실행에 허용 물음이 뜨는지 확인해야 한다.

## 덱 · 다른 묶음과 다른 곳
- 덱 36장은 「회의록 스킬로 업무 항목을 만들어 저장한다」고 적었다. 이 묶음은 잇는 차례를 담는 스킬 `work-items`를 하나 더 만들고, 결과 파일의 이름을 실습 3의 `_작업목록`이 아니라 `_업무항목`으로 한다(`meeting-actions`는 고치지 않고 불러 쓴다).
- 덱 36장의 첫 칸은 「파일시스템 서버의 도구로 회의록 파일을 읽는다」이고 셋째 칸은 「업무 항목을 만들어 저장한다」다. 이 묶음에서 읽기는 서버가, 저장은 AI의 파일 편집이 한다(서버를 읽기 전용으로 띄운다). 덱은 저장을 누가 하는지 적지 않았으므로 어긋나지는 않는다.
- 실습 2 묶음은 서버 셋(시간 포함)을 `업무자료/` 폴더에 연결한다. 이 묶음은 같은 서버 둘을 `회의록/` · `자료/`에 연결한다. 서버 파일은 같고 설정의 폴더만 다르다.
- 실습 3의 완성본은 회의록_1의 작업이 17건이고 이 묶음도 17건이다. 첫 판(공개 서버로 돌린 것)은 16건이었다. 같은 스킬이어도 실행마다 건수와 짝지은 자료가 달라질 수 있다(이번에는 회의록_2의 작동유 재고 확인을 예비품 목록과 짝짓지 않았다).

## 확인하지 못한 것
- Copilot 채팅에서의 실행 전부: 화면 문구, 새 채팅 단추, 도구 호출의 허용 물음, 스킬이 이름으로 불리는지, `.github/copilot-instructions.md`를 자동으로 읽는지(4 · 5단계의 요청은 규칙 파일을 읽으라는 문장으로 시작한다).
- VS Code에서 `.vscode/mcp.json`의 서버를 시작 · 다시 시작하는 화면과 문구, 도구의 수가 보이는지, `${workspaceFolder}`가 풀리는지, 설정을 고친 뒤 다시 시작해야 반영되는지. 가이드의 그 대목(준비 3, 5단계 1, 7단계 1)은 화면을 보지 못하고 썼다.
- 설정의 `"command": "python"`이 수업 PC에서 통하는지. 이 PC에서는 `python`이 없어 다른 이름의 파이썬으로 띄웠다.
- Windows: 한글이 든 경로로 두 서버가 뜨는지, 4단계의 `git log` 명령이 PowerShell에서 그대로 통하는지, 변경의 번호가 Windows에서도 같은지(줄바꿈 변환을 끄도록 했으나 돌려 보지 못했다).
- Copilot이 상대경로를 넘겨 4차와 같은 실패를 겪는지, 겪었을 때 스스로 바로잡는지.
- 가이드 2단계 표의 「다르게 정하려면」 칸의 선택들, 8단계의 둘째 · 셋째 거리, 「시간이 남으면」의 두 과제는 돌려 보지 않았다.

- 가이드 화면은 아홉 장을 1200폭 헤드리스 Chrome으로 렌더했고 그 가운데 세 장(준비, 4 · 5단계)을 눈으로 보았다. 5단계의 오류 문장 상자가 옆으로 넘쳐 줄이 접히게 고쳤는데, 고친 뒤의 화면은 다시 보지 않았다. 버튼 동작(복사, 단계 이동, 글 칸 저장)은 눌러 보지 않았다. 좁은 화면은 보지 못했다.
