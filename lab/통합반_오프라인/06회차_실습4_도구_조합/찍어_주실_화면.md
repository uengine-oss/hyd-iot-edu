# 찍어 주실 화면

가이드의 빗금 상자 번호와 같다. VS Code 창을 1440 × 900쯤으로 맞춰 찍으면 가이드에 그대로 들어간다.

1. 시작 폴더를 연 VS Code 화면. 왼쪽 탐색기에 .github, .vscode, 회의록, 도구, 결과, 자료가 보이고 아래 터미널에 자료_준비.py의 출력(변경 기록 10건)이 보이게.
2. .vscode/mcp.json을 연 편집기 화면. 두 서버 이름 위의 시작 · 실행 중 표시와 도구 수가 보이게. git 서버의 저장소 경로 줄에 빨간 테두리를 얹는다.
3. 위 요청에 대한 Copilot의 답. 두 서버의 도구와 넘길 값을 정리한 부분, 파일을 바꾸는 도구가 없다고 말한 부분, 변경 기록의 건수, 올라가지 않은 파일을 말한 부분이 보이게(길면 두 장).
4. 2단계 요청에 대한 Copilot의 계획. 「도구를 부르는 차례」와 되묻는 항목이 보이게. 변경 기록을 어떻게 나눠 묻는지 적은 줄과, 다시 물어 온 항목에 테두리를 얹는다.
5. Copilot이 work-items의 SKILL.md를 만들면서 허용을 묻거나 변경을 보여 주는 화면. 파일 경로와 「유지/허용」 버튼이 보이게.
6. 새 대화에서 요청을 보낸 뒤, 채팅에 도구 호출이 차례로 쌓인 화면. filesystem 서버의 읽기, git 서버의 git_log 여러 번과 git_status, 마지막의 파일 만들기가 보이게. 허용을 묻는 물음이 떠 있으면 함께 찍는다.
7. 결과 md 파일과 회의록 원문을 좌우로 나란히 연 VS Code 화면. 결과 파일 맨 위의 집계 줄이 보이게.
8. mcp.json에서 git 서버의 저장소 경로를 회의록으로 고친 화면. 고친 낱말에 빨간 테두리를 얹고, 두 서버가 모두 실행 중으로 보이게.
9. 위 요청에 대한 Copilot의 답. git 서버의 호출이 실패했다고 밝힌 부분과 돌아온 오류 문장, 「미완료」가 몇 건인지 말한 부분에 테두리를 얹는다.
10. 위 요청에 Copilot이 결과 파일을 바꾸지 않고 규칙을 들어 멈춘 답. 어느 규칙 때문인지 말하는 부분과, 대신 할 수 있는 길을 제안하는 부분에 테두리를 얹는다.
11. 저장소 경로를 자료로 되돌린 mcp.json과, 「미완료」였던 항목을 채웠다고 답한 Copilot 채팅이 함께 보이는 화면.
12. 되돌려 준 뒤 Copilot이 work-items의 SKILL.md에서 바뀐 부분을 보여 주는 화면(새로 생긴 절이 초록색으로 표시된 화면).
