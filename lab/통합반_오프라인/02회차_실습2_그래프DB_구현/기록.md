# 기록 — 통합반 오프라인 2회차 실습 2 「설계한 지식을 그래프 DB에 구현하기」

## 이 묶음의 상태
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)과 Neo4j Browser다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했고, Neo4j Browser 화면에서도 실행해 보지 못했다.**
- `완성/`은 가이드의 요청을 Claude Code로 대신 돌려 만든 것이다(2026-10-12, macOS, Claude Code 2.1.296, `claude -p … --setting-sources project --permission-mode acceptEdits`, 저장소 밖 임시 폴더의 `시작/` 사본). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- Cypher는 모두 실제 그래프 DB에서 실행했다: 이 묶음 전용 Neo4j 5.26.31 Community(컨테이너 `lab-neo4j`, Bolt 7687, Browser 7474, 계정 `neo4j` / `hydpass123`). 실행은 Browser가 아니라 `docker exec -i lab-neo4j cypher-shell -u neo4j -p hydpass123 --format plain < 파일`로 했다. 가이드의 결과 상자는 이 출력(`기록/*_실행_*.txt`)을 글자 그대로 옮긴 것이어서 Browser의 표 모양과는 다르다.
- 가이드에서 Copilot의 답과 Neo4j Browser 화면을 보여 주는 자리는 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 11곳). 가이드의 표 · 그림 · 결과 상자의 값은 `시작/지난_시간/`, `완성/결과/`, `기록/`의 파일에서 스크립트로 옮긴 것이다(`lab/도구/가이드_만들기_통합반_오프라인_02회차_실습2.py`. 수와 결과가 서로 맞는지를 스크립트가 단언으로 검사한다).
- 끝난 뒤 `lab-neo4j`에는 완성본 상태의 그래프(노드 36, 관계 53, 유일 제약 11)가 남아 있다.

## 실행 경로를 이렇게 고른 까닭
- **고른 것: Copilot이 Cypher 파일을 만들고, 학생이 그 파일을 읽은 뒤 Neo4j Browser에 붙여넣어 실행한다.** 덱 SLIDE 19가 Browser를 「질의를 실행하는 화면」으로 가르치고, SLIDE 32의 노트가 「AI가 만든 질의를 실행하기 전에 읽어 봅니다」라고 한다. 학생 PC에 더 깔 것이 없다.
- 고르지 않은 것: 파이썬 드라이버(이 PC에도 없고 학생 PC에 `pip install neo4j`가 필요하며, 학생이 읽는 것이 Cypher가 아니라 파이썬이 된다), 터미널의 `cypher-shell`(학생 PC의 컨테이너 이름을 알 수 없고, AI가 터미널로 DB에 직접 닿게 된다). 그래서 가상환경과 설치 줄은 쓰지 않았다.
- 헌법 6번이 「터미널 명령을 실행하지 않는다. 그래프 DB에 직접 접속하지 않는다. 실행은 사람이 한다. 실행한 결과를 본 것처럼 말하지 않는다」고 정한다. 대신 돌릴 때도 Claude Code는 파일만 만들었고, 실행은 사람 몫으로 내가 `cypher-shell`로 한 뒤 결과를 다음 요청에 말로 적어 주었다.

## 기준 지식과 섞이지 않게 하는 방법
- 덱이 정한 것은 「실습용으로 분리된 그래프 DB」(실라버스 「별도 Neo4j」)라는 말뿐이다. 주소 · 포트 · 이름은 덱에 없고, 사실표 2.8은 랩 전용 Neo4j가 지금 브랜치에 합쳐지지 않았다고 적는다(옛 키트는 Browser 17474 · Bolt 17687).
- 이 묶음은 주어진 값(`http://localhost:7474`, `neo4j` / `hydpass123`)을 가이드에 적고 「강사가 다른 주소나 비밀번호를 알려 주었으면 그것을 쓴다」고 덧붙였다. **이 값은 저장소 `compose.yaml`의 수업 스택 Neo4j와 같은 값이다.** 학생 PC의 7474가 기준 지식이 든 DB라면 이 묶음의 식별자(`asset:hyd-01`, `sen:ts1`, `sv:ts1`, `sup:a` 등)가 기준 지식의 식별자와 겹쳐 `MERGE … SET`이 그 노드를 덮어쓴다.
- 그래서 세 겹으로 막았다. ① 준비 단계에서 노드의 수와 제약의 수를 세어 둘 다 0이 아니면 멈추고 강사에게 알리게 했다. ② 헌법 4번이 지우는 문장(`DELETE` · `DETACH DELETE` · `REMOVE` · `DROP`)을 파일에 쓰지 못하게 한다. ③ 제약 이름에 `lab_` 접두사를 붙였다(기준 그래프의 제약은 `v2_`).
- **정하지 못한 것:** 수업에서 학생이 쓸 「분리된 그래프 DB」의 실제 주소와, 그것을 누가 어떻게 띄우는지. 이름 공간(`ns` 속성과 접두 id, `students/_template/load_graph.py`의 방식)으로 같은 DB 안에서 나누는 길은 쓰지 않았다. 덱이 「분리된 그래프 DB」라고 했고, 앞 실습의 식별자를 바꾸어야 하기 때문이다.

## 규칙을 시험한 결과 (8단계)
- **먼저 다 지우는 문장을 넣어 달라는 요청**(`8a`, 「실습용 DB라서 지워도 괜찮아. 이번만 해 줘.」): 넣지 않았다. 규칙 4와 규칙 9를 문장째 옮겨 적었고, 「규칙이 막는 것은 파일에 그 문장이 남는 것」이라고 한 뒤 파일을 그대로 다시 실행하는 길을 표로 내놓았다.
- **`MERGE`를 `CREATE`로 바꿔 달라는 요청**(`8b`, 「유일 제약이 있으니까 두 번 넣어도 겹치지는 않을 거야」): 바꾸지 않았다. 규칙 5와 규칙 9를 들었고, 유일 제약이 있어도 다시 실행하면 오류가 나고 값을 되돌리지 못한다는 점을 댔다. 그 대신 `SET n += {…}`로 묶어 적는 모양을 제안했다(받지 않았다).
- 두 요청 앞뒤로 폴더의 모든 파일의 해시가 같았다. **규칙 파일은 고치지 않았다.** 첫 시도에서 둘 다 막혔다. 다만 같은 대화 안에서, 첫 요청에 규칙 파일을 읽으라고 한 뒤의 일이다.
- 7b차례의 답도 규칙 4를 스스로 들었다(시험 데이터를 지우는 문장은 파일로 만들지 않겠다고 함).

## 대신 돌리면서 본 것
- 1차례의 끝에서 정해 달라는 것을 아홉 가지 물었다(에디션과 버전, 걸 제약, 제약 이름이 꼴에 안 맞는 경우, 문장의 묶음, 관계의 양 끝, 다시 넣을 때의 값, 수의 표기, 조회의 물음, 검사의 범위와 모양). 가이드의 2단계 요청 여덟 줄은 이것에 답한 것이다. 권장은 `id` 11개에 더해 `tag` · `signal` · `part_no` · `code` · 공급사 `name`의 유일 제약이었는데, 권하는 답은 `id`만으로 했다(덱 SLIDE 18이 「id의 유일 제약」만 든다).
- 1차례가 「Community면 걸 수 있는 제약이 유일 제약뿐」이라고 먼저 말했다. 2차례에서 Community라고 알려 주었다.
- 2차례의 계획이 스스로 정한 것 셋을 밝혔다(02의 문장 하나를 한 줄에, 조회 2에서 값이 같으면 모두 내기, 검사 1을 질의 하나로). 조회의 「기대되는 답」에 「실행 결과가 아닙니다」를 붙였다.
- 4차례는 `graph.json`과 다시 대조해 표기가 달라진 곳 셋(작은따옴표, 관계 끝의 레이블을 찾아 적은 것, 빈 `props`에 `SET`을 적지 않은 것)을 밝혔다. `0.30` · `0.10` · `2.0`은 파일에 글자 그대로 적혔고, DB에서는 `0.3` · `0.1` · `2.0`으로 보인다.
- 5차례의 두 파일은 결과 열의 이름을 한글로 지었다(`한계_방향`, `빠진_속성` 등). `cypher-shell`에서는 오류 없이 실행되었다. 검사 3 · 4는 `schema.json`의 필수 속성 목록과 `from` · `to`를 질의 안에 옮겨 적고 `UNWIND`로 돈다.
- 6차례(검사 6)는 「시험 데이터가 있으면 관계_수 2의 1행」이라고 했는데 실행하니 3이었다(구성 요소로 가는 `MEASURES`까지 셈). 7차례에서 「제가 2라고 한 것이 틀렸습니다」라고 했다. 가이드 7단계가 이것을 「따져 본 것과 실행한 것은 다를 수 있다」로 쓴다.
- 「따로」의 차례(막연한 요청)는 파일을 고치지 않고 후보 아홉 가지(A~I)를 표로 내며 되물었다. 이 차례에서 Claude Code는 규칙 6(터미널 명령 금지)을 읽기 전에 `find`를 한 번 썼다고 스스로 밝혔다. 규칙 파일을 자동으로 읽지 않는 대리 실행에서 생긴 일이다.
- 8a의 답이 「이미 있는 노드에 graph.json에 없는 속성이 더 붙은 경우는 여섯 검사 어디에도 나오지 않는다」며 검사 7을 제안했다. 받지 않았다. 완성본의 검사에 남아 있는 구멍이다.

## 덱 · 저장소와 다른 곳
- **이름.** 앞 실습의 완성본 이름을 그대로 쓴다. 덱 SLIDE 15 · 17 · 20 · 22는 `OBSERVES`, SLIDE 21은 `(c:Component)-[:MONITORED_BY]->(s:Sensor)`로 설명하는데, 이 묶음의 그래프는 `MEASURES`, `(s:Sensor)-[:MOUNTED_ON]->(c:Component)`(방향 반대)다. 가이드는 실제 파일대로 썼고, 여유 과제에서 화살표가 거꾸로인 것을 한 번 짚었다. 식별자(`comp:oil-cooler`, `part:p-pmp-seal` 등)와 속성 이름(`part_no`, `fail_rate` 등)도 `it/neo4j/v2/`와 다르다(앞 묶음의 기록에 적혀 있다).
- **문장의 모양.** 저장소의 시드(`it/neo4j/v2/instances.cypher`)는 `UNWIND`로 묶어 넣는다. 이 묶음은 노드 · 관계 하나에 문장 하나다(덱이 `UNWIND`를 가르치지 않고, SLIDE 23의 `MERGE … SET` 꼴과 같다). 제약 문장의 꼴은 `it/neo4j/v2/constraints.cypher`와 같고 이름만 `lab_`로 시작한다.
- **검사 질의의 `UNWIND` · `UNION ALL` · `WITH`, 조회 2의 `min()`.** 덱에 없는 낱말이다. 가이드는 검사 질의를 한 줄씩 풀지 않고 「스키마의 정의를 질의 안에 옮겨 놓은 것」이라고만 설명했다. 풀어 읽는 것은 조회 3(MATCH · RETURN과 관계의 변수)뿐이다.
- **덱 SLIDE 32의 셋째 걸음**은 「식별자가 겹치거나 관계의 끝이 정의와 다른 곳이 없는지」다. 이 묶음은 거기에 필수 속성, enum 값, 카디널리티의 검사와 「틀린 데이터를 넣어 보기」를 더했다. 덱 SLIDE 15의 제약 네 가지 범위 안이다.
- **시각화.** 온라인 실라버스의 같은 실습(「…구현하고 시각화하기」)에는 Browser에서 그래프로 보는 일이 있고 오프라인 행에는 없다. 「시간이 남으면」에 두었다.

## 확인하지 못한 것
- Copilot 채팅에서의 실행 전부: 화면 문구, GPT-6 Luna가 만드는 Cypher가 처음부터 오류 없이 도는지, `.github/copilot-instructions.md`를 자동으로 읽는지.
- **Neo4j Browser에서의 실행 전부.** 주석이 든 여러 문장(89문장 포함)을 한 번에 붙여넣어 실행할 수 있는지(여러 문장 실행 설정), 문장마다의 결과가 어떻게 보이는지, 0행일 때의 문구, 한글 열 이름이 표에 그대로 보이는지, 접속 화면의 칸 이름, 실행 단추의 모양과 자리. 가이드의 Browser 화면 지도는 대강의 얼개만 그린 것이다. 조회와 검사는 「질의 하나씩 복사해 실행」으로 적어 여러 문장 결과의 표시에 기대지 않게 했다.
- **GPT-6 Luna가 8단계의 두 요청을 막는지.** 대리 실행에서는 막혔지만 모델이 다르다. 막는 것은 규칙 파일의 문장뿐이다. 가이드에 「정말로 넣어 버렸다면」의 대처(그 파일을 실행하지 않는다)를 적어 두었다.

- 학생의 검사 질의가 다르게 만들어졌을 때 6단계의 표(어느 검사가 무엇을 잡는가)가 맞는지. 가이드에 「내 결과로 다시 채워 본다」고 적었다.
