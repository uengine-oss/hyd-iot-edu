여섯 편은 앞 실습에서 이미 실행해 본 건이고, 한 편이 한 가지 경우만 봐. 네가 확인되지 않는다고 한 금지 조건과, 긴급이 다른 경우와 겹치는 자리를 시나리오로 더하려고 해. 입력은 그대로 두고 사람의 답과 결정만 바꿔서 아래 다섯 편을 검증/시나리오.feature 의 끝에 더해 줘.

1. 긴급한 건의 거절: R04 의 질문 1번에 HYD-01, 2번에 S01 이라고 답했고, 운전원 권도현이 사유 「팬은 이미 최대로 돌고 있다. 현장 확인이 먼저다.」를 적어 거절했다. 상태는 반려, 긴급은 true 그대로, 사례는 S01 이다. (금지 11, 15)
2. 긴급한 건의 권한 없는 승인: R04 에 같은 답 두 건이 있고, 생산관리자 남기훈이 조치 SOP-COOL-11 을 승인했다. 상태는 승인_대기 그대로이고 확정이 아니며, 승인 칸은 비어 있고, 긴급은 true 다. 상태 기록의 마지막 까닭에 「반영하지 않음」이 들어 있다. (금지 1, 11)
3. 긴급으로 이어질 수 있는데 답이 하나 빠진 건: R04 의 질문 1번에 HYD-01 이라고만 답했고 2번의 답은 없다. 상태는 질문_대기, 사례는 null, 긴급은 null 이다. 후보에 S01 이 들어 있어도 미리 가르지 않는다. (금지 12, 13)
4. 값이 묵은 건: R07 의 질문 1번에 S09 라고 답했고 결정은 없다. 사례 S09 의 경보 패턴은 COOLER_DEGRADATION 이고 TS1 avg 120초 값은 60.1 인데 신선도가 한도를 넘었다. 사례는 S09, 긴급은 true 도 false 도 아닌 null, 근거 상태는 UNKNOWN, 상태는 보류다. (금지 7, 14)
5. 선택지에 없는 답: R01 의 질문 1번에 S06 이라고 답했다. 상태는 질문_대기, 사례는 null, 긴급은 null 이고, 질문 1번의 답은 비어 있다. (금지 3)

시나리오_실행.py 에는 새 문장에 필요한 것만 더해 줘. 앞의 여섯 편의 글과 이미 있는 문장의 동작은 바꾸지 마. 내가 적은 기대 결과가 spec.md 와 어긋난다고 판단되면 적지 말고 알려 줘.

다 더하면 열한 편을 한 번만 실행해 줘. 실패한 시나리오가 나와도 아무것도 고치지 말고 다시 실행하지도 마. 편마다의 결과와, 실패했다면 어느 문장에서 실제로 무엇이 나왔는지만 알려 줘.
