# meeting-actions

회의록 파일 하나를 읽고 작업 목록을 만든다. 남겨야 하는 것은 회의 내용의 요약이 아니라 **회의가 끝난 뒤의 다음 행동**이다.

입력은 회의록 파일 경로 하나다. 경로가 없거나 여러 개면 어느 파일인지 먼저 묻는다.

## 지킬 것

- 회의록 파일은 읽기만 한다. 고치거나 지우거나 새로 만들지 않는다.
- 회의록에 적혀 있지 않은 담당자, 날짜, 결정을 지어내지 않는다.
- 풀이해서 채운 값에는 원래 표현을 함께 적는다.
- 만드는 파일은 아래 「결과 파일」의 두 개뿐이다. 프로그램이나 스크립트는 만들지 않는다.
- 이 문서가 정하지 않은 경우를 만나면 스스로 정하지 말고 묻는다.

## 1. 회의록 읽기

회의록을 처음부터 끝까지 읽고 먼저 다음을 확인한다.

- 회의 일시: 연도, 월, 일, 요일. 날짜 풀이의 기준이 된다.
- 참석자와 불참자.

## 2. 문장 가르기

회의록의 문장을 아래 셋으로 가른다.

| 구분 | 기준 | 어디에 적나 |
|---|---|---|
| 작업 | 회의 뒤에 누군가 해야 하는 일. 담당자나 완료 시점이 없어도 하기로 했으면 작업이다. | 작업 목록 |
| 미결 안건 | 논의했지만 결론이 나지 않은 안건(「결론을 내지 못했다」, 「정하지 않고 넘어갔다」 등). | 미결 안건 |
| 그 밖 | 배경 설명, 경위, 개인 의견, 다음 회의 일정 안내. | 적지 않는다 |

- 「확인이 필요하다」처럼 하기로 했다고 못 박지 않았지만 할 일이 드러난 문장은 작업으로 넣고, `할일` 끝에 `(확인 필요)`라고 표시한다.
- 일하는 조건만 정한 문장(예: 어떤 양식을 쓴다)은 따로 작업으로 만들지 않는다. 그 조건이 걸린 작업의 `할일`에 조건으로 넣고, `근거`에 그 문장도 함께 싣는다.
- 결정만 있고 뒤따르는 행동이 없는 문장은 작업이 아니다. 그 결정 때문에 해야 하는 일이 회의록에 적혀 있을 때 그 일을 작업으로 적는다.

## 3. 작업 한 건 채우기

작업 한 건은 `할일`, `담당자`, `완료시점`, `근거` 네 가지로 이루어진다.

### 할일

- 무엇을 하는지를 행동으로 적는다(「~을 고쳐 올린다」, 「~에 알린다」). 논의 내용의 요약으로 적지 않는다.
- 회의록에 있는 말로 적고, 회의록에 없는 범위나 방법을 보태지 않는다.
- 표시가 붙는 경우 `할일` 끝에 괄호로 적는다: `(중복)`, `(확인 필요)`. 둘 다 해당하면 `(중복) (확인 필요)` 순서로 적는다.

### 담당자

- 회의록에 그 일을 맡는다고 적힌 사람만 적는다.
- 회의록에 없으면 `미정`이라고 적는다.
- 부서만 언급되었거나(「구매 쪽에서 해야 한다」), 불참자·보고받는 사람으로만 나온 사람은 담당자가 아니다. 이때도 `미정`이다.
- 둘 이상이면 모두 적고 `공동 담당`이라고 표시한다: `한서윤, 오민재 (공동 담당)`

### 완료시점

- 회의록에 없으면 `미정`이라고 적는다. 「근무표를 보고 정한다」처럼 나중에 정하겠다고 한 것도 `미정`이다.
- 날짜가 적혀 있으면 `YYYY-MM-DD`로 적는다. 연도가 빠져 있으면 회의 일시의 연도를 쓰고, 원래 표현을 괄호로 붙인다: `2026-10-16 (10월 16일)`
- 날짜가 아닌 표현은 하루로 정해지는지에 따라 다르게 다룬다.
  - 하루로 정해지는 표현(「다음 주 금요일」, 「내일」, 「모레」)은 회의 날짜를 기준으로 날짜로 바꾸고 원래 표현을 괄호로 붙인다: `2026-10-16 (다음 주 금요일)`
  - 하루로 정해지지 않는 표현(「이번 주 안」, 「점검 당일」, 「10월 넷째 주」, 「월말쯤」)은 원래 표현만 적는다.
- 날짜로 바꿀 때는 회의 일시에 적힌 요일에서 하루씩 세어 계산한다. 한 주는 월요일에 시작해 일요일에 끝나는 것으로 본다.
- 회의 일시에 연도나 날짜가 없어서 기준을 알 수 없으면 날짜로 바꾸지 않고 원래 표현만 적는다. 그리고 그 사실을 md 파일의 「알림」과 답에 밝힌다.

### 근거

- 그 작업이 나온 회의록 원문의 문장을 글자 그대로 옮긴다. 줄이거나 고쳐 쓰지 않는다. 줄 머리의 기호(`-`, `·`, 번호)만 뺀다.
- 할일, 담당자, 완료시점이 서로 다른 문장에 적혀 있으면 그 문장들을 모두 싣는다.

## 4. 같은 일이 두 번 나올 때

- 같은 일이 회의록에 두 번 나오면 작업은 하나로 합치고 `할일` 끝에 `(중복)`이라고 표시한다.
- `근거`에는 두 문장을 모두 적는다.
- 담당자나 완료 시점이 한쪽에만 적혀 있으면 적혀 있는 쪽의 값을 쓴다.
- 두 문장의 담당자나 완료 시점이 서로 다르면 합치지 말고 묻는다.

## 5. 미결 안건

- 결론이 나지 않은 안건은 작업 목록에 넣지 않고 「미결 안건」에 따로 적는다.
- 한 건에는 안건 이름과 근거 문장만 적는다. 안건 이름은 회의록의 안건 제목이나 표현을 쓴다.
- `근거`에는 결론이 나지 않았다는 문장만 싣지 않는다. 그 안건에서 의견을 낸 사람과 그 의견이 적힌 원문 문장도 모두 함께 싣는다. 다음 회의를 준비하려면 누가 어떤 의견이었는지를 알아야 하기 때문이다. 2절은 개인 의견을 적지 않는다고 하지만, 미결 안건에 딸린 의견은 여기에 싣는다.
- 의견 문장은 「오민재: … 의견.」처럼 의견을 낸 사람의 이름이 붙은 원문 그대로 옮긴다. 이름을 떼어 내거나 의견을 줄여 쓰지 않는다. 문장은 회의록에 나온 순서대로 싣는다.
- 의견을 낸 사람이 회의록에 적혀 있지 않으면 문장만 싣는다. 누구의 의견인지 짐작해서 채우지 않는다.
- 누구의 의견이 옳은지, 어떻게 결론 날지는 적지 않는다.

## 6. 결과 파일

`결과/` 폴더에 두 파일을 만든다. `<회의록 파일 이름>`은 확장자를 뺀 이름이다.

- `결과/<회의록 파일 이름>_작업목록.md`
- `결과/<회의록 파일 이름>_작업목록.json`

두 파일의 내용은 같아야 한다. 작업의 수와 순서, 네 칸의 값, 미결 안건이 서로 일치해야 한다. 작업은 회의록에 나온 순서대로 적는다.

### md

```markdown
# <회의록 제목> 작업 목록

- 회의록: <회의록 파일 경로>
- 회의 일시: <회의록에 적힌 그대로>

## 작업 목록

| 번호 | 할일 | 담당자 | 완료시점 | 근거 |
|---|---|---|---|---|
| 1 | … | … | … | "원문 문장" |
| 2 | … (중복) | … | … | "원문 문장 1"<br>"원문 문장 2" |

## 미결 안건

- <안건 이름>
  - 근거: "원문 문장"

## 알림

- <날짜로 바꾸지 못한 까닭 등 밝혀야 할 것>
```

- 작업이 없으면 표 대신 「없음」, 미결 안건이 없으면 「없음」이라고 적는다.
- 「알림」은 밝힐 것이 있을 때만 둔다.

### json

```json
{
  "작업": [
    {
      "할일": "…",
      "담당자": "…",
      "완료시점": "…",
      "근거": ["원문 문장"]
    }
  ],
  "미결 안건": [
    {
      "안건": "…",
      "근거": ["원문 문장"]
    }
  ]
}
```

- 작업 한 건의 칸은 `할일`, `담당자`, `완료시점`, `근거` 네 개뿐이다. 다른 칸을 보태지 않는다.
- `근거`는 문장이 하나여도 항상 배열이다.
- `공동 담당`, `(중복)`, `(확인 필요)`, 괄호 안의 원래 표현은 md와 똑같이 값 안에 적는다.
- 해당하는 것이 없으면 빈 배열(`[]`)로 둔다.

## 7. 끝내기 전에 점검

- `근거`의 모든 문장이 회의록 원문과 글자 그대로 같은가.
- 회의록에 없는 담당자, 날짜, 결정이 들어가지 않았는가.
- 풀이한 완료시점에 원래 표현이 괄호로 붙어 있는가. 하루로 정해지지 않는 표현을 날짜로 바꾸지 않았는가.
- 담당자나 완료 시점이 없는 칸이 비어 있지 않고 `미정`으로 적혀 있는가.
- 미결 안건이 작업 목록에 섞이지 않았고, 담당자 없는 작업이 미결 안건으로 빠지지 않았는가.
- 요약만 있고 행동이 없는 `할일`이 없는가.
- md와 json의 내용이 같은가.
- 회의록 파일을 건드리지 않았는가.

## 8. 답하기

- 한국어로 답한다.
- 작업 수와 미결 안건 수, 풀이해서 채운 값(원래 표현 포함), 묻고 싶은 점을 짧게 알린다.
- 만든 파일의 경로를 답의 끝에 적는다.
