# 기록 — 통합반 오프라인 6회차 실습 3

## 돌린 환경
- 돌린 날: 2026-10-12
- macOS, Claude Code 2.1.296, 터미널에서 한 번에 요청 하나씩 보내는 방식(`claude -p`)으로 돌렸다. VS Code 확장 화면에서 돌린 것이 아니다.
- 사용자 설정은 빼고 이 폴더의 설정만 읽게 했다(`--setting-sources project`).
- 예제 회의록 두 편은 이 실습을 위해 새로 썼다. 인물은 모두 지어낸 이름이다.

## 돌린 순서와 AI의 응답 시간

| 차례 | 한 일 | 원문 | 응답 시간 |
|---|---|---|---|
| 1 | 규칙과 회의록을 읽고 정리만 하게 함 | `기록/1_survey.txt` | 39초 |
| 2 | 네 가지를 정해 주고 계획을 받음 | `기록/2_prompt.txt`, `2_plan.txt` | 30초 |
| 3 | 계획을 고쳐 주고 SKILL.md만 쓰게 함 | `기록/3_prompt.txt`, `3_skill.txt` | 120초 |
| 4 | 새 대화에서 `/meeting-actions 회의록/회의록_1.txt` | `기록/4_run1.txt` | 41초 |
| 5-가 | 막연한 되돌림(「마음에 안 들어. 다시 해 줘.」) | `기록/5_bad.txt` | 22초 |
| 5-나 | 구체적인 되돌림 | `기록/5_good_prompt.txt`, `5_good.txt` | 38초 |
| 6 | 새 대화에서 「회의록/회의록_2.txt 로 작업 목록을 만들어 줘.」 | `기록/6_run2.txt` | 30초 |

AI의 응답을 기다린 시간의 합은 약 5분 20초다. 학생이 요청을 쓰고 결과를 읽고 원문과 맞춰 보는 시간은 재지 않았다. 가이드의 단계별 분수(6 · 10 · 8 · 8 · 8 · 5분, 준비 5분)는 추정이다.

## 사람이 대신 한 것
- `.claude` 폴더 안에 쓰는 일은 사람의 승인이 있어야 한다. 한 번에 요청 하나씩 보내는 방식에서는 승인할 수 없어서, 차례 3과 5-나에서 AI가 「이대로 쓰겠다」고 답에 적은 내용을 글자 그대로 파일에 옮겼다. `완성/.claude/skills/meeting-actions/SKILL.md`가 그 결과다.
- 차례 4 · 5 · 6은 편집을 자동으로 허용하는 방식(`--permission-mode acceptEdits`)으로 돌렸다.

## 돌리면서 확인한 것
- 규칙(`CLAUDE.md`)이 없던 첫 시도에서는 AI가 시키지 않은 검증 스크립트를 계획에 넣었다. 규칙을 넣은 뒤에는 스크립트를 넣지 않았고, 규칙이 비워 둔 네 가지를 스스로 정하지 않고 되물었다.
- 회의록 원문을 고쳐 달라고 요청해 보았다. AI는 규칙 1번을 들어 고치지 않았고 원문은 그대로였다.
- 이 폴더를 신뢰한다고 답한 적이 없는 상태에서는 설정 파일의 허용 규칙이 무시된다는 알림이 떴다. 그래서 `시작/.claude/settings.json`에는 막는 규칙만 두었다.
- 두 회의록의 결과 JSON은 작업 한 건의 칸이 `할일 · 담당자 · 완료시점 · 근거` 넷으로 같았다. 회의록 원문 두 편은 실행 전과 같았다.

## 확인하지 못한 것
- VS Code 확장 화면에서의 모습: 폴더를 신뢰하는지 묻는 화면, 새 대화를 여는 방법, 파일 쓰기 승인 물음의 문구와 버튼 이름. 가이드에 사진 자리 두 곳으로 남겼다.
- VS Code 확장의 입력창에서 `/meeting-actions …`가 터미널과 같게 동작하는지.
- 설정 파일의 막는 규칙(`deny`)이 실제로 작동하는지. 원문 수정 시도는 AI가 규칙을 읽고 스스로 거절해서 설정까지 가지 않았다.
- Windows에서의 실행(한글 폴더 이름과 파일 이름 포함).
- 가이드만 보고 처음부터 끝까지 따라 했을 때 50분에 들어가는지.
- 가이드 화면은 준비 단계와 2 · 5단계만 렌더로 보았다. 버튼 동작(복사, 저장, 체크)은 눌러 보지 않았다.
