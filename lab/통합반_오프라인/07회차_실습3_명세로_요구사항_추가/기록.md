# 기록 — 통합반 오프라인 7회차 실습 3 「새로운 요구사항을 추가해도 기존 기능 유지하기」

## 이 묶음의 상태
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)이다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했다.** `완성/`과 `기록/`은 2026-10-13에 Claude Code 2.1.296으로 대신 돌린 것이다(macOS, Python 3.14). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- **이 묶음은 한 번 다시 만들었다.** 처음에는 5회차 실습 2의 완성본에서 따로 출발했는데, 같은 회차 실습 2의 묶음이 완성된 뒤 그 `완성/`을 바탕으로 처음부터 다시 돌렸다. 앞 실행의 기록은 남기지 않았다.
- 가이드의 Copilot 복사 상자 열한 개(1 · 2 · 3 · 4 · 5 · 6a · 6b · 7a · 7 · 8과 여유 과제의 9)는 모두 `기록/`의 `*_prompt.txt`를 그대로 읽어 싣는다. 글자 하나 바꾸지 않고 실제로 보낸 글이다. 터미널 복사 상자 넷의 명령도 실제로 실행한 것이다(대신 돌릴 때는 `python3`).
- 직접 쓰는 글 칸은 한 곳(7단계 되돌려 주기)이다. 3단계의 여섯 결정은 표로 선택지를 보이고 권하는 답을 복사 상자로 준다.
- Copilot의 답을 보여 주는 자리는 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 11곳). 가이드에 글로 실은 결과는 `시작/` · `완성/`의 파일과 `기록/`의 결과 파일(`2_spec.md`, `5_견주기.txt`, `7_손으로_고친_뒤_견주기.txt`)에서 스크립트가 읽어 옮긴 것이고, 준비와 1단계의 견주기 출력은 스크립트가 `시작/검증/견주기.py`를 실제로 실행해 받은 것이다.
- 가이드는 `lab/도구/가이드_만들기_통합반_오프라인_07회차_실습3.py`로 만든다.

## 사전 검증한 사례(`시작/사례/`)
- 시작 폴더에서 규칙 파일 · `검증/` · `사례/`를 뺀 사본 셋에 새 대화로 덱 16장의 문장 「긴급한 경보는 빨리 처리되게 해 주세요.」만 보냈다(`기록/모호한_요청/`). 셋을 한 번씩 돌렸고 고르거나 버린 실행은 없다.
- 세 사본 모두 되묻지 않고 고쳤다(128초 · 152초 · 166초).
  - 사본 1: 긴급을 트립 경보 셋으로 정해 프로그램 안에 적었다. 결과에 `긴급` 칸이 생겼고 열 건 모두 `false`다. md는 그대로다.
  - 사본 2: `인터록_여유` 칸을 더했다. md 「사람이 할 일」의 차례가 바뀌었다(답할 질문 R01 R08 → R08 R01, 승인 대기 R02 R04 R05 → R04 R05 R02). `도구.py`에 새 도구를 만들고 허용 목록에 넣었다.
  - 사본 3: 요청 결과 json은 그대로다. md의 승인 대기 차례가 R04 R05 R02로 바뀌었다. `도구.py` · 허용 목록 · **`에이전트.py`를 고쳐 점검 계획을 다시 썼다**(사례 열한 건 모두 `호출_기록`이 늘고 `정지_근접` 칸이 생겼다). 사본 3의 답에는 `에이전트.py`를 고쳤다는 말이 없다.
- **질문이나 승인을 줄인 사본은 없었다.** 기존 일곱 칸은 세 사본 모두 열 건이 그대로다. 실라버스의 「실패/계약 변화 사례」 가운데 이 묶음이 실제로 보인 것은 계약 변화(다른 이름의 칸, 사람이 읽는 차례, 허용 목록, 이어받은 에이전트와 그 결과)이고, 상태나 승인이 틀려지는 실패는 나오지 않았다. 가이드 1단계의 메모에 그대로 적었다.
- 사례의 답은 Claude Code의 답이다. 학생 화면(`사례/읽는_법.md`)에는 도구 이름을 적지 않았다. 사본마다 바뀐 파일만 실었고, 사본 3의 `점검_계획.md`는 싣지 않았다.

## 헌법이 고정한 것과 비워 둔 것
- 실습 2의 헌법에서 그대로 이은 것: 온톨로지 · 입력은 읽기만, **사람 폴더의 두 파일은 사람이 쓴다**, 빠진 값을 짐작해 채우지 않는다, **승인이 없는 요청을 확정으로 적지 않는다(급하다는 것도 승인을 대신하지 않는다)**, 이어받은 에이전트와 점검 계획을 고치지 않는다, 요청받지 않은 파일을 만들지 않는다, 계획을 먼저 말하라고 하면 만들지 않는다, **요청을 받아도 바꾸지 않고 「이번만」이라는 예외도 두지 않는다**. 「정해져 있는 것」의 프로그램 · 읽는 파일 · 실행 방법 · 질문은 한 번에 하나 · 상태의 다섯 값도 그대로 적었다.
- 실습 2가 비워 두었던 여섯 가지(무엇을 묻는지, 어떤 답과 승인을 받아들이는지 등)는 **「지금의 `요청_처리.py`가 하는 그대로이고 바꾸는 요청은 받지 않는다」로 고정했다.**
- 이번에 더해 고정한 것: `사례/` · `검증/변경_전/` · 견주기는 읽기만, **명세가 먼저다**(6번), 기존 일곱 칸과 요청의 순서를 바꾸지 않는다(7번), `spec.md`의 자리와 다섯 절, 수용 기준의 꼴, 더하는 칸 `긴급`(자리와 세 값, md에는 한 줄만), `긴급_기준.json`의 자리와 여섯 칸, 긴급을 가르는 값은 `도구.센서_집계`로 읽는다, `검증/시나리오.json`의 칸.
- 비워 둔 것(학생이 정한다): 어떤 요청이 긴급인지, 사례가 정해지지 않은 요청의 긴급, 값을 읽지 못한 요청의 긴급, 긴급일 때 달라지는 것, 수용 기준과 시나리오에 적을 요청.
- 실습 2의 헌법과 다른 점 하나: 「말하는 방식」에 경로를 **이 폴더에서 본 경로로** 적으라고 했다(대신 돌릴 때 절대경로가 답에 찍히는 것을 막으려는 것이다).
