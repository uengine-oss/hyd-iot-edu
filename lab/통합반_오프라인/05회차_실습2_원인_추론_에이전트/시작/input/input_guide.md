# 센서 입력 설명

`sensor_input.json`은 경보가 뜬 사례 열한 건이다. 사례 한 건은 경보가 뜬 설비에서 판단하는 시각에 읽은 값의 묶음이다.

## 사례 한 건의 칸
| 칸 | 뜻 |
|---|---|
| `번호` | 사례 번호 (`S01`~`S11`) |
| `설비` | 경보가 뜬 설비 |
| `경보_패턴` | 경보에 붙어 온 이상 패턴의 코드. 온톨로지의 이상 패턴 `code`와 같은 글자다 |
| `판단_시각` | 값을 읽은 시각 |
| `freshness` | 신선도. 최신 유온(TS1) 값이 판단하는 시각보다 얼마나 묵었는가 |
| `readings` | 구간 집계 값의 목록 |
| `메모` | 현장에서 함께 넘어온 말. 센서 값이 아니다 |

## freshness
`{"tag": "TS1", "age_s": 0.6, "max_age_s": 60, "ok": true}`
- `age_s`는 최신 값이 몇 초 전의 것인지, `max_age_s`는 허용하는 한도(60초)다.
- 최신 값이 한도보다 오래되었으면 `ok`가 `false`다.

## readings의 한 건
`{"tag": "CE", "aggregate": "avg", "windowSeconds": 30, "value": 46.2, "coverage": {"samples": 30, "max_gap_s": 1.004, "limit_s": 3, "covered": true}}`
- `tag`, `aggregate`, `windowSeconds`는 온톨로지의 증거가 쓰는 것과 같은 이름이다. 판단하는 시각에서 `windowSeconds`초를 거슬러 올라간 구간의 값을 `aggregate` 방법으로 줄인 것이 `value`다.
- `coverage`는 관측 충분성이다. `samples`는 그 구간에 들어온 값의 수, `max_gap_s`는 값과 값 사이의 가장 긴 공백, `limit_s`는 그 태그의 수집 계약이 허용하는 공백이다. 공백이 한도 안이면 `covered`가 `true`다.
- TS4는 10초마다 들어오는 태그여서 값의 수가 적고 한도가 12초다.
- 값을 얻지 못한 건은 `value`가 `null`이다.

## 사례마다 들어 있는 집계
사례마다 아래 일곱 건이 들어 있다. 경보의 종류와 상관없이 같은 일곱 건이다.

| 태그 | 집계 | 구간 | 정상 부근 값 |
|---|---|---|---|
| CE 냉각 효율 | 평균 | 30초 | 84 % |
| VS1 팬 진동 | 평균 | 120초 | 0.58 mm/s |
| VS1 팬 진동 | 최대 − 최소 | 300초 | — |
| TS1 유온 | 평균 | 120초 | 48 ℃ |
| TS4 캐비닛 온도 | 평균 | 120초 | 28 ℃ |
| PS1 토출 압력 | 평균 | 120초 | 181 bar |
| FS1 유량 | 평균 | 120초 | 8.9 l/min |
