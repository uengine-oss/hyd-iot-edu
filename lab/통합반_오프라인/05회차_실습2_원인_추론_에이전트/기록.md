# 기록 — 통합반 오프라인 5회차 실습 2 「설비 이상 원인을 추론하는 에이전트 직접 제작하기」

2026-10-13에 다시 만들었다. 이전 판(모델을 부르지 않는 파이썬 프로그램)은 저장소의 커밋 `ee2a5c2`에 있다.

## 무엇이 바뀌었나
- **에이전트가 모델을 실제로 부른다.** 수업에서 학생마다 접속 정보를 받는다는 전제로, OpenAI 호환 주소의 모델(`.env`의 `OPENAI_BASE_URL` · `LLM_API_KEY` · `LLM_MODEL`)을 부른다.
- 일의 나눔: 모델은 도구를 골라 부르고 원인을 가린다. 실행 고리(`에이전트.py`)는 허용 목록, 호출 기록, 멈춤 조건, 대조를 맡는다. 판단의 규칙은 코드가 아니라 `에이전트_정의.json`의 `작업_규칙`에 문장으로 둔다.
- 가이드는 실습을 진행하는 데 필요한 것만 남겼다(무엇을 열고, 무엇을 보내고, 무엇이 보이면 되고, 다르면 어떻게 하는지).

## 실제로 돌린 것
환경: macOS, Python 3.14, 모델 `frentis-ai-model`(사내 서버, OpenAI 호환, `temperature` 0, 생각 과정 끔).

- **이전 판(모델 없이 규칙대로 계산한 결과)과 견줌.** 원인의 구분은 열한 건 모두 같았다. 사례의 근거 상태는 아홉 건이 같고 두 건이 달랐다(S03: 모델 UNKNOWN, 규칙대로는 SUPPORTED. S10: 모델 UNKNOWN, 규칙대로는 UNSUPPORTED). 8단계의 되돌려 주기는 이것을 소재로 삼았다.
- **멈춤 조건이 꼭 있어야 했다.** 멈춤 조건 없이 돌린 첫 시험에서 모델은 필요한 호출 여덟 번을 순서대로 한 뒤 마지막 호출을 서른 번 가까이 되풀이하고 답을 내지 못했다. 같은 물음을 되풀이하면 도구를 거두고 답을 요구하게 하자 답이 나왔다. 열한 건 가운데 네 건이 이 길로 끝났다.
- 조치의 절차 번호는 이전 판보다 적게 붙었다(예: S01은 SOP-COOL-13 · 14만. 이전 판은 11~14). 작업 규칙의 마지막 문장을 모델이 좁게 읽은 것으로 보인다. 고치지 않고 두었다.
- 사내 모델에 쓴 호출은 시험과 본 실행을 합해 사례 스물다섯 건쯤이다.

## 확인하지 못한 것
- **가이드의 요청 글 여덟 개는 보내 보지 않았다.** `완성/`의 `도구.py`와 `에이전트.py`는 제작자가 직접 썼다(이전 판은 Claude Code에 요청을 보내 만들었다). Copilot이 이 요청으로 같은 것을 만드는지는 확인하지 않았다. 6단계의 두 요청(`6a` · `6b`)만 이전 판에서 실제로 보내 거절되는 것을 보았다.
- Copilot과 GPT-6 Luna, Windows에서의 실행. 사진 자리 10곳.
- 단계별 시간(합 50분)은 추정이다.
- 학생 PC에서 모델 서버에 닿는지. 서른 명이 동시에 부를 때의 응답 시간.
- 모델의 답이 실행마다 얼마나 달라지는지(같은 사례를 여러 번 돌려 보지 않았다). 가이드는 「한 번 돌린 결과」라고 밝히고 실었다.
