# 찍어 주실 화면

가이드의 빗금 상자 번호와 같다. VS Code 창을 1440 × 900쯤으로 맞춰 찍으면 가이드에 그대로 들어간다.

1. 터미널에서 자료_준비.py 를 실행한 뒤의 VS Code 화면. 탐색기에 업무자료 폴더가 생긴 것과 터미널의 출력(커밋 5건, 커밋하지 않은 변경 두 줄)이 함께 보이게.
2. Copilot 채팅이 열린 VS Code 전체 화면. 입력 칸 아래의 방식(에이전트)과 모델(GPT-6 Luna) 표시가 보이게. 그 두 곳과 Copilot 아이콘에 빨간 테두리를 얹는다.
3. 1단계 요청에 대한 Copilot의 답. 서버 셋을 견준 표와, 답의 끝에서 「정해 주셔야 하는 것」을 묻는 부분이 보이게(길면 두 장). 아래 세 곳에 ①②③ 테두리를 얹는다.
4. 2단계 요청에 대한 Copilot의 계획. 단계마다 「제가 할 일」과 「직접 하실 일」이 나뉘어 보이게. 시간 서버의 설정 예와, 다시 물어 온 항목에 테두리를 얹는다.
5. Copilot이 .vscode/mcp.json 을 고치면서 허용을 묻는 화면, 또는 고친 뒤의 변경 화면. 파일 경로와 time 항목, 「유지/허용」 버튼이 보이게.
6. .vscode/mcp.json 을 연 편집기에서 time 항목 위에 「실행 중 · 도구 2개」가 표시된 화면. 「시작/중지/다시 시작」 글자의 위치에 테두리를 얹는다.
7. Copilot이 get_current_time 을 부르기 전에 허용을 묻는 화면. 서버 이름(time), 도구 이름, 넘기는 인수(timezone)가 보이게.
8. .vscode/mcp.json 을 연 편집기에서 세 서버가 모두 「실행 중」이고 도구 수가 2 · 5 · 4로 표시된 화면.
9. 결과/서버_비교.md 의 미리보기 화면. 여섯 줄의 표와 그 아래 「세 서버가 어떻게 다른가」가 보이게.
10. 6단계 첫 요청에 대한 Copilot의 답. 「접근 거부」 오류 문장과 「입력 오류」 오류 문장이 그대로 보이게.
11. git 서버를 멈춘 뒤 Copilot이 git_log 를 부르지 못했다고 답한 화면. mcp.json 의 git 항목이 「중지됨」인 것이 함께 보이면 좋다.
12. 위 요청에 Copilot이 아무것도 고치지 않고 규칙을 들어 멈춘 답. 어느 규칙 때문인지 말하는 부분과, 대신 할 수 있는 길을 제안하는 부분에 테두리를 얹는다.
13. 되돌려 준 뒤 Copilot이 결과/서버_비교.md 의 바뀐 부분을 보여 주는 화면. 맨 아래에 새 절이 초록색으로 더해지고 위의 표는 바뀌지 않은 것이 보이게.
