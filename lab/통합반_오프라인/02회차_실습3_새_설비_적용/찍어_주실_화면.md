# 찍어 주실 화면

가이드의 빗금 상자 번호와 같다. VS Code 창을 1440 × 900쯤으로 맞춰 찍으면 가이드에 그대로 들어간다.

1. 시작 폴더를 연 VS Code 화면. 왼쪽 탐색기에 .github, 결과, 새_설비, 도구 네 폴더가 펼쳐져 있고 결과 폴더의 schema.json, graph.json이 보이게.
2. Copilot 채팅이 열린 VS Code 전체 화면. 입력 칸 아래의 방식(에이전트)과 모델(GPT-6 Luna) 표시가 보이게. 그 두 곳과 Copilot 아이콘에 빨간 테두리를 얹는다.
3. 위 요청에 대한 Copilot의 답. HYD-04의 자료를 줄마다 「이미 있음」과 「새 노드」로 가른 표와, 답의 끝에서 정해 달라는 것을 번호로 묻는 부분이 보이게(길면 두 장). 아래 세 곳에 ①②③ 테두리를 얹는다.
4. Copilot이 결과/질의.py를 만들고 터미널 명령(python 결과/질의.py HYD-01 HYD-04)의 실행 허용을 묻는 화면. 명령 글자와 「허용/계속」 버튼이 보이게.
5. 3단계 요청에 대한 Copilot의 계획. 더할 노드를 식별자와 함께 적은 표와, 더한 뒤의 노드 · 관계 전체 수가 보이게. 새 구성 요소 셋의 식별자에 테두리를 얹는다.
6. Copilot이 결과/graph.json의 맨 뒤에 HYD-04의 노드와 관계를 더한 변경을 보여 주는 화면. 더해진 줄(초록색)과 「유지/허용」 버튼이 보이게.
7. 터미널에 python 결과/질의.py HYD-01 HYD-04 의 결과가 나온 화면. [HYD-01]과 [HYD-04] 두 표가 한 화면에 보이게. HYD-04의 표에서 팬 베어링이 적힌 두 줄에 테두리를 얹는다.
8. 스키마의 cardinality를 고쳐 달라는 요청에 Copilot이 고치지 않겠다고 답한 화면. 규칙을 근거로 든 문장과, 대신 할 수 있는 일을 적은 부분에 테두리를 얹는다.
9. 되돌려 준 뒤 터미널에서 python 결과/질의.py --부품 P-FAN-BRG 를 실행한 화면. 구성 요소 세 줄과 설비 칸이 보이게.
