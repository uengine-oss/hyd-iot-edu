## 이 묶음의 상태
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)과 Neo4j Browser다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했고, Neo4j Browser 화면도 열어 보지 못했다.**
- `완성/`은 가이드의 요청을 Claude Code로 대신 돌려 만든 것이다(2026-10-12, macOS, Claude Code 2.1.296, Python 3.14, `claude -p … --setting-sources project --permission-mode acceptEdits`, 저장소 밖 임시 폴더의 `시작/` 사본). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- **그래프 DB의 주소.** 가이드, 규칙 파일, 학생 파일에는 수업 스택의 주소(`bolt://localhost:7687`, `http://localhost:7474`)를 적었다. 대신 돌릴 때는 다른 작업과 겹치지 않게 따로 띄운 Neo4j 5.26 community(컨테이너 `lab-neo4j-b`, Bolt 7688, HTTP 7475)에 넣었다. `graphdb.py`가 환경 변수 `NEO4J_HTTP`에서 주소를 읽으므로(기본값 `http://localhost:7474`) `NEO4J_HTTP=http://localhost:7475`만 주고 돌렸다. 그래서 `기록/*_넣기_출력.txt`의 첫 줄에는 7475가 보인다. 가이드는 그 첫 줄을 빼고 싣는다. **수업 스택의 7474/7687에서는 한 번도 돌려 보지 못했다.**
- 가이드의 복사 상자 가운데 Copilot에게 보내는 열 개는 모두 `기록/`의 `*_prompt.txt`를 그대로 읽어 싣는다. 글자 하나 바꾸지 않고 실제로 보낸 글이다. Neo4j Browser에 넣는 질의 여덟 개는 `기록/조회/q*.cypher`를 그대로 읽어 싣고, 그 결과 표는 같은 폴더의 `*.out`(cypher-shell로 실제 실행한 출력)에서 스크립트가 읽어 옮긴다.
- 직접 쓰는 글 칸은 한 곳(8단계 되돌려 주기)이다. Copilot의 답과 Neo4j Browser 화면을 보여 주는 자리는 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 9곳).
- 가이드는 `lab/도구/가이드_만들기_통합반_오프라인_04회차_실습3.py`로 만든다.

## 헌법에서 고정한 것과 비워 둔 것
- **하면 안 되는 것 열 줄**: 문서 · 지난 시간 · 받은 프로그램은 읽기만(1), 승인하지 않는다 — 사람이 번호를 짚은 값만 옮겨 적고 검토자 이름 없이는 승인을 적지 않는다(2), 승인이 아닌 것과 보류는 넣는 문장으로 만들지 않는다(3), 출처 없이 넣지 않고 인용은 글자 그대로(4), 스키마에 없는 이름을 쓰지 않고 이미 있는 대상의 id · name · 속성값을 바꾸지 않는다(5), 지우는 문장과 `CREATE`를 만들지 않는다(6), 그래프 DB에 쓰는 일은 사람이 한다 — `넣기`와 `그래프_준비.py`를 실행하지 않는다(7), 요청받지 않은 파일(8), 계획 먼저(9), **요청을 받아도 바꾸지 않고 「이번만」이라는 예외도 두지 않는다**(10).
- **정해져 있는 것**: 그래프 DB의 주소, `검토`의 값 셋(`대기` · `승인` · `제외`)과 `검토자` · `검토_메모` 칸, 출처를 받는 자리(조치 → 단계 → 절 → 문서, 원인 · 조치 → 절), 절과 문서 노드의 id · ref · title · name, 단계의 order · text · citation, 새로 만드는 것에 붙이는 `_manual_document`, `반영.py`의 두 가지 실행(인자 없음은 파일만, `넣기`는 파일을 그대로 한 번에), `반영.cypher`의 모양(`;`, `//`, 매개변수 없음, `MERGE`에 레이블과 id만), `반영_요약.md`의 맨 위.
- **정해져 있지 않은 것 일곱 줄**: 조건을 담는 자리 / 관계의 출처 / 단계의 id와 수치 / 이미 있는 대상에 덧붙일 것 / 일부만 넣게 되는 경우 / 요약에 더 적을 것 / 넣기 전에 확인할 것.

- 다음 실습(4회차 실습 4, 지식 개정에 따른 변경 결과 확인)의 묶음이 이 완성본을 이어받는지. 그 묶음은 아직 없다.

## 사용자가 정해야 할 것
- **실습용 그래프 DB를 어떻게 줄 것인가.** 수업 스택의 Neo4j에 HYD 기본 지식이 들어 있다면 이 묶음과 2회차 실습 2 묶음은 그 DB에서 돌릴 수 없다. 분리된 Neo4j를 하나 더 띄우거나(그러면 가이드와 규칙 파일의 주소를 그 포트로 바꾼다), 이름 공간 방식으로 바꾸거나(그러면 두 묶음의 id와 질의가 모두 바뀐다) 가운데 하나를 정해야 한다.
- 넣는 방법을 프로그램(HTTP, 한 번에)으로 한 것. 2회차 실습 2처럼 Neo4j Browser에 붙여넣는 쪽으로 맞추려면 4 · 7단계와 헌법의 「반영 프로그램과 파일」을 고친다. 그러면 「어긋나면 모두 취소」는 겪을 수 없다.
- `출처_스키마.json`을 시작 폴더에 미리 준 것(학생이 스키마를 넓히는 일을 하지 않는다)과 `REFERS_TO`를 조치 · 원인까지 넓힌 것.
- 조건(금지)을 관계의 속성으로 담은 것. 저장소의 확정 스키마가 금지를 어디에 두는지에 맞추려면 3단계의 3번 줄을 고친다.
- 완성본에 `제외`와 수정이 없는 것. 「뺄 것」을 겪게 하려면 틀린 후보가 든 시작 자료가 필요한데, 앞 랩의 완성본을 그대로 이어받는 것과 부딪친다.
- 검토자의 이름을 학생이 요청 글 안에서 고쳐 쓰게 한 것(2 · 7단계, 여유). 글 칸은 아니지만 복사한 글을 한 낱말 고치는 일이 세 번 있다.
- 6단계에 넣을 어긋나는 요청의 조합. 지금은 「대기인 것을 넣어 달라」와 「그래프 DB를 비워 달라」가 본 단계에, 「넣기를 대신 실행해 달라」가 여유 과제에 있다.
