# 찍어 주실 화면

가이드의 빗금 상자 번호와 같다. VS Code 창과 웹 브라우저 창을 1440 × 900쯤으로 맞춰 찍으면 가이드에 그대로 들어간다.

1. 시작 폴더를 연 VS Code 화면. 왼쪽 탐색기에 .github, 문서, 지난_시간, 결과 폴더와 맨 위의 네 파일(대조.py, 출처_스키마.json, graphdb.py, 그래프_준비.py)이 보이게.
2. Neo4j Browser에 접속해 위 질의를 실행한 화면. 주소 표시줄의 localhost:7474, 맨 위의 입력 칸, 결과 표의 노드 36 · 관계 53이 보이게.
3. 위 요청에 대한 Copilot의 답. 후보와 관계의 표(이미 있는 것과 새것, 검토 값이 보이게), 고장 유형에서 문서까지의 길, 끝의 정해 달라고 묻는 부분이 보이게(길면 두 장). 아래 세 곳에 ①②③ 테두리를 얹는다.
4. 결과/후보.json과 문서/HM-8_cooler-fan-manual.md를 좌우로 나란히 연 VS Code 화면. 왼쪽은 K-004의 조건, 오른쪽은 HM-8.8이 보이게.
5. 3단계 요청에 대한 Copilot의 계획. 새로 생기는 노드와 관계의 수를 레이블과 유형별로 적은 표, 이미 있어 늘지 않는 것, 끝의 「더 정해 주셔야 하는 것」이 보이게. 수의 합계와 다시 물어 온 항목에 테두리를 얹는다.
6. Copilot이 터미널 명령 실행의 허용을 묻는 화면. 명령 글자(python 반영.py)와 「허용/계속」 버튼이 보이게.
7. 위 질의의 결과를 그래프 보기로 연 Neo4j Browser 화면. 고장 유형 「쿨러 냉각 성능 상실」에서 팬 최대 운전, 작업 단계 셋, 절 HM-8.5, 문서 HM-8까지 이어진 노드와 관계의 이름(MITIGATED_BY, HAS_STEP, REFERS_TO, PART_OF)이 보이게. 작업 단계 하나를 눌러 오른쪽에 citation 속성이 보이면 더 좋다.
8. 위 요청에 Copilot이 반영.cypher를 고치지 않고 규칙을 들어 멈춘 답. 어느 규칙 때문인지 말하는 부분과, 대신 할 수 있는 방법(원문과 대조한 뒤 번호를 짚어 승인)을 제안하는 부분에 테두리를 얹는다.
9. 되돌려 준 뒤 Copilot이 반영.py의 바뀐 부분을 보여 주는 화면(새로 생긴 줄이 초록색으로 표시되고, 문장을 만드는 부분은 바뀌지 않은 것이 보이게).
