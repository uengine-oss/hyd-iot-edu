# 기준 — 실습 (모든 실습 공통)

실습 하나(랩 · 실습 대본 · 촬영 · 가이드)를 만들거나 고칠 때 [기준_공통](기준_공통.md) 다음에 이 문서를 끝까지 읽고, 그 실습의 종류 기준 하나를 이어서 끝까지 읽는다 — 도구 실습(포털 · ARROWS · Notion · Neo4j Browser · bpmn.io처럼 화면 · 조작이 정해진 실습)이면 [기준_실습_도구](기준_실습_도구.md), 코딩 랩(VS Code에서 AI와 직접 만드는 실습)이면 [기준_실습_코딩랩](기준_실습_코딩랩.md). 이 셋이면 실습 하나를 끝낼 수 있다. 종류 기준 머리 표의 「없는 것」은 이 문서의 일반 조항보다 앞선다. 첫 단계는 실라버스 그 행의 문장과 배정 시간이다(기준_공통 G0 「범위와 시간」). 말하는 법(화자 · 말투 · 소리 내어 읽는 것)은 기준_공통 G6. 여러 도구가 함께 쓰는 녹화 구현값(음성 설정, ego 스크립트 · 큐 리듬, 구간 기록 파일, 게시 명령)은 `제작용/촬영/README.md`, 도구마다의 값 · 함정 · 재개 지점은 `제작용/촬영/<도구>/촬영준비.md`. 이 갈래의 스킬: 실습 하나 · 가이드 hyd-lab-guide, 포털 영상 hyd-portal-video.

- **이 갈래의 성향:** 강사 한 사람이 실제로 작업하며 하나의 수업처럼 보여 주는 원맨쇼 영상과, 학생이 강사 없이 혼자 따라 하는 가이드를 만든다. 영상의 조작은 부드럽게, 설명하면서, 설명이 조금 먼저 나온다.
- **앞에서 받는 것:** 그 회차 덱의 실습 설명 장(목표 · 산출물 · 성공 기준)과 앞 이론 · 포털 실습에서 세운 개념 이름.

## P1 시작할 때

실습 하나를 시작 → 수행 → 검증 → 저장 → 영상 · 가이드 전달까지 끝낸 뒤 다음 실습으로 간다. 실습 한 개를 만드는 순서는 시작(P1) → 랩 강화(그 종류 기준) → 대본(P2) → 분량 → 리허설 · 녹음 · 촬영(P3~P6) → 검사(P7) → 마무리 — 가이드 · ZIP을 만들고 학생 경로로 받기 시험을 하고(P8~P11), 영상은 other-pc, 문서는 main에 올린다(P12). 완료 표에 커밋 · 해시 · 검증 결과를 적는다.

1. **시작 전:** 그 종류 기준의 본보기 실습을 통독해 「실제 강사가 이렇게 말하고 보인다」를 잡는다. 인계의 옛 완료 표시는 믿지 않고 실제 파일을 연다.
2. **실라버스 행에서 시작한다(가장 중요).** 실라버스를 안 보면 50분 수업이 7분이 된다. 대조표는 기준_공통 G0 「범위와 시간」대로 만들되 실습은 항목마다 영상 구간과 분을 적어, 합이 배정 시간을 채우는지 이 단계에서 본다.
3. **앞 이론 · 앞 포털 실습과 잇기:** 바로 앞 이론 대본(덱의 실습 간지 · 설명 장)과, 코딩 랩이면 앞에서 본 포털 화면에서 연결점을 찾아 기준_공통 G0의 잇는 말이 화면으로 보이게 짠다(포털에 대응 기능이 없으면 앞 이론에서).
4. 실습은 과정의 줄기(기준_공통 G0)의 각 단계를 학생이 직접 만들어 보는 곳이다. 구분은 이론과 실습 둘뿐이다 — 도구를 조작해 결과물을 만들거나 실행을 확인하면 강사 혼자 보여 줘도 실습, 결과 예상 · 근거 비교 · Wrap-up은 이론.
5. 두 과정의 같음 · 다름은 기준_공통 G2 「두 과정의 차이」 표가 정한다(차이는 대본만이 아니라 랩 · 가이드 · 판정에 둔다).
6. **분량:** 대본으로 계획 시간을 재서 대조표의 합과 맞춘다(P1-2).
7. **이어받기 전에 대조한다.** 폐기판 산출물(랩 폴더 · 구성안 · 대본)과 옛 구성안의 「사용자 확인 대기」 항목은 실라버스 그 행과 대조하지 않고 이어받지 않는다 — 요청문의 「재사용할 수 있다」는 「대조해 맞으면 쓴다」이지 「쓴다」가 아니다.
8. **실습 제작 · 촬영은 모두 브라우저 기반이다.** 포털 · ARROWS · Notion · Neo4j는 브라우저 화면이고, VS Code도 데스크톱 앱이 아니라 공식 `code serve-web`으로 띄운 웹 VS Code를 ego 브라우저 탭에서 조작한다(값 · 함정은 `제작용/촬영/vscode/촬영준비.md` 「통과한 길」). 데스크톱 앱 조작 · computer use · CDP 원격 디버깅 경로는 쓰지 않는다 — 학생 가이드에 넣을 네이티브 장면만 따로 캡처한다(P9-2).

## P2 대본 — 강사 원맨쇼

1. **강사 원맨쇼로, 하나의 수업처럼 진행한다(가장 중요) — 도구 실습과 코딩 랩 모두.** 강사 본인이 실제로 작업하며 설명한다. 받은 프로젝트는 목적과 요구만 알고 출발한다(이미 탐색한 것처럼 내부 구조 · 정답 프롬프트를 말하지 않음). 학생 가이드 읽기 · 학생 작업 · 대기 시간을 넣지 않는다.
2. **바로 실습에 들어가지 않고 먼저 연다:** 지난 이론에서 무엇을 배웠는지 → 오늘 무엇을 왜 하는지(현장에서 왜 필요한지) → 무엇을 만드는지 → 무엇으로 맞았다고 판정하는지 → 순서. 앞 이론은 이름으로 받아 잇고, 다시 설명하는 것은 코딩 랩만 한다(기준_실습_코딩랩 K4-4, 도구 실습은 기준_실습_도구 T1-2). 그다음 **한 단계씩 차근차근** — 무엇을 왜 할지 말하고, 하고, 결과를 확인하고, 짚은 뒤 다음으로(AI 대기를 녹화 밖으로 빼도 흐름은 잇는다). 앞 단계와는 실제로 배운 내용을 이름으로 받아 화면에서 잇는다(기준_공통 G0). 같은 도입을 복제하지 않는다.
3. **처음 나오는 도구 · 화면은 설명한다.** 통합반은 처음 쓰는 비전공자 기준으로 처음 필요할 때 차근차근 보이고 뒤로 갈수록 줄인다. 실전반도 모른다는 전제로 핵심 위치를 한두 문장으로 짧게 짚되 이번 자료 · 요구 · 실행 위치 · 판정 안내는 줄이지 않는다. 중요한 화면은 자세히, 보조 메뉴는 용도 · 위치만.
4. **진행하면서 매번 이어서 말한다:** 어디를 왜 보는지 → 결과가 무슨 뜻이고 왜 그렇게 나왔는지 → 어떻게 확인하는지 → 어디에 쓰는지. 결과를 띡띡 읽기만 하지 않는다.
5. **말과 조작:** 대상의 위치 · 이름 · 할 일을 먼저 짚기 시작하고, 알아들을 수 있는 시점부터 설명하며 조작한다 — 문단이 끝날 때까지 기다리지 않고, 조작을 끝내고 뒤늦게 해설하거나, 아직 안 나타난 메뉴를 연속 클릭하지 않는다. 결과 설명은 결과가 화면에 나타난 뒤 한다. 선택 해제 · 빈 곳 클릭 · 입력칸 선택 · 탭 전환 · 필요한 키 같은 선행 조작도 말하고 한다. 익힌 기능은 정의를 줄이되 이번 위치 · 입력값 · 선행 조작은 빼지 않는다.
6. **연출하지 않는다**(기준_공통 G3-8). 통합반에서 막히기 쉬운 곳을 더 풀어도 실패를 꾸미지 않는다. 과정 차이는 기준_공통 G2 표.
7. **파일 꼴:** 「발화 | 조작·결과 확인 — 비낭독」 표(본보기). 내용 · 순서는 랩 · 가이드에 맞춰 확정하고 발화 · 전환 · 속도는 촬영 때 고칠 수 있다.

## P3 촬영 원칙

1. **본보기대로 말과 조작이 함께 간다** — 대상을 먼저 짚기 시작하고 설명하며 조작하고, 결과는 나타난 뒤 말하며, 선행 조작도 말하고 한다. 긴 대본이나 이미 만든 음성 길이에 맞춰 화면을 기다리게 하지 않고, 문장마다 멈추는 낭독 리듬으로 만들지 않는다.
2. **움직임 프레임이 최우선이다.** 커서 순간이동 금지 — 이동 경로가 연속해 보이고, 실제 클릭 좌표와 표시 화살표 끝이 맞고, 누름 · 뗌과 선택 변경이 화면에 나타나야 한다. 커서뿐 아니라 스크롤 · 드래그 · 타이핑 · 전환 모두 사람이 목표를 보고 연속해서 조작하는 속도로 — 작은 이동 호출과 대기를 반복해 찔끔찔끔 움직이지 않는다. 타이핑 · 이동을 일부러 늦추거나 모든 조작에 고정 대기를 붙이지 않고, 사람처럼 보이려고 무의미한 이동 · 실수를 만들지 않는다. 짧은 입력은 직접 치고 긴 명령 · URL은 붙여넣는다. 커서는 글을 가리지 않는 가까운 여백에, 스크롤은 문맥이 보존되는 범위로 왕복 없이. 한두 번 휘청이는 정도는 둔다(반복되면 P7 오류 대응). 녹화 중 같은 PC에서 무거운 계산 · 인코딩 · 검사를 돌리지 않는다.
3. **실수는 다시 찍지 말고 수습한다.** 헛클릭 · 오타 · 위치 조정 같은 사소한 것은 그 화면에서 바로잡고 이어 간다(필요하면 짧은 수습 큐). 같은 문제가 반복되면 원인을 고치고 반복된 부분만 다시 하며, 처음부터 다시 찍지 않는다. 상태가 망가져 수습할 수 없을 때만 P3-4대로 실패 직전 큐에서 잇는다. 사용자가 재생해 확정한 영상은 다시 찍지 않는다(고침은 기준_공통 G4-2, 보강은 새 영상에서).
4. **분할 촬영 · 이어 찍기.** 기능 · 결과 단위 구간으로 나눠 찍고, 녹화만 멈춘 뒤 같은 페이지 · 입력값 · 선택 · 스크롤 · 배치 · 배율 · 패널 · 커서 상태에서 잇는다. 다음 구간 첫 프레임을 앞 구간의 실제 절단 프레임과 대조한다(배율 · 위치 · 선택이 갑자기 바뀌면 정상 이음매가 아님). 쉬는 동안 학습에 필요한 조작을 화면 밖에서 하지 않는다. 실패하면 원본과 끝 상태를 보존하고 실패 직전 큐에서 같은 상태로 잇는다(정상 구간 보존). 배속 · 중간 컷 · 편집 확대로 필요한 조작을 대신하지 않고, 여러 구간을 합친 파일을 무편집 단일 촬영이라 부르지 않는다. 앞 구간이 실패하면 뒤 구간을 시작하지 않는다.
5. **기다리는 일은 녹화 밖으로.** AI 추출 · 판단, Codex 응답 대기는 구간 사이로 빼고 끝난 것을 확인한 뒤 다음 구간을 찍는다.
6. **상태 복원은 가져오기로, 실행 취소는 최후에.** 이전 끝 상태는 저장해 둔 끝 상태 데이터를 가져와 맞춘다(실행 취소는 포커스 · 글자 단위 기록 때문에 다른 내용을 잃는다). 실제 조작과 상태 확인을 구별한다.
7. **화면 준비.** 1920×1080 · UI 약 150%는 시작값이고, 기준은 학생이 실제 재생 크기에서 대상의 글자 · 속성 · 관계를 읽을 수 있는가다. 전체 지도는 구조를 소개 · 정리할 때, 개별 대상은 읽을 크기로 확대해 보이고, 앱의 실제 줌 · 이동 · 패널 조절은 설명과 함께 한다. 촬영 전에 대표 화면을 실제 녹화 프레임으로 확인한다(1080p 출력이나 디코드 통과는 가독성 합격이 아니다). 커서는 후광 없는 흰 화살표 · 얇은 검은 테두리. 확인하지 않은 버튼 색은 대사에 넣지 않는다.
8. **새 실습 시작 화면은 깨끗하게.** 이전 시연의 입력 · 결과 · 오류 · 열린 메뉴 · 탭 · 알림을 정리하고 실제 첫 프레임으로 확인하되, 이어 찍기에 필요한 직전 학습 결과는 보존한다. 수업 중 정리 · 패널 접기 · 탭 전환은 무엇을 왜 하는지 말하며 한다. 화면 정리와 DB 데이터 삭제를 혼동하지 않고, 개인 페이지를 정리한다고 지우지 않는다.
9. **촬영 전용 공간 하나.** 전용 문서 · 페이지 하나에서 이어 쓰고 재시도마다 사본을 늘리지 않으며, 최종본은 촬영으로 덮어쓰지 않는다.
10. **사용자의 것은 건드리지 않는다.** 물리 마우스 · 키보드 · 전경 창 · Claude 설정을 바꾸지 않고, 사용자가 배치한 데이터는 읽기 전용으로 쓴다. 사용자가 직접 배치 · 입력하면 녹화를 멈추고 작업 공간을 넘긴 뒤 되찾고, 결과는 앱 저장 데이터로 읽는다. 사용자가 ego 공간을 잡고 있으면 우회하지 않고 「계속」을 받은 뒤 되찾는다. 인증 정보와 개인 화면(개인 Notion 페이지 · 계정 화면 · 사용자의 Codex 대화 목록)은 공개 영상 · other-pc에 넣지 않는다.
11. **커서 표시 보정**은 기록된 위치 · 클릭 시각을 유지할 때만 허용하고 보정판을 구별한다. 하지 않은 조작을 합성하거나 누락 프레임을 복구했다고 말하지 않고, 원본 포인터가 함께 보이면 쓰지 않는다.
12. **설치 구간만** 다운로드 · 재부팅 대기를 줄여도 된다(P4-8 「배속 · 중간 컷 없음」의 유일한 예외, 다른 실습으로 확대하지 않는다).

## P4 촬영 순서와 작업 흐름

1. **준비 → 리허설 1회 → 수정 → 본 촬영 → 사진 추출 → 동기화.** 준비 때 실습 자료 · 시작 상태 · 완료 조건과 대본 초안 · 가이드 단계를 정적으로 맞춘다(AI 응답 · 실행 결과는 기준_공통 G3-8대로 미리 쓰지 않는다). 리허설은 학생과 같은 경로로 한 번 해서 실행 · 흐름 · 시간을 함께 보고(준비 · 설명 · AI 대기 · 구현 · 확인 · 막힘 · 완성본 전환을 구별해 기록), 고친 뒤에는 바뀐 곳과 연결만 다시 본다.
2. 촬영은 실라버스 순서대로, 그 실습의 랩 코드 수정이 끝난 뒤 시작한다. 새 리듬 · 도구는 대표 구간 1~2분을 먼저 찍어 보여 주고 품질을 확인한 뒤 전체로 넓힌다.
3. **길뚫기**는 처음부터 전달까지(학생 시작 상태 → 환경 준비 → 대본 · 음성 → 리허설 → 촬영 → 합성 → 검증 → 가이드 · 배포) 실제로 통과한 제작 경로를 남기는 일이다. 실행 파일 · 입력 설정 · 시작/끝 상태 · 결과 경로 · 재개 지점 · 검증 근거를 도구 촬영준비에 바로 기록한다. 길을 뚫을 때는 상태를 바꾸지 않는 보기만 한다(되돌릴 수 없는 조작 뒤 화면은 코드 · API로 미리 알아 둔다). 뚫은 길은 재사용하고 안 뚫린 길을 먼저 뚫는다. 막히면 추측 재시도 대신 원인을 확인하고 그 구간만 고친다.
4. 새 세션 · 재개 · 실패 직후에는 기준_공통 G1-4 · G3-5에 더해 그 도구 촬영준비를 다시 읽고, 지금 PC의 실제 도구 사용 가능 범위를 먼저 확인한다. 과거 공간 번호 · 페이지 이름을 추측해 쓰지 않는다.
5. **시간은 촬영 전에 큐 원고로 재고**, 배정과 차이가 크면 촬영 전에 범위를 정한다(기준_공통 G0).
6. **큐 원고:** 구간별 `[구간, 발화, 조작 목록]`. 조작은 발화 안 시점이나 문장 끝 직전에 실행되고, 클릭과 입력이 별도 행동이면 큐도 나눈다. 수습 큐는 번호를 따로 준다(뒤 큐 번호 · 음성을 다시 만들지 않으려고).
7. **시간 계산 → 음성(기준_공통 G6 「음성」) → 구간 녹화:** 시작 상태 확인 → 녹화 → 끝 상태 · 프레임 · 행동 시각 저장(파일 이름은 도구 촬영준비). 한 구간씩 찍고 바로 실측한다(이동별 최대 프레임 공백, 클릭 좌표 오차, 문장보다 늦은 조작, 마지막 프레임). take는 매번 새 이름으로 보존하고, 실패 take는 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.
8. **합성:** 구간 원본 시간 그대로 이어 붙인다(배속 · 중간 컷 없음). 실패 조각은 이어 찍은 큐 시작 시각에서 자르고, 발화가 시작된 뒤를 임의로 자르지 않는다. 녹음 뒤 문장 · 길이 변경, 발화 중간 절단 · 큐 누락/중복 · 저장 결과 불일치가 있으면 합성기가 멈춘다.
9. **이음매:** 새 이음매마다 앞뒤 0.2초 프레임을 나란히 본다(그림 · 내용 연속이 기준).
10. **동기화:** 실제 촬영 큐에서 바뀐 대사 · 입력 · 순서 · 결과만 기준_공통 G4-9대로 맞추고, 사소한 발화 차이로 재촬영하지 않는다. 수습 큐는 대본에 「다시 할 때는 없음」으로 표시하고 가이드에서는 뺀다.
11. **기록:** 도구 촬영준비에 구간 순서 · 실측 시간 · 연결 상태 · 남은 확인을 적는다(새 음성이면 계수를 다시 맞춘다, 기준_공통 G0 「범위와 시간」).
12. **끄기:** 포털 · Docker를 쓴 작업(로컬 · 촬영 · 받기 시험)이 끝나면 Docker Desktop을 끄고 프로세스가 0인지 확인한다.

## P5 음성

음성(ElevenLabs 강사 복제 음성, 비용 먼저 알림, 키, 안내 → 조작 → 결과 단위)은 기준_공통 G6 「음성」이 정한다.

## P6 녹화 도구(ego)

ego 구현은 로컬에서 찍는 도구(ARROWS · Notion · Neo4j · VS Code)에 쓰고, 호출 방법 · 공간 API · 해상도 · 지연 값 같은 세부는 도구 촬영준비가 갖는다.

1. 설치된 `ego-browser skill` 출력도 끝까지 읽는다(API는 설치 버전 우선). ego lite 설치 · 로그인은 사용자가 한다. 스크립트는 보내기 전에 문법을 검사하고, 고친 스크립트가 실제로 다시 실행됐는지 확인한다.
2. 같은 작업은 같은 작업 공간을 쓰고, 다른 세션과 같은 공간 · 페이지를 동시에 조작하지 않는다.
3. 해상도 · 배율은 녹화 스크립트마다 도구 `config.json` 값으로 설정하고 한 도구 안에서 바꾸지 않는다. 받은 프레임은 즉시 저장하고, 앞에 보이는 탭에서만 프레임이 오니 ego 창을 최소화하지 않는다.
4. **진행 리듬:** 모든 ego 호출은 하나의 직렬 큐로. 표시 포인터와 실제 입력은 같은 경로 · 같은 시각으로 움직이고, 실제 입력이 끝날 때까지 포인터를 목표에 고정한다. 움직이는 대상은 멈춘 것을 확인한 뒤 출발한다. 조작은 행동 문장이 끝나기 직전에, 다음 음성은 행동이 끝난 뒤. 녹화 시작 전에 조작 큐가 돌면 즉시 실패시키고, 긴 이동 · 긴 문자열 입력을 큐 한 항목에 넣지 않는다. 녹화 전에 서비스 상태와 PC 부하를 보되 수치만으로 중단하지 않고 실제 반응 · 프레임 간격으로 판정한다.
5. 촬영 도구는 `제작용/촬영/<도구>/촬영도구/`에 있고 PC마다 다른 값은 `config.json`과 환경변수로만 받는다. 녹화 원본 · 음성 · 끝 상태는 `.evidence/`(Git 밖).
6. 같은 정지가 반복되면 저비용 · 고효율인 다른 방식(순수 Playwright 등)으로 옮겨도 된다(P3 · P7 기준은 같다).

## P7 검사와 완료

1. **기술 검사**(게시 전 모두, 결과는 `.evidence/`): `verify`(길이 · 싱크 · 무음), `listen`(받아쓰기 대조 — 「확인할 것」 문장을 매번 눈으로), `scenes`(끝까지 2~3초 간격 장면을 **모두**, 의심 구간은 0.5초 간격), 이음매, 이동 중 프레임 공백 · 클릭 오차(100ms 넘는 공백은 프레임을 잘라 직접 봄) · 표시 커서와 실제 입력(드래그)이 함께 촘촘한지, 영상 · 음성 끝 시각이 구간 합계와 0.1초 안. 이었거나 잘랐으면 합본에 다시 한다.
2. 출력 30/60fps · 디코드 성공 · 음성 겹침 0 · 자동 받아쓰기 일치는 합격 근거가 아니다. 포인터 끊김을 자연스러운 대기로 포장하지 않고, 말과 조작이 겹쳤다는 이유만으로 오류 판정하지 않는다(P3-1). 표본만 본 것은 기준_공통 G4-7대로 표본 범위만 적는다.
3. **기술 검사는 「완료」가 아니다.** 수업으로 성립하는지(실라버스 대조 · 시간 보고, 기준_공통 G0)는 따로 판정한다.
4. 청취 · 사용자 재생은 실제로 한 것만 `확인됨`이다(직접 청취 도구가 없으면 `미확인`). 영상 파일이 있다는 것과 사용자 품질 승인은 다르다 — 확정은 사용자가 재생해 본 뒤에만 쓰고, 그 판정을 기다리느라 다른 단계를 멈추지 않는다. 무음 캡처를 완성 영상으로 표시하지 않는다. 「검증했다」고 할 때는 무엇을 어떻게 봤는지(간격 · 문장 수 · 관찰)를 함께 쓴다.
5. **수업 성립 판정은 기술 검사와 별개다:** 대조표 항목이 다 들어갔는지, 설명이 충분한지, 그 종류의 시연이 실제로 보이는지, 범위와 시간(기준_공통 G0)을 지키는지.
6. 실행 성공과 학습목표 달성, 배포 환경 검증과 학생 완주 · 이해를 따로 확인하고, 돌리지 못한 것은 `미확인`으로 적는다. 같은 판본으로 맞춘 뒤(기준_공통 G4-9) 실제 수행을 확인한다.

## P8 가이드의 역할과 구성

1. **가이드는 강사 없이 따라 하는 학생 자료다.** 오프라인 학생이 가이드만 펼쳐 준비 → 작업 → 결과 확인까지(코딩 랩은 시작 파일 받기와 저장 · 다음 실습까지) 하고, 막힌 곳만 강사의 도움을 받는다(강사가 전체 따라 하기를 이끄는 수업이 아님).
2. **온라인 영상은 강사 원맨쇼다** — 영상에 가이드 화면을 띄우거나 읽어 주지 않는다. 가이드는 온라인 · 오프라인 학생 모두 노션 회차 페이지(실습 묶음 ZIP)에서 받는다.
3. 두 과정의 가이드 공유 범위는 기준_공통 G2 표. 강사의 ProcessGPT 시연(기준_공통 G2)은 학생이 따라 하는 가이드의 대상이 아니다. 가이드는 실습의 완료 항목에서 빠뜨리지 않는다.
4. 새 가이드 파일 이름은 `guide.html`이고, 기존 `가이드.html` · `안내.html`은 배포 안내가 가리키므로 이름을 바꾸지 않는다. 새 가이드는 그 종류 본보기 가이드의 절 구조와 단계 꼴(P8-7)을 그대로 따르고 새 절 구조를 만들지 않는다 — 학생이 읽을 것 말고는 아무것도 없다(소재 · 길이 · 순서는 실라버스와 랩이 정한다).
5. **첫 화면**은 만드는 결과와 진행 순서를 짧게 말한다. 파일 이름 나열로 시작하지 않고 단계에서 필요한 파일 · 도구를 소개한다(코딩 랩의 받은 폴더는 기준_실습_코딩랩 K3-5). 회차 첫 화면에서 각 실습과 다음 실습으로 잇되 제공되지 않은 자료를 완료로 표시하지 않는다. 실습마다 독립 안내를 두고 한 HTML에 몰지 않는다.
6. **흐름**은 앞 단계 결과 → 아직 풀리지 않은 문제 → 이번 기능이 필요한 이유 → 학생이 정할 요구 → 구현 → 관찰 → 다음이다. 설치 가이드처럼 절차만 나열하거나 개념 사전처럼 설명만 늘어놓지 않는다. 필요한 준비 · 설치는 빼먹지 않되 실제 사용처가 확인된 것만.
7. **단계는 본보기 꼴대로** 짧은 목적 · 할 행동(위치를 첫 문장에 녹임, 예: 「왼쪽 세로 아이콘줄 맨 위」) · 복사 가능한 입력 · 실제 화면 · 결과 확인(마지막 화면에서 눈으로 판단할 성공 조건 한 문장)이다. 기능 · 결과 단위로 묶고 클릭마다 쪼개지 않는다(사진은 조작마다, P9-1). 전체 완성 그림 한 장으로 중간 작업을 대신하지 않는다. 결과 없는 단계는 없고, 명령마다 확인할 출력 · 화면과 다음 행동을 적는다.
8. **복사할 것은 텍스트로.** 프롬프트 · 명세 · 쿼리 · 명령은 사진 속 글자로만 주지 않고 복사할 수 있는 블록이나 파일로 주며, 예시 · 빈 양식 · 학생 작성 결과를 구분한다. 블록 종류(읽는 지침 · AI 프롬프트 · 터미널 명령 · 코드 수정 위치 · 붙여넣는 코드)를 색과 글자로 함께 표시하고, 복사는 본문만(설명 · 줄 번호 · 셸 기호 X), 완료 메시지는 그 목적지에 맞춘다. 터미널 블록에는 쓸 셸과 실행 폴더를 적는다. 복사가 막히면 수동 복사와 붙여넣을 곳을 알려 주고, 빈 학생 입력을 복사 성공으로 표시하지 않는다. 판단이 필요한 명령(복구 미리보기와 실제 적용 등)은 블록을 나눈다.
9. **결과 화면**에는 확인할 값 · 상태 · 출처 · 판정 기준을 붙이고 기대값과 실제 관측값을 나눈다. 다르면 원문 · 입력 · 조건을 확인해 고치고 다시 확인하도록 잇는다. 쿼리 결과가 그래프인지 표인지 요약인지 반환 대상에 맞춰 설명한다. 앞 단계에서 있을 수 없는 화면을 성공 기준으로 요구하지 않는다. AI 응답 · 생성 결과 화면은 「강사 화면의 예」로 표시하고 성공 판정은 원자료 대조 조건으로 적는다.
10. **끝**은 「오늘 한 것과 확인한 결과」다. 도구 실습은 결과를 그 도구 화면에서 확인하고 끝나고, 코딩 랩의 저장 · 다시 열기 · 다음 랩에 넘길 판본은 기준_실습_코딩랩 K3-5.
11. 기존 안내 · 산출물 경로를 유지하고 옮길 때는 배포 안내도 함께 고친다.

## P9 가이드의 사진과 화면

1. **학생은 가이드만 보고 따라 하므로, 모든 과정을 사진으로 담는다(가장 중요).** 준비 · 입력 · 작업 · 결과 확인까지(코딩 랩은 폴더 열기와 저장 · 다시 열기도) 학생이 하는 조작마다 그 순간의 실제 화면을 둔다(단계를 묶어도 조작마다). 사진이 없는 조작은 따라 할 수 없는 조작이다. 화면마다 현재 위치 · 조작 대상 · 확인할 결과를 표시와 짧은 설명으로 알아보게 하고, 사진만으로 목적 · 조건 · 판정 근거를 대신하지 않는다.
2. **사진은 본 촬영 화면에서 뽑는다.** 리허설 전에 사진 가이드를 완성하지 않는다 — 단계 · 자료 링크 · 판정 조건을 먼저 준비하고, 랩이 안정된 뒤 본 촬영 화면에서 추출하며 모자라거나 읽히지 않는 장면만 같은 판본으로 보충한다(보충 화면은 판본과 출처를 기록). 기존 사진이 최신 영상의 상태와 같으면 재사용한다. 코딩 랩에서 웹판 촬영과 다른 네이티브 장면(다운로드 · 압축 해제 · 폴더 열기 · 신뢰 창)은 실제 네이티브 화면을 따로 캡처한다. 터미널 출력을 그림으로 그려 넣지 않는다.
3. **없는 화면을 지어내지 않는다.** 「이런 화면일 것이다」나 비슷한 화면으로 채우지 않고, 못 찍은 단계는 `미촬영` 자리와 필요한 장면 · 확인 기준 · 파일 위치를 적는다. 실패한 실행을 정상 화면으로 쓰지 않는다.
4. **표시:** 클릭 · 입력 · 확인할 요소마다 빨간 사각형(색 · 두께는 문서 안에서 같게). 좌표는 실제로 재고, 표시는 원본에서 다시 그리며(원본 보존) 상자 위에 상자를 겹치지 않는다. 관찰만 하는 결과 화면에도 볼 곳 하나는 표시한다. 표시가 값 · 글자를 가리지 않게 하고, UI 글자 · 결과를 합성하지 않는다.
5. **읽히게:** 사진 속 글자가 원래 크기에서 읽혀야 한다. 키워 흐리게 만들지 말고 더 나은 원본이나 그 영역 캡처를 쓴다. 같은 화면을 전체 · 확대로 두 번 싣지 않고(누를 곳이 너무 작을 때만 확대본), 글자를 읽어야 하는 화면은 나란히 두지 않는다. 그래프는 노드 위치보다 연결 · 레이블 · 속성 · 결과가 보이는 구도로.
6. 캡처 속 개인 경로 · 계정은 가리고 그 자리에 학생이 보게 될 값을 적는다. 공개 전에 그림 · 로그에 비밀값 · 정답이 보이지 않는지 확인한다. 남의 캡처의 옛 표시가 지금 설명과 맞는지 보고, 이미 받은 캡처를 다시 요청하지 않는다.
7. 별도 위치 지도 · 미니맵 상자를 넣지 않는다(위치는 행동 문장에, P8-7).

## P10 가이드의 학생 안내 문장

1. 가이드에는 진행에 필요한 것만 담는다 — 행동 · 명령 · 실제 화면 · 확인할 것 · 오류 대처. 「다르면 확인하세요」 같은 막연한 말 · 불필요한 경고 · 설계 까닭의 긴 설명 · 단서와 면책(「교육용이라 실제와 다르다」, 기준_공통 G3-3) · 사실이 아닌 안심 문구 · 이모지는 넣지 않는다(제작 흔적 금지는 기준_공통 G0-6).
2. 본문은 상황과 필요한 이유를 설명하고(환경 준비 안내만 짧은 행동 · 성공 확인 · 실패 복구 중심), 이론을 놓쳐도 이해되게 쓰되 이론 장을 길게 반복하지 않는다. 덱과 같은 사실은 같은 숫자 · 같은 용어로(기준_공통 G3-7).
3. UI 이름은 실제 화면에서 확인한 명칭만, 메뉴 · 버튼은 한국어 UI 기준으로 굵게 쓰고 영어 화면과 다를 수 있으면 괄호에 영어를 같이 적는다. 부정 지시(「로그인하지 않는다」)에는 이유를 한 문장 붙이거나 뺀다. 「직접 치지 말고 붙여넣는다」는 첫 등장 때 한 번.
4. 오류 안내는 실제로 재현되는 증상과 바로 할 조치만 그 단계 자리에 둔다(뒤로 몰지 않음, 없는 오류를 상상하지 않음). 검사 통과 · 아직 구현 안 한 과제의 예상 멈춤 · 서비스 오류를 구분하고, 막히면 AI에게 실행 명령 · 오류 전문 · 화면을 보내도록 잇는다. 명령이 새 사건을 만들면 어느 식별자로 찾는지 안내한다. 「(권장)」 선택지를 원문을 보고 고르는 장면(기준_공통 G3-8)을 가이드에도 둔다.
5. 힌트는 무엇을 질문하고 판단할지 돕는 것이다 — 작업 방법 · 질문 순서 · 핵심 힌트는 기본 화면에 짧게 보이고 숨기거나 겹 토글로 만들지 않는다. 코드 해석 · 정답 요청문을 늘어놓거나 그대로 붙이면 정답이 나오는 긴 프롬프트로 쓰지 않는다(Cypher처럼 따라 하는 실습의 복사용 질의는 그대로). 응답 재생 저장분이 만들어지기 전에는 재생을 되는 것처럼 쓰지 않는다.

## P11 가이드의 정적 검사 · 받기 시험

1. **동기화:** 함께 갱신할 범위는 기준_공통 G4-9다. 외부 게시는 요청이 있을 때 하고, 이전 ZIP의 루트 폴더 이름을 유지한다.
2. **정적 검사**(실행 없음): 자료 참조 경로 · 식별자 · 입출력 · 값과 단위 · 시점 · 조건 대조, Python은 AST · JSON/XML/BPMN은 파싱만, HTML의 내용 · 순서 · 로컬 링크, 복사 자료 해시, ZIP 안 **정확한 경로 집합**과 각 파일 바이트를 배포 폴더와 비교(합계만 같으면 통과 아님). 실행 위치 · 명령 인수 · 상태값 · 화면 확인 조건이 지금 코드와 맞는지 대조한다. 구문 통과는 구현 성공이 아니다.
3. **받기 시험**(실제 실행): 코딩 랩은 학생 경로 그대로 다운로드 → 압축 해제(새 시험 폴더) → 열기 → 가이드의 위치 · 명령대로 실행 → 저장 → 다시 열기, 도구 실습은 가이드의 위치 · 조작대로 그 도구 화면에서 결과까지. 정상 · 경계 · 오류와 복구를 확인하고, GUI는 실제 화면 · 상태 변화로 본다(CLI 로그를 GUI 증거로 쓰지 않음). 복사한 것과 붙여넣은 것의 일치, 학생 작성 내용 보존, 브라우저 표시(읽기 순서 · 코드 복사 · 사진 크기 · 여백 · 모바일 가로 넘침)와 단계 이동 버튼 · 직접 링크 · 키보드 이동이 같은 화면으로 가는지를 실제로 본다. 학교 PC 초기화 뒤 검증과 개인 환경 검증을 구별한다.
4. 학생 패키지 검사(`제작용/실습시작/verify_packages.py`)와 경로 · 쓰기 권한 · 네트워크 · 보안 경고 · VS Code 폴더 신뢰는 실제 환경에서 확인해 기록하고, 직접 청취 · 자동 검사 · 학교 초기화 확인의 상태어는 기준_공통 G4-7.

## P12 게시와 학생 패키지

원격 push와 노션 게시는 기준_공통 G4-3대로 사용자에게 묻고 한다.

1. 영상 · 자막은 `other-pc`에만 올린다(원칙은 기준_공통 G5). 커밋 전에 원격 other-pc를 받아 병합하고, 여러 세션이 같은 폴더를 쓰면 브랜치를 바꾸지 말고 임시 인덱스로 커밋한다(명령은 도구 촬영준비). 영상 한 편은 100 MiB 아래.
2. 파일 이름은 `course/videos/{통합반,실전반}/<과정>_<NN>회차_<대본 번호>_실습_<이름>.mp4`(대본 파일 이름과 같게, 공통이면 두 벌)이고 `course/videos/README.md` 표를 고친다. 올린 뒤 raw 링크가 200이고 크기가 원본과 같은지 확인한다.
3. 노션 학습 포털의 두 과정 회차 페이지 「🎬 강의 영상」 탭에 그 커밋에 고정한 링크를 다른 영상과 같은 모양으로 넣고 다시 열어 확인한다. 영상은 Notion에 올리지 않고 링크로 건다(링크 모양 · 크기 한도는 도구 촬영준비). 유튜브는 쓰지 않는다.
4. 노션의 디자인 · 기존 수업 내용 · 날짜 · 강사 첨부 · 링크는 바꾸지 않고 새 자료 항목만 바꾼다. API 성공만으로 화면 확인을 대신하지 않는다. 게시 커밋 고정 링크 · 해시 · 검증 · 남은 의존성을 기록한다.
5. 학생 패키지에 키 · 개인정보 · 강사 정답이 없어야 한다 — `제작용/실습시작/verify_packages.py`로 검사한다. 실행 의존성은 `_` 접두사 · lock 파일이라는 이유만으로 빼지 않고, 필수 파일이 빠지면 목록을 결과에 맞춰 줄이지 않는다. 개인 절대경로 · 정답 하드코딩 · 로컬 검증용 localhost 목록은 배포하지 않는다.
6. 포털 전체 설치 · 촬영용 clone과 개별 랩 다운로드를 구별한다. 학생은 전체 저장소나 여러 회차를 한꺼번에 받지 않는다.

## P13 마지막 종합 실습

1. **마지막 적용 실습은 교대 인수인계 한 시나리오다**(통합 온라인 11 · 실전 온라인 8 · 통합 오프라인 9~10 · 실전 오프라인 8~9). 강사 제공 보충 매뉴얼을 기존 제조 스키마로 추출 · 원문 검토 · 추가 적재하고, 설비 · 정비 · ERP 조회로 미완료 · 주의 · 기록 불일치를 정리하는 에이전트 · 스킬을 만들고, bpmn.io의 조회 → 인계안 → 인계자 검토 → 인수자 확인/보완 → 완료 흐름을 포털의 별도 정의 · 시작 폼 · 역할 · 작업에 연결해 실행한다(시작 입력 · 검토 · 보완 분기는 유지). 강사 코드로 허용되는 행동은 제공 문서 검토 · 추가 적재, 에이전트 · 스킬 편집, 제공 교대 BPMN의 표시 이름 · 배치 · 초안 단계 에이전트 배정 · 별도 판본 등록이다. 강사 승인 문서 · 판본 · 수업 행동만 허용하고 임의 문서 · 도구 · 무제한 AI 실행을 열지 않으며, 임의 학생 코드를 자동 연결하지 않는다. 같은 조건의 추출 재사용은 표시하고 사람의 검토 · 적재는 유지한다(제공 문서의 추출 후보 재사용과 에이전트의 현재 자료 조회는 다르다). 인계 확인은 정비 완료 · 실제 조치 · 발주가 아니다.
