# 실습 — 랩·입력·응용 범위 — 상세 기준

## 2026-10-27 마지막 적용 랩 범위 정정

통합온라인11·실전온라인8 및 대응 오프라인 마지막 적용 랩은 자유 개인 주제가 아닌 **교대 인수인계**다. 제공 보충 매뉴얼의 추가 적재와 기존 지식/시스템 재사용, 별도 에이전트·BPMN의 포털 실행을 수행한다. 승인된 자료·도구·수업 행동만 허용한다. 구체 계약은 [공통 기준](2_기준.md)의 최신 절을 따른다. 아래 옛 개인 주제/로컬에서만 완료 설명은 이 범위에 적용하지 않는다. 실제 랩 패키지와 완주 검증은 후속 작업이다.

## 현재 실라버스와 랩 보강 경계 — C66

[실제 랩·지원 범위와 후속 보강](근거/2026-10-27_실라버스_실제랩과지원범위.md)를 먼저 대조한다. 현재 랩이 최종 요구를 이미 구현했다고 가정하지 않는다. 이번 실라버스 작업은 랩 코드를 변경하지 않고 독립 시작본·실제 로컬 추출 구현·외부 MCP·자기 Notion 퀴즈와 실전 활용 출력의 제작 요구를 남긴다. [C66 VS Code 최종 흐름](근거/2026-10-27_VSCode랩_최종흐름.md)가 포털 제한과 로컬 제작을 구분하는 정본이다. 기존 AL1~AL8의 확장 원칙을 적용하며 새로운 능력이 없는 에이전트 반복 제작을 피한다. 랩 제작 때 같은 판본의 입력·코드·가이드·대본·ZIP을 맞춘 뒤 실제 수행을 확인한다.

## 바이브 코딩의 제공 경계 — 2026-10-26 후속 결정

환경 준비·원자료·짧은 작업 규칙·START의 과제와 완료 기준을 제공한다. 이번 과제의 모델링·적재·조회 등 해결 로직과 완성 프롬프트를 미리 넣지 않는다. 학생은 목표·입력·제약·확인 사례를 자기 말로 정리하고 AI의 계획과 실행 결과를 원자료에 대조하며 필요한 수정을 한다. 아무 요청이나 해도 정답이 자동 완성되는 구조로 만들지 않는다. AI가 처음부터 맞게 만들었다면 고의 오류를 연출하지 않는다.

AGENTS 등 지침은 학습 맥락과 작업 범위 안내이며 강제 보안 장치가 아니다. 별도 DB·주소·권한 경계와 실제 검증을 구별한다. 실전반의 차이는 승인된 업무 활용이며 빈칸 수·추가 숙제가 아니다. 적용·공식 모범 사례·실행 근거는 [실습 시작 검증](근거/2026-10-26_실습시작과독립랩.md)을 따른다.

## 독립 시작본과 PC 초기화 — 2026-10-26

학생 개인 GitHub·commit/push·이름/이메일 설정을 필수로 요구하지 않는다. 각 실습은 필요한 자료만 받아 독립 시작한다. 연결 실습에는 앞 단계 완성 상태를 시작본으로 제공하고 이번 요구를 구현·변경하게 한다. 학생의 이전 결과 가져오기는 선택이며 진행의 필수 조건이 아니다. 이번 과제의 강사 정답은 학생 폴더 밖에 둔다. 이전 기능을 변경하는 과제까지 모두 빈칸 채우기로 바꾸지 않는다. 저장·내보내기 방법과 초기화 시 결과가 사라질 수 있음을 안내하며 자동 복구를 약속하지 않는다. 배포·시작 도구의 진행 상태는 [실습 인계](인계_실습제작과배포.md)를 따른다.

## Notion 주제 갤러리 — 2026-10-22 최신 확정

이 절은 Notion 학습노트의 확정된 구성 기준이다. 현재 제작 상태는 현황과 촬영 준비 문서를 따른다. **학습노트 하나 → 여러 주제 카드 → 자유로운 내용·하위 페이지**를 유지한다. 홈은 큰 표지 없이 작은 이미지 카드로, 전체 주제 표는 이름·분야·이해도가 보이게 구성했다. 주제별 예시와 재사용 템플릿을 포함한 두 과정 공통 29단계 대본·입력·가이드 HTML·ZIP을 동기화했다. 디자인·입력 정본은 촬영 준비 문서에 연결한다. 승인된 2분40초대 샘플처럼 위치 안내→조작·입력→결과 확인을 나누고, 반복 설명만 줄인다. 이론/실습/실수노트 분류나 별도 자료 DB를 강제하지 않는다. 이 절의 2026-10-22 준비 기록과 이후 촬영 완료 기록을 구별한다. 최신 촬영 판정은 촬영 준비 문서와 현황을 따른다. 상세 구조와 입력은 [촬영 준비](../../제작용/촬영/notion/촬영준비.md), 발화는 실습 대본 기준을 따른다.


랩의 목적·자료·학생/강사 작성 범위·응용·결과 판정을 만들거나 고칠 때 읽는다. 두 과정 관계는 [공통 기준](2_기준.md#두-과정의-공통-범위와-차이--사용자-확정2026-10-27-갱신)을 따른다. 온라인1회차는 공통이다. 이후 공통 도구 실습의 자료·절차는 재사용하고 대본은 과정별 설명 초점에 맞춘다. VS Code는 구현 요구·활용 결과에도 차이를 둔다. 최신 범위와 C57 영상의 재사용 경계는 공통 기준을 따른다. 가이드는 [실습 가이드](기준_실습가이드.md), 강사 발화는 [실습 대본](기준_실습대본.md), 검증은 [마감](검증과마감.md)에서 관리한다.

기존 조항 번호와 본문을 보존했다. 숫자만으로 위치를 찾지 말고 절 제목을 함께 본다. [작업별 읽기](4_만드는_법.md)에서 필요한 범위를 선택한다.

## VS Code 코딩 랩의 활용 가치와 과정별 차이 — 2026-10-20 사용자 확정

이 절의 강화 대상은 VS Code에서 요구를 구현·수정하는 코딩 랩이다. 통합반도 단순 예제 실행·정답 복사·한 번의 AI 요청으로 끝나는 장난감 수준으로 만들지 않는다. 실제 문제와 자료를 대조하고 요구에 맞게 구현·수정·검증하여 다른 입력·업무·PBL에서 다시 쓸 수 있는 결과를 남긴다. 필요한 난도는 허용하며 쉽게 끝내기 위해 핵심 조건·검증을 빼지 않는다. 기능 수·파일 수·문서량·시간으로 난도를 꾸미지 않는다.

2회차부터 실전반은 같은 핵심 주제를 실제로 적용하는 요구 해석·설계 선택·구현·검증·재사용을 실습 수행에 가미한다. 차이는 대본의 설명 깊이에만 두지 않고 랩·가이드·결과 판정에도 반영한다. 난도나 기능 수를 늘리는 것 자체가 목적은 아니다. 상세 적용 범위는 [공통 기준](2_기준.md)을 따른다.

VS Code로 자료 폴더를 여는 것과 코딩 랩을 구별한다. 설치·환경 준비·포털 관찰·Notion·arrows.app 등의 활동에 이 절을 기계적으로 적용해 코드 과제를 추가하지 않는다. 환경 준비는 공통 선행 조건과 실제 준비 완료의 판정까지 갖추되 과정별로 일부러 다른 도구·설정을 요구하지 않는다. 전체 과정에서 코딩 랩의 차이를 확보하는 것과 모든 실습·준비 단계마다 추가 과제를 붙이는 것은 다르다.

실습 영상 제작은 [실습 영상 제작 안내](방법_ego_실습영상_촬영.md)를 따른다. 1회차는 두 과정 공통이며 독립 코딩 과제를 만들거나 추가 차이 설계부터 시작하지 않는다. 확정 이론과 기존 내용 근거·실습 수정은 보존한다. 차이안 작성과 실제 랩·대본·HTML·ZIP 반영 완료를 구별한다.

## 상세 적용 — 제조 업무 맥락과 반복 구조의 해석

실습은 포털과 연결되는 제조 업무의 목적·요구사항을 중심으로 설계한다. 짧은 일반 회의록의 단순 요약이나 명칭만 제조 용어로 바꾼 사례로 끝내지 않는다. 회의를 사용할 경우 어떤 부서가 어떤 근거·제약을 놓고 무엇을 결정하는 회의인지 구체화한다. 자료 분량이나 어려운 전문 용어로 난도를 꾸미지 않고, 서로 연결된 자료를 대조하여 판단하고 결과를 확인하는 작업을 확보한다. 실제 공장 자료와 교육용 가상 사례는 구별한다.

## 10. 실습

54. **구분은 이론과 실습 둘뿐이다.** 개념의 결과를 예상하고 근거를 비교하는 활동과 Wrap-up은 이론에 속한다. 도구를 조작해 결과물을 만들거나 실행을 확인하는 것은 강사가 혼자 보여 주어도 실습이다. 온라인 복습은 해당 실라버스 항목에 대응시키며 새 행을 만들거나 다른 회차의 Wrap-up 시간을 임의로 옮기지 않는다.

55. **제작 실습은 결과물을 완성하는 일이다.** 포털의 짧은 관찰·ProcessGPT 강사 시연은 실라버스에 정한 체험 범위를 따른다. 목적, 입력, 절차, 산출물, 성공 판정, 예외가 있다.

56. **앞에서 만든 것을 뒤에서 다시 쓴다**(온톨로지, DB, 작업 절차, 결정표). 매번 다시 만들지 않는다. 에이전트 응용은 서로 다른 일을 하게 한다.

57. **두 과정의 핵심 주제는 같되 실전반의 실제 응용 수행에 차이를 둔다.** 1회차 공통 유지와 2회차 이후의 과정별 구성은 [공통 기준](2_기준.md)을 따른다. 포털·공통 도구는 재사용하되 VS Code 랩 전체를 대본만 다른 공통판으로 처리하지 않는다.

60. **포털 체험을 긴 독립 강의로 만들지 않는다.** 앞에서 설명한 개념이 실제로 어떻게 쓰이는지 눈으로 확인하는 것이 목적이다.

### 제조 업무와 PBL 연결

랩마다 결정할 업무, 입력과 출처, 조건·예외, 구현할 기능, 결과 확인 방법, 다음 단계에서 가져갈 산출물을 연결한다. 난이도를 올리려고 기능 수를 늘리지 않는다. 도구 열기 같은 준비 단계는 뒤 업무를 위한 짧은 단계로 둔다. 특히 각 과정의 랩의 기록 추적 → 지식 구조·판단 → 근거 추출 → 에이전트·도구 → 명세·검증 → 승인·실행 → 종합 제조 조율이 재사용할 명세·지식·출력 계약·BPMN·검증 기록으로 남아야 한다.

입력·시작본·참조 완성본을 분리한다. 원문·교육용 가상 자료·제공 실행 발췌의 성격과 시점을 표시한다. 같은 이름이라는 이유로 다른 설비·요청·판본을 합치지 않는다. 연결 랩은 제공된 이전 단계 완성 시작본을 기본 입력으로 사용한다. 학생이 자기 결과를 가져오기로 선택하면 판본·입출력 계약을 확인하고 별도 보관한 뒤 사용하며 기존 결과를 덮어쓰지 않는다. 결과 생성·수정·재확인·저장·재열기를 흐름에 포함하고, 실제 실패가 없는데 정상 자료를 망가뜨려 실패를 연출하지 않는다.
