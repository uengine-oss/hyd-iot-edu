# 실습 — 랩·입력·응용 범위 — 상세 기준

## Notion 주제 갤러리 — 2026-10-22 최신 확정

현재 범위는 완성된 Notion 학습노트의 촬영 전 자료 동기화다. **학습노트 하나 → 여러 주제 카드 → 자유로운 내용·하위 페이지**를 유지한다. 홈은 큰 표지 없이 작은 이미지 카드로, 전체 주제 표는 이름·분야·이해도가 보이게 구성했다. 주제별 예시와 재사용 템플릿을 포함한 두 과정 공통 29단계 대본·입력·가이드 HTML·ZIP을 동기화했다. 디자인·입력 정본은 촬영 준비 문서에 연결한다. 승인된 2분40초대 샘플처럼 위치 안내→조작·입력→결과 확인을 나누고, 반복 설명만 줄인다. 이론/실습/실수노트 분류나 별도 자료 DB를 강제하지 않는다. 본 촬영·전체 음성 생성·50분 실측은 미수행이다. 상세 구조와 입력은 [촬영 준비](../../제작용/촬영/notion/촬영준비.md), 발화는 실습 대본 기준을 따른다.


랩의 목적·자료·학생/강사 작성 범위·응용·결과 판정을 만들거나 고칠 때 읽는다. 두 과정 관계는 [공통 기준](2_기준.md#두-과정의-공통-범위와-차이--사용자-확정2026-10-23-갱신)을 따른다. 랩은 두 과정이 한 벌을 쓰며 과정별로 현실 조건을 따로 더하지 않는다. 가이드는 [실습 가이드](기준_실습가이드.md), 강사 발화는 [실습 대본](기준_실습대본.md), 검증은 [마감](검증과마감.md)에서 관리한다.

기존 조항 번호와 본문을 보존했다. 숫자만으로 위치를 찾지 말고 절 제목을 함께 본다. [작업별 읽기](4_만드는_법.md)에서 필요한 범위를 선택한다.

## VS Code 코딩 랩의 활용 가치와 과정별 차이 — 2026-10-20 사용자 확정

이 절의 강화 대상은 VS Code에서 요구를 구현·수정하는 코딩 랩이다. 통합반도 단순 예제 실행·정답 복사·한 번의 AI 요청으로 끝나는 장난감 수준으로 만들지 않는다. 실제 문제와 자료를 대조하고 요구에 맞게 구현·수정·검증하여 다른 입력·업무·PBL에서 다시 쓸 수 있는 결과를 남긴다. 필요한 난도는 허용하며 쉽게 끝내기 위해 핵심 조건·검증을 빼지 않는다. 기능 수·파일 수·문서량·시간으로 난도를 꾸미지 않는다.

랩(실습 내용물)은 두 과정이 한 벌이며 난이도는 실전반에 맞춘다: 요구 해석의 자율성, 설계 선택과 근거, 복합 조건·예외 처리, 구현·검증·재사용의 깊이를 두 과정 모두에 요구한다. 랩 자체에는 과정 차이를 두지 않으며, 실습 쪽 과정 차이는 VS Code 코딩 랩의 대본에만 있다(정본 [공통 기준](2_기준.md#두-과정의-공통-범위와-차이--사용자-확정2026-10-23-갱신)). 실전반이 10명 미만이라는 정보는 사용자에게서 들은 참고 정보이며 인원 확정이나 과제량 증대의 근거로 삼지 않는다.

VS Code로 자료 폴더를 여는 것과 코딩 랩을 구별한다. 설치·환경 준비·포털 관찰·Notion·arrows.app 등의 활동에 이 절을 기계적으로 적용해 코드 과제를 추가하지 않는다. 환경 준비는 공통 선행 조건과 실제 준비 완료의 판정까지 갖추되 과정별로 일부러 다른 도구·설정을 요구하지 않는다. 전체 과정에서 코딩 랩의 차이를 확보하는 것과 모든 실습·준비 단계마다 추가 과제를 붙이는 것은 다르다.

현재 우선 작업은 [5종 약5분 샘플 제작 검증](인계_5분샘플_제작검증.md)이다. 실제 산출물을 빠르게 만드는 화면으로 제작 가능성을 먼저 확인하고 전체 회차 개정과 구별한다. 1회차는 두 과정 공통이며 독립 코딩 과제를 만들거나 추가 차이 설계부터 시작하지 않는다. 샘플 실행·녹화·음성은 최신 사용자 허용 범위, 이번 인계 세션은 문서 동기화만 수행한다. 확정 이론과 기존 내용 근거·실습 수정은 보존한다. 차이안 작성과 실제 랩·대본·HTML·ZIP 반영 완료를 구별한다.

## 상세 적용 — 제조 업무 맥락과 반복 구조의 해석

실습은 포털과 연결되는 제조 업무의 목적·요구사항을 중심으로 설계한다. 짧은 일반 회의록의 단순 요약이나 명칭만 제조 용어로 바꾼 사례로 끝내지 않는다. 회의를 사용할 경우 어떤 부서가 어떤 근거·제약을 놓고 무엇을 결정하는 회의인지 구체화한다. 자료 분량이나 어려운 전문 용어로 난도를 꾸미지 않고, 서로 연결된 자료를 대조하여 판단하고 결과를 확인하는 작업을 확보한다. 실제 공장 자료와 교육용 가상 사례는 구별한다.

## 10. 실습

54. **구분은 이론과 실습 둘뿐이다.** 개념의 결과를 예상하고 근거를 비교하는 활동과 Wrap-up은 이론에 속한다. 도구를 조작해 결과물을 만들거나 실행을 확인하는 것은 강사가 혼자 보여 주어도 실습이다. 복습은 해당 실라버스 항목에 대응시키며 새 행을 만들거나 다른 회차의 Wrap-up 시간을 임의로 옮기지 않는다.

55. **실습은 구경이 아니라 결과물을 완성하는 일이다.** 목적, 입력, 절차, 산출물, 성공 판정, 예외가 있다.

56. **앞에서 만든 것을 뒤에서 다시 쓴다**(온톨로지, DB, 작업 절차, 결정표). 매번 다시 만들지 않는다. 에이전트 응용은 서로 다른 일을 하게 한다.

57. **공통 실습은 통합반과 실전반이 같다.** 랩은 한 벌이며 과정 차이는 [공통 기준](2_기준.md#두-과정의-공통-범위와-차이--사용자-확정2026-10-23-갱신)을 따른다(옛 문장 「실전반은 일부에만 현실 조건을 더한다」는 2026-10-22 랩 한 벌 확정으로 폐기).

60. **포털 체험을 긴 독립 강의로 만들지 않는다.** 앞에서 설명한 개념이 실제로 어떻게 쓰이는지 눈으로 확인하는 것이 목적이다.

### 제조 업무와 PBL 연결

랩마다 결정할 업무, 입력과 출처, 조건·예외, 구현할 기능, 결과 확인 방법, 다음 단계에서 가져갈 산출물을 연결한다. 난이도를 올리려고 기능 수를 늘리지 않는다. 도구 열기 같은 준비 단계는 뒤 업무를 위한 짧은 단계로 둔다. 특히 두 과정이 함께 쓰는 랩의 기록 추적 → 지식 구조·판단 → 근거 추출 → 에이전트·도구 → 명세·검증 → 승인·실행 → 종합 제조 조율이 재사용할 명세·지식·출력 계약·BPMN·검증 기록으로 남아야 한다.

입력·시작본·참조 완성본을 분리한다. 원문·교육용 가상 자료·제공 실행 발췌의 성격과 시점을 표시한다. 같은 이름이라는 이유로 다른 설비·요청·판본을 합치지 않는다. 앞 결과를 다음 폴더의 input에 가져오되 빈 양식이나 제공 완성본으로 덮어쓰지 않는다. 결과 생성·수정·재확인·저장·재열기를 흐름에 포함하고, 실제 실패가 없는데 정상 자료를 망가뜨려 실패를 연출하지 않는다.
