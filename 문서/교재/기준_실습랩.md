# 실습 — 랩·입력·응용 범위 — 상세 기준

랩의 목적·자료·학생/강사 작성 범위·응용·결과 판정을 만들거나 고칠 때 읽는다. [공통 기준](2_기준.md)의 두 과정 관계를 적용한다. 같은 주제와 공통 기반을 유지하고 일부에만 필요한 현실 조건을 더한다. 가이드는 [실습 가이드](기준_실습가이드.md), 강사 발화는 [실습 대본](기준_실습대본.md), 검증은 [마감](검증과마감.md)에서 관리한다.

기존 조항 번호와 본문을 보존했다. 숫자만으로 위치를 찾지 말고 절 제목을 함께 본다. [작업별 읽기](4_만드는_법.md)에서 필요한 범위를 선택한다.

## 온라인 상세 17

17 : **제조 맥락** : 포털과 해당 이론의 실제 제조 업무와 연결한다. 회의라면 부서·근거·결정할 내용을 명확히 한다.

## 온라인 상세 18

18 : **장난감 금지** : 짧은 요약이나 한 번의 요청으로 누구나 끝내는 과제로 축소하지 않는다. 자료 대조·조건 해석·구현 결과 판단이 있어야 한다. 분량과 기능 수로 난도를 꾸미지 않는다.

## 온라인 상세 19

19 : **PBL 활용성** : 난이도 상승 자체가 목표가 아니다. 특히 실전반은 실제 포털의 제조 업무처럼 관련 자료·조건·근거를 연결하여 구현하고 확인한 결과를 PBL에 재사용할 수 있어야 한다. 짧은 문서 요약이나 한 번의 요청만으로 끝나는 장난감 과제로 축소하지 않는다. 요구 구체화·근거 선택·조건 조율·결과 판단은 실제 업무 목적에 필요한 만큼 둔다.

## 온라인 상세 20

20 : **연결** : 앞 요청·명세·지식 구조·스킬·검증 결과를 다음 실습에서 이어 쓰고 저장·재열기를 포함한다.

## 온라인 상세 21

21 : **참조본 구별** : 제공 사례·템플릿·완성본과 수업에서 작성·확인하는 결과를 구별한다.

## 상세 적용 — 제조 업무 맥락과 반복 구조의 해석

실습은 포털과 연결되는 제조 업무의 목적·요구사항을 중심으로 설계한다. 짧은 일반 회의록의 단순 요약이나 명칭만 제조 용어로 바꾼 사례로 끝내지 않는다. 회의를 사용할 경우 어떤 부서가 어떤 근거·제약을 놓고 무엇을 결정하는 회의인지 구체화한다. 자료 분량이나 어려운 전문 용어로 난도를 꾸미지 않고, 서로 연결된 자료를 대조하여 판단하고 결과를 확인하는 작업을 확보한다. 실제 공장 자료와 교육용 가상 사례는 구별한다.

## 10. 실습

54. **구분은 이론과 실습 둘뿐이다.** 개념의 결과를 예상하고 근거를 비교하는 활동과 Wrap-up은 이론에 속한다. 도구를 조작해 결과물을 만들거나 실행을 확인하는 것은 강사가 혼자 보여 주어도 실습이다. 복습은 해당 실라버스 항목에 대응시키며 새 행을 만들거나 다른 회차의 Wrap-up 시간을 임의로 옮기지 않는다.

55. **실습은 구경이 아니라 결과물을 완성하는 일이다.** 목적, 입력, 절차, 산출물, 성공 판정, 예외가 있다.

56. **앞에서 만든 것을 뒤에서 다시 쓴다**(온톨로지, DB, 작업 절차, 결정표). 매번 다시 만들지 않는다. 에이전트 응용은 서로 다른 일을 하게 한다.

57. **공통 실습은 통합반과 실전반이 같다.** 실전반은 일부에만 현실 조건을 더한다.

60. **포털 체험을 긴 독립 강의로 만들지 않는다.** 앞에서 설명한 개념이 실제로 어떻게 쓰이는지 눈으로 확인하는 것이 목적이다.

### 제조 업무와 PBL 연결

랩마다 결정할 업무, 입력과 출처, 조건·예외, 구현할 기능, 결과 확인 방법, 다음 단계에서 가져갈 산출물을 연결한다. 난이도를 올리려고 기능 수를 늘리지 않는다. 도구 열기 같은 준비 단계는 뒤 업무를 위한 짧은 단계로 둔다. 특히 실전반의 기록 추적 → 지식 구조·판단 → 근거 추출 → 에이전트·도구 → 명세·검증 → 승인·실행 → 종합 제조 조율이 재사용할 명세·지식·출력 계약·BPMN·검증 기록으로 남아야 한다.

입력·시작본·참조 완성본을 분리한다. 원문·교육용 가상 자료·제공 실행 발췌의 성격과 시점을 표시한다. 같은 이름이라는 이유로 다른 설비·요청·판본을 합치지 않는다. 앞 결과를 다음 폴더의 input에 가져오되 빈 양식이나 제공 완성본으로 덮어쓰지 않는다. 결과 생성·수정·재확인·저장·재열기를 흐름에 포함하고, 실제 실패가 없는데 정상 자료를 망가뜨려 실패를 연출하지 않는다.
