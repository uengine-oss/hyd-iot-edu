## 목표와 순서

사용자는 각 도구에서 실제로 산출물을 빠르게 만드는 약 5분 영상을 보고, 우리가 이 작업을 정말 수행할 수 있는지 확인하려 한다. 대상은 arrows.app, bpmn.io, Neo4j Browser, VS Code, Notion의 5종이다. arrows 1편부터 완료하고 나머지를 이어간다. 50분 강의·전체 회차·사진 가이드·두 과정 차이안을 먼저 만드는 작업이 아니다. 5분 안에 의미 있는 제작 과정을 압축한다. 억지로 시간을 채우지 않는다.

실제 화면에서 작업 시작→제작→저장→완성 결과 확인을 보여 준다. 설명은 이 실제 흐름에 맞춰 대본으로 추가하고 기존 지정 음성인 **안치윤v5**를 사용한다. 긴 대본·음성에 맞추기 위해 화면을 기다리게 만들지 않는다. 이전에 만든 음성은 적합한 경우 재사용하며 그 길이·내용에 화면을 강제로 맞추지 않는다.

가장 중요한 것은 강사 본인이 원맨쇼로 실제 작업하는 자연스러움이다. 커서 이동·스크롤·드래그·타이핑·클릭·확인·전환 전체에 적용한다. 목표 지점까지 찔끔찔끔 이동하거나 고정 대기를 반복하지 않는다. 설명할 대상을 짚고 필요한 결과가 읽힐 때 진행한다. 짧은 명령·바이브 요청은 사람 속도로 타이핑하고 긴 명령은 붙여넣어도 된다. 중간 컷·속도 변경·화면 확대 없이 연속 진행하는 기존 방향을 유지한다. 첫 UI 설명 이후 반복 설명과 이론 복습을 늘리지 않는다. 본인 발화·제3자·영어 철자·수치 낭독은 실습 대본에 연결된 공통 규칙을 따른다.

VS Code 본 강의는 처음부터 학생 입장의 강사 본인이 자료를 받아 해당 폴더를 여는 장면으로 시작한다. 실제 처음 볼 때는 필요한 탐색기·채팅·터미널 UI를 간단히 소개하고 이후에는 길게 반복하지 않는다. 요구를 제시하고 AI와 현재 기능·제약을 파악한 뒤 완료 기준과 필요한 계획·구현·검증으로 간다. 파일·함수·정답을 미리 아는 듯 말하지 않는다. SDD는 그 학습 시점과 실제 변경에 맞춰 사용하며 모든 랩에 문서 작업을 같은 길이로 강요하지 않는다. 사용자가 지정한 시연 도구는 VS Code Codex gpt-6-luna다.

VS Code 랩의 촬영 준비에는 시작본·참조 완성본·실행 절차와 완료 조건을 갖춘다. 강사가 처음부터 실제로 작업하되 진행이 막혀도 완성된 결과의 실행·결과 확인으로 마무리할 수 있도록 한다. 참조본 전환 사실은 짧게 말하고 중복 설명하지 않는다. 샘플 성공을 학생용 시작본 전체의 검증 성공으로 보고하지 않는다.

1회차에는 독립 VS Code 코딩 랩이 없다. 두 과정 공통으로 필요한 설치 목록의 역할·필요성만 짧게 말하고 설치 완료를 가정한다. 수업용 HYD 저장소 main clone→VS Code 폴더 열기→명령의 목적을 설명하며 입력·기동→포털 열기→아키텍처 위치와 앞 이론을 짧게 연결한다. 촬영용 main 판본은 확인 대상이며 현재 develop을 임의로 main으로 바꾸지 않는다. 짧은 명령·바이브 요청은 직접 타이핑, 긴 명령은 붙여넣기를 허용한다.

대본은 강사 본인이 지금 무엇을 해 보고 왜 그렇게 판단하는지를 말하는 실제 발화다. 앞 이론·포털을 실제로 마친 것처럼 자연스럽게 연결할 수 있으나 아직 보지 않은 장면·성공을 사실로 지어내지 않는다. 오늘 목적·만들 결과·필요한 UI·이번 판단은 설명해도 된다. 이론 재강의·영어 철자 전부 읽기·모든 수치 낭독·제3자 제작 지시문·가상 학생 문답으로 채우지 않는다. 조작 메모는 비낭독 영역에 둔다.

## Computer Use와 녹화 조사 — 가능성과 현재 연결을 구별

사용자는 타인의 실제 사례를 봤으며 Computer Use 녹화 불가능 단정을 지적했다. 그 단정은 철회했다. 다음은 공급자 문서에서 확인한 구현이며 이 환경에 설치·연결·검증했다는 뜻은 아니다.

- [Cua Driver 녹화](https://cua.ai/docs/cua-driver/reference/mcp-tools/recording): `start_recording`/`stop_recording`, `record_video: true`, MP4 H.264 30fps. Windows는 FFmpeg gdigrab 사용.
- [Everstack Computer Use](https://docs.everstack.ai/getting-started/sandboxes/computer-use/): 원격 가상 데스크톱 조작·녹화 API·MP4 다운로드·VNC 보기.
- [agent-browser 녹화](https://agent-browser.dev/recording): 브라우저 작업 녹화·커서 표시·최대60fps. 브라우저 방식이며 Windows 네이티브 앱 제어와 혼동하지 않는다.

현재 도구에 녹화 버튼이 보이지 않는다는 이유로 Computer Use 전체가 불가능하다고 말하지 않는다. 현재 이용 가능한 기능을 확인하고 녹화기 결합을 판단한다. 높은 fps만으로 실제 입력의 끊김이 해결되지는 않는다.

### 이전 환경에서 관찰한 오류·시도

- Windows Computer Use `@oai/sky`의 Chrome `get_window_state`는 현재 URL을 충분히 확인하지 못했다는 오류로 해당 턴을 중단시켰다. 사용자 창 최소화가 확정 원인이라는 설명은 잘못이었다. 이 오류를 우회하거나 정책을 끄지 말고 현재 정상 연결 여부를 진단한다. 도구가 중단을 지시하면 따른다.
- `mcp__cua_repl`의 IAB는 동작했지만 당시 공개 capabilities에 녹화 기능이 없었다. 통합 기능의 부재를 별도 녹화 결합 불가능으로 해석하지 않는다. 현재 capabilities는 재확인 대상이다.
- 별도 headed Chromium + Playwright의 공식 screencast로 위3.16초 파일은 생성됐다. 이것을 Computer Use로 조작한 영상이라고 부르지 않는다. 대체 녹화 방식으로 사용자가 허용한 경로다.
- 이전 본 촬영용 이동 함수는 18개의 작은 mouse.move 호출과 대기를 반복해 사용자에게 끊겨 보였다. 긴 REPL 호출은 시간 초과·초기화됐다. 그 방식을 그대로 반복하지 않는다. 새 방식의 실제 부드러움은 미검증이다.
