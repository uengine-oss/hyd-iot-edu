# 실습과 랩 — 상세 제작 기준

공통 원칙·읽기 규칙은 [공통 기준](2_기준.md)을 따른다. 발화·수치·촬영 경계는 [덱과 이론 대본](기준_덱과이론대본.md)의 공통 발화 규칙도 적용한다. 기존 번호를 보존한다. 동기화·마감 판정은 [검증과 마감](검증과마감.md)을 따른다.

## 온라인 상세 10

10 : **온라인·오프라인 구별** : 온라인 영상은 강사 원맨쇼로, 학생용 가이드를 제공·읽게 하거나 학생 작업 시간을 기다리는 전제가 없다. 오프라인 랩 가이드는 학생에게 배포할 자료다. 작업 화면·결과 화면 사진 중심에 짧고 정확한 설명, 확인할 부분과 판정 기준을 붙인다. 온라인에서는 제작 참고로 활용한다. 실제 화면 촬영은 별도 단계다.

## 온라인 상세 11

11 : **시작** : 이론·실제 앞서 본 포털과 목적을 짧게 연결하고 코드 다운로드→압축 해제→VS Code 열기로 진행한다. 구글드라이브 언급·ZIP 목록 설명을 본론에 넣지 않는다.

## 온라인 상세 12

12 : **강사 출발점** : 목적·요구사항만 알고 프로젝트 내부는 모른다. 탐색 전 파일·함수·정답 프롬프트를 아는 척하지 않는다.

## 온라인 상세 13

13 : **첫 바이브 코딩** : AI와 현재 기능·제약을 파악한 뒤 요구·완료 기준을 구체화하고 필요한 계획·구현·결과 확인으로 간다.

## 온라인 상세 14

14 : **뒤 회차 반복** : 첫 방법 설명 후 앞 명세·결과를 이어 쓰고 이번에 새로 생긴 요구·판단·검증을 설명한다.

## 온라인 상세 15

15 : **절차 강요 금지** : 매 랩을 같은 길이의 절차로 강제하지 않는다. 작은 명확한 변경은 직접 처리하며 SDD·BDD는 학습 시점과 필요에 맞춘다.

## 온라인 상세 16

16 : **코드 위치** : 소스코드 해설은 중심이 아니다. 프롬프트·스킬·명세·조건·결과와 판단을 보여 준다.

## 온라인 상세 17

17 : **제조 맥락** : 포털과 해당 이론의 실제 제조 업무와 연결한다. 회의라면 부서·근거·결정할 내용을 명확히 한다.

## 온라인 상세 18

18 : **장난감 금지** : 짧은 요약이나 한 번의 요청으로 누구나 끝내는 과제로 축소하지 않는다. 자료 대조·조건 해석·구현 결과 판단이 있어야 한다. 분량과 기능 수로 난도를 꾸미지 않는다.

## 온라인 상세 19

19 : **PBL 활용성** : 난이도 상승 자체가 목표가 아니다. 특히 실전반은 실제 포털의 제조 업무처럼 관련 자료·조건·근거를 연결하여 구현하고 확인한 결과를 PBL에 재사용할 수 있어야 한다. 짧은 문서 요약이나 한 번의 요청만으로 끝나는 장난감 과제로 축소하지 않는다. 요구 구체화·근거 선택·조건 조율·결과 판단은 실제 업무 목적에 필요한 만큼 둔다.

## 온라인 상세 20

20 : **연결** : 앞 요청·명세·지식 구조·스킬·검증 결과를 다음 실습에서 이어 쓰고 저장·재열기를 포함한다.

## 온라인 상세 21

21 : **참조본 구별** : 제공 사례·템플릿·완성본과 수업에서 작성·확인하는 결과를 구별한다.

## 온라인 상세 22

22 : **결과 수정** : 요구와 실제 결과를 대조하고 관찰한 문제를 수정·재확인한다. AI 응답·성공 결과 선기입과 억지 실패 금지.

## 온라인 상세 23

23 : **시간 끌기 금지** : 가상 학생·억지 문답·불필요한 실패·반복 경고·타이핑·대기로 분량을 채우지 않는다.

## 상세 적용 — 제조 업무 맥락과 반복 구조의 해석

실습은 포털과 연결되는 제조 업무의 목적·요구사항을 중심으로 설계한다. 짧은 일반 회의록의 단순 요약이나 명칭만 제조 용어로 바꾼 사례로 끝내지 않는다. 회의를 사용할 경우 어떤 부서가 어떤 근거·제약을 놓고 무엇을 결정하는 회의인지 구체화한다. 자료 분량이나 어려운 전문 용어로 난도를 꾸미지 않고, 서로 연결된 자료를 대조하여 판단하고 결과를 확인하는 작업을 확보한다. 실제 공장 자료와 교육용 가상 사례는 구별한다.

도입→설명→요약이라는 공통 구조 자체는 허용한다. 이해의 진전 없이 같은 예고·재설명을 연속 반복하는 부분을 조정한다. 표현을 억지로 다르게 만들거나 필요한 개념·조건·예외·복습을 삭제하지 않는다.

온라인 강사 원맨쇼, 목적·요구사항만 알고 프로젝트는 모르는 출발점, 짧은 실습 코드 내려받기→압축 해제→VS Code 열기, AI 탐색을 통한 요구 구체화와 구현·검증, 코드 해설을 중심으로 삼지 않기, 이후 반복 방법 설명의 점진적 축소를 유지한다. 시간은 내용과 작업의 결과이며 50분 등 목표에 맞추지 않는다. 실제 실행 없이 정확한 영상 시간을 확정하지 않는다.

## 상세 적용 — 이론의 반복 점검과 실습 시작 장면

이론은 회차별 내용이 다르다는 이유로 반복 검토를 면제하지 않는다. 개념 설명·역할 있는 복습·조건과 예외는 보존하되, 같은 도입·예고·재요약·수사적 질문이 실제 이해의 진전 없이 되풀이되는지 문맥으로 확인한다. 일괄 문장 치환이나 반복 단어 개수만으로 삭제하지 않는다. 이번 기준 기록만으로 이론 전체의 새 재독을 완료했다고 표현하지 않는다.

실습은 내려받기·압축 해제·VS Code 열기와 이미 익힌 바이브 코딩 절차를 매번 길게 설명하지 않는다. 첫 사용에서 화면 조작을 이해할 만큼 보여 주고, 이후에는 필요한 조작을 간결하게 수행한다. 시작 발화는 해당 랩의 실제 이론·앞서 본 포털 경험과 오늘 만들 결과를 짧게 연결하고, 실습 코드를 받아 VS Code로 여는 장면으로 넘어간다. 모든 랩에 같은 도입 문장을 복제하지 않는다. 아직 보지 않은 포털 장면을 보았다고 가정하지 않는다. 열린 화면의 표시는 실제 자료 확인 후 대본에 확정하며 미확인 화면을 만들어 말하지 않는다.

다운로드 서비스 이름·파일 목록·소스 구조를 설명거리로 늘리지 않는다. 구체적인 내려받기 위치는 화면 조작으로 전달한다. 프로젝트를 모르는 상태라는 전제와 목적·요구사항만으로 시작한다는 전제는 유지한다. 이후 AI 탐색·요구 구체화·구현 과정으로 연결하며 그 절차의 반복 설명은 아래 바이브 코딩과 설명의 점진적 축소 기준을 따른다.

## 상세 적용 — 온라인 실습의 바이브 코딩과 설명의 점진적 축소

온라인은 강사 한 사람이 목적·요구사항만 알고 처음 받은 랩 프로젝트에서 제작을 진행하는 영상이다. 학생용 가이드를 읽는 시간·학생 작업 시간은 영상 분량에 넣지 않는다. 기존 가이드는 제작 참고 자료로 보존한다. 소스코드 해설·파일 목록·ZIP 구성 설명을 본론으로 삼지 않는다. 필요한 코드의 역할만 짧게 짚고, 학습 대상인 프롬프트·스킬·명세·조건과 결과를 화면에서 보여 준다.

도입은 앞 이론과 실제 앞서 본 포털의 장면을 오늘 만들 결과에 짧게 연결한다. 아직 보지 않은 것을 보았다고 말하지 않는다. 해당 실습 코드를 내려받고 VS Code로 여는 조작은 간결하게 진행한다. 다운로드 서비스의 사용법이나 파일 구조를 길게 낭독하지 않는다.

첫 바이브 코딩 실습은 모르는 프로젝트에서 목적·요구사항을 제시하고, AI가 관련 부분을 조사하게 하며, 현재 기능과 필요한 결정을 확인하고, 요구사항·완료 기준을 구체화해 계획·구현·결과 검증으로 이어가는 방법을 설명한다. 강사가 미리 알고 있는 파일·함수·정답 프롬프트를 탐색 없이 지정하지 않는다. AI 답변·실행 결과를 선기입하지 않고, 관찰한 근거에 따라 다음 요청을 발전시킨다. 소스 내부 탐색은 AI가 수행하되 강사는 기능·제약·변경 영향과 결과로 이해하고 판단한다.

이후에는 익힌 절차를 매번 처음부터 가르치지 않는다. 같은 프로젝트의 이전 명세·계획·결과를 이어 쓰고 이번에 달라진 요구·판단·검증 지점에 시간을 쓴다. 첫 적용은 이유와 판단 과정을 충분히 보여 주고, 재적용은 새 차이만 설명하며, 익숙한 작은 작업은 짧은 요청과 결과 확인으로 진행한다. 새로운 프로젝트나 불명확한 요구·큰 변경이면 필요한 탐색·계획을 다시 수행하되 방법론 소개를 반복하지 않는다. 설명을 줄이는 것이 필요한 실제 검증을 생략한다는 뜻은 아니다.

매 랩에 탐색→명세→계획→구현→검증을 같은 길이의 형식으로 강제하지 않는다. 명세 문서는 SDD가 학습 목표이거나 변경 기준을 지속해서 관리할 때 사용한다. 초기 회차에 아직 배우지 않은 SDD·BDD 전문 용어나 문서 작업을 앞질러 강제하지 않는다. 익숙한 기본 동작은 자연스럽게 수행하고, 이번 랩만의 학습상의 새 판단이 있어야 한다. 흥미를 위해 억지 실패·가상 학생·불필요한 기능·드라마를 만들지 않는다.

분량은 강사의 설명·실제 제작·결과 해석 흐름의 결과로 추정한다. 코드 해설·타이핑·같은 절차의 재설명·대기·학생 활동으로 배정 시간을 채우지 않는다. 실행 리허설 없이 안정적인 정확한 영상 길이를 확정하지 않는다. 이번 조사와 기록에서 실제 실습·학생 코드/테스트·AI 시연·HYD/DB·브라우저 실습·캡처를 수행하지 않는다.

공식 자료에서 채택한 원칙(2026-10-19 확인): VS Code는 복잡하거나 접근이 불명확한 변경에서 계획을 분리하고, 작은 명확한 변경은 직접 구현할 수 있다고 설명한다. GitHub는 목적·범위·수용 기준을 명확히 하되 정확한 파일 경로를 모를 때 에이전트가 관련 코드를 찾을 수 있다고 설명한다. 이를 수업의 첫 설명→차이 중심 재적용→자연스러운 활용으로 구성하는 것은 사용자 요구에 따른 교육 설계이며, 모든 랩에 대한 유일한 최적 절차가 연구로 확정됐다는 주장이 아니다.

## 10. 실습

54. **구분은 이론과 실습 둘뿐이다.** 개념의 결과를 예상하고 근거를 비교하는 활동과 Wrap-up은 이론에 속한다. 도구를 조작해 결과물을 만들거나 실행을 확인하는 것은 강사가 혼자 보여 주어도 실습이다. 복습은 해당 실라버스 항목에 대응시키며 새 행을 만들거나 다른 회차의 Wrap-up 시간을 임의로 옮기지 않는다.
55. **실습은 구경이 아니라 결과물을 완성하는 일이다.** 목적, 입력, 절차, 산출물, 성공 판정, 예외가 있다.
56. **앞에서 만든 것을 뒤에서 다시 쓴다**(온톨로지, DB, 작업 절차, 결정표). 매번 다시 만들지 않는다. 에이전트 응용은 서로 다른 일을 하게 한다.
57. **공통 실습은 통합반과 실전반이 같다.** 실전반은 일부에만 현실 조건을 더한다.
58. **온라인은 강사가 혼자 자료를 받고 직접 만들고 확인하는 실습 영상이다.** 학생 가이드 읽기·학생 작업·가상 응답 시간을 넣지 않는다. 가이드는 제작 참고로 유지한다. 실습 대본은 지금 하는 일과 판단이 이어지게 쓰며 필요한 설명을 성기게 생략하지 않는다. 소스코드 해설은 중심이 아니다. 촬영 때 발화·전환·진행 속도는 튜닝할 수 있다. 관찰하지 않은 실행·실패·복구를 성공 결과처럼 쓰지 않는다.
59. **오프라인 랩 가이드는 학생 배포용이다.** 학생이 실제 작업을 따라가고 결과를 대조할 수 있도록 작업 화면·결과 화면 사진을 중심으로 짧은 설명과 확인 포인트를 붙인다. 사진만으로 목적·조건·판정 근거를 대신하지 않는다. 온라인에서는 학생에게 가이드를 읽히지 않고 강사가 직접 진행한다. 사진은 실제 촬영 후 넣고 현재 미촬영 화면을 실제 검증 결과처럼 만들지 않는다. 오프라인 전체 랩 제작을 이번 온라인 작업 범위로 자동 확대하지 않는다.
60. **포털 체험을 긴 독립 강의로 만들지 않는다.** 앞에서 설명한 개념이 실제로 어떻게 쓰이는지 눈으로 확인하는 것이 목적이다.
60-1. **실습은 목적과 요구사항에서 실제 제작·검증으로 이어 간다.** 자료 다운로드→압축 해제→VS Code 작업 공간 열기를 짧게 보여 주고 필요한 탐색·요구 구체화·계획·구현·결과와 근거 확인·문제 수정·재확인·저장·재열기로 잇는다. 앞 결과를 이어 쓰고 이미 익힌 방법을 매번 길게 설명하지 않는다. 참조 완성본은 직접 만든 결과와 구별한다. 네 단계나 완성본 설명을 형식적으로 추가하지 않으며 Notion을 포함해 고정 시간으로 늘리지 않는다.

## 5. 랩 자체·자료·온라인 진행·오프라인 배포

### 제조 업무와 PBL 연결

랩마다 결정할 업무, 입력과 출처, 조건·예외, 구현할 기능, 결과 확인 방법, 다음 단계에서 가져갈 산출물을 연결한다. 난이도를 올리려고 기능 수를 늘리지 않는다. 도구 열기 같은 준비 단계는 뒤 업무를 위한 짧은 단계로 둔다. 특히 실전반의 기록 추적 → 지식 구조·판단 → 근거 추출 → 에이전트·도구 → 명세·검증 → 승인·실행 → 종합 제조 조율이 재사용할 명세·지식·출력 계약·BPMN·검증 기록으로 남아야 한다.

입력·시작본·참조 완성본을 분리한다. 원문·교육용 가상 자료·제공 실행 발췌의 성격과 시점을 표시한다. 같은 이름이라는 이유로 다른 설비·요청·판본을 합치지 않는다. 앞 결과를 다음 폴더의 input에 가져오되 빈 양식이나 제공 완성본으로 덮어쓰지 않는다. 결과 생성·수정·재확인·저장·재열기를 흐름에 포함하고, 실제 실패가 없는데 정상 자료를 망가뜨려 실패를 연출하지 않는다.

첫 코딩은 목적과 요구에서 AI 탐색 → 현재 준비·미구현 확인 → 요구와 완료 기준 → 필요한 계획·구현 → 원문과 결과 대조로 간다. 이후에는 익힌 방법을 재강의하지 않고 새 조건·요구·검증을 설명한다. SDD·BDD는 해당 학습 시점과 업무에 필요한 범위에 둔다. 실제 명령은 촬영용 절차로 표시하며 이번 문서 작업에서 실행하지 않는다.

### 온라인

강사 혼자 자료를 내려받아 압축을 풀고 VS Code에서 작업한다. 학생이 가이드를 읽거나 답할 시간을 넣지 않는다. HTML은 제작 참고 자료다. 파일 목록·소스 해설을 본론으로 늘리지 않고 입력할 프롬프트·스킬·명세·판단 근거·실제 결과를 보여 준다. 실습 대본의 내용과 순서는 랩·가이드에 맞춘 상태로 확정하며, 발화·전환·진행 속도는 촬영 때 튜닝할 수 있다.

### 오프라인 학생용 가이드

학생 배포 폴더와 강사 solution·제작 기록을 분리한다. Copilot이 정답을 읽지 않도록 강사 완성본을 학생 시작 폴더 안에 넣지 않는다. 기존 안내·산출물 경로는 유지하고 새 구조로 옮길 때 실제 배포 안내를 함께 갱신한다. 새 코드 이름은 해당 STRUCTURE의 재사용 가능한 영어 이름 규칙을 따르되 기존 한국어 입력자료·참조를 일괄 개명하지 않는다. 키·실제 접속값을 배포물에 넣지 않는다.

1. 첫 화면은 만드는 결과와 진행 순서를 짧게 설명한다. 파일 이름 나열로 시작하지 않고 실제 단계에서 필요한 파일·도구를 소개한다. 받은 폴더는 VS Code 탐색기 구조로 알아볼 수 있게 보여 준다.
2. 작업 화면마다 화면 식별자, 목적, 직전 상태, 조작, 확인할 부분을 둔다. 짧은 설명과 표시가 사진을 안내해야 하며 필요한 조건·예외를 사진만으로 대신하지 않는다.
3. 결과 화면에는 확인할 값·상태·출처·판정 기준을 붙인다. 결과가 다르면 원문/입력/조건을 확인하고 수정·재검증하도록 연결한다. 기대값과 실제 관측값을 분리한다.
4. 입력할 프롬프트·스킬·명세는 사진 속 글자만으로 제공하지 않는다. 선택·복사·수정 가능한 HTML 텍스트 또는 별도 파일로 제공하고 가이드에서 링크한다. 예시·빈 양식·학생 작성 결과를 구분한다.
5. 저장 위치·다시 열어 볼 항목·다음 랩에 넘길 판본을 안내한다. 이어지는 랩은 앞 결과의 파일/식별자/출력 계약을 실제로 받아 이어 쓰도록 설계한다.
6. 지금은 `미촬영` 자리와 필요한 장면·확인 기준·파일 위치를 기록한다. 실제 작업·결과 사진과 촬영 환경·판본은 후속 허용된 촬영에서 채운다. 임의 화면을 실제 결과처럼 만들지 않는다. 이 제작 절차 복원이 오프라인 전 과정 제작·실행 완료를 뜻하지 않는다.

### 정적 검사와 배포 완료 조건

자료 참조 경로·식별자·명세 입출력·값/단위·시점·조건을 대조한다. Python은 AST, JSON/XML/BPMN은 파싱만 하며 학생 코드 import나 테스트 실행을 하지 않는다. 구문 통과는 구현 성공이 아니다. HTML의 내용·순서·로컬 링크와 복사 자료 해시를 확인하고 ZIP 내부 목록·각 파일 바이트를 배포 폴더와 비교한다. 이전 ZIP의 루트 폴더 접두어를 유지한다. 가이드/강사대본이 달라지면 ZIP도 갱신한다.
