## PC 초기화와 배포 결정

학생 PC는 재부팅하면 작업이 사라질 수 있다. **학생 개인 GitHub·commit·push·Git 이름/이메일 입력을 필수로 만들지 않는다.** GitHub는 강사 측 원본·버전·배포 관리에 쓴다. 학생이 전체 저장소나 여러 회차를 한꺼번에 받을 필요는 없다.

각 실습 패키지는 독립 시작본이다. 연결 실습에는 앞 단계의 완성 상태를 제공하고 이번 요구를 구현·변경하게 한다. 앞 학생 결과를 가져오는 것은 선택이며 다음 실습 진입 조건이 아니다. 이전 기능 변경 과제라면 작동하는 이전 기능이 출발점이므로 모든 과제를 빈칸 채우기로 만들지 않는다. 이번 과제의 강사 정답·solution은 학생 폴더 밖에 둔다. 개인 결과를 보관하려는 학생에게는 별도 내보내기 경로를 안내하되 개인 Git을 강제하지 않는다.

승인된 시험 방향은 **PC의 ‘실습 시작’ 도구 → 과정/회차/실습 선택 → 해당 판본 다운로드·압축 해제 → VS Code에서 정확한 폴더와 가이드 열기**다. 학생의 명령어 입력·경로 지정·Git 설정을 기본 동선에서 없앤다. 구체 구현·다운로드 주소·설치 위치는 새 세션에서 결정하고 시험한다. GitHub의 버전 고정 패키지 배포를 우선 검토하며 아직 Release 게시·런처 설치를 완료했다고 쓰지 않는다.

Notion 일반 링크를 누르는 것만으로 PC 명령이 자동 실행되지는 않는다. 로컬 시작 도구가 실제 다운로드와 VS Code 실행을 맡고, Notion/HTML 가이드는 진입 안내와 자료 링크를 제공한다. `code -n "<폴더>"` 같은 명령은 구현 내부 후보이며 학생에게 입력시키는 확정 절차가 아니다. 브라우저 버튼 직접 연동은 별도 연결 장치·확인이 필요하므로 이미 된 기능처럼 약속하지 않는다.

시제품 판정 조건:

1. 선택한 실습만 받아 정확한 판본·시작 파일·가이드를 연다. 키·개인정보·강사 정답을 포함하지 않는다.
2. 같은 실습을 다시 열 때 학생 수정 파일을 덮어쓰지 않는다. 새로 시작은 별도 폴더를 만든다.
3. 다운로드 실패·VS Code 미설치/명령 미등록을 설명하고 재시도와 수동 ZIP 대안을 제공한다.
4. 초기화된 PC에서 재다운로드로 시작할 수 있다. 학생 수정 결과 자동 복구를 약속하지 않는다.
5. 학교 기본 이미지에 시작 도구가 남는지 또는 복구 경로가 있는지 확인한다. 경로·쓰기 권한·네트워크·보안 경고·VS Code 폴더 신뢰 확인을 실제 환경에서 기록한다. 아직 미확인이다.
6. 코드 다운로드와 Docker/DB·AI 로그인·키 준비를 구별한다. 기존 포털 DB에 랩 데이터를 넣지 않는다.
