# Claude 두 세션 분담 — C65

C68의 기본 미사용·현장 가능 시 선택 조건은 [공통 기준](2_기준.md#오프라인-notion-선택-실습--c68)이 정본이다. [최신 결정과 세션 동기화](2_기준.md#최신-결정의-우선-적용과-세션-간-동기화)를 함께 적용한다. 온라인은 유지하며 개별 산출물의 적용 완료는 별도 검증한다.

C67 최신 적용: [최상위 학습 목표](1_목적과_방향.md)와 [전체 편성 재검토](근거/2026-10-27_VSCode랩_최종흐름.md)를 먼저 읽는다. 온톨로지는 설계부터 문서 인제스천·검토·적재·조회까지 직접 구축, 에이전트는 서로 다른 활용과 구현·검증 경험이 목표다. Notion 한 사례에 한정하지 않는다. 포털 제한은 독립 VS Code의 외부 MCP·자기 자료 사용을 금지하지 않는다. Excel·기준·인계는 개정했으며 실제 랩·덱·대본·가이드·영상은 후속 반영 대상이다. 최신 게시 판본은 전체 편성 재검토의 게시 절을 따른다.

사용자가 직접 별도 세션을 연다. 이 문서는 작업 범위와 서로 읽을 인계를 정한 것이며, 두 세션이 실제 실행 중이라고 확인한 기록은 아니다. 시작한 세션은 자신의 인계 맨 위에 시작 시각·현재 커밋·작업 대상을 남긴다.

## 공통으로 지킬 경계

- **공통1회차 유지, 실전반은8회차다.** ‘모든 반11회차’를 새로 만드는 것이 아니다. 이론 전 범위 품질을 검토하되 실전반2~8은 별도 압축·응용 구조가 핵심이다. 80장은 예시다.
- A는 실습 폴더·실습 대본·가이드·촬영 도구를 수정하지 않는다. B는 이론 폴더·이론 대본·PPTX·제작용/구성을 수정하지 않는다. 교재 실습 간지/참조 장 번호는 B가 변경 요구를 남기고 A가 반영한다.
- 공통 기준·실라버스·포털 시스템·Notion은 두 세션의 수정 대상이 아니다. 같은 현황/대조표/인계 파일을 동시에 편집하지 않는다. 각자 전용 인계와 작업별 근거만 갱신한다. 공통 문서 반영이 필요하면 전용 인계에 대상 문장·제안·근거를 남긴다.
- 같은 체크아웃에서 `git add .`, 일괄 되돌리기·reset·clean·stash를 하지 않는다. 커밋은 자신의 경로만 명시하고 상대 staged 변경이 있으면 임의로 포함/해제하지 않는다. 동시 Git 쓰기는 기다린다. 별도 체크아웃이어도 원격 갱신을 확인하고 상대 변경을 덮어쓰지 않는다.
- 한 세션의 별도 환경·네이티브 VS Code·AI 모델 성공을 다른 세션도 확인한 것으로 기록하지 않는다. `.evidence`와 촬영 원본은 clone에 없으므로 실제 파일 존재와 게시 판본을 확인한다.

## 서로 전달할 것과 순서

1. **A**는2·3회차 학습 개념·용어·전후 연결에서 확정/변경 중인 부분을 먼저 남긴다. **B**는 각 랩의 목표·입력·학생 구현 범위·완료 조건과 제공 시작본 판본을 먼저 남긴다. 서로의 기록을 읽고 같은 개념과 요구를 사용한다.
2. A가 전체 교재를 끝낼 때까지 B의 랩 보강을 멈추지 않는다. B도 랩 초안의 실행 결과를 확정처럼 넘기지 않는다. 녹음/최종 영상에서 직접 언급하는 개념·결과만 안정된 상대 판본과 대조한다. 장 번호·날짜에 의존하는 낭독은 피한다.
3. B는 두 반2회차에서 **랩→실습 대본→리허설→영상→가이드→HTML/ZIP→다운로드·실행·저장 확인**을 닫고3회차로 이어 간다. 랩·영상만 만들고 가이드를 후속으로 빠뜨리지 않는다.
4. A는 실제로 달라진 내용·순서·장 번호·확정 판본을 남긴다. B는 새 시작본·영상·가이드·ZIP 링크와 검증을 남긴다. 상대가 전달한 링크·해시·상태를 다음 작업 시작 시 읽는다. 서로의 완료 상태를 대신 확정하지 않는다.
5. 후속 통합 담당자가 두 인계의 일치 여부를 보고 공통 현황·Notion을 갱신한다. 자동 세션 메시지는 보내지 않는다. 문서에 이미 답이 있는 사항은 사용자에게 되묻지 않는다.
