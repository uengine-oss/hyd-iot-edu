## 1. 배경과 목표

- 수혜자는 경남대 피지컬AI 사관학교 통합반 · 실전반 온라인 학생이다. 이론 영상(덱 장 그림 + 강사 복제 음성 + 자막)과 강사가 직접 찍는 실습 영상으로 수업을 따라온다.
- 이론 영상 완료 판정(사용자 원문 요지): 「싱크가 최우선」, 「끊김 없이」, 「대본대로」. 시간은 「알아서 줄든 늘든 상관없다」. 사용자가 전부 들어 보지 않아도 되게 검사로 막는다.
- 대본 수정 판정(원문): 「내용이 잘못된 건가 의도가 잘못된 거만 수정」, 「이미 이 대본은 윤문까지 다 한 거니까」. 학생이 「어디를 말하는 거지?」 하고 놓칠 곳을 잡는다.

## 2. 확정된 방향 — 바꾸지 마라

1. **두 과정 기준**(정본 `2_기준.md` 「두 과정의 공통 범위와 차이」): 교재 · 모든 랩(VS Code 포함)은 한 벌이고 난이도는 실전반. 도구 실습(포털 · Notion · arrows.app) 대본은 공통. VS Code 랩 대본만 과정별(통합반은 더 풀어서, 실전반은 판단 근거 · 검증 위주). 이론 대본은 실라버스 배정에 따라 과정별, 1회차만 공통. — 왜: 「다르게 하면 일을 2번 해야 되니까」, 「실습을 어렵게 하면 할수록 좋거든 실전반에 맞게 … 장난감 수준은 아닌 상태에서」.
2. **실전반 1회차 = 통합반 1회차**(이론 대본 · 실습 대본 · 랩 · ZIP, 과정 이름만 다름). — 왜: 「1회차는 다 맞추셈」. 낭독 시간 차이(99.5분 대 99.8분)가 아니라 옛 차이안 시절 문장이 남은 것이었다.
3. **대본 수정 범위**: 화면에 없는 위치 · 모양을 가리키는 말, 화면과 다른 내용, 실습 목적을 비튼 안내(「자료를 내려받고」 「파일을 저장하고 다시 열어」 「첫 기록」), 한 장 안의 겹친 예고 · 시점 모순만 고친다. 문체 윤문은 하지 않는다 — **확정본(1회차)에 한한다.** 2회차처럼 아직 확정이 아닌 회차는 윤문에서 놓친 곳도 함께 고친다(「윤문까지 꼼꼼하게 … 놓친 부분 없는지」, 전체 재작성은 아님). 고칠 곳은 **전 · 후를 보여 승인받은 뒤** 반영한다. 같은 덱을 쓰는 다른 과정 대본도 같은 문장을 맞춘다. — 왜: 사용자 지시(대응표 #24 · #30 · #36).
4. **음성 · 쉼 값**: 목소리 이 계정의 「안치윤」 `--voice tlxL9ilynpbOVf9sZXKh`(도구 기본값은 옛 계정 음성이라 반드시 지정), 모델 eleven_v4, 쉼 `--pause-short 0.15 --pause-mid 0.45 --pause-long 0.8 --pause-question 0.5 --pause-para 0.4 --gap 1.2`. 쉼 자리(0~3)는 세션이 문장을 읽고 채운다. 시간을 맞추려고 쉼을 늘리지 않는다(2_기준 39번). — 왜: 사용자 확정 값.
5. **다른 PC 작업**: develop은 문서 · 대본 · 도구, `other-pc`는 develop + 영상 · 음성 · 자막 · 시간표. 다른 PC에서는 `other-pc`를 받아 작업하고, 문서 · 대본 수정은 develop에 커밋한 뒤 other-pc로 병합한다. — 왜: 「차라리 브랜치를 새로 만들고요 다른 PC 전용작업」.

## 3. 절대 규칙 — 어기면 산출물이 무효다

- **키(ELEVENLABS_API_KEY 등)를 어느 브랜치 · 파일에도 커밋하지 않는다.** 저장소는 공개(public)다. 키는 클라우드면 환경 설정의 환경변수, 로컬이면 커밋하지 않는 `.env`. 사용자가 「키 담긴 env 파일을 올려 달라」고 했으나 공개 저장소라 거절했다(대응표 #65).
- **맑은 고딕 글꼴 파일(MALGUN.TTF 등)을 저장소에 올리지 않는다**(마이크로소프트 라이선스). 영상 장 그림에 필요하므로 새 환경에서 사용자에게 받아 `/usr/share/fonts/truetype/malgun/`에 두고 `fc-cache -f`. 다른 글꼴로 대신 만들지 않는다.
- **승인 전에 대본 · 덱을 고치지 않는다.** 점검 결과는 전 · 후로 보여 준다.
- **음성을 뽑기 전에 대본 화면 대조를 먼저 한다.** 뽑은 뒤 고치면 그 장 음성을 다시 산다(01편에서 254 · 168 크레딧을 버렸다).
- **영상마다 검사 두 개를 돌리고 결과를 보고한다**: `python3 제작용/기존제작/tools/video/검사/말머리_잘림.py <영상>` → 「앞이 말소리인 자리 0」, `python3 제작용/기존제작/tools/video/검사/장넘김_싱크.py <영상> <시간표.md>` → 「못 맞춘 기대 0 · 기대 밖 바뀜 0」. 소리 품질(발음 · 억양)은 기계로 못 잰다고 보고에 적는다.
- `제작용/온라인/labs/online/practical-day01/`의 옛 생성 스크립트를 돌리지 않는다(지운 실전반 1회차 옛 랩이 되살아난다).
- 커밋은 경로를 지정한다(`git add .` 금지). 덱 원고 MD는 지금 빌드 도구로 다시 빌드하면 47장 「메시지가 두 문장」 규칙에 걸려 멈춘다. 덱 문구 한두 곳은 배포된 PPTX의 그 런만 python-pptx로 바꾸고 원고 MD도 같은 문구로 맞춘다(1일차 71장에서 한 방식).

## 5. 폐기된 판단 — 되살리지 마라

- 1회차 실전반만 다른 대본 · 랩(「1회차 두 과정 차이안」) — 「1회차는 다 맞추셈」으로 폐기. `제작용/구성/01회차_두과정_차이안.md`에 폐기 표시.
- 「과정 차이는 VS Code 랩에만, 도구 실습 랩은 공통」의 중간안, 「랩 과정별 + 대본 공통」안 — 최종은 §2-1.
- 확정본(1회차) 대본 전반 윤문 — 하지 않는다. 지적이 없는 곳의 문장 다듬기 제안은 보고하지 않는다. (2회차 이후 미확정 회차는 §2-3대로 윤문 누락도 본다.)
- 1회차 실습1(Notion) · 실습2(환경 · 포털) 대본을 새로 쓰자는 제안 — 「애초에 실습은 여기서 할 게 아니잖아.. 우리는 이론만 할거임」.
- 대본을 고칠 때 발표자 노트 · 실습 발췌 · ZIP을 함께 맞추는 일 — 「발표자 노트 이런 건 필요 없는데」. 영상은 대본 파일로 만들므로 노트는 그대로 둔다(1회차 노트는 1일차 수정 전 문장, 실전반 1회차 노트는 폐기된 차이안 문장이 남아 있음 — 알고 둔다).
