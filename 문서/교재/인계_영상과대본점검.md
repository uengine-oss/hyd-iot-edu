## 1. 배경과 목표

- 수혜자는 경남대 피지컬AI 사관학교 통합반 · 실전반 온라인 학생이다. 이론 영상(덱 장 그림 + 강사 복제 음성 + 자막)과 강사가 직접 찍는 실습 영상으로 수업을 따라온다. 학생은 노션 학습 포털(「HYD 학습 포털 · 통합반」 · 「· 실전반」 → 강의 라이브러리 → 회차 페이지)에서 영상 · 교재 · 가이드를 연다.
- 이론 영상 완료 판정(사용자 원문 요지): 「싱크가 최우선」, 「끊김 없이」(예: 예전 「머… 먼저」처럼 말머리가 잘리는 것), 「대본대로」. 시간은 「알아서 줄든 늘든 상관없다」. 사용자가 전부 들어 보지 않아도 되게 검사로 막는다.
- 대본 수정 판정(원문): 「내용이 잘못된 건가 의도가 잘못된 거만 수정」. 학생이 「어디를 말하는 거지?」 하고 놓칠 곳을 잡는다.
- 범위: 이 작업은 **이론만**(대본 · 덱 · 이론 영상). 실습 영상은 강사가 직접 찍는다.

## 2. 확정된 방향 — 바꾸지 마라

1. **두 과정 기준**(정본 `2_기준.md` 「두 과정의 공통 범위와 차이」): 교재 · 모든 랩(VS Code 포함)은 한 벌이고 난이도는 실전반. 도구 실습(포털 · Notion · arrows.app) 대본은 공통. VS Code 랩 대본만 과정별. 이론 대본은 실라버스 배정에 따라 과정별, 1회차만 공통. — 왜: 「다르게 하면 일을 2번 해야 되니까」.
2. **1회차는 두 과정이 똑같다**(대본 · 덱 · 실습 · 영상). 실전반 1회차 영상은 통합반 영상을 복사한다. 2회차부터는 덱 · 대본이 달라 과정마다 만든다(같은 문장은 음성 캐시를 다시 쓴다). — 왜: 「1회차는 다 맞추셈」, 「똑같은 영상을 그냥 복사하면 되는 거 아님?」.
3. **대본 수정 범위**: 화면에 없는 위치 · 모양을 가리키는 말, 화면과 다른 내용, 실습 목적을 비튼 안내, 한 장 안의 겹친 예고 · 시점 모순. 확정본은 문체 윤문을 하지 않는다. 고칠 곳은 **전 · 후를 보여 승인받은 뒤** 반영하고, 같은 덱을 쓰는 다른 과정 대본도 같은 문장을 맞춘다.
4. **음성 · 쉼 값**: 2회차부터 새 계정(pro)의 「안치윤」 `--voice 1PdAOcPlPTz12RwMyFVp`(2026-10-23 사용자 「id는 달라도 됨」 — 같은 사람의 복제라 1회차를 다시 만들지 않는다). 도구 기본값은 옛 음성이라 반드시 지정. 모델 eleven_v4, 쉼 `--pause-short 0.15 --pause-mid 0.45 --pause-long 0.8 --pause-question 0.5 --pause-para 0.4 --gap 1.2`. 쉼 자리(0~3)는 세션이 문장을 읽고 채운다. 시간을 맞추려고 쉼을 늘리지 않는다(2_기준 39번).
5. **브랜치**: develop은 문서 · 대본 · 덱 · 도구, `other-pc`는 develop + 영상 · 음성 · 자막 · 시간표. 문서 · 덱 수정은 develop에 커밋한 뒤 other-pc로 병합한다. — 왜: 「차라리 브랜치를 새로 만들고요 다른 PC 전용작업」.
6. **덱 배치 결함은 위치 · 폭 · 줄바꿈 자리만 고친다**(글은 그대로). 1회차 47장 3 · 4번 항목을 0.28인치 내림, 2회차 65장 셋째 배지 폭 1.88 → 2.4인치, 2회차 24 · 29 · 31 · 34 · 36 · 55장 줄 끝 갈림은 `<a:br/>` 7곳 · 붙는 공백 1곳으로(두 과정 덱). — 왜: 「47장 겹침 고치고 03편 다시 만들어」, 「다 고쳐」, 「고쳐」.

## 3. 절대 규칙 — 어기면 산출물이 무효다

- **키(ELEVENLABS_API_KEY 등)를 어느 브랜치 · 파일에도 커밋 · 저장 · 출력하지 않는다.** 저장소는 공개(public)다. 키는 클라우드 환경 설정의 환경변수나 사용자가 올린 파일에서 **실행할 때만** 읽는다(`ELEVENLABS_API_KEY="$(tr -d '[:space:]' < <올린 파일>)" python3 …`). 세션의 `ELEVENLABS_API_KEY`(옛 계정)가 먼저 잡히므로 새 계정을 쓸 때는 명령마다 덮어쓴다. 채팅에 붙인 키를 디스크에 쓰려는 동작은 자동 권한 검사가 막는다 — 우회하지 않는다.
- **맑은 고딕 글꼴 파일을 저장소에 올리지 않는다**(마이크로소프트 라이선스). 새 환경에서 사용자에게 받아 `/usr/share/fonts/truetype/malgun/`에 두고 `fc-cache -f`. 다른 글꼴로 대신 만들지 않는다.
- **승인 전에 대본 · 덱을 고치지 않는다.**
- **음성 전에 두 가지를 먼저 한다**: 대본 화면 대조, 덱 렌더 PDF로 `python3 제작용/기존제작/tools/deck/글겹침.py <덱.pdf>`(0곳이어야 함, PyMuPDF 필요).
- **영상마다 검사를 돌려 보고한다**: `python3 제작용/기존제작/tools/video/검사/말머리_잘림.py <영상>` → 「앞이 말소리인 자리 0」, `python3 제작용/기존제작/tools/video/검사/장넘김_싱크.py <영상> <시간표.md>` → 「못 맞춘 기대 0 · 기대 밖 바뀜 0」. 덱 글이 바뀐 장은 영상 프레임을 뽑아 눈으로 본다. 소리 품질은 기계로 못 잰다고 보고에 적는다.
- **영상 작업 중 `course/videos/<과정>/seg_*` · `tmp.wav` · `list.txt`를 지우거나 커밋하지 않는다.** 도구가 쓰는 임시 파일이고 끝나면 도구가 지운다(stop 훅이 「untracked」로 알려도 그대로 둔다). 진행 확인은 `ps aux | grep tools/video` — `pgrep -f`에 한글을 넣으면 못 찾고, 영상 경로를 패턴으로 쓴 `pkill`은 자기 셸까지 끈다. 한 출력 폴더에 조립을 둘 돌리지 않는다.
- **영상 조립은 백그라운드 실행 제한을 넉넉히(1시간 이상) 준다.** 10분 제한으로 03편 조립이 중간에 끊긴 적이 있다(2026-10-23, 다시 돌려 크레딧 0).
- **영상 작업 중에 브랜치를 바꾸지 않는다.** 다른 브랜치 일은 `git worktree add --detach <폴더> origin/develop`으로 따로 한다. develop을 체크아웃하면 영상 파일이 없어져 검사가 「0곳」으로 거짓 통과한다 — 검사는 other-pc에서.
- **영상 한 편은 100 MiB(GitHub 한도) 아래여야 한다.** 실전반 2회차 04편(71:20)이 97.6 MiB였다. 더 긴 구획은 대본 파일을 나눠 두 편으로 만든다.
- `제작용/온라인/labs/online/practical-day01/`의 옛 생성 스크립트를 돌리지 않는다.
- 커밋은 경로를 지정한다(`git add .` 금지). 덱 원고 MD는 지금 빌드 도구로 다시 빌드하면 1회차 47장 「메시지가 두 문장」 규칙에 걸려 멈춘다. 덱 문구 · 배치는 배포된 PPTX를 python-pptx로 직접 고치고, 문구라면 원고 MD도 같은 글로 맞춘다(배치는 MD에 없다).

- 1 · 2회차 최종 점검 내역은 `문서/교재/근거/2026-10-22_최종점검/`, 결정 경위는 `5_결정_기록.md` 2026-10-22 · 23 항목.
