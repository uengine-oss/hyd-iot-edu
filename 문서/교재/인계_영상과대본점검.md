## 1. 배경과 목표

- 수혜자는 경남대 피지컬AI 사관학교 통합반 · 실전반 온라인 학생이다. 이론 영상(덱 장 그림 + 강사 복제 음성 + 자막)과 강사가 직접 찍는 실습 영상으로 수업을 따라온다.
- 이론 영상 완료 판정(사용자 원문 요지): 「싱크가 최우선」, 「끊김 없이」(예: 예전 「머… 먼저」처럼 말머리가 잘리는 것), 「대본대로」. 시간은 「알아서 줄든 늘든 상관없다」. 사용자가 전부 들어 보지 않아도 되게 검사로 막는다.
- 대본 수정 판정(원문): 「내용이 잘못된 건가 의도가 잘못된 거만 수정」. 학생이 「어디를 말하는 거지?」 하고 놓칠 곳을 잡는다.
- 범위: 이 작업은 **이론만**(대본 · 덱 · 이론 영상). 실습 영상은 강사가 직접 찍는다.

## 2. 확정된 방향 — 바꾸지 마라

1. **두 과정 기준**(정본 `2_기준.md` 「두 과정의 공통 범위와 차이」): 교재 · 모든 랩(VS Code 포함)은 한 벌이고 난이도는 실전반. 도구 실습(포털 · Notion · arrows.app) 대본은 공통. VS Code 랩 대본만 과정별. 이론 대본은 실라버스 배정에 따라 과정별, 1회차만 공통. — 왜: 「다르게 하면 일을 2번 해야 되니까」.
2. **1회차는 두 과정이 똑같다**(대본 · 덱 · 실습 · 영상). 실전반 1회차 영상은 따로 만들지 않고 통합반 영상을 복사한다. — 왜: 「1회차는 다 맞추셈」, 「똑같은 영상을 그냥 복사하면 되는 거 아님?」.
3. **대본 수정 범위**: 화면에 없는 위치 · 모양을 가리키는 말, 화면과 다른 내용, 실습 목적을 비튼 안내(「자료를 내려받고」 「파일을 저장하고 다시 열어」 「첫 기록」), 한 장 안의 겹친 예고 · 시점 모순. 확정본은 문체 윤문을 하지 않는다. 고칠 곳은 **전 · 후를 보여 승인받은 뒤** 반영하고, 같은 덱을 쓰는 다른 과정 대본도 같은 문장을 맞춘다.
4. **음성 · 쉼 값**: 목소리 이 계정의 「안치윤」 `--voice tlxL9ilynpbOVf9sZXKh`(도구 기본값은 옛 계정 음성이라 반드시 지정), 모델 eleven_v4, 쉼 `--pause-short 0.15 --pause-mid 0.45 --pause-long 0.8 --pause-question 0.5 --pause-para 0.4 --gap 1.2`. 쉼 자리(0~3)는 세션이 문장을 읽고 채운다. 시간을 맞추려고 쉼을 늘리지 않는다(2_기준 39번).
5. **브랜치**: develop은 문서 · 대본 · 덱 · 도구, `other-pc`는 develop + 영상 · 음성 · 자막 · 시간표. 문서 · 덱 수정은 develop에 커밋한 뒤 other-pc로 병합한다. — 왜: 「차라리 브랜치를 새로 만들고요 다른 PC 전용작업」.
7. **발표자 노트는 대본과 같게 맞춘다**(기준_이론대본 87번). 노트는 강사가 그 장에서 할 말 전체이고 화면에서 짚는 위치도 그 안에 있다. 영상은 대본 파일로 만들어 노트와 무관하다. — 왜: 2026-10-23 사용자 「노트도 수정이 필요하면 해도 되는데」, 「원래 의미는 어디를 설명하는지 아니였나요」(앞서 「노트 이런 건 필요 없는데」를 뒤집음).
6. **덱 배치 결함은 위치 · 폭만 고친다**(글은 그대로). 1회차 47장 3 · 4번 항목을 0.28인치 내림, 2회차 65장 셋째 배지 폭 1.88 → 2.4인치(두 과정 덱). — 왜: 「47장 겹침 고치고 03편 다시 만들어」, 「다 고쳐」.

## 3. 절대 규칙 — 어기면 산출물이 무효다

- **키(ELEVENLABS_API_KEY 등)를 어느 브랜치 · 파일에도 커밋하지 않는다.** 저장소는 공개(public)다. 키는 클라우드면 환경 설정의 환경변수, 로컬이면 커밋하지 않는 `.env`(이름만 있는 틀은 `.env.example`). 세션 키를 파일로 꺼내는 동작은 자동 권한 검사가 막는다 — 우회하지 않는다.
- **맑은 고딕 글꼴 파일을 저장소에 올리지 않는다**(마이크로소프트 라이선스). 새 환경에서 사용자에게 받아 `/usr/share/fonts/truetype/malgun/`에 두고 `fc-cache -f`. 다른 글꼴로 대신 만들지 않는다.
- **승인 전에 대본 · 덱을 고치지 않는다.**
- **음성 전에 두 가지를 먼저 한다**: 대본 화면 대조, 덱 렌더 PDF로 `python3 제작용/기존제작/tools/deck/글겹침.py <덱.pdf>`(0곳이어야 함, PyMuPDF 필요).
- **영상마다 검사 두 개를 돌려 보고한다**: `python3 제작용/기존제작/tools/video/검사/말머리_잘림.py <영상>` → 「앞이 말소리인 자리 0」, `python3 제작용/기존제작/tools/video/검사/장넘김_싱크.py <영상> <시간표.md>` → 「못 맞춘 기대 0 · 기대 밖 바뀜 0」. 덱 글이 바뀐 장은 영상 프레임을 뽑아 눈으로 본다. 소리 품질은 기계로 못 잰다고 보고에 적는다.
- **영상 작업 중 `course/videos/<과정>/seg_*` · `tmp.wav` · `list.txt`를 지우지 않는다.** 도구가 쓰는 임시 파일이고 끝나면 도구가 지운다(2026-10-22 지웠다가 02편 작업이 깨졌다). 진행 확인은 `ps aux`로 한다 — `pgrep -f`에 한글을 넣으면 못 찾고, 영상 경로를 패턴으로 쓴 `pkill`은 자기 셸까지 끈다.
- **영상 작업 중에 브랜치를 바꾸지 않는다.** 다른 브랜치 일은 `git worktree add <폴더> develop`으로 따로 한다. develop을 체크아웃하면 영상 파일이 없어져 검사가 「0곳」으로 거짓 통과한다 — 검사는 other-pc에서.
- `제작용/온라인/labs/online/practical-day01/`의 옛 생성 스크립트를 돌리지 않는다.
- 커밋은 경로를 지정한다(`git add .` 금지). 덱 원고 MD는 지금 빌드 도구로 다시 빌드하면 1회차 47장 「메시지가 두 문장」 규칙에 걸려 멈춘다. 덱 문구 · 배치는 배포된 PPTX를 python-pptx로 직접 고치고, 문구라면 원고 MD도 같은 글로 맞춘다(배치는 MD에 없다).
