# 교재 공통 기준과 기준 안내

## 최신 결정의 우선 적용과 세션 간 동기화

교재 제작의 해석 순서는 **현재 사용자의 명시적 지시 → 이 문서에 반영한 최신 결정(C66·C67·C68)과 최종 실라버스 → 작업별 상세 기준 → 과거 인계·샘플**이다. 최신 결정과 Excel이 어긋나면 임의로 양쪽을 섞지 말고 해당 셀·결정 ID를 기록하여 승인된 수정 범위에서 맞춘다. 이 우선순위는 포털 기능이나 작업 권한을 확대하지 않는다.

| 반드시 이어받을 결정 | 담당 정본과 적용 범위 |
|---|---|
| 온톨로지를 직접 구축하고 다양한 에이전트 활용을 구현·검증한다(C67) | 아래 「최상위 학습 목표」와 [목적과 방향](1_목적과_방향.md). Notion 한 사례나 이름만 바꾼 반복으로 축소하지 않는다. |
| 포털 제한과 독립 VS Code 제작을 구분한다(C66) | 아래 「두 과정의 공통 범위와 차이」와 [회차별 제작 요구](근거/2026-10-27_VSCode랩_최종흐름.md). 포털은 현 지원 범위, VS Code는 외부 MCP·자체 도구·자기 자료 활용을 허용한다. |
| 학생이 핵심 로직을 구현하고 결과를 판단한다(C65·C66) | [랩 기준](기준_실습랩.md)의 제공 경계·독립 시작본. 환경·자료·가드레일과 이번 과제 정답을 구별한다. |
| 과정별 차이와 공통 원본을 함께 보존한다(C57·C63·C67) | 아래 과정별 기준. 온라인1과 촬영된 Cypher 공통 영상은 유지하고 VS Code는 구현 요구·결과·검증에 차이를 둔다. |
| 오프라인 Notion은 기본 미사용, 현장 가능 시 선택한다(C68) | 바로 아래 C68 조항 및 최종 Excel. 온라인 Notion 실습을 삭제하거나 오프라인 전면 금지로 되돌리지 않는다. |

새 세션은 이 절 → 해당 작업 기준 → [세션 분담](세션분담_교재와실습_20261027.md) → 자기/상대 인계의 최신 판본을 확인한다. 공통 기준·Excel·공통 현황·Notion은 통합 담당 범위, A는 이론, B는 랩·실습 대본·가이드·촬영 범위다. 별도 사용자 요청이 없으면 상대 담당 파일을 직접 수정하지 않고 자기 인계에 필요한 변경과 근거를 남긴다.

시작과 커밋·푸시 직전에 실제 원격 변경을 확인한다. 상대 변경은 보존하여 병합하며 rebase·강제 push·일괄 stage/되돌리기를 하지 않는다. 공통 문서 수정은 한 담당자가 반영하고 결정 ID·변경 파일·검증·커밋·게시 상태·남은 제작을 기록한다. 문서 동기화는 기존 랩·교재·영상의 개정 완료가 아니다. 실행 중인 다른 세션이 이 변경을 이미 읽었다고 가정하지 않는다.

## 오프라인 Notion 선택 실습 — C68

오프라인 기본 진행은 Notion 없이 한다. 현장에서 Notion 설치·접속·MCP 연결과 자기 자료 준비가 가능하면 강사가 해당 교시 안에서 선택 실습으로 진행한다. 통합 오프라인6은 조회 도구 실습 대신 자기 노트 퀴즈(문항 생성→답변→채점·해설·원문 근거 확인)를 선택할 수 있다. 실전 오프라인5는 제공 파일 대신 자기 Notion 기록을 후속 협의 안건에 활용할 수 있다. 불가능하면 기본 파일·Git·시간 MCP 실습을 계속한다. 온라인 Notion 실습, 시간·날짜·강사 배정은 유지한다.


## 최상위 학습 목표 — C67

[목적과 방향](1_목적과_방향.md)의 도달 목표를 이론·랩·대본·가이드의 판단 기준으로 삼는다. 온톨로지는 질문 정의→설계→그래프 구현→절차·조건 연결→문서 인제스천→검토·적재·근거 조회까지 직접 구축하는 과정이다. 에이전트는 그 지식도 활용하며 목적·자료·도구·결과가 다른 여러 활용을 구현하고 검증하는 과정이다. Notion은 한 사례다. 이름·자료만 바꾼 반복이나 정답 실행으로 끝내지 않는다. 실전반도 온톨로지의 구축 과정을 생략하지 않고 활용 결과와 판단에 차이를 둔다. [전체 편성 재검토와 회차 대응](근거/2026-10-27_VSCode랩_최종흐름.md)을 따른다.

## 2026-10-27 최종 적용 실습 확정 — 교대 인수인계

마지막 적용 실습은 **개인 자유 주제가 아니라 교대 인수인계 한 시나리오**다. 이 결정은 아래 이전 개인 제작·임의 개인 자료·로컬에서만 완료하는 경계보다 우선한다. 통합온라인11·실전온라인8, 통합오프라인9~10·실전오프라인8~9에 반영한다. 이 시나리오 결정 당시 시간·날짜·강사 배정과 ABC는 유지했다. 현재 편성·강사 배정은 아래 운영 기준과 최신 실라버스를 따른다.

강사 제공 설비 점검·이상 확인 보충 매뉴얼을 기존 제조 스키마로 추출·원문 검토·추가 적재하고, 설비·정비·ERP 조회로 미완료/주의/기록 불일치를 정리하는 에이전트·스킬을 만든다. bpmn.io의 조회→인계안→인계자 검토→인수자 확인/보완→완료 흐름을 포털의 별도 정의·시작 폼·역할·작업에 명시적으로 연결해 실행한다. 임의 학생 코드를 자동 연결하지 않는다. 인계 확인은 정비 완료·실제 설비 조치·발주가 아니다.

포털과 마지막 교대의 포털 실행에서는 강사 승인 문서·판본·수업 행동만 허용한다. 동일 조건 추출 재사용은 표시하고 사람의 검토·적재는 유지한다. 마지막 실습에서도 임의 문서/도구/무제한 AI 실행을 개방하지 않는다. 권한·비용·모델의 정본은 [시스템 기준](../시스템/2_기준.md)의 2026-10-27 절이다.

현재 제공 문서 캐시와 로컬 수업 실행 경로를 연결하고, 실제 교대 초안·인계자 검토·인수자 보완·인수 확인 한 건을 완료했다. 통합반11/실전반8 교대 시작 ZIP·가이드와 온라인 이론 PPTX·대본은 현재 교대 시나리오에 맞췄다. 새 실습 대본은 작성됐으나 학생별 전 과정 실행과 촬영은 미확인이고, 오프라인 파생 자료도 별도 확인이 필요하다. 전체 수업·새 교실 PC 검증은 아직 완료되지 않았다. 범위와 근거는 [시스템 인계](../시스템/6_남은_일.md)의 최신 절을 따른다.

## 기준 읽기와 작업 복원

작업 시작 시 공통 기준과 [작업별 진입점](4_만드는_법.md)의 해당 행에 지정된 상세 기준을 읽는다. 해당 상세 기준 전체와 연결된 적용 조항을 확인하되, 다른 작업의 기준 전문을 매번 함께 재출력하지 않는다. 동일 판본을 읽은 기록이 있는 작업을 요약 후 재개할 때는 공통 기준·작업 상태·변경된 기준을 복원하고, 이미 읽은 동일 판본의 상세 기준은 기록으로 재사용한다. 읽은 기록이 없거나 판본이 달라졌거나 요약으로 적용 근거를 복원할 수 없으면 해당 상세 원문 전체를 읽는다. 미확인 내용을 요약·키워드 검사로 대신하지 않는다. 두 루트의 동일 본문은 해시 일치를 확인해 한 번 읽고 차이가 있으면 차이 전체를 읽는다.

읽은 문서·판본 해시·범위는 현재 작업 상태에 기록한다. 미확인 상세 기준은 반드시 읽는다. 효율은 반복 확인을 줄이는 것이며 회차의 미확인 내용·조건·예외를 생략하는 것이 아니다. 최신 지시는 기존 전체 기준에 추가·정정하며 관련 없는 기존 기준을 폐기하지 않는다.

규칙을 바꾸면 담당 문서만 고치고 결정 기록에 이유를 남긴다. 인계·현황·산출물 목록에는 규칙 전문을 복사하지 않는다. 내용·상태·역사의 구분은 아래 문서 역할을 따른다.

## 최신 제작 범위와 반복 검토 금지

덱·발표자 노트·대본·랩·입력자료·가이드 및 필요한 HTML·ZIP 동기화에 집중한다. 최신 사용자 지시로 PDF 제작·검토는 제외하며, 아래 기존 PDF 관련 절차는 현재 작업에 적용하지 않는다. 기존 PDF는 보존한다.

이미 같은 판본으로 확인·확정한 산출물 내용은 검토 근거를 재사용한다. 변경 부분과 그 앞뒤 연결·영향받은 파생물·미확인 범위만 점검하며, 구체적 결함 없이 같은 검토를 반복하지 않는다. 기준 읽기와 복원은 적용 지침을 확인하는 절차이며 확정 산출물 전체를 다시 검사하라는 뜻이 아니다.

효율은 같은 판본의 확정 근거와 공통 원문을 재사용하고 불필요한 재생성·반복 수정을 줄이는 것이다. 효율을 이유로 미확인 회차를 일부만 읽거나 표본·키워드 검사로 전체 내용 검토를 대신하지 않는다. 해당 회차의 이론·전체 발화·화면·랩·입력자료·가이드를 빠짐없이 대조하고, 수정 후 앞뒤 연결과 영향을 받는 파생물까지 확인한다. 검토 범위표에 확인/근거 재사용/미확인을 구분하고, 누락이 없을 때만 회차를 확정한다. 기준 전독과 산출물 재검토는 구별한다.

최종 GitHub 교재는 `산출물/{통합반,실전반}/{이론,실습}/NN회차`로 정리한다. 현재 온라인 산출물이며 제작 원고·도구·구성 기록은 `제작용/`에 둔다. PDF와 과거 중복 전달 폴더는 활성 산출물에 두지 않는다. 같은 파일의 별도 배포 사본을 만들지 않고 이 위치를 직접 갱신한다.

## 두 과정의 공통 범위와 차이 — 사용자 확정(2026-10-27 갱신)

온라인1회차는 교재·실습·대본 공통이다. 2회차부터 이론은 과정별이며 실전반은 통합반의 대응 회차를 묶어 핵심 개념과 활용·판단을 설명한다. 반복 도입·재요약과 과도한 부연은 줄이되 이해에 필요한 정의·조건·근거를 생략하지 않는다.

포털·Neo4j·ARROWS·bpmn.io·프로세스 실습은 같은 기능·자료·절차를 사용할 수 있다. 같은 실습에서도 통합반은 조작과 원리를 단계적으로 설명하고, 실전반은 기본 조작 설명을 간결하게 하며 활용 목적·선택 이유·결과 해석을 짚는 과정별 대본을 구성한다. 차이가 성립하지 않는 단계는 공통 설명을 재사용한다. 단순 말투 변경이나 억지 응용을 요구하지 않는다. 이미 촬영한 C57 Cypher는 두 과정 공통 영상으로 보존·사용한다. 과정별 설명 차이를 이유로 이를 다시 촬영하지 않는다. 실전반도 통합반과 비슷한 말과 난도로 차근차근 설명하고, 실제 활용 목적과 결과 해석이 필요한 곳에만 차이를 둔다(C63).

VS Code 제작 랩은 같은 코어를 사용하되 구현 요구·활용 결과·완료 기준을 과정별로 둔다. 실전반은 공급 정보 조회, 조치 검토 결과, 작업 확인 카드, 점검 요청 초안, 다음 협의 안건과 해당 기능의 명세·검증을 수행한다. 통합반 과제에 추가 숙제를 붙이거나 빈칸 수로 차이를 만들지 않는다.

실전 응용은 실제 입력·도구·출처를 사용해 활용 가능한 결과를 구현하고 검증하는 것이다. 포털 실습은 현재 지원 기능과 승인 자료 안에서 진행하며 시스템 로직은 변경하지 않는다. 독립 VS Code 랩에서는 외부 MCP·직접 만든 MCP·자기 Notion 기록·다른 문서를 연결하고 응용할 수 있다. 피지컬 AI를 중심으로 학습 퀴즈·회의 후속 업무 등 다양한 활용 경험도 포함한다. 기능 수·용어 난도나 억지 조직 설정으로 차별화하지 않는다. [C66 VS Code 최종 흐름](근거/2026-10-27_VSCode랩_최종흐름.md)의 단계별 확장·출제와 채점·과정별 결과 요구를 따른다.

### 학생 포털과 로컬 제작의 경계

[시스템 기준](../시스템/2_기준.md)의 현재 수업 권한을 따른다. 기본 포털에서는 준비된 A/B/C 실행·자료 조회, 지정 모델·준비 조회 서버 안의 에이전트/스킬 구성과 질문을 사용한다. 준비된 도구의 목록·직접 읽기는 허용하지만 관리·쓰기 설정은 별개다. 일반 BPMN 등록·배포, 임의 도구 서버 추가, 임의 문서 추출을 학생 실습으로 요구하지 않는다. bpmn.io에서 직접 그린 흐름은 기준 흐름·매핑과 비교하고, 포털에서는 이미 등록된 흐름을 실행하여 이력과 대조한다.

마지막 교대 실습은 강사 코드로 허용된 제공 문서 검토·추가 적재, 에이전트·스킬 편집, 제공 교대 BPMN의 표시 이름·배치·세 초안 단계 에이전트 배정·별도 판본 등록을 사용한다. 시작 입력·검토·보완 분기는 유지한다. VS Code 구현과 별도 랩 DB 작업은 포털 운영 기능 변경이나 학생 코드의 자동 연결과 구별한다. 시스템 검증 기록은 해당 판본의 근거이며 새 교실 PC·전체 학생 완주를 보장하지 않는다.

### 오프라인 운영과 온라인 대응

온라인 배정 시간은 편성 기준으로 유지하며 실제 영상 길이에 맞추어 내용을 자르거나 늘리지 않는다. 오프라인은 같은 과정의 온라인 실습 중 학습 가치가 큰 활동을 선별하여 직접 수행한다. 별도 응용 과제를 새로 만드는 운영이 아니다. 최신 C62: 오프라인은50분 수업·10분 휴식×4교시다. 이론이 있는 회차는 첫 교시50분으로 편성하고 온라인 선행학습을 바탕으로 목적·필수 개념·적용 판단을 연결한다. 실행 중심 회차는 실습 안에서 필요한 설명을 한다. 내용 부족을 억지 반복으로 채우지 않는다. 기본 편성은 수업200분+휴식40분이며 강사가 학생 진행에 따라 실제 시간을 조절한다. 10·15분의 행정·다음 회차 준비를 독립 수업으로 늘리지 않는다.

포털 관찰과 반복 조작은 간결하게 하고 직접 설계·구현·결과 확인을 확보한다. 첫날에는 HYD 전체 구조·학습 목표를 설명하고 실제 포털로 경보→판단→승인→조치→결과를 보여준 뒤 관계 모델로 들어간다. 각 회차는 앞 학습→오늘의 목적→학생 수행·결과 확인→다음 회차에서 이 결과를 어떻게 쓸지로 연결한다. 도입·다음 연결을 별도10분 행정 활동으로 편성하지 않는다. 실전반8명은 개별 결과·질문·선택 근거 확인에 활용하며 추가 과제나 자동 시간 단축의 근거로 삼지 않는다. 통합반은 첫 조작 안내·수행·막힘 지원을 확보한다. 첫 오프라인 그래프 실습에는 Cypher 생성·조회·조건·수정·삭제·재조회와 노드 속성 확인을 명시한다. 같은 과정의 온라인·오프라인은 같은 교재를 쓰지만 회차 번호를 일대일로 맞추지 않는다. 마지막 ProcessGPT 시연은 유지한다. 편성 시간과 학생 수행 실측은 구분한다.

## 1. 중심

0-2. **교재 전체의 검토 대상은 통합반·실전반 온라인 두 과정이며, 현재 수행 범위는 위 현재 요청의 단계를 따른다.** 대상과 확정 상태는 맨 위 적용 범위 표를 따른다. 공통 원본과 과정별 배정·대본 차이를 보존하며 실제 브랜치·커밋·미커밋 수정으로 최신 원고를 확인한다. 기준서 정리는 산출물 최종 검증 완료가 아니다.

> **원리와 까닭, 역할과 구조가 줄기다. 전문성 있게 다 알려 준다. 실제로 쓰이는 재료는 그 역할에 「이런 것들이 있다」로만 얹는다.**

0. **까닭: 제품이 바뀌어도 원리와 역할을 이해한 지식은 남는다.** 역할·구조·가치를 줄기로 삼고, 특정 제품의 사용법을 이론의 뼈대로 삼지 않는다. 실제로 가르치는 언어·표준·문법은 제품과 구분한다(16번).
0-1. **판정하는 물음:** 제품을 바꿔도 역할과 원리에 대한 설명이 성립하는가. 다만 수업 주제인 언어·표준·문법의 정확한 이름과 동작을 제품 이름처럼 지우지 않는다(16번).
1. **재료를 하나씩 설명하고 재료의 사용법을 알려 주는 식으로 쓰지 않는다.** 절대 안 된다. 재료를 차례로 소개하는 뼈대에 까닭을 덧붙이는 것도 같은 잘못이다.

3-1. **전문성은 정확한 내용으로 지키고, 어려움은 설명으로 낮춘다.** 화면에는 필요한 정식 용어·정의·근거 있는 값과 관계를 남긴다. 대본은 그것이 필요한 장면, 까닭과 원리를 초심자가 따라올 순서로 풀고 정확한 개념으로 돌아온다. 쉬워 보이려고 이름이나 내용을 흐리지 않고, 전문적으로 보이려고 용어와 예외를 늘리지 않는다. 판정은 학생이 그 용어를 써서 상황과 판단의 까닭을 설명할 수 있는가이다. `근거/이야기_흐름_본보기.txt`는 전개 방식의 참고이며 사실·수치의 근거가 아니다.

## 11. 사실

61. **실행 사실은 실제 관측 근거로만 보고한다.** 교육용 사례·앞으로 수행할 대본·예상 판정 조건은 실제 실행 기록과 구별하여 작성한다. 결과를 지어내지 않고 미확인 실행은 미수행으로 남긴다. 설계 추정·정적 검사·실측을 구분한다.
62. **값·이름·동작은 사실표와 코드의 근거를 확인해 쓴다.** 설정값·관측값·예측값·설계 추정을 구분한다. 뜻과 출처를 설명할 수 없는 값은 소리 내어 읽지 않고 확인 대상으로 남긴다. 수치의 낭독은 98-1번을 따른다.
63. **실라버스 최종본의 행·제목·상세 항목·순서·이론/실습 구분은 고정이다(실전반 이론은 [실전반 기준](실전반_기준.md)대로 큰 틀만 따른다).** 그 안에서 깊이와 충실도를 높인다. 시간은 39~41번 범위에서 유연하게 조율한다. 교재의 표현을 바꾸는 일과 실라버스를 바꾸는 일을 혼동하지 않는다.
64. **설비 시스템은 고치지 않는다.** 교재가 시스템과 다르면 설명을 고친다.
65. **해석의 순위:** 가장 뒤의 사용자 결정 > 실라버스 최종본 > 그 앞의 문서.

## 12. 일하는 방식

66. **최신 사용자 요청에서 승인된 범위를 끝까지 수행한다.** 이번 최종 검증·수정은 이미 요청됐으므로 기준 정리나 수정 제안만 하고 중단하지 않는다. 새로운 범위·실제 실행 권한이 필요한 경우에만 구분해서 확인한다.
66-1. **검토만 요청된 작업과 검토·수정이 함께 요청된 작업을 구별한다.** 이번에는 필요한 수정과 동기화·검증까지 수행한다. 과거의 수정안 대기 절차를 적용하여 다시 승인을 요구하지 않는다.
67. **대표 단원을 덱과 대본으로 함께 확인한 뒤 넓힌다.** 단원 안의 설명이 이어지는지부터 검토하고, 승인된 방향을 나머지 범위에 적용한다. 이미 승인된 범위의 반복 작업마다 다시 승인을 받지는 않는다.
68. **충돌하거나 정하기 어려운 것은 쉬운 말로 물어 사용자가 정한다.** 확정된 최신 결정은 옛 것을 덮고, 확정이 아닌 것은 양쪽을 살려 조율한다.
69. **원본과 파생 산출물의 상태를 맞춘다.** 덱을 고치면 대본·조립 덱·PPTX·배포 묶음·현황에 미치는 영향을 확인하고 허용된 범위에서 함께 갱신한다. 범위 밖이거나 조립 전환을 기다리는 것은 의존성과 갱신 대기를 명시한다. 재생성하지 않은 파일을 최신이라고 보고하지 않는다.
70. **비용이 드는 일은 미리 알린다**(음성 생성, 모델을 많이 부르는 일, 작업자를 여럿 쓰는 일).
71. **작업자를 쓸 때:** fable 모델을 쓰지 않는다. 방향이 정해지는 문서는 작업하는 세션이 직접 읽고, 사실을 적은 문서만 나눠 준다. 작업자는 요약하지 않고 원문과 줄 번호를 가져온다. 합치는 것은 한 사람이 한다.
72. **결과는 열어 볼 수 있는 파일로 건넨다.** 사용자는 claude.ai 링크를 열 수 없으므로 로컬 파일(HTML 등)로 준다.
73. **현재 지시와 역사적 기록을 분리한다.** 현재 문서를 정합하게 갱신하고 예전 지시가 활성 지침으로 남지 않게 한다. 사용자 요청으로 기존 미커밋 수정·다른 회차·검증 근거·.evidence·before.json은 삭제·초기화·덮어쓰기하지 않는다. 과거 문서는 결정 이력으로 보존하고 현재 위치를 연결한다.

## 13. 저장소

74. **위 경로·권한 절의 활성 정본과 확인한 현재 Git 상태를 사용한다.** 두 과정 모두 main에서 작업한다(2026-10-23 사용자 지시로 develop을 main에 합치고 폐기). 통합반의 분리된 HEAD와 보존 태그를 임의로 이동하거나 삭제된 작업 브랜치(develop 포함)를 재생성하지 않는다. 옛 작업 경로로 전환하거나 두 작업 폴더를 합치지 않는다.
75. **최신 사용자 요청으로 허용된 교재 변경만 경로를 지정해 커밋·푸시한다.** 실제 원격 상태를 확인하고 관련 없는 미커밋 수정을 보존한다. 기계적인 pull/rebase/autostash로 현재 작업을 옮기지 않는다. 원격과 충돌하면 확인한 상태에 맞게 처리하며 강제 푸시는 하지 않는다.
76. **공개 저장소에 비밀정보를 올리지 않는다.** 키·개인 연락처·내부 비밀 주소는 어느 브랜치에도 올리지 않는다. 강의 영상·음성·자막은 main에 올리지 않고, 다른 PC 작업용 브랜치 `other-pc`에만 올린다(2026-10-22 사용자 지시. 공개 저장소이므로 그 브랜치도 공개다). 키는 실행 환경의 환경변수로 받는다. 사용자가 명시한 복구 작업 경로는 인계와 재현 링크에 사용한다. 교육용 회의는 개인 신상 대신 역할을 사용한다.
77. **`.env`는 열지 않는다.** 키 파일의 값을 출력하거나 커밋하지 않는다.
