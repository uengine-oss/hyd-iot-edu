# 교재 공통 기준과 기준 안내

## 2026-10-27 최종 적용 실습 확정 — 교대 인수인계

마지막 적용 실습은 **개인 자유 주제가 아니라 교대 인수인계 한 시나리오**다. 이 결정은 아래 이전 개인 제작·임의 개인 자료·로컬에서만 완료하는 경계보다 우선한다. 통합온라인11·실전온라인8, 통합오프라인9~10·실전오프라인8~9에 반영한다. 시간·날짜·강사 배정과 ABC는 유지한다.

강사 제공 설비 점검·이상 확인 보충 매뉴얼을 기존 제조 스키마로 추출·원문 검토·추가 적재하고, 설비·정비·ERP 조회로 미완료/주의/기록 불일치를 정리하는 에이전트·스킬을 만든다. bpmn.io의 조회→인계안→인계자 검토→인수자 확인/보완→완료 흐름을 포털의 별도 정의·시작 폼·역할·작업에 명시적으로 연결해 실행한다. 임의 학생 코드를 자동 연결하지 않는다. 인계 확인은 정비 완료·실제 설비 조치·발주가 아니다.

강사 승인 문서·판본·수업 행동만 허용한다. 동일 조건 추출 재사용은 표시하고 사람의 검토·적재는 유지한다. 마지막 실습에서도 임의 문서/도구/무제한 AI 실행을 개방하지 않는다. 권한·비용·모델의 정본은 [시스템 기준](../시스템/2_기준.md)의 2026-10-27 절이다.

현재는 **편성·문서 동기화 완료, 실제 보충 매뉴얼·에이전트·BPMN·캐시/권한 구현과 완주 검증은 미완료**다. 기존 마지막 회차 PPTX·ZIP·대본·가이드는 이전 판본이며 신규 확정 내용에 맞춰 후속 제작한다. 근거와 구현 순서는 [시스템 인계](../시스템/6_남은_일.md)의 최신 절을 따른다.

## 기준 읽기와 작업 복원

작업 시작 시 공통 기준과 [작업별 진입점](4_만드는_법.md)의 해당 행에 지정된 상세 기준을 읽는다. 해당 상세 기준 전체와 연결된 적용 조항을 확인하되, 다른 작업의 기준 전문을 매번 함께 재출력하지 않는다. 동일 판본을 읽은 기록이 있는 작업을 요약 후 재개할 때는 공통 기준·작업 상태·변경된 기준을 복원하고, 이미 읽은 동일 판본의 상세 기준은 기록으로 재사용한다. 읽은 기록이 없거나 판본이 달라졌거나 요약으로 적용 근거를 복원할 수 없으면 해당 상세 원문 전체를 읽는다. 미확인 내용을 요약·키워드 검사로 대신하지 않는다. 두 루트의 동일 본문은 해시 일치를 확인해 한 번 읽고 차이가 있으면 차이 전체를 읽는다.

읽은 문서·판본 해시·범위는 현재 작업 상태에 기록한다. 미확인 상세 기준은 반드시 읽는다. 효율은 반복 확인을 줄이는 것이며 회차의 미확인 내용·조건·예외를 생략하는 것이 아니다. 최신 지시는 기존 전체 기준에 추가·정정하며 관련 없는 기존 기준을 폐기하지 않는다.

규칙을 바꾸면 담당 문서만 고치고 결정 기록에 이유를 남긴다. 인계·현황·산출물 목록에는 규칙 전문을 복사하지 않는다. 내용·상태·역사의 구분은 아래 문서 역할을 따른다.

## 최신 제작 범위와 반복 검토 금지

덱·발표자 노트·대본·랩·입력자료·가이드 및 필요한 HTML·ZIP 동기화에 집중한다. 최신 사용자 지시로 PDF 제작·검토는 제외하며, 아래 기존 PDF 관련 절차는 현재 작업에 적용하지 않는다. 기존 PDF는 보존한다.

이미 같은 판본으로 확인·확정한 산출물 내용은 검토 근거를 재사용한다. 변경 부분과 그 앞뒤 연결·영향받은 파생물·미확인 범위만 점검하며, 구체적 결함 없이 같은 검토를 반복하지 않는다. 기준 읽기와 복원은 적용 지침을 확인하는 절차이며 확정 산출물 전체를 다시 검사하라는 뜻이 아니다.

효율은 같은 판본의 확정 근거와 공통 원문을 재사용하고 불필요한 재생성·반복 수정을 줄이는 것이다. 효율을 이유로 미확인 회차를 일부만 읽거나 표본·키워드 검사로 전체 내용 검토를 대신하지 않는다. 해당 회차의 이론·전체 발화·화면·랩·입력자료·가이드를 빠짐없이 대조하고, 수정 후 앞뒤 연결과 영향을 받는 파생물까지 확인한다. 검토 범위표에 확인/근거 재사용/미확인을 구분하고, 누락이 없을 때만 회차를 확정한다. 기준 전독과 산출물 재검토는 구별한다.

최종 GitHub 교재는 `산출물/{통합반,실전반}/{이론,실습}/NN회차`로 정리한다. 현재 온라인 산출물이며 제작 원고·도구·구성 기록은 `제작용/`에 둔다. PDF와 과거 중복 전달 폴더는 활성 산출물에 두지 않는다. 같은 파일의 별도 배포 사본을 만들지 않고 이 위치를 직접 갱신한다.

## 두 과정의 공통 범위와 차이 — 사용자 확정(2026-10-26 갱신)

**1회차는 두 과정 공통이다. 2회차부터 핵심 주제는 공유하고, 실전반 VS Code 코딩 랩은 응용·활용 결과를 처음부터 과제에 포함한다.** 통합반 전체 과제 뒤에 숙제를 더하거나 말투·예외 수만 바꾸지 않는다. 기존 제조 자료와 도구로 가능한 범위를 사용한다.

| 대상 | 적용 원칙 |
|---|---|
| 이론 덱·대본 | 2회차부터 과정별. 같은 핵심 개념에 설계 선택·판단·활용을 가미한다. 상세는 [실전반 기준](실전반_기준.md). |
| 포털·ARROWS·Neo4j 기본·bpmn.io | 공통 시나리오·절차·가이드·캡처·도구 대본을 재사용한다. 차별화를 위해 새 포털 과제를 만들지 않는다. 학생 로컬 모델이 다르면 적재 결과와 확인 질문만 해당 랩에 맞춘다. |
| VS Code 랩·입력·가이드 | 핵심 주제는 같고 실제 요구·수행·활용 결과·완료 기준은 과정별이다. 기존 자료를 재사용하며 실전반은 공급 정보 조회, 조치 검토 결과, 작업 확인 카드, 점검 요청 초안, 다음 협의 안건, 앞 활용 기능의 명세·검증을 만든다. 세부 시간·과제는 [실라버스](실라버스/피지컬AI_실라버스_최종본.xlsx). |
| 실습 대본·영상 | 공통 도구는 공통판, 실제 코딩 수행이 다른 구간은 과정별 랩과 일치시킨다. 실제 실행·촬영은 별도 요청된 범위에서 진행한다. |
| 포털 시스템 경계 | **포털 시스템 로직은 절대 변경하지 않는다.** 판단 엔진·DB 구조·권한·실행 부품·경보 연결 기능을 과정 차별화 목적으로 고치지 않는다. 기존 UI의 수업용 설정·매핑은 공통 절차로 사용한다. 학생 로컬 결과가 포털 에이전트에 자동 연결된다고 설명하지 않는다. |
| 형식·개인 제작 | 덱 형식·용어·사실 근거는 유지한다. 두 과정 모두 교대 인수인계 제작을 수행한다(2026-10-27 확정). 제공 자료·코드·스킬과 승인된 포털 설정을 사용한다. 새 서비스·외부 쓰기 연동을 필수로 만들지 않는다. |

‘모든 랩 한 벌·VS Code 대본만 차이’와 ‘도구 실습까지 전부 과정별’은 모두 현재 방향이 아니다. 기존 확정 근거는 해당 판본에 보존한다. 이번 확정은 실라버스 편성 및 문서·노션 동기화이며, 새 랩·가이드·대본·캡처의 제작 완료와 구별한다.

### 오프라인 운영과 온라인 대응

온라인은 설명·강사 시연·Wrap-up을 유지한다. 오프라인은 온라인 선행 학습 후 가이드를 펼쳐 학생이 독립 수행하고 강사는 막힌 부분을 지원한다. 오프라인 복습·Wrap-up은 편성하지 않으며 이론은 **최대 50분**, 현재 회차별 10~45분이다. 매회 실제 수업 200분+휴식40분=240분을 유지한다. 포털 관찰·Cypher 문법 반복은 압축하고 bpmn.io 직접 설계·개인 제작은 보존한다. 마지막 회차 ProcessGPT 강사 시연은 20분이다.

같은 과정의 온라인·오프라인은 같은 이론 교재를 쓰지만 회차 번호를 일대일로 맞추지 않는다. 엑셀의 온라인 대응 범위로 필요한 단원을 골라 사용한다. 온라인 배포일보다 먼저 필요한 자료는 사전 열람을 준비한다. 편성 시간은 실측이 아니며 수행·AI 대기·녹화 길이는 후속 확인이다.

온라인 실습 영상의 중심은 강사 자기 자신이 실제 작업을 보여 주며 설명하는 자연스러움이다. 오프라인은 위 자율 수행 운영을 따른다. 발화·UI 첫 설명과 반복 축소·커서로 현재 위치 짚기·스크롤·조작 속도·완성본 전환은 [실습 대본 기준](기준_실습대본.md#강사-본인의-자연스러운-원맨쇼--2026-10-20-사용자-확정), 사진·하이라이트는 [가이드 기준](기준_실습가이드.md#사진-가이드의-제작-시점과-범위--2026-10-20), 준비→후속 리허설·실측→필요 수정→본 촬영·사진 추출·동기화 순서는 [검증과 마감](검증과마감.md#실습-준비와-후속-촬영의-순서--2026-10-20)에서 관리한다. 현재 문서·정적 준비와 후속 실제 실행·촬영을 구별한다.

## 현재 요청의 단계

승인 실라버스·강사 배정본의 Notion 첨부는 게시 근거를 재사용한다. 현재 세션은 실습 결정·인계·요청문을 Git에 게시한 뒤 Notion 다듬기를 맡고, 새 세션은 실습 시작 도구 시제품·실습 제작을 맡는다. 범위와 순서는 [실습 제작·배포 인계](인계_실습제작과배포.md)를 따른다. 학생 개인 Git·commit/push는 필수가 아니며 실습마다 독립 시작본을 제공한다. 현재 세션에서는 실습 구현·실행·촬영을 시작하지 않는다. 기존 이론·영상 확정 근거는 유지한다. 현재 완료·미완료는 [작업 상태](작업상태.md)를 따른다.

## 1. 중심

## 11. 사실

61. **실행 사실은 실제 관측 근거로만 보고한다.** 교육용 사례·앞으로 수행할 대본·예상 판정 조건은 실제 실행 기록과 구별하여 작성한다. 결과를 지어내지 않고 미확인 실행은 미수행으로 남긴다. 설계 추정·정적 검사·실측을 구분한다.
62. **값·이름·동작은 사실표와 코드의 근거를 확인해 쓴다.** 설정값·관측값·예측값·설계 추정을 구분한다. 뜻과 출처를 설명할 수 없는 값은 소리 내어 읽지 않고 확인 대상으로 남긴다. 수치의 낭독은 98-1번을 따른다.
63. **실라버스 최종본의 행·제목·상세 항목·순서·이론/실습 구분은 고정이다(실전반 이론은 [실전반 기준](실전반_기준.md)대로 큰 틀만 따른다).** 그 안에서 깊이와 충실도를 높인다. 시간은 39~41번 범위에서 유연하게 조율한다. 교재의 표현을 바꾸는 일과 실라버스를 바꾸는 일을 혼동하지 않는다.
64. **설비 시스템은 고치지 않는다.** 교재가 시스템과 다르면 설명을 고친다.
65. **해석의 순위:** 가장 뒤의 사용자 결정 > 실라버스 최종본 > 그 앞의 문서.

## 12. 일하는 방식

66. **최신 사용자 요청에서 승인된 범위를 끝까지 수행한다.** 이번 최종 검증·수정은 이미 요청됐으므로 기준 정리나 수정 제안만 하고 중단하지 않는다. 새로운 범위·실제 실행 권한이 필요한 경우에만 구분해서 확인한다.
66-1. **검토만 요청된 작업과 검토·수정이 함께 요청된 작업을 구별한다.** 이번에는 필요한 수정과 동기화·검증까지 수행한다. 과거의 수정안 대기 절차를 적용하여 다시 승인을 요구하지 않는다.
67. **대표 단원을 덱과 대본으로 함께 확인한 뒤 넓힌다.** 단원 안의 설명이 이어지는지부터 검토하고, 승인된 방향을 나머지 범위에 적용한다. 이미 승인된 범위의 반복 작업마다 다시 승인을 받지는 않는다.
68. **충돌하거나 정하기 어려운 것은 쉬운 말로 물어 사용자가 정한다.** 확정된 최신 결정은 옛 것을 덮고, 확정이 아닌 것은 양쪽을 살려 조율한다.
69. **원본과 파생 산출물의 상태를 맞춘다.** 덱을 고치면 대본·조립 덱·PPTX·배포 묶음·현황에 미치는 영향을 확인하고 허용된 범위에서 함께 갱신한다. 범위 밖이거나 조립 전환을 기다리는 것은 의존성과 갱신 대기를 명시한다. 재생성하지 않은 파일을 최신이라고 보고하지 않는다.
70. **비용이 드는 일은 미리 알린다**(음성 생성, 모델을 많이 부르는 일, 작업자를 여럿 쓰는 일).
71. **작업자를 쓸 때:** fable 모델을 쓰지 않는다. 방향이 정해지는 문서는 작업하는 세션이 직접 읽고, 사실을 적은 문서만 나눠 준다. 작업자는 요약하지 않고 원문과 줄 번호를 가져온다. 합치는 것은 한 사람이 한다.
72. **결과는 열어 볼 수 있는 파일로 건넨다.** 사용자는 claude.ai 링크를 열 수 없으므로 로컬 파일(HTML 등)로 준다.
73. **현재 지시와 역사적 기록을 분리한다.** 현재 문서를 정합하게 갱신하고 예전 지시가 활성 지침으로 남지 않게 한다. 사용자 요청으로 기존 미커밋 수정·다른 회차·검증 근거·.evidence·before.json은 삭제·초기화·덮어쓰기하지 않는다. 과거 문서는 결정 이력으로 보존하고 현재 위치를 연결한다.

## 13. 저장소

74. **위 경로·권한 절의 활성 정본과 확인한 현재 Git 상태를 사용한다.** 두 과정 모두 main에서 작업한다(2026-10-23 사용자 지시로 develop을 main에 합치고 폐기). 통합반의 분리된 HEAD와 보존 태그를 임의로 이동하거나 삭제된 작업 브랜치(develop 포함)를 재생성하지 않는다. 옛 작업 경로로 전환하거나 두 작업 폴더를 합치지 않는다.
75. **최신 사용자 요청으로 허용된 교재 변경만 경로를 지정해 커밋·푸시한다.** 실제 원격 상태를 확인하고 관련 없는 미커밋 수정을 보존한다. 기계적인 pull/rebase/autostash로 현재 작업을 옮기지 않는다. 원격과 충돌하면 확인한 상태에 맞게 처리하며 강제 푸시는 하지 않는다.
76. **공개 저장소에 비밀정보를 올리지 않는다.** 키·개인 연락처·내부 비밀 주소는 어느 브랜치에도 올리지 않는다. 강의 영상·음성·자막은 main에 올리지 않고, 다른 PC 작업용 브랜치 `other-pc`에만 올린다(2026-10-22 사용자 지시. 공개 저장소이므로 그 브랜치도 공개다). 키는 실행 환경의 환경변수로 받는다. 사용자가 명시한 복구 작업 경로는 인계와 재현 링크에 사용한다. 교육용 회의는 개인 신상 대신 역할을 사용한다.
77. **`.env`는 열지 않는다.** 키 파일의 값을 출력하거나 커밋하지 않는다.
