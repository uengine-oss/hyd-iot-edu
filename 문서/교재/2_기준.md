## 기준 읽기와 작업 복원

작업 시작 시 공통 기준과 [작업별 진입점](4_만드는_법.md)의 해당 행에 지정된 상세 기준을 읽는다. 해당 상세 기준 전체와 연결된 적용 조항을 확인하되, 다른 작업의 기준 전문을 매번 함께 재출력하지 않는다. 동일 판본을 읽은 기록이 있는 작업을 요약 후 재개할 때는 공통 기준·작업 상태·변경된 기준을 복원하고, 이미 읽은 동일 판본의 상세 기준은 기록으로 재사용한다. 읽은 기록이 없거나 판본이 달라졌거나 요약으로 적용 근거를 복원할 수 없으면 해당 상세 원문 전체를 읽는다. 미확인 내용을 요약·키워드 검사로 대신하지 않는다. 두 루트의 동일 본문은 해시 일치를 확인해 한 번 읽고 차이가 있으면 차이 전체를 읽는다.

읽은 문서·판본 해시·범위는 현재 작업 상태에 기록한다. 미확인 상세 기준은 반드시 읽는다. 효율은 반복 확인을 줄이는 것이며 회차의 미확인 내용·조건·예외를 생략하는 것이 아니다. 최신 지시는 기존 전체 기준에 추가·정정하며 관련 없는 기존 기준을 폐기하지 않는다.

규칙을 바꾸면 담당 문서만 고치고 결정 기록에 이유를 남긴다. 인계·현황·산출물 목록에는 규칙 전문을 복사하지 않는다. 내용·상태·역사의 구분은 아래 문서 역할을 따른다.

## 최신 제작 범위와 반복 검토 금지

덱·발표자 노트·대본·랩·입력자료·가이드 및 필요한 HTML·ZIP 동기화에 집중한다. 최신 사용자 지시로 PDF 제작·검토는 제외하며, 아래 기존 PDF 관련 절차는 현재 작업에 적용하지 않는다. 기존 PDF는 보존한다.

이미 같은 판본으로 확인·확정한 산출물 내용은 검토 근거를 재사용한다. 변경 부분과 그 앞뒤 연결·영향받은 파생물·미확인 범위만 점검하며, 구체적 결함 없이 같은 검토를 반복하지 않는다. 기준 읽기와 복원은 적용 지침을 확인하는 절차이며 확정 산출물 전체를 다시 검사하라는 뜻이 아니다.

효율은 같은 판본의 확정 근거와 공통 원문을 재사용하고 불필요한 재생성·반복 수정을 줄이는 것이다. 효율을 이유로 미확인 회차를 일부만 읽거나 표본·키워드 검사로 전체 내용 검토를 대신하지 않는다. 해당 회차의 이론·전체 발화·화면·랩·입력자료·가이드를 빠짐없이 대조하고, 수정 후 앞뒤 연결과 영향을 받는 파생물까지 확인한다. 검토 범위표에 확인/근거 재사용/미확인을 구분하고, 누락이 없을 때만 회차를 확정한다. 기준 전독과 산출물 재검토는 구별한다.

최종 GitHub 교재는 `산출물/{통합반,실전반}/{이론,실습}/NN회차`로 정리한다. 현재 온라인 산출물이며 제작 원고·도구·구성 기록은 `제작용/`에 둔다. PDF와 과거 중복 전달 폴더는 활성 산출물에 두지 않는다. 같은 파일의 별도 배포 사본을 만들지 않고 이 위치를 직접 갱신한다.

## 두 과정의 공통 범위와 실전·응용 차이 — 사용자 확정

**교재와 포털 실습은 통합반·실전반이 동일하다. 대본과 랩은 과정별로 구성하되, 하는 주제와 공통 기반은 같다. 실전반은 그 주제 안에서 실전·응용에 맞게 수행한다.**

| 대상 | 적용 원칙 |
|---|---|
| 교재 | 공통 개념·사례·설명·화면을 동일하게 사용한다. 과정 배정·표지 식별과 내용 차이를 혼동하지 않는다. 랩 수행 차이를 이유로 공통 교재를 다르게 만들지 않는다. |
| 포털 실습 | 같은 포털에서 같은 주제·시나리오·조작·관찰·확인 흐름을 사용한다. 과정별 별개 포털 실습이나 구현 과제를 끼워 넣지 않는다. |
| 대본 | 과정별 진행·연결·실습 수행에 맞춰 작성한다. 공통 설명을 억지로 다르게 쓰거나 모든 대본을 동일 문장으로 강제하지 않는다. 낭독 본문은 본인이 실제 하는 말이며 조작·촬영 메모는 밖에 둔다. |
| 랩 | 같은 주제와 공통 기반 안에서 수행한다. 실전반은 그 안에서 실제 조건에 적용하고 판단·구현·검증하거나 한 번 더 응용하는 방식으로 구성한다. 별개 주제·도구·과제를 추가해 차이를 만드는 것이 아니다. |

응용의 차이는 해당 주제에서 필요한 수행 범위로만 둔다. 과정 이름 때문에 차이를 과장하거나 모든 랩에 추가 과제를 의무적으로 붙이지 않는다. 불필요한 복잡도·반복 설명·목표 시간 채우기를 금지한다. 기존 자료에 차이가 있다는 사실만으로 그 차이를 유지하지 않는다.

‘실전반 근거 추적 도구 구현을 별도 추가 활동으로 유지한다’는 이전 작업자 해석은 사용자 확정 기준이 아니며 철회한다. 해당 내용을 남길지 여부도 위 공통 주제와 실제 랩 목적에 따라 판단한다. 포털 실습의 과정별 차이로 정당화하지 않는다.

2026-10-19. 최신 사용자 결정과 기존 상세 조항을 통합했다. 충돌 해소 위치와 이전 원문은 [결정 기록](5_결정_기록.md)에 있다.

## 현행 적용 범위와 확정 기준

통합반 온라인 1–11회차와 실전반 온라인 1–8회차를 함께 최종 검증·수정한다. 현재 개정본의 생성·정적 검증 완료와 새로 요청한 최종 내용 확정 판정은 구별한다. 완료 표시만으로 검증을 생략하지 않는다.

| 대상 | 이번에 해야 할 일 | 이후 상태 |
|---|---|---|
| 이론 내용·이론 대본 | 개념·사례·조건·예외·용어·전개·중복·어색함·원본 대응을 검증하고 필요한 수정 및 동기화 | 이번 최종 검증을 마치면 최종본으로 확정 |
| 랩 자체·입력자료·시작본·참조본·랩 가이드 | 목적과 요구사항, 제조 맥락, 난이도, 자료 대조와 구현·검증 조건, 앞뒤 결과 연결을 검증·수정 | 이번 최종 검증을 마치면 최종본으로 확정 |
| 실습 대본 | 위 확정 자료와 내용·순서·입출력·검증 조건을 일치시킴 | 촬영 때 발화·전환·조작 타이밍·진행 속도 튜닝 가능 |
| 실제 실행·촬영·전체 진행 시간 | 현재 수행하지 않음 | 회차별 촬영 준비/리허설에서 별도 허용 후 확인 |

실습 대본의 튜닝 가능성을 이유로 나머지 확정을 미루지 않는다. 지금 문서·정적 검토로 해결할 문제를 촬영 단계로 넘기지 않는다. 검증에서 확인한 오류뿐 아니라 누락·중복·어색함·자료 연결 문제도 수정 대상이다. ‘반복하지 말라’는 말은 필요한 최종 검증·수정을 하지 말라는 뜻이 아니다. 시간은 내용의 결과이며 목표 분·장수에 맞춰 늘리거나 줄이지 않는다.

최종 확정 후에는 확인된 오류·누락·모순·진행 차단 문제 또는 사용자의 새 요청이 있을 때 해당 부분을 다시 연다. 최종 판정 결과와 실제 검증 범위는 현황과 마감 보고에 기록하며, 미실시한 실행·촬영을 완료로 표시하지 않는다.

## 1. 중심

0-2. **현재 작업 범위는 통합반·실전반 온라인 두 과정의 최종 검증·수정이다.** 대상과 확정 상태는 맨 위 적용 범위 표를 따른다. 공통 원본과 과정별 배정·대본 차이를 보존하며 실제 브랜치·커밋·미커밋 수정으로 최신 원고를 확인한다. 기준서 정리는 산출물 최종 검증 완료가 아니다.

> **원리와 까닭, 역할과 구조가 줄기다. 전문성 있게 다 알려 준다. 실제로 쓰이는 재료는 그 역할에 「이런 것들이 있다」로만 얹는다.**

0. **까닭: 제품이 바뀌어도 원리와 역할을 이해한 지식은 남는다.** 역할·구조·가치를 줄기로 삼고, 특정 제품의 사용법을 이론의 뼈대로 삼지 않는다. 실제로 가르치는 언어·표준·문법은 제품과 구분한다(16번).
0-1. **판정하는 물음:** 제품을 바꿔도 역할과 원리에 대한 설명이 성립하는가. 다만 수업 주제인 언어·표준·문법의 정확한 이름과 동작을 제품 이름처럼 지우지 않는다(16번).
1. **재료를 하나씩 설명하고 재료의 사용법을 알려 주는 식으로 쓰지 않는다.** 절대 안 된다. 재료를 차례로 소개하는 뼈대에 까닭을 덧붙이는 것도 같은 잘못이다.
2. **말의 뼈대:** 왜 이렇게 설계해야 했는가 → 왜 이렇게 층을 나눴는가 → 각자 무슨 역할을 하는가.
3. **구조의 기준은 설계서 v3다**(`문서/시스템/참조/설계서_v3_유압설비_IoT-SCADA_아키텍처.pdf`). 원래 하려던 구조가 이것이다. 계층의 이름과 역할, 그 자리의 재료, 「왜 이렇게 설계했나」의 원칙(2절 두 개의 축, 7절 명령 경로와 안전)을 여기서 가져온다. 값과 예는 실제로 돌려 얻은 것(사실표)을 쓴다.
3-1. **전문성은 정확한 내용으로 지키고, 어려움은 설명으로 낮춘다.** 화면에는 필요한 정식 용어·정의·근거 있는 값과 관계를 남긴다. 대본은 그것이 필요한 장면, 까닭과 원리를 초심자가 따라올 순서로 풀고 정확한 개념으로 돌아온다. 쉬워 보이려고 이름이나 내용을 흐리지 않고, 전문적으로 보이려고 용어와 예외를 늘리지 않는다. 판정은 학생이 그 용어를 써서 상황과 판단의 까닭을 설명할 수 있는가이다. `근거/이야기_흐름_본보기.txt`는 전개 방식의 참고이며 사실·수치의 근거가 아니다.
4. **무게는 온톨로지와 에이전트에 있다.** 설비와 SCADA 구간은 그 뒤의 판단을 이해하는 데 필요한 범위로 다룬다. 시간 조율은 39~41번을 따른다.

## 11. 사실

61. **실행 사실은 실제 관측 근거로만 보고한다.** 교육용 사례·앞으로 수행할 대본·예상 판정 조건은 실제 실행 기록과 구별하여 작성한다. 결과를 지어내지 않고 미확인 실행은 미수행으로 남긴다. 설계 추정·정적 검사·실측을 구분한다.
62. **값·이름·동작은 사실표와 코드의 근거를 확인해 쓴다.** 설정값·관측값·예측값·설계 추정을 구분한다. 뜻과 출처를 설명할 수 없는 값은 소리 내어 읽지 않고 확인 대상으로 남긴다. 수치의 낭독은 98-1번을 따른다.
63. **실라버스 최종본의 행·제목·상세 항목·순서·이론/실습 구분은 고정이다.** 그 안에서 깊이와 충실도를 높인다. 시간은 39~41번 범위에서 유연하게 조율한다. 교재의 표현을 바꾸는 일과 실라버스를 바꾸는 일을 혼동하지 않는다.
64. **설비 시스템은 고치지 않는다.** 교재가 시스템과 다르면 설명을 고친다.
65. **해석의 순위:** 가장 뒤의 사용자 결정 > 실라버스 최종본 > 그 앞의 문서.

## 12. 일하는 방식

66. **최신 사용자 요청에서 승인된 범위를 끝까지 수행한다.** 이번 최종 검증·수정은 이미 요청됐으므로 기준 정리나 수정 제안만 하고 중단하지 않는다. 새로운 범위·실제 실행 권한이 필요한 경우에만 구분해서 확인한다.
66-1. **검토만 요청된 작업과 검토·수정이 함께 요청된 작업을 구별한다.** 이번에는 필요한 수정과 동기화·검증까지 수행한다. 과거의 수정안 대기 절차를 적용하여 다시 승인을 요구하지 않는다.
67. **대표 단원을 덱과 대본으로 함께 확인한 뒤 넓힌다.** 단원 안의 설명이 이어지는지부터 검토하고, 승인된 방향을 나머지 범위에 적용한다. 이미 승인된 범위의 반복 작업마다 다시 승인을 받지는 않는다.
68. **충돌하거나 정하기 어려운 것은 쉬운 말로 물어 사용자가 정한다.** 확정된 최신 결정은 옛 것을 덮고, 확정이 아닌 것은 양쪽을 살려 조율한다.
69. **원본과 파생 산출물의 상태를 맞춘다.** 덱을 고치면 대본·조립 덱·PPTX·배포 묶음·현황에 미치는 영향을 확인하고 허용된 범위에서 함께 갱신한다. 범위 밖이거나 조립 전환을 기다리는 것은 의존성과 갱신 대기를 명시한다. 재생성하지 않은 파일을 최신이라고 보고하지 않는다.
70. **비용이 드는 일은 미리 알린다**(음성 생성, 모델을 많이 부르는 일, 작업자를 여럿 쓰는 일).
71. **작업자를 쓸 때:** fable 모델을 쓰지 않는다. 방향이 정해지는 문서는 작업하는 세션이 직접 읽고, 사실을 적은 문서만 나눠 준다. 작업자는 요약하지 않고 원문과 줄 번호를 가져온다. 합치는 것은 한 사람이 한다.
72. **결과는 열어 볼 수 있는 파일로 건넨다.** 사용자는 claude.ai 링크를 열 수 없으므로 로컬 파일(HTML 등)로 준다.
73. **현재 지시와 역사적 기록을 분리한다.** 현재 문서를 정합하게 갱신하고 예전 지시가 활성 지침으로 남지 않게 한다. 사용자 요청으로 기존 미커밋 수정·다른 회차·검증 근거·.evidence·before.json은 삭제·초기화·덮어쓰기하지 않는다. 과거 문서는 결정 이력으로 보존하고 현재 위치를 연결한다.

## 13. 저장소

74. **위 경로·권한 절의 활성 정본과 확인한 현재 Git 상태를 사용한다.** 두 과정 모두 develop에서 작업한다. 통합반의 분리된 HEAD와 보존 태그를 임의로 이동하거나 삭제된 작업 브랜치를 재생성하지 않는다. main 또는 옛 작업 경로로 전환하거나 두 작업 폴더를 합치지 않는다.
75. **최신 사용자 요청으로 허용된 교재 변경만 경로를 지정해 커밋·푸시한다.** 실제 원격 상태를 확인하고 관련 없는 미커밋 수정을 보존한다. 기계적인 pull/rebase/autostash로 현재 작업을 옮기지 않는다. 원격과 충돌하면 확인한 상태에 맞게 처리하며 강제 푸시는 하지 않는다.
76. **공개 저장소에 비밀정보를 올리지 않는다.** 키·개인 연락처·내부 비밀 주소·음성·영상은 제외한다. 사용자가 명시한 복구 작업 경로는 인계와 재현 링크에 사용한다. 교육용 회의는 개인 신상 대신 역할을 사용한다.
77. **`.env`는 열지 않는다.** 키 파일의 값을 출력하거나 커밋하지 않는다.
