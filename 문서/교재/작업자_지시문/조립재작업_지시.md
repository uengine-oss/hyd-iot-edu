# 조립 덱 다시 만들기 — 전체 점검 반영 (Opus)

> 자리표시: `<저장소>`는 저장소 루트, `<작업 폴더>`는 저장소 밖의 임시 작업 폴더(본문의 「scratchpad」)다. 이 지시문이 쓰이는 단계는 같은 폴더의 `README.md`에 있다.

HYD 제조 AI 교육과정의 통합반 원 덱(`만들기/decks/integrated/0N일차/`)이 전체 점검 결과로 고쳐졌다(제목이 바뀐 장, 지워지거나 합쳐진 장, 새 장, 바뀐 문구가 있다). 그 덱에서 장을 가져오는 조립 덱을 다시 만들고, 점검이 조립 덱에서 찾은 문제를 고친다. 맡은 과정(프롬프트가 알려 줌)만 한다. 서브에이전트를 쓰지 않는다.

저장소: `<저장소>`. scratchpad: `<작업 폴더>/`

## 읽을 것
1. `문서/교재/2_기준.md`(3 · 8 · 13-1 · 13-2절).
2. scratchpad `점검반영_지시.md`의 「덱 사이의 결정」 1~8 — 원 덱이 따른 규칙이다. 조립 덱의 새 장(`새장_*.md`)과 손질 문구도 같은 규칙을 따른다.
3. 원 덱이 어떻게 바뀌었는가: `git log -3 --stat -- 만들기/decks/integrated`과 `git diff 5747907 HEAD -- 만들기/decks/integrated/0N일차/통합반_0N일차.md`(맡은 덱이 가져오는 일차만), 그리고 scratchpad `점검반영/` 아래의 영향 목록(`조립영향_통합반_01-04.txt`, `w58/asm_after.txt`, `w0911/`의 대조 결과와 스크립트). 원 덱 작업자들의 보고 요지는 프롬프트에 있다.
4. 맡은 과정의 점검 결과: scratchpad `전체점검/결과_<과정>.md` **전부**.
5. 맡은 과정의 `조립.py`와 `새장_*.md` 전부.

## 할 일
1. **조립이 다시 돌게 한다.** 맡은 과정의 `조립.py`를 하나씩 돌려, 멈추는 곳(제목이 없음, 손질 원문이 없음)을 원 덱의 지금 모습에 맞춰 고친다. 손질의 **뜻**은 지킨다(그 손질이 왜 있었는지 — 회차 표기 바꾸기, 빠진 장을 가리키는 말 고치기, 풀네임 붙이기 등 — 를 보고, 원 덱이 이미 같은 일을 해 놓았으면 손질을 지우고, 아니면 새 원문에 맞춰 다시 건다). 지워지거나 합쳐진 장은 합쳐진 쪽을 가져오거나 순서표에서 뺀다. 원 덱에 새로 생긴 장은 그 회차의 실라버스 항목과 분량(단원 본문 = 분 ÷ 1.5, ±15 %, 모자라면 안 됨. 한두 장 넘는 것은 된다)을 보고 넣을지 정한다(실전반 온라인 8일차는 통합반 11일차를 전부 가져오는 덱이므로 새 장도 넣고 장 순서도 원 덱을 따른다).
2. **멈추지 않고 지나가는 변화도 본다.** 조립 뒤 덱 MD를 이전 판과 `git diff`로 견줘, 원 덱의 바뀐 문구가 이 과정에서 틀린 말이 되지 않았는지 본다: 통합반 일차 번호(「3일차에」「9일차에 프로세스가 처리한」 등 원 덱이 새로 넣은 일차 언급을 이 과정의 일차 · 회차로), 「지난 시간에」, 이 과정에 싣지 않은 장이나 그림을 가리키는 말.
3. **점검 결과의 반영.** 맡은 과정 결과 파일의 「상」과 「중」 전부, 「하」는 쉬운 것. 「원문」 표시 항목은 원 덱에서 이미 고쳐졌을 것이니 조립 뒤에 실제로 풀렸는지만 확인한다(풀리지 않았으면 보고에 적는다. 통합반 원 덱은 고치지 않는다). 조립 탓인 항목은 여기서 고친다: 정의 없이 쓰이는 용어(원 덱의 정의 장을 더 가져오거나 손질로 한 구절 붙인다), 실습을 받치는 이론이 없는 곳(장을 더 가져온다), 흐름이 튀는 자리, 실린 장만으로 풀리지 않는 퀴즈, 실습 설명에서 빠진 실라버스 항목(학생이 실제로 하거나 알아야 하는 것 — 「기준 흐름으로 되돌린다」「기준 그래프와 랩 그래프를 구분한다」 — 은 한 칸 · 한 줄로 싣는다. 근거 없는 「복구 상태 확인」은 싣지 않는다), 새 장의 「이 실습을 마치면」 틀 반복(틀을 섞는다), 덱 사이 값의 어긋남(같은 사건의 값이 회차 사이에 말없이 바뀌는 곳 — 원 덱이 9일차에 「프로세스가 처리한 같은 종류의 경보 한 건」임을 밝혀 두었다. 그 장을 가져오지 않은 회차라면 값이 처음 바뀌는 장에 손질로 한 구절을 넣는다).
4. **전 문장 통독.** 다시 조립한 덱을 회차 순서대로 화면 글과 노트 전부 읽어(프롬프트가 「통독이 덜 된 덱」으로 지목한 것은 특히) 어색한 문장, 정의 없는 용어, 앞에서 보이지 않은 것을 가리키는 말, 덱 사이의 결정에 어긋나는 낱말(새장 원고와 손질 문구의 「조치 카드 묶음 · 반려 · 반려율 · 쿨러 과열 · 같은 사건」)을 찾아 고친다.
5. **빌드.** 고친 덱마다 `cd <저장소> && python3 <조립.py> && uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py <md> <pptx> --render <scratchpad/조립재작업_<과정>/NN>`. 렌더는 다른 작업과 차례로 돈다(기다린다). 새 장, 화면이 바뀐 손질 장, 원 덱에서 새로 그려진 그림이 든 장은 렌더를 눈으로 본다(`만들기/tools/deck/시트.py`). 덱 폴더에 렌더 · `__pycache__`를 남기지 않는다.

## 지킬 것
통합반 원 덱, 다른 과정의 덱, 도구, 스킬 문서, 제작 기준, 사실표는 고치지 않는다. 덱 MD를 손으로 고치지 않는다(고칠 곳은 `조립.py`와 `새장_*.md`). 커밋 · push는 하지 않는다. `.DS_Store`와 `~$…pptx`는 건드리지 않는다(잠금 파일이 있는 덱의 PPTX 덮어쓰기가 실패하면 보고에 적는다).
