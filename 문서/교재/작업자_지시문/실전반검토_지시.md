# 실전반 덱 검토 (검토 단계 · 고치지 않는다)

> 자리표시: `<저장소>`는 저장소 루트, `<작업 폴더>`는 저장소 밖의 임시 작업 폴더(본문의 「scratchpad」)다. 이 지시문이 쓰이는 단계는 같은 폴더의 `README.md`에 있다.

## 무엇을 검토하는가
HYD 제조 AI 교육과정 **실전반** 이론 교재(PPTX 덱)다. 실전반은 통합반과 같은 주제를 더 짧은 시간에 다뤄서, 이미 검토를 마친 통합반 덱에서 장을 **그대로 가져와** 조립하고 몇 장만 새로 썼다. 그러므로 장 하나하나의 문장을 다시 검토할 필요는 없다. 볼 것은 **조립해서 생긴 문제**다: 빠진 장 때문에 흐름이 끊기는 곳, 정의 없이 쓰이는 용어, 실전반의 일차 구성과 맞지 않는 말, 시간, 그리고 새로 쓴 장의 품질.

강사(사용자)의 요구: 처음부터 끝까지 매끄럽게 흘러가고(필요 → 개념 → 적용), 학생(노베이스 대학생)이 따라오며 이해할 수 있고, 전문성과 내용이 충분하고, 시간 안에 다 설명할 수 있어야 한다. 유치하거나 내용이 없으면 안 된다.

## 읽을 것
1. `문서/교재/덱_제작기준.md` 전체.
2. 실전반 덱 MD(자기 일차): `production/decks/practical/0N일차/실전반_0N일차.md` — 전체. 같은 폴더의 `조립.py`(어느 장을 어디서 가져왔고 무엇을 손질했는지)와 `새장_0N일차.md`(새로 쓴 장).
3. 실라버스: `문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx`의 「실전반 온라인 32H」 시트에서 자기 일차(이론과 실습 행의 상세 교육 내용).
4. 화면: 덱을 scratchpad에 렌더해 본다(덱 폴더에 아무것도 남기지 않는다).
   `cd <저장소> && uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py production/decks/practical/0N일차/실전반_0N일차.md <scratchpad>/s0N.pptx --render <scratchpad>/s0N_r` 뒤 `uv run --no-project --with pillow python production/tools/deck/시트.py <scratchpad>/s0N_r <scratchpad>/s0N_sh --cols 3 --per 9`. 렌더는 다른 작업과 차례로 돈다(기다린다). **새로 쓴 장과 손질한 장은 반드시 보고**, 나머지는 훑어본다.

## 볼 것
A. **흐름**: 단원마다 메시지만 차례로 읽는다. 장과 장 사이가 이어지는가. 앞 장이 없어져 갑자기 튀는 곳, 「필요」 없이 개념이 먼저 나오는 곳, 같은 말을 되풀이하는 곳.
B. **전제**: 어떤 장이 쓰는 용어 · 약어 · 그림 · 값이 그 앞 어디에서도 소개되지 않은 곳(정의하던 장을 가져오지 않은 경우). 약어 풀네임이 실전반에서 처음 나오는 장에 붙어 있는가(실전반 1일차 = 통합반 1일차이므로 그 덱이 붙인 OT · DMZ · IT · PLC · SCADA · MQTT · HMI · HITL · MES는 제외).
C. **일차와 장을 가리키는 말**: 「지난 시간」「앞에서 본」「N일차의 결과물」「뒤에서 다룬다」 등이 실전반 구성과 맞는가(실전반: 1일차 = 지식 자산화 · 시스템 구조와 데이터 흐름 · 온톨로지의 필요성 / 2일차 = 클래스와 인스턴스 · 스키마 설계 · 그래프 DB와 Cypher · 조치 절차와 판단 규칙 / 3일차 = 성과 평가 · 인제스천 · 전체 정리). 없는 장을 가리키는 노트.
D. **실라버스 대조**: 자기 일차 이론 행의 상세 교육 내용에 적힌 항목이 모두 다뤄지는가. 실습마다 간지 + 설명 1장이 있는가. 실습 설명이 실전반 실라버스의 실습 내용과 맞는가.
E. **시간**: 단원별 이론 본문 장수와 실라버스 분 ÷ 1.5의 차이. 넘는 단원은 무엇을 빼면 되는지, 모자란 단원은 통합반의 어느 장을 더 가져오면 되는지.
F. **새로 쓴 장과 손질**: 제작기준 3 · 5 · 8절에 맞는가(쓸모를 말하는 메시지, 문어체, 유치함 · 구호 · 길 안내 · 구현 설명 · 단서 금지, 같은 문장 틀 반복). 용어 정리가 실전반 본문의 용어와 맞는가. 퀴즈 3문항이 실전반 본문으로 풀리는가, 정답 번호가 몰리지 않는가.
G. **화면**: 새 장과 손질 장의 넘침 · 겹침 · 작은 글자.

## 산출물
scratchpad `실전반검토_0N일차.md`: 맨 위에 단원별 본문 장수와 판정 한 줄, 그 아래 고칠 것 목록 `심각도(상 · 중 · 하) | 장 번호 | 제목 | 문제 | 고치는 법(한 줄. 통합반의 어느 장을 가져오면 되는지 포함)`. 상 = 흐름이 끊겨 이해가 안 됨, 정의 없는 핵심 용어, 사실 오류, 실라버스 항목 누락, 넘침. 문제가 아닌 것은 적지 않는다.

## 지킬 것
아무 파일도 고치지 않는다(렌더 산출물은 scratchpad에만). 커밋하지 않는다. 서브에이전트를 쓰지 않는다. 보고는 짧게: 판정, 심각도별 건수, 「상」 전부, 못 본 것.
