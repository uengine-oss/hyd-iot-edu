# 기술 사실표 만들기 (읽기 단계)

> 자리표시: `<저장소>`는 저장소 루트, `<작업 폴더>`는 저장소 밖의 임시 작업 폴더(본문의 「scratchpad」)다. 이 지시문이 쓰이는 단계는 같은 폴더의 `README.md`에 있다.

HYD 제조 AI 교육과정 이론 교재(PPTX 덱)를 쓰기 위한 「기술 사실표」를 만든다. 너는 덱을 만들지 않는다. 저장소를 읽어 사실을 확인하고 한 문서로 정리한다. **읽기 전용**이다(저장소의 기존 파일 수정 · 커밋 금지, 컨테이너 · DB에 쓰기 금지, `.env` 값 열람 금지 — 키 이름만. 사실표 파일 하나만 새로 쓴다).

저장소: `<저장소>`
- 먼저 읽을 것: `문서/시스템/3_현황.md`(현재 상태와 문서 지도), `문서/교재/2_기준.md`(교재의 기준 — 대상은 노베이스 대학생, 깊이는 「무엇이고, 왜 있고, 우리 시스템에서 무슨 일을 하는가」까지, 개념은 표준대로 가르치고 예는 HYD의 실제 대상으로 든다, 구현 설명은 화면에 쓰지 않는다)
- 실라버스: `문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx`의 「통합반 온라인 44H」 시트(openpyxl). 자기 범위 일차의 **이론 행**(제목과 상세 교육 내용)이 교재의 틀이다. 실습 행은 교재에 간지 + 설명 1장만 들어가므로 「무엇을 하고 무엇이 만들어지는가」만 알면 된다. 「실전반 온라인 32H」 시트에서 같은 주제의 이론 행도 읽어, 실전반이 따로 요구하는 항목이 있으면 사실표에 표시한다.
- 본보기(형식 · 근거 표기 · 깊이를 이것에 맞춘다): `문서/교재/사실표/통합반_02-04일차_기술사실표.md`. 이미 확인된 사실(온톨로지, SOP · 결정표, 인제스천 등)은 다시 조사하지 않고 참조로 쓴다. `통합반_01일차_기술사실표.md`도 참조한다(에이전트의 추천 · 승인 · 실행의 경계, 명령 경로 등이 일부 있다).
- 앞 일차 덱(이미 가르친 것을 알기 위해 장 제목과 메시지만 훑는다): `만들기/decks/integrated/0N일차/통합반_0N일차.md` (1~4일차).

## 쓰는 방식
- 산출물: 프롬프트가 알려 주는 파일 하나(일차별 절).
- 실라버스 이론 행의 상세 교육 내용에 나오는 **항목마다**: (가) 표준 개념으로서의 정의와 정식 영어 명칭(일반 지식. 확실한 것만), (나) HYD에 실제로 있는 대응물과 근거 `[저장소] 경로:줄`, (다) 교재에 그대로 쓸 수 있는 **실제 예**(식별자, 이름, 값, 짧은 설정 · 메시지 · 로그 한 건). 노베이스 학생에게 보여 줄 만한 것으로 넉넉히 뽑는다.
- 1~4일차와 이어지는 사건을 예로 쓴다: HYD-01의 유온 상승 → 쿨러 성능 저하 경보 → 원인 후보(쿨러 핀 오염 · 팬 구동 불량 · 주변 온도 상승) → 조치 후보 넷(팬 최대 운전 SOP-COOL-11 등) → 담당자 승인. 이 사건에서 에이전트 · 프로세스가 실제로 한 일의 기록(처리 기록, 도구 호출의 입력 · 출력, 시각)을 저장소의 검증 기록과 고정본에서 찾는다(`문서/시스템/검증_기록/`, `tests/fixtures/`, `문서/시스템/참조/scenario-walkthrough.md` 등).
- 실행 중인 서비스에서 읽기 전용(GET, read 모드)으로 확인한 것은 `[실측]`과 명령을 적는다. 서비스가 떠 있지 않으면 저장소만으로 한다(띄우지 않는다).
- 확인하지 못한 것은 추측으로 채우지 말고 「확인 못 한 것」 절에 모은다. 문서와 코드가 다르면 코드를 따르고 다른 점을 따로 모은다.
- 실라버스 문구가 구현과 다른 곳(실라버스에는 있는데 구현에 없는 것, 이름이 다른 것)을 일차별로 표로 정리한다. 교재는 없는 것을 있다고 쓰지 않는다.
- 약어는 영어 풀네임과 함께 적는다(공식 명칭만).
- 실습 행마다 한두 줄: 무엇을 하는 실습이고 끝나면 무엇이 만들어지는가(실라버스 문구 + 저장소에서 확인되는 것).
- 공개 저장소에 올라간다. 절대 경로(`/Users/…`), 사람 이름, 키 값을 쓰지 않는다(경로는 저장소 기준 상대 경로).
