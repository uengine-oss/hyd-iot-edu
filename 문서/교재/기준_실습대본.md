## 강사 본인의 자연스러운 원맨쇼 — 2026-10-20 사용자 확정

가장 중요한 기준은 강사 본인이 실제로 작업하며 설명하는 사람처럼 자연스럽게 진행하는 것이다. 앞 이론과 실제로 마친 포털 경험을 짧게 받아 오늘 할 일·목적·만들 결과·확인 기준으로 이어 간다. 처음 받은 프로젝트에서는 목적과 요구만 알고 출발하며, 이미 탐색한 것처럼 내부 구조나 정답을 미리 말하지 않는다. 실제 관찰과 판단을 따라 요청·구현·결과 확인을 이어 간다. 자연스러움을 이유로 설명·필수 검증을 생략하거나 실수·실패를 연출하지 않는다.

VS Code·Codex를 처음 사용할 때 폴더 열기, 탐색기·채팅·터미널 등 당장 필요한 UI와 이유를 설명한다. 바이브 코딩과 SDD는 실제 학습 시점과 필요에 맞춰 처음 적용할 때 설명하고, 이후 익숙한 조작·방법은 수행하되 길게 재설명하지 않는다. 새 요구·조건·판단·검증에 설명을 쓴다. 이론 대본 온라인 상세05·15절의 본인 발화, 제3자·제작 문구 분리, 영어·식별자·수치 선별 규칙을 그대로 적용한다.

각 실라버스 촬영 구간 안에서는 중간 편집·배속·줌인 없이 작업을 이어 간다. 촬영 전에 읽을 수 있는 글자 크기와 패널 배치를 준비한다. 설명할 항목으로 커서를 옮겨 지금 보는 위치를 짚고, 글자·값을 가리지 않는 곳에 둔다. 화면이 바뀌면 필요한 위치를 짧게 알려 준다. 스크롤은 필요한 문맥을 보존하는 범위로 움직인 뒤 읽고 설명하며, 빠르게 지나가거나 이유 없이 왕복하지 않는다. 클릭·입력·붙여넣기·전환은 실제 작업 목적과 설명·확인에 맞춰 진행한다. 커서 이동·드래그·스크롤·타이핑을 포함한 모든 상호작용은 사람이 목표를 보고 연속해서 조작하는 속도와 호흡으로 보여 준다. 작은 이동 호출과 대기를 반복해 찔끔찔끔 움직이는 방식은 피한다. 녹화 fps만 높여 입력의 끊김이 해결됐다고 판정하지 않는다. 모든 조작에 고정 초 단위 지연을 붙이거나 사람처럼 보이려고 무의미한 커서 이동·느린 타이핑·실수를 추가하지 않는다. 기술·판본·예외 메모만 비낭독 영역에 둔다. 학생에게 필요한 위치·조작 안내는 실제 발화에 포함하며 메모로 대신하지 않는다.

VS Code 랩은 완성한 결과의 실행·판정·저장으로 마무리하도록 준비한다. 진행이 막혀 참조 완성본이 필요하면 전환 사실을 짧게 밝히고 해당 판본에서 실행·결과를 확인한다. 참조본을 방금 직접 만든 결과로 말하지 않는다. 이 절의 실행·촬영은 허용된 촬영 단계에서 수행한다. 최신 요청의5종 샘플은 실제 조작·녹화가 허용됐으며 이번 인계 세션에서는 문서만 동기화한다. 준비·리허설·가이드·본 촬영의 순서와 재확인 경계는 [검증과 마감](검증과마감.md#실습-준비와-후속-촬영의-순서--2026-10-20)을 따른다.

## 1회차 환경 준비·포털 안내 — 2026-10-22 사용자 확정

1회차는 두 과정 공통이다. VS Code는 파일을 열고 수정·실행할 작업 공간, Git은 프로젝트를 내려받고 변경 이력을 관리하는 도구로 쉽게 설명한다. IDE 같은 처음 보는 용어를 설명 없이 쓰지 않는다. Codex는 요구를 전달하고 코드 작성·수정·결과 확인을 함께 진행할 AI 코딩 도구이며, 실습 재료나 확장 프로그램이라는 분류 중심으로 소개하지 않는다.

Docker는 다른 도구보다 필요성을 충분히 설명한다. 필요한 서비스를 각각 직접 설치·설정하는 부담을 줄이고 준비된 환경을 실행한다는 이유에서 출발한다. 이미지·컨테이너·접속 포트·데이터 보관은 실제 화면과 설정에서 필요한 만큼 쉽게 연결한다. 개념을 먼저 길게 강의하거나 모든 옵션을 깊이 풀이하지 않는다. 대부분의 서비스는 Docker로 준비하되 실제 설치 목록을 확인하며 전부 Docker 안에 있다고 단정하지 않는다. 현재 README에는 Node.js도 설치 대상으로 있으므로 촬영용 main 판본에서 다시 확인한다. 근거 없는 ‘나머지 실행 도구’ 항목을 만들지 않는다.

공식 다운로드 위치를 보여주고 설치 완료 상태에서 진행한다. 설치 대기·계정 로그인은 본론으로 늘리지 않는다. HYD 촬영용 main clone → VS Code 폴더 열기 → 실제 배포 절차의 시작 명령 → 출력·상태 확인 → 실제 주소로 포털 접속 순서다. 활성 develop과 미커밋 수정은 보존하며 main 배포 완료로 단정하지 않는다. 사용하는 명령은 작업 위치·목적·기대 결과를 조작하면서 한두 마디씩 설명한다. 명령의 모든 토큰·옵션·철자를 낭독하거나 깊이 강의하지 않는다. 짧은 명령·바이브 요청은 직접 타이핑하고 긴 명령은 붙여넣어도 된다.

포털 메뉴는 실제로 열며 언제 쓰고 무엇을 확인하는지 안내한다. 중요한 화면은 쉬운 예시를 짚고, 보조 메뉴는 용도·위치만 소개한다. 아직 배우지 않은 전문용어·설정은 지금 화면을 이해하는 만큼만 풀고 ‘뒤에서 직접 다룰 테니 지금은 이런 화면이 있다는 정도로 보시면 됩니다’처럼 부담을 낮춘다. 이 안내도 메뉴마다 반복하지 않는다. 시스템 구성은 앞 이론과 짧게 연결하고 사건 전체 실행은 해당 실습에서 수행한다. 종전 ‘아키텍처 위치만 안내’는 이 전체 메뉴 안내로 확대한다.

분량은 실제 설명·조작의 결과다. 50분을 맞추려고 느리게 타이핑하거나 대기하지 않는다. 처음 보는 기능과 중요한 결과에는 여유를 주고 익숙한 조작은 자연스럽게 진행한다. 환경 준비+메뉴 안내 34~45분은 대화에서 나온 계획 추정일 뿐 실측·고정 배정이 아니다.

## 촬영 가독성과 현재 조작 제약 — 2026-10-22

과거 Computer Use 시험의 파란 후광 수용 기록은 현재 선호 기준이 아니다. 최신 공통 기준은 아래 참조 영상의 후광 없는 화살표와 자연스러운 이동이다. 촬영 작업은 사용자 PC 입력과 분리하는 환경을 우선 검증한다. 별도 환경에서도 강사 원맨쇼·실제 화면 조작·가독성·결과 확인 기준은 같다. 연결 구성과 확인 상태는 샘플 인계에 둔다.

현재 범위는 완성된 Notion 학습노트의 촬영 전 자료 동기화다. **학습노트 하나 → 여러 주제 카드 → 자유로운 내용·하위 페이지**를 유지한다. 홈은 큰 표지 없이 작은 이미지 카드로, 전체 주제 표는 이름·분야·이해도가 보이게 구성했다. 주제별 예시와 재사용 템플릿을 포함한 두 과정 공통 29단계 대본·입력·가이드 HTML·ZIP을 동기화했다. 디자인·입력 정본은 촬영 준비 문서에 연결한다. 승인된 2분40초대 샘플처럼 위치 안내→조작·입력→결과 확인을 나누고, 반복 설명만 줄인다. 이론/실습/실수노트 분류나 별도 자료 DB를 강제하지 않는다. 본 촬영·전체 음성 생성·50분 실측은 미수행이다. 기존 완성본을 먼저 짧게 보여 주고 빈 페이지에서 따라 만든다. 처음 보는 메뉴는 위치·선택·입력·결과를 하나씩 설명하며, 이미 한 조작은 길게 반복하지 않는다. 표지와 카드 이미지·아이콘·여백·읽기 쉬운 제목을 학습 가치와 함께 다룬다. 학생은 템플릿의 항목과 하위 페이지를 자유롭게 바꾸며 정해진 양식으로 제출하지 않는다. 공유·게시·내보내기는 예시 내용을 채운 뒤 마지막에 설명한다.

첫 바이브 코딩 실습은 모르는 프로젝트에서 목적·요구사항을 제시하고, AI가 관련 부분을 조사하게 하며, 현재 기능과 필요한 결정을 확인하고, 요구사항·완료 기준을 구체화해 계획·구현·결과 검증으로 이어가는 방법을 설명한다. 강사가 미리 알고 있는 파일·함수·정답 프롬프트를 탐색 없이 지정하지 않는다. AI 답변·실행 결과를 선기입하지 않고, 관찰한 근거에 따라 다음 요청을 발전시킨다. 소스 내부 탐색은 AI가 수행하되 강사는 기능·제약·변경 영향과 결과로 이해하고 판단한다.

### 커서 표시 보정과 실제 조작의 구별 — 2026-10-23 정정
