## 강사 본인의 자연스러운 원맨쇼 — 2026-10-20 사용자 확정

가장 중요한 기준은 강사 본인이 실제로 작업하며 설명하는 사람처럼 자연스럽게 진행하는 것이다. 앞 이론과 실제로 마친 포털 경험을 짧게 받아 오늘 할 일·목적·만들 결과·확인 기준으로 이어 간다. 처음 받은 프로젝트에서는 목적과 요구만 알고 출발하며, 이미 탐색한 것처럼 내부 구조나 정답을 미리 말하지 않는다. 실제 관찰과 판단을 따라 요청·구현·결과 확인을 이어 간다. 자연스러움을 이유로 설명·필수 검증을 생략하거나 실수·실패를 연출하지 않는다.

VS Code·Codex를 처음 사용할 때 폴더 열기, 탐색기·채팅·터미널 등 당장 필요한 UI와 이유를 설명한다. 바이브 코딩과 SDD는 실제 학습 시점과 필요에 맞춰 처음 적용할 때 설명하고, 이후 익숙한 조작·방법은 수행하되 길게 재설명하지 않는다. 새 요구·조건·판단·검증에 설명을 쓴다. 이론 대본 온라인 상세05·15절의 본인 발화, 제3자·제작 문구 분리, 영어·식별자·수치 선별 규칙을 그대로 적용한다.

각 실라버스 촬영 구간 안에서는 중간 편집·배속·줌인 없이 작업을 이어 간다. 촬영 전에 읽을 수 있는 글자 크기와 패널 배치를 준비한다. 설명할 항목으로 커서를 옮겨 지금 보는 위치를 짚고, 글자·값을 가리지 않는 곳에 둔다. 화면이 바뀌면 필요한 위치를 짧게 알려 준다. 스크롤은 필요한 문맥을 보존하는 범위로 움직인 뒤 읽고 설명하며, 빠르게 지나가거나 이유 없이 왕복하지 않는다. 클릭·입력·붙여넣기·전환은 실제 작업 목적과 설명·확인에 맞춰 진행한다. 커서 이동·드래그·스크롤·타이핑을 포함한 모든 상호작용은 사람이 목표를 보고 연속해서 조작하는 속도와 호흡으로 보여 준다. 작은 이동 호출과 대기를 반복해 찔끔찔끔 움직이는 방식은 피한다. 녹화 fps만 높여 입력의 끊김이 해결됐다고 판정하지 않는다. 모든 조작에 고정 초 단위 지연을 붙이거나 사람처럼 보이려고 무의미한 커서 이동·느린 타이핑·실수를 추가하지 않는다. 필요한 위치·조작 메모는 비낭독 영역에 두고 발화를 지시문으로 대체하지 않는다.

VS Code 랩은 완성한 결과의 실행·판정·저장으로 마무리하도록 준비한다. 진행이 막혀 참조 완성본이 필요하면 전환 사실을 짧게 밝히고 해당 판본에서 실행·결과를 확인한다. 참조본을 방금 직접 만든 결과로 말하지 않는다. 이 절의 실행·촬영은 허용된 촬영 단계에서 수행한다. 최신 요청의5종 샘플은 실제 조작·녹화가 허용됐으며 이번 인계 세션에서는 문서만 동기화한다. 준비·리허설·가이드·본 촬영의 순서와 재확인 경계는 [검증과 마감](검증과마감.md#실습-준비와-후속-촬영의-순서--2026-10-20)을 따른다.

## 1회차 환경 준비와 입력 방식 — 2026-10-20 사용자 정정

필요한 설치 목록은 도구가 무엇을 하고 왜 필요한지만 짧게 설명한다. 설치는 완료된 상태를 전제로 하며 설치 마법사·다운로드·긴 인증 과정으로 실습을 늘리지 않는다. 수업용 HYD 저장소를 main 기준으로 clone하고 VS Code로 폴더를 여는 흐름을 준비한다. main 배포 판본에 필요한 실행 파일·자료가 들어 있는지는 촬영 전에 별도로 확인한다. 교재 작업 중인 develop을 main으로 전환·병합·게시하라는 지시로 확대하지 않는다.

어느 터미널·폴더에서 무슨 명령을 치는지와 그 명령의 목적을 설명하며 기동한다. 짧은 명령과 바이브 코딩 요청은 사람이 내용을 생각하며 입력하는 속도로 직접 타이핑하는 것을 기본으로 한다. 긴 명령·긴 원문은 붙여넣기를 허용하되 의미와 확인할 결과를 짚는다. 고정 글자 간격·고정 지연·빠른 일괄 붙여넣기로 사람의 진행을 대신하지 않는다. 처음의 UI 설명 뒤에는 익숙한 조작 설명을 반복하지 않는다.

포털은 실제 시작 출력의 주소로 열고, 시스템 아키텍처 화면이 있는 위치와 앞 이론의 연결만 짧게 짚는다. 같은 구조를 다시 강의하거나 환경 준비에서 다음 사건 실습을 선행 실행하지 않는다. 기존 수동 기동 명령은 현재 배포의 시작 절차·동적 포트·설정 준비와 대조한 후 선택한다. clone만으로 비공개 설정과 진단 지식까지 갖춰졌다고 말하지 않는다. 현재는 대본 설계만 하며 clone·명령 실행·브라우저 실습·촬영을 수행하지 않는다.

다운로드 서비스 이름·파일 목록·소스 구조를 설명거리로 늘리지 않는다. 구체적인 내려받기 위치는 화면 조작으로 전달한다. 프로젝트를 모르는 상태라는 전제와 목적·요구사항만으로 시작한다는 전제는 유지한다. 이후 AI 탐색·요구 구체화·구현 과정으로 연결하며 그 절차의 반복 설명은 아래 바이브 코딩과 설명의 점진적 축소 기준을 따른다.

## 상세 적용 — 온라인 실습의 바이브 코딩과 설명의 점진적 축소

온라인은 강사 한 사람이 목적·요구사항만 알고 처음 받은 랩 프로젝트에서 제작을 진행하는 영상이다. 학생용 가이드를 읽는 시간·학생 작업 시간은 영상 분량에 넣지 않는다. 기존 가이드는 제작 참고 자료로 보존한다. 소스코드 해설·파일 목록·ZIP 구성 설명을 본론으로 삼지 않는다. 필요한 코드의 역할만 짧게 짚고, 학습 대상인 프롬프트·스킬·명세·조건과 결과를 화면에서 보여 준다.

도입은 앞 이론과 실제 앞서 본 포털의 장면을 오늘 만들 결과에 짧게 연결한다. 아직 보지 않은 것을 보았다고 말하지 않는다. 해당 실습 코드를 내려받고 VS Code로 여는 조작은 간결하게 진행한다. 다운로드 서비스의 사용법이나 파일 구조를 길게 낭독하지 않는다.

첫 바이브 코딩 실습은 모르는 프로젝트에서 목적·요구사항을 제시하고, AI가 관련 부분을 조사하게 하며, 현재 기능과 필요한 결정을 확인하고, 요구사항·완료 기준을 구체화해 계획·구현·결과 검증으로 이어가는 방법을 설명한다. 강사가 미리 알고 있는 파일·함수·정답 프롬프트를 탐색 없이 지정하지 않는다. AI 답변·실행 결과를 선기입하지 않고, 관찰한 근거에 따라 다음 요청을 발전시킨다. 소스 내부 탐색은 AI가 수행하되 강사는 기능·제약·변경 영향과 결과로 이해하고 판단한다.

이후에는 익힌 절차를 매번 처음부터 가르치지 않는다. 같은 프로젝트의 이전 명세·계획·결과를 이어 쓰고 이번에 달라진 요구·판단·검증 지점에 시간을 쓴다. 첫 적용은 이유와 판단 과정을 충분히 보여 주고, 재적용은 새 차이만 설명하며, 익숙한 작은 작업은 짧은 요청과 결과 확인으로 진행한다. 새로운 프로젝트나 불명확한 요구·큰 변경이면 필요한 탐색·계획을 다시 수행하되 방법론 소개를 반복하지 않는다. 설명을 줄이는 것이 필요한 실제 검증을 생략한다는 뜻은 아니다.

매 랩에 탐색→명세→계획→구현→검증을 같은 길이의 형식으로 강제하지 않는다. 명세 문서는 SDD가 학습 목표이거나 변경 기준을 지속해서 관리할 때 사용한다. 초기 회차에 아직 배우지 않은 SDD·BDD 전문 용어나 문서 작업을 앞질러 강제하지 않는다. 익숙한 기본 동작은 자연스럽게 수행하고, 이번 랩만의 학습상의 새 판단이 있어야 한다. 흥미를 위해 억지 실패·가상 학생·불필요한 기능·드라마를 만들지 않는다.

분량은 강사의 설명·실제 제작·결과 해석 흐름의 결과로 추정한다. 코드 해설·타이핑·같은 절차의 재설명·대기·학생 활동으로 배정 시간을 채우지 않는다. 실행 리허설 없이 안정적인 정확한 영상 길이를 확정하지 않는다. 일반 정적 교재 조사와 기록에서는 실제 실습·학생 코드/테스트·AI 시연·HYD/DB·브라우저 실습·캡처를 수행하지 않는다. 최신 요청으로 허용된5종 샘플 제작은 [공통 기준의 현재 요청 단계](2_기준.md#현재-요청의-단계)를 따른다.

공식 자료에서 채택한 원칙(2026-10-19 확인): VS Code는 복잡하거나 접근이 불명확한 변경에서 계획을 분리하고, 작은 명확한 변경은 직접 구현할 수 있다고 설명한다. GitHub는 목적·범위·수용 기준을 명확히 하되 정확한 파일 경로를 모를 때 에이전트가 관련 코드를 찾을 수 있다고 설명한다. 이를 수업의 첫 설명→차이 중심 재적용→자연스러운 활용으로 구성하는 것은 사용자 요구에 따른 교육 설계이며, 모든 랩에 대한 유일한 최적 절차가 연구로 확정됐다는 주장이 아니다.

## 10. 실습

58. **온라인은 강사가 혼자 자료를 받고 직접 만들고 확인하는 실습 영상이다.** 학생 가이드 읽기·학생 작업·가상 응답 시간을 넣지 않는다. 가이드는 제작 참고로 유지한다. 실습 대본은 지금 하는 일과 판단이 이어지게 쓰며 필요한 설명을 성기게 생략하지 않는다. 소스코드 해설은 중심이 아니다. 촬영 때 발화·전환·진행 속도는 튜닝할 수 있다. 관찰하지 않은 실행·실패·복구를 성공 결과처럼 쓰지 않는다.

60-1. **실습은 목적과 요구사항에서 실제 제작·검증으로 이어 간다.** 자료 다운로드→압축 해제→VS Code 작업 공간 열기를 짧게 보여 주고 필요한 탐색·요구 구체화·계획·구현·결과와 근거 확인·문제 수정·재확인·저장·재열기로 잇는다. 앞 결과를 이어 쓰고 이미 익힌 방법을 매번 길게 설명하지 않는다. 참조 완성본은 직접 만든 결과와 구별한다. 네 단계나 완성본 설명을 형식적으로 추가하지 않으며 Notion을 포함해 고정 시간으로 늘리지 않는다.

### 제조 업무와 PBL 연결

첫 코딩은 목적과 요구에서 AI 탐색 → 현재 준비·미구현 확인 → 요구와 완료 기준 → 필요한 계획·구현 → 원문과 결과 대조로 간다. 이후에는 익힌 방법을 재강의하지 않고 새 조건·요구·검증을 설명한다. SDD·BDD는 해당 학습 시점과 업무에 필요한 범위에 둔다. 실제 명령은 촬영용 절차로 표시하며 이번 문서 작업에서 실행하지 않는다.

### 온라인

강사 혼자 자료를 내려받아 압축을 풀고 VS Code에서 작업한다. 학생이 가이드를 읽거나 답할 시간을 넣지 않는다. HTML은 제작 참고 자료다. 파일 목록·소스 해설을 본론으로 늘리지 않고 입력할 프롬프트·스킬·명세·판단 근거·실제 결과를 보여 준다. 실습 대본의 내용과 순서는 랩·가이드에 맞춘 상태로 확정하며, 발화·전환·진행 속도는 촬영 때 튜닝할 수 있다.
