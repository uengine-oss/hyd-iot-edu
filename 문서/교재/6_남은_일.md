# 교재 6. 남은 일 — 최종 내용 검증·수정 후 확정

## 지금 수행할 작업

1. [인계](인계_통합반_회차별_점검.md)와 [기준서](2_기준.md)를 읽고 두 정확한 원본의 Git 상태·검증 근거를 확인한다. 기준을 다시 정하거나 이미 허용된 수정마다 승인을 반복 요청하지 않는다.
2. 이론·이론 대본을 덱과 함께 검증한다. 개념/사례/조건/예외/용어/복습/퀴즈/정답 보존, 자연스러운 전개, 불필요한 중복·어색함, 제품 구현과 범용 원리 구별, 실라버스·원본 배정을 확인한다. 실제 확인 범위를 기록하며 기존 완료 표시만 믿거나 새 전수 재독을 했다고 과장하지 않는다.
3. 랩 자체·입력자료·시작본·참조본·랩 가이드를 검증한다. 제조 목적과 요구, 자료 대조·조건 판단·구현과 확인에 필요한 충분한 작업, 첫 프로젝트 탐색과 이후 새 판단 중심 진행, 앞 결과 재사용·저장/재열기, 결과 근거와 수정·재확인 흐름을 확인한다. 단순 요약·복사·장난감 과제도, 시간 채우기용 복잡함도 허용하지 않는다.
4. 과거 남은 일의 수치 미확인·자료 부재·덱 지적 중 온라인 확정에 관련된 것은 현재 파일과 대조한다. 현재도 남아 있으면 이번에 해결하거나 실제 실행에서만 확인 가능한 이유를 기록한다. 이미 해결된 지적을 새 작업으로 재생성하지 않는다. 오프라인 항목은 완료로 바꾸지 않는다.
5. 발견한 문제를 수정하고 실습 대본의 내용·순서를 맞춘다. 관련 덱·노트·분할/합본/낭독본·PDF·HTML·입력자료·ZIP을 동기화한다. 원본 대응·누락·PDF 원문/전쪽 배치·링크·ZIP 목록/바이트·복사 해시·필요한 정적 구문/참조를 검증한다.
6. 이론·이론 대본·랩·가이드를 최종본으로 판정하고, 수정 내역·전후 장수/발화/동일 산식 낭독 추정/랩 및 산출물 수·검증 범위를 보고한다. 실습 대본은 내용 일치 상태를 마감하고 촬영 발화·전환·속도 튜닝 가능으로 구분한다. 실제 미해결 결함을 숨겨 확정하지 않는다.
7. 현황·남은 일·인계·제작 기록을 현재 상태로 갱신한다. 현행 지시와 역사 기록을 분리하고 서로 충돌하는 최신 절을 덧붙이지 않는다. 사용자가 직접 재개할 요청문을 제공하며 새 세션을 자동 생성하지 않는다.

## 촬영 준비/리허설에 남길 항목

실제 AI 응답, 학생 코드/테스트 실행 결과, HYD/DB와 MCP 권한·연결, 브라우저 화면, 단계별 조작 소요와 전체 진행 시간, 캡처·촬영. 별도 허용 전 실행하지 않는다. 문서로 해결 가능한 결함은 이 목록으로 미루지 않는다. 실습 대본의 발화·전환·속도는 실제 화면에 맞춰 튜닝한다. 시간에 맞추려는 본론 삭제나 불필요한 보충은 하지 않는다.
