# 교재 6. 남은 일

다음에 할 일과, 「확인했다」고 말하면 안 되는 것을 적는다. 기준일 2026-10-14.

## 0. 다음에 할 일 (차례대로)

통합반 1회차는 2026-10-14에 새 기준으로 덱과 대본을 다시 썼고, 같은 날 사용자 검토에 따라 덱의 도입과 지식 자산화 단원을 다시 고쳤다(95장 → 90장, `3_현황.md` 0절). 그다음은 이렇다.

1. **1회차 덱 1~44장(정식 용어로 다시 쓴 판)을 확인받는다.** 2026-10-14 사용자 지적(「덱에 전문성이 없다」)으로 기준 29-1번을 두고, 1~44장 가운데 35장을 정식 용어가 서게 다시 썼다(제목 9장 포함). 그 판을 아스트라에 한 번 보냈고(379개 문구, 검사 통과, 새 용어 모두 유지), 넘친 메시지 4개(2 · 16 · 20 · 26장)와 15장 그림 라벨은 칸의 기준을 알려 아스트라에서 다시 받았다. 다시 받은 문구가 명사형으로 딱딱하게 줄어든 것은 사용자 판단을 기다린다. 확인받으면 온톨로지 단원(49~81장)을 같은 기준으로 본다. 키는 환경변수 `REAL_OPEN_API_KEY`(새 세션에서 먼저 확인). 순서와 명령은 `4_만드는_법.md` 3부 2절의 「덱 문구 윤문」이다.
2. **1회차 대본을 89장 덱에 맞춘다.** 대본은 아직 95장 판의 번호다. 할 일: 도입(표지 · 학습목표 · 목차)을 새 학습목표대로 새로 쓴다 · 지식 자산화 단원(5~10장)과 노션 실습 묶음을 새 덱대로 다시 쓴다 · 시스템 단원에서 빠진 두 장(따라갈 사건, 유온이 오르는 까닭)의 대본을 빼고 사건 추적의 말을 구조 중심으로 바꾼다 · 「값」을 「데이터 · 계측값」으로 나눠 쓴다 · 시연 묶음에서 온톨로지 단원으로 넘어가는 첫머리를 「이 흐름이 돌아가려면 먼저 무엇이 있어야 하나」로 다시 쓴다(시연은 기술 구성 없이 일반적인 말로, 각 단계는 이어지는 회차에서 배운다고 잇는다) · 1부의 「감지 서비스 detector」, 3부의 「오늘 처음 쓴 약어」, 1부 첫 문장의 「1일차」를 고친다 · 세 부분을 처음부터 끝까지 통독해 덱과 어긋나는 곳을 고친다. 그 뒤 아스트라 윤문 → 길이 재기 → 문서 맞추기.
3. **덱 45~89장(실습 묶음, 온톨로지 단원, 끝부분)을 같은 원칙으로 본다.** 아직 손대지 않았다. 이 클라우드에는 맑은 고딕이 없어 렌더 그림의 줄바꿈이 실제와 조금 다르다(빌드 검사는 통과).
4. **승인된 1회차를 본보기로 2~11일차를 하루씩 같은 기준으로 다시 쓴다.** 순서는 1일차와 같다: 덱의 제목과 메시지만 이어 읽어 뼈대를 본다 → 재료를 차례로 소개하는 단원은 뼈대부터 다시 짜고, 물음으로 이어지는 단원은 늘어난 곳과 한 장에 둘을 설명하는 곳만 잡는다 → 대본을 새 덱에 맞춰 다시 쓴다 → 대본은 아스트라가, 덱은 작업하는 세션이 윤문한다 → 조립 덱, PPTX, 배포 묶음, 문서를 맞춘다(`4_만드는_법.md` 1부). 우리가 붙인 서비스 이름과 재료의 이름이 2~11일차 덱과 대본에도 나온다(세어서 보고한다).
5. **윤문:** 대본은 아스트라에게 「내용과 설명의 수준은 자료를 보고 이미 다 맞춰 놓은 완성본이다. 내용은 손대지 말고 윤문 작업만 해 달라」고 알려 한 번 보내고, 돌아오면 숫자, 이름, 굵게 표시, 문단 수, 음절 수, 끝말의 분포를 검사한다. 덱은 작업하는 세션이 직접 윤문하고 빌드로 넘침을 확인한다(`2_기준.md` 8절).
6. 영상은 사용자가 범위를 말하면 만든다. 1회차는 장 번호가 바뀌었으므로 쉼 자리를 다시 정한다.

## 1-1. 랩과 덱이 어긋나 정해 주어야 하는 것

| 무엇 | 왜 열려 있나 |
|---|---|
| 학생이 쓸 실습용 그래프 DB의 주소 | 덱은 분리된 DB라고만 한다. 수업 스택의 그래프 DB에는 기준 지식이 들어 있어 학생이 넣는 것과 식별자가 겹친다. 두 묶음은 DB가 비어 있지 않으면 준비 단계에서 멈춘다 |
| 랩의 스키마 이름 | 2회차 랩은 `MEASURES`, `MOUNTED_ON`을 쓰고 덱은 `OBSERVES`, `MONITORED_BY`로 설명한다 |
| 2회차 랩 스키마의 `USES_PART` | 이어받은 스키마는 `1:N`, 저장소의 확정 스키마는 `N:M`이다 |
| 4회차 실습 3의 판단 규칙 | 덱은 판단 규칙까지 조회한다고 하나 이어받은 후보에 규칙이 없어 랩에서 뺐다 |
| 4회차 실습 4의 개정 값 | 덱에 새 값이 없다. 랩은 48시간으로 했는데 HYD나 덱의 값이 아니다 |
| 6회차의 MCP 서버 | 덱은 공개 서버 셋이라고 하나 설치 방법이 저장소에 없다. 랩은 묶음 안에 파이썬으로 쓴 서버를 쓴다 |
| 6회차 랩의 중복 처리 | 덱은 「합치지 않고 표시」, 랩은 합친다 |
