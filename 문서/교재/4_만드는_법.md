# 교재 4. 만드는 법 — 현행 온라인 정합화 절차

## 원본과 수정 순서

내용 기준은 [2_기준.md](2_기준.md), 검증할 범위는 [6_남은_일.md](6_남은_일.md)다. 통합반은 D:/work/study/hyd-integrated-recovered-20261018, 실전반은 D:/work/study/hyd-portal-latest-20261014에서 각각 작업한다.

이론 화면 원본은 각 과정의 `만들기/decks/integrated/dayNN/` 또는 `만들기/decks/practical/dayNN/`이다. 이론/실습 발화 원본은 각 과정의 `산출물/교재/대본/<과정>_온라인/NN회차/구성.json`이 가리키는 분할 파일이다. 랩 자료는 `산출물/실습/<과정>_온라인/NN회차_실습_안내.md`가 연결하는 폴더다. 원본대응.json 및 최신 실라버스로 통합반 원본과 실전반 조립 관계를 확인한다.

수정할 원본과 영향 범위를 먼저 확인하고 화면과 발화를 함께 조정한다. 제목·장수·배정이 바뀌면 구성·원본 대응까지 맞춘다. 과거 조립/콘텐츠 생성기를 일괄 실행하면 최신 분할 원고를 덮을 수 있으므로 실행하지 않는다. 공통 본문 변경은 원본과 배정된 과정 모두에 대응을 남겨 반영한다.

## 파생물 생성과 검증

최근 동기화 구현은 실전반 `만들기/labs/online/revision20261019/sync.py`에 있다. 현재 두 원본을 사용하여 노트·분할/합본/낭독본·랩 HTML·PDF·ZIP을 맞춘다. 이 스크립트는 화면을 새로 그리는 전체 덱 빌더가 아니다. 화면 변경이 있으면 기존 덱 빌더로 해당 PPTX와 덱 PDF를 다시 생성하고 검사해야 한다.

**재사용 전 필수:** 이 스크립트와 finish_checks.py/metrics.py는 과거 `.evidence/online-revision-20261019` 경로를 사용한다. 새로운 작업은 별도 근거 디렉터리와 시작 해시를 만들고 해당 경로를 새 작업용으로 분리해야 한다. 과거 before.json·검사 결과·렌더에 덮어쓰지 않는다. edit.py/manufacturing.py/refine.py/closeout.py는 당시 콘텐츠 변경/기록 도구이며 현재 원본에 재실행하지 않는다.

덱 빌더는 `.claude/skills/lecture-deck/scripts/deck2pptx.py`이다. 사용 전 실제 인자와 해당 원본 경로를 확인한다. 화면 변경과 노트 변경을 구별하며 단순 발화 변경을 위해 화면 원본을 임의로 다시 조립하지 않는다. 과거 빌드 명령과 도구 제약은 결정 기록의 보존 원문에서 참고할 수 있으나 예전 C 경로·전체 재조립·실행 명령을 현재 지시로 사용하지 않는다.

검사 항목은 원본 내용 대응·누락·노트/대본 일치·PDF 원문과 수정 PDF 전쪽 배치·로컬 링크·ZIP 파일 목록/바이트·복사 자료 해시·정적 구문/참조다. 실제 학생 프로그램을 import하거나 실행하지 않는다. AST/JSON/XML 파싱은 실행 성공이 아니다. 변경 없는 산출물을 반복 생성하지 않는다.

## 보고·게시

변경 전후 수치와 수정 이유, 사용한 낭독 산식과 추정/실측 구분, 생성·검증한 실제 범위를 기록한다. 교재 경로만 지정하여 커밋·푸시하고 원격 HEAD를 확인한다. CLAUDE.md·포털·Supabase·시스템 별도 미커밋 수정은 제외하고 해시로 보존을 확인한다. evidence는 로컬 보존한다. 새 세션은 사용자가 직접 시작한다.
