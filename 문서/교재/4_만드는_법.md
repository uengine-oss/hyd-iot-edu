## 2. 내용과 전개를 검증하는 순서

1. 최신 사용자 범위·실라버스 원문·사실표·분할 원본·기존 검토 근거를 읽는다. 기존 검토와 이번 실제 확인을 구별하고 시작 해시를 새 근거 폴더에 저장한다.
2. 실라버스 상세 항목 → 단원·장 → 설명 → 실제 랩의 목적·판정 조건을 대응시킨다. 선수 개념, 정식 용어·정의·이유, 사례·조건·예외·복습·퀴즈·정답의 위치를 확인한다. 제목 목록이나 키워드 검색만으로 내용 검토를 완료했다고 하지 않는다.
3. 변경이 필요한 문장은 앞뒤와 실제 촬영 경계까지 읽는다. 아직 배우거나 수행하지 않은 활동을 완료했다고 말하는지, 출처 없는 값이나 현재 구현을 일반 원리처럼 설명하는지 확인한다. 이론의 실습 간지·설명은 이론 파일 안에 두고 실제 실습 삽입·재개는 비낭독 표시로 구별한다.
4. 수정 전후 원문·위치·이유·근거와 영향을 남긴다. 이미 허용된 수정은 다시 승인을 요청하지 않고 해당 범위에서 끝낸다. 근거 없는 확장이나 문체 취향을 이유로 전부 재작성하지 않는다.
5. 수정 원본 → 해당 파생물 → 정적 검증 → 필요한 렌더 확인 순서로 진행한다. 사실·의미·전개 검토, 원문 정합성, 화면 배치는 서로를 대신하지 않는다.
6. 같은 산식으로 변경 전후 낭독 추정을 계산한다. 한글 음절 + 숫자×1.6 + 영문 글자×0.6을 275로 나누며 영문 뒤 한글 독음은 기존 도구의 치환 규칙을 따른다. 제목·제작 메모는 발화 시간에서 빼고 학습 대기는 별도 기록한다. 조작·AI 응답·전체 진행 시간으로 단정하거나 목표 시간에 맞추지 않는다.
7. 확정 항목·구체적 미해결·촬영 확인을 분리해 현황·남은 일·인계·제작기록을 갱신한다. 실제 확인하지 않은 청취·PowerPoint 앱·실행 성공을 기록하지 않는다.

## 3. 화면·삽화·조립 참조 수정

### 수정과 빌드

- 장 제목을 바꾸기 전에 현재 원본대응·목차·구성.json·ORDER와 손질 문자열을 검색한다. 손질은 원문에서 정확히 한 번 대응해야 한다. 실패한 손질을 무조건 지우지 말고 회차 표기·빠진 장 참조·용어 보완 등 원래 목적이 현재 원본에서 이미 해결됐는지 판단한다.
- 장 추가가 실전반에 자동 배정되는 것은 아니다. 실라버스 행·단원 경계에 맞춰 가져온 장과 새 표지/목차/복습·퀴즈를 대응시키고 선수 개념·누락·중복을 확인한다. 공식 실라버스는 사용자가 변경한 판본만 적용한다.
- 화면 변경은 `.claude/skills/lecture-deck/scripts/deck2pptx.py`의 현행 인자와 `.claude/skills/lecture-deck/references/덱MD-PPTX형식.md`에 맞춘다. `python <빌더> --check <원고>`로 형식을 검사하고, 실제 지원되는 원고·출력 인자로 해당 PPTX를 만든다. 저장 위치는 `산출물/교재/PPTX/<과정>_온라인/`과 `산출물/교재/PDF/<과정>_온라인/`이다. 과거 예제의 `만들기/` 출력 경로로 최신 배포본을 대신하지 않는다.
- 발표자 노트만 바뀌면 현재 분할 발화를 노트에 반영하고 화면 XML·관계·미디어 바이트 불변을 검사한다. 덱 PDF 화면이 같으면 다시 렌더·생성하지 않는다. 내용이 바뀐 이론 낭독 PDF는 다시 만든다.
- PowerPoint 잠금 파일(`~$…pptx`)이 있으면 해당 출력 파일이 열려 있는지 확인한다. 렌더의 LibreOffice 프로세스를 강제로 종료하지 않는다.

### 그림과 라벨

라벨의 글·좌표·폭은 덱 MD 요소를, SVG 형상은 해당 `figures/만들기_삽화.py`를, 실제 데이터 그래프는 `figures/만들기_그래프.py`와 원자료를 수정한다. 그림체·색·선 굵기는 기존 `삽화_기본.py` 계열을 유지한다. 같은 생성기가 여러 그림을 다시 쓸 수 있으므로 변경 파일과 해시를 확인한다. 승인된 그림을 이유 없이 재생성하지 않는다.

그림 파일명으로 현재 덱 MD를 검색해 실전반의 공통 그림 참조까지 찾는다. 그림이 바뀌어도 덱 MD diff는 없을 수 있다. 참조 장을 실제 크기 렌더로 확인하여 라벨 어긋남·선과 글자 충돌·빈 그림을 잡는다.

### 렌더와 배포 검사

렌더는 새 근거 디렉터리의 짧은 경로에 둔다. 묶음 그림은 한 장당 최대9페이지로 만들고 글자가 작은 부분·의심스러운 장은 개별 PNG로 본다. 잘림·겹침·낱말 하나가 떨어진 줄·작은 글자·불필요한 큰 빈칸·코드 하단·화살표·그림 누락·앞뒤 연결을 확인한다. 변경 PDF는 모든 페이지를 검증한다. 기존 검증본과 픽셀이 동일한 페이지와 이번 직접 본 변경 페이지를 구별해 기록할 수 있다.

원본/산출물의 장수·구성표·원본 대응·현재 산출물 목록을 맞춘다. 전체 과정 ZIP을 자동 재생성하지 말고 요청된 배포 묶음의 대상 파일 목록과 ZIP 내부 목록·바이트를 확인한다. 보호 대상 시스템 현황은 이번 교재 작업에 섞지 않는다. 장수 변경이 그 문서에 영향을 주면 별도 동기화 필요를 기록한다.

## 4. 대본·낭독본·발표자 노트·PDF

이론과 실습 모두 사용자 강사 본인이 실제 말할 문장을 원본에 쓴다. 제목·구성표·조작·촬영 메모·입력할 프롬프트는 비낭독 표시로 분리한다. 설명을 “강사가 설명한다”라는 지시로 대체하지 않는다. 시스템에서 강사라는 권한 역할을 설명하는 말과 화자 자신을 제삼자로 부르는 말은 구별한다.

| 원본 변경 | 갱신 순서 | 완료 확인 |
|---|---|---|
| 이론 분할 발화 | 화면 원고의 노트·PPTX 노트 → 이론 합본·개별 낭독본·회차 낭독 합본 → 이론 대본 PDF 및 같은 내용의 배포 사본 | 장 범위/순서/노트 일치, PDF 원문, 변경 페이지 배치, 화면 불변 또는 화면 변경 검증 |
| 실습 분할 발화 | `NN회차/낭독본/<분할파일명>.md` → 랩 `강사대본.md`·HTML → 개별 강사대본 PDF·회차 `실습_낭독합본.md`·실습대본 PDF → 해당 ZIP | 개별 낭독본도 반드시 검사. 합본·PDF 통과로 개별 낭독본 누락/구버전을 덮지 않음 |
| 구성·확정 상태 | 구성.json → 구성표·합본의 구성표 | 이론·랩 확정과 실습 대본의 촬영 튜닝 가능 상태 구분 |

이론 합본에는 실제 실습 발화를 섞지 않는다. 실습 간지·설명·복습 재개 구간은 이론 구성에 유지한다. 실습은 별도 낭독 합본과 PDF로 제공한다. 낭독본 생성 시 `>` 제작 메모와 구분선을 빼고 강조 표지만 제거한다. 제목은 탐색 표지이며 낭독하지 않는다. 본문을 요약하거나 발화 문단을 빠뜨리지 않는다.

현행 합성 코드는 실전반 `만들기/labs/online/revision20261019/sync.py`, 공통 문서 검사는 `만들기/labs/online/finalize20261019/audit.py`다. sync.py는 양쪽 현재 원본을 읽고 개별 실습 낭독본까지 생성한다. audit.py는 해당 낭독본의 존재와 원문 일치도 검사한다. 이 도구는 화면을 새로 그리는 전체 덱 빌더가 아니다.

**재사용 전 필수:** sync.py·finish_checks.py·metrics.py에는 과거 근거 경로가 들어 있다. 새 검증 폴더를 지정하고 새 시작 해시와 기준을 분리한 뒤 요청된 범위만 실행한다. 과거 before.json·검사 결과·렌더에 덮어쓰지 않는다. edit.py·manufacturing.py·refine.py·closeout.py·이번 repair_speech.py 등 일회성 편집/기록 도구는 다시 실행하지 않는다. 변경 없는 회차를 생성기로 반복 덮지 않는다.

대본시간·묶음그림 도구는 통합반 `만들기/tools/deck/대본시간.py`·`시트.py`, 실전반 `production/tools/deck/대본시간.py`·`시트.py`에 있다. 실제 파일과 인자를 확인해 사용한다. 시간 도구의 옛 하한 경고는 합격 기준이 아니다. PDF는 현재 낭독 원문에서 생성하고 원문 일치·전쪽 배치·복사본 바이트를 검사한다. 폰트·크기·줄간격은 기존 검증된 제작 방식을 유지한다.

## 5. 랩 자체·자료·온라인 진행·오프라인 배포

### 제조 업무와 PBL 연결

랩마다 결정할 업무, 입력과 출처, 조건·예외, 구현할 기능, 결과 확인 방법, 다음 단계에서 가져갈 산출물을 연결한다. 난이도를 올리려고 기능 수를 늘리지 않는다. 도구 열기 같은 준비 단계는 뒤 업무를 위한 짧은 단계로 둔다. 특히 실전반의 기록 추적 → 지식 구조·판단 → 근거 추출 → 에이전트·도구 → 명세·검증 → 승인·실행 → 종합 제조 조율이 재사용할 명세·지식·출력 계약·BPMN·검증 기록으로 남아야 한다.

입력·시작본·참조 완성본을 분리한다. 원문·교육용 가상 자료·제공 실행 발췌의 성격과 시점을 표시한다. 같은 이름이라는 이유로 다른 설비·요청·판본을 합치지 않는다. 앞 결과를 다음 폴더의 input에 가져오되 빈 양식이나 제공 완성본으로 덮어쓰지 않는다. 결과 생성·수정·재확인·저장·재열기를 흐름에 포함하고, 실제 실패가 없는데 정상 자료를 망가뜨려 실패를 연출하지 않는다.

첫 코딩은 목적과 요구에서 AI 탐색 → 현재 준비·미구현 확인 → 요구와 완료 기준 → 필요한 계획·구현 → 원문과 결과 대조로 간다. 이후에는 익힌 방법을 재강의하지 않고 새 조건·요구·검증을 설명한다. SDD·BDD는 해당 학습 시점과 업무에 필요한 범위에 둔다. 실제 명령은 촬영용 절차로 표시하며 이번 문서 작업에서 실행하지 않는다.

### 온라인

강사 혼자 자료를 내려받아 압축을 풀고 VS Code에서 작업한다. 학생이 가이드를 읽거나 답할 시간을 넣지 않는다. HTML은 제작 참고 자료다. 파일 목록·소스 해설을 본론으로 늘리지 않고 입력할 프롬프트·스킬·명세·판단 근거·실제 결과를 보여 준다. 실습 대본의 내용과 순서는 랩·가이드에 맞춘 상태로 확정하며, 발화·전환·진행 속도는 촬영 때 튜닝할 수 있다.

### 오프라인 학생용 가이드

학생 배포 폴더와 강사 solution·제작 기록을 분리한다. Copilot이 정답을 읽지 않도록 강사 완성본을 학생 시작 폴더 안에 넣지 않는다. 기존 안내·산출물 경로는 유지하고 새 구조로 옮길 때 실제 배포 안내를 함께 갱신한다. 새 코드 이름은 해당 STRUCTURE의 재사용 가능한 영어 이름 규칙을 따르되 기존 한국어 입력자료·참조를 일괄 개명하지 않는다. 키·실제 접속값을 배포물에 넣지 않는다.

1. 첫 화면은 만드는 결과와 진행 순서를 짧게 설명한다. 파일 이름 나열로 시작하지 않고 실제 단계에서 필요한 파일·도구를 소개한다. 받은 폴더는 VS Code 탐색기 구조로 알아볼 수 있게 보여 준다.
2. 작업 화면마다 화면 식별자, 목적, 직전 상태, 조작, 확인할 부분을 둔다. 짧은 설명과 표시가 사진을 안내해야 하며 필요한 조건·예외를 사진만으로 대신하지 않는다.
3. 결과 화면에는 확인할 값·상태·출처·판정 기준을 붙인다. 결과가 다르면 원문/입력/조건을 확인하고 수정·재검증하도록 연결한다. 기대값과 실제 관측값을 분리한다.
4. 입력할 프롬프트·스킬·명세는 사진 속 글자만으로 제공하지 않는다. 선택·복사·수정 가능한 HTML 텍스트 또는 별도 파일로 제공하고 가이드에서 링크한다. 예시·빈 양식·학생 작성 결과를 구분한다.
5. 저장 위치·다시 열어 볼 항목·다음 랩에 넘길 판본을 안내한다. 이어지는 랩은 앞 결과의 파일/식별자/출력 계약을 실제로 받아 이어 쓰도록 설계한다.
6. 지금은 `미촬영` 자리와 필요한 장면·확인 기준·파일 위치를 기록한다. 실제 작업·결과 사진과 촬영 환경·판본은 후속 허용된 촬영에서 채운다. 임의 화면을 실제 결과처럼 만들지 않는다. 이 제작 절차 복원이 오프라인 전 과정 제작·실행 완료를 뜻하지 않는다.

### 정적 검사와 배포 완료 조건

자료 참조 경로·식별자·명세 입출력·값/단위·시점·조건을 대조한다. Python은 AST, JSON/XML/BPMN은 파싱만 하며 학생 코드 import나 테스트 실행을 하지 않는다. 구문 통과는 구현 성공이 아니다. HTML의 내용·순서·로컬 링크와 복사 자료 해시를 확인하고 ZIP 내부 목록·각 파일 바이트를 배포 폴더와 비교한다. 이전 ZIP의 루트 폴더 접두어를 유지한다. 가이드/강사대본이 달라지면 ZIP도 갱신한다.

## 6. 실라버스 변경·촬영·게시

사용자가 새 실라버스를 주면 이론 제목/상세 항목은 단원·사실표·장으로, 실습 추가/삭제/제목은 간지·설명·실습 목록·구성으로, 이론↔실습 변경은 촬영 경계로 대응한다. 시간 행 변경을 내용 삭제·늘리기로 바로 처리하지 않는다. 실전반·오프라인만 바뀌면 공통 원본을 새로 쓰기 전에 배정과 단원 조립을 확인한다. 바뀌는 범위를 알리고 이미 허용된 작업은 영향 범위에서 수행한다.

실제 AI·코드/테스트·HYD/DB·MCP·브라우저·캡처·음성/영상은 별도 촬영 범위다. 환경 준비는 시스템의 현행 운영 문서를 따르며 다른 프로젝트의 포트·데이터를 임의로 변경하지 않는다. 현재 문서 작업에서는 서비스나 워커를 시작하지 않는다. 음성/영상 도구의 존재를 실행 허용으로 해석하지 않는다.

변경 전후 장수·발화·낭독 추정·랩·산출물 수와 실제 검증/미검증을 기록한다. 허용된 교재 경로만 커밋·푸시하고 원격 HEAD를 확인한다. CLAUDE.md·포털·Supabase·시스템 별도 미커밋 수정은 제외하고 보존을 확인한다. 근거·렌더·캐시는 로컬 evidence에 둔다. 새 세션은 자동 생성하지 않는다.
