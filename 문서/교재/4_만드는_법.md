# 교재 4. 만드는 법

지금 쓰는 도구와 순서만 적는다. 지킬 규칙은 `2_기준.md`에 있다. 명령은 모두 저장소 루트에서 실행하고, 실제로 돌려 본 것만 적었다.

필요한 것: `uv`, `python3`. 렌더에는 LibreOffice(`soffice`) · `pdftoppm` · 맑은 고딕 글꼴, 대본 PDF에는 `pandoc`과 Chromium 계열 브라우저가 필요하다. 렌더 폴더 · 묶음 그림 · 중간 PDF · `__pycache__`는 저장소에 두지 않는다.

## 1부. 덱

### (가) 고칠 파일

| 고치려는 것 | 고칠 파일 |
|---|---|
| 덱의 장(모든 반 공통) | 원 덱 `만들기/decks/integrated/dayNN/통합반_NN일차.md` |
| 삽화 라벨의 글 · 위치 | 같은 덱 MD의 그 장 요소(`라벨 \| 설명 \| x,y[,폭]`). 그림은 그대로 |
| 그림 자체 | 그 회차의 `figures/만들기_삽화.py`(SVG), 실제 데이터 그래프는 `figures/만들기_그래프.py`(PNG) |

덱 MD가 원본이고 PPTX는 거기서 다시 만든다. 덱 MD를 고치지 않았으면 저장소의 PPTX를 덮어쓰지 않는다. 형식(장 유형 · 칸 · 요소 수 · 아이콘)의 전체는 `.claude/skills/lecture-deck/references/덱MD-PPTX형식.md`다.

### (나) 검사와 빌드

```bash
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py --check 만들기/decks/integrated/day03/통합반_03일차.md
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py \
  만들기/decks/integrated/day03/통합반_03일차.md 산출물/교재/PPTX/통합반_온라인/통합반_03일차.pptx
```

- `--check`는 파일을 쓰지 않고 규칙 위반과 넘침 추정을 장 번호 · 칸 이름과 함께 모아 찍는다. 걸리면 문구를 다듬거나 장을 나누거나 유형을 바꾼다.
- 삽화 라벨은 글자 자리 둘레 0.1인치 안에 그림의 선 · 다른 라벨이 들어오면 실패한다. 라벨 좌표 · 폭이나 그림의 배치를 옮긴다.
- 카드 · 비교 · 흐름 · 단계는 내용이 적으면 빌더가 글자를 본문 영역의 80 %까지 키운 뒤 같은 넘침 검사를 한다.
- PowerPoint에서 그 PPTX를 열어 둔 채(`~$…pptx`)면 덮어쓰기가 실패할 수 있다.

### (다) 렌더와 묶음 그림

```bash
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py \
  만들기/decks/integrated/day03/통합반_03일차.md <작업 폴더>/d03.pptx --render <작업 폴더>/d03_r1
uv run --no-project --with pillow python 만들기/tools/deck/시트.py <작업 폴더>/d03_r1 <작업 폴더>/d03_sheet --cols 3 --per 9
```

- 렌더 폴더는 매번 새 이름으로, 저장소 밖 작업 폴더에 둔다. 렌더는 파일 잠금으로 한 번에 하나씩 돈다(다른 렌더가 돌면 기다리고, `soffice`를 죽이지 않는다).
- 볼 것: 넘침, 겹침, 잘린 글자, 낱말 하나만 떨어진 줄, 글머리표 둘째 줄의 들여쓰기, 작은 글자, 큰 빈 칸, 코드 상자 아래 잘림, 빈 그림(2_기준 51번). 의심스러운 장은 렌더 폴더의 원본 PNG(`*-NN.png`)를 연다.

### (라) 그림 고치기

```bash
cd 만들기/decks/integrated/day10/figures && python3 만들기_삽화.py                                       # SVG (표준 라이브러리만)
cd 만들기/decks/integrated/day03/figures && uv run --no-project --with matplotlib python 만들기_그래프.py   # 그래프 PNG
```

- 스크립트는 그 폴더의 SVG를 모두 다시 쓴다. `git diff --stat`으로 의도한 그림만 바뀌었는지 본다. 1회차 `만들기_삽화.py`는 승인된 그림을 다시 쓰지 않게 되어 있다.
- 화풍은 `삽화_기본.py`(1회차 조각의 사본)에서 가져온다. 그래프 꼴 그림에서 원 안 라벨이 들어가지 않으면 원과 간격을 키운다(지도와 같은 축척 1인치 = 100).
- 그림을 고친 뒤에는 그 그림을 쓰는 장을 원본 크기 PNG로 본다.

### (바) 다른 반의 하루치 덱

새 방식(2_기준 12번): 그날의 회차 덱들에서 표지를 떼고 회차를 이어 붙인 뒤 그날 표지 하나를 앞에 붙인다. 이 일을 하는 도구는 아직 없다(`6_남은_일.md` 0절 4번).

옛 방식: `만들기/decks/practical*/`, `integrated-offline/`의 `조립.py` 27개와 `.claude/skills/hyd-course-deck/scripts/재조립.py`는 장 제목으로 장을 찾아 문구를 손질하던 도구다. 원 덱의 장 제목이 모두 바뀌어 지금 돌리면 멈춘다. 쓰지 않는다.

### (사) 도구의 알려진 제약

| 제약 | 내용 | 걸렸을 때 |
|---|---|---|
| 메시지 | 한 줄(16pt, 한글 대략 46~60자) · 한 문장 | 문장을 줄인다 |
| 제목 | 28pt 한 줄. 표지와 간지만 ` / `로 줄을 끊는다 | 제목을 줄인다 |
| 요소 수 | 카드 2~4, 비교 2, 흐름 2~6, 단계 3~5, 풀이 2~6, 표 2~9, 구조 2~12, 파이프라인 3~7, 관계도 2~8, 코드 · 그림의 짚을 점 0~4, 문답 보기 2~5, 목차 2~9 | 장을 나누거나 유형을 바꾼다 |
| 요소 한 줄 | `칸1 \| 칸2 \| 칸3`까지(표도 3열). 표의 셋째 칸은 ` / `로 세 줄까지. 카드 · 비교의 꼬리표가 칸보다 넓으면 실패 | 넷째 열은 칸2 안에 ` / `로 나누거나 장을 나눈다 |
| 삽화 라벨 | 16개까지, 가운데 정렬, 크기 두 단계(`라벨: 큰`). 셋째 칸 `x,y[,폭]`, 폭 기본은 그림 폭의 16 %. 이름 칸을 비우면 설명 줄만 작게 | 끊기면 폭을 넓히거나 풀네임을 설명 줄로 |
| 코드 장 | ` / `는 줄바꿈, 글자 빗금은 `\/`. 상자 높이는 본문 영역을 넘지 못한다 | 길면 렌더로 보고 장을 나눈다 |
| `**` | 강조색. 칸1 전체를 감싸면 강조 칸. 짝이 안 맞으면 뒤가 모두 강조 | 짝을 맞춘다 |
| 빼기표 `−`(U+2212) | 화면 문구에 있으면 실패(덱 글꼴에 없다) | 하이픈(-) |
| 없앤 칸 | `핵심` `설명` `다음` `현재` | 형식 문서의 허용 칸 |
| 아이콘 | 유형마다 수가 정해져 있다(파이프라인은 필수) | `scripts/find_icon.py <낱말>` |
| 그림 경로 · 관계도 좌표 | 덱 MD 기준 상대 경로, 파일이 없으면 실패. 관계도의 두 원이 너무 가까우면 실패 | 경로를 고치거나 좌표를 벌린다 |
| 렌더 | 경로가 약 235자를 넘거나 맑은 고딕이 아닌 글꼴로 그려지면 멈춘다. 20분을 넘기면 끊는다 | 짧은 경로, 맑은 고딕 설치 |

도구의 한계는 우회하지 않고 도구를 고친다(2_기준 45번). 도구를 고치면 덱 여럿을 렌더해 본다. 스킬(도구 · 형식 문서)의 유일한 원본은 저장소의 `.claude/skills/`다.

### (아) 커밋과 push

교재 작업은 구간이 끝나면 커밋하고 작업 브랜치 `claude/hyd-handoff-work-xziutz`에 push한다(2_기준 48번). `git status`와 경로별 diff로 잠금 파일 · 렌더 · 캐시 · 비밀값이 섞이지 않았는지 본 뒤 경로를 지정해 커밋하고, `git pull --rebase`(autostash 없이) 뒤 push한다.

## 2부. 새로 만들기와 다시 짜기

### 0. 덱과 대본을 함께 설계하고 확인하는 흐름

| 단계 | 할 일 | 남길 근거 |
|---|---|---|
| 1. 범위 | 최신 요청 · 실라버스 원문 · 사실표 · 현재 원고 · 결정을 읽는다 | 원문과 버전, 미결 |
| 2. 대응과 전개 설계 | 실라버스 상세 항목과 압축 전 원고를 대응시킨다. 단원의 물음, 선수 개념, 핵심 메시지, 화면 근거와 말로 풀 순서를 함께 짠다 | 항목 → 화면 · 노트 · 대본, 보강 · 삭제 까닭 |
| 3. 대표 단원 | 덱과 대본을 함께 쓰고 정의 · 전후 · 실제 값 · 그림이 설명을 받치는지 본다. 사용자 승인 | 대표 단원의 덱 · 대본 |
| 4. 확장 | 승인된 방향을 나머지에 넓힌다. 쓰고 다듬는 데까지 세션이 한다 | 혼란이 생긴 곳과 해결 |
| 5. 검사 · 시간 | `--check` → 바뀐 장과 연결부 렌더 → 낭독본을 뽑아 단원 통독 → `대본시간.py`. 새 정의 · 값이 생기면 덱으로 돌아간다 | 실제 검사 출력, 구성표, 확인하지 못한 범위 |
| 6. 사용자 검증 | 사용자가 직접 아스트라로 검증 · 피드백 수정을 한다(세션은 부르지 않는다) | — |
| 7. 동기화 · push | PPTX · 낭독본 · 대본 PDF · 하루치 덱 · 배포 묶음 · `3_현황.md` · `6_남은_일.md`를 맞추고 push | 갱신한 파생물, 보류 목록 |

시간 조율에서 내용이 바뀌면 영향받는 단계로 돌아간다. 시간을 먼저 정해 장 뒤에 문단을 덧붙이지 않는다. 최종 확인은 2_기준 9절이다.

### 1. 실라버스가 바뀌었을 때

실라버스는 사용자가 직접 쓴다. 바뀐 xlsx를 받으면 고치기 전에 무엇이 달라지는지 먼저 사용자에게 말한다.

| 바뀐 것 | 할 일 |
|---|---|
| 이론 행의 제목 · 상세 내용 | 해당 단원과 대조해 빠진 항목을 사실표 근거로 더한다. 근거가 없으면 사실 조사부터 |
| 이론 행의 시간 | 장수부터 바꾸지 않고 설명의 깊이와 회차 배분을 다시 본다(2_기준 32 · 33번) |
| 실습 행 | 실습 간지와 설명 장(2장)을 더하거나 빼거나 고치고 `실습_목록.md`를 다시 뽑는다 |
| 이론 ↔ 실습 구분 | 덱의 틀과 목차의 구분을 바꾼다(예: ProcessGPT 이론 단원 → 시연 실습) |

실라버스 읽기:

```bash
uv run --no-project --with openpyxl python -c "import openpyxl; wb=openpyxl.load_workbook('문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx'); print(wb.sheetnames)"
```

네 시트(통합반 온라인 44H, 실전반 온라인 32H, 통합반 오프라인 정규 10회, 실전반 오프라인 정규 9회)의 열은 `구분 | 제목 | 상세 교육 내용 | 시간(분)`이고, 회차마다 머리 줄, 시트 끝에 「운영 유의」와 「실습 사전검증」 줄이 있다.

#### 3.2 새 틀의 랩

통합반 오프라인 5회차 실습 2 「설비 이상 원인을 추론하는 에이전트 직접 제작하기」(50분) 하나다. 학생 `산출물/실습/통합반_오프라인/05회차_실습2_원인_추론_에이전트/코드`, 완성본 `산출물/실습/통합반_온라인/05일차_실습2_원인_추론/코드`, 강사 `만들기/labs/offline/05-2-cause-agent`.

- 에이전트가 도구 넷(`find_causes`, `get_evidence`, `read_sensor`, `get_actions`)으로 사례 11건의 원인을 가린다. 사내 LLM 서버로 단계마다 실제로 돌렸다. 규칙 8줄에서는 사례 하나가 호출 횟수 한도에 걸렸고, 읽을 값을 증거로 한정하는 9번째 줄을 넣자 11건 모두 답했다.
- 확인하지 못한 것: 가이드의 요청문 여덟 개를 Copilot에 보내 보지 않았다. 사진 자리 10곳이 비어 있다(`screenshots.md`). 사용자 검토 대기.

### 4. HYD 시스템을 띄울 때

절차는 `../시스템/4_켜고_돌리는_법.md`다. 같은 PC에서 다른 프로젝트가 5432 · 7474 · 7687 · 8080 · 8088 · 5432x 포트를 쓰고 있으면 저장소 파일은 고치지 않고: 업무 DB는 `it/supabase`를 임시 폴더에 복사해 포트를 바꿔 `npx supabase@2.119.0 start`로 띄우고, compose는 `SUPABASE_DSN` · `ENTERPRISE_READ_DSN` · `EFFECTS_SMTP_PORT`를 셸 환경변수로 주며 겹치는 포트를 옮기는 덧씌움 파일을 `-f`로 더한다. 포털은 브라우저에서 8080을 직접 부르므로 자동 조작 브라우저에서는 그 요청을 옮긴 포트로 돌린다.
