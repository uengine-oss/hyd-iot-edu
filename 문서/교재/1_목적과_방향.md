# 교재 1. 목적과 방향

교재는 HYD 제조 AI 교육과정(경남대학교 피지컬AI 사관학교)의 강의 덱, 낭독 대본, 강의 영상, 실습 랩, 실습 촬영 대본을 말한다. 이 폴더(`문서/교재/`)만 읽으면 이어서 만들 수 있게 썼다. 앞 세션의 대화와 기억은 남아 있지 않다고 본다.

## 1. 읽는 순서

| 하려는 일 | 읽을 문서 |
|---|---|
| 무엇을 지켜야 하는지 | `2_기준.md` (공통 원칙과 상세 기준의 진입점). 실전반 이론만 다른 점은 `실전반_기준.md` |
| 덱, 대본, 윤문, 영상, 랩을 만드는 도구와 순서 | `4_만드는_법.md` |

공통 기준 아래 덱·실습·검증 상세 기준을 주제별로 나눈다. 그 밖에 이 폴더에 있는 것은 자료다: 사실의 근거 `사실표/`, 수업의 범위와 순서 `실라버스/`(정본 `피지컬AI_실라버스_최종본.xlsx`). 진행 기록 · 지난 근거는 main에 두지 않는다. 구조의 기준인 설계서 v3와 시스템(포털과 설비)에 관한 것은 `../시스템/`에 있다.

## 2. 누구에게 무엇을 가르치는가

- **대상은 노베이스 대학생, 취업 준비생이다.** 코딩을 모르는 사람이 대부분이다.
- **과정은 넷이다.** 통합반 온라인(44시간, 11일), 실전반 온라인(32시간, 8일), 통합반 오프라인(정규 10회), 실전반 오프라인(정규 9회). 온라인1은 공통이고 이후 이론·대본은 과정별이다. 포털·공통 도구의 절차·자료와 확정 Cypher 영상은 재사용한다. VS Code 랩은 같은 코어에 과정별 구현·활용 결과·검증 차이를 둔다. 상세는 `2_기준.md`와 최종 실라버스를 따른다.
- **온라인은 강사 한 사람이 영상으로 설명하고 조작해 보인다.** 오프라인은 학생이 직접 한다.
- **피지컬 AI의 전체 맥락은 설비·지식·판단·사람·실행의 연결이다.** 설비 데이터로 상황을 확인하고, 지식으로 원인을 검토하며, 에이전트가 제안하고 사람이 승인한다. 포털은 그 완성 흐름을 보여주고 VS Code는 주요 기능을 직접 구축·활용하는 곳이다. 아래 학습 도달 목표를 기준으로 편성한다.

## 최상위 학습 도달 목표 — C67

**온톨로지는 학생이 직접 구축할 수 있도록 이끈다.** 필요한 질문과 범위를 정하고, 클래스·관계·식별자·제약을 설계하고, 그래프를 구현하며, 절차·판단 조건과 문서 인제스천을 연결한다. 원문을 검토해 적재하고 처음 질문에 답하는 지식과 출처를 확인한다. 설비 사례를 통해 원리와 구축 과정을 충분히 이해하며, 다른 소재를 많이 나열하는 것을 목표로 삼지 않는다. 최종 결과는 질문·모델·문서·추출/검토·적재 코드·조회 검증을 갖춘 구축 결과다.

**에이전트는 범용적인 활용 범위와 구현·검증 방법을 경험하게 한다.** 설비 원인 점검뿐 아니라 품질 접수, 분석·시각화, 회의 후속 업무, 자기 자료 학습, 작성·검토 협업 등 목적·입력·도구·결과가 다른 활용을 연결한다. 같은 에이전트의 이름·자료만 바꿔 반복 제작하지 않는다. 어떤 일을 맡길 수 있는지와 어떤 자료·도구·권한·검증이 필요한지를 함께 판단한다. 활용 가능성이 넓다는 것을 모든 작업의 자동 성공으로 설명하지 않는다.

두 영역 모두 완성 답안을 실행하는 장난감 실습으로 끝내지 않는다. 학생이 요구·설계를 판단하고 직접 구현한 결과를 다른 입력·근거·기대 행동으로 검증한다. 마지막 업무 흐름과 교대 PBL은 이 구축·활용 경험을 종합한다. 과정별 대응과 제작 계약은 [VS Code 전체 흐름](근거/2026-10-27_VSCode랩_최종흐름.md)을 따른다.

## 3. 방향

> **원리와 까닭, 역할과 구조가 줄기다. 전문성 있게 다 알려 준다. 실제로 쓰이는 재료는 그 역할에 「이런 것들이 있다」로만 얹는다.**

재료(제품과 기술 이름)를 하나씩 설명하고 사용법을 알려 주는 교재가 아니다. 왜 이렇게 설계해야 했는지, 왜 이렇게 나눴는지, 각자 무슨 역할을 하는지를 전문성을 바탕에 두고 쉽게 풀어 간다. 자세한 기준은 `2_기준.md`에 있다.

## 4. 이 방향이 나온 곳

| 언제 | 무엇 | 요지 |
|---|---|---|
| 2026-10-01 | 설계 회의(대표, 이사) | 온톨로지와 에이전트를 많이 한다. 스카다 쪽은 많이 하고 싶지 않다. 시나리오 기반으로 가되 기술 딥다이브를 약간씩 넣는다. 계속 바뀌는 값은 그래프에 두지 않는다(기준 정보와 실황 정보). 설비와 납기 사이의 결정은 사람이 한다 |
| 2026-10-08 | 사용자의 실라버스 지시 | 가치 단위로 짠다. 「재료가 메인이 되면 안 된다.」 「왜 이걸 하고 어떻게 해서 이런 결과가 나오는가를 경험하게.」 하나의 스토리텔링. 질질 끌지 않는다. 미니가 장난감은 아니다 |
| 2026-10-10 | 교재 초안 검토 회의(이사, 교재 담당자) | 전문성이 모자란다. 용어를 가리지 않는다. 한 장에 주제 하나. 덱에는 개념만 싣는다. 구분은 이론과 실습 둘뿐. 사람이 쓴 문어체로. 전체 흐름(실라버스)은 좋다 |
| 2026-10-10 | 덱과 대본 제작 지시문 | 화면은 간결하게, 강사 설명은 자세하게. 대본만 읽어도 수업이 이어져야 한다. 같은 말을 되풀이해 분량을 채우지 않는다. 억지로 드라마처럼 만들지 않는다 |
| 2026-10-11 | 실라버스 최종본 | 사용자가 직접 썼다. 수업의 범위와 순서는 이것이 정한다 |
| 2026-10-12 | 실습 운영 원칙 | `기준_실습랩.md` · `기준_실습대본.md` |
| 2026-10-13~14 | 저장소를 정리한 세션의 대화 | `2_기준.md` 1절 |
| 2026-10-23 | 실전반 재편과 문서 정리 | 실전반 이론은 통합반 묶음의 압축판 + 단원별 실전 응용(`실전반_기준.md`). 가장 뒤의 결정이다 |

## 5. 저장소에 없는 것

새 PC에서 이어 하려면 따로 옮기거나 다시 마련한다.

| 무엇 | 왜 필요한가 | 없으면 |
|---|---|---|
| 키 파일 둘 | ElevenLabs 키(영상), 사내 LLM 서버의 주소와 키(오프라인 랩 실행) | 영상을 만들 수 없고, 랩은 저장된 실행 기록의 재생만 된다 |
| 강사 배정과 일정표 | 실명과 시수가 들어 있어 올리지 않는다 | 사용자에게 받는다 |
| Codex 로그인 | 윤문(gpt-6-astra)을 부를 때 쓴다 | 윤문을 보낼 수 없다 |

옛 1일차 영상 9편과 그 음성은 2026-10-14에 덱과 대본을 다시 쓰면서 쓸모가 없어졌다. 옮기지 않는다.

필요한 프로그램: Python 3, `uv`, LibreOffice(`soffice`), `pdftoppm`, `ffmpeg`.
