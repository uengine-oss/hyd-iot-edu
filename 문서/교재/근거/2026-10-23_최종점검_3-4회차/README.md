# 2026-10-23 3 · 4회차 대본 · 덱 최종 점검 — 진행 기록

1 · 2회차(`../2026-10-22_최종점검/`)와 같은 방법이다. 점검자는 모두 Opus 추론 최대이고, 저장소는 읽기만 하고 결과는 세션 스크래치에 쓴다. 끝난 점검자의 결과는 그때그때 이 폴더로 옮겨 커밋한다(사용자: 「커밋푸시 실시간으로 하면서요 … 한도 때문에 다시 이어서 해요」).

## 범위 — 회차마다 두 과정 모두

| 점검자 | 범위 | 상태 |
|---|---|---|
| A | 통합반 3회차 01~03(01 · 02의 확정 실전반 2회차 04편 공유 줄은 고정) + 실전반 3회차 01의 실전반 전용 줄 | **1차 끝** — `1차/A/` |
| B | 통합반 4회차 01 + 실전반 3회차 02의 실전반 전용 줄 | **1차 끝** — `1차/B/` |
| C | 통합반 4회차 02 + 실전반 3회차 03의 실전반 전용 줄 | **1차 끝** — `1차/C/` |
| D | 실전반 4회차 01 SLIDE 1~28 | **1차 끝** — `1차/D/` |
| E | 실전반 4회차 01 SLIDE 29~59 | **1차 끝** — `1차/E/` |
| F | 실전반 4회차 02 + 03 SLIDE 82~101 | **1차 끝** — `1차/F/` |
| G | 실전반 4회차 03 SLIDE 102~132 | **1차 끝** — `1차/G/` |

두 과정이 문단을 같이 쓰는 방식(`공유표/`): 실전반 3회차 = 통합반 3회차 03편 + 통합반 4회차, 실전반 4회차 = 통합반 5 · 6회차. 같은 문단은 한쪽에서 고쳐 `tools/merge4.py`가 다른 쪽에 줄 단위로 옮긴다(통합반 3 · 4 → 실전반 3, 실전반 4 → 통합반 5 · 6).

## 2단계(마지막 손질) 상태

- 4회차 쪽(D~G): 1차 결과를 `tools/merge4.py`로 모아 `제안_4회차/`를 만들었다(옮김 92 · 한쪽 전용 건너뜀 · 충돌 0). `tools/sharecheck.py`로 두 과정이 같이 쓰던 문단 514개를 대조해, 실전반에서만 바뀐 3문단은 모두 점검자가 「실전반 전용」으로 적은 편 경계 · 실습 안내 · 마무리 문장임을 확인했다. 낭독 줄의 「N %」는 확정 회차 표기대로 「N퍼센트」(`tools/pct.py`, 14줄). 마지막 손질 D2~G2 진행 중.
- 3회차 쪽(A~C): 1차 결과를 모아 `제안_3회차/`(실전반 3회차로 옮김 41 · 충돌 0). 같이 쓰던 문단 364개 중 실전반에서만 바뀐 4곳은 점검자가 「실전반 전용」으로 적은 LLM 풀이 · 마무리 문장. 통합반 3회차 01 · 02의 확정 2회차 공유 줄 변경 0(11장은 확정 2회차 문장과 「앞 회차에서 / 앞부분에서」만 다름 — 과정 사실 차이). 퍼센트 12줄. 마지막 손질 A2~C2 진행 중.

## 기준 (지시문 `1차_공통지시.md`)

0순위는 학생이 「지금 화면 어디를 말하는 거지?」 하고 놓치는 곳이다. 틀린 위치와 빠진 위치를 모두 본다. 그다음은 결함(내용 · 실습 안내 · 편 경계 · 퀴즈), 놓친 윤문(고친 문장이 앞뒤와 이어지게), 수준 낮은 학생을 위한 쉬운 설명(처음 나오는 용어를 생활 말로 한 번, 왜 필요한지, 사실은 사실표 · 코드로 확인), 덱(화면 뜻이 틀린 곳만)이다.

## 이어서 하는 순서

1. 남은 점검자 결과를 받는다. 장 그림은 `tools/deck_text.py` · soffice로 다시 만들 수 있고, 대응은 `tools/imgmatch.py`를 쓴다.
2. `tools/merge4.py <저장소> <점검 폴더> <출력>`으로 제안본을 만든다(범위 밖 변경 · 확정 2회차 공유 줄 변경이면 멈춘다).
3. `마지막손질_공통지시.md`로 마지막 손질(위치 재확인 · 이음새 윤문 · 사실 검산 · 의심 반영 · 쉬운 설명 검산)을 돌린다.
4. 통합 → 대본 · 덱 글 · 덱 원고 MD 반영 → 발표자 노트를 대본과 같게(`../2026-10-22_최종점검/tools/notes.py`) → 영상 도구 `--dry` → `tools/report34.py`로 3 · 4회차 전 · 후 HTML · MD → 문서 갱신 → 커밋 · 푸시(develop → other-pc 병합).

같은 날 1 · 2회차 덱 네 개의 발표자 노트를 확정 대본과 같게 맞췄다(통합반 1회차 34장, 2회차 43장, 실전반 1회차 46장, 2회차 74장 — 화면 글 변화 없음 확인).
