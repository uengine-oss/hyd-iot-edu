# 지시문 모음

이 문서는 덱을 새로 만들거나 전체를 다시 점검할 때, 작업자(서브에이전트 또는 다른 세션)에게 줄 지시문을 고를 때 읽는다.

교재를 만든 세션이 실제로 쓴 지시문 열다섯 개다. 내용은 줄이지 않았고 공개 저장소에 맞게 경로만 자리표시로 바꿨다. 단계의 흐름과 배운 점은 `../4_만드는_법.md` 2부에 있다.

## 자리표시와 읽는 법

| 표기 | 뜻 |
|---|---|
| `<저장소>` | 저장소 루트(`hyd-iot-edu`를 내려받은 폴더) |
| `<작업 폴더>` | 저장소 밖의 임시 작업 폴더. 지시문 본문의 「scratchpad」가 이것이다. 렌더 폴더, 묶음 그림, 계획표, 검토서처럼 저장소에 올리지 않는 것을 둔다 |
| 「프롬프트가 알려 준다」 | 지시문은 여러 작업자에게 같이 주는 공통 문서이고, 작업자마다 다른 것(맡은 일차, 사실표 파일, 산출물 이름)은 조율자가 프롬프트에 따로 적어 주었다 |
| 「조율자」 | 작업을 나눠 주고 결과를 합친 세션. 커밋과 push는 조율자만 했다 |

지시문은 쓰인 시점의 상태를 적고 있다(「통합반 1~4일차 덱이 완성돼 있고」, 「사용자는 자고 있고 결과만 본다」 등). 다시 쓸 때는 그 문장을 지금 상태에 맞게 고친다.

## 어느 단계에 쓰는가

| 파일 | 단계 | 작업자가 하는 일 | 고치는가 |
|---|---|---|---|
| `사실조사_지시.md` | 새 일차 ① 사실 조사 | 저장소를 읽어 기술 사실표를 쓴다 | 사실표 파일 하나만 새로 쓴다 |
| `새일차쓰기_지시.md` | 새 일차 ② 쓰기 → 검토 → 반영 | 통합반 원 덱 한 일차를 쓰고, 검토자를 하나 불러 반영까지 한다 | 덱을 만든다 |
| `새일차검토_지시.md` | 새 일차 ③ 검토 | 위 작업자가 부르는 검토자가 따른다 | 고치지 않는다 |
| `실전반계획_지시.md` | 조립 덱 ① 계획표(실전반 온라인) | 통합반 덱에서 가져올 장의 순서표와 새 장 명세를 쓴다 | 고치지 않는다 |
| `실전반쓰기_지시.md` | 조립 덱 ② 조립 | 계획표대로 `조립.py`와 `새장_*.md`를 쓰고 빌드한다 | 덱을 만든다 |
| `실전반검토_지시.md` | 조립 덱 ③ 검토 | 조립 탓에 생긴 문제(끊긴 흐름, 정의 없는 용어)를 찾는다 | 고치지 않는다 |
| `오프라인계획_지시.md` | 조립 덱 ① 계획표(오프라인 과정) | 회차마다 계획표를 쓴다 | 고치지 않는다 |
| `오프라인쓰기_지시.md` | 조립 덱 ② 조립 → 검토 → 반영(오프라인 과정) | 회차 덱을 조립하고 검토자를 하나 불러 반영한다 | 덱을 만든다 |
| `오프라인일괄_지시.md` | 조립 덱 ①~③을 한 작업자가 | 위 두 문서를 이어서 하도록 바꾼 점만 적었다. 두 문서와 함께 준다 | 덱을 만든다 |
| `오프라인맞춤_지시.md` | 조립 덱 ④ 과정 전체 맞춤 | 회차 묶음을 나눠 만든 뒤 풀네임 자리, 전제, 겹친 퀴즈, 틀을 맞춘다 | `조립.py`와 `새장_*.md`만 |
| `전체점검_지시.md` | 전체 점검 ① 점검 | 맡은 덱 묶음을 읽어 점수표와 고칠 것 목록을 낸다 | 고치지 않는다 |
| `점검반영_지시.md` | 전체 점검 ② 반영(통합반 원 덱) | 점검 결과와 「덱 사이의 결정」 여덟을 원 덱에 반영한다 | 통합반 원 덱만 |
| `조립재작업_지시.md` | 전체 점검 ③ 재조립 | 고쳐진 원 덱에 맞춰 조립 덱을 다시 만들고 조립 덱의 점검 결과를 반영한다 | `조립.py`와 `새장_*.md`만 |
| `화면확인_지시.md` | 따로 쓰는 것: 전 장 화면 확인 | 완성 덱을 렌더해 화면의 결함만 찾는다 | 고치지 않는다 |
| `원덱결함_지시.md` | 따로 쓰는 것: 원 덱의 작은 결함 수정과 재조립 | 조립 작업자들이 보고한 원 덱의 결함을 고치고 조립 스크립트를 모두 다시 돌린다 | 통합반 원 덱과 손질 목록 |

## 지시문이 가리키지만 저장소에 없는 것

지시문 본문은 그때 `<작업 폴더>`에 있던 파일을 가리킨다. 아래는 저장소에 남기지 않았다. 다시 쓸 때는 그 단계의 산출물을 새로 만든다.

| 지시문이 가리키는 것 | 무엇이었나 | 지금 대신할 것 |
|---|---|---|
| `실전반계획_0N일차.md`, `오프라인계획_<과정>_<NN>회차.md`, `오프라인계획_<과정>_요약.md` | 계획 단계의 산출물(계획표) | 형식은 `실전반계획_지시.md`의 「산출물」 절에 다 적혀 있다. 조립 결과는 각 덱 폴더의 `조립.py`가 계획표를 대신한다 |
| `새일차검토_0N일차.md`, `실전반검토_0N일차.md`, `오프라인검토_*.md` | 검토 단계의 산출물(검토서) | 반영이 끝나 남기지 않았다 |
| `전체점검/결과_*.md` 여섯 개 | 전체 점검의 결과 | 점수표와 요지는 `../3_현황.md` 5절에 옮겼다 |
| `점검반영/` 아래의 영향 목록(`조립영향_통합반_01-04.txt` 등) | 원 덱을 고친 작업자들이 낸 「조립에 영향」 표 | 다음에 원 덱을 고칠 때 `점검반영_지시.md`의 보고 형식대로 다시 받는다 |
| `조립재작업_지시.md`의 `git diff 5747907 HEAD` | 그때 원 덱이 고쳐지기 전의 커밋 | 다시 쓸 때는 원 덱을 고치기 직전의 커밋으로 바꾼다 |
| `원덱결함_지시.md`의 「고칠 목록」 열다섯 항목 | 그때 보고된 결함. 모두 처리했다 | 목록의 모양만 본보기로 쓰고 항목은 새로 채운다 |
