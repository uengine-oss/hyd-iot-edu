# 장부 분류 의뢰서 (모든 묶음 공통)

**서브에이전트 생성 금지(직접 읽는다).** 저장소: `D:/work/study/hyd-iot-edu-system`. 쓸 수 있는 파일은 자기 묶음의 `문서/교재/근거/기준정리/분류/결과_<묶음>.tsv` 하나뿐이다. 다른 파일은 고치지 않는다. git 명령으로 상태를 바꾸지 않는다.

## 할 일

장부의 행(원본 문서의 문장 하나 또는 표 행 하나)마다 「갈래 · 갈곳 · 핵심어 · 메모」를 정한다. 목적은 교재 기준 문서를 작업당 두 개(진입 `2_기준` + 갈래 기준 하나)로 다시 쓰는 것이고, **원문 문장 하나도 장부 없이 사라지지 않게** 하는 것이다.

1. `문서/교재/근거/기준정리/새구조.md`를 끝까지 읽는다(새 문서 · 절 코드 · 갈곳 표기법 · 알려진 충돌).
2. 자기 묶음의 원본 문서를 **처음부터 끝까지** 읽는다(문맥을 알아야 한 문장을 판정할 수 있다). 장부 행만 보고 판정하지 않는다.
3. `분류/입력_<묶음>.tsv`(열: 번호 · 파일 · 줄 · 절 · 원문)의 **모든 행**을 판정해 `분류/결과_<묶음>.tsv`에 쓴다.
   - 첫 줄 머리: `번호	갈래	갈곳	핵심어	메모` (탭 구분, UTF-8). 칸 안에 탭 · 줄바꿈을 넣지 않는다.
   - **시작하자마자 머리 줄을 쓰고, 원본 파일 하나를 끝낼 때마다 그 행들을 덧붙인다**(진행이 파일로 보이게).
   - 입력의 모든 번호가 결과에 정확히 한 번 나와야 한다. 원문을 결과에 옮겨 적지 않는다(번호로 잇는다).

## 판정 기준

- 지금도 유효한 규칙 → `옮김 <절>`. 어느 절인지는 `새구조.md` 표에서 고른다. 규칙과 날짜 · 사용자 인용이 한 문장에 섞였으면 `옮김`으로 두고 메모에 `+이력`.
- 같은 묶음 안에서 뜻이 같은 규칙이 여러 번 나오면 가장 완전한 행 하나를 `옮김`, 나머지를 `합침 <그 번호>`. 묶음 밖에 같은 규칙이 있을 것 같으면 `옮김`으로 두고 핵심어 첫 낱말에 묶음 이름(예: `[C71]`, `[ElevenLabs]`, `[START]`)을 붙인다 — 메인이 묶음 사이 중복을 합친다.
- 같은 대상에 다른 값 · 상반된 규칙 → `충돌 <짝 번호 또는 짝 문서:줄>`. 메모에 양쪽 요지, 어느 쪽이 최신 결정인지(날짜 · C번호), `제안:`. 최신 결정이 분명히 옛 규칙을 대체했다고 원문이 스스로 밝힌 경우(예: 「C69가 …를 대체」)는 옛 쪽을 `폐기: C69가 대체`로 두고 메모에 대체한 쪽 좌표.
- 날짜 · 인용 · 경위 · 과거 판단 → `이력`. 진행 · 완료 · 실측 · 다음 할 일 → `상태`. 한 도구 · 생성기의 값 · 경로 · 명령 · 함정 → `도구`. 제목 · 목차 · 가리키기만 하는 문장 → `안내`. 포털 · 설비 시스템 규칙 → `시스템`.
- 더는 적용하지 않는 규칙 → `폐기: <까닭 한 줄>`. 확신이 없으면 폐기하지 말고 `옮김` + 메모 `폐기 후보: <까닭>`. 사용자가 전부 확인한다.
- 「항상」 「반드시」 「절대」 「~만」처럼 강도가 있는 말은 핵심어에 넣어 새 문서에서 약해지지 않게 한다.
- 핵심어(`옮김` · `합침` · `충돌` 행): 새 문서에 반드시 살아 있어야 할 낱말 1~3개, `;`로 구분. 원문에 실제로 있는 낱말을 쓴다.
- 갈래: 새 문서 코드 G · D · S · L · C · H, 기준이 아니면 `-`.
