# 실제 랩·수업 환경에 맞춘 실라버스 보강 — C63

이 문서는 최종 Excel의 상세 활동을 실제 자료·코드·현재 수업 권한에 연결한다. 실라버스가 후속 교재 제작의 기준이며, 오래된 랩을 실행하기 위해 포털 기능을 새로 개발하지 않는다. **이번 수정 대상은 실라버스와 기준·인계 문서다. 랩 코드·ZIP·덱·개별 대본·영상은 수정하지 않았다.** 아래 보강 요구는 구현 완료 기록이 아니다.

## 1. 판정과 근거의 범위

- 두 과정 랩 폴더 88개를 목록화했다. 텍스트·입력·코드 1,169파일은 동일 바이트 중복을 제외하면 339종이다. 파일 수는 검증 통과 수가 아니다. 활성 랩의 요구·입력 계약·가이드와 제공 구현을 대조하고, 마지막 회차의 옛 개인 프로젝트 12폴더는 현행 교대 랩과 구분했다. 과거 비교 실행의 대용량 출력 전체를 새로 검증하거나 학생 코드를 실행한 것은 아니다.
- 공통 기준·실전반 기준·랩 기준·작업별 진입점·마감 기준과 기존 인계를 대조했다. 이전 38회차·211행 검토는 편성 검토였으며, 그때 모든 실제 랩을 검증한 것으로 확대하지 않는다.
- 코드 근거: `common/hydcommon/{course_access.py,course_content.json,course_handover.py,handover_tools.py}`, `it/process/procsvc/{course_access.py,manual_approved_cache.py}`. 현재 개발·배포·실행 근거는 [시스템 남은 일](../../시스템/6_남은_일.md)의 최신 항목을 따른다. 같은 파일도 시스템 세션에서 바뀌고 있으므로 소스 존재·배포·학생 화면 확인을 구별한다.
- 자료 근거: 아래 각 온라인 회차의 `랩/`에 있는 README·원자료·입출력 계약·가이드·검사/준비 코드. `check.py`는 ID·끝점·중복 등 구조만 검사한다. 원자료의 뜻·단위·질문에 대한 정답까지 검사한다고 설명하지 않는다.
- 로컬 상세 목록·해시는 `.evidence/lab-audit-20261027/inventory.json`, 현재 Excel 값은 `current-workbook.json`, 변경은 `edits.json`, 승인 문서 대조는 `document-hashes.json`이다. 로컬 evidence는 clone으로 전달되지 않는다. 후속 담당자에게 필요한 판단·수정 범위는 이 문서에 남긴다.

## 5. 시작본·난도·시간의 제작 요구

1. 각 랩에 필요한 이전 기능이 완성된 독립 시작본을 제공한다. 개인 결과는 선택이다. 현재 여러 `input/README.md`의 ‘앞 실습 결과 복사’ 지시만으로 독립 시작이 되는 것은 아니다.
2. 제공할 것은 환경·자료·이전 기능·짧은 작업 규칙·START의 목표/완료 조건이다. 이번 과제의 해결 로직·완성 프롬프트·완성 결과는 학생 폴더 밖에 둔다. 변경 과제에서는 이전 기능이 있어야 무엇을 보존하고 바꾸는지 배울 수 있다.
3. 학생이 요구 정리→AI 계획 검토→구현→원자료/명세와 실행 결과 대조→필요 수정→저장·재열기를 수행한다. 구조 검사 성공·AI 완료 문구만으로 합격하지 않는다. 이미 맞은 결과에 고의 실패를 만들지 않는다.
4. 온라인 시간·회차 큰 틀은 유지하고 실제 영상은 내용에 맞춘다. 오프라인은 기존50분×4교시와 강사 배정을 유지한다. 실습을 빈 상태에서 전부 재구현하도록 편성하지 않고, 해당 교시의 핵심 변경만 학생이 작성하도록 시작점을 맞춘다.
5. 오프라인 첫날은 HYD 목표·실제 포털 시연→ARROWS→Cypher→작은 모델 확인이다. 모델 전체 설계·적재기·공급 기능을 한 교시에 모두 새로 만들게 하지 않는다. 직접 구현은 다음 회차로 연결한다.
6. 통합 오프라인5의 원인·품질·시각화, 실전 오프라인2의 조건표·판정·성과, 마지막 실행·교대·ProcessGPT는 시간 위험이 있는 묶음이다. 앞 단계 완성 시작본으로 핵심 구현/검증을 선별한다. 편성값은 학생 실측이 아니며, 리허설에서 대기·구현·질문 시간을 확인해 강사가 진행 범위를 조절한다. 필수 확인을 빼고 완료로 표시하지 않는다.
7. 실전 대본은 통합반과 비슷한 말과 난도로 설명한다. 예: “오더가 만들어졌네요. 정비가 끝났다는 뜻인지는 완료 시각을 함께 보겠습니다.” 낯선 전문 용어·여러 예외를 한 문장에 몰지 않는다. 활용 질문이 성립하지 않는 장면은 같은 설명을 쓴다. 실전반만 VS Code 기본 UI 설명을 생략하고 필요한 새 도구 설명은 유지한다.
