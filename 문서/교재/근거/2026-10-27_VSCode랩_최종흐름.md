# VS Code 랩 최종 편성 — C66·C67

## 전체 재검토의 최상위 기준 — C67

사용자는 온톨로지는 설계부터 인제스천까지 직접 구축할 수 있게, 에이전트는 다양한 활용·응용 가능성을 실제 구현과 검증으로 경험하게 하는 방향을 최상위 기준으로 확정했다. Notion 한 사례나 여덟 단계의 숫자에 편성을 맞추지 않는다. [목적과 방향](../1_목적과_방향.md)이 정본이다.

| 전체 흐름 재검토 | 판정·수정 | 후속 제작에서 확인할 것 |
|---|---|---|
| 공통1의 HYD·관계도·학습노트 | 전체 경험의 출발점 유지. 기존 영상 재촬영 요구 없음 | 목표 소개가 온톨로지 구축과 에이전트 활용으로 이어지는지 |
| 통합2~4 / 실전2~3 온톨로지 | 설계·구현·SOP/판단·추출·검토·적재 단계는 유지. 끝에서 구축 결과가 분절되지 않도록 통합4 C41~42·실전3 C36과 대응 오프라인 보강 | 질문·모델·문서·코드·검토·조회 결과를 연결해 설명하고 다른 문서 추가 가능 |
| 통합5~6 / 실전4 에이전트 | 원인·품질·시각화·회의·학습·협업의 활용 차이를 이론 도입에도 명시. 외부/자체 MCP와 자기 자료 사용 복원 | 이름만 다른 반복인지, 실제 목적·입력·도구·결과 판정의 차이가 있는지 |

이번 재검토는 Excel 네 시트의 학습 흐름과 관련 원문, C63 실제 랩·시스템 조사 근거, C66 전체 랩 대응을 대조한 것이다. 이미 확인한 변경 없는 자료는 근거를 재사용했다. 모든 랩 코드·영상·덱을 새로 전수 실행·청취·수정한 기록이 아니다.

## 이번 결정과 적용 범위

VS Code 랩은 포털에서 본 기능을 직접 구현하고 다른 자료·업무에도 적용하는 주요 제작 실습이다. 외부 MCP, 직접 만든 MCP, 자기 Notion 기록과 문서를 사용할 수 있다. 포털의 제공 시나리오·승인 문서·캐시·도구 등록 제한을 독립 로컬 랩에 확대 적용하지 않는다. 포털 시스템 로직과 수업 권한은 변경하지 않는다.

피지컬 AI의 지식·판단·에이전트·업무 흐름이 중심이다. 학습 퀴즈와 회의 후속 업무는 배운 기술을 자기 생활과 다른 업무에 활용하는 경험이다. 모든 소재를 설비로 억지 변경하지 않는다. 재미는 자기 자료가 문제와 피드백으로 돌아오고 입력·도구·지침을 바꾸면 결과가 달라지는 경험에서 만든다. 단순 예제 실행이나 고정 질문·정답을 보여주는 시연으로 끝내지 않는다.

이번 수정은 공개/강사 배정 Excel 네 시트와 기준·제작 인계다. 랩 코드·ZIP·개별 대본·영상·가이드는 후속 제작 대상이며 구현·실행 완료로 간주하지 않는다. 온라인 시간·오프라인50분×4·날짜·강사 배정·온라인1·기존 공통 Cypher 영상·마지막 교대 시나리오는 유지한다.

## 기존 여덟 단계와 현재 편성 대응

근거는 Git `0a4cee2f6dea9aa7c47d6bfd1f5f31c36bb31f35`의 `docs/실라버스.md` AL1~AL8이다. 같은 커밋의 `docs/handoff/DECISIONS.md` §111과 교재 인계에는 L26 지식 퀴즈·Notion MCP·오답 노트가 있다. 당시 포털 자유 등록 절차나 옛 시간표를 그대로 복원하지 않고 구성요소를 쌓는 원칙을 현재 편성에 적용한다.

| 기존 기능 | 현재 통합반 / 실전반 온라인 | 직접 구현·확인할 결과 |
|---|---|---|
| AL1 에이전트 실행 고리 | 5 / 4 | 요청·도구 선택·결과 관찰·종료를 기록하고 근거가 있는 원인 후보·점검 결과 생성 |
| AL2 현재값 조회 도구 | 5 / 4 | 센서 입력과 조회 함수를 연결하고 시각·누락·도구 오류를 구분 |
| AL3 지식 그래프 연결 | 2~4의 모델·문서 결과를 5 / 4에서 활용 | 별도 랩의 관계·문서 근거를 읽어 실제 입력과 함께 사용 |
| AL4 직접 만든 MCP | 6 / 4 | 제공 서버 골격에서 조회 함수를 구현하고 도구로 노출하여 외부 MCP와 함께 호출 |
| AL5 스킬로 작업 방법 변경 | 6 / 4 | 회의의 결정·제안·담당 미정·후속 확인을 구분하고 다른 회의에도 같은 기준 적용 |
| AL6 판단 규칙과 추천 | 3 / 2~3에서 구현, 5 / 4에서 재사용 | 후보별 제외·미확인·비교 이유를 보존하고 근거 없는 단정을 막음 |
| AL7 평가 | 7~8 / 5 | 실제 기대 결과·정상·경계·누락·도구 오류를 판정하고 회귀 검증 |
| AL8 통합 활용 | 통합8 로컬 자료 연결, 최종 통합11 / 실전8 교대 | 서로 다른 출처·사람 확인·검증 결과를 종합. 로컬 코드를 포털에 자동 배포한다고 설명하지 않음 |

현재 편성의 질문·답변·재개, 작성자/검토자, SDD·BDD는 그대로 연결한다. 회차마다 새 에이전트를 처음부터 만드는 대신 같은 프로젝트의 해당 기능을 확장한다. 품질 대응은 원인 점검에서 익힌 실행 구조를 다른 업무로 옮기는 실습이며, 센서 시각화는 자료 해석·시각 출력의 활용 실습이다. 각각 새 학습 목표가 없는 반복 구현은 합치거나 이전 완성 시작본으로 제공한다.

## 자기 Notion으로 출제·풀이·피드백

통합 온라인6 C63 / 오프라인6 C49의 기본 경로는 자기 Notion 학습노트의 MCP 읽기 연결이다. 이전에 정리한 주제·원문을 고르고 그 자료로 문제를 만든다. 정답 기준·해설·원문 근거는 학생이 답하기 전 화면에서 숨긴다. 답변을 입력하면 정답·부분 정답·오답과 이유를 보여주고 해당 원문을 다시 열 수 있게 한다. 다음 문항 또는 틀린 개념 재도전으로 이어가며 풀이 기록을 저장한다. Notion 쓰기는 별도 권한을 확인한 선택 확장이며 기록의 기본 저장은 로컬 파일이다.

학생이 구현할 핵심은 자료 읽기·근거 연결, 출제/정답 공개 시점, 답변 판정과 피드백, 풀이 상태·재도전이다. 완성 채점 로직이나 문제·정답 세트를 시작본에 넣지 않는다. 표현만 다른 정답, 부분 답, 오답, 노트에 없는 질문으로 결과를 비교한다. 문자열 완전 일치만으로 채점하거나 LLM의 판정을 무조건 정답으로 취급하지 않는다. 근거가 모자라거나 판정이 애매하면 보류하고 원문 확인으로 돌린다. 동일 답변에 서로 모순된 평가가 나오면 원문·채점 기준과 대조하여 수정한다.

실전 온라인4 C48 / 오프라인5 C40~41에서는 같은 외부 연결 기술을 자기 Notion 회의·학습 기록과 점검 메모로 만든 다음 협의 안건에 적용한다. 통합반 퀴즈에 추가 숙제를 붙이지 않는다. 기록이 부족하면 제공 자료로 시작하며 자기 자료로 바꿔 재사용할 수 있어야 한다.

Notion 연결 실패 시 같은 노트의 Markdown 내보내기는 대안이다. 이를 기본 경로로 바꾸거나 MCP 연결 성공으로 보고하지 않는다. 인증 방법·지원 도구 이름·설치 명령은 후속 제작 시 실제 제공 서비스와 클라이언트로 확인한다. 현재 편성 승인과 실제 계정 연결·교실 완주를 구분한다.

## 장난감 실습을 막는 제작 조건

- 입력·출처·요구·제약·결과 판정을 학생이 정리하고 AI의 계획을 검토한 뒤 구현한다. 한 문장 프롬프트와 완성 결과를 복사하는 것으로 종료하지 않는다.
- 제공 범위는 환경·원자료·작업 규칙·START·필요한 이전 기능이다. 이번 요구의 해결 로직·완성 프롬프트·강사 정답은 학생 폴더 밖에 둔다.
- 다른 입력·표현·문서에도 적용해 원문 근거와 출력 계약을 검사한다. 정상 결과를 일부러 깨뜨려 재시도를 연출하지 않는다.
- 포털 문서 실습은 승인 캐시·검토 흐름을 사용한다. 로컬 문서 랩은 실제 추출 기능을 구현한다. 비교용 캐시를 재생한 것은 새 추출 성공이 아니다.
- MCP 연결은 서버 개수 채우기가 아니다. 연결 설정·도구 목록·입력/반환값·출처·실패 처리를 확인하고 기존 에이전트의 결과에 활용한다. 서버 골격·실행 환경은 제공하고 해당 조회 함수는 학생이 작성한다.
- 연결 실습마다 이전 기능이 완성된 독립 시작본을 제공한다. 학생의 이전 결과·개인 Git 설정은 필수가 아니다. 현재 랩에 필요한 도구만 연결하고 권한·키를 ZIP·영상에 포함하지 않는다.
- 실전반은 더 복잡한 용어보다 점검 요청·작업 확인 카드·다음 협의 안건처럼 활용 가능한 결과와 그 검증으로 차이를 만든다. 통합반도 근거·누락·다른 입력 검증을 생략하지 않는다.

## 후속 제작·게시

A 교재 세션은 이 흐름과 개념·실습 간지·이론 대본을 맞춘다. B 실습 세션은 해당 회차의 랩·입력·출력 계약·대본·가이드·ZIP·촬영을 맞춘다. 현재 B의 착수 범위인 두 반2~3회차를 임의로6회차 촬영으로 바꾸지 않는다. 이후 회차 담당도 이 계약을 사용한다.

외부 MCP 인증·실제 모델 실행·별도 DB·교실 PC·리허설 시간은 후속 확인이다. 새 랩·가이드·영상이 아직 개정되지 않았다는 이유로 실라버스의 학습 요구를 다시 축소하지 않는다. 연결 장애는 의존성과 대안을 기록한다.
