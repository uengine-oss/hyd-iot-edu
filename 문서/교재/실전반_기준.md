# 실전반 이론 덱·대본 기준

실전반 온라인 2~8회차의 이론 덱과 이론 대본을 만들거나 고칠 때 읽는다. 두 과정의 공통 범위는 [공통 기준](2_기준.md#두-과정의-공통-범위와-차이--사용자-확정2026-10-23-갱신), 화면 형식·그림체는 [이론 덱](기준_이론덱.md), 발화·표기·낭독 형식은 [이론 대본](기준_이론대본.md)을 따른다. 이 문서는 실전반이 통합반과 **다른 점만** 적는다. 결정 경위는 [결정 기록](5_결정_기록.md)의 2026-10-23 항목에 있다.

## 1. 무엇을 만드나

실전반 한 회차는 통합반 여러 회차를 묶어 편성돼 있다(아래 3절 표). 실전반 덱·대본은 **그 묶음을 한 회차 분량으로 압축한 판**이다. 설명 방식은 통합반과 같은 결로 차근차근 가되, 단원마다 **배운 것을 실전에서 어떻게 써먹는지**를 어느 정도 분명하게 보여 준다.

| 항목 | 기준 |
|---|---|
| 출발점 | 묶인 통합반 회차의 확정 덱·대본. 통합반 원본은 고치지 않는다. |
| 범위 | 실라버스 실전반 시트의 큰 틀(회차 주제·이론/실습 순서·행 제목)을 따른다. 실전반 행에 없는 통합반 장은 뺀다(예: 2회차의 클래스 계층·상속·새 클래스 기준). 세부 내용은 실전반에 맞게 달라도 된다. |
| 개념 | 학생도 처음 듣는다는 전제로 뜻과 필요를 충분히 설명한다. 짧게 만드는 것을 목표로 삼지 않는다. |
| 압축 | 두 회차에 걸쳐 되풀이되던 도입·예고·재요약과 같은 말의 반복을 뺀다. 겹치는 장은 합친다. 내용(개념·조건·예외·판단 근거)은 빼지 않는다. |
| 응용 | 단원마다 실전 응용을 둔다. 형태는 경보 하나에 답하는 지식을 단계로 세우기, 둘 다 가능한 설계를 질문으로 고르기, 요구가 바뀔 때 고칠 곳 찾기, 학생이 먼저 푸는 판단 문제 등. 덱에 응용 장을 더할 수 있다. |
| 난이도 | 통합반보다 살짝 위. 새 이론을 더하지 않고, 판단의 조건 수·예외·설계 선택·결과 추적으로 올린다. |

## 2. 근거와 분량

- **현장 사례의 근거.** 사례·값·이름은 HYD 시나리오 정본(`it/neo4j/v2/schema.json` · `instances.cypher`, [사실표](사실표/))에서만 가져온다. 시나리오는 실제 표준과 업계 자료(ISO 14224 고장 분류·설비 위계, UCI 데이터셋 447 센서 이름, 승인 공급사 목록 관행 등)를 바탕으로 교육용으로 다듬은 것이다(`문서/시스템/검증_기록/2026-10-09/scenario-research.md` 1절). 교육용으로 줄인 수치(예: 유온 한계 65 ℃)를 실제 현장 값이라고 말하지 않는다. 수업용 가정은 가정으로 말한다.
- **실습 자료의 틀을 이론에 끌어오지 않는다.** 이론 대본에서 「받은 자료」「원자료」처럼 실습 자료를 전제한 말을 쓰지 않고, 현장 상황으로 설명한다.
- **분량은 참고만 한다.** 통합반 한 회차 이론 분량과 실라버스 실전반 이론 시간을 염두에 두되 맞추려 하지 않는다. 필요한 내용을 지워 맞추지 않고, 담을 것이 더 있는데 잘라 내지 않으며, 부족하다고 억지로 늘리지 않는다. 결과 길이는 [이론 대본](기준_이론대본.md) 39~41번 방식으로 재서 기록한다.

## 3. 회차 편성

| 실전반 | 묶인 통합반 회차 |
|---|---|
| 1회차 | 1회차(두 과정 공통, 재편 대상 아님) |
| 2회차 | 2회차 + 3회차 앞부분(작업 절차와 판단 조건) |
| 3회차 | 3회차 뒷부분 + 4회차 |
| 4회차 | 5회차 + 6회차 |
| 5회차 | 7회차 + 8회차 |
| 6회차 | 9회차 |
| 7회차 | 10회차 |
| 8회차 | 11회차 |

## 4. 만드는 순서와 완료 확인

1. 회차 하나씩 한다. 원고는 `제작용/온라인/decks/practical/dayNN/실전반_NN일차.md`를 직접 고친다(2~8회차는 조립 스크립트가 없다). 빌드·렌더·검사는 [만드는 법](4_만드는_법.md)과 스킬 `hyd-course-deck`의 명령을 쓴다.
2. 대표 편(덱 + 대본)을 먼저 시안으로 보이고 사용자 승인을 받은 뒤 나머지 편으로 넓힌다. 승인 전에는 `산출물/실전반/`의 대본·덱을 고치지 않는다.
3. 반영할 때 `산출물/실전반/이론/NN회차/` 대본·PPTX, 발표자 노트, `제작용/구성/실전반/NN회차/` 구성표·구성.json, 장 번호가 바뀐 다른 편의 참조 문장을 함께 맞춘다.
4. 완료 확인: 빌드 넘침 0, `제작용/기존제작/tools/deck/글겹침.py` 0곳, 대본 `[SLIDE NN]`과 덱 장 번호 일치, 실라버스 실전반 행 대비 빠진 개념 없음, 통합반과 같은 화면·같은 대본 문장의 비율 측정 기록.
5. 영상은 승인 뒤에 만든다(스킬 `hyd-lecture-video`).
