# 두 과정 교재 작업 인계 — 새 세션은 5회차부터

현재 진행은 [작업 상태](작업상태.md), 확정 회차는 [현황](3_현황.md), 적용 규칙은 [공통 기준](2_기준.md)에서 확인한다. 상세 규칙은 [덱과 이론 대본](기준_덱과이론대본.md)·[실습과 랩](기준_실습과랩.md)·[검증과 마감](검증과마감.md)에 나뉘어 있다. 요약만으로 세부 기준을 대체하지 않는다.

## 시작 위치와 완료 범위

활성 저장소는 `D:/work/study/hyd-portal-latest-20261014`, 브랜치는 `develop`, 원격은 origin이다. 시작 때 실제 HEAD·미커밋·원격을 확인한다. 두 과정 산출물은 [통합반](../../산출물/통합반/README.md)·[실전반](../../산출물/실전반/README.md)에서 찾는다. `산출물/{과정}/{이론,실습}/NN회차/`가 정본이며 제작 원고·도구는 `제작용/`, 구성은 `제작용/구성/{과정}/NN회차/구성.json`이다. 별도 사본·배포 구조를 새로 만들지 않는다.

1·2회차는 확정 상태로 재검토하지 않는다. 3회차 내용과 레이아웃은 마감했고, 4회차 전체 내용·수정·동기화·201장 화면·정적 검사를 마쳤다. [4회차 완료 근거](근거/2026-10-19_04회차_두과정_내용검토.md)를 재사용한다. 로컬 증거는 `.evidence/day04-final-20261019/`에 있으며 다른 장치에서는 최종 Git 판본과 커밋된 마감 근거를 사용한다.

이전 통합반 복구 루트의 분리된 HEAD·태그·미커밋은 보존용이다. 과거 루트에 재동기화하거나 구버전으로 현재 정본을 덮지 않는다. 학교PC 설치 등 다른 프로젝트 자료는 이번 교재 범위가 아니다.

## 다음 작업 — 두 과정 5회차

통합반5는70장·4랩, 실전반5는107장·4랩이다. 각 구성.json에서 분할 대본·덱·PPTX·진행 순서를 확인하고 실라버스·사실표·원본대응과 연결한다. 통합반5의 공통 이론은 실전반4에서 확인한 범위가 많으므로 같은 판본의 근거를 재사용하되, 과정 고유 도입·연결·정리·촬영 경계와4랩 전체는 별도로 확인한다. 실전반5의 배정은 해당 덱 폴더의 원본대응.json에서 확인한다. 제목 검색이나 정합 검사만으로 내용 검토를 마치지 않는다.

이미 반영된 의존성 수정:

- 통합반5: 화면21의 재시도 계획,31의 검토·개정 갱신 태그. 발화13·18·20·21·32·35·46. 원인추론 실습2의 입력 집계 창 불일치·미제공 원문 안내와 HTML/ZIP.
- 통합반6: 화면19·66의 카드 레이아웃, 발화19·46·54·66. 실습2 MCP 보조 코드3개와 HTML/ZIP.

이 부분은 4회차의 공통 수정 동기화이며 5·6회차 전체 확정이 아니다. 수정된 내용을 다시 예전 사본으로 돌리지 않는다. 통합반5의 품질대응카드·센서이상시각화 등 고유 실습은 아직 전체 검토 대기다.

표 선택과 반복 점검은 두 과정 모든 후속 회차에 적용한다. 일관된 디자인 안에서 비교는 표, 개념·관점은 카드, 관계는 도식, 순서는 흐름으로 내용에 맞게 표현한다. 표 비율을 목표로 하지 않으며 수치·조건·근거를 삭제하지 않는다. 읽는 순서가 바뀌면 대본·발표자 노트를 함께 수정한다.

## 진행과 마감

같은 판본으로 이미 확인한 작업은 반복하지 않고 변경 범위와 미확인 내용을 이어서 처리한다. 전체 내용 확인·윤문·수정·동기화를 효율을 이유로 생략하지 않는다. 화면 전 장 확인과 내용 검토는 별도다. 과거 전체 조립·합본 생성기를 바로 실행하지 않는다. 현재 분할 대본을 기준으로 필요한 파생물만 동기화한다. `제작용/온라인/tools/deck/회차노트동기화.py`는 구성.json을 받아 덱·PPTX 노트만 맞춘다.

실제 실습·AI·학생 코드/테스트·서비스·DB·브라우저 실습·캡처·PDF는 실행하지 않는다. PPTX 직접 PNG 내보내기와 화면 확인, 코드 AST·JSON 등 정적 검사는 가능하다. 실행 성공·촬영·청취·전체 시간 실측을 주장하지 않는다. [남은 촬영 확인](6_남은_일.md)은 별도 범위다.

각 회차의 산출물·제작 원본·관련 기록을 마무리한 뒤 커밋·origin/develop 푸시하고 다음 회차를 준비한다. 새 세션·다른 작업자를 자동 생성하지 않는다.
