## 새 세션의 첫 작업 — 두 과정 4회차

사용자가 직접 새 세션을 연다. 자동 생성하지 않는다. 1–3회차는 내용 확정이며 새 회차 작업을 이유로 다시 열지 않는다. 이번 인계는 지금까지의 상세 지시를 대체하는 요약 기준이 아니다. 아래 목록과 함께 2_기준.md·4_만드는_법.md의 상세 원문을 전독하고 적용한다.

1. 실제 Git 상태부터 확인한다. 통합반은 3f88ff6의 분리된 HEAD와 archive/integrated-recovered-20261019 태그를 보존한다. 1–2회차 수정이 로컬 미커밋으로 남아 있으므로 삭제·초기화·브랜치 전환하지 않는다. 실전반2회차는 develop의 bb37fc7로 원격 확인됐고, 이후 인계 커밋은 실제 Git 로그에서 확인한다.
2. 두 경로의 저장소 지침, 목적·기준·현황·제작법·결정 기록·남은 일, 이 인계, 근거/2026-10-19_온라인_랩_후속개정.md, 온라인_최종산출물_목록.md, 1·2회차 마감 근거를 읽는다. 동일 문서는 일치 확인 후 공통 원문을 전독하고 차이 전체를 읽는다. 컨텍스트 요약 뒤에도 상세 기준을 다시 전독한다. 이력에만 남은 유효한 상세 지침이 발견되면 현행 문서에 복원한다.
3. 통합반4회차69장·랩3개, 실전반4회차132장·랩4개를 각각 현행 구성.json·실라버스·원본대응으로 확인한다. 회차 번호가 같다는 이유로 배정을 같게 만들지 않는다. 통합반4의 문서 지식 이론은 실전반3에 이미 배정돼 있으므로 해당 확정 판본을 대조해 근거를 재사용하고, 수정 시 그 의존성만 동기화한다.
4. 해당 회차의 화면·이론 발화·실습 발화·랩·입력·시작/참조본·가이드를 빠짐없이 읽어 사실·정의·이유·조건·예외·순서·원본 대응·윤문을 함께 본다. 구체적 결함만 수정하되 지금 해결할 누락·모순·어색한 연결을 촬영 단계로 미루지 않는다.
5. 원본 수정→덱/발표자 노트→분할·합본·개별/합본 낭독본→랩 HTML·ZIP·안내를 영향 범위에서 동기화하고 검증한다. PDF 제작·검토와 실제 AI·학생 코드/테스트·HYD/DB·브라우저 실습·캡처는 하지 않는다. 문서 생성·정적 참조 검사·필요한 덱 배치 확인만 한다.
6. 이론·랩·자료·가이드는 검토를 마쳐 확정하고, 실습 발화는 내용·순서 정합 확정과 촬영 때 발화·전환·속도 튜닝 가능을 구분한다. 장수·수정 발화/이유·같은 산식 시간 변화·랩 수·동기화/검증 범위·미수행을 보고하고 양쪽 현황·남은 일·인계·제작기록을 갱신한다. 기준 정리만 하고 멈추지 않는다.

### 효율과 누락 방지 — 둘 다 필수

효율은 같은 판본의 확정 근거와 공통 원문을 재사용하고 불필요한 재생성·반복 수정을 줄이는 것이다. 효율을 이유로 미확인 회차를 일부만 읽거나 표본·키워드 검사로 전체 내용 검토를 대신하지 않는다. 해당 회차의 이론·전체 발화·화면·랩·입력자료·가이드를 빠짐없이 대조하고, 수정 후 앞뒤 연결과 영향을 받는 파생물까지 확인한다. 검토 범위표에 확인/근거 재사용/미확인을 구분하고, 누락이 없을 때만 회차를 확정한다. 기준 전독과 산출물 재검토는 구별한다.

### 상세 지시를 적용할 때 빠뜨리지 않을 것

- 낭독 본문은 내가 직접 수강생에게 하는 말 그 자체다. 나를 ‘강사’라고 제삼자로 부르거나 ‘대본·스크립트·영상’ 같은 제작 설명으로 대신하지 않는다. 제목·파일명·조작/촬영 메모·입력 프롬프트는 밖에 분리한다. 단어 치환만 하지 말고 문맥·호흡·대상·시점·앞뒤 전개를 함께 윤문한다.
- 교재·포털 실습은 공통이다. 대본·랩은 같은 주제 안에서 필요한 실전·응용 차이만 둔다. 과정 차이를 만들려고 별도 도구/주제를 넣지 않는다.
- 제조 업무의 자료·조건·근거를 연결해 판단·구현·검증하고 앞 산출물을 뒤 실습과 PBL에서 재사용한다. 짧은 요약/한 번의 요청만으로 끝나는 장난감 과제, 억지 복잡도·실패 연출은 금지한다. 기초 조회·포털 관찰은 본 작업에 필요한 준비 범위로 둔다.
- 프로젝트를 미리 아는 척하지 않는다. 목적·요구에서 AI 탐색으로 현재 기능과 제약을 파악하고 구현·결과 대조로 간다. 이후 익힌 절차는 반복 강의하지 않되 필요한 검증은 유지한다. AI 응답·실행 성공을 미리 지어 쓰지 않는다.
- 온라인은 본인이 진행하며 학생에게 가이드를 읽히거나 학생 작업을 기다리지 않는다. 오프라인 학생용 가이드는 작업/결과 사진 중심의 짧은 설명·확인점, 복사·수정할 수 있는 프롬프트·스킬·명세를 갖춘다. 실제 사진은 미촬영으로 두며 이번에 캡처하지 않는다.
- 시간은 내용의 결과다. 목표 시간·분량을 채우거나 맞추려고 증감하지 않는다. 이론 설명·필요한 판단·구현·검증은 보존하고 반복 설명을 줄인다. 낭독 추정과 실제 수행/전체 시간은 별개다.
- 기존 미커밋과 역사적 .evidence/before.json은 보존한다. 새 근거 디렉터리를 쓰고 과거 일회성 편집 도구를 다시 실행하지 않는다. 옛 C 작업 경로나 상대 루트의 과거 다른 과정 사본을 사용하지 않는다.

## 완료와 계속할 작업

1회차 공통 범위 정정과 파생물 동기화·검증은 완료했다. 기존 전체 내용 검토와 이번 변경 범위의 검증 근거를 함께 사용해 최종 확정한다. 2회차의 내용 검토·수정·파생물 검증도 완료했다. 3회차까지 마쳤고 다음은 두 과정 4회차이며 전체 과정 마감으로 기록하지 않는다. 이미 같은 판본으로 확인·확정한 산출물 내용은 검토 근거를 재사용한다. 변경 부분과 그 앞뒤 연결·영향받은 파생물·미확인 범위만 점검하며, 구체적 결함 없이 같은 검토를 반복하지 않는다. 기준 전독은 적용 지침을 복원하는 절차이며 확정 산출물 전체를 다시 검사하라는 뜻이 아니다.

모든 대본은 본인이 실제 하는 말로 쓰고 조작/촬영 메모는 낭독 밖에 둔다. 목표 시간 채우기·반복 설명·억지 난이도를 넣지 않는다. 제조 업무의 조건·근거·구현·검증·PBL 재사용을 유지한다. 온라인은 학생 가이드 미제공, 오프라인 배포 가이드는 실제 작업/결과 사진 중심의 짧은 설명·확인점과 복사 가능한 프롬프트/스킬/명세로 구별한다. 사진은 후속 촬영 범위다.

실제 AI·코드·테스트·HYD/DB·브라우저 실습·캡처는 하지 않는다. 실행 가능성·실제 화면·전체 시간은 남은 일의 촬영 항목이다. 문서에서 찾은 오류·누락은 지금 수정한다. 구체적 오류·입력/조건/참조 모순·파생물 불일치·실행 결함이 생기면 해당 구간만 다시 연다.

현행 기준·제작 절차·현황·남은 일 및 근거/2026-10-19_온라인_랩_후속개정.md와 온라인_최종산출물_목록.md를 먼저 읽는다. 복원된 세부 제작 절차를 역사로 다시 밀어내지 않는다. 시작 시 확인한 모든 기존 미커밋 수정과 역사 .evidence/before.json을 보존하고 교재 변경만 커밋·푸시한다.

## 회차별 전달 산출물과 게시 — 최신 사용자 지시

각 회차를 완료하면 PPTX·대본·랩·HTML 가이드 등 해당 회차 산출물을 커밋·푸시하고 다음 회차를 준비한다. 이미 끝낸 내용 검토를 반복하지 않는다. 상세 기준 전체는 계속 적용하며 최신 지시 일부만 적용하는 방식으로 축소하지 않는다.

각 반의 회차 안에서 이론(PPTX·이론 대본)과 실습(실습 대본·랩 자료·HTML·다운로드 ZIP)으로 구분한다. 제작용 덱 원고·도구는 만들기/, 기준·사실표·검토 기록은 문서/교재/에 유지하고 전달 파일과 섞지 않는다. 3회차 전달 위치는 산출물/교재/{통합반,실전반}/온라인/03회차/{이론,실습}이다. 기존 제작·동기화 원본은 보존한다.

이번 게시 대상은 두 과정3회차다. 전체19회차의 폴더 전환은 진행하지 않으며 생성했던 초안은 로컬 evidence에 분리했다. 1–2회차 확정본을 다시 검토하거나 게시 구조 정리를 위해 수정하지 않는다. PDF는 생성·검토하지 않고 기존 파일을 보존하되 이번 전달 폴더와 ZIP에는 넣지 않는다. 통합반3은 정확한 통합반 정본의 출처·해시를 확인하여 게시하며 두 작업 루트를 통째로 합치지 않는다.


## Git 운영과 보존

작업 중 외부 Git 정리가 반영되었다. 실전반은 develop에서 작업하며 외부 시스템 변경 dc56c7c를 fast-forward로 반영했다. 통합반은 archive/integrated-recovered-20261019의 3f88ff6에서 분리된 HEAD다. 기존 미커밋 수정은 보존 커밋에 포함되었고 CLAUDE.md에는 main/develop만 유지하는 새 운영 지침이 추가되었다. 이 작업은 해당 변경을 되돌리지 않는다. 통합반의 추가 마감 문서 수정은 이 경로에 보존하며 삭제된 작업 브랜치를 재생성하거나 보존 태그를 이동하지 않는다.
