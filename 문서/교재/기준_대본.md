# 기준 — 대본 · 발표자 노트

이론 대본, 실습 대본, 온라인 덱의 발표자 노트를 쓰거나 고칠 때 이 문서와 [기준_공통](기준_공통.md)을 끝까지 읽는다. 새로 쓰면 S0 본보기 하나를 통독하고 같은 결로 쓴다. 첫 단계는 실라버스 그 행의 문장과 배정 시간이다(기준_공통 G0 「범위와 시간」). 이 갈래의 스킬: 이론 대본 · 노트 hyd-course-deck, 실습 대본 hyd-lab-guide.

- **이 갈래의 성향:** 강사 본인이 학생 앞에서 하는 구어체 말이고, 화면의 어디를 짚는지가 먼저다(S5-1 · S6-5).
- **앞에서 받는 것:** 이론 대본은 확정된 덱의 장(메시지 · 화면의 대상과 위치 · 읽는 순서), 실습 대본은 실제로 돌려 본 랩(시작본 · 화면에 보일 결과 · 확인 조건)과 가이드 단계. 덱 · 랩의 결함은 대본으로 수습하지 않고 그쪽을 고친다.
- **뒤가 가져가는 것:** 촬영은 문장마다 조작을 붙이고 이 대본으로 음성을 만들어 길이를 잰다 — 발화와 조작을 나눠 두고 화면 대조를 끝낸 뒤 넘긴다(S8). 이론 강의 영상은 분할 파일 하나를 영상 하나로 만든다.

## S1 누가 말하나

1. 대본은 강사 본인이 학생 앞에서 실제로 하는 말 그 자체다. 요약 · 지시 · 해설로 대신하거나, 화자를 제삼자로 부르거나 「이 대본에서는」처럼 제작물을 설명하지 않는다.
2. 제목 줄 · 구성표 · 조작 · 기술 메모 · 입력할 프롬프트는 비낭독으로 분리하고, 학생에게 필요한 위치 · 조작 안내는 발화에 넣는다. 제목은 읽지 않으므로 제목을 들어야만 알아듣는 문장을 쓰지 않는다.

## S2 말투

1. **본보기대로 차분히 설명하는 구어체, 한 문장에 한 가지.** 「~입니다」만 반복하지 않되 어미 일괄 치환 · 매 문장 「보이죠」는 금지이고, 어미를 바꾼 것으로 윤문이 끝나지 않는다. 입력값 · UI 이름 · 판단 조건은 그대로 둔다.
2. **제작 말투를 쓰지 않는다.** 이렇게 말고: 「앞 실습에서」 「앞 이론」 「랩 그래프」 「펌프 사십, 팬 칠십」 「판정 · 대조 · 산출물 · 기록 번호」 「~를 가른다」 남발, 시나리오 기호 「A · B · C」, 조회를 「생성 · 연결」로 부르기. 이렇게: 「이론 시간에는 …을 배웠습니다. 이번에는 …을 직접 확인해 보겠습니다.」
3. 과장 · 추임새 · 가상 학생 반응 · 억지 문답 · 드라마를 넣지 않는다.
4. 윤문은 작성자가 스스로 한다 — 다 쓴 뒤 처음부터 끝까지 이어 읽으며 고치고 기준을 다시 묻지 않는다. 자동 받아쓰기 일치는 자연스러움 검수가 아니다.
5. 확정 영상의 대본: 문체를 바꾸지 않고, 내용이 틀렸거나 화면과 어긋난 곳만 기준_공통 G4-2대로 전 · 후를 보여 고친다(음성을 다시 만드는 비용).

## S3 무엇을 소리 내어 읽나

1. **데이터를 읽지 않는다.** 식별자 · 속성 키 · 관계 영문명은 뜻으로 말한다(「펌프 축 씰 키트의 부품 번호」 O, 「P-PMP-SEAL」 X). 「이 값」처럼 무엇인지 모를 지시어로 바꾸지도, 식별자를 한글 발음으로 옮겨 줄줄이 읽지도 않는다.
2. 예외는 셋뿐: ① 문법을 배우는 대목의 키워드(MATCH)와 「s는 변수, Sensor는 레이블」 같은 문법 구분 ② 배우는 언어 · 표준의 이름(Cypher · BPMN · MCP)은 영어 그대로 ③ 학생이 입력하는 값은 입력하기 전에 말한다.
3. 같은 이름을 우리말 · 영어로 나란히 읽지 않는다(학생 UI 언어가 다를 수 있으면 「왼쪽 탐색기(Explorer)」). 약어는 통용 표기를 쓴다. 장 번호 · 날짜 · 페이지 수처럼 바뀌는 값에 기대어 말하지 않는다.
4. **수치는** 무엇의 값인지 → 왜 보는지 → 무엇과 비교하는지 → 어떤 판단이 나오는지를 먼저 말하고, 판단을 가르는 임계값 · 경계만 정확한 수치와 단위로, 나머지는 「기준보다 낮다」처럼 말한다. 근사로 판정 · 순위가 바뀌면 안 되고, 근거 없는 값 · 인과를 만들지 않으며, 뜻과 출처를 설명할 수 없는 값은 확인 대상으로 남긴다.
5. 명령은 위치 · 목적 · 기대 결과만 말하고 토큰 · 옵션을 낭독하지 않는다. UI는 위치와 정확한 이름으로 짚고, 확인하지 않은 색은 말하지 않는다.

## S4 길이와 시간

길이는 기준_공통 G0 「범위와 시간」이 정하고 거기 적힌 도구로 잰다. 고치면 다시 재서 구성표의 낭독 추정을 갱신한다.

## S5 이론 대본

1. **슬라이드의 어디를 설명하는지 먼저 말한다(가장 중요).** 「왼쪽 그림의 펌프」 「표의 둘째 줄」처럼 대상과 위치부터 — 대본만 읽어도 화면을 짚으며 설명할 수 있어야 한다. 화면의 칸은 가려서 푼다: 메시지를 받치거나 뒤에서 다시 쓰이거나 까닭의 고리이거나 실습에서 직접 다루는 것만 풀고 나머지는 화면에 맡긴다. 모든 글자 · 수치를 읽는 것으로 화면 대응을 대신하지 않는다.
2. **파일:** `산출물/{과정}/이론/NN회차/대본/`의 분할 파일 하나 = 촬영 구간 하나 = 영상 하나. 파일 머리(제목 · 대응 덱 · 「촬영 전 안내 — 낭독하지 않음」)와 「이 회차의 구성」 표는 본보기대로 두고, 표(낭독 추정 · 학습 대기 포함)는 구성.json에서 만들며 손으로 고치지 않는다.
3. **제목 줄:** 본보기대로 실라버스 행마다 `# [이론] <행 제목> · NN분` · `# [실습] <행 제목> · NN분 (대본은 연결 멘트만)` · `# [도입]` · `# [마무리]`, 장은 `## [SLIDE NN] 제목`, 장 사이 `---`, 실습 간지와 설명 장은 `## [SLIDE NN~MM]` 한 묶음. 실라버스 이론 행과 촬영 경계를 대조해 나누고 실습 뒤 복습은 같은 파일에서 잇는다. 끝에 `# 촬영 본문 끝`과 `## 제작 확인용 — 낭독하지 않음`(노트에 없는 말을 더한 곳과 근거, 뜻을 못 찾은 값, 덱과 어긋나 보이는 곳).
4. **구간의 시작과 끝:** 「이번 시간에는 …」으로 열고 「다음 시간에는 …」으로 잇는다. 첫 문장을 「그럼 · 그러면 · 그래서 · 자 · 이제 · 이어서」로 시작하지 않는다(`강의영상.py --dry`가 잡는다). 「영상」이라 말하지 않고 회차 전체는 「이번 회차에서는」. 강사 소개는 1회차 첫 구간에서만(경남대학교 피지컬AI 사관학교, 유엔진솔루션즈 연구원 안치윤). 중간 구간 끝을 하루의 끝처럼 말하지 않고, 회차 마지막은 짧은 맺음 · 다음 회차 연결 · 끝인사이고 복습을 다시 읽지 않는다. 이런 말은 대본에만 두고 덱에는 넣지 않는다.
5. **자리와 맺음:** 학습목표 · 목차 · 간지 · 실습 시작 · 복습 · 용어 · 퀴즈 · 정답에서는 무슨 자리인지 한 번 말하고 바로 물음이나 할 일로 간다. 보통 장에는 시작 · 종료 선언이 없고, 한 장 안에서는 끝에서 한 번만 맺는다.
6. **복습 · 퀴즈:** 복습은 배운 구분을 사건에 적용하거나 헷갈리는 짝을 가려 근거를 확인하는 일이다(본문 재낭독 X, 용어의 영어 이름을 차례로 읽는 것은 복습이 아니다). 퀴즈는 정답의 까닭과 오답의 혼동을 풀어 준다.
7. **이론과 실습의 경계:** 이론은 실습 간지 · 설명 장까지 안내하고 끊는다(목적과 만들 결과만 짧게, 「자료를 내려받고」 같은 부속 동작은 앞세우지 않음). 실습은 실제 작업 화면에서 따로 시작하고 이론 대본에 실습 발화를 섞지 않으며, 같은 소개를 이론 끝과 실습 시작에서 두 번 하지 않는다. 이론 대본 · 노트에서 「받은 자료 · 원자료」처럼 실습 자료를 전제한 말을 쓰지 않는다.

## S6 실습 대본

1. **강사 원맨쇼로, 하나의 수업처럼 진행한다(가장 중요) — 도구 실습과 코딩 랩 모두.** 강사 본인이 실제로 작업하며 설명한다. 받은 프로젝트는 목적과 요구만 알고 출발한다(이미 탐색한 것처럼 내부 구조 · 정답 프롬프트를 말하지 않음). 학생 가이드 읽기 · 학생 작업 · 대기 시간을 넣지 않는다.
2. **바로 실습에 들어가지 않고 먼저 연다:** 지난 이론에서 무엇을 배웠는지 → 오늘 무엇을 왜 하는지(현장에서 왜 필요한지) → 무엇을 만드는지 → 무엇으로 맞았다고 판정하는지 → 순서. 앞 이론은 다시 설명하지 않되 이 실습에 필요한 핵심은 가볍게 다시 짚는다(학생이 다 기억하지 못한다). 그다음 **한 단계씩 차근차근** — 무엇을 왜 할지 말하고, 하고, 결과를 확인하고, 짚은 뒤 다음으로(AI 대기를 녹화 밖으로 빼도 흐름은 잇는다). 앞 단계와는 실제로 배운 내용을 이름으로 받아 화면에서 잇는다(기준_공통 G0). 같은 도입을 복제하지 않는다.
3. **처음 나오는 도구는 설명한다**(VS Code · 포털 화면 · Codex 채팅 · 터미널 · 랩 DB · Neo4j). 통합반은 VS Code를 처음 쓰는 비전공자 기준으로 폴더 열기 · 탐색기 · 편집 · 저장 · 터미널 · AI 채팅을 처음 필요할 때 차근차근 보이고 뒤로 갈수록 줄인다. 실전반도 모른다는 전제로 핵심 위치를 한두 문장으로 짧게 짚되 이번 폴더 · 자료 · 요구 · 실행 위치 · 판정 안내는 줄이지 않는다. 중요한 화면은 자세히, 보조 메뉴는 용도 · 위치만.
4. **진행하면서 매번 이어서 말한다:** 어디를 왜 보는지 → 결과가 무슨 뜻이고 왜 그렇게 나왔는지 → 어떻게 확인하는지 → 어디에 쓰는지. 결과를 띡띡 읽기만 하지 않는다.
5. **말과 조작:** 대상의 위치 · 이름 · 할 일을 먼저 짚기 시작하고, 알아들을 수 있는 시점부터 설명하며 조작한다 — 문단이 끝날 때까지 기다리지 않고, 조작을 끝내고 뒤늦게 해설하거나, 아직 안 나타난 메뉴를 연속 클릭하지 않는다. 결과 설명은 결과가 화면에 나타난 뒤 한다. 선택 해제 · 빈 곳 클릭 · 입력칸 선택 · 탭 전환 · 필요한 키 같은 선행 조작도 말하고 한다. 익힌 기능은 정의를 줄이되 이번 위치 · 입력값 · 선행 조작은 빼지 않는다.
6. **코딩 랩은 바이브 코딩을 매번 실제로 보여 준다.** 랩마다 프롬프트 · 자료 · 판단이 다르므로 일곱 단계(기준_공통 G0-2)를 매 랩 처음부터 끝까지 화면에서 한다. 「바이브 코딩이란」 소개만 첫 코딩 랩에서 한 번.
7. **코드는 설명하지 않는다.** 「코드는 몰라도 된다」고 분명히 말해 안심시키고, 그 실습의 판단 지점(요구를 내 말로 정하기, 결과를 원자료와 대조하기)을 분명히 짚는다. 「AI가 이렇게 만들었습니다」까지만 보이고 판단은 요구 반영 · 원자료 대조 · 다른 입력 · 업무 쓸모로 한다. 화면에 보여 줄 것은 프롬프트 · 스킬 · 명세 · 조건 · 결과이고, 소스 해설 · 파일 목록 · ZIP 구성은 본론이 아니다.
8. **연출하지 않는다**(기준_공통 G3-8). 통합반에서 막히기 쉬운 곳을 더 풀어도 실패를 꾸미지 않는다. 과정 차이는 기준_공통 G2 표.
9. **자료와 마무리:** 코딩 랩은 시작 도구 또는 ZIP으로 받아 VS Code에서 연다(첫 사용은 조작을 보여 주고 이후에는 짧게, 다운로드 서비스 · ZIP 목록 설명은 본론 밖). 마무리는 결과의 실행 · 판정 · 저장 · 다시 열기다.
10. **완성본 리뷰(코딩 랩):** 영상 끝에 학생용 완성본(따로 받는 묶음)을 실행해 방금과 같은 결과가 나오는 것을 보여 주고, 「계정이 없으면 완성본으로 결과를 확인하고, 바이브 코딩 과정은 영상으로 보며 습관을 익히세요」라고 안내한다.
11. **파일 꼴:** 「발화 | 조작·결과 확인 — 비낭독」 표(본보기). 내용 · 순서는 랩 · 가이드에 맞춰 확정하고 발화 · 전환 · 속도는 촬영 때 고칠 수 있다.

## S7 발표자 노트

1. 노트는 오프라인 강의용 메모다. 모든 회차 · 모든 장(간지 · 실습 설명 · 퀴즈 포함)에 그 장만의 노트를 두고, 「앞 장 노트와 같음」처럼 다른 장 노트로 대신하는 노트는 쓰지 않는다.
2. **꼴은 본보기대로** `[짚을 곳]` → `·` 메모(핵심 정의, 꼭 말할 수치 · 경계, 까닭, 헷갈리는 짝, 실습 장은 목표 · 입력 · 결과물 · 성공 기준) → `[다음]`. 덱 MD에서는 한 줄로 쓰고 ` / `가 줄바꿈이다. 말투는 강사의 구어체이고, 「비유 제안:」 같은 라벨 없이 그대로 읽을 수 있게 쓴다.
3. 온라인 대본과 같은 내용 · 순서 · 값이되 글자까지 같을 필요는 없다. 핵심(정의 · 판단 근거 · 수치)은 빠뜨리지 않되 전문을 옮기지 않고, 화면과 대본에 없는 새 핵심을 노트에만 두지 않는다.
4. 노트에는 단원 밖을 예고하는 말을 두지 않는다.

## S8 고친 뒤 맞출 것

1. 함께 맞출 범위는 기준_공통 G4-9다. 구성을 고치면 `구성.json`을 고친 뒤 구성표를 다시 만든다.
2. 음성을 만들기 전에 대본을 장 화면 · 실습 화면과 대조한다 — 대사가 가리키는 위치 · 모양이 실제로 있는지, 실습 안내가 실습의 목적을 말하는지.
3. 점검은 제목과 표시를 뺀 본문을 처음부터 끝까지 이어 읽는 것이다 — 앞에서 배운 것만으로 이해되는지, 정의하지 않은 용어 · 미완료 활동을 전제하지 않는지, 같은 설명을 되풀이하지 않는지, 줄이거나 합친 뒤 필요한 정의 · 값이 빠지지 않았는지, 지금 구현을 일반 원리처럼 말하지 않는지. 낱말 검색 · 빌드 통과 · 자동 받아쓰기로 판정하지 않는다.
