## S1 누가 말하나

1. 대본은 강사 본인이 학생 앞에서 실제로 하는 말 그 자체다. 요약 · 지시 · 해설로 대신하지 않고, 화자를 제삼자로 부르거나 「이 대본에서는」처럼 제작물을 설명하지 않는다.
2. 제목 줄 · 구성표 · 조작 · 기술 메모 · 입력할 프롬프트는 비낭독 표시로 분리한다. 학생에게 필요한 위치 · 조작 안내는 메모가 아니라 발화에 넣는다. 제목은 읽지 않으므로 제목을 들어야만 알아듣는 문장을 쓰지 않는다.
3. 하지 않은 일 · 보지 않은 화면 · 관찰하지 않은 결과를 한 것처럼 말하지 않는다. AI 응답 · 실행 결과 · 추천안 이름 · 점수 · 순위는 대본에 미리 쓰지 않고, 화면에 나온 뒤 읽고 쓴다.

## S2 말투

1. 실제 강사가 차분히 설명하는 구어체로 쓴다. 한 문장에 한 가지를 담는다. 「~입니다」만 반복하지 않고 「~볼게요 · ~네요 · ~죠 · ~하면 돼요」를 문맥대로 섞는다. 어미를 일괄 치환하거나 매 문장에 「보이죠」를 붙이지 않으며, 어미를 바꾼 것으로 윤문이 끝났다고 하지 않는다. 입력할 값 · UI 이름 · 판단 조건은 윤문 중에도 그대로 둔다.
2. 제작 말투를 쓰지 않는다. 이렇게 말고: 「앞 실습에서」 「앞 이론」 「랩 그래프」 「펌프 사십, 팬 칠십」 「판정 · 대조 · 산출물 · 기록 번호」 「~를 가른다」 남발, 시나리오 기호 「A · B · C」, 번역투. 동작을 틀리게 부르지도 않는다(조회를 「생성 · 연결」로, 지도를 「실행」한다고 말하지 않음). 이렇게: 「이론 시간에는 …을 배웠습니다. 이번에는 …을 직접 확인해 보겠습니다.」
3. 과장 · 추임새 · 가상 학생 반응 · 억지 문답 · 드라마를 넣지 않는다.
4. 윤문은 작성자가 스스로 한다. 다 쓴 뒤 처음부터 끝까지 이어 읽으며 고치고, 윤문 기준을 사용자에게 다시 묻지 않는다. 자동 받아쓰기 일치는 자연스러움 검수가 아니다.
5. 사용자가 재생해 확정한 영상의 대본은 문체를 바꾸지 않고, 내용이 틀렸거나 화면과 어긋난 곳만 기준_공통 G4-2대로 전 · 후를 보여 고친다(음성을 다시 만드는 비용이 든다).

## S3 무엇을 소리 내어 읽나

1. 데이터를 읽지 않는다: 부품 번호 · 기록 번호 같은 식별자, 속성 키, 관계 영문명은 뜻으로 말한다. 이렇게: 「펌프 축 씰 키트의 부품 번호」 / 이렇게 말고: 「P-PMP-SEAL」. 「이 값」처럼 무엇인지 모를 지시어로 바꾸지도 않는다. 식별자를 한글 발음으로 옮겨 줄줄이 읽지도 않는다.
2. 예외는 셋뿐이다. ① 문법을 배우는 대목의 언어 키워드(MATCH 등)와 「s는 변수, Sensor는 레이블」 같은 문법 구분 ② 배우는 언어 · 표준의 이름(Cypher · BPMN · MCP)은 영어 그대로 ③ 학생이 직접 입력하는 값은 입력하기 전에 말한다(본보기의 「Type에 OCCURS_IN이라고 적겠습니다」).
3. 같은 이름을 우리말과 영어로 나란히 읽지 않는다. 예외: 화면 UI 언어가 학생 화면과 다를 수 있으면 위치와 두 이름을 함께 짚는다(「왼쪽 탐색기(Explorer)」). 약어는 통용 표기를 쓴다. 장 번호 · 날짜 · 페이지 수처럼 바뀌는 값에 기대어 말하지 않는다.
4. 수치는 무엇의 값인지 → 왜 보는지 → 무엇과 비교하는지 → 어떤 판단이 나오는지를 먼저 말한다. 임계값 · 경계 · 범위처럼 판단을 가르는 값만 정확한 수치와 단위로, 나머지는 「기준보다 낮다」처럼 말한다. 근사 때문에 판정 · 순위가 바뀌면 안 된다. 근거 없는 값 · 인과를 만들지 않고, 뜻과 출처를 설명할 수 없는 값은 읽지 않고 확인 대상으로 남긴다.
5. 명령은 작업 위치 · 목적 · 기대 결과를 한두 마디로 말하고 토큰 · 옵션을 낭독하지 않는다. UI는 위치와 정확한 이름으로 짚고, 실제 화면에서 확인하지 않은 색은 말하지 않는다.

## S4 길이와 시간

1. **온라인 실습 영상:** 내용이 먼저다. 실라버스 항목 · 설명 · 바이브 코딩을 시간과 상관없이 최대한 넣는다. 배정 +10분까지는 괜찮고, 그보다 길면 조정한다. 모자라면 문제다 — 빠진 항목과 얕은 설명을 찾아 그 회차 범위 안에서 보강하고(다음 회차를 당겨오지 않음), 정말 더 넣을 것이 없을 때만 멈추고 사유를 기록한다. 50분 실습이 7분이면 실습이 아니다.
2. 채우는 것은 실질 내용뿐이다. 대기 · 느린 타이핑 · 같은 말 반복 · 가상 학생 · 억지 실패로 채우지 않고, 시간을 줄이려 필수 안내 · 판단 · 결과 확인을 빼지도 않는다.
3. **이론:** 시간은 내용의 결과다. 배정에 맞추려 지우거나 늘리지 않는다. 실라버스 항목 · 정식 용어 · 정의 · 필요성 · 예시 · 판단 근거의 깊이를 최대한 확보하고, 더 보강할 근거가 없으면 멈춘다. 회차별 차이와 누적 차이를 기록한다. 오프라인 이론 덱의 시간은 [기준_이론덱](기준_이론덱.md) D7.
4. **템포:** 실제 강사 복제 음성으로 맞춘 계수 하나(`제작용/촬영/시간계수.json`)로 잰다. 실습 큐는 `제작용/촬영/시간계산.py estimate`, 이론 대본은 `제작용/기존제작/tools/deck/대본시간.py`가 같은 계수를 쓴다. 새 음성이 생기면 `시간계산.py calibrate`(문장 음성) · `calibrate-lecture`(이론 영상 장별 시간)로 다시 맞춘다. 제목 · 제작 메모는 빼고 학습 대기는 따로 센다. 낭독 추정은 실제 진행 시간이 아니다(조작 · AI 응답 대기는 별도). 쉼을 늘이거나 줄여 시간을 맞추지 않는다. 대본을 고치면 같은 계수로 전후 시간을 다시 잰다.

## S5 이론 대본

1. **슬라이드의 어디를 설명하는지 먼저 말한다(가장 중요).** 학생은 화면을 보며 듣는다. 대본이 어느 자리를 설명하는지 말하지 않으면 학생은 슬라이드의 어디를 봐야 할지 모른다. 설명마다 대상과 위치를 먼저 짚는다 — 「왼쪽 그림의 펌프」 「표의 둘째 줄」 「가운데 화살표」 「오른쪽 카드」. 강사가 대본만 읽어도 화면을 짚으며 설명할 수 있어야 한다. 화면의 칸은 가려서 말한다 — 그 장의 메시지를 받치거나, 뒤에서 다시 쓰이거나, 까닭의 고리이거나, 학생이 실습 화면에서 직접 다루는 것만 풀고 나머지는 화면에 맡긴다. 모든 글자 · 수치를 읽는 것으로 화면 대응을 대신하지 않는다.
2. **파일:** `산출물/{과정}/이론/NN회차/대본/`의 분할 파일 하나 = 촬영 구간 하나 = 영상 하나. 맨 위에 제목 · 대응 덱 · 「촬영 전 안내 — 낭독하지 않음」 · 「이 회차의 구성」 표(구분 · 실라버스 제목 · 원래 배정 · 조정 배분 · 해당 SLIDE · 낭독 추정 · 학습 대기, 구성.json에서 만들고 손으로 고치지 않는다).
3. **제목 줄:** 실라버스 행마다 `# [이론] <행 제목> · NN분` 또는 `# [실습] <행 제목> · NN분 (대본은 연결 멘트만)`, 표지 · 학습목표 · 목차는 `# [도입]`, 끝은 `# [마무리]`. 장은 `## [SLIDE NN] 제목`, 장 사이 `---`, 실습 간지와 설명 장은 `## [SLIDE NN~MM]` 한 묶음. 실라버스 이론 행과 촬영 경계를 대조해 나누고, 실습 뒤 복습은 같은 이론 파일에서 이어 간다. 본문 끝에 `# 촬영 본문 끝`과 `## 제작 확인용 — 낭독하지 않음`(노트에 없는 말을 더한 곳과 근거, 뜻풀이를 못 찾은 값, 덱과 어긋나 보이는 곳).
4. **구간의 시작과 끝:** 「이번 시간에는 …」으로 목표 · 물음을 알리고 「다음 시간에는 …」으로 잇는다. 첫 문장을 「그럼 · 그러면 · 그래서 · 자 · 이제 · 이어서」로 시작하지 않는다(`강의영상.py --dry`가 잡는다, 기준_촬영 C9-1). 「영상」이라는 말을 쓰지 않고, 회차 전체는 「이번 회차에서는」이다. 강사 소개는 1회차 첫 구간에서만(경남대학교 피지컬AI 사관학교, 유엔진솔루션즈 연구원 안치윤). 중간 구간 끝에서 하루가 끝난 것처럼 말하지 않는다. 회차 마지막은 짧은 맺음 · 다음 회차 연결 · 끝인사이고 복습을 다시 읽지 않는다. 이런 말은 대본에만 두고 덱에는 넣지 않는다.
5. **자리와 맺음:** 학습목표 · 목차 · 간지 · 실습 시작 · 복습 · 용어 · 퀴즈 · 정답에서는 지금 무슨 자리인지 첫머리에 한 번 말하고 곧바로 물음이나 할 일로 들어간다. 보통 장에는 시작 · 종료 선언을 붙이지 않는다. 한 장 안에서는 설명을 마친 뒤 끝에서 한 번만 맺는다(중간에 「살펴보겠습니다」로 맺고 다시 시작하지 않음).
6. **복습 · 퀴즈:** 복습은 배운 구분을 사건에 적용하거나 헷갈리는 짝을 가린 뒤 근거를 확인하는 일이다. 본문을 다시 읽거나 용어의 영어 이름을 차례로 읽는 것은 복습이 아니다. 퀴즈는 문제와 보기를 말하고 정답의 까닭과 오답의 혼동을 풀어 준다.
7. **이론과 실습의 경계:** 이론은 실습 간지 · 설명 장까지 안내하고 끊는다 — 실습의 목적과 만들 결과를 짧게, 「자료를 내려받고」 같은 부속 동작은 앞세우지 않는다. 실습은 실제 작업 화면에서 따로 시작하고 이론 대본에 실습 발화를 섞지 않는다. 같은 소개를 이론 끝과 실습 시작에서 두 번 하지 않는다. 이론에서 「받은 자료 · 원자료」처럼 실습 자료를 전제한 말을 쓰지 않는다(덱 · 노트 쪽은 기준_이론덱 D2-4).

## S6 실습 대본

1. **강사 원맨쇼로, 하나의 수업처럼 진행한다(가장 중요) — 도구 실습과 코딩 랩 모두.** 강사 본인이 실제로 작업하며 설명한다. 받은 프로젝트는 목적과 요구만 알고 출발한다 — 이미 탐색한 것처럼 내부 구조 · 파일 · 정답 프롬프트를 말하지 않는다. 학생 가이드 읽기 · 학생 작업 · 대기 시간을 넣지 않는다.
2. **바로 실습에 들어가지 않고 먼저 연다:** 지난 이론에서 무엇을 배웠는지 → 오늘 무엇을 왜 하는지(현장에서 왜 필요한지) → 무엇을 만드는지 → 무엇으로 맞았다고 판정하는지 → 어떤 순서로 할지. 그다음 **한 단계씩 차근차근** — 단계마다 지금 무엇을 왜 할지 말하고, 하고, 결과를 확인하고, 무엇을 했는지 짚은 뒤 다음 단계로 간다. AI 대기를 녹화 밖으로 빼도 이 흐름은 끊기지 않게 잇는다. 앞 단계와는 실제로 배운 내용을 이름으로 받아 화면에서 잇는다(잇는 말은 기준_공통 G0). 같은 도입을 복제하지 않는다.
3. **처음 나오는 도구는 설명한다** — VS Code · 포털 화면 · Codex 채팅 · 터미널 · 랩 DB · Neo4j 등. 통합반은 VS Code를 처음 쓰는 비전공자 기준으로 폴더 열기 · 탐색기 · 편집 · 저장 · 터미널 · AI 채팅을 처음 필요할 때 차근차근 보이고 뒤로 갈수록 줄인다. 실전반도 모른다는 전제로 핵심 위치를 한두 문장으로 짧게 짚되, 이번 폴더 · 자료 · 요구 · 실행 위치 · 판정 안내는 줄이지 않는다. 중요한 화면은 쉽고 자세히, 보조 메뉴는 용도 · 위치만 가볍게. 아직 배우지 않은 용어는 지금 화면을 이해할 만큼만 풀고 「뒤에서 직접 다룹니다」로 부담을 낮춘다.
4. **진행하면서 매번 이어서 말한다:** 어디를 왜 보는지 → 결과가 무슨 뜻이고 왜 그렇게 나왔는지 → 어떻게 확인하는지 → 어디에 쓰는지. 결과를 띡띡 읽기만 하지 않는다.
5. **말과 조작:** 대상의 위치 · 이름 · 할 일을 먼저 짚기 시작하고, 알아들을 수 있는 시점부터 설명하며 조작한다 — 문단이 끝날 때까지 기다리지 않고, 조작부터 끝내고 뒤늦게 해설하거나 아직 나타나지 않은 다음 메뉴를 연속 클릭하지 않는다. 결과 설명은 결과가 화면에 나타난 뒤 한다. 선택 해제 · 빈 곳 클릭 · 입력칸 선택 · 탭 전환 · 필요한 키 같은 선행 조작도 말하고 한다. 익힌 기능은 정의를 줄이되 이번 위치 · 입력값 · 선행 조작은 빼지 않는다.
6. **코딩 랩은 바이브 코딩을 매번 실제로 보여 준다:** ① 파일을 바꾸지 않고 AI와 프로젝트를 파악 ② 요구와 기대 답을 내 말로 정함 ③ 계획 검토 ④ 작게 구현 ⑤ 실행 결과를 원자료와 대조 ⑥ 고침 ⑦ 저장하고 다시 열어 확인. 랩마다 프롬프트 · 자료 · 판단이 다르므로 이 과정을 매 랩 처음부터 끝까지 화면에서 한다. 「바이브 코딩이란」 방법 소개만 첫 코딩 랩에서 한 번 한다. 명세 주도 개발(SDD) · 행동 주도 개발(BDD)은 배운 회차(통합 7 · 8, 실전 5)부터 쓰고, 그 전에는 용어 · 명세 문서를 앞당기지 않는다.
7. **코드는 읽어 검사하지 않는다.** 「AI가 이렇게 만들었습니다」까지만 보이고, 판단은 요구 반영 · 원자료 대조 · 다른 입력 · 업무 쓸모로 한다. 화면에 보여 줄 것은 프롬프트 · 스킬 · 명세 · 조건 · 결과이고, 소스 해설 · 파일 목록 · ZIP 구성을 본론으로 삼지 않는다.
8. **연출하지 않는다.** AI가 처음에 맞혔으면 고의 오류를 만들지 않고, 억지 실패 · 재시도 · 「예상과 다르면」 같은 가정 분기를 넣지 않는다. 막혀서 참조 완성본으로 바꾸면 그 사실을 짧게 밝히고, 참조본을 방금 만든 결과로 말하지 않는다. AI 질문 카드의 「(권장)」 선택지는 원문을 열어 보고 고르거나 직접 쓴다.
9. **과정 차이**는 기준_공통 G2 표를 따른다(통합반 코딩 랩에서 막히기 쉬운 곳을 더 풀어도 S6-8대로 실패는 연출하지 않는다).
10. **자료와 마무리:** 코딩 랩은 시작 도구 또는 ZIP으로 받아 VS Code에서 연다 — 첫 사용은 조작을 보여 주고 이후에는 짧게. 다운로드 서비스 · ZIP 목록 설명을 본론에 넣지 않는다. 마무리는 결과의 실행 · 판정 · 저장 · 다시 열기다.
11. **파일 꼴:** 「발화 | 조작·결과 확인 — 비낭독」 표(본보기). 내용 · 순서는 랩 · 가이드에 맞춰 확정하고 발화 · 전환 · 속도는 촬영 때 고칠 수 있다.

## S7 발표자 노트

1. 노트는 오프라인 강의용 메모다. 모든 회차 · 모든 장(간지 · 실습 설명 · 퀴즈 포함)에 그 장만의 노트를 두고, 「앞 장 노트와 같음」처럼 다른 장 노트로 대신하는 노트는 쓰지 않는다([다음]의 잇는 구절은 둔다).
2. 꼴: `[짚을 곳]` 화면에서 짚을 대상과 순서 → `·` 메모 몇 줄(핵심 개념 · 정의, 꼭 말할 수치와 단위 · 경계, 까닭, 헷갈리는 짝, 실습 장은 목표 · 입력 · 결과물 · 성공 기준) → `[다음]` 다음 장으로 잇는 한 구절. 덱 MD에서는 한 줄로 쓰고 ` / `가 줄바꿈이다. 말투는 강사의 구어체이고, 「비유 제안:」 같은 라벨은 떼고 그대로 읽을 수 있는 문장으로 쓴다.
3. 온라인 대본과 같은 내용 · 순서 · 값이어야 하고 글자까지 같을 필요는 없다. 대본의 핵심(정의 · 판단 근거 · 수치)은 빠뜨리지 않되 전문을 옮기지 않는다. 화면과 대본에 없는 새 핵심을 노트에만 두지 않는다.
4. 노트에는 단원 밖을 예고하는 말을 두지 않는다(오프라인 덱의 두 예외는 [기준_이론덱](기준_이론덱.md) D7).

## S8 고친 뒤 맞출 것

1. 이론 대본을 고치면 덱 MD 노트 · PPTX 노트를, 실습 대본을 고치면 그 실습의 가이드 · ZIP을 기준_실습가이드 H5-1대로, 구성을 고치면 `구성.json` → 구성표를 같은 판본으로 맞춘다. 같은 덱을 쓰는 다른 과정 대본도 같은 문장을 맞춘다.
2. 음성을 만들기 전에 대본을 장 화면 · 실습 화면과 대조한다 — 대사가 가리키는 위치 · 모양이 그 화면에 실제로 있는지, 실습 안내가 실습의 목적을 말하는지.
3. 점검은 제목과 표시를 뺀 본문을 처음부터 끝까지 이어 읽는 것이다: 앞에서 배운 것만으로 이해되는지, 정의하지 않은 용어 · 미완료 활동을 전제하지 않는지, 같은 설명을 되풀이하지 않는지, 줄이거나 합친 뒤 필요한 정의 · 값이 빠지지 않았는지, 지금 구현을 일반 원리처럼 말하지 않는지. 낱말 검색 · 빌드 통과 · 자동 받아쓰기로 판정하지 않는다.
