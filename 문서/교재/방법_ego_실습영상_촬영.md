## 1. 핵심 원칙 — 2026-10-22 · 23 사용자 확정

**강사 본인의 자연스러운 시연이다.** 대상의 위치 · 이름 · 할 일을 먼저 짚기 시작하고, 알아들을 수 있는 시점부터 설명을 이어 가며 조작한다. 음성 파일이 끝날 때까지 매번 기다리지 않는다. 조작을 먼저 끝내고 뒤늦게 해설하지 않으며, 결과 설명은 결과가 화면에 나타난 뒤 한다. 선택 해제 · 빈 곳 클릭 · 입력칸 선택 · 탭 전환 · 필요한 키 같은 선행 조작도 말하고 수행한다. 처음 쓰는 기능은 역할과 이유를, 익숙해진 기능은 이번 위치 · 입력값만 말한다. 대사의 표현 기준은 [실습 대본 기준](기준_실습대본.md)을 따른다.

**움직임 프레임이 최우선이다.** 커서 순간이동 금지. 이동 경로가 연속해 보이고 실제 클릭 좌표와 표시 화살표 끝이 맞아야 한다. 출력 30fps · 디코드 성공 · 음성 겹침 0은 합격 근거가 아니다. 이동 중 100ms 이상 프레임 공백은 조사 대상이며, 녹화 중 무거운 계산(원 여러 개 찾기 등)을 넣지 않는다. 타이핑 · 이동을 일부러 늦추거나 모든 조작에 고정 대기를 붙이지 않는다. 입력 중 커서는 글을 가리지 않는 가까운 여백에 둔다.

**실수는 자연스럽다 — 다시 찍지 말고 수습한다. 반복되는 것만 원인을 잡는다.** 헛잡기 · 오타 · 잘못 만든 블록을 지우고 다시 만들기 · 반응 없는 클릭을 다시 누르기 · 위치 조정 · 원이 엉뚱한 곳으로 간 것처럼 사람이 할 법한 사소한 것은 그 화면에서 바로잡아 이어 가고 이미 찍힌 것은 둔다(필요하면 「아, 원 하나가 너무 멀리 끌려갔네요. 다시 끌어오겠습니다」 같은 수습 큐). 커서가 한두 번 휘청이는 정도도 둔다. 다만 같은 문제가 반복되면 사소해도 원인이 있는 문제다 — 원인을 고쳐 다음 구간에 나오지 않게 하고, 반복된 부분만 다시 한다(커서 휘청이 여러 이동에 반복, 1초 안팎 화면 멈춤이 잦음 등). 처음부터 다시 찍지 않는다. 사람처럼 보이려고 실수 · 무의미한 이동을 일부러 만들지 않는다. 녹화가 멈추거나 뒤 구간 내용이 틀어지면 멈춘 큐에서 같은 상태로 이어 찍는다.

**헤매지 말고 길을 뚫는다.** 진행이 막히면 추측 재시도 · 같은 실행 반복을 하지 않고 원인을 확인해 고친 뒤, 그 자리에서 대응을 기록한다(공통은 6절 표, 도구 고유는 그 도구의 촬영준비 표). 뚫린 길은 기록된 방법 그대로 다시 쓴다.

**분할 촬영 · 이어 찍기.** 모든 실습은 기능 · 결과 단위 구간으로 나눠 찍는다. 녹화만 멈추고 같은 페이지 · 입력값 · 선택 · 스크롤 · 배치 상태에서 이어 간다. 쉬는 동안 학습에 필요한 조작을 화면 밖에서 하지 않는다. 실패하면 원본과 끝 상태를 보존하고 실패 직전 큐에서 같은 상태로 이어 찍는다(합성 때 그 시각에서 자름). 정상 구간은 보존한다. 여러 구간을 합친 파일을 무편집 단일 촬영이라고 부르지 않는다.

**상태 복원은 가져오기로, 실행 취소는 최후에.** 녹화 밖에서 이전 끝 상태를 만들어야 하면 저장해 둔 끝 상태 데이터를 새 문서 · 새 그림으로 가져와 맞춘다. 실행 취소는 입력칸 포커스 · 글자 단위 기록 · 되돌려지지 않는 스타일 때문에 다른 내용을 잃기 쉽다.

**사용자와 함께 쓴다.** 사용자가 ego 화면에서 직접 배치 · 입력해 줄 수 있다. 이때는 그 결과를 화면 캡처로 재지 말고 앱의 저장 데이터(예: `localStorage`)를 읽기 전용으로 그대로 쓴다. 사용자가 조작하려면 녹화를 멈추고 `task.handOff()`로 제어권을 넘긴 뒤 `takeOverTaskSpace(<번호>)`로 되찾고, 그 결과에서 다음 구간을 이어 찍는다. 녹화를 유지한 채 사용자가 조작하는 것은 안 된다: 에이전트가 탭을 쥔 동안 사용자 클릭은 페이지에 들어가지 않고 창만 움직인다(ARROWS `manual` 조작으로 시도해 확인). 사용자의 물리 마우스 · 키보드 · 전경 창 · Claude 설정은 건드리지 않는다.

**시간은 촬영 전에 계산한다.** 큐를 쓰면 [시간 계산](../../제작용/촬영/시간계산.py)으로 예상 길이를 낸다. 배정은 구성의 기준이지 채울 최소나 넘으면 안 되는 상한이 아니다. 차이가 크면 촬영 전에 범위를 정하고, 보강은 해당 회차 범위에서만 한다(다음 회차 실습을 앞당기지 않음). 대기 · 느린 입력 · 반복 설명으로 늘리지 않고, 시간을 줄이려 필수 안내 · 판단 · 결과 확인을 빼지 않는다. 계획 시간은 발화와 조작의 합집합이며 말하며 한 조작을 다시 더하지 않는다.

**화면 준비.** 원본 1920×1080, UI 약 150%로 글자를 읽을 수 있게 촬영 전에 정한다. 촬영 중 줌인 · 배속 · 중간 컷으로 조작을 대체하지 않는다. 커서는 후광 없는 흰 화살표 · 얇은 검은 테두리. 참조 영상은 사용자가 지정한 `D:/다운로드/notion-tutorial-1080p-안치윤.mp4`(완벽한 튜토리얼)와 `D:/다운로드/CrDmHzk0W022NnSU56tgag.mp4`(새 참고, 분석 전)이다. 확인하지 않은 버튼 색은 대사에 넣지 않는다.

**커서 표시 보정.** 기록된 위치 · 클릭 시각을 유지하는 표시 보정은 허용한다. 원본 · 음성 · 조작 순서 · 결과는 보존하고 보정판을 구별한다. 하지 않은 조작을 합성하거나 누락된 원본 프레임을 복구했다고 말하지 않는다. 원본 포인터를 안전하게 숨길 수 없어 두 개가 보이면 쓰지 않는다.

## 2. 작업 흐름

1. **큐 원고**: 구간별로 `[구간, 발화, 조작 목록]`을 쓴다. 조작은 발화 안의 시점(`at` 비율)이나 문장 끝 직전에 실행된다. 클릭 · 입력이 별도 행동이면 큐도 나눈다. 촬영 중 수습 큐는 번호를 따로 준다(ARROWS `o091b`처럼) — 뒤 큐 번호 · 음성을 다시 만들지 않기 위해서다. 쓸 수 있는 조작 이름과 인자는 도구 촬영준비의 「큐 조작」 표에 있다(ARROWS: click · type · key · grow · edge · connect · layoutNorm · download · choose · verify 등).
2. **시간 계산**: `python 제작용/촬영/시간계산.py estimate <cues.json> --target <분>`.
3. **음성**: ElevenLabs `eleven_v4`, 「안치윤」 `1PdAOcPlPTz12RwMyFVp`, stability 0.5 · similarity 0.75. 바뀐 문장만 생성한다. 키는 사용자가 지정한 위치(ARROWS: `D:/다운로드/env.txt`, 이론 영상: 환경변수 `ELEVENLABS_API_KEY`)에서만 읽고 출력 · 커밋하지 않는다. `.env`는 열지 않는다. 비용이 드는 생성은 미리 알린다.
4. **구간 녹화**: 시작 상태 확인 → 녹화 → 끝 상태(`end-state.json`) · 프레임 · 행동 시각(`timing.json`) 저장. 한 구간씩 찍고 바로 실측한다.
5. **실측**: 이동별 최대 프레임 공백, 클릭 좌표 오차, 문장보다 늦은 조작. 마지막 프레임을 눈으로 본다.
6. **합성**: 구간 원본 시간 그대로 이어 붙인다(배속 · 중간 컷 없음). 실패 조각은 이어 찍은 큐 시작 시각에서 자른다. 녹음 뒤 큐 문장 · 길이가 바뀌었으면 합성기가 멈춘다.
7. **이음매 확인**: 새 이음매마다 앞뒤 0.2초 프레임을 나란히 본다. 그림 · 내용 연속이 기준이고 패널 선택 표시 차이는 사소로 둔다.
8. **동기화**: 대본 · 가이드 HTML · 입력 · 참조 완성본 · ZIP을 생성기로 함께 갱신한다(대본 · 가이드는 실제 촬영 큐에서 만든다. 수습 큐는 대본에 「다시 할 때는 없음」으로 표시하고 학생 가이드에서는 뺀다).
9. **계수 재보정 · 기록**: `시간계산.py calibrate <근거폴더>` · `check`. 도구 촬영준비 · [작업 상태](작업상태.md) · [남은 일](6_남은_일.md)을 고치고, 사용자 결정은 [결정 기록](5_결정_기록.md)에 남긴다. 경로를 지정해 커밋 · 푸시한다(영상 · 음성 · 자막은 main에 올리지 않음).
10. **사용자 재생 확인**: 확정은 사용자 확인 뒤에만 쓴다. 그 전에는 「미확인」.
11. **학습 포털 연결**: 영상 · 자막을 `other-pc` 브랜치 `course/videos/{통합반,실전반}/<과정>_<NN>회차_<대본 번호>_실습_<이름>.mp4`(대본 파일 이름과 같게, 두 과정 공통이면 같은 파일 두 벌)와 `_작업/영상_자막_기록/`에 올리고 `course/videos/README.md` 표를 고친다. Notion 회차 페이지 「📂 강의 자료 → 🎬 강의 영상」 탭에 그 커밋에 고정한 링크 세 가지(영상 열기 · MP4 내려받기 · 페이지 안 재생 토글)를 다른 영상과 같은 모양으로 넣는다. Notion 커넥터 파일 업로드는 한 번에 20MiB라 영상은 링크로 건다. 공개 저장소 푸시는 사용자에게 먼저 확인한다(자동 승인이 거부한다). 여러 세션이 같은 폴더를 쓰면 브랜치를 바꾸지 말고 임시 인덱스로 커밋을 만든다: `GIT_INDEX_FILE=<.git 안 짧은 경로> git read-tree origin/other-pc` → `git hash-object -w` · `git update-index --cacheinfo` → `git write-tree` · `git commit-tree -p origin/other-pc` → `git push origin <커밋>:refs/heads/other-pc`. 임시 파일을 긴 경로(스크래치 폴더)에 두면 Windows `Filename too long`으로 실패한다. 올린 뒤 raw 링크가 200이고 크기가 원본과 같은지 확인한다.

## 3. ego 촬영 구현

### 연결과 설정

- ego lite(이 PC 0.6)를 설치 · 로그인하는 것은 사용자다. 에이전트는 `ego-browser nodejs -e "await import('file:///<절대경로>.mjs?<판>')"`로 스크립트를 실행한다. 한글 · 긴 코드는 `-e`에 넣지 말고 UTF-8 `.mjs`로 저장해 불러온다.
- 작업 공간은 `taskSpace(<번호 또는 이름>)`로 쥐고, 같은 작업은 같은 공간을 쓴다(ARROWS 6, Notion `notion rhythm 20261023`). 다른 세션과 같은 공간 · 같은 페이지를 동시에 조작하지 않는다(상태 파일 EPERM).
- 해상도: 녹화 스크립트 안에서 매번 `Emulation.setDeviceMetricsOverride`를 도구 `config.json` 값으로 설정한다(ARROWS 2304×1296 dsf1 → CSS 1536×864, Notion 1536×864 dsf1 → CSS 1024×576, 둘 다 프레임 1920×1080). 한 도구 안에서는 바꾸지 않는다(구간 이음매가 달라짐). 스크립트가 끝나면 풀리므로 확인 · 복원 스크립트에서도 먼저 설정한다.
- 녹화: `Page.startScreencast`(JPEG), 프레임을 받는 즉시 저장하고 ACK. 앞에 보이는 탭에서만 프레임이 온다. ego 창을 최소화하지 않고 다른 창 뒤에 둔다.

### v10 진행 리듬(ARROWS · Notion 공통)

- 모든 ego 호출은 하나의 직렬 큐로 보낸다(캡처 ACK와 조작이 번갈아 쓰게). 긴 이동 명령이나 문자열 전체 입력을 한 항목으로 넣지 않는다.
- 표시 포인터는 페이지에 그린 SVG 화살표를 `element.animate`(컴포지터)로 움직이고, 실제 입력은 같은 경로를 8단계 `mouse.move(steps:1)`로 보낸다(16단계는 명령이 밀렸다). 메인 스레드에 묶인 포인터 갱신이 끊김의 원인이었다. 애니메이션이 목표에 닿아도 실제 입력이 모두 끝날 때까지 화살표를 목표에 고정한다 — 늦게 도착한 중간 입력이 화살표를 뒤로 끌어 목표에서 튀는 휘청이 거의 모든 이동에서 났다(Notion 25~29구간). 메뉴처럼 위치가 바뀌는 대상은 150ms 간격 두 번 같은 위치일 때 출발한다.
- 녹화 전에 PC 부하를 본다: 화상회의(Zoom 등) · 큰 앱이 돌거나 남은 메모리가 2GB 안팎이면 녹화하지 않는다(Notion 30~36구간에서 1~2초 정지 반복, 입력 명령 시간 초과). 녹화 중에는 같은 PC에서 인코딩 · 검사 같은 무거운 작업을 하지 않는다.
- 안전장치: 녹화 시작 전에 조작 큐가 돌면 즉시 실패, 앞 구간이 실패하면 뒤 구간을 시작하지 않는다(엉뚱한 화면에서 다음 구간이 돈 사고). 이어 찍을 때는 앞 구간 끝 페이지를 열고 화살표를 끝 위치에 다시 그린 뒤 시작한다. 반응 없는 클릭 · 덜 잡힌 선택은 사람처럼 한 번 더 한다.
- 판정은 숫자와 화면을 함께 본다: 구간마다 이동 중 최대 공백 · 클릭 오차 · 막아 낸 늦은 입력 수를 남기고, 큰 값이 나온 이동은 앞뒤 프레임을 잘라 화살표 위치를 직접 본다. 메뉴 · 창을 연 직후 화살표가 출발하기 전 1~2초 서 있는 것(페이지가 바빠 출발 명령이 늦음)과 이동 중 건너뜀을 구별한다.
- 조작은 행동 문장이 끝나기 약 250ms 전에 실행(gate)하고, 다음 음성은 행동 종료 + 250ms에 시작한다. 결과 발화는 행동 종료 뒤.
- 입력 중 커서를 입력칸 아래로 비킨다. 한글은 완성형 글자 단위 입력이며 IME 조합 시연이 아니다.
- 구현 위치(저장소): ARROWS에서 완성한 녹화 도구는 [`제작용/촬영/arrows/촬영도구/`](../../제작용/촬영/arrows/촬영도구/)에 있다 — `ctrl.mjs`(구간 녹화) · `ui.mjs`(arrows 대상 찾기 · 조작) · `restore.mjs`(녹화 밖 상태 복원 · 저장 좌표 읽기) · `run.sh`(ego 실행기: `rec` · `restore` · `coords`) · `voice.py` · `encode.py` · `measure.py` · `plan_order.py` · `common.py` · `config.json`. PC마다 다른 값은 `config.json`(근거 폴더 상대 경로 · ego 공간 이름 · 키 파일 위치)과 환경변수 `FFMPEG`로만 받는다. 녹화 원본 · 음성 · 끝 상태는 근거 폴더(`.evidence/`, Git 밖)에 쌓인다. 새 도구는 이 폴더를 복사해 `ui.mjs`의 대상 찾기와 큐 조작만 바꾼다. Notion은 같은 구성으로 [`제작용/촬영/notion/촬영도구/`](../../제작용/촬영/notion/촬영도구/)에 있다 — `segs/seg-NN.mjs`(기능 구간) · `lib/`(Notion 대상 찾기 · 조작) · `restore.mjs`(구간별 자른 시점 복원) · `chain.sh`(구간 연속 녹화). `제작용/촬영/ego/`의 예제는 1280×800 시절 최소 재현이며 현재 리듬이 아니다.

## 4. 도구 유형별 길

### 일반 웹 페이지 — Notion · 포털 · Neo4j Browser의 입력 화면

- 대상은 DOM에서 찾는다(보이는 요소, 정확한 텍스트 · 역할). 화면 밖 요소를 고정 좌표로 누르지 않는다. 150%에서 표 오른쪽 도구가 밀리면 보이는 열을 줄이거나 전체 페이지로 연다(촬영 중 확대 변경 금지).
- 클릭 직전 대상 위치를 한 번 더 읽어 움직였으면 다시 간다(레이아웃이 바뀌는 앱).
- 서비스 장애 문구가 녹화에 들어가면 그 구간을 교체한다. 시작 전 서비스 상태를 확인한다(Notion 2026-10-23 전체 장애 사례).
- 촬영 전용 문서 · 페이지 하나만 만들어 이어 쓰고 재시도마다 사본을 늘리지 않는다. 최종본은 촬영으로 덮어쓰지 않는다.

### 캔버스 · 그래프 도구 — ARROWS · Neo4j Browser 그래프 · bpmn.io

DOM에 대상이 없으므로 아래 길을 쓴다. 값과 앱별 함정은 [ARROWS 촬영준비](../../제작용/촬영/arrows/촬영준비.md) 표에 있다.

- **대상 찾기**: 캔버스 그리기 함수(`arc` · `fillText`)를 감싸 마지막 한 판의 원 · 글자 위치를 기록한다(원래 함수는 보관해 두 번 감싸지 않음). 글자는 가장 가까운 원에만 배정하고 이름 조각을 모아 정확히 일치시킨다. 원 반지름은 그림 전체가 같으므로 가장 큰 반지름의 75% 이상만 원으로 본다(라벨 알약 모서리 제외). 기록이 비면 `resize` 이벤트로 다시 그리게 한다.
- **화면 자동 맞춤**: 그래프 앱은 그림 전체를 화면에 맞춘다. 위치는 150ms 간격 두 번 읽어 멈춘 뒤 누른다. 원을 그림 바깥으로 끌면 끄는 중에도 계속 축소돼 폭주하므로 기존 원은 그림 범위 안에서만 옮긴다.
- **배치**: 저장 좌표(그림 좌표)로 설계하고, 두 기준 원으로 배율을 재 화면 좌표로 바꿔 끈다. 사용자 배치는 그 그림의 저장 좌표를 그대로 읽는다. 옮기는 순서는 녹화 전에 계산해 큐에 고정한다(아직 안 옮긴 원 자리에 놓지 않음, 그림 범위가 줄지 않음 — ARROWS `plan-order.py`). 녹화 중 순서를 다시 계산하지 않는다.
- **선택 · 빈 곳**: 화살표는 출발 원 쪽 35% 지점을 누른다(모이는 도착 원 근처의 다른 선 회피). 빈 곳은 고정 좌표가 아니라 원 · 화살표 · 글자에서 가장 먼 캔버스 지점을 한 번의 페이지 평가로 고른다.
- **새 원 · 관계 만들기**: 테두리 끌기 시작점은 반지름×1.09, 이어진 화살표 방향 · 다른 선 16px · 바깥 글자 22px 안을 피해 빈 곳을 찾는다. 관계 이름이 잘리지 않게 원 사이 거리를 넉넉히(선 길이 약 2배).
- **확인**: 저장 · 다시 열기 뒤 노드 · 관계 · 속성 수를 저장 데이터로 대조한다.

### 데스크톱 앱 — VS Code · 설치 화면 · 파일 탐색기

ego 페이지 녹화 범위 밖이다. 웹 VS Code를 로컬 VS Code와 같다고 보지 않는다. 별도 가상 화면(Docker 등) 또는 데스크톱 녹화 경로가 필요하며 아직 이 리듬으로 검증되지 않았다. 상태는 [환경세팅 촬영준비](../../제작용/촬영/환경세팅/촬영준비.md)를 따른다. 원칙(1절)과 흐름(2절)은 같게 적용한다.

## 5. 완료 판정과 기록할 것

발화 · 행동 타임라인, 실제 화면 결과, 이동 프레임 공백 · 클릭 오차, 음성 · 영상 재생, 이음매를 각각 확인한다. 구간 순서 · 실측 시간 · 연결 상태 · 남은 확인을 도구 촬영준비에 적는다. 결과는 검증됨 / 미검증으로 나누고, 청취 · 사용자 재생은 실제로 한 경우만 확인이라고 쓴다.

## 6. 오류 대응표 — 공통

도구 고유 함정은 각 촬영준비 표에 둔다. 새 원인을 찾으면 해당 행을 고치거나 더한다.

| 증상 | 원인 · 대응 |
|---|---|
| 명령이 출력 없이 멈춤(목록 조회는 됨) | 시간 초과로 CLI를 끊어도 스크립트는 ego의 `ego.mojom.NodeService`에서 계속 돈다. 그 utility 프로세스만 종료한다(창 · 탭 유지). 브라우저 본체는 끄지 않는다. 끊긴 명령이 실제로는 실행됐을 수 있으니 상태를 확인한다 |
| 스크립트가 조용히 멈춤 | 문법 오류. 보내기 전에 `node --check`. 코드에 줄바꿈 문자는 `String.fromCharCode(10)` |
| 고친 파일이 반영되지 않음 | 같은 `file:///` 주소 모듈은 다시 실행되지 않는다. 실행마다 `?판` 표시나 새 이름 |
| 셸 스크립트 안에서만 멈춤 | `ego-browser nodejs -e`가 stdin을 기다린다. `< /dev/null` |
| 뒤쪽 탭 프레임 없음 | 앞에 보이는 탭에서만 녹화 · 확인 |
| 해상도 · 배율이 풀림(원이 작게 잡힘) | `setDeviceMetricsOverride`는 스크립트가 끝나면 풀린다. 모든 스크립트 시작에서 설정 |
| 이동 중 프레임 공백 | 큐 점유(긴 이동 · 전체 문자열 입력 · 녹화 중 무거운 페이지 평가)와 같은 PC의 CPU 경쟁(녹화 중 같은 세션이 검사 · 변환을 돌림 — Notion take-27 4회)을 확인한다. 녹화 중에는 무거운 작업을 하지 않는다. 포인터는 컴포지터 애니메이션, 입력은 16단계. 출력 fps · 복제 프레임으로 숨기지 않음. 숫자만 보지 말고 공백 앞뒤 프레임의 화살표 위치를 잘라 본다(출발 전 정지와 이동 중 건너뜀 구별) |
| 대상 앞에서 화살표가 한 번 더 움직임(휘청) | 메뉴가 걸러지는 중 · 레이아웃이 움직이는 중에 출발함. 150ms 간격 두 번 같은 위치일 때 출발한다 |
| 화살표가 목표에 닿은 뒤 뒤로 튀었다 돌아옴(휘청) | 늦게 도착한 실제 입력이 애니메이션이 끝난 화살표를 끌어당김. 실제 입력이 모두 끝날 때까지 화살표를 목표에 고정한다(3절) |
| 1~2초 화면 정지 · 입력 명령 시간 초과가 갑자기 반복 | 같은 PC의 화상회의 · 메모리 부족(Notion: Zoom 실행, 여유 1.9GB). 녹화를 멈추고 부하가 사라진 뒤 멈춘 큐부터 이어 찍는다 |
| 앞 구간이 실패했는데 다음 구간이 돎 | 실행 묶음이 실패를 무시함. 구간 연속 실행은 실패 시 멈추는 실행기(`chain.sh`)로만 한다 |
| EPERM 상태 파일 충돌 | 같은 공간의 중복 실행. 한 프로세스 · 직렬 큐, 세션마다 공간 분리. 실행 중인 다른 명령은 `ego-browser.exe` 프로세스로 확인한다(`NodeService`는 스크립트가 끝나도 남는 상주 프로세스라 기준이 아님) |
| 사용자 클릭이 페이지에 안 들어감 | 에이전트가 제어 중. `handOff` → 사용자 조작 → `takeOverTaskSpace` |
| 녹화 밖 복원이 꼬임 | 입력칸 포커스면 Ctrl+Z가 칸으로 감, 스타일은 안 되돌아감, 지나치면 글자 단위로 지워짐. 끝 상태 데이터 가져오기로 복원(1절) |
| 최소화된 ego 캡처 오류 | 사용자가 복원한 뒤 새 시험. 자동으로 앞에 띄우지 않음 |
| 캡처에 커서 없음 | 페이지 내부 포인터 설치 · `mousemove` 수신 확인. 운영체제 포인터 녹화라고 하지 않음 |
