## C1 원칙

1. **강사 본인의 자연스러운 시연이다.** 말과 조작의 순서는 기준_대본 S6-5(대상을 먼저 짚기 시작하고 설명하며 조작, 결과는 나타난 뒤 말함, 선행 조작도 말하고 수행)를 따른다. 긴 대본이나 이미 만든 음성 길이에 맞춰 화면을 기다리게 하지 않고, 문장마다 멈추는 낭독 리듬으로 만들지 않는다.
2. **움직임 프레임이 최우선이다.** 커서 순간이동 금지. 이동 경로가 연속해 보이고 실제 클릭 좌표와 표시 화살표 끝이 맞아야 하며, 클릭의 누름 · 뗌과 선택 변경이 화면에 나타나야 한다. 커서뿐 아니라 스크롤 · 드래그 · 타이핑 · 전환 모두 사람이 목표를 보고 연속해서 조작하는 속도로 — 작은 이동 호출과 대기를 반복해 찔끔찔끔 움직이지 않는다. 타이핑 · 이동을 일부러 늦추거나 모든 조작에 고정 대기를 붙이지 않고, 사람처럼 보이려고 무의미한 이동 · 실수를 만들지 않는다. 짧은 입력은 직접 치고 긴 명령 · URL은 붙여넣어도 된다. 커서는 설명 · 입력 중인 글을 가리지 않는 가까운 여백에 둔다. 스크롤은 문맥이 보존되는 범위로 하고 이유 없이 왕복하지 않으며, 결과는 눈으로 확인할 여유를 준다. 커서가 한두 번 휘청이는 정도는 둔다(반복되면 C7). 녹화 중에는 같은 PC에서 무거운 계산 · 인코딩 · 검사를 돌리지 않는다.
3. **실수는 자연스럽다 — 다시 찍지 말고 수습한다.** 헛클릭 · 오타 · 위치 조정 같은 사소한 것은 그 화면에서 바로잡고 이어 간다(필요하면 짧은 수습 큐). 같은 문제가 반복되면 원인이 있는 문제다 — 원인을 고치고 반복된 부분만 다시 한다. 처음부터 다시 찍지 않는다. 상태가 망가져 수습할 수 없을 때만 C1-4대로 실패 직전 큐에서 이어 찍는다. 사용자가 재생해 확정한 영상은 다시 찍지 않는다(고침은 기준_공통 G4-2, 시간이 모자라도 보강은 새 영상에서).
4. **분할 촬영 · 이어 찍기.** 모든 실습은 기능 · 결과 단위 구간으로 나눠 찍고, 녹화만 멈춘 뒤 같은 페이지 · 입력값 · 선택 · 스크롤 · 배치 · 배율 · 패널 · 커서 상태에서 이어 간다. 다음 구간 첫 프레임을 앞 구간의 실제 절단 프레임과 대조한다(배율 · 위치 · 선택이 갑자기 바뀌면 정상 이음매가 아님). 쉬는 동안 학습에 필요한 조작을 화면 밖에서 하지 않는다. 실패하면 원본과 끝 상태를 보존하고 실패 직전 큐에서 같은 상태로 이어 찍는다(정상 구간은 보존). 배속 · 중간 컷 · 편집 확대로 필요한 조작을 대신하지 않고, 여러 구간을 합친 파일을 무편집 단일 촬영이라 부르지 않는다. 앞 구간이 실패하면 뒤 구간을 시작하지 않는다.
5. **기다리는 일은 녹화 밖으로.** AI 추출 · 판단, Codex 응답처럼 기다리는 시간은 구간 사이로 빼고, 끝난 것을 확인한 뒤 다음 구간을 찍는다. 대기로 영상을 늘리지 않는다.
6. **상태 복원은 가져오기로, 실행 취소는 최후에.** 녹화 밖에서 이전 끝 상태를 만들어야 하면 저장해 둔 끝 상태 데이터를 가져와 맞춘다(실행 취소는 입력칸 포커스 · 글자 단위 기록 때문에 다른 내용을 잃는다). 실제 조작과 상태 확인을 구별한다.
7. **화면 준비.** 원본 1920×1080 · UI 약 150%는 시작값이고, 기준은 학생이 실제 재생 크기에서 설명 대상의 글자 · 속성 · 관계를 읽을 수 있는가다. 전체 지도는 구조를 소개 · 정리할 때, 개별 대상은 읽을 크기로 확대해 보여 주고, 앱의 실제 줌 · 이동 · 패널 조절은 설명과 함께 한다. 촬영 전에 대표 화면을 실제 녹화 프레임으로 확인한다(1080p 출력이나 디코드 통과는 가독성 합격이 아니다). 커서는 후광 없는 흰 화살표 · 얇은 검은 테두리. 확인하지 않은 버튼 색은 대사에 넣지 않는다.
8. **새 실습 시작 화면은 깨끗하게.** 이전 시연의 입력 · 결과 · 오류 · 열린 메뉴 · 탭 · 알림을 정리하고 실제 첫 프레임으로 확인한다. 이어 찍기에 필요한 직전 학습 결과는 보존한다. 수업 중 정리 · 패널 접기 · 탭 전환은 무엇을 왜 하는지 말하며 한다. 화면 정리와 DB 데이터 삭제를 혼동하지 않는다. 개인 페이지를 정리한다고 지우지 않는다.
9. **촬영 전용 공간 하나.** 촬영은 전용 문서 · 페이지 하나에서 이어 쓰고 재시도마다 사본을 늘리지 않으며, 최종본은 촬영으로 덮어쓰지 않는다.
10. **사용자의 것은 건드리지 않는다.** 사용자의 물리 마우스 · 키보드 · 전경 창 · Claude 설정을 바꾸지 않는다. 사용자가 배치한 데이터는 읽기 전용으로만 쓴다. 사용자가 직접 배치 · 입력하면 녹화를 멈추고 작업 공간을 사용자에게 넘긴 뒤 되찾고, 그 결과는 화면 캡처가 아니라 앱 저장 데이터로 읽는다. 사용자가 ego 공간을 잡고 있으면 우회하지 않고 「계속」을 받은 뒤 되찾는다. 인증 정보와 개인 화면(개인 Notion 페이지 · 계정 화면 · 사용자의 Codex 대화 목록)은 공개 영상 · other-pc에 넣지 않는다.
11. **커서 표시 보정**은 기록된 위치 · 클릭 시각을 유지할 때만 허용하고 보정판을 구별한다. 하지 않은 조작을 합성하거나 누락 프레임을 복구했다고 말하지 않는다. 원본 포인터를 숨길 수 없어 두 개가 보이면 쓰지 않는다.
12. **설치 구간만** 다운로드 · 재부팅 대기를 줄여도 된다(C3-3 「배속 · 중간 컷 없음」의 유일한 예외, 다른 실습으로 확대하지 않는다).
13. **AI 응답 재생**(키 없는 학생용)은 포털 실습(워커)에만 쓴다. 코딩 랩은 모델을 실제로 부른다(기준_실습랩 L5-4). 재생으로 찍은 영상은 기준_공통 G3-3대로 재생 모드임을 한 번 밝힌다.

## C2 순서

1. 실습 하나의 전체 순서는 기준_실습랩 L1이고, 촬영 쪽은 **준비 → 리허설 1회 → 수정 → 본 촬영 → 사진 추출 → 동기화** 순서다. 준비 때 랩 코드 · 입력 · 시작본 · 참조본 · 완료 조건과 대본 초안 · 가이드 단계를 정적으로 맞추고, AI 응답 · 실행 결과는 미리 확정하지 않고 관찰할 항목과 판단 조건만 준비한다. 리허설은 한 번으로 실행 · 흐름 · 시간을 함께 보고(학생 경로 리허설 기준_실습랩 L7-1 ①을 겸한다, 준비 · 설명 · AI 대기 · 구현 · 확인 · 막힘 · 완성본 전환을 구별해 기록), 고친 뒤에는 바뀐 곳과 영향받는 연결만 다시 본다. 사진은 기준_실습가이드 H3-2대로 본 촬영 화면에서 뽑는다(사진 가이드 완성은 촬영의 선행 조건이 아니다).
2. 촬영은 실라버스 순서대로, 그 실습의 랩 코드 수정이 끝난 뒤 시작한다. 새 리듬 · 도구는 대표 구간 1~2분을 먼저 찍어 보여 주고 품질을 확인한 뒤 전체로 넓힌다.
3. **길뚫기**는 처음부터 전달까지 실제로 통과한 제작 경로를 남기는 일이다(학생 시작 상태 → 환경 준비 → 대본 · 음성 → 리허설 → 촬영 → 합성 → 검증 → 가이드 · 배포). 새 세션이 그대로 쓸 실행 파일 · 입력 설정 · 시작/끝 상태 · 결과 경로 · 재개 지점 · 검증 근거를 도구 촬영준비에 바로 기록한다. 길을 뚫을 때는 상태를 바꾸지 않는 보기만 한다(되돌릴 수 없는 조작 뒤 화면은 코드 · API로 미리 알아 둔다). 이미 뚫은 길은 재사용하고, 코딩 랩 전에는 안 뚫린 길(Codex 채팅 · 터미널 · 시작 도구 장면 · 별도 랩 DB)을 먼저 뚫는다. 막히면 추측 재시도 대신 원인을 확인하고 그 구간만 고친다.
4. 새 세션 · 요약 뒤 재개 · 실패 직후에는 기준_공통 G1-4 · G3-5에 더해 그 도구 촬영준비를 다시 읽고, 지금 PC의 실제 도구 사용 가능 범위를 먼저 확인한다. 과거 공간 번호 · 페이지 이름을 추측해 쓰지 않는다.
5. **시간은 촬영 전에 계산한다**(도구 · 계수는 기준_대본 S4-4). 계획 시간은 말과 조작의 합집합이다(말하며 한 조작을 다시 더하지 않음). 분량 기준은 기준_대본 S4 — 차이가 크면 촬영 전에 범위를 정하고, 보강은 그 회차 범위에서만 한다.

## C3 작업 흐름

1. **큐 원고:** 구간별 `[구간, 발화, 조작 목록]`. 조작은 발화 안 시점이나 문장 끝 직전에 실행되고, 클릭과 입력이 별도 행동이면 큐도 나눈다. 촬영 중 수습 큐는 번호를 따로 준다(뒤 큐 번호 · 음성을 다시 만들지 않으려고).
2. **시간 계산 → 음성(C4) → 구간 녹화:** 시작 상태 확인 → 녹화 → 끝 상태 · 프레임 · 행동 시각 저장(파일 이름은 도구 촬영준비). 한 구간씩 찍고 바로 실측한다(이동별 최대 프레임 공백, 클릭 좌표 오차, 문장보다 늦은 조작, 마지막 프레임). take는 매번 새 이름으로 보존하고, 실패 · 잘못된 상태 take는 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.
3. **합성:** 구간 원본 시간 그대로 이어 붙인다(배속 · 중간 컷 없음). 실패 조각은 이어 찍은 큐 시작 시각에서 자른다. 발화가 시작된 뒤를 임의로 자르지 않는다. 녹음 뒤 문장 · 길이가 바뀌었거나, 발화 중간 절단 · 큐 누락/중복 · 저장 결과 불일치가 있으면 합성기가 멈춘다.
4. **이음매:** 새 이음매마다 앞뒤 0.2초 프레임을 나란히 본다(그림 · 내용 연속이 기준).
5. **동기화:** 실제 촬영 큐에서 바뀐 대사 · 입력 · 순서 · 결과만 기준_실습가이드 H5-1대로 대본 · 가이드 · 입력 · 참조본 · ZIP에 맞추고, 사소한 발화 차이 때문에 재촬영하지 않는다. 수습 큐는 대본에 「다시 할 때는 없음」으로 표시하고 가이드에서는 뺀다.
6. **기록:** 도구 촬영준비에 구간 순서 · 실측 시간 · 연결 상태 · 남은 확인을 적는다(계수 다시 맞추기는 기준_대본 S4-4).
7. **Codex 요청이 있는 코딩 랩**은 구간을 나눈다(검증 상태는 `제작용/촬영/vscode/촬영준비.md`): ① 요청 구간(왜 이 요청을 하는지 + 요청 문장은 미리 쓰고, 전송 뒤 응답이 흐르기 시작하는 몇 초까지 녹화) ② 녹화 밖 대기(편집 승인 창은 `결과/` 아래일 때만 허용, 승인 장면은 첫 등장 랩에서 한 번 녹화) ③ 끝난 응답 · 바뀐 파일 · 실행 출력을 읽어 본 것만으로 「결과 확인」 큐를 쓰고 이때 음성을 만듦 ④ 결과 확인 구간(이미 있는 응답을 짚고 결과 파일 · 원자료를 열어 대조, Codex를 다시 부르지 않음).

## C4 음성

1. ElevenLabs 강사 복제 음성(목소리 「안치윤」)만 쓰고 OpenAI 음성은 절대 쓰지 않는다. 모델 · 목소리 · 설정값은 도구 기본값이다(바꾸지 않음).
2. 비용(글자 수 · 크레딧)은 기준_공통 G4-4대로 먼저 알린다. 바뀐 문장만 생성한다. 대본과 화면을 맞춘 뒤에 만든다(초안 판본에 맞춰 최종 음성을 먼저 만들지 않음).
3. 키는 환경변수 `ELEVENLABS_API_KEY`나 사용자가 지정한 위치에서 읽는다(비밀 원칙은 기준_공통 G5).
4. 전체 음성을 먼저 만들어 화면을 억지로 맞추지 않고 안내 → 조작 → 결과 단위로 맞춘다. 녹화 뒤 화면과 다른 대사를 찾으면 그 문장만 고쳐 다시 녹음한다(구간 길이 안에서).

## C5 ego 구현과 도구 유형별 길

포털 촬영은 클라우드 세션 Playwright가 정본이고(`제작용/촬영/포털/촬영준비.md`, 스킬 hyd-portal-video), 로컬 ego로 찍은 포털 구간(지식 지도)은 같은 문서 6절에 있다. 이 절의 ego 구현은 그 밖의 도구(ARROWS · Notion · Neo4j · VS Code)와 포털의 로컬 구간에 쓴다. 호출 방법 · 공간 API · 해상도 설정 · 지연 값 같은 구현 세부는 도구 촬영준비가 갖는다.

1. 설치된 `ego-browser skill` 출력도 끝까지 읽는다(API는 설치 버전이 우선). ego lite 설치 · 로그인은 사용자가 한다. 스크립트는 보내기 전에 문법을 검사하고, 고친 스크립트가 실제로 다시 실행됐는지 확인한다.
2. 같은 작업은 같은 작업 공간을 쓰고, 다른 세션과 같은 공간 · 페이지를 동시에 조작하지 않는다.
3. 해상도 · 배율은 녹화 스크립트마다 도구 `config.json` 값으로 설정하고 한 도구 안에서는 바꾸지 않는다. 녹화는 받은 프레임을 즉시 저장하고, 앞에 보이는 탭에서만 프레임이 오니 ego 창을 최소화하지 않는다.
4. 진행 리듬: 모든 ego 호출은 하나의 직렬 큐로. 표시 포인터와 실제 입력은 같은 경로 · 같은 시각으로 움직이고, 실제 입력이 다 끝날 때까지 표시 포인터를 목표에 고정한다. 위치가 바뀌는 대상은 멈춘 것을 확인한 뒤 출발한다. 조작은 행동 문장이 끝나기 직전에 실행하고 다음 음성은 행동이 끝난 뒤 시작한다. 녹화 시작 전에 조작 큐가 돌면 즉시 실패시키고, 긴 이동 · 긴 문자열 입력을 큐 한 항목에 넣지 않는다. 녹화 전에 서비스 상태와 PC 부하를 보되 수치만으로 중단하지 않고 실제 반응 · 프레임 간격으로 판정한다.
5. **일반 웹 페이지**(Notion · 포털 · Neo4j 입력 화면): 대상은 DOM에서 보이는 요소 · 정확한 텍스트로 찾고 화면 밖 요소를 고정 좌표로 누르지 않는다. 클릭 직전 위치를 다시 읽는다. 서비스 장애 문구가 녹화에 들어가면 그 구간을 교체한다.
6. **캔버스 · 그래프 도구**(ARROWS · Neo4j 그래프 · bpmn.io): 그리기 함수를 감싸 대상 위치를 기록하고, 자동 맞춤 · 선택 상태가 구도에 주는 영향을 앱마다 확인한다. 배치 순서는 녹화 전에 계산해 큐에 고정하고(녹화 중 재정렬 X) 저장 · 다시 열기 뒤 노드 · 관계 수를 저장 데이터로 대조한다. 값과 함정은 도구 촬영준비.
7. **VS Code:** 공식 `code serve-web`을 ego 탭으로 열어 같은 리듬으로 찍는다. 웹판과 네이티브의 동선 차이는 숨기지 않고 따로 처리한다(가이드 사진은 기준_실습가이드 H3-2). CDP 원격 디버깅 경로는 쓰지 않는다. 설치 화면 · 파일 탐색기 같은 데스크톱 앱 촬영의 검증 상태는 `제작용/촬영/vscode/촬영준비.md`.
8. 촬영 도구는 `제작용/촬영/<도구>/촬영도구/`에 있고 PC마다 다른 값은 `config.json`과 환경변수로만 받는다. 녹화 원본 · 음성 · 끝 상태는 `.evidence/`(Git 밖)에 쌓인다. 포털 · Docker를 쓴 작업이 끝나면 Docker Desktop을 끄고 프로세스가 0인지 확인한다.
9. 같은 정지가 반복돼 ego로 시간이 들면 저비용 · 고효율인 다른 방식(순수 Playwright 등)으로 옮겨도 된다. C1 · C6 기준은 같다.

## C6 검사와 완료

1. **기술 검사**(게시 전 모두, 결과는 `.evidence/`): `verify`(길이 · 싱크 · 무음), `listen`(받아쓰기 대조 — 출력의 「확인할 것」 문장을 매번 눈으로), `scenes`(끝까지 2~3초 간격 장면을 **모두** 보고 의심 구간은 0.5초 간격으로), 이음매, 이동 중 프레임 공백 · 클릭 오차(100ms 넘는 공백은 프레임을 잘라 직접 봄) · 표시 커서와 실제 입력(드래그)이 함께 촘촘한지, 영상 · 음성 끝 시각이 구간 합계와 0.1초 안. 이었거나 잘랐으면 합본에 다시 한다.
2. 출력 30/60fps · 디코드 성공 · 음성 겹침 0 · 자동 받아쓰기 일치는 합격 근거가 아니다. 포인터 끊김을 자연스러운 대기로 포장하지 않는다. 말과 조작이 겹쳤다는 이유만으로 오류 판정하지 않는다(기준_대본 S6-5). 일부 프레임 · 표본만 본 것은 기준_공통 G4-7대로 표본 범위만 적는다.
3. **기술 검사는 「완료」가 아니다.** 수업 성립은 기준_실습랩 L7-3대로 따로 판정한다.
4. 청취 · 사용자 재생은 실제로 한 것만 `확인됨`이다(직접 청취 도구가 없으면 `미확인`). 영상 파일이 있다는 것과 사용자 품질 승인은 다르다 — 확정은 사용자가 재생해 본 뒤에만 쓰고, 기존 영상의 청취 판정을 기다리느라 다른 단계를 멈추지 않는다. 무음 캡처를 완성 영상으로 표시하지 않는다. 「검증했다」고 보고할 때는 무엇을 어떻게 봤는지(간격 · 문장 수 · 관찰)를 함께 쓴다.

|---|---|
| 명령이 출력 없이 멈춤 | 끊어도 스크립트는 ego `NodeService`에서 계속 돈다 — 그 utility 프로세스만 종료하고(창 · 탭 유지) 실제로 실행됐는지 상태를 확인한다 |

| 해상도 · 배율이 풀림 / 1080p인데 글자가 작음 | 모든 스크립트 시작에서 metrics 설정 / 실제 UI 배율 · 대상 확대 · 패널 폭을 고치고 대표 프레임 확인(압축 품질로 해결했다고 하지 않음) |

| 1~2초 정지 · 시간 초과가 갑자기 반복 | 화상회의 · 메모리 부족 — 녹화를 멈추고 부하가 사라진 뒤 멈춘 큐부터 |

## C8 게시

원격 push와 노션 게시는 기준_공통 G4-3대로 사용자에게 묻고 한다.

1. 영상 · 자막은 `other-pc`에만 올린다(브랜치 · 커밋 · push 원칙은 기준_공통 G5). 커밋 전에 원격 other-pc를 받아 병합한다. 여러 세션이 같은 폴더를 쓰면 브랜치를 바꾸지 말고 임시 인덱스로 커밋을 만든다(명령은 도구 촬영준비). 영상 한 편은 100 MiB 아래.
2. 파일 이름은 `course/videos/{통합반,실전반}/<과정>_<NN>회차_<대본 번호>_실습_<이름>.mp4`(대본 파일 이름과 같게, 공통이면 두 벌)이고 `course/videos/README.md` 표를 고친다. 올린 뒤 raw 링크가 200이고 크기가 원본과 같은지 확인한다.
3. 노션 학습 포털의 두 과정 회차 페이지 「🎬 강의 영상」 탭에 그 커밋에 고정한 링크를 다른 영상과 같은 모양으로 넣고 다시 열어 확인한다. 영상은 Notion에 올리지 않고 링크로 건다(링크 모양 · 크기 한도는 도구 촬영준비). 유튜브는 쓰지 않는다.
4. 노션의 디자인 · 기존 수업 내용 · 날짜 · 강사 첨부 · 링크는 바꾸지 않고, 새 자료가 준비되면 그 항목만 바꾼다. API 성공만으로 화면 확인을 대신하지 않는다. 게시 커밋 고정 링크 · 해시 · 검증 · 남은 의존성을 기록한다.

## C9 이론 강의 영상

1. 덱 · 대본 반영과 검사가 끝난 뒤 만든다. 범위(대본 파일 단위)를 듣기 전에는 음성도 영상도 만들지 않고, 견적은 기준_공통 G4-4대로 먼저 알린다. 도구는 `제작용/기존제작/tools/video/강의영상.py`(먼저 `--dry`로 첫 문장 이음말 · 대본 형식을 검사).
2. 음성 전에 대본을 장 그림과 대조하고(기준_대본 S8-2) 덱 렌더의 글겹침 0을 확인한다.
3. 쉼은 0 잇는다(앞 문장을 받아 바로 풀어 주는 곳) · 1 짧게(같은 이야기 안 한 박자) · 2 한 호흡(이야기가 끝난 곳 · 중요한 말 · 물음 뒤) · 3 크게(화제가 바뀌는 곳, 한 장에 많아야 한두 곳). 쉼으로 시간을 맞추지 않는다(기준_대본 S4-4).
4. 완료 판정은 「싱크가 최우선, 끊김 없이, 대본대로」다: 쉼 바로 앞에 말소리가 남은 자리(말머리 잘림) 0, 화면 전환 시각 = 시간표의 장 시작 시각, 소리와 화면 길이 일치, 자막이 문장 단위. 사용자가 끊김을 찾게 하지 않는다. 들어 본 확인은 사용자가 한다.
5. 장 그림 영상에 마우스 포인터 · 강조 상자를 넣지 않는다. 확정된 영상을 새 키 · 계정 목소리로 다시 만들지 않는다.
6. 사용자가 재생해 확정한 이론 강의 영상이 생기면 C0 본보기 표에 적는다.
