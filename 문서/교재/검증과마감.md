# 내용 검토·동기화·검증·마감

내용 검토와 기계적 정합 검사는 다르다. 제작 기준은 [작업별 진입점](4_만드는_법.md)의 해당 산출물 정본, 읽기·재사용 규칙은 [공통 기준](2_기준.md)을 따른다. 이미 완료한 검토는 해당 판본의 근거를 재사용한다.

## 단계별 완료 기록

현재 작업 상태에 `전체 내용 확인 / 수정 / 동기화 / 화면·정적 검사 / 마감·게시`를 구분해 기록한다. 이론 덱·이론 대본·실습 랩·가이드·실습 대본의 완료 범위를 구분한다. [작업별 완료 기록](4_만드는_법.md)의 기준 위치·산출물·판본·근거·미완료를 연결하고, 기존 근거는 재사용한다. 근거 없이 전체 완료를 선언하거나 확정 전체를 철회하지 않는다. 확인 완료한 파일·범위와 해시 또는 커밋을 연결한다. 동일 파일을 여러 단계에서 읽을 때 각 단계의 목적을 구분한다. 변경 없는 내용을 다시 전독하거나 같은 생성기를 반복 실행하지 않는다. 새 변경이 있으면 그 부분·앞뒤 연결·영향받는 파생물만 확인한다. 미확인 범위가 있으면 마감하지 않는다.

## 실습 준비와 후속 촬영의 순서 — 2026-10-20

모든 도구의 대본·시연·음성·촬영은 [실습 공통 제작 지침](기준_실습대본.md#적용-범위--모든-실습의-공통-제작-지침)을 적용한다. 발화 선행·선행 클릭과 입력값·UI 시각 단서·구어체·연속성·실제 움직임·결과 확인을 해당 판본의 근거와 연결한다. 화면 표본이나 로그만 확인하고 전 구간 청취·재생까지 마친 것으로 기록하지 않는다. 이미 확인한 동일 판본은 재사용하고 수정 영향과 실제 결함만 재확인한다.

공통 기준을 바꾼 작업에서는 규칙 동기화와 개별 원고 적용을 나누어 기록한다. 검토 시 새 기능의 안내가 충분한지, 반복 설명을 과하게 남기거나 필수 조작을 생략하지 않았는지, 화면 색상에 실제 근거가 있는지, 구어체가 어미 치환에 그치지 않았는지 확인한다. 목표 시간을 맞추기 위한 불필요한 행동은 제거한다. 기준은 실습 대본 정본을 따른다.

실행 허용 뒤에는 대상·행동이 안내된 시점과 행동 시작·종료, 결과 표시와 결과 발화를 대조한다. 음성과 행동이 겹쳤다는 이유만으로 오류 판정하지 않는다. 안내보다 앞선 클릭·입력과 결과보다 앞선 결과 발화는 수정한다. 커서의 연속 이동·실제 클릭 위치·입력 중 가독성·스크롤 움직임 프레임을 우선 검사한다. 출력fps·디코드 성공·음성 중첩0은 움직임 합격 근거가 아니다. 이동 중 프레임 공백과 조작 지연을 실제 재생과 함께 확인하고 문제가 있으면 장시간 촬영으로 확대하지 않는다. 이번에는 문서와 Notion 사본만 정리하며 촬영·새 음성 생성은 하지 않는다.

1. 현재 준비 단계에서 랩 코드·입력·시작본·참조 완성본과 완료 조건을 정적으로 대조하고, 실제 발화의 대본 초안·진행 순서·가이드의 단계와 확인 조건을 함께 맞춘다. 사진·하이라이트 가이드를 먼저 완성하지 않는다. AI 응답·실행 결과는 미리 확정하지 않고 관찰할 항목과 판단 조건을 준비한다.
2. 후속 실행 허용 단계에서 한 번의 리허설로 실행·진행 흐름·시간을 함께 확인한다. 준비·설명·AI 대기·구현·실행·결과 확인과 막힘·완성본 전환을 구별해 기록한다. 낭독 추정을 실제 전체 시간으로 쓰지 않는다.
3. 발견한 문제를 모아 수정하고 변경 부분과 영향받는 연결만 재확인한다. 전체 리허설을 관행적으로 반복하지 않는다. 실제 결함이나 큰 변경으로 전체 확인이 필요하면 그 이유와 범위를 남긴다. 재확인 자체를 금지하거나 시간 부족·초과만으로 랩을 늘리고 줄이지 않는다.
4. 안정된 판본으로 본 촬영을 하고 그 화면에서 가이드용 사진을 추출한다. 준비부터 결과 확인·저장·재열기까지 전체 작업 단계를 사진과 하이라이트로 연결한다. 누락되거나 읽히지 않는 장면만 별도 보충하며 본 영상을 사진 때문에 전체 재촬영하지 않는다. 별도 보충 화면은 판본과 촬영 출처를 기록한다. 본 영상은 실습 대본의 원맨쇼·커서·스크롤·속도 기준을 따른다.
5. 대본의 실제 순서·조건·판단·결과에 영향을 준 차이만 반영하고, 가이드·HTML·ZIP·제작 원본을 같은 판본으로 동기화한다. 사소한 발화 차이까지 일치시키려고 재촬영하지 않는다. 정적 준비 완료, 실행 확인, 실측, 사진 가이드 완료, 영상 완료를 각각 구분한다.

전체 회차 준비의 기본 순서는 위와 같다. 현재 재개 범위·기존 영상·수정 대상은 [촬영 인계](인계_5분샘플_제작검증.md)를 따른다. 짧은 시험은 전체 수업을 압축하는 과제가 아니라 새 진행 리듬과 움직임 프레임을 검증하는 구간이다. 기준·규칙은 기존 문장을 수정하며 상반된 예외를 뒤에 누적하지 않는다. 사용자 의도가 불명확한 충돌만 해당 항목을 구체적으로 질문한다.

## 8. 윤문

44. **표현만 다듬는 윤문과 내용·구조 점검을 구분한다.** 요청이 윤문이면 뜻을 유지해 표현을 다듬고, 종합 점검이면 45-2번대로 설명의 순서와 내용까지 고친다. 자연스러운 문장이 되었다는 이유로 이해되는 강의가 되었다고 판정하지 않는다.
45. **현재 세션이 승인된 범위의 검증·수정·윤문과 파생물 동기화를 끝까지 수행한다.** 과거 아스트라 위임 방식은 결정 기록의 원문 이력이며 현재 자동 호출 지시가 아니다.
45-1. **효율은 맥락과 정확도를 해치지 않는 범위에서 높인다.** 필요한 기준·원고·사실표를 읽고 같은 판본의 불필요한 재출력을 줄인다. 수정 이유와 근거를 기록하고 도구 검증과 문맥 검토를 구별한다. 사용자에게 이미 정한 것을 반복 설명하도록 요구하지 않는다.
45-2. **종합 점검은 내용·구조·표현과 원본 보존을 함께 본다.** 압축 전 원고와 장별로 대조하고, 실라버스 상세 항목·사실표의 누락·사실 오류·기준 위반·흐름을 검증한다. 필요한 원본 수정→연속된 대본 윤문→동기화→검증까지 진행한다. 과거 위임 결과를 그대로 넣던 절차를 현재 수정 금지로 해석하지 않는다. 근거와 어긋나는 수정은 무조건 반영하지 않는다.
45-3. **재개 문서는 append가 아닌 현재 상태 갱신으로 관리한다.** 충돌과 중복을 해소하고 과거 상태는 결정 이력으로 보존한다. 컨텍스트 압축 후 정확한 경로·기준·수정·남은 검증을 문서로 복원한다. 사용자가 직접 새 세션을 시작하므로 자동으로 새 세션을 열지 않는다.
46. **표현만 다듬는 요청과 최종 종합 검증을 혼동하지 않는다.** 표현만 다듬을 때는 뜻을 유지한다. 이번 종합 검증에서는 필요한 내용·구조·표현 수정까지 허용되며 상세 기준과 원본 대응을 함께 확인한다.
47. **수정한 문구는 의미·근거와 화면 배치를 함께 검증한다.** 넘침·겹침은 필요한 내용을 보존하며 해결하고 대본·노트에 반영한다. 과거 특정 작업자의 윤문을 그대로 반영하던 규정은 현재 문구 수정 금지가 아니다.
48. **다른 세션이나 외부 대상에 요청을 보내는 것은 사용자의 허용 범위에서만 한다.** 이번 인계는 문서와 붙여 넣을 요청문을 제공하여 사용자가 직접 재개하는 방식이다.
49. **윤문 뒤에 뜻과 근거가 보존됐는지 대조한다.** 이름과 값의 원자료를 확인하되, 대본에서 선별하거나 근사한 것은 98~100번에 따라 판단한다. 자연스러워진 표현을 원래 문자열로 되돌리지 않는다. 촬영 구간 안의 연속성은 5-2번, 구간별 시작·끝과 앞뒤 연결은 52·97-1번을 함께 적용한다. 구간이 나뉜다고 앞 학습과의 연결을 없애거나, 연결한다고 설명을 마친 구간을 계속 읽는 듯 시작하지 않는다.

## 16. 점검

104. **전 문장과 개념의 의존 순서를 함께 검토한다.** 화면·노트·낭독본을 단원 순서와 실제 촬영 경계에 따라 읽는다. 새 개념의 정식 용어·정의·필요한 이유·예시·판단 또는 실습 검증 기준이 빠지지 않았는지 본다. 앞에서 배운 내용만으로 다음 설명을 이해할 수 있는지, 아직 정의하지 않은 용어·불분명한 수치·미완료 활동을 전제하지 않는지, 같은 설명을 반복하지 않는지 점검한다. 화면의 대상·읽는 순서와 대본의 설명이 대응해야 한다. 낱말 검색과 빌드 통과만으로 이해 가능성을 판정하지 않는다. 청취하지 않았으면 청취했다고 쓰지 않는다. 이론에 설명이 있다는 것과 포털·랩의 실제 구현·검증 완료를 별도로 보고한다.

## 최신 제작 범위와 반복 검토 금지

[공통 기준](2_기준.md#최신-제작-범위와-반복-검토-금지)의 같은 이름 절을 따른다(같은 문단을 여기 다시 적지 않는다).

## 공통 내용과 과정별 수행의 수정·동기화 절차

1. 같은 주제의 교재 화면과 포털 실습의 시나리오·조작·관찰·확인 흐름을 대조한다. 포털 실습 흐름은 두 과정 공통으로 맞춘다.
2. 두 과정의 공통 범위와 차이는 `2_기준.md` 「두 과정의 공통 범위와 차이」가 정본이다: 1회차·랩(한 벌, 실전반 난이도)·도구 실습 대본은 공통, 2회차부터 이론 덱·대본과 VS Code 랩 대본은 과정별(실전반 이론은 [실전반 기준](실전반_기준.md)).
3. 공통 덱(1회차) 변경은 두 과정 해당 덱·화면 원고·발췌에 함께 반영한다. 통합반 2회차 이후 원 덱의 사실·값·용어를 고치면, 같은 내용을 쓰는 실전반 원고도 확인해 맞춘다(문구·구성은 과정별로 다를 수 있다). 대본 변경은 각 과정 발표자 노트·합본·낭독본에 반영한다. 랩 변경은 해당 자료·가이드·실습 대본·HTML·ZIP에 반영한다.
4. 공통 내용의 일치와 각 과정 대본·랩의 대응을 각각 검증한다. 파일명·과정 표지·노트·경로가 다른 것을 공통 화면의 내용 차이와 혼동하지 않는다. 반대로 랩 차이를 이유로 화면·포털 흐름 불일치를 허용하지 않는다.
5. 발견한 문서 결함은 지금 해결한다. 전체 회차의 실제 AI·코드·테스트·HYD/DB·브라우저 실습·캡처·전체 시간 실측은 촬영 확인으로 분리한다. 5종 샘플은 위 최신 예외 범위에서 실행과 실측을 기록한다. 완료한 범위만 확정한다.

내용 판정은 [2_기준.md](2_기준.md), 완료 상태는 [3_현황.md](3_현황.md), 실제 남은 일은 [6_남은_일.md](6_남은_일.md)에서 관리한다. 이 문서는 산출물별 작업 방법이다. 문서 정합화 때 이력으로 옮겨졌던 유효한 세부 절차를 현재 경로·분할 원본에 맞춰 복원했다. 과거 원문과 대응은 [결정 기록](5_결정_기록.md)에 있다.

## 1. 정확한 원본과 작업 경계

두 과정의 활성 정본은 공통 기준의 저장소 경로를 따른다. 이전 복구 루트는 보존용이며 재동기화하지 않는다. 실제 HEAD·브랜치·원격·미커밋을 확인하고 시작한다.

| 대상 | 정본·수정 위치 | 연결해 확인할 곳 |
|---|---|---|
| 통합반 화면 | 통합반 `제작용/온라인/decks/integrated/dayNN/통합반_NN일차.md` | 해당 PPTX·덱 PNG·이론 대본·배정된 실전반 장 |
| 실전반 화면 | 실전반 `제작용/온라인/decks/practical/dayNN/실전반_NN일차.md`(1회차는 `day01/조립.py`가 통합반 1일차에서 만든다. 2~8회차는 이 원고를 직접 고친다) | 최신 실라버스 실전반 시트·묶인 통합반 회차·[실전반 기준](실전반_기준.md). 실전반8은 통합반11 |
| 이론·실습 발화 | `제작용/구성/<과정>/NN회차/구성.json`이 가리키는 분할 파일 | 구성표·발표자 노트·랩 가이드 |
| 온라인 랩·자료 | 각 과정 `산출물/<과정>/실습/NN회차/README.md`에서 연결된 폴더 | 입력·시작본·참조본·가이드·강사대본·ZIP |
| 삽화·그래프 | 해당 덱의 `figures/`와 그림 생성 원본 | 그 파일을 참조하는 모든 현재 배정 장 |
| 랩 구조 | `제작용/기존제작/labs/STRUCTURE.md` | 현재 배포 위치는 해당 과정 안내에서 확인. 과거 `course/` 경로·온라인 완성본 운영을 현행 온라인에 기계적으로 적용하지 않음 |

현재 온라인 덱은 분할 원고와 노트가 이미 동기화된 결과다. 예전 전체 재조립기를 곧바로 실행하면 최신 발화를 덮을 수 있으므로 쓰지 않는다. 실전반 1회차의 `조립.py`만 통합반 1일차를 고친 뒤 돌린다. 공통 내용(1회차, 두 과정이 같이 쓰는 사실·값·용어) 변경은 통합반 원본과 실전반에 함께 반영한다. 전체 폴더를 복사하거나 과거 사본으로 치환하지 않는다.

## 2. 내용과 전개를 검증하는 순서

1. 기준 읽기와 요약 후 복원은 [공통 기준의 읽기 규칙](2_기준.md#기준-읽기와-작업-복원)을 따른다. 최신 사용자 범위·실라버스 원문·사실표·분할 원본·기존 검토 근거를 읽는다. 기존 검토와 이번 실제 확인을 구별하고 시작 해시를 새 근거 폴더에 저장한다.
2. 실라버스 상세 항목 → 단원·장 → 설명 → 실제 랩의 목적·판정 조건을 대응시킨다. 선수 개념, 정식 용어·정의·이유, 사례·조건·예외·복습·퀴즈·정답의 위치를 확인한다. 제목 목록이나 키워드 검색만으로 내용 검토를 완료했다고 하지 않는다.
3. 변경이 필요한 문장은 앞뒤와 실제 촬영 경계까지 읽는다. 아직 배우거나 수행하지 않은 활동을 완료했다고 말하는지, 출처 없는 값이나 현재 구현을 일반 원리처럼 설명하는지 확인한다. 이론의 실습 간지·설명은 이론 파일 안에 두고 실제 실습 삽입·재개는 비낭독 표시로 구별한다.
4. 수정 전후 원문·위치·이유·근거와 영향을 남긴다. 이미 허용된 수정은 다시 승인을 요청하지 않고 해당 범위에서 끝낸다. 근거 없는 확장이나 문체 취향을 이유로 전부 재작성하지 않는다.
5. 수정 원본 → 해당 파생물 → 정적 검증 → 필요한 렌더 확인 순서로 진행한다. 사실·의미·전개 검토, 원문 정합성, 화면 배치는 서로를 대신하지 않는다.
6. 같은 산식으로 변경 전후 낭독 추정을 계산한다. 한글 음절 + 숫자×1.6 + 영문 글자×0.6을 275로 나누며 영문 뒤 한글 독음은 기존 도구의 치환 규칙을 따른다. 제목·제작 메모는 발화 시간에서 빼고 학습 대기는 별도 기록한다. 조작·AI 응답·전체 진행 시간으로 단정하거나 목표 시간에 맞추지 않는다.
7. 확정 항목·구체적 미해결·촬영 확인을 분리해 현황·남은 일·인계·제작기록을 갱신한다. 실제 확인하지 않은 청취·PowerPoint 앱·실행 성공을 기록하지 않는다.

## 6. 실라버스 변경·촬영·게시

사용자가 새 실라버스를 주면 이론 제목/상세 항목은 단원·사실표·장으로, 실습 추가/삭제/제목은 간지·설명·실습 목록·구성으로, 이론↔실습 변경은 촬영 경계로 대응한다. 시간 행 변경을 내용 삭제·늘리기로 바로 처리하지 않는다. 실전반만 바뀌면 통합반 원본은 두고 실전반 원고를 [실전반 기준](실전반_기준.md)대로 고친다. 바뀌는 범위를 알리고 이미 허용된 작업은 영향 범위에서 수행한다.

실제 AI·코드/테스트·HYD/DB·MCP·브라우저·캡처·음성/영상은 별도 촬영 범위다. 환경 준비는 시스템의 현행 운영 문서를 따르며 다른 프로젝트의 포트·데이터를 임의로 변경하지 않는다. 현재 문서 작업에서는 서비스나 워커를 시작하지 않는다. 음성/영상 도구의 존재를 실행 허용으로 해석하지 않는다.

변경 전후 장수·발화·낭독 추정·랩·산출물 수와 실제 검증/미검증을 기록한다. 허용된 교재 경로만 커밋·푸시하고 원격 HEAD를 확인한다. CLAUDE.md·포털·Supabase·시스템 별도 미커밋 수정은 제외하고 보존을 확인한다. 근거·렌더·캐시는 로컬 evidence에 둔다. 새 세션은 자동 생성하지 않는다.
