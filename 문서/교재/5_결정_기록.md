# 교재 5. 결정 기록

「이것은 왜 이렇게 되어 있는가」, 「바꿔도 되는가」가 궁금할 때 읽는다. 지금 유효한 결정만 둔다. 뒤집힌 결정은 최종 결정에 합쳤고, 지난 문장은 git 이력에 있다. 규칙 자체는 `2_기준.md`에 있고 「기준 N」은 그 번호다.

## 5. 일하는 방식

| 결정 | 까닭 |
|---|---|
| 검토 결과를 사용자에게 「열어 보고 확인해 달라」고 넘기지 않는다. 결정이 필요한 것만 묻는다 | 컨펌된 기준으로 직접 확인하고 진행한다 |
| 방식은 먼저 제안해 승인받고, 하나를 만들어 확인받은 뒤 넓힌다 | 덱은 샘플 16장을 먼저 확정한 뒤 회차를 만들었다 |
| 근본을 고친다. 우회하지 않는다 | 도구가 멈추면 문구 · 장 구성 · 도구를 고친다. 우회한 것이 있으면 먼저 말한다 |
| 동기화(원본을 고치면 PPTX · 낭독본 · 하루치 덱 · 배포 묶음 · 현황을 맞추는 일)는 묻지 않고 한다 | 사용자 지시(2026-10-12). 범위는 `산출물/` · `만들기/` · `.claude/skills/` · `문서/교재/` |

| 찌꺼기를 남기지 않는다. 다시 쓰면 옛 판을 같은 작업에서 지우고, 문서는 `문서/` 두 폴더에만 둔다 | 「레거시 지침과 노이즈가 섞이면 핵심이 가려진다.」 지운 것은 git 이력에 있다 |
