# 교재 5. 결정 기록

「이것은 왜 이렇게 되어 있는가」, 「이것을 바꿔도 되는가」가 궁금할 때 읽는다. 지금 지키는 규칙은 `2_기준.md`에 있고, 여기에는 그 경위와 덱의 낱낱의 결정을 적는다.

아래는 사용자가 정한 것과, 그 기준에 따라 전체 점검 뒤 정해 반영한 것이다. 다시 묻지 않고 따른다. 제작 기준(`문서/교재/덱_제작기준.md`)에 이미 적힌 것은 절 번호만 가리키고 까닭을 덧붙였다. 제작 기준에 없는 것은 여기에 적는다. 바꾸려면 사용자에게 먼저 묻는다.

## 1. 교재의 방향

| 결정 | 까닭과 범위 | 제작 기준 |
|---|---|---|
| 그림체는 컨펌된 샘플 판이다. 바꾸지 않는다 | 사용자가 샘플 덱(`production/decks/integrated/sample/`)의 삽화 판을 보고 확정했다. 새 삽화는 `삽화_기본.py`의 선 굵기 · 색 · 그림 조각으로 그린다. 이미지 생성 AI는 쓰지 않는다 | 7절 |
| 실라버스는 틀이면서 방향이다 | 실라버스가 정하는 것은 주제, 순서, 이론과 실습의 구분이다. 제목 표현 · 분량 · 깊이는 교재가 정하고, 내용은 구현과 원본 자료에서 가져온다. 그러면서도 실라버스 이론 행의 「상세 교육 내용」에 적힌 항목은 빠짐없이 다뤄야 한다(전체 점검의 「실라버스 충실」이 이것을 본다) | 2절 |
| 실라버스는 사용자가 직접 쓴다. 교재를 실라버스와 다르게 가야 하거나 실라버스가 바뀌어 덱을 고쳐야 하면, 고치기 전에 먼저 말한다 | 실라버스 문구가 구현과 다르면 구현을 따르되 그 차이를 화면이 아니라 보고에 적는다 | 2절 |
| 한 장에 1분 30초. 단원의 본문 장수 ≈ 실라버스의 이론 분 ÷ 1.5 | 한 장 1분으로 자르면 장수가 많아 강의가 버겁고, 2분이 넘으면 화면에 없는 말을 외워야 한다. 강사가 화면만 보고 말할 수 있어야 한다 | 5절 |
| 분량을 채우려고 장을 늘리지 않는다 | 장수의 기준(±15 %)은 어림이다. 모자라면 채우지 않고 사용자에게 알린다(2026-10-14에 바뀜. 전에는 「하한 아래로 내려가면 안 된다」였다). 정의가 빠지지 않게 하느라 상한을 한두 장 넘는 것은 괜찮다 | 5절 |
| 개념 설명 외에는 다 실습이고, 실습은 덱에 2장이다 | 간지와 「무엇을 하고 무엇이 만들어지는지」 설명 한 장. 절차 · 메뉴 · 화면 캡처 · 길 안내는 덱에 싣지 않는다. 교재는 개념을 설명하는 문서이고 실습의 절차는 실습 가이드가 맡는다. 이 기준으로 이론 단원을 한 번 점검했다(`6_남은_일.md` 5.1절. 통합반 1일차 Notion 단원의 다섯 장만 결정 대기로 남았다) | 9절 |
| 구현 설명, 단서, 가상 강조, 「시뮬레이션」 문구는 쓰지 않는다 | 화면에도 노트에도 쓰지 않는다. 실라버스의 실습 문구에 범위 단서가 있어도 같다. 학생이 몰라도 되는 것을 밝혀 「그럼 이건 가짜인가」 하는 의문을 만들지 않는다. 없는 것을 있다고 쓰지는 않는다 | 3절 |
| 대상은 노베이스 대학생이지만 내용을 덜어 쉽게 만들지 않는다 | 초기 판이 「유치하다」 「내용이 없다」는 지적을 받았다. 전문용어를 살리고 정확한 정의와 실제 값을 화면에 싣는다 | 1절 |
| 문어체, AI가 쓴 티가 나지 않게 | 같은 문장 틀의 반복, 구호, 과장, 길 안내, 질문형 연결을 쓰지 않는다 | 8절 |
| 실전반과 오프라인 덱은 따로 쓰지 않고 통합반 덱에서 조립한다 | 같은 내용을 두 벌로 쓰면 품이 두 번 들고 한쪽을 고쳤을 때 다른 쪽이 어긋난다 | 13-1 · 13-2절 |

## 2. 덱의 구체적인 결정

| 결정 | 까닭과 범위 | 어디에 적혀 있나 |
|---|---|---|
| 강사가 제품을 보여 주는 시연도 실습이다 | 실라버스가 실습으로 분류하면 실습이다. 시연할 대상을 소개하는 장을 몇 장 둘 수 있다 | 제작 기준 9절 |
| ProcessGPT는 시연이다. PPT에는 간단한 소개만 둔다(간지를 포함해 다섯 장 안팎) | 실라버스에 이론으로 적혀 있던 통합반 11일차(실전반 8일차)의 ProcessGPT 단원을 시연 실습으로 바꿨다. 실라버스의 그 행도 「실습」으로 고쳐져 있다. 지금 덱은 간지 한 장과 소개 다섯 장, 모두 6장이다(장의 제목은 `6_남은_일.md` 5.2절). 이 묶음은 단원 번호를 매기지 않고 목차에 실습으로 올리며 본문 장수에 넣지 않는다. 뺀 원고는 `production/decks/integrated/day11/보관/`에 있다 | 제작 기준 9 · 13절, `NOW.md` 4.7절 |
| 시연으로 넘어가는 메시지는 「이때까지 한 것과, 포털보다 훨씬 고도화된 것이 적용된 제품」이다 | 사용자가 준 문장이다. 소개 장은 이 메시지로 시연에 넘어가게 쓴다 | 여기 |

| 실행 회차가 둘이다. 값을 한 벌로 바꾸지 않는다 | 통합반 1~8일차는 경보 `ALT-hyd01-0014-e0a1`의 회차, 9~11일차는 단계별 프로세스 기록이 남은 `ALT-hyd01-0026-767a`의 회차를 쓴다. 바뀌는 자리(9일차)에서 「프로세스가 처리한 같은 종류의 경보 한 건」임을 한 번 밝힌다. 「같은 사건」이라고 쓰지 않는다 | 제작 기준 8절, `NOW.md` 4.7절 |

## 3. 일하는 방식

| 결정 | 까닭과 범위 |
|---|---|
| 검토 결과를 사용자에게 「열어 보고 확인해 달라」고 넘기지 않는다 | 컨펌된 기준으로 직접 확인하고 진행한다. 사용자에게는 **결정이 필요한 것만** 묻는다 |
| 방식은 먼저 제안해 승인받고, 하나를 만들어 확인받은 뒤 넓힌다 | 덱은 샘플 16장을 먼저 확정한 뒤 일차를 만들었다. 대본, 랩, 촬영 대본도 하나 → 30%쯤 → 전체의 순서로 한다(`2_기준.md` 12절) |
| 서브에이전트에 fable 모델을 쓰지 않는다 | 사용자 지시. 저장소 루트 `CLAUDE.md` 3절에도 있다 |
| 읽기 · 계획 · 검토 · 문서는 가벼운 모델, 쓰기는 Opus로 한다. 가벼운 모델이 주간 한도에 걸리면 Opus로 한다 | 토큰을 아끼되 덱의 문장은 품질이 먼저다. `작업자_지시문/`에 적힌 모델 표기는 그때그때의 배정이다 |
| 근본을 고친다. 우회하지 않는다 | 도구가 멈추면 우회하지 않고 원인(문구, 장 구성, 도구)을 고친다. 우회한 것이 있으면 먼저 말한다 |
| 커밋은 경로를 지정하고, 구간이 끝나면 push 해 `main`을 맞춘다 | `4_만드는_법_덱_고치기.md` (라) |
| 학생의 AI는 키로 제공된다 | 학생 계정을 걱정하거나, AI 없이 가는 대비 경로를 설계하지 않는다|
| 동기화(덱을 고치면 조립 덱, 배포 묶음, 딸린 문서를 함께 맞추는 일)는 묻지 않고 한다 | 사용자 지시(2026-10-12). 범위는 `course/`, `production/`, `.claude/skills/` 안이다 |
| 덱 화면에 대본을 다 넣지 않는다 | 화면 글은 메시지와 그것을 받치는 본문까지다. 강사의 말은 노트에 서너 문장으로 둔다(제작 기준 5절) |


## 4. 저장소에 올리지 않은 것

| 무엇 | 까닭 | 남긴 것 |
|---|---|---|
| 강사 배정과 일정표 | 실명과 시수가 들어 있다 | 원칙만 아래에 적는다 |
| 회의 메모, 사용자가 준 파일의 원문 | 공개 저장소다 | 결정은 이 문서와 제작 기준에 옮겼다 |
| 실행 증거(`.evidence/`) | gitignore이며 만든 PC에만 있다 | 사실표가 값과 출처를 옮겨 적었다 |
| 사용자가 본보기로 준 파일(다른 과정의 가이드와 대본, 다른 프로젝트의 흐름 설명) | 사용자가 준 파일이다 | 거기서 가져온 기준은 `4_만드는_법_대본_영상_실습.md` 1절에 적었다 |
| 음성과 영상 파일, 키 파일 | 강사의 목소리이고, 키는 공개할 수 없다 | `1_목적과_방향.md` 5절 |

강사 배정의 원칙(사람 이름은 적지 않는다):

- 내용 덩어리 단위로 한 사람이 영상(온라인)과 오프라인을 이어 맡는다.
- 강사를 바꾸는 것은 서로 독립인 영역 사이에서만 한다.
- 오프라인 첫 회차는 환경 설치와 세팅 때문에 강사 전원이 들어간다.

## 5. 2026-10-13~14에 정한 것 (저장소를 정리한 세션)

| 결정 | 경위 |
|---|---|
| 원리와 까닭, 역할과 구조가 줄기다. 재료는 「이런 것들이 있다」로만 얹는다 | 사용자: 「재료가 메인이 되지 말고, 등장은 하되 여기에 이것을 쓴다는 식으로.」 「LLM을 쓰는데 오픈AI라고 뼈를 박아 버리면 안 되는 것과 같다.」 LLM · RAG 같은 큰 말은 개념이고, 그것을 구현한 제품이 재료다 |
| 지금의 덱과 대본은 방향이 잘못됐다. 뼈대부터 다시 짠다 | 2026-10-13에 장마다 까닭을 넣었으나, 재료를 차례로 소개하는 뼈대를 둔 채 덧붙인 것이었다. 사용자: 「애초에 이걸 추가하기 전에도 방향이 잘못되었다.」 「재료 설명하고 재료 사용 방법, 절대 이러면 안 된다.」 |
| 전문성을 바탕에 두고 쉽게 풀어 가는 설명으로 쓴다 | 본보기 글은 풀어 가는 방식은 좋으나 전문성이 없고, 지금 덱은 전문 내용은 있으나 풀어 가지 못한다. 둘을 조합한다 |
