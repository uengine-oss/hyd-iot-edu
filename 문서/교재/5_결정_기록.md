## 1회차부터의 차이 설계와 VS Code 랩 가치 강화 — 2026-10-20

사용자는 실제 수행을 지금 시작하라는 뜻이 아니라고 정정했고, 최종 요청에서 문서·기준·인계를 먼저 동기화한 뒤 1회차부터 기존 자료를 읽고 두 과정 차이안을 잡도록 했다. 실행·촬영은 보류다. 이전 인계의5·6회차는 미확인 내용의 위치이며 이번 설계의 시작점이 아니다. 1회차 환경 설정을 코딩 랩으로 오인하지 않는다.

VS Code 코딩 랩은 두 과정 모두 장난감 수준을 피하고 다른 업무·PBL에 활용할 가치가 있어야 하며 필요한 난도를 허용한다. 실전반은 같은 기반에서 실제 요구 해석·판단·구현·검증의 차이를 확보한다. 담당 정본은 기준_실습랩.md이며 공통 기준은 연결과 현재 범위를 갱신했다. 강사의 자연스러운 원맨쇼·공통 발화·커서·스크롤·사진 가이드·후속 리허설 순서는 유지한다.

환경 준비는 설치 완료 전제로 목록의 역할·필요성만 짧게 설명하고, 수업용 main clone→VS Code→명령 설명과 직접 타이핑→기동→포털의 아키텍처 위치만 짧게 연결하는 방식으로 사용자 정정했다. 짧은 명령·바이브 코딩 요청은 직접 입력하고 긴 명령은 붙여넣기를 허용한다. 촬영용 main 게시 필요와 활성 develop의 현재 작업은 구별하며 이번에 main을 변경하거나 clone·실행하지 않는다. 실제 현재 원격 두 브랜치는 다른 커밋이므로 main 준비 여부는 후속 확인으로 남겼다.

Notion 원본은 사용자 지정 `D:/다운로드/노션 자산화 (2일차 1교시).pptx` 41장이다. 보존본과 슬라이드 텍스트는 표지1장만 다르고2–41장은 같다. Notion MCP로 기존 내 학습 노트·DB 속성·세 보기·기본 학습 템플릿을 읽었지만 UI 재현·실행·실측·촬영은 확인하지 않았다. MCP의 구조 확인과 사람이 UI에서 만드는 과정 확인은 구별한다. 원본·완성본은 조사 근거로 사용하며 기존 노트는 수정하지 않는다.

## 강사 본인의 원맨쇼와 촬영 준비 순서 — 2026-10-20

사용자는 실습의 가장 중요한 기준을 “사람처럼”, “강사 자기자신이 원맨쇼로 보여주고 설명”으로 확정했다. 이론·실제로 마친 포털 경험을 자연스럽게 연결하고 첫 UI·방법 설명은 제공하되 이후 반복을 줄인다. 본인 발화·제3자 표현·영어 철자·수치 선별은 이론 대본 공통 규칙을 적용한다. 현재 위치를 커서로 짚고 스크롤·클릭·입력·전환을 설명과 실제 확인 속도에 맞추는 원칙은 실습 대본 기준에 반영했다. 고정 초 지연이나 가짜 실수는 요구되지 않았으며 자연스러움의 구현 원칙으로 배제했다.

사용자는 시간 확인 후 랩 수정으로 가이드를 다시 만드는 중복을 지적했고, 정적 준비→후속 리허설의 실행·시간 통합 확인→문제 일괄 수정과 영향 범위 재확인→안정된 판본의 본 촬영과 화면 사진 추출 순서에 동의했다. 전체 작업 과정은 사진·하이라이트로 연결한다. 담당 정본은 실습 대본·가이드·검증과 마감이며 상태·인계·요청문은 연결과 현재 위치만 갱신했다. 과거 커서 지침은 검색에서 정확한 파일을 특정하지 못해 수정하지 않았다. 현재 실제 실행·촬영 금지는 유지하며 이번 방향 합의가 회차 내용 마감이나 실측 완료를 뜻하지 않는다.
