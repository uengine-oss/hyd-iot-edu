## 재개 순서와 근거

1. 실제 Git 상태와 위 미커밋 102파일·보존 manifest를 확인해 새 시작 근거를 남긴다. 이론을 재검토하지 않는다.
2. 1회차 차이안을 시작점으로 기존 활동을 분류한다. 환경 준비에 코드 과제를 추가하지 않는다. 현재 환경 대본의 오래된 예고·수동 기동 안내와 최신 배포 경로의 불일치는 설계안에 남아 있고 산출물 반영은 대기다.
3. 후속 회차에서 실제 코딩 랩의 요구·자료·시작본·참조본·검증 조건을 읽고 통합반의 활용 가치와 실전반의 실제 판단·구현·예외 검증 차이를 먼저 설계한다. 이번 요청은 차이안까지이며 코드·대본·가이드·HTML·ZIP의 실제 수정·회차 마감으로 자동 확대하지 않는다. 기존 확정 근거를 활용하고 키워드·파일 개수로 내용 완료를 선언하지 않는다.
4. 이후 통합반7–11·실전반7–8의 미완료 실습을 주제 대응에 맞춰 진행한다. 이미 반영한 공통 수정은 근거를 재사용하되 전체 회차 완료로 간주하지 않는다. 통합10↔실전7, 통합11↔실전8은 공통 기반이다. 통합7·8과 실전5 등은 실라버스·원본 대응을 확인한다.
5. 현재는 기준·설계·상태·인계 문서만 선별 커밋·origin/develop 게시한다. 후속 산출물 반영 단계에서 해당 원본·파생물·근거를 동기화한 뒤 회차 마감을 판단한다. 다른 회차의 미커밋은 보존한다.
