# 기준 — 실습 가이드

실습 가이드(학생이 받는 가이드 HTML)를 만들거나 고칠 때 이 문서와 [기준_공통](기준_공통.md)을 끝까지 읽는다. 새 가이드 파일 이름은 `guide.html`이고, 기존 `가이드.html` · `안내.html`은 배포 안내가 가리키므로 이름을 바꾸지 않는다. 첫 단계는 실라버스 그 행의 문장과 배정 시간이다(기준_공통 G0 「범위와 시간」). 이 갈래의 스킬: hyd-lab-guide.

- **이 갈래의 성향:** 학생이 강사 없이 혼자 따라 하는 안내이고, 조작마다 실제 화면 사진이 있다(H1-1 · H3-1).
- **앞에서 받는 것:** 실제로 돌려 본 랩(`START.md` · 입력 · 원자료 · 확인 사례 · 저장 위치)과 본 촬영 화면. 학생 실습 폴더에 있는 것만 쓰고, 정답 · 해결 로직 · 완성 프롬프트 · 강사 폴더나 강사 참조를 가리키는 말 · 키 · 접속값은 넣지 않는다. 학생용 완성본은 실습 폴더와 따로 받는 묶음이라고만 안내한다(계정이 없는 학생이 결과를 확인하는 용도).
- **뒤가 가져가는 것:** 받기 시험(H5-3)과 노션 회차 페이지 연결 — 가이드만으로 받기 → 저장 · 다시 열기까지 가야 한다.

## H0 본보기

| 무엇 | 원본 | 확정 |
|---|---|---|
| 캔버스 도구 가이드 | `산출물/통합반/실습/01회차/랩/01일차_실습4_관계그림/가이드.html` (ARROWS) | 사용자 확정 영상과 같은 판본 |
| 웹 도구 가이드 | `산출물/통합반/실습/01회차/랩/01일차_실습1_학습노트/가이드.html` (Notion) | 사용자 확정 영상과 같은 판본 |

새 가이드는 본보기의 절 구조와 단계 꼴(H2-3)을 그대로 따르고 새 절 구조를 만들지 않는다 — 학생이 읽을 것 말고는 아무것도 없다(소재 · 길이 · 순서는 실라버스와 랩이 정한다).

## H1 역할

1. **가이드는 강사 없이 따라 하는 학생 자료다.** 오프라인 학생이 가이드만 펼쳐 시작 파일 받기 → 준비 → 작업 → 결과 확인 → 저장 → 다음 실습까지 하고, 막힌 곳만 강사의 도움을 받는다(강사가 전체 따라 하기를 이끄는 수업이 아님).
2. **온라인 영상은 강사 원맨쇼다** — 영상에 가이드 화면을 띄우거나 읽어 주지 않는다. 가이드는 온라인 · 오프라인 학생 모두 노션 회차 페이지(실습 묶음 ZIP)에서 받는다.
3. 두 과정의 가이드 공유 범위는 기준_공통 G2 표. 강사의 ProcessGPT 시연(기준_공통 G2)은 학생이 따라 하는 가이드의 대상이 아니다. 가이드는 실습의 완료 항목에서 빠뜨리지 않는다.

## H2 구성

1. **첫 화면**은 만드는 결과와 진행 순서를 짧게 말한다. 파일 이름 나열로 시작하지 않고 단계에서 필요한 파일 · 도구를 소개하며, 받은 폴더는 VS Code 탐색기 구조로 보인다. 회차 첫 화면에서 각 실습과 다음 실습으로 잇되 제공되지 않은 자료를 완료로 표시하지 않는다. 실습마다 독립 안내를 두고 한 HTML에 몰지 않는다.
2. **흐름**은 앞 단계 결과 → 아직 풀리지 않은 문제 → 이번 기능이 필요한 이유 → 학생이 정할 요구 → 구현 → 관찰 → 다음이다. 설치 가이드처럼 절차만 나열하거나 개념 사전처럼 설명만 늘어놓지 않는다. 필요한 준비 · 설치는 빼먹지 않되 실제 사용처가 확인된 것만.
3. **단계는 본보기 꼴대로** 짧은 목적 · 할 행동(위치를 첫 문장에 녹임, 예: 「왼쪽 세로 아이콘줄 맨 위」) · 복사 가능한 입력 · 실제 화면 · 결과 확인(마지막 화면에서 눈으로 판단할 성공 조건 한 문장)이다. 기능 · 결과 단위로 묶고 클릭마다 쪼개지 않는다(사진은 조작마다, H3-1). 전체 완성 그림 한 장으로 중간 작업을 대신하지 않는다. 결과 없는 단계는 없고, 명령마다 확인할 출력 · 화면과 다음 행동을 적는다.
4. **복사할 것은 텍스트로.** 프롬프트 · 명세 · 쿼리 · 명령은 사진 속 글자로만 주지 않고 복사할 수 있는 블록이나 파일로 주며, 예시 · 빈 양식 · 학생 작성 결과를 구분한다. 블록 종류(읽는 지침 · AI 프롬프트 · 터미널 명령 · 코드 수정 위치 · 붙여넣는 코드)를 색과 글자로 함께 표시하고, 복사는 본문만(설명 · 줄 번호 · 셸 기호 X), 완료 메시지는 그 목적지에 맞춘다. 터미널 블록에는 쓸 셸과 실행 폴더를 적는다. 복사가 막히면 수동 복사와 붙여넣을 곳을 알려 주고, 빈 학생 입력을 복사 성공으로 표시하지 않는다. 판단이 필요한 명령(복구 미리보기와 실제 적용 등)은 블록을 나눈다.
5. **결과 화면**에는 확인할 값 · 상태 · 출처 · 판정 기준을 붙이고 기대값과 실제 관측값을 나눈다. 다르면 원문 · 입력 · 조건을 확인해 고치고 다시 확인하도록 잇는다. 쿼리 결과가 그래프인지 표인지 요약인지 반환 대상에 맞춰 설명한다. 앞 단계에서 있을 수 없는 화면을 성공 기준으로 요구하지 않는다. AI 응답 · 생성 결과 화면은 「강사 화면의 예」로 표시하고 성공 판정은 원자료 대조 조건으로 적는다.
6. **끝**은 「오늘 한 것 · 저장 · 다음 회차에 쓰는 것」이다 — 저장 위치 · 다시 열어 볼 것 · 다음 랩에 넘길 판본. 연결 랩은 앞 단계 완성 시작본으로 이어 쓴다(자기 이전 결과를 가져오는 것은 선택).
7. 기존 안내 · 산출물 경로를 유지하고 옮길 때는 배포 안내도 함께 고친다.

## H3 사진과 화면

1. **학생은 가이드만 보고 따라 하므로, 모든 과정을 사진으로 담는다(가장 중요).** 폴더 열기 · 준비 · 입력 · 작업 · 결과 확인 · 저장 · 다시 열기까지 학생이 하는 조작마다 그 순간의 실제 화면을 둔다(단계를 묶어도 조작마다). 사진이 없는 조작은 따라 할 수 없는 조작이다. 화면마다 현재 위치 · 조작 대상 · 확인할 결과를 표시와 짧은 설명으로 알아보게 하고, 사진만으로 목적 · 조건 · 판정 근거를 대신하지 않는다.
2. **사진은 본 촬영 화면에서 뽑는다.** 리허설 전에 사진 가이드를 완성하지 않는다 — 단계 · 자료 링크 · 판정 조건을 먼저 준비하고, 랩이 안정된 뒤 본 촬영 화면에서 추출하며 모자라거나 읽히지 않는 장면만 같은 판본으로 보충한다(보충 화면은 판본과 출처를 기록). 기존 사진이 최신 영상의 상태와 같으면 재사용한다. 웹판 촬영과 다른 네이티브 장면(다운로드 · 압축 해제 · 폴더 열기 · 신뢰 창)은 실제 네이티브 화면을 따로 캡처한다. 터미널 출력을 그림으로 그려 넣지 않는다.
3. **없는 화면을 지어내지 않는다.** 「이런 화면일 것이다」나 비슷한 화면으로 채우지 않고, 못 찍은 단계는 `미촬영` 자리와 필요한 장면 · 확인 기준 · 파일 위치를 적는다. 실패한 실행을 정상 화면으로 쓰지 않는다.
4. **표시:** 클릭 · 입력 · 확인할 요소마다 빨간 사각형(색 · 두께는 문서 안에서 같게). 좌표는 실제로 재고, 표시는 원본에서 다시 그리며(원본 보존) 상자 위에 상자를 겹치지 않는다. 관찰만 하는 결과 화면에도 볼 곳 하나는 표시한다. 표시가 값 · 글자를 가리지 않게 하고, UI 글자 · 결과를 합성하지 않는다.
5. **읽히게:** 사진 속 글자가 원래 크기에서 읽혀야 한다. 키워 흐리게 만들지 말고 더 나은 원본이나 그 영역 캡처를 쓴다. 같은 화면을 전체 · 확대로 두 번 싣지 않고(누를 곳이 너무 작을 때만 확대본), 글자를 읽어야 하는 화면은 나란히 두지 않는다. 그래프는 노드 위치보다 연결 · 레이블 · 속성 · 결과가 보이는 구도로.
6. 캡처 속 개인 경로 · 계정은 가리고 그 자리에 학생이 보게 될 값을 적는다. 공개 전에 그림 · 로그에 비밀값 · 정답이 보이지 않는지 확인한다. 남의 캡처의 옛 표시가 지금 설명과 맞는지 보고, 이미 받은 캡처를 다시 요청하지 않는다.
7. 별도 위치 지도 · 미니맵 상자를 넣지 않는다(위치는 행동 문장에, H2-3).

## H4 학생 안내 문장

1. 가이드에는 진행에 필요한 것만 담는다 — 행동 · 명령 · 실제 화면 · 확인할 것 · 오류 대처. 「다르면 확인하세요」 같은 막연한 말 · 불필요한 경고 · 설계 까닭의 긴 설명 · 단서와 면책(「교육용이라 실제와 다르다」, 기준_공통 G3-3) · 사실이 아닌 안심 문구 · 이모지는 넣지 않는다(제작 흔적 금지는 기준_공통 G0-6).
2. 본문은 상황과 필요한 이유를 설명하고(환경 준비 안내만 짧은 행동 · 성공 확인 · 실패 복구 중심), 이론을 놓쳐도 이해되게 쓰되 이론 장을 길게 반복하지 않는다. 덱과 같은 사실은 같은 숫자 · 같은 용어로(기준_공통 G3-7).
3. UI 이름은 실제 화면에서 확인한 명칭만, 메뉴 · 버튼은 한국어 UI 기준으로 굵게 쓰고 영어 화면과 다를 수 있으면 괄호에 영어를 같이 적는다. 부정 지시(「로그인하지 않는다」)에는 이유를 한 문장 붙이거나 뺀다. 「직접 치지 말고 붙여넣는다」는 첫 등장 때 한 번.
4. 오류 안내는 실제로 재현되는 증상과 바로 할 조치만 그 단계 자리에 둔다(뒤로 몰지 않음, 없는 오류를 상상하지 않음). 검사 통과 · 아직 구현 안 한 과제의 예상 멈춤 · 서비스 오류를 구분하고, 막히면 AI에게 실행 명령 · 오류 전문 · 화면을 보내도록 잇는다. 명령이 새 사건을 만들면 어느 식별자로 찾는지 안내한다. 「(권장)」 선택지를 원문을 보고 고르는 장면(기준_공통 G3-8)을 가이드에도 둔다.
5. 힌트는 무엇을 질문하고 판단할지 돕는 것이다 — 작업 방법 · 질문 순서 · 핵심 힌트는 기본 화면에 짧게 보이고 숨기거나 겹 토글로 만들지 않는다. 코드 해석 · 정답 요청문을 늘어놓거나 그대로 붙이면 정답이 나오는 긴 프롬프트로 쓰지 않는다(Cypher처럼 따라 하는 실습의 복사용 질의는 그대로). 응답 재생 저장분이 만들어지기 전에는 재생을 되는 것처럼 쓰지 않는다.

## H5 정적 검사 · 배포 · 받기 시험

1. **동기화:** 함께 갱신할 범위는 기준_공통 G4-9다. 외부 게시는 요청이 있을 때 하고, 이전 ZIP의 루트 폴더 이름을 유지한다.
2. **정적 검사**(실행 없음): 자료 참조 경로 · 식별자 · 입출력 · 값과 단위 · 시점 · 조건 대조, Python은 AST · JSON/XML/BPMN은 파싱만, HTML의 내용 · 순서 · 로컬 링크, 복사 자료 해시, ZIP 안 **정확한 경로 집합**과 각 파일 바이트를 배포 폴더와 비교(합계만 같으면 통과 아님). 실행 위치 · 명령 인수 · 상태값 · 화면 확인 조건이 지금 코드와 맞는지 대조한다. 구문 통과는 구현 성공이 아니다.
3. **받기 시험**(실제 실행): 학생 경로 그대로 다운로드 → 압축 해제(새 시험 폴더) → 열기 → 가이드의 위치 · 명령대로 실행 → 저장 → 다시 열기. 정상 · 경계 · 오류와 복구를 확인하고, GUI는 실제 화면 · 상태 변화로 본다(CLI 로그를 GUI 증거로 쓰지 않음). 복사한 것과 붙여넣은 것의 일치, 학생 작성 내용 보존, 브라우저 표시(읽기 순서 · 코드 복사 · 사진 크기 · 여백 · 모바일 가로 넘침)와 단계 이동 버튼 · 직접 링크 · 키보드 이동이 같은 화면으로 가는지를 실제로 본다. 학교 PC 초기화 뒤 검증과 개인 환경 검증을 구별한다.
4. 학생 패키지 검사(`제작용/실습시작/verify_packages.py`)와 경로 · 쓰기 권한 · 네트워크 · 보안 경고 · VS Code 폴더 신뢰는 실제 환경에서 확인해 기록하고, 직접 청취 · 자동 검사 · 학교 초기화 확인의 상태어는 기준_공통 G4-7.
