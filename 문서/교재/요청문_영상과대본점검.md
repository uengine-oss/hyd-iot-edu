# 요청문 — 영상과 대본 점검

사용자가 다른 PC 세션을 시작할 때 준 요청문 원문이다(2026-10-22). 이어서 할 일과 현재 상태는 [인계_영상과대본점검.md](인계_영상과대본점검.md)가 정본이다.

2026-10-22 상태: 1 · 2회차 이론 대본 · 덱 최종 점검본을 사용자가 확정했다(develop 4e46e36b). 영상은 사용자가 다른 곳에서 만들고, DoD 4(새 영상의 말머리 잘림 · 장 넘김 검사)는 그때 확인한다.

## 원문

```text
의도(Why & Value)
경남대 피지컬AI 사관학교 통합반·실전반 학생을 위해, 1·2일차 이론 영상과 두 과정 공통 실습을 화면·실습과 어긋남 없이 완성한다.

작업요령과 컨텍스트
uengine-oss/hyd-iot-edu 저장소의 other-pc 브랜치를 받는다(영상·음성 캐시 포함). 문서·대본 수정은 develop에 커밋하고 other-pc로 병합한다.
문서/교재/인계_영상과대본점검.md를 먼저 읽고, 실제 git 상태·최신 사용자 지시와 대조한다. 다르면 실제와 최신 지시가 이긴다.
두 과정 기준은 문서/교재/2_기준.md 「두 과정의 공통 범위와 차이」: 랩은 한 벌·실전반 난이도, 차이는 VS Code 랩 대본과 이론 대본(1회차는 공통)에만.
대본은 윤문하지 않고 내용·의도가 어긋난 곳만 전/후로 보여 승인받은 뒤 고친다. 음성을 뽑기 전에 화면 대조를 먼저 한다.
키는 환경변수 ELEVENLABS_API_KEY로만 받고 어디에도 커밋하지 않는다(공개 저장소). 맑은 고딕이 없으면 사용자에게 받는다.
인계 §5의 폐기된 판단을 되살리지 않는다. 시작은 인계 §9의 1번이다. 진행하며 인계를 갱신한다.

인수조건(DoD)
1. 인계 §6의 승인 대기 항목(1회차 랩 공통판, 2일차 대본·덱)이 사용자 결정대로 두 과정에 반영된다.
2. 같은 덱 장을 쓰는 두 과정 대본의 같은 문장이 서로 다른 곳이 0건이다.
3. 대사가 가리키는 위치·모양이 그 장 화면에 없는 곳이 0건이다.
4. 새로 만든 영상마다 말머리 잘림 0곳, 장 넘김 불일치 0곳이다.
5. 키·글꼴 파일이 저장소에 0건이다.
6. 인계·현황·남은 일·영상 목록이 실제 상태와 맞게 갱신된다.
```
