## 3. 확인하지 못한 것

- 회의 준비 예시(종합 랩의 예시 사례)를 실제 구글 계정으로 한 번 돌려 보는 일. 연결 경로는 구현했으나 구글 앱 등록과 계정 동의, 실제 실행은 하지 않았다.
- 수업 리허설. 학생 PC마다의 환경, 외부 MCP 서버 세 가지(파일, Git, 시간)의 설치와 권한, Notion 쓰기 권한, 수강생이 따라 하는 데 걸리는 시간.
- 승인 · 거절에서 시스템 종료까지의 모든 화면을 실시간으로 찍은 증거. 첫 실시간 캡처 도구가 중간에 끊겼다.
- A 시나리오에서 조치 뒤 실제로 회복되어 닫히는 경우.
- 덱의 값 가운데 통합반 10일차 「정기 점검의 추천안」 「재고 보충의 추천안」 두 장은 사실표가 아니라 로컬 실행 기록에서 읽은 것이고, 그 기록은 저장소에 없다.

## 4. 문서와 코드가 어긋난 채 남은 곳

코드가 맞다. 문서는 아직 고치지 않았다(`6_남은_일.md` 2절).

| 무엇 | 문서 | 코드 |
|---|---|---|
| 명령 관문의 검사 가짓수 | 여러 곳이 「5종」 | 검사 이름 일곱(스키마, 허용 목록, 만료, 중복, 승인, 모드, 속도 제한). `dmz/cmd-gateway/gw/validate.py` |
| 메시지 기록의 보존 기간 | `참조/topics.md`: 값 7일, 파형 7일, 상태 30일, 특징 30일 | 값 1일, 파형 6시간, 상태 7일, 특징 3일. `it/redpanda/topics.sh` |
| 시간 배율을 받는 서비스 | 「네 서비스」 | 환경 변수를 받는 것은 셋(설비 시뮬레이터, 감지, 프로세스 엔진). 에이전트는 프로세스 엔진이 알려 주는 값을 읽는다 |
| 기본으로 떠 있는 컨테이너 | `참조/RUNBOOK.md`: 15개 | 16개(효과 확인용 MCP가 빠져 있다) |
| 에이전트용 MCP 묶음 | 서비스 둘 | 다섯(정비용과 구매용 업무 MCP, 워커 컨테이너가 더 있다) |
| 스키마의 크기 | `참조/ontology/schema-v2.md` 본문: 클래스 36, 관계 66 | 클래스 46, 관계 74. `참조/ontology/class-table.md`(생성 파일)가 맞다 |
| 순위 점수식의 자리 | `schema-v2.md`: 규칙의 주석 | 규칙의 `rankingPolicy`. `참조/ranking-policy.md`가 맞다 |
| 펌프 누설, 팬 진동 | `schema-v2.md`: 시뮬레이터와 감지에 아직 없다 | 둘 다 있다 |
| 에이전트가 읽는 질의 틀 | `참조/scenario-walkthrough.md`: `t2_actions` | `t2_skills`. 이 문서는 첫 판 기준이라 승인 API와 질의가 지금 배포본에서 그대로 돌지 않는다 |

확인하지 못한 채 남은 것: 사건(Incident)이 닫힐 때만 그래프에 기록되는지 진행 중에도 투영되는지, `AGENT_BRIDGE=off`를 어느 서비스에 주어야 하는지, 기준 정의에서 승인 기한이 지나면 책임자 호출로 가는지.

## 5. 이 PC와 다른 PC

- 시스템은 Windows PC에서 개발했고 그 PC에서는 2026-10-13에 모두 내렸다(데이터는 그대로 두었다).
- 교재를 만든 macOS PC에는 colima 프로필 `hyd`로 띄운 스택이 따로 있다. 켜는 법은 `4_켜고_돌리는_법.md`에 있다.
- 실행 증거 폴더 `.evidence/`는 저장소에 올리지 않는다. PC마다 내용이 다르다.
