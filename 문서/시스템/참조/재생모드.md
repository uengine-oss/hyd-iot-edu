# AI 응답 재생 — API 키 없이 실습하기

온라인 학생은 영상을 보며 자기 PC의 포털에서 같은 조작을 따라 한다. 포털 · 가상 설비 · 처리 흐름은 학생 PC에서 실제로 실행된다. 일부 단계는 AI가 응답해야 진행된다. 이 단계에서는 워커가 Claude Code나 Codex로 LLM을 호출하는데, 학생에게 API 키가 없으면 여기서 막힌다.

**AI 응답 재생은 API 키가 없을 때, AI가 응답할 단계에만 미리 실제 AI로 실행하며 저장한 응답을 넣는다.** 그 밖의 모든 것은 실제로 실행된다. 경위는 `../5_결정_기록.md` 1절 2026-10-22 행, 지키는 규칙은 `../2_기준.md` 12절이다.

## 1. 동작

| `AI_MODE` | 하는 일 | 쓰는 때 |
|---|---|---|
| `auto`(기본) | 워커가 켜질 때 API 키 · CLI 로그인을 확인한다. **키가 없으면 `replay`, 있으면 `live`**. 확인할 수 없을 때도 `replay`다 | 늘 |
| `live` | 실제 AI(기존 그대로) | 키가 있을 때 |
| `record` | 실제 AI로 실행하면서, CLI가 낸 실행 이벤트 · 결과 파일 · 작업 기록을 업무마다 `AI_REPLAY_DIR`(기본 `it/agent-worker/replay/`)에 저장한다 | 저장분을 만들 때 |
| `replay` | CLI를 부르지 않고, 같은 업무의 저장된 실행 이벤트를 이 처리 건의 값으로 바꿔 내보낸다 | 키가 없을 때 |

- 바꾸는 곳은 워커 `Runner`의 CLI 실행 자리(`exec_fn`) 하나다(`it/agent-worker/worker/ai_replay.py`, 고르는 곳은 `worker/main.py`의 `build_runner`).
- 그 뒤의 최종 응답 해석, 결과 형식 검사, 사람에게 묻기 · 보류, 결과 저장, 처리 과정 이벤트는 실제 실행과 같은 코드다.
- 재생한 단계마다 처리 과정에 한 줄이 남는다: 「AI 응답 재생 — 미리 저장한 응답이며 지금 AI가 새로 추론한 것이 아닙니다(「우선순위 · 카드 작성」, 저장 시각 저장). 쓰기 도구(hyd-dmn/submit_decision)는 이 PC에서 다시 실행했습니다.」 뒤 문장은 쓰기 도구를 다시 부른 단계에만 붙는다. 포털 처리 과정은 긴 줄 끝을 「…」로 자르므로 핵심을 앞에 두었다(2026-10-23 화면 확인).
- 워커가 `replay`로 켜지면 로그에 경고가 남고, 워커 `/health`에 `ai_mode`가 보인다.

## 2. 규칙: 같은 업무면 저장된 응답을 쓴다

- 업무는 **무엇에 대한 처리 건인가 + 업무 이름**으로 가린다.
  - 경보로 시작한 처리 건은 경보 종류(처리 건 값 `pattern`: 쿨러 열화 · 펌프 누설 · 팬 진동 · 정기 정비 도래 · 재고 기준 이탈 …).
  - 문서 추출은 문서 내용 해시(`manual_source.sha256` — 올릴 때마다 바뀌는 문서 id가 아니라 내용)와 긴 문서의 구간 번호. 두 과정의 HM-8 원문이 달라 따로 저장된다. 학생이 다른 문서를 올리면 그 문서의 저장분이 없어 실패한다.
  - 둘 다 없는 처리 건(질문 답변 등)은 업무 이름만.
  - 업무 이름은 워커 프롬프트의 「## 업무」 줄(작업 단계 이름, 예: 원인 진단)이다. 띄어쓰기 · 대소문자는 무시한다.
  - 경보 종류를 넣는 까닭: 쿨러 · 펌프 · 팬은 같은 흐름(`anomaly_response`)의 같은 업무 이름을 쓴다. 이름만으로 가리면 펌프 사건에 쿨러 응답이 들어간다.
  - 흐름 정의 id는 넣지 않는다. 학생이 bpmn.io로 그린 흐름은 id가 강사 것과 달라서, 넣으면 따라 그린 흐름도 재생되지 않는다.
- 입력 값이나 지시문이 저장할 때와 달라도 같은 응답을 쓴다. 학생이 무엇을 하든 AI 단계는 저장된 응답으로 답한다.
- 업무 하나에 파일 하나(`<업무 해시>.json.gz`, gzip으로 압축한 JSON, 형식 `hyd-ai-replay/2`)다. 실제 AI는 도구 결과를 크게 받아 와서 압축 전에는 업무 하나가 0.3~5 MB였다. 압축하면 5 %로 준다(2026-10-23 실측). 그 안에 실행이 순서대로 들어 있다.
  - 첫 실행
  - 같은 세션을 이어 간 실행: AI가 사람에게 묻고 사람이 답한 뒤의 실행, 결과 형식 교정 요청 뒤의 실행
- 재생할 때도 같은 순서로 이어진다. 학생이 질문에 다른 글로 답해도 저장된 다음 응답이 나온다. Claude Code는 이어 해도 세션 id가 같아서, 이어 하기는 그 세션의 마지막 실행 뒤에 붙인다(첫 실행 뒤에 붙이면 세 번째부터 가운데가 지워졌다 — 2026-10-23 실측 결함, 고침).
- 같은 업무를 다시 저장하면 그 파일을 덮어쓴다.
- **저장분이 없는 업무는 지어내지 않고 그 단계를 실패시킨다.** 처리 과정에 「AI 응답 재생: 「…」 업무의 저장된 AI 응답이 없습니다. API 키를 넣으면 실제 AI로 실행합니다.」가 남고, 다음 단계로 가지 않는다. 포털은 실제 실행이 실패했을 때와 같이 그 작업을 닫을 수 있게 한다.
- 저장된 응답이 그 처리 건의 결과 형식에 맞지 않으면 실제 실행과 같은 형식 검사가 실패시킨다. 이어지는 교정 응답이 저장돼 있지 않으면 그 단계는 실패로 끝난다.

## 3. 이 처리 건의 값으로 바꿔 끼우기, 쓰기 도구 다시 부르기

저장된 응답을 그대로 내보내면 저장할 때의 처리 건 id · 사건 번호 · 판단 id가 학생 처리 건에 들어간다. 처리 흐름은 이것을 받지 않는다. 예를 들어 「우선순위 · 카드 작성」의 판단 id는 **그 작업 · 세대가 직접 등록한 판단**이어야 한다(`procsvc/decision_scope.validate_output`). 그래서 재생은 두 가지를 한다.

1. **값 바꿔 끼우기.** 저장할 때의 작업 기록(`context/task.json`의 작업 id · 처리 건 id · `process_scope` · 입력 데이터)과 지금 작업 기록을 같은 자리끼리 비교한다. 달라진 값을 저장된 응답 · 도구 입력 · 결과 파일에서 지금 값으로 바꾼다. 글 속에서는 id처럼 생긴 값(공백 없이 5자 이상, 숫자와 문자가 섞인 것)만 바꾼다. AI 설명은 저장할 때 조각을 한 덩이로 합쳐 두어, 조각 경계에 걸린 id도 바뀐다.
2. **쓰기 도구는 이 PC에서 다시 부른다.** 저장된 AI가 부른 MCP 도구 가운데 서버가 읽기 전용으로 표시하지 않은 것(`mcp_check.read_only_verdict`, 예: `submit_decision` · `submit_purchase`)은 저장된 결과를 쓰지 않는다. 바꿔 끼운 입력으로 이 PC의 서버를 실제로 부른다. 서버 설정은 이번 실행의 작업 폴더 `.mcp.json`(실제 실행이면 CLI가 읽을 그 파일)이다. 그 도구가 돌려준 새 id(`id` · `*_id` · `*Id` 칸)도 뒤의 응답 · 결과에서 바꿔 끼운다.
   - 승인 전 에이전트의 쓰기는 승인 대기 카드 등록뿐이다(`../2_기준.md`). 설비 명령은 사람 승인 뒤 process가 실행한다.
   - 다시 부른 쓰기 도구가 오류를 돌려주면 그 단계를 실패시키고 사유를 남긴다.
   - 읽기 도구는 다시 부르지 않고 저장된 결과를 쓴다. 명령형(stdio) 서버는 읽기로 본다(이 시스템의 명령형 서버는 읽기 전용 neo4j뿐이고, 학생이 등록한 서버는 읽기 도구만 허용된다).
   - `submit_decision`은 학생 PC의 지식 · 시계열 · 업무 데이터로 카드를 다시 계산한다. 그래서 등록되는 판단(추천 · 카드 순서)은 학생 처리 건의 값으로 만들어진다. AI 설명 글과 결과의 요약 글은 저장할 때 것이다.

학생이 따라 하지 않을 때의 영향은 다음과 같다.
- 포털 · 설비 · 처리 흐름은 학생 것 그대로 실제로 돈다. 학생이 만든 흐름 · 에이전트도 돈다.
- AI 단계의 설명 · 판단 글은 저장된 것이라 학생 상황과 어긋날 수 있다(예: 저장할 때 측정값을 말한다). 처리 과정의 재생 알림으로 구분하고, 수업 영상에서 재생 모드임을 알린다.
- 업무 이름이 저장분에 없는 단계(학생이 새로 만든 업무)는 실패한다.

## 4. 저장분과 보안

- **저장 파일 내용:** 형식, 업무 이름, 저장 시각, CLI 종류, 실행 목록(세션 id, 실행 이벤트, 결과 파일 `output/result.json`, 작업 기록 값). 내부 생각(`THINKING`)은 빼고 도구 호출과 결과는 넣는다. CLI 원문 줄(`raw`)은 종류를 모르는 이벤트만 넣는다.
- **비밀값:** 아래 값이 저장 내용에 있으면 그 값을 `********`로 가리고 저장한다. 어느 이름의 값을 가렸는지(값은 빼고) 경고 로그를 남긴다. 가린 값은 저장 파일 어디에도 남지 않는다. 예: 실제 AI가 작업 폴더의 `.mcp.json`을 읽어 neo4j 비밀번호가 실행 기록에 들어갔다(2026-10-23 실측). 저장을 거절하면 그 단계를 재생할 수 없어서 가리기로 했다.
  - 워커가 켜질 때 보이는 비밀 환경 변수: 워커가 자식 프로세스에서 지우는 이름(`env_guard`: DSN · 비밀번호 · 토큰 · API 키 · `HYD_SECRET_*`)과 CLI 로그인 키(`ANTHROPIC_API_KEY` 등).
  - 이번 실행의 `.mcp.json` env · headers 가운데 비밀 이름의 값(학생이 등록한 서버의 토큰 등)과 「Bearer <토큰>」의 토큰.
- **API 키:** 워커 환경 변수에만 둔다. 포털 화면 · 저장 파일 · 로그에 넣지 않는다. 개발 · 시험은 대역 CLI로 했고 실제 키를 쓰지 않았다.
- **설비 권한과의 관계:** 재생은 AI 응답만 바꾼다. 승인 뒤의 설비 명령은 실제 실행처럼 학생 PC의 가상 설비로 간다. 설비 명령 권한은 AI 키와 상관없다.
- **바깥 호출:** 재생 중 워커는 CLI · LLM을 부르지 않는다. 다시 부르는 쓰기 도구는 이 PC의 업무 도구 서버다.

## 5. 저장분 만들기와 쓰기

- **만들기:** 키가 있는 PC에서 워커를 `AI_MODE=record`로 켜고 실습을 끝까지 한 번 한다. 끝나면 `it/agent-worker/replay/`를 커밋한다. 실제 AI 저장분은 압축 뒤 고장 하나(AI 단계 넷)가 0.4~0.7 MB, HM-8 추출(시도 셋)이 1.2 MB였다(대부분 도구 결과 JSON).
- **쓰기:** 학생은 아무것도 하지 않는다. API 키가 없으면 워커가 알아서 `replay`로 켜진다(`auto`). 키가 있으면 실제 AI가 응답한다.

## 6. AI가 응답하는 단계가 있는 실습(두 과정 대응표)

조사(2026-10-22)에서 두 과정 실습을 모두 읽었다. 통합반은 45편, 실전반은 39편이다. 모든 실습 문서가 「실제 실행 · 촬영 미수행」 상태라, 아래는 문서와 코드로 정한 것이다.

| 통합반 | 실전반 | 워커 AI가 응답하는 단계 | 저장 · 재생 대상 |
|---|---|---|---|
| 01-3 쿨러 사건 관찰 | 01-3 | 원인 진단 · 조치 후보 조회 · 규정 검토 · 우선순위 · 카드 작성. 수업 설정 `AGENT_BRIDGE=off`일 때만 워커가 응답하고, `legacy`면 내장 판단이라 키가 필요 없다 | 예(워커 경로일 때). 이 실습으로 끝까지 검증했다(7절) |
| 04-1 매뉴얼 등록과 검토 | 03-3 | 매뉴얼 추출 `task:extract-manual` | 예 |
| 05-1 업무 에이전트 구성 | 04-1 | 질문 답변 `task:answer` | 예 |
| 06-1 업무 도구 연결 · 호출 | 04-4 앞부분 | 마지막 「에이전트에 요청 전달」 | 예 |
| 09-4 실행 기록 확인 | 06-7 | 가져온 흐름의 판단 · 제안 `task:decide`(판단 등록 = 쓰기 도구 다시 부르기) | 예 |
| 10-2 · 10-4 정기 점검 · 재고 보충 실행 | 07-2 · 07-4 | 판단 · 제안(`submit_decision` · `submit_purchase`) | 예 |
| 11-3 · 11-4 제안 에이전트 · 흐름 실행 | 08-3 · 08-4 | 학생 에이전트 단계 | 예(업무 이름이 저장분과 같을 때) |

- **AI가 응답하지 않는 포털 실습:** 02-2, 03-1, 07-1, 09-3 등이다. 키가 없어도 그대로 된다.
- **VS Code + Copilot 실습:** 학생 본인의 GitHub Copilot이 AI다. 워커와 상관없다.
- **두 과정이 같은 업무 이름을 쓰면 저장분 하나를 같이 쓴다.** 과정마다 다른 응답이 필요하면 `AI_REPLAY_DIR`을 과정별로 나눈다.
- **미확인:** 04-2 · 05-2(실전반 03-4 · 04-2)는 학생 코드가 모델을 직접 부르라고 하는데, 랩 폴더에 호출 수단이 없다. 워커 재생으로는 다룰 수 없다.

## 7. 검증과 미확인

- **단위 시험(`tests/test_ai_replay.py`, 28건 통과):** 가짜 CLI · 가짜 도구 서버로 「저장 → 다른 처리 건에서 재생」을 확인했다.
  - CLI를 부르지 않는다, CLI가 설치돼 있지 않은 PC에서도 돈다, 알림 한 줄(「강사」 같은 말 없음)
  - 그 업무의 저장분이 없으면 다른 업무 저장분이 있어도 실패한다, 업무 이름의 띄어쓰기 · 대소문자는 무시한다
  - 같은 업무 이름이라도 경보 종류가 다르면 다른 업무다(쿨러 저장분을 펌프 사건에 쓰지 않는다), 문서 추출은 문서 내용 · 구간으로 가린다
  - 입력 · 지시문이 달라도 같은 업무면 재생한다, 다시 저장하면 파일 하나를 덮어쓴다
  - 형식에 안 맞는 저장분은 실패한다. 형식 교정 · 사람 질문 → 다른 글로 답 → 다음 응답이 순서대로 이어진다. 같은 CLI 세션의 실행 셋도 모두 순서대로 남는다
