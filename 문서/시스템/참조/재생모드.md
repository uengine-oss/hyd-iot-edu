# AI 응답 재생 — API 키 없이 실습하기

온라인 학생은 영상을 보며 자기 PC의 포털에서 같은 조작을 따라 한다. 포털 · 가상 설비 · 처리 흐름은 학생 PC에서 실제로 실행된다. 일부 단계는 AI가 응답해야 진행된다. 이 단계에서는 워커가 Claude Code나 Codex로 LLM을 호출하는데, 학생에게 API 키가 없으면 여기서 막힌다.

**AI 응답 재생은 API 키가 없을 때, AI가 응답할 단계에만 미리 실제 AI로 실행하며 저장한 응답을 넣는다.** 그 밖의 모든 것은 실제로 실행된다. 경위는 `../5_결정_기록.md` 1절 2026-10-22 행, 지키는 규칙은 `../2_기준.md` 12절이다.

## 1. 동작

| `AI_MODE` | 하는 일 | 쓰는 때 |
|---|---|---|
| `auto`(기본) | 워커가 켜질 때 API 키 · CLI 로그인을 확인한다. **없다고 확인되면 `replay`**, 있거나 확인할 수 없으면 `live` | 늘 |
| `live` | 실제 AI(기존 그대로) | 키가 있을 때 |
| `record` | 실제 AI로 실행하면서, CLI가 낸 실행 이벤트와 결과 파일을 업무마다 `AI_REPLAY_DIR`(기본 `it/agent-worker/replay/`)에 저장한다 | 저장분을 만들 때 |
| `replay` | CLI를 부르지 않고, 같은 업무의 저장된 실행 이벤트를 그대로 내보낸다 | 키가 없을 때 |

- 바꾸는 곳은 워커 `Runner`의 CLI 실행 자리(`exec_fn`) 하나다(`it/agent-worker/worker/ai_replay.py`, 고르는 곳은 `worker/main.py`의 `build_runner`).
- 그 뒤의 최종 응답 해석, 결과 형식 검사, 사람에게 묻기 · 보류, 결과 저장, 처리 과정 이벤트는 실제 실행과 같은 코드다.
- 재생한 단계마다 처리 과정에 한 줄이 남는다: 「AI 응답 재생: 「원인 진단」 — 미리 저장한 응답입니다(저장 시각). 지금 AI가 새로 추론한 것이 아닙니다.」
- 워커가 `replay`로 켜지면 로그에 경고가 남고, 워커 `/health`에 `ai_mode`가 보인다.

## 2. 규칙 하나: 업무 이름이 같으면 저장된 응답을 쓴다

- 업무 이름은 워커 프롬프트의 「## 업무」 줄(작업 단계 이름, 예: 원인 진단)이다. 입력 값이나 지시문이 저장할 때와 달라도 같은 응답을 쓴다. 학생이 무엇을 하든 AI 단계는 저장된 응답으로 답한다.
- 업무 하나에 파일 하나(`<업무 이름 해시>.json`, 형식 `hyd-ai-replay/2`)다. 그 안에 실행이 순서대로 들어 있다.
  - 첫 실행
  - 같은 세션을 이어 간 실행: AI가 사람에게 묻고 사람이 답한 뒤의 실행, 결과 형식 교정 요청 뒤의 실행
- 재생할 때도 같은 순서로 이어진다. 학생이 질문에 다른 글로 답해도 저장된 다음 응답이 나온다.
- 같은 업무를 다시 저장하면 그 파일을 덮어쓴다.
- **저장분이 없는 업무는 지어내지 않고 그 단계를 실패시킨다.** 처리 과정에 「AI 응답 재생: 「…」 업무의 저장된 AI 응답이 없습니다. API 키를 넣으면 실제 AI로 실행합니다.」가 남는다.
- 저장된 응답이 그 처리 건의 결과 형식에 맞지 않으면 실제 실행과 같은 형식 검사가 실패시킨다. 이어지는 교정 응답이 저장돼 있지 않으면 그 단계는 실패로 끝난다.

학생이 따라 하지 않을 때의 영향은 다음과 같다.
- 포털 · 설비 · 처리 흐름은 학생 것 그대로 실제로 돈다. 학생이 만든 흐름 · 에이전트도 돈다.
- AI 단계의 응답만 저장된 것이라, 내용이 학생 상황과 어긋날 수 있다(예: 저장할 때 사건의 값을 말한다). 처리 과정의 재생 알림으로 구분하고, 수업 영상에서 재생 모드임을 알린다.

## 3. 저장분과 보안

- **저장 파일 내용:** 형식, 업무 이름, 저장 시각, CLI 종류, 실행 목록(세션 id, 실행 이벤트, 결과 파일 `output/result.json`). 내부 생각(`THINKING`)은 빼고 도구 호출과 결과는 넣는다.
- **비밀값:** 워커가 켜질 때(자식 프로세스용 환경 정리 전) 보이는 키 · 토큰 · 비밀번호 환경 변수의 값이 저장 내용에 있으면 저장하지 않고 오류 로그를 남긴다.
- **API 키:** 워커 환경 변수에만 둔다. 포털 화면 · 저장 파일 · 로그에 넣지 않는다. 개발 · 시험은 가짜 CLI로 했고 실제 키를 쓰지 않았다.
- **설비 권한과의 관계:** 재생은 AI 응답만 바꾼다. 승인 뒤의 설비 명령은 실제 실행처럼 학생 PC의 가상 설비로 간다. 설비 명령 권한은 AI 키와 상관없다.
- **바깥 호출:** 재생 중 워커는 CLI · LLM을 부르지 않는다.

## 4. 저장분 만들기와 쓰기

- **만들기:** 키가 있는 PC에서 워커를 `AI_MODE=record`로 켜고 실습을 끝까지 한 번 한다. 끝나면 `it/agent-worker/replay/`를 커밋한다.
- **쓰기:** 학생은 아무것도 하지 않는다. API 키가 없으면 워커가 알아서 `replay`로 켜진다(`auto`). 키가 있으면 실제 AI가 응답한다.

## 5. AI가 응답하는 단계가 있는 실습(두 과정 대응표)

조사(2026-10-22)에서 두 과정 실습을 모두 읽었다. 통합반은 45편, 실전반은 39편이다. 모든 실습 문서가 「실제 실행 · 촬영 미수행」 상태라, 아래는 문서와 코드로 정한 것이다.

| 통합반 | 실전반 | 워커 AI가 응답하는 단계 | 저장 · 재생 대상 |
|---|---|---|---|
| 01-3 쿨러 사건 관찰 | 01-3 | 원인 진단 · 조치 후보 · 규정 검토 · 우선순위. 수업 설정 `AGENT_BRIDGE=off`일 때만 워커가 응답하고, `legacy`면 내장 판단이라 키가 필요 없다 | 예(워커 경로일 때) |
| 04-1 매뉴얼 등록과 검토 | 03-3 | 매뉴얼 추출 `task:extract-manual` | 예 |
| 05-1 업무 에이전트 구성 | 04-1 | 질문 답변 `task:answer` | 예 |
| 06-1 업무 도구 연결 · 호출 | 04-4 앞부분 | 마지막 「에이전트에 요청 전달」 | 예 |
| 09-4 실행 기록 확인 | 06-7 | 가져온 흐름의 판단 · 제안 `task:decide` | 예 |
| 10-2 · 10-4 정기 점검 · 재고 보충 실행 | 07-2 · 07-4 | 판단 · 제안 | 예 |
| 11-3 · 11-4 제안 에이전트 · 흐름 실행 | 08-3 · 08-4 | 학생 에이전트 단계 | 예(업무 이름이 저장분과 같을 때) |

- **AI가 응답하지 않는 포털 실습:** 02-2, 03-1, 07-1, 09-3 등이다. 키가 없어도 그대로 된다.
- **VS Code + Copilot 실습:** 학생 본인의 GitHub Copilot이 AI다. 워커와 상관없다.
- **두 과정이 같은 업무 이름을 쓰면 저장분 하나를 같이 쓴다.** 과정마다 다른 응답이 필요하면 `AI_REPLAY_DIR`을 과정별로 나눈다.
- **미확인:** 04-2 · 05-2(실전반 03-4 · 04-2)는 학생 코드가 모델을 직접 부르라고 하는데, 랩 폴더에 호출 수단이 없다. 워커 재생으로는 다룰 수 없다.

## 6. 검증과 미확인

- **시험(`tests/test_ai_replay.py`, 17건 통과):** 가짜 CLI로 「저장 → 다른 처리 건에서 재생」을 확인했다.
  - 재생할 때 CLI를 부르지 않고, 같은 결과가 저장되고, 알림 한 줄이 남는다(「강사」 같은 말이 없다)
  - 그 업무의 저장분이 없으면 다른 업무 저장분이 있어도 실패한다
  - 입력 · 지시문이 달라도 같은 업무면 재생한다
  - 다시 저장하면 그 업무 파일 하나를 덮어쓴다
  - 결과 형식에 안 맞는 저장분은 실패한다, 형식 교정은 순서대로 저장 · 재생된다
  - 사람 질문 → 다른 글로 답 → 저장된 다음 응답으로 이어진다
  - 비밀값을 저장하지 않는다, 결과 파일을 저장 · 복원한다
  - 모드 결정, CLI가 없는 워커가 `replay`로 켜진다
- **돌연변이 확인:** 일부러 깨뜨린 세 경우가 시험에 잡혔다(없는 업무에 다른 저장분 쓰기, 재생 알림 빼기, 비밀값 검사 빼기).
- **기존 워커 회귀:** 워커를 쓰는 시험 38개 파일 555건 가운데 551건 통과, 1건 건너뜀, 3건 실패다. 실패 3건은 기준 판본(develop)에서도 실패하던 포털 UI 시험이다.
- **미확인:**
  - 실제 AI로 저장(`record`)한 뒤 키 없는 PC에서 재생하는 실제 실행. 이 클라우드에서는 유료 AI 호출을 하지 않아 돌리지 않았다.
  - 실제 Claude Code · Codex 이벤트가 가짜 CLI와 다른 칸을 쓸 때의 차이.
  - 포털 화면에서 재생 알림이 어떻게 보이는지.
  - 로그인 확인(`claude auth status` 등)이 학생 PC에서 「없음」을 바르게 돌려주는지.
