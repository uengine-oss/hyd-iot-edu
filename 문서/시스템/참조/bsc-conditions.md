# BSC 영향 경로와 조건 해석

조치에서 BSC 지표로 이어지는 관계를 경로별로 보존하고, 검토된 조건식이 있으면 현재 사실 또는 해당 후보의 예측으로 적용 여부를 평가한다. 자연어 `condition` 원문은 그대로 유지한다. “베어링 마모 시 크게”처럼 강도를 설명하는 문장을 임의의 적용/제외 임계치로 바꾸지 않는다.

## 조회와 평가

MCP `tradeoffs(skill_ids)`는 Skill의 AFFECTS 관계에서 시작해 최대 네 개의 INFLUENCES 관계를 거쳐 처음 만나는 Measure까지 각 경로를 반환한다. 노드 순서, 관계 식별자·종류·양 끝 ID·sign·strength·delta·unit·note·condition·conditionPolicy, 지표와 소유자를 남긴다. 같은 지표로 향하는 여러 경로를 하나의 조건으로 합치지 않는다. 이 목록은 구조 조회이며 조건이 참이라는 증거가 아니다.

MCP `evaluate_cards`의 후보별 `tradeoffEvaluation`에는 다음 판정과 사용한 입력이 남는다.

| 판정 | 의미 | 점수 입력 처리 |
|---|---|---|
| TRUE | 무조건 관계이거나 검토한 조건식이 현재 입력에서 참 | 확인된 영향으로 집계 |
| FALSE | 경로의 조건 중 하나 이상이 거짓 | 점수에서 제외하되 경로와 근거 보존 |
| UNKNOWN | 원문만 있고 식이 없거나, 원문 변경·입력 없음·계산 오류 | 미확인 추정으로 별도 집계 |

경로의 부호는 관계 sign의 곱이다. Measure의 UP/DOWN 방향과 비교해 득실을 정한다. 경로 가중치는 INFLUENCES의 high=1, medium=0.6, low=0.3을 곱한다. 이는 현재 HYD의 정성적 비교 척도이며 확률·금액·실측 영향량이 아니다. AFFECTS의 delta/unit은 근거로 보존하며 이 가중치 계산에 물리량으로 곱하지 않는다. 알 수 없는 strength/sign/direction이나 순환 경로는 정상 영향으로 추정하지 않고 계산 오류로 처리한다.

같은 지표·같은 부호에서 TRUE의 최대 가중치를 확인된 영향으로 사용한다. UNKNOWN의 최대 가중치가 그보다 클 때만 차이를 미확인 영향으로 추가한다. 예를 들어 TRUE 0.3과 UNKNOWN 1.0이면 확인 0.3, 미확인 0.7이다. 초기 순위 정책의 미확인 계수 0.5를 적용하면 0.65가 된다. 이미 확인한 0.3을 다시 더하지 않는다. 동일 최대값의 모든 지지 경로도 남긴다. 서로 반대인 부호는 별도 득실로 유지한다.

미확인 계수는 [명시 순위 정책](ranking-policy.md)의 업무 가정이다. 회의 원문이 정한 수치 또는 안전성 판정이 아니다. 과거 미리 집계한 효과 행을 받는 내부 호환 경로는 `materialized_without_path`로 표시하며 존재하지 않는 원자 경로를 만들지 않는다.

## 조건식 검토·변경

`GET /api/kg/bsc/conditions`로 현재 관계·원문·정책·revision을 조회한다. 정확한 대상 관계의 `key`를 URL 인코딩하여 `PUT /api/kg/bsc/conditions/{key}`로 수정한다. key는 현재 Neo4j 관계 elementId다. 백업 복원이나 관계 재생성 뒤에는 목록을 다시 읽는다. 외부 영구 업무 식별자로 사용하지 않는다.

```json
{
  "expected_revision": "방금 조회한 관계의 revision",
  "request_id": "새 UUID",
  "by": "지식 작성자",
  "reason": "조건 해석의 검토 근거",
  "policy": {
    "version": 1,
    "description": "대상 관계의 condition 원문과 정확히 같은 문자열",
    "inputs": {
      "x": {"source": "fact", "variable": "선언된 InputData 변수"}
    },
    "expression": "x > 1"
  }
}
```

이 임계치는 작성 형식 예시다. 업무에 맞게 원문과 단위·입력·조건 의미를 검토한다. `fact`는 현재 InputData 변수, `forecast`는 해당 후보의 StateVariable ID(예: `sv:ts1`)를 명시한다. 관측값과 후보 예측을 같은 입력으로 숨기지 않는다. 선언이 없거나 모호한 입력은 저장을 거절한다. 조건식은 [순위 정책의 제한된 식 문법](ranking-policy.md)을 사용하며 결과가 실제 불리언이어야 한다. 문자열·숫자의 truthiness나 None의 암묵적 false 변환은 없다. `x is None` 같은 분기는 작성자가 명시한 해석이다.

원문과 description이 다르면 저장을 거절한다. 저장 뒤 원문이 바뀌어도 이전 해석으로 참을 선언하지 않고 UNKNOWN으로 남긴다. `policy: null`은 실행 해석만 제거하며 원문을 지우지 않는다. 원문이 남아 있으면 UNKNOWN으로 돌아간다.

관계 변경과 KnowledgeEdit 영수증은 한 거래에 기록한다. 오래된 revision은 409, 잘못된 식·원문·입력은 400이다. 같은 UUID와 같은 요청의 재시도는 당시 영수증을 반환하며 현재 정책을 과거로 덮어쓰지 않는다. 원문 적재가 소유한 대상은 원천 검토를 통해 변경해야 한다. 현재 로컬 지식 관리 API의 권한 범위를 따르며 새 다중 사용자 인증·분리 승인 체계를 제공하지 않는다.

승인 재검사에서는 경로·정의·판정과 실제 점수 근거를 다시 비교한다. 명시 조건이 참/거짓/미확인으로 바뀌면 새 검토가 필요하다. 실제 물리 DB 조건 입력은 값과 출처도 비교한다. 센서 입력은 동일 판정을 유지하는 작은 변동만으로 모든 카드를 폐기하지 않으며 기존 예측 악화·준수·신선도 검사는 유지한다. 카드 상세에 사용한 입력값을 보존하지만 연속 센서값을 정의 지문에 포함하지 않는다.

## 실제 검증과 남은 범위

A070은 실제 그래프의 약한 조건/강한 조건 경로에서 기존 max(weight)와 head(conditions)가 서로 다른 경로를 섞는 반례를 보존했다(`.evidence/reaudit/a070-before.json`). 전체 973검사와 실제 PG·HTTP·Neo4j·MCP·승인 14항목이 통과했다(`a070-full-final.log`, `a070-live-first/`). 원자 경로의 가중치·원문 연결, TRUE/FALSE/UNKNOWN, 중복 없는 미확인 증가분, 조건 변경·충돌·재요청·잘못된 식/입력 거절, 원문 보존 및 별도 후보 예측 입력을 확인했다. 시험 원천·그래프 노드만 정리하고 변경 영수증을 남겼다. 새 Codex 추론이나 직접 UI 검수는 이 시험에 포함하지 않는다.

근거는 회의2 385~413행의 업무 데이터·설비 상태·상충 대안·사람 선택과 P03 process-gpt-strategy `1db85d3b0ab7acf50204360b8115e14fcb4ffb25`의 `app/graph/age_adapter.py`262~347행이다. 제품 코드는 관계 양 끝·종류·속성을 보존한다. 이 원칙을 HYD의 경로 근거에 반영했다. AGE의 속성 변경 시 삭제/재생성 구현은 Neo4j에 복제하지 않았다. 해당 코드는 BSC 조건 실행 엔진이 아니며, HYD의 조건식·정성 가중치·집계 정책은 별도 명시 계약이다. 참고 파일은 CRLF/LF 바이트 차이만 있고 HEAD와 행 내용이 일치한다(`a070-reference-read.json`).

기존 자연어 조건 전체의 전문가 의미 검토와 실제 AI 해석, 정량 인과 모델, 첫 Measure 이후 전략망 전파, 임의 업무 조건의 자동 생성은 완료하지 않았다. 미확인을 식으로 작성할 수 있다는 기능과 실제 원문의 업무 의미가 검증됐다는 주장을 구별한다.

동일 배포본 쿨러 회귀는 `a070-cooler/`의42/42다. 같은20배속·허용치의 legacy bridge에서 사람 승인→PLC ACK→재관측→CMMS `WO-1004-D6FD`→ev:closed와 Execution 투영을 확인했다. 18서비스/비정상0·시험 잔여0·worker0, 변경 소스 및 서빙 JS의 로컬 일치도 확인했다. 직접 화면 품질과 새 Codex 실행은 미검증이다.
