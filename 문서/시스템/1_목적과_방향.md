# 시스템 1. 목적과 방향

HYD 시스템은 경남대학교 피지컬AI 사관학교의 제조 AI 교육과정에서 강의와 실습에 쓰는 시스템이다. 유압 설비 세 대(HYD-01 · 02 · 03)의 값이 현장에서 올라와 저장되고, 이상이 감지되면 에이전트가 근거를 모아 조치를 추천하고, 사람이 승인하면 시스템이 실행하고 결과를 확인한다.

## 1. 무엇을 만드는가

- **만드는 대상은 ProcessGPT의 업무 기능이다.** 강의용으로 따로 줄인 장난감을 목표로 삼지 않는다. 설계 회의의 요구와 실제 참고 저장소의 코드를 근거로, 프로세스 인스턴스와 거기에 속한 에이전트 작업 · 사람 작업 · 시스템 작업을 HYD에 구현한다(2026-10-06 목표 정정).
- **그 개발 과정이 수강생의 학습 내용이다.** 수강생은 이 시스템을 보면서 온톨로지와 에이전트를 중심으로 배운다.
- **무게는 온톨로지와 에이전트에 있다.** 설계 회의에서 대표가 「온톨로지하고 에이전트 쪽 파트를 많이 하려는 것이지, 그 밑의 스카다 쪽을 많이 하고 싶지는 않다」고 했다. 과정의 비율은 온톨로지 40 : 에이전트 35 : 업무 흐름(BPMN) 25다.
- **구성은 미니멀하다.** 스키마는 「교육에 쓰는 시나리오에 맞춘 것만」 둔다. 수강생이 오픈소스 구성요소로 전체를 이해하는 것이 목적이고, 데이터 패브릭과 ProcessGPT 제품은 과정 끝에서 확장으로 소개한다. 다만 미니가 장난감을 뜻하지는 않는다.

## 2. 설계 회의가 요구한 것 (2026-10-01)

1. 온톨로지 스키마와, 문서에서 지식을 뽑아 넣는 적재(인제스천)
2. 그래프 DB(Neo4j)를 MCP로 열고, 스키마를 받아 질의를 만드는 에이전트
3. 업무 DB와 그것을 읽는 MCP
4. **계속 바뀌는 값은 그래프에 두지 않는다.** 그래프에는 기준 정보를 두고, 실황 값은 「어느 DB에 있다」는 연결만 둔다
5. 규칙에서 질의를 만든다
6. 범용 에이전트(코딩 에이전트)를 서버가 불러 일을 시킨다
7. 이벤트(경보)로 에이전트가 일을 시작한다
8. 설비 관점(멈춤)과 납기 관점(팬을 올리고 계속 운전)처럼 상충하는 대안을 놓고 판단한다
9. 사람이 확인하는 포털과 알림. 사람은 버튼만 누르고, 직접 제어는 현장이 한다
10. 프로세스 인스턴스가 중심이다
11. 처리 과정을 보는 화면
12. 세 시나리오
13. 후반 확장: 데이터 패브릭, ProcessGPT

## 3. 세 시나리오

| | 무엇 | 어떻게 시작하나 | 어디까지 가나 |
|---|---|---|---|
| A 긴급 대응 | HYD-01 쿨러 과열 | 센서 경보 | 설비에 명령이 나가고 효과를 확인한다 |
| B 정기 점검 | HYD-02 | 정비 시스템(CMMS)의 점검 도래 | 작업지시, 부품 예약, 생산팀 공지 |
| C 재고 보충 | HYD-03 씰 키트 | ERP의 재고 이탈 | 발주, 통지, 입고, 재고 반영 |

B와 C는 설비까지 가지 않는다. 세 시나리오의 흐름은 같다.

> 버튼 → 이벤트 → 처리 건 → 에이전트 추천 1개 → 담당자 알림 → 승인 또는 거절 → 시스템 처리 → 자동 확인 → 결과 보고

## 4. 구조

- 아홉 개의 기능 계층(L1 설비 ~ L9 업무 흐름)과 세 개의 보안 영역(OT, 완충 구역, IT)으로 되어 있다. 계층과 영역은 서로 다른 분류다.
- OT와 IT를 잇는 것은 완충 구역의 서비스뿐이다(올라가는 값의 수집, 내려가는 명령의 검사).
- **원래 설계는 `참조/설계서_v3_유압설비_IoT-SCADA_아키텍처.pdf`(2026-09-23)다.** 아홉 계층의 역할과 재료, 두 개의 축(기능 계층과 배치 영역), 토픽, 명령 경로와 안전, 시나리오의 순서가 여기 있다.
- 구조 · 경계 · 토픽 · 명령 검사 · PLC 모드는 이 설계서대로다. **제품 자리 가운데 일부는 같은 역할을 하는 작은 서비스가 대신한다**(이상 감지, 한 방향 수집 등). 제품으로 바꾸는 일은 방향만 정하고 보류했다(`5_결정_기록.md` 2절).
- 코드의 자리: `ot/`(설비 시뮬레이터, PLC), `dmz/`(수집, 명령 관문), `it/`(메시지 기록, 저장소, 감지, 지식 그래프, 에이전트, 프로세스 엔진, 포털, 업무 시스템 대역), `common/`(공용 토픽 · 스키마), `students/`(종합 랩 출발본, 세 시나리오의 참조 흐름).
- 구조를 한 장으로 본 것은 `참조/ARCHITECTURE.md`다.

## 5. 사람과 에이전트의 선

- 사람은 승인하거나 거절한다. 에이전트는 승인 없이 실행하지 않는다.
- 승인 전의 에이전트는 조회하고 계산하기만 한다.
- 설비로 가는 명령은 프로세스 엔진의 사건(Incident) 경로 하나로만 나간다.
- 처리 과정에 감춘 곳이 없다. 가져온 값과 출처, 그래프 경로, 도구 호출의 입력과 출력, 지는 안, 승인, 실행, 확인이 화면에서 일반인의 말로 읽힌다.
