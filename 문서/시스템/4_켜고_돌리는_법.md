# 시스템 4. 켜고 돌리는 법

macOS(colima)에서 실제로 쓴 절차다. Windows(Git Bash)의 전체 절차는 `참조/RUNBOOK.md`에 있다.
학생·학교 Windows PC의 진입점은 [README 설치 순서](../../README.md#학교-pc에-설치하고-켜기)다. 설치가 끝난 강의실 PC는 `git pull` → 루트 `.env`의 `LLM_API_KEY=` 뒤에 받은 강의 중계 키 한 줄 → `시작.bat` → `점검.bat`이고, 종료는 `끄기.bat`(AI 워커까지 끈다)이다. `.env.example`이 키 말고 모두 채운 강의 배포본이다(`참조/RUNBOOK.md` §0). 기존 프로그램은 버전과 관계없이 유지한다. 상세 화면·수동 설치는 [학교 PC 설치·실행 확인](../../산출물/설치/학교PC_설치확인/학교PC_설치확인.md), WSL·Docker 오류가 났을 때만 [오류 해결 가이드](참조/Windows_Docker_설치.md)를 사용한다.

## 1. 준비

### 강사 관리 서버의 승인 등록 (2026-10-27, 운영 전환 미완료)

강사 compose override에는 `HYD_CLASSROOM_UPSTREAM_KEY_FILE`과 별도로 `HYD_CLASSROOM_WORKER_KEY_FILE`(절대 경로)이 필요하다. 후자는 process/worker 사이의 실행 인증키 파일이며 학생 키·모델 upstream 키와 다르다. Git 밖 전용 디렉터리에 기존 `scripts/setup_mcp_oauth_keys.py --directory <디렉터리>`로 준비한 worker-runtime.key를 지정한다. 기존 운영 키를 교체하지 말고 전환할 강사 환경의 키를 사용한다. 두 서비스는 같은 파일을 `/run/secrets/classroom_worker_runtime`으로 읽는다. worker에는 process-data 볼륨·oauth.key·원문 보관 DB를 마운트하지 않는다. Docker 공식 [Compose secrets 문서](https://docs.docker.com/compose/how-tos/use-secrets/)의 서비스별 파일 공유 방식을 따른다. **컨테이너 내부 AI 자식 프로세스의 OS 권한 분리는 아직 미확인/미구현 범위이며 이 설정만으로 운영 활성화하지 않는다.**

강사 override의 `HYD_CLASSROOM_AGENT_ENABLED`는 기본0이다. 승인 판본·도구/예산 정책·HTTPS·학생 upstream 우회 차단을 준비한 뒤 강사 서버에서만1로 설정한다. 값은0/1만 허용한다. 학생 설정이나 요청으로 이 서버 플래그를 바꿀 수 없다. 현재 운영 활성화 증거는 아직 없다.

관리 워커 도구 catalog: `policy.tool_io.catalog`의 키는 tools와 같은 `서버/도구`이며 값은 `{description, inputSchema, annotations: {readOnlyHint: true}}`다. 현재 최대64도구/전체512000바이트이며 쓰기 도구는 거절한다. runner의 관리 정의는 승인된 catalog로만 MCP를 교체하므로 학생 상태 연결 실패 시 강사 상태로 대체되지 않는다. 제안 등록 전용 경로·학생 폴링은 구현·격리 시험을 마쳤으나 운영 승인·HTTPS·직접 중계 차단 검증 전에는 운영을 활성화하지 않는다.

관리 에이전트 명세(아직 기본 비활성): `policy.agents[수업참조명]`은 `{definition, version, activity, revision, input_schema}`다. definition/version/activity는 강사 서버에 이미 등록된 판본/AI 단계이며 revision은 `classroom_agents.revision(runtime, approval)`로 그 정의·에이전트·스킬 본문·입력 계약을 읽어 얻는다. 임의 문자열 해시를 승인해도 실행 시 대조에 실패한다. 입력 schema는 object/additionalProperties=false이고 해당 단계 inputData만 포함한다. 학생 요청은 참조명과 inputs만 전달하며 모델·프롬프트·새 request_id를 받지 않는다. runner/MCP·학생 폴링은 구현됐지만 운영 배포 검증 전이므로 운영 `agent_enabled`는 아직 끈 상태다. 종료 결과는 과거 검토용 제안이며 현재 상태의 새 판단으로 재사용하지 않는다.

학생 상태 전달 준비 코드: migration67은 관리 DB에만 적용한다. 강사 정책의 `tool_io`에는 `tools`(서버/도구 이름 목록), `max_calls`, `max_input_bytes`, `max_result_bytes`, `total_result_bytes`를 명시한다. 전송 상한은 호출256·인자12000바이트·결과128000바이트이며 정책은 더 낮출 수 있다. 공개 API는 본인 활성 실행의 요청 조회/응답만 받는다. 이 계약만 추가해 agent_run을 운영 허용하지 않는다. 실제 에이전트 판본 승인·서버 워커/학생 읽기 MCP 연결·upstream 차단은 별도 미완료다.

학생 작성 후보를 강사 서버에 반영하는 순서(구현·격리PG 검증 완료, 운영 미배포):

1. 학생 작업DB에서 `python -m procsvc.classroom_manifest export --manifest candidate.json --tenant <교육공간> --approval target.json`을 실행한다. target.json은 위 definition/version/activity/input_schema와 임시 revision을 포함한다. SUPABASE_DSN은 실행 환경에서만 읽는다. 출력 후보에는 실행 자료만 들어가며 키·DB 메타데이터·MCP 연결 설정은 제외한다. 기존 파일은 덮어쓰지 않는다.
2. `python -m procsvc.classroom_manifest review --manifest candidate.json`으로 DB 없이 정의·실제 담당·스킬 본문·입력 계약을 검토한다. 이어 강사 작업DB의 SUPABASE_DSN을 사용해 `review-target --manifest candidate.json --tenant <교육공간>`으로 기존/변경 내용과 공유 스킬 영향 에이전트를 확인한다. 후보 fingerprint와 target_fingerprint를 함께 보관한다.
3. 강사 서버에서 `apply --manifest candidate.json --tenant <교육공간> --fingerprint <검토한 후보 해시> --target-fingerprint <검토한 대상 해시>`로 반영한다. 해시가 달라지면 다시 검토한다. 같은 판본 덮어쓰기와 기본 자료 변경은 거절한다. 사용자 작성 자료는 수정할 수 있지만 진행 중 cliagents 작업이 있으면 변경을 거절한다. 짧은 적용 트랜잭션은 작성/작업 테이블 쓰기를 잠그고 잠금 대기는5초로 제한한다. 중간 실패는 전체 소스 변경을 롤백한다. 정의 등록은 배포 포인터를 바꾸지 않는다.
4. 적용 결과의 approval을 아래 정책 agents에 넣고 도구 catalog·응답 정책·모델·예산 전체를 검토해 기존 approve 명령으로 승인한다. agent_run 승인에는 강사 작업DB의 SUPABASE_DSN도 필요하다. 서버 저장 내용이 승인 revision과 다르면 승인하지 않는다. **apply는 소스 반영이며 permission_granted=false다.** 작업DB와 승인 장부가 별개이면 소스 적용 성공 후 정책 승인 실패가 가능하다. 이 경우 소스만 있고 실행 권한은 없는 상태이며, 재검토 후 승인 단계를 수행한다. 실패했다고 누적 비용 장부를 초기화하지 않는다.

학생에게는 관리 DB 접속 정보나 upstream 모델 키를 배포하지 않는다. 다음 CLI는 강사 서버의 기존 `manuals.sqlite3`와 migration65가 적용된 관리 PostgreSQL에 직접 접근하는 관리자용이다. 공개 HTTP에는 승인 편집/키 발급 경로가 없다. **현재 agent_run 운영 연결·HTTPS 배포·기존 중계 키 차단이 미완료이므로 이 CLI 작성만으로 학생 비용 통제가 완성된 것은 아니다.**

1. 강사 서버에 원문을 보관하고 검토한 `source_id`·SHA-256을 승인 명세에 적는다. 명세의 최상위는 `subject`(관리 실행기 TENANT_ID와 동일), `scope`(승인 범위 판본), `expires_at`(시간대 포함 ISO 시각), `policy` 네 필드다. 원문이 READY가 아니거나 해시가 다르면 등록을 거절한다.
2. `policy`에는 `profile: {model, revision}`, `documents: {"<sha256>": {"source_id": "<보관 원문 ID>"}}`, `max_concurrency`, `total_calls`, `total_input_bytes`, `total_output_tokens`, `actions`를 넣는다. `actions.manual_extract`에는 `max_seconds`, `max_calls`, `max_input_bytes`, `max_output_tokens` 양의 정수를 명시한다. 자동 무제한 기본값은 없다. 교정 호출도 호출/입출력 예산을 쓴다. 모델은 실제 중계에서 Luna로 연결된 별칭을 확인해 사용한다. `agent_run`은 실제 서버 실행 경로를 연결·검증하기 전 허용 완료로 표시하지 않는다.
3. 강사 서버 환경의 `HYD_CLASSROOM_AUTHORITY_DSN`과 `PROCESS_STATE_PATH`를 설정하고 process Python 환경에서 실행한다. 예: `python -m procsvc.classroom_admin approve --key-file /run/secrets/student-class-key --manifest /run/instructor/class-policy.json`. 키는 파일에서 읽고 값은 출력하지 않으며 DB에는 해시만 저장한다. 명세에 키를 넣지 않는다. 출력은 교육 공간/범위·문서 수·누적량뿐이다.
4. 회수는 `python -m procsvc.classroom_admin revoke --key-file /run/secrets/student-class-key`. 같은 키의 정책을 갱신하거나 다시 활성화해도 누적 사용량은 초기화하지 않는다. 다른 교육 공간으로 기존 키를 이동하지 않는다. 정책 변경은 진행 중 실행의 기존 허가를 무효화한다.

학생 배포본의 관리 서버 주소는 강사가 미리 설정하며 학생이 입력할 값은 기존 `LLM_API_KEY` 한 줄이다. `시작.bat`은 `HYD_CLASSROOM_URL`이 있으면 `/v1/classroom/session`으로 권한만 확인한다. 이 확인은 AI 호출이나 추출 작업 예약을 만들지 않는다. 실제 BAT 완주·배포 증거는 `3_현황.md`에서 별도로 확인한다.

- 파이썬: 저장소 루트의 `.venv`(3.12). 다시 만들 때:
  `uv venv --python 3.12 .venv && uv pip sync --python .venv/bin/python scripts/live/venv-py312-freeze.txt`
  `requirements-dev.txt`만 깔면 `fastmcp`가 없어 시험 두 건이 실패한다.
- 도커: colima 프로필 `hyd`(이 프로젝트 전용). 켤 때 먼저 `colima start hyd`.
- `.env`의 값은 열지 않는다. 키의 이름만 본다.

## 2. 켜기

```bash
bash scripts/start_all.sh        # 강의실과 같은 한 번에 켜기(업무 DB 업데이트 · AI 워커 · 수업 흐름 · 중계 키 확인)
```

손으로 켤 때:

```bash
cd it/supabase && supabase start && supabase migration up --local && cd ../..
docker compose -p hyd-iot-edu up -d
```

- `.env`의 `COMPOSE_PROFILES`(예시 파일 값)에 `cliagents`가 들어 있어 AI 워커 컨테이너까지 뜬다. 셸에 `COMPOSE_PROFILES`가 있으면 그것이 이기므로 비운다.
- zsh는 변수에 든 서비스 목록을 나누지 않는다. 서비스 이름은 직접 적는다.
- 업무 시스템 대역을 다시 띄울 때는 `ENTERPRISE_BACKEND=supabase`를 명시한다. 빼면 메모리 저장으로 떠서 업무 값이 사라진다.

켠 뒤 확인:

```bash
docker inspect hyd-iot-edu-process-1 --format '{{.State.StartedAt}} {{.RestartCount}}'
curl -s localhost:8080/api/scenario/status
```

포털은 `http://localhost:8088`이다.

## 4. 워커

강의 배포본의 워커는 컨테이너 `agent-worker`다(위 켜기에 포함, 모델 호출은 `.env`의 키로 강의 중계). 개발용으로 이 PC의 Claude Code 구독 로그인을 쓸 때만 컨테이너 워커를 멈추고(`docker compose stop agent-worker`) 호스트 워커를 켠다:

```bash
bash scripts/run_worker_host.sh
```

- **하나만 돌린다.** 멈출 때는 `pkill -f worker.main` 뒤 포트를 확인한다(`lsof -iTCP:8097 -sTCP:LISTEN`).
- 실패한 에이전트 작업은 취소가 아니라 포털의 「단계 닫기」(`POST /api/todolist/{wid}/close`)로 끝낸다.
- 긴 실행 전에는 `caffeinate -dimsu -t 28800 &`으로 잠들지 않게 한다.

## 5. 쓰기 전에: 잠금

스택은 하나뿐이다. 쓰는 일을 하기 전에 `.evidence/LIVE_LOCK`을 본다. 있으면 기다린다. 없으면 「누가, 시각, 하는 일, 예상 끝」 한 줄을 쓰고 시작하고, 원래대로 되돌린 뒤 지운다.

- 잠금이 필요한 일: 빌드와 재시작, 워커, 버튼 누르기, 회귀 시험, 지식 추출과 적재, 흐름 배포, 그래프 볼륨 바꾸기.
- 잠금 없이 되는 일: 조회, 코드, 단위 시험, 문서.

## 6. 세 시나리오를 끝까지 돌리기

1. 그래프를 구조판으로 바꾼다:
   `docker compose -p hyd-iot-edu -f compose.yaml -f scripts/live/neo4j-c3.override.yaml up -d --no-deps neo4j`
2. 흐름: 시작 스크립트가 `c3_flows.py ensure`로 이미 배포한다(손으로는 `.venv/bin/python scripts/c3_flows.py deploy`).
3. 워커: 컨테이너 워커가 이미 떠 있다(`curl -s localhost:8097/healthz`).
4. 한 번에 한 건씩 한다. A가 끝나면 [쿨러 복구]를 누르고, 그다음 B, C.
5. 되돌리기: `c3_flows.py deploy-reset <이름>` → 워커 멈춤 → 그래프를 원래 볼륨으로(override 없이 `up -d --no-deps neo4j`) → 설비 `POST localhost:8000/api/reset` → B와 C의 [초기화] → 진행 중인 처리 건이 0인지 확인 → 잠금을 지운다.

- 거절이나 무응답으로 끝난 A는 경보가 올라간 채다. [쿨러 복구] 뒤 감지가 경보를 내릴 때까지 65초쯤은 다음 주입이 새 처리 건을 열지 않는다. 결함이 아니다.
- 그래프의 두 판: `neo4j-data`가 전체판, 이름 끝에 `-c3`이 붙은 것이 구조판이다. 지금 어느 것인지는
  `docker inspect hyd-iot-edu-neo4j-1 --format '{{range .Mounts}}{{.Name}} {{end}}'`로 본다.

## 7. 시험

- 단위 시험: `.venv/bin/python -m pytest`
- 쿨러 회귀: `scripts/scenario_instance_test.py --worker`
- 펌프 · 팬 회귀: `scripts/scenario_pump_fan_test.py --worker --reassess-held`(흐름은 기준, 그래프는 전체판, 설비는 초기화, 워커 하나인 상태에서)
- 화면 검사: `scripts/ui_capture_all_tabs.py`. 콘솔 오류 0과 가로 넘침 0은 전제일 뿐이고, 완료는 사람이 캡처를 보고 판정한다.
- 화면만 볼 때는 포털 컨테이너를 건드리지 않고 `python -m http.server <포트> --bind 127.0.0.1 -d it/portal/www`로 띄워 본다.

```bash
docker compose -p hyd-iot-edu stop
cd it/supabase && supabase stop
colima stop hyd
```
