승인 전 업무 에이전트의 Python 셸 허용은 읽기 전용 MCP를 우회하므로 기본 실행에서 차단한다. 파일은 기본 Read/Write, 업무 조회·계산은 등록 도구로 처리한다. 권한 거절을 출력 형식 교정으로 되풀이하지 않으며, 중단 전 세션을 소유권 검사와 함께 보관한다. 컨테이너 CLI 판은 고정해 같은 시험 조건을 재현한다.

Neo4j MCP 0.4.1의 표시 없는 목록 삭제/JSON 절단을 그대로 사용하지 않는다. 같은 도구 계약을 교육 환경에 맞게 구현해 작은 결과는 보존하고 큰 결과에는 제한·잘림·재조회 안내를 붙인다. EXPLAIN의 실제 읽기/쓰기 판정 뒤 실행하며 쓰기 도구는 노출하지 않는다. 문서 사이 참조는 정확한 소유 기록이 있을 때만 보존하고, 참조 대상 삭제와 기록 밖 변경은 계속 거절한다. 수치 대조는 원문 불일치를 드러내는 검토 보조이며 단위 환산·의미까지 자동 보증하지 않는다.

문서 개정에서 지워지는 지식을 적용 전에 보여주고 영수증에도 남긴다. 여러 독립 추출 오류는 한 번에 알려주며, 구간 추출을 합친 뒤 빠지는 검사도 수행한다. 원문의 느슨한 인용 일치를 정확 일치와 구별한다.

질의가 실행됐다는 사실과 답이 맞다는 주장을 구별한다. 질문 화면은 실제 반환값과 모델 요약을 함께 보여주고 수치·ID의 누락을 표시한다. 단위 환산·계산·의미 해석까지 자동 검증했다는 배지는 붙이지 않는다. 문서별 골든 퀘스천에서 입력으로 받은 노드 ID만 인용하는 것은 근거로 인정하지 않으며 실제 조회와 반환 원문을 확인한다. 큰 도구 입력은 원문 보관소에 한 번 저장하고 화면·이벤트에는 작은 미리보기와 참조를 쓴다. 보관 실패는 숨기지 않는다.

## 2. 보류한 것: 현장 계층의 제품 교체

2026-10-08 저녁에 사용자가 「강의 재료가 되려면 굵직한 것을 가져와야 한다」며 다시 열었다가 「보류, 원래 목표까지만」으로 닫았다. 다시 열 때의 출발점만 남긴다.

- 방향: 원래 설계서가 계약이고, 설계서대로 제품을 쓴 다른 프로젝트가 구현의 참고다.
- 바꿀 자리: 한 방향 수집은 Kafka Connect, 이상 감지는 Flink SQL, PLC는 OpenPLC, 현장 수집은 EdgeX, 알림은 Alertmanager, 구역 사이는 라우터로 세 망을 나눈다. 메시지 중개(EMQX), 메시지 기록(Redpanda), 명령 관문은 그대로 둔다.
- 바뀌지 않는 것: 토픽 일곱 개의 이름, 메시지의 모양, 승인 → 관문 → PLC 응답의 흐름.
- 드는 것: 4~5일과 전체 회귀. 메모리가 3.5GB쯤 는다(학생 PC는 16GB).
- 다시 열 때 먼저 볼 것: 메시지 기록과 중개가 인증 없이 열려 있을 때, 사무실 망의 공격자가 명령 토픽에 직접 쓸 수 있는지. 명령 관문이 명령의 출처(승인 기록)를 대조하는지는 확인하지 못했다.

## 4. 여러 번 바뀐 것

- **워커가 쓰는 도구와 모델.** Claude Code → Codex를 함께 → Claude Code(Opus)만 → 2026-10-12에는 Codex와 Sol 6.1만. 마지막 지시는 그때 시스템을 개발하던 세션에 준 것이다. 스크립트의 기본값(`scripts/run_worker_host.sh`)은 Claude Code다. 수업에서 무엇으로 돌릴지는 정해지지 않았다(`6_남은_일.md`).
