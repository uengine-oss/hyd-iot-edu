## 2. 보류한 것: 현장 계층의 제품 교체

2026-10-08 저녁에 사용자가 「강의 재료가 되려면 굵직한 것을 가져와야 한다」며 다시 열었다가 「보류, 원래 목표까지만」으로 닫았다. 다시 열 때의 출발점만 남긴다.

- 방향: 원래 설계서가 계약이고, 설계서대로 제품을 쓴 다른 프로젝트가 구현의 참고다.
- 바꿀 자리: 한 방향 수집은 Kafka Connect, 이상 감지는 Flink SQL, PLC는 OpenPLC, 현장 수집은 EdgeX, 알림은 Alertmanager, 구역 사이는 라우터로 세 망을 나눈다. 메시지 중개(EMQX), 메시지 기록(Redpanda), 명령 관문은 그대로 둔다.
- 바뀌지 않는 것: 토픽 일곱 개의 이름, 메시지의 모양, 승인 → 관문 → PLC 응답의 흐름.
- 드는 것: 4~5일과 전체 회귀. 메모리가 3.5GB쯤 는다(학생 PC는 16GB).
- 다시 열 때 먼저 볼 것: 메시지 기록과 중개가 인증 없이 열려 있을 때, 사무실 망의 공격자가 명령 토픽에 직접 쓸 수 있는지. 명령 관문이 명령의 출처(승인 기록)를 대조하는지는 확인하지 못했다.

## 3. 다시 꺼내지 말 것

| 무엇 | 왜 버렸나 |
|---|---|
| 포털 안에 흐름 그리는 도구 만들기 | 2~3일이 들고 깨질 곳이 많다. bpmn.io로 충분하다 |
| 사람의 선택이 쌓여 다음 추천을 바꾸는 순환 | 단발성 교육이다 |
| 포털에서 온톨로지 스키마 설계하기, 문서 저장 · 검색, 파일 첨부 | 스키마는 고정하고 내용만 채운다 |
| 정의의 임시 판본 | 판본은 바꾸지 않고 새 판본이 변경이다 |
| LLM 없이 도는 대비 경로를 수업 기본으로 삼기 | 학생의 AI는 키로 준다. 예외는 온라인 학생의 포털 실습뿐이다: 2026-10-22 요청으로 키 없는 재생 모드가 기본이다(위 1절). 재생은 대비 경로가 아니라 녹화한 실제 실행을 다시 보여 주는 것이고, 실제 AI 실행은 선택으로 남는다 |
| 예약 대기, 시운전, 입고 대기, 미달, 납기 초과, 원인 입력 버튼 | B와 C는 처리되면 끝난다 |
| 시나리오 넷을 돌아가며 파는 구성, 작동유 열화 시나리오, 옛 75시간 25회차 | 실라버스 최종본이 대신한다 |
| 데이터 패브릭의 본격 구현 | 「데이터 연결」 화면으로 읽기 전용 미니만 두고, 과정 끝에서 설명한다 |
| 설비에 자동으로 역명령 보내기 | 설비는 어떤 경우에도 자동으로 되돌리지 않는다 |
| 포털 로그인과 회원가입 | 넣지 않는다 |
