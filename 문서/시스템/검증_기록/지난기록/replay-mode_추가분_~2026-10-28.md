## 옛 3_현황 추가분

**2026-10-23 AI 응답 재생(브랜치 `replay-mode`):** API 키가 없는 PC에서도 AI가 응답할 단계에 미리 저장한 응답을 넣어 실습이 끝까지 가게 했다(`it/agent-worker/worker/ai_replay.py`, 워커 `AI_MODE`). 키가 있으면 실제 AI, 없으면 재생이다. 포털 · 설비 · 처리 흐름은 그대로 실제로 돈다. 규칙은 「같은 업무(경보 종류 또는 문서 + 업무 이름)면 저장된 응답」 하나다. 데이터를 쓰는 도구(판단 등록)는 학생 PC에서 다시 실행한다.
- 처음에 만든 포털 전체 재생은 사용자 판정(과한 수정, 목표는 AI 응답만)으로 지웠다. 포털 `index.html`은 develop과 같다.
- 검증(실제 AI): Claude Code + 강의 중계로 쿨러 · 펌프 · 팬 고장과 HM-8 추출을 저장했다. 키 · CLI · 바깥 인터넷 없이 재생했고 결과는 아래와 같다.
  - 쿨러 40/40, 다른 경보 세기 40/40, 펌프 15/15, 팬 14/14, 다른 설비에 재생(가림) 16/16
  - HM-8 추출은 저장할 때와 같은 결과(중계 모델이 세 번 다 원문 검증에서 거부됨). 다른 문서는 「저장분 없음」으로 실패
  - 사람 질문 → 답 → 이어 하기도 실제 스택에서 확인했다. 단위 시험 28건, 기존 워커 시험은 기준과 같은 포털 UI 3건만 실패
  - 질문 답변 실습(05-1): 실제 AI · 재생 모두 답함, 근거 9개 모두 서버 대조 통과. 흐름 B · C는 이번 스택에 수업 지식이 없어 실제 AI가 보류했고 재생도 같게 보류. 포털 화면에 재생 알림이 보인다(문구 순서를 화면에 맞게 고침). Codex 경로의 쓰기 도구 다시 부르기를 넣었다

  - 리허설 C에서 찾은 재생 결함: 큰 쓰기 도구 결과(51 KB)를 Claude Code가 파일로 빼서 새 판단 id를 짝짓지 못하고 저장 때 판단을 넣었다 → 원래 결과를 저장하고 짝을 못 지으면 실패시킨다. 단위 시험 31건.
  - 리허설에서 본 문서 적재 결함 6건(재생과 무관 — 빈 값 충돌, 구매 칸 없는 지시, 사라지는 규칙, 후보 규칙 미추출, `--reuse` 새 판본)은 `6_남은_일.md`. 후보 규칙은 검토에서 원문 근거로 더했다(`참조/재생모드.md` 5.4).

- 미확인: 가져온 흐름(09-4) · 학생 에이전트(11-x), 학생 PC가 수업 상태가 아닐 때, 학생 PC에서 워커를 켜는 방법. 학생에게 줄 저장분(`it/agent-worker/replay/`)은 저장소에 아직 없다(리허설 저장분은 `.evidence/ai-replay/class/lib`, 시험용).

| # | 무엇 | 근거 · 비고 |

| 1 | 추출 지시는 「확인할 수 없는 link 값은 비워 두라」고 하는데, AI가 빈 글(`''`)을 넣으면 검사가 잘못된 id로 거부한다(`fm:… 형식의 온톨로지 id가 필요합니다 ('')`). PM-02 · PR-07 재추출이 이 때문에 세 번 다 거부됐다 | `procsvc/manual_extraction.py` 지시문, `manual_knowledge.py` `_link`(`fm is not None`). 지시를 「키를 빼거나 null」로 하거나 검사가 빈 글을 없음으로 보게 한다 |
| 2 | 추출 지시의 link 꼴에 구매 절차 칸(scope · parts · executable · supplier_policy)이 없다. AI가 구매 절차를 고장 조치처럼 채워 거부된다 | 같은 지시문 link 줄. 검토 의견으로 꼴을 알려 줘서 통과했다 |
