### 가장 큰 빈틈 다섯 가지

1. **바이브코딩 랩 자료가 하나도 없다(2~7일차 20행).** 소형 냉각장치 샘플 · 스키마 설명 · CSV · 짧은 매뉴얼 · 추출 후보 · 연습용 DB · 결정표 입력 3종 · 회의 메모 2개 · 랩용 Neo4j MCP 설정 · 랩용 판단 MCP · 효과 · 비용 비교 결과가 저장소에 없다. `students/`에는 캡스톤 키트(`_template/`)만 있다. 근거: `냉각장치` · `회의 메모` · `*.csv` · `.mcp.json` · `*lab*` 검색 결과 0건(`.claude` · `.evidence` 제외).
2. **10일차 정기 정비 · 예비품 구매 흐름이 실라버스와 다르다.** 실라버스는 예약 시각 대기 → 정비 → 시운전(정상/미달) → 주기 갱신, 발주 → 공급사 메일 → 입고 대기 → 정상 입고/납기 초과를 요구한다. 확정 배포 흐름은 B = 승인 → 오더 등록 · 공지 → 보고, C = 승인 → 발주 · 메일 → **즉시** 입고 → 보고다(`scripts/c3_flows.py:8-10, 113-142`, `tests/test_c3_bc_simplified.py:35`). 부품과 단위 시험은 남아 있다(`service_parts.py:178-340`, `tests/test_c2_execution.py:176-293, 295-410`). DECISIONS 112(10-09)와 최신 실라버스(10-10)가 충돌한다 — 4절 결정 1.
3. **설비 결함 인지 · 조치(A)에 승인 거절 경로가 없다.** 조치 카드 선택 부품(`task:select`)은 고르기만 하고 거절 값을 내지 않는다(`anomaly_response_v22.json` task:select 출력 = `chosen_skill`, `chosen_skill_kind`; `verification/2026-10-10/cap-g1g7.md` 9절 "select_card 는 반려를 내지 않아"). 반려가 있는 일반 승인 부품(`human:approve`)은 설비 명령(`task:command`, 입력 `chosen_skill`)과 이어지지 않는다. 실라버스 92 · 102 · 104행은 거절 경로와 거절 실행을 요구한다.
4. **비정상 결과를 학생이 만들 입력 수단이 없다.** A 조치 미달: 열화 세기가 `moderate`로 고정(`scenario_buttons.py:45`). 시운전 미달: 정비 부품이 설비를 복구한 뒤 읽으므로 미달을 만드는 입력이 없다. 납기 초과: 지연 버튼을 지웠고(`verification/2026-10-09/c3-assembly.md:173`) enterprise-sim 거래 `skill:delay-delivery`만 남았다(`entsim/state.py:46, 308`). 세 가지 모두 단위 시험만 있고 라이브 실행 기록이 없다.
5. **수업용 준비물이 흩어져 있다.** bpmn.io에서 열리는 A · B · C 참조 `.bpmn`이 없다(`c3_flows.py`의 XML에는 그림 좌표 `bpmndi`가 0개). Notion MCP 연결 설정이 없다. 수업 시작 상태(구조판 + 문서 적재 + 흐름 배포 + 워커)를 만드는 절차가 `docs/RUNBOOK.md`에 없다(`c3_flows` 언급 0건, 절차는 `NOW.md` 2절 "버튼 완주 순서"에만 있음).

1. **정기 정비 · 예비품 구매를 실라버스 모양으로 되돌리는가.** DECISIONS 112(10-09, 감독 지시 "설비까지 가지 않는다, 처리되면 끝")와 최신 실라버스 109~114행 · 인계 ZIP `01_최신_확정_계약.md` 4절("예약 대기, 시운전 정상/미달", "입고 확인/납기 지연")이 충돌한다. 이 문서는 "실라버스가 이긴다"는 지시대로 묶음 2에 넣었다. 되돌리면 정비 부품이 설비 시뮬레이터를 복구하므로 "B는 설비까지 가지 않는다"도 함께 바뀐다. 이름도 정한다: 실라버스 「정기 정비 · 예비품 구매」 / `NOW.md` 0.1 「정기 점검 · 재고 보충」(버튼 이름).
2. **연습용 그래프와 연습용 DB를 어디에 두는가.** 실라버스는 "수업 스택에 포함된 Neo4j Browser"(22행)와 "연습용 Neo4j 그래프"(36행), 오프라인은 "준비된 랩 전용 Neo4j"(오프 17행), "연습용 DB"(46행)라고만 쓴다. 같은 Neo4j에 이름 공간으로 둘지(캡스톤 방식, `students/_template/schema.json`), 따로 띄울지, 연습용 DB가 SQLite 파일인지 Supabase 표인지 정해지지 않았다.
3. **랩 출발본을 어디까지 주는가.** 실라버스 34 · 58행은 "Claude Code로 만든다"이고, 조사 지시에는 "결정표 평가 함수 출발본"이 있다. 빈 폴더 + 자료만 줄지, 뼈대 코드까지 줄지, 정답 예는 강사용으로만 둘지.

### 실라버스 문구가 불분명한 곳

1. **"기존 처리 기록"(109 · 112 · 53~56행 등)이 어디서 오는가.** 강사가 미리 한 건 돌려 둔 기록인지, 스택에 미리 넣어 둔 기록인지 쓰여 있지 않다. 처리 건을 내보내고 가져오는 기능은 찾지 못했다(`config_bundle.py`는 구성만 다룬다).
2. **110 · 113행의 "준비된 업무 서비스"가 지금 부품 이름과 1:1인지.** 실라버스는 정비 오더 · 공지 / 예약 대기 / 정비 / 시운전을 따로 적지만 지금 부품은 오더 + 공지가 한 부품(`task:work-order` + mail), 대기 + 정비가 한 부품(`svc:maintenance` `until`)이다. 따로 그린 Task를 `svc:wait` + `svc:maintenance`로 나눠 매핑해도 되는지는 돌려 보지 않았다.
3. **113행 "ERP 발주 → 공급사 메일"을 두 Task로 그리면** 메일만 보내는 부품이 필요하다. 지금은 `svc:erp-po`의 `mail` 설정으로 한 Task다. `svc:mcp-call`로 메일을 보낼 수 있는지는 확인하지 못했다.
4. **104행 "조치 미달"을 어떤 입력으로 만드는가.** 실전반 72행은 "준비된 입력"이라고만 한다.
5. **21행 "포털의 클래스 구성"이 어느 화면인지.** 데이터 연결의 '클래스 ↔ 표 · 열'로 판정했다. 지식 지도의 층 표시를 뜻할 수도 있다.
6. **12행 학생 PC에서도 A 시연을 돌리는가.** 강사 시연만이면 수업 시작 상태 절차는 강사용 한 장이면 된다.
