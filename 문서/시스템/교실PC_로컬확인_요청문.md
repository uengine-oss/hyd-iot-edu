# 메인 PC를 교실 PC로 보고 하는 로컬 확인 — 준비와 요청문

클라우드 Linux에서 최종 판본(main `76472b44` 이후)으로 빈 설치부터 포털 수업 01~13·90을 한 번에 통과했다(`6_남은_일.md` 맨 앞). 남은 것은 실제 Windows에서 같은 판본으로 갱신·시작하고, 실제 강사 코드로 교대를 여는 확인이다.

## 사용자가 미리 준비할 것

1. Docker Desktop이 켜져 있고, 다른 무거운 작업(교재 촬영 세션 등)이 Docker를 쓰지 않는 시간을 잡는다. 약 2시간.
2. 강사 해제 코드 파일의 위치를 안다(이전 세션이 채팅 outputs에 따로 보관한 파일). 세션에는 경로만 알려 주고 내용은 붙여 넣지 않는다.
3. 루트 `.env`에 수업 키(`LLM_API_KEY`)가 들어 있다. 키는 다시 묻지 않는다.
4. 로컬 Claude 세션을 메인 PC의 이 저장소 폴더에서 열고 아래 요청문을 붙여 넣는다.

## 요청문 (그대로 붙여 넣기)

```text
의도(Why & Value)
수업 당일 학생이 막힘없이 쓰도록, 메인 PC를 교실 PC로 보고 이번 판본의 갱신·시작부터 마지막 날 교대 해제까지 실제 Windows에서 끝까지 확인한다.

작업요령과 컨텍스트
CLAUDE.md 맨 앞 원칙과 문서/시스템/6_남은_일.md 맨 앞(클라우드 결과·다음 행동·재실행 금지), 4_켜고_돌리는_법.md 「현재 배포」를 먼저 읽는다.
클라우드에서 끝낸 결함 수정·연속 확인을 다시 조사하지 않고, Windows에서만 확인되는 것만 한다.
1) 기존 설치 폴더를 교실 PC 갱신 경로대로 git pull → 시작.bat 한다(워커가 Node 24.22.1로 다시 빌드된다). 기존 데이터·.env·포트 기록은 보존한다.
2) 운영 데이터를 더럽히지 않도록 연속 확인은 새 폴더(clone)에서 한다. 시작 스크립트가 폴더별로 이름을 분리한다. Docker 메모리 때문에 기존 HYD 컨테이너는 데이터 삭제 없이 잠시 멈추고 끝나면 같은 이미지로 되살린다.
3) 새 폴더에서 scripts/class_round.py --only 01,02,03,04,05,05c,06,07,08,09,10,11,12,13,90 --ai-runs 1 --unlock-code-file <사용자가 알려 준 강사 코드 경로> 를 한 번 돌린다. 시험용 키 이미지는 쓰지 않는다.
유료 상한: 모델 요청 100회·2시간. 실패하면 같은 조건으로 다시 돌리지 말고 원본 응답·처리 건·장부를 보존한 채 원인을 고치고 그 실습만 다시 확인한다.
강사 코드·키는 출력·로그·커밋하지 않는다. 검사가 도는 동안 compose build/up/restart 하지 않는다. 교재·실라버스는 건드리지 않는다.
끝나면 새 폴더 스택을 멈추고(볼륨 보존), 기존 HYD를 되살려 기본 잠금(guided)·LIVE_LOCK 없음을 확인하고, 결과를 3_현황·6_남은_일에 적어 main·replay-mode·other-pc에 반영한다(rebase·강제 push 금지).

인수조건(DoD)
1. 기존 폴더에서 git pull 뒤 시작.bat 1~8단계가 종료코드 0이고, 워커 node가 v24.22.1이며, 기존 .env·포트 기록·데이터가 그대로다.
2. 새 폴더 시작.bat 1~8단계가 종료코드 0이고 기존 설치와 Compose·업무 DB 이름이 분리된다.
3. 연속 확인 판정이 모두 통과다(「측정 안 함」은 통과로 세지 않고 따로 적는다). 실패가 남으면 원인·수정·해당 실습 재확인 결과가 있다.
4. 실제 강사 코드로 13의 해제가 열리고, 잘못된 코드는 한국어로 거절되며, 교대 처리 건이 인수 확인으로 끝나고 설비·발주·정비 실행이 없다.
5. 확인 뒤 기존 HYD가 모두 healthy이고 기본 잠금 상태이며, 새 폴더의 해제 기록이 기존 설치에 남지 않는다.
6. 모델 요청 수와 실제 확인/미확인 구분이 기록에 있고, 출력 예약 토큰을 실제 사용량으로 적지 않는다.
```
