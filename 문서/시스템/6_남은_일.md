# 시스템 6. 남은 일

## 다음 세션 인계 — 수업 준비 마무리 (2026-10-25, 사용자 지시 원문 요약)

**목표(사용자 /goal)**: ① 학생이 할 수 있는 모든 행위(포털 버튼 · 학생 BPMN · 에이전트 · MCP 등)에 결함이 없는지 — 이미 확인한 것은 다시 하지 않고 — 점검하고 고친다. ② `.env.example`을 다 채워 **`LLM_API_KEY` 한 줄만** 넣으면 되게 한다(빈 포트 자동 배정 `scripts/prepare_ports.py`는 그대로). ③ 강의실에서 **`git pull` → 시작.bat** 만으로 세팅이 끝나게 bat · 스크립트를 고친다. ④ main에 push.

**사용자가 정한 것**
- 브랜치는 main 하나로 한다. replay-mode(키 없는 온라인 재생)는 손대지 않는다 — 필요 없어졌는지는 사용자가 정한다. main에 재생 코드를 넣지 않는다.
- 강의실 학생 PC는 이미 clone · 설치가 끝나 있고 VS Code에 Copilot · Codex 확장이 있다. 쓰는 AI는 Codex의 **gpt-6-luna** 하나다(Claude는 이 개발 세션의 도구일 뿐, 강의실과 무관). 나눠 주는 것은 강의 중계(LiteLLM) 키뿐이다. 중계 `/v1/models`는 모델 이름 `coding` 하나(2026-10-23 실측) — 그 뒤가 luna인지는 중계 설정이다.
- 일하는 방식: 효율 우선, 이미 한 확인 · 질문을 되풀이하지 않는다. 결정이 필요한 것만 짧게 묻는다. 안내는 한국어로 짧게, 결론 먼저.

**사실(이 세션에서 확인)**
- 시작.bat(`scripts/start_all.sh`)은 ① 업무 DB 마이그레이션을 적용하지 않는다(`supabase start`는 기존 DB에 새 마이그레이션 059~062를 적용하지 않음 → enterprise-sim이 멈추고 「응답하지 않는 포트 8095」) ② `AGENT_BRIDGE`를 바꾸지 않는다(`.env.example` 기본 `legacy`) ③ 워커를 켜지 않는다 ④ 수업 흐름(`c3_flows.py deploy`)을 배포하지 않는다.
- `AGENT_BRIDGE=legacy`의 내장 판단은 기준 흐름의 판단 4단계만 채운다. 수업 흐름 A · B · C의 「판단 · 제안」(T_agent)은 워커만 처리한다 — 워커가 없으면 그 단계에서 멈춘다(2026-10-25 실측, A).
- 설치.bat(`scripts/install_windows.ps1`)은 Docker · VS Code · Node · Git · Python 3.14.7 · WSL만 설치한다. 워커용 파이썬 환경(`.venv314` + `requirements-dev.txt`)과 Codex CLI는 설치하지 않는다. Windows 워커 실행기 `scripts/run_worker_host.ps1`의 기본 CLI는 codex(구독 로그인 전제). Codex를 중계에 붙이는 설정은 `CODEX_MODEL_PROVIDER_BASE_URL` · `CODEX_MODEL_PROVIDER_API_KEY` · `CODEX_MODEL`(`it/agent-worker/worker/settings.py` 78~83행) — 워커가 확장에 든 `codex.exe`를 찾게 하는 일은 아직 없다.
- 중계 주소를 `.env.example`에 넣는 것은 `2_기준.md` 6절(「중계 주소와 키는 저장소에 적지 않는다」)과 다르다. 사용자 최신 지시(키만 넣게)에 따라 주소는 넣고 키는 넣지 않는다 — 바꾸면 2_기준 · 5_결정_기록에 적는다.

**이미 확인한 것(되풀이 금지)**: 실제 AI로 A 승인(수업 흐름) · C 거절 · 질문 답변 · 워커 회귀 40/40 · 학생 쿨러 흐름 가져오기→배포→완주 · 관리 탭 되돌리기(수업 흐름 남김) · B · C 초기화, 앞서 B 승인 · 거절 · C 승인 · A 거절. 결정론 회귀 쿨러 40/40 · 펌프 · 팬 49/49(다시 평가 포함). 단위 시험 3065. 2026-10-25 학생 행위 점검(`.evidence/student-sweep-1025/gaps.json`, 26건 중 실패 2건은 시험 쪽 칸 읽기 오류): 학생 MCP 서버(`students/_template/mcp_table_reader` + `table.sql`) 등록 · 연결 검사 · 도구 목록 · 써 보기 · 잘못된 이름 · 중복 거절, 에이전트 만들기 · 빈 폼 거절 · 기본 에이전트 복제, 깨진 .bpmn 거절, 빈 출발 그림(`students/_template/flow.bpmn`) 가져오기 · 사전 검사 사유 12건 · 검사 실패 등록 거절, 학생 B · C 사본(`students/flows/pm-planning` · `spare-purchase`) 가져오기 · 검사 · 등록 · 배포 · 내 에이전트 배정 · 경보 → 흐름 표.

**남은 일(순서대로)**
1. 결함 고치기 — 학생이 수업 흐름 id(`c3_pm` 등)로 흐름을 가져오면 받아들여 강사 초안을 덮고, 그 id로 등록 · 배포(또는 포털 판본 배포 · 되돌리기)하면 수업 흐름 표시 없는 판본이 경보를 가져가 [기준 흐름으로 되돌리기]가 내린다(B · C 멈춤). 고칠 곳: `flows_api.py` 가져오기 — 지금 배포의 수업 흐름 표시(`deployed_heads` class_flow)가 있는 id는 본문 `class_flow: true` 없으면 409, `ImportReq`에 `class_flow: bool = False`; `instances.py` `deploy_definition` — 그 흐름이 수업 흐름으로 배포돼 있으면 `class_flow=True` 아닌 배포 · 되돌리기를 사유와 함께 거절; `scripts/c3_flows.py` 가져오기 본문에 `"class_flow": True`. 시험과 돌연변이 확인을 함께.
2. 아직 안 돌린 학생 행위: 학생 B · C 사본을 실제 워커로 끝까지(`approval_stage_live.py B-approve --flow my_pm`, `C-approve --flow my_spare`, 학생 에이전트 배정 상태), 포털 화면 전체 읽기 순회(JS 오류 · 실패한 요청), 에이전트 모델 칸(자유 입력 — 중계는 `coding`만 받는다)에 다른 이름을 넣었을 때 사유가 보이는지.
3. `.env.example` 채우기: `PROCESS_MODE=instance` · `ENTERPRISE_BACKEND=supabase` · `PROCESS_MEM_LIMIT=768m` · `SEED_EDITION=structure` · `AGENT_BRIDGE=off` · `WORKER_URL=http://host.docker.internal:8097` · `OPENAI_BASE_URL`(중계 주소) · `LLM_MODEL=coding` · `LLM_API_KEY=`(빈칸, 사용자가 넣음) · Codex 중계 값은 이 값에서 시작 스크립트가 만든다.
4. 시작.bat · `start_all.sh`: Supabase 뒤 `migration up`, 위 값 보장, compose 뒤 수업 흐름 배포(이미 수업 흐름으로 배포돼 있으면 건너뜀), 워커 켜기(`.venv314`가 없으면 만들어 `requirements-dev.txt` 설치, VS Code 확장 폴더 `%USERPROFILE%\.vscode\extensions\openai.chatgpt-*`의 `codex.exe`를 찾아 PATH에, Codex 중계 = `.env`의 주소 · 키 · 모델), 점검.bat이 워커 · A 한 바퀴까지 보게. 끄기.bat은 워커도 끈다. Mac(`시작.command`)도 같게. 문서 적재(HM-8 → PM-02 → PR-07)는 수업 랩 단계이므로 시작.bat에 넣지 않는다.
5. 강의실과 같은 방식(새 `.env` + 키만)으로 처음부터 켜서 A · B · C가 끝까지 도는지 한 번 확인 → 문서(3_현황 · 6_남은_일 · 5_결정_기록 · 2_기준 6절) → main push.

## 중요 미래 TODO — 온라인 안내형 재생 모드 (2026-10-23)

**지금 구현하지 않는다.** 사용자가 중요 과제로 기록·동기화만 요청했다. 온라인 학생에게 실제 설비·공용 AI 키를 배포하지 않고 포털 실습을 직접 체험하게 하기 위한 후속 작업이다. 온라인 포털 실습 전체를 관찰만 하는 수업으로 확정한 것은 아니다.

- 구현 착수 전 두 과정의 전체 포털 실습·대본·입력·결과·선후 의존성을 읽고 지원 경로를 확정한다. 모든 사용자 행동을 예측하는 범용 시뮬레이터가 아니라, 확정된 강사 시연 경로만 수행할 수 있는 안내형 재생이다.
- 안내된 입력·행동과 저장된 응답/상태를 연결하고, 순서 밖 행동은 안내·제한한다. 사례 선택·처음부터 재시작·실습 간 초기화와 판본 대응이 필요하다. 실제 AI 응답처럼 가장하지 않고 재생 모드임을 표시한다.
- 키 없는 재생 모드를 기본 제공하고, 본인 키 또는 승인된 권한을 사용하는 실제 AI 실행을 선택할 수 있도록 설계한다. AI 키와 실제 설비 접근 권한은 별개다. 공유 키를 코드·브라우저·배포 파일에 포함하지 않는다. 비밀 보관·비용·접근 범위는 설계 시 별도 검증한다.
- 별도 개발 브랜치에서 준비한다는 사용자 방향을 기록한다. 브랜치명·분기 시점·배포 방식은 미정이며 현재 브랜치를 생성하지 않는다. 공통 코드와 모드 분리 방식은 구현 전 검토한다.
- 먼저 대표 실습 한 편의 완주·잘못된 순서·재시작·저장 응답 일치를 검증한 뒤 확대한다. 이는 미래 작업 순서이며 지금 시제품을 만들라는 지시가 아니다.
- 작업량은 전체 수업과 자유 입력/에이전트 추가 범위를 조사한 후 산정한다. 현재 정량 견적 없음. 상세 흐름을 모른 채 작거나 단순한 작업으로 판단하지 않는다.
