## 다음 세션 인계 — 수업 준비: 키 하나로 켜기 · 포털 실습 전수 점검 (2026-10-25 확정)

### 0. 목표(사용자 원문 요지)
1. 강의실에서 **`git pull` → `.env`에 `LLM_API_KEY` 한 줄 → 시작.bat → 점검.bat** 이면 수업 준비가 끝나게 한다. `.env.example`은 키 말고 다 채운다. 빈 포트 자동 배정(`scripts/prepare_ports.py`)은 유지.
2. **포털 실습**(아래 3절, 실라버스 기준 13개)이 학생이 하는 그대로 잘 도는지, 결함 · 오류 · 품질 문제가 없는지 확인하고 고친다. 랩(VS Code 안에서 끝나는 실습) · Notion · arrows.app · ProcessGPT 시연은 범위 밖.
3. main에 push.

### 1. 확정된 결정
- 작업 브랜치는 **main**. `replay-mode`(키 없는 온라인 학생용 AI 응답 재생)는 **필요 — 유지**, main을 병합해 따라간다. main에 재생 코드를 넣지 않는다.
- 강의실 학생 PC는 이미 clone · 설치가 끝났다. VS Code의 Copilot · Codex 확장은 **바이브 코딩 랩용**이며 이 시스템과 무관하다. 학생에게 주는 것은 **LiteLLM(강의 중계) 키 하나**다.
- 포털의 AI 단계(A · B · C 「판단 · 제안」, 에이전트에게 질문, 매뉴얼 추출, 학생 에이전트)는 **AI 워커**가 처리한다: 워커(일거리 가져오기 · 돌려주기) → 실행기 CLI(도구를 여러 번 쓰는 작업 루프) → **모델 호출은 전부 LiteLLM**. 실행기는 **유지보수 우선으로 저장소의 Docker 워커 이미지(`it/agent-worker/Dockerfile`, Claude Code CLI)** 를 그대로 쓰고 compose 설정으로 LiteLLM에 붙인다(Anthropic 계정 · 모델을 쓰지 않음). 강의실 PC에는 아무것도 더 깔지 않는다.
- 모델: LiteLLM 모델 이름 `coding`(사용자: 강의실은 gpt-6-luna 계열). 구조(결정론 판단 엔진 + 서버 검사 + 정해진 출력 형식)가 잘 짜여 있으면 결과가 잘 나온다는 전제로, 막히면 **프롬프트 · 스킬 · 지시문을 튜닝**한다.

### 2. 사실(2026-10-25 이 세션에서 확인)
- 지금 시작.bat(`scripts/start_all.sh`)은 ① 업무 DB 마이그레이션 미적용(`supabase start`는 기존 DB에 새 마이그레이션 059~062를 적용하지 않음 → 새 enterprise-sim이 멈추고 「응답하지 않는 포트 8095」) ② `AGENT_BRIDGE` 미설정(`.env.example` 기본 `legacy`) ③ 워커 미기동(compose 프로필 `cliagents`가 기본 목록에 없음) ④ 수업 흐름(`scripts/c3_flows.py deploy`) 미배포. `AGENT_BRIDGE=legacy`의 내장 판단은 기준 흐름 4단계만 채우고 수업 흐름 A · B · C의 「판단 · 제안」(T_agent)은 워커만 처리한다 → 지금 그대로면 A · B · C가 그 단계에서 멈춘다(실측).
- `enterprise-mcp` · `enterprise-mcp-maint` · `enterprise-mcp-purchase` · `dmn-mcp` · `agent-worker`는 모두 프로필 `cliagents`(compose.yaml). 워커는 tenants.mcp의 이 서버들을 컨테이너 이름으로 부른다.
- LiteLLM 실측: `/v1/models` = `coding` 하나, `/v1/chat/completions` · `/v1/responses` · `/v1/messages` 모두 200. 주소(비밀 아님, `.env.example`에 넣는다 — 사용자 지시가 `2_기준.md` 6절 「주소를 저장소에 적지 않는다」를 바꾼다): OpenAI 방식 `https://knu-litellm-1087825885001.asia-northeast3.run.app/v1`, Anthropic 방식(실행기용) 같은 주소에서 끝의 `/v1` 없이.
- 2026-10-23~25 실제 AI 점검은 호스트 워커(Claude Code CLI)에 `ANTHROPIC_BASE_URL`=중계(끝의 /v1 없이) · `ANTHROPIC_API_KEY`=키 · `ANTHROPIC_MODEL` · `ANTHROPIC_SMALL_FAST_MODEL` · `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`=`coding` · `CLI_MODEL=coding` · `DISABLE_TELEMETRY=1` · `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`을 주고 돌렸다(A · C · 질문 · 회귀 40/40 통과). 컨테이너 워커에 같은 값을 compose로 넣으면 된다. `env_guard`는 `ANTHROPIC_API_KEY`를 실행기에 남긴다(`CLI_AUTH_KEEP`), 키가 있으면 실행마다 따로 `CLAUDE_CONFIG_DIR`(settings.py `isolate_config_dir`).
- 키: 저장소 · 로그 · 증거 · 화면에 넣지 않는다. 이 클라우드 환경 설정의 `LLM_API_KEY`는 401(낡음), `OPENAI_BASE_URL`은 옛 주소 — 사용자가 환경 설정을 고치거나 세션마다 키 파일을 올린다(올린 파일에서 실행할 때만 읽고 출력 · 복사하지 않는다).
- 클라우드 전용(저장소에 넣지 않음): 이미지 빌드용 베이스 `python:3.12-slim`에 프록시 CA와 `NODE_EXTRA_CA_CERTS`까지 넣어야 워커 이미지의 npm이 된다(CLAUDE.md 5절 방법 + 그 ENV). 디스크 여유가 1~2 GB라 빌드 뒤 `docker builder prune -af`. 클라우드 python은 3.13 — `start_all.sh`의 3.14.7 요구는 강의실 기준이므로 고치지 말고 `uv python install 3.14`로 맞추거나 같은 단계를 손으로 실행한다.

### 6. 작업 규칙(사용자 지시 — 반드시)
- **해피패스 금지**: 실습마다 3절의 예외 · 실패 경로를 실제로 돌린다. 정상 한 번 통과로 끝내지 않는다. 시험 데이터를 정답에 맞추거나(구세주 데이터) 정답을 하드코딩하지 않는다.
- **누구는 되고 누구는 안 되면 안 된다**(사용자 2026-10-25: 학생들은 강사를 따라 같은 순서로 같은 것을 한다 — 각자 다른 행동을 하지 않는다). 판정은 「같은 단계를 한 학생 모두가 같은 결과를 받아 다음 단계로 가는가」.
  - **AI 결과의 흔들림**: AI 단계마다 같은 입력으로 **3번** 돌려 추천 카드 · 승인 역할 · 근거 · 추출 결과 · 소요 시간이 갈리는지 본다(2026-10-25 A 추천이 생산관리자 승인 카드로 나와 운전원 안내와 어긋난 사례). 갈리면 프롬프트 · 스킬 · 순위 입력을 안정되게 고치고, 그래도 갈리면 보고한다(가이드에 「카드의 승인 역할을 보고 「나」를 고른다」 같은 공통 안내가 필요한지 포함).
  - **속도 차이**: 20배속 시간 창(승인 요청 30초 · 예측 유효시간 · 승인 지연 알림)이 AI 응답이 느린 PC에서도 같은 결과인가 — 3번 중 가장 느린 소요 시간 기준으로 본다.
  - **PC 상태 차이**: 수업 시작 상태 그대로(구조판, 문서 적재 전, 처리 건 0)에서 실라버스 순서대로 누적해 간다. 포트가 옮겨진 PC, 시작 스크립트를 두 번 돌린 PC, 앞 회차 처리 건이 남은 PC에서도 같은 결과인가.
  - **뒤처진 학생이 따라붙는 길**: 멈춘 상태마다 화면에서 되돌릴 방법([초기화] · [닫기] · [다시 평가] · 되돌리기)이 있고 실제로 되는가. 오류 · 거절은 한국어 사람 글로 무엇을 하라는지 말한다(영문 예외 · 500 · 빈 화면 · 무한 대기 금지).
