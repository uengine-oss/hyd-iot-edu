# 배포 묶음과 업로드

공통 기준(`../lecture-common/공통기준.md`)과 저장소 루트 `CLAUDE.md`, 대상 강의의 수신자·배포 계약을 먼저 따른다.
HYD 교재 PPTX의 배포 묶음(`만들기/dist/교재_전체.zip`)은 `../hyd-course-deck/scripts/배포묶음.py`로 만든다(`hyd-course-deck` 스킬). 아래 경로는 이 스킬 폴더 기준이다.
묶음 제작과 외부 전송은 별개다. 사용자가 파일 제작을 요청했으면 로컬 완성·검증까지 진행한다.
업로드·공유는 **명시 요청이 있을 때만** 아래 「업로드」 절로 승인된 대상과 범위에서 한다.

덱·PPTX·대본은 `lecture-deck`이 만든 현재 파일을 그대로 묶는다. 이 스킬은 PPTX를 만들거나 고치지 않는다.
Google Drive에 올릴 형태로 묶어 달라는 요청도 로컬 파일과 ZIP으로 완성하며 Drive 연결이나 업로드를 요구하지 않는다.

HYD 배포는 `문서/교재/4_만드는_법.md` 1부와 `6_남은_일.md` 0절 4번(다른 반 하루치 덱의 전환 상태)를 먼저 확인한다. 최신 원본과 아직 갱신하지 않은 파생물을 한 판으로 배포하지 않는다.

## 1. 구성 확정

1. 학생·학교 검토자·내부 검토자 중 수신자를 확인한다. 학생용에는 공개가 승인된 코드·가이드·데이터·준비물을,
   검토용에는 요청한 판단에 필요한 계약·정답·검증 근거를 포함한다. 받은 자료의 공유 권한을 확인하고 원본은 보존한다.
2. 실제 파일을 읽어 포함 목록과 제외 이유를 정한다. `_` 접두사·이미 보낸 파일·lock 파일이라는 이유만으로
   실행 의존성을 빼지 않는다. 전체 배포본인지 변경분인지 요청에 맞춘다. 정답 분리는 설명·예상 출력 금지가 아니다.
3. 프로젝트 루트의 선언 파일을 읽는다. 포함할 파일과 충돌하면 의도를 확인해 해결하며 조용히 우회하지 않는다.
4. 파일 단위 상대 경로 JSON 배열(`/` 구분)을 내부 작업 위치에 작성한다. 학생 배포본에 목록이나 내부 보고를 자동 포함하지 않는다.
   파일명이 아닌 실제 역할과 의존성을 검토한다. 필수 파일이 빠지면 목록을 결과에 맞춰 축소하지 않는다.

### 프로젝트 선언 파일 (루트, 한 줄에 하나, `#` 뒤는 주석)

| 파일 | 뜻 | 주의 |
|---|---|---|
| `.검토제외` | 묶음에서 뺄 파일·폴더 이름. 경로의 어느 부분과 같아도 걸린다 | 명시 목록에 이 이름이 들어 있으면 `검토자료.py`가 오류로 멈춘다 |
| `.차단예외` | 차단 패턴에 걸리지만 공개 가능성이 확인된 **전체 줄** | 줄 전체가 정확히 같을 때만 통과하고 통과 건을 모두 출력한다. 실제 비밀을 예외로 통과시키지 않는다 |
| `.가릴이름` | 정규식으로 못 찾는 실명·사내 고유명 | 묶을 때 `○○○`으로 바꾼다. 선언하지 않은 실명은 가려지지 않는다 |

## 2. 제작

프로젝트 전용 배포기가 있으면 그 계약과 검증을 확인해 사용한다. 공용 `검토자료.py`는 다음처럼 사용한다.
작업 폴더는 대상 강의 루트이며, `<스킬>`은 실제 `.claude/skills/lecture-deliver` 경로다. 특정 셸 변수 문법을 강제하지 않는다.

```text
python <스킬>/검토자료.py --목록 files.json --미리보기
python <스킬>/검토자료.py --목록 files.json --이름 날짜-작업명-학생
```

- **실제 ZIP에는 명시 목록(`--목록`)이 필요하다.** 목록 없는 자동 탐지는 `--미리보기` 진단용이며, 목록 없이 ZIP을 만들려 하면 종료코드 2로 멈춘다.
- ZIP은 프로젝트 루트에 `<이름>.zip`으로 생긴다. 같은 이름이 있으면 도구가 멈추므로 새 이름으로 만들고 검증 후 현재 산출물을 지정한다.
- 도구는 텍스트 파일마다 **차단 검사를 먼저** 하고 **그다음에 가린다.** 순서가 바뀌면 키·이메일이 `sk-****`로 바뀐 뒤라
  차단이 못 잡는다. 차단 건이 하나라도 남으면 ZIP을 지우고 종료코드 1로 끝난다(값은 출력하지 않는다).
- 가리기는 이메일·프로젝트 ID·결제계정 번호·API 키·사용자 홈 경로와 `.가릴이름` 실명을 자리만 남기고 바꾼다.
- 미리보기는 파일 구성 확인이며 내용·비밀값 검사 통과가 아니다.

## 3. 내용과 파일 검증

- 예정 목록·미리보기·ZIP 내부의 **정확한 경로 집합**을 대조한다. 합계만 같으면 통과가 아니다.
- 압축을 새 시험 폴더에 풀고 학생 가이드의 위치·명령대로 실행한다. 정상·경계·명시 오류와 복구를 확인한다.
  GUI는 실제 화면·상태 변화를 확인한다. CLI 로그를 GUI를 본 증거로 쓰지 않는다.
- 학생용에 강사용 정답·비밀값·개인정보·의도하지 않은 내부 기록이 없는지 내용과 실제 그림을 확인한다.
  예상 출력·설명·학습에 필요한 단서는 정답과 구분한다. 공개 범위는 강의 계약이 정한다.
- 알려진 패턴 검사는 완전한 비밀 탐지기가 아니다. 바이너리 문서·이미지는 해당 도구로 열어 검토한다.
- 값이 검출됐다고 원본을 임의 수정하지 않는다. 배포용 사본에서 처리하고 원문과 변환 내용을 구분한다.
  실제 자격증명이면 보고하되 값 자체를 로그·보고에 재출력하지 않는다.
- 검사·예시·dummy라는 단어는 우회 근거가 아니다. `.차단예외`가 적용된 파일과 유형을 매번 검토한다.
- 실패·미검증이 있으면 배포 준비 완료로 표시하지 않는다. 이미 있는 정상 산출물과 사용자 작업은 보존한다.

## 4. 업로드 — 명시 요청 시에만

스킬 작성·자료 제작·묶음 요청만으로 업로드·공유 권한 변경·원격 삭제를 실행하지 않는다.
Google Drive 전용 복사본이나 `배포본/구글드라이브에올릴것`, `drive-upload`, 날짜별 업로드 사본 같은 별도 배포 트리를 만들지 않는다.
검증된 최종 파일을 직접 올린다. 도구상 필요한 임시 전송 자원은 정본으로 취급하지 않는다.

1. 강의 폴더, 최종 산출물 경로, 대상 Drive 폴더 URL/ID, 이번 업로드 요청을 확인한다.
   대상 폴더가 없으면 연결된 Drive 검색으로 확인하고, 동명 후보가 여러 개면 대상만 묻는다.
2. 정본 파일의 절대경로·크기·SHA256과 검증 기록을 확인한다. 작업기록·정답·비밀키·내부 설계 문서를 업로드 목록에 섞지 않는다.
   ZIP이면 실제 항목을 검사하고, 학생 출발본의 핵심 과제가 이미 완성된 채 섞이지 않았는지 제작 목록과 비교한다.
   불완전한 자료를 사용자가 검토용으로 올리라고 했다면 그 범위와 상태를 기록한다.
3. 현재 호스트에 연결된 Drive 도구를 찾아 실제 스키마대로 호출한다. 도구·업로드 URL·성공 결과를 추측하지 않는다.
   파일의 원래 형식을 보존하고 문서 변환·새 프레젠테이션 제작을 하지 않는다.
4. **같은 대상 파일을 갱신할 때는 조회로 확인한 파일 ID를 사용한다.** 같은 이름이라는 이유만으로 다른 강의 파일을 덮어쓰지 않는다.
5. 실패 후에는 **원격 목록·파일 메타데이터부터 다시 확인한다.** 성공 여부가 불명확한 생성 요청을 반복해 중복 파일을 만들지 않는다.
6. 완료 응답 뒤 Drive에서 이름·MIME·대상 폴더·크기를 다시 읽는다. 체크섬을 제공하면 로컬 값과 비교하고,
   제공하지 않으면 확인하지 못한 항목을 명시한다.
7. 공유 범위는 기존 설정을 유지한다. 승인받지 않은 공개 링크 전환·이메일 발송·원격 삭제는 하지 않는다.

강의의 내부 작업기록에 로컬 경로·SHA256·원격 ID·확인 시각·실제 URL을 저장한다. 비밀 토큰은 기록하지 않는다.

## 5. 보고

수신자·구성 전후·실제 명령과 시험 결과·제외 및 변환·미검증 범위를 보고한다.
업로드했다면 실제 링크와 실패·미검증 범위를 쓰고, 업로드 성공과 공유 권한 설정 성공을 구분한다.
파일을 실제로 보내지 않았으면 발송했다고 쓰지 않는다. 예전 문서의 경로·파일 수·완료 주장은 재확인한다.
문서 사이 불일치는 `lecture-plan`, 품질 판정은 `lecture-verify`로 넘긴다.
