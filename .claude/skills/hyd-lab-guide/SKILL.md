# HYD 실습 랩 · 실습 대본 · 가이드

실습 하나를 시작 → 수행 → 검증 → 저장 → 영상 · 가이드 전달까지 끝내는 절차다(기준_실습 P1). 규칙은 기준 문서에 있고, 이 문서는 순서 · 경로 · 명령과 기준 절 번호만 적는다(「기준_X Yn」은 `문서/교재/기준_X.md`의 Yn절, 「Yn-k」는 그 k항). 경로는 저장소 루트 기준이다.

## 먼저 읽는다

1. `문서/교재/기준_공통.md` 끝까지(실라버스 · 시간은 G0 「범위와 시간」, 말하는 법 · 음성은 G6).
2. **실습 종류를 하나 고른다.** 화면 · 조작이 정해진 도구 실습(포털 · ARROWS · Notion · Neo4j Browser · bpmn.io)인가, VS Code에서 만드는 코딩 랩인가. 둘은 별개의 실습이다 — 서로의 장면 · 예고를 섞지 않는다.
3. `문서/교재/기준_실습.md`(모든 실습 공통) 끝까지, 이어서 그 종류 기준 하나만 끝까지: 도구 실습 `기준_실습_도구.md`, 코딩 랩 `기준_실습_코딩랩.md`.
4. 촬영하면 그 도구의 `제작용/촬영/<도구>/촬영준비.md`와 `제작용/촬영/README.md`.
5. 본보기: 도구 실습은 기준_실습_도구 T0(ARROWS · Notion의 랩 · 대본 · 영상 · 가이드), 코딩 랩은 기준_실습_코딩랩 K0 · K2 제공물 표.
6. 새 코드 이름은 `제작용/기존제작/labs/STRUCTURE.md`(기준_실습_코딩랩 K2-6).

## 무엇이 어디 있나

| 무엇 | 위치 |
|---|---|
| 학생 랩 폴더 · ZIP · 가이드 | `산출물/<과정>/실습/NN회차/랩/<NN일차_실습M_이름>/` + 같은 이름 `.zip`. 새 가이드는 `guide.html`, 기존 `가이드.html` · `안내.html`은 이름 유지(기준_실습 P8-4) |
| 실습 대본 | `산출물/<과정>/실습/NN회차/대본/<번호>_실습_<이름>.md` |
| 회차 안내 | `산출물/<과정>/실습/NN회차/README.md` |
| 코딩 랩 강사 참조 답안 · 기대 결과 | `제작용/실습시작/reference/…`(학생 폴더 밖, 기준_실습_코딩랩 K2-4) |
| 실습 시작 도구 · 패키지 빌드 · 검사 | `제작용/실습시작/`(`실습시작.cmd`, `build_*.py`, `verify_packages.py`, `verify_reference.py`) |
| 이전 구조의 랩 원본 | `제작용/기존제작/labs/offline/`, `course/labs/offline/05-2-cause-agent/`(기준_실습_코딩랩 K2-6, 일괄 이전 안 함) |
| 촬영 도구 | `제작용/촬영/<도구>/촬영도구/`, 시간 계산 `제작용/촬영/시간계산.py` |
| 실습의 범위 | 실라버스 정본 `문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx`의 그 실습 행 |

## 실습 하나의 절차 (기준_실습 P1 순서)

각 단계는 앞 단계가 끝나야 넘어간다.

- [ ] **0. 시작 전(기준_실습 P1-1 · P1-7):** 기준 세 문서(공통 · 실습 · 종류) 통독, 그 종류 본보기 통독. 인계의 옛 완료 표시와 폐기판 산출물은 실라버스와 대조하기 전에는 이어받지 않는다(기준_공통 G1-4).
- [ ] **1. 배정 시간과 실라버스 대조표(기준_실습 P1-2, 가장 먼저):** 그 행의 배정 시간을 적고, 상세 문장을 한 줄씩 떼어 표를 만든다.

  | 실라버스 상세 문장(원문 그대로) | 영상 구간 | 설명 · 화면 | 확인 방법 | 예상 분 |
  |---|---|---|---|---|

  합이 배정 시간을 채우는지 본다(기준_공통 G0 「범위와 시간」). 빈칸이 있으면 다음 단계로 가지 않는다. 행에 없는 장면 · 타이핑으로 채우지 않는다. 실라버스를 고칠 일이면 기준_공통 G0 「범위와 시간」 6~8.
- [ ] **2. 앞 이론 · 앞 포털 실습과 잇기(기준_실습 P1-3):** 그 회차 덱의 실습 간지 · 설명 장과 앞 이론 대본에서 연결점을 찾는다(잇는 말은 기준_공통 G0). 도구 실습은 다음 실습을 예고하지 않는다(기준_실습_도구 T1-1).
- [ ] **3. 실습 자료:** 도구 실습은 그 도구 화면의 시작 상태와 경계(기준_실습_도구 T1 · T2). 코딩 랩은 설계(기준_실습_코딩랩 K1), 제공물 표와 제공 경계(K2), 판단이 갈리는 지점 하나 이상(K2-3), 강사 참조를 실제로 실행해 풀리는 과제임을 증명(K2-4), 시작본 · 연결 · 저장(K3).
- [ ] **4. 구성안 사용자 확인:** 기준_공통 G4-10의 꼴(시간 · 구성 · 실라버스 대조 · 발췌 · 판단 지점)로 보여 확인받는다.
- [ ] **5. 대본(기준_실습 P2, 코딩 랩은 기준_실습_코딩랩 K4도):** 파일 꼴 기준_실습 P2-7, 말하는 법 기준_공통 G6. 덱의 문장을 옮기지 않고 지금 하는 행위를 말한다. 다 쓴 뒤 스스로 이어 읽으며 윤문한다(기준_공통 G6-6).
- [ ] **6. 대본 사용자 확인:** 기준_공통 G4-10의 꼴로.
- [ ] **7. 분량(기준_실습 P1-6):** 큐 원고로 계획 시간을 내고 배정과 비교한다. 모자라면 그 회차 범위 안에서 보강한다.

  ```bash
  python 제작용/촬영/시간계산.py estimate <cues.json> [--target 분]
  ```

- [ ] **8. 리허설 · 녹음 · 촬영(기준_실습 P3~P6):** 도구 촬영준비와 함께. 순서는 기준_실습 P4-1, 음성 비용은 먼저 알림(기준_공통 G6-14 · G4-4), 뚫린 길 재사용 · 안 뚫린 길 먼저(기준_실습 P4-3), 새 리듬 · 도구는 대표 구간 1~2분을 먼저 보여 확인(기준_실습 P4-2). 포털 화면은 hyd-portal-video, 코딩 랩의 Codex 요청 구간은 기준_실습_코딩랩 K5. 찍은 뒤 `시간계산.py check`로 예상과 비교하고, 바뀐 대사 · 입력 · 순서를 기준_실습 P4-10 · 기준_공통 G4-9대로 맞춘다.
- [ ] **9. 검사(기준_실습 P7):** 기술 검사(P7-1)와 따로 수업 성립 판정(P7-5). 코딩 랩은 완성 판정 네 가지(학생 경로 리허설 · 검사기가 망가뜨린 입력을 잡음 · 강사 참조 실행 · 가이드만으로 받기 시험)와 장난감 판정(기준_실습_코딩랩 K6).
- [ ] **10. 가이드 · 패키지(기준_실습 P8~P11):** 구성 P8 · 사진 P9(본 촬영 화면에서, P9-2) · 문장 P10. 정적 검사(P11-2) → 패키지 검사 → 받기 시험(P11-3). 바뀌면 두 과정의 원본 · HTML · 학생 파일 · 이미지 · ZIP · README · 시작 도구 목록을 같은 판본으로(기준_공통 G4-9).

  ```bash
  python 제작용/실습시작/verify_packages.py      # 키 · 개인정보 · 강사 정답이 학생 패키지에 없는지(기준_실습 P12-5)
  ```

- [ ] **11. 게시(기준_실습 P12):** 영상은 other-pc, 문서는 main, 노션 두 과정 회차 페이지에 영상 · 가이드 · ZIP 연결 후 실제로 열어 확인. 원격 push · 노션 게시는 사용자에게 묻고 한다(기준_공통 G4-3).
- [ ] **12. 완료 보고:** 아래 「보고」.

## 덱과 다른 사실을 찾았을 때

가이드만 맞추지 않고 같은 사실을 쓰는 덱 · 대본 · 랩 · 가이드 · 코드를 함께 고친다(기준_공통 G3-6). 덱은 hyd-course-deck 절차로 고친다.

## 보고

항목별로 요구 → 결과 → 근거를 대조해 적고, 상태어는 기준_공통 G4-7로 쓴다.

| 항목 | 적을 것 |
|---|---|
| 종류 | 도구 실습 / 코딩 랩, 읽은 기준 목록 |
| 시간 | **배정 N분 / 계획(시간계산) N분 / 실측 N분**(기준_공통 G0 「범위와 시간」 5) — 이 숫자 없이 「끝났다」고 쓰지 않는다 |
| 대조표 | 빈칸 0, 실라버스 원문과 다시 맞춘 결과(기준_실습 P1-2) |
| 사용자 확인 | 구성안 · 대본 확인 여부(기준_공통 G4-10 꼴) |
| 코딩 랩 완성(기준_실습_코딩랩 K6-1) | ① 학생 경로 리허설 ② 검사기 고의 손상 ③ 강사 참조 실행 ④ 받기 시험 — 각각 상태어와 근거 |
| 수업 성립(기준_실습 P7-5) | 대조표 항목 반영 · 설명 충분 · 그 종류의 시연이 실제로 보임 · 분량 |
| 기술 검사(기준_실습 P7-1) | 무엇을 어떻게 봤는지(간격 · 문장 수) |
| 게시 | 커밋 · 해시 · 링크 · 열어 본 확인, 남은 의존성 |
| 돌리지 못한 것 | `미확인`으로(기준_실습 P7-6) |
