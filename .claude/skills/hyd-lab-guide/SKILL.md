# HYD 실습 가이드

HYD 과정의 실습을 학생이 따라 하는 가이드를 쓴다. 교재 덱은 실습을 2장(간지 + 설명)으로만 싣고, 절차는 이 가이드가 맡는다. 경로는 모두 저장소 루트 기준이다.

`lecture-lab` 스킬과 겹치는 내용은 그쪽을 가리키고, 여기에는 HYD에서 달라지는 것만 적는다. **둘이 부딪치면 이 문서가 우선한다.** 이 문서는 아래 착수 문서와 형식 문서의 요약이다. 부딪치면 그 문서들이 우선한다(사용자가 정한 것이 거기에 있다).

## 먼저 읽는다

1. `docs/교재/인계/06_실습가이드_착수.md` — 정해진 것(2절), 실습 160건의 목록(3절), 착수 순서(4절), 시작 전에 사용자에게 받을 것(5절), 덱과 어긋날 때(6절).
2. `docs/실습가이드/틀/형식.md`와 `docs/실습가이드/틀/실습가이드_틀.html` — 주어진 틀. 형식은 이것을 그대로 따른다.
3. `../lecture-lab/SKILL.md`, `../lecture-lab/references/HTML실습가이드.md`(복사 상자의 종류와 목적지, 명령 다음에 결과를 읽는 법), `../lecture-lab/references/그림요구.md`(지어내면 안 되는 것).
4. 그 실습이 속한 일차의 덱 MD(`docs/교재/통합반/NN일차/통합반_NN일차.md`)에서 실습 간지와 설명 장, 그 앞의 이론 장 — 용어와 값을 맞추기 위해서다. 간지와 설명 장의 번호는 `python3 .claude/skills/hyd-lab-guide/scripts/실습목록.py 통합반 --day N`으로 뽑는다(저장소 루트에서). 실습의 범위는 실라버스(`docs/교재/기준/피지컬AI_실라버스_최종본.xlsx`)의 실습 행이 정한다.
5. 저장소 루트 `CLAUDE.md`와 `docs/handoff/NOW.md` — 스택을 올리는 법, 배속, 건드리면 안 되는 것.

위 1 · 2의 파일이 아직 없으면 쓰기 전에 사용자에게 틀과 착수 문서의 위치를 묻는다. 틀 없이 형식을 지어내지 않는다.

## 정해진 원칙

1. **실제로 돌려 본 것만 쓴다.** 명령, 프롬프트, 출력, 화면은 이 저장소에서 가이드의 순서대로 직접 실행해 확인한 것이다. 돌리지 못한 구간은 쓰지 않고 「확인하지 못함」으로 보고한다.
2. **MD 원고에서 HTML로.** 원고는 MD 하나가 원본이고 그림은 같은 폴더의 이미지 파일이다. 배포는 HTML이다. MD → HTML 변환 스크립트는 아직 없다: 본보기의 HTML은 틀을 복사해 채워 만들고, 본보기를 확정한 뒤 변환 스크립트를 만든다(착수 문서 4.2절). 그 뒤로는 HTML을 직접 고치지 않는다.
3. **주어진 틀의 형식 그대로.** 절 구조, 상자의 종류, 색, 글꼴을 새로 만들지 않는다. 블록이 더 필요하면 틀의 블록을 조합하고, 그래도 안 되면 사용자에게 묻는다(형식 문서 1절).
4. **화면을 다루는 법.**
   - VS Code 화면은 찍지 않는다.
   - 명령과 프롬프트는 복사 상자에 넣는다(어디에 붙여 넣는지를 상자가 말한다).
   - 출력은 터미널 재현 상자에 글자로 싣는다(실제 실행의 출력을 옮긴 것).
   - 사진은 결과를 보는 브라우저 화면에만 쓴다(HYD 포털, Neo4j Browser, bpmn.io, arrows.app).
   - 예외: VS Code 확장을 열고 로그인하는 처음 한 번과 Windows 설치 화면은 수업 PC에서 찍은 사진을 받아 넣는다.
5. **AI에게 일을 시키는 다섯 걸음**을 가이드의 뼈대로 삼는다: 파악 → 할 일과 끝난 모습 → 계획부터 → 작게 만들고 확인 → 틀렸을 때 되돌려 주기. 실라버스의 실습 시간 안에 들어가는지 실습마다 따지고, 짧은 실습은 걸음을 합친다.
6. **요청마다 「왜 이렇게 시키는가」**를 붙인다. 학생이 배우는 것은 정답 프롬프트가 아니라 시키는 법이다.
7. **나쁜 예와 좋은 예**를 나란히 보인다. 나쁜 예도 실제로 돌려 본 결과로 든다.
8. **뒤로 갈수록 빈칸.** 앞 실습은 요청을 그대로 주고, 뒤는 틀만 주고, 마지막은 목표만 준다.
9. **출력 예는 「이 항목이 있으면 된다」**로 준다. AI의 답은 실행마다 달라지므로 글자가 같기를 요구하지 않고, 출력 상자 아래에 확인할 것 두세 줄을 둔다.
10. **흔히 막히는 곳**을 실습마다 한두 개 싣는다(AI가 없는 값을 지어냈을 때, 시키지 않은 파일까지 고쳤을 때). 이것도 실제로 겪은 것만 쓴다.
11. **본보기 하나를 먼저 만들어 확인받는다.** 실습 하나를 끝까지(원고 → HTML → 직접 따라 하기) 만들어 사용자에게 보이고, 확인받은 뒤 같은 기준으로 나머지를 만든다.
12. **ProcessGPT 시연은 대상이 아니다.** 강사가 제품을 보여 주는 시연(통합반 11일차, 실전반 8일차)은 학생이 따라 하는 가이드를 쓰지 않는다.

## 작업 순서

1. 착수 문서 3절의 목록에서 대상을 정하고(본보기의 후보는 4.1절), 시작 전에 받을 것(5절: 실습을 돌릴 PC, 범위와 순서, 제공 자료, 학생 환경, 사진, 배포 방식 등. 수업 도구는 VS Code의 GitHub Copilot 채팅으로 정해졌고 세팅은 따로 준비된 세팅 가이드가 맡는다)이 있는지 본다. 없는 것은 그것만 묻고, 받지 못했으면 그것이 필요 없는 실습부터 한다. 없는 자료를 지어내지 않는다.
2. 스택을 올리고 실습을 처음부터 끝까지 직접 한다. 명령, 프롬프트, 출력, 막힌 곳과 푼 방법을 저장소 밖 임시 폴더에 기록한다. 실습마다 돌린 날, 환경(PC · OS · 배속), 걸린 시간, 출력의 출처를 남긴다.
3. 기록을 바탕으로 MD 원고를 쓴다. 틀의 절 구조에 다섯 걸음을 얹고, 요청마다 까닭과 확인할 항목을 붙인다.
4. HTML로 만들고 브라우저에서 연다(본보기는 틀을 복사해 채우고, 변환 스크립트를 만든 뒤에는 그것으로 만든다). 복사 상자가 본문만 복사하는지, 붙여 넣을 곳의 안내가 맞는지, 좁은 화면에서 넘치지 않는지 본다.
5. 원고만 보고 처음부터 다시 따라 한다. 가이드에 없는 준비나 암묵적인 단계가 나오면 원고를 고친다.
6. 본보기는 여기서 사용자에게 보인다. 확정되면 변환 스크립트를 만들고(본보기의 MD를 변환한 결과가 확정본과 같아야 한다), 형식 문서 6절 「MD 원고와의 대응」을 채운다.
7. 그 뒤의 실습은 확인받은 본보기와 같은 기준으로 만든다. 통합반 온라인을 먼저 하고, 같은 도구의 실습을 묶어 돌린다(착수 문서 4.2절). 일차가 끝날 때마다 앞 실습과 용어 · 형식이 같은지 대조한다.

파일을 두는 곳은 정해지지 않았다. 제안은 `docs/실습가이드/<과정>/<NN일차>/`이며 본보기를 만들 때 사용자에게 확인한다(착수 문서 4.3절).

## 덱과 어긋나는 사실을 찾았을 때

실습을 실제로 돌리면 덱이나 사실표와 다른 것(이름, 값, 단계, 화면에 보이는 말)이 나올 수 있다.

가이드만 맞추고 덱을 두지 않는다. 덱도 함께 고친다(착수 문서 6절).

1. 무엇이 다른지 적는다: 덱과 장의 제목, 덱의 값, 실제로 본 값, 돌린 환경, 근거(파일 위치나 명령과 출력).
2. 다름의 종류를 가린다: 덱이 틀린 것인가, 실행 회차가 달라 값이 다른 것인가(덱은 두 실행 회차의 값을 쓴다 — `docs/교재/인계/04_결정_기록.md` 2절), 시스템이 그 뒤 바뀐 것인가. 코드와 실제 실행이 기준이다. 판단이 서지 않으면 사용자에게 묻는다.
3. 가이드는 실제대로 쓴다. 덱에 맞추려고 실제와 다른 말을 쓰지 않는다.
4. 덱이 틀렸으면 통합반 원 덱을 고치고 조립 덱과 배포 묶음까지 다시 만든다. `hyd-course-deck` 스킬과 `docs/교재/인계/02_덱_고치는_법.md` (나)의 순서를 따른다. 근거가 되는 사실표의 절도 함께 고친다.
5. 실습 설명 장(덱의 「무엇을 하고 무엇이 만들어지는지」 한 장)이 가이드의 실제 산출물과 맞는지 실습마다 대조한다. 덱에서 정의한 용어는 가이드에서 같은 말로 쓰고 다시 풀지 않는다.
6. 닫힌 것은 `docs/교재/인계/05_남은_일.md`에서 지우고, 고치지 못하고 남긴 것은 거기에 올린다.

## 지킬 것

- 공개 저장소다. 키 · 토큰 값, 계정, 사람 이름, 절대 경로를 원고 · 출력 재현 · 사진에 넣지 않는다. 출력에 찍힌 것은 자리표시로 바꾸고 바꿨다고 적는다.
- 학생 화면에 제작 메모, 검증 이력, 강사용 메모를 넣지 않는다. 단서와 면책(「교육용이라 실제와 다르다」)도 넣지 않는다(제작 기준 3절과 같다).
- 실행 중인 검사가 있을 때 스택을 다시 올리지 않는다. 시험이 만든 것(시험 인스턴스, 임시 데이터)은 스스로 치운다(저장소 루트 `CLAUDE.md` 3절).
- 서브에이전트를 쓴다면 `hyd-course-deck` 스킬의 「서브에이전트를 쓸 때」를 따른다(fable 모델 금지).
- 커밋 · push는 요청받았을 때만 한다.

## 산출물과 보고

원고(MD)와 HTML, 브라우저 결과 사진의 경로. 직접 돌려 확인한 범위와 확인하지 못한 범위. 덱과 어긋난 곳의 목록. 사용자가 정해야 할 것.
