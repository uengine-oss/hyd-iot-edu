# HYD 실습 랩과 가이드

HYD 과정의 실습을 만든다. 교재 덱은 실습을 2장(간지와 설명)으로만 싣고, 절차는 랩과 가이드가 맡는다. 경로는 모두 저장소 루트 기준이다.

이 문서는 아래 문서들의 요약이다. 부딪치면 그 문서들이 맞다.

## 먼저 읽는다

1. `문서/교재/2_기준.md`: 공통 기준과 두 과정의 공통 범위와 차이, 일하는 방식. 실습 상세는 `문서/교재/기준_실습랩.md`(랩·입력·응용), `문서/교재/기준_실습가이드.md`(가이드·HTML), `문서/교재/기준_실습대본.md`(강사 대본·촬영). 옛 번호(10절 등)는 2_기준 「기존 상세 번호의 위치」표로 찾는다.
2. `문서/교재/4_만드는_법.md`의 실습 행(읽을 기준과 대조할 산출물). 진행 상태는 로컬 `.evidence/기록/`.
3. `제작용/기존제작/labs/STRUCTURE.md`: 랩의 폴더와 이름의 틀.
4. 본보기: 1회차 확정 실습(`산출물/통합반/실습/01회차/` 랩 · 대본).
5. 그 실습이 속한 일차의 덱 원고(`제작용/온라인/decks/integrated/dayNN/통합반_NN일차.md`)에서 실습 간지와 설명 장. 실습의 범위는 실라버스 정본(`문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx`)의 실습 행이 정한다.

## 무엇을 만드는가

| 수업 | 만드는 것 | 어디 |
|---|---|---|
| 오프라인 | 학생이 받아 VS Code로 여는 폴더와 `guide.html` | `course/labs/offline/<회차-실습번호-주제>/` |
| 오프라인 | 완성본, 실행 기록, 가이드를 만드는 스크립트 | `제작용/기존제작/labs/offline/<같은 이름>/` |
| 온라인 | 키 없이 실행되는 완성본(저장된 실행의 답을 재생한다) | `course/labs/online/<같은 이름>/` |
| 온라인 | 강사가 보며 찍는 촬영 대본 | `제작용/기존제작/labs/online/dayNN-M-주제/` |

## 지킬 것

- **두 과정의 관계는 `문서/교재/2_기준.md` 「두 과정의 공통 범위와 차이」가 정본이다**(요지: 랩은 한 벌·실전반 난이도, 실습 쪽 과정 차이는 VS Code 코딩 랩 대본에만). 산출물은 `산출물/<과정>/실습/NN회차/`에 두며, VS Code 코딩 랩 대본 말고는 두 과정이 같은 내용이다.
- 실습 안내(이론 대본의 실습 간지 · 설명 장)는 실습의 목적을 말한다. 「자료를 내려받고」 「파일을 저장하고 다시 열어」 같은 부속 동작이나 실습에 없는 일을 앞세우지 않는다.

- 실제로 돌려 본 것만 쓴다. 명령, 요청문, 출력, 화면을 지어내지 않는다. 돌리지 못한 것은 강사 폴더의 기록에 「확인하지 못한 것」으로 적는다.
- 방식은 먼저 제안해 승인받는다. 하나를 만들어 확인받고 넓힌다. 여러 묶음을 한꺼번에 고치지 않는다.
- 가이드에는 실습을 진행하는 데 필요한 것만 담는다. 설계의 까닭을 길게 풀거나 만드는 사람에게 하는 말을 넣지 않는다.
- 학생 폴더와 가이드에 강사 폴더, 완성본, 제작 기록을 가리키는 말을 넣지 않는다. 단서와 면책(「교육용이라 실제와 다르다」)도 넣지 않는다.
- 랩의 에이전트는 모델을 실제로 부른다. 접속 정보는 `.env`에 두고, 학생 폴더에는 값이 빈 `.env`를 넣는다.
- 촬영 대본은 덱의 문장을 옮기지 않고 지금 하는 행위를 말한다. 촬영에서 실제로 일어나지 않은 「예상과 다르게 됐을 때」의 가정 분기와 이론의 되풀이는 쓰지 않는다. 다만 통합반 VS Code 코딩 랩 대본은 2_기준대로 학생이 막히기 쉬운 지점의 대처를 더 풀어 설명한다(실패를 연출하지 않는다). 실제로 생긴 실수의 처리는 `문서/교재/기준_실습대본.md` 「길 뚫기와 실수 처리」를 따른다.
- 문장은 다 쓴 뒤 한 번만 윤문한다.
- ProcessGPT 시연(통합반 11일차, 실전반 8일차)은 학생이 따라 하는 가이드의 대상이 아니다.
- 공개 저장소다. 키, 계정, 사람 이름, 절대 경로를 넣지 않는다.

## 덱과 다른 사실을 찾았을 때

가이드만 맞추고 덱을 두지 않는다. 실라버스 실습 행의 순서로 덱도 함께 고친다.
