# HYD 실습 랩 · 실습 대본 · 가이드

실습 하나를 시작 → 수행 → 검증 → 저장 → 영상 · 가이드 전달까지 끝내는 절차다(기준_실습랩 L1). 규칙은 기준 문서에 있고, 이 문서는 순서 · 경로 · 명령과 기준 절 번호만 적는다(「기준_X Yn」은 `문서/교재/기준_X.md`의 Yn절, 「Yn-k」는 그 k항). 경로는 저장소 루트 기준이다.

## 먼저 읽는다

1. `문서/교재/기준_공통.md`와 `문서/교재/기준_실습랩.md` 끝까지.
2. L1 단계에서 부르는 기준을 그 단계에서 끝까지 읽는다: 대본 단계 `기준_대본.md`, 촬영 단계 `기준_촬영.md` + 그 도구의 `제작용/촬영/<도구>/촬영준비.md` + `제작용/촬영/README.md`, 가이드 단계 `기준_실습가이드.md`.
3. 가이드만 고치는 작업이면 `기준_공통.md` + `기준_실습가이드.md`(랩 · 촬영에서 받는 것은 그 머리말에 있다).
4. 본보기: 본보기 실습의 랩 · 대본(L0), 가이드(H0).
5. 새 코드 이름은 `제작용/기존제작/labs/STRUCTURE.md`(L4-6).

## 무엇이 어디 있나

| 무엇 | 위치 |
|---|---|
| 학생 랩 폴더 · ZIP · 가이드 | `산출물/<과정>/실습/NN회차/랩/<NN일차_실습M_이름>/` + 같은 이름 `.zip`. 새 가이드는 `guide.html`, 기존 `가이드.html` · `안내.html`은 이름 유지(기준_실습가이드 머리말) |
| 실습 대본 | `산출물/<과정>/실습/NN회차/대본/<번호>_실습_<이름>.md` |
| 회차 안내 | `산출물/<과정>/실습/NN회차/README.md` |
| 강사 참조 답안 · 기대 결과 | `제작용/실습시작/reference/…`(학생 폴더 밖, L4-4) |
| 실습 시작 도구 · 패키지 빌드 · 검사 | `제작용/실습시작/`(`실습시작.cmd`, `build_*.py`, `verify_packages.py`, `verify_reference.py`) |
| 이전 구조의 랩 원본 | `제작용/기존제작/labs/offline/`, `course/labs/offline/05-2-cause-agent/`(L4-6, 일괄 이전 안 함) |
| 촬영 도구 | `제작용/촬영/<도구>/촬영도구/`, 시간 계산 `제작용/촬영/시간계산.py` |
| 실습의 범위 | 실라버스 정본 `문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx`의 그 실습 행 |

## 실습 하나의 절차 (L1 순서)

각 단계는 앞 단계가 끝나야 넘어간다.

- [ ] **0. 시작 전(L1-0):** 기준 두 문서 통독, 본보기 실습 대본 하나 통독. 인계의 옛 완료 표시는 믿지 않고 실제 파일을 연다(기준_공통 G1-4).
- [ ] **1. 배정 시간과 실라버스 대조표(L1-1, 가장 먼저):** 그 행의 배정 시간을 적고, 상세 문장을 한 줄씩 떼어 표를 만든다.

  | 실라버스 상세 문장(원문 그대로) | 영상 구간 | 설명 · 화면 | 확인 방법 | 예상 분 |
  |---|---|---|---|---|

  합이 배정 시간을 채우는지 본다(기준_공통 G0 「범위와 시간」). 빈칸이 있으면 다음 단계로 가지 않는다. 숫자 · 부정 조건 · 예외 · 순서를 보존한다. 실라버스를 고칠 일이면 기준_공통 G0 「범위와 시간」 6~8.
- [ ] **2. 앞 이론 · 앞 포털 실습과 잇기(L1-2):** 그 회차 덱의 실습 간지 · 설명 장과 앞 이론 대본, 코딩 랩이면 앞 포털 화면에서 연결점을 찾는다(잇는 말은 기준_공통 G0).
- [ ] **3. 랩 강화(L2 · L3 · L4 · L5 · L6):** 종류와 목적(L2), 지킬 것과 판정(L3), 제공물 표와 제공 경계(L4-1 · L4-2), 판단이 갈리는 지점 하나 이상(L4-3), 강사 참조를 실제로 실행해 풀리는 과제임을 증명(L4-4), 시작본 · 연결 · 저장(L5), 과정 차이와 포털 경계(L6, 기준_공통 G2 표).
- [ ] **4. 구성안 사용자 확인(기준_공통 G4-3 예외):** 대조표 · 잇기 · 랩 구성을 묶은 구성안을 사용자에게 보여 확인받는다.
- [ ] **5. 대본(L1-4):** `기준_대본.md`를 끝까지 읽고 S6대로 쓴다(파일 꼴 S6-11). 덱의 문장을 옮기지 않고 지금 하는 행위를 말한다. 다 쓴 뒤 스스로 이어 읽으며 윤문한다(S2-4).
- [ ] **6. 대본 전문 사용자 확인(기준_공통 G4-3 예외).**
- [ ] **7. 분량(L1-5, 기준_공통 G0 「범위와 시간」):** 큐 원고로 계획 시간을 내고 배정과 비교한다. 모자라면 그 회차 범위 안에서 보강한다.

  ```bash
  python 제작용/촬영/시간계산.py estimate <cues.json> [--target 분]
  ```

- [ ] **8. 리허설 · 녹음 · 촬영(L1-6):** `기준_촬영.md` + 도구 촬영준비. 순서는 C2-1(준비 → 리허설 1회 → 수정 → 본 촬영 → 사진 추출 → 동기화), 리허설은 학생 경로 리허설 L7-1 ①을 겸함, 음성 비용은 먼저 알림(C4-2, 기준_공통 G4-4), 뚫린 길 재사용 · 안 뚫린 길 먼저(C2-3), 새 리듬 · 도구는 대표 구간 1~2분을 먼저 보여 확인(C2-2). 포털 화면은 hyd-portal-video. 찍은 뒤 `시간계산.py check`로 예상과 비교하고, 바뀐 대사 · 입력 · 순서를 C3-5 · 기준_공통 G4-9대로 맞춘다.
- [ ] **9. 검사(L1-7, L7):** 기술 검사(C6-1)와 따로 L7-1의 네 가지(학생 경로 리허설 · 검사기가 망가뜨린 입력을 잡음 · 강사 참조 실행 · 가이드만으로 받기 시험), 장난감 판정(L7-2), 수업 성립 판정(L7-3).
- [ ] **10. 가이드 · 패키지(L1-8):** `기준_실습가이드.md`를 끝까지 읽고 H2 구성 · H3 사진(본 촬영 화면에서, H3-2) · H4 문장. 정적 검사(H5-2) → 패키지 검사 → 받기 시험(H5-3). 랩 · 대본 · 가이드가 바뀌면 두 과정의 원본 · HTML · 학생 파일 · 이미지 · ZIP · README · 시작 도구 목록을 같은 판본으로(기준_공통 G4-9).

  ```bash
  python 제작용/실습시작/verify_packages.py      # 키 · 개인정보 · 강사 정답이 학생 패키지에 없는지(L8-4)
  ```

- [ ] **11. 게시(L1-8, 기준_촬영 C8):** 영상은 other-pc, 문서는 main, 노션 두 과정 회차 페이지에 영상 · 가이드 · ZIP 연결 후 실제로 열어 확인. 원격 push · 노션 게시는 사용자에게 묻고 한다(기준_공통 G4-3).
- [ ] **12. 완료 보고:** 아래 「보고」.

## 덱과 다른 사실을 찾았을 때

가이드만 맞추지 않고 같은 사실을 쓰는 덱 · 대본 · 랩 · 가이드 · 코드를 함께 고친다(기준_공통 G3-6). 덱은 hyd-course-deck 절차로 고친다.

## 보고

항목별로 요구 → 결과 → 근거를 대조해 적고, 상태어는 기준_공통 G4-7로 쓴다.

| 항목 | 적을 것 |
|---|---|
| 시간 | **배정 N분 / 계획(시간계산) N분 / 실측 N분**(기준_공통 G0 「범위와 시간」 5) — 이 숫자 없이 「끝났다」고 쓰지 않는다 |
| 대조표 | 빈칸 0, 실라버스 원문과 다시 맞춘 결과(L1-1) |
| 사용자 확인 | 구성안 · 대본 전문 확인 여부 |
| 랩 완성(L7-1) | ① 학생 경로 리허설 ② 검사기 고의 손상 ③ 강사 참조 실행 ④ 받기 시험 — 각각 상태어와 근거 |
| 수업 성립(L7-3) | 대조표 항목 반영 · 설명 충분 · 바이브 코딩이 실제로 보임 · 분량 |
| 기술 검사(C6-1) | 무엇을 어떻게 봤는지(간격 · 문장 수) |
| 게시 | 커밋 · 해시 · 링크 · 열어 본 확인, 남은 의존성 |
| 돌리지 못한 것 | `미확인`으로(L7-4) |
