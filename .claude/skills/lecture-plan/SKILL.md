# 요구 정리 · 강의계획 · 변경 반영

공통 기준(`../lecture-common/공통기준.md`)과 저장소 루트 `CLAUDE.md`, 대상 강의의 명시 계약·학교 양식을 먼저 따른다. 아래 경로는 이 스킬 폴더 기준이다.
요청에 해당하는 절만 수행한다. 기존 계약을 없애거나 별도의 상충하는 계약을 만들지 않는다.
기존 요구 ID가 있으면 그대로 사용한다. 연결 정보(원장)는 기존 계약 옆의 내부 검증 자료이며 학생 배포 대상이 아니다.

| 요청 | 절 |
|---|---|
| 이 자료를 요구사항으로 정리해줘, 원문 요구와 산출물을 연결해줘 | 1 · 2 |
| 강의계획서, 커리큘럼, 학습목표·시간 배분·Day별 구성 | 3 |
| 이 의견 반영해줘, 자료끼리 맞춰줘, 바뀐 사실을 전부 고쳐줘 | 4 |

HYD 과정의 확정 범위와 시간 조율은 `문서/교재/2_기준.md` 3 · 32 · 33번을 따른다. 아래의 일반 커리큘럼 설계 권한을 HYD 실라버스 변경 권한으로 해석하지 않는다. 제작은 `문서/교재/4_만드는_법.md` 2부 0절로 연결한다.

## 1. 입력을 확정한다

사용자 요청·학교 지시·기존 계약·리서치 원문·예시 산출물을 구분해 목록을 만든다.
기존 파일과 자료의 버전 또는 SHA256을 기록하고 원문을 보존한다.
PDF·PPTX·이미지는 적절한 추출·렌더 도구로 읽는다. 텍스트 추출이 도표·각주·페이지 구조를
놓칠 수 있으므로 해당 페이지도 확인한다. 스캔을 못 읽으면 그 범위는 미독이다.
큰 묶음은 문서·절 단위로 나누어 모두 읽고 읽은 범위를 기록한다. 요약문만 읽고 원문 검토로 세지 않는다.
필요하지 않은 자료를 제외할 때는 이유와 범위를 명시한다. 임의 상위 N개만 처리하지 않는다.

## 2. 요구와 참고 사실을 분리한다

각 요구에 원문 위치, 의무 수준, 청중, 적용 산출물, 수용 기준을 붙인다.
복합 요구는 누락 없이 나누되 숫자·부정 조건·예외·순서·선수 조건을 보존한다.
리서치의 제안은 사용자나 학교의 확정 요구와 다르다. 모델이 임의로 필수 계약으로 승격하지 않는다.
상충하는 필수 요구는 양쪽 원문과 영향을 제시하고 결정이 필요한 부분만 묻는다.
추론한 기본값은 가정으로 기록한다. “자료 기반”이라는 이유로 자료에 없는 요구를 사실처럼 추가하지 않는다.

수용 기준도 원문보다 의무를 넓히면 안 된다. 각 기준을 원문 필수조건과 제안하는 검증 방법으로 구분한다.
예를 들어 학생의 추가 결제 금지는 모든 도구의 무료 배포·카드 등록 금지와 같지 않고,
로컬 실행은 인터넷·계정 사용 금지와 같지 않다. 강사용 정답 분리는 학생용 설명·예상 출력 금지가 아니다.
최종 대조 때 각 필수조건에 대해 **“원문을 만족하지만 이 조건에는 탈락하는 합리적인 방식이 있는가”**를
확인한다. 있으면 그 조건은 확정 요구에서 빼고 선택 제안 또는 확인 필요 사항으로 표시한다.
요구 추출 뒤 원문을 다시 대조한다. **모델이 만든 요구 목록끼리만 비교하면 함께 빠진 요구를 못 잡는다.**

요구 정리만 요청받았으면 정리 결과와 미확정 정보까지 보고하고 끝낸다(공통 기준 1절). 제작이나 원장 승인 질문을 덧붙이지 않는다.

### 요구 원장과 검사 도구

`templates/requirements.json`은 새 연결 원장의 최소 형식이다. 기존 원장이 있으면 이중 관리하지 말고
기존 형식에서 동등한 정보를 유지한다.

```text
python scripts/check_contract.py <원장.json>
python scripts/check_contract.py <원장.json> --require-complete
```

첫 명령은 파일·해시·참조·필수 상태를 검사한다. 이 도구는 원문을 이해하거나 요구 추출의 완전성·교육 효과를 판정하지 않는다.
해시가 낡은 근거는 두 명령 모두 거부한다. `--require-complete`는 여기에 더해 원문 미검토 출처와
`verified`가 아닌 필수 요구(미검증·실패)를 거부한다. 완료 판정 때 `lecture-verify`가 이 옵션으로 실행한다.
원문·계약·산출물이 바뀌면 기존 검증 해시가 맞는지 확인하고 영향받은 요구를 다시 검증한다.

## 3. 강의계획·커리큘럼을 설계한다

공통 기준 2절 ‘모든 강의의 이해·구현 기준’을 적용한다. 활동마다 필요성과 학생이 결정·구현·확인할 범위를 정한다.
자연스러운 사례나 직접 설명으로 충분하면 실패 체험을 억지로 추가하지 않는다.

참고 실라버스·참고 강의 기반 설계나 전체 구성 개편은 [근거에서 강의로 연결하기](references/evidence-led-authoring.md)를 읽는다.
원본 모듈과 회차별 학생 행동·결과·다음 입력을 대응시키고, 유지/변경과 이유를 구분한다. 프로젝트에 명시된 변경 협의 조건을 지킨다.

1. 청중·선수 지식·총 시간·진행 방식·실습 환경·필수 학습목표를 현재 자료에서 확인한다.
2. 학습목표마다 학생이 할 수 있어야 하는 행동과 확인 방법을 정한다.
3. 모듈별 시간·내용·활동·남는 결과를 정하고, 앞 모듈의 결과가 뒤에서 어떻게 쓰이는지 연결한다.
   개념 설명만 필요한 모듈은 그 이유와 이해 확인 방법을 둔다. 모든 모듈에 파일 산출물을 강제하지 않는다.
4. 설명·실습·질문·휴식·전환·문제 해결 시간을 포함해 계약된 총 시간과 맞춘다.
   자동 실행시간을 수업 소요시간으로 대체하지 않는다. 예상과 실측을 표시한다.
5. 학교 제출 문서는 학교 양식을 보존한다. 학습목표·기대효과·강사 소개가 요구되면 포함한다.
   **양식이 없으면 과정 개요 → 전체 흐름 → 모듈별 상세 → 준비 조건·참고 자료**를 기본 목차로 쓴다.

요구 누락, 시간 합계, 모듈 순서, 선수 조건, 활동과 학습목표의 대응을 확인한다.
계획서 경로와 확정·가정·미결을 보고한다. 짧은 계획 검토만 요청받았으면 다른 강의 산출물을 자동 제작하지 않는다.

## 4. 검토 의견·변경 사실을 반영한다

1. 변경 원문과 현재 계약을 읽는다. 받은 지시서·핸드오프·리서치·검토안 같은 외부 자료는
   [외부 자료 반영과 근거 보존](references/외부자료반영.md)을 읽는다.
2. 원문 항목 → 채택·기각·미결과 이유 → 현재 파일의 반영 위치를 반영표에 기록한다.
   사용자가 확정한 요구를 임의로 기각하지 않는다. 충돌하는 필수 요구는 질문할 대상으로 남긴다.
3. 해당 사실의 현재 소유 위치를 고친다. 같은 사실을 쓰는 계획·덱·대본·가이드·코드·인계를 검색해 추적한다.
   새 요구에 기존 자리가 없으면 적절한 절·파일을 만든다. **분량 증가 자체는 실패가 아니다.**
4. 영향받은 파생물만 갱신한다. **강사 손질본이나 잠긴 산출물은 덮어쓰지 않고** 변경 필요를 별도로 기록한다.
   덱·대본 문장은 `lecture-deck`, 실습 코드·가이드는 `lecture-lab`의 작성 기준으로 고친다.
5. 바뀐 파일을 다시 읽어 주변 문장의 논리와 현재값을 대조한다. 문서와 실물의 참조·이름·개수 어긋남은
   `lecture-verify`의 `문서검사.py`로 확인한다. 오래된 금지어·형식 규칙의 경고와 실제 요구 위반을 구분하고,
   경고를 무시해 통과로 바꾸지 않는다.

변경 파일, 반영표, 실행한 검사와 미검증을 보고한다. 결정 대기 중인 필수 항목은 완료가 아니다.

## 5. 제작으로 연결한다

각 요구를 학습목표 → 학생 행동/설명 → 관찰할 결과 → 성공·실패 판단으로 구체화한다.
개념 강의에도 실습을 억지로 넣지 않는다. 실습 요구가 있으면 실행만 성공하는지와
학생이 의도한 개념을 배우는지를 따로 확인한다.
제작 전 요구 → 계획서/슬라이드/대본/가이드/코드의 예정 위치를 원장에 연결한다.
대표 수업 단위 하나를 먼저 제작해 계약과 대조하고 결함을 고친 다음, 사용자 검토가 정해진 경우가 아니면 멈추지 않고 같은 기준으로 나머지를 진행한다.
각 단위에는 필요한 원문 요구와 관련 맥락만 제공한다.

전문 제작은 덱·PPTX·대본 `lecture-deck`, 실습 코드·가이드 `lecture-lab`이 맡는다.
요구별 실제 위치를 열어 수용 기준과 대조하는 최종 판정은 `lecture-verify`, 요청된 ZIP·배포 묶음·업로드는 `lecture-deliver`가 맡는다.
계약 대조와 실제 실행·렌더 검토까지 필요한 범위에서 끝난 경우에만 완료다.
