# 근거에서 강의로 연결하기

참고 강의의 제작 방식을 가져오거나 강의를 크게 개편할 때 읽는다. 특정 강의의 시나리오·모델·플랫폼을 공통 규칙으로 만들지 않는다.

## 확장 전에 연결할 것

현재 사용자가 지정한 실라버스와 고정 조건을 확인한다. 오래된 초안과 새 기준이 다르면 새 기준을 식별하고, 프로젝트에서 요구한 변경 협의 절차를 따른다. 참고 자료의 완성도만으로 사실이나 교육 적합성을 인정하지 않는다.

기존 작업 문서에 다음 대응을 남긴다. 별도 관리 문서를 중복 생성할 필요는 없다.

| 원본 챕터/출처 | 이번 회차의 질문 | 필요한 선수 개념 | 학생이 할 행동 | 관찰/판단할 결과 | 다음 회차에서 쓰는 이유 | 변경과 근거 |
|---|---|---|---|---|---|---|

주제가 바뀌는 지점마다 앞의 결과가 다음 문제를 왜 만드는지 설명한다. 연결되지 않는 모듈은 기술 이름을 더해 덮지 말고 목적·순서·제외 여부를 검토한다. 확정된 일정과 시수를 내용 개편을 이유로 바꾸지 않는다.

## 사실과 제작물의 연결

수치·API·제품 동작·데이터 해석 등 검증 가능한 주장에는 원문 위치 또는 코드 경로/리비전과 실행 근거를 연결한다. 코드에서 확인한 동작, 직접 실행한 결과, 설명용 가정, 미확인 사항을 구분한다. 소스에 TTS 호출이 있다는 것과 실제 공개 영상에서 사용됐다는 것은 다른 주장이다. 영상의 일부 프레임만 봤다면 전편 검토로 기록하지 않는다.

대표 설명 단위를 먼저 만들어 실라버스 → 설명 → 실습 행동 → 결과 → 검증 기준이 이어지는지 확인한 뒤 확장한다. 원본의 오류·과장·장황함까지 복제하지 않는다.

## 초보자도 응용할 수 있는 구성

학생과 에이전트의 역할을 수업 계약에 맞춰 나눈다. 에이전트가 코드를 만드는 수업에서는 학생이 목적·입력·제약·성공 조건을 말하고 결과를 판단하게 한다. 코딩 문법 설명이나 직접 입력을 일괄 강제하지 않는다. SDD는 필요한 수준의 짧은 명세와 확인 기준으로 시작할 수 있다.

첫 예제는 안내와 관찰 기준을 충분히 주고, 다음 예제는 입력·조건 하나를 바꿔 차이를 설명하게 한다. 개인 PBL에서는 같은 스택으로 다른 문제를 정의하고 근거로 결과를 확인하게 한다. 난이도는 기능 수보다 학생이 스스로 결정하는 범위로 조절한다. 고급 기법은 해결할 실패와 비교 효과가 분명할 때 선택한다.

실습 가이드는 행동하는 지점에 이유·필요한 개념·기대 관찰·복구를 배치한다. 이론을 놓쳐도 이해되도록 쓰되 별도 이론 장을 길게 반복하지 않는다. 결석 복귀용 시작 상태가 요구되면 회차별 선행 결과와 복구본을 명시한다. 실패 예시는 실제 조건을 밝히며 원하는 결론을 위해 결과를 조작하지 않는다.

## 범위 유지

대본은 요청된 수업 방식에만 제작한다. 영상·음성은 명시 요청 때 공용 `demo-video` 스킬(세션에 있을 때)이 맡으며, 강의 검토 요청이 새 영상 제작을 뜻하지 않는다. 모델 선택과 유료 실행은 현재 사용자 지시·예산에 따르며 참고 저장소의 모델을 고정하지 않는다.
