# 덱 · PPTX

이론 교재 덱을 만든다. 덱 MD(화면 원고)가 원본이고, `scripts/deck2pptx.py`가 덱 MD를 읽어 고정된 디자인의 PPTX를 찍는다. 같은 덱 MD는 언제나 같은 디자인으로 나온다.

경로는 모두 저장소 루트 기준이다. 이 스킬의 상대 경로는 이 스킬 폴더 기준이다.

이 저장소의 HYD 과정 덱은 `hyd-course-deck` 스킬과 `문서/교재/2_기준.md`를 먼저 따른다. 이 스킬은 덱 MD의 형식과 생성 도구를 맡는다.

## 입력 확인

HYD 교육과정 덱은 만들기 전에 아래를 읽는다. 다른 강의면 그 강의의 제작 기준을 먼저 찾는다.

1. 기준 `문서/교재/2_기준.md` — 방향, 설명, 덱의 화면, 대본, 시간, 점검. 규칙은 거기에만 있다. 이 스킬 문서에 복사하지 않는다.
2. 기술사실표 `문서/교재/사실표/`의 넷(`통합반_01일차_…`, `통합반_02-04일차_…`, `통합반_05-08일차_…`, `통합반_09-11일차_기술사실표.md`) — 화면에 쓰는 사실의 근거. 확인하지 못한 것은 쓰지 않는다.
3. 실라버스 `문서/교재/실라버스/피지컬AI_실라버스_최종본.xlsx` — 행·상세 항목의 대응과 시간 조율은 `2_기준.md` 3 · 32 · 33번을 따른다.
4. 같은 그림체의 실제 덱 — `만들기/decks/integrated/sample/샘플.md`, `만들기/decks/integrated/day01/통합반_01일차.md`. 옛 발췌 예시를 현재 내용·구성의 기준으로 쓰지 않는다.

## 작업

1. **장 목록과 설명 전개를 맞춘다.** HYD는 `4_만드는_법.md` 2부 0절의 순서를 따른다. 메시지·화면 근거와 대본에서 풀 순서를 함께 확인한 뒤 장 유형을 고른다.
2. **덱 MD를 쓴다.** 장마다 `### 화면 내용` / `### 화면 구성` / `### 제작 기준`을 둔다. 스크립트는 화면 내용만 읽는다. 유형, 칸, 요소 수, 아이콘 규칙은 [덱 MD → PPTX 형식](references/덱MD-PPTX형식.md)을 따른다. 제작 기준 칸에는 그 장의 사실이 사실표 어느 절에 근거하는지 적는다.
3. **삽화와 그래프를 그린다.** 직접 그린 SVG(글자 없음)와 실제 데이터 그래프를 덱 폴더의 `figures/`에 그리는 스크립트와 함께 둔다. 라벨은 덱 MD의 요소로 얹는다.
4. **아이콘을 고른다.** `scripts/find_icon.py <낱말> [--preview <png>]`로 찾는다(한국어 낱말도 된다).
5. **빌드한다.**
   ```bash
   uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py <덱.md> <출력.pptx> [--render <새 PNG 폴더>]
   ```
   `--check`(파일을 쓰지 않고 검사만)를 먼저 돌려도 된다. 스크립트가 멈추면 문구를 다듬거나 장을 나누거나 유형을 바꾼다. 도구의 한계는 우회하지 않고 도구를 고친다. 명령의 전체와 도구 제약은 `문서/교재/4_만드는_법.md` 1부다.
6. **렌더해 본다.** `--render`는 LibreOffice(soffice)와 pdftoppm이 필요하고 한 번에 하나씩 돈다. 렌더 폴더는 새 이름으로 쓴다. 묶음 그림은 `만들기/tools/deck/시트.py`로 만든다.

## 검증

`문서/교재/2_기준.md` 9절에 따라 자동 검사·사실·화면·낭독 전개를 확인한다. 넘침·라벨 간격은 `--check`로 검사한다. 검사 결과의 적용 범위와 렌더하지 못한 환경을 보고한다.

## 산출물과 미결

덱 MD, PPTX, `figures/`의 실제 경로와 최종 장수를 전달한다. 못 본 장, 확인하지 못해 뺀 사실, 실라버스와 달라 구현을 따른 곳을 적는다. 잠긴 파일과 받은 예시는 보존한다. 승인된 원본의 갱신 여부는 최신 요청과 `4_만드는_법.md` 1부를 따른다. 기본 `pptx` 스킬은 기존 PPTX를 읽거나 국소 수정할 때 쓴다.
