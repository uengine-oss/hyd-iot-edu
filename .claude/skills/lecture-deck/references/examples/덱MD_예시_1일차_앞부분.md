- 요소:

  2. **자신의 언어로 다시 쓴 기록** | 자료를 보지 않고 개념을 직접 서술한 기록이다 / 서술이 끊기는 자리에서 모르는 부분이 드러난다 / 그 부분을 보완해 고쳐 쓴 문장은 다시 설명할 수 있다 / 분류와 이해도를 함께 적어 두어 다시 찾아 쓴다 | 재사용하는 자산

## SLIDE 12 — 템플릿: 모든 기록이 같은 틀을 갖게 하는 양식
### 화면 내용
- 유형: 코드
- 메시지: 템플릿은 새 항목을 만들 때 본문에 미리 채워지는 양식으로, 기록의 형식을 하나로 맞춘다.
- 코드: # 개념 이름 / (자료를 보지 않고 자신의 문장으로 쓴 설명) /  / # 이 시스템에서의 쓰임 / (어느 구성요소가 이 일을 하는가) /  / # 다음에 확인할 것 / [ ] 설명이 끊긴 자리 / [ ] 답에서 새로 나온 낯선 용어
- 요소:
  1. 개념별 제목 | 개념 하나에 제목 하나를 둔다. 제목이 나중에 검색어가 된다.
  2. 다음에 확인할 것 | 막힌 자리를 체크 목록으로 남긴다. 해결해도 지우지 않아 진행이 기록된다.
  3. 기본 템플릿 | 기본으로 지정해 두면 어느 보기에서 항목을 만들어도 같은 양식이 채워진다.
- 노트: 템플릿은 새 항목을 만들 때 본문에 미리 채워지는 양식입니다. 왼쪽이 이 과정에서 쓸 양식의 한 예입니다. 양식을 한번 정하면 모든 기록에 같은 틀을 씁니다.
### 화면 구성
왼쪽 양식 예, 오른쪽 짚을 점 셋.
### 제작 기준

## SLIDE 14 — 공유와 게시: 공개 범위의 차이
### 화면 내용
- 유형: 비교
- 아이콘: lock, world
- 메시지: 게시한 페이지는 링크를 아는 누구에게나 보이므로 공개하기 전에 내용의 범위를 확인한다.
- 요소:
  1. 공유 | 지정한 사용자에게만 열람 · 편집 권한을 준다 / 권한을 받은 계정으로 로그인해야 보인다 / 함께 작업하는 사람과 쓸 때 고른다 | 지정한 사람만
  2. **게시** | 페이지를 웹 주소로 공개한다 / 로그인 없이 링크만으로 열린다 / 페이지 안의 데이터베이스 항목도 함께 보인다 / 개인 정보, 계정, 접속 키는 넣지 않는다 | 링크를 아는 누구나
- 노트: 공개 방식은 둘입니다. 공유는 지정한 사람에게만 권한을 주고, 게시는 링크만 있으면 누구나 볼 수 있게 합니다. 게시하면 페이지 안의 데이터베이스 항목도 함께 보이므로 접속 키와 계정 정보는 노트에 적지 않습니다.
### 제작 기준
