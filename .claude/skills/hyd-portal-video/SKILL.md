# HYD 포털 실습 영상

포털(`http://127.0.0.1:8088`)을 헤드리스 Chromium으로 조작하며 녹화하고, 강사 복제 음성을 입혀 영상으로 만든 뒤 검증 · 게시 · 노션 연결까지 하는 절차다. 규칙은 기준 문서에, 포털의 순서 · 명령 · 값 · 함정은 `제작용/촬영/포털/촬영준비.md` 하나에 있다. 이 스킬은 그 문서를 쓰는 순서 · 멈출 곳과 기준 절 번호만 적는다(「기준_X Yn」은 `문서/교재/기준_X.md`의 Yn절, 「Yn-k」는 그 k항). 도구는 `제작용/촬영/포털/촬영도구/`에 있고 명령은 그 폴더에서 돌린다.

## 먼저 읽는다

1. `문서/교재/기준_공통.md`와 `문서/교재/기준_촬영.md` 끝까지(랩 · 대본에서 받는 것과 가이드가 가져가는 것은 그 머리말에 있다).
2. `제작용/촬영/포털/촬영준비.md` 전체. 0절이 지금 있는 영상 · 노션 위치 · 남은 확인, 1절이 처음부터 다시 찍는 순서, 4절이 함정, 6절이 로컬 ego로 찍는 지식 지도 구간이다(기준_촬영 C5 머리말).
3. 여러 도구 공통 구현 · 설정값(음성 설정, 구간 기록 파일, 게시 명령): `제작용/촬영/README.md`.
4. 찍을 원고: `제작용/촬영/포털/*_큐.json`과 그 녹화 모듈 `촬영도구/segs/*.mjs`. 새 영상이면 기존 원고를 본보기로 쓴다.
5. 회차 대본 `산출물/<과정>/실습/NN회차/대본/`. 과정별로 찍을지 한 편을 두 과정이 쓸지는 기준_공통 G2 표 「도구 실습 영상」 · 기준_촬영 C8-2.

## 시작 전 확인 — 하나라도 아니면 멈추고 알린다

| 확인 | 어떻게 |
|---|---|
| 스택 · 워커 · 녹화 브라우저가 떠 있고 other-pc가 origin/main을 포함한다 | `./stack.sh check` 모두 ✓. 아니면 `./stack.sh up`(main을 새로 병합했으면 `up --build`) |
| 처음부터 찍을 데이터 상태 | `stack.sh` 마지막 줄 「처리 건 0 · 보관 원문 0」. 아니면 초기화가 필요하다 — 볼륨 삭제 · DB 재설정이므로 실제 동작 이름으로 사용자에게 묻고 허락을 받는다(기준_공통 G4-3, 촬영준비 1절 2번) |
| 음성 키 | 사용자가 올린 키 파일. 값을 출력 · 저장 · 커밋하지 않는다(`tr -d`로 환경변수에 바로 넣는다, 기준_촬영 C4-3) |
| 사용자가 범위를 정했다 | 어떤 영상(새로 · 다시 · 합치기 · 검수만)인지. 검수만이면 고치지 않고 보고한다(기준_공통 G4-1) |
| 음성 비용 | 글자 수 · 크레딧 견적을 먼저 알린다(기준_촬영 C4-2) |

## 작업

촬영준비 1절 순서를 그대로 따른다. 판단이 필요한 곳과 기준 절:

1. **길뚫기**(기준_촬영 C2-3): 상태를 바꾸지 않는 것만 한다 — `look.mjs`(다른 메뉴 보고 되돌림), `dry.mjs`(대상 시험). 미리보기 · 추출 요청 · 적재 · 결함 주입 · 승인 · 「나」 바꾸기는 되돌릴 수 없으니 그 뒤 화면은 코드(`it/portal/www/*.js`) · API로 미리 알고, 그 조작 직후에 구간을 끊어 다음 구간 전에 화면을 본다.
2. **대본**: AI 판단 결과는 미리 쓰지 않고 화면에 나온 뒤 쓴다(기준_공통 G3-8), 제작 말투 · 시나리오 기호 금지(S2-2). 승인 구간은 이름 없이 짧게, 이름과 근거는 승인 뒤 화면을 읽고 쓴다.
3. **기다리는 일은 녹화 밖으로**(기준_촬영 C1-5). 승인 요청은 20배속에서 30초 안에 승인해야 하므로 승인 구간은 녹화 전 준비가 승인 버튼을 기다렸다 바로 녹화를 시작한다.
4. **실패한 구간만 다시**(기준_촬영 C1-3 · C1-4). 되돌릴 수 없는 조작을 이미 했으면 그 뒤 상태에서 이어 찍도록 그 구간의 첫 조작을 바꾼다(처음부터 다시 하려면 초기화 허락).
5. **화면과 다른 대사**는 그 문장만 고쳐 다시 녹음한다(기준_촬영 C4-4, 구간 길이 안, `encode.py`가 자막을 맞춘다).
6. **AI 응답 재생**으로 찍었으면 재생 모드임을 첫머리에 한 번 밝힌다(기준_공통 G3-3).

## 검증 — 게시 전에 모두, 결과를 `.evidence/`에 (기준_촬영 C6-1)

- `verify.py <영상> <자막>`: 길이 · 겹침 · 무음 · 최고점 · 검은 화면 + 문장마다 한 장면. 실패 0.
- `scenes.py <영상> 2`: 끝까지 2~3초 간격 장면을 **모두** 눈으로 본다. 의심 구간은 0.5초 간격으로.
- `listen.py <영상> <자막>`: 받아쓰기 대조(크레딧 사용). 「확인할 것」은 매번 눈으로 본다.
- 영상을 이었으면(`join.py`) 합본에 셋을 다시 하고 이음매 앞뒤 프레임을 본다(C3-4).
- `cut.py`로 자르는 것은 기준이 허용하는 자리만이다 — 설치 구간의 대기(C1-12), 실패 조각(C3-3). 자른 뒤 `verify.py`를 다시 하고 자른 자리 앞뒤를 0.5초 간격으로 본다. 장(chapter)이 든 영상은 잇거나 자른 뒤 `ffprobe -show_chapters`로 장 시간 · 이름을 확인한다.

「검증했다」고 보고할 때 무엇을 어떻게 봤는지(간격 · 문장 수 · 남긴 관찰)를 함께 쓴다(C6-4). 귀로 듣는 판정은 사용자 재생 확인으로 남긴다. 기술 검사는 완료가 아니다 — 수업 성립은 따로 판정한다(C6-3, 기준_공통 G0 「범위와 시간」).

## 게시 · 노션 · 기록 (기준_촬영 C8 — 원격 push · 노션 게시는 사용자에게 묻고 한다)

- 영상 · 자막은 other-pc에만. 커밋 전 `git fetch origin other-pc && git merge origin/other-pc`, 경로 지정 커밋, 올린 뒤 raw 링크 200 · 크기 일치(C8-1 · C8-2). 이름 규칙 · 노션 블록 모양은 촬영준비 1절 10~11번.
- 노션은 두 과정의 그 회차 페이지(ID는 촬영준비 0절)에 같은 모양으로 넣고 다시 fetch해 확인한다(C8-3 · C8-4).
- 끝나면 촬영준비 0절 표와 `course/videos/README.md`를 고치고, 진행 기록은 로컬 `.evidence/기록/`에 남긴다. 새 함정은 촬영준비 4절에 한 줄로 더한다(C3-6).

## 보고

항목별로 요구 → 결과 → 근거를 대조해 적는다: 산출물 `course/videos/{통합반,실전반}/<과정>_<NN>회차_<번호>_실습_<이름>.mp4`(+ 자막), 노션 칸, `.evidence/portal-video-<날짜>/`의 녹화 · 검증 근거, 검증 항목별 관찰, 게시 커밋 · 해시. 미결로 남기는 것: 사용자 재생 확인, 다른 세션 조각의 관찰 사항(고치지 않고 보고), 초기화가 필요한데 허락이 없는 다시 찍기. 상태어는 기준_공통 G4-7.
