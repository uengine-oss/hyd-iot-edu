# HYD 포털 실습 영상

포털(`http://127.0.0.1:8088`)을 헤드리스 Chromium으로 조작하며 녹화하고, 안치윤 복제 음성을 입혀 영상으로 만든 뒤 검증 · 게시 · 노션 연결까지 하는 절차다. 순서 · 명령 · 값 · 함정의 정본은 `제작용/촬영/포털/촬영준비.md` 하나다. 이 스킬은 그 문서를 어떤 순서로 쓰는지와 멈출 곳만 적는다. 도구는 `제작용/촬영/포털/촬영도구/`에 있고 명령은 그 폴더에서 돌린다.

## 먼저 읽는다

1. `제작용/촬영/포털/촬영준비.md` 전체. 0절이 지금 있는 영상 · 노션 위치 · 남은 확인, 1절이 처음부터 다시 찍는 순서, 4절이 함정이다.
2. `문서/교재/방법_ego_실습영상_촬영.md` 1절(모든 실습 영상 공통 원칙). 포털에만 다른 것은 촬영준비가 가진다.
3. 찍을 원고: `제작용/촬영/포털/*_큐.json`과 그 녹화 모듈 `촬영도구/segs/*.mjs`. 새 영상이면 기존 원고를 본보기로 쓴다.
4. 회차 대본 · 실라버스는 `문서/교재/2_기준.md` 「두 과정의 공통 범위와 차이」와 `산출물/<과정>/실습/NN회차/대본/`. 1회차 실습은 두 과정 공통(같은 파일 두 벌).

## 시작 전 확인 — 하나라도 아니면 멈추고 알린다

| 확인 | 어떻게 |
|---|---|
| 스택 · 워커 · 녹화 브라우저가 떠 있고 other-pc가 origin/main을 포함한다 | `./stack.sh check` 모두 ✓. 아니면 `./stack.sh up`(main을 새로 병합했으면 `up --build`) |
| 처음부터 찍을 데이터 상태 | `stack.sh` 마지막 줄 「처리 건 0 · 보관 원문 0」. 아니면 초기화가 필요하다 — **볼륨 삭제 · DB 재설정이라 사용자에게 실제 동작 이름으로 묻고 허락을 받는다**(촬영준비 1절 2번). 묻지 않고 지우지 않는다 |
| 음성 키 | 사용자가 올린 키 파일. 값을 출력 · 저장 · 커밋하지 않는다(`tr -d` 로 환경변수에 바로 넣는다) |
| 사용자가 범위를 정했다 | 어떤 영상(새로 · 다시 · 합치기 · 검수만)인지. 검수만이면 고치지 않고 보고한다 |

## 작업

촬영준비 1절 순서를 그대로 따른다. 판단이 필요한 곳만 여기 적는다.

1. **길뚫기는 상태를 바꾸지 않는 것만** 한다: `look.mjs`(다른 메뉴 보고 되돌림), `dry.mjs`(대상 시험). 미리보기 · 추출 요청 · 적재 · 결함 주입 · 승인 · 「나」 바꾸기는 되돌릴 수 없다 — 그 뒤 화면은 코드(`it/portal/www/*.js`) · API로 미리 알고, 그 조작 직후에 구간을 끊어 다음 구간 전에 화면을 본다.
2. **대본**에 AI 판단 결과(추천안 이름 · 점수 · 순위)를 미리 쓰지 않는다. 실행마다 다시 계산된다. 승인 구간은 이름 없이 짧게, 이름과 근거는 승인 뒤 화면을 읽고 쓴다. 시나리오 기호(A · B · C)는 말하지 않는다.
3. **기다리는 일**(에이전트 추출 · 판단)은 녹화 밖으로 뺀다. 승인 요청은 20배속 30초 안에 승인해야 하므로 승인 구간은 녹화 전 준비가 승인 버튼을 기다렸다 바로 녹화를 시작한다.
4. 녹화가 중간에 실패하면 실패한 구간만 다시 찍는다. 되돌릴 수 없는 조작을 이미 했으면 그 뒤 상태에서 이어 찍도록 그 구간의 첫 조작을 바꾼다(처음부터 다시 하려면 초기화 허락).
5. 녹화 뒤 화면과 다른 대사를 찾으면 그 문장만 고쳐 다시 녹음한다(구간 길이 안, `encode.py`가 자막을 맞춘다).

## 검증 — 게시 전에 셋 다, 결과를 `.evidence/`에

- `verify.py <영상> <자막>`: 길이 · 겹침 · 무음 · 최고점 · 검은 화면 + 문장마다 한 장면. 실패 0이어야 한다.
- `scenes.py <영상> 2`: 끝까지 2~3초 간격 장면을 **모두** 눈으로 본다. 의심 구간은 0.5초 간격으로 다시 본다.
- `listen.py <영상> <자막>`: 받아쓰기로 빠진 · 잘린 · 잘못 읽은 말을 찾는다(크레딧 사용). 「확인할 것」은 매번 눈으로 본다.
- 영상을 이었으면(`join.py`) 합본에 셋을 다시 하고 이음매 그림을 본다.
- 말 없는 구간을 잘라 냈으면(`cut.py`) `verify.py`를 다시 하고 자른 자리 앞뒤를 0.5초 간격으로 본다. 장(chapter)이 든 영상은 잇거나 자른 뒤 `ffprobe -show_chapters`로 장 시간 · 이름을 확인한다.

「검증했다」고 보고할 때 무엇을 어떻게 봤는지(간격 · 문장 수 · 남긴 관찰)를 함께 쓴다. 귀로 듣는 판정은 사용자 재생 확인으로 남긴다.

## 게시 · 노션 · 기록

- 영상 · 자막은 other-pc에만(main에 올리지 않는다), 커밋 전 `git fetch origin other-pc && git merge origin/other-pc`, 경로 지정 커밋, 올린 뒤 raw 링크 200 · 크기 일치. 이름 규칙 · 노션 블록 모양은 촬영준비 1절 10~11번.
- 노션은 통합반 · 실전반 1회차 페이지(ID는 촬영준비 0절)에 같은 모양으로 넣고 다시 fetch해 확인한다.
- 끝나면 촬영준비 0절 표, `course/videos/README.md`, `문서/교재/3_현황.md` · `6_남은_일.md`를 고친다. 새 함정은 촬영준비 4절에 한 줄로 더한다.

## 산출물과 미결

산출물: `course/videos/{통합반,실전반}/<과정>_<NN>회차_<번호>_실습_<이름>.mp4`(+ 자막), 노션 PRACTICE 칸, `.evidence/portal-video-<날짜>/`의 녹화 · 검증 근거. 미결로 남기는 것: 사용자 재생 확인, 다른 세션 조각의 관찰 사항(고치지 않고 보고), 초기화가 필요한데 허락이 없는 다시 찍기.
