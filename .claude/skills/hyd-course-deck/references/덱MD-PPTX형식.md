# 덱 MD → PPTX 형식

덱 MD 한 개를 `scripts/deck2pptx.py`에 넣으면 같은 디자인의 PPTX가 나온다. 색, 글꼴, 배치는 스크립트가 정하고 덱 MD는 **장 유형, 화면 문구, 아이콘**만 정한다. 실제 모습은 [1일차 앞부분 예시](examples/덱MD_예시_1일차_앞부분.md)와 `workspace/강의제작/제작도구/온라인/decks/integrated/` 아래 덱을 본다. 규칙을 어기면 스크립트가 장 번호와 칸 이름을 찍고 실패한다.

## 장의 모양

장마다 `### 화면 내용`, `### 화면 구성`, `### 제작 기준`을 둔다. 스크립트는 **`### 화면 내용`만 읽는다.** 나머지 둘(배치 지시, 사실 근거)은 화면에 나가지 않는다.

```markdown
## SLIDE 12 — MQTT: 발행 · 구독 기반의 경량 메시징 프로토콜
### 화면 내용
- 유형: 풀이
- 메시지: MQTT는 브로커를 사이에 두고 발행자와 구독자를 분리하여 **비동기 전달**을 지원하는 프로토콜이다.
- 요소:
  1. **MQTT** | TCP/IP 위에서 동작하는 발행 · 구독 방식의 메시징 프로토콜이다. / 헤더가 작아 불안정한 현장 네트워크에 적합하다. | Message Queuing Telemetry Transport
  2. 브로커 | 발행자가 보낸 메시지를 토픽 기준으로 구독자에게 전달하는 중개 서버이다. | Broker
- 노트: (강사가 읽는 말. 한 줄로 쓴다)
### 화면 구성
(배치와 관계 지시)
### 제작 기준
(근거 사실표 절, 저장소 사실과 일반 지식의 구분, 오해 금지)
```

- `## SLIDE NN — 제목`: 그 장이 다루는 기술적 주제. **한 줄**에 들어가야 한다(제목 28pt). 첫 장은 반드시 표지다.
- 화면 내용의 줄은 `- 칸: 값`이다. 읽을 수 없는 줄, 허용되지 않는 칸은 실패한다. 허용 칸: `유형` `메시지` `노트` `요소` `아이콘` `그림` `문장` `기관` `과정` `부제` `번호` `구분` `머리` `영역` `연결` `사이` `코드` `라벨`. 옛 칸 `핵심` `설명` `다음` `현재`는 쓰지 않으며 쓰면 실패한다.
- `메시지`: 본문 장의 거버닝 메시지. **한 줄, 완결된 한 문장.** 두 문장을 이으면 실패한다. `**굵게**`는 강조색이다. 본문 유형(표지, 목차, 간지를 뺀 모든 유형)은 메시지가 필수다.
- `노트`: 발표자 노트. 덱 MD에서는 한 줄로 쓰고, ` / `(앞뒤 공백)가 PPTX 노트 안의 줄바꿈이 된다. 화면에는 나가지 않는다. HYD 교재의 노트 내용 기준은 `workspace/강의제작/지침/덱.md` D-113 ~ D-124.
- `요소`: 아래 줄들이 요소다(`1.` 번호나 `-`로 시작). 한 줄은 `칸1 | 칸2 | 칸3`이고 칸은 **최대 3개**다. 구분자 `|`는 앞을 띄운다(앞에 공백, 뒤에 공백이나 줄 끝). 빈 칸도 칸이다(`라벨 | | 40,20`). 칸2 안의 ` / `는 줄바꿈이다. 칸1 전체를 `**`로 감싸면 강조 칸(하늘색)이다.
- 글자 수 한도는 없다. 상자마다 넘침을 글자 폭으로 추정해 멈추므로, 멈추면 문구를 다듬거나 장을 나눈다.
- 화면 문구(노트 제외)에 유니코드 빼기표(−, U+2212)가 있으면 실패한다. 하이픈(-)을 쓴다.

## 장 유형

요소 수가 범위를 벗어나면 실패한다. 본문 영역은 세로 약 5.2인치다.

| 유형 | 언제 | 칸과 요소 |
|---|---|---|
| 표지 | 덱 첫 장 | `기관:` `과정:`(필수) `부제:` `아이콘:` 1~3개. 장 제목은 ` / `로 줄을 끊는다. uEngine 로고는 자동 |
| 목차 | 덱에 한 번 | 요소 2~9: `단원명` 또는 `단원명 \| 구분` |
| 간지 | 단원이 바뀔 때, 퀴즈 앞 | `번호:` `구분:` `부제:` 모두 생략 가능. 제목은 ` / `로 줄을 끊는다. 연한 배경. 좌측 상단에 표지의 기관명이 자동으로 들어간다 |
| 풀이 | 용어와 개념의 정의 | 요소 2~6: `용어 \| 설명(여러 줄) \| 정식 명칭` |
| 구조 | 구성요소와 흐름(아키텍처) | `영역: A \| B \| C`(필수), 요소 2~12: `이름 \| 설명 \| 영역`, `연결: A > B : 라벨 ; C => D : 라벨` |
| 표 | 대상별 속성, 대응 | `머리: A \| B \| C`(생략 가능), 요소 2~9: `라벨 \| 값 \| 상태` |
| 코드 | 메시지, 데이터, 질의의 실제 형식 | `코드:`(필수), 요소 0~4: `짚을 점 \| 설명` |
| 흐름 | 순서와 인과가 있는 2~6단계 | 요소 2~6: `제목 \| 설명(여러 줄)` |
| 단계 | 번호 붙은 절차, 상태 전이 | 요소 3~5: `제목 \| 설명(여러 줄)` |
| 비교 | 두 가지를 맞세움 | 요소 **정확히 2개**: `제목 \| 줄 / 줄 / 줄 \| 판정` |
| 카드 | 대등한 항목 | 요소 2~4: `제목 \| 줄 / 줄 \| 꼬리표` |
| 강조 | 한 문장을 크게 | `문장:`(필수, ` / `로 줄을 끊는다), 보조 요소 0~3 |
| 그림 | 실제 화면, 그래프(래스터 또는 SVG) | `그림:`(필수), 오른쪽 짚을 점 요소 0~4: `제목 \| 설명` |
| 삽화 | 직접 그린 그림 위에 라벨 | `그림:`(필수), `라벨: 큰`(생략 가능), 요소 0~16: `라벨 \| 설명 \| x,y[,폭]` |
| 파이프라인 | 한 방향으로 지나가는 경로 | 요소 3~7: `이름 \| 설명 \| 영역`, `아이콘:` 요소 수만큼(필수), `영역:` `사이:`(생략 가능) |
| 관계도 | 노드와 이름 붙은 관계 | 요소 2~8: `이름 \| 종류 \| x,y`, `연결:`(필수), `아이콘:` 요소 수만큼 또는 없음 |
| 문답 | 퀴즈 한 문항 | `메시지:`(상황) `문장:`(물음, 필수), 보기 요소 2~5: `보기 \| 덧붙임` |

그림 파일은 덱 MD 위치 기준 상대 경로이고 없으면 실패한다. SVG는 PNG로 바꿔 넣는다.

### 아이콘

`아이콘:`은 이름을 쉼표로 요소 순서대로 적는다. 이름은 `assets/icons/tabler-outline/`의 파일 이름이며 `scripts/find_icon.py`로 찾는다.

| 유형 | `아이콘:` 개수 |
|---|---|
| 표지 | 1~3개 |
| 파이프라인 | 요소 수와 같게(필수) |
| 흐름, 카드, 비교, 표, 단계, 강조, 관계도 | 요소 수와 같게 또는 0개 |
| 그 밖의 모든 유형(목차, 간지, 풀이, 구조, 코드, 그림, 삽화, 문답) | 0개 |

내용이 많은 장은 아이콘 없이 글에 자리를 준다. 카드 · 단계 · 강조는 글이 적으면 아래가 비어 보이므로, 내용이 많은 주제는 풀이 · 표 · 구조 · 코드 · 비교를 먼저 고려한다.

### 구조

- `영역`은 왼쪽에서 오른쪽으로 놓이는 띠(예: `OT | DMZ | IT`)다. 요소의 셋째 칸이 그 상자가 들어갈 영역이며 `영역:`에 있어야 한다. 같은 영역의 상자는 적은 순서대로 위에서 아래로 놓인다.
- `>`는 데이터 흐름(남색 실선), `=>`는 명령 흐름(파란 점선)이다. 기호 앞뒤를 띄우고, 이름은 요소 이름과 같아야 한다. 라벨에는 실제 토픽, 프로토콜 이름을 쓴다.
- 영역이 다른 상자 사이는 가로 화살표다. **수평에 가깝게 되도록** 영역마다 상자 순서와 개수를 맞춘다(대각선이 교차하면 읽기 어렵다). 한 장에 상자 7~9개, 화살표 6~8개를 넘기지 않는다. 넘으면 장을 나눈다(전체 → 부분).

### 파이프라인

- 요소가 한 줄의 관 위에 왼쪽에서 오른쪽으로 놓인 원(아이콘)이 된다. 값이나 명령이 한 방향으로 지나가는 경로에만 쓴다. 갈라지거나 되돌아오는 경로는 삽화, 구조, 관계도를 쓴다.
- `영역:`을 주면 요소의 셋째 칸이 영역이 되어 같은 영역의 요소를 바탕 띠로 묶는다. 같은 영역의 요소는 이어서 적는다(끊겼다 다시 나오면 실패).
- `사이: 라벨 | 라벨`은 이웃한 두 요소 사이의 관 위에 놓이는 짧은 낱말이다. 개수는 요소 수 - 1이어야 하며 빈 칸은 허용된다. 요소가 6개 이상이면 글자가 한 단계 작아지므로 설명은 두 줄 안으로 쓴다.

### 관계도

- 요소가 원(노드), `연결:`이 이름 붙은 화살표다(`>` 실선, `=>` 점선). 화살표의 방향은 관계 이름의 주어에서 목적어로 향하게 적는다.
- 셋째 칸 `x,y`는 본문 영역의 왼쪽 위를 0,0, 오른쪽 아래를 100,100으로 한 **원 중심**이다. 두 원이 너무 가까우면(화살표와 라벨이 들어갈 틈이 없으면) 실패하므로 좌표를 벌린다. 노드가 6개 이상이면 원이 작아진다.
- 노드 안에는 이름과 종류 한두 줄만 넣는다. 영문 관계 이름(`HAS_COMPONENT` 등)은 한 줄에 들어간다. 대상이 무엇인지 그림으로 보여야 하는 장은 삽화를 쓴다.

### 삽화

- 그림을 본문 영역에 깔고 요소를 그 위의 **고칠 수 있는 글상자**로 얹는다. 그림 안에는 글자를 넣지 않는다.
- 셋째 칸 `x,y[,폭]`: 그림 상자의 왼쪽 위를 0,0, 오른쪽 아래를 100,100으로 한 글상자의 **가운데 위** 지점이고, 폭은 그림 폭의 %(기본 16)다. 설명이 없으면 `라벨 \| \| 40,20`. 라벨은 가운데 정렬뿐이다.
- `라벨: 큰`은 라벨 글자를 16pt, 13pt로 키운다(기본 13.5pt, 11pt). 라벨이 적고 그림이 큰 장, 강의실 화면에서 설명 줄까지 읽혀야 하는 장에 쓴다. 라벨이 열 개 안팎인 그림은 기본 크기로 둔다.

### 코드

- `코드:` 안의 ` / `(앞뒤 공백)는 줄바꿈이고, 글자 그대로의 빗금은 `\/`로 쓴다. 빗금 사이를 띄워 한 줄로 보이려면 `plant \/ hyd01 \/ tag \/ TS1`처럼 적는다.
- 영문과 숫자는 고정폭 글꼴(Consolas)로, 한글과 ℃ · 화살표 같은 기호는 덱 글꼴로 그려진다. 코드 칸에 단위와 기호를 쓸 수 있다.
- 오른쪽 요소는 코드의 짚을 점이다.

### 배치

- 카드, 비교, 코드 상자는 **내용 높이에 맞춰** 본문 영역의 세로 가운데에 놓인다. 흐름, 단계, 파이프라인, 풀이, 표, 강조도 세로 가운데로 놓인다. 내용이 적어도 빈 칸을 늘이지 않는다.
- 카드와 비교의 꼬리표(셋째 칸)가 담긴 칸보다 넓으면 밖으로 넘치므로 실패한다. 문구를 줄인다.
- 표의 셋째 칸(상태)은 ` / `로 줄을 바꾸며 3줄까지 허용한다. 비교의 `판정`과 풀이의 정식 명칭도 꼬리 칸이다.
- 퀴즈 번호는 보기 순서대로 1부터 붙는다. 정답과 판단 기준은 뒤의 표 장 하나에 모은다.

## 자주 걸린 제약과 수정 요령

교재 기준(`workspace/강의제작/지침/덱.md`)에서 옮겨 온 도구 쪽 세부다. 도구의 한계를 만나면 우회하지 않고 도구를 고친다. 고친 뒤에는 같은 빌더를 쓰는 덱 가운데 영향받는 유형이 든 덱을 렌더해 영향 범위를 기록한다.

| 제약 | 내용 | 걸렸을 때 |
|---|---|---|
| 메시지는 한 줄 · 한 문장 | 두 문장을 이으면 실패하고, 한 줄(16pt)을 넘으면 넘침으로 멈춘다. 한글로 대략 46~60자 | 문장을 줄인다 |
| 제목은 한 줄 | 28pt 한 줄. 표지와 간지만 ` / `로 줄을 끊는다 | 제목을 줄인다. 통합반 1일차 장 제목을 바꾸면 실전반 1회차 `조립.py`가 멈출 수 있다 |
| 요소 수 한도 | 유형마다 범위가 있다: 카드 2~4, 비교 정확히 2, 흐름 2~6, 단계 3~5, 풀이 2~6, 표 2~9, 구조 2~12, 파이프라인 3~7, 관계도 2~8, 코드의 짚을 점 0~4, 그림의 짚을 점 0~4, 문답 보기 2~5, 목차 2~9 | 장을 나누거나 유형을 바꾼다 |
| 요소 한 줄은 세 칸까지 | `칸1 \| 칸2 \| 칸3`. 표도 3열이다. 구분자 `\|`는 앞을 띄운다 | 넷째 열이 필요하면 칸2 안에 ` / `로 줄을 나누거나 장을 나눈다 |
| 표의 셋째 칸은 세 줄까지 | ` / `로 줄을 바꾼다 | 문구를 줄인다 |
| 꼬리표가 칸보다 넓으면 실패 | 카드 · 비교의 셋째 칸 | 문구를 줄인다 |
| 삽화 라벨 | 16개까지, 가운데 정렬뿐, 크기는 두 단계(기본 13.5 / 11pt, `라벨: 큰`이면 16 / 13pt). 셋째 칸은 `x,y[,폭]`이고 폭의 기본은 그림 폭의 16 %. 이름 칸을 비우면(`| 설명 | x,y`) 설명 줄만 작은 일반 글씨로 쓴다(그래프의 관계 이름처럼) | 라벨이 끊기면 폭 값을 넓히거나 풀네임을 설명 줄로 내린다 |
| 코드 장 | `코드:` 안의 ` / `(앞뒤 공백)는 줄바꿈, 글자 그대로의 빗금은 `\/`. 코드 상자의 높이는 본문 영역을 넘지 못한다 | 줄이 많으면 상자 아래가 잘릴 수 있으니 렌더로 본다. 길면 장을 나눈다(몇 줄부터 잘리는지는 이 문서에서 재지 않았다 — 확인 필요) |
| `**` | 메시지와 요소 안의 `**굵게**`는 강조색으로 그려진다. 요소의 칸1 전체를 `**`로 감싸면 강조 칸이 된다. 짝이 맞지 않으면 그 뒤가 모두 강조로 그려진다 | 짝을 맞춘다 |
| 유니코드 빼기표(−, U+2212) 금지 | 화면 문구에 있으면 실패한다(덱 글꼴에 없어 다른 글꼴로 바뀐다). 노트는 검사하지 않는다 | 하이픈(-)을 쓴다 |
| 허용되지 않는 칸 | `핵심` `설명` `다음` `현재`는 없앤 칸이며 쓰면 실패한다 | 형식 문서의 허용 칸을 쓴다 |
| 아이콘 수 | 유형마다 정해져 있다(요소 수와 같게 또는 0개. 파이프라인은 필수) | `scripts/find_icon.py <낱말>`로 찾는다 |
| 그림 경로 | 덱 MD 위치 기준 상대 경로이고 파일이 없으면 실패한다 | 실전반 덱은 통합반 일차 폴더의 `figures/`를 상대 경로로 가리킬 수 있다 |
| 관계도의 좌표 | 두 원이 너무 가까우면 실패한다 | 좌표를 벌린다 |
| 렌더 잠금 | 렌더는 파일 잠금으로 한 번에 하나씩 돈다. 다른 렌더가 돌고 있으면 기다린다. 20분을 넘기면 도구가 끊고 알린다. `soffice` 프로세스를 죽이지 않는다 | 기다린다. 여러 덱을 동시에 렌더하지 않는다 |
| 렌더 폴더 | 매번 새 이름으로 쓴다. 경로가 약 235자를 넘으면 멈춘다 | 짧은 경로를 쓴다 |
| 글꼴 | 맑은 고딕이 아닌 글꼴로 그려지면 렌더가 멈춘다 | 맑은 고딕을 설치한다 |

- **글머리표**의 둘째 줄은 글머리표 뒤 글자에 맞춰 시작한다. **관계도 노드**가 원 안 글자 폭보다 작으면 원과 간격을 키운다(지도와 같은 축척 1인치 = 100).
- **장 제목을 바꾸기 전에** 원본대응 · 목차 · `구성.json` · ORDER와 손질 문자열을 검색한다. 손질은 원문에서 정확히 한 번 대응해야 하고, 실패한 손질은 무조건 지우지 말고 원래 목적(회차 표기 · 빠진 장 참조 · 용어 보완)이 지금 원본에서 이미 풀렸는지 본다.
- `python <빌더> --check <원고>`로 형식을 검사하고 배포본은 `workspace/강의제작/산출물/<과정>/이론/NN회차/`에 만든다(옛 `workspace/강의제작/제작도구/온라인/` 출력 경로로 대신하지 않음). 실전반 2~8회차 원고는 `workspace/강의제작/제작도구/온라인/decks/practical/dayNN/실전반_NN일차.md`를 직접 고친다(조립 스크립트 없음).
- 발표자 노트만 바뀌면 화면 XML · 관계 · 미디어 바이트가 그대로인지 검사하고 다시 렌더하지 않는다. `~$…pptx` 잠금 파일이 있으면 그 PPTX가 열려 있는지 본다. 렌더의 LibreOffice를 강제로 끄지 않는다.
- **그림 고칠 곳:** 라벨의 글 · 좌표 · 폭은 덱 MD, SVG 형상은 그 `figures/만들기_삽화.py`, 실제 데이터 그래프는 `figures/만들기_그래프.py`와 원자료. 그림체 · 색 · 선 굵기는 `삽화_기본.py` 계열을 유지하고, 같은 생성기가 여러 그림을 다시 쓰므로 변경 파일과 해시를 확인한다. 그림이 바뀌어도 덱 MD diff는 없을 수 있으니 그림 파일명으로 덱 MD를 검색해 실전반의 공통 그림 참조까지 찾는다.
- 렌더 폴더는 저장소 밖 짧은 경로에 새 이름으로 둔다. 배포 ZIP은 전체를 자동 재생성하지 말고 요청된 묶음의 대상 목록과 ZIP 안 목록 · 바이트를 확인한다.

## 만들기와 확인

```bash
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/hyd-course-deck/scripts/deck2pptx.py <덱.md> <출력.pptx> [--render <PNG 폴더>]
```

- 입력과 출력이 같은 파일이면 거절한다. 규칙 위반이나 넘침 추정이 있으면 파일을 쓰기 전에 장 번호와 함께 모아서 실패한다.
- 저장한 뒤 파일을 다시 열어 검사한다(실패하면 파일은 남아 있다): 그림 장이 아닌 곳에 이미지가 없는지(그림 장은 이미지 1개), 아이콘 수가 덱 MD와 같은지, 아이콘이 장 면적의 12%를 넘지 않는지, 제목이 텍스트 상자에 있는지. 글자는 모두 고칠 수 있는 텍스트 상자다.
- `--render`는 LibreOffice(soffice)로 PDF를 만들고 pdftoppm(80dpi)으로 장마다 PNG를 낸다. 렌더는 파일 잠금으로 **한 번에 하나씩** 돌아서 다른 렌더가 끝날 때까지 기다린다. 20분이 넘으면 끊고 알린다(soffice 프로세스를 죽이지 않는다). 맑은 고딕이 아닌 글꼴로 그려지면 멈춘다. 렌더 폴더 경로가 약 235자를 넘으면 멈춘다.
- PNG를 모두 열어 잘림, 겹침, 넘침, 낱말 하나만 떨어진 줄, 화살표 교차, 비어 보이는 장을 본다. 묶음 그림은 `workspace/강의제작/제작도구/기존제작/tools/deck/시트.py`로 만든다.
