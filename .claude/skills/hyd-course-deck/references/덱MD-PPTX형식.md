# 덱 MD → PPTX 형식

`scripts/deck2pptx.py`가 읽는 덱 MD 문법과 빌더 동작이다. 색 · 글꼴 · 배치는 빌더가 정하고 덱 MD는 장 유형 · 화면 문구 · 아이콘만 정한다. 덱 MD가 이 형식을 어기면 빌더는 장 번호와 칸 이름을 찍고 실패한다. 어느 유형을 고를지, 통과 조건, 명령 순서는 `workspace/강의제작/지침/덱.md`가 정한다.

## 장의 모양

```markdown
## SLIDE 12 — MQTT: 발행 · 구독 기반의 경량 메시징 프로토콜
### 화면 내용
- 유형: 풀이
- 메시지: MQTT는 브로커를 사이에 두고 발행자와 구독자를 분리하여 **비동기 전달**을 지원하는 프로토콜이다.
- 요소:
  1. **MQTT** | TCP/IP 위에서 동작하는 발행 · 구독 방식의 메시징 프로토콜이다. / 헤더가 작아 불안정한 현장 네트워크에 적합하다. | Message Queuing Telemetry Transport
  2. 브로커 | 발행자가 보낸 메시지를 토픽 기준으로 구독자에게 전달하는 중개 서버이다. | Broker
- 노트: [짚을 곳] … / · … / [다음] …
### 화면 구성
(배치 지시)
### 제작 기준
(근거)
```

- 빌더는 `### 화면 내용` 칸과, 그 밖의 칸에서 줄 맨 앞에 쓴 `레이아웃: 이름` 한 줄만 읽는다. `### 화면 구성`과 `### 제작 기준`의 글은 화면에 나가지 않는다.
- `## SLIDE NN — 제목`: 제목은 28pt 한 줄이다. 표지와 간지만 ` / `로 줄을 끊는다. 첫 장이 표지가 아니면 실패한다.
- 화면 내용의 줄은 `- 칸: 값` 꼴이다. 읽을 수 없는 줄과 허용 밖의 칸은 실패한다. 허용 칸: `유형` `메시지` `노트` `요소` `아이콘` `그림` `문장` `기관` `과정` `부제` `번호` `구분` `머리` `영역` `연결` `사이` `코드` `라벨` `단`. 옛 칸 `핵심` `설명` `다음` `현재`는 실패한다.
- `메시지`: 본문 유형(표지, 목차, 간지를 뺀 모든 유형)에 메시지가 없으면 실패한다. 두 문장을 이으면 실패하고, 16pt 한 줄(한글 약 46~60자)을 넘으면 넘침으로 멈춘다.
- `**굵게**`: 메시지와 요소 안에서 강조색으로 그려진다. 짝이 맞지 않으면 그 뒤가 모두 강조로 그려진다.
- `노트`: 덱 MD에서는 한 줄로 쓰고, ` / `(앞뒤 공백 포함)가 PPTX 노트 안의 줄바꿈이 된다. 노트는 화면에 나가지 않는다.
- `요소`: 그 아래 줄들(들여 쓰고 `1.` 번호나 `-`로 시작하는 줄)이 요소다. 한 줄은 `칸1 | 칸2 | 칸3` 꼴이고, 칸은 최대 3개다(표도 3열). 구분자 `|`는 앞을 띄운다(뒤는 공백이나 줄 끝). 빈 칸도 칸으로 센다(`라벨 | | 40,20`). 칸2 안의 ` / `는 줄바꿈이다. 칸1 전체를 `**`로 감싸면 강조 칸(하늘색)이 된다. 넷째 열이 필요하면 칸2를 ` / `로 나누거나 장을 나눈다.
- 글자 수 한도는 없다. 대신 빌더가 상자마다 넘침을 글자 폭으로 추정해, 넘치면 멈춘다.
- 화면 문구(노트 제외)에 유니코드 빼기표(−, U+2212)가 있으면 실패한다. 덱 글꼴에 이 글자가 없기 때문이다. 하이픈(-)을 쓴다.

### 레이아웃

`레이아웃: 이름`(장마다 한 줄, 쓰지 않아도 된다)은 그 장을 유형 대신 설명용 레이아웃 코드로 그리게 한다. `### 화면 내용` 안에 쓰면 읽을 수 없는 줄로 실패하므로 `### 화면 구성` 아래에 쓴다. 이름: `그래프경로` · `관점격자` · `판단격자` · `계산기준선` · `지식변환` · `제안검토` · `승인기록` · `출처연결` · `검증연결`. 코드는 `workspace/강의제작/제작도구/온라인/tools/deck/설명레이아웃.py` 하나이고, 내용은 그 장의 요소에서 읽는다. 없는 이름을 쓰면 그 코드가 실패한다. 코드 파일이 없으면 빌더가 경로를 대며 멈추므로, workspace 파일이 풀린 저장소에서 돌린다.

## 장 유형

요소 수가 범위를 벗어나면 실패한다. 본문 영역은 세로 약 5.2인치다.

| 유형 | 언제 | 칸과 요소 |
|---|---|---|
| 표지 | 덱 첫 장 | `기관:` `과정:`(필수) `부제:` `아이콘:` 1~3개. 제목은 ` / `로 줄을 끊는다. uEngine 로고는 자동 |
| 목차 | 덱에 한 번 | 요소 2~9: `단원명` 또는 `단원명 \| 구분` |
| 간지 | 단원이 바뀔 때, 퀴즈 앞 | `번호:` `구분:` `부제:` 모두 생략 가능. 제목은 ` / `로 줄을 끊는다. 좌측 상단에 표지의 기관명이 자동으로 들어간다 |
| 풀이 | 용어와 개념의 정의 | 요소 2~6: `용어 \| 설명(여러 줄) \| 정식 명칭` |
| 구조 | 구성요소와 흐름(아키텍처) | `영역: A \| B \| C`(필수), 요소 2~12: `이름 \| 설명 \| 영역`, `연결: A > B : 라벨 ; C => D : 라벨` |
| 표 | 대상별 속성, 대응 | `머리: A \| B \| C`(생략 가능), 요소 2~9: `라벨 \| 값 \| 상태`. `단: 2`는 라벨 · 값 두 칸, 머리 필수, 아이콘 · 상태 칸 없이 4~12개를 왼쪽 단부터 최대 6행씩 |
| 코드 | 메시지 · 데이터 · 질의의 실제 형식 | `코드:`(필수), 요소 0~4: `짚을 점 \| 설명` |
| 흐름 | 순서와 인과가 있는 2~6단계 | 요소 2~6: `제목 \| 설명(여러 줄)` |
| 단계 | 번호 붙은 절차, 상태 전이 | 요소 3~5: `제목 \| 설명(여러 줄)` |
| 비교 | 두 가지를 맞세움 | 요소 정확히 2개: `제목 \| 줄 / 줄 / 줄 \| 판정` |
| 카드 | 대등한 항목 | 요소 2~4: `제목 \| 줄 / 줄 \| 꼬리표` |
| 강조 | 한 문장을 크게 | `문장:`(필수, ` / `로 줄을 끊는다), 보조 요소 0~3 |
| 그림 | 실제 화면, 그래프(래스터 또는 SVG) | `그림:`(필수), 오른쪽 짚을 점 요소 0~4: `제목 \| 설명` |
| 삽화 | 직접 그린 그림 위에 라벨 | `그림:`(필수), `라벨: 큰`(생략하면 `보통`), 요소 0~16: `라벨 \| 설명 \| x,y[,폭]` |
| 파이프라인 | 한 방향으로 지나가는 경로 | 요소 3~7: `이름 \| 설명 \| 영역`, `아이콘:` 요소 수만큼(필수), `영역:` `사이:`(생략 가능) |
| 관계도 | 노드와 이름 붙은 관계 | 요소 2~8: `이름 \| 종류 \| x,y`, `연결:`(필수), `아이콘:` 요소 수만큼 또는 없음 |
| 문답 | 퀴즈 한 문항 | `메시지:`(상황) `문장:`(물음, 필수), 보기 요소 2~5: `보기 \| 덧붙임` |

그림 파일은 덱 MD 위치를 기준으로 한 상대 경로이고, 파일이 없으면 실패한다(실전반 덱은 통합반 일차 폴더의 `figures/`를 가리킬 수 있다). SVG는 PNG로 바꿔 넣는다.

### 아이콘

`아이콘:`에는 아이콘 이름을 쉼표로 나눠 요소 순서대로 적는다. 이름은 `assets/icons/tabler-outline/`의 파일 이름이고, 없는 이름이면 실패한다. 찾을 때는 `scripts/find_icon.py <낱말> [--preview <png>]`를 쓴다(한국어 낱말도 된다).

| 유형 | `아이콘:` 개수 |
|---|---|
| 표지 | 1~3개 |
| 파이프라인 | 요소 수와 같게(필수) |
| 흐름, 카드, 비교, 표, 단계, 강조, 관계도 | 요소 수와 같게 또는 0개 |
| 그 밖(목차, 간지, 풀이, 구조, 코드, 그림, 삽화, 문답) | 0개 |

### 구조

- `영역`은 왼쪽에서 오른쪽으로 놓이는 띠다(예: `OT | DMZ | IT`). 요소의 셋째 칸이 그 상자의 영역이며, `영역:`에 있는 이름이어야 한다. 같은 영역의 상자는 적은 순서대로 위에서 아래로 놓이고, 영역이 다른 상자 사이는 가로 화살표로 잇는다.
- `>`는 데이터 흐름(남색 실선), `=>`는 명령 흐름(파란 점선)이다. 기호 앞뒤를 띄우고, 이름은 요소 이름과 같아야 한다.

### 파이프라인

- 요소가 한 줄의 관 위에 왼쪽에서 오른쪽으로 놓인 원(아이콘)이 된다.
- `영역:`을 주면 요소의 셋째 칸이 영역이 되어 같은 영역 요소를 바탕 띠로 묶는다. 같은 영역 요소는 이어서 적는다(끊겼다 다시 나오면 실패).
- `사이: 라벨 | 라벨`은 이웃한 두 요소 사이의 관 위 낱말이다. 개수는 요소 수 - 1이고 빈 칸은 허용된다. 요소가 6개 이상이면 글자가 한 단계 작아진다.

### 관계도

- 요소가 원(노드), `연결:`이 이름 붙은 화살표다(`>` 실선, `=>` 점선). 이름은 요소 이름과 같아야 한다.
- 셋째 칸 `x,y`는 원 중심의 위치이고, 본문 영역의 왼쪽 위를 0,0, 오른쪽 아래를 100,100으로 잡는다. 두 원 중심이 원 지름 + 0.6인치보다 가까우면 실패하므로 좌표를 벌린다. 노드가 6개 이상이면 원이 작아진다(지름 1.9 → 1.6인치). 영문 관계 이름(`HAS_COMPONENT` 등)은 한 줄에 들어간다.

### 삽화

- 그림을 본문 영역에 깔고, 요소를 그 위에 고칠 수 있는 글상자로 얹는다.
- 셋째 칸 `x,y[,폭]`의 `x,y`는 글상자의 가운데 위 지점이고, 그림 상자의 왼쪽 위를 0,0, 오른쪽 아래를 100,100으로 잡는다. 폭은 그림 폭에 대한 %이고 기본은 16이다. 설명이 없으면 `라벨 | | 40,20`처럼 쓴다. 이름 칸을 비우면(`| 설명 | x,y`) 설명 줄만 작은 일반 글씨로 쓴다. 정렬은 가운데뿐이고, 요소는 16개까지다.
- 라벨 글자 크기(이름 · 설명)는 기본이 13.5pt와 11pt이고, `라벨: 큰`이면 16pt와 13pt다.
- 라벨 줄이 그림의 선이나 아이콘과 겹치거나 0.1인치 안으로 붙으면 실패한다. 라벨끼리 겹치거나 붙어도 실패한다. 이때는 좌표나 폭을 바꾼다.
- SVG 변환(`svg_to_png`, PyMuPDF)은 `stroke-dasharray`를 그리지 않아 점선이 실선이 된다. 그래서 점선은 생성기에서 짧은 선분으로 그린다(1회차 `만들기_삽화.py`의 `dash_line`, `dash_rect`). 구조와 관계도의 `=>`는 빌더가 도형으로 그리므로 점선으로 나온다.

### 코드

- `코드:` 안의 ` / `(앞뒤 공백 포함)는 줄바꿈이고, 글자 그대로의 빗금은 `\/`로 쓴다(예: `plant \/ hyd01 \/ tag \/ TS1`).
- 영문과 숫자는 고정폭 글꼴(Consolas)로, 한글과 ℃, 화살표 같은 기호는 덱 글꼴로 그려진다. 오른쪽 요소는 코드에서 짚을 점이다.
- 글자는 13pt이고, 코드 상자는 본문 영역을 넘지 못한다. 접힌 줄까지 세어 22줄부터 넘침으로 멈춘다(21줄은 통과). 넘침 추정은 줄 사이 2pt를 세지 않으므로, 20줄 안팎이면 렌더로 확인한다.

### 배치

- 카드, 비교, 코드 상자는 높이를 내용에 맞춰 본문 영역의 세로 가운데에 놓인다. 흐름, 단계, 파이프라인, 풀이, 표, 강조도 세로 가운데에 놓인다. 내용이 적어도 빈 칸을 늘이지 않는다.
- 카드와 비교의 꼬리표(셋째 칸)가 칸보다 넓으면 실패한다. 표의 셋째 칸(상태)은 ` / `로 나눠 3줄까지 쓴다. 비교의 `판정`과 풀이의 정식 명칭도 꼬리 칸이다.
- 퀴즈 번호는 보기 순서대로 1부터 붙는다.

## 빌더 동작

명령은 셋이다. `<덱.md> <출력.pptx> [--render <새 폴더>]`는 빌드한다. `<덱.pptx> --render <새 폴더>`는 있는 PPTX를 렌더만 하고 PPTX는 그대로 둔다. `--check <덱.md | -> [--base <덱 폴더>]`는 파일을 쓰지 않고 검사만 한다. `-`는 표준 입력이고, `--base`는 이때 그림 경로의 기준 폴더다.

- 입력과 출력이 같은 파일이면 거절한다. 실패는 파일을 쓰기 전에 난다. 칸 규칙, 요소 수, 넘침 추정의 오류는 장 번호와 함께 모아 한 번에 알린다. 읽을 수 없는 줄, 모르는 칸, 옛 칸, 세 칸을 넘는 요소, 너무 가까운 관계도 원은 만난 자리에서 바로 멈춘다.
- 같은 원고면 같은 바이트로 저장하고(zip 항목 날짜 고정), 이미 같은 바이트의 파일이 있으면 쓰지 않는다(「[같음]」을 찍는다).
- 저장한 뒤 다시 열어 검사한다(실패해도 파일은 남는다). 그림 장이 아닌 장에는 이미지가 없어야 하고, 그림 장에는 1개여야 한다. 아이콘 수가 덱 MD와 같아야 하고, 아이콘은 장 면적의 12 % 이하여야 하며, 제목은 텍스트 상자여야 한다. 글자는 모두 고칠 수 있는 텍스트 상자다.
- `--render`는 LibreOffice(soffice)로 PDF를 만들고, pdftoppm(80dpi)으로 장마다 PNG를 낸다. pdftoppm이 없으면 멈춘다. 운영체제 파일 잠금 때문에 한 번에 하나씩만 돌고, 잠금 대기와 PDF 변환은 각각 20분이 넘으면 끊는다.
- PDF에 박힌 글꼴이 맑은 고딕이나 고정폭 글꼴이 아니면 멈춘다. PDF 전체 경로가 235자를 넘어도 멈춘다. 그림과 아이콘의 PNG 캐시는 시스템 임시 폴더의 `deck2pptx_icons`에 두고(환경 변수 `DECK2PPTX_CACHE`가 있으면 그 폴더), 파일 이름은 SVG 내용과 배율로 정한다.
