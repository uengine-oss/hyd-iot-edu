# HYD 교재 덱

이 저장소의 이론 교재(PPTX 덱 38개)를 만들고 고치는 절차다. 규칙은 제작 기준에, 경위와 상세 절차는 인계 묶음에 있다. 이 문서는 순서와 명령만 적는다. 경로는 모두 저장소 루트 기준이고 명령은 저장소 루트에서 돌린다.

## 먼저 읽는다

1. `docs/교재/기준/제작기준.md` — 전체. 규칙은 여기에만 있다. 다른 문서와 어긋나면 이 문서가 이긴다.
2. `docs/교재/인계/README.md` — 할 일에 맞는 문서를 고르는 표. 이어서 `01_현황.md`.
3. 상황별 문서(아래 표). 덱 MD의 형식은 `../lecture-deck/references/덱MD-PPTX형식.md`, 폴더와 대응표는 `docs/교재/README.md`.

| 하려는 일 | 읽을 문서 |
|---|---|
| 한 장 고치기((가)), 원 덱을 고친 뒤의 재조립 · 배포((나)), 도구의 제약((다)), 커밋((라)) | `docs/교재/인계/02_덱_고치는_법.md` |
| 새 일차 · 회차 덱(1 · 2절), 전체 점검(3절), 실라버스가 바뀌었을 때(4절) | `docs/교재/인계/03_덱_만드는_법.md`, `docs/교재/인계/지시문/README.md` |
| 정해진 것과 남은 것 | `docs/교재/인계/04_결정_기록.md`, `docs/교재/인계/05_남은_일.md` |

## 덱의 구조

- **원 덱**: 통합반 온라인 1~11일차. `docs/교재/통합반/NN일차/통합반_NN일차.md`가 원본이고 PPTX는 거기서 만든다.
- **조립 덱** 27개: 실전반 온라인 1~8일차, 통합반 오프라인 1~10회차, 실전반 오프라인 1~9회차. 폴더마다 `조립.py`(실전반 1일차는 `docs/교재/실전반/만들기_01일차.py`)가 원 덱에서 장을 **제목으로** 찾아 가져오고 손질 목록을 적용한다. 새로 쓴 장은 `새장_*.md`에 있다.
- 사실의 근거는 `docs/교재/기준/`의 기술사실표 넷, 실라버스는 `docs/교재/기준/피지컬AI_실라버스_최종본.xlsx`다.

## 한 장 고치기

1. 고칠 곳을 정한다. 통합반 덱은 덱 MD, 조립 덱은 `조립.py`의 순서표 · 손질 목록이나 `새장_*.md`다.
2. 고친 뒤 빌드하고 렌더해 그 장과 앞뒤 장을 눈으로 본다. 렌더 폴더는 저장소 밖(임시 폴더)에 새 이름으로 둔다.

```bash
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py \
  docs/교재/통합반/03일차/통합반_03일차.md docs/교재/통합반/03일차/통합반_03일차.pptx --render <새 렌더 폴더>
uv run --no-project --with pillow python docs/교재/도구/시트.py <렌더 폴더> <출력 접두어> --cols 3 --per 9
```

3. 통합반 덱을 고쳤으면 아래 「원 덱을 고친 뒤」를 이어서 한다.

## 원 덱을 고친 뒤: 재조립 → 빌드 → 배포 묶음

```bash
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --dry-run        # 돌릴 스크립트 27개와 읽는 통합반 일차
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --day 3 --build  # 통합반 3일차를 읽는 것만 조립하고, 바뀐 덱만 빌드
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --build          # 전부 조립하고, 바뀐 덱만 빌드
python3 .claude/skills/hyd-course-deck/scripts/장수.py --units            # 38개 덱의 전체 · 단원별 본문 장수
python3 .claude/skills/hyd-course-deck/scripts/배포묶음.py --check        # zip의 구성과 낡은 항목 검사
python3 .claude/skills/hyd-course-deck/scripts/배포묶음.py                # docs/교재/배포/교재_전체.zip 다시 만들기
```

- `조립.py`가 멈추면 원 덱에서 장 제목이나 손질 대상 문구가 바뀐 것이다. 멈춘 스크립트의 순서표 · 손질 목록을 고치고 다시 돌린다. 멈춘 채로 빌드하지 않는다.
- 「바뀐 덱」은 덱 MD가 커밋과 다른 덱이다. 빌드한 덱은 렌더해 고친 장이 조립 덱에서도 맞게 보이는지 확인한다(원 덱에서 뺀 장을 조립 덱이 전제하지 않는가, 손질한 문구가 어색하지 않은가).
- 장수가 달라졌으면 `장수.py`의 값으로 제작 기준 13절 · 13-1절 · 13-2절, `docs/교재/README.md` 머리 문단, `docs/교재/인계/01_현황.md` 1절, `docs/handoff/NOW.md` 1절 「교재(슬라이드)」 줄의 숫자를 맞춘다.
- 마지막에 배포 묶음을 다시 만들고 `--check`가 통과하는지 본다.

## 새 일차 · 회차 덱 만들기

지시문은 `docs/교재/인계/지시문/`에 있다. 작업자에게 그대로 줄 수 있게 쓴 것이므로, 경로와 범위만 지금 일에 맞춰 고쳐 쓴다.

- **원 덱(통합반 새 일차)**: 사실 조사(`사실조사_지시.md` → 기술사실표) → 쓰기(`새일차쓰기_지시.md`: 장 목록 → 본문 · 노트 · 그림 → 빌드 · 렌더) → 검토(`새일차검토_지시.md`, 고치지 않는다) → 반영 → 다시 빌드 · 렌더.
- **조립 덱(실전반, 오프라인 회차)**: 계획표(`실전반계획_지시.md`, `오프라인계획_지시.md` — 가져올 장을 일차 · 번호 · 제목으로) → 조립(`실전반쓰기_지시.md`, `오프라인쓰기_지시.md`, `오프라인일괄_지시.md` — `조립.py`와 `새장_*.md`) → 검토(`실전반검토_지시.md`) → 과정 전체 맞춤(`오프라인맞춤_지시.md`: 약어 풀네임의 첫 자리, 뒤 회차의 전제, 퀴즈 겹침, 목차의 틀).
- 다 만들면 `장수.py`로 세어 제작 기준 13절의 표에 행을 더하고 `docs/교재/README.md`의 대응표를 고친다.

## 전체 점검과 반영

점검(`전체점검_지시.md`, `화면확인_지시.md` — 고치지 않고 목록만) → 원 덱에 반영(`점검반영_지시.md`, `원덱결함_지시.md`) → 조립 덱 다시 만들기(`조립재작업_지시.md`와 위 「원 덱을 고친 뒤」) → 장수 · 문서의 숫자 · 배포 묶음. 지난 점검의 결과와 확인의 한계는 `docs/교재/인계/01_현황.md`에 있다.

## 반드시 지킬 것

제작 기준에서 가장 자주 어긴 것이다. 근거와 세부는 괄호 안의 절에 있다.

1. **그림체를 바꾸지 않는다.** 컨펌받은 샘플(`docs/교재/통합반/샘플/`)과 1일차 `그림/`의 선 · 색 · 그림 조각을 쓴다. 이미지 생성 AI를 쓰지 않는다(7절).
2. **실습은 2장**(간지 + 설명 한 장)이다. 개념 설명이 아닌 것은 실습이고, 강사의 시연도 실습이다. 절차 · 메뉴 · 화면 캡처 · 길 안내를 싣지 않는다(9절).
3. **구현 설명과 단서를 쓰지 않는다.** 「우리 시스템은 이렇게 구현했다」, 면책, 내부 사정, 가상 · 시뮬레이터 강조는 화면에도 노트에도 없다(3절).
4. **한 장 1분 30초.** 단원의 본문 장수는 실라버스 분 ÷ 1.5가 기준이고, 모자라게 만들지 않는다(5절, 13절).
5. **문어체.** 같은 문장 틀을 한 단원에 서너 번 넘게 되풀이하지 않는다. 길 안내 · 질문형 연결 · 구호를 쓰지 않는다(8절).
6. **덱 사이의 용어와 값을 맞춘다.** 추천안, 승인 · 거절, 쿨러 성능 저하 경보, 쿨러 사건, 같은 사건의 수치(8절 「덱 사이의 용어」, 10절).
7. **조립 덱 MD를 손으로 고치지 않는다.** 고칠 곳은 `조립.py`와 `새장_*.md`다(13-1절).
8. **원 덱의 장 제목을 바꾸면 조립이 멈춘다.** 제목이나 손질 대상 문구를 바꿨으면 그 장을 가져가는 `조립.py`를 함께 고친다.
9. **결과 확인을 사용자에게 넘기지 않는다.** 전 문장 통독과 전 장 화면 확인을 직접 하고(12.2절), 못 본 장은 번호로 적는다. 사용자에게는 결정만 묻는다.
10. **사실은 사실표와 저장소에 근거가 있는 것만** 쓴다. 확인하지 못한 것은 뺀다(11절).
11. **커밋은 요청받았을 때만** 한다. 규칙은 `docs/교재/인계/02_덱_고치는_법.md`의 「(라) 커밋 규칙」을 따른다. 교재 파일만 골라 담고(같은 브랜치에서 다른 세션이 일한다), 렌더 폴더 · 묶음 그림 · `__pycache__` · `.DS_Store` · `~$*.pptx`는 올리지 않는다. 절대 경로 · 사람 이름 · 키 값을 넣지 않는다.

## 서브에이전트를 쓸 때

- 덱 원고를 쓰거나 고치는 일은 Opus로 한다. 읽기 · 계획표 · 검토 · 문서 정리는 가벼운 모델(Sonnet)로 하되, 한도에 걸리면 Opus로 한다. **fable 모델은 쓰지 않는다**(저장소 루트 `CLAUDE.md` 3절).
- 쓰는 작업자가 덱을 빌드하고 한 번 확인한 뒤 **스스로 검토자를 하나 부르게** 한다. 검토자는 고치지 않고 목록만 내고, 작업자가 「상」「중」을 모두 반영한 뒤 다시 빌드한다. 검토자의 제안이 제작 기준이나 사실과 어긋나면 따르지 않고 까닭을 보고에 적는다.
- 여러 작업자가 동시에 따로 쓰면 덱 사이가 어긋난다. 나누기 전에 **용어 · 값 · 약어 풀네임을 붙이는 자리의 기준**을 먼저 주고(제작 기준 8절 · 10절), 다 모은 뒤 과정 전체 맞춤을 한 번 한다.
- 지시에는 범위(고칠 파일), 금지(다른 덱 · 도구 · 기준 문서 수정, 커밋), 임시 산출물을 둘 저장소 밖 폴더, 짧은 보고 양식을 적는다. 렌더는 한 번에 하나씩 돌므로 기다리는 것이 정상이다.

## 도구의 알려진 제약

자세한 것은 `../lecture-deck/references/덱MD-PPTX형식.md`와 `docs/교재/인계/02_덱_고치는_법.md`의 「(다) 도구의 알려진 제약」에 있다.

- 메시지는 한 줄이다(한글 46~60자쯤). 넘치면 도구가 장 번호와 함께 멈춘다. 문구를 다듬거나 장을 나누거나 유형을 바꾼다.
- 유니코드 빼기표(−)는 쓰지 않고 하이픈을 쓴다. 코드 칸에서 ` / `는 줄바꿈이고 글자 빗금은 `\/`다.
- 카드는 넷까지, 표 한 칸은 세 줄까지, 삽화 라벨은 16개까지다. 꼬리표가 칸보다 넓으면 실패한다.
- 그림은 덱 MD 위치 기준 상대 경로다. 조립 덱은 그림을 복사하지 않고 통합반 폴더의 것을 가리킨다.
- `--render`는 LibreOffice(soffice), pdftoppm, 맑은 고딕이 있어야 하고 한 번에 하나씩 돈다. 렌더 폴더는 매번 새 이름으로 쓴다.
- 도구의 한계는 우회하지 않고 도구(`../lecture-deck/scripts/deck2pptx.py`)를 고친다. 고쳤으면 덱 전부를 다시 빌드해 달라진 장이 없는지 본다.
