# HYD 교재 덱 · 이론 대본

이론 덱(통합반 11회차 · 실전반 8회차 온라인, 오프라인 이론 덱)과 이론 대본 · 발표자 노트를 만들고 고치고 점검하는 절차다. 규칙은 기준 문서에 있고, 이 문서는 순서 · 명령 · 점검 항목과 기준 절 번호만 적는다(「기준_X Yn」은 `문서/교재/기준_X.md`의 Yn절, 「Yn-k」는 그 k항). 경로는 저장소 루트 기준이고 명령은 저장소 루트에서 돌린다.

## 먼저 읽는다

1. `문서/교재/기준_공통.md` 끝까지.
2. 덱 작업이면 `문서/교재/기준_이론덱.md` 끝까지. 덱을 새로 짜면 D0 본보기 덱 하나를 렌더로 처음부터 끝까지 넘겨 본다.
3. 이론 대본 · 노트 작업이면 `문서/교재/기준_대본.md` 끝까지(오프라인 덱의 노트는 덱 작업이라 기준_이론덱 D7-6). 대본을 새로 쓰면 S0 본보기 이론 대본 하나를 통독한다.
4. 이론 전체 검토는 덱 · 대본 두 기준을 함께 본다(기준_공통 G1-3).
5. 덱 MD의 형식과 빌더 제약은 `.claude/skills/lecture-deck/references/덱MD-PPTX형식.md`.

## 한 장 고치기

1. 확정 회차(D7-4)면 먼저 결함을 「대상 · 어긋남 · 근거 · 고칠 문장」으로 적어 승인을 받는다(기준_공통 G4-2). 노트만이면 승인 없이 고친다.
2. 원고 덱 MD를 고친다. 장마다 `### 제작 기준` 칸(D9-3).
3. 빌드 · 렌더 · 묶음 그림 · 글겹침. 렌더 폴더는 저장소 밖에 매번 새 이름으로 둔다.

```bash
python3 .claude/skills/lecture-deck/scripts/deck2pptx.py \
  제작용/온라인/decks/integrated/day03/통합반_03일차.md <출력.pptx> --render <새 렌더 폴더>
python3 제작용/기존제작/tools/deck/시트.py <렌더 폴더> <출력 접두어> --cols 3 --per 9
python3 제작용/기존제작/tools/deck/글겹침.py <렌더한 덱.pdf>
```

4. 그 장과 앞뒤 장을 렌더로 직접 본다(D9-7). 글겹침 0곳.
5. 통합반 1회차를 고쳤으면 `practical/day01/조립.py`로 실전반 1회차를 다시 만든다(D7-1). 공통 내용이면 다른 과정 원고도 확인한다(D7-3).
6. 장수 · 장 번호 · 읽는 순서가 바뀌면 D9-6의 목록(분할 대본 `[SLIDE NN]`, 노트, `구성.json` → 구성표, 다른 편의 장 참조 문장)을 같은 판본으로 맞춘다.

## 확정 PPTX를 고칠 때

확정 덱은 PPTX를 다시 빌드하지 않는다(D9-5).

- 노트만: 커밋본 PPTX에 노트 칸만 주입하고 화면 XML · 미디어 바이트 불변을 확인한다(본보기 커밋 `a12f065`).
- 승인된 화면 문구: 배포된 `산출물/<과정>/이론/NN회차/*.pptx`에서 그 문구가 든 런만 python-pptx로 바꾸고, 같은 문구를 두 과정 PPTX(1회차) · 원고 MD · 실습 랩의 `참고_교재_발췌.md` · 그 랩 ZIP에 맞춘다(기준_공통 G3-6 · G4-9). 그 장을 렌더해 글이 칸 안에 드는지 본다. 원고 MD가 지금 빌더 규칙에 걸려 다시 빌드되지 않으면 그 위반은 따로 고칠 일로 남긴다.
- 배치 결함: 위치 · 폭 · 줄바꿈 자리만 고친다(D9-5).

범위 · 화면 · 노트 · 시간은 D7-6의 네 항목을 하나씩 대조한다. 온라인 덱이 바뀌면 다시 조립 · 대조한다.

## 실전반 2~8회차 재구성

회차 하나씩, 시안 · 사전 승인 단계 없이 반영 · 검사까지 끝낸 뒤 그 회차를 보고하고, 지적이 오면 그 회차만 고친다(D7-5, 기준_공통 G4-3).

1. 출발점: 묶인 통합반 회차(기준_공통 G2 표 「편성」)의 확정 덱 · 대본을 읽는다. 통합반 원본은 고치지 않는다(D7-2).
2. 실라버스 실전반 행의 상세 항목 → 단원 · 장 대응표를 만든다(D9-2, 기준_공통 G0 「범위와 시간」). 압축 전 원고의 정의 · 용어 · 값과도 대응시키고 삭제 · 통합의 까닭을 적는다.
3. 압축 원고를 쓴다: 되풀이 빼기 · 겹치는 장 합치기 · 행에 없는 장 빼기, 단원마다 실전 응용 장, 한 단계 깊은 내용은 네 조건(기준_공통 G2 표 「이론 덱」, D7-2).
4. 대본을 압축된 덱에 맞춘다(기준_공통 G2 표 「이론 대본」, 기준_대본 S5).
5. 아래 「점검」 1~6을 모두 하고 「실전반 완료 확인」을 채운다.

## 이론 대본 · 노트

1. 덱과 함께 설계한다 — 덱 → 대본 → 노트 순서, 화면 결함은 덱으로 돌아가 고친다(D9-1).
2. 파일 머리 · 제목 줄 · 끝 표시는 기준_대본 S5-2 · S5-3, 구간 시작 · 끝은 S5-4, 노트 꼴은 S7.
3. 길이를 잰다(기준_공통 G0 「범위와 시간」, 기준_대본 S4). 고치면 같은 계수로 전후를 다시 잰다.

```bash
python 제작용/기존제작/tools/deck/대본시간.py 산출물/<과정>/이론/NN회차/대본/*.md
```

4. 영상이 될 대본은 `강의영상.py --dry`로 첫 문장 이음말 · 장 범위를 검사한다(기준_대본 S9-1, hyd-lecture-video).
5. 고친 뒤 맞출 것: 기준_공통 G4-9 · 기준_대본 S8-1(덱 MD 노트 · PPTX 노트, `구성.json` → 구성표, 같은 덱을 쓰는 다른 과정 대본).
6. 점검: 제목과 표시를 뺀 본문을 처음부터 끝까지 이어 읽는다(기준_대본 S8-3).

## 점검 (전체 점검 · 회차 마감)

전체 점검은 고치지 않고 목록만 내는 점검 → 반영 → 빌드 · 렌더 · 글겹침 순서다(검토만이면 목록에서 멈춘다, 기준_공통 G4-1). 못 본 장은 번호로 적는다.

1. **구조 점검(D4):** 첫 장이 표지 · `목차`는 덱에 한 번 · 마무리가 복습 → 용어 정리 → 퀴즈 간지 → 퀴즈 3문항 → 정답과 판단 기준 순서 · 실습은 간지와 설명 두 장(D4-4) · 표지 · 용어 정리 · 퀴즈의 고정 문구(D4 표).
2. **렌더 점검:** `시트.py --cols 3 --per 9`로 9장 묶음을 만들어 전 장을 읽을 크기로 본다. 넘침 · 겹침 · 잘린 글자 · 작은 글자 · 큰 빈칸(D6-7) · 한 장 두 주제(D5-4) · 같은 형태의 긴 연속(D6-2). `글겹침.py` 0곳(D9-7).
3. **글 점검:** 화면 문구와 노트를 한 문장씩 통독한다 — 제목 · 메시지(D5-5), 쓰지 않는 말(D5-9), 용어 · 약어(D5-6), 「그 장만 보고 핵심을 아는가」(D5-2 · D9-7). 낱말 검색으로 갈음하지 않는다.
4. **선수 개념 · 복습 위치:** 정의하지 않은 용어나 뒤의 원리를 먼저 쓰지 않는지(D2-3), 복습이 마무리 한 자리에만 있는지(D4-2), 회차 사이 앞지르기가 없는지(D2-4).
5. **덱 사이 용어 · 값:** 앞뒤 회차 덱 MD와 용어 · 대표 값 · 사건 기록을 대조한다(기준_공통 G3-7, D8).
6. **통합반과의 닮음(실전반):**

```bash
python3 제작용/기존제작/tools/deck/닮음.py 제작용/온라인/decks/practical/dayNN/실전반_NN일차.md \
  --ref 제작용/온라인/decks/integrated/dayAA/통합반_AA일차.md [통합반_BB일차.md] [--slides …]
```

   판정은 기준_공통 G2 표의 값(0.8 이상이면 다시 짬, 실습 간지 · 설명 장 예외)으로 한다. 도구가 찍는 「통과/닮음」(0.6 경계)은 그 판정이 아니다.

**실전반 완료 확인** — 회차 보고에 항목마다 값과 근거를 적는다:

| 항목 | 확인 |
|---|---|
| 빌드 넘침 | 0 (`deck2pptx.py`가 멈추지 않음) |
| 글겹침 | `글겹침.py` 0곳 |
| 대본 ↔ 덱 | 분할 대본의 `[SLIDE NN]`과 덱 장 번호 일치(D9-6) |
| 실라버스 | 실전반 행 상세 항목 대비 빠진 개념 0(D9-2) |
| 통합반과 같은 화면 | `닮음.py` 0.8 이상 장 수와 번호(예외 장 표시) |
| 같은 대본 문장 비율 | 측정값만 기록(D7-2 — 대본의 겹침은 괜찮다) |

## 작업자를 쓸 때

작업자 · 검토자 운용은 기준_공통 G4-5(한 세션 = 한 회차, 모델 `opus` · fable 금지, 회차를 끝내기 전 새 검토자가 기준 대조와 품질 비교를 한 번, 검토자는 목록만), 나누기 전 용어 · 값 기준 주기와 모은 뒤 맞춤은 D8. 지시에는 범위(고칠 파일) · 금지(다른 덱 · 도구 · 기준 문서 수정, 커밋) · 임시 산출물을 둘 저장소 밖 폴더 · 보고 양식을 적는다. 검토 목록은 상 · 중 · 하 등급으로 받고 「상」「중」을 반영한 뒤 다시 빌드한다. 검토자의 제안이 기준이나 사실과 어긋나면 따르지 않고 까닭을 보고에 적는다. 지난 작업자 지시문(점검 · 화면확인 · 사실조사)은 로컬 `.evidence/인계/근거/지난_작업자_지시문/`에 있고, 범위 나누기 · 등급 같은 방법만 다시 쓴다(조립 덱 · 옛 오프라인 · `production/` 경로 전제는 쓰지 않는다). 렌더는 한 번에 하나씩 돌므로 기다리는 것이 정상이다.

## 도구의 알려진 제약

세부는 `.claude/skills/lecture-deck/references/덱MD-PPTX형식.md`(「자주 걸린 제약과 수정 요령」 절).

- 메시지는 한 줄(한글 46~60자쯤). 넘치면 도구가 장 번호와 함께 멈춘다 — 문구 · 장 나누기 · 유형 바꾸기(D9-4).
- 유니코드 빼기표(−) 대신 하이픈. 코드 칸의 ` / `는 줄바꿈, 글자 빗금은 `\/`.
- 카드는 넷까지, 표 한 칸은 세 줄까지, 삽화 라벨은 16개까지. 꼬리표가 칸보다 넓으면 실패한다.
- 그림은 덱 MD 위치 기준 상대 경로. 실전반 덱은 통합반 폴더의 그림을 가리킬 수 있다.
- `--render`는 LibreOffice(soffice) · pdftoppm · 맑은 고딕이 필요하고 한 번에 하나씩 돈다. 맑은 고딕이 없으면 멈춘다(글꼴은 저장소에 넣지 않고 사용자에게 받는다).
- `글겹침.py`(PyMuPDF 필요)는 글줄끼리 겹침, 배지 · 꼬리표 칸 밖 글, 장 밖 글을 찾는다. 삽화 안의 글은 보지 못한다.
- 도구의 한계는 우회하지 않고 `deck2pptx.py`를 고치고, 고쳤으면 같은 빌더를 쓰는 덱 전부를 다시 빌드한다(D9-4).
