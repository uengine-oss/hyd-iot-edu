# 공유 스킬 저작 규칙

스킬을 고치거나 새로 만들 때 직접 연다(자동으로 불러오지 않는다).

스킬 원본은 이 저장소의 `.claude/skills` 한 곳에 둔다. 공용 스킬(이 저장소 밖에서 받아 오는 것)은 그 스킬의 저장소에서 고친다.
본문은 훅·슬래시 명령 실행에 의존하지 않는다.

- `name`과 `description`을 YAML frontmatter에 둔다. 이름은 폴더명과 같은 소문자·숫자·하이픈이다.
- 설명은 하는 일과 실제 사용자가 요청하는 상황을 짧게 쓴다. 인접 스킬과 겹칠 때 경계를 적는다.
  최소 글자 수를 채우거나 “반드시”를 반복하지 않는다. 이름·설명·호스트에 전달된 목록을 함께 진단한다.
- 공통 본문은 입력 확인 → 작업 → 검증 → 산출물·미결의 흐름을 갖는다.
  조건부 자료는 참조 파일에 두고 언제 읽는지와 실제 상대 경로를 적는다.
- 500줄은 정리 신호이지 품질 판정이 아니다. 문장 중복 수·금지어 0건을 의미 정확도로 취급하지 않는다.
- 사용자에게 승인된 작업은 진행한다. 필요한 질문 도구를 제거해 무인 실행을 강제하지 않는다.
  도구 권한은 호스트가 소유하며, 한 호스트의 설정을 다른 호스트의 보장으로 쓰지 않는다.
- 자동 선택을 원하면 `disable-model-invocation: true`를 무심코 복사하지 않는다.
  명시 호출 전용 스킬의 정책은 사유 없이 해제하지 않는다.
- 문서 수정·로컬 파일 생성과 외부 게시·전송·비용 실행은 승인 범위가 다르다.
- 구조 검사와 새 세션의 실제 선택·작업 품질 검증을 별도로 기록한다.
  스킬 파일이 있다고 자동 선택 성공, 문법이 맞다고 결과가 정확하다고 판정하지 않는다.
- 기존 감사기의 경고도 검사 대상이다. 오래된 도구별 수치나 규정이 현행 공식 자료와 다르면
  해당 규정을 고치되, 실패를 숨기려고 결과나 검사기를 우회하지 않는다.

공식 근거:
- https://code.claude.com/docs/en/skills
- https://code.claude.com/docs/en/hooks

로컬 구조 검사는 저장소 루트에서 `uv run --no-project --with pyyaml python .claude/skills/lecture-common/workflow_doctor.py .`로 한다.
이 검사는 스킬 발견 경로·메타데이터를 검사하며 의미·자동 발동을 판정하지 않는다.

새 스킬 추가와 실제 선택·수행 시험은
[스킬 추가·검증 가이드](skill-admission.md)를 따른다.
