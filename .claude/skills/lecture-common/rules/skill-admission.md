# 스킬 추가와 검증 가이드

스킬을 추가하거나 선택·수행 시험을 할 때 직접 연다(자동으로 불러오지 않는다).

스킬을 추가할 때마다 전체 강의나 전체 분석을 다시 실행하지 않는다. 아래 증거를 따로 확인한다.
가장 작은 단위를 일률적으로 고르지 않는다. 변경의 실패를 판별할 수 있는 적정 범위가 기준이다.
입출력 연결은 실제 동선, 배포는 패키지 전체, 문서 정합성은 영향 문서 전체를 확인할 수 있다.
축소하면 핵심 조건이 사라지는 시험은 줄이지 않고, 판단에 기여하지 않는 별도 시험은 만들지 않는다.

| 단계 | 확인할 것 | 성공 근거 |
|---|---|---|
| 발견 | 정본, 지원 목록(`.claude/skills/lecture-common/workflow-skills.json`), 자동 선택 정책 | 구조 검사와 새 세션의 실제 목록 |
| 선택 | 사용자가 스킬 이름을 말하지 않은 요청 | 호스트 실행 기록의 스킬 호출 또는 본문 읽기 |
| 수행 | 실패를 판별할 수 있는 실제 업무 범위 | 파일·실행 결과·화면 등 산출물과 요구 대조 |
| 유지 | 관련 문서 갱신과 근거 보관 | 사용자 요청 전체 완료 후 작업 보고 갱신(공용 `work-report` 스킬이 세션에 있으면 그 절차로) |

## 추가할 때

1. 기존 스킬에 빠진 절차인지 독립된 반복 업무인지 판단한다. 같은 책임의 별칭 스킬을 늘리지 않는다.
2. 사용자 요청 예시 2개와 인접 스킬이 맡을 경계 예시 1개를 [routing-cases.json](routing-cases.json)에 적는다. 기대 스킬과 수용 기준은 시험 대상 모델에게 주지 않는다.
3. `.claude/skills/<이름>/SKILL.md`에 역할·사용 상황·입력·작업·검증·실제 산출물을 적는다.
   기존 승인 결과물이 있으면 위치·해시·승인 근거·재사용 가능한 특성을 참조한다. 옛 실행 수치를 새 작업의 성공으로 복사하지 않는다.
4. 읽을 필요 없는 대형 자료는 조건부 참조로 둔다. 이미 공통 기준(`../공통기준.md`)과 저장소 루트 `CLAUDE.md`가 소유한 보호·보고 규칙을 다른 표현으로 복제하지 않는다.
5. `.claude/skills/lecture-common/workflow-skills.json`과 `.claude/skills/README.md`의 표에 추가한다. 다른 위치에 복사본을 만들지 않는다.
6. 구조 검사 후 새 호스트 세션에서 긍정·경계 요청을 시험한다. 실패한 계층만 고쳐 재검증한다.

## 적은 비용으로 실제 선택을 시험하기

- 첫 실행은 호스트별 대표 요청 1개부터 시작한다. CLI·확장·Desktop은 관찰한 호스트별로 기록한다.
- 같은 세션에 모든 문제를 연속으로 주면 앞선 지시가 선택에 영향을 준다. 독립 선택 시험은 새 세션을 사용한다.
- 시험 프롬프트에 기대 스킬 이름이나 경로를 넣지 않는다. 명시 호출 시험은 별도 항목이다.
- `선택했다`는 답변만으로 통과하지 않는다. 실행 기록의 Skill 호출 또는 실제 SKILL.md 읽기와 결과를 확인한다.
- 선택 시험은 파일 변경·서비스 실행이 필요 없는 작은 실제 요청으로 시작한다. 수행 시험은 승인된 작은 산출물을 만든다.
- 시간·입출력 사용량·호출 수를 저장한다. 예산·인증·도구 권한으로 중단되면 스킬 실패와 구분한다. 자동으로 유료 재시도하지 않는다.
- 변경한 스킬과 혼동될 인접 스킬부터 시험하고, 안정된 무관 업무의 전수 실행은 반복하지 않는다.
- 여러 요청의 담당 스킬만 한 번에 분류하는 시험은 설명의 중복을 저렴하게 찾는 용도다. 실제 자동 호출·수행 시험으로 세지 않는다.
- 기대 정답도 검토한다. 단순 채팅에 스킬을 강제하거나 타당한 인접 선택을 실패로 몰아 지침을 과도하게 늘리지 않는다.

## 기록할 최소 항목

날짜, 호스트/버전, 작업 폴더, 입력 원문, 관련 스킬과 루트 계약의 해시, 명령과 제한,
실제 선택 근거, 산출물 근거, 기대/실제/판정, 사용량, 미검증 범위.

`검증됨`, `실패`, `미검증`, `해당 없음`을 구분한다. 자동 선택·산출물 품질·전체 실행을 한 PASS로 합치지 않는다.
모든 스킬을 통합 작업 하나에서 불렀다는 이유로 각 스킬의 독립 선택이 증명되지는 않는다.

기록된 CLI 시험은 공용 도구 폴더의 `inspect_host_probe.py`로 재검사할 수 있다.
`python .claude/skills/lecture-common/inspect_host_probe.py <실행폴더> --workspace . --skill <스킬명>`
도구는 실제 본문 전달·종료 상태·현재 지침 해시·기록 무결성을 따로 출력한다. 명시 호출은 자동 선택으로 세지 않는다.
본문이 보여도 실행 기록의 무결성 해시가 없으면 미검증이다. 이중 Windows 경로의 읽기 시도도 식별하지만,
종료 코드 0과 파일 읽기 명령만으로 기록에 없는 본문을 전달받았다고 추정하지 않는다.
이전 기록에 호출 방식이나 무결성 해시가 없으면 추정해서 채우지 않는다. 본문 전달 확인도 의미 정확성 통과가 아니다.

## 업무별 수행 시험 예시

| 업무 | 출발점 예시: 필요한 경우 범위 확대 | 확인 |
|---|---|---|
| 강의 | 학습목표 1개에 해당하는 설명·실습·학생 가이드 | 요구 반영, 실제 실행, 설명과 결과 일치 |
| UI/UX | 대표 화면의 핵심 동선 1개 | 역할·이름·안정적 식별자로 조작, 상태 assertion, 화면·오류 확인 |
| Analyzer | 작은 전체 소스와 필요한 DDL | 실제 Parser→Analyzer→wire→graph→소비자; 합성 fixture 시험과 구분 |
| 데모 | 승인 기준을 적용한 연속 장면 1개 | 실제 조작·화면 가독성·음성 일치·장면 경계; 최종 영상은 전체 QC 별도 |
| 연구노트 | 근거가 있는 연구 항목 1개 | 목적·방법·관찰·결론과 출처, Google Docs 양식 보존 |

좌표는 캔버스 등 요소 식별이 불가능한 조작에 한정한다. 고정 대기나 강제 클릭으로 실패를 숨기지 않는다.
확정된 승인 산출물이 없는 상태에서 임의 결과물을 모범 기준으로 승격하지 않는다.

실제 분석 견적은 먼저 입력이 현재 Parser의 언어·확장자·문법 지원 범위인지 확인한다.
손으로 만든 구조의 요청 크기만 재서 실행 가능한 전체 분석 견적으로 제시하지 않는다.

## 실행 자원 정리

시험이 만든 프로세스·임시 파일의 소유와 수명을 기록한다. 프로세스는 보유한 실행 핸들로 종료 상태를 확인하고,
시간 초과 시 해당 프로세스 계통만 정리한다. 이름·포트·오래된 PID 파일만으로 종료 대상을 고르지 않는다.
Windows CLI 시험은 `../owned_process.py`를 사용한다. 이미 분리된 백그라운드 작업까지 정리됐다고 주장하지 않는다.
원문·승인 산출물·검증 근거·복구용 사본과 재생성 가능한 임시물을 구분한다. 단순히 오래됐거나 용량이 크다는 이유로 삭제하지 않는다.
