# 강의 스킬 공통 기준

`lecture-plan` · `lecture-deck` · `lecture-lab` · `lecture-verify` · `lecture-deliver`가 함께 전제하는 기준이다. 이 스킬들은 원래 저장소 밖 작업 공간에 있었고, 거기서는 작업 공간 루트의 `CLAUDE.md`(「공통 계약」)와 세션 훅이 이 내용을 맡았다. 저장소에는 그 문서와 훅이 없으므로 여기에 적는다. 작업 공간의 원문은 옮길 수 없어, 스킬 문서들이 인용하던 내용을 모아 다시 썼다.

우선순서: 사용자의 최신 지시 → 저장소 루트 `CLAUDE.md`(이 저장소의 프로젝트 계약) → 대상 강의의 기준 문서(HYD 교재는 `문서/교재/2_기준.md`) → 이 문서 → 각 스킬 문서. HYD 과정의 일은 `hyd-course-deck`(교재 덱)과 `hyd-lab-guide`(실습 가이드)가 일반 스킬보다 먼저다.

## 1. 범위와 판정

- 요청한 범위까지만 한다. 정리만 요청받았으면 정리로 끝내고, 검토만 요청받았으면 고치지 않는다. 요청하지 않은 ZIP · 보고서 · 인계 파일 · 업로드를 덧붙이지 않는다.
- 답은 열어서 확인한 뒤에 낸다. 결론에는 파일 위치나 명령과 그 출력을 근거로 붙인다. 열어 보았는데도 나오지 않을 때만 「확인하지 못함」이다.
- 판정은 `검증됨` · `실패` · `미검증` · `해당 없음`으로 나눈다. 구조 검사 통과, 파일의 존재, mock, 문법 검사는 완주가 아니다. 하지 않은 실행 · 렌더 · 화면 확인을 완료로 쓰지 않는다. 표본만 보았으면 표본 범위만 검증됨이다.
- 결과 확인을 사용자에게 넘기지 않는다. 정해진 기준으로 스스로 확인하고, 사용자에게는 결정이 필요한 것만 묻는다.
- 도구의 한계를 만나면 우회하지 않고 원인을 고친다. 검사기의 경고를 무시해 통과로 바꾸지 않는다.

## 2. 모든 강의의 이해 · 구현 기준

- 필요가 먼저다. 활동마다 왜 필요한지와, 학생이 결정 · 구현 · 확인할 범위를 정한다.
- 학생이 결정할 부분을 남긴다. 핵심을 모두 만들어 주거나, 빈칸을 대신 채워 주는 것으로 끝내지 않는다. 에이전트에게 무조건 맡기게 하지도 않는다.
- 출발본마다 제공하는 기반 / 학생이 이해하고 결정할 것 / 에이전트가 구현할 핵심 / 실제로 확인할 결과를 잇는다.
- 실행이 성공하는 것과 학습목표를 이루는 것을 따로 확인한다. 배포 환경의 검증과 학생의 완주 · 이해 검증도 따로 적는다.
- 직접 설명이나 자연스러운 사례로 충분하면 실패 체험이나 실습을 억지로 넣지 않는다.

## 3. 보존과 공개

- 받은 원문, 강사가 손질한 파일, 승인된 산출물은 덮어쓰지 않는다. 고쳐야 하면 새 파일로 내거나 변경 필요를 따로 적는다.
- 외부 전송 · 게시 · 공유 권한 변경 · 원격 삭제 · 비용이 드는 실행은 명시 요청이 있을 때만 한다.
- 이 저장소는 공개 저장소다. 사람 이름, 절대 경로, 키 · 토큰 값, 회의 메모 원문, 다른 과정의 본문과 화면을 넣지 않는다. 경로는 저장소 기준 상대 경로로 쓴다. 비밀값은 로그와 보고에도 다시 찍지 않는다.
- 커밋과 push는 요청받았을 때만 한다.

## 4. 사용자 표시 (훅 없이 따른다)

작업 공간에서는 세션 훅이 아래 표시를 찾아 지시를 덧붙였다. 저장소에는 그 훅이 없으므로, 사용자 문장에 표시가 있으면 직접 따른다. 표시가 없어도 판정은 스스로 한다.

| 표시 | 할 일 |
|---|---|
| `!근거` | 추측하지 않고 열어서 확인한 뒤 답한다. 결론마다 근거를 붙인다 |
| `!조사만` | 읽기만 한다. 파일을 만들거나 고치거나 지우지 않고, 영향 범위까지 내고 멈춘다 |
| `!불만` | 되풀이된 지적이다. 지적과 현재 지침 · 행동 · 실제 결과를 대조해, 승인된 범위에서 가장 좁은 자산(스킬 문서 · 기준 문서)을 고친다 |

## 5. 스킬을 고칠 때

스킬 목록과 관계는 `../README.md`, 스킬 문서의 규격은 `rules/스킬-공식규격.md`, 추가와 시험 절차는 `rules/skill-admission.md`, 경계 사례는 `rules/routing-cases.json`에 있다. 스킬 본문은 훅이나 슬래시 명령의 실행에 기대지 않게 쓴다.
