# 강의 자료 검토와 완료 판정

공통 기준(`../lecture-common/공통기준.md`)과 저장소 루트 `CLAUDE.md`, 대상 강의의 명시 계약을 먼저 따른다. 아래 경로는 이 스킬 폴더 기준이다.

HYD 교재의 내용·시간·표기 판정은 `문서/교재/2_기준.md` 9절과 그 참조 규칙을 따른다. 검토 순서는 `문서/교재/4_만드는_법.md` 2부 0절이다. 일반 검사 항목을 HYD 기준과 별개인 금지 규칙으로 확대하지 않는다.

## 검토

1. **요청이 검토만이면 파일을 수정하지 않는다.** 수정까지 요청됐으면 발견한 결함을 해당 스킬
   (계획·반영 `lecture-plan`, 덱·대본 `lecture-deck`, 실습 `lecture-lab`)의 기준으로 고친다.
2. 원자료·학교 요구·학습목표를 기준으로 요구 항목 → 자료 위치 → 검증 근거를 연결한다.
   계약 기반 강의는 `lecture-plan`의 요구 정리 규칙(1·2절)으로 원문을 다시 대조해 누락된 요구부터 확인한다.
   요구 목록끼리만 비교하지 않는다.
3. 계획서의 시간 합계·선수 지식·준비물, 덱의 개념 도입 순서·대본 대응,
   실습의 입력·실행·관찰·판단·실패 복구, 배포본의 파일·정답 분리를 영향 범위에서 확인한다.
4. 수치·제품 동작·출처는 원문과 확인한다. 실행 또는 브라우징이 필요한 주장은 해당 근거를 확보한다.
5. 덱은 `lecture-deck`의 슬라이드 기준(화면만 보고 핵심을 찾는가, 필요한 정의·값·변화 전후가 있는가)과
   화면 문구·제작 지시·대본의 역할 분리, 전 장 연결을 확인한다. PPTX는 글자가 편집 가능한 텍스트 상자인지(통이미지 장 0)도 본다.
   PPTX/PDF/HTML/그림은 실제 표시를 열어 잘림·겹침·가독성을 확인한다.
   코드가 있으면 문법 검사는 보조로 쓰고 실행 주장은 실제 실행 근거로만 판정한다.
6. 각 결함은 파일·위치·문제·영향·수정 방향으로 보고한다. 검사하지 못한 환경·파일은 별도 표기한다.

## 구조 검사 도구

둘 다 구조 증거다. 통과해도 설명·교육 효과는 직접 읽어 판정한다.

**요구 원장** — 원장이 있는 강의의 완료 판정에는 다음을 실행한다.

```text
python ../lecture-plan/scripts/check_contract.py <원장.json> --require-complete
```

종료코드 0이 아니면 그 범위는 완료가 아니다. 원문 미검토 출처, `verified`가 아닌 필수 요구,
해시가 바뀐 대상·근거, 대상·근거·검토 메모 없는 `verified`를 거부한다. 요구 추출의 완전성은 판정하지 않는다.

**문서와 실물** — 강의 프로젝트 폴더 안에서 실행한다. `<스킬>`은 실제 `.claude/skills/lecture-verify` 경로다.

```text
python <스킬>/문서검사.py              모든 항목
python <스킬>/문서검사.py --항목 참조   한 항목만 (참조·이름·개수·레거시·코드블록·규칙)
python <스킬>/문서검사.py --조용        어긋난 것만
```

문서가 부르는 파일·그림·코드 이름이 실물에 있는지, 같은 대상의 개수가 문서마다 같은지,
취소선 레거시와 학생이 복붙할 파이썬 블록의 문법을 본다. `틀림`이 있으면 종료코드 1, `대기`(아직 만들 것)만 있으면 0이다.
소스와 사용법을 먼저 확인하고, 오래된 규칙에 의한 경고와 실제 요구 위반을 구분한다. 경고를 무시해 통과로 바꾸지 않는다.

강의마다 다른 값은 프로젝트의 문서 폴더 또는 루트의 `문서검사.규칙.json`에 둔다. 없으면 모두 빈 목록이다.

| 키 | 뜻 |
|---|---|
| `랩아닌파일` | 랩 개수에서 뺄 도구·공용 배관 파일 이름 |
| `남의것` | 이 말이 든 줄은 참고 원본의 코드 이야기로 보고 이름·참조 검사를 건너뛴다 |
| `남의문서` | 파일 이름에 이 말이 들면 원본을 다루는 문서로 보고 건너뛴다 |
| `금지` | `[{"패턴": 정규식, "까닭": 설명}]` — 다시 나타나면 안 되는 옛 값 |

작성 예: [references/문서검사.규칙.예시.json](references/문서검사.규칙.예시.json)(다른 강의에서 쓰던 값의 모양).

## 완료 기준

공통 기준 2절 ‘모든 강의의 이해·구현 기준’을 실제 내용으로 검토한다. 필요성 설명이 자연스러운지, 학생이 결정할 부분이 남는지, 에이전트 구현을 무조건 맡기지 않는지, 핵심을 모두 제공하거나 빈칸 대행으로 끝내지 않는지 확인한다. 배포 환경의 실제 검증과 학생 완주·이해 검증을 구분한다.

참고 강의 기반 자료는 원본 챕터 → 회차 질문 → 학생 행동 → 결과 → 다음 회차의 연결을 확인한다. 출처의 구현 사실과 실행 확인을 구별하고, 앞서 정의하지 않은 용어·설명과 다른 코드·근거 없는 예시를 찾는다.

HYD 영상 검수는 `../hyd-lecture-video/SKILL.md`를 따른다. 다른 영상 검수는 공용 `demo-video` 스킬의 기준을 따른다(이 저장소에는 없다. 세션에 있을 때만 쓴다). 검토 대상이 덱·가이드뿐이면 새 녹화·음성 생성을 하지 않는다.

필수 요구가 모두 자료에 반영되고 해당 검증 근거가 있어야 그 범위를 완료로 판정한다.
샘플 검토는 샘플 범위만 검증됨이다. 대기·건너뜀·단순 파일 존재를 통과로 세지 않는다.
자체 도구의 숫자가 설명·교육 효과를 보증하지 않는다. 학생이 판단할 문제에 정답을 미리 주는지 직접 읽는다.
검토 결과를 내기 위해 ZIP·보고서·인계 파일을 자동 생성하지 않는다. 판정 구분은 공통 기준 1절.
