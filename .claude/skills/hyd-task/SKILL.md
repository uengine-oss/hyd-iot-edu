# 작업 하나 — 시작부터 정리까지

아래 순서를 스스로 밟고 단계마다 번호 보고를 한다. push · 지우기는 기본으로 먼저 묻고, 사용자가 "알아서 해"로 맡겼으면 묻지 않고 끝까지 한다(헌법 4절).

## 1. 작업 폴더

- 열린 작업이 있으면(`PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py status`) 사용자 범위와 일치하는 폴더의 `스펙.md`·`기록.md`부터 읽고 잇는다. 병행 작업은 범위와 담당 경로를 구분해 다른 세션의 현재 상태를 덮어쓰지 않는다.
- 새 일이면 `PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py 시작 "짧은 제목"` → `작업/<오늘>_<제목>/`. `스펙.md`에 의도 · 범위 · 읽을 문서 · 인수 조건을 채운다.
- 녹화 원본 · 시험 출력 · 임시 파일은 그 작업 폴더나 `작업/촬영/<도구>/`에만 둔다. 저장소 다른 자리에 흩지 않는다.

## 2. 착수 전 원문 완독

`workspace/README.md` 색인에서 해당 작업의 지침을 찾는다. 읽을 규칙 문서는 많아야 2개다(산출물 지침 하나, 촬영이면 그 도구의 촬영준비, 덱이면 형식 문서). 사실표 · 포털 기능 표 · main 코드는 필요한 대목만 찾아본다.

제작자와 감독은 작업을 시작하거나 이어받을 때, 요약이 일어날 때마다 다음 제작 · 검수 전에 담당 작업 폴더의 `스펙.md` · `기록.md`와 현재 산출물의 지침 원문을 처음부터 마지막 인수 조건까지 직접 읽는다. 파일 · 해시가 같아도 다시 읽고, 출력이 잘리면 빠진 범위를 나누어 읽는다. 동일 판본 산출물의 검증 근거는 재사용한다. Claude에서는 `.claude/hooks/guide_gate.py`가 이것을 동작으로 돕는다: 지침을 끝까지 읽기 전에는 Edit · Write로 그 산출물을 고치는 것과 파이썬으로 직접 부른 덱 · 영상 빌드가 막히고, 요약이 일어나면 읽은 기록이 비워져 막히는 이유와 읽을 줄을 알려 준다. 스크립트의 직접 쓰기 · sed는 잡지 못하니 이 절은 그때도 지킨다. 동작 시험은 `guide_gate.py selftest`. Codex는 요약 직후 안내까지다.

## 3. 만들기 · 검사

- 결과물은 그 문서의 인수 조건 표 전 항목으로 판정한다. 근거 있는 통과 또는 해당 없음(이유)만 남고 불통과·미확인·누락이 0이어야 완료다.
- 문서를 고쳤으면 `workspace/강의제작/제작도구/검사/재편검사.py` 오류 0. 링크를 바꿨으면 끊긴 링크 0.
- 실행한 것만 「됐다」고 쓴다. 안 잰 것은 미검증으로 남긴다.

### 강의 산출물(입구 스킬 hyd-syllabus · hyd-course-deck · hyd-script · hyd-video · hyd-coding-lab · hyd-lab-guide 공통)

1. 시작 보고에 2절에서 실제로 읽은 문서와 판본, 이번 산출물에 적용할 기준을 적는다.
2. 한 세션이 한 회차를 처음부터 끝까지 맡는다. 스펙에서 사용자가 요청한 범위와 실라버스 행 순서를 확인하고 기록에 현재 단계와 다음 단계를 표시한다. 같은 회차의 산출물을 서로 다른 세션에 나눠 동시에 제작하지 않는다.
3. 그 세션 안에서 한 번에 한 종류를 작업한다. 먼저 실라버스와 기존 정본으로 수업의 흐름을 잡고 실습에 필요한 입력·실제 행동·성공 조건을 확인한다. 새로 만드는 이론은 덱 → 그 장을 설명하는 대본·노트 → 영상 순으로, 실습은 도구 동선 또는 랩 검증 → 연결 교재와 설명 일치 확인 → 촬영 대본·큐 → 촬영 → 실제 화면을 쓴 가이드·ZIP 순으로 잇는다. 각 산출물에 착수할 때 2절대로 인수조건까지 지침 전체를 먼저 읽는다. 목적·가치는 내용 선택에, 작업 컨텍스트는 입력 자료·대상·앞뒤 연결에, 작업 요령은 실제 제작 과정에 적용한다. 이미 마친 단계는 판본과 인수 근거를 확인해 이어 쓴다. 앞 단계와 어긋나면 원인이 있는 자리와 영향을 받은 연결만 고친 뒤 진행한다. 두 반이 같은 결과물을 쓰면 한 번 만들고 양쪽 연결을 확인한다.
4. 끝내기 전에 만든 사람이 아닌 검토자가 지침 원문·실제 산출물·본보기를 대조하여 전 항목을 판정한다. 작업자가 만든 결과는 직접 수정하지 않은 감독이 검토할 수 있다. 감독이 직접 수정한 부분은 다른 검토자가 맡는다. 검토자는 고치지 않고 문제·근거를 보고하며, 같은 판본의 유효한 근거는 재사용한다. 현재 도구의 에이전트를 사용한다(Codex 작업은 Codex). 특정 모델명 때문에 다른 CLI·계정·서비스를 실행하지 않는다. 사용자의 명시적인 도구·모델 선택이 우선이다.
5. 작업 중에는 실제 수행한 내용과 확인 근거를 남긴다. 산출물을 마칠 때 그 판본을 기준으로 인수조건 전 항목을 판정한다. 별도 검토자는 기존 근거를 대조하고, 근거가 비거나 어긋난 항목·변경부·연결부를 직접 확인한다. 실습 영상의 재생 범위는 영상.md V요-35를 따른다. 결함이 생기면 마지막 정상 상태와 원본을 보존해 그 범위만 고치고, 영향을 받은 후속 산출물만 다시 판정한다. 통과 근거를 새로 만들기 위해 같은 작업을 되풀이하지 않는다.

보고:

- 인수 조건 N항목 중 통과 · 불통과 · 해당 없음(까닭) 숫자, 불통과 목록(번호 · 근거 위치).
- 각 단계가 끝나면 `기록.md`의 해당 산출물 자리에 판본, 실제로 한 일, 하지 않은 일, 확인하지 못한 결과, 남은 조치와 인수전표 위치를 적는다. 나중에 수행 여부를 물으면 이 기록과 전표로 답한다. 판본이 바뀌거나 근거에 공백이 있는 범위만 다시 확인한다.
- 작업 폴더의 `인수전표.json`에 지침·산출물·근거의 경로와 SHA256, 항목별 판정·위치·이유, 작성자·검토자를 연결한다. 형식과 명령은 `workspace/강의제작/제작도구/검사/인수검사.py` 머리말을 따른다. 완료 보고 전 `…/인수검사.py <인수전표.json> --완료` 오류 0을 확인한다. 이 검사는 누락·판본·독립성·상태를 검사하며 내용·윤문·시각 판단을 대신하지 않는다.

## 4. 제자리에 넣기 — 최신 하나만

| 무엇 | 어디 | 규칙 |
|---|---|---|
| 최종본(덱 · 대본 · 랩 · 가이드 · 영상 · 실라버스) | `workspace/강의제작/산출물/…` | 이전 판을 지우고 바꿔 끼운다. 이름에 판 꼬리(v1 · 날짜 · 사본)를 붙이지 않는다. 영상이면 `산출물/영상/README.md` 그 행을 고쳐 쓴다 |
| 다시 만들 재료(원고 · 큐 · 구성 · 음성 캐시 · 도구) | `workspace/강의제작/제작도구/…` | 고칠 때 다시 쓰는 것만. 녹화 원본 · 프레임 · 합성 wav는 재료가 아니다 |
| 규칙이 바뀜 | 그 산출물의 지침 문서 그 자리 | 덧붙이지 않고 그 주제 자리를 다시 써서 합친다 |
| 시스템 코드 | main(`it` · `ot` · `dmz` · `common` …) | 시스템 문서는 `workspace/개발/문서/`의 소수만. 새 설명 문서를 늘리지 않는다 |
| 공개하면 안 되는 개인 자료 | `작업/_로컬/` | 어느 브랜치에도 올리지 않는다 |

## 5. 동기화

1. `PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py commit "무엇을 왜" [main 경로 …] [--만 workspace 경로 …]` — workspace는 지금 모습 그대로, main은 준 경로만이다. 다른 작업 폴더가 열려 있으면 그 미완성이 섞이지 않게 `--만`으로 이 작업의 경로만 올린다(`status`가 로컬에만 · 내용 다름을 보여 준다). 이전 판 경고가 나오면 고치고 다시.
2. `… workspace/동기화.py push` — 키 검사 0일 때만 두 브랜치를 올린다(강제 push 없음). 맡기지 않은 작업이면 push 전에 묻는다.

## 6. 정리

`스펙.md`의 상태를 「확정」으로 바꾸고 `… workspace/동기화.py 정리 --실행` → 작업 폴더가 지워진다. 끝 보고에는 바뀐 것 · 자리 · 검증 결과 · 남은 일만 적는다.

## 늘

- 딱 봤을 때 정말 필요한가로 본다 — 지울 것은 「이건 이런 건데 필요합니까」로 묻는다. "알아서 해"로 맡겼으면 분명히 필요 없는 것은 지우고(지운 것은 git 이력) 애매한 것만 묻는다.
- 같은 사실은 한 곳에만 쓰고 나머지는 가리킨다. 사본을 만들지 않는다.
