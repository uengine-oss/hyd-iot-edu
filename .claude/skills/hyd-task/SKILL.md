# 작업 하나 — 시작부터 정리까지

아래 순서를 스스로 밟고 단계마다 번호 보고를 한다. push · 지우기는 기본으로 먼저 묻고, 사용자가 "알아서 해"로 맡겼으면 묻지 않고 끝까지 한다(헌법 4절).

## 1. 작업 폴더

- 열린 작업이 있으면(`PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py status`) 그 폴더의 `스펙.md` · `기록.md`부터 읽고 잇는다.
- 새 일이면 `PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py 시작 "짧은 제목"` → `작업/<오늘>_<제목>/`. `스펙.md`에 의도 · 범위 · 읽을 문서 · 인수 조건을 채운다.
- 녹화 원본 · 시험 출력 · 임시 파일은 그 작업 폴더나 `작업/촬영/<도구>/`에만 둔다. 저장소 다른 자리에 흩지 않는다.

## 2. 읽을 문서 하나

`workspace/README.md` 색인에서 하려는 일의 문서 하나를 골라 끝까지 읽는다(촬영이면 그 도구의 촬영준비 하나를 더). 강의 제작이면 그 산출물의 `hyd-*` 스킬을 이어서 쓴다.

## 3. 만들기 · 검사

- 결과물은 그 문서의 인수 조건 표로 판정한다. 불통과 0이 완료다.
- 문서를 고쳤으면 `workspace/강의제작/제작도구/검사/재편검사.py` 오류 0. 링크를 바꿨으면 끊긴 링크 0.
- 실행한 것만 「됐다」고 쓴다. 안 잰 것은 미검증으로 남긴다.

### 강의 산출물(입구 스킬 hyd-syllabus · hyd-course-deck · hyd-script · hyd-video · hyd-coding-lab · hyd-lab-guide 공통)

1. 그 문서를 끝까지 읽는다. 대화가 요약 · 재개된 뒤에도 다시 끝까지 읽는다(요약을 믿지 않는다).
2. 작업 컨텍스트에서 이번 일의 입력(실라버스 행 · 본보기 · 앞뒤 산출물 · 지금 상태)을 실물로 확인한다.
3. 담당자에게 해당 산출물의 목적·가치, 작업 컨텍스트·요령, 인수조건과 현재 판본을 함께 전달한다. 담당자는 작업 직전에 해당 문서를 정독하고 해당 범위를 제작한다. 변경 구간과 연결부를 먼저 고치고, 검증한 판본·근거를 재사용해 같은 자료의 재독·모델 호출·전체 재생성을 줄인다. 도구 · 명령 · 경로는 그 문서의 작업 컨텍스트(도구 · 경로 표)와 작업 요령에 있다. 로컬 Windows는 `PYTHONUTF8=1 .venv314/Scripts/python.exe`.
4. 끝내기 전에, 만든 사람이 아닌 검토자(서브에이전트 opus, 문서와 산출물만 받고 고치지 않고 목록만)가 그 문서의 인수 조건 표 전 항목을 판정한다.
5. 불통과를 고치고, 고친 범위를 다시 판정한다. 불통과 0이 되기 전에는 끝났다고 쓰지 않는다.

보고:

- 인수 조건 N항목 중 통과 · 불통과 · 해당 없음(까닭) 숫자, 불통과 목록(번호 · 근거 위치).
- 실행하지 않은 것 · 열어 보지 않은 것은 `미확인`으로 따로 적는다.

## 4. 제자리에 넣기 — 최신 하나만

| 무엇 | 어디 | 규칙 |
|---|---|---|
| 최종본(덱 · 대본 · 랩 · 가이드 · 영상 · 실라버스) | `workspace/강의제작/산출물/…` | 이전 판을 지우고 바꿔 끼운다. 이름에 판 꼬리(v1 · 날짜 · 사본)를 붙이지 않는다. 영상이면 `산출물/영상/README.md` 그 행을 고쳐 쓴다 |
| 다시 만들 재료(원고 · 큐 · 구성 · 음성 캐시 · 도구) | `workspace/강의제작/제작도구/…` | 고칠 때 다시 쓰는 것만. 녹화 원본 · 프레임 · 합성 wav는 재료가 아니다 |
| 규칙이 바뀜 | 그 산출물의 지침 문서 그 자리 | 덧붙이지 않고 그 주제 자리를 다시 써서 합친다 |
| 시스템 코드 | main(`it` · `ot` · `dmz` · `common` …) | 시스템 문서는 `workspace/개발/문서/`의 소수만. 새 설명 문서를 늘리지 않는다 |
| 공개하면 안 되는 개인 자료 | `작업/_로컬/` | 어느 브랜치에도 올리지 않는다 |

## 5. 동기화

1. `PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py commit "무엇을 왜" [main 경로 …]` — workspace는 지금 모습 그대로, main은 준 경로만. 이전 판 경고가 나오면 고치고 다시.
2. `… workspace/동기화.py push` — 키 검사 0일 때만 두 브랜치를 올린다(강제 push 없음). 맡기지 않은 작업이면 push 전에 묻는다.

## 6. 정리

`스펙.md`의 상태를 「확정」으로 바꾸고 `… workspace/동기화.py 정리 --실행` → 작업 폴더가 지워진다. 끝 보고에는 바뀐 것 · 자리 · 검증 결과 · 남은 일만 적는다.

## 늘

- 딱 봤을 때 정말 필요한가로 본다 — 지울 것은 「이건 이런 건데 필요합니까」로 묻는다. "알아서 해"로 맡겼으면 분명히 필요 없는 것은 지우고(지운 것은 git 이력) 애매한 것만 묻는다.
- 같은 사실은 한 곳에만 쓰고 나머지는 가리킨다. 사본을 만들지 않는다.
