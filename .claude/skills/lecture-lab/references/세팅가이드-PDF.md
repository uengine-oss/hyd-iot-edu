# 캡처 기반 환경 세팅 문서 — 내용·캡처 기준

설치·계정 설정·편집기/도구 준비를 초보 학생이 화면을 보며 따라 하는 문서에 적용한다.
작성 틀과 PDF 생성은 [실습가이드-틀](실습가이드-틀.md)의 「준비안내의 틀」과 `md2pdf.py`가 정본이다. 이 문서는 그 위에 얹는 기준이다.
일반 코딩 실습의 구성을 이 기준으로 덮어쓰지 않는다. 강의 계약·사용자 템플릿이 우선한다.

## 디자인 기준 자산

"기존 세팅 PDF와 같은 모양" 요청의 시각 기준이던 완성본 PDF(18쪽)와 그 본문 생성 코드(`doc2.py`)는 다른 과정의 교재 본문과 화면 캡처여서 이 저장소에 싣지 않았다. 같은 모양이 필요하면 사용자에게 기준 PDF를 받아 표지·단계·화면 배치를 열어 비교한다.
`../assets/setup-guide-reference/`에는 배치 규칙만 남겼다: `common.py`(CSS와 `step()`·`fig()`·`cover()` — WeasyPrint 생성기의 공통부), `render.sh`(렌더와 몽타주), `annotate_example.py`(빨간 네모·크롭), `original-instructions.md`(그 생성기의 원래 지침. `doc2.py`·`doc2_reference.pdf`를 가리키는 대목은 위 사정으로 대상이 없다). 출처 보존용이며 그대로 실행하지 않는다.

## 입력

1. 대상 강의의 학생 OS/UI 언어·필수 프로그램·도달할 준비 상태를 확인한다.
2. 받은 캡처/ZIP을 전부 열어 각 이미지의 원본 크기와 행동 전후 상태를 기록한다. 이미 받은 자료에서 필요한 화면을 먼저 찾는다.
   캡처가 없으면 접근 가능한 실제 UI에서 확보하고, 접근할 수 없을 때만 번호 목록(전체 화면 기준·어느 상태)으로 요청한다. 이미 있는 화면은 다시 요청하지 않는다.
3. 강의에 실제 쓰는 설치만 넣는다. 기준 예시의 확장 목록·무조건 재설치·Allow all·모델명·요금은 재사용하지 않고 현재 공식 근거로 확인한다.
   실제 사용처가 확인되지 않은 설치를 넣었다가 "왜?"라는 질문을 받으면 이미 실패다.

## 단계 구성

표지 다음 바로 1장으로 시작한다. 개요·읽는 법·미니맵·준비물 표·체크리스트·부록을 기본으로 넣지 않는다
(학교가 요구한 준비물·안전 안내는 예외).

- **행동:** 위치를 첫 문장에 녹인다("왼쪽 세로 아이콘줄 맨 위"). 별도 위치 지도 상자를 만들지 않는다.
- **화면:** 행동 화면과 그 결과 화면. 결과 없는 단계는 없다. 누구나 누르는 확인 창은 캡처 없이 한 줄로 쓴다.
- **확인:** 마지막 화면에서 눈으로 판단할 수 있는 성공 조건 한 문장.
- **주의/화면이 다를 때:** 실제로 재현되는 차이만 둔다. 없는 오류를 상상하지 않는다.

UI 이름은 실제 화면에서 확인한 명칭만 쓴다. 아직 나오지 않은 개념을 앞 단계에서 꺼내지 않는다.

## 캡처

- 원본 캡처는 보존하고 크롭·표시본을 따로 저장한다. 빨간 네모 규칙은 실습가이드-틀의 「캡처에는 누를 자리를 표시한다」를 따른다.
- 같은 화면을 전체·확대로 두 번 싣지 않는다. 누를 곳이 전체 화면에서 너무 작을 때만 확대본을 쓴다.
- 원본보다 키워 흐리게 만들지 않는다. 작으면 더 나은 원본이나 관련 영역 캡처를 확보한다.
- 글자를 읽어야 하는 설정·목록·터미널 캡처는 나란히 두지 않는다. 대칭인 두 화면만 나란히 둔다.

## 검증

PDF 전 쪽을 PNG로 떠서 장 제목만 남은 쪽, 화면과 확인의 분리, 잘림·겹침, 큰 빈 여백, 흐린 캡처를 확인한다.
지적은 그 항목만이 아니라 같은 유형 전체에 적용한다. 디자인 예시나 새로 쓴 예상 출력을 실제 실행 결과라고 부르지 않는다.
PDF 렌더 검증과 학생 환경 설치·완주 검증은 따로 기록한다.
