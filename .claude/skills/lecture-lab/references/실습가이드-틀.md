# 실습가이드·준비안내 틀

Markdown/PDF 실습가이드, 준비안내(환경 세팅), 따라하기 문서를 쓰기 전에 읽는다. PDF 생성기는 `../assets/가이드기준/md2pdf.py`다.
HYD 과정의 실습 가이드는 이 틀이 아니라 `docs/실습가이드/틀/`(`형식.md`, `실습가이드_틀.html`)을 따른다(`hyd-lab-guide` 스킬).
강의 계약·학교 양식·기존 가이드 구조가 있으면 그쪽이 우선이다. 없으면 **새 절 구조를 만들지 않는다.** 아래 두 틀의 절·단계·캡처·에러 자리를 그대로 쓰고 내용만 바꾼다(자체 절 구조로 낸 가이드가 틀을 따르지 않았다는 지적으로 폐기된 적이 있다).

틀의 바탕이 된 기준 원문 둘(실습가이드, 준비안내)과 설치 화면 캡처 23장은 다른 과정의 교재 본문과 화면이어서 이 저장소에 싣지 않았다. 틀의 뼈대는 아래 두 코드 블록에 있다.

| 자산 | 무엇 |
|---|---|
| `md2pdf.py` | 가이드 MD → A4 PDF. `python md2pdf.py <가이드.md> <출력.pdf> "<제목>"`. 그림은 md 위치 기준 상대경로, 없는 그림이면 멈춘다 |

## 실습가이드의 틀

```
# N회차 실습 · 주제
## 시작 전에 · (이 공장은 축소 모형입니다)      ← 모형·정한 값 표·「방향은 진짜, 크기만 줄였다」
## 1 · ~합니다                                    ← 절 제목은 행동. 도입 1~2문장이 「왜 이걸 하나」
**① ~합니다**  ▸ 앱 이름                          ← 단계는 ①②③, 굵게, 뒤에 ▸ 어느 창인지
(한두 줄 안내)
```                                                ← 치는 것은 코드칸. ```주소 는 크롬 주소창
명령
```
![이 화면이 보이면 된 것입니다](그림/실습/실습_N_이름.png)   ← 캡션이 「무엇이 보이면 성공」을 말한다
(그 명령이 한 일 2~4문장 — 학생이 방금 본 것의 뜻)
**여기서 에러가 나면 …**                            ← 에러 대처는 그 자리. 뒤로 몰지 않는다
**⑤ 화면에서 세 가지를 확인합니다**                  ← 절 끝은 「확인할 것」 목록
- …
**이 탭은 그대로 둡니다.**                           ← 다음 절로 넘길 상태
```

- 숫자는 대조해 준다(7일 × 24시간 × 60분 = 10,080 · 여섯 대 = 60,480). 카드 숫자가 다르면 왜 다른지 한 줄.
- **블록·잡내용 금지(2026-09-16 사용자 확정).** `>` 인용 블록으로 배경 설명을 늘어놓지 않는다 — 꼭 필요한 배경은 그 자리의 본문 한두 문장으로 쓴다.
  제작 로그·내부 판정·검증 이력·강사용 메모·「제작자 검증본의 실제 응답」 같은 우리 작업 흔적은 한 줄도 넣지 않는다.
  학생이 읽을 것은 행동·명령·실제 화면·확인할 것·에러 대처뿐이다.
- 학생이 정하는 자리는 「여기가 벽입니다」처럼 절을 따로 두고, 정답을 미리 쓰지 않는다.
- 회차 마지막 절은 「오늘 한 것 · 저장 · 다음 회차에 쓰는 것」이다.
- 덱과 같은 사실은 같은 숫자·같은 용어로 쓴다. 덱에서 정의한 용어를 가이드에서 풀어쓰지 않는다.

## 준비안내의 틀

```
# 강의명 — 실습 환경 준비
N가지를 차례로 합니다. **⑦번의 X가 뜨면 끝**입니다.
## ① 이름 (분)
**무엇인가 한 문단.** 왜 필요한지, 실습에서 어디에 쓰는지 — 초보자가 「왜 깔아야 하나」를 안다
**1. 소단계** — 행동. 굵은 UI 이름.
![캡션 — 무엇을 누른다](그림/앱_번호_이름.png)
| 물어보는 것 | 이렇게 하세요 |                     ← 설치 중 묻는 것은 표
> 주의 한 문단                                      ← 진짜 재현되는 실수만
## ⑦ 켜 보기                                       ← 마지막은 실제로 켜서 화면이 뜨는 것
### ~가 안 켜지면                                   ← 안 될 때는 맨 끝 절. 「잘못하신 것이 아닙니다」로 시작
| 이렇게 나오면 | 무엇이 어긋났나 | 하실 일 |
```

- 그 강의에 이미 확인된 설치 단계 원문이 있으면 그대로 쓰고, 바뀐 것(폴더 이름·실습 파일·주소·명령)만 바꾼다.
- 원문에 없는 단계는 같은 틀(무엇인가 → 소단계 → 캡처 → 확인)로 이어 붙인다.
- 캡처가 없는 단계는 `<!-- 사진: 어느 화면 · 어느 상태 -->` 로 자리를 적고 사용자에게 요청한다. 유사 화면으로 채우지 않는다.

## 렌더와 검사

`python <스킬>/assets/가이드기준/md2pdf.py 가이드.md 가이드.pdf "제목"` 로 PDF 를 만든다(Playwright 크로미움 필요).
코드칸 말머리(`주소`·`python`·`json`·`모양`·`지시문` 등)와 라벨은 md2pdf.py 의 `칸종류`가 정본이다.
말머리 없는 칸은 첫 낱말이 `명령시작` 목록에 있을 때만 「터미널에 칩니다」, 아니면 「화면에 이렇게 나옵니다」가 된다.
새 명령을 쓰면 그 첫 낱말이 목록에 있는지 본다 — 없으면 치라고 준 명령이 출력처럼 보인다.
`.env` 에 넣을 줄은 `python` 말머리(파일에 씁니다)로, 화면 입력칸에 칠 문장은 코드칸이 아니라 본문 굵은 글씨로 쓴다.
### 캡처에는 누를 자리를 표시한다

화면만 붙여 놓으면 학생은 「그래서 어디를 누르라는 건가」에서 멈춘다.
**클릭·입력·확인할 요소마다 빨간 사각형**을 그린다. 색·두께는 한 문서 안에서 같게 간다
(빨강 `(230,30,30)`, 두께 `너비/200` 기준. 실제 UI 글자·결과는 합성하지 않는다).

- 좌표는 **눈금 사본으로 실제로 재서** 넣는다. 어림으로 그리면 요소에서 어긋난다.
- 원본은 `그림/_표시전/` 에 남기고, 다시 그릴 때도 **항상 원본에서** 다시 그린다. 상자 위에 상자를 겹치지 않는다.
- 결과 화면(관찰만 하는 화면)에도 **무엇을 봐야 하는지** 한 곳은 표시한다.
- 남의 캡처를 가져올 때는 **거기 붙어 있던 옛 표시**가 우리 설명과 맞는지 본다.
  맞지 않으면 지우거나 잘라 낸다(실측 2026-09-17 — 「여기에 붙여넣습니다」 캡처의 상자가 휴지통에 있었다).
- 캡처 속 경로·계정은 가린다. 가린 자리에 **그 학생이 보게 될 값**을 적어 둔다(`…\lab>`).

### 참고 자산이 있으면 화면까지 가져온다

「참고 저장소를 활용한다」가 계약이면 **서버 API 만이 아니라 화면도 그 자산을 쓴다.**
원본에 쓸 만한 화면이 있는데 새로 만들면, 겉모습이 초라해지고 계약도 어긴 것이 된다
(실측 2026-09-17: 원본 `ops-console` 이 126줄 Vue 로 우리 것보다 많은 일을 하고 있었는데
우리는 바닐라 JS 로 새로 만들어 두고 몰랐다).

원본을 그대로 못 쓰면 **디자인 토큰·레이아웃·상태 배지만이라도** 가져온다. 색과 카드 규칙을 맞추는 것은
API 를 안 건드리므로 위험이 낮다.

### 화면과 학생 코드 사이에는 창구를 낸다

학생이 채울 파일이 화면의 DOM 을 뒤지게 두지 않는다. `document.querySelector('#assets button.active')`
같은 코드는 화면을 조금만 바꿔도 깨지고, 학생에게 「무엇을 쓸 수 있는지」도 안 보인다.
화면이 **작은 공개 객체**를 내주고 학생 코드는 그것만 쓰게 한다.

    window.lab = { asset(), question(), refresh(), onSelect(f) }

그 이름을 학생 파일의 주석과 가이드 지시문에 **같은 말로** 적는다.

### 템플릿 강의는 「바꿀 자리」가 한 곳이어야 한다

분야를 바꾸려면 어디를 고치는지가 한 문장으로 나와야 한다. 화면 코드 여기저기를 고쳐야 하면 템플릿이 아니다.
대상·측정값·라벨은 **정의 파일 하나**에 모으고 화면은 그 계약만 보고 그린다.

### 영역 관리 — 끊기지 않게, 남으면 채우게 (2026-09-17 사용자 확정)

**한 단계가 쪽 경계에서 갈라지면 안 된다.** 설명과 그 화면이 떨어지거나 표가 잘리면 학생이 길을 잃는다.
md2pdf 는 `.keep` 으로 단계·명령·캡처를 한 덩어리로 묶고 `figure` · `.term` · `tr` 에 `break-inside: avoid` 를 건다.

**묶고 나서 쪽 아래에 여백이 남으면 그 쪽의 캡처를 늘려 채운다.** 이미지를 작게 고정해 두고 여백을 남기지 않는다.
md2pdf 가 PDF 를 한 번 뽑아 쪽마다 바닥에 남은 높이를 재고, 그 쪽 캡처에만 남은 만큼을 더해 다시 뽑는다(2차 배치).
CSS 상한만 올리면 반대로 나빠진다 — 실측(준비안내): 상한 90mm 는 여백 80mm 넘는 쪽이 4개인데 130mm 로 올리면 16개다.
캡처가 커진 만큼 다음 덩어리가 밀려 한 쪽에 캡처 하나만 남기 때문이다.

세로가 가로의 1.2배를 넘는 캡처는 `img.tall` 로 높이를 더 준다. 안 그러면 폭까지 같이 줄어 본문 폭의 3분의 1만 쓴다.

재는 법 — 쪽마다 `(쪽 높이 − 아래 여백 − 마지막 요소 바닥)` 을 mm 로 계산한다. 80mm 넘게 남는 쪽이 절 끝 말고 또 있으면 배치가 덜 된 것이다.

PDF 전 쪽을 PNG 로 떠서 본다 — 캡처와 캡션이 쪽 경계에서 갈라졌는가, 표가 잘렸는가, 그림이 흐린가.
가이드가 부르는 그림이 다 있는지는 md2pdf 가 멈춰서 알려 준다. 있다고 맞는 화면은 아니다 — 캡션과 그림을 대조한다.
