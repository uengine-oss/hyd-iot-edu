# 실습 환경 세팅 문서 (PDF) 작성 스킬

## 0. 이 스킬이 만드는 것

- A4 PDF 한 부. 표지 1장 + 장(章) 단위 본문. 본문 10pt.
- 독자: 개발 도구를 처음 보는 학생. **"유치원생도 따라온다"** 가 기준.
- 도구: Python 3 + `weasyprint` + `Pillow`. 폰트는 Noto Sans CJK KR.
- 산출: `/mnt/user-data/outputs/<번호>_<제목>.pdf` 로 저장 후 `present_files`.

`reference/` 에 완성본 예시(2번 문서: VS Code 설치 및 코딩 에이전트 세팅)와 그 생성 코드가 있다. **새 문서는 항상 `reference/common.py` 를 그대로 가져다 쓰고, `reference/doc2.py` 를 복사해서 내용만 바꾼다.** 레이아웃 규칙이 코드에 이미 들어 있다.

## 1. 문서 구조 (고정)

```
[표지]  남색 전면 슬라이드. 시리즈 라벨(실습 환경 세팅 문서 · n/4) · 큰 번호 · 제목 · 부제 1~2줄 · 설명 3문장 · 하단 기준(날짜·OS)
[1장]  ← 표지 다음 장에서 바로 시작. 개요·목차·"읽는 법"·준비물 표 같은 것 없음
  번호 단계 1
  번호 단계 2
[2장] ...
(끝)   ← "꼭 기억할 것", 체크리스트, 부록, 기록판 등 없음
```

- 표지의 설명 3문장이 개요의 전부다. "무엇을 설치하는지 · 끝나면 뭐가 되는지 · 어디까지가 이 문서인지" 한 문맥으로.
- 장은 새 페이지에서 시작한다. 장 제목은 「n장. 무엇 — 한 줄 부연」.
- 장 제목 아래 1~2문장 안내(왜 하는지)는 허용. 그 이상은 안 됨.

## 2. 단계(step) 하나의 구조 (고정)

```
(번호) 단계 제목
 1. 행위 — 어디를 어떻게 누른다
 2. 행위
 [화면] 행위 화면 (빨간 네모)         ← 설명과 같은 페이지에 반드시 붙는다
 [화면] 결과 화면                    ← 행위 → 결과. 결과 없는 단계는 없다
 확인 · 이렇게 보이면 성공           ← 마지막 화면과 같은 페이지
 (주의 · 빨강) (팁 · 노랑) (화면이 다를 때 · 보라)
```

- **행위 → 결과.** 버튼을 눌렀으면 눌러서 뭐가 됐는지 화면이 있어야 한다. "폴더 선택"을 눌렀으면 폴더 이름이 탐색기에 뜬 화면까지.
- **위치는 문장 안에.** "왼쪽 세로 아이콘줄 맨 위", "입력창 바로 아래", "창 맨 위 오른쪽 끝" 식으로 첫 문장에 녹인다. 별도의 위치 지도/미니맵/아이콘 안내 상자를 만들지 않는다 (어색하다고 확정됨).
- **확인 줄은 한 문장.** 눈으로 보고 판단할 수 있는 것만. "설정 끝" 같은 감상 X.
- **화면이 다를 때(보라)** 는 그 단계에서 실제로 갈릴 수 있는 것만. 없는 오류 상상하지 말 것.

## 3. 화면(캡처) 규칙

### 3-1. 무엇을 넣나
- **전체 화면 → 확대** 패턴은 "누를 곳이 전체 화면에서 콩알만 할 때"만. 확대본이 이미 충분히 크면 전체 화면을 넣지 않는다 (중복).
- 반대로 전체 화면만으로 충분히 보이면 확대본을 넣지 않는다.
- 같은 화면이 두 번 나오면 하나는 지운다. 예: 신뢰 창 전체 + 신뢰 창 확대 → 확대 하나만.
- **누구나 다 누르는 확인 창**(활성화/OK/예)은 캡처 안 넣는다. 글로 "활성화를 누른다" 한 줄.
- 설치 상세 페이지(확장 마켓 상세 화면 등)처럼 정보값 없는 화면은 뺀다.
- 채팅 패널 열기처럼 "단축키 하나면 누구나 보이는 것"은 전체 화면 X, 결과만.

### 3-2. 크기 규칙 (코드가 자동 처리 — `fig()`)
- 이미지는 **가로 페이지 폭(180mm) 또는 세로 150mm 중 먼저 걸리는 쪽까지** 키운다. 한쪽이 막히면 거기가 끝.
- 단 **원본 픽셀 크기(96dpi 환산)를 넘겨 확대하지 않는다.** 작은 부분 캡처는 흐려지므로 원본 크기 상한. → 사용자가 부분 영역만 잘라 준 캡처는 굳이 키우지 않아도 된다는 뜻.
- 페이지 아래 여백이 크게 남으면 그 페이지의 이미지를 더 키운다(가로·세로 함께). 캡처가 작아서 못 읽히는 페이지가 하나라도 있으면 실패.
- 나란히(figrow)는 **정보가 대칭인 두 장**(설치 마법사 2·3화면, 검색창·결과)에만. 설정 화면·목록·터미널처럼 글자를 읽어야 하는 캡처는 절대 나란히 두지 않는다 (글자가 안 보임).
- 폭이 넓고 세로가 짧은 캡처(설정 항목 3개 등)는 **관련 영역만 잘라서** 넣는다 (`c_*.png` 처럼 크롭본 생성).

### 3-3. 빨간 네모
- PIL 로 원본에 직접 그린다(`box()`). 선 두께 4~5px, 색 (230,30,30).
- 좌표는 **원본 픽셀 기준**. 뷰어에서 축소된 이미지를 보고 좌표를 잡으면 틀린다 → 반드시 `Image.open(f).size` 로 원본 크기 확인 후 환산.
- 한 캡처에 네모는 하나. 누를 곳 하나.

### 3-4. 캡처 요청
- 사용자에게 추가 캡처를 요청할 땐 **번호 목록으로, 전체 화면 기준, 어떤 상태(무엇을 누른 직후)인지** 명시. "자르지 말고 전체로, 이름은 아무렇게나".
- 이미 있는 캡처와 겹치는 요청은 하지 않는다(사용자가 지적함). 요청 전에 zip·이전 업로드를 전부 다시 훑을 것.
- 없는 캡처는 `todo_fig('그림 n-m. …')` 로 점선 상자를 두고 캡션에 무엇이 들어갈지 적는다. 사용자가 나중에 채운다.

## 4. 글 규칙

- 명령형 현재. "~한다", "~를 누른다". 존댓말 X (본문). 표지 부제는 "~한다" 유지.
- 메뉴·버튼 이름은 **굵게**, 한국어 UI 기준으로 쓰고 괄호에 영어 병기: **기본 설정: 사용자 설정 열기(JSON)** (Preferences: Open User Settings (JSON)).
- 키는 `<span class="kbd">Ctrl</span>+<span class="kbd">Alt</span>+<span class="kbd">I</span>`.
- 붙여넣는 값은 `<pre>` (검은 상자). "직접 치지 말고 붙여넣는다"를 첫 등장 때 한 번.
- 강의별로 바뀌는 값(폴더명·URL·명령)은 `<div class="cmd">` 에 "[ 강의별 — 추후 기입 ]" 자리표시.
- 아직 안 나온 개념을 미리 꺼내지 않는다. 예: 1장 설치 결과 화면 캡션에 "채팅 패널이 없어도 정상(4장에서 연다)" → 혼란. 4장에서 처음 말한다.
- 사실이 아닌 안심 문구 X. 확인 안 된 것은 넣지 않거나 "드물게 ~한 경우도 있다" 수준으로. 금액·정책은 공식 문서로 확인한 것만.
- "로그인하지 않는다" 같은 부정 지시는 왜인지 없으면 빼거나, 한 문장으로 이유를 붙인다.
- 이모지·과장·"완벽·간단" 같은 수식 X.

## 5. 페이지 넘김 규칙 (코드가 처리 — `step()`, CSS)

- `.keep` 두 개: ① 단계 번호+설명+첫 화면, ② 마지막 화면+확인+주의. 이 두 덩어리는 절대 페이지를 넘기지 않는다. 중간 화면만 넘어갈 수 있다.
- 장 제목은 `break-before: page`.
- 캡션·확인·주의 상자는 `break-inside: avoid`.
- 렌더 후 **반드시 전 페이지 몽타주를 만들어 눈으로 본다.** 확인할 것: 장 제목만 덜렁 있는 페이지 / 확인 줄만 넘어간 페이지 / 아래 절반이 빈 페이지 / 글자 안 읽히는 캡처. 하나라도 있으면 폭·높이·나란히 여부를 조정해 다시 렌더.

## 6. 작업 순서

1. 재료 전독. zip 은 전부 열어서 본다(문서만 보고 "전수 열람"이라 쓰지 않는다). 각 캡처의 원본 크기를 기록.
2. 장·단계 목차를 먼저 사용자에게 한 번 보여주고 흐름 합의. 이때 "이 화면이 더 있으면 좋다" 목록도 같이 (겹치지 않게).
3. `reference/common.py` 복사, `docN.py` 작성 → 렌더 → 몽타주 확인 → 수정 반복.
4. 사용자 지적은 **그 항목만이 아니라 같은 유형 전체**에 적용한다. ("10번 화면이 안 보인다" → 모든 페이지의 작은 캡처를 점검.)
5. 이전 판정이 뒤집히면 "이건 폐기"라고 말한다. 조용히 바꾸지 않는다.

## 7. 하지 말 것 (사용자가 직접 지적한 것들)

- 개요 페이지, 읽는 법 표, 준비물 표, 흐름 상자, 부록, 체크리스트, "꼭 기억할 것"
- 위치 지도 / 미니맵 / "지금 어디?" 상자
- 같은 화면 중복 (전체+확대 둘 다 넣기)
- 누구나 누르는 확인 창 캡처
- 강의에 필요 없는 설치 (Node.js, Container Tools 등 — 실제 사용처 확인 안 된 것은 넣지 않는다. 넣었다가 "왜?"라는 질문을 받으면 그건 이미 실패)
- 캡처를 줄여서 여백 남기기. 반대로 원본보다 키워서 흐리게 만들기
- 글자 읽어야 하는 캡처를 나란히 배치
- 아직 안 나온 개념 미리 언급
- 미확인 사실 단정 (예: 임시 결제 금액, 오류 창에 링크가 있다 등)

## 8. reference/ 내용

- `doc2.py` — 완성본 생성 코드. 새 문서는 이걸 복사해 시작.
