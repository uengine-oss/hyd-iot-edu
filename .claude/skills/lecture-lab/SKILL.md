# 실습코드·학생 가이드·실행 검증

공통 기준(`../lecture-common/공통기준.md`)과 저장소 루트 `CLAUDE.md`, 대상 강의의 계약·학습목표·학생 환경을 먼저 따른다.
아래 경로는 이 스킬 폴더 기준이다. 학교 지시·리서치 기반 제작은 `lecture-plan`으로 요구와 수용 기준을 먼저 연결한다.
영상 녹화·UI 시연 영상·음성 싱크는 이 스킬의 범위가 아니다. 명시 요청 때 공용 `demo-video` 스킬이 맡는다(이 저장소에는 없다. 세션에 있을 때만 쓴다).

HYD 실습은 `../hyd-lab-guide/SKILL.md`로 시작하고, 수업 구성과 덱·실습 자료의 경계는 `문서/교재/2_기준.md` 6절 · 37번을 따른다.

## 가이드 형식 고르기

형식은 강의 계약·학교 양식·사용자 지정이 먼저다(예: 편집 가능한 원본 + HTML, PDF 없음).

| 요청 | 읽을 것 |
|---|---|
| HTML 실습가이드·복사 버튼·붙여넣을 위치·단계별 이야기 | [HTML실습가이드](references/HTML실습가이드.md) |
| Markdown/PDF 실습가이드·준비안내(환경 세팅)·따라하기 문서 | [실습가이드-틀](references/실습가이드-틀.md) — 절·단계·캡처·에러 자리의 틀, PDF는 `assets/가이드기준/md2pdf.py` |
| 설치·계정·편집기 준비를 캡처로 따라 하는 세팅 문서, "기존 세팅 PDF와 같은 모양" | 위 틀에 더해 [세팅가이드-PDF](references/세팅가이드-PDF.md) |

틀을 쓰더라도 현재 실행 환경·파일·명령을 확인한다. 기존 WSL·Docker 설치 순서나 과거 PDF를 자동 복제하지 않는다.
PDF는 계약·사용자가 요구한 경우에만 만든다.

## 실습가이드 내용

실습 본문은 상황과 필요한 이유를 설명한다. 환경 준비 안내를 짧게 쓰라는 요청을 실습 본문의 설명 삭제로 확대하지 않는다.
코딩 Agent 실습은 학생이 기능을 이해하고 연결·수정 영향을 조사시킨 뒤, 범위와 확인 방법을 정해 구현·검증하는 작업 방법을 가르친다.
힌트는 학생이 무엇을 질문하고 판단할지 돕는다. 완성 프롬프트는 막힐 때만 펼치는 보조 예시이며 기본 행동을 복사 과제로 바꾸지 않는다.
정답 코드는 출발본에 섞지 않는다. 환경 준비 안내는 짧은 행동·성공 확인·실패 복구 중심으로 쓰며 장황한 이론은 넣지 않는다.

## 실습 설계

공통 기준 2절 ‘모든 강의의 이해·구현 기준’을 적용한다. 출발본마다 제공 기반 / 학생이 이해·결정할 것 / 에이전트가 구현할 핵심 / 실제 확인 결과를 연결한다. DB·MCP 연결도 해당 회차 목표라면 구현 범위에 둔다. 검증된 환경 제공을 이유로 핵심 구현까지 미리 완성하지 않는다.

참고 강의 기반 제작에는 `../lecture-plan/references/evidence-led-authoring.md`를 읽어 학생과 에이전트의 역할, 단계별 응용, 가이드 내 개념 설명을 연결한다.

1. 청중의 선수 지식·설치 환경·계정·네트워크·하드웨어·시간·학생 배포 범위를 확인한다.
2. 각 실습의 학생 행동, 바꾸는 입력, 관찰할 결과, 성공 판단, 실패 복구를 정한다.
   실행 성공과 학습목표 달성을 구분한다. 파라미터 조정·빈칸·자유 구현 중 계약에 맞는 방식을 택한다.
3. 여러 실습이면 앞 결과와 뒤 입력을 연결하고 대표 실습 하나를 실제로 검증한 뒤 확장한다.
   필요한 외부 서비스나 비용이 승인되지 않았으면 그 실행만 보류하고 독립 제작을 진행한다.

## 코드와 가이드

코드는 명시 입력과 명확한 오류를 사용하고 비밀값·사용자 절대경로·정답 하드코딩을 배포하지 않는다.
학생용 빈칸이 요구되면 빈칸의 판단을 주석에서 미리 풀지 않는다. 강사용 정답·검증 도구는 따로 둔다.
한 사실의 코드 소유 위치와 설명 위치를 정하고 값 변경 시 함께 맞춘다.

학교 양식이나 기존 학생 가이드가 있으면 그 구조를 보존한다. 없으면 위 「가이드 형식 고르기」의 틀을 쓴다.
처음 등장하는 개념은 청중 수준에 맞게 설명한다. 전공자라고 가정하거나 용어 설명을 일괄 금지하지 않는다.
필요한 준비물·폴더 구조·예상시간·도움말은 학생의 실행을 돕는 위치에 둔다.
문체는 `../lecture-deck/references/문체.md`를 참고하되 가이드에는 학생 행동을 명확하게 적는다.

## 실행·화면

학생 배포본과 같은 입력·폴더·명령에서 실행한다. 필요한 준비와 설치를 가이드에서 빼먹지 않는다.
전체 완주를 요청했으면 실제 처음부터 끝까지 실행한다. 작은 수정은 영향받은 실습을 검증한다.
명령·환경·입력·종료 상태·출력·시간을 근거로 남긴다. 자동 실행시간은 학생 수업시간이 아니다.
mock·문법 검사는 완주가 아니다(공통 기준 1절). 실행할 수 없는 GPU·계정·장비 구간은 정확히 미검증으로 표시한다.

화면 제작 전 `references/그림요구.md`와 `references/그림도구.md`를 읽는다.
`가이드그림.py`는 실제 실행 로그를 그림으로 재구성한다. 도구의 출력 잘림·종료코드 한계를 확인한다.
PNG 존재와 실제 그림 내용을 모두 확인한다. 실패한 실행을 정상 화면으로 쓰지 않는다.
브라우저·GUI 캡처는 현재 사용 가능한 도구로 실제 확인한다. 접근할 수 없을 때만 필요한 상태를 특정해 요청한다.
학생 공개 전에 로그·그림의 비밀값과 정답 노출을 확인한다.

## 검증과 결과

요구와 실제 코드·가이드·출력을 연결해 검토한다. 파일 수나 키워드만으로 교육 내용을 판정하지 않는다.
신규 학생 배포본은 가이드대로 따라가며 의도한 결과와 실패 복구가 가능한지 확인한다.
여러 날의 실습은 뒤로 갈수록 형식·설명·검증이 빠지지 않았는지 각 단위에서 대조한다.
코드 변경이 덱·계획의 사실에 영향을 주면 `lecture-plan`의 반영 절차로 영향 문서를 맞춘다.
최종 검토는 `lecture-verify`, ZIP·배포 묶음 요청은 `lecture-deliver`를 사용한다.
파일 경로·실제 실행 범위·관찰 결과·미검증·필요한 사용자 입력을 보고한다.
