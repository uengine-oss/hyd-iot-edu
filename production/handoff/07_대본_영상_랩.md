# 07. 낭독 대본 · 강의 영상 · 실습

이 문서는 통합반 온라인의 낭독 대본, 그 대본으로 만드는 강의 영상, 실습 랩과 실습 촬영 대본을 이어서 만드는 세션이 읽는다.

기준일 2026-10-13. 일하는 규칙은 `README.md` 2절, 덱에 대한 결정은 `04_결정_기록.md`에 있다. 이 문서에는 대본 · 영상 · 실습에 대해 정해진 것, 지금 상태, 다음에 할 일을 적는다.

## 1. 정해진 것

사용자가 정했다. 바꾸려면 먼저 묻는다.

### 1.1 대본

| 정해진 것 | 내용 |
|---|---|
| 강사는 대본만 읽는다 | 화면을 보지 않는다. 그래서 화면의 이름, 정의, 값, 예가 모두 말에 들어 있다 |
| 이야기 흐름으로 쓴다 | 단원 처음에 물음을 던지고, 앞 대목의 답이 다음 대목의 물음이 되게 이어 가며, 끝에서 처음 물음으로 돌아와 닫는다. 구성요소나 제품을 차례로 소개하는 식으로 쓰지 않는다. 본보기는 통합반 1일차 「시스템 구조」 단원(17~53장)이다 |
| 역할과 까닭으로 설명한다 | 현업에서 쓰는 것(PLC, Modbus, Kafka, Flink)은 말하되, HYD가 어떻게 구현됐는지(프로그램으로 대신했다, 교육용이다)는 말하지 않는다. HYD가 하지 않는 일을 한다고 말하지는 않는다. 현장의 일반 사실은 「현장에서는」으로 말한다 |
| 전문성은 그대로 둔다 | 실제 값, 메시지, 조건을 쓴다. 비유는 줄인다. 난이도는 지금 수준이다 |
| 시간을 다 채운다 | 하루 낭독의 합이 그날 이론 배정 분과 같아야 한다(분당 260음절). 모자라면 이론을 억지로 늘리지 않고, 까닭을 푸는 이야기와 퀴즈(문제 · 보기 · 정답 · 까닭)로 채운다. 넘치면 실습에서 뺀다. 실라버스의 행마다 분을 맞추지는 않는다 |
| 넣은 까닭은 근거를 가린다 | 새로 쓰는 까닭마다 근거가 무엇인지 가린다: 사실표와 코드, 회의 원문, 검색으로 확인한 현장의 일반 사실, 상식. HYD에 대해 말하는 것은 사실표나 코드에서 확인하고, 현장의 일반 사실은 검색으로 확인한다. 확인하지 못했으면 까닭이 아니라 결과로 말하거나 뺀다. 넣은 자리와 근거는 대본 끝의 제작 확인 절에 적는다 |
| 퀴즈는 다 말한다 | 문제, 보기 넷, 정답, 까닭. 틀린 보기가 왜 틀렸는지도 말한다 |
| 영어 식별자는 한글 발음으로 적는다 | 「리모트 오토」처럼 음성이 읽을 수 있게 쓴다. 1일차 영상에 이미 들어간 여섯 군데는 사용자가 들어 보고 그대로 두기로 했다 |
| 실습 도구의 이름을 되풀이하지 않는다 | 「바이브 코딩으로 …」라고 말한다. 도구 이름은 통합반 1일차의 도구 소개 한 곳에만 있다 |

### 1.2 윤문

| 정해진 것 | 내용 |
|---|---|
| 모델 | gpt-6-astra. 윤문에만 쓴다 |
| 부르는 법 | 로그인된 Codex로 부른다. 다 쓴 글만 모아 한 번, 필요한 글만 넘긴다 |
| 하는 일 | 윤문 그 자체다. 내용을 보태거나 말을 이어 붙여 길이를 늘리는 일이 아니다 |
| 요청하는 법 | 구체적인 지시를 붙이지 않는다. 상황만 준다(전문가가 노베이스 대학생에게 하는 강의의 낭독 대본이다)고 알리고 「윤문해 달라」고만 한다. 지시를 자세히 주면 오히려 글이 이상해진다 |
| 나누는 일 | 까닭, 이야기 흐름, 내용을 채우는 일은 작업하는 세션이 한다. 윤문은 그렇게 완성한 글의 말투만 다듬는다 |
| 영상의 경계 | 영상은 실라버스 행마다 따로 재생된다. 영상의 첫 문장이 「그럼 · 그러면 · 그래서 · 자 · 이제 · 이어서」로 시작하면 안 된다 |
| 검사 | 윤문 뒤에 숫자와 이름이 바뀌지 않았는지 검사한다 |

### 1.3 음성과 영상

| 정해진 것 | 내용 |
|---|---|
| 음성 합성 | ElevenLabs, 모델 `eleven_v4` 고정. 구형 모델에 빠르기 설정을 건 음성은 목소리가 무너져 버렸다 |
| 목소리 | 강사의 복제 음성. 음성 ID는 `강의영상.py`의 기본값에 있다 |
| 빠르기 | `eleven_v4`에는 빠르기 설정이 없다. 읽은 음성을 그대로 두고 쉼만 보탠다 |
| 쉼 | 문장 사이마다 잇는다 · 짧게 · 한 호흡 · 크게(0 · 0.15 · 0.45 · 0.8초)를 정한다. 물음표 뒤는 적어도 0.5초, 문단 사이는 적어도 0.4초, 장이 넘어갈 때는 1.2초. 쉼 단계는 작업하는 세션이 대본을 읽고 정한다 |
| 쉼으로 시간을 맞추지 않는다 | 쉼을 늘려 배정 시간에 맞추면 2~4초짜리 쉼이 생겨 어색했다 |
| 영상 하나 | 실라버스 행 하나가 영상 하나다. 행과 장의 대응은 각 대본 맨 위의 「이 일차의 구성」 표에 있다 |

## 3. 통합반 1일차

### 한 것

- 「시스템 구조」 단원(17~53장)의 대본을 1.1절의 기준으로 고쳤다. 「설비의 통신에는 왜 암호가 없는가」로 열고 53장에서 그 물음으로 돌아와 닫는다. 제어기를 설비 옆에 두는 까닭, 현장 통신을 단순하게 두는 까닭, 엣지 게이트웨이, 완충 구역이 보안을 맡는 구조, 기록 장부에 먼저 적는 까닭, 흐르는 값을 바로 읽는 까닭을 넣었다.
- 퀴즈(97~101장)를 장마다 따로, 문제 · 보기 · 정답 · 까닭을 다 말하게 고쳤다.
- 덱 23 · 25 · 27 · 29 · 50장의 화면 문구를 대본에 맞추고, 통합반 · 실전반 1일차 PPTX와 배포 묶음을 다시 만들었다.
- 새로 쓴 문단 47개를 한 번 윤문했다(23개 바뀜, 검사 통과). 기록은 `production/decks/integrated/day01/통합반_01일차_대본_보강_윤문_보고.json`.
- 그 뒤 17~101장 전체를 「까닭 없이 단정하는 곳이 없는가」로 다시 보고 서른 장쯤에 물음과 답을 넣었다(왜 층을 나누나, 왜 받는 쪽이 먼저 등록하나, 왜 저장소를 또 두나, 왜 두 번 검사하나, 왜 AI가 직접 실행하지 못하게 했나, 왜 잰 값을 그래프에 넣지 않나 등). 같은 말을 바꿔 되풀이하던 문장과 비유 셋(사서함, 안내 데스크, 병원)은 뺐다. 회의 원문의 설명(기준 정보와 현황의 구분, 설비와 납기 사이의 결정은 사람이 한다)을 86 · 48장에 넣었다.
- 덱은 닻이고 대본이 나머지를 다 푼다. 덱은 슬라이드에 담을 수 있는 만큼만, 그 장의 까닭이 화면에서 잡히게 고쳤다: 메시지 20장쯤과 본문의 카드 · 라벨 · 짚을 점 열두 장. 제작 기준을 지켰다(메시지는 한 줄 한 문장, 같은 문장 틀이 한 단원에 몰리지 않게, 간지는 번호 · 단원명 · 구분과 원래 부제, 화면에 물음꼴을 쓰지 않음, 노트는 다섯 문장 안, 화면에 없는 내용을 노트에만 두지 않음). 장 제목과 장 수는 그대로다. 겹쳐 보이는 87 · 88장(정의 한 장과 같은 예로 견주는 한 장)과 20 · 50 · 52장(같은 그림 세 번)은 제작 기준 6절이 허용하는 구성이어서 빼지 않았다.
- 이 보강분은 **윤문하지 않았다.** Notion 단원(4~16장)은 손대지 않았다.
- 새로 쓴 까닭 가운데 현장의 일반 사실로 쓴 것(Modbus, 작동유의 과열, 저압, 인터록의 수동 리셋, 구독자가 없는 발행, 키와 순서, 스트림 처리, 원격과 현장 운전 모드, 온톨로지와 지식 그래프의 구분)은 검색으로 확인했고, 근거와 넣은 자리는 각 대본 끝의 「2026-10-13에 넣은 까닭」 절에 적었다.
- 대본 길이는 세 파일이 34.0 · 45.6 · 59.0분, 합계 138.6분이다(분당 260음절). 이론 배정은 110분이며, 넘는 시간은 사용자가 실습 쪽에서 조정한다.

### 하지 않은 것

- 영상과 음성을 다시 만들지 않았다. 지금 있는 9편(112.6분)은 고치기 전의 것이다.
- 고친 장의 쉼 단계를 정하지 않았다. 영상 도구는 음성을 만든 뒤에 쉼 자리 파일을 만들므로 영상을 만들 때 채운다.
- 고친 대본은 4~5분쯤 길어졌다. 실제 길이는 음성을 만들어야 나온다. 배정을 넘는 것이 문제가 되는지 사용자에게 물어 둔 상태다.

## 4. 도구

모두 저장소 루트에서 실행한다. 키는 저장소 밖의 파일에 두고 `--env`로 넘긴다.

```
# 대본 길이
python3 production/tools/deck/대본시간.py <대본.md>

# 강의 영상: <일차> <첫 장> <끝 장> <목표 초, 0이면 맞추지 않음> <출력 폴더>
python3 production/tools/video/강의영상.py 01 4 14 0 <출력 폴더> --polished2 --breath \
  --pause-short 0.15 --pause-mid 0.45 --pause-long 0.8 --pause-question 0.5 --pause-para 0.4 --gap 1.2 --env <키 파일>

# 윤문: 다듬을 글을 요청문 파일 하나에 모아 한 번 부른다
npx -y @openai/codex@0.162.1 exec -m gpt-6-astra --skip-git-repo-check -s read-only \
  -c model_reasoning_effort=medium -o <결과 파일> - < <요청문 파일>

# 실습 촬영 대본: runsheet.json → runsheet.html
python3 production/labs/build_runsheet.py production/labs/online/<폴더>

# 랩 가이드: guide.html
python3 production/labs/offline/05-2-cause-agent/build_guide.py
```

- `강의영상.py`는 PPTX를 LibreOffice로 PDF, `pdftoppm`으로 그림으로 바꾸고, 장마다 음성을 뽑아 `production/tools/video/음성_저장/`에 둔다. 글 · 음성 · 모델이 같으면 다시 뽑지 않는다. 이 폴더는 저장소에 올라가지 않는다.
- 쉼의 자리는 `쉼_저장/`에서 읽는다(장마다 파일 하나, `"쉼"`에 문장 사이마다 0~3). 적히지 않은 장이 있으면 `"쉼": null`인 파일을 만들고 멈춘다. 그 파일을 채운 뒤 다시 돌린다.
- 쉼의 길이만 바꿔 다시 만드는 것은 크레딧이 들지 않는다. 하루치 음성에는 5,000 크레딧 안팎이 든다.
- `production/tools/video/윤문.py`와 `윤문2.py`는 11일치 윤문본을 만들 때 쓴 도구다. OpenAI API 키를 요구한다. 11일치가 끝나 다시 돌릴 일은 없고, 돌려야 하면 사용자에게 먼저 묻는다.

## 7. 랩과 덱이 어긋나 정해 주어야 하는 것

| 무엇 | 왜 열려 있나 |
|---|---|
| 학생이 쓸 실습용 그래프 DB의 주소 | 덱은 분리된 DB라고만 한다. 수업 스택의 그래프 DB에는 기준 지식이 들어 있어 학생이 넣는 것과 식별자가 겹친다. 두 묶음은 DB가 비어 있지 않으면 준비 단계에서 멈춘다 |
| 랩의 스키마 이름 | 2회차 랩은 `MEASURES`, `MOUNTED_ON`을 쓰고 덱은 `OBSERVES`, `MONITORED_BY`로 설명한다 |
| 2회차 랩 스키마의 `USES_PART` | 이어받은 스키마는 `1:N`, 저장소의 확정 스키마는 `N:M`이다 |
| 4회차 실습 3의 판단 규칙 | 덱은 판단 규칙까지 조회한다고 하나 이어받은 후보에 규칙이 없어 랩에서 뺐다 |
| 4회차 실습 4의 개정 값 | 덱에 새 값이 없다. 랩은 48시간으로 했는데 HYD나 덱의 값이 아니다 |
| 6회차의 MCP 서버 | 덱은 공개 서버 셋이라고 하나 설치 방법이 저장소에 없다. 랩은 묶음 안에 파이썬으로 쓴 서버를 쓴다 |
| 6회차 랩의 중복 처리 | 덱은 「합치지 않고 표시」, 랩은 합친다 |
| 7회차 실습 4의 「오류를 수정」 | 완성본에 시나리오를 돌리니 어긋남이 나오지 않았다. 실패를 심지 않고, 사람의 승인 한 줄을 바꿔 회귀 편이 실패하는 것을 보게 했다 |
| 덱의 「모호한 한 문장이 기존 동작을 깨뜨린다」 | 7회차 랩에서 그 문장을 보내면 AI가 고치지 않고 되묻는 일이 잦았다 |
| 수업 문서 원문의 「교육용」 문구 | 매뉴얼 HM-8 원문에 있다. 포털에 올리는 문서와 같아야 해서 랩에서 고치지 않았다 |

## 8. 확인하지 못한 것

- 대본 본문은 작업자에게 나눠 썼다. 전 장을 한 사람이 읽은 적이 없고, 자동 검사(숫자, 이름, 길이)와 일부 장의 확인만 했다. 덱 안의 어긋남은 각 대본 끝의 「제작 확인용」 절에 있다.
- 윤문본도 자동 검사만 거쳤다. 지어낸 설명이 끼어든 곳은 자동으로 잡지 못한다.
- 2~11일차 대본은 퀴즈의 보기를 읽지 않는다.
- 영상은 만든 세션이 들어 보지 못한다. 쉼의 분포를 `ffmpeg`의 `silencedetect`로 재어 견줬을 뿐이다.
- 1일차 실습 3은 포털의 화면과 버튼, 이전 처리 기록의 단계와 걸린 시간을 보고 썼다.

## 9. HYD 시스템을 띄울 때

표준 절차는 `docs/handoff/NOW.md` 2절과 `docs/RUNBOOK.md`다. 1일차 실습 2의 촬영 대본도 그 절차를 따른다.

- 포털은 브라우저에서 8080을 직접 부른다. 자동 조작 브라우저에서는 그 요청을 옮긴 포트로 돌린다.
