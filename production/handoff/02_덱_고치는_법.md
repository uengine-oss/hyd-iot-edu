# 02. 덱 고치는 법

이 문서는 이미 있는 덱의 장을 고치거나, 통합반 원 덱을 고친 뒤 조립 덱과 배포 묶음까지 다시 만들 때 읽는다.

명령은 모두 저장소 루트에서 실행한다. 필요한 것은 `uv`, `python3`, 렌더할 때의 LibreOffice(`soffice`) · `pdftoppm` · 맑은 고딕 글꼴이다. 이 문서의 요약이 스킬 `.claude/skills/hyd-course-deck/SKILL.md`이고, (나)의 도구 셋(`재조립.py` · `장수.py` · `배포묶음.py`)은 그 스킬의 `scripts/`에 있다. 규칙(무엇을 어떻게 써야 하는가)은 `production/standards/제작기준.md`에 있고, 이 문서는 순서와 명령만 적는다.

## (가) 한 장 고치기

### 1. 어느 파일을 고치는가

| 고치려는 장 | 고칠 파일 | 그 뒤 |
|---|---|---|
| 통합반 온라인 덱의 장 | `production/decks/integrated/NN일차/통합반_NN일차.md` | 빌드. 그 장을 가져가는 조립 덱이 있으면 (나)로 간다 |
| 조립 덱의 장 가운데 통합반에서 **가져온** 장 — 모든 과정에서 고쳐져야 한다 | 통합반 원 덱 | (나) |
| 조립 덱의 장 가운데 가져온 장 — 그 덱에서만 달라야 한다(회차 표기, 빠진 장을 가리키는 말 등) | 그 덱 폴더의 `조립.py`: 그 장의 `G(...)`에 `(찾을 말, 바꿀 말)`을 더한다 | `조립.py` 실행 → 빌드 |
| 조립 덱의 **새로 쓴** 장(표지, 학습목표, 용어 정리, 정답, 그 과정에만 있는 실습 설명 등) | 그 덱 폴더의 `새장_*.md` | `조립.py` 실행 → 빌드 |
| 조립 덱에서 장을 더 가져오거나 빼기, 순서 바꾸기 | `조립.py`의 `ORDER` | `조립.py` 실행 → 빌드 |
| 실전반 1일차 | 통합반 1일차 원 덱(실전반 1일차는 과정 이름만 바꾼 사본이다) | `python3 production/decks/practical/만들기_01일차.py` → 빌드 |

**조립 결과 MD(`실전반_0N일차.md`, `<과정>_오프라인_NN회차.md`)는 손으로 고치지 않는다.** 다음 조립에서 덮여 사라진다. 어떤 장이 가져온 것인지 새 장인지는 `조립.py`의 `ORDER`에서 본다: `G("10", "제목", …)`은 통합반 10일차에서 가져온 장, `N("[N3]")`은 `새장_*.md`의 장이다.

`조립.py`의 손질은 찾을 말이 그 장 안에 **정확히 한 번** 있어야 한다. 없거나 두 번 있으면 스크립트가 장 번호와 문구를 찍고 멈춘다.

### 2. 빌드

```bash
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py \
  production/decks/integrated/day03/통합반_03일차.md production/decks/integrated/day03/통합반_03일차.pptx
```

- 규칙 위반과 넘침 추정이 있으면 파일을 쓰기 전에 장 번호와 칸 이름을 모아 찍고 실패한다. 문구를 다듬거나 장을 나누거나 유형을 바꿔 고친다.
- 덱 MD를 고치지 않았으면 저장소의 PPTX를 다시 만들어 덮어쓰지 않는다(`production/decks/README.md` 「원본과 산출물」).
- PowerPoint에서 그 PPTX를 열어 둔 채(`~$…pptx` 잠금 파일이 있을 때) 빌드하면 덮어쓰기가 실패할 수 있다.

### 3. 렌더와 묶음 그림으로 확인

```bash
# 렌더: 출력 PPTX와 렌더 폴더를 저장소 밖(작업 폴더)에 둔다. 렌더 폴더는 매번 새 이름
uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py \
  production/decks/integrated/day03/통합반_03일차.md <작업 폴더>/d03.pptx --render <작업 폴더>/d03_r1

# 묶음 그림: 검토용은 한 묶음 9장 이하
uv run --no-project --with pillow python production/tools/deck/시트.py <작업 폴더>/d03_r1 <작업 폴더>/d03_sheet --cols 3 --per 9
```

- 묶음 그림(`…_1.png`, `…_2.png`)을 열어 고친 장과 그 앞뒤를 본다. 의심스러운 장은 렌더 폴더의 원본 PNG(`*-NN.png`)를 따로 연다.
- 볼 것: 넘침, 겹침, 잘린 글자, 낱말 하나만 떨어진 줄, 작은 글자, 큰 빈 칸, 비스듬한 화살표, 코드 상자 아래가 잘림, 그림이 비어 있음.
- 저장소의 PPTX를 갱신하려면 2의 명령으로 저장소 경로에 한 번 더 빌드한다(또는 렌더할 때 출력을 저장소 경로로 준다).
- 렌더 폴더, 묶음 그림, 중간 PDF, `__pycache__`는 저장소에 두지 않는다.

### 4. 삽화와 그래프 고치기

삽화는 직접 그린 SVG이고 그리는 스크립트가 같은 폴더에 있다. 그림 안에는 글자가 없다. 라벨은 덱 MD의 요소(`라벨 | 설명 | x,y[,폭]`)다.

| 고칠 것 | 방법 |
|---|---|
| 라벨의 글이나 위치 | 덱 MD의 그 장 요소만 고친다. 그림은 그대로다 |
| 그림 자체 | 그 일차의 `figures/만들기_삽화.py`에서 그 그림의 함수를 고치고 다시 돌린다 |
| 실제 데이터 그래프(PNG) | `figures/만들기_그래프.py`를 고치고 다시 돌린다 |

```bash
cd production/decks/integrated/day10/그림 && python3 만들기_삽화.py                               # SVG (표준 라이브러리만 쓴다)
cd production/decks/integrated/day03/그림 && uv run --no-project --with matplotlib python 만들기_그래프.py   # 그래프 PNG
```

- 스크립트는 그 폴더의 SVG를 모두 다시 쓴다. 돌린 뒤 `git diff --stat`으로 의도한 그림만 바뀌었는지 본다. 1일차의 `만들기_삽화.py`는 이미 있는 승인된 그림을 다시 쓰지 않게 되어 있다.
- 화풍(선 굵기, 색, 그림 조각)은 `삽화_기본.py`(1일차의 것을 복사한 것)에서 가져온다. 그림체는 바꾸지 않는다(`04_결정_기록.md` 1절).
- 그림을 고친 뒤에는 그 그림을 쓰는 장을 원본 크기 PNG로 본다. 라벨 좌표가 그림과 어긋날 수 있다.
- 통합반의 그림은 조립 덱도 함께 쓴다. 그림을 고쳤으면 그 그림이 든 장을 가져가는 조립 덱의 PPTX도 다시 빌드한다(덱 MD는 바뀌지 않으므로 `git diff`로는 드러나지 않는다 — 그림 파일 이름으로 `production/decks`의 덱 MD를 검색한다).

## (나) 통합반 원 덱을 고친 뒤 따라오는 일

### 1. 고치기 전에 — 제목과 손질 원문

- **장 제목을 바꾸거나, 장을 지우거나 합치면 그 장을 가져가는 `조립.py`가 멈춘다**(「통합반 N일차에서 장을 찾지 못함」). 꼭 필요할 때만 하고, 바꾼 것을 적어 둔다.
- 장 안의 문구를 고쳤는데 그 문구가 어느 `조립.py`의 손질 원문이면 그 스크립트도 멈춘다(「바꿀 말이 0번 있음」). 고치기 전에 찾아본다.

```bash
grep -rn --include='조립.py' '고치려는 문구' production/decks
```

- 멈춘 손질은 지우지 말고 **뜻**을 본다. 그 손질이 하던 일(회차 표기 바꾸기, 빠진 장을 가리키는 말 고치기, 풀네임 붙이기)을 원 덱이 이미 해 놓았으면 손질을 지우고, 아니면 새 원문에 맞춰 다시 건다.

### 2. 원 덱 빌드

(가) 2 · 3과 같다.

### 3. 조립 스크립트 27개를 다시 돌린다

```bash
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --dry-run     # 돌릴 스크립트와 읽는 통합반 일차만 본다(아무것도 바꾸지 않는다)
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --day 3       # 통합반 3일차를 읽는 스크립트만 돌린다
python3 .claude/skills/hyd-course-deck/scripts/재조립.py               # 27개를 모두 돌린다
```

- 이 도구는 `실전반/만들기_01일차.py`와 `조립.py` 26개를 차례로 돌리고, 멈춘 스크립트와 그 까닭을 모아 보인다. 스크립트 하나만 돌리려면 `python3 production/decks/<과정>/<NN일차|NN회차>/조립.py`다.
- 고친 일차를 쓰는 덱만 돌려도 된다(대응표는 `production/decks/README.md`). 전부 돌려도 바뀌지 않은 덱은 같은 결과가 나온다.
- 멈추면 그 `조립.py`의 순서표나 손질 원문을 원 덱의 지금 모습에 맞춰 고치고 다시 돌린다.
- 멈추지 않고 지나가는 변화도 있다. 원 덱에 새로 넣은 「N일차에」 같은 일차 언급, 그 과정에 싣지 않은 장을 가리키는 말은 조립 덱에서 틀린 말이 된다. 조립 뒤 `git diff`로 조립 덱 MD의 바뀐 줄을 읽는다.
- 원 덱에 새 장을 넣었으면 조립 덱에는 저절로 들어가지 않는다. 그 회차의 실라버스 항목과 분량을 보고 `ORDER`에 넣을지 정한다(실전반 8일차는 통합반 11일차를 전부 가져오는 덱이라 새 장도 넣는다).

### 4. 바뀐 덱만 빌드

```bash
python3 .claude/skills/hyd-course-deck/scripts/재조립.py --build-only   # 조립은 건너뛰고, 덱 MD가 커밋과 다른 덱만 빌드한다
```

- 3과 4를 한 번에 하려면 `재조립.py --build`(또는 `--day 3 --build`)다. 멈춘 스크립트가 있으면 빌드하지 말고 먼저 고친다.
- 「바뀐 덱」은 `git status`에서 덱 MD가 커밋과 다른 덱이다. 이미 커밋한 뒤라면 이 도구는 바뀐 덱을 찾지 못하므로, `git -c core.quotepath=false diff --name-only <고치기 전 커밋> HEAD -- production/decks`로 덱 MD를 가려 (가) 2의 명령으로 하나씩 빌드한다.
- 렌더 없이 빌드만 하므로 빠르다. 그 뒤 화면이 바뀐 장 몇 곳을 골라 (가) 3의 방법으로 렌더해 본다.

### 5. 배포 묶음 다시 만들기

```bash
python3 .claude/skills/hyd-course-deck/scripts/배포묶음.py           # production/dist/교재_전체.zip을 다시 만든다(PPTX 38개)
python3 .claude/skills/hyd-course-deck/scripts/배포묶음.py --check   # zip이 과정 폴더의 PPTX와 같은지만 본다
```

묶음의 구성은 `production/dist/README.md`에 있다. `--check`가 「검사 통과」를 내면 끝이다. PowerPoint에서 PPTX를 열어 둔 채면 잠금 파일(`~$…pptx`)이 있다고 알린다. 닫고 다시 한다.

### 6. 현황표의 숫자 맞추기

장수가 바뀌었으면 아래 네 곳을 같은 값으로 고친다.

| 어디 | 무엇 |
|---|---|
| `production/standards/제작기준.md` 13 · 13-1 · 13-2절 | 전체 장수, 단원별 본문 장수, 실습 건수, 가져옴 / 새로 |
| `production/decks/README.md` 머리 문단 | 과정별 장수 |
| `docs/handoff/NOW.md` 1절 「교재(슬라이드)」 줄 | 과정별 장수 |
| `production/handoff/01_현황.md` 1절 | 장수와 합계 |

세는 법:

```bash
python3 .claude/skills/hyd-course-deck/scripts/장수.py --units   # 38개 덱의 전체 · 본문 · 실습 간지 수와 단원별 본문 장수
```

본문 장수는 간지와 다음 간지 사이의 이론 본문 장 수다(실습 설명, 용어 정리, 퀴즈 제외 — 제작 기준 13절 머리). 가져옴 / 새로의 「새로」는 그 덱 폴더 `새장_*.md`의 장 수(`grep -c '^## SLIDE ' <파일>`)이고 「가져옴」은 전체에서 그것을 뺀 수다. 실습 간지의 번호가 바뀌어도 `06_실습가이드_착수.md` 3절은 고칠 것이 없다(제목만 싣는다). 간지의 제목을 바꿨을 때만 고친다.

## (다) 도구의 알려진 제약

형식의 전체는 `.claude/skills/lecture-deck/references/덱MD-PPTX형식.md`에 있다. 아래는 작업하며 자주 걸린 것이다.

| 제약 | 내용 | 걸렸을 때 |
|---|---|---|
| 메시지는 한 줄 · 한 문장 | 두 문장을 이으면 실패하고, 한 줄(16pt)을 넘으면 넘침으로 멈춘다. 한글로 대략 46~60자 | 문장을 줄인다. 조립 덱의 손질로 메시지를 늘릴 때도 같다 |
| 제목은 한 줄 | 28pt 한 줄. 표지와 간지만 ` / `로 줄을 끊는다 | 제목을 줄인다(조립에 영향 — (나) 1) |
| 요소 수 한도 | 유형마다 범위가 있다: 카드 2~4, 비교 정확히 2, 흐름 2~6, 단계 3~5, 풀이 2~6, 표 2~9, 구조 2~12, 파이프라인 3~7, 관계도 2~8, 코드의 짚을 점 0~4, 그림의 짚을 점 0~4, 문답 보기 2~5, 목차 2~9 | 장을 나누거나 유형을 바꾼다 |
| 요소 한 줄은 세 칸까지 | `칸1 \| 칸2 \| 칸3`. 표도 3열이다. 구분자 `\|`는 앞을 띄운다 | 넷째 열이 필요하면 칸2 안에 ` / `로 줄을 나누거나 장을 나눈다 |
| 표의 셋째 칸은 세 줄까지 | ` / `로 줄을 바꾼다 | 문구를 줄인다 |
| 꼬리표가 칸보다 넓으면 실패 | 카드 · 비교의 셋째 칸 | 문구를 줄인다 |
| 삽화 라벨 | 16개까지, 가운데 정렬뿐, 크기는 두 단계(기본 13.5 / 11pt, `라벨: 큰`이면 16 / 13pt). 셋째 칸은 `x,y[,폭]`이고 폭의 기본은 그림 폭의 16 % | 라벨이 끊기면 폭 값을 넓히거나 풀네임을 설명 줄로 내린다 |
| 코드 장 | `코드:` 안의 ` / `(앞뒤 공백)는 줄바꿈, 글자 그대로의 빗금은 `\/`. 코드 상자의 높이는 본문 영역을 넘지 못한다 | 줄이 많으면 상자 아래가 잘릴 수 있으니 렌더로 본다. 길면 장을 나눈다(몇 줄부터 잘리는지는 이 문서에서 재지 않았다 — 확인 필요) |
| `**` | 메시지와 요소 안의 `**굵게**`는 강조색으로 그려진다. 요소의 칸1 전체를 `**`로 감싸면 강조 칸이 된다. 짝이 맞지 않으면 그 뒤가 모두 강조로 그려진다 | 짝을 맞춘다 |
| 유니코드 빼기표(−, U+2212) 금지 | 화면 문구에 있으면 실패한다(덱 글꼴에 없어 다른 글꼴로 바뀐다). 노트는 검사하지 않는다 | 하이픈(-)을 쓴다 |
| 허용되지 않는 칸 | `핵심` `설명` `다음` `현재`는 없앤 칸이며 쓰면 실패한다 | 형식 문서의 허용 칸을 쓴다 |
| 아이콘 수 | 유형마다 정해져 있다(요소 수와 같게 또는 0개. 파이프라인은 필수) | `scripts/find_icon.py <낱말>`로 찾는다 |
| 그림 경로 | 덱 MD 위치 기준 상대 경로이고 파일이 없으면 실패한다 | 조립 덱은 `../../통합반/NN일차/figures/…`(스크립트가 바꾼다) |
| 관계도의 좌표 | 두 원이 너무 가까우면 실패한다 | 좌표를 벌린다 |
| 렌더 잠금 | 렌더는 파일 잠금으로 한 번에 하나씩 돈다. 다른 렌더가 돌고 있으면 기다린다. 20분을 넘기면 도구가 끊고 알린다. `soffice` 프로세스를 죽이지 않는다 | 기다린다. 여러 덱을 동시에 렌더하지 않는다 |
| 렌더 폴더 | 매번 새 이름으로 쓴다. 경로가 약 235자를 넘으면 멈춘다 | 짧은 경로를 쓴다 |
| 글꼴 | 맑은 고딕이 아닌 글꼴로 그려지면 렌더가 멈춘다 | 맑은 고딕을 설치한다 |

도구의 한계를 만나면 우회하지 않고 도구를 고치는 것이 원칙이다(제작 기준 12.1절). 다만 도구를 고치면 38개 덱 전부의 화면이 달라질 수 있으니, 고친 뒤에는 덱 여럿을 렌더해 본다.

스킬(도구와 형식 문서)은 저장소의 `.claude/skills/`가 **유일한 원본**이다. 고칠 때는 여기서 고친다(목록은 `.claude/skills/README.md`).

## (라) 커밋 규칙

| 규칙 | 내용 |
|---|---|
| 경로를 지정해 add 한다 | `git add production/decks/integrated/day03 …`처럼 고친 경로만. `git add .`과 `-A`는 쓰지 않는다 |
| 넣지 않는 것 | `.DS_Store`, `~$…pptx`(PowerPoint 잠금 파일), `__pycache__`, 렌더 폴더, 묶음 그림. `production/decks/.gitignore`가 앞의 셋을 막지만 add 전에 `git status`로 본다 |
| 순서 | 먼저 커밋 → `git pull --rebase` → push. autostash는 쓰지 않는다(커밋하지 않은 변경을 들고 rebase 하지 않는다) |
| 건드리는 범위 | `production/decks`, `production/labs/_old/실습가이드`, `.claude/skills` 안만. 같은 브랜치(`claude/hyd-handoff-work-xziutz`)에서 다른 세션이 포털과 기능을 고치고 있다 |
| `docs/handoff/NOW.md` | 교재에 관한 줄(1절의 「교재(슬라이드)」 줄, 4.7절, 6절 문서 지도의 「교재」 줄)만 고친다 |
| `docs/handoff/DECISIONS.md` | 고치지 않는다 |
| push | 원격 push는 사용자에게 묻고 한다(저장소 루트 `CLAUDE.md` 3절) |
| 커밋 메시지 | 지금까지의 꼴은 「교재: 무엇을 했는가」다(`git log --oneline -- production/decks`) |
| 공개 저장소 | 사람 이름, 절대 경로, 키 값을 문서와 덱의 제작 기준 칸에 쓰지 않는다 |
