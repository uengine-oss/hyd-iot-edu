# 교재 인계 — 여기서 시작한다

HYD 제조 AI 교육과정(경남대학교 피지컬AI 사관학교)의 교재를 이어서 만드는 세션이 가장 먼저 읽는 문서다. 교재는 강의 덱, 낭독 대본, 강의 영상, 실습 랩, 실습 촬영 대본을 말한다.

기준일 2026-10-13. 이 저장소만 있으면 이어서 할 수 있게 썼다. 앞 세션의 대화, 기억, 작업 폴더는 남아 있지 않다고 본다.

> **2026-10-13 밤:** 인계 문서를 목적별 여섯 개로 다시 모으는 일이 진행 중이다. 다음 세션은 `00_이어받기.md`부터 읽는다.

## 1. 읽는 순서

1. 이 문서를 끝까지 읽는다. 2절의 규칙은 사용자가 정한 것이다.
2. 할 일에 맞는 문서 하나를 읽는다.

| 하려는 일 | 읽을 문서 |
|---|---|
| 낭독 대본, 강의 영상, 실습 랩, 실습 촬영 대본 | `07_대본_영상_랩.md` |
| 덱 한 장을 고치거나 원 덱을 고쳐 조립 덱까지 다시 만들기 | `02_덱_고치는_법.md` |
| 새 덱 만들기, 전체 점검, 실라버스가 바뀌었을 때 | `03_덱_만드는_법.md` |
| 덱이 지금 몇 개이고 어디까지 확인됐는지 | `01_현황.md` |
| 왜 이렇게 되어 있는지, 바꿔도 되는지 | `04_결정_기록.md` |
| 덱에 무엇이 열려 있는지 | `05_남은_일.md` |
| 네 과정의 실습이 무엇이고 몇 건인지 | `06_실습_목록.md` |

3. 덱이나 기준 문서를 고친다면 `production/standards/제작기준.md`를 먼저 읽는다. 덱의 규칙은 거기에만 있다.

포털과 설비 시스템은 다른 세션이 맡는다. 그쪽 문서는 `docs/handoff/NOW.md`이고, 교재 세션은 그 문서의 교재 줄(1절 「교재(슬라이드)」, 4.7절)만 고친다.

## 2. 일하는 규칙

사용자가 정했다. 다시 묻지 않고 따른다.

| 규칙 | 내용 |
|---|---|
| 먼저 제안하고 승인받는다 | 작업 방식, 표현, 구조는 하기 전에 제안해 승인받는다. 승인받은 범위 안의 일은 묻지 않고 끝까지 한다 |
| 하나 만들어 확인받고 넓힌다 | 하나 → 확인 → 30%쯤 → 확인 → 전체. 여러 묶음을 한꺼번에 고치지 않는다 |
| 비용이 드는 일은 미리 알린다 | 음성 생성, 모델을 많이 부르는 일, 작업자를 여럿 쓰는 일 |
| 실제로 돌려 본 것만 쓴다 | 명령, 출력, 좋은 예와 나쁜 예를 지어내지 않는다. 돌려 보지 못한 것은 「확인하지 못함」으로 적는다 |
| 음성 합성은 ElevenLabs만 쓴다 | OpenAI의 음성은 쓰지 않는다 |
| gpt-6-astra는 윤문에만 쓴다 | 다 쓴 글을 모아 한 번만, 필요한 글만 넘긴다. 그 밖의 일(쉼 판단, 검증, 영상)은 작업하는 세션이 한다 |
| fable 모델을 쓰지 않는다 | 메인 세션과 서브에이전트 모두 |
| 영상은 지시받은 범위만 만든다 | 범위를 듣기 전에는 음성도 영상도 만들지 않는다 |
| 설비 시스템은 고치지 않는다 | 교재가 시스템과 다르면 설명을 고친다 |
| 딸린 것은 묻지 않고 맞춘다 | 덱을 고치면 조립 덱, PPTX, 배포 묶음, 딸린 문서를 같은 작업에서 맞춘다 |
| 결과는 파일로 건넨다 | 사용자에게 보일 것은 열어 볼 수 있는 파일(HTML 등)로 준다. 「열어 보고 확인해 달라」로 넘기지 않고, 결정이 필요한 것만 묻는다 |

저장소 규칙:

| 규칙 | 내용 |
|---|---|
| 브랜치 | `main`과 `claude/hyd-handoff-work-xziutz` 둘만 쓴다. 작업은 뒤쪽에서 한다 |
| 커밋과 push | 경로를 지정해 add 한다. 먼저 커밋하고 `git pull --rebase` 한 뒤 push 한다. autostash는 쓰지 않는다. 구간이 끝나면 `git push origin claude/hyd-handoff-work-xziutz:main`으로 `main`을 같은 지점에 맞춘다 |
| 고치는 범위 | `course/`, `production/`, `.claude/skills/` 안이다. 같은 브랜치에서 다른 세션이 포털과 기능을 고친다 |
| 열지 않는 것, 고치지 않는 것 | 저장소의 `.env`는 열지 않는다. `docs/handoff/DECISIONS.md`는 고치지 않는다 |
| 공개 저장소 | 키, 사람 이름, 메일, 절대 경로, 내부 주소를 올리지 않는다. 음성과 영상 파일도 올리지 않는다 |

## 6. 문서 사이의 약속

- 덱의 규칙은 `production/standards/제작기준.md`, 랩의 틀은 `production/labs/STRUCTURE.md`, 대본 · 영상 · 실습에 대해 정해진 것은 `07_대본_영상_랩.md`에 있다. 한 규칙은 한 곳에만 적는다.
- 이 묶음에서 「원 덱」은 통합반 온라인 덱 11개, 「조립 덱」은 거기서 장을 가져와 만든 나머지 27개 덱이다.
- 문서의 말과 저장소의 실제가 다르면 저장소가 맞다. 다른 것을 찾으면 문서를 고친다.
