## SLIDE 18 — 점대점 연결의 한계: 강한 결합과 중개

## SLIDE 21 — OT와 IT를 직접 잇지 않는 이유

## SLIDE 23 — Layer 3 · 이벤트 로그: 추가 전용 기록과 재처리
### 화면 내용
- 유형: 코드
- 메시지: 메시지를 레코드로 바꿔 이벤트 로그에 덧붙이면, 소비자는 각자 오프셋을 기준으로 읽고 다시 읽는다.
- 코드: # 브로커가 전달한 메시지 / topic    plant/hyd01/tag/TS1 / payload  {"t": "2026-10-10T02:13:08.508Z", /           "v": 55.71, "q": "good"} /  / # 이벤트 로그에 남은 레코드 / topic    plant.tag / key      hyd01 / value    {"asset": "HYD-01", "name": "TS1", /           "t": "2026-10-10T02:13:08.508Z", /           "v": 55.71, "q": "good"}
- 요소:
  1. **추가 전용 로그(Append-only Log)** | 생산자(Producer)가 쓴 레코드를 받은 순서대로 뒤에 덧붙이기만 한다. 이 역할에는 Kafka 같은 것이 있다.
  2. 오프셋(Offset) | 소비자(Consumer)마다 어디까지 읽었는지의 위치이다. 되돌리면 처음부터 다시 읽는다(재처리).
  3. asset · name | 토픽 경로에 있던 설비와 태그 이름이 페이로드(본문) 안으로 들어왔다.
  4. key hyd01 | 같은 설비의 레코드를 한 줄로 모아 잰 순서대로 읽히게 한다.
- 노트: 수집 서비스가 데이터를 옮기는 곳은 Layer 3, 이벤트 백본의 이벤트 로그입니다. 위쪽은 브로커가 전달한 메시지이고 아래쪽은 로그에 남은 레코드로, 설비와 태그 이름을 토픽 경로에서 페이로드 안으로 옮겨 레코드 한 건만으로도 출처를 알 수 있게 했습니다. 이벤트 로그는 받은 순서대로 덧붙이는 추가 전용 로그이며, 기록을 쓰는 쪽을 생산자, 읽는 쪽을 소비자라고 합니다. 기록이 남아 있으므로 소비자는 오프셋을 기준으로 각자의 속도에 맞춰 읽고, 필요하면 다시 읽을 수 있습니다. IT 서비스는 설비를 직접 읽는 대신 이 로그나 여기서 데이터를 옮긴 저장소에서 계측값을 읽습니다.

## SLIDE 32 — 명령 한 건과 실행 응답 ACK
### 화면 내용
- 유형: 코드
- 메시지: 명령에는 할 일·승인자·유효 시각이 실리고, PLC는 처리 결과를 확인 응답 **ACK**로 돌려준다.
- 코드: # 명령 / cmdId       CMD-1010-0001-b94a / asset       HYD-01 / incident    INC-1010-01-d55a / actions     FAN_SET  fan_pct 100 / approvedBy  user:kim-op / issuedAt    11:14:57 / expiresAt   11:16:57 /  / # PLC의 응답(ACK)  11:14:58 / cmdId       CMD-1010-0001-b94a / result      DONE / interlock   PASS

  2. **approvedBy** | 승인한 사람이다. 승인 없이는 명령이 만들어지지 않고, 누가 책임지는지가 남는다.
