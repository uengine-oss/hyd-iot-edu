## SLIDE 09 — 승인 대기: 토큰이 사용자 작업에 머문 상태
### 화면 내용
- 유형: 코드
- 메시지: 승인 대기는 멈춤이나 오류가 아니라, 토큰이 사용자 작업에 머물러 사람의 결정을 기다리는 정상적인 실행 상태이다.
- 코드: "status": "RUNNING", / "current_activity_ids": ["T_approve"] /  / T_agent     DONE / T_approve   IN_PROGRESS / T_cmd       TODO / T_reobs     TODO / T_wo        TODO
- 요소:
  1. 처리 건의 상태 | 끝나지 않았으므로 / RUNNING이다.
  2. **열려 있는 단계** | 토큰이 있는 곳이 / T_approve, 운전원 승인이다.
  3. 단계의 상태 | 끝난 것은 DONE, / 닿지 않은 것은 TODO이다.
- 노트: 운전원의 승인을 기다리는 처리 건의 기록입니다. 처리 건의 상태는 실행 중을 뜻하는 RUNNING이고, 열려 있는 단계는 운전원 승인인 T_approve입니다. 아래는 단계마다의 상태로, 에이전트의 단계는 DONE, 운전원 승인은 IN_PROGRESS, 아직 닿지 않은 단계는 TODO입니다. 승인 대기는 고장이 아니라 토큰이 사용자 작업에 머문 정상 상태입니다.
### 화면 구성
왼쪽 처리 건의 상태와 단계의 상태, 오른쪽 짚을 점 셋. 단계 id는 그림의 작업에 붙은 식별자다.
### 제작 기준
[기록] 승인 단계가 열려 있는 동안의 스냅샷(처리 건 `RUNNING` · `current_activity_ids: ["T_approve"]` · `T_approve` `IN_PROGRESS` · 아직 안 간 단계 `TODO`): 사실표 2.2 「무응답 경우의 스냅샷」 · 4.5 실행 상태 표. [저장소] 포털 말 「단계」: 사실표 4.1 (나). 실라버스 95행의 「승인 대기 · 정상 종료를 혼동하지 않는다」.

## SLIDE 12 — COMPLETED는 성공을 뜻하지 않는다
### 화면 내용
- 유형: 비교
- 아이콘: circle-check, ban
- 메시지: 거절로 닫힌 처리 건도 상태는 COMPLETED이므로, 업무의 결과는 닿은 끝 이벤트와 결과 보고의 내용으로 판단한다.
- 요소:
  1. 승인된 처리 건 | status: COMPLETED / end_event: E_end / 결과 보고: 정상 / 설비 명령: CMD-1010-0001-01d1 / 회복에 미달해도 end_event는 E_end이고 결과 보고가 미달로 달라진다 | 끝
  2. **거절된 처리 건** | status: COMPLETED / end_event: E_rejected / 결과 보고: 거절(기록의 값은 반려) / 설비 명령: 없음 / 냉각 명령, 재관측, 작업지시 등록은 CANCELLED | 거절 종결
- 노트: 같은 정의에서 나온 두 처리 건입니다. 왼쪽은 승인되어 설비 명령이 나갔고, 오른쪽은 거절되어 설비 명령이 없으며 결과 보고의 값은 거절을 뜻하는 반려로 적혔습니다. 그런데 두 건의 상태는 똑같이 COMPLETED입니다. COMPLETED는 실행이 끝났다는 뜻일 뿐이어서, 업무가 어떻게 끝났는지는 닿은 끝 이벤트와 결과 보고로 읽어야 합니다. 승인된 뒤 회복에 미달한 경우도 끝 이벤트는 같으므로 결과 보고가 정상인지 미달인지를 봅니다.
### 제작 기준
[기록] 승인 경우(`COMPLETED` · `E_end` · 정상 · `CMD-1010-0001-01d1` · `WO-1010-1198`)와 거절 경우(`COMPLETED` · `E_rejected` · 단계 이름 「결과 보고: 거절」, 결과 값 반려 · 설비 명령 0건 · `T_cmd` · `T_reobs` · `T_wo` `CANCELLED`): 사실표 2.2 표와 「함정」 항목. 정상과 미달이 같은 끝 이벤트 `E_end`로 간다: 같은 항목(화면에는 01단원의 완료 조건 표에 미달의 닫힘이 있다).

- 노트: 누가 승인 작업을 끝낼 수 있는지, 책임의 경계를 묻는 문항입니다. 승인 작업을 끝낼 수 있는 역할이 누구였는지, 그리고 다른 역할의 시도가 어떻게 남았는지를 떠올려 보시기 바랍니다.
### 제작 기준
통합반 11일차의 「Quiz 1. 판단이 제출된 시점의 처리 건」은 7회차의 「Quiz 3. 냉각 명령을 시작시키는 쪽」과 같은 장면(판단 제출 뒤 다음 작업을 여는 쪽)을 묻고 근거 장도 이 회차에 없어, 실라버스가 든 「승인 권한」을 묻는 문항으로 새로 썼다(과정 맞춤). 승인 작업은 운전원 역할만 끝낼 수 있고 다른 역할의 시도는 거부되어 `DECISION_DENIED`로 남는다: 사실표 4.5절(역할 검사 403 + 감사 기록). 거부는 사람의 거절이 아니므로 승인 단계는 그대로 열려 있다. 본문의 「프로세스가 에이전트 밖에서 보장하는 것」 · 「감사 기록(Audit Log)」 · 「승인 대기」 장으로 풀린다. 정답 4번.

## SLIDE 30 — Quiz 3. 승인을 기다리는 동안 배포된 새 판본
### 화면 내용
- 유형: 문답
- 메시지: 어느 긴급 대응 처리 건이 운전원 승인에서 기다리는 동안, 갈림의 조건을 고친 정의가 새 판본으로 배포되었다.
- 문장: 기다리던 처리 건에 대한 설명으로 옳은 것은?
- 요소:
  1. 기다리던 처리 건은 닫히고 새 판본으로 다시 열린다
  2. 기다리던 처리 건은 열릴 때의 판본으로 끝까지 간다
  3. 기다리던 처리 건의 남은 단계부터 새 판본의 조건이 적용된다
  4. 기다리던 처리 건은 새 판본이 배포되는 순간 거절로 닫힌다
- 노트: 고친 정의가 언제부터 적용되는지를 묻는 문항입니다. 등록과 배포가 각각 무엇을 바꾸는지, 그리고 이미 열린 처리 건이 어느 판본을 따르는지를 떠올려 보시기 바랍니다.
### 제작 기준
통합반 9일차의 「Quiz 1. 승인 지연 알림이 나간 처리 건」과 「Quiz 3. 냉각 명령을 시작시키는 쪽」은 7회차에 실었다. 실라버스가 든 「정의 버전」을 묻는 문항이 통합반에 없어 본문의 「판본과 배포: 고친 프로세스가 적용되는 시점」 장만으로 풀리는 문항을 새로 썼다(등록만으로는 바뀌지 않고, 배포한 판본으로 다음 경보부터 열리며, 열린 처리 건은 열릴 때의 판본으로 끝까지 간다: 사실표 4.7절). 정답 2번.

## SLIDE 31 — 정답과 판단 기준
### 화면 내용
- 유형: 표
- 메시지: 세 문항은 판단의 근거가 되는 기록, 승인할 수 있는 역할의 경계, 판본이 적용되는 시점을 바르게 읽는지 확인한다.

  1. Quiz 1 | COMPLETED는 실행이 끝났다는 뜻이다. 결과는 끝 이벤트와 단계의 상태로 읽는다. | 1번
