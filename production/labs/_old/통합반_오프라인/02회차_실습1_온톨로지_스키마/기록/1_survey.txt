`.github/copilot-instructions.md`를 읽었고 그 규칙대로 진행했습니다. 파일은 하나도 고치지 않았습니다.

먼저 밝힐 것이 하나 있습니다. 규칙 4(터미널 명령 금지)를 읽기 전에 폴더의 파일 목록을 보려고 터미널 명령(`find`)을 한 번 실행했습니다. 읽기만 하는 명령이라 바뀐 것은 없고, 그 뒤로는 파일 읽기만 썼습니다.

## 1. 지난 시간의 스키마와 그래프에 이미 들어 있는 것

노드는 모두 33개, 관계는 모두 46개입니다.

| 클래스 | 한글 이름 | 노드 수 | `id`, `name` 외 속성 |
|---|---|---|---|
| `Asset` | 설비 | 3 | 없음 |
| `Component` | 구성 요소 | 6 | `aliases` |
| `Sensor` | 센서 | 5 | `tag`, `virtual` |
| `Actuator` | 구동기 | 3 | `signal`, `min`, `max`, `options`, `note` |
| `StateVariable` | 상태 변수 | 8 | `aliases`, `unit`, `normal`, `limit`, `limit_note` |
| `Part` | 부품 | 3 | `part_no` |
| `Symptom` | 증상 | 2 | 없음 |
| `FailureMode` | 고장 유형 | 1 | 없음 |
| `Cause` | 원인 | 1 | 없음 |
| `Skill` | 조치 | 1 | 없음 |

| 관계 | 방향 | 개수 |
|---|---|---|
| `HAS_COMPONENT` | Asset → Component | 18 |
| `MOUNTED_ON` | Sensor, Actuator → Component | 9 |
| `MEASURES` | Sensor → StateVariable | 5 |
| `CONTROLS` | Actuator → StateVariable | 3 |
| `USES_PART` | Component → Part | 3 |
| `SHOWS` | Sensor → Symptom | 2 |
| `INDICATES` | Symptom → FailureMode | 2 |
| `CAUSES` | Cause → FailureMode | 1 |
| `MITIGATED_BY` | FailureMode → Skill | 1 |
| `OCCURS_IN` | FailureMode → Component | 1 |
| `RELATED_TO` | Cause → Part | 1 |

- **공유 구조**: 설비만 한 대에 노드 하나이고, 구성 요소·센서·구동기·상태 변수·부품은 세 대가 같은 노드를 함께 가리킵니다.
- **`conventions`**: 문장 20개가 있습니다. 식별자 접두사, 다른 이름은 `aliases`에 넣기, 빈 값은 적지 않기 등입니다.
- **규칙과 어긋난 곳**: 관계 11개 모두에 `cardinality` 칸이 없습니다. 규칙은 관계마다 이 칸을 두라고 합니다. 관계에 `properties`를 둔 곳도 아직 없습니다.

## 2. 새 자료에서 담지 못하는 것과 다르게 적힌 곳

### 지금의 스키마로 담지 못하는 것

- **공급사**: `공급_조건.csv`에 A정밀, B-OEM, C트레이딩 세 곳이 나옵니다. 클래스도, 부품과 잇는 관계도 없습니다.
- **공급 조건 7줄**: 단가(만원), 불량률, 납기(일), 승인 여부를 둘 속성이 없습니다. 같은 공급사라도 부품마다 값이 다릅니다(A정밀의 단가는 35 / 18 / 180).
- **공급사 이름의 괄호 말**: 「(저가)」, 「(순정)」, 「(최저가 · 비승인)」을 둘 곳이 없고, 규칙의 이름 표에도 없습니다.
- **설비 코드**: `Asset`에 `code`가 없습니다. 지금은 `id`와 `name` 안에만 들어 있습니다.
- **설비의 「구분」**: 값 「유압 파워팩」과 비고 「HYD-01과 같은 모델」을 둘 속성이 없습니다.
- **한계의 방향**: `limit_direction`이 없습니다. 지금은 `limit_note`의 문장으로만 알 수 있습니다. 메모 4절은 유온 65와 팬 진동 2.0이 위쪽, 토출 압력 130이 아래쪽이라고 적었습니다.
- **센서의 다른 이름**: `Sensor`에 `aliases`가 없어서 「TS1 오일 온도」를 둘 곳이 없습니다.
- **비고와 작성자**: 아래 내용을 둘 속성이 없습니다.
  - 구성 요소 목록의 작성자(한서윤, 문태오, 남궁현)
  - 구성 요소 비고(「센서 없음」, 「A 펌프」, 「교체부품 칸 확인 못 함」)
  - 예비품 비고(「HYD-01~03 공용」, 「세척으로 회복되지 않을 때 교체」)
  - 예비품의 출처(구매 기준서 PR-07)

## 3. 보완하기 전에 정해 주셔야 하는 것

1. **담을 범위**: 공급 조건을 담을지 정해 주세요. 메모 6절의 다섯째 물음(「어느 공급사에서 얼마에 살 수 있는가」)에 답하려면 필요합니다. 담지 않으면 아래 2~4번은 필요 없습니다.
2. **공급사와 공급 조건의 자리**: 공급사는 `Supplier` 클래스로, 단가·불량률·납기는 `SUPPLIED_BY` 관계의 속성으로 두기를 권합니다. 부품과 공급사의 짝마다 값이 달라서 그렇습니다.
   - **승인 여부**: 공급사의 속성인지 관계의 속성인지 정해 주세요. 자료에서는 공급사마다 값이 한 가지뿐이라 자료만으로는 가릴 수 없습니다. 공급사 이름에 「비승인」이 붙어 있어 공급사의 속성 쪽을 권합니다.
   - **방향과 카디널리티**: `Part` → `Supplier`, `N:M`을 권합니다.
3. **공급사의 이름과 식별자**:
   - 괄호 말을 뗀 「A정밀」을 `name`으로 할지, 「A정밀 (저가)」 전체로 할지.
   - 뗀다면 「저가 / 순정 / 최저가」를 버릴지, 새 속성으로 둘지. 새 속성은 이름을 제안해 확인받아야 합니다.
   - 접두사(예: `sup:`)와 쌍점 뒤의 말(예: `sup:b-oem`). 「A정밀」과 「C트레이딩」은 영어로 어떻게 옮길지도 필요합니다.
4. **공급 조건의 자료형과 값**:
   - `price`: 자료대로 만원 단위의 수(35)로 둘지, 원으로 바꿀지.
   - `fail_rate`: 0.12가 비율인지 퍼센트인지 자료에 없습니다. 자료의 수를 그대로 옮길지.
   - `approved`: 「예 / 아니오」를 `boolean`으로 바꿔도 되는지.
   - 네 속성의 필수 여부.
5. **설비 코드**: `Asset`에 `code`(「HYD-01」, `string`)를 둘지와 필수 여부. 「구분」(유압 파워팩)도 담을지 정해 주세요. 담는다면 속성 이름을 제안해 확인받겠습니다.
6. **한계의 방향**: `limit_direction`을 `StateVariable`의 `enum` 속성으로 둘지, 허용값을 무엇으로 할지(예: `upper` / `lower`). 한계가 없는 상태 변수가 다섯이라 필수는 아님을 권합니다. 이미 있는 `limit_note`와 `conventions`의 문장은 지우지 않고 문장을 더합니다.
7. **표기가 다른 줄의 중복 처리**:
   - 「주 펌프 A」와 「A 펌프」를 `aliases`에 넣을지, 표기만 다른 것으로 보고 넣지 않을지.
   - 「작동유 온도」를 `sv:ts1`의 `aliases`에 넣을지.
   - 태그(TS1 등)를 상태 변수의 `aliases`에 넣을지. 태그는 이미 센서의 `tag`에 있습니다.
   - 「TS1 오일 온도」를 위해 `Sensor`에 `aliases`를 더할지, 중복 줄로 보고 버릴지.
8. **값이 다르게 적힌 곳**:
   - 「130 bar」는 수 130으로 보고, 「L/min」과 빈 단위 칸은 이미 있는 「l/min」과 「mm/s」를 그대로 두려고 합니다. 이렇게 이미 든 값을 따를지 정해 주세요.
   - HYD-03의 빈 교체부품 칸이 있어도 주 펌프의 `USES_PART`를 그대로 둘지.
9. **비고와 작성자**: 작성자, 구성 요소 비고, 예비품 비고, 출처(PR-07)를 담을지 정해 주세요. 담는다면 어느 클래스에 어떤 이름으로 둘지 제안해 확인받겠습니다.
10. **이미 있는 관계 11개의 `cardinality`**: 이번에 함께 채울지 정해 주세요. 채운다면 값을 확인받겠습니다. 예를 들어 `HAS_COMPONENT`는 세 설비가 같은 구성 요소 노드를 가리키므로 `N:M`이 되고, `MOUNTED_ON`도 펌프 전환 밸브가 두 펌프에 붙어 있어 `N:M`이 됩니다.
