# 기록 — 통합반 오프라인 6회차 실습 3 (Copilot판)

## 이 묶음의 상태
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)이다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했다.**
- `완성/`은 같은 요청을 Claude Code로 대신 돌려 만든 것이다(2026-10-12, macOS, Claude Code 2.1.296). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- 가이드의 요청 글은 대신 돌릴 때 실제로 보낸 글이다. 가이드에서 Copilot의 답을 보여 주는 자리는 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 10곳).
- 예제 회의록 두 편은 이 실습을 위해 새로 썼다. 인물과 회사 사정은 모두 지어낸 것이다.

## 대신 돌린 순서와 응답 시간

|---|---|---|---|---|

- 1~3차는 이전 실행 그대로이고(SKILL.md의 첫 판), 4차부터는 그 SKILL.md가 든 시작 폴더의 사본에서 이번에 새로 돌렸다. 이전 판의 `4_run1.txt`, `6_run2.txt`는 새 실행의 기록으로 바꿨다.
- 응답을 기다린 시간의 합은 약 8분이다. 가이드의 단계별 분수는 추정이다.
- 사람이 대신 한 것: 4차와 8차의 요청 앞에 「먼저 .github/copilot-instructions.md 를 읽고 그 규칙을 따라 줘.」를 붙였다(Claude Code는 이 파일을 자동으로 읽지 않는다). 가이드의 4 · 8단계 요청에는 이 문장이 없다. `기록/1_prompt.txt`도 같은 까닭으로 가이드의 글과 첫 문장이 다르다.

## 대신 돌리면서 본 것
- 규칙 파일이 비워 둔 다섯 가지를 AI가 스스로 정하지 않고 되물었다. 계획에 요청하지 않은 단계가 들어 있었고, 빼라고 하자 뺐다.
- **규칙 위반 요청 둘 다 멈췄다. 규칙 파일(`시작/.github/copilot-instructions.md`)은 고치지 않았다.**
  - 5-1: 회의록도 결과도 고치지 않았다. 「하면 안 되는 것」 1번(회의록은 읽기만)과 2번(없는 담당자 · 날짜를 지어내지 않는다)을 들었다. 대신 사람이 회의록에 직접 써 넣거나, 「이번만 규칙 1의 예외」라고 분명히 말해 주면 하겠다고 했다. 곧 규칙은 잠금장치가 아니고, 요청하는 사람이 예외를 주면 풀릴 수 있다. 가이드 5단계의 대처 상자에 이 점을 적었다. 예외를 실제로 주어 보지는 않았다.
  - 5-2: JSON을 바꾸지 않았다. 「정해져 있는 것」의 칸 이름 줄과 SKILL.md를 들었다. 대신 규칙 파일과 SKILL.md를 먼저 고치는 길을 권했다.
  - 두 요청 뒤 회의록 두 편과 결과 두 파일의 해시가 보내기 전과 같았다.
- 4차와 8차에서 AI가 폴더 구조를 보려고 터미널 명령(`find`)을 한 번씩 실행했고, 답에서 규칙 4번에 어긋났다고 스스로 밝혔다(읽기만 하는 명령이며 바뀐 파일은 없다). 규칙 4번은 이 환경에서 완전히 지켜지지는 않았다. Copilot에서는 터미널 실행에 허용 물음이 뜨는지 확인해야 한다.
- 6-1: 「다른 절은 건드리지 마」를 지켜 새 절만 더했고, 그 때문에 절차와 예시가 새 절과 어긋난다는 것을 답의 끝에서 스스로 짚었다. 6-2에서 세 곳을 맞췄는데, 요청한 세 곳 밖에서 새 절 안의 두 문장도 함께 고쳤다고 밝혔다. 요청에 없던 것(빈 묶음의 표기, 「이번 주 안」 같은 표현은 기한 미정에 넣지 않는다, 묶음 안의 순서)은 스스로 정하고 답에 밝혔다.
- 7: SKILL.md의 「나누는 기준」 가운데 미결 안건 항목에만 다섯 줄을 더했다. 회의록_1의 「경보 기준 온도 조정 요청」의 근거가 한 문장에서 네 문장으로 늘었다.
- 결과: 회의록_1은 작업 17건 · 미결 안건 2건 · 따로 챙길 것(담당 미정 5, 기한 미정 7, 중복 1). 회의록_2는 작업 8건 · 미결 안건 2건 · 따로 챙길 것(담당 미정 1, 기한 미정 1, 중복 0). 이전 실행에서는 회의록_1이 18건이었다(「11월 정기 회의 장소를 공지한다」를 이번에는 작업으로 보지 않았다). 같은 스킬이어도 실행마다 건수가 달라질 수 있다.
- 두 결과의 JSON은 작업 한 건의 칸이 `할일 · 담당자 · 완료시점 · 근거` 넷이고, 근거 문장은 모두 회의록 원문에 그대로 있었다(스크립트로 대조). 회의록 원문은 실행 전과 같았다.

## 덱과 다른 곳
- 덱 34장은 「겹치는 항목은 합치지 않고 중복으로 표시」라고 적었다. 이 묶음의 권하는 답(2단계 3번 줄)과 완성본은 하나로 합치고 `[중복]`을 붙인다. 가이드 2단계의 표에 「합치지 않고 두 줄에 모두 중복」을 다른 선택으로 적어 두었다. 어느 쪽을 권하는 답으로 할지는 정해야 한다.

## 확인하지 못한 것
- Copilot 채팅의 화면 문구(방식 「에이전트」, 모델 이름, 새 채팅 단추, 허용 물음)와 아이콘의 위치.
- Copilot이 `.github/copilot-instructions.md`를 자동으로 읽는지. VS Code 문서에는 설정 하나(`github.copilot.chat.codeGeneration.useInstructionFiles`)가 켜져 있어야 한다고 적혀 있다. 가이드의 첫 요청은 설정과 무관하게 통하도록 파일 경로를 직접 적었다. **5단계의 규칙 위반 요청은 새 대화(4단계)에 이어 보내므로, 이 설정이 꺼져 있으면 규칙 파일이 대화에 들어 있지 않을 수 있다.** 대신 돌릴 때는 4차 요청에 규칙 파일을 읽으라는 문장을 붙였다. SKILL.md에도 회의록을 고치지 않는다는 줄과 칸 이름 줄이 있어 스킬만으로도 멈출 가능성은 있으나 확인하지 못했다.
- 채팅에서 `/meeting-actions`로 스킬이 불리는지. VS Code 문서에는 `.github/skills/<이름>/SKILL.md`를 `/`로 부를 수 있다고 적혀 있다.
- Copilot에서 원문 수정이나 터미널 실행을 막는 설정. 이 판에는 넣지 않았다.
- 가이드 2단계 표의 「다르게 정하려면」 칸의 선택들은 돌려 보지 않았다. 권하는 답 한 벌만 돌렸다.
- 7단계에서 학생이 다른 거리(보고의 담당자, 기한 미정의 범위)를 골랐을 때의 결과.
- Windows에서의 실행, 가이드만 보고 따라 했을 때 50분에 들어가는지.
- 가이드 화면은 아홉 장(준비~8단계)을 모두 1200폭 헤드리스 Chrome으로 렌더해 보았고, 7단계는 접어 둔 요청을 펼친 모습도 보았다. 버튼 동작(복사, 단계 이동, 글 칸 저장)은 눌러 보지 않았다. 좁은 화면(휴대폰 폭)은 보지 못했다.
