촬영 전에

  • Docker Desktop이 켜져 있고, HYD 서비스는 모두 내려가 있는 상태에서 시작한다.
  • VS Code로 저장소 폴더를 열어 두고 터미널은 닫아 둔다.
  • 명령은 Git Bash 기준이다. 저장소 맨 위 폴더에서 실행한다.
  • 주소는 수업 환경 기준이다(포털 http://127.0.0.1:8088).
  • 대본과 요점은 그대로 읽는 글이 아니다. 조작하면서 이 정도를 말한다는 기준이다. 예시와 한마디는 상황에 맞게 바꿔 말한다.
  • 예상과 다르게 나오면 무엇이 다른지 화면에서 짚고, 왜 그런지 말한 다음 고친다.
  • 구간마다 끊어서 찍는다. 말이 꼬이면 그 구간만 다시 찍는다. 배정 시간은 다 채운다.

  3. Docker Desktop 창을 잠깐 띄워 엔진이 실행 중인 것을 보여 준다.
  4. VS Code 오른쪽의 Copilot 채팅 창을 열었다 닫는다.

입력할 글자

어디에적을 글자

대본

먼저 오늘부터 쓸 도구를 확인하겠습니다. 터미널을 열고요. 도커 버전부터 볼게요. 이렇게 버전이 나오면 설치돼 있는 겁니다.

Docker는 서비스를 컨테이너라는 단위로 실행해 줍니다. 서비스마다 필요한 환경을 통째로 담아서 띄우는 거예요. 그래서 여러분 PC에 데이터베이스나 브로커를 하나하나 설치하지 않아도 됩니다.

Docker Compose는 그 컨테이너 여러 개를 한 번에 띄우는 도구입니다. 아까 본 compose.yaml을 읽어서요. Python은 이 서비스들과 앞으로 랩에서 만들 코드가 쓰는 언어고요.

마지막으로 이 VS Code가 작업 공간입니다. 편집기이자 터미널이죠. 오른쪽 채팅 창이 GitHub Copilot인데, 여기에 말로 요청해서 코드를 만드는 방식은 다음 실습부터 씁니다.

하는 동안 한마디 (골라서)

  • 버전을 보며: 버전 숫자가 화면과 조금 달라도 괜찮다. 명령이 실행되고 버전이 나오는지만 본다.

대본

이제 본체입니다. 명령은 한 줄이에요. docker compose up, 그리고 뒤에 -d. 실행하겠습니다.

올라오는 이름을 보세요. 아까 그림에서 본 것들입니다. 설비와 제어기, 브로커가 먼저 뜨죠. 여기가 공장 쪽입니다. 그다음에 수집 창구와 명령 관문, 그리고 이벤트 로그가 올라옵니다.

Healthy라고 바뀌는 건 그 서비스가 준비됐다는 뜻이에요. 서비스들은 서로를 기다립니다. 브로커가 준비돼야 수집 창구가 뜨고, 로그가 준비돼야 감지 서비스가 뜨는 식이죠. 값이 올라가는 순서와 같습니다.

다 올라왔네요. 하나만 더 띄울게요. 에이전트가 업무 데이터와 판단 규칙을 조회할 때 쓰는 도구 서버 둘입니다. 이건 뒤에서 에이전트를 다룰 때 다시 나옵니다.

하는 동안 한마디 (골라서)

  • 올라오는 동안: Exited라고 나오는 것이 몇 개 있다. 처음에 한 번 돌고 끝나는 준비 작업이라 정상이다(토픽 만들기, 지식 적재, 화면 설정).
  • 올라오는 동안: 이 명령 한 줄이 서비스 열일곱 개를 띄운다. 손으로 하나씩 설치했다면 하루가 걸릴 일이다.

나머지가 IT입니다. redpanda가 이벤트 로그, timescaledb가 시계열 저장소, detector가 감지 서비스, grafana가 분석 화면. 그리고 neo4j, agent, process, portal. 이쪽이 앞으로 우리가 주로 다룰 지식과 에이전트와 프로세스입니다.
