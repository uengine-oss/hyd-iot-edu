물어본 것을 이렇게 정할게.

1. 그래프 DB는 Neo4j 5.26 Community 야. 그래서 제약은 유일 제약만 건다.
2. 유일 제약은 클래스 11개 모두의 id 에 건다. tag, signal, part_no, code, 공급사의 name 에는 이번에는 걸지 않는다.
3. 문장은 노드 하나에 하나, 관계 하나에 하나씩 쓴다. 묶지 않는다. 내가 graph.json 의 줄과 한 줄씩 맞춰 읽을 거야.
4. 관계의 양 끝은 레이블과 id 를 함께 적어 MATCH 로 찾은 다음 MERGE 로 잇는다. 끝 노드가 없으면 만들지 않는다.
5. 다시 넣을 때 이미 들어 있는 속성값은 graph.json 의 값으로 덮어쓴다.
6. 수는 graph.json 에 적힌 글자 그대로 적는다.
7. 조회 질의는 지난 시간에 던진 세 물음에 답하게 한다. 물음에 나온 말은 name 과 aliases 에서 정확히 같은 것으로 찾고, 설비는 code 로, 공급사의 등급은 grade 로 찾는다.
   (1) '열교환기'에 붙어 있는 센서 가운데 실물 계기는 무엇이고, 그것이 재는 값의 한계는 얼마이며 위쪽 한계인가 아래쪽 한계인가?
   (2) HYD-02 의 '유압 펌프'에 들어가는 교체 부품을 승인 공급사 가운데 가장 싸게 사려면 어디에서 얼마인가?
   (3) 순정 공급사에서만 산다면 팬 베어링은 얼마이고 며칠 걸리는가?
8. 검사 질의는 다섯 가지를 본다. 첫째는 수를 내고, 나머지 넷은 어긋난 것만 행으로 낸다(0행이면 통과).
   (1) 레이블별 노드의 수와 관계 유형별 관계의 수
   (2) 같은 id 를 가진 노드가 둘 이상인 곳(레이블이 달라도 잡는다)
   (3) 필수 속성이 빠진 노드와 관계
   (4) 양 끝의 레이블이 schema.json 의 from, to 와 다른 관계
   (5) enum 속성의 값이 허용값 밖인 노드
