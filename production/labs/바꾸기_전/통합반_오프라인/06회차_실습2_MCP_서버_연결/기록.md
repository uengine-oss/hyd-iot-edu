# 기록 — 통합반 오프라인 6회차 실습 2 (Copilot판)

## 이 묶음의 상태
- 실라버스의 행: 「여러 MCP를 직접 연결하고 비교하기」(50분). 덱의 실습 간지는 31장 「서로 다른 MCP 서버의 연결과 비교」, 설명 장은 32장이다.
- 수업 도구는 VS Code의 GitHub Copilot 채팅(GPT-6 Luna)이다. 이 PC에는 VS Code와 Copilot이 없어서 **Copilot으로는 한 번도 돌려 보지 못했다.**
- `완성/`은 같은 요청을 Claude Code로 대신 돌려 만든 것이다(2026-10-13, macOS, Claude Code 2.1.296, Python 3.14, git 2.50.1). Copilot과 GPT-6 Luna로 다시 돌려 바꿔야 한다.
- 가이드의 요청 글은 대신 돌릴 때 실제로 보낸 글이다(다른 곳은 아래 「사람이 대신 한 것」). Copilot의 답과 VS Code 화면은 모두 사진 자리로 비워 두었다(`찍어_주실_화면.md`, 13곳).
- 서버 셋은 이 묶음에서 새로 쓴 파이썬 파일이다(`시작/서버/`, 표준 라이브러리만 쓴다). 덱 32장의 제작 기준이 「세 서버의 설치 · 설정 · 도구 이름은 저장소에 없다」고 적어 둔 자리를 채운 것이다. 공개된 서버를 받아 쓰려면 수업 PC에 Node와 uv, 내려받을 네트워크가 있어야 해서 쓰지 않았다. 도구 이름은 널리 쓰이는 파일시스템 · Git · 시간 서버의 이름을 닮게 지었으나 같은 프로그램이 아니다.
- `업무자료/`는 `도구/자료_준비.py`가 만든다(저장소 안에 Git 저장소를 넣어 둘 수 없어서다). 기준 문서 셋은 `docs/samples/`의 것 그대로이고(교육용 예시라는 머리말도 원문 그대로다), 회의록 둘은 6회차 실습 3의 것이다. 쿨러 점검 메모, 3호기 점검 기록, 읽어_주세요, 주간 협의 메모에 더한 두 줄, 구매팀 발주 대기 목록은 새로 썼다. 회의록에 있는 일만 옮겼고 HYD의 수치는 새로 짓지 않았다. 사람 이름은 실습 3의 지어낸 이름이다.
- `완성/업무자료/`에는 Git 이력(.git)이 없다. 완성 폴더에서 Git 서버를 써 보려면 `python 도구/자료_준비.py --다시`로 다시 만든다.

## 사람이 대신 한 것
- **`.vscode/mcp.json`을 사람이 붙여넣었다(3 · 4차).** Claude Code가 `.vscode/` 아래의 파일을 민감한 파일로 보아 편집을 막았고, 허용 규칙을 주어도 풀리지 않았다. 막힌 것을 돌아가지 않고, 답에 적힌 설정 블록을 글자 그대로 파일에 넣었다. 완성본의 `mcp.json`은 4차의 답에 적힌 것과 같다. Copilot에서는 이 파일을 직접 고치는지, 허용 물음이 뜨는지 확인해야 한다. 가이드 3 · 4단계의 대처 상자에 「고치지 못한다고 하면 직접 붙여넣는다」를 적었다.
- **서버의 시작과 중지.** VS Code에서는 학생이 설정 파일에서 누른다. 대신 돌릴 때는 차례마다 `.vscode/mcp.json`을 Claude Code의 형식으로 바꿔 `--mcp-config`로 넘겼다(`${workspaceFolder}` → 실행 폴더, `python` → `python3`). 멈춘 서버는 그 차례에 빼고 넘겼다.
- **가이드와 보낸 글이 다른 곳 하나.** 3b차에 보낸 글은 「.vscode/mcp.json 은 네가 준 내용으로 내가 직접 바꿨고, time 서버를 시작했어. …」로 시작한다. 가이드 3단계의 요청은 앞 구절을 빼고 「time 서버를 시작했어. …」로 시작한다. 3y차의 글(허용했으니 다시 써 달라)은 가이드에 싣지 않았다.
- 결과 두 파일과 기록에 찍힌 실행 폴더의 경로를 `<임시 폴더>`로 바꿨다. 그 밖의 글자는 AI가 쓴 그대로다.

## 대신 돌리면서 본 것
- 규칙이 비워 둔 다섯 가지 가운데 연결에 필요한 넷을 스스로 정하지 않고 물었다. 다섯째(어느 도구를 부를지)는 「그 단계에서 묻겠다」고 했고 계획에서 다시 물었다.
- time 서버를 부를 때 요청에 없던 `timezone`을 `Asia/Seoul`로 채웠고, 도구 설명의 기본 시간대에서 가져왔다고 답했다.
- 5차: 여섯 호출이 모두 성공했다. 표의 필수 인수는 점검 프로그램의 출력과 같다. `convert_time`의 결과가 다섯 줄에서 잘려 UTC 시각이 빠졌다는 것과, 「읽기 전용」 칸은 호출이 아니라 서버 파일을 보고 채웠다는 것, 「다시 불러도 같은지」는 time만 실제로 견주었다는 것을 스스로 밝혔다.
- 6차: 권한 밖의 경로에는 서버의 「접근 거부」 문장이, `Seoul`에는 「입력 오류」 문장이 그대로 돌아왔다. git 서버를 빼자 도구가 목록에서 사라져 호출을 보내지 못했고, 앞에서 받은 git_log 결과로 대신 답하지 않았다. 셋째 줄의 「돌아온 것」에는 Claude Code가 낸 영문 알림이 적혀 있다. Copilot에서는 이 문장이 다를 것이다.
- **규칙 위반 요청 둘 다 멈췄다. 규칙 파일은 고치지 않았다.**
  - 7-1: 터미널도 파일 읽기도 쓰지 않았고 두 결과 파일을 고치지 않았다. 「하면 안 되는 것」 2 · 3 · 4 · 7번을 문장과 함께 들었다. 대신 서버를 다시 켠 뒤 실제로 부르는 길을 내놓았고, 그때도 실패 줄은 지우지 않겠다고 했다.
  - 7-2: `서버/파일시스템_서버.py`를 고치지 않았다. 1 · 7번을 들었다. 대신 허용 폴더는 사람이 정하는 자리이니 `.vscode/mcp.json`의 허용 폴더에 `구매팀_자료`를 더하는 길을 내놓았다.
  - 두 요청의 앞뒤로 실행 폴더의 모든 파일(Git 내부와 파이썬 캐시 제외) 해시가 같았다. 시작 때와 견주어도 `결과/`와 `mcp.json` 말고는 같았다.
- 8차: 요청한 절만 더했다. 센 수(5 · 4 · 0, 4 · 1 · 0, 2 · 2 · 0)는 점검 프로그램의 출력과 같다(가이드 스크립트가 이 일치를 검사한다). 요청하지 않은 참고(읽기 전용을 빼면 6 · 5 · 1)를 더하고, 확인한 값이 아니라고 밝힌 뒤 빼겠느냐고 물었다. 빼지 않고 두었다.
- 8v(막연한 말): 무엇이 불편한지 묻지 않고 파일의 짜임을 바꿨다(표 하나 → 서버별 세 표, 네 줄 → 소제목). 칸 여섯은 규칙을 들어 그대로 두었고, 답의 끝에서 불편한 곳이 칸의 길이였느냐고 되물었다.
- **규칙 4번(터미널 명령을 실행하지 않는다)은 완전히 지켜지지 않았다.** 1차에서 폴더를 보려고 `ls`를 한 번, 5차에서 아무 일도 하지 않는 명령(`true`)을 한 번 실행했고, 두 번 다 답에서 규칙에 어긋났다고 스스로 밝혔다. 바뀐 파일은 없다.
- 점검 프로그램으로 따로 확인한 것: 서버가 없는 설정(「연결된 서버가 없다」), 허용 폴더를 적지 않은 서버(「연결 실패」와 서버가 남긴 말), 필수 인수가 빠진 호출(`isError: true`, 「필수 인수가 없다 — target_timezone」), 없는 도구, 없는 서버 이름. `--read-only`를 빼면 도구가 6개가 되고 `write_file`의 읽기 전용 표시가 false다. 허용 폴더에 구매팀_자료를 더하면 같은 호출이 내용을 돌려준다.
- `자료_준비.py`를 두 번 실행해(시험 폴더와 실행 폴더) 마지막 커밋 번호가 같았다(`42f785f`). 날짜와 쓴 사람을 고정해 두었기 때문이다. Windows에서도 같은지는 보지 못했다.

## 덱과 다른 곳
- 덱 32장은 「서버가 연결되지 않았을 때 돌아오는 오류를 확인한다」고 적었다. 대신 돌린 실행에서는 멈춘 서버의 도구가 목록에서 사라져 호출 자체가 가지 않았고, 서버가 돌려준 오류는 없었다. 가이드 6단계는 실제대로 「서버의 말은 없다」고 썼다. Copilot에서 어떻게 보이는지는 확인해야 한다.
- 덱 19장은 HYD의 호스트를 Claude Code로 적는다. 이 실습의 호스트는 VS Code다(덱 32장의 노트와 같다).
- 실라버스는 「파일시스템 · Git · 시간 MCP 서버 3종 이상」이라고 적었다. 이 묶음은 셋만 잇는다.

## 판단이 갈렸던 곳
- 공개된 서버 대신 묶음 안의 파이썬 서버를 쓴 것(위 「이 묶음의 상태」). 수업에서 공개 서버를 쓰기로 하면 도구 이름과 인수(예: 저장소 경로를 호출마다 넘기는지)가 달라져 4 · 5 · 6단계의 표를 다시 만들어야 한다.
- 넷째 실습(여러 도구의 조합)이 이 서버들을 이어받는지는 맞추지 못했다. 그 묶음은 같은 때에 따로 만들어졌다. 파일시스템 서버를 읽기 전용으로 둔 것은 넷째 실습의 「저장」과 부딪칠 수 있다(읽기 전용을 풀면 `write_file`이 나온다).
- 시간 서버는 PC에 시간대 자료가 없으면 서머타임이 없는 열 곳의 표로 대신한다. Windows의 파이썬에는 시간대 자료가 없을 수 있어서 넣었다.

## 확인하지 못한 것
- Copilot에서의 실행 전부. 특히 `.vscode/mcp.json`의 형식(`servers`, `type`, `command`, `args`, `${workspaceFolder}`)으로 서버가 뜨는지, 설정 파일의 서버 항목 위에 「시작 · 중지」가 뜨는지와 그 문구, 서버를 처음 띄울 때의 신뢰 물음, 도구 호출 전의 허용 물음, 에이전트 방식에서만 도구가 불리는지. 가이드의 이 대목은 VS Code 문서에 대한 기억으로 썼고 화면으로 확인하지 못했다.
- Copilot이 `.github/copilot-instructions.md`를 자동으로 읽는지. 첫 요청에 경로를 직접 적었고 한 대화를 끝까지 잇도록 짰다. 새 대화를 열면 규칙이 들어 있지 않을 수 있다.
- Copilot이 멈춘 서버의 도구를 편집기의 파일 읽기나 터미널로 대신하지 않는지(규칙 2번). VS Code에는 Copilot이 쓸 수 있는 파일 읽기 도구가 늘 있다.
- Windows: `python` 명령으로 서버가 뜨는지, 한글 파일 이름의 서버 파일과 한글 경로, 표준 입출력의 UTF-8, `자료_준비.py`의 한글 옵션(`--다시`), Git이 깔려 있는지.
- 가이드 2단계 표의 「다르게 정하면」 칸은 채팅으로 돌려 보지 않았다(읽기 전용을 푸는 것과 허용 폴더를 넓히는 것만 점검 프로그램으로 보았다).
- 8단계에서 학생이 다른 거리(잘린 결과, 실패 뒤에 할 일)를 골랐을 때의 결과.
- 가이드만 보고 따라 했을 때 50분에 들어가는지. 허용 물음이 여러 번 뜨는 5단계가 8분에 되는지.
- 가이드 화면은 준비 · 3 · 5 · 6 · 8단계를 1200폭 헤드리스 Chrome으로 렌더해 보았다. 나머지 단계와 버튼 동작(복사, 단계 이동, 글 칸 저장), 좁은 화면은 보지 못했다.
