# 사람이 쓰는 두 파일

이 폴더의 두 파일은 사람이 편집기에서 직접 쓴다. 에이전트는 읽기만 한다.

## 답변.json — 에이전트의 질문에 답한다
답 한 건이 한 항목인 목록이다.

```json
[
  {"요청": "R06", "질문": 1, "답": "S08", "답한_사람": "서유나"}
]
```

| 칸 | 뜻 |
|---|---|
| `요청` | 질문이 붙은 요청의 번호 |
| `질문` | 그 요청에서 몇 번째 질문인지. `결과/요청_처리.json`의 질문 `순번`과 같은 수다 |
| `답` | 답. 질문에 선택지가 있으면 그 가운데 하나를 글자 그대로 적는다 |
| `답한_사람` | 답한 사람의 이름 |

## 승인.json — 추천된 조치를 승인하거나 거절한다
결정 한 건이 한 항목인 목록이다.

```json
[
  {"요청": "R03", "결정": "승인", "절차_번호": "SOP-COOL-11", "역할": "운전원", "이름": "권도현", "사유": null},
  {"요청": "R02", "결정": "거절", "절차_번호": null, "역할": "생산관리자", "이름": "남기훈", "사유": "오후 출하분 생산이 끝난 뒤에 다시 본다"}
]
```

| 칸 | 뜻 |
|---|---|
| `요청` | 결정하는 요청의 번호 |
| `결정` | `승인` 또는 `거절` |
| `절차_번호` | 승인하는 조치의 절차 번호. 그 요청의 점검 계획에 붙은 조치 가운데 하나다. 거절이면 `null` |
| `역할` · `이름` | 결정한 사람의 역할과 이름. 역할은 온톨로지의 역할 이름과 같은 글자다 |
| `사유` | 거절하는 까닭. 승인이면 `null` |

## 쓸 때 주의할 것
- 항목과 항목 사이에 쉼표를 넣고, 마지막 항목 뒤에는 쉼표를 넣지 않는다.
- 글자는 큰따옴표로 감싼다. 질문의 순번은 따옴표 없이 수로 적는다.
- 저장한 뒤 `python 요청_처리.py`를 다시 실행해야 반영된다.
