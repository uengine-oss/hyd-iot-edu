유압설비 IIoT SCADA×지식 지도 기반 Agent 조치 프로세스

설비에서 올라온 데이터로 이상을 잡는 것에서 끝나지 않는다. 온톨로지 지식 지도가 원인 · 조치 · 부서 KPI · 규정 · 기업 시스템을 이어 주고, 에이전트는 그 지도를 따라 회사 전체에 이로운 조치를 제안한다. 사람이 권한에 따라 승인하면 설비와 기업 시스템에 실행된다.

레이어 L9 → L1, 그리고 각 레이어로 들어가는 문

v3 설계서의 기능 레이어 9개와 배치 영역(OT · DMZ · IT)을 그대로 옮겼다. 무거운 제품은 같은 이름·같은 메시지 계약을 지키는 작은 파이썬 서비스로 바꿨고, 가벼운 실제 제품(EMQX, FUXA, Redpanda, TimescaleDB, Grafana, Neo4j)은 그대로 쓴다. 점은 5초마다 확인하는 상태다.

이 프로토타입의 초점은 L7 ~ L9다. L1~L6은 경보가 나면 팬을 올리는 즉각 제어까지다. L7 온톨로지는 여기에 조직 · KPI · 규정 · ERP/MES/CMMS/QMS · 에이전트 스킬을 이어, L8 에이전트가 부서 간 상충을 전사 관점에서 판단하고 L9가 승인 권한에 따라 기업 시스템에서 실행하게 한다. 왼쪽 아래 지식 · 판단 · 실행 메뉴에서 따라가 보자.
OT 설비·실시간 운전 (ot-net)DMZ 유일한 통로 (ot-net + it-net)IT 장부·분석·지식·프로세스 (it-net)괄호 안은 원래 아키텍처의 제품 이름

강의 순서 (Compose 프로필)

M1 ot → M2 backbone → M3 detect → M4 monitor → M5 knowledge → M6 agent → M7 process. docker compose --profile ot up처럼 필요한 단계만 띄울 수 있다. 시나리오는 결함 시나리오 시뮬레이션에서, 결과는 이상 확인 & 조치와 실시간 설비 모니터링에서 본다.

온톨로지 지식 지도 (L7)

왼쪽 세 열(설비·관측, 고장, 조치)은 "무엇이 고장났고 무엇을 하면 되는가"를 담는다. 오른쪽 세 열(조직·KPI·규정, 시스템·스킬·프로세스, 판단·사례)은 "그 조치가 회사의 누구에게 어떤 이익과 손해인가, 필요한 정보는 어느 시스템에 있는가, 누가 승인하는가"를 담는다. 에이전트는 이 지도를 따라 판단한다.

매뉴얼 업로드 → SOP 인제스천

정비 매뉴얼(.md · .txt · .pdf)을 올리면 절 제목(예: HM-8.1 쿨러 팬 벨트 점검)은 매뉴얼 절로, 번호 매긴 줄(1. …)은 SOP 단계로 읽는다. 미리보기에서 확인하고 조치와 연결한 뒤 적재한다. 예시 매뉴얼 받기

버튼을 누르면 템플릿 원문이 나온다. Neo4j Browser(7474)에 붙여 넣어 직접 실행해 볼 수 있다.

에이전트 스킬 카탈로그 (L8)

에이전트가 판단한 뒤 실행을 제안할 수 있는 업무 단위다. 스킬마다 실행 시스템, 업무 프로세스, 승인 역할, 거는 규정, 필요한 정보가 온톨로지 관계로 연결돼 있다. 이름 · 설명 · 상세와 연결을 여기서 고치면 다음 판단부터 반영된다. 에이전트는 스킬을 직접 실행하지 않는다.

전사 의사결정 시나리오 (L8)

같은 설비 이상이라도 생산 · 보전 · 구매 · 품질 · 영업 · 에너지 부서마다 최선의 답이 다르다. 에이전트는 온톨로지에서 대안과 KPI 산식, 규정, 필요한 정보의 위치를 꺼내 ERP · MES · CMMS · QMS · SCM · EMS를 조회하고, 부서 관점과 전사 관점의 1위를 따로 계산한다. LLM 없이 같은 입력이면 항상 같은 답이 나온다.

업무 프로세스 · 시스템 연계 (L9)

에이전트가 제출한 판단을 사람이 승인한다. 승인할 수 있는 역할은 온톨로지가 정한다. 승인되면 프로세스 엔진이 대안의 스킬을 ERP · MES · CMMS · QMS · EMS에 실행하고, 설비 즉시 제어만은 기존 HITL 경로(action.cmd → cmd-gateway)로 남긴다.

설비 3기의 현재 값과 PLC 상태. "쿨러 열화 주입"을 누르면 유온이 오르고, SCADA에 알람이 뜨고, 탐지기가 경보를 내고, 에이전트가 가이드를 만든다. 승인은 이상 확인 & 조치 탭에서 설비를 눌러 한다.

이상 확인 & 조치

설비 3기의 흐름도와 실측값이다. 경보가 붙은 설비를 누르면 아래에 그 설비의 프로세스(에이전트 트레이스 → 가이드 카드 → 승인 → PLC ACK → 재관측 → 종결)가 나타난다. 승인된 조치만 action.cmd로 나가고, 게이트웨이와 PLC 검증을 거쳐 실행된다.
