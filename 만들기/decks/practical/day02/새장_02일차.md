## SLIDE [N5] — 결정표가 가리는 것과 SOP가 정하는 것
### 화면 내용
- 유형: 흐름
- 아이콘: list-details, table, checks, list-numbers
- 메시지: 결정표는 후보에 남을 조치를 가릴 뿐이고, 남은 조치의 수행 단계와 승인 역할과 완료 확인 기준은 **SOP**가 정한다.
- 요소:
  1. 조치 후보 넷 | 쿨러 냉각 성능 상실에 / 매뉴얼이 정해 둔 / 네 가지 조치
  2. **결정표의 판정** | plc_mode != REMOTE_AUTO / → 제외 / fan100_hours > 24 / → 감점 / forecast_ts1 >= 55 / → 경고
  3. 남은 후보 | 예: SOP-COOL-11 / 팬 최대 운전 / 운전 모드가 / REMOTE_AUTO이면 / 후보에 남는다
  4. SOP의 수행 | 단계: 확인, 수행, 판정 / 제한: 100 % 연속 운전은 / 24시간 이내 / 승인: 운전원 / 완료: 15분 동안 / TS1이 55 ℃ 미만
- 노트: 절차와 규칙이 맡는 일을 조치 한 건의 흐름으로 잇습니다. 네 후보에 지금의 값을 대면 결정표가 제외와 감점과 경고를 내고, 여러 행이 함께 맞으면 그 출력이 모두 붙습니다. 운전 모드가 원격 자동이면 팬 최대 운전은 후보에 남고, 남은 조치를 어떤 단계로 하고 누가 승인하며 무엇으로 끝났다고 보는지는 SOP가 정합니다. 결정표의 행에는 순서도 승인 역할도 완료 확인 기준도 적히지 않으므로 규칙이 절차를 대신하지 못합니다.
### 제작 기준
실전반 2일차 실라버스의 「SOP와 DMN 비교」「절차를 모두 규칙으로 대체할 수 없음」. 가져온 「SOP와 DMN의 차이」 장의 결론을 조치 한 건의 흐름으로 이었다. 새 사실 없음. 세 규칙의 조건과 출력: 사실표 3.2(「세 판정을 내는 실제 규칙」 장과 같은 값). SOP-COOL-11의 단계 · 연속 운전 제한 · 승인 역할, HM-8.6의 완료 확인 기준: 사실표 3.1(「SOP 원문 한 편」「수행 단계 · 담당 역할 · 완료 확인 기준 · 금지 사항의 원문」 장과 같은 값).

## SLIDE [N7] — 실습에서 만드는 것과 완성되는 것
### 화면 내용
- 유형: 흐름
- 아이콘: search, gauge, table, ban
- 메시지: 작업 기준의 조건은 조치의 허용과 제외를 가르는 결정표의 행이 되고, 겹친 행에는 제외 사유가 남는다.
- 요소:
  1. 조건 찾기 | 제공된 작업 기준에서 / 온도, 압력, 설비 상태의 / 허용 기준과 / 금지 기준을 찾는다
  2. 입력 정하기 | 조건마다 / 무엇을 보는지를 / 입력으로 정한다
  3. 행으로 옮기기 | 입력, 연산자, 기준값의 / 조건에 출력을 붙인다 / 허용: 후보에 남는다 / 제외: 후보에서 뺀다
  4. **겹침 기록** | 임계값 조건과 금지 조건의 / 행이 함께 맞으면 / 제외로 두고 맞은 조건을 / 제외 사유로 적는다
- 노트: 제공된 작업 기준을 읽고 온도, 압력, 설비 상태에 걸린 허용 기준과 금지 기준을 찾는 데서 시작합니다. 조건마다 무엇을 보는지를 입력으로 정하고, 입력과 연산자와 기준값으로 된 조건에 출력을 붙여 한 행으로 적으며, 허용은 제외되지 않고 후보에 남는다는 뜻입니다. 앞에서 본 것처럼 여러 행이 함께 맞을 수 있으므로, 임계값 조건과 금지 조건이 함께 맞는 경우에는 제외로 두고 맞은 조건을 제외 사유로 적습니다. 결과가 예상과 다르면 연산자가 「넘는다」인지 「이상」인지와 경계값을 먼저 확인합니다.
### 제작 기준
실전반 2일차 실라버스의 실습 「제공된 작업 기준으로 조치 허용 · 제외 조건표 만들기」(제공 SOP 조건에서 온도 · 압력 · 설비 상태의 허용/금지 기준을 찾아 DMN 형식 표를 만든다, 임계값과 금지 조건이 중첩될 때 제외 사유를 기록한다). 제작기준 9절: 간지 + 설명 한 장, 절차 · 메뉴 이름 · 화면 캡처 없음. 제공 자료의 내용은 확인하지 못했으므로 대상 이름과 값을 적지 않았다.

- 머리: 용어 | 한 줄 뜻 | 영문

  4. 스키마 | 클래스, 속성, 관계, 제약의 정의 | Schema

  8. DMN | 업무의 의사결정을 정의하는 표기 표준 | Decision Model and Notation
  9. 임계값 | 판정이 갈리는 기준값 | Threshold
- 노트: 오늘 새로 쓴 용어입니다. 위의 다섯은 지식을 정의하는 말이고, 레이블은 그래프 DB의 말이며, 아래 셋은 조치 기준을 적는 말입니다. 이 아홉 개와 함께 속성, 제약, 별칭, 질의, 운전 모드, 결정표, 입력 데이터, 규칙, 판정이 오늘의 용어입니다. 하나를 골라 자료를 덮고 자신의 문장으로 적어 봅니다.
### 제작 기준
제목은 제작기준 4절의 고정 문구. 통합반 2일차와 3일차의 용어 정리 장에서 행을 가져왔다(한 줄 뜻은 그 장과 본문의 정의 장에 쓴 문구). 표의 한도가 아홉 행이어서 속성 · 제약 · 별칭 · 질의 · 운전 모드 · 결정표 · 입력 데이터 · 규칙 · 판정은 노트에 두었다.
