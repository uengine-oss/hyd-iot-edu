## SLIDE [N5] — 실습에서 추가하는 것과 완성되는 것
### 화면 내용
- 유형: 단계
- 아이콘: circle-plus, link, git-compare
- 메시지: 스키마를 고치지 않고 새 설비의 인스턴스만 더해도 공용 부품과 복수 센서의 관계가 같은 질의로 조회된다.
- 요소:
  1. 인스턴스를 더한다 | 기존 스키마는 그대로 두고 / 새 설비의 인스턴스와 / 식별자를 만든다
  2. 관계를 잇는다 | 두 설비가 함께 쓰는 부품과 / 한 구성 요소를 재는 여러 센서를 / 관계로 잇는다
  3. **결과를 견준다** | 같은 질의를 새 설비와 / 기존 설비에 실행해 / 결과를 나란히 본다
- 노트: 설비가 새로 생겼을 때 더하는 것은 클래스가 아니라 인스턴스입니다. 부품을 함께 쓰면 부품 인스턴스 하나에 두 설비 쪽의 관계가 모이고, 센서가 여럿이면 센서마다 인스턴스와 관계가 생깁니다. 같은 질의를 두 설비에 실행해 결과가 같은 모양으로 나오는지 견줍니다. 스키마를 다시 만들지 않았는데도 질의가 그대로 통하는지가 확인할 점입니다.
### 제작 기준
오프라인 실라버스 02회차 실습 3행(기존 스키마 유지, 새 설비 인스턴스 추가, 공용 부품 · 복수 센서의 관계 표현, 질의 결과 비교). 실라버스의 「대형 신규 온톨로지를 다시 만들지 않는다」는 범위 단서여서 「스키마는 그대로 둔다」로만 적었다. 부품은 구성 요소에 USES_PART로, 센서는 구성 요소에 MONITORED_BY로 이어진다: 사실표 2.3 · 2.4. 설비와 부품의 이름은 실습 자료가 정하므로 화면에 적지 않았다.

## SLIDE [N7] — Quiz 3. 이름을 고쳐 다시 넣는 문장
### 화면 내용
- 유형: 문답
- 메시지: 식별자가 sen:ts1이고 이름이 「유온 센서」인 노드가 이미 있으며, 이름을 「온도 센서」로 고쳐 다시 넣으려 한다.
- 문장: 있던 노드를 찾아 이름만 고치는 문장은?
- 요소:
  1. CREATE (s:Sensor {id: 'sen:ts1', name: '온도 센서'})
  2. MERGE (s:Sensor {id: 'sen:ts1', name: '온도 센서'})
  3. CREATE (s:Sensor {id: 'sen:ts1'}) SET s.name = '온도 센서'
  4. MERGE (s:Sensor {id: 'sen:ts1'}) SET s.name = '온도 센서'
- 노트: 무엇을 같은 노드로 볼지를 괄호 안에 적은 것이 정한다는 점을 확인하는 문항입니다. 보기마다 먼저 찾아보는 문장인지, 찾을 때 무엇을 기준으로 삼는지를 따져 보시기 바랍니다.
### 제작 기준
식별자 `sen:ts1`, 레이블 `Sensor`: 사실표 2.3. 본문의 「CREATE와 MERGE: 새로 만들기와 찾아서 만들기」 장으로 풀린다(MERGE의 괄호 안에는 식별자만 적는다, 이름까지 넣으면 이름을 고쳐 다시 실행했을 때 같은 노드를 찾지 못한다). 이름을 「온도 센서」로 고치는 예는 「식별자와 이름」 장의 노트와 같다. 통합반 2일차 퀴즈에 MERGE를 묻는 문항이 없어 새로 썼다.
