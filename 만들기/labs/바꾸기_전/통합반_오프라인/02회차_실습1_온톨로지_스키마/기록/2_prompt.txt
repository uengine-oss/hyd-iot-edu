물어본 것을 이렇게 정할게.

1. 답하려는 질문은 현장 메모 6절의 다섯 가지 전부야. 그래서 공급 조건도 담는다.
2. 공급사는 Supplier 클래스로 둔다. 단가, 불량률, 납기는 부품과 공급사의 짝마다 다르니 SUPPLIED_BY 관계의 속성으로 두고, 승인 여부는 Supplier 의 속성으로 둔다. 방향은 Part 에서 Supplier 로 한다.
3. price, fail_rate, lead_days 는 number 로 하고 자료의 수를 그대로 옮긴다(단가는 만원 단위 그대로). approved 는 boolean 으로 하고 '예'는 true, '아니오'는 false 로 옮긴다. 넷 다 필수다.
4. 공급사의 name 은 자료에 적힌 그대로 둔다. 식별자는 sup: 뒤에 이름 맨 앞의 영문자를 소문자로 적는다(sup:a, sup:b, sup:c).
5. Asset 에 code 를 필수 string 으로 더한다. 설비의 구분은 담지 않는다. 한계의 방향은 StateVariable 에 limit_direction 을 enum(upper, lower)으로 더하고, 한계가 있는 상태 변수에만 적는다.
6. 중복 처리는 지난 시간의 규칙을 그대로 따른다. 새 자료에 처음 나온 표기 '주 펌프 A', 'A 펌프', '작동유 온도'는 노드를 새로 만들지 않고 같은 노드의 aliases 에 더한다. 태그는 aliases 에 넣지 않는다. 'TS1 오일 온도' 줄은 한 번 더 적힌 줄로 보고 버린다. '130 bar', 'L/min', 빈 단위 칸처럼 다르게 적힌 값은 이미 들어 있는 값을 따른다. 공급사는 이름이 같으면 노드 하나다. 작성자와 비고는 담지 않는다.
7. cardinality 는 이미 있는 관계 열한 개와 새 관계에 모두 채운다. 값은 graph.json 에 실제로 이어진 모양을 근거로 네가 제안하고 까닭을 표로 말해 줘.
