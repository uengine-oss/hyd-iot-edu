한 번에 한 단계씩 AI와 구현하기

  1. VS Code 채팅을 열고 현재 작업 공간이 시작코드인지 확인합니다. README, 기록 발췌, 수정할 함수를 필요한 범위만 첨부합니다. 완성본을 첨부하지 않습니다.
  2. 먼저 코드 작성을 보류하고 자료 구조와 비교할 필드를 질문합니다. 강사가 작업지시의 decision_id와 판단의 id를 직접 찾아 자신의 답을 입력합니다.
  3. 빈 값·다른 값·같은 값의 규칙을 말로 정합니다. AI의 질문에 강사가 답하고, 이 규칙이 맞는지 확인한 뒤 함수 하나만 요청합니다.
  4. 변경 비교 화면에서 check_link만 바뀌었는지, 빈 값을 먼저 검사하는지, 반환 키가 호출부와 맞는지 봅니다. 입력 자료나 테스트를 바꿔 통과시키려는 변경은 적용하지 않습니다.
  5. 저장하고 새 터미널을 엽니다. 현재 경로가 시작코드인지 확인한 뒤 python trace_records.py를 입력합니다. 명령 자체가 실패하면 오류를 읽고, 결과가 예상과 다르면 해당 조건부터 다시 확인합니다.
  6. 가림 자료와 테스트 결과를 비교합니다. 오류가 있을 때만 실제 오류와 해당 함수로 다음 요청을 좁힙니다. 오류가 없는데 실패한 장면을 꾸미지 않습니다.
첫 대화 · 아직 코드 없이 자료부터 이해하기

첨부한 README와 case_a.json으로 작업지시에서 판단을 찾아가려 합니다. 아직 파일을 수정하지 마세요. 제가 어느 두 필드를 비교해야 한다고 생각하는지 한 가지 질문부터 해 주세요. 제 답을 들은 다음 두 필드의 의미를 확인해 주세요.

강사의 답 · 판단 근거를 먼저 정하기

work_order.decision_id와 decision.id를 비교하겠습니다. 같은 설비라는 이유만으로 연결하지 않겠습니다. 값이 없으면 미확인, 둘 다 있고 다르면 실패, 둘 다 있고 같으면 확인으로 정하고 싶습니다. 빈 문자열 두 개가 같은 경우에도 미확인이 되어야 합니다. 이 기준에서 빠진 조건이 있는지만 먼저 검토해 주세요.

부분 구현 · 함수 하나만 요청하기

지금 정한 기준으로 trace_records.py의 check_link 함수만 구현해 주세요. 함수 설명의 반환 키를 유지하고 호출부, recorded 자료, 테스트는 수정하지 마세요. 변경 이유를 조건별로 설명하고 제가 검토할 수 있게 해 주세요.

AI 답은 정해진 대사로 만들지 않습니다. 실제 응답을 읽고 입력 자료·조건·반환 형식과 맞는지 판단합니다. 접속할 수 없다면 완성본 비교 경로로 전환했다는 사실을 밝히고, AI가 답한 것처럼 말하지 않습니다.
