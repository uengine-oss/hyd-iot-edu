# 실전반 2회차 실습 2 — 기준 설비 지식의 실제 연결 구조 확인하기 · 구성안

> 제작 문서(낭독하지 않음). 이 구성안을 사용자에게 보여 확인받은 뒤 대본 전문 → 녹음 → 촬영 순서로 간다. 이전 판(9:13, 2026-10-28)은 실라버스 대조 · 이론 발화 기준 미적용으로 폐기.

## 1. 실라버스와 시간

- 행: 실습 「기준 설비 지식의 실제 연결 구조 확인하기」 · **배정 10분 → 목표 10분, 최저 8분(C71)**
- 상세 원문: 포털 지식 지도에서 설비·구성 요소·부품·문서의 연결을 펼치고 노드의 ID·속성과 관계 방향을 확인한다. 한 부품을 사용하는 설비를 찾고, 연결이 있다는 사실과 실제 재고·공급 조건이 확보됐다는 판단을 구분한다. 이어지는 로컬 랩에서는 제공 공급 자료로 답할 질문을 정한다.
- 앞: 이론 클래스·인스턴스(25) · 스키마(20) · 그래프 DB(15), 실습 Cypher(15). 뒤: 실습 「설비·부품·공급 정보를 연결하는 온톨로지 설계하기」(40).

## 2. 앞 이론에서 받아 올 것 (실전 2회차 이론 대본 기준)

| 이론 | 이 실습에서 화면으로 확인할 것 |
|---|---|
| 9장 설비 · 구성 요소 · 부품, 14장 경보에서 교체품까지 길 잇기 | 부품에서 거꾸로 구성 요소 → 설비로 올라가는 길 |
| 11장 관계 유형: 이름 · 방향 · 양 끝 클래스 | 나가는 관계 / 들어오는 관계의 화살표 방향과 양 끝 대상의 종류 |
| 18장 공통 노드 하나로 둘까, 설비마다 나눌까 | 설비를 바꿔도 같은 구성 요소 · 부품 노드가 이어지는가 → 이 지도는 어느 설계를 택했나 |
| 19 · 20장 공급 관계에 딸린 값 vs 공급사에 딸린 값 | 공급사 노드에는 승인 여부가 보이고, 단가 · 납기 · 불량률은 지도에 없다 |
| 21장 판단 문제(비승인 공급사의 가격 인하) | 승인되지 않은 공급사를 지도에서 확인하고 「연결 ≠ 살 수 있음」으로 잇기 |
| 24장 식별자 · 이름 · 별칭 | 화면의 이름과 부품 번호(식별자)를 구별해 읽기 |

|---|---|---|---|---|
| 지식 지도 열기 · 설비 선택 | 2 | 앞 실습의 예제 그래프와 다른, 강사가 준비한 기준 지식이라는 점(두 환경은 서로 반영되지 않음). 지도의 칸이 클래스별 묶음이라는 점 | 왼쪽 메뉴 지식 묶음 → 지식 지도, 설비 HYD-01, 보기 칩 | 기록에 주소 · 확인 시각 · 설비 |

| 관계 방향 | 2~3 | 나가는 관계는 이 부품에서 출발, 들어오는 관계는 다른 대상에서 이 부품으로 — 양 끝 클래스를 함께 읽어야 뜻이 정해진다(이론 11장) | 상세의 나가는 · 들어오는 관계 | 시작 → 관계 → 끝 그대로 |
| 한 부품을 사용하는 설비 찾기 | 3 | 부품 → 이 부품을 교체 부품으로 가진 구성 요소 → 그 구성 요소를 가진 설비로 거꾸로 올라간다(이론 14장의 반대 방향) | 들어오는 관계의 구성 요소(주 펌프 A) → 그 상세의 들어오는 관계(설비) | 설비 → 구성 요소 → 부품 경로 |
| 설비를 바꿔 같은 부품 확인 | 3 | HYD-02 · 03으로 바꿔도 같은 구성 요소 · 부품 노드가 이어진다 → 이 지도는 「공통 노드 하나」 설계(이론 18장). 그래서 세 설비가 같은 부품을 쓴다는 답은 쉽지만, 설비별 교체 이력은 이 노드에 달 수 없다 | 설비 칸 HYD-02 · 03 | 설비별 경로 · 공통 노드 여부 |
| 문서의 연결 | 3 | 부품에 어떤 문서 · 조치 방법이 이어져 있는지, 그 연결이 무엇을 알려 주고 무엇은 알려 주지 않는지 | **확인 필요(포털 탐색)** — 부품의 들어오는 관계에 조치 방법이 보였음(발주 조치 4개). 문서 노드가 직접 이어지는지는 녹화 전 확인 | 문서 · 조치 방법 연결 |
| 연결 사실 vs 재고 · 공급 조건 확보 | 4 | 공급사 셋과 승인 여부는 보이지만 단가 · 납기 · 불량률 · 재고는 지도에 없다. 이론 19장대로 이 값은 공급 관계에 붙어야 하는데 지금 지도에는 없다 → 「공급 연결이 있다」와 「지금 살 수 있다」는 다른 판단. 승인되지 않은 공급사는 연결이 있어도 후보가 아니다(이론 21장) | 부품의 공급사 노드 셋을 차례로 눌러 승인 여부 | 공급사별 승인 여부, 지도에 없는 값 |
| 다음 로컬 랩에서 답할 질문 정하기 | 5 | 지도에 없는 값을 다음 실습의 공급 자료로 답하게 질문을 만든다 — 질문이 다음 설계의 출발점(이론 스키마 35장 「역량 질문」) | VS Code 기록 | 질문 2~3개 |

## 5. 낭독 표기(기준_대본 S3)

- 부품 번호 문자열(P-PMP-SEAL), 속성 키(partNo · avl · aliases), 관계 영문명은 읽지 않는다 → 「부품 번호」, 「승인 공급사 여부」, 「별칭」처럼 뜻으로 말하고 철자는 화면에 맡긴다.
- 「랩 그래프」 같은 제작 용어 금지 → 「앞 실습에서 만든 예제 그래프」.
- 수치는 판단에 필요한 것만(이 실습은 공급 조건 값이 지도에 없다는 사실이 핵심이라 숫자 낭독이 거의 없다).
