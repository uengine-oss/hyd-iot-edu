## 1. 바로 가는 길 — 통과한 길(VS Code 웹(serve-web) + ego, 2026-10-28 로컬 Windows 실측)

공식 `code serve-web`(같은 워크벤치, 확장 호스트·터미널은 이 PC에서 실행)을 ego 탭으로 열어 기존 ego 촬영 리듬을 그대로 쓴다. 이 길로 0절의 다섯 편(구간 `p22-*` · `p31-*` · `p33-*` · `i22-*` · `i31-*`)을 찍었다. 근거 폴더는 3절.

### 1-1. 서버 켜기(PowerShell)

```powershell
$env:HOME=$env:USERPROFILE; $env:CODEX_HOME="$env:USERPROFILE\.codex"
code.cmd serve-web --host 127.0.0.1 --port 8790 --connection-token-file <절대경로>\token.txt --accept-server-license-terms --server-data-dir <근거>\data --disable-telemetry
```

토큰은 파일에서만 읽고 출력하지 않는다(토큰 파일 위치는 [config.json](촬영도구/config.json) `tokenFile`). Git Bash에서 띄우지 않는다(2절).

### 1-2. 확장 설치(처음 한 번)

```
~/.vscode/cli/serve-web/<commit>/bin/code-server.cmd --server-data-dir <data> --install-extension openai.chatgpt
```

한국어 팩도 같은 방식으로 설치되지만 웹판 표시 언어는 영어로 둔다(1-6).

### 1-3. 실습 폴더 열기 · 신뢰 · 탭 정리

1. 학생 동선과 같게 ZIP을 `D:/HYD-Practice/<id>-<uuid8>`에 풀고 serve-web 주소로 연다.
2. 주소: `http://127.0.0.1:8790/?tkn=<파일값>&folder=` + `encodeURIComponent('/D:/...')` (드라이브 앞 `/` 필수)
3. 신뢰: 상태 표시줄 Restricted Mode → 신뢰 창에서 실제 맨 위 요소인 `Trust` 텍스트를 좌표로 클릭. 신뢰는 `.statusbar-item`의 Restricted Mode로만 판정
4. 탭 정리: Welcome 닫기 = `.tab .tab-actions .action-label`. 미리보기 탭 고정은 dblclick 이벤트 발송(ego `mouse.dblclick` 없음).

### 1-4. Codex 준비

로그인 불필요(`~/.codex` 공유, 로그 `authenticatedAccountPresent=true authMethod=chatgpt`). 첫 안내 Next 4회. 「GPT-6.1 Sol」 홍보 창은 **Continue with current model**. 입력창 아래 `GPT-6 Luna Medium` 화면 확인. 한국어 `keyboard.type` 입력·Enter 전송 → 5초 응답 확인. 촬영 전 새 대화로 바꿔 사용자의 기존 Codex 대화 제목 목록이 화면에 나오지 않게 한다(V-79).

### 1-5. 터미널

편집기 클릭 → `Control+Backquote` → `keyboard.type` + Enter. `python --version` → `Python 3.14.7` 확인. 기본 셸은 PowerShell(Git Bash로 바꾸려면 프로필 설정).

### 1-6. 표시 언어와 화면 차이

웹판은 **영어로 둔다**(까닭은 2절). 대사는 「왼쪽 탐색기(Explorer)」처럼 위치와 두 이름을 함께 짚는다. 웹판과 네이티브의 화면 차이는 3절.

### 1-7. 포털 구간 시작 상태(실전 3-1)

제외 후보 만들기: 결함 시뮬레이션 HYD-01 운전 모드 「현장 제어」 → 원격 제어 카드 3개 rule:auto-mode 제외. 녹화·시험 뒤 반드시 「원격 자동」 복귀(`POST 127.0.0.1:8000/api/mode`로 확인). 조건별 손익은 Docker를 켠 직후 보류되니 몇 분 기다린다(2절).

### 1-8. 음성 만들기(녹화 전)

ElevenLabs만 쓴다. OpenAI 음성은 쓰지 않는다. 값(목소리 ID · 모델 · 설정)은 3절이고 [voice.py](촬영도구/voice.py)에 박혀 있다(도구 기본값을 바꾸지 않는다). 키는 `config.json`의 `keyFile`에서만 읽고 출력하지 않는다.

```bash
# Git Bash, 촬영도구/ 에서
PYTHONUTF8=1 python voice.py [<큐 파일, 촬영도구/ 기준>]   # 기본 voice-jobs.json. 같은 문장이 캐시에 있으면 다시 만들지 않는다
```

결과는 음성 캐시(`config.json` `audio`)의 `<큐id>.mp3` · `<큐id>.json`(text, duration_ms). 녹화의 `ctx.say(큐id)`는 이 캐시를 읽으므로 음성이 없으면 「Voice cue missing (생성 후 촬영)」으로 멈춘다 — 음성을 먼저 만든다. 이 폴더의 큐 파일(`*_큐.json`)은 `id` · `segment` · `text` 꼴이다. 촬영 전 길이 예상은 `python ../../시간계산.py estimate <큐 파일>`.

### 1-9. 찍기(구간 하나씩)

녹화 도구: `제작용/촬영/vscode/촬영도구/` — Notion 촬영도구(`ctrl.mjs`·`run.sh`·`chain.sh`·`voice.py`·`encode.py`·`measure.py`·`common.py`)를 복사해 Notion 전용 검사(업데이트 막대·검수 음성·restore)만 뺐다. `ui.mjs`는 v10 포인터·이동·gate를 그대로 옮기고 VS Code 조작(`clickSel`·`explorer`·`tab`·`codexInput`·`type`·`key`·`terminalOpen`)을 더했다. Codex 채팅은 웹뷰 iframe이라 `.part.auxiliarybar` 영역 비율 좌표로 누른다. 구간 모듈은 `segs/<이름>.mjs`(ctx를 받아 `vscode(ctx)`로 조작 층을 만들고 `ctx.say(큐id, 조작)`). 실전 2-2에서 `ui.mjs`에 `menuItem`(그림자 루트 포함 문맥 메뉴)·`explorerRow(이름, aria-level)`·`lineEnd`·`typeFast`·`scrollTo`·`selectValue`를 더했다.

```bash
# Git Bash, 촬영도구/ 에서 (run.sh 머리말 그대로)
./run.sh rec <이름> <구간 파일(segs/ 기준)> [앞 구간 이름 | '{x:..,y:..}']        # 구간 하나 녹화 → 실측. 앞 구간 끝 포인터에서 시작
SPACE=<ego 작업 공간> VP='{width:1536,height:864,dsf:1.5}' ./run.sh rec …       # VS Code 밖 화면(포털). 앞 구간 URL로 되돌아가지 않는다
./run.sh measure <이름>                                                        # 녹화 하나 다시 실측
```

- ego: 설치된 `ego-browser skill` 출력도 끝까지 읽는다(API는 설치 버전이 우선). ego lite 설치 · 로그인은 사용자가 한다.
- `run.sh`가 하는 일: `ctrl.mjs` · `ui.mjs` · `segs/*.mjs`를 `node --check`(ego는 문법 오류에 조용히 멈춘다), 다른 `ego-browser.exe`가 떠 있으면 시작하지 않음, 실행 스크립트를 UTF-8 `.mjs`로 쓰고 `ego-browser nodejs -e "await import('file:///<절대경로>.mjs')"`를 `< /dev/null`로 부름(같은 주소는 다시 실행되지 않아 실행마다 새 파일), 시간 초과(`TMO`초, 기본 900)면 ego NodeService만 정리, 끝나면 `measure.py`.
- 작업 공간: VS Code 구간과 포털 구간을 서로 다른 ego 공간에서 찍는다(이름은 3절). `SPACE`가 있으면 resumeUrl 생략. 같은 작업은 같은 공간을 쓰고, 다른 세션과 같은 공간 · 페이지를 동시에 조작하지 않는다. 사용자 마우스 · 키보드 · 전경 창은 쓰지 않는다.
- 캡처: 녹화는 `Page.startScreencast`로 프레임을 받는 즉시 저장 · ACK하며, 앞에 보이는 탭에서만 프레임이 온다 — ego 창은 최소화하지 말고, 그 창 안에서 작업 탭이 앞 탭이어야 캡처된다. 해상도는 녹화마다 `Emulation.setDeviceMetricsOverride`를 `config.json` `viewport`(포털 구간은 `VP`)로 설정한다(값 3절).
- 부하 문: 화상회의(Zoom · Teams)가 돌면 `run.sh`가 멈춤. 남은 메모리 3 GB 미만은 경고만 하고 `measure.py`의 프레임 간격(최대 0.8초 이하)으로 판정. 수치만으로 중단하지 않고 실제 반응 · 프레임 간격으로 본다.
- 진행 리듬(`ctrl.mjs` · `ui.mjs`): 모든 ego 호출은 하나의 직렬 큐로 보낸다. 표시 포인터는 페이지에 그린 SVG 화살표를 `element.animate`로 움직이고, 실제 입력은 같은 경로를 단계별 `mouse.move`로 보내며, 실제 입력이 다 끝날 때까지 화살표를 목표에 고정한다. 위치가 바뀌는 대상은 150ms 간격 두 번 같은 위치일 때 출발한다. 조작은 행동 문장이 끝나기 약 250ms 전에 실행하고 다음 음성은 행동 종료 + 250ms에 시작한다. 녹화 시작 전에 조작 큐가 돌면 즉시 실패시키고, 긴 이동 · 긴 문자열 입력을 큐 한 항목에 넣지 않는다.
- 클릭 시점: `ctx.say(id, fn, {at:'대사 속 구절'})` — 그 구절 끝에 첫 클릭(ctrl.mjs). 여러 조작 중 첫 동작이 앞 문장에 있을 때 쓴다. 두 동작이 다른 문장에 있으면 큐를 나눈다(p31-21 / p31-21b).
- 포털 구간의 「화면 안」 판정·굴릴 자리는 본문 실제 높이 비율로(`segs/p31-common.mjs` `p.show`). 프로그램 굴리기라 화살표를 옮기지 않는다.
- 사용자가 ego 공간을 잡으면 「Control of this task space is with the user」로 멈춘다. 우회하지 않고 사용자 「계속」 뒤 `takeOverTaskSpace`. 사용자가 직접 배치 · 입력할 때는 녹화를 멈추고 `task.handOff()`로 넘긴 뒤 `takeOverTaskSpace(<번호>)`로 되찾고, 그 결과는 화면 캡처가 아니라 앱 저장 데이터(VS Code는 실습 폴더의 파일)로 읽는다.
- 구간 기록: 구간마다 시작 상태 확인 → 녹화 → 끝 상태(`end-state.json`) · 프레임 · 행동 시각(`timing.json`)이 `config.json` `work` 아래 `<이름>/`에 저장된다. 한 구간씩 찍고 바로 실측한다(이동별 최대 프레임 공백, 클릭 좌표 오차, 문장보다 늦은 조작, 마지막 프레임 — `measure.py`).
- take는 매번 새 이름으로 보존하고(예: `p22-2` 뒤 다시 찍은 `p22-2b`), 실패 · 잘못된 상태 take는 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.

### 1-10. 합성

ffmpeg는 PATH에 없다. 시스템 Python의 `imageio_ffmpeg`가 가진 `ffmpeg-win-x86_64-v7.1.exe`를 `FFMPEG`로 준다.

```bash
# Git Bash, 촬영도구/ 에서
FFMPEG="$(python -c 'import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())')" PYTHONUTF8=1 python encode.py <출력이름> <구간[:여기까지 쓸 ms]> ...
```

결과는 `config.json` `work` 아래 `<출력이름>_안치윤_1080p.mp4`(30 fps, libx264 crf 18, AAC 160k)와 `verification.json`(구간 · 큐 시각 · 클릭 오차 · 이동 프레임 공백). 문장 겹침 · 음성 교체 길이 초과면 멈춘다(V요-32).

### 1-11. 검사

포털 촬영도구 [verify.py](../포털/촬영도구/verify.py)(ffprobe 없이 ffmpeg로 길이)·[scenes.py](../포털/촬영도구/scenes.py)(3초 간격)를 시스템 Python(PIL 있음)으로.

```bash
python ../../포털/촬영도구/verify.py <영상.mp4> <자막.srt> [<결과 폴더>]
python ../../포털/촬영도구/scenes.py <영상.mp4> 3 [<결과 폴더>]
```

`verify.py`가 만든 문장별 장면 그림과 `scenes.py` 모음 그림을 끝까지 눈으로 본다.

### 1-12. 게시(other-pc · 노션)

- 커밋 전 `git fetch origin other-pc && git merge origin/other-pc`. 여러 세션이 같은 폴더를 쓰면 브랜치를 바꾸지 말고 임시 인덱스로 커밋을 만든다(`GIT_INDEX_FILE` → `read-tree` → `commit-tree` → push). 영상 한 편은 100 MiB 아래.
- 노션 학습 포털의 두 과정 회차 페이지 「🎬 강의 영상」 탭에는 그 커밋에 고정한 링크 세 가지(영상 열기 · MP4 내려받기 · 페이지 안 재생 토글)를 다른 영상과 같은 모양으로 넣고 다시 열어 확인한다. Notion 파일 업로드는 한 번에 20 MiB라 영상은 링크로 건다. 유튜브는 쓰지 않는다.

### 1-13. 가이드 사진(영상 밖)

학생 가이드 사진은 같은 결과 파일을 네이티브 한국어 VS Code에서 computer use(보기·클릭)로 캡처한다. ego 웹 화면의 성공을 네이티브 VS Code 촬영 성공으로 대신하지 않는다.

## 4. 아직 안 뚫린 길

### 4-1. Codex가 일하는 랩의 촬영 방식(계획, 실전 2-3에서 처음 시험 — 미검증)

구간을 「요청 보내기」와 「결과 확인」으로 나누는 규칙은 [영상](../../../문서/교재/영상.md) V요-13 · V-159 · V-218(결과를 미리 쓰지 않는 것은 V-57, 억지 실패 · 재시도 연출 금지는 V-154). 이 도구에서 처음 시험할 실행 세부:

1. 요청 구간: 요청 입력·전송 뒤 응답이 흐르기 시작하는 몇 초까지 녹화하고 구간을 닫는다.
2. 녹화 밖 대기: 편집 승인 창은 경로가 `결과/` 아래일 때만 Allow once.
3. 관찰: 끝난 응답·바뀐 파일·실행 출력을 DOM 글자와 파일로 읽어, 본 것만으로 「결과 확인」 구간 큐를 쓴다(결과의 뜻 → 원자료 대조 방법 → 다음 판단). 음성(1-8)은 이때 만든다.
4. 결과 확인 구간: 이미 화면에 있는 응답을 굴려 보며 짚고, 결과 파일·원자료를 열어 대조한다. Codex를 다시 부르지 않으니 녹화 중 응답이 바뀌지 않는다.
5. 구간 사이 이음매는 「잠시 기다리면」 같은 한 문장으로 잇는다. 응답이 예상과 다르면 그대로 다음 판단으로 이어 간다.

### 4-2. 코딩 랩 동선(촬영 전 확인)

촬영 전에 확인할 실제 동선: 시작 도구에서 과정/회차/실습 선택 → VS Code의 폴더와 START → AI가 작업 규칙/자료를 읽음 → 학생이 목표·제약·확인 사례를 작성 → 계획 검토 → 부분 구현/실행 → 원자료 대조/필요한 수정 → 저장/복사본 재열기.

### 4-3. 시작 도구 · 네이티브 장면

- 기본 앱으로 HTML 열기에서 한 번 응답이 멈췄다. 시작 도구에 10초 제한의 별도 프로세스와 수동 경로 안내를 추가했다. 실제 GUI 재확인은 남아 있다.
