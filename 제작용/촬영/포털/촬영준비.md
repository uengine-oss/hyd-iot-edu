## 1. 처음부터 다시 찍는 순서

명령은 `제작용/촬영/포털/촬영도구/`에서 돌린다. 한 단계가 실패하면 다음으로 넘어가지 않는다.

1. **스택 점검 · 복구** — `./stack.sh check`, 꺼진 것이 있으면 `./stack.sh up`. main을 새로 병합했으면 `./stack.sh up --build`(새 마이그레이션 적용 + 앱 이미지 다시 빌드, 데이터 유지). other-pc가 origin/main을 병합하지 않았으면 멈춘다 — `git fetch origin main other-pc && git merge origin/other-pc && git merge origin/main`(rebase · 강제 push 금지) 뒤 다시. 마지막 줄 「처리 건 0 · 보관 원문 0」이어야 처음부터 찍을 수 있다. 아니면 2단계.
2. **데이터 초기화(사용자 허락 필요)** — 매뉴얼을 적재하고 판단이 한 번이라도 돌면 적재 되돌리기가 거절된다(DIAGNOSED_AS 이력). 볼륨 3개 삭제 + 업무 DB 재설정이라 자동 승인이 막는다. 사용자에게 「데이터 볼륨 neo4j · detector · process 삭제와 Supabase db reset」을 실제 동작 이름으로 묻고 허락을 받은 뒤:
   ```bash
   kill <워커 PID>   # .evidence/…/worker.pid, 8097 응답 없어진 것 확인
   docker compose -p hyd-iot-edu stop && docker compose -p hyd-iot-edu rm -f neo4j detector process
   docker volume rm hyd-iot-edu_neo4j-data hyd-iot-edu_detector-data hyd-iot-edu_process-data
   (cd it/supabase && npx -y supabase@2.119.0 db reset)
   ./stack.sh up     # kg-seed 로그 「read-back: 16 checks, 0 failed」 확인
   ```
   녹화 브라우저의 「나」(localStorage `hyd.me`)는 포털 소개 구간 1이 지우고 실습3 구간 1은 최운전이어야 한다(구간 모듈이 확인).
3. **길뚫기(녹화 없이)** — 녹화할 화면을 먼저 본다. 상태를 바꾸지 않는 보기만 한다.
   - `node look.mjs <메뉴> [선택자 …]`: 다른 메뉴를 열어 한 화면씩 PNG로 저장하고 요소 글 · 위치를 출력한 뒤 원래 메뉴 · 스크롤로 되돌린다.
   - `node dry.mjs <segs 모듈> <구간>`: 큐의 point · scroll · wait · 메뉴 누르기를 실제로 하고 대상이 하나로 찾아지는지 본다. 되돌릴 수 없는 조작(아래)은 건너뛴다.
   - **되돌릴 수 없는 조작**: 매뉴얼 미리보기(원문이 서버에 보관됨) · 에이전트 추출 요청 · 결과 적재 · 결함 주입 · 승인 · 거절 · 「나」 바꾸기. 이것 뒤의 화면은 dry로 볼 수 없다 → 그 화면을 만드는 코드(`it/portal/www/*.js`)를 읽고, 서버 데이터는 API로 읽는다(예: 추출 결과 `GET /api/kg/manuals/sources/<id>/extractions/<실행>`, 처리 건 `GET :8080/api/instances`). 또는 그 조작 직후에서 구간을 끊고, 다음 구간을 쓰기 전에 그 화면을 look으로 본다.
4. **대본(큐 JSON)** — 형식 `{"cues":[{"id","segment","text","ops":[[조작, 대상, 시점 0~1, …]]}]}`. 조작: point · click · scroll(대상을 위에서 top px로) · select(대상, 값) · file(대상, 경로) · wait(대상이 나타날 때까지) · waittext(글이 나타날 때까지, 150초). 대상 이름 → 화면 요소는 구간 모듈의 표(`portal_tour.mjs` FIXED/target, `manual.mjs` MORE). 규칙:
   - 행동 문장 안에서 누른다(시점 0.6~0.9). 서버 응답 뒤 그려지는 결과는 다음 문장 첫 조작을 `wait`/`waittext`로 둔다.
   - **AI 판단 결과(추천안 이름 · 점수 · 순위)는 대본에 미리 쓰지 않는다** — 실행마다 그때 값으로 다시 계산된다(길뚫기 때 1등 팬 최대 운전 → 녹화 때 팬 최대 운전과 부하 80 %). 승인 구간 대사는 「추천안을 보고 승인」처럼 이름 없이 쓰고, 이름과 순위는 승인 뒤 구간에서 화면을 읽고 쓴다.
   - 시나리오 기호(A · B · C)는 말하지 않는다(화면 글자에는 보인다).
   - 길이는 `python3 ../../시간계산.py estimate <큐>`로 잰다.
5. **음성** — `ELEVENLABS_API_KEY="$(tr -d '\r\n ' < <키 파일>)" python3 voice.py <큐> [구간 …]`. 같은 글은 다시 사지 않는다. 키 파일은 사용자 업로드(`/root/.claude/uploads/<세션>/…-env.txt`), 값을 출력하지 않는다(`sed`로 들여다보지 않는다 — 2026-10-23 한 번 출력함).
6. **녹화** — `./run.sh up`(녹화 브라우저) → 구간 1 `./run.sh rec <이름> <모듈>` → 나머지 `./chain.sh <앞 이름> <이름:모듈> …`(실패하면 멈춤). 구간 모듈의 BEFORE(녹화 전 준비)가 기다릴 조건을 맞춘다: 구간 시작 화면 · 「나」 확인 · 승인 요청이 뜰 때까지 기다림. 기다리는 일(에이전트 추출 약 3분 · 판단 약 3~5분)은 구간 사이로 빼고, 끝난 것을 확인한 뒤 다음 구간을 찍는다. 녹화 중에는 무거운 작업을 돌리지 않는다.
7. **합성** — `python3 encode.py <이름> <구간…>`. 녹화 뒤 대사만 고쳐 음성을 다시 만든 문장(화면과 맞추는 정정)은 고친 음성의 글 · 길이로 자막을 쓰고, 구간 끝을 넘으면 실패한다.
8. **검증(게시 전 모두)** — 셋 다 하고 결과를 `.evidence/`에 남긴다.
   - `python3 verify.py <영상> <자막> <폴더>`: 길이 · 자막 겹침 · 무음 · 최고점 · 검은 화면, 문장마다 한 장면 그림.
   - `python3 scenes.py <영상> 2`: 끝까지 2~3초 간격 장면 그림을 **모두** 본다(튐 · 로딩 · 오류 창 · 엉뚱한 화면). 의심 구간은 0.5초 간격으로 다시 뽑는다.
   - `ELEVENLABS_API_KEY=… python3 listen.py <영상> <자막> <폴더>`: 소리를 받아써 자막과 대조(크레딧 사용). 「확인할 것」 목록은 매번 눈으로 본다 — 긴 문장 속 짧은 구절이 바뀌면 일치율이 0.9 언저리라 종료 코드로는 안 잡힌다. 남는 것 대부분은 다음 문장 첫 단어가 걸린 것과 영어 이름 표기 차이.
9. **여러 영상 잇기(필요할 때)** — `python3 join.py <출력.mp4> <조각1.mp4>:<조각1.srt> …`. 조각마다 소리 크기를 재서 −16 LUFS로 맞추고, 자막 시간을 밀어 합치고, 이음매 앞뒤 장면을 남긴다. 장(chapter)은 조각의 장을 밀어 옮기고, 장이 없는 조각은 `<조각.mp4>:<자막>:<장 이름>`으로 이름을 준다(자막이 없으면 `<조각.mp4>::<장 이름>`). 100 MiB가 넘으면 `CRF=20`으로 다시. 이은 뒤 8단계를 합본에 다시 한다.
   말 없는 구간(광고 알림 · 빈 화면)을 빼려면 `python3 cut.py <입력.mp4> <입력.srt> <출력.mp4> <시작초>-<끝초> …` — 자막 · 장을 당겨 맞추고, 자막이 걸치면 멈춘다. 자른 자리 앞뒤를 0.5초 간격으로 본다.
10. **게시** — 이름 `<과정>_<NN>회차_<대본 번호>_실습_<이름>.mp4`(대본 파일 이름과 같게, 두 과정 공통이면 같은 파일 두 벌), 자막은 `course/videos/_작업/영상_자막_기록/` 같은 이름, `course/videos/README.md` 표에 행. other-pc에만 커밋(경로 지정, 커밋 전 `git fetch origin other-pc && git merge origin/other-pc`). 올린 뒤 raw 링크가 200이고 크기가 같은지 확인.
11. **노션** — 회차 페이지를 fetch해 그 칸의 「⏳ 영상 준비 중」 블록을 다른 영상과 같은 모양(길이 · 실습 종류 · 한 문단 설명 · `[영상 열기](blob 링크) · [MP4 내려받기](raw 링크)` · 「페이지 안에서 재생」 토글 안 `<video source="raw 링크">`)으로 바꾼다(`update_content`, 통합반 · 실전반 두 페이지). 다시 fetch해 남은 「영상 준비 중」이 없는지 본다(검색 색인은 늦게 바뀐다).
12. **기록** — 이 문서 0절 표, `course/videos/README.md`, `문서/교재/3_현황.md` · `6_남은_일.md`.
