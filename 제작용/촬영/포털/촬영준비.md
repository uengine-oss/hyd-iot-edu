## 포털 함정과 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 화면 녹화 프레임이 1280×720 | 헤드리스 화면 녹화는 CSS 픽셀 크기로 보낸다(배율 1.5를 줘도) | 실행 플래그 `--force-device-scale-factor=1.5` + 문맥 배율 1.5 → 1920×1080, 글자 선명(browser.mjs) |
| 이동 중 프레임 공백 100~190ms(가끔 333ms)가 이동의 약 1/5 | 클라우드 4코어에서 1920×1080 소프트웨어 합성 · 화면 녹화가 스택(Supabase DB 약 25 %, process 약 13 % 등, 평균 부하 3.1)과 순간적으로 경쟁. 진단으로 배제: 페이지 긴 작업 0, 실제 입력 없이 애니메이션만 해도 같음, JPEG 품질 75 · 85 같음. 녹화 우선순위 올리기(renice −15)는 조금 나음, 코어 분리(컨테이너 0-1 · 브라우저 2-3)는 더 나빠져 되돌림 | 「커서 표시 보정」(안내 1절): `config.json` `pointer: overlay` — 페이지 화살표는 투명으로 두고 이동 기록(출발 · 도착 · 시작 시각 · 계획 길이)으로 합성 때 30fps마다 화살표를 그린다(`encode.py`). 실제 입력 · 클릭 · 화면 · 시각은 원본. 클릭 지점과 그린 화살표 끝 차이 1px 미만(test-click-3 실측). 화면 내용 자체의 멈춤(스크롤 등)은 이 보정으로 고칠 수 없다 — 보정판으로 구별해 적는다 |
| 휠 스크롤이 뚝뚝 끊김 | 헤드리스에서는 휠 한 번이 부드럽게 굴러가지 않고 그 거리만큼 바로 뛴다(120px씩 나누니 520px가 프레임 6장 · 공백 191ms) | 약 30px씩 30ms 간격, 처음과 끝은 작게(ui.mjs `wheel`) |
| 위 막대 「나 고르기」를 못 찾음 | 화면 안 판정이 위 70px 여백을 요구해 고정 막대 요소를 화면 밖으로 봄 | 화면 안 판정은 위 · 아래 8px 여백만 본다(ui.mjs `inView`) |
| 「나 고르기」를 누르면 화면이 「내 작업함」으로 바뀜 | 포털 동작(역할 고르기가 작업함에 있음) | 대사에서 「작업함으로 넘어가 역할을 고르는」 흐름으로 안내 |
| 다른 사이트(GitHub)로 옮기면 화면이 800×600 | 상주 브라우저의 화면 크기 설정이 사이트가 바뀌며 풀린다 | 녹화마다 그 세션에서 `Emulation.setDeviceMetricsOverride`(1280×720 × 1.5)를 다시 건다(ctrl.mjs). 탐색 스크립트도 먼저 건다 |
