## 다시 찍거나 이어 찍는 법

1. ego 공간 1(`arrows recording test 20261022`)의 p1 탭. 녹화 설정은 `Emulation.setDeviceMetricsOverride` 2304×1296(브라우저 150% 확대 → CSS 1536×864, 프레임 1920×1080). 제어기가 매번 설정한다.
2. 큐 수정 → `python build_ontology.py cues .evidence/arrows-ontology-20261023/cues.json` → `python voice.py <구간>`(바뀐 문장만 생성) → `TMO=초 ./rec.sh <이름> <구간> [시작큐] [이전 구간 이름]` → `python measure.py <이름>` → `python encode.py <출력> <조각[:자를ms]> …`. 녹음 뒤 큐 문장이 바뀌면 encode가 멈춘다.
3. 실패하면 그 조각의 원본을 보존하고, 실패한 큐 시작에서 잘라 같은 상태로 이어 찍는다. 상태가 바뀌었으면 녹화 밖에서 실행 취소로 이전 끝 상태 좌표와 맞춘 뒤 시작한다.
4. 사용자가 직접 조작하게 하려면 `task.handOff()`로 제어권을 넘기고 `takeOverTaskSpace(1)`로 되찾는다. 에이전트가 쥔 동안 사용자의 클릭은 페이지에 들어가지 않는다.

## arrows.app에서 확인한 함정과 대응

ego 공통 문제(시간 초과 뒤 NodeService 정리, 문법 오류 시 무응답, 같은 모듈 주소 재사용, stdin, 뒤쪽 탭)는 [ego 촬영 방법](../../../문서/교재/방법_ego_실습영상_촬영.md)의 대응표에 있다.

| 증상 | 원인 | 대응 |
|---|---|---|
| 스타일·Label 칸에서 엔터 후 원이 하나 더 생김 | 엔터가 앱 단축키로 전달됨 | Tab으로 확정 |
| 원을 끌면 끝없이 멀어지거나 원 1개일 때 좌표가 수천으로 밀림 | arrows가 그림 전체를 화면에 자동으로 맞춤. 가장자리 원을 바깥으로 끌면 끄는 중에도 계속 축소 | 기존 원은 현재 그림 범위 안에서만 옮긴다. 공간은 테두리 끌기로 새 원을 가장자리 가까이 놓아 만든다(놓을 때 한 번만 축소) |
| 테두리 끌기가 빈 곳 클릭이 됨 | 선택 테두리 띠가 원 크기·배율에 비례. 고정 11px는 축소 뒤 띠 밖 | 시작점은 반지름×1.09, 시작점이 어떤 화살표 근처(16px)면 피함 |
| 원 위치를 못 찾음 | 화면에 그려진 원·글자로 찾는다. 겹친 원·비슷한 이름·지나가는 관계 이름이 섞임 | 글자를 가장 가까운 원에만 배정하고, 이름 조각만 모아 정확히 일치 |
| 관계 이름이 잘림 | 선 길이 < 이름 길이 | 원 중심 거리를 반지름 6.6배 우선(선 길이 약 2배) |
| 배치 정리 | 화면 좌표 목표는 화면 맞춤 때문에 어긋남 | 그림 좌표로 설계해 원마다 배율을 다시 재 옮기고, 어긋나면 2차 보정 |
| New로 만든 그림에 빈 원 1개 | 앱 기본 동작 | 영상에서 선택해 Delete로 지우는 장면을 넣음 |
| 다운로드 대기 시간 초과 | 대기를 직렬 큐에 넣어 클릭이 막힘 | `waitForEvent`·`waitForFileChooser`는 큐 밖에서 건다 |
| 그림 영역이 좁음 | 오른쪽 패널 | 오른쪽 위 ☰로 패널 접기(가로 1111→1536) |
| 여러 원 함께 선택 안 됨 | Shift+클릭은 단일 선택 | Ctrl+클릭(Merge 버튼이 함께 보임). 색은 STYLE node-color 칸에 색상값 입력 후 Tab |
