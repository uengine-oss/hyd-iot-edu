## 다시 찍거나 이어 찍는 법

1. ego 작업 공간은 이름으로 쥔다(`촬영도구/config.json`의 `space`, 지금 `arrows ontology 20261023b` — 번호는 바뀔 수 있다). p1 탭. 녹화 설정은 `Emulation.setDeviceMetricsOverride` 2304×1296(브라우저 150% 확대 → CSS 1536×864, 프레임 1920×1080). 도구가 매번 설정한다.
2. 시작 상태가 이전 끝과 달라졌으면 녹화 밖에서 `./촬영도구/run.sh restore <이전 구간> [출발원 도착원]`으로 맞춘다(끝 상태 데이터를 새 그림으로 가져오기, 원 크기 되돌리기, 상대 위치 확인, 마지막 화살표 선택 — 하나라도 다르면 멈춤). 그림 주소가 바뀌므로 첫 구간은 `run.sh rec`의 다섯째 인자 `relax`로 찍는다. 순서: 큐 수정 → `python build_ontology.py cues .evidence/arrows-ontology-20261023/cues.json` → `python 제작용/촬영/시간계산.py estimate <cues.json>` → 배치가 바뀌었으면 `python 촬영도구/plan_order.py <시작 구간>` → `python 촬영도구/voice.py <구간>`(바뀐 문장만 생성) → `TMO=초 ./촬영도구/run.sh rec <이름> <구간> [시작큐] [이전 구간] [relax]` → `python 촬영도구/measure.py <이름>` → `FFMPEG=<ffmpeg.exe> python 촬영도구/encode.py <출력> <조각[:자를ms]> …` → `python build_ontology.py sync`. 녹음 뒤 큐 문장이 바뀌면 encode가 멈춘다. 사용자가 ego에 배치해 둔 그림의 좌표는 `./촬영도구/run.sh coords`로 읽는다.
3. 실패하면 그 조각의 원본을 보존한다(원칙은 안내 1절). 화면이 틀어진 정도면 **되돌리지 말고 그 화면에서 수습 큐로 이어 찍는다**(예: `o091b` 「원 하나가 너무 멀리 끌려갔네요. 다시 끌어오고…」, 번호를 따로 줘 뒤 큐 번호·음성 유지). 상태가 망가져 수습할 수 없을 때만 실패한 큐 시작에서 자르고 녹화 밖에서 맞춘다(아래 표 「녹화 밖 실행 취소」).
4. 사용자가 직접 조작하게 하려면 `task.handOff()`로 제어권을 넘기고 `takeOverTaskSpace(<공간>)`으로 되찾는다(녹화는 멈춘 상태에서). 에이전트가 쥔 동안 사용자의 클릭은 페이지에 들어가지 않는다.
