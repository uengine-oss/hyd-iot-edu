## 1. 바로 가는 길

확정 영상을 실제로 만든 순서다. 셸은 Git Bash, 작업 폴더는 이 폴더(`제작용/촬영/arrows/`), 파이썬은 `PYTHONUTF8=1 python`([run.sh](촬영도구/run.sh) 안에서도 `python`을 부른다). 녹화 원본 · 음성 · 끝 상태는 모두 근거 폴더(3절)에 쌓이고 저장소에 올리지 않는다.

1. **환경 준비(PC마다 한 번).**
   - ego lite 설치 · 로그인은 사용자가 한다. 설치된 `ego-browser skill` 출력도 끝까지 읽는다(API는 설치 버전이 우선).
   - 녹화 도구(저장소): [촬영도구/](촬영도구/). 다른 PC에서는 [config.json](촬영도구/config.json)의 키 파일 위치(`keyFile`)와 환경변수 `FFMPEG`만 맞추면 된다. `work`(근거 폴더) · `space`(ego 작업 공간 이름)도 그 파일에 있다.
   - ego 작업 공간은 이름으로 쥔다(`촬영도구/config.json`의 `space`, 지금 `arrows ontology 20261023b` — 번호는 바뀔 수 있다). p1 탭. 같은 작업은 같은 공간을 쓰고, 다른 세션과 같은 공간 · 페이지를 동시에 조작하지 않는다. ego 창을 최소화하지 않는다(앞에 보이는 탭에서만 프레임이 온다).
2. **큐 · 시간 · 배치 순서(녹화 전).** 큐(발화+조작)의 원본은 [build_ontology.py](build_ontology.py)의 `CUES`다(조작 이름은 3절).
   ```bash
   python build_ontology.py cues ../../../.evidence/arrows-ontology-20261023/cues.json
   python ../시간계산.py estimate ../../../.evidence/arrows-ontology-20261023/cues.json
   python 촬영도구/plan_order.py <시작 구간 이름>      # 배치가 바뀌었을 때만: 겹침 · 그림 범위 축소가 없는 순서를 계산해 ORDER 검사
   ```
   10구간 배치는 사용자가 ego에서 직접 잡은 그림 `zo9DD…`의 저장 좌표를 읽어 쓰고(원 15개), 새 원 2개는 왼쪽 위에 두었다. 사용자가 배치 · 입력할 때는 녹화를 멈추고 `task.handOff()`로 넘긴 뒤 `takeOverTaskSpace(<공간>)`으로 되찾는다(에이전트가 쥔 동안 사용자의 클릭은 페이지에 들어가지 않는다). 사용자가 공간을 잡고 있으면 우회하지 않고 「계속」을 받은 뒤 되찾는다. 그 배치는 화면 캡처가 아니라 저장 좌표로 읽는다:
   ```bash
   ./촬영도구/run.sh coords
   ```
3. **음성(바뀐 문장만).** 비용은 먼저 알린다(V요-42 · 단가 V맥-12). 같은 문장이면 다시 만들지 않는다.
   ```bash
   python 촬영도구/voice.py <구간번호...>
   ```
4. **시작 상태 맞추기(이어 찍을 때만, 녹화 밖).** 끝 상태 데이터를 새 그림으로 가져오기, 원 크기 되돌리기, 상대 위치 확인, 마지막 화살표 선택 — 하나라도 다르면 멈춤.
   ```bash
   ./촬영도구/run.sh restore <이전 구간> [출발원 도착원]
   ```
   그림 주소가 바뀌므로 첫 구간은 `run.sh rec`의 다섯째 인자 `relax`로 찍는다.
5. **구간 녹화(한 번에 한 구간).** [ctrl.mjs](촬영도구/ctrl.mjs)가 매번 해상도(3절)를 설정하고, 시작 상태 확인 → 녹화 → 끝 상태 · 프레임 · 행동 시각을 저장한다. 이름은 매번 새로(`s1-t2`처럼 구간+take, 같은 이름 폴더에 프레임이 있으면 `ctrl.mjs`가 멈춘다), 실패 take도 이름 그대로 남기고 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다(합성 출력 이름도 새로). 녹화 전에 PC 부하를 보되 수치만으로 중단하지 않고 실제 반응 · 프레임 간격으로 판정하고, 녹화 중 같은 PC에서 인코딩 · 검사를 돌리지 않는다.
   ```bash
   TMO=<초> ./촬영도구/run.sh rec <이름> <구간> [시작큐] [이전 구간] [relax]
   python 촬영도구/measure.py <이름>      # 이동별 최대 프레임 공백 · 클릭 좌표 오차 · 문장보다 늦은 조작
   ```
   구간마다 바로 실측하고, 다음 구간 첫 프레임을 앞 구간 절단 프레임과 대조한다. 앞 구간이 실패하면 뒤 구간을 시작하지 않는다.
   - 실패하면 그 조각의 원본을 보존한다(V요-23 · V요-25). 화면이 틀어진 정도면 **되돌리지 말고 그 화면에서 수습 큐로 이어 찍는다**(예: `o091b` 「원 하나가 너무 멀리 끌려갔네요. 다시 끌어오고…」, 번호를 따로 줘 뒤 큐 번호·음성 유지). 상태가 망가져 수습할 수 없을 때만 실패한 큐 시작에서 자르고 녹화 밖에서 맞춘다(아래 표 「녹화 밖 실행 취소」).
   - 확정판의 조각(16개, 순서대로): `s1-t2 s2-t5 s3-t1 s4-t1 s4b-t2 s5-t3 s6-t1 s6b-t2`(1~6구간) · `n7-t1 n8-t1 n9-t1 n9b-t1`(7~9구간, 9구간은 실패 직전 큐에서 이어 찍음) · `m10-t1 m11-t1 m12-t1 m13-t1`(10~13구간, 사용자 배치). 조각별 사용 길이 32.9~114.7초([예상시간](예상시간.md)).
6. **합성.** 구간 원본 시간 그대로(배속 · 중간 컷 없음) 이어 붙이고 음성 · 자막을 입힌다. 녹음 뒤 큐 문장이 바뀌면 encode가 멈춘다. 오류로 끝난 take는 자를 ms를 줘야 한다.
   ```bash
   FFMPEG=<ffmpeg.exe> python 촬영도구/encode.py <출력> <조각[:자를ms]> …
   ```
   결과: 근거 폴더 `<출력>/<출력>_안치윤_1080p.mp4`, `자막.srt`, `verification.json`(구간 · 큐 타임라인 · 이동별 프레임 공백 · 클릭 오차). 확정판 출력 이름은 `ARROWS-온톨로지-길이수정`. 새 이음매마다 앞뒤 0.2초 프레임을 나란히 본다(확정판 `seam_sheet.jpg`).
7. **검사.** V요-34대로(verify · scenes · listen, 이음매, 이동 중 프레임 공백 · 클릭 오차, 영상 · 음성 끝 시각). 소리는 사용자가 듣는다(V요-35).
8. **연결 산출물 동기화.** 대본 · 수업원고 · 예상시간 · 두 과정 가이드 · 대상_목록 · ZIP을 다시 쓰고 [동기화판본.json](동기화판본.json)에 해시를 남긴다(함정표 「sync가 가이드를 덮어씀」 먼저 확인).
   ```bash
   python build_ontology.py sync
   ```
9. **게시.**
   - other-pc에 `course/videos/통합반/통합반_01회차_08_실습_관계그림.mp4`와 바이트 같은 `course/videos/실전반/실전반_01회차_08_실습_관계그림.mp4`를 올리고 `course/videos/README.md` 표를 고친다. 커밋 전 `git fetch origin other-pc && git merge origin/other-pc`. 여러 세션이 같은 폴더를 쓰면 브랜치를 바꾸지 말고 임시 인덱스로 커밋을 만든다(`GIT_INDEX_FILE` → `read-tree` → `commit-tree` → push). 영상 한 편은 100 MiB 아래(확정판 46,382,646바이트).
   - Notion: 두 과정 1회차 페이지 「📂 강의 자료 → 🎬 강의 영상」 탭 PRACTICE 4에 그 커밋에 고정한 링크 세 가지(영상 열기 · MP4 내려받기 · 페이지 안 재생 토글)를 다른 영상과 같은 모양으로 넣고 다시 열어 확인한다. Notion 파일 업로드는 한 번에 20 MiB라 영상은 링크로 건다. 유튜브는 쓰지 않는다.

## 2. 함정표

## 3. 값

**화면 · 녹화**
- 녹화 설정은 `Emulation.setDeviceMetricsOverride` 2304×1296(브라우저 150% 확대 → CSS 1536×864, 프레임 1920×1080). 도구가 매번 설정한다([ctrl.mjs](촬영도구/ctrl.mjs) · [restore.mjs](촬영도구/restore.mjs), 스크립트가 끝나면 풀린다).

## 4. 아직 안 뚫린 길

- **확정판의 자른 ms:** `encode.py`에 준 조각별 `:자를ms`(특히 오류로 끝난 `n9-t1`)는 이 문서에 남아 있지 않다 — 근거 폴더 `ARROWS-온톨로지-길이수정/verification.json`의 `segments[].used_ms`에 있다. 근거 폴더가 없는 PC에서는 미확인.
- **sync가 읽는 영상 판:** [build_ontology.py](build_ontology.py)의 `VIDEO`는 `ARROWS-온톨로지-최종배치`(끝 7.1초가 잘린 20:12.9판)의 `verification.json`을 읽는다. 확정판은 `ARROWS-온톨로지-길이수정`이다. 다시 sync하면 길이 표시가 어느 판을 따르는지 실행해 확인한 적 없다(미확인).
- **다른 PC에서 처음부터:** 근거 폴더 없이(음성 · 구간 원본 · 끝 상태 없이) 새 PC에서 1절을 처음부터 돈 적은 없다. `restore` · `plan_order.py` · `encode.py`는 근거 폴더의 구간 원본을 읽으므로 그 PC에서는 1구간부터 새로 찍어야 한다.
