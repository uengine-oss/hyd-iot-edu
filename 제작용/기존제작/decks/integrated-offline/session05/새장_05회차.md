# 통합반 오프라인 5회차 — 새로 쓰는 장

조립.py가 이 파일의 장을 `[N1]` 같은 표지로 찾아 통합반 5일차에서 가져온 장 사이에 끼운다. 장 번호는 조립할 때 다시 매긴다.

## SLIDE [N1] — 현장 문제를 직접 해결하는 / AI 에이전트의 제작
### 화면 내용
- 유형: 표지
- 기관: 경남대학교 피지컬AI 사관학교
- 과정: 통합반 오프라인 5회차
- 부제: 에이전트가 정보와 도구를 써서 업무를 수행하는 원리
- 아이콘: robot, tool, list-search
### 제작 기준
표지 틀은 제작기준 4절. 제목은 오프라인 05회차 실라버스의 주제 「현장 문제를 직접 해결하는 AI 에이전트 만들기」를 명사구로 고쳤다. 부제와 아이콘은 통합반 5일차 표지와 같다.

## SLIDE [N2] — 실습: 여러 증거의 비교와 점검 우선순위 결정
### 화면 내용
- 유형: 간지
- 구분: 실습
- 부제: 원인 추론 에이전트에 서로 다른 센서 값과 고장 후보를 넣어 점검 순서와 근거를 보완한다
### 제작 기준
오프라인 05회차 실라버스의 셋째 실습 「여러 증거를 비교해 점검 우선순위 결정하기」. 통합반 5일차에서는 원인 추론 실습 한 건에 들어 있던 점검 순서 결정이 오프라인에서는 따로 한 실습이어서 새로 썼다.

## SLIDE [N3] — 실습에서 견주는 증거와 보완하는 점검 순서
### 화면 내용
- 유형: 흐름
- 아이콘: chart-line, scale, zoom-question, list-numbers
- 메시지: 입력을 바꾸어 넣으면 점검 순서와 근거가 달라지고, 증거가 모자라거나 어긋날 때는 단정 대신 추가 확인 요청이 나온다.
- 요소:
  1. 다른 입력을 넣는다 | 서로 다른 센서 값과 / 고장 후보를 / 에이전트에 넣는다
  2. 증거를 견준다 | 후보마다 맞는 증거와 / 맞지 않는 증거를 / 나란히 놓는다
  3. **부족과 충돌을 가린다** | 증거가 모자라거나 / 서로 어긋나면 / 추가 확인을 요청한다
  4. 점검 순서를 정한다 | 먼저 점검할 것부터 / 순서를 매기고 / 근거를 보완한다
- 노트: 셋째 실습에서는 앞에서 만든 에이전트를 그대로 씁니다. 서로 다른 센서 값과 고장 후보를 넣어 후보마다 맞는 증거와 맞지 않는 증거를 견줍니다. 증거가 모자라거나 서로 어긋날 때 에이전트가 원인을 단정하지 않고 추가 확인을 요청하는지를 봅니다. 그런 다음 무엇부터 점검할지의 순서와 그 근거를 보완합니다.
### 화면 구성
네 칸 흐름. 셋째 칸 강조.
### 제작 기준
오프라인 05회차 실라버스의 셋째 실습 상세(「앞서 만든 에이전트에 서로 다른 센서값과 고장 후보를 적용한다. 증거 부족 · 충돌 상황에서는 추가 확인을 요청하고 점검 순서 및 근거를 보완한다」)에서 하는 일 네 칸과 남는 것만 뽑았다. 근거가 모자랄 때 단정하지 않는다는 원칙은 본문의 「멈추지 않는 에이전트가 만드는 결과」「근거의 세 가지 상태」 장이 받친다.
