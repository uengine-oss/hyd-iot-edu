# 실습 시작 도구와 독립 시작본

학생 진입은 `index.html` → `실습시작.zip` 다운로드 → 압축 해제 → `실습시작.cmd` 실행이다. 일반 웹 링크는 PC 명령을 실행하지 않는다. 학교 기본 설치에 Python·VS Code가 있어야 하며 DB 실습은 Docker가 필요하다. 현재 개발 PC에서만 확인했고 학교 초기화 이미지의 포함 여부는 미확인이다.

기본 작업 위치는 사용자가 선택한 `D:/HYD-Practice`다. `settings.json`에서 바꿀 수 있다. 새 시작은 UUID를 붙인 별도 폴더, 이전 작업 열기는 기록된 기존 폴더를 사용한다. 학생 개인 Git 설정은 사용하지 않는다. VS Code 신뢰 설정은 바꾸지 않는다.

## 생성

```powershell
python 제작용/실습시작/build.py
python 제작용/실습시작/verify_packages.py
python 제작용/실습시작/test_launcher.py
```

기본 주소는 로컬 검증 서버 `http://127.0.0.1:8765`다. 공개 배포 시 패키지를 먼저 게시하고, 해당 커밋의 raw URL을 `build_launcher.py --base-url`에 넣어 시작 도구를 묶는다. `catalog.json`은 SHA-256으로 ZIP 판본을 확인한다. 주소만 바꾸고 검증 없이 게시 완료로 표시하지 않는다.

오프라인1 전체 가이드는 각 과정 `01회차/오프라인1_가이드.zip`이다. 압축을 풀고 `가이드열기.html`을 열면 된다. 정본 HTML과 실제 참조 이미지·자료·시작 도구를 함께 묶고 내부 링크를 확인한다. 시작 도구를 새로 묶은 뒤에는 `build_guide_bundle.py`도 실행한다. ZIP을 다시 생성하면 컨텐츠가 같아도 ZIP 메타데이터 해시가 바뀔 수 있으므로 게시 커밋과 해시는 항상 함께 고정한다.

`build_labs.py` → `build_offline.py` → `build_conditions.py` → `build_launcher.py` 순서다. 앞 생성기만 실행하면 뒤 단계 목록을 다시 생성해야 한다. `build.py`가 순서를 묶는다. 실제 캡처는 정본 `images/`에 보존하며 캡처를 재생성하지 않는다. `extract_verified_screens.py`는 보존된 원본 화면의 지정 영역을 잘라내는 제작 도구다.

## 제공 범위

- 온라인2 설계: 원자료·규칙·요구·빈 결과 틀. 실전반에는 앞 단계 설비/센서/부품 모델이 있고 공급 연결은 학생이 작성한다.
- 온라인2 그래프: 앞 단계 완성 모델 + `lab_db.py` 환경 준비. 이번 적재·조회 로직은 제공하지 않는다.
- 오프라인1 적재: 승인 편성의 제공 절차에 따라 `offline_load.py`와 질문을 제공한다. 온라인 구현 ZIP에 넣지 않는다.
- 실전반 조건표: 기존 원문·사례·입력틀, 학생용 START·가이드. 결과 조건표와 판단 기록은 학생이 작성한다.
- `reference/`와 `verify_reference.py`는 강사 제작용이며 학생 ZIP 밖에 둔다.

## 실행과 촬영의 구분

`lab_db.py`는 폴더별 새 컨테이너와 자동 배정된 루프백 포트를 사용한다. `랩_연결.json`의 ID와 컨테이너 라벨이 일치할 때만 재사용한다. 포털 DB에 접속하지 않는다. 이미지 최초 다운로드·Docker 기동·학교 네트워크는 별도 조건이다. `NEO4J_AUTH=none`은 새 로컬 교육 컨테이너에만 적용하며 외부 주소에 바인딩하지 않는다.

실행 근거와 미확인은 [제작·검증 근거](../../문서/교재/근거/2026-10-26_실습시작과독립랩.md)를 따른다. Python 함수·DB 검증과 학생 AI 수행, 데스크톱 화면 확인, 음성 포함 영상 완성은 서로 다른 판정이다.
