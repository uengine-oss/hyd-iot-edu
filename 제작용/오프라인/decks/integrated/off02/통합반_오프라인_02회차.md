## SLIDE 09 — CREATE · MERGE · SET의 역할
### 화면 내용
- 유형: 코드
- 메시지: 다시 실행해도 같은 대상이 하나로 남게 하려면, 바뀌지 않는 식별자로 찾고 없을 때만 만든다.
- 코드: CREATE (s:Sensor {id: 'sen:ts1', /                   name: '유온 센서', /                   tag: 'TS1'}) /  / MERGE (s:Sensor {id: 'sen:ts1'}) / SET s.name = '유온 센서', /     s.tag  = 'TS1', /     s.unit = '℃' /  / ── sen:ts1이 이미 있을 때 CREATE의 결과 ── / Node already exists with label `Sensor` /   and property `id` = 'sen:ts1'
- 요소:
  1. **CREATE** | 적은 대로 새 노드를 만든다. 이미 있는지는 보지 않는다. sen:ts1이 이미 있으면 유일 제약에 걸려 거절된다.
  2. **MERGE** | 패턴에 맞는 노드를 찾고 없으면 만든다. 이 예는 id 유일 제약 아래 같은 id로 반복 실행한다.
  3. SET | 찾았거나 만든 노드의 속성에 값을 넣는다.
  4. 식별자로 찾는다 | 같은 id를 조건으로 기존 센서를 찾는다. 이름과 태그 같은 값은 SET으로 넣는다.

## SLIDE 25 — SOP 원문과 조치 방법(Skill) · 작업 단계(Step)
### 화면 내용
- 유형: 코드
- 메시지: SOP 한 편은 조치 방법(Skill) 하나가 되고, 번호 붙은 단계는 순서와 근거 절을 가진 작업 단계(Step)가 된다.
- 코드: ── 원문: HM-8.5의 SOP-COOL-11 ── / 1. PLC 운전 모드가 REMOTE_AUTO인지 확인한다. / 2. 팬 속도를 100 %로 올린다. / 3. 15분 재관측으로 HM-8.6 회복 판정을 한다. / 승인: 운전원. /  / ── 구조화: 노드와 관계 ── / (:Skill {sopId: 'SOP-COOL-11', /         name: '팬 최대 운전', kind: 'control'}) / (:Skill)-[:HAS_STEP]-> /     (:Step {order: 2, text: '팬 속도를 …'}) / (:Step)-[:REFERS_TO]-> /     (:ManualSection {ref: 'HM-8.5'}) / (:Skill)-[:APPROVED_BY]->(:Role {name: '운전원'})
- 요소:
  1. **Skill · sopId** | SOP 한 편이 조치 방법 노드 하나이다. 절차 번호를 식별자로 그대로 쓴다.
  2. Step · order | 번호 붙은 단계 하나가 Step 하나이다. order가 순서를 지킨다.
  3. HAS_STEP · REFERS_TO | 조치 방법에서 단계로, 단계에서 근거 절로. 추천에 출처 절이 따라 나온다.
