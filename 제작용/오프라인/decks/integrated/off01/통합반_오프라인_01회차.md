## SLIDE 14 — 명령·확인 응답·재관측의 구별
### 화면 내용
- 유형: 코드
- 메시지: PLC의 확인 응답은 명령 처리 결과를 알리며, 설비가 회복되었는지는 계측값을 다시 읽어 확인한다.
- 코드: # 명령: 11:14:57 / cmdId       CMD-1010-0001-b94a / asset       HYD-01 / incident    INC-1010-01-d55a / actions     FAN_SET fan_pct 100 / approvedBy  user:kim-op / expiresAt   11:16:57 /  / # PLC 확인 응답: 11:14:58 / cmdId       CMD-1010-0001-b94a / result      DONE / interlock   PASS /  / # 재관측 결과 / TS1         61.4 ℃ → 51.5 ℃ / alert       CLEAR
- 요소:
  1. 승인된 명령 | 11:14:56에 승인한 팬 최대 운전이다. 팬 속도를 60 %에서 100 %로 올린다.
  2. cmdId와 만료 시각 | cmdId는 같은 명령을 식별한다. PLC가 중복을 검사하며 expiresAt 뒤에는 실행을 거절한다.

- 노트: [짚을 곳] 코드 위 명령 → 가운데 PLC 확인 응답 → 아래 재관측 / · 세 질문을 따로: 요청을 보냈나, 실제로 처리됐나, 그 결과 온도가 내려갔나 / · 명령: 팬 속도 60 % → 100 %, 승인자, 유효 시각(만료 뒤에는 실행 거절). 명령 번호로 다른 요청과 구별 / · ACK(확인 응답) = 처리 결과. 실행 완료 + 인터록 정상(인터록 = 위험 조건에서 다른 명령보다 앞서 설비를 안전한 상태로 돌리는 PLC의 보호 동작, PASS = 막을 조건이 없었다). 운전 상태 메시지에 실려 돌아오고, 프로세스 엔진이 번호로 자기 명령의 응답인지 맞춘다 / · 재관측: 유온 61.4 → 51.5 ℃, 경보 해제 = 원하는 냉각 효과의 확인 / · 처리 응답 ≠ 회복: 완료 응답인데 유온이 계속 오르면 문제는 미해결. 온도만 내려갔다고 명령이 실행됐다고 단정도 못 한다 / [다음] 서로 다른 기록을 무엇으로 잇나

### 화면 구성
