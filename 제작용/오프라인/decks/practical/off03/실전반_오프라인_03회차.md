## SLIDE 05 — 매뉴얼 한 문단과 등록된 지식

- 코드: # 매뉴얼 HM-8.4의 한 문단(발췌) / 쿨러 핀 오염이 가장 흔하다(사전 확률 0.6). 최근 30초 냉각 효율 / 평균이 70 % 미만이고 … 팬은 정상이면 핀 오염으로 판정한다. / 관련 부품은 쿨러 코어다. /  / # 같은 내용이 지식 그래프에 들어간 모습 / (:Cause {name: '쿨러 핀 오염', prior: 0.6}) /   -[:CAUSES]->(:FailureMode {name: '쿨러 냉각 성능 상실'}) / (:Cause)-[:EVIDENCED_BY]->(:Evidence {tag: 'CE', /   aggregate: 'avg', window_seconds: 30, expect: 'lt', threshold: 70}) / (:Cause)-[:INVOLVES_PART]->(:Part {name: '쿨러 코어'})
- 요소:
  1. 섞인 문단 | 원인 · 흔한 정도 · 판정 기준 · 부품이 한 문단에 있어 사람이 읽고 가려야 쓰인다.
  2. **나뉜 지식** | 원인은 노드, 판정 기준은 증거의 칸, 고장 유형과 부품은 관계가 된다.
  3. 기준만 있다 | 증거에는 비교할 기준 70만 있고 지금의 냉각 효율은 없다.
  4. 출처 | 등록된 지식마다 HM-8.4의 인용이 붙는다.
- 노트: [짚을 곳] 왼쪽 코드 위(HM-8.4 문단) → 아래(그래프의 모습) → 오른쪽 항목 넷 / · 문단에 원인 · 흔한 정도 · 판정 기준 · 부품이 섞여 있어 사람만 가려 읽는다 / · 나뉜 지식: 원인은 노드(prior 0.6 칸), 고장 유형 CAUSES · 부품 INVOLVES_PART 관계 / · 판정 기준은 증거의 칸: CE · 평균 · 30초 · 70 미만 / · 증거에는 기준 70만, 지금의 냉각 효율은 없다 / · 등록된 지식마다 HM-8.4 인용이 붙는다 → 조치 검토 결과에 출처를 적을 수 있었던 까닭 / [다음] 샘플 인스턴스 적재와 문서 인제스천
