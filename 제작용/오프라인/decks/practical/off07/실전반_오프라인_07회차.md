## SLIDE 07 — 문장으로 적은 절차와 BPMN으로 그린 절차
### 화면 내용
- 유형: 비교
- 메시지: **BPMN**(Business Process Model and Notation)은 도형과 선의 뜻을 정한 표기 표준이라, 문장에 묻힌 갈림이 드러난다.
- 요소:
  1. 문장으로 적으면 | 「승인하면 … 아니면 … 거절하면」이 흩어진다 / 재관측과 보고를 누가 하는지 빠지기 쉽다 / 알림 뒤에도 기다리는지 사람마다 달리 읽는다 | 달리 읽힌다
  2. **BPMN으로 그리면** | 갈림은 마름모, 끝은 굵은 원으로 센다 / 작업은 맡는 쪽의 레인에 놓인다 / 기다림은 작업에 붙은 타이머의 선 모양으로 정해진다 | 같은 뜻으로 읽힌다
- 노트: [짚을 곳] 왼쪽 칸(문장) → 강조한 오른쪽 칸(BPMN) → 세 줄이 같은 물음에 대응 / · 문장: 「승인하면 … 아니면 … 거절하면」이 흩어져 갈래를 세려면 다시 읽음 / · 문장: 재관측 · 보고를 누가 하는지 빠지기 쉽고, 알림 뒤에도 기다리는지 사람마다 다르게 읽음 / · BPMN: 갈림은 마름모, 끝은 굵은 원으로 셀 수 있음, 작업은 맡는 쪽 레인에, 기다림은 타이머의 선 모양 / · BPMN(Business Process Model and Notation): 도형과 선의 뜻을 정한 표기 표준, OMG 관리, BPMN 2.0은 국제 표준 / · 현업과 구현하는 쪽이 같은 그림으로 같은 흐름을 확인 / · 그렸다고 곧바로 실행되지는 않는다(뒤의 연결 값에서) / [다음] 한 장으로 그린 긴급 대응 프로세스

## SLIDE 16 — 승인 작업의 타이머와 역할: 그림과 연결 값
### 화면 내용
- 유형: 코드
- 메시지: 그림은 타이머가 승인 작업에 붙어 끊지 않는다는 구조를 담고, 10분 기한과 승인 역할은 연결 값이 정한다.
- 코드: 그림 파일(.bpmn) / <userTask id="T_approve" name="운전원 승인"> … / <boundaryEvent id="B_overdue" name="승인 지연" /     attachedToRef="T_approve" cancelActivity="false"> /   <timerEventDefinition \/>      ← 기한이 비어 있다 /  / 연결 값(mapping.json) / "timers":    { "B_overdue": "PT10M" } / "T_approve": { "part": "task:select-or-reject", /                "role": "운전원" }
- 요소:
  1. attachedToRef | 이 타이머가 운전원 승인 작업에 붙어 있다.
  2. **cancelActivity="false"** | 비중단형이다. 알림 뒤에도 승인 작업이 열려 있다.
