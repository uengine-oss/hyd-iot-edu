## SLIDE 06 — 공급 관계에 딸린 값과 공급사에 딸린 값
### 화면 내용
- 유형: 관계도
- 메시지: price · failRate · leadDays는 짝마다 달라 공급 관계(SUPPLIED_BY)에 두고, avl은 공급사에 둔다.
- 요소:
  1. 펌프 축 씰 키트 | Part / P-PMP-SEAL | 45,0
  2. B-OEM | Supplier / avl true | 0,0
  3. **C트레이딩** | Supplier / avl false | 100,0
  4. A정밀 | Supplier / avl true | 45,100
  5. 팬 베어링 | Part / P-FAN-BRG | 100,100
- 연결: 펌프 축 씰 키트 > B-OEM : 55만원 · 0.02 · 5일 ; 펌프 축 씰 키트 > C트레이딩 : 20만원 · 0.30 · 1일 ; 펌프 축 씰 키트 > A정밀 : 35만원 · 0.12 · 2일 ; 팬 베어링 > A정밀 : 18만원 · 0.10 · 1일
- 노트: [짚을 곳] 위 가운데 씰 키트 → 세 공급사로 나간 선의 숫자 → 오른쪽 아래 팬 베어링 선 → 원 안의 승인 여부(강조한 C트레이딩) / · 부품에 단가를 적으면 누구 값인지 못 정하고, 공급사에 적으면 다른 부품 값과 섞인다 → 짝에 딸린 값은 공급 관계의 속성 / · 선마다 단가(만원) · 불량률(비율) · 납기(일): B-OEM 55 · 0.02 · 5일, C트레이딩 20 · 0.30 · 1일, A정밀 35 · 0.12 · 2일 → 가장 싼 곳은 빠르지만 불량률 최고, 가장 비싼 곳은 불량률 최저 · 납기 최장 → 셋을 함께 따진다 / · 같은 A정밀도 팬 베어링은 18 · 0.10 · 1일 → 부품이 바뀌면 값이 다르다 / · 원 안 값은 공급사에 딸림: C트레이딩은 승인 공급사가 아니다(avl false). 구매 규칙은 핵심 부품을 승인 공급사에서만 → 가장 싸고 빨라도 후보에서 뺀다 / · 승인 여부는 어느 부품을 사든 같은 값 → 관계가 아니라 공급사의 속성. 실제 구매도 승인 공급사 목록을 따로 두고 단가 · 품질 · 납기를 함께 본다 / [다음] CREATE · MERGE · SET

### 화면 구성
관계도 노드 다섯. 왼쪽은 부품 둘(위 씰 키트, 아래 팬 베어링), 오른쪽은 공급사 셋(위 C트레이딩 강조, 가운데 B-OEM, 아래 A정밀). 공급 관계의 값(단가 · 불량률 · 납기)은 선 위 라벨에, 공급사의 값(avl)은 공급사 원 안에 둬서 「값이 선에 붙는가, 노드에 붙는가」가 배치로 보이게 한다. 아래 팬 베어링 → A정밀 선은 같은 공급사도 부품이 바뀌면 짝의 값이 달라짐을 보인다. 선이 엇갈리지 않게 A정밀을 아래에 둔다.

## SLIDE 07 — CREATE · MERGE · SET: 새로 만들기와 찾아서 쓰기
### 화면 내용
- 유형: 코드
- 메시지: 적재를 중간에 멈췄다가 다시 돌려도 센서가 하나로 남으려면, 식별자로 찾고 없을 때만 만드는 MERGE를 쓴다.
- 코드: CREATE (s:Sensor {id: 'sen:ts1', /                   name: '유온 센서', /                   tag: 'TS1'}) /  / MERGE (s:Sensor {id: 'sen:ts1'}) / SET s.name = '유온 센서', /     s.tag  = 'TS1', /     s.unit = '℃' /  / ── sen:ts1이 이미 있을 때 CREATE의 결과 ── / Node already exists with label `Sensor` /   and property `id` = 'sen:ts1'
- 요소:
  1. **CREATE** | 있는지 보지 않고 새 노드를 만든다. 같은 id가 있으면 유일 제약이 거절한다.
  2. **MERGE** | 패턴에 맞는 노드를 찾아 쓰고, 없을 때만 만든다.
  3. SET | 찾았거나 만든 노드에 속성값을 넣는다.
  4. 쓰는 자리 | 시드는 MERGE만 써서 다시 돌려도 같다. 매번 새로 남길 기록은 CREATE로 만든다.
- 노트: [짚을 곳] 맨 위 CREATE → 맨 아래 오류 메시지 → 가운데 MERGE와 SET → 오른쪽 넷째 칸 / · CREATE = 있는지 안 보고 새 노드. 같은 식별자가 있으면 유일 제약이 거절(아래 메시지) / · MERGE = 식별자로 찾아 있으면 쓰고 없을 때만 만든다. SET = 찾았거나 만든 노드에 이름 · 태그 · 단위. 찾는 일과 값 넣는 일을 나눠 적었다 / · 적재를 중간에 멈추고 처음부터 다시 돌려도 MERGE면 같은 센서가 하나로 남는다 / · 이 시스템의 기준 그래프 파일도 MERGE만 써서 다시 실행해도 결과가 같다 / · 매번 새 대상이 생겨야 하는 곳(문서 적재 때마다 「언제 무엇을 넣었다」 기록)엔 CREATE. 새 대상인가, 같은 대상을 다시 다루나로 고른다 / [다음] 스키마 정의에서 적재 검증까지
