# 사람의 결정과 명세로 검증하는 점검 요청 에이전트

실전반 5회차 이론 덱(01 · 04 · 06 · 08편, 74장). 통합반 7회차 · 8회차를 출발점으로 실전반 기준(`문서/교재/실전반_기준.md`)대로 새로 짰다. 실라버스 실전반 53~60행의 큰 틀을 따르고, 실전반 행에 없는 통합반 장(작성자 · 검토자 실습, 모호한 변경 비교 실습, 교대 인수인계 실습 · 데이터 패브릭, 판단 채점 가중치 등)은 뺐다. 1차본(56장) 뒤 2026-10-28 완성판에서 통합반 7 · 8회차 대본을 다시 통독하고 빠진 개념 장 18장(승인에서 출발한 명령 · 멈춘 작업 닫기 · 질문의 한계 · 가드레일 · 새 기능만 본 확인 · spec.md 여섯 칸 · 깨는 변경 · 금지 조건의 장치 · 검사로 옮긴 약속 · 손 확인의 한계 · 거절 시나리오 · 명세와 시나리오의 대응 · 승인 단계 시험 · 두 실행 기록 · 회귀 기록 · 기준과 과정 · 금지 조건의 다섯 자리 · 운영 중 먼저 볼 곳)을 되살렸다. 줄기는 실전반의 같은 점검 요청 프로젝트(질문 · 재개 → 긴급 확인 표시 명세 · 구현 → 기대 결과 · 회귀)다. 노트는 오프라인 강의 메모(기준_이론대본 87번)이고, 낭독 원고는 대본 `산출물/실전반/이론/05회차/대본/`이다.

## SLIDE 41 — Given · When · Then 시나리오 한 편
### 화면 내용
- 유형: 코드
- 메시지: 시나리오를 전제 Given · 행동 When · 기대 결과 Then으로 나누면, 준비할 입력과 확인할 값이 줄마다 갈린다.
- 코드: Feature: 점검 요청의 긴급 확인 표시 /   Scenario: 유효한 유온 평균이 기준 이상인 쿨러 경보 /     Given 쿨러 성능 저하 경보의 점검 요청이 있다 /     And   TS1 120초 평균이 60.4 ℃이고 /           신선도와 표본이 유효하다 /     When  에이전트가 요청을 처리한다 /     Then  urgent는 true이다 /     And   긴급 이유에 판정 값과 기준이 적힌다 /     And   점검 결과는 승인 대기 상태이다
- 요소:
  1. 서식 | Feature 아래 Scenario를 Given · When · Then · And로 적는 서식이 **Gherkin**이다.
  2. Given | 입력과 자료의 상태다. 값과 함께 유효성도 적는다.
