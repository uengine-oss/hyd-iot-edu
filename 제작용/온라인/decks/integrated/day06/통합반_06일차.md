  3. 근거가 없으면 어떻게 할 것인가 | 값을 읽지 못한 채 원인을 고르면 지어낸 판단이 된다 | 예외

## SLIDE 34 — 도구 정의 한 건: part_quotes
### 화면 내용
- 유형: 코드
- 메시지: 모델이 도구를 부를지 정할 때 읽는 것은 도구 목록의 항목에 든 이름과 설명과 입력 스키마이다.
- 코드: { /   "name": "part_quotes", /   "description": "SCM 부품별 견적: …단가(만원) · /     불량률 · 납기(일) · 승인 여부(avl)를 /     읽습니다. …", /   "inputSchema": { /     "type": "object", /     "properties": { /       "part": { /         "type": "string", /         "default": "P-PMP-SEAL", /         "description": "부품 번호 …" } } }, /   "annotations": { "readOnlyHint": true } / }
- 요소:
  1. name | 호출할 때 쓰는 도구의 이름이다.
  2. **description** | 모델이 읽고 부를지를 정하는 글이다.
  3. inputSchema | 이름 · 형 · 기본값 안내이다. 기본값의 실제 적용은 구현이 맡는다.
  4. annotations | 읽기 전용인지 같은 표시가 붙는다.
- 노트: 그 목록에 든 항목 하나를 그대로 옮겨 왔습니다. 화면 왼쪽이에요. 구매 쪽 업무 DB 서버가 내주는 부품 견적 조회 도구입니다. 맨 위가 도구의 이름이에요. 호출할 때 이 이름을 씁니다. 그 아래가 설명이고요. 부품별로 공급사의 단가, 불량률, 납기, 승인 여부를 읽는다고 적혀 있죠. 가운데 입력 스키마는 넘길 값을 정합니다. 부품 번호 하나를 글자로 받고, 생략하면 이 서버 구현에서는 펌프 축 씰 키트를 기본으로 씁니다. 값의 이름과 형, 그리고 비웠을 때 쓸 값까지 적혀 있으니, 모델이 무엇을 어떤 모양으로 넣을지 판단할 단서가 됩니다. 이 정의는 JSON Schema라는 표준 형식으로 적습니다. 스키마의 기본값 표시는 안내이고, 검사기가 빠진 값을 자동으로 채운다는 뜻은 아니에요. 실제 기본값 처리는 이 도구의 구현에서 합니다. 맨 아래에는 이 도구가 읽기만 한다는 표시가 붙어 있어요. 오른쪽에서 강조한 게 설명이죠. 모델이 이 도구를 부를지 말지 정할 때 읽는 게 바로 이 설명과 입력 스키마거든요. 그러니까 도구의 설명은 사람을 위한 주석에 그치지 않습니다. 설명이 모호하면 모델이 엉뚱한 도구를 고르거나, 필요한 도구를 그냥 지나쳐요. 스킬의 설명이 스킬을 고르는 기준이었던 것처럼, 도구의 설명은 도구를 고르는 기준입니다.
