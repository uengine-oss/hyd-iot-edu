# 포털 화면 규칙 — 화면을 고치거나 더할 때 읽는 한 장

포털(`it/portal/www/`, 정적 JS — 서비스는 같은 출처 `/svc/<서비스>/`로만 부르고 nginx가 프록시한다: `it/portal/nginx.conf`, 주소 함수는 `layers.js`의 `SVC` 하나)의 화면 규칙이다. 화면을 더할 때는 **더한 것만** 이 규칙으로 다듬는다(기존 화면을 함께 재작성하지 않는다).

## 교재에서 찾는 포털 기능

메뉴 이름은 `it/portal/www/index.html` 주 메뉴 기준이다. 제출 · 승인 · 실행 결과는 이 표가 아니라 그 사건 · 실습의 실제 기록으로 확인한다. 수업 단계에서 막히는 행동은 3절.

| 학생이 찾는 것 | 메뉴 | 화면에서 할 수 있는 일 |
|---|---|---|
| 내가 맡은 일 | 작업 → 내 작업함 | 자신의 작업 목록에서 처리할 항목을 찾는다. |
| 처리 중인 업무 | 작업 → 처리 건 | 처리 건을 열어 내 차례와 에이전트 활동을 살핀다. |
| 설비에 적용할 결함 | 설비 → 결함 시뮬레이션 | 결함 시나리오와 적용할 설비를 확인한다. |
| 오일 검사 결과를 넣는 곳 | 설비 → 오일 분석 입력 | 분석 결과 입력 양식을 확인한다. |
| 경보가 생긴 사건 | 설비 → 이상 확인 · 조치 | 이상 사건과 연결된 조치 내용을 확인한다. |
| 센서값의 시간 변화 | 설비 → 실시간 모니터링 | Grafana 패널에서 유온 추이를 찾는다. FUXA 운전 화면의 경고 기준은 1회차 기술사실표에 있다. |
| 판단 조건 | 판단 → 조치 판단 규칙 | 조치 판단에 쓰는 조건을 읽는다. |
| 조건에 따른 손익 | 판단 → 조건별 손익 | 비교할 시험 기준과 조건을 확인한다. |
| 판단 이후의 업무 결과 | 판단 → 승인과 실행 | 기존 처리 건에서 판단 결과와 실행 결과를 구분해 읽는다. 완료된 건에서는 정비 요청도 확인할 수 있다. |
| 업무 흐름 그림 | 판단 → 흐름 가져오기 | 흐름 그림을 가져오는 입력 화면을 찾는다. |
| 설비와 센서의 연결 | 지식 → 지식 지도 | 노드를 선택해 종류·이름·속성과 들어오고 나가는 관계를 읽는다. 상세창에 표시되는 식별 정보는 2회차 기술사실표 2.8절에 있다. |
| 조치의 순서와 근거 | 지식 → 조치 방법 | 조치 한 건을 열어 사유·담당, 절차, 연결된 지식을 읽는다. |
| 매뉴얼과 업무 데이터 | 지식 → 지식 관리 | 등록된 매뉴얼과 업무 데이터 연결, 질의 보기를 찾는다. |
| 데이터가 온 곳 | 지식 → 데이터 연결 | 원천과 표를 열어 업무 DB·옛 설비 DB·시계열 DB를 구별한다. |
| 질문과 응답 기록 | 인공지능 설정 → 에이전트에게 질문 | 질문 입력란과 지난 질문을 찾는다. |
| 에이전트 구성 | 인공지능 설정 → 에이전트 | 구성된 AI 에이전트 목록을 살핀다. |
| 에이전트가 쓰는 도구 | 인공지능 설정 → 도구 연결 | 지식 그래프·판단 시스템·업무 자료에 연결되는 도구를 찾는다. |
| 같은 조건에서의 시험 | 인공지능 설정 → 시험 비교 | 어떤 조건으로 시험을 비교할지 확인한다. |
| 판단 품질을 평가하는 곳 | 인공지능 설정 → 판단 채점 | 정답표·채점 실행·실행 기록·지식 수정 전후 비교를 구별한다. |
| 운영 성과 | 성과 → 성과 지표 | 지표의 기간·단위와 계산 정의를 확인한다. |
| 학습의 출발점 | 시스템 → 홈 | 설비·데이터·AI 연결 그림과 결함·사건·처리 건 바로가기를 찾는다. |
| 각 구성 요소의 역할 | 시스템 → 시스템 구성 | 설비에서 판단과 실행까지 이어지는 시스템의 구성과 역할을 살핀다. |
| 환경 관리 | 시스템 → 관리 | 현재 사례와 출발본 내보내기·불러오기, 복원 항목의 위치를 확인한다. |

회차별 수치 · 설명은 그 회차 [기술사실표](../../강의제작/지침/사실표/)(찾는 순서는 `공통.md` C-2). 메뉴 · 표시가 바뀌면 이 표의 그 행과 그 사실을 쓰는 회차 사실표를 함께 고친다.

## 1. 판정 기준
| 기준 | 뜻 |
|---|---|
| 10초 | 학생이 그 화면에서 할 일을 10초 안에 찾는가. 찾지 못하면 그 화면이 틀렸다 |
| 카드 하나에 행동 하나 | 카드(`.card` — 제목 · 핵심 값 · 상태 칩 · 보조 한 줄)마다 주 행동 버튼은 하나 |
| 보조 정보는 접기 | id · 원문 · 점수 분해 · 모델 이름 · 조건식은 `details.fold` 안. 화면 첫 줄은 사람 말 |
| 기존 것 재사용 | 새 컴포넌트 · 간격 · 색을 만들지 않는다 — `components.css`의 `.card` · `.chip`(톤 5종) · `.field` · `.form-section` · `.empty`, 간격 `--s3`(카드 사이) · `--s6`(섹션 사이), 색 토큰(`--accent` · `--ok` · `--warn` · `--alarm`) |
| 글 폭 | 설명 · 요약 글은 `.prose`(최대 768px) |

## 2. 실패를 실패로 보인다
- 읽기 실패를 「없음」 · 빈 목록 · 끝없는 「불러오는 중」으로 보이지 않는다. 그 자리에 `UI.errorBlock(제목, 사유, {retry})`(`ui.js`) — 사유는 서버의 학생용 문장, `retry`면 [다시 시도] 단추.
- 「한 번 읽고 실패하면 끝」을 만들지 않는다: 처음 읽기에 실패한 화면은 셸의 `show()`가 메뉴를 다시 열 때 새로 그린다(화면 모듈의 `failed()`).
- 요청은 `requestJ`(`app.js`) 하나로 — 네트워크 끊김 · 시간 초과 · 403/404/422를 쉬운 말로 바꾼다. 오래 걸리는 계산은 `timeout` 옵션. 사본 요청 함수를 만들지 않는다.
- 학생에게 내부어를 보이지 않는다: 환경 변수 이름 · 표 이름 · 영문 예외 · 경보 코드(`COOLER_DEGRADATION` → `UI.patternName`) · 도구 서버 id(→ `hydWords.serverName`) · 실행기 제품 이름. 원문은 접기 안에서만.
- 처리 기록 문구는 상태로 정한다: 결과가 없을 때 「…하는 중」은 그 단계가 진행 중일 때만, 그 밖에는 「결과 기록 없음 — 단계 상태」.

## 3. 수업 경계 표시 — 서버 표를 읽기만 한다
- 정본은 서버 `GET /api/course-access`(`it/process/procsvc/course_policy.py` `Policy.view()`), 화면 모듈은 `courseAccess.js` 하나. 메뉴는 잠그지 않는다(23개 모두 연다).
- 막힌 행동의 단추는 그릴 때 `hydCourseAccess.attrs('<행동 키>')`를 단다 — 막혔으면 꺼짐 + 서버가 준 까닭. 행동 키: `tool_servers.register` · `documents.golden` · `ddl.meanings` · `config.import`.
- 값마다 갈리는 판정은 `assignBlocked(정의)` · `startBlocked(정의)` · `importBlocked(흐름 id)`, 수업 모델은 `hydCourseAccess.model`, 제공 문서만 받는지는 `documentsProvidedOnly`.
- 상단 한 줄에 지금 단계(수업 / PBL · 기한, PBL 기한 지남). 표를 못 읽으면 잠그지 않고 「수업 단계 정보 읽기 실패」 + [다시 시도](자동으로 3 · 10 · 30초 뒤 세 번) — 그동안 판정은 서버가 한다.
- 화면에 규칙 사본(막을 메뉴 · 단추 목록, 허용 정의 목록)을 손으로 적지 않는다.

## 4. 화면 용어(정본 — 코드 · API · DB 이름은 바꾸지 않고 화면 문구만)
| 같은 것 | 화면 이름 | 쓰지 않는 말 |
|---|---|---|
| 경보 한 건의 처리 | 처리 건(처리 건 탭) · 사건(이상 확인 탭, 번호는 보조 줄) | 인스턴스 · 인시던트 · 실행 |
| 사람 몫의 일 | 내 차례(화면) · 단계(흐름 안) | todolist · 워크아이템 · 작업(task) |
| 에이전트가 낸 선택지 | 조치 후보(고르기 전) · 결정(고른 뒤) · 조치 방법(목록 화면, 번호 `SOP-…`는 보조 줄) | 가이드 카드 · 스킬 = SOP |
| 사람이 고르는 행위 | 조치 선택(화면) · 버튼 「결정」 · 「승인」 | HITL · 이 카드로 결정 |
| 정비 요청 | 정비 요청 | 작업지시 · WO_CREATE |
| 조치 뒤 확인 | 효과 확인(15분) | 재관측 · ACK · 15분 재관측 |
| 책임자에게 넘김 | 책임자 확인 | 에스컬레이션 · 상급자 호출 |
| 설비 쪽 | 설비 제어 · 설비에 명령 · 설비 응답 | PLC 명령 · action.cmd · ACK DONE |
| 수행 주체 | AI 에이전트 · 시스템 수행자 · 역할 이름(운전원 · 생산관리자) | 워커 · CLI · sys:agent · 다리 |
| 재작업 차수 | n차(예: 2차 처리) | 세대 · generation |
| 지식 | 지식(지도 탭) · 항목 · 연결 | 온톨로지 Execution 레이어 · 관계명 원문 · Cypher(질의 보기 안에서만) |
| 폼 라벨 | 담당자 · 사유 · 역할 | 결정자 · 승인자 · 확인자 · 판단 사유 · 반려 사유(사유 하나로) |
| 설비 값 | 유온 · 냉각 효율 · 팬 속도 · 토출 압력 · 유량 · 팬 진동 · 설비 상태 · 경보(태그 코드 TS1 등은 작은 보조 글씨) | PLC 상태 · 탐지 단계 |
| 운전 모드 | 원격 자동 · 원격 수동 · 현장 제어 · 운전 중 · 보호 정지 | REMOTE_AUTO · TRIP 원문 |

## 5. 상태 이름 · 색
| 코드값 | 화면 이름 | 칩 톤 |
|---|---|---|
| TODO | 예정 | neutral |
| IN_PROGRESS · RUNNING(처리 건) | 진행 중 | accent |
| SUBMITTED | 제출됨(엔진 차례) | accent |
| PENDING | 보류 | warning |
| DONE · COMPLETED(처리 건) | 완료 | success |
| CANCELLED | 취소 | danger |
| SKIPPED(단계) | 건너뜀 | neutral |
| 실행 HUMAN_ASKED | 답변 기다림 | warning |
| 실행 STARTED · FB_REQUESTED · FAILED | 진행 중 · 반영 중 · 실패(danger) | — |
| 승인 전달 PENDING · DELIVERED · FAILED · DISCARDED(단계 상태와 다른 축 — `UI.deliveryChip`) | 전달 대기 · 전달 완료 · 전달 실패 · 승인 폐기 | warning · success · danger · neutral |

## 6. 검사
- 화면 순회 테스트 `workspace/개발/tests/test_portal_ui.py`(Playwright, 메뉴 23개 × 1366 · 1920): 콘솔 오류 · 실패 요청 · 14초 뒤 남는 로딩 · 내부어 · 가로 넘침 · 수업 단계에서 막힌 행동 단추가 켜져 있는지(눌리는데 거절). 떠 있는 스택에 `HYD_TEST_PORTAL_URL=http://127.0.0.1:<포털 포트>`로 돌린다(`RUNBOOK.md` §5). 쓰기 단추는 누르지 않는다.
- 걸린 화면은 앱 내장 브라우저로 눈으로 한 번 더 본다.
