# AI 응답 재생 — 강의 중계 키 없이 실습하기

온라인 학생은 영상을 보며 자기 PC의 포털에서 같은 조작을 따라 한다. 포털 · 가상 설비 · 처리 흐름은 학생 PC에서 실제로 돈다. AI가 답을 만드는 단계(수업 AI 자리)만 키가 있어야 진행되는데, 키가 없는 PC에서는 **강사가 미리 실제 AI로 진행하며 녹화한 응답을 그 자리에 넣는다.** 그 밖의 모든 것은 실제로 실행된다.

코드: 워커 `it/agent-worker/worker/ai_replay.py`(녹화 · 재생 · 같은 요청 저장), 실행 자리 `worker/runner.py`, 수업 AI 자리의 정본 `it/process/procsvc/course_policy.py`. 테스트: `workspace/개발/tests/test_ai_replay.py` · `test_runner.py`(실행법은 `RUNBOOK.md` §5).

## 1. 모드 — 시작.bat이 정한다
| `AI_MODE` | 하는 일 | 누가 정하나 |
|---|---|---|
| `live` | 실제 AI. 워커 CLI는 키를 모르고 process의 로컬 중계 관문을 거친다(`procsvc/course_model.py`) | 시작.bat — `.env`의 `LLM_API_KEY`가 있으면 |
| `replay` | CLI를 부르지 않고, 그 수업 AI 자리의 녹화를 이 처리 건의 값으로 바꿔 내보낸다 | 시작.bat — 키가 없으면 |
| `record` | 실제 AI로 실행하며 성공한 실행을 녹화한다(`it/agent-worker/replay/`) | 강사 — `bash scripts/start_all.sh --record`(키 필요) |

- 이 셋 말고는 워커가 켜지지 않는다. 워커 `/health`의 `ai_mode`로 보인다. 학생은 아무것도 고르지 않는다.
- 바뀌는 곳은 CLI 실행 자리 하나다. 그 뒤의 결과 해석 · 결과 형식 검사 · 사람에게 묻기 · 보류 · 저장 · 처리 과정 기록은 실제 실행과 같은 코드다.
- 재생한 단계마다 처리 과정에 한 줄이 남는다: 「AI 응답 재생 — 미리 저장한 응답이며 지금 AI가 새로 추론한 것이 아닙니다 …」(쓰기 도구를 이 PC에서 다시 불렀으면 그 사실도).

## 2. 녹화를 찾는 규칙 — 수업 AI 자리 + 처리 건 종류
- **수업 AI 자리**는 서버가 정한다(`course_policy.AI_SLOTS` — 제공 흐름에서 뽑은 것). 워커는 AI 단계를 실행하기 직전에 서버에 판정을 묻고(`POST /internal/worker/course-decision`), 받은 자리 이름으로 녹화를 찾는다.

  | 자리 | 흐름 · 단계 |
  |---|---|
  | `c3_cooling/T_agent` · `c3_pm/T_agent` · `c3_spare/T_agent` | 수업 흐름 A 냉각 · B 정기 정비 · C 예비품 구매의 판단 · 제안 |
  | `handover/draft-1` · `draft-2` · `draft-3` | 교대 인수인계의 인계안 작성 · 보완 1 · 보완 2(학생이 가져오는 `ShiftHandover`와 제공 정의 `shift_handover`가 같은 자리) |
  | `question` | 에이전트에게 질문(질문 글이 같아야 같은 녹화 — 띄어쓰기 · 끝 물음표는 무시) |

- **처리 건 종류**: 경보로 연 처리 건은 경보 종류(`pattern`), 질문은 질문 글, 교대는 빈 값. 열쇠 = `sha256(종류|자리)` 앞 16자 = 파일 이름(`<열쇠>.json.gz`, 형식 `hyd-ai-replay/3`).
- 작업 이름 · 흐름 그림의 이름 · 배치는 열쇠에 들어가지 않는다 — 학생이 실라버스대로 bpmn.io에서 이름을 바꿔도 같은 녹화가 재생된다.
- 한 녹화 안의 실행은 차례대로 쓴다(첫 실행, 사람 답 뒤 이어 하기, 결과 형식 교정). 재작업 세대 · 보류 뒤 재평가는 그 차례의 녹화가 있어야 한다. 워커가 다시 켜져 같은 작업을 다시 잡으면 끊긴 실행을 처음부터 다시 낸다.
- **녹화가 없으면 지어내지 않고 그 단계를 멈추며, 학생이 할 수 있는 말로 안내한다** — 예: 교대 보완 2(「교대 인계안은 보완 요청 1번까지 녹화돼 있습니다 … [확인]으로 넘기세요」), 재작업 · 재평가, 녹화와 다른 경보 종류, 수업 밖 단계, 녹화하지 않은 질문(녹화된 질문 목록을 보인다). 「API 키를 넣으면」 · 경보 코드 · 예외 이름은 쓰지 않는다.
- 녹화와 다른 설비(데이터를 고르는 입력)로 시작한 처리 건은 바꿔 끼우지 않고 멈춘다 — 「강의 녹화의 「…」은 설비 HYD-01 처리 건으로 만들었습니다 … 설비를 HYD-01로 해서 다시 시작하세요」. 다른 설비의 실측을 이 설비 것처럼 보이지 않게 하려는 것이다.

## 3. 이 처리 건의 값으로 바꿔 끼우기 · 쓰기 도구 다시 부르기
1. **바꿔 끼우는 값은 처리 건마다 새로 생기는 식별자뿐**: 작업 · 처리 건 · 점유(`process_scope`), 경보 · 사건 id, 시각(`*_at` · `*_since` · 날짜가 박힌 id). 목록은 같은 `id`의 항목끼리 짝짓고, 글 속에서는 id처럼 생긴 값만 한 번에 바꾼다.
2. **쓰기 도구는 이 PC에서 다시 부른다**: 녹화된 AI가 부른 도구 중 서버가 읽기 전용으로 표시하지 않은 것(`submit_decision` · `submit_purchase`)은 녹화 결과를 쓰지 않고, 바꿔 끼운 입력으로 이 PC의 서버를 실제로 부른다. 새로 만든 것의 id(결과 문서 맨 위 `id`)만 뒤의 응답 · 결과에 끼운다. 그래서 등록되는 판단(추천 · 카드 순서)은 학생 PC의 지식 · 시계열 · 업무 데이터로 계산된다. 녹화 때 오류였던 쓰기는 다시 부르지 않는다. 다시 부른 쓰기가 오류면 그 단계는 실패로 끝난다.
3. 녹화가 쓴 도구 서버가 지금 단계의 에이전트에 없으면(학생이 도구 서버를 뺐을 때) 멈추고 「[에이전트]에서 … 도구 서버를 다시 넣고」로 안내한다.
4. 읽기 도구는 다시 부르지 않고 녹화 결과를 쓴다. 그래서 AI의 설명 글은 녹화 때 것이다 — 처리 과정의 재생 알림과 수업 영상으로 구분한다.

## 4. 키 있는 PC — 같은 요청이면 앞선 결과를 다시 쓴다
- 같은 설정(에이전트 프롬프트 · 업무 규칙 · 스킬 본문 · 도구 서버 · 허용 도구 · 모델) + 같은 입력(정의 · 판 · 단계 · 지시와 입력 · 피드백 · 사람 답 · 폼)으로 앞서 **결과 검사를 통과해 제출된** 실행이 있고 그 작업이 지금도 끝남(DONE)이면, AI를 다시 부르지 않고 그 결과를 쓴다. 처리 과정에 「같은 설정 · 같은 입력의 앞선 실행 결과를 다시 썼습니다(새로 추론하지 않음)」가 남는다.
- 재생과 같은 장치다(같은 형식 · 같은 재생기). 쓰기 도구는 이 PC 서버로 다시 불러 새 id를 끼운다. 저장 자리는 워커 작업 공간의 `.ai-cache`(PC 안).
- 설정 · 입력이 하나라도 다르거나, 앞선 실행이 실패였거나, 다시 쓴 결과를 처리 흐름이 돌려보내면 실제 AI로 새로 실행한다.

## 5. 저장분과 보안
- 녹화 파일: 형식, 자리, 처리 건 종류, 업무 이름(표시용), 저장 시각, 실행 목록(세션 id, CLI 이벤트, 결과 파일, 작업 기록 값). 내부 생각은 빼고 도구 호출과 결과는 넣는다.
- **비밀값 가림은 한 곳**(`worker/diagnostics.py` `hide`): 점유 하나 동안 워커의 모든 DB 기록(처리 과정 · 결과 · 보류 · 원문 · 알림), 실행 추적, 결과 사본, 녹화 저장이 그 함수를 지난다. 가리는 값은 워커 환경의 비밀 변수 값, 이번 실행의 도구 서버 env · headers 비밀 값, 「Bearer/HydModel <토큰>」 조각.
- 강의 중계 키는 process만 쥔다. 워커 CLI는 작업에 묶인 실행 토큰만 받는다(관문 장부 `procsvc/course_ledger.py` — 한 실행 · 한 작업 · PC 전체 상한, 최종 비용 방어는 중계 키의 한도).
- 재생 중 워커는 CLI · LLM을 부르지 않는다. 다시 부르는 쓰기 도구는 이 PC의 업무 도구 서버다. 설비 명령은 사람 승인 뒤 process가 이 PC의 가상 설비로 보낸다(AI 키와 무관).

## 6. 강사 — 녹화하기
| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | 수업과 같은 상태의 스택(수업 흐름 · 수업용 기본 지식, 워커 하나). `.env`에 `LLM_API_KEY` | 점검.bat 통과 |
| 2 | 녹화 모드로 시작: `bash scripts/start_all.sh --record` — 한 바퀴 자동은 `bash workspace/개발/scripts/record_replay.sh`(포털 실습을 돌며 녹화, 옛 녹화를 지우지 않음, 끝에 빠진 자리가 있으면 실패) | 워커 `/health`의 `"ai_mode": "record"` |
| 3 | 평소처럼 실습을 진행 · 촬영한다. 성공으로 끝난 실행만 녹화된다(형식 교정 끝까지 실패 · 오류로 끝난 실행은 앞 녹화를 덮지 않는다) | 워커 로그 「AI 응답 저장: …」 |
| 4 | 목록: `bash workspace/개발/scripts/ai_replay_list.sh` — 자리마다 녹화 유무, 빠진 자리가 있으면 종료 코드 1 | `[녹화 없음]` 줄이 없을 것 |
| 5 | 재생 확인(권장): `.env`의 키 줄을 비우고 시작.bat → 같은 실습을 한 번 | 처리 과정에 재생 알림, 끝까지 감 |
| 6 | 녹화 폴더만 main에 커밋 · push(`git add -- it/agent-worker/replay/`, 커밋 뒤 `git show --stat`) | — |

- 워커는 늘 하나다(컨테이너 워커). 개발용 호스트 워커로 녹화할 때는 먼저 `docker compose stop agent-worker`(`RUNBOOK.md` §5).
- 승인 · 실행까지 녹화하려면 에이전트 서비스(`agent`)도 켜져 있어야 한다(승인 때 process가 지금 조건을 다시 묻는다).
- 같은 질문을 두 에이전트에 물어 비교하는 실습은 재생에서 두 답이 같다(같은 자리 · 같은 질문 = 같은 녹화). 비교는 영상으로 보인다.
