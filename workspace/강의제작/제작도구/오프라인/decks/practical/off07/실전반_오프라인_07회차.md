## SLIDE 06 — Task와 End-to-End: 끝났다고 말하는 자리
### 화면 내용
- 유형: 비교
- 메시지: **End-to-End**(종단 간)는 시작 사건에서 최종 결과까지라서, 업무 완료는 Task가 아니라 그 끝에서 판단한다.
- 요소:
  1. Task(작업) | 프로세스 안의 작업 하나 / 예: 원인 진단 · 냉각 조치 제안 / 끝났을 때: 추천안뿐, 설비 명령 없음 / 처리 건 시간의 절반 남짓을 썼다 | 업무의 앞부분
  2. **End-to-End** | 경보에서 결과 보고까지 전체 / 끝났을 때: 명령 처리 · 유온 회복 · 작업지시 / 경계: 작업지시 등록까지, 세척 완료는 밖 / 개선을 견줄 때도 같은 경계로 | 업무의 완료
- 노트: [짚을 곳] 왼쪽 Task → 강조한 오른쪽 End-to-End → 오른쪽 넷째 줄(경계) / · Task: 프로세스 안의 작업 하나(원인 진단 · 냉각 조치 제안) / · Task가 끝나면 추천안뿐, 설비 명령 없음, 그런데 처리 건 시간의 절반 남짓 / · End-to-End(종단 간): 시작 사건에서 최종 결과까지, 끝나면 명령 처리 · 유온 회복 · 작업지시 / · 업무 완료는 Task가 아니라 End-to-End의 끝에서 판단 / · 경계: 이 처리 건은 작업지시 등록까지, 세척 완료는 밖 / · 개선을 견줄 때도 같은 경계로 → 작업 하나가 빨라진 걸 업무 전체로 착각하지 않게 / [다음] 비즈니스 프로세스 · 처리 건 · 오케스트레이션

### 화면 구성
