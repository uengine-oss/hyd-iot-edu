## SLIDE 07 — 승인 · 거절 · 보류가 처리 건에 남기는 것
### 화면 내용
- 유형: 표
- 메시지: 승인만 설비 명령으로 이어지고 거절은 명령 없이 닫히며, 보류는 누가 왜 멈췄는지에 따라 할 일이 다르다.
- 머리: 결정 | 쿨러 사건의 처리 | 처리 건은
- 요소:
  1. **승인** | 승인 역할의 담당자가 추천안을 고른다 / 이때부터 재확인 · 명령 · 재관측 · 작업지시가 이어진다 | 끝까지 처리된다
  2. 거절 | 사유를 적어야 받아들여진다 / 설비 명령 · 업무 처리는 0건이다 | 거절로 닫힌다 / (기록의 값은 반려)
  3. 보류: 사람의 무응답 | 기한 10분이 지나면 지연 알림만 나간다 / 알림 뒤에도 승인 · 거절할 수 있다 | 승인 작업이 / 열린 채 기다린다
  4. 보류: 에이전트의 멈춤 | 근거가 모자라 결과를 내지 않았다 | 다시 처리하거나 / 사람이 닫는다
  5. 보류: 에이전트의 질문 | 필수 업무 정보를 묻고 기다린다 | 답을 받으면 / 이어서 처리한다
- 노트: [짚을 곳] 위 두 줄(결정) → 아래 세 줄(보류라 부를 상황) / · 승인: 이때부터 재확인 · 명령 · 재관측 · 작업지시, 끝까지 처리 / · 거절: 사유 필수, 설비 명령 · 업무 처리 0건, 기록 값은 「반려」 / · 보류는 사람이 누르는 단추 하나가 아니라 세 상황으로 나뉜다 / · 무응답: 기한 10분 뒤 지연 알림만, 자동 승인 · 자동 거절 없음, 알림 뒤에도 결정 가능 / · 에이전트의 멈춤: 근거 부족, 다시 처리하거나 사람이 닫음 / · 에이전트의 질문: 답을 받으면 이어서 처리 / · 겉모습은 같아도 누가 왜 멈췄는지가 달라 할 일이 다르다 → 상태와 사유부터 / [다음] 질문 상황을 점검 요청에서

## SLIDE 26 — Given · When · Then 시나리오 한 편
### 화면 내용
