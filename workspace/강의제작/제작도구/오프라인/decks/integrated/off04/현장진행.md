# 통합반 현장 4회 이론 진행표

실라버스 「통합반 오프라인 정규 10회」 30행의 **50분 기본 진행안**이다. 장마다 던질 물음, 그 답을 가르는 화면 근거, 답이 갈릴 때 되짚을 곳은 PPTX의 장별 발표자 노트에 있다. 시간은 교실 진행을 위한 배정이며, 학생 반응을 포함한 실측은 수업 뒤에 기록한다.

| 누적 시간 | 장 | 교사가 짚을 근거 | 학생이 할 판단 |
|---|---|---|---|
| 0~3분 | 1~4 | 학습목표 세 카드의 꼬리표, 목차 두 단원 | 쿨러 핀 세척의 조건을 판단에 쓰기까지 세 카드를 어떤 순서로 거치는가? |
| 3~13분 | 5~14 | 5장 원문과 옮긴 모양, 7장 업무 DB 줄, 9장 절 첫 문장, 10장 한계와 지식 후보, 12장 기존 식별자 줄, 14장 이름만 확인 갈래 | 「넘겼다면」은 이상인가 초과인가, 번호 줄만 읽으면 빠지는 조건은 무엇인가, 부품 이름만으로 기존 식별자에 이을 수 있는가 |
| 13~20분 | 15~21 | 15장 글자 확인과 뜻 확인, 16장 바뀐 뜻 칸, 18장 수정 · 제외의 조건, 19장 전체 취소, 20장 두 절, 21장 3 · 4단계 | 인용이 원문에 있어도 틀린 지식 후보는 무엇이며, 「24분 이내」는 수정인가 제외인가 |
| 20~26분 | 22~27 | 22장 답하는 물음 셋, 23장 원문 위치의 세 값, 24장 지문, 25 · 26장 판본의 상태, 27장 되돌리기 | 이름만 바꾼 사본은 새 판본인가, 승인 전 1.2판의 저압수 세척은 채택인가 보류인가 |
| 26~29분 | 28~30 | 28장 비유의 다른 점, 29장 사람이 보는 때 · 값과 견주는 법, 30장 규칙 · 입력 · 결과 | 판단에 거듭 쓸 조건은 어느 방식으로 두는가 |
| 29~33분 | 31~34 | 31장 지식과 현재값 칸, 32장 복사한 값과 예약, 33장 읽을 자리, 34장 오래된 기록 · 읽지 못한 값 | 기록 시각이 지난 0개는 지금의 재고 기준 이탈인가 |
| 33~39분 | 35~40 | 36장 조회 전에 적는 기대 답, 37장 CONDITION_OF, 38 · 39장 구축 마디와 직접 만든 결과, 40장 결과 3행 | 관계 하나가 빠지면 어느 칸이 비는가, 결과 3행이 기대 답과 같은지 어느 칸으로 확인하는가 |
| 39~42분 | 41~43 | 41장 따로 확인할 것, 42장 HM-8.2 행, 43장 관계 하나만 지운 뒤의 두 결과 | 돌아온 행이 물은 작업의 답인가, 지식 노드를 지워도 되는가 |
| 42~46분 | 44~48 | 44장 답하는 곳 칸, 45장 결과 1행, 46장 지금 확인할 셋, 47장 found 0, 48장 오른쪽 띠 | 지식 그래프가 답하지 못하는 질문은 어디서 답을 얻는가, 빈 답을 「없다」로 읽어도 되는가 |
| 46~50분 | 49~55 | 49장 헷갈리는 짝, 50장 원문 대조 · 사람 검토 줄, 퀴즈 세 문항과 판단 기준 | 세 문항에 답하고, 각 판단을 가른 화면 근거 하나를 말한다. 55장에서 해설한 뒤 포털 실습으로 넘긴다. |

학생은 온라인 4회차에서 같은 범위를 이미 들었으므로, 장마다 노트의 물음 하나만 던지고 화면 근거로 답을 가른 뒤 넘어간다. 간지 · 목차 · 퀴즈 간지는 읽기만 한다. 답이 갈리는 장에서만 노트의 「답이 갈리면」 줄로 돌아가고, 그 시간은 5~21장(인제스천)과 41~47장(의미와 질문의 경계)에서 먼저 쓴다.

이론 뒤에는 31행에서 포털로 매뉴얼 지식을 원문과 견주어 검토하고 업무 DB 구조를 지식에 잇는다. 32행에서 문서에서 근거 있는 지식을 추출하는 기능을, 33행에서 검토한 지식을 그래프 DB에 적재하고 조회하는 기능을 만든다.

기준 자료는 [현장 덱과 발표자 노트 원고](통합반_오프라인_04회차.md)와 [현장 장별 출처와 순서](구성.json)다.
