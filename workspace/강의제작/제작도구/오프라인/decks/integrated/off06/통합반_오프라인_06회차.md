## SLIDE 08 — SKILL.md 발췌 ②: 절차
### 화면 내용
- 유형: 코드
- 메시지: 절차는 도구와 입력, 권장 순서, 예외를 알려 주며 실제 실행이 그 기준을 지켰는지 확인할 근거가 된다.
- 코드: ## 절차 / 1. context/task.json 의 입력에서 asset · /    pattern · alert.alertId · incident 를 읽는다. / 2. hyd-dmn diagnose(asset, pattern, alert_id) /    — 원인 1순위 · 고장 유형 · 가이드 카드. /    withheld 이면 원인을 지어내지 말고 /    보류로 낸다. / 3. 필요하면 enterprise 로 납기 오더 · /    출하 대기 로트를 확인한다(조회만). / 4. hyd-dmn evaluate_cards(asset, pattern, /    cause, failure_mode) — 후보 · 규정 · 순위. /    추천 안이 왜 이기고 다른 안이 어디서 /    지는지 한 줄씩 정리한다. / 5. hyd-dmn submit_decision(…) /    — 돌려준 id 가 decision_id 다.
- 요소:
  1. 1단계 | 입력을 읽을 파일과 읽을 항목을 가리킨다.
  2. **2단계와 그 끝** | 도구의 이름과 넘길 값, 근거가 없을 때의 행동을 적는다.

## SLIDE 52 — 정답과 판단 기준
### 화면 내용
- 유형: 표
- 메시지: 세 문항은 스킬과 도구의 역할, 응답이 알려 준 범위, 읽기와 쓰기의 경계를 올바로 판단하는지를 확인한다.
- 머리: 문항 | 판단 기준 | 정답
- 요소:
  1. Quiz 1 | 스킬은 방법을 적은 글이고 실행은 서버가 한다. 서버가 연결되지 않으면 그 값을 받지 못한다. | 2번
  2. Quiz 2 | 실패한 조회는 값이 없다는 사실을 알려 주지 않는다. 실패는 실패로 적는다. | 4번
  3. Quiz 3 | 읽기임이 확인된 도구만 허용 목록에 오른다. 표시가 없으면 명세의 기본값대로 읽기 도구로 보지 않는다. | 1번
- 노트: [짚을 곳] 표 세 줄 위에서부터, 판단 기준 → 정답 / · Quiz 1 정답 2번(업무 DB 서버 enterprise 연결): 스킬에 방법은 있고 빠진 것은 실행할 연결. 연결 뒤 호출 권한 · 입력 확인. 오답 1 · 3은 스킬을 고쳐 연결을 못 채우고, 4는 남은 도구까지 줄인다 / · Quiz 2 정답 4번(조회 실패로 확인 못 함): 실패는 재고가 없다는 게 아니라 모른다는 것만 알려 준다. 오답 1 모르는 것을 없는 것으로, 2 지난 값을 지금 값처럼, 3 확인 못 한 사실까지 삭제 / · Quiz 3 정답 1번(read_rows 하나): 기본 판정은 읽기 표시 + 이름이 쓰기 아님만 인정. update_row는 쓰기 표시, export는 표시가 없어 명세 기본값대로 읽기가 아니라 걸러진다. 2번은 표시 없는 도구를 읽기로 본 혼동 / · 맺음: 일하는 방법은 스킬로, 도구는 MCP로 연결하되 권한 · 비밀 · 불완전한 응답을 관리한다 / · 이론 시간에는 일하는 방법을 스킬로 적는 법, 그 스킬이 부르는 도구를 MCP로 잇는 원리, 연결의 권한 · 범위 · 비밀값 · 불완전한 응답을 다루는 기준을 짚었습니다. 이번에는 포털에서 나의 스킬을 써서 5회에 만든 나의 에이전트에 붙였다 떼며 같은 쿨러 이상 질문의 답과 근거를 견주고, 도구 연결 화면에서 업무 도구를 직접 불러 반환값을 에이전트의 근거와 대조해 보겠습니다 / · 이어 VS Code에서 파일 · Git · 시간 MCP를 연결해 접근 범위를 정하고, 점검 자료 조회 함수를 MCP 도구로 만들어 함께 불러 출처와 조회 실패를 확인합니다. 그다음 회의록에서 결정사항 · 담당자 · 완료 시점을 뽑는 SKILL.md를 쓰고, 내 Notion 학습노트를 MCP로 읽어 출제 · 채점하는 퀴즈 에이전트를 만듭니다 / · 다음 회에는 점검 요청에 정보가 빠지거나 요구가 바뀔 때, 에이전트가 멈추고 사람에게 물어야 하는 자리를 다룹니다 / [다음] 실습으로
