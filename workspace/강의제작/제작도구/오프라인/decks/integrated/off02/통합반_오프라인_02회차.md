- 노트: [짚을 곳] 코드 위 MATCH 두 줄 → RETURN → 아래 결과 두 행 → 오른쪽 강조한 결과 행 / · 첫 역량 질문(쿨러를 살피는 센서)을 쿼리로 적는다 / · 절 = 쿼리를 하는 일별로 나눈 한 부분. ## SLIDE 45 — RETURN: 속성값과 노드 · 관계
### 화면 내용
- 유형: 코드
- 메시지: 같은 패턴을 찾더라도 속성값을 받으면 표로 읽고, 노드와 관계를 받으면 연결을 그릴 수 있다.
- 코드: MATCH (c:Component {id: 'comp:cooler'}) /       -[r:MONITORED_BY]->(s:Sensor) / RETURN c.name, s.tag /  / ── 같은 MATCH, 다른 RETURN ── / RETURN c, r, s /  / ── 반환하는 대상(속성 일부 생략) ── / (:Component)  [:MONITORED_BY]  (:Sensor {tag: 'TS1'}) / (:Component)  [:MONITORED_BY]  (:Sensor {tag: 'CE'})
- 요소:
  1. 찾는 패턴 | 두 쿼리 모두 같은 쿨러와 센서의 연결을 찾는다.
  2. 속성값 반환 | c.name, s.tag는 각 노드의 값이다. 이름과 태그 두 열을 받는다.
  3. **노드 · 관계 반환** | c, r, s는 구성 요소, 계측 관계, 센서다.
  4. 표와 그래프 | 두 결과 모두 두 행이다. 아래 결과를 그래프로 그리면 쿨러 하나와 센서 둘이 나타난다.
- 노트: [짚을 곳] 코드 위 속성값 RETURN → 아래 「같은 MATCH, 다른 RETURN」 → 반환 대상 두 줄 → 오른쪽 강조한 노드 · 관계 반환 / · 이름 · 태그 목록이면 속성값, 연결된 모양을 보려면 노드와 관계 자체를 받는다 / · 생각할 시간(약 15초): 두 RETURN이 받는 것이 값인지 노드 · 관계인지 / · 위: 표의 칸에 글자. 아래: 구성 요소 노드 · 계측 관계 · 센서 노드(관계에도 변수를 붙였다) / · 패턴이 같으니 둘 다 두 행. 아래 결과를 그리면 쿨러가 같은 노드라서 선은 한 쿨러에서 센서 둘로 뻗는다 / · 속성값만 받은 표를 그래프로 바꾼다고 관계가 생기지 않는다. MATCH = 찾을 범위, RETURN = 그중 무엇을 꺼낼지 / [다음] 반환한 값이 겹치는 결과 행의 정리

## SLIDE 46 — DISTINCT: 반환한 값의 중복 제거
### 화면 내용
- 유형: 표
- 메시지: DISTINCT는 반환하는 값의 조합이 같은 행을 하나로 남기며, 저장된 노드를 지우지 않는다.
- 머리: 같은 MATCH의 반환 절 | 결과 | 남는 행
- 요소:
  1. RETURN c.name | 오일 쿨러 / 오일 쿨러 | 2행

  4. 중복 제거(DISTINCT) | 쿨러 → 계측 채널 둘의 같은 패턴에서 반환 절만 바꾼다 / 반환한 모든 열의 값이 같을 때 한 행으로 남긴다 | 결과 정리
- 노트: [짚을 곳] 표 첫 줄(이름만, 2행) → 강조한 둘째 줄(DISTINCT, 1행) → 셋째 줄(이름 + 태그, 2행) → 넷째 줄 설명 / · 이름 열만 남겨도 MATCH가 찾은 연결은 여전히 둘 → 같은 이름이 두 번 / · DISTINCT = 중복 제거. 반환한 값의 조합이 같은 행을 하나로 남긴다. 이름만이면 쿨러가 한 번 / · 이름 + 태그를 받으면 조합이 달라(쿨러 · 유온 센서와 쿨러 · 냉각 효율 채널) 두 행 그대로 → 열 하나가 아니라 반환한 열 전체의 조합을 본다 / · DISTINCT는 저장된 센서 · 관계를 지우지 않는다. 보여 줄 결과만 정리 / [다음] 목록 말고 개수가 필요할 때

### 화면 내용

## SLIDE 56 — 기존 노드를 찾아 관계 생성
### 화면 내용

- 메시지: 관계는 양 끝 노드를 식별자로 먼저 찾은 뒤, 스키마에 정한 방향으로 그 사이에 만든다.
