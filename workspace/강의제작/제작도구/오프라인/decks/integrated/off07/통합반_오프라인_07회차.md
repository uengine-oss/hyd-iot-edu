## SLIDE 21 — 시나리오 한 편: 승인 단계의 거절
### 화면 내용
- 유형: 코드
- 메시지: 거절의 시나리오는 Then에 일어나지 않아야 할 일까지 적어, 금지 조건이 지켜지는지를 확인하게 한다.
- 코드: Feature: 승인 단계 /   Scenario: 담당자가 추천을 거절한다 /     Given 에이전트가 추천안을 내어 /           승인 단계가 열려 있다 /     When  승인 권한이 있는 담당자가 /           사유를 적고 거절한다 /     Then  설비 명령이 만들어지지 않는다 /     And   업무 처리가 일어나지 않는다 /     And   처리 건이 거절로 닫힌다
- 요소:
  1. 서식 | 기능(Feature) 아래에 시나리오를 Given · When · Then · And로 적는 이 서식의 이름이 **Gherkin**이다.
  2. Given | 승인 단계가 열린 상태까지가 전제이다.
  3. When | 행동은 거절 하나뿐이다.
  4. **Then · And** | 기대 결과를 한 줄에 하나씩 적는다. And는 앞줄과 같은 부분을 잇는다.

- 노트: [짚을 곳] 왼쪽 코드 Feature → Scenario → Given · When · Then · And, 오른쪽 요소 → 강조한 Then · And / · 앞의 거절을 구조가 보이는 글로 적은 예: 맨 위 기능 이름, 그 아래 시나리오 이름, 이어서 전제 · 행동 · 기대 결과 / · 이 서식의 이름이 Gherkin. Given은 승인 단계가 열린 상태까지, When은 거절 하나뿐 / · And: 앞줄과 같은 부분을 잇는다. 명령이 없다 + 업무 처리도 없다 + 거절로 닫힌다 / · 볼 점: 하지 않아야 할 일도 기대 결과로 적는다 → 금지 조건이 지켜지는지 확인 / · Gherkin은 BDD에서 널리 쓰는 표현 방법. 서식을 썼다고 자동 시험이 완성되진 않고 실행 · 대조를 맡을 코드에 연결해야 한다 / [다음] Then의 조건
