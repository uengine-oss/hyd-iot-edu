- 노트: [짚을 곳] 왼쪽 클래스의 정의와 설비 · 센서 클래스의 속성 → 오른쪽 강조한 인스턴스 → 설비 세 대 → 센서 두 줄의 값 / · 관계 그림에서 원마다 적은 Asset · Sensor 같은 종류를 이제부터 클래스라고 부른다. 클래스 = 공통 특성을 가진 대상의 유형, 인스턴스가 채울 속성을 정한다 / · 인스턴스 = 그 클래스에 속하는 대상 하나하나. HYD-01 · 02 · 03은 모두 설비이면서 서로 구별되는 세 대 → 같은 종류의 설비와 실제 설비 한 대는 다르다 / · 속성값 = 클래스가 정한 속성마다 인스턴스가 실제로 채운 값. 유온 센서는 태그 TS1 · 단위 ℃ · 계산 채널 아님(false), 냉각 효율 채널은 CE · % · 계산 채널(true) / · 같은 속성을 다른 값으로 채웠을 뿐이라 두 센서를 같은 줄에서 비교한다 / · 쓰임: 새 센서는 클래스를 만들지 않고 인스턴스를 더한다. 「센서 전부」는 클래스로, 「유온 센서의 단위」는 인스턴스의 속성값으로 묻는다 / [다음] 유온의 한계는 어디에 두나

## SLIDE 06 — 한계를 둘 자리: 속성과 관계
### 화면 내용

- 메시지: 태그처럼 칸 하나로 끝나는 값은 속성으로 두고, 한계를 가진 유온은 상태 변수로 따로 두어 관계로 잇는다.
