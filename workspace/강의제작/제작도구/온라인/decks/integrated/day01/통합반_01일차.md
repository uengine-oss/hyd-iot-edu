## SLIDE 07 — AI와 주고받으며 고치고, 모르는 곳은 깊게 판다
### 화면 내용
- 유형: 흐름
- 아이콘: microphone, messages, arrow-down, repeat
- 메시지: 넓게 말하고 주고받으며 고치되, 모르는 곳은 파인만 기법(Feynman Technique)으로 쉬운 말까지 파고든다.
- 요소:
  1. 넓게 말한다 | 배운 범위를 / 처음부터 끝까지 / 일단 말해 본다
  2. 주고받는다 | 지적을 듣고 / 이해한 대로 다시 말해 / 「이런 건가요?」 / 하고 되묻는다
  3. 깊게 판다 | 모르는 곳은 / 초등학생도 알게 / 풀어 달라고 해 / 쉬운 말부터 잡는다

## SLIDE 23 — 세 보안 영역과 DMZ: 값은 공장 안에서 내보낸다
### 화면 내용

- 메시지: OT와 IT 사이에 완충 구역 **DMZ**(Demilitarized Zone)를 두어, 망을 **세 보안 영역**으로 나눈다.

DMZ 중계 = DMZ에서 값을 받아 사무실 쪽으로 넘겨 주는 프로그램. 받은 값을 IT의 이벤트 로그에 옮겨 쓰고, 분석과 AI는 쌓인 값을 읽기만 할 뿐 OT로 접속하지 않는다 / · 거꾸로 공장으로 가야 하는 것(사람이 승인한 조치)도 바깥에서 가지고 들어가지 않는다. DMZ에 두면 공장 쪽이 나와서 가져간다. 이 화면은 값이 나가는 길만, 들어가는 길은 층을 끝까지 올라간 뒤에 / · 문단속이 단순해진다: 공장 문은 공장 쪽에서만 열고 나오고, 바깥에서 두드려 여는 문은 두지 않는다 → DMZ가 뚫리더라도 공격자가 거기서 공장 안으로 마음대로 들어가기가 어려워진다(들어갈 수 없다가 아니다) / · 세 보안 영역 = 망을 OT · DMZ · IT 셋으로 나눈 것. IT와 OT는 DMZ에서만 만난다 / · 현업 이름(화면 맨 아래 줄): 공장 망을 설비 쪽부터 사무 쪽까지 단계로 나눈 그림은 Purdue 모델, 구역과 그 사이 통로를 나누는 보안 방식은 IEC 62443 표준 / [다음] 공장 안을 이렇게까지 막는 또 하나의 까닭

  2. 프로세스 엔진 | 승인된 것만 / 요청으로 만든다 | IT

  4. 브로커 · 엣지 | OT 안에서 / 요청을 전한다 | OT

- 노트: [짚을 곳] 세 구역 이번에는 왼쪽부터 IT → DMZ → OT → 왼쪽 승인 담당자부터 → 가운데 명령 관문 → 맨 오른쪽 PLC와 안전계장 / · 비유: 식당 손님은 주방에 들어가 불을 직접 켜지 않고 주문서를 낸다. 주방이 지금 만들 수 있는지 보고 조리 → 사무실 쪽도 설정값을 직접 쓰지 않고 「이걸 바꾸고 싶다」는 요청을 보낸다 / · 올라온 길을 거꾸로 타지 않고 따로 정해 둔 좁은 길 하나로. 자리마다 그 일을 가장 잘 아는 쪽이 하나씩 정한다 / · 승인 담당자가 허락하면 프로세스 엔진이 승인된 것만 요청으로 만들어 기록으로 남기고 보낸다 / · 명령 관문 = IT와 OT 경계에 둔 검증 통로 하나. 바깥에서 설비로 가는 요청은 모두 이 한 곳. 공장 안 사정은 모르니 정해진 길로 온 승인된 요청인지 자격만 본다. IT와 OT 경계에서 요청을 검사하는 곳이 이 한 곳이라 지키기 쉽다 / · 바깥에서는 공장 안으로 들어가지 않는다고 했다 → 「이 요청은 어떻게 안으로 들어가나」: 요청이 공장 안으로 들어가는 건 맞다. 다만 앞에서 본 택배 보관함 그대로다. 명령 관문이 밀어 넣지는 않는다. 통과시킨 요청을 올려 두기만 하고, 공장 쪽 브로커가 수시로 와서 「우리한테 온 요청 있어요?」 하고 가져간다. 화살표 위의 「OT가 가져감」이 이 뜻. 요청이 들어갈 때도 먼저 움직이는 쪽은 공장 / · 설비를 바꾸는 요청이 지나는 길이라 값이 나가는 길보다 위험하다 → 명령 관문 하나에 기대지 않고 심층 방어처럼 겹을 더 둔다 / · 브로커와 엣지가 요청을 맨 오른쪽 PLC에 전하면 PLC가 지금 설비 상태를 보고 받을지 정한다. 운전원이 지금 직접 다루는 중이거나 위험한 상태면 바깥 요청을 받지 않는다. 승인은 「바꿔도 된다」는 허락이지 「지금 당장 하라」는 강제가 아니다 = 설비 곁 PLC의 검사 / · PLC와 함께 적힌 안전계장은 이 길과 따로 서 있다. 어떤 요청이 들어왔든 상관없이 설비를 지켜보고 있어서, 잘못된 요청이 명령 관문과 PLC를 다 지나가도 설비가 위험해지면 안전계장이 세운다 / · 무엇을 할지는 IT가 정해도, 지금 실제로 해도 되는지는 명령 관문이 아니라 설비 곁 PLC가 정한다 / [다음] 요청을 보낸 뒤 따로 묻는 세 가지
### 화면 구성
연속된 IT · DMZ · OT 영역 위에 다섯 자리를 놓고, 자리마다 그곳이 정하는 것 한 줄을 둔다. 검사 항목 목록과 토픽 이름은 싣지 않는다.
### 제작 기준
바깥 요청은 검증 통로 하나를 거치고 최종 수용은 제어 영역: NAMUR NE 178 Verification of Request(현업조사 12 §1-C · §1-E C2). 결정이 층마다 나뉨(무엇을 할지 · 허락할지 · 지금 받아들일지 · 물리적으로 되는지): 현업조사 16 §5. 요청 → 경계 → OT 안의 수용 → 결과, OT 쪽이 연 연결: 현업조사 16 §4-2 ① ~ ⑤. AI 권고를 기존 변경 관리 절차에 넣음: CISA 외 AI-OT 지침 p.18-19. 실라버스 온라인 8행 끝 문장(승인된 조치가 설비에 닿을 때 명령 관문과 설비 곁 PLC가 각각 무엇을 검사하는지와 그 까닭).
