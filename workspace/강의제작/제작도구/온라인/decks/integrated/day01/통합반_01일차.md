## SLIDE 05 — AI가 정리한 자료와 내가 아는 것
### 화면 내용
- 유형: 비교
- 아이콘: file-text, microphone
- 메시지: AI가 정리한 요약은 읽을 때 다 아는 듯한 착각을 주기 쉽고, 자료를 덮고 말해 봐야 막힌 곳이 드러나 내 것이 된다.
- 요소:
  1. AI에게 요약을 맡긴다 | 자료를 넘기면 보기 좋게 요약해 준다 / 술술 읽혀 다 아는 것 같은 착각이 든다 / 덮으면 설명이 막혀 다시 공부해야 한다 | 유창성 착각(Illusion of Fluency)
  2. **AI에게 바로 덤벼든다** | 자료를 덮고 AI에게 바로 말해 본다 / 설명하다 막히거나 틀리는 곳이 드러난다 / 고쳐 가며 말한 내용이 내 것이 된다 | 내가 아는 것
- 노트: [짚을 곳] 「AI에게 요약을 맡긴다」 → 강조한 「AI에게 바로 덤벼든다」 / · 설명하려니 막히는 그 막힘은 AI가 요약해 준 글을 읽을 때 더 잘 숨는다 / · 요약은 술술 읽혀 다 아는 것 같다 → 착각. 술술 읽혀서 안다고 느끼는 것 = 유창성 착각 / · 덮고 설명해 보면 막힌다. 이해했다는 건 내 말로 설명할 수 있다는 것, 설명이 안 되면 아직 내 것이 아니다 / · 결국 그 요약을 다시 붙잡고 공부해야 하니, 맡겨서 아낀 줄 알았던 공부를 다시 하는 셈 / · 그래서 바로 덤벼든다: 요약을 맡기지 말고 자료를 덮은 채 배운 걸 AI에게 말로 해 본다. 막히고 틀리는 곳이 그 자리에서 드러난다 / [다음] AI에게 어떻게 설명하나
### 화면 구성
기본 배치
### 제작 기준
실라버스 온라인 6행. 「안다고 착각한다」 · 「꺼내 본 내용이 남는다」의 근거: 같은 원문을 다시 공부한 쪽은 기억할 자신감이 더 높았고, 5분 뒤에는 다시 공부한 쪽이, 2일 · 1주 뒤에는 피드백 없이 자유 회상으로 꺼내 본 쪽이 더 많이 기억했다 — Roediger · Karpicke(2006), Test-Enhanced Learning: Taking Memory Tests Improves Long-Term Retention, Psychological Science 17(3):249-255. AI에게 말로 설명하고 지적을 받아 고치는 방법은 이 연구의 범위 밖이며 1차 자료 없음 — 일반 학습 원리로 쓴다. 유창성 착각: 쉽게 읽히는 자료를 보면 안다고 과대평가하는 현상 — Bjork · Dunlosky · Kornell(2013), Self-Regulated Learning, Annual Review of Psychology 64.

## SLIDE 07 — AI와 주고받으며 고치고, 모르는 곳은 깊게 판다
### 화면 내용
- 유형: 흐름
- 아이콘: messages, arrow-down, repeat
- 메시지: 내 말로 설명하고 모르는 곳은 쉬운 말까지 내려가 채워 다시 설명하는 고리가 파인만 기법(Feynman Technique)이다.
- 요소:
  1. 주고받는다 | 짚어 준 곳을 듣고 / 이해한 대로 / 다시 말해 보며 / 맞는지 되묻는다
  2. 깊게 판다 | 모르는 곳은 / 초등학생도 알게 / 풀어 달라고 해 / 쉬운 말부터 잡는다
  3. **다시 말한다** | 쉬운 말에서 / 한 단계씩 올라와 / 처음부터 끝까지 / 다시 설명한다
- 노트: [짚을 곳] 주고받는다 → 깊게 판다 → 강조한 「다시 말한다」 / · 드러난 곳을 고치는 차례. 내 말로 설명해 보고, 모르는 곳은 쉬운 말까지 내려가 채운 뒤 다시 설명하는 이 고리 전체 = 파인만 기법(물리학자 파인만의 이름을 딴 방법) / · 주고받는다: 지적을 듣고 끝내지 않고 이해한 대로 다시 말해 본다. 「그럼 이건 이렇게 흘러가는 거죠? 이거랑 비슷한 거예요?」 → AI가 「살짝 달라요」 하며 다시 바로잡는다. 들은 말을 내 말로 바꿔 해 봐야 정말 알아들었는지 드러난다 / · 깊게 판다: 설명이 또 어려우면 「초등학생도 알아듣게 풀어 줘」. 모르는 곳이니 여기서 AI의 풀이를 받는다. 어려운 말을 어려운 말로 들으면 또 막히니 가장 쉬운 말까지 내려가 거기서부터 잡는다 / · 다시 말한다: 쉬운 말에서 한 단계씩 올라와 처음부터 끝까지 다시 설명. 원리를 잡고 나면 어려운 표현도 보는 순간 감이 온다 / [다음] 실제로 주고받는 대화 한 장면
### 화면 구성
흐름 세 칸을 고치는 차례로 놓고 마지막 칸을 강조한다.
### 제작 기준
실라버스 온라인 6행. 쉬운 말까지 내려갔다 올라오는 순서는 일반 학습 원리로 쓴다. 파인만 기법: 개념을 아이에게 가르치듯 쉬운 말로 설명해 보고, 막히는 곳을 원자료로 돌아가 채운 뒤 다시 단순하게 설명하는 학습법(물리학자 Richard Feynman의 이름을 딴 통칭). 이름은 6장의 설명하기부터 이 장의 다시 말하기까지 고리 전체에 붙인다.

- 노트: [짚을 곳] OT → IT → 먼저 지킬 것(멈추지 않음 · 안전, 허가된 사람만 보고 바꿈) / · OT(Operational Technology, 운영 기술) = 공장 안 설비 쪽 망, IT(Information Technology, 정보 기술) = 사무실 컴퓨터 쪽 망 / · 지금까지 본 설비 · PLC · 엣지 · 브로커는 OT, 값을 분석하고 AI가 원인을 따지는 서버는 IT / · OT: 설비를 감시하고 움직이는 망. 잘못된 명령 하나가 곧 사고 → 설비가 멈추지 않는 것, 사람과 설비의 안전이 먼저 / · IT: 업무 데이터 · 분석 · AI. 메일 · 인터넷과 이어져 늘 뚫릴 가능성 → 허가된 사람만 보고 바꾸게 하는 것이 먼저 / · 줄 하나로 바로 이으면 사무실 PC 한 대가 뚫렸을 때 그 줄을 타고 PLC까지 → 정보 사고가 그대로 설비 사고 / · 사무실 쪽이 멈추거나 뚫려도 공장은 혼자 돌아야 하니 두 망을 나누고 직접 잇지 않는다 = 망 분리. 그래도 값은 건너가야 하니 건너는 자리를 따로 / [다음] 두 망 사이의 완충 구역
### 화면 구성
두 망을 같은 물음(어디의 망인가, 무엇을 하나, 위험, 먼저 지킬 것)으로 맞세운다.

## SLIDE 23 — 세 보안 영역과 DMZ: 값은 공장 안에서 내보낸다
### 화면 내용
- 유형: 구조
- 메시지: OT와 IT 사이에 완충 구역 **DMZ**(Demilitarized Zone)를 두어, 망을 **세 보안 영역**으로 나눈다.
- 참고: 관련 표준 | Purdue 모델 · IEC 62443
- 영역: OT | DMZ | IT
- 요소:
  1. 현장 · PLC · 운전 화면 | 제어와 조작 | OT
  2. 브로커 | 지금 값의 허브 | OT
  3. **DMZ 중계** | OT가 내보낸 값을 받아 넘긴다 | DMZ
  4. 이벤트 로그 | 넘겨받은 값을 쌓는다 | IT
  5. 분석 · AI | 쌓인 값을 읽는다 | IT
- 연결: 브로커 > DMZ 중계 ; DMZ 중계 > 이벤트 로그
- 노트: [짚을 곳] 세 칸 OT → DMZ → IT → 브로커에서 DMZ 중계로 가는 화살표 → 이벤트 로그 → 분석 · AI / · DMZ(Demilitarized Zone, 원래 비무장 지대) = OT와 IT 사이에 두는 완충 구역 / · 비유: 아파트 택배 보관함. 기사는 집 안까지 안 들어오고 보관함에 넣어 두면 주민이 나와 꺼내 간다. 반품도 주민이 나와 넣어 두고 기사가 거기서 가져간다. 물건은 양쪽으로 오가지만 바깥 사람이 집 안으로 들어오는 일은 없다. 보관함까지 나오는 건 주민 쪽 / · 공장도 같다: 값은 공장 쪽이 DMZ까지 내보내고 바깥은 DMZ에서만 꺼내 간다(브로커 → DMZ 중계 화살표). DMZ 중계 = DMZ에서 값을 받아 사무실 쪽으로 넘겨 주는 프로그램. 받은 값을 IT의 이벤트 로그에 옮겨 쓰고, 분석과 AI는 쌓인 값을 읽기만 할 뿐 OT로 접속하지 않는다 / · 거꾸로 공장으로 가야 하는 것(사람이 승인한 조치)도 바깥에서 가지고 들어가지 않는다. DMZ에 두면 공장 쪽이 나와서 가져간다. 이 화면은 값이 나가는 길만, 들어가는 길은 층을 끝까지 올라간 뒤에 / · 문단속이 단순해진다: 공장 문은 공장 쪽에서만 열고 나오고, 바깥에서 두드려 여는 문은 두지 않는다 → DMZ가 뚫리더라도 공격자가 거기서 공장 안으로 마음대로 들어가기가 어려워진다(들어갈 수 없다가 아니다) / · 세 보안 영역 = 망을 OT · DMZ · IT 셋으로 나눈 것. IT와 OT는 DMZ에서만 만난다 / · 현업 이름(화면 맨 아래 줄): 공장 망을 설비 쪽부터 사무 쪽까지 단계로 나눈 그림은 Purdue 모델, 구역과 그 사이 통로를 나누는 보안 방식은 IEC 62443 표준 / [다음] 공장 안을 이렇게까지 막는 또 하나의 까닭
### 화면 구성
OT · DMZ · IT 세 띠. 데이터 화살표는 왼쪽에서 오른쪽으로만 간다. 오른쪽에서 왼쪽으로 가는 화살표를 그리지 않는다.
### 제작 기준
「All connections with the OT environment should be initiated as outbound connections from within the OT environment.」: OT 연결 원칙 p.11(현업조사 19 C2가 12 §1-B의 근거를 이 문서로 바로잡음). OT와 IT의 외부 연결은 DMZ를 거침: 같은 문서 p.19 · p.25(현업조사 19 C1). Purdue 모델(망 층)과 IEC 62443 영역 · 통로(보안 경계): 현업조사 12 §1-A. OT가 밀어내고(push) 바깥은 DMZ에서만 끌어감: CISA Defense in Depth 2016 §2.4.2(현업조사 16 §4-2 ①). AI는 OT 밖에서 밀려 나온 데이터를 씀: CISA 외 AI-OT 지침 p.15 · p.20(현업조사 12 §1-B 3).

## SLIDE 24 — 오래된 현장 규약과 심층 방어
### 화면 내용
- 유형: 풀이
- 메시지: 보호 기능이 없는 오래된 현장 규약은 OT 안에 가두고, 여러 겹의 방어로 보완한다.
- 요소:
  1. 오래된 현장 규약 | Modbus는 처음부터 인증 · 암호화 없이 만들어졌다. / 깔린 장비가 많아 한꺼번에 바꾸기 어렵다. | Legacy Protocol

### 화면 구성
약점(규약) → 가두기(격리) → 겹겹 방어의 순서로 세 줄을 둔다.
### 제작 기준
전통 Modbus의 인증 · 무결성 부재와 TLS 보안판: Modbus Organization — Modbus Security. 「Default to the latest secure versions of industrial protocols (… Modbus to Modbus Security, OPC DA to OPC UA).」: OT 연결 원칙 p.18(현업조사 16 §3). 여러 겹의 구역 방어와 3구역 구성: CISA Defense in Depth 2016 §2.4(현업조사 12 §1-B 5). 경계와 PLC 앞의 스키마 검사: OT 연결 원칙 p.17(현업조사 16 §4-2 ②).

### 화면 구성
연속된 IT · DMZ · OT 영역 위에 다섯 자리를 놓고, 자리마다 그곳이 정하는 것 한 줄을 둔다. 안전계장은 요청을 받는 자리가 아니므로 이 길에 두지 않는다. 검사 항목 목록과 토픽 이름은 싣지 않는다.
### 제작 기준
바깥 요청은 검증 통로 하나를 거치고 최종 수용은 제어 영역: NAMUR NE 178 Verification of Request(현업조사 12 §1-C · §1-E C2). 결정이 층마다 나뉨(무엇을 할지 · 허락할지 · 지금 받아들일지 · 물리적으로 되는지): 현업조사 16 §5. 요청 → 경계 → OT 안의 수용 → 결과, OT 쪽이 연 연결: 현업조사 16 §4-2 ① ~ ⑤. PLC가 인터록 조건이면 바깥 요청을 받지 않음: 현업조사 12 §1-D H1, 16 §4-2 ④. AI 권고를 기존 변경 관리 절차에 넣음: CISA 외 AI-OT 지침 p.18-19. 「명령 관문」은 실라버스 온라인 8행 끝 문장의 낱말이고 정해진 영문 이름이 없어 괄호를 달지 않는다.
