- 노트: [짚을 곳] 코드 두 줄: MERGE 줄의 찾는 자리 { } → SET 줄 → 오른쪽 짚을 점 셋(셋째가 피할 꼴) / · MERGE = 적은 패턴 전체로 기존 대상을 찾고, 없을 때만 만든다. 그래서 같은 문장을 여러 번 돌려도 노드는 하나 / · 찾는 자리 { }에는 식별자만 적는다. 식별자는 이름이 바뀌어도 그대로인 값이었다 / · 이름 · 계통처럼 바뀔 수 있는 값은 SET으로 따로 넣는다. SET = 노드의 속성 값을 넣거나 바꾼다 / · 피할 꼴: MERGE (c:Component {id: 'HYD-02:cooler', name: '오일 쿨러'})처럼 이름까지 찾는 자리에 적으면, 나중에 이름을 고쳐 다시 돌릴 때 그 패턴 전체에 맞는 노드가 없어 새로 만들려 한다. 유일 제약이 없으면 같은 id의 노드가 둘, 있으면 그 문장이 거절된다 / · 그래서 자료를 다시 넣어도 늘지 않게 하려면 MERGE의 찾는 자리에 식별자만 둔다 / [다음] 이제 처음 물음을 쿼리로 꺼낼 수 있나

## SLIDE 55 — 처음 물음을 Cypher 쿼리 한 문장으로
### 화면 내용
- 유형: 코드
- 메시지: 손으로 따라가던 길을 MATCH · WHERE · RETURN 한 문장으로 적으면, 한계가 있는 센서 한 행이 나온다.
- 코드: MATCH (a:Asset {id: 'HYD-02'}) /       -[:HAS_COMPONENT]->(c:Component {id: 'HYD-02:cooler'}) /       -[:MONITORED_BY]->(s:Sensor) /       -[:OBSERVES]->(q:Quantity) / WHERE s.limit IS NOT NULL / RETURN q.name, s.tag, s.limit, s.unit

  1. MATCH | HYD-02 → 오일 쿨러 → 센서 → 물리량, 손으로 따라간 그 길
  2. WHERE | 센서 다섯 가운데 한계가 적힌 것만
  3. 결과 1행 | 유온 · TS1 · 65.0 · ℃

## SLIDE 69 — Quiz 3. 관계까지 한 번에 적은 MERGE
### 화면 내용
- 유형: 문답
- 메시지: HYD-04:cooler와 HYD-04:TS1 노드는 있고 둘 사이 관계만 없는 DB에서, 유일 제약 없이 아래 MERGE를 돌렸다.
