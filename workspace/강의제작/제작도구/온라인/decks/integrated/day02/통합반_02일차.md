## SLIDE 05 — 클래스와 인스턴스
### 화면 내용
- 유형: 비교
- 메시지: 클래스는 공통 특성을 가진 대상의 유형이고, 인스턴스는 그 유형에 속하는 개별 대상이다.
- 요소:
  1. 클래스(Class) | 공통 특성을 가진 대상의 유형 / 설비(Asset), 센서(Sensor) / 인스턴스가 쓸 속성과 관계를 정한다 | 공통 정의
  2. **인스턴스(Instance)** | 클래스에 속하는 개별 대상 / Asset: HYD-01 · HYD-02 · HYD-03 / Sensor: 유온 센서 · 냉각 효율 채널 / 「유온 센서는 센서의 하나이다」 | 개별 대상
- 노트: [짚을 곳] 오른쪽 설비 세 대 → 왼쪽 클래스 → 오른쪽 강조한 인스턴스 → 아래 센서 둘 → 맨 아래 문장 / · 경보 설비를 가리키려면 세 대는 서로 구별돼야 하고, 동시에 모두 설비라는 공통점이 있다. 관계 그림에서 원마다 적은 Asset · Sensor 같은 종류를 클래스라는 이름으로 정의한다 / · 클래스 = 공통 특성을 가진 대상의 유형(설비 · 센서). 인스턴스가 적을 정보와 연결할 대상을 공통으로 정한다 / · 인스턴스 = 그 클래스에 속하는 대상 하나하나. 같은 정의를 쓰되 이름과 내용은 각자 / · 유온 센서와 냉각 효율 채널: 둘 다 센서 클래스의 인스턴스, 서로 다른 대상. 읽는 법 「유온 센서는 센서의 하나이다」 / · 쓰임: 새 센서는 클래스를 새로 만들지 않고 내용만 채운다. 「센서 전부」는 클래스로, 「유온 센서의 단위」는 인스턴스로 묻는다 → 찾는 범위가 다르다 / · 인스턴스 하나가 무엇을 하나로 셀지(실물 한 대 · 같은 기종의 여러 설비가 함께 가리키는 공통 구성 하나)는 모델이 답할 질문이 정한다. 기종 전체의 정보면 공통 구성, 한 대의 이력이면 실물마다 / · 두 질문을 견준다. 자료의 클래스를 물으면 클래스, 경보 설비를 물으면 설비 코드를 대조해 고른 한 인스턴스 / [다음] 센서에 채우는 값

## SLIDE 06 — 센서 클래스의 속성과 속성값
### 화면 내용
- 유형: 표
- 메시지: 속성값(Property Value)은 클래스가 정한 속성마다 인스턴스가 채운 내용이다.
- 머리: 속성(Property) | 유온 센서의 속성값 | 냉각 효율 채널의 속성값
- 요소:
  1. 식별자(id) | sen:ts1 | sen:ce
  2. 이름(name) | 유온 센서 | 냉각 효율
  3. 태그(tag) | TS1 | CE
  4. 단위(unit) | ℃ | %
  5. 계산 채널 여부(virtual) | false: 직접 계측 | true: 다른 계측값으로 계산
- 노트: [짚을 곳] 왼쪽 속성 열 → 가운데 유온 센서 → 오른쪽 냉각 효율 채널 / · 값을 담는 항목이 속성. 그 칸에 인스턴스마다 실제로 채운 내용이 속성값 → 인스턴스끼리 같은 줄에서 비교한다 / · 태그 줄: 어느 센서든 같은 태그 속성을 읽어 계측 데이터를 찾는다. 단위 줄: 섭씨와 퍼센트, 같은 속성을 다른 값으로 채웠을 뿐 / · 계산 채널 여부: 직접 재는 유온 센서 false, 계산하는 냉각 효율 채널 true / · 세로로 읽으면 한 센서의 값, 가로로 읽으면 두 센서의 비교. 어느 대상의 값인지는 같은 열의 식별자까지 / · 50이라는 숫자의 뜻은 채널의 태그와 단위로 확인한다. 직접 계측값과 계산값은 검토할 원자료가 다르다 / [다음] 센서와 물리량의 정상값 · 한계
### 화면 구성
유온 센서와 냉각 효율 채널의 속성을 하나의 대응표로 보인다. 두 값 열은 같은 폭 · 같은 글씨로 둔다. 공통 항목과 두 인스턴스의 값을 같은 가로줄에서 비교하도록 하며 별도 그림은 만들지 않는다.
### 제작 기준
`it/neo4j/v2/schema.json`의 Sensor 정의와 속성 다섯, `it/neo4j/v2/instances.cypher` 센서 UNWIND의 sen:ts1 · sen:ce 실제 값. 사실표 2.3. 저장 이름은 「냉각 효율 (가상)」이고 화면에는 「냉각 효율」로 적는다. 속성값은 같은 클래스 안에서도 다를 수 있다는 뜻이며 모든 칸이 반드시 달라야 한다는 주장이 아니다.

## SLIDE 07 — 센서와 상태 변수
### 화면 내용
- 유형: 비교
- 메시지: 같은 유온을 재는 계측 채널을 하나 더 정의하면 채널은 둘이 되고, 두 채널이 쓸 한계는 유온 한 곳에 남는다.
- 요소:
  1. 센서(Sensor) | 값을 내놓는 계측 채널 / 유온 센서: sen:ts1 / 태그 TS1 · 단위 ℃ / 채널을 더하면 식별자 1개 → 2개 | 재는 쪽
  2. **상태 변수(StateVariable)** | 설비의 상태를 나타내는 물리량 / 유온: sv:ts1 / 이 설비의 정상값(normal) 48 ℃ · 한계(limit) 65 ℃ / 두 채널이 재는 유온 1개 · 한계 1개 | 재어지는 쪽
- 노트: [짚을 곳] 왼쪽 유온 센서의 식별자와 태그 → 오른쪽 유온의 식별자와 이 설비의 정상값 · 한계 → 양쪽 마지막 줄 / · 상태 변수 = 설비의 상태를 나타내는 물리량. 정상값과 한계가 붙는다. 이 설비에서는 유온의 한계 65 ℃ — 닿으면 설비가 멈추도록 정한 값 / · 센서를 바꿔도 관리할 유온은 같다 → 허용할 온도는 그대로 / · 같은 유온을 재는 계측 채널을 하나 더 정의하면 식별자는 둘, 유온은 하나. 한계를 채널마다 적으면 두 군데, 한쪽만 고치면 한계가 둘 / · 두 채널의 값이 다르면 채널마다 값과 시각을 남기고 설치 · 측정 조건을 확인한다. 한계를 한 곳에 두는 것과 기록을 합치는 것은 다른 결정 / [다음] 센서의 태그와 유온의 한계를 찾는 길
### 화면 구성
두 칸 위에서 현재 센서와 물리량의 식별자를 짚고 아래에서 같은 유온을 재는 채널을 한 개 더 둔 가정을 비교한다. 왼쪽 마지막 줄은 식별자 수의 변화, 오른쪽 마지막 줄은 공유하는 물리량과 한계의 수다.
### 제작 기준
실라버스 「통합반 온라인 44H」 17행. 사실표 「2~4일차」의 「TS1은 센서의 태그이자 상태 변수의 다른 이름」과 「상태 변수」 표. `it/neo4j/v2/instances.cypher`의 sen:ts1은 tag TS1, unit ℃를 갖고 sv:ts1을 OBSERVES로 잇는다. sv:ts1의 normal 48, limit 65는 저장된 기준이다. `it/neo4j/v2/schema.json`의 OBSERVES N:1 선언에 근거해 같은 유온을 재는 별도 채널을 한 개 더 등록하는 가정을 비교한다.

하위 클래스의 인스턴스는 상위 클래스의 인스턴스라는 상속의 정의는 W3C OWL 2 Primer §4.2 Class Hierarchies. https://www.w3.org/TR/owl2-primer/#Class_Hierarchies 위 칸은 it/neo4j/v2/schema.json의 Sensor(tag 필수 · unit)와 OBSERVES(Sensor → StateVariable), 인스턴스는 instances.cypher의 sen:ts1 · sen:ce이고 sen:ce는 OBSERVES로 sv:ce(냉각 효율)에 이어진다. 아래 칸의 계산 채널 하위 클래스와 계산식 속성은 스키마에 없는 설계이고, 화면 아래 줄과 낭독이 그 조건을 밝힌다. 실제 스키마는 계산 채널을 Sensor.virtual로 구별하며 extends가 있는 클래스는 Event · Task · Gateway(→ FlowNode)와 User · Agent(→ ExecutionActor)뿐이다(사실표 2.2). 하위 클래스가 상위 클래스의 속성을 물려받고 뺄 수 없다는 것은 workspace/개발/scripts/ontology_v2.py의 all_props(자기 속성 + extends 부모 속성)와 validate가 실제 하위 클래스 노드에 상위 클래스의 필수 속성까지 검사하는 동작, 관계를 받아 쓰는 것은 schema.json SEQUENCE_FLOW(FlowNode → FlowNode)를 하위 클래스 노드가 쓰는 것으로 확인한다. 오른쪽은 schema.json의 MONITORED_BY(Component → Sensor)이다.

## SLIDE 48 — Cypher 쿼리와 실행 화면의 역할
### 화면 내용
- 유형: 풀이

- 요소:
  1. 쿼리(Query) | 데이터베이스에 보내는 요청 한 건이다. 무엇을 찾거나 만들지를 적는다. / 쿨러 사건에서 경보로부터 원인 후보를 찾은 것도 그래프에 보낸 쿼리였다. |
