# 통합1-06-포털-다시찍기

- 시작: 2026-11-12 · 상태: 진행
- 상태는 `진행` · `중단` · `끝` 셋 가운데 하나다. 일이 끝나면 「끝」으로 바꾸고 `<py> workspace/동기화.py 정리 --실행`으로 이 폴더를 지운다(클라우드는 지운 것을 커밋한다).

## 의도
통합 1회차 실습 06 「전체과정관찰」(포털: 매뉴얼 적재 → 열화 주입 → AI 판단 → 승인 → 조치)을 새 대본으로 **다시 찍는다**. 지금 게시본은 조작마다 한 문장씩 중계하는 딱딱한 말이고, 쉼넣기로 화면을 멈춘 시간이 25분 가운데 7분 31초(30%)라 얼어 보인다. 사용자: 「다시 찍을 때 … 설명을 쉽게 최대한 쉽게 … 어색한 표현 없고 원테이크로 … 줄줄 하나의 실 … 진짜 다시 찍는 거만큼 대본에 맞게 완벽하게」 · 「원래는 행위로만 해서 그렇지 설명을 하면서 … 자연스럽게」 · 「이번 촬영은 리스크 없이 완벽한 버전이어야 한다 … 이슈 있는데 놓쳐서 막 다시 찍고 그런 거는 없이 부드럽고 사람이 사용하는 것처럼 자연스럽게」.

## 하는 일
1. 대본: `입력/06_새대본_화면그대로판.md`는 「화면 그대로 쉼넣기」 제약(단위마다 옛 조작 자리 · 글자 수 1.2배)으로 쓴 판이다. 이 제약을 걷어내고 **다시 찍을 판**으로 다시 쓴다 — 본보기 `입력/본보기_Notion_다시찍을판_확정.md`(사용자 「이대로 확정」)의 꼴: 단계 표 → 단계마다 한 덩어리 글, `▸` 조작 자리 · `‖` 쉬는 자리, 끝에 「동선 바뀐 곳」. `입력/06_새대본검토.md`(지적 42건) · `입력/06_다시찍기판정.md` · `입력/06_걸린곳.md`의 화면 · 값 지적(쿨러 성능 비율 73 → 67 → 61 → 55 %, 작업지시는 「조치 뒤 정비 점검」 등)은 다시 찍을 판에서도 맞는 것만 반영하고, 모든 값 · 이름은 실제 화면과 코드에서 다시 확인한다.
2. 독립 적대 검토 1회(`입력/새대본검토의뢰.md`) → 목록 고침 → 사용자 확정(최종본 파일 · 전후 비교 · 물을 곳).
3. 길뚫기(포털 촬영준비 「길」 클라우드) → 큐 JSON · 음성 견적(사용자 승인 뒤 구매, 영상 V-4) → 구간마다 녹화하고 바로 확인(화면대조 · measure · 끝 상태, 문제는 그 구간만 즉시 다시) → 합성 → 사용자 청취.
4. 06을 끝낸 뒤 같은 길(1~3)로 차례로 더 한다 — 포털 화면은 모두 이 클라우드 세션이 찍는다(사용자 「하면서 2회차 포탈도 같이 neo4j도 등등 다 해야 하는 거 아닌가요」):
   - 통합 2회차 실습 05 「지식지도탐색」 — 입력 `입력/2회차05_새대본_화면그대로판.md`(다른 세션이 쉼넣기용으로 쓴 판, 모든 큐가 새 글) · `입력/2회차05_걸린곳.md`. 다시 찍을 판으로 다시 쓴다.
   - 통합 1회차 실습 04 「실행환경」의 포털 둘러보기(포털이 처음 열리는 pt101부터 끝) — 이 PC 세션이 다시 찍을 판 대본을 써서 `입력/1회차04_포털둘러보기_새대본.md`로 올린다(올라오기 전에는 06 · 2회차 05를 먼저). 참고 `입력/1회차04_다시찍기판정.md` · `입력/1회차04_지금낭독.json`. 그 앞 설치 구간은 이 PC가 쉼넣기로 하므로, 포털 둘러보기 첫 화면은 지금 게시본의 그 자리(시스템 켜기 끝 → 포털 첫 화면)와 이어지게 찍는다.
5. 빼는 것: 다른 실습 영상, 시스템 코드 변경(촬영을 막는 포털 결함은 따로 보고).
