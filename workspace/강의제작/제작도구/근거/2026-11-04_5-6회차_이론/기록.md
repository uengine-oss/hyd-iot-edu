# 5 · 6회차 이론 준비 — 기록(환경 · 함정 · 통한 길)

## 통한 길(클라우드 VM, main 체크아웃 + `동기화.py pull`)

- 받기 · 올리기: CLAUDE.md 7절 그대로(`동기화.py pull · commit --만 · push`, 해시 5~10분이라 백그라운드). 세션 브랜치가 `claude/…`여도 그 커밋이 main과 같으면 `동기화.py push`가 main · workspace를 올린다(main은 변경 0).
- 사실 대조용 그래프: `setsid nohup dockerd &` → `AI_MODE=replay CMD_FINGERPRINT_KEY=x PROCESS_CALLER_TOKEN=x docker compose up -d neo4j kg-seed`(compose의 필수 변수 셋 때문에 값이 없으면 멈춘다). 기본 시드(174노드)만 뜨고, 수업 문서 적재분(Rule 25 · Skill · Cause)은 `근거/2026-11-03_5-6회차_인계/실측/` 덤프로 댔다 — 11-03 뒤 `it/neo4j` · `course_extractions.json` 변경 없음을 git으로 확인. 조회는 `docker exec hyd-iot-edu-neo4j-1 cypher-shell -u neo4j -p hydpass123 --access-mode read`.
- 렌더 환경: `workspace/강의제작/제작도구/기존제작/tools/deck/렌더환경_클라우드.sh <맑은 고딕 폴더>`(우분투 26.10 stonking chroot에 LibreOffice 26.8.1.1 · ko_KR.UTF-8, debootstrap은 `gutsy` 스크립트로 판 이름표를 대신). chroot · LO 설치 · bind mount · `soffice` 감싸개까지는 이 VM에서 실제로 돌렸고, 맑은 고딕 단계는 글꼴을 받지 못해 돌리지 못했다(미검증).
- 글꼴이 없을 때: 같은 LO 26.8로 Noto CJK 미리보기를 그려(`/usr/local/lo268/bin/soffice --headless --convert-to pdf` → `pdftoppm -r 80`) 검토자가 화면 내용 · 위치를 판정하고, 줄바꿈 · 넘침 · 글겹침(D-86 등)만 미확인으로 남겼다. `deck2pptx.py --render`는 맑은 고딕이 아니면 멈추므로 미리보기는 soffice를 직접 부른다.
- 작업 순서: 온라인 작업자 넷(덱 하나에 하나) → 오프라인 작업자 둘(과정 하나에 하나) → 사실표 작업자 하나(모든 작업자의 `사실표_고칠곳.md`를 모아 한 번) → 검토자 여섯(온라인 넷 · 오프라인 둘, 한 번) → 원래 작업자가 목록만 수정 → 감독 확인 하나(목록대로인지만, 근거 빈 통과 항목 채움) → 오프라인 다시 조립. 의뢰서는 `의뢰/`.

## 함정

- 사용자 메시지의 `@C:\Windows\Fonts\MALGUN.TTF` 같은 경로 참조는 클라우드 VM에 파일이 오지 않는다 — 글꼴은 파일 첨부로 받는다(CLAUDE.md 7절에 고침).
- VM이 다시 켜지면 `dockerd`와 chroot bind mount가 사라진다(파일은 남음) — 위 명령을 다시 돌린다.
- `동기화.py status`는 「내용 다름」 목록을 30줄 남짓만 찍는다(합계 줄의 수보다 적다) — 올릴 목록은 `git hash-object`와 `git rev-parse origin/workspace:<경로>`를 견줘 뽑았다.
- 검토 뒤 고친 장은 `장확정.py`가 장 해시로 다시 「볼 장」에 올린다(통합5 9장) — 고친 뒤 감독이 실물을 보고 다시 확정한다.
- 검토자가 근거 한 칸에 여러 경로를 「 · 」로 이으면 전표가 「파일 없음」으로 멈춘다 — `도구/전표만들기.py`가 나눠 단다.
- 오프라인 덱의 불통과가 재사용 온라인 장에서 오면 오프라인 쪽에서 고치지 않고 온라인을 고친 뒤 `만들기.sh`로 다시 조립한다(오6실전 D-14 · D-165, 오7실전 D-95, 오5통합 D-68 · D-69).
- `인수검사.py --출력`은 근거 폴더 안을 거절한다(「다른 작업 폴더 파일이어야 함」) — 작업 폴더에 쓰고 근거로 복사했다.
- 키 검사(`secret_scan.py`)는 근거 글의 `GOOGLE_TOKEN = 설명` · JSON `"GOOGLE_TOKEN": "설명"`처럼 이름 뒤에 8자 넘는 글이 오면 키로 본다 — 설명은 괄호나 [이름, 설명] 꼴로 쓴다(검사는 우회하지 않는다).

## 2차에서 뚫은 길 · 다시 쓸 것(같은 날, 세션이 지워져도 남기려고 여기 적음)

- **맑은 고딕 렌더(통함)**: 사용자가 첨부한 `MALGUN*.TTF`를 폴더에 모아 `bash workspace/강의제작/제작도구/기존제작/tools/deck/렌더환경_클라우드.sh <폴더>` → 끝까지 됨(chroot 안 fc-list에 맑은 고딕). 그 뒤 `PATH=/usr/local/lo268/bin:$PATH`로 `deck2pptx.py <PPTX> --render <폴더>` · `만들기.sh … <렌더 폴더>`가 그대로 돈다. 여덟 덱 렌더는 순서대로 약 10분.
- **되풀이 · 순서 점검은 따로 짧게**: 340개 인수 조건을 한꺼번에 본 첫 검토자는 S-37 · S-76을 모두 통과로 줬는데, 그 두 항목만 보게 한 점검자는 같은 대본에서 94건을 찾았다. 청취에 닿는 항목(되풀이 · 순서 · 화면 짚기 · 물음 밀도)은 큰 검토와 따로, 덱 하나에 점검자 하나로 돌린다. 의뢰서 `2차_되풀이순서렌더/의뢰/의뢰_순서되풀이점검.md` · `의뢰_고침2.md`(장 번호 바꾸지 않기 · 대본 순서를 화면에 맞추기 · 걸린 문장만 · 남기면 까닭).
- **렌더 보기 의뢰**: `의뢰/의뢰_렌더보기.md` — 9장 묶음 시트 + 의심 장 원본. 오프라인 렌더 결함의 상당수는 재사용 온라인 장이 원인이라, 온라인 장 화면만 고치고 오프라인을 다시 조립하면 함께 풀린다(오프라인 쪽에서 고치지 않는다).
- **음성만 먼저 사기**: `2차_되풀이순서렌더/음성/음성사기.py`가 `강의영상.py`의 `slides_text` · `cache_key` · `tts`를 그대로 불러 캐시(`tools/video/음성_저장/`)만 채운다(영상 굽기 없이). 대표 1구획을 먼저 사서 단가를 재고(`--한도 1`), 상한 · 실패 즉시 멈춤 · 캐시 있는 구획 건너뜀. 장부 `음성기록.json`은 `강의영상.py --audio-ledger` 꼴이라 굽기 때 넘기면 시간표에 실제 크레딧이 찍힌다. 실측 0.485크레딧/자(292구획 · 139,721자 → 67,748).
- **함정**: 작업 폴더를 정리(`동기화.py 정리`)한 뒤 그 폴더를 가리키던 작업자 기록 경로가 끊긴다 — 2차 기록은 새 작업 폴더에서 쓰고 근거로 옮겼다. 근거 폴더의 1차 재편 · 빌드 스크립트(`<덱키>/근거/*.py`)를 다시 돌리면 2차 고침이 덮인다(README에 적음). `git ls-tree`로 한글 경로를 견줄 때는 `-c core.quotepath=false`(안 주면 따옴표 · 8진수 경로라 모든 파일이 「새 파일」로 보인다).
- **효율**: 한 덱 = 한 작업자를 끝까지 이어 쓰면(SendMessage로 되살림) 지침을 다시 읽지 않아 빠르다. 같은 판본에서 통과한 검사는 다시 돌리지 않고, 고친 장만 렌더 · 확인한다. 커밋은 `동기화.py commit --만 <목록>`을 백그라운드로(해시 5~10분), 목록은 `git hash-object`와 origin 블롭을 견줘 뽑는다.
- **다음(남은일.md 2절)**: 영상 12편 굽기(음성 캐시 있음 → 크레딧 0, 장 그림은 `PATH=/usr/local/lo268/bin:$PATH`로 LO 26.8 맑은 고딕) → 강조 → 영상 검토 1회 → README · 입고 → 노션(통합 5 · 6, 실전 5 · 6 회차 쪽 + 과정 홈 오프라인 링크) → 전표.
