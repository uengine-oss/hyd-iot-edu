## 어디서 무엇을
- 고치는 곳: `/home/user/portal-ux`(브랜치 `portal-ux`의 worktree) 하나. **커밋 · push는 하지 않는다**(감독이 한다). main · workspace 체크아웃(`/home/user/hyd-iot-edu`)은 읽기만.
- 먼저 끝까지 읽을 것: `/home/user/hyd-iot-edu/workspace/강의제작/제작도구/근거/2026-11-13_포털실습-다시만들기/스펙.md`(「나침반」 · 잣대 일곱), 같은 폴더 `디자인기준.md`, `기록.md`의 「사용자 기준」 절, `/home/user/portal-ux/workspace/개발/문서/UIUX_PLAN.md`.
- 떠 있는 스택: 포털 `http://127.0.0.1:8088`(재생 모드). `compose.override.yaml`이 `it/portal/www`를 물려 두어 화면 파일은 새로 고침만으로 반영된다. **`docker compose build/up/restart`를 하지 않는다**(다른 작업자가 같은 스택을 본다). 서버 코드(`it/process` 등)를 고쳐야 하면 고치지 말고 보고에 적는다.
- **유료 호출 금지**: 이 VM 환경 변수에 AI 키가 실제 값으로 있다. pytest · 도구는 반드시 `env -u LLM_API_KEY -u OPENAI_BASE_URL -u LLM_MODEL AI_MODE=replay …`로 돌린다. `.env`는 읽지 않는다. 키 값을 어디에도 출력하지 않는다.
- 시험: `cd /home/user/portal-ux && env -u LLM_API_KEY -u OPENAI_BASE_URL -u LLM_MODEL AI_MODE=replay HYD_TEST_DSN=postgresql://postgres:postgres@127.0.0.1:54322/hyd_test_<내이름> HYD_TEST_PORTAL_URL=http://127.0.0.1:8088 PYTHONUTF8=1 PYTHONPATH=<옛 VM 스크래치>/srv python3 -m pytest -c workspace/개발/pytest.ini -p srvplug -p no:warnings -q --no-header <파일>`. 화면 코드 시험은 `workspace/개발/tests/test_www_*.py`. 끝나면 만든 시험 DB를 지운다(`psql -h 127.0.0.1 -p 54322 -U postgres`, 비밀번호 postgres, `drop database`는 한 명령에 하나).
- 화면은 Playwright(파이썬 `playwright.sync_api`, `chromium.launch()` 옵션 없이)로 찍어 **자기 눈으로 본다**. 그림은 자기 폴더에 둔다.
- 서브에이전트를 만들지 않는다(직접 읽고 직접 고친다). 새 기능 · 새 라이브러리를 넣지 않는다. 화면 문구에 작업자 말(「강의용 실습장」 · 「수업 시나리오」 · 「미니판」 · 「강사」 · 「녹화」)을 넣지 않는다. 전문 용어는 그대로 둔다.
- 고친 것마다 화면 코드 시험을 붙이거나 고치고(장난감 시험 금지 — 문자열 존재만 보는 시험을 새로 만들지 않는다), 기존 `test_www_*.py` · `test_zones.py`가 통과해야 한다. `workspace/개발/scripts/class_round.py`가 고친 화면의 선택자를 쓰면 함께 고친다.
- rebase · reset · stash 금지. 상대 작업자의 파일(아래 「나눔」)을 고치지 않는다. 꼭 필요하면 고치지 말고 보고에 적는다.
- 보고(한국어): 무엇을 왜 어떻게 바꿨는지(파일:줄), 전후 그림 경로, 돌린 시험과 결과, 고치지 않고 남긴 것과 까닭, 감독이 정해야 하는 것. 보고는 자기 폴더의 `보고.md`에도 적는다.
