## 2. CSS 파일 짜임 — 무리의 경계

싣는 차례: 키트 → `portal-kit.css` → `knowledge` → `plant` → `build` → `trial` → `system` → `case` → `live`. 22화면을 실제 브라우저로 열어 「그 화면의 요소에 다른 무리 파일의 규칙이 걸리는가」를 셌고 **0건**이다(처음에는 일곱 부류가 걸렸다 — 아래에서 옮겼다).

- 무리를 정한 법: 선택자의 클래스 · id · `#view-…`로 정하고, 이름만으로 모르는 것은 그 클래스를 내는 JS와 `index.html`의 화면 구역을 찾아 정했다. 둘 이상의 무리가 쓰는 것은 `portal-kit.css`(실시간 계열은 `live.css`)로 보냈다.
- 이름과 달리 다른 무리 것이어서 옮긴 것: 설비 회로의 정보 카드가 `.sys-info`를 함께 써서 겹쳐 그려졌다 → `.sys-info` 바탕 규칙과 `.btn-cv`를 `portal-kit.css`(캔버스 공통)로. `.agents-*`(처리 건의 「자세한 기록」) → `case.css`. `.doc-bar`(문서 등록 원문 + 스킬 문서) · `.opt-detail*` · `.dec-*`(규칙 판단 + 처리 건 + 업무 시스템 기록) · `.stream-phases` · 흐름 그림 구획 → `portal-kit.css`. `#decOrphans` · `.dc-folds`(업무 시스템 기록) → `plant.css`. `.hc-bar, .sys-bar` 한 규칙은 둘로 갈라 `plant.css` · `system.css`에.
- `trial.css`는 지금 규칙 하나(`.opt-money`)뿐이다. 판단 실험 넷의 배치는 두 칸 틀(`.io`)이 전부 갖고 있었기 때문이다.

**무리 파일의 「옛 모양 — 이 무리 작업자가 마크업을 옮기면 지운다」 구획**

| 파일 | 규칙 | 아직 쓰는 곳 |
|---|---|---|
| `knowledge.css` 맨 아래 | `.fab-body, #fabResult` · `.fab-body h4` | `fabric.js`(데이터 원천의 결과 칸) |
| `system.css` 맨 아래 | `#sourceEventRetry input, textarea` · `#sourceEventList .btn` | `sourceEvents.js`(관리 › 접수 기록) |
| `portal-kit.css` `.pane-ic` 세 줄(주석으로 표시) | 상세 머리 왼쪽의 아이콘 칸 | `agents.js` · `ask.js` · `fabric.js` · `flows.js` · `instances.js` · `mcp.js` · `sourceEvents.js` — 여러 무리가 쓰므로 무리 파일로 내리지 못했다. 마지막으로 쓰는 무리가 지운다 |

옛 「대응 규칙」 구획의 나머지는 쓰는 곳이 없어 지웠다(아래).

**무리 작업자가 알아 둘 것**: 옛 설정 줄 `.set-row` · `.set-what` · `.set-do` · `.set-more` · `.set-msg`(`system.css`)와 새 `.setting`은 다른 이름이다(관리 화면을 `UI.settingRow`로 옮기면 `.set-*`를 지운다). 꼬리표의 `data-plain` 속성과 화면 구역의 `data-kit` 속성은 이제 걸리는 규칙이 없다(마크업을 옮길 때 지운다). 세그먼트는 칸이 넷 넘으면 300px 목록 칸에서 두 줄이 된다(처리 건 · 에이전트 — 대응표대로 묶음으로 바꾸면 없어진다).
