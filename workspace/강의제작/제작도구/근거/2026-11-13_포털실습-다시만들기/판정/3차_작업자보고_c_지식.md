## 2. 새로 넣은 것 — 한 번에 적재(대응표 6절)

- 제공 문서 줄 왼쪽의 고르기 칸으로 여럿을 고르면 목록 아래에 [고른 n개 한 번에 적재]가 나온다. 문서마다 올리기 → AI 추출 → 적재를 차례로 돌리고, 줄마다 지금 하는 일(「AI 추출 — 구간 3개 가운데 1개를 읽었습니다」 등)이 흐른다.
- 적재하지 않고 「검토 필요」로 멈추는 때: 자동 검증이 통과하지 못함, 고장 유형이 정해지지 않은 조치 방법, 손대지 않은 칸으로는 적재 요청을 만들 수 없음, 개정으로 이전 판의 항목이 빠짐, 같은 원문이 다른 문서로 이미 적재됨. 멈춘 문서는 [검토 열기]로 검토 단계가 열린다.
- 이미 적재된 문서를 고르면 한 편씩 누를 때와 같이 그 문서의 개정으로 올린다.
- 서버 주소는 그대로다(preview · extractions · changes · commit). 적재 요청은 검토 화면과 같은 함수 `commitRequest`가 만든다(`hitl.js`). 검토 화면의 적재 단추 안에 있던 코드를 이 함수로 옮겼다.
- 스택에서 밟은 결과: HI-01(새 문서) + HM-8(개정) 둘 다 적재됐다. 제공 문서 넷은 모두 자동 검증을 통과하므로 「검토 필요」로 멈추는 길은 스택에서 일으키지 못했고 시험으로만 봤다.

## 4. 지운 기능 · 「이건 이런 건데 필요합니까」 · 교재 어긋남

- **코드에서 지운 기능**: 없다. 자리만 옮겼다. 화면에서 사라진 것은 지식 지도의 「가장 많이 이어진 항목」 여섯 개(찾기와 안내로 대신 — 교재 · `class_round.py`에서 「가장 많이 이어진」 검색 결과 0)와 데이터 원천의 숫자 카드 둘이다.
- **필요합니까**: ① 지식 지도로 옮긴 「AI가 이 지도를 읽는 질의문」(Cypher 여덟 종류) — 교재(`산출물/`)에서 「질의문」 검색 결과 0, `class_round.py`도 쓰지 않는다. 캔버스 도구의 `{ }` 단추 하나로 남겼다. ② 한 번에 적재의 고르기 칸 — 기본 제공 문서 셋이 처음부터 적재돼 있어 수업에서 새로 넣을 문서는 HI-01 하나뿐이다.
- **교재 어긋남(교재는 고치지 않았다)**:
  - 「등록된 매뉴얼」 → 「적재한 문서」, 「현재 판본으로 올라왔네요」 → 판본 표시 없음: `통합반 · 실전반/실습/01회차/대본/06_실습_전체과정관찰.md` 32 · 137 · 279줄(32줄은 `#manualHistory h2.sec` 선택자도 적혀 있다), `실전반/실습/03회차/대본/06_실습_매뉴얼검토.md` 95 · 97줄.
  - 그 밖에 뒤 회차 교재가 가리킬 만한 것(찾아보지 못함): 조치 방법의 「식별자」 접기와 출처 줄의 [문서 등록에서 열기], 표 정의의 「연결 이력」과 [되돌리기] 단추, 데이터 원천의 처음 보기와 숫자 카드, 문서 등록 아래의 질의문 접기.
