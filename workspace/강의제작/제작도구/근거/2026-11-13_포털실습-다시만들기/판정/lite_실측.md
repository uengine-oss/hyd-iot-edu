## 2. 띄운 법

```bash
cd 작업/2026-11-16_포털-lite-참고/lite
npm install --ignore-scripts --no-audit --no-fund     # node-pty 빌드를 건너뛴다. 바뀐 package-lock.json은 git checkout으로 되돌린다
npx vite --port 5180 --strictPort --host 127.0.0.1    # 뒤에 띄워 둔다

```

- 로그인: 라우터 가드는 `localStorage`의 세션 토큰이 있는지만 본다(`src/main.js:35-37`). 시작 스크립트가 가짜 토큰을 `pgpt-pro-session`에 넣고, 화면 언어 `pgl-lang=ko`, 테마 `pgpt-pro-theme=light`(낮 테마 고정), 장소 `pgpt-pro-place`(서울, 대략 위치)를 넣었다. 장소를 넣어 두었으므로 ipapi.co를 부르지 않는다.
- 요청: Playwright `context.route('**/*')`가 `/api/*`를 모두 가로채 가짜 JSON을 돌려준다. 실시간 이벤트 `/api/events`는 `hello` 한 번만 보내고 닫는다(lite는 3초 뒤 다시 붙는다). 바깥 요청은 글꼴(jsdelivr의 Pretendard, Google Fonts)만 통과시켰고, 날씨(open-meteo)는 가짜 값을, Google 파비콘은 회색 PNG를 돌려주었으며, 그 밖은 막도록 했다(실제로 막힌 요청은 0건).
- 기다림: 화면마다 `goto` 뒤 4.5초를 기다리고, 마우스를 창 오른쪽 아래 끝으로 옮긴 뒤 찍고 셌다. 하늘 배경(SkyCanvas, WebGL)은 그려졌다.
- 채팅을 보내지 않았으므로 lite가 모델을 부를 길이 없다. 환경 변수의 `LLM_API_KEY` 등은 읽지 않았다.

## 4. 세는 규칙

우리 `shoot.py`의 `COUNT_JS`를 그대로 옮겼다(`shoot_lite.py`의 `COUNT_JS`). 단추 = `button` · `[role=button]` · `summary` · 단추 모양 `a`, 링크 = 그 밖의 `a`, 뱃지 = 아래 선택자, 입력 = `input`(숨김 아님) · `select` · `textarea`, 글 덩어리 = 위 넷 밖의 글자 마디가 든 가장 가까운 블록(같은 블록은 한 번). 창 안 = 상자가 창과 겹치고 크기가 있고 숨지 않은 것이며, 닫힌 `details` 안은 `summary`만 센다. 단추 · 링크 안의 뱃지와 글은 세지 않는다.

우리 함수에서 바꾼 곳은 넷이다.
1. 영역을 선택자 목록으로 받는다(우리는 `#sidebar` · `.topbar` · `.view.active`로 고정했다). 영역 자신이 단추이면 그 단추도 센다(설정의 닫기 단추처럼 셸이 단추 하나인 경우).
2. 뱃지 선택자를 lite의 상태 알약으로 바꾸고, 뱃지는 단추 · 링크가 아닌 요소로 한정했다. lite는 `button.attn`처럼 같은 클래스를 단추에도 쓰는데, 우리 원래 식대로면 그런 단추가 아예 세어지지 않는다.
3. 보이는지 볼 때 조상 요소의 `opacity: 0`도 숨김으로 본다. lite는 설정 시트를 열 때 뒤의 본문을 `opacity: 0`으로 남겨 두기 때문이다(영역을 `.settings`로 잡았으므로 수에는 영향이 없었다).
4. 목록에 적는 글에 `placeholder`를 덧붙였다(수에는 영향이 없다).

**뱃지 선택자**(lite 코드에서 상태나 종류를 말하는 작은 알약 — `scan_pills.py`로 창 안의 알약 후보를 모은 결과와 코드를 대어 골랐다):
`span.badge`(목록 줄의 입력 필요 · 작업 중 · 진행 중 · 에이전트 작업 중, 폴더 색인 상태), `span.pill`(인스턴스 상태: 진행 중 · 완료), `span.attn` · `span.wait` · `span.bad`(단계의 입력 필요 · 확인 대기 · 실패), `.sk > code`(단계에 묶인 스킬 이름), `span.verb`(Home 카드의 결정 · 입력 · 추천 · Review · Submit), `span.tag`(예약 n, 보관함 종류), `span.tool`(커넥터의 도구 이름 칩), `span.state`(커넥터의 「✓ 연결됨」 — 배경 없는 상태 글이지만 상태 표시라 넣었다), `span.cst`(개선 목록의 제약), `span.st` · `i.newdot`(마이닝 상태 · 새 제안 수), `span.svc` · `span.count`(스킬 상세), `div.working`(채팅 위 「작업하는 중」). 후보로 나왔지만 뺀 것: `.seg`(세그먼트 단추 묶음), `div.plan`(설정의 워드마크 알약 — 상표라 글로 셈), `div.av`(머리글자 원 — 글로 셈).

**셸과 본문**:
- 채팅 · 프로젝트 · 인스턴스 · 개선 · 마이닝 · 폴더: 셸 = 위 막대 `header.top`(Home 단추, 탭 셋 채팅 · 프로젝트 · 폴더, 메시지, 검색, 아바타 = 단추 7. 안 읽음 수 점은 단추 안이라 따로 세지 않는다). 본문 = `.main > .content`(왼쪽 Home 칸 또는 프로젝트 목록 + 가운데 칸 + 바닥 입력창) 또는 각 화면의 `.content`.
- 설정 네 화면: 위 막대가 사라진다(`MainView.vue:105`). 셸 = 오른쪽 위 닫기 단추 `.settings > button.x` 하나. 본문 = `.settings`에서 그 단추를 뺀 것(뒤로 단추와 제목은 본문에 넣었다).

## 6. 범위 밖과 한계

- 띄우지 못한 화면은 없다.
- 지시 목록에 없어 찍지 않은 화면: 상세 화면 `/improve/:defId` · `/mining/:id` · `/folders/:slug`, 대화 맥락 `/chat/c/:cid`, 프로젝트 대화 `/projects/:id`, 설정의 나머지 다섯 쪽(예약된 작업 · 지갑 · 시스템 설정 · 보안 · 프로필), 인스턴스의 「다이어그램」 보기, 휴대폰 폭. 상세 화면은 응답 모양(개선의 단계별 합계 · 가치 흐름 · 크리티컬 패스 계산 결과 등)이 커서 코드만 읽고 꾸미면 틀릴 곳이 많다. 필요하면 `shoot_lite.py`의 `api_answer`와 `SCREENS`에 더해 같은 법으로 잴 수 있다.
- 가짜 응답의 모양은 화면 코드가 읽는 필드에서 거꾸로 만든 것이다. 진짜 서버가 더 주는 필드가 있으면(예: 답 메시지의 `context`가 있으면 말풍선 위에 대화 맥락 알약이 붙고 위에 「대화 n개 · 맥락별로 보기」가 생긴다 — `Message.vue:58-61`, `ConversationBar.vue:34-36`) 같은 화면의 수가 달라진다. 이번 값은 그런 맥락 라우터 결과 · 메일 액션 카드 · 패널이 없는 상태다.
- 날짜와 「n분 전」은 찍은 시각에서 거꾸로 셈한 값이라 다시 재면 글자는 바뀌지만 수는 같다.

## 7. 다시 재는 법

2절의 명령을 그대로 돌린다. `shoot_lite.py`의 `SCREENS`가 화면 · 셸 · 본문 · 본문 안 나눔 선택자를, `LAYOUT`이 배치를 잴 자리를, `BADGE`가 뱃지 선택자를 갖고, 가짜 데이터는 파일 위쪽의 상수(`INSTANCES`, `STEPS`, `NOTIFICATIONS` …)에 있다. 결과는 `counts_lite.json`(화면마다 본문 · 셸의 수와 목록, 부분별 수, 배치, 콘솔 오류, 가짜 응답이 없던 요청)과 그림으로 나온다.
