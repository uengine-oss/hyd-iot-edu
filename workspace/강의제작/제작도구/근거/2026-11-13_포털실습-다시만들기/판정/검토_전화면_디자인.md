첫 화면 한 장씩만 떼어 Linear · Vercel 옆에 놓으면 같은 키트(shadcn 계열)의 옷을 입었으니 한눈에는 비슷한 급으로 보인다. 홈 · 처리 건(승인 대기) · 규칙 판단 결과 · 에이전트 · 스킬은 그 급이다. 그러나 **한 번만 내려 보거나 접기를 하나만 펼치면, 그리고 화면 둘을 나란히 놓으면 바로 「키트를 입힌 내부 관리 도구」로 떨어진다.** 까닭은 셋이다. ① **같은 일을 화면마다 다르게 한다** — 되돌리기 하나가 네 이름(기준으로 되돌리기 · 처음 상태로 되돌리기 · 전체 초기화 · 원래대로)과 네 모양(빨간 단추 · 접기 · 「고급」 접기 · 꺼진 outline)으로, 다시 읽기가 네 모양(글+아이콘 · 아이콘만 · 더 보기 안 · 「새로 고침」)으로, 조치 후보 표가 세 화면에서 세 짜임으로 나온다. 다섯 작업자의 손이 그대로 보인다. ② **화면이 읽는 곳이 됐다** — 폼 칸마다 3~6줄 도움말, 폼 아래 다시 한 문단, 같은 말(「AI 모델은 돌리지 않습니다」)이 한 화면에 세 번, 상세의 절마다 오른쪽 보조 글이 붙는다. 텍스트를 줄여야 할 곳을 줄이지 않고 「접기」로 숨겨 접기가 숲이 됐다(처리 건 한 건에 접기 33개, 업무 시스템 기록 14개, 흐름의 「단계 설정」 접기 하나가 6,194px · 꺼진 입력 104칸). ③ **날것의 데이터를 보이는 한 가지 방식이 없다** — JSON이 17개 파일에서 각자 `JSON.stringify(…, null, 2)`로 그려져, 한 판 안에서 밝은 바탕 한 줄 JSON · 어두운 들여쓴 JSON · 어두운 한 줄 「… (생략됨)」이 섞이고, 해시 · UUID · `ALT-hyd01-…` · `WO-1114-C81AA…` · `mcp__hyd-dmn__diagnose` · `(시나리오 A)`가 본문 문장과 제목 안에 그대로 들어온다. ### 2. 보기 바꾸기(`.seg` · 탭)

`.seg` 하나가 다섯 가지 일에 쓰인다: 목록 거르기(처리 건 · 조치 방법 · 흐름 · 에이전트), 화면의 하위 보기 전환(문서 등록 · 데이터 원천 · 판단 채점), 상세 판 안의 내용 전환(도구 연결의 「도구 / 호출 기록」), 폼 안의 선택지(조건별 손익의 「기준 · 업무 값 · 규칙 · 주별」, 결함 시뮬레이션 현장 패널의 운전 모드 — 이것은 **값을 바꾸는 버튼**이다), 표의 대상 고르기(조건별 손익 「손익 내역」의 조치 넷). 같은 회색 알약이 「보기」를 바꾸기도 하고 「설비 운전 모드」를 바꾸기도 한다(`scenario_open_1440_full.png` 현장 패널 · `whatif_result_1440_full.png`).

**정본 제안**: 목록 거르기 = `.seg`(건수 숫자 포함, 목록 위). 화면 하위 보기 = 키트 `.tabs`(밑줄 탭, 머리 바로 아래 왼쪽, 지금 판단 채점의 「채점 · 정답표 · 전·후 비교」 자리). 판 안의 내용 전환 = 같은 밑줄 탭 작게. **값을 바꾸는 선택(운전 모드)은 `.seg`가 아니라 라디오 묶음이나 select** — 보기 바꾸기와 모양이 같으면 안 된다.

### 10. 빈 상태 · 읽는 중 · 오류

빈 상태가 네 모양이다: 점선 카드 + 아이콘 + 제목 + 두 줄(규칙 판단 · 손익 · 채점 · 시험 비교 · 질문하기), 점선 카드 + 아이콘 없음(데이터 원천 · 오일 분석 입력), 실선 카드 안 글만(관리 › 접수 기록), 빈 카드에 단추 하나만(시험 비교 「지난 시험과 비교」 — 제목 · 설명 아래 빈 칸에 「저장된 시험 불러오기」가 오른쪽 끝에 떠 있다). `UI.empty`(ui.js 475줄)에 아이콘 · 단추 인자가 없어 화면들이 각자 `class="empty"`를 손으로 쓴 결과다(evaluation · agents · whatif · mcp · flows · enterprise · compare · ask에 손 마크업).

- 같은 뜻 · 다른 아이콘: 「실행 · 계산」에 play(모의 판단 · 불러오기 · 시험 실행 · 채점 실행 · 써 보기)와 send(입력 보내기 · 보내기), database(묶어 보기), upload(문서 올리기)가 섞였다. 「불러오기」는 조건별 손익에서 play, 관리에서 upload, 시험 비교 「저장된 시험 불러오기」에서 history.
- 다른 뜻 · 같은 아이콘: rotate-ccw가 「쿨러 복구」 · 「초기화」 · 「전체 초기화」 · 「원래대로」 · 「다시 불러오기」(refresh)에 두루 쓰인다(`scenario_1440.png`, `whatif_result_1440_full.png`).

- 아이콘만 있는 단추: 에이전트 머리의 새로고침 하나만 아이콘만이다(다른 화면은 글+아이콘).

**정본 제안**: 아이콘 사전(뜻 → 이름) 한 장: 계산 · 실행 = play, 보내기(사람이 값을 넣어 보냄) = send, 다시 읽기 = refresh-cw, 되돌리기 = undo-2, 설비 복구 = wrench, 불러오기(파일) = upload, 지우기 = trash-2(destructive ghost). 목록 줄 아이콘은 **종류**(사건 · 질문 · 문서 추출)를, 뱃지는 **상태**를 말하게 가른다.

## 고치는 차례

**먼저 — 공통 부품을 정하면 한꺼번에 풀리는 것**(갈래 ① 바탕 쪽, `ui.js` · `portal-kit.css` · `plainWords.js`)
1. **`UI.raw` · `UI.id` · `UI.code`**(날것의 데이터 절) — 처리 건 실행 기록 · 자세히 · 결함 시뮬레이션 조작 기록 · 업무 시스템 기록 원문 · 도구 연결 호출 기록 · 시험 비교 원본 · 관리 · 지식 지도 조건식이 한 번에 같은 모양이 된다. 화면 모듈의 `JSON.stringify(…, null, 2)` 17곳을 이것으로 바꾼다.
2. **동작 이름 사전 + 아이콘 사전**(단추 · 아이콘 절) — 다시 읽기 · 되돌리기 · 취소 · 저장 · 실행의 이름과 아이콘이 모든 화면에서 같아진다. 되돌리기의 사본 셋(흐름 · 에이전트 · 도구 연결)을 지우고 관리 한 곳으로.
3. **상태 이름표**(뱃지 절) — 처리 건 상태 넷, 연결 상태 셋, 종류는 badge · 상태는 tag. 처리 건 목록 · 설비 회로 · 흐름 · 에이전트 · 도구 연결이 같은 말이 된다.
4. **화면 머리 정본**(머리 절) — 다시 읽기는 ⋯ 안, 거르기는 목록 위, 꺼진 주 단추 지움, 머리의 상태 알약 지움.
5. **`UI.empty({icon,title,sub,action})`**, **글자 크기 변수 여섯**, **접기 머리 오른쪽은 수만**, **절 머리 오른쪽은 수 · 상태만** — CSS · 도우미 한 곳씩.
6. **조치 후보 표 한 부품**(`UI.optionsTable`) — 처리 건 · 규칙 판단 · 손익 · 시험 비교.
7. 캔버스: 위 조각은 도구 막대 하나, 자동 배치 알림은 학생 흐름에만, 늘 맞춤으로 열기(흐름 보기 부품 한 곳).

**그다음 — 화면마다 따로**(짜임이 바뀌는 것, 무게 차례)
1. 성과 지표 — 지표 카드 격자 + 계산 불가 한 곳.
2. 업무 시스템 기록 — 카드 일곱 → 표 하나, 같은 건의 두 번 보이기 없앰.
3. 처리 건 — 단계마다의 「자세히」를 줄 누름 + 옆 판으로, 목록 날짜 묶음, 「알림」 접기 빼기.
4. 흐름 — 「단계 설정」의 꺼진 칸 숲을 읽기 전용 표로, 「경보별 운영 흐름」 표를 보기 하나로.
