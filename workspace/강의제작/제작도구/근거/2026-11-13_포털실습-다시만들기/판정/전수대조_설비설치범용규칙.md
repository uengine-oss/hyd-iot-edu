## EMQX 관리 화면(호스트 18083)으로 승인 없이 `plant/+/cmd/auto`를 낼 수 있는가

설정으로 가린 것:
- 관리 화면은 컨테이너 18083에서 듣고 호스트 `127.0.0.1:${HYD_PORT_18083:-18083}`로 열린다(`compose.yaml:49`). 관리자 계정은 EMQX 기본 `admin`이고 초기 비밀번호가 compose에 평문으로 있다(`compose.yaml:52`, 「키검사: 허용」). 이 PC의 어느 프로그램이든(브라우저 · 터미널 · 코딩 랩의 Codex) 이 주소에 닿는다. 다른 웹 페이지의 스크립트는 관리 API의 토큰을 읽지 못한다(EMQX 관리 API는 기본으로 다른 출처를 허용하지 않는다 — 설정에 `dashboard.cors`가 없다).
- 토픽 규칙(`acl.conf`)은 MQTT 클라이언트 연결에 걸린다. 바깥 입구(1884 · 8083)는 계정 `student` 하나이고 구독만 한다. 안쪽 입구(1883, 이름만)는 호스트에 열지 않았다. 관리 화면의 「웹소켓 클라이언트」 도구는 브라우저가 8083 입구에 MQTT로 붙는 것이라 이 규칙을 받는다(student로는 발행하면 끊긴다).
- 설비 쪽(edge)은 `cmd/auto`로 온 것을 지문 확인 없이 출처 HITL로 PLC에 넣고(`edge.py:89-91`), PLC는 형식 · 모드(REMOTE_AUTO) · 만료(보낸 쪽이 적은 `expiresAt`) · 최근 32개 중복 · 범위 · 인터록만 본다(`plc.py:95-125`). 승인 장부(HMAC 지문)는 명령 관문만 본다.

EMQX 5.8의 동작으로 가린 것(문서 지식 — 이 PC에서 재지 않았다):
- 관리 REST API의 발행(`POST /api/v5/publish`, 관리 화면에서 로그인한 토큰이나 API 키로 부름)은 MQTT 클라이언트 연결이 아니라 브로커 안에서 바로 메시지를 내므로, 클라이언트 연결에 거는 권한 검사(authorization 원천 = `acl.conf`)를 거치지 않는 것으로 알려져 있다. 그렇다면 관리자 로그인 하나로 `plant/hyd01/cmd/auto`가 설비에 닿는다.
- 관리 화면은 내장 계정 DB에 사용자를 더할 수 있다(`is_superuser` 포함). 슈퍼유저는 토픽 규칙을 건너뛰므로, 바깥 입구 1883(호스트)로 붙어 `cmd/auto`를 낼 수 있는 두 번째 길이 된다. 규칙 엔진의 「다시 발행(republish)」 동작도 같은 부류다.
- 판정: **낼 수 있을 가능성이 높다(미확인)**. 06-9 · 14의 「미확인」은 지금 코드에서도 그대로이고, `emqx.conf:10`의 「「승인 1회 뒤에만 설비가 움직인다」가 브로커에서도 참이다」는 관리 API를 빼고 한 말이다. 인수조건 6은 아직 채워지지 않았다.

실측할 것(버려도 되는 스택, 재생 모드, HYD-01 운전 모드 REMOTE_AUTO에서. 검토자는 하지 않았다):
1. `TOKEN=$(curl -s -X POST http://127.0.0.1:18083/api/v5/login -H 'content-type: application/json' -d '{"username":"admin","password":"<compose.yaml:52 의 값>"}' | jq -r .token)`
2. `curl -s -X POST http://127.0.0.1:18083/api/v5/publish -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{"topic":"plant/hyd01/cmd/auto","qos":1,"payload":"{\"cmdId\":\"probe-1\",\"expiresAt\":\"<지금+60초 ISO>\",\"writes\":[{\"res\":\"FanSpeedSP\",\"v\":70}]}"}'` → plant-sim 로그에 `HYD-01 cmd/auto probe-1 -> ACCEPTED`가 나오는지, `GET http://127.0.0.1:8000/api/state`의 팬 지령이 70이 됐는지 본다. 명령 관문 기록(`/svc/cmd-gateway/…`)과 처리 건에는 아무것도 없어야 「승인 없는 길」로 확정된다.
3. 같은 토큰으로 `POST /api/v5/authentication/password_based:built_in_database/users`에 슈퍼유저를 더한 뒤 `mosquitto_pub -h 127.0.0.1 -p 1883 -u <그 계정> -P <비밀번호> -t plant/hyd01/cmd/auto -m '<위와 같은 꼴, cmdId probe-2>'`로 같은 확인을 한다.
