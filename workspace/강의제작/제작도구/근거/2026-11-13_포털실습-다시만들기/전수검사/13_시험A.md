## 3. 시험이 없는 중요한 동작 (이 범위에서)

1. **승인 뒤 전달 · 효과 보상 · 사람 확인의 실패 가지는 흐름 A(냉각)로만 잰다.** `test_approval_delivery.py` 셋, `test_effect_compensation.py:62-129`, `test_approval.py`(정기 점검은 503 한 경우뿐)이 모두 `world.start_cooling()` 이다. 흐름 B(정기 정비 — 범위 오더 · 부품 예약)와 C(구매 — 발주 · 입고)의 「전달 뒤 진행 실패」, 「현재 조건이 동의를 받지 않음」, 「업무 시스템이 역거래를 거절 → 사람 확인」 가지는 아무 시험도 끝까지 밟지 않는다. `test_entsim_main.py:126-154` 만 B 의 범위 오더 취소를 업무 시스템 수준에서 본다.
2. **정의가 있는 작업에서 폼을 찾지 못하는 경우**(지적 #1)는 시험이 없다 — 지금은 조용히 자유형식이 된다.
3. **실행 관문의 「표시 없는 카드」가 실제로 오는지**(지적 #3) — 생산자 쪽에서 표시를 빠뜨리는 경우를 재는 시험이 없다.
4. **에이전트 만들기 · 배정 · 채점 정답표 · 데이터 연결 적재 API 가 없는 사람 · 자유 글 `by` 를 거절하는지**(지적 #5) — 흐름 API 와 달리 시험이 없다(오히려 받는 쪽을 지킨다).
5. **시험 비교에서 펌프 · 팬 시나리오 실행** — `test_agent_trials.py:83-88` 은 `cooler` 하나만 돌린다. 나머지 두 고정 시나리오도 처리 건 없이 도는지 재지 않는다.
6. **조치값 변경안(`approval._parameterized`)의 `load_pct` 성공 경로와 하한 밖 값** — `fan_pct` 100 · 101 만 잰다.
7. **업무 경보 감지 경계**(PM_DUE 가 언제 울리고 언제 안 울리는가, 재고 기준점 경계) — `test_business_monitor.py` 는 근거 칸 · 출처만 본다. 범위 밖 파일(test_main 등)에 있을 수 있어 「이 범위에 없음」으로만 적는다.

## 4. 못 읽은 것

없다. 이름순 `test_agent_authoring.py` ~ `test_handover_tools.py` 94개와 `conftest.py` 1712줄을 모두 끝까지 읽었다. 시험을 실행하지 않았으므로 「지금 통과하는가」는 미검증이다. 지적 #3 의 표시 없는 카드 생산자 존재, 1절의 `OPERATOR` 시험 통과 여부도 미검증이다.
