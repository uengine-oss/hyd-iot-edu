## 4. 문제 없던 것

- procdb: 작업 행 쓰기는 모두 부모 처리 건을 먼저 잠근다(`_workitem_connection`, `release_engine_claims` 도 처리 건마다). 워커 결과 저장은 집은 워커만(`expected_consumer`). 정의 판본은 같은 번호에 다른 내용이면 거절. 처리 기록 흐름(SSE) 위치는 커밋 순서로 매긴다.
- approval_store · current_approval · decision_scope · decision_reviews: 승인 의도는 처리 건 · 작업 행 소유를 확인하며 넣고, 현재 조건 검사는 409 와 연결 실패를 구분하며(HTTPError 를 먼저 잡음), 판단 접수는 세대 · 판본 · 워커 claim 을 모두 맞춘다. 검토본은 덮어쓰지 않고 지문을 확인한다.
- effect_compensation: 되돌리기 계약이 없는 거래는 실패로 멈추고(되돌릴 수 있다고 짐작하지 않음), PLC 명령은 자동 역명령 없이 사람 확인으로만 정리한다. 같은 요청 id 재요청은 저장된 영수증을 돌려준다.
- 그래프 투영(case_projection · execution_graph · projection_repo · projection_repair): 판 번호 울타리와 받은 영수증 대조가 있고, 충돌은 다시 보내지 않고 사람 수리로 넘긴다. 실패 재시도 간격이 두 배씩 늘어난다.
- handover: 인계안은 네 영역 각각 한 번, 근거 없으면 needs_check, 인계 확인은 「설비 조치 · 발주 · 정비 완료가 아님」을 받아야 한다. 근거 고치기(reconcile_trace)는 하나뿐인 완전한 조회 결과에서만 쿼리를 바꾼다.
- maintenance_policy: 패키지 간격 정수배 · 누적 부품 · 위상 추정 거절 · 묶음 인원은 원문 규칙에서만(상수 없음). 실패 때 진단을 싣는다.
- kpi: 원천이 없으면 「계산 불가 — 사유」, 구성 지표 하나라도 없으면 합성 지표도 계산 불가, 단위가 다르면 판정하지 않는다. MTBF 는 벽시계 × TIME_SCALE(시간 규칙과 맞음).
- timeutil.time_scale: 기본값 없이 실패한다. reobs_series: 읽지 못한 창도 `error` 와 함께 기록한다.
- business_monitor: 감시 루프를 지운 까닭과 버튼 경로가 주석과 코드에서 같다(패턴 상수 자체는 10 G11 · S2 가 다룸).
- definition_diff: 표에 없는 칸도 「기타 설정(칸)」으로 비교한다. bpmn.io 무작위 id 를 사람 글에서 숨긴다.
- course_bootstrap: 수업 흐름 표시는 프로세스 안 호출에만 싣는다. 같은 내용이면 다시 설치하지 않는다.
- instances.cypher 1~279 · scenario_structure · pm_capabilities · constraints: MERGE · SET 만 쓰고, 감지 · 업무 경보 패턴의 사람 글(rule)을 TESTS 행에서 만든다. 임계값마다 출처(KnowledgeSource)를 단다.
- main.py 1346~1423: DDL 적재 · 공급사 동기화 · 적재 배치 지우기 모두 `actor_or_400` 으로 「누가」를 받고 실패를 503 · 502 로 올린다.
