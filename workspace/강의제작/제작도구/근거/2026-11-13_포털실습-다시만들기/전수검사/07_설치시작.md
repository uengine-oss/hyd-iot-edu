## 3. 문제 없던 것

- **창 유지와 종료 코드**: `시작.bat` · `끄기.bat` · `점검.bat`은 Git Bash 경로를 세 자리와 `where git.exe`에서 찾는다. 못 찾으면 안내한 뒤 `pause`로 멈춘다. 끝에서도 `pause`를 하고 `exit /b %HYD_EXIT%`로 종료 코드를 넘긴다. `.command` 셋도 종료 코드를 넘긴다.
- **줄 끝과 BOM**: `.gitattributes`는 `*.bat`를 CRLF로, 나머지를 LF로 고정한다. 작업 사본에서 bat는 CRLF이고 BOM이 없으며, ps1 넷은 UTF-8 BOM이 있다(PowerShell 5.1이 한글을 읽는다). sh · command는 LF다(`git ls-files --eol`로 확인).
- **`set -euo pipefail`과 단계 사이 실패 전파**: `start_all.sh`는 모든 단계를 `|| die`로 묶는다. 앞 단계가 실패하면 다음 단계로 가지 않는다. 8단계만 실패하면 포털 주소와 까닭을 보이고 종료 코드 1로 끝난다(README 151줄과 같다).
- **두 번 누름**: `.hyd-runtime/start.lock`이 동시 실행을 막고, pid로 끝나지 못한 앞 실행의 잠금을 넘겨받는다(`start_all.sh:26-34`). 6 · 7단계는 같으면 건너뛰고, kg-seed는 MERGE · SET만 하며, topic-init은 「이미 있음」만 통과로 본다.
- **pull 뒤 갱신**: `supabase migration up --local`이 새 마이그레이션을 적용한다(`start_all.sh:73`). 사람 고르기 삭제는 시드만이 아니라 마이그레이션 `20261113000072_single_owner.sql`로도 들어갔다. 시계열 DB의 후속 변경은 connect-sink가 접속할 때마다 더한다(`it/timescaledb/init.sql:1-3`). 포털은 이미지에 구워 `up --build`로 새로 만든다.
- **끄기**: `compose --profile '*' stop`과 `supabase stop`(`--no-backup` 없음)만 쓴다. 끈 뒤 켜진 컨테이너 수를 세어 0이 아니면 멈춘다(`stop_all.sh:18-23`). 저장소 어디에도 `down -v`나 `--no-backup` 호출이 없다. 지우는 볼륨은 표에 적힌 `enterprise-data` 하나이고, 이 폴더의 프로젝트 라벨이 붙은 것만 지운다(`prepare_ports.py:73-75,457-479`).
- **포트**: compose의 바깥 포트는 모두 `127.0.0.1:`에 묶였다. 시작은 빈 포트를 bind로 재서 고르는데(`SO_EXCLUSIVEADDRUSE`), 이 방법은 Hyper-V 예약 범위도 잡는다.
- **키 · 비밀**: 키 유무는 `hyd_env.py` 한 곳에서 보고 값은 출력하지 않는다. `relay_probe.py`는 키를 출력하지 않는다. `.env`와 `it/supabase/.env`는 `.gitignore`의 `.env` · `.env.*`(깊이 무관)로 빠진다. 빌드 문맥에서는 `.dockerignore`가 루트 `.env`를 뺀다. `it/supabase/.env`는 빌드 문맥에 들어가지만 어느 Dockerfile도 `it/supabase`를 COPY하지 않는다. `.env.example`의 `LLM_API_KEY=` 값 칸은 비어 있다.
- **`.env` 읽기**: BOM, CRLF, `KEY = 값`, 따옴표를 받는다. UTF-8이 아니면 메모장에서 다시 저장하라고 안내한다. 쓸 때는 LF, BOM 없이 임시 파일을 거쳐 한 번에 바꾼다.
- **점검이 재는 것**: 서비스 판정은 손으로 적은 목록이 아니라 `docker compose config --services` 전부다. healthcheck 상태, 한 번 도는 작업의 종료 코드, 10초 뒤 재시작 수 증가를 본다. 포털은 `/`와 `/svc/process/healthz`를 실제로 부른다. 쿨러 한 바퀴는 실제 API로 끝 상태(T_cmd · T_reobs · T_wo · R_ok)까지 판정한다. 늘 통과하는 검사나 문자열만 보는 검사는 없다.
- **README와 사람 고르기**: README에 「나 고르기」, 직원 이름, 옛 탭 이름이 없다. 스크립트가 학생에게 가리키는 「처리 건」 메뉴는 지금 포털에 있다(`index.html:32`).
- **compose 시작 순서**: `depends_on`의 `service_healthy` · `service_completed_successfully`가 redpanda → topic-init → 하류, neo4j → kg-seed → agent · dmn-mcp, process → agent-worker 순서를 지킨다. 5단계는 그 뒤에 180초를 더 기다린다.
- **Python 패키지 판**: 모든 requirements가 `==`로 고정됐다. cliagents도 커밋 해시로 고정됐다.

## 4. 못 읽은 것

- 실행으로만 확인할 수 있는 것(학교망, OneDrive, Server 서비스가 꺼진 PC, WSL 커널의 Landlock, 실제 메모리 사용량, Supabase 컨테이너의 실제 바인드 주소)은 이번 범위에서 돌리지 않았다. 표에는 「미확인」으로 적었다.
- 대조용으로 일부만 읽은 영역 밖 파일은 1절 끝에 적은 줄 범위만 읽었고, 그 밖은 못 읽었다.
- `.env`는 읽지 않았다(지시대로).
