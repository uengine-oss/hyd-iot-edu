## 2. 화면별 장

표기: **읽기** / **쓰기** = 부르는 API, **단추** = 값을 바꾸는 동작, **들어옴** / **나감** = 다른 화면과의 길, **쪽** = 미니판 · 실습장 · 걸침 · 개발운영.

### 2-1 내 작업함 (`#/inbox`, inbox.js)
- 하는 일: 사람이 승인 · 입력해야 하는 열린 단계와 포털 알림을 담당자(`user:me`) 기준으로 모아 보이고, 누르면 그 처리 건의 단계로 보낸다(`inbox.js:84-91, 149-154`).
- 읽기: `GET /api/inbox/users` · `/api/inbox?user_id=` · `/api/inbox/notifications` · SSE `/api/inbox/notifications/stream`(`inbox.js:26, 47, 58`). 쓰기: `POST /api/inbox/notifications/read`(`inbox.js:77`).
- 단추: 모두 읽음, 알림 한 줄 누르기(읽음 처리). 승인 · 입력 자체는 여기서 하지 않는다.
- 겹침: 「처리할 단계」 = 처리 건 화면의 「내 차례」(`instances.js:166-195`, 데이터는 `/api/todolist?status=IN_PROGRESS` 로 출처가 다름). 이 화면에만 있는 것: 알림 목록 · 읽음 상태 · 역할별 보기 · 기한(due) 표시.
- 들어옴: 알림 종(`shell.js:146`). 나감: 줄마다 `#/instances/<id>/task/<id>`(`inbox.js:72`), 빈 화면에서 결함 시뮬레이션(`inbox.js:112`).
- 쪽: 미니판.
- 없어지면 못 하는 일: 알림 읽음 처리 · 알림 목록 보기(상단 종 숫자는 inbox.js 의 `unread()` 를 읽으므로 모듈 자체는 남아야 한다 — `shell.js:124`).

### 2-2 처리 건 (`#/instances`, instances.js 외)
- 하는 일: 모든 흐름 인스턴스(사건 흐름 · 질문 · 매뉴얼 추출 · 직접 시작)의 목록과 상세, 그리고 **사람 단계의 실제 행동(조치 고르기 · 승인 · 반려 · 폼 제출 · AI 질문 답)이 일어나는 유일한 곳**(`instances.js:4-6`; `enterprise.js:550` 「판단은 처리 건의 승인 단계에서만 승인 · 거절한다」).
- 읽기: `/api/process/mode` · `/api/instances?limit=50` · `/api/process/definitions/{id}` · `/api/todolist?status=IN_PROGRESS` · `/api/todolist?proc_inst_id=` · `/api/instances/{id}`(+`/graph`) · `/api/graph-projections` · `/api/todolist/{id}` · `/api/decisions/{id}`(`instances.js:35-89`), 처리 기록이 `/api/events` · `/api/incidents/{id}` · `/api/agents` · `/api/inbox/users`(`caseRecord.js:7-10, 49`), 실행 중 에이전트 `/api/agents/status` · `/api/todolist?…agent_orch=cliagents`(`agentsPanel.js:18-19`), SSE `/api/events/stream`(`liveStream.js:183`).
- 쓰기: `POST /api/todolist/{id}/select · reject-card · decision-preview · approve · submit · human-response`(`instances.js:334-515`), 승인 재전달 · 폐기 · 단계 닫기 · 실행 취소(`instances.js:805-877`), 다시 수행 `/api/instances/{id}/rework`(`instanceRework.js:126`), 실행 효과 확인 · 취소(`instanceEffects.js:44, 115`), 보류 · 재평가 `/api/todolist/{id}/reassess`(`taskDeferral.js:24, 64`).
- 단추: 조치 카드 고르기 · 승인 · 반려, 폼 제출, 질문 답, 같은 내용 다시 전달, 폐기, 단계 닫기, 실행 취소, 다시 수행, 실행 효과 취소, 보류, 목록 상태 거르기 · 다시 읽기, 상세 탭 넷.
- 겹침:
  - 내 차례 ↔ 내 작업함 「처리할 단계」.
  - 진행 상황 탭의 흐름도 ↔ 판단 · 실행 기록 화면의 「업무 흐름」(같은 처리 건을 같은 `hydFlow.render` 로 그림, `hitl.js:145` vs `instances.js:638`).
  - 결과 보고 카드가 **같은 화면 안에서 두 번**: 진행 상황 탭(`instances.js:682`)과 결과 탭(`instances.js:646`).
  - 처리 기록 탭의 원인 · 증거 · 사건 이력(`caseRecord.js:173, 353-356, 500, 581`) ↔ 이상 확인 · 조치의 「분석 근거」 · 「진행 경과」(`app.js:590, 599`).
  - 「실행 중인 AI 에이전트」 접기 ↔ 시스템 구성 · 상단 띠의 agent-worker 응답 점(`layers.js:25`).
  - 질문 처리 건 ↔ 에이전트에게 질문의 지난 질문 목록(질문 하나 = 처리 건 하나, `ask.js:2`).
  - 이 화면에만 있는 것: 승인 · 제출 등 모든 사람 행동, 다시 수행 · 실행 효과 · 보류 · 재전달 · 폐기, 단계 상세 패널, 단계 표 · 이벤트 원문.
- 들어옴(가장 많음): 내 작업함(`inbox.js:72`), 이상 확인 · 조치 조치 패널 [승인 화면으로 이동](`hitl.js:101-114`) · 사건 상세 [처리 건에서 보기](`app.js:610-615`), 설비 카드의 업무 표시 칩(`app.js:317, 322, 335-338`), 판단 · 실행 기록 [승인 화면으로 이동](`enterprise.js:565-570`), 흐름 가져오기 [시작](`flows.js:525`), 관리 정의 실행(`definitionRegistry.js:121`), 오일 분석 [처리 건 보기](`oilInput.js:51`), 에이전트에게 질문 [처리 건에서 보기](`ask.js:176`), 도구 연결 호출 기록(`mcp.js:339`), 성과 지표 [처리 건 열기](`kpi.js:92`), 홈 바로가기(`main.js:128`). 지식 관리의 추출 실패 문장은 「처리 건 화면에서 확인」이라고만 쓰고 링크가 없다(`hitl.js:655`).
- 나감: 빈 화면에서 결함 시뮬레이션(`instances.js:522`). 그 밖에는 화면 안에서 끝난다.
- 쪽: 미니판(뼈대의 중심).
- 없어지면 못 하는 일: 승인 · 반려 · 제출 · 답변 · 다시 수행 · 효과 취소 등 사람 행동 전부. **모든 주된 흐름이 반드시 거치는 화면.**

### 2-3 결함 시뮬레이션 (`#/scenario`, app.js)
- 하는 일: 가상 설비 3기의 값을 1초마다 보이고, 설비마다 정해 둔 수업 실험 하나(A 쿨러 열화 주입 · 복구, B 정기 점검 시작 · 초기화, C 재고 보충 시작 · 초기화)를 누르게 한다(`app.js:216-306`).

## 4. 주된 흐름 셋의 화면 순서 (코드로 본 길, 실행 안 함)

### ① 문서 올려 지식 만들기
1. 지식 관리 — 파일 선택 → [문서 등록](`hitl.js:815-829`).
2. 지식 관리(같은 자리) — [AI 추출 시작] → 3초마다 결과 확인(`hitl.js:641-674`). 추출은 처리 건 하나로 돌고 처리 건 목록에도 뜬다. 실패하면 「처리 건 화면에서 확인」 글만 있고 링크는 없다(`hitl.js:655`).
3. 지식 관리(같은 자리) — 검토(절차마다 「연결 · 단계 수정」 접기) → 검토 확인 체크 → [검토한 내용 적재](`hitl.js:601-603, 684-768`).
4. 지식 관리 → 지식 지도 또는 조치 방법([…에서 보기] `hitl.js:764`).
5. 판단에 반영됐는지 보려면 조치 판단 규칙이나 조건별 손익으로 메뉴로 가야 한다(링크 없음). 적재 문장이 「후보 규칙에 연결」 여부를 말해 준다(`hitl.js:759-761`).
- 화면 이동: 1~3 은 한 화면, 4 에서 1번, 5 에서 메뉴 1번 → **2~3번**.
- 두 번 보는 곳: 등록한 문서가 카드와 이력 표에 두 번(`hitl.js:420-424`). 적재된 조치 방법을 조치 방법 목록과 지식 지도 노드로 두 번. 「이 문서로 답할 수 있는 질문」은 문서 카드 안, 「판단 채점」은 다른 묶음 — 지식이 쓸모 있는지 재는 두 길이 따로 있다.

### ② 사건 한 건 (A 쿨러)
1. 결함 시뮬레이션 — [쿨러 열화 주입](`app.js:354`). 카드에 「경보가 났습니다. 처리 건의 승인 단계에서…」 안내(`app.js:278`)가 뜨지만 A 카드에는 처리 건으로 가는 칩이 없다(칩은 B·C 만 `app.js:313`).
2. (경보 · AI 판단은 기다림) 상단 「진행 중 사건」 수가 오른다. 알림 종에 숫자가 붙는다.
3. 길 셋 중 하나로 처리 건에 간다: 알림 종 → 내 작업함 → 줄 누르기 → 처리 건 단계 / 메뉴 처리 건 → 내 차례 / 이상 확인 · 조치 → 설비 카드 → 조치 패널 [승인 화면으로 이동].
4. 처리 건 — 조치 카드 고르기 → 승인(또는 반려). 단계 패널에서 끝난다.
5. 처리 건 — 진행 상황 탭에서 명령 · 재관측 · 결과 보고, 처리 기록 탭에서 이야기. 결과 보고는 결과 탭에도 같은 것.
6. (선택) 판단 · 실행 기록에서 업무 시스템 표 변화, 이상 확인 · 조치에서 사건 경과, 실시간 모니터링에서 유온 추이.
- 화면 이동: 최소 시뮬레이션 → (종) 작업함 → 처리 건 = **2번**. 이상 확인을 거치면 3번.
- 두 번 보는 곳: 조치 후보 카드(이상 확인 · 처리 건 · 판단 기록 세 곳), 원인 · 증거(이상 확인 · 처리 건), 사건 진행(이상 확인 · 처리 건), 흐름 그림(처리 건 · 판단 기록), 결과 보고(처리 건 두 탭), 설비 값(시뮬레이션 · 이상 확인 · 모니터링).
- B·C 는 1 에서 [정기 점검] · [재고 보충] → 카드의 「처리 중 →」 칩으로 처리 건에 바로 간다(`app.js:317`).

### ③ 자기 것 만들기
코드가 요구하는 순서는 메뉴 순서와 다르다.
1. 에이전트 — 「담당 배정」 탭 → 「역할 만들기」(흐름의 레인 이름과 같게, `agents.js:316-318`). 필요하면 에이전트 탭에서 새 에이전트 · 스킬.
2. 도구 연결 — 자기 도구 서버 등록 · 연결 검사(에이전트가 그 서버 도구를 고르려면 먼저 있어야 한다, `mcp.js:529`). 그 뒤 에이전트로 돌아가 도구 서버를 붙인다.
3. 흐름 가져오기 — .bpmn 가져오기 → 단계 종류 · 역할 · 에이전트 매핑 → 검사 → 판본 등록(`flows.js:430-447`). 에이전트를 1·2 뒤에 만들었으면 다시 열어야 고르기 칸에 나온다(`flows.js:543-550`).
4. 관리 — 「흐름 판본 배포」 접기를 열고 정의 고르기 · 사유 · 배포(경보로 시작하는 흐름일 때만, `flows.js:441`).
5. 시작 — 경보 흐름이면 결함 시뮬레이션 · 오일 분석으로 경보, 아니면 흐름 가져오기의 판본 줄 [직접 시작] → 시작 폼 → 처리 건(`flows.js:491-529`).
6. 처리 건 — 사람 단계 처리 · 결과 확인.
7. (선택) 시험 비교로 에이전트 A·B — 단 시나리오가 쿨러 · 펌프 · 팬 고정이라 자기 흐름은 못 잰다(`compare.js:2`).
8. (뒷정리) 관리 「내 사례 · 출발본」에서 꼬리표 · 파일 받기 · 되돌리기.
- 메뉴 묶음으로 보면: 인공지능 설정(에이전트) → 인공지능 설정(도구 연결) → 인공지능 설정(에이전트, 다시) → **판단**(흐름 가져오기) → **시스템**(관리) → 판단 또는 설비(시작) → 작업(처리 건) → 시스템(관리). 화면 이동 **6~8번**, 묶음을 네 번 넘나든다.
- 두 번 보는 곳: 단계 담당 에이전트(흐름 매핑 · 에이전트 담당 배정), 등록 · 시작(흐름 가져오기 · 관리 정의 패널), 되돌리기(각 화면 · 관리 출발본).

### 5-3 접을 후보 (개발자 · 운영용을 한 곳으로)
- 관리 「원천 이벤트 접수 · 재시도」(sourceEvents.js) — 사건보다 앞 단계의 접수 원장. 학생 흐름에 나오지 않는다.
- 관리 「프로세스 정의 등록 · 실행」(JSON) — H5 를 하지 않으면 여기로.
- 지식 관리 「질의 보기」(Cypher 8종, `index.html:235-243`).
- 처리 건 「단계 표」 탭의 이벤트 원문 · 지식 반영 상태(`instances.js:68-73, 738-756`), 「모든 처리 건의 실시간 활동」 · 「실행 중인 AI 에이전트」 접기(`index.html:167-168`).
- 데이터 원천(fabric) 전체 — 읽기 전용 진단 성격(H7 을 하지 않으면).
- 시험 비교 — 실습장 시나리오 고정이라 자기 사례에 못 씀(`agent_trials.py:67`).
- 시스템 구성의 외부 도구 링크(서비스 `/docs` · Redpanda · EMQX …).
- 결함 시뮬레이션 「최근 제어 요청 결과」(게이트웨이 기록)는 이미 접혀 있다.
- 함께 옮길 것: 각 접기의 담당자(me) 읽기(`hydInbox.me`), 수업 경계 판정(`hydCourseAccess`).

### 5-4 없앨 후보 (다른 화면이 다 하는 것 — 못 하게 되는 일 0 만)
조건에 맞는 것은 아래뿐이다. 나머지는 2장 「없어지면 못 하는 일」이 0 이 아니다.
- 처리 건 결과 보고의 두 번째 사본(H9) — 한 쪽을 지워도 잃는 것 없음.
- 이상 확인 · 조치의 조치 패널(보기 전용 카드 + 이동 단추, `hitl.js:75-108`) — 처리 건 승인 단계가 같은 카드를 행동과 함께 보인다. 잃는 것 없음(화면 자체는 회로 그림 · 감사 기록 때문에 0 이 아님 → H2).
- 판단 · 실행 기록의 「업무 흐름」 그림(`hitl.js:131-152`) — 처리 건 진행 상황 탭과 같은 그림. 잃는 것 없음.
- 판단 · 실행 기록의 판단 상세 카드 · 승인 이력 — 처리 건 처리 기록 · 승인 단계가 같은 판단을 읽는다(`caseRecord.js:8`). **처리 건 없이 제출된 판단**은 처리 건 쪽에 안 나오므로(`enterprise.js:555-557`), 그런 판단이 생길 수 있는 한 0 이 아니다 — 확인 필요.
- 관리 「프로세스 정의 등록 · 실행」 — 흐름 가져오기가 bpmn 으로 같은 일을 하지만, JSON 직접 등록 · 경보 JSON 시작은 거기 없다 → 0 이 아님(접을 후보).
- 홈 「바로가기」 카드 3장 — 메뉴와 같은 목적지. 잃는 것 없음(다만 첫 화면 안내 역할).

## 6. 처음 온 사람의 눈 (코드로 본 추정)

- 처음 열면 홈이 보인다(`app.js:119`). 그런데 메뉴에서 홈은 맨 아래 「시스템」 묶음 21번째이고, 하단 이전 · 다음 단추는 「21 / 23」 을 보이며 [다음]이 시스템 구성 → 관리 → 마지막 화면으로 간다(`app.js:87-99`). 「무엇부터」를 이전 · 다음 순서로 따라가면 끝 쪽에서 시작하는 셈이다.
- 메뉴 맨 위는 「작업 › 내 작업함 · 처리 건」이다. 처음에는 둘 다 비어 있고, 빈 안내가 결함 시뮬레이션으로 보낸다(`inbox.js:112`, `instances.js:522`). 즉 첫 일은 세 번째 줄(설비 › 결함 시뮬레이션)에 있다.
- 홈의 바로가기 3장과 [설비 상태 확인]은 모두 실습장(결함 시뮬레이션 · 이상 확인 · 처리 건)으로 간다(`main.js:128, 178`). 자기 사례를 들고 온 사람에게 「어디서 만드나」(에이전트 · 도구 연결 · 흐름 가져오기 · 배포)를 가리키는 길은 홈에 없다.
- 자기 것 만들기의 다섯 화면이 묶음 셋(인공지능 설정 · 판단 · 시스템)에 흩어져 있고, 필수 단계인 배포는 「관리」의 닫힌 접기 안이다(4장 ③).
- 묶음 이름만 보고는 뼈대(어디에나 쓰는 것)와 실습장(유압 설비 사례)이 갈리지 않는다. 예: 「판단」 묶음에 실습장 시험 화면과 뼈대 흐름 화면이 같이 있다.
- 같은 아이콘: 오일 분석 입력 · 이상 확인 · 조치가 둘 다 `alert`(`index.html:35-36`), 처리 건 · 판단 · 실행 기록 · 흐름 가져오기가 셋 다 `process`(`index.html:32, 41, 42`), 질문 · 에이전트가 둘 다 `agent`(`index.html:49-50`).

메뉴 이름과 화면 제목이 다른 곳:
- 「에이전트」 ↔ h1 「AI 에이전트」(`index.html:50` · `ui.js:542` vs `agents.js:381`).
- 「판단 · 실행 기록」 ↔ 코드 머리말 「승인과 실행」(`index.html:139` 주석, `enterprise.js:1, 489`) — 화면 글은 같음.
