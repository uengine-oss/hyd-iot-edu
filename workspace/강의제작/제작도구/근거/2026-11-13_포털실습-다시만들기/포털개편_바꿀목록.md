# 포털 개편 — 바꿀 목록 (승인받을 판)

## 이번 범위 (사용자 2026-11-13 「나, 끝 이런 류들 손보고요 … 사용자 행위에 혼란을 주는 것들만」 · 「너무 유치원스럽게 바꾸진 말고」)

**고치는 것은 사용자가 무엇을 해야 하는지 · 무슨 일이 일어났는지를 헷갈리게 하는 것뿐이다.** 현업 용어(결함 시뮬레이션 · 열화 주입 · 적재 · 재측정 등), 메뉴 차례, 글자 크기 · 색 체계는 그대로 둔다. 고친 말은 업무 시스템의 말투로 쓴다.

| 자리 | 지금 | 바꾼 안 |
|---|---|---|
| 내 작업함 고르기 칸 | 나 / 고르기 | 사용자 선택 / 「최운전 (운전원)」. 오른쪽 위 계정 자리에도 같은 표시 |
| 승인 폼 | 「위의 [나 고르기]에서…」(그 화면에 없는 버튼) · 승인자 「최운전 (나)」 | 「승인하려면 사용자를 선택하세요」 + 그 자리의 [사용자 선택] · 「승인자: 최운전 (운전원)」 |
| 처리 건 상태 | 끝 | 처리 완료 |
| 처리 과정 이름표 | 지금 · 넘김 · 수행 · 대기 · 경과 · 맡음 · 남음 · 짐 | 진행 중 · 전달 · 담당 · 대기 중 · 경과 시간 · 배정 · 남은 시간 · 미채택 |
| 처리 건 「내 차례」 | 남의 단계까지 다 보임(열면 「승인할 수 없습니다」) | 선택한 사용자의 단계만 |
| 지식 관리 | [미리보기](실제로는 파일 올리기) | [문서 등록] |
| 지식 관리 | 올리자마자 AI 없이 나오는 절 · 절차 결과와 「수정할 항목 있음」 | AI 추출 뒤에만 표시, 문구 「검토 필요 N건」. 서버의 줄 모양 읽기(`manual_review.proposal`)는 삭제 |
| 지식 관리 | [추출 제안 준비] · [추출 진행 · 결과 확인] 두 버튼 | [AI 추출 시작] 하나, 결과는 저절로 표시 |
| 지식 관리 | 담당자 칸 기본값 「지식 관리자」 | 선택한 사용자로 기록(칸 삭제) |
| 조치 판단 규칙 | [판단 실행] | [모의 판단] + 「승인 · 실행으로 이어지지 않습니다」 |
| 메뉴 | 승인과 실행(여기서는 승인 못 함) | 판단 · 실행 기록 |
| 이상 확인 · 조치 | 누를 수 없는 조치 카드 + [처리 건에서 선택하기 →] | 「승인 대기 — [내 작업함에서 처리 →]」 한 줄 |
| 승인 버튼 | [거절](빨강 채움) · [반려](회색)가 화면마다 다름 | [승인] 주 버튼 · [반려] 보조 버튼으로 통일 |
| 운전 모드 칩 | 원격 자동 | 이름 그대로, 도움말만: 「승인된 원격 명령을 수신하는 운전 모드」 |
| 메뉴 | 데이터 연결 | 데이터 원천 |

이미 낸 다른 회차 영상 · 가이드와 어긋나는 곳은 이 표의 자리뿐이다.

# 참고 — 검토에서 나온 전체 후보 (이번 범위 밖, 고치지 않음)

아래는 독립 검토가 낸 전체 후보다. 위 표에 든 것만 이번에 고치고, 나머지는 기록으로 둔다.

- 기준: **처음 쓰는 학생이 어느 화면에서도 걸리거나 거슬리지 않는다.** 상용 서비스 수준의 말 · 흐름 · 디자인을 목표로 한다. 고치는 것은 혼란을 주는 것뿐이다: 이름과 동작이 다른 것, 뜻이 안 보이는 한 글자 이름표, 개발자 내부어, 같은 것을 여러 이름으로 부르는 것. **현업에서 쓰는 전문 용어(결함 시뮬레이션 · 열화 주입 · 적재 · 재측정 · 사전 확률 · 결정표 등)는 그대로 두고**, 필요하면 도움말 한 줄만 붙인다. 고친 말도 업무 시스템의 말투로 쓰고, 풀어 쓴 유아적인 말은 쓰지 않는다(사용자 2026-11-13 「전문성인데 혼란을 주지 않는 전문성 … 너무 유치원스럽게 바꾸진 말고」).
- 근거: 독립 검토자의 적대 검토(화면 코드 전체 + CSS)와 떠 있는 포털 직접 확인. 가장 큰 결함 셋은 원문으로 확인했다.
- 작업 자리: 로컬 전용 브랜치 `portal-ux`의 작업 사본(`작업/2026-11-13_포털실습-다시만들기/포털개편/`). 수업 폴더(main)와 떠 있는 수업 스택은 건드리지 않는다.
- 바꾸지 않는 것: 서버 API 이름 · DB · 처리 흐름의 동작. 서버는 미리보기의 「줄 모양 읽기」를 지우는 것 하나만 고친다(A-3).

## A. 흐름 — 가장 먼저 고칠 넷

### A-1. 사람 고르기를 「로그인」 자리로

| 지금 | 바꾼 안 | 까닭 |
|---|---|---|
| 내 작업함 안의 고르기 칸 「나」(기본값 「고르기」), 오른쪽 위 「나 선택 안 함」 | 오른쪽 위 계정 자리 하나로 모은다: 「**최운전 · 운전원** ▾」. 누르면 「사용자 바꾸기(수업용 — 로그인 대신)」 목록이 열린다. 아무도 안 골랐으면 「사용자 고르기」 버튼 | 사람 고르기가 업무 동작처럼 보여 「고르면 승인된다」로 읽힌다. 상용 서비스는 로그인이 계정 자리에 있다 |
| 승인 폼 「위의 [나 고르기]에서 이 역할의 사람을 고르세요」(그 화면에는 고르는 칸이 없음) | 「승인하려면 먼저 사용자를 고르세요」 + [사용자 고르기] 버튼(그 자리에서 목록이 열림) | 없는 버튼을 찾게 된다 |
| 승인 폼의 승인자 「최운전 (나)」 | 「**최운전 · 운전원** 이름으로 승인합니다」 | 누구 이름으로 기록되는지 한 문장으로 |

### A-2. 승인은 한 곳에서, 「내 차례」는 정말 내 일만

| 지금 | 바꾼 안 | 까닭 |
|---|---|---|
| 처리 건 「내 차례」가 사람을 거르지 않고 진행 중인 사람 단계 전부를 보인다(`instances.js:50`). 운전원을 골라도 공장장 단계가 뜨고, 열면 「승인할 수 없습니다」 | 「내 차례」는 고른 사용자의 단계만 보인다(내 작업함과 같은 목록을 쓴다). 남의 단계는 「다른 사람의 단계 N」 접기로 | 두 화면 숫자가 다르고, 남의 일을 열어 거절당한다 — 「흐름이 납득이 안 된다」의 실제 원인 |
| 내 작업함 목록을 누르면 처리 건 화면으로 넘어가 거기서 다시 찾는다 | 누르면 그 처리 건의 **그 단계 승인 패널이 바로 열린다**(스크롤 · 강조) | 작업함 → 그 일 → 결정, 한 길 |
| 「이상 확인 · 조치」: 조치 카드 전부 + 「추천」 칩 + [처리 건에서 선택하기 →] | 카드는 읽기 전용으로 접고, 맨 위에 「**승인 기다리는 중** — [내 작업함에서 처리하기 →]」 한 줄 | 카드를 눌러 고르려다 실패한다 |
| 「승인과 실행」 메뉴: 판단 카드 + [처리 건에서 승인하기 →] | 이름을 「**판단 · 실행 기록**」으로. 승인 버튼은 두지 않고 기록만 보인다 | 메뉴 이름이 지키지 않는 약속을 한다 |
| 조치 선택 패널: 제목 「승인 요청」, 버튼 [거절](빨강 채움) · 일반 승인은 [반려](회색) | 제목 「**조치 승인**」, 버튼 [승인하기](주) · [반려하기](보조, 빨간 테두리). 모든 승인 화면에서 같게 | 같은 결정에 이름 넷 · 버튼 말 둘 · 무게 둘. 위험 버튼이 주 버튼보다 눈에 띈다 |
| 다른 안 고르기가 「다른 안 N개는 왜 졌나」 접기 속 [이 안으로 바꾸기] | 안 목록을 고르기(라디오)로 펼쳐 두고, 추천 안에 「AI 추천」 표시. 「왜 이 안이 아닌가」는 각 안 아래 한 줄 | 다른 안을 고를 수 있다는 걸 모른다 |

### A-3. 지식 관리 — 3단계 진행줄

| 지금 | 바꾼 안 | 까닭 |
|---|---|---|
| 버튼 「미리보기」(실제로는 파일 올리기 · 원문 보관) | 진행줄 「① 문서 등록 → ② AI 추출 → ③ 검토 · 적재」. ①의 버튼은 [문서 등록] | 이름과 동작이 다르다 |
| 올리자마자 AI 없이 줄 모양만 읽은 「절 N · 절차 N」 결과 + 「현재 지식 기준 검사」 · 노란 「수정할 항목 있음」 | ①이 끝나면 「올린 문서: 파일 이름 · N쪽 · 글자 읽음」과 [원문 보기]만. 절 · 절차 목록과 점검 칸은 **②가 끝난 뒤에만** 나온다 | AI가 아무것도 안 했는데 결과와 경고가 먼저 떠서 「문서가 틀렸나 · 형식이 정해져 있나」로 오해된다 |
| 서버의 「줄 모양 읽기」(`manual_review.proposal` — 정해진 번호 꼴 문서에서만 맞는 해피패스) | **지운다.** 올리기 응답은 원문 보관 · 읽기 확인 · 이전 판 정보만 준다. 그 시험(`test_manual_review.py`의 해당 두 곳)도 함께 고친다 | 쓰는 곳이 화면과 그 시험뿐이다(시작 파일 · `c3_ingest.py`는 AI 정리 결과만 쓴다 — 코드로 확인). 해피패스 금지 · 지우기 우선 |
| [추출 제안 준비] · [추출 진행 · 결과 확인] 두 버튼, 결과를 보려면 거듭 눌러야 하고 안 끝나면 처리 건 탭으로 보냄 | [AI 추출 시작] 하나. 누르면 「AI 추출 중… (보통 1~2분)」이 뜨고 끝나면 저절로 결과를 보인다 | 다음 할 일이 버튼 이름에 없다 |
| 「현재 결과는 구조화된 줄 파서입니다…」 | 지운다 | 개발자 말 |
| 정리 결과: 절차마다 범위 · 종류 · 고장 유형 · 관계 · 영향 · JSON 접기 · 단계 입력 칸이 기본으로 펼쳐짐. 「영향」 칸에 `sv:bearing-wear:-` 같은 id를 직접 입력 | 절차마다 요약 한 줄(이름 · 연결된 고장 유형 · 원문 쪽)과 [제외] · [수정]. [수정]을 눌러야 칸이 열린다. 「영향」은 지표 선택 + 증가/감소 | 「잘된 건 넘어가고 잘못된 것만 본다」가 칸 수십 개에 묻힌다 |
| 「검토한 내용 적재」 → 「적재 완료: 절 · 조치 방법 · 단계」 한 줄 | [검토 완료 · 적재] → 「적재 완료」 + [지식 지도에서 보기 →] | 막다른 곳. 다음 화면으로 가는 길이 없다 |
| 첫 화면의 「등록할 문서: 새 문서 등록 / ○○ · 문서 개정」 | 기본은 「새 문서」. 개정은 아래 「등록된 매뉴얼」 카드의 [개정판 등록]에서 시작 | 잘못 고르면 앞 문서 지식이 바뀌는 선택이 첫 화면에 있다 |
| 담당자 자유 입력, 기본값 「지식 관리자」(지식 관리 · 업무 데이터 연결 · 조치 방법) | 계정 자리의 사용자로 기록(A-1). 칸은 없앤다 | 역할처럼 보이는 기록용 이름. 다른 화면과 기록 방식이 다르다 |
| 「질의 보기」 버튼 8개 → 질의문 원문 | 지식 관리에서 빼서 「개발자 보기」(C-6)로 | 흐름 한가운데의 개발 화면 |
