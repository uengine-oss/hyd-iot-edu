# 권한과 연결 검사 · 46~53장

실라버스 온라인 61행의 읽기·쓰기 권한을 둘째 쿨러 경보의 생산 오더 조회와 판단 제출에서 시작한다. 49장 그림에 없는 이름을 읽던 대목과 51장에서 호스트의 파일 도구를 마지막 줄로 지칭하던 대목을 실제 위치에 맞췄다.

| 장 | 맞춰 본 화면과 실행 근거 |
|---|---|
| 46~47 | 업무 기록을 읽는 mes_orders와 메일을 쓰는 send_mail을 구별한다. effects-mcp의 같은 요청 키는 첫 결과를 반환한다. 지정한 메일함에서 발송 여부를 확인하는 사례다. |
| 48~49 | readOnlyHint는 서버 선언이다. read_only_verdict와 confirmable에서 도구의 이름·쓰기 표시·추가 확인 조건을 읽었다. 그림에서 part_quotes의 파란 선만 오른쪽까지 이어진다. 마지막 성공 검사의 설정 지문과 현재 설정도 일치해야 한다. |
| 50~51 | 연결 거절·이름 해석/망 경로·시간 초과의 확인 위치를 표에서 짚었다. 기본 별표와 질문 단계의 고정 조회 목록, 차단된 셸의 마지막 두 줄을 allowed_for_run과 대조했다. |
| 52~53 | 추천안 기록과 승인 뒤 설비 명령·메일을 구별했다. enterprise의 TOOLSETS 원문 네 이름과 세 이름을 정비·구매 행에 모두 배치했다. |

공식 LibreOffice 26.8.1.1와 맑은 고딕의 전체 78장 PDF SHA-256은 `3b46e9aa4958353c287dedd5ecccde3444ad9a72869436d93f7542cd445e7868`이다. 45~54장 경계를 비교했다. 전체 PDF 글겹침 0곳, 이 단원 고립어 후보 0곳. 47·52·53장 강사 음원과 나머지 다섯 장의 무료 시험 낭독을 구별해 저장했다. 46~53장은 현장 34~38장의 원본에 영향을 준다(온라인 47·48·49·51·53장). 다음 단원은 54장의 파일 범위다.
