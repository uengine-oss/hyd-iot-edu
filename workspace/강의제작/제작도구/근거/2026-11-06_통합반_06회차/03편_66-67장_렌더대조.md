# 점검 보고서에 남길 근거 · 66~67장

65장의 질문별 호출 기록에서 출처를 확인하는 원리를 로컬의 파일·Git·시간 서버로 이어 간다. 66장에는 실라버스 64행 제목을 그대로 두었다. 67장 가운데의 질문은 파일 읽기를 거부당한 상황에서 보고서에 쓸 수 있는 근거를 묻는다. 상단에는 각 도구에서 확인한 파일 경로·변경 이력·조회 시각을 남기고 읽지 못한 내용은 미확인으로 두는 기준이 보인다. 조회 시각 자체를 파일의 작성 시각이나 점검을 수행한 시각으로 해석하지 않는다.

**실습 원자료.** 배포물 `06일차_실습2_MCP서버조합.zip` 안의 안내.html, 실습 05 대본, 세 서버와 공용 stdio 골격을 열었다. 별도 START.md는 없다. `코드/서버/mcp_기본.py`의 `서버.도구`는 함수·이름·입력 스키마를 등록하고, `tools/list`와 `tools/call`이 그 정의를 사용한다. 배포본은 세 서버 조합을 안내하지만 점검 자료 조회 함수를 새로 써서 등록하고 기존 에이전트에 연결하는 활동은 담지 않는다. 67장 노트는 같은 원칙을 직접 만드는 도구에도 적용한다고 설명한다. 실라버스 64행의 자작 도구 수행은 실습 자료 보완과 별도 검증이 필요하다.

**실행.** ZIP을 분리한 작업 폴더에 풀고 `코드/도구/자료_준비.py`와 `설정_작성.md`의 구성을 사용했다. `연결_점검.py`는 세 서버에 stdio로 접속했다. 동일 클라이언트로 `tools/call`을 보내 파일 서버의 `read_text_file`이 허용된 쿨러 점검 메모의 내용을 돌려주고, 허용 범위 밖 구매팀 파일에는 `isError=true`와 접근 거부를 돌려주는지 확인했다. `git_status`는 수정된 회의록과 미추적 점검 파일을, `get_current_time`은 Asia/Seoul의 조회 시각을 반환했다. 이 검사는 에이전트 추론을 호출하지 않는다.

**정식 렌더.** PPTX `c5eee7969864`, 맑은 고딕을 사용한 LibreOffice 26.8.1.1 PDF `23d2b145a895`. 65~68장의 실물 렌더를 보았고, 66장 간지와 67장 중앙 질문의 읽는 순서를 확인했다. 전체 글겹침 0곳, 65~68장 고립어 후보 0곳, 덱 원고 78장 형식 검사 통과. 실습 소개는 이론 본문 시간에서 제외되며 현장 6회차 이론에 이 두 장을 복사하지 않는다.
