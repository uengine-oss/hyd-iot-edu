## 가이드만으로 부족했던 곳(고칠 방향)

1. **12단계 「포털 기준 지도와 비교」 — 화면이 없음(막힘).** 할 일 · 요청에 담을 것 · 실행 방법이 모두 「guide.html 이 단계에 실린 지식 지도 화면」을 가리키는데, guide.html과 안내.html에 그림(`<img>` · `<svg>`)이 0개다. 질문 4와 판단할 증거(「설비 · 쿨러 · 센서마다 두 쪽의 식별자와 관계 방향」)를 채울 수 없다. → 포털 지식 지도의 설비 → 쿨러 → 센서 화면(식별자와 화살표 방향이 보이게)을 이 절에 넣거나, 사진을 못 넣으면 그 화면의 식별자 · 방향을 글 표로 싣는다.
2. **12단계가 쓰라는 「8단계 조회 결과」에는 식별자가 없을 수 있음.** 8단계 요청 힌트는 물리량 · 단위 · 한계만 말해서 조회가 구성 요소 「이름」만 돌려준다. 12단계에서 id를 보려면 조회를 하나 더 돌려야 했다. → 8단계 「결과의 꼴」에 「구성 요소 · 센서의 id도 함께」를 넣거나, 12단계 실행 방법에 id를 돌려주는 조회를 요청하라고 적는다.
3. **8~10단계 「설비 하나를 받아」 · 「품번 하나를 받아」를 Browser에서 어떻게 넘기는지 없음.** 나는 「맨 위 한 곳에서 바꾸게」라고 요청해 `WITH "HYD-01" AS assetId` 꼴을 받았지만, 학생이 그냥 요청하면 `$asset` 꼴이 나와 Browser에서 「Expected parameter(s)」로 멈출 수 있다(완성본 queries/는 `:param asset => ...`을 먼저 실행하는 방식). → 8단계 실행 방법에 「`$` 자리가 있으면 `:param 이름 => '값'`을 먼저 실행」 한 줄이나, 요청 힌트에 「물을 값을 바꾸는 자리」를 넣는다.
4. **3단계 판단할 증거가 「줄이 실제로 있다」에서 멈춤.** 루나가 수정본 삭제 줄을 중복 행으로 못 봤어도 증거는 통과한다. 함정은 11단계 증거(「실제로 있는 센서가 사라지지 않았는지」)에서야 잡힌다. → 3단계 「정하거나 물을 것」에 「삭제 · 수정 줄이 원자료의 어느 행과 같은 값인지도 짚게 한다」를 더하면 더 일찍 잡힌다(선택).
5. **수정본 반영 뒤 적재만 다시 돌리면 고친 값이 되돌아감.** 루나가 만든 load.cypher는 `SET node = row.props`라 update 뒤 load를 다시 실행하면 HYD-02 이름 · HYD-07 상태 등이 원래 값으로 돌아간다. 13단계 「다를 때」의 「같은 순서로 다시 실행」이 막아 주지만, 11단계에는 말이 없다. → 11단계 「왜 하는가」나 13단계에 「다시 넣을 때는 적재 → 수정 순서로」를 한 문장 더한다(선택).
6. Browser에 48KB · 14문장짜리 load.cypher를 한 번에 붙여 넣는 일, 연결 창(비밀번호 비움)은 이 리허설에서 확인하지 못했다(미확인) — 이 PC에서 실제 Browser로 한 번 확인할 것.
