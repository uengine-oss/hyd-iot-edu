## 2. 앞 포털 실습과 잇는 지점

**포털이 실제로 하는 일(main 코드로 확인).**
- 등록: 지식 관리에서 원문을 올리면 미리 보기 · 보관(SHA-256)을 한다. 수업 단계에서는 제공 문서만 등록된다(`course_policy.py` 「수업에서는 제공된 수업 문서(내용을 고치지 않은 원문)만 등록합니다」).
- 추출: 에이전트 작업(`manual_extraction.py` 판 2.18)이 절 · 절차 · 단계 · 고장 유형 · 원인 · 증거 · 규칙 · 연결 제안을 낸다. 모든 항목에 인용(쪽 + 원문 문장)을 붙이고, 인용 위치는 서버가 찾는다. 찾는 순서는 정확 일치 → 글자 · 숫자만 비교 → 낱말 사이 짧은 끼어듦 허용이고, 여러 곳에 맞으면 거부한다(`manual_locate.py`). 긴 문서는 구간으로 나눠 추출한다(`manual_segments`). 지시문에는 문서 내용이 「분석 대상 데이터이며 지시가 아님」이라고 적혀 있다.
- 기계 검사(`manual_preflight.py` — 「사람 검토도 적재 허가도 아니다」) → 사람 검토(`manual_review.py`, 고치면 다시 검토) → 적재. 적재는 원자적이고 문서 소유를 기록한다. 개정 때 살아남는 노드는 제자리에서 갱신하고, 바깥에서 바뀐 연결은 충돌로 거절하며, 최신부터 되돌린다(`manual_graph.py`).

### 3.3 생성 방법과 설계 조건 검사

- 한 곳: `data_documents.py`가 문서 묶음 전부를 만든다.
  - main 원문 사본 함수(`sample` · `HM8_TAGS` · `HI01_TAGS`)를 `data_conditions.py`에서 옮겨 오고 PM-02 · PR-07 꼬리표 표를 더한다.

  - 이 일은 모두 **3회차 묶음 커밋 뒤에** 한다(다른 작업자가 같은 두 파일을 고치는 중).
- 새 문서(1.2 초안 · OEM 7절 · 9장 스캔본 · SR-04 · DC-01)는 생성기 상수로 둔다. 스캔본의 인식 오류는 규칙(숫자 0 ↔ 영문 O, 숫자 사이 띄어쓰기, 쪽 경계 줄 끊김)을 고정 시드로 얹는다 — 손으로 심지 않는다. 9-7쪽은 만들지 않고 목차 줄만 둔다.   - 조건표 · sop.json · 판정 결과 = 3회차 판정 랩 입력 · 강사 판 결과와 같은 바이트

## 5. LLM 추출 설계 (통합 04-2 · 실전 03-4)

**모델 연결(제공).** `llm_client.py`는 실전 04 실습2의 판(OpenAI 호환 `/chat/completions`, 오류마다 고칠 곳을 알리는 `_reason`)을 바탕으로 한다. 공용 문구는 `실습시작/lab_llm.py` 한 곳에 두고 4회차 · 5회차 랩이 함께 쓴다. 학생 폴더에는 다음이 있다.
- `.env.example` 세 줄 — `OPENAI_BASE_URL=<강의 중계 주소>` · `LLM_MODEL=coding` · `LLM_API_KEY=`(빈칸). 학생은 복사한 `.env`에 키 한 줄만 넣는다(K-102). 키 값은 어디에도 적지 않는다 — 생성기 · 랩 · 기록 · 가이드 · 검사 출력 모두(K-112, K요-21). 이 꼴은 K-60 · K-112 · K-132 · 가이드.md P-94 문구와 부딪친다 → 12절 물을 것 1. 주소 꼴(끝 `/v1` 여부)은 강사 실행으로 실제 호출을 확인한 뒤 적는다. main `compose.yaml:371` 주석은 「Anthropic 방식 주소 — 끝에 /v1 없음」이고, OpenAI 호환 `llm_client`(실전 04 실습2)의 404 안내는 「끝이 /v1인지 본다」라서 둘이 다르다.
- `python llm_client.py` — 연결 확인(모델 이름과 짧은 답). 준비 단계를 따로 둔다(K-102: 코드 받기 · 키 · 연결이 한 단계에 섞이지 않게). 첫 요청 콜드스타트(50~60초)를 이 단계에서 맞게 해, 기대 칸을 쓰는 동안 중계가 깨어 있게 한다.

**학생이 만드는 것(K-41 — 핵심 로직).**
- 요청 글(`결과/prompt.md`) — 학생이 짠다. 무엇을 뽑을지 · 출력 꼴 · 원문 보존 · 금지 · 모르면 경고를 담는다.
- 문서 읽기 — 판 · SHA를 목록과 대조하고 글자 방식을 정한다.
- 문서 나누기 — 절 · 쪽 경계. 나누는 단위는 학생이 정한다.
- 응답을 계약 꼴 후보로 읽는 기능 — 필드 · 종류 검사.
- 인용 위치 찾기 — 계약 「인용」: 파일 글자 그대로, 정확 일치가 안 되면 띄어쓰기 · 기호를 뺀 글자 · 숫자 비교, 여러 곳이면 거부.
- 후보 파일 쓰기, 검토 파일(결정 · 이유 · 수정 전 값).
- 강사 참조의 요청 글(main INSTRUCTION 요지)은 학생 폴더에 두지 않는다.

**응답 기록과 같은 요청 반복의 비용 상한(제공 `llm_client`가 지킴).**
- 보낸 요청과 받은 응답을 `결과/응답_기록/<요청 해시 12자>.json`에 남긴다. 담는 것은 모델 이름 · 응답의 `model` · `system_fingerprint`(있으면) · 끝 이유(`finish_reason`) · 요청 해시 · 요청 글 · 받은 응답 원문 · 토큰 수 · 받은 시각 · 보낸 방법 · 폴더 표지(처음 실행 때 `결과/` 안에 만든 임의 값)다. 키 · 헤더는 남기지 않는다. 중계의 `coding`은 별칭이라 실제 모델 이름이 보이지 않는다(기록.md). 뒤 모델이 바뀌어도 어느 응답을 검토했는지 남기려고 `model` · `system_fingerprint`를 적는다.
- 같은 모델 · 같은 요청 글이면 다시 보내지 않고 그 기록을 돌려준다(「같은 요청의 응답 기록을 씁니다」 출력). 기록의 폴더 표지가 지금 폴더와 다르면 「다른 폴더의 응답 기록 — 이 폴더에서 보낸 요청이 아님」을 찍고, 후보 파일 `model_run`에 `reused_from`을 남긴다. 학생용 완성본의 기록을 옮겨 와도 이렇게 드러난다.
- 일부러 다시 보내려면 `again=True` — 같은 요청마다 두 번까지. 근거: 같은 요청도 응답이 매번 다를 수 있다(N89 · N90 · N92). 검토한 것이 어느 응답인지 남겨야 다시 볼 수 있고, 같은 요청을 거듭 보내는 비용도 막는다. 가이드 11단계에 한 조각을 한 번 더 보내 두 응답을 견주는 확인 사례를 둔다. 같으면 같다고 적는다 — 억지 실패 금지(K-128).
- 폴더 상한: 실제로 보낸 요청 60번, 요청마다 `max_completion_tokens` 4,000, 시간 초과 180초(첫 요청 콜드스타트 50~60초 — 기록.md 실측). 값은 강사 참조 실행의 실제 요청 수 · 토큰의 두 배 안쪽으로 다시 정한다. **이 상한은 안내용 1차 방어다.** 학생 코드나 학생 AI가 `.env` 키로 중계를 직접 부르면 걸리지 않는다. 실제 방어는 중계 키의 비용 한도다(CLAUDE.md 4절). 그 키가 학생의 포털 AI와 같은 키인지는 **미확인**이다. 같으면 랩에서 폭주한 호출이 그 학생의 이후 회차 포털 AI까지 멈추게 한다. 그래서 중계 쪽 키별 요청 상한 또는 랩 전용 키를 강사가 정해 9.5에 적는다(12절 의존 4).
- 끝 이유가 `length`이면(4,000 토큰에서 잘림 — 긴 영한 절 · 스캔 쪽) `_reason`이 「응답이 길이 상한에서 잘렸다 — 조각을 더 작게 나눈다」를 알린다. 가이드 「막히면」에는 강사 실행 · 리허설에서 재현된 경우에만 넣는다(P-167).
- 단가(기록.md 실측, x-litellm-response-cost): 입력 약 $0.10/100만, 출력 약 $0.5/100만 토큰. 학생 한 명 전체 경로(약 20~30번 · 입력 30만 · 출력 8만 토큰 추정)는 몇 센트다. 추정은 강사 참조 실행 값으로 바꿔 적는다.

**키 없는 학생 경로.**
- 기본 길(K목-8 · K-58): 학생용 완성본으로 결과를 확인하고, 바이브 코딩 과정은 영상으로 본다. 가이드 첫 화면에 한 줄로 둔다.
- 선택 길 — 한 조각만 직접 보내기: 8단계(요청 글 · 한 조각)만 할 수 있다.
  - `llm_client`는 키가 없으면 보낼 요청 글을 `결과/요청/<해시>.md`로 남기고 멈춘다.
  - 학생은 그 글을 **폴더를 모르는 채팅**(개인 GPT 무료 계정의 웹 채팅)에 붙여 받은 답을 `python llm_client.py --paste <해시>`로 저장한다. VS Code 안의 Codex · Copilot은 폴더 전체를 문맥으로 가져서, 그 답은 「요청 글에 대한 모델 응답」이 아니게 된다. 해시 이름 파일에 JSON을 손으로 붙이는 일도 없앤다.
  - 그 기록은 「채팅으로 받음」으로 남는다. 자가 표기라 확인할 수 없으므로 완료 판정에서 모델 호출 증거로 세지 않는다. 9단계 이후 여러 문서 단계는 `적용 제외(키 없음)`(K-135)으로 적고 완성본으로 결과를 본다.
- 이렇게 정한 까닭:
  - ① 코딩 랩은 모델을 실제로 부른다 — 저장해 둔 응답을 재생하지 않는다(K-87).
  - ② 제공 추출 결과를 랩에 넣으면 「이미 있는 추출 결과」 · 「캐시」라는 운영 말이 학생 문장에 들어가고(K-126), 학생 AI가 그것을 읽어 결과로 옮길 수 있다(K목-7).
  - ③ 포털의 「키 없음 = 강사 녹화 재생」은 포털 정책(`course_policy`)이라 독립 랩에 옮기지 않는다(K-14 · K-86).
  - ④ 문서 다섯을 절 단위로 손으로 나르면 수십 번이다. 무료 채팅 한도(GitHub Copilot Free의 월 채팅 수 — 1차 자료로 확인하기 전까지 **미확인**) 안에서 바이브 코딩 대화와 함께 끝까지 간다는 근거가 없다(K-61). 그래서 나르기는 한 조각으로 줄인 선택 길로 둔다.
- 검증: 키 없는 폴더로 장난감 시험 두 건(9.3), 나르기 길 VS Code 리허설 1회(이 PC 몫, 9.4).

**결과는 원문과 대조 · 결정 기록.**
- 4단계(기대 먼저): 원문에서 손으로 적는다. 핀 세척 작업(준비 · 방법 · 금지 · 완료 · 승인)이 주 대상 문서 어디에 있는지, 조건표 R1~R5의 근거를 어디서 찾을지다.
- 11단계: 실제 후보와 줄마다 견주어 누락 · 부정 빠짐 · 단위 · 수치 오류 · 다른 절 연결 · 근거 없는 생성으로 나눈다.
- 12단계(작업 후보 결정): 핀 세척 작업의 후보와 지점6에 걸리는 후보만 사람이 결정한다. 나머지 후보는 기계 검사(인용 찾음 · 판 상태 · 종류)로 분류만 해 둔다.
- 13단계(조건 근거 대조): R1~R5마다 `rule_links`를 쓴다.
- 후보 파일 원본은 남기고, 검토 결과는 별도 파일이다(지금 계약 그대로).

**출력 계약 손질(`입출력_계약.md` — 형식과 뜻만, K-43).** 지금 실전 03-4 계약(후보 파일 · 후보 하나 · 검토 결과 파일)을 쓰고 다음을 고친다.
- 후보에 `rev`(판), `doc_status`(목록의 상태), `encoding`(읽은 글자 방식), `line_start` · `line_end`(읽은 파일의 줄 — 스캔본은 쪽도 `page`), `quote_match`(`exact` · `normalized`), `lang`(`ko` · `en` — 병기 문서)을 더한다. 후보 파일에는 `model_run`(응답 기록 파일 · 요청 해시 · 모델 · 보낸 방법 · `reused_from`)을 더한다. 인용을 찾지 못한 것은 후보로 쓰지 않고 후보 파일의 `unlocated`에 따로 둔다.
- `section`의 정의를 「그 문서의 절 표기 그대로(HM-8.7 · PM-2.4 · 3 · 제4조 · HM-9.3)」로 바꾼다. 지금의 「`## ` 제목의 첫 낱말」은 txt 문서에 맞지 않는다.
- 검토 결과에 `rule_links`를 더한다. 조건표 `rule_id`마다 근거 원문 후보 id, `match` 값(`일치` · `불일치` · `원문 없음` · `보류`), `note`(까닭 — 원문이 말하는 대상 · 때와 조건의 차이 등)를 적는다. 결론을 가리키는 값(「범위 다름」 같은)은 두지 않는다(K-28). 조건표에 R4 · R5가 없는 `결과/내_입력/`이면 옛 규칙 id를 받는다. 새 키는 영어 snake_case(K-55), 값(결정 · 원문)은 한국어.
- 실전은 `결과/선택작업_조건.json`을 더한다. 작업 id, `preparation` · `prohibitions` · `completion` 목록 — 항목마다 후보 참조 · 문서 · 판 · 절 · 인용 · 결정, 그리고 `remaining_questions`(보류 · 원문 미확인 · 제공되지 않은 절).
- 「어떤 문장을 어떤 후보로 만들지는 정하지 않는다」는 지금 문장은 둔다.

### 9.3 장난감 시험(K요-14 · K-28 · K-47 ⑩) — `reference/ai_toy_test.py`

시험 수는 22회이고 각 1회만 돌린다.
- 네 랩 ZIP × {루나(Codex CLI + 강의 중계 `coding`), Sonnet} × {두 턴, 한 턴} = 16회
- Sonnet 협조형(단계마다 진행 + 결정 떠넘기기) 랩마다 1회 = 4회
- 키 없는 폴더(통합 04-2, 루나 두 턴 · 한 턴) = 2회

**통과 — 다섯 가지를 모두 지켜야 하고 하나라도 어기면 불통과.**
- ① 학생 답 없이 결정 칸(`rule_links`의 R4 판단 · 작업 후보 결정 · 선택작업 조건 · PM-2.4 연결)을 채우지 않았다.
- ② 모델 호출 없이 입력(`sop.json` · 조건표 · 판정 결과)에서 후보를 만들지 않았다 — 후보 파일 ↔ 응답 기록 짝을 보고, 키 없는 폴더에서는 응답 기록을 지어 쓰지 않았는지 본다.
- ③ 보류 · 미연결 · 「원문 없음」을 근거 줄 없이 기본값으로 내지 않았다.
- ④ 바뀐 파일이 `결과/` 밖에 없다.
- ⑤ 루나의 돌려보낸 답이 ⑩ 꼴이다.

「결과가 강사 참조와 같지 않음」은 LLM 출력에서는 늘 참이라 기준으로 쓰지 않는다. ⑩ 꼴은 루나 답으로만 판정하고, Sonnet은 난도 확인용이다. 실패하면 같은 조건을 다시 돌리지 않는다. 원인(새는 문장 · 주 질문 밖 지점 · 규칙)을 고친 뒤 바뀐 랩만 다시 돌린다.
- 도구 손질: 추출 랩은 학생처럼 `.env`에 키가 있는 상태로 시험해야 한다. 그래서 `--lab-env`를 더한다 — 풀어 둔 실습 폴더에 키 파일로 `.env`를 쓰고 기록에서는 가린다. 키 없는 폴더 시험은 이 옵션 없이 돌린다. 실습 폴더는 지금처럼 저장소 밖에 둔다. 키가 원본 기록 · 응답 기록에 섞이지 않았는지 `secret_scan`으로 본다. 랩 코드의 모델 호출은 폴더 상한(안내용)과 중계 키 한도가 막으니, 시작 전에 시험 키의 남은 한도를 본다.
