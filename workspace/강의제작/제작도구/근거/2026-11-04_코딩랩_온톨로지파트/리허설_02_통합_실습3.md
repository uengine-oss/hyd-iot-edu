## 가이드만으로 부족했던 곳

1. **6단계 「정하거나 물을 것」 · 「확인 방법」** — 「태그 이름이 다른데 같은 물리량을 재는 센서를 모아 보여 달라고 한다」만으로는, 루나가 같은 설비의 태그 가운데 일부(Q_MAIN · T_OIL)는 묶고 일부(P_MAIN · T_TANK)는 「근거 약함」으로 따로 둔 것을 학생이 알아채기 어렵다. 표가 그럴듯해서 노베이스는 그대로 넘어갈 가능성이 큼 → 기준답 갈래와 어긋남. 고칠 방향: 확인 방법에 「따로 둔 물리량마다 왜 따로인지 원자료 줄로 말하게 하고, 같은 설비 안에서 묶은 것과 따로 둔 것의 기준이 같은지 본다」를 더하고, 정하거나 물을 것에 「계장태그 칸(현장 메모 4절)도 같은 물리량의 근거가 되는지 묻는다」를 넣는 것.
2. **7단계 「지킬 것」 「단위를 알 수 없는 값은 짐작하지 않고 미확인으로 둔다」 ↔ 기준답** — 이 문장대로 HYD-03 VS1(센서 54행, 단위 빈 칸)을 「미확인」으로 두었는데, 기준답(`reference/통합반/기대답.json` A · B 모두, `graph.json`)은 `mm/s`. 둘 중 하나를 맞춰야 함: 기준답이 맞다면 7단계에 「같은 물리량의 기준 단위나 같은 모델의 같은 태그로 단위를 알 수 있으면 그 근거 줄로 채우고, 원래 빈 칸을 남긴다」를 넣고, 가이드 문장이 맞다면 기준답과 검사(판정)가 `미확인`도 받게.
3. **10단계 「지킬 것」 「9단계 기능을 바꾸지 않는다」** — 확인 코드 하나가 설비 코드와 품번을 함께 받으므로, 「없는 값」 문구는 9단계 때(「모델에 없는 설비 코드」)와 달라질 수밖에 없다. 가이드는 이 지점을 말하지 않아 학생이 직접 정했다(나는 「모델에 없는 설비 코드 · 품번 · 표기: …」 한 줄로 허락). 고칠 방향: 10단계 「정하거나 물을 것」에 「설비 코드도 품번도 아닌 글자를 어떻게 알릴지」를 넣고, 지킬 것을 「9단계에서 있던 설비의 출력은 바꾸지 않는다」로.
4. **질문 2 뒷부분(이름이 달라도 같은 물리량 찾기)** — 9 · 10단계는 설비 · 품번으로만 묻게 해서, 이 질문은 확인 코드로 물어보는 단계가 없다. 나는 6단계 `build_model.py` 출력의 물리량 표로만 확인했다. 고칠 방향: 9단계 확인 방법에 「같은 물리량의 다른 설비 센서도 함께 보이는지」를 넣거나, 6단계 표를 질문 2의 판단 증거로 쓴다고 분명히.
5. (작음) **8단계** — 「근거 없이 품번을 짐작해 잇지 않고」만 읽은 조심스런 학생은 HYD-03 주 펌프 A(29행 빈 칸)를 미확인으로 남겨 P-PMP-SEAL 사용 설비가 두 대가 되기 쉽다(기준답은 세 대, 근거 예비품 2행). 「칸이 비었거나 품명만 적힌 행을 어느 근거 줄로 이었는지 묻습니다」가 있어 나는 풀었지만, 「빈 칸이라도 다른 자료(예비품 목록 비고)가 그 설비를 짚는지 찾는다」가 있으면 덜 갈림.
6. (작음) **요청하지 않은 파일** — 루나 실행 중 실습 폴더 맨 위에 빈 `.git` 폴더(18:54, Codex 샌드박스가 만든 것으로 보임)와 `결과/__pycache__/`가 생김. 가이드는 「요청하지 않은 파일이 생기지 않았는지 확인」하라고 하므로 학생이 당황할 수 있음. VS Code 탐색기는 `.git`을 기본으로 숨기지만 `__pycache__`는 보임 → 「`__pycache__`는 파이썬이 저절로 만드는 폴더라 괜찮다」 한 줄이 있으면 좋음(이 환경 특성일 수 있어 Windows Codex에서 다시 볼 것).
7. (환경) 12단계 VS Code 닫고 다시 열기는 이 환경에서 못 해 새 셸로 대신함 — 미검증.
