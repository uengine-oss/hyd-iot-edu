학생 몫과 제공 몫의 경계(사용자 말)
- 학생이 AI와 구현하는 것: 「어떻게 잡느냐에 따라 방향이 갈리는」 판단이다. 예는 너무 큰 문서를 어떤 단위로 나눌지, 무엇을 조건으로 뽑을지, 사내 기준과 제조사 기준 중 무엇을 따를지, 지식을 그래프에 어떤 모양으로 이을지다. 사람마다 결과가 다르게 나와도 좋다.
- 제공하는 것: 「문자열 공백 제거」처럼 누가 해도 같은 일반 로직이다. 결제 모듈을 가져다 쓰듯 준다. 글자 방식 처리, 파일 읽기, 모델 호출, 인용 줄 찾기, 계약 꼴로 쓰기, 적재 실행, 내보내기, 검사가 여기에 든다.
정답과 가이드: 정답은 둔다. 가이드의 단계마다 「정답 보기」 토글로 넣고, 학생은 힌트 · 상황을 보고 AI와 스스로 해 보다가 막히면 펼쳐 따라 가거나 AI에 붙여 넣는다. 그래도 안 되면 학생용 완성본으로 결과를 보고 넘어간다. 정답 토글 가이드는 VS Code로 여는 랩 폴더와 ZIP 밖에 둔다(노션 「가이드문서」 링크, 그리고 시작 도구가 랩 폴더 옆에 내려 두는 가이드 파일). 폴더 안이면 학생 AI가 펼치기 전에 먼저 읽기 때문이다 — 토글은 사람 눈에만 숨긴다. 랩 폴더에는 정답 없는 `START.md`와 힌트만 두고, 작업 규칙에 「가이드 문서는 열지 않는다」 한 줄을 더한다.
결과 보기: 학생 폴더 루트의 제공 파일 하나가 단계마다 `결과/보기.html`을 다시 쓴다. 파이썬이 쓰는 순수 HTML에 공용 CSS(12랩 같은 모양)와 작은 바닐라 JS를 더하고, 표준 라이브러리만 쓰며, 서버 · 설치 · 인터넷 없이 연다. 처음 ZIP의 `결과/`에는 README와 빈 틀만 둔다. Vue · npm은 쓰지 않는다. 그래프 모양은 랩 DB의 실제 Neo4j Browser로 보고, 터미널은 명령과 오류에만 쓴다.

- 유료 실행(강사 추출 재실행 · 리허설 · 장난감 시험)은 목적과 상한을 정해 한 번씩 하고, 실패한 같은 조건은 다시 돌리지 않는다.

- fable 모델은 쓰지 않는다.
- workspace를 오염시키지 않는다: 지침 · `workspace/README.md` · 남은일 · 근거 문서에 덧붙이지(append) 않는다. 규칙이 더 바뀌면 그 주제 자리를 다시 써서 합치고 재편검사 오류 0. 생성기 상태를 적은 사실 칸(실습시작 README 「생성」 표 「지금」 칸)은 사실대로 고친다.
- 커밋은 `동기화.py pull → commit --만 <경로> → push`로 한다. 경로는 실습시작의 바꾼 생성기 · 제공 도구 · 참조 · 완성본 묶기, `package-index.json` · `catalog.json` · `실습시작.zip`, `산출물/*/실습/0[2-4]회차/랩/` 가운데 대상 12랩, 그 완성본이다. 다른 세션 미커밋은 넣지 않는다.
- 결정과 진행은 작업 폴더 `기록.md` 하나에 지금 사실로 고쳐 쓴다. 이번 일은 끝나도 작업 폴더를 지우지 않는다.
결과를 DoD와 번호마다 대조해 원인을 고치고 바뀐 범위만 다시 검증한다. 같은 실패가 세 번 되풀이되면 그 시도를 멈추고 의도 · DoD · 입력의 어긋남부터 다시 본다. 사용자 결정이나 새 비용이 필요한 곳은 판단 재료와 함께 묻고, 독립적으로 할 수 있는 일은 계속한다.

[50분과 가치 — 사용자 요구]
1. 12랩 각각이 오프라인 실라버스 그 칸(50분 — 강사 설명은 짧게 있을 수도 있고 학생은 실습하며 듣는다, 학생이 파악 · 고민 · 판단하는 시간 포함) 안에 끝나야 한다. 실전 한 칸에 랩 둘이면 사용자가 정한 처리대로 판정하고, 포털과 한 칸이면 랩 몫 35분으로 판정한다.

6. 학생이 AI와 구현하는 곳은 방향이 갈리는 판단뿐이어야 한다. 공백 정리 · 글자 방식 · 파일 읽기 · 모델 호출 · 인용 줄 찾기 · 계약 꼴 쓰기 · 적재 실행 · 내보내기 · 검사 같은 일반 로직은 제공 코드로 돌아가야 한다.
7. 사람마다 다른 선택이 나올 수 있는 자리마다, 학생이 고른 것과 원문 근거를 적는 칸이 있어야 한다.
8. 단계를 하나 깰 때마다 제공 HTML 결과 화면에 그 단계의 결과(대조표 · 판정 변화 · 전후 개수 등)가 보여야 한다.

12. 정답이 든 가이드가 랩 폴더 · ZIP 안에 없어야 하고, 시작 도구로 받으면 랩 폴더 옆(VS Code로 여는 폴더 밖)에 놓여야 한다.
13. 단계마다 힌트가 다섯 요소(목적 · 입력 · 지킬 것 · 결과의 꼴 · 확인 방법)를 갖추고, 그대로 보내면 결과가 나오는 완성 프롬프트는 0이어야 한다(정답은 폴더 밖 가이드 토글에만).
