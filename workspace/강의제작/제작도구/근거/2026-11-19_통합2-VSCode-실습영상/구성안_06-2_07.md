# 2회차 VS Code 실습 영상 세 편 — 장 차례

## 06-1 VS Code 랩 시작하기 — 바이브 코딩으로 일하는 법 (약 32분)

**랩 진행 (짧게)**

1. 여는 말(상황부터): 여러분은 유압 공장 보전팀이 보낸 자료를 받은 지식 정리 담당이다 → 보전팀은 이런 질문을 자주 받는다 → 우리가 할 일은 그 질문에 답하는 지식을 만드는 것이다 → 문서를 넣으면 한 방에 지식이 되는 인제스천은 4회차에서 배우는데, 그것도 담을 틀이 먼저 있어야 한다 → 그래서 오늘은 정석대로 한 걸음씩: 가장 먼저 설비 · 부품 · 센서 같은 기본 자료를 가져와 틀을 세우고 채워 본다(현업도 이 뼈대는 회사 시스템의 표에서 옮겨 온다)
2. 폴더 받아 열기: ZIP 받기 → 압축 풀기 → VS Code로 열기 → 신뢰 (직접 녹화)
3. VS Code 화면: 파일 목록 · 편집기 · 터미널 · Codex
4. 랩 구조와 첫 실행: 폴더 네 부분, `python run.py`

**바이브 코딩 (길게)**

5. 바이브 코딩이란: 말로 시키고, 결과는 내가 판단한다
6. 해 온 방식의 문제: 막연하게 「정리해 줘」 → 맞는지 모르는 블랙박스
7. AI와 일하는 관계: 처음엔 물어 가며 배우고, 익숙해지면 내가 위에서 판단
8. 잘 쓰는 요령 8가지: 제대로 갖춘 부탁을 다시 보내 자료를 파악
9. 일하는 차례 7가지: 방금 한 것이 첫 걸음
10. 폴더가 나뉜 까닭: 핵심만 비워 둔 랩, 규칙 파일 AGENTS.md (Claude Code에서는 CLAUDE.md)
11. 끝의 뜻: 내 말로 설명할 수 있어야 끝

## 06-2 온톨로지 설계 (약 37분): 자료를 어떻게 정리할지 정한다

1. 질문과 기대 답: 오늘은 문서 넣기가 아니라 담을 틀을 정하는 설계라고 한 마디 되짚고, 현장 메모의 「알고 싶은 것」 셋 → 나와야 할 답을 먼저 적기(시험지와 답안지부터)
2. 클래스 · 식별자 · 관계: 무엇을 한 종류로 볼지, 무엇으로 구별할지, 어느 쪽으로 이을지
3. 고르기 ①: 바꾼 펌프를 따로 셀까 → 따로 센다
4. 고르기 ②: 온도를 하나로 묶을까 → 재는 자리마다 나눈다
5. 부품 번호 잇기: 여러 표기를 한 번호로
6. 확인: 다른 설비 · 옛 번호 · 없는 번호로도 물어보기
7. 마무리: 다시 열어 같은 답인지 보고, 무엇을 왜 골랐는지 내 말로

## 07 그래프 구현과 검증 (약 39.5분): 정한 대로 넣고 꺼내 본다

1. 랩 DB 띄우기: Docker로 그래프 DB 띄우기
2. 받은 모델 보기: 클래스 → 레이블, 대상 → 노드, 관계 → 화살표
3. 기대 답과 고르기: 안 쓰는 설비를 지울까 → 「안 씀」 표시만 바꿔 남긴다
4. 넣기: 한 번 더 넣어도 늘지 않게
5. 질문 ① ② 쿼리: 하나씩 묻고 기대 답과 맞추기
6. 질문 ③ 쿼리: 다른 표기로 찾기, 없는 번호는 「없음」으로
7. 바뀐 것만 고치기
8. 포털 지도와 견주기: 쿨러를 하나로 센 지도 vs 설비마다 센 내 그래프
9. 마무리: 다시 열어 같은 결과인지 보고, 그래프를 파일로 꺼내기 → 다음 회차에서는 이 그래프 위에 조치 절차와 판단 조건을 잇는다고 한 줄로 잇기
