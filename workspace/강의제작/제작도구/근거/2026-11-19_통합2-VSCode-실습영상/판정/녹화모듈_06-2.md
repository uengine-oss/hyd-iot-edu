## 3. 녹화 차례(촬영도구/에서, Git Bash)

```bash
./run.sh up
SEG=00 ./run.sh reset wo-reset-snap.mjs          # 06-1 마지막 구간을 받아들인 직후, wo-01 앞(06-1 끝의 파일 사본)
```
구간마다 아래 셋 가운데 하나다(이름은 `wo<구간>-dry1` · `wo<구간>-r1`, 앞 take = 바로 앞 구간의 좋은 take).
- 첫 페이지, 부탁 없음: `./run.sh dry wo03c-dry1 wo-03c.mjs` → `SEG=03c ./run.sh reset wo-reset.mjs` → `./run.sh rec wo03c-r1 wo-03c.mjs wo03b-r1` → `SEG=03c ./run.sh reset wo-reset-snap.mjs`
- 첫 페이지, 부탁 구간: `WO_NOSEND=1 ./run.sh dry wo03b-dry1 wo-03b.mjs`(부탁 글을 넣기까지 해 보고 보내지 않는다 — 한도를 쓰지 않음, 앞쪽의 답 보기는 실제 답으로 리허설됨) → `SEG=03b ./run.sh reset wo-reset.mjs` → `TMO=1500 CODEX_HOME=<촬영준비 길 1의 값> ./run.sh rec wo03b-r1 wo-03b.mjs wo03a-r1` → 답과 고친 파일을 보고 FIND · PICK을 맞춘다 → `SEG=03b ./run.sh reset wo-reset-snap.mjs`(바뀐 파일 목록을 찍는다 — 읽기 부탁인데 app/features가 바뀌면 멈춘다)
- 둘째 페이지: `PAGE=1 ./run.sh dry wo03d-dry1 wo-03d.mjs` → `SEG=03d ./run.sh reset wo-reset.mjs`(F5 앞의 옛 결과 화면을 다시 띄운다 — dry가 F5를 해서 꼭 해야 한다) → `PAGE=1 ./run.sh rec wo03d-r1 wo-03d.mjs wo03c-r1`

차례는 2절 표 그대로다(01 → 02a → 02b → 02c → 02d → 03a …). 리허설은 맨 처음 실행이면 `reset`이 앞 구간 끝 기록(`작업/촬영/vscode/_wo/<구간>.end.json`)과 사본을 쓰므로, 앞 구간을 리허설이든 녹화든 끝까지 한 번 돌린 뒤에 한다.
- 요청을 보낸 뒤에 멈춘 take(대화에 부탁이 이미 들어감 — 다시 보내지 않는다): 멈춘 take 폴더의 `since.json` 값으로 `WO_SINCE=<since> TMO=1500 CODEX_HOME=… ./run.sh rec wo03b-r2 wo-03b.mjs wo03b-r1:<자를 ms>` — 보내는 큐까지 건너뛰고 그 뒤 큐부터 찍는다. 자를 ms는 멈춘 take `timing.json` actions에서 보낸 큐 다음 큐의 시작. 합성은 `wo03b-r1:<자를 ms> wo03b-r2:<cut>`. 이음새에서 진행 표시의 초가 뛴다(최후 복구).

2. 「구석에 작게 남긴다」(다섯 칸 그림 wo0103 · 질문 글상자 wo0202) — 그림 층은 펜 그림 하나 · 글상자 하나만 띄운다. 그래서 작은 다섯 칸 · 세 질문 · 남은 일을 펜 그림 「길잡이」 하나로 묶었다(웹 VS Code = 탐색기 아래, 결과 화면 = 오른쪽 위). 「화면 위쪽」이 아니라 탐색기 아래인 까닭은 그 자리만 편집기 · 터미널 · Codex 답을 가리지 않아서다. 「줄인다 · 키운다」는 걷고 띄우기다(wo0202 · wo0321 · wo0322 · wo1002). 결과 화면 길잡이는 자리가 좁아 질문 줄이 없어서, wo0421의 「구석의 질문 글상자 ①」은 질문 ①을 잠깐 글상자로 띄워 짚는다. 큰 그림(물리량 두 길 · 펌프 자리 · 다섯 칸 · 세 걸음)을 그리는 동안은 길잡이를 걷는다. 제안: draw.mjs에 늘 떠 있는 둘째 층(고정 그림)과 크기 바꾸기를 두면 조작 칸 그대로 된다(공용 도구).
3. 점선 — wo0101 ③ · wo0103 ⑤(「점선으로 바꿔」 → 동그라미) · wo0203 ①–⑤ 점선(→ 위로 도는 화살표) · wo0403 떼어 낸 펌프의 점선 테두리와 「달려 있던 때」 띠(→ 「달려 있던 때 · 떼어 냄」 글) · wo1004 ③. 그림 층에 점선이 없다. 제안: box · arrow에 `dash`를 더한다(공용 도구, `draw_check.mjs` 시험 함께).
4. wo0403 「센서를 짧은 실선으로 붙이고」 — 화살표(머리 있음)로 그었다.
5. 「흐린 띠」(wo0221 · wo0291 · wo0422 · wo0514 · wo0918 · wo0917 등) — 띠는 한 가지뿐이라 보통 띠로 긋는다.
6. wo0321 「글상자 옆에 석 줄」 — 글상자가 하나라 석 줄은 펜 그림 글로 띄우고, 그동안 길잡이를 걷는다. wo0503 「decisions 5행을 잠깐 띄운다」는 두 길 글상자가 떠 있어 길잡이 아래 줄에 글로 띄운다.
7. wo1003 「고른_것 · 근거 · 바뀌는_답 칸(밑줄)」 — Codex가 쓴 줄의 근거 · 바뀌는_답은 편집기 오른쪽 밖으로 길어(CSV는 줄바꿈이 없다) 칸 머리(3행)에 긋는다. wo0483의 근거 칸도 보이는 데까지만 긋는다.
8. wo0484(wo0421 앞 조각) — 명령은 말이 끝난 뒤에 친다. 「classes를 다시 돌려 보면」은 뒤 조각 첫 말이라 화면 전환 뒤에 들린다.
9. 길이: 구간 경계 쉼은 2.3초, 큐 사이 쉼은 1.3초다(`lab-common.mjs` PAUSE). 구간 49개면 경계가 48곳이고, 나누지 않아도 생기는 장 경계 9곳 밖의 39곳이 1초씩 길어져 영상이 약 39초 늘어난다(셈 — 음성 길이는 아직 모름). 이음새는 영상 V-14의 「구간이 바뀌는 곳」이다.
10. 공용 도구 쪽(보고만): 편집기 줄 · CSV 칸 짚기, 결과 화면 카드 · 모으는 그림 · 대조 표 찾기, 붙여넣기, 기다림 말에 조작 붙이기, 이음새 자르기(cut)가 wv-common · wg-common · wo-common에 편마다 따로 있다 — lab-common으로 모으면 관리할 곳이 준다. 06-1 「같은 세 칸」(STEPS)만 wv-common에서 받아 쓰는데, 그쪽이 칸 이름을 바꾸면 wo-common이 불러올 때 멈춘다.
