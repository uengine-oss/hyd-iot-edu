사용자 원문: 「아니 영어로 이런말 x」 · 「create는 생성하는거고 / 어떻게 생성하냐 뒤에 이거는 이런거고 이런뜻이고 등등 하면 OO 이고 OO인 노드가 생겨난다는 뜻입니다 라는식으로 가면안되는거임」 · 「내가말하는 명확하다라는게 뭔지알겠음?」 · 「놓친요소없이가되 쓸데없는건 깁게 설명하지말고」 · 「설명자체가 쉽냐는거임 단어 문장자체가 매끄럽고」 · 「기준 : 학생이 이걸 듣고 사이퍼쿼리를 모든 문법을 스스로 다 이해해서 작성하고 그래프 db를 잘 다룰수있는가?」 · 「쉽게 라는말이 추상적인가 어려우면 이걸 쉽게 설명해봐라고 하는거랑 똑같은데..」

## 4. 「스스로 쓸 수 있는가」 — 어디서 어떻게

쿼리마다 「이 꼴을 보고 다른 이름 · 다른 조건의 쿼리를 내가 쓸 수 있나」를 댔다. 범위는 실라버스 행 안(CREATE · MATCH · WHERE · RETURN · MERGE · SET · DELETE · DETACH DELETE, 한 단계 · 여러 단계 경로, 조건 · 집계)이고, 행 밖 문법과 뒤 실습을 예고하는 말은 넣지 않았다.

1. 절이 처음 나오는 자리에 「무엇을 하고 싶을 때 쓰는 절인가」가 있는지: CREATE g0403(새로 만드는 절 — 이번에 하는 일로 고침), MATCH g0502(맞는 것을 찾으라는 절), RETURN g0511(돌려 달라는 절), WHERE g0601(찾은 것 가운데 일부만 받고 싶을 때), MERGE g0701 · g0702(여러 번 돌려도 하나만 남게 / 있으면 찾고 없을 때만 만든다), SET g0707(속성에 값을 적어 넣는 절) · g0901(고칠 때도 SET), DELETE g1003(지우는 절), DETACH DELETE g1004(붙은 관계를 떼어 함께 지운다). CREATE 말고는 이미 있어 그대로 두었다.
2. 빠져 있던 쓰는 법을 채운 곳:
   - g0707 — 칸 5-1의 셋째 줄 `RETURN s`를 말하는 곳이 없었다 → 「마지막 줄 RETURN은 그 센서 노드를 돌려받습니다」.
   - g0802 — MATCH 괄호의 중괄호가 「그 값인 노드만 찾는다」는 뜻이라는 말이 없었다(「아이디로 찾아요」뿐) → 「찾는 괄호에도 중괄호를 적을 수 있는데, 그러면 거기 적은 값이 같은 노드만 찾습니다. 여기서는 아이디죠.」
   - g0805 — 관계의 대괄호를 노드 괄호와 같은 규칙으로 읽게 → 「가운데 대괄호가 관계예요. 읽는 법은 노드의 괄호와 같아서 …」.
