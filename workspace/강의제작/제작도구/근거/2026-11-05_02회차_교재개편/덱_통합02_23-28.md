## 조각 메모

- **처음 푼 용어와 자리.** 앞에서 쓴 클래스·속성·관계는 24장에서 센서의 스키마(공통 정의)와 인스턴스 데이터(실제 대상·속성값·연결)의 구별에 쓴다. 25장은 앞에서 본 식별자와 이름에 별칭의 역할을 붙인다. 26장에서는 설비 대장의 이전 코드와 일련번호, 27장에서는 이미 배운 유온 센서와 상태 변수 유온, 28장에서는 그래프와 시계열 저장소의 서로 다른 열 이름을 사용한다.
- **쓴 비유.** 새 비유 없이 센서의 두 카드, 쿨러 하나의 세 속성, 설비 대장 두 코드, 같은 채널의 이웃한 실측값을 사용했다.
- **18행의 문장과 자리.** 스키마와 인스턴스 데이터, 서로 다른 정의가 불러오는 의미 불일치는 24장에서 조건과 실제 값·관계 방향을 짚는다. 공통 식별자와 동일 대상 판정은 25~28장에서 이름·별칭, 이전 코드·일련번호, 같은 문자열의 다른 역할, 설비·채널·한 시점의 값을 비교한다. 속성명·자료형·필수 여부와 관계의 시작·종료 클래스·카디널리티·유효한 연결은 29~36장, 설비 모델을 스키마로 발전시키는 과정과 설비·진단·판단·성과 영역은 37~43장이 받는다.
- **끝 문장.** “HYD-01을 설비 표의 code에 맞추면 되므로 이때에는 태그나 시각이 필요하지 않다.” 다음 29장에서는 식별한 센서가 어떤 값과 관계를 가질 수 있는지 묻는다.
- **계획 시간.** 18행 전체는 40분이다. 현재 낭독을 기준으로 이번 본문 24~28장의 추정은 9.36분, 23장 간지는 45.1초다. 단원 낭독 분량을 확정하는 단계에서 23장의 안내를 물음까지 줄인다.

## 대본과 제작 입력 인계

02편 대본 `02_이론_스키마설계.md`는 23~43장을 담는다. 덱 단계에서 이 대본을 최종 낭독으로 판정하지 않았다. 23장은 첫 물음, 24장은 실제 태그와 관계 양끝, 25장은 같은 쿨러의 세 속성, 26장은 대장의 두 코드와 같은 일련번호, 27장은 한계의 대상과 단위, 28장은 채널과 시각을 고르는 순서에 맞춘다. 26장의 옛 가상 쿨러 기록과 28장의 냉각 효율 평균은 현 화면의 증거가 아니다.

기존 `강조_통합반_02회차_02_이론_스키마설계.json`의 23~28장 표시는 각각 0·3·2·1·3·5개다. 24장의 이전 두 카드 문구, 25장의 사라진 여러 식별자, 26장의 바뀐 판단 그림, 27장의 한계, 28장의 두 시각에 새 낭독 문장·낱말과 좌표를 맞춘다. 23장의 무강조 사유와 각 장의 쉼은 확정 대본 단계 뒤 장별점검표와 제작 파일에 남긴다. 편별 재사용·신규 구획과 견적, 실제 제작 명령은 그때 갱신한다. 말머리·강조 시각·장 넘김·자막 싱크·청취는 영상 생성 후 확인한다.

`덱측정.py 통합2`의 현행 전체 79장 중 이론 본문은 53장이다. 17행 클래스는 50분 배정에 본문 35.00분(하한까지 5.00분 부족), 18행 스키마는 40분에 30.87분, 19행 그래프는 25분에 31.12분이다. 직접 실습과 복습은 이 수치에 포함하지 않는다.
