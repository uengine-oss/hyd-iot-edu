설비 관계를 조회하고 모델로 검증하기

오일 쿨러에서 측정값까지 이어지는 길을 따라간 뒤, 현장 자료로 설비별 센서와 공용 부품을 찾는 모델을 만듭니다.

압축을 푼 뒤 시작하세요

ZIP 전체를 한 폴더에 풀고 가이드열기.html을 여세요. Docker Desktop의 엔진이 실행 중이면 압축을 푼 폴더에서 관계조회열기.cmd를 두 번 누르세요. 이 작업 폴더 전용 DB가 준비되고, 브라우저에 관계조회 가이드와 Neo4j Browser가 열립니다. 같은 폴더에서 다시 실행하면 쓰던 DB에 연결합니다.

포털은 강사가 안내한 주소에서 엽니다. 코딩 단계에서도 이 안내를 열어 둔 채, 단계에 적힌 실행 파일을 압축 해제한 폴더에서 두 번 누르세요. VS Code가 자동으로 열리지 않으면 파일 → 폴더 열기에서 그 단계의 02회차/랩 아래 설계 또는 구현 폴더를 골라 START.md를 여세요.

관계 탐색 실습 · Neo4j와 포털 (배정 50분)

Neo4j 실습 가이드를 열어 별도 랩 DB에 연결하세요. 작은 그래프에서 속성을 바꾼 뒤 같은 대상으로 다시 조회합니다. 노드와 관계를 반환했을 때의 그림과 속성값만 반환했을 때의 표를 비교하세요. 연습 데이터만 삭제하고 재조회한 뒤 제공 설비 예제로 넘어갑니다. 구성 요소별 센서 수는 집계 전 행과 대조하세요.

이제 포털 지식 지도 가이드를 열고 같은 질문을 포털에서 따라가세요. HYD-01의 오일 쿨러에서 센서와 교체 부품을 각각 눌러 보세요. TS1이 센서의 태그로 보일 때와 상태 변수의 별칭으로 보일 때 종류와 방향이 어떻게 다른가요? 이름 공간 day02-sensors에서 같은 이름의 유온 센서 두 개를 찾으세요. 설비 코드와 계장태그를 대조한 뒤 수업 기준으로 돌아와 sen:ts1을 보세요. 실습 DB와 포털 기준 지도에서 어떤 연결을 직접 확인했나요?

관계도에서 설비 모델 설계하기 (배정 50분)

설계실습열기.cmd를 열면 VS Code에 설계 폴더와 START.md가, 브라우저에 설계 실습 가이드가 열립니다. 왼쪽 탐색기에서 자료를 고르고 가운데 편집기에서 근거 행을 읽으세요.

제공된 관계도와 현장 원자료에서 같은 이름의 센서가 서로 다른 설비에 달린 사례를 골라 보세요. 그 행을 별칭·중복·누락 사례와 비교하세요. 어느 항목으로 계기를 구별할지, 단위가 비면 무엇까지 말할 수 있는지 AI와 상의하고 근거를 남기세요.

설비별 센서와 여러 설비가 쓰는 부품에 대해 묻고 싶은 질문을 자기 말로 적으세요. 먼저 기대 답을 원자료에서 찾고, 계획에 동의하면 AI와 스키마·그래프를 작성하세요. 구조 검사를 실행한 뒤 첫 사례와 다른 설비에서도 뜻과 관계 방향이 맞는지 대조하세요. 확인된 모델 두 파일을 함께 저장하세요.

내 모델을 적재하고 조회로 검증하기 (배정 50분)

구현실습열기.cmd를 열면 새 VS Code 창과 그래프 구현 가이드가 열립니다. 방금 설계한 모델을 쓰려면 이 창의 실습 폴더에 내_모델 폴더를 만들고, 설계 실습의 결과/schema.json과 결과/graph.json을 함께 복사하세요. 두 파일을 열어 앞에서 고른 품번의 ID와 관계 방향을 확인하고 AI에게 이번 적재에 쓸 두 파일을 알려 주세요. 개인 모델을 가져오지 못한 경우에는 입력/의 제공 모델로 시작하고 어느 모델과 자료 기준일을 사용했는지 검증 기록에 적으세요.

별도 랩 DB에서 내 스키마의 정의와 실제 노드·관계를 나란히 보세요. 설비에서 센서·부품을 찾고, 반대로 공용 부품에서 사용 설비를 찾아 원자료와 대조하세요. 같은 입력을 다시 적재한 뒤 노드·관계 수와 선택한 ID가 그대로인지 보세요.

수정 자료에서 이름이 달라진 설비를 찾고 앞의 ID로 다시 조회하세요. 바뀌어야 할 값과 유지되어야 할 연결을 먼저 적고 필요한 변경만 반영하세요. 코드·질의·전후 결과를 저장하고 복사본을 다시 열어 같은 질문에 답할 수 있는지 확인하세요.
