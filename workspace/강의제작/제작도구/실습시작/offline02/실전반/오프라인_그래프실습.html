실전반 · 오프라인 2회차

설비 관계를 조회하고 모델로 검증하기

펌프 씰을 쓰는 설비를 찾고, 이 품번에 어느 공급사의 어떤 조건이 연결되는지 원자료에서 확인합니다.

압축을 푼 뒤 시작하세요

ZIP 전체를 한 폴더에 풀고 가이드열기.html을 여세요. Docker Desktop의 엔진이 실행 중이면 압축을 푼 폴더에서 관계조회열기.cmd를 두 번 누르세요. 이 작업 폴더 전용 DB가 준비되고, 브라우저에 관계조회 가이드와 Neo4j Browser가 열립니다. 같은 폴더에서 다시 실행하면 쓰던 DB에 연결합니다.

포털은 강사가 안내한 주소에서 엽니다. 코딩 단계에서도 이 안내를 열어 둔 채, 단계에 적힌 실행 파일을 압축 해제한 폴더에서 두 번 누르세요. VS Code가 자동으로 열리지 않으면 파일 → 폴더 열기에서 그 단계의 02회차/랩 아래 설계 또는 구현 폴더를 골라 START.md를 여세요.

관계 탐색 실습 · Neo4j와 포털 (배정 50분)

Neo4j 실습 가이드를 열어 별도 랩 DB에 연결하세요. 작은 그래프에서 속성을 바꾼 뒤 같은 대상으로 다시 조회합니다. 노드와 관계를 반환했을 때의 그림과 속성값만 반환했을 때의 표를 비교하세요. 연습 데이터만 삭제하고 재조회한 뒤 제공 설비 예제로 넘어갑니다. 구성 요소별 센서 수는 집계 전 행과 대조하세요.

이제 포털 지식 지도 가이드를 열고 같은 질문을 포털에서 따라가세요. 펌프 축 씰 키트에서 들어오는 관계를 따라 주 펌프와 소속 설비를 찾으세요. 발주 방법에 연결된 규칙과 근거 문서까지 따라가 보세요. 지도에서 확인한 사용처와, 현재 견적·재고를 알아야 답할 수 있는 질문을 구별하세요.

공급 모델 설계와 조회 (두 활동 배정 합계 50분)

품번을 물은 구매 담당자에게 어떤 답이 필요한가요?

설계실습열기.cmd를 열면 VS Code에 설계 폴더와 START.md가, 브라우저에 설계 실습 가이드가 열립니다. 왼쪽 탐색기에서 자료를 고르고 가운데 편집기에서 근거 행을 읽으세요.

앞에서 씰 키트와 공급사가 연결된 것을 봤습니다. 품번 교차표에서 품번을, 견적표와 승인 목록에서 기준일에 비교할 두 기록을 골라 보세요. AI에게 읽은 자료를 짚어 주고, 가격·불량률·납기와 승인을 어떻게 구분해서 보여 줄지 상의하세요. 답이 달라지는 판단은 근거 행과 함께 요구사항에 기록하세요.

첫 사례에서 기대하는 답과 AI가 이해한 목표가 맞으면 모델 작성을 맡기세요. 실제로 바뀐 파일을 열고 구조 검사를 실행하세요. 공용 부품의 ID가 설비마다 중복 생성되지는 않았는지 확인하고, 다음 조회에 쓸 스키마와 그래프를 한 쌍으로 저장하세요.

내가 만든 모델이 같은 질문에 답하나요?

구현실습열기.cmd를 열면 새 VS Code 창과 그래프 구현 가이드가 열립니다. 방금 설계한 모델을 쓰려면 이 창의 실습 폴더에 내_모델 폴더를 만들고, 설계 실습의 결과/schema.json과 결과/graph.json을 함께 복사하세요. 두 파일을 열어 앞에서 고른 품번의 ID와 관계 방향을 확인하고 AI에게 이번 적재에 쓸 두 파일을 알려 주세요. 개인 모델을 가져오지 못한 경우에는 입력/의 제공 모델로 시작하고 어느 모델과 자료 기준일을 사용했는지 검증 기록에 적으세요.

구현 폴더의 START.md와 가이드는 온라인 전체 질문을 담고 있습니다. 이 50분 수업에서는 결과/검증_기록.md에 사용할 모델, 씰 키트의 사용 설비·공급 조건, 다른 품번·없는 품번, 반복 적재 확인을 오늘의 범위로 적으세요. AI와 계획을 확인할 때 온라인 질문 4의 실측 납기와 수정본 반영은 뒤로 두세요.

별도 랩 DB에 적재하고 펌프 씰 키트를 쓰는 설비 세 대와 공급 조건 세 행을 조회하세요. 각 공급사의 승인 상태·단가·불량률·납기를 원자료의 날짜·단위와 대조하세요. 비승인 공급사를 알아볼 수 있는지, 품번을 바꾸거나 없는 품번을 넣었을 때 앞 결과가 남지 않는지도 보세요.

같은 입력을 한 번 더 적재해 노드와 관계 수를 비교하세요. 조회문과 결과, 판단 근거, 남은 의문을 저장하고 다시 열어 보세요. 동료에게 이 결과로 답할 수 있는 구매 질문과 아직 더 필요한 정보를 하나씩 설명하세요.

빨리 끝나면 해 볼 것 · 구현 가이드의 입고 이력으로 돌아가 견적 납기와 완료된 입고의 실측 납기를 비교하세요. 완료 건이 없는 경우 결과에 어떻게 나타나는지 확인하세요.
