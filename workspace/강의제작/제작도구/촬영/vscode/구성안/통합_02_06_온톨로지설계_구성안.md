## ② 흐름 — 시작, 진행, 끝

### 시작 화면과 첫 설명

첫 프레임은 클래스룸에서 받은 ZIP 안의 **온톨로지 설계 실습 폴더를 연 웹 VS Code**다. 탐색기에 입력·자료·결과·START.md가 있고, START.md의 목표를 열어 둔다. Codex는 새 대화이며, 지난 요청·완성 코드·다른 실습 결과를 먼저 보여 주지 않는다. 제한 모드 해제와 필요한 로그인은 녹화 전 준비에서 확인한다.

ZIP 받기·압축 풀기·폴더 열기는 말로 한 문장 안내한다. 브라우저 밖의 파일 관리 화면은 이 영상에 넣지 않는다. 웹 VS Code와 학생의 설치형 VS Code에서 메뉴가 다른 부분은 처음 쓰는 자리에서 짚는다. 편집기·터미널·Codex의 위치는 실제 화면을 확인한 뒤 대본에 적는다.

학생이 받은 관계 그림과 현장 원자료를 화면에 놓고, 이번에 답할 설비별 센서와 공용 부품 질문으로 연다. 앞 포털 활동은 연결을 읽어 본 경험으로만 받는다. 학생이 이미 스키마·그래프 파일을 완성했다거나 VS Code 코딩을 해 봤다고 전제하지 않는다. 바이브 코딩의 방식은 이 첫 코딩 랩에서 한 번만 설명한다. **코드를 몰라도 자료를 읽고 요구와 기대 답을 정해 결과를 검증할 수 있다**는 점을 실제 첫 요청에 연결한다.

### 매 판단에서 반복할 행동

1. 지금 답할 질문과 원자료의 해당 줄을 연다.
2. 강사가 사람의 판단을 자기 말로 밝히고 근거를 짚는다.
3. 필요한 목적·입력·제약·결과·확인 방법을 하나씩 정리해 현재 단계의 요청을 만든다. 완성된 모범 프롬프트를 먼저 펼쳐 복사하지 않는다.
4. Codex의 요청 전송·진행·완료를 잇는다. 쓰기 요청에는 바꿀 파일을 `결과/` 아래로 한정한다. 한 번에 START.md 한 단계만 맡긴다.
5. 실제 응답과 바뀐 파일을 확인하고 실행한다. 코드의 줄별 해설과 참조 정답 공개 대신, 결과 표에서 학생의 판단이 어떻게 나타났는지 읽는다.
6. 원자료에서 먼저 정한 기대 답과 견주고 기록한다. 차이가 실제로 생긴 자리에서만 별도 고침 구간을 찍는다. 결과 확인 구간에서는 Codex를 다시 부르지 않는다.

구간 10·12·14·16에서는 함수가 결과를 가르는 기준이라는 정도만 설명한다. 제공 코드의 내부 구조를 강의하거나 스키마·그래프 전체를 AI에게 한꺼번에 맡기는 수업으로 바꾸지 않는다. 모델을 만드는 제공 코드는 랩 그대로 사용한다.

### 종료 조건과 마지막 화면

다음이 실제 화면과 파일로 확인된 뒤에 마친다.

- 설비별 구성 요소·센서, 같은 물리량, 공용 부품의 사용 설비에 대한 기대 답과 실제 답을 대조했다.
- 다른 표기의 품번과 없는 품번을 확인했다. 선택한 두 기준의 근거와 답에 미친 영향을 설명할 수 있다.
- 구조 검사 결과를 확인했고, 고친 점과 미확인을 기록했다. 실행 성공만으로 완료라고 말하지 않았다.
- 저장한 폴더를 다시 열어 같은 명령을 실행했다. 학생용 완성본에서도 같은 질문을 실행하고 결과를 읽었다.

마지막 화면은 웹 VS Code에서 해당 결과·근거 파일을 확인하는 모습이다. 마무리는 이번에 확인한 질문과 보관할 기록으로 끝낸다. 학생용 완성본 ZIP의 `완성본_안내.md`에서 `python show_result.py`와 `결과/보기.html` 경로를 확인했다. 실행 결과는 촬영 경로에서 실제 확인한 뒤 낭독에 넣는다.

### 다음 VS Code 실습과의 이음새

07편은 실습 4 폴더가 열린 웹 VS Code에서 별도로 시작한다. 현재 검증된 랩의 기본 입력은 `입력/schema.json`·`입력/graph.json`의 **제공 모델**이다. 내 모델을 선택할 때만 `결과/내_모델/`에 복사한다. 이번 결과가 자동으로 다음 폴더에 들어간다고 말하지 않는다.

실라버스의 「앞 실습에서 설계한 … 모델을 … 적재」와 실제 기본 경로의 차이는 기존 `남은일.md`의 통합 2회차 23행 항목에 기록돼 있다. 이번에는 제공 모델을 기본 경로로 구성하고, 첫 설명에서 사용 중인 모델을 화면의 입력 파일로 명확히 한다. 랩의 동작과 실라버스의 이 차이를 새 대본에서 감추지 않는다. 07편 구성안은 06편에서 확정한 용어·질문·보관 파일을 이어받아 작성한다.

## ④ 처음 · 중간 · 끝 발췌

다음은 흐름 확인을 위한 짧은 새 발췌다. 최종 대본은 구성 확인 뒤 「발화 | 조작·결과 확인 — 비낭독」 표로 작성한다. 결과를 말하는 문장은 해당 실행을 확인한 뒤 확정한다.

**처음 — 구간 01**

> 클래스룸의 실습 자료에서 ZIP을 받아 풀고, 안쪽의 온톨로지 설계 폴더를 VS Code로 엽니다. 여기 있는 설비와 센서 자료로, 어느 설비에 어떤 센서와 교체 부품이 연결되는지 직접 정리하겠습니다. 코드를 몰라도 괜찮습니다. 자료를 읽고 요구를 정한 다음, AI가 만든 결과를 원자료와 함께 확인해 볼게요. 먼저 왼쪽에서 자료 폴더를 펼치겠습니다.

**중간 — 구간 09, 실제 출력 확인 뒤**

> 이 표는 원자료의 각 행에 지금 정한 식별자를 붙인 결과입니다. 같은 식별자가 나온 행을 함께 보겠습니다. 같은 대상이 두 번 적힌 것인지, 다른 설비의 센서를 하나로 묶은 것인지 원자료로 확인해야 합니다. 표에 나온 파일을 열어 설비 코드와 태그를 나란히 보겠습니다.

**끝 — 구간 21, 실제 대조와 재실행 뒤**

> 저장한 결과를 다시 열어 설비별 센서와 공용 부품의 사용 설비를 확인했습니다. 확인한 답과 그 근거는 함께 보관하겠습니다. 아직 확인하지 못한 항목도 기록에 남겨 두겠습니다. 수업을 마치기 전에 이 폴더를 개인 저장 공간으로 복사해 두세요.
