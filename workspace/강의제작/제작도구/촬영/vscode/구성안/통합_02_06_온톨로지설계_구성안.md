# 통합반 2회차 VS Code 실습 06 — 온톨로지 직접 설계하기

상태: 01~03구간(가이드 1단계 — 목적과 작업 화면, 원자료와 첫 실행, 첫 결과 화면)은 대본 · 큐 · 모듈 · dry 리허설까지 갖췄다. 04구간부터(가이드 2~11단계)는 아래 표의 순서대로 녹화하며 쓴다. 음성 · 녹화 · 영상은 아직 없다.

## 범위와 시간

실라버스 배정은 설계45분, 그래프 구현35분이다. 촬영 실측은 없다. 현재 랩의 사람 작업 계획과 배정 합계의 차이는 작업 기록과 남은일에서 관리하며, 반복 설명이나 대기로 채우지 않는다.

## 시작과 진행

첫 화면은 `ontology-lab`을 연 웹 VS Code다. Dark Modern·125%, 가운데 짧은 README, 왼쪽 data/app/AGENTS, 오른쪽 빈 Codex 대화를 준비한다. ZIP 받기·압축 풀기·폴더 열기는 한 문장으로 짚고 네이티브 사진은 가이드에 둔다.

처음에는 만들 결과를 설명하고 탐색기·편집기·Codex를 짚는다. 바이브 코딩과 코드를 몰라도 된다는 설명은 이때 한 번만 한다. AGENTS는 AI의 공통 원칙인 헌법 파일로 짧게 소개한다. 구체적인 질문과 기준은 자료를 파악한 뒤 정한다.

진행 순서는 바깥 `ontology-lab_guide.html`의11단계를 따른다. 가이드를 영상에 띄우지는 않는다. 각 기능에서 지금 필요한 정보를 Codex에게 묻고, 응답이 가리킨 원문을 열어 확인한다. 사람이 고른 기준을 현재 기능에만 반영한 뒤 실행한다. 다음 명령을 입력하기 전에 실제 결과 화면을 새로고침해 확인한다.

| 가이드 | 화면에서 할 일 | 실행 |
|---|---|---|
| 1 폴더·자료 | README 역할과 원자료 파일·행 수 | `python run.py` |
| 2 파악 | 설비 하나의 자료 위치와 줄 확인, 파일 변경 없음 | Codex 읽기 요청 |
| 3 질문·판단 | 요구·기대 답·선택 근거를 자기 말로 기록 | `python run.py expected` |
| 4 식별자·관계 | 구분 기준과 방향 계획 검토 후 해당 표 작성 | `python run.py design` |
| 5 장치 이름 | 같은 장치와 중복 행 처리 기준 구현 | `python run.py names` |
| 6 물리량 | 태그·회로·수집방식으로 묶을 기준 구현 | `python run.py quantities` |
| 7 단위 | 기준 단위와 빈 값의 근거 확인 | `python run.py units` |
| 8 부품 | 선택한 품번 기준으로 연결하고 모델 생성 | `python run.py parts` |
| 9 질문 대조 | 기대 답과 실제 답, 다른 입력·없는 품번 확인 | `python run.py query` |
| 10 구조 | 중복·끝점·방향 검사와 의미 대조 구별 | `python run.py check` |
| 11 저장 | 같은 폴더 재열기·모델 생성·조회·검사를 하나씩 확인 | 기능별 실행 후 F5 |

학생이 고치는 곳은 `app/features/`, 자동 결과는 `output/`이다. 일반 처리와 화면 표시는 제공한다. Codex 전송·진행·응답·변경 파일·첫 실행까지 한 흐름으로 잇고, 결과 확인 대사는 실제 응답과 출력을 읽은 뒤 쓴다. 차이가 있을 때만 원인을 확인해 그 기능을 고친다.

## 실라버스와 확인할 결과

| 행 상세 문장 | 가이드 | 확인 |
|---|---|---|
| 제공 설비·센서·부품 원자료를 읽고 설비별 센서와 공용 부품을 찾을 질문을 정한다. | 1~3 | 원문 줄과 자기 질문·기대 답 |

## 끝과 다음 편의 입력

저장한 폴더를 다시 열어 질문의 답이 유지되는지 확인하고 선택 근거와 미확인을 보관한다. 별도 `ontology-lab-completed.zip`은 README의 명령으로 실행해 자기 판단과 차이를 살펴본다. 결과·근거가 보이는 웹 VS Code에서 마친다.

07편은 별도 `graph-lab`으로 시작한다. 기본 제공 모델은 `data/model/`, 자기 모델은 선택할 때만 `app/features/model/`에 두 JSON을 함께 둔다. 자동으로 이어진다고 설명하지 않는다. 그래프 가이드는12단계이며 적재·조회·수정을 각각 실행해 확인한다.

## 다시 촬영할 때 확인

01~03구간은 새 구조 화면에서 dry 연속 통과했다(10 · 13 · 3큐, 예상 4.0분). 첫 프레임 시각, 음성 시점, 녹화 실측은 아직 없다. 04구간부터는 Codex 요청이 들어가므로, 구간마다 요청 → 응답 끝(`task_complete`) → 바뀐 파일 · 실행 출력을 읽은 뒤 결과 확인 발화를 쓴다. 녹화 전 상태는 `촬영도구/segs/i206-reset.mjs`로 맞추고, 학생 파일을 바꾼 구간 뒤에는 ZIP을 새로 풀어 그 지점까지 다시 간다.
