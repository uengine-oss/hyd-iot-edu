# 웹 VS Code 촬영준비

코딩 랩과 VS Code 장면은, 공식 `code serve-web`으로 띄운 웹 VS Code를 이 PC의 녹화 브라우저에서 찍는다(클라우드에서는 찍을 수 없다). 녹화 브라우저는 포털 · Neo4j 녹화와 같은 [포털 촬영도구](../포털/촬영도구/)의 `browser.mjs`를 이 도구의 `config.json`으로 띄운 Playwright 헤드리스 Chromium이다. 창이 없어 주소창 같은 브라우저 흔적이 프레임에 들어가지 않는다. 서버는 저장소 루트의 PowerShell에서 띄우고, 음성, 녹화, 합성은 Git Bash에서 [촬영도구/](촬영도구/)를 현재 위치로 두고 한다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md)에 있다.

## 길

1. 서버 — 포트 8793에 다른 서버가 떠 있으면 멈춘다. 비어 있을 때만 같은 판본, 포트, 데이터로 켠다(PowerShell). Codex가 학생 역 계정과 모델(`gpt-6-luna` medium)을 쓰도록, 켜기 전에 `$env:CODEX_HOME`에 코딩랩 길 6의 학생 역 CODEX_HOME(그 줄 한 곳에만 적는다)을 둔다. 이 값이 없으면 기본 `~/.codex` 설정으로 떠서 모델이 「Custom High」로 보인다. 같은 자리에서 `$env:PSExecutionPolicyPreference`를 `Bypass`로 둔다. 이 값은 이 서버 프로세스와 그 터미널에만 걸리고 PC의 실행 정책은 바꾸지 않으며, 이 값이 있어야 녹화 터미널의 PowerShell이 경고 없이 뜬다(「함정」). `BROWSER` 환경변수도 같은 자리에서 지우고 켠다(이렇게 켠 서버의 터미널에서 `python run.py`는 이 PC에 브라우저 창을 띄우지 않았다 — 길 6). 서버를 다시 켤 때는 `code-tunnel.exe`만 끄면 자식 `node.exe`가 8793을 계속 쥐므로, 명령줄에 `v143`이 든 프로세스를 모두 끈 뒤 포트가 비었는지 본다.
   ```powershell
   $codexHome = '<코딩랩 길 6의 학생 역 CODEX_HOME>'
   $r = (Resolve-Path '작업/촬영/vscode/v143').Path
   $commit = 'e646868227c3e3a9e3f24277c8c7220be42c0be7'
   $listener = Get-NetTCPConnection -LocalPort 8793 -State Listen -ErrorAction SilentlyContinue
   if ($listener) {
       $server = Get-CimInstance Win32_Process -Filter "ProcessId=$($listener.OwningProcess)"
       if ($server.Name -ne 'code-tunnel.exe' -or !$server.CommandLine.Contains($r) -or !$server.CommandLine.Contains($commit)) { throw '8793을 다른 서버가 사용 중' }
   } else {
       if (!(Test-Path "$r/access.txt" -PathType Leaf) -or !(Test-Path "$r/data/extensions/extensions.json" -PathType Leaf)) { throw '접속 파일 · 확장 프로필 확인' }
       $env:CODEX_HOME = $codexHome
       $env:PSExecutionPolicyPreference = 'Bypass'
       Remove-Item Env:BROWSER -ErrorAction SilentlyContinue
       $exe = Join-Path $env:LOCALAPPDATA 'Programs/Microsoft VS Code/bin/code-tunnel.exe'
       Start-Process -FilePath $exe -WindowStyle Hidden -ArgumentList "serve-web --commit-id $commit --host 127.0.0.1 --port 8793 --connection-token-file `"$r\access.txt`" --cli-data-dir `"$r\cli`" --server-data-dir `"$r\data`" --disable-telemetry --accept-server-license-terms"
   }
   ```
2. Codex 확장(확장이 사라졌을 때만) — 맞는 조합은 웹 VS Code 1.143.1, 화면 확장 26.422.71525, 실행 엔진 26.1021.22027(Windows)이다.
   - 확장은 `& "$r/cli/serve-web/$commit/bin/code-server.cmd" --server-data-dir "$r/data" --install-extension openai.chatgpt@26.422.71525 --force`로 설치한다.
   - 사용자 설정의 `chatgpt.cliExecutable`이 `$r/app-server-26.1021.22027/codex.exe`의 절대 경로(`/` 구분자)여야 한다. 이 설정은 서버가 아니라 녹화 브라우저 프로필(`config.json`의 `profile`)의 저장소에 있고, 값은 `config.json`의 `settings`에 적혀 있어 `./run.sh prep`(길 4)이 넣는다(`{work}`는 `work`의 절대 경로로 바뀐다). `v143` 폴더를 옮겼는데 옛 경로가 남아 있으면 Codex 패널이 로고만 띄운 채 멈추고, 서버 로그 `data/data/logs/<시각>/exthost*/remoteexthost.log`에 `spawn … codex.exe ENOENT`가 찍힌다. 그때는 `./run.sh prep`을 다시 돌린다.
   - 엔진 폴더를 잃었으면 VSIX의 `extension/bin/windows-x86_64/` 전체를 그 자리에 둔다(VSIX는 `작업/_로컬/VSCode웹복구/`에 있다). 3. 폴더 열기 — 학생처럼 ZIP을 `segs/lab-common.mjs` LABS 표의 촬영 폴더(`D:/HYD-Practice/<접두>p-<ZIP sha256 앞 8자리>/`)에 풀고, `http://127.0.0.1:8793/?tkn=<access.txt 값>&folder=` 뒤에 `encodeURIComponent('/D:/...')`를 붙인 주소로 연다. 이 주소는 `page.mjs`의 `folderUrl`이 `config.json`의 `token_file`에서 토큰을 읽어 만들고, `./run.sh prep <랩 폴더 절대 경로>`(길 4)와 되돌리기 `resetLab`(길 6)이 이 주소로 열어 아래의 폴더 신뢰까지 한다. 토큰 값은 로그나 화면에 남기지 않는다. 새로 푼 폴더는 Restricted Mode로 열리고, 그동안은 Codex 확장이 꺼져 확장 목록에서 흐리게 보이며 오른쪽 패널에는 Copilot Chat만 있다. 그러니 폴더 신뢰를 먼저 준다. F1 → `Workspaces: Manage Workspace Trust`로 Workspace Trust 편집기를 연다(상태 표시줄의 Restricted Mode 클릭은 편집기를 열지 못할 때가 있다). 그 안의 `Trust` 단추(`.monaco-button`)를 단추 중심 좌표로 누른다. 신뢰됐는지는 `.statusbar-item`에서 「Restricted Mode」가 사라질 때까지 기다려 판정한다(불러온 직후에 한 번 읽은 값은 아직 바뀌기 전일 수 있다). 상태 표시줄에 「Screen Reader Optimized」가 보이면 F1 → `Toggle Screen Reader Accessibility Mode`로 끈다. 켜진 채로 두면 편집기 줄바꿈이 달라지고 그 표시가 화면에 남는다. Welcome 탭은 `.tab .tab-actions .action-label`로 닫는다. 미리보기 탭을 고정하려면 dblclick 이벤트를 보낸다.
4. Codex와 터미널 — Codex는 오른쪽 Codex 탭에서 쓴다(새 프로필의 첫 안내 네 쪽은 `./run.sh prep`이 Next로 넘긴다. 그 뒤 모델을 묻는 안내가 뜨면 Continue with current model을 고른다). 녹화 전에 이 촬영의 시험 대화만 확장 화면에서 보관한다. 해당 대화 행에 커서를 올려 `Archive chat` → `Confirm`을 누르고, 목록에서 사라졌는지와 새 대화 입력칸이 비었는지 확인한다. 다른 대화는 건드리지 않는다. 세션 파일을 직접 옮기면 대화 목록의 경로와 어긋나므로 옮기지 않는다. 기존 연결 확인이 없을 때만 짧은 질문 하나로 답이 오는지 본다. 탐색기의 파일은 그 행을 누른 뒤 Enter로 연다(한 번 누르기는 선택만 한다). 새 터미널은 위 메뉴 줄의 `Terminal` → `New Terminal`로 열고(`lab-common.mjs`의 `newTerminal`), 명령은 `typeKeys`(키 입력)로 친다. 터미널은 `insertText`로 넣은 글자를 받지 않는다. 녹화 화면의 글자는 영어다(한국어로 맞출 수 없는 까닭은 「함정」). 대사는 영상 V-3대로 그 차이를 말하지 않고, 학생이 자기 화면에서 할 행동만 말한다.
   - 화면을 학생의 VS Code와 같게 맞춘다(영상 V-3). 설정 값은 `촬영도구/config.json`의 `settings` 한 곳에 있고, `./run.sh prep [랩 폴더 절대 경로]`(`prep.mjs`)가 넣는다. 이 명령은 폴더를 주면 그 폴더를 열어 신뢰를 주고, F1 → `Preferences: Open User Settings (JSON)`에서 기존 설정을 보존하며 `settings`의 값만 덮어써 저장하고, 창을 새로 고친 뒤 메뉴 줄 여덟(`File` … `Help`)이 펴졌는지, ☰ 단추가 없는지, 색이 어두운지, Welcome 탭이 없는지, 폴더가 신뢰됐는지, 칸 폭과 앞에 둔 탭이 맞는지를 잰다. Screen Reader Optimized가 켜져 있으면 끄고, 새 프로필에서 Codex 패널이 띄우는 첫 안내 네 쪽을 Next로 넘겨 새 대화 화면에서 끝낸다(Codex 요청은 보내지 않는다). 하나라도 다르거나 Codex 새 대화 화면이 60초 안에 뜨지 않으면 멈춘다. 작업자는 프로필을 새로 만들었거나 `settings`를 고쳤을 때 이 명령을 돌리고, 그 뒤 새 터미널의 제목이 `powershell`이고 첫 줄이 경고 없이 `PS <폴더>>`인지 프레임으로 확인한다. 이 설정은 녹화 브라우저의 사용자 설정에만 두고 학생 랩 파일에 넣지 않는다(서버 쪽 `data/data/Machine/settings.json`에 넣은 메뉴 줄 설정은 듣지 않았다). `prep`은 `settings`에 없는 키를 지우지 않으므로, 사용자 설정에 `terminal.integrated.defaultProfile.windows`가 `Command Prompt`로 남아 있으면 손으로 지운다.
     `settings`의 값은 여덟이다. `window.menuBarVisibility: visible`은 ☰ 단추 대신 메뉴 줄을 편다(웹 VS Code에서 `classic` 값은 메뉴 줄을 숨긴다). `workbench.startupEditor: none`은 폴더를 열 때 「Get Started with VS Code for the Web」이 든 시작 화면을 띄우지 않고, `terminal.integrated.initialHint: false`는 빈 터미널에 뜨는 Copilot 안내 글을 끈다. `terminal.integrated.gpuAcceleration: off`는 터미널을 캔버스가 아니라 DOM으로 그리게 한다. 그래야 구간 모듈이 `.xterm-rows`에서 프롬프트 줄과 출력 줄의 위치를 읽어 짚을 수 있다. `workbench.colorTheme: Dark Modern`은 색상이고(새 프로필의 기본은 밝은 색이다), `chatgpt.cliExecutable`은 길 2의 엔진 경로다. `extensions.ignoreRecommendations: true`는 CSV 파일을 열 때 오른쪽 아래에 뜨는 확장 추천 알림을 끈다(그 알림이 Codex 입력칸을 가렸다). `chat.disableAIFeatures: false`는 기본값이고, 학생 화면처럼 오른쪽 칸에 「Chat | Codex」 두 탭과 제목 줄의 채팅 아이콘, 상태 줄의 Copilot 아이콘이 보이게 둔다(옛 프로필에 남은 `true`를 덮으려고 적어 둔다). 터미널 기본 프로필은 정하지 않아 학생과 같은 PowerShell이 뜬다. 배율은 아래 「공간 · 화면」의 125%를 유지한다.
     `prep`은 설정 말고 두 가지를 더 맞춘다. 오른쪽 칸은 Codex 탭을 앞에 둔다(새 프로필은 Chat 탭이 앞에 있다 — `resetLab`도 편마다 Codex 탭을 앞에 둔다). 그리고 탐색기 칸과 오른쪽 칸의 폭을 `config.json`의 `layout`(CSS px — 탐색기 362, 오른쪽 칸 555)에 맞춘다. 이 값은 1회차 실습2 가이드 사진 `codex-response.png`의 비율(폭 1920 가운데 탐색기 377, 오른쪽 칸 578)을 이 화면 폭으로 옮긴 것이고, 이 폭에서 Codex 입력칸 아래에 「Default permissions」와 모델 이름 「6-Luna Medium」이 글자로 보인다. 웹 VS Code에는 칸 폭 설정이 없어서 `prep`이 칸과 편집기 사이 경계를 마우스로 끌어 맞추고, 창을 새로 고친 뒤에도 같은 폭인지 재서 다르면 다시 맞춘다. 폭은 프로필에 저장되어 모든 랩 폴더에 똑같이 걸린다.
   - Codex 로그인은 서버 쪽 CODEX_HOME(길 1)에 있어, 녹화 브라우저 프로필을 새로 만들어도 남는다(새 프로필에서 첫 안내만 넘기면 새 대화 화면이 떴다). 새 프로필에서 Codex 탭이 숨겨져 있으면 오른쪽 `Additional Views`에서 Codex를 연다. 로그인이 풀려 `Sign in with ChatGPT`가 보이면, 녹화 브라우저에는 창이 없어 사용자가 그 안에서 로그인할 수 없으므로 멈추고 사용자에게 알린다. 확장의 웹뷰 안 단추는 녹화 밖에서는 `p.clickText('<단추 글>')`(`page.mjs` — 프레임을 따라 들어가 글이 정확히 같은 보이는 요소 하나를 누르고, 하나가 아니면 멈춘다)로 누르고, 녹화 구간에서는 `codexEl`로 재어 화살표를 옮겨 누른다(길 6).
   - 새 학생 프로필에 `Set up Agent sandbox to continue`가 뜨면 `Set up`으로 준비한다. 관리자 방식이 실패해 `Use backup sandbox`를 제공하면 그 경로로 준비하고 `Sandbox is ready`를 확인한다. 설정 뒤 로고만 남고 확장 호스트가 다시 연결되지 않으면 편집기를 먼저 클릭해 F1 → `Developer: Reload Window`로 다시 연다. 준비 완료 문구만으로 응답까지 확인됐다고 쓰지 않고, 짧은 질문의 화면 응답과 `task_complete`를 확인한다.
5. 음성 — 포털 촬영도구의 `voice.py` 하나로 산다(이 폴더에는 따로 없다). 큐 파일 `*_큐.json`은 포털과 같은 꼴 `{"voice_id", "model_id", "cues": [{"id", "segment", "text"}]}`이고, `segment`는 구간 모듈 파일 이름이다. 견적은 키 없이 `<py> ../../포털/촬영도구/voice.py ../<큐 파일> [구간 모듈 이름 …] --도구 vscode --견적`으로 낸다. 이 명령은 사지 않고, 지금 사면 새로 살 큐의 id와 음성에 보낼 글자 수를 찍는다. 구매(유료, 영상 V-4의 견적과 승인 뒤)는 같은 명령에서 `--견적`을 빼고 영상 「자료」의 `음성키.py 실행`으로 감싸 부른다. 음성은 `config.json`의 `audio`(`vscode/음성/`)에 `<큐 id>.mp3`와 `.json`(text · said · duration_ms · credits)으로 쌓이고, 글이 같은 큐는 다시 사지 않는다. 음성이 없는 큐가 있으면 녹화가 「Voice cue missing」으로 멈춘다.
6. 찍기 — 구간 모듈은 `segs/<이름>.mjs`이고, `vscode(ctx)`로 조작 층을 받아 `ctx.say(큐id, 조작, {at:'대사 속 구절'})`로 큐와 조작을 잇는다. 온톨로지 파트 랩(통합 2~4회차, 실전 2 · 3회차)의 모듈은 `segs/lab-common.mjs`의 `labUi(ctx)`를 쓴다. 이 층은 조작마다 `ctx.report`에 기록을 남겨 dry가 큐와 조작을 재게 한다. 대상이 없거나 화면 밖이면 실패로 멈추고, 글을 칠 자리에 입력 초점이 없으면(Codex 입력칸에 가 있으면) 글을 보내지 않고 멈춘다. 한 큐에서 여럿을 차례로 짚을 때는 고정 대기 대신 `atPhrase`로 그 대상을 말하는 구절에 맞추고, 쉼 값은 영상 V-14의 2회차 값을 `PAUSE`로 준다. 촬영 폴더 · ZIP · 큐 파일은 `LABS` 표 한 곳에 있고, 되돌리기 `resetLab`은 폴더 이름의 해시가 지금 ZIP과 다르면 멈춘다(ZIP을 다시 만들면 촬영 폴더를 새로 푼다).
   - 강조(영상 V-14) — 대본이 짚는 대상은 `c.emph(대상, {shape, phrase})`로 짚는다. 이 조작은 화살표를 대상 옆의 글을 덮지 않는 자리로 옮기고, 화살표가 닿은 때 강조를 페이지에 그린다. 모양은 `band`(띠, 기본) · `underline`(밑줄) · `box`(테두리) · `circle`(동그라미)이고 고르는 기준은 영상 V-11이다. 대상은 `lab-common.mjs`의 `em.line('줄의 첫 글')`(편집기 줄) · `em.term('줄에 든 글')`(터미널 줄) · `em.row('첫 칸 글'[, 칸 번호])`(결과 표의 행이나 칸) · `em.codex(x0, y0, x1, y1)`(Codex 패널 안의 비율 상자)로 만들고, 줄 안의 조각은 `phrase: '조각 글'`로 준다. Codex 답은 웹뷰라 바깥 문서에서 잴 수 없으므로 `codexBoxes(c, ctx, '<웹뷰 안 CSS>', '<든 글>')`가 프레임을 따라 들어가 그 요소의 상자를 재고(패널보다 넓은 표는 보이는 폭까지만), `em.box(상자)`로 짚는다. 제목은 `h2` · `h3`, 굵은 글씨는 `strong`, 목록은 `li`, 표는 `table`, 메모 줄 링크는 `span.break-words`(글은 「현장 메모 3, 6행 (line 3)」 꼴)다. 답이 끝나면 패널이 답 끝으로 굴러가 있으므로, 짚기 전에 `codexScrollInto(c, ctx, () => 상자)`로 그 요소를 보이는 칸에 들인다(화살표를 패널 가운데로 옮긴 뒤 휠로 굴린다). 찾는 글은 그 take의 답에서 고르고, 답이 바뀌면 그 답에 맞춰 고친다(본보기 `segs/wv-06b.mjs`). 진행 표시처럼 글이 계속 바뀌는 자리만 비율 상자로 짚고, 그 말이 끝날 때 걷는다(`segs/wv-06a.mjs`). 강조는 다음 `emph`가 시작할 때, 화살표가 다른 곳으로 떠날 때, 누르기 · 입력 · 굴리기가 시작할 때, 구간의 마지막 말이 끝날 때 지워진다. 두 대상을 견주는 말에서는 둘째 `emph`에 `keep: true`를 주고, 조작 없이 말이 다음 화제로 넘어가면 `c.clearEmph()`로 지운다.
   - 펜 그림 — 화면 위에 손으로 긋듯 그리는 그림은 정의 하나(`{id, board, items}` — 판과 칸 `box` · 화살표 `arrow` · 글 `text`, 좌표는 1920×1080 프레임 px, 속이 안 보이는 칸은 `fill: 'black'`)를 그 편의 공용 모듈에 두고 `const fig = c.pen(정의)`로 받는다. `fig.draw('칸', …)`는 말에 맞춰 한 획씩 긋고, `fig.show()`는 긋는 움직임 없이 다시 띄우고, `fig.ring('칸')`은 그 칸에 「지금 여기」 동그라미를 치고, `fig.trace('화살표')`는 이미 그은 획을 빨갛게 덧긋고, `fig.hide()`는 그림을 걷는다. 걷으면 페이지에 남는 것이 없으므로, 다른 구간과 다른 편에서는 같은 정의로 `show`한다. 칸 글의 조각은 `c.emph({pen: '칸'}, {shape: 'underline', phrase})`로 짚는다. 정의의 본보기는 `draw_check.mjs`의 `FLOW`다.
   - 글상자 — 화면에 없는 짧은 목록은 `c.note(['줄', …], {title, at})`로 띄우고 `c.note(null)`로 걷는다. 자리 `at`은 위아래 `t`|`b`와 좌우 `l`|`c`|`r` 두 글자(기본 `tr`)나 프레임 px `[x, y]`이고, 기본 자리가 Codex 패널을 가리는 화면에서는 편집기 위의 `[x, y]`를 준다(`segs/ws-01c.mjs`). 줄은 `c.emph({note: 줄 번호 | '줄에 든 글'})`로 짚는다.
   - 펜 그림과 글상자는 띄운 구간 안에서 걷는다. 구간이 끝날 때 떠 있으면 녹화와 리허설이 멈춘다. 없는 대상, 여럿 잡힌 대상, 칸 밖으로 굴러간 줄, 화면 밖에 그려질 것, 정의에 없는 이름도 큐 id를 대며 그 큐에서 멈춘다. 그림 층(`draw.mjs`)이나 녹화 제어를 고친 작업자는 `node draw_check.mjs`를 통과시킨다. 이 자가시험은 녹화 브라우저와 웹 VS Code 없이, 스스로 띄운 흉내 화면을 실제로 녹화하고, 강조마다 떠 있을 때와 지워진 뒤의 프레임을 `작업/촬영/vscode/draw-check-<시각>/확인/`에 남긴다.
   ```bash
   ./run.sh up                                 # 녹화 브라우저 띄우기(이미 떠 있으면 그대로). 다 찍으면 ./run.sh down — 「down」이 찍혀야 한다
   ./run.sh prep [랩 폴더 절대 경로]             # 화면 설정을 넣고 잰다(길 4) — 프로필을 새로 만들었거나 settings를 고친 뒤
   ./run.sh reset <편>-reset.mjs               # 녹화 밖 상태 맞춤: 그 편의 시작 화면을 만든다
   ./run.sh dry <이름> <모듈>                   # 리허설: 녹화 없이 조작만 해 보고 큐마다 검사(dry.json), 실패면 종료 코드 1
   ./run.sh rec <이름> <모듈> [앞 구간[:자른 ms] | '{x:..,y:..}']   # 구간 하나 녹화 → 실측
   PAGE=1 ./run.sh rec <이름> <모듈> [앞 구간]   # 녹화 브라우저의 둘째 페이지(랩 결과 화면 · 그림 한 장)에서 찍는다. dry도 같다
   CODEX_HOME=<길 1의 값> ./run.sh rec <이름> <모듈> [앞 구간]   # Codex에 요청을 보내는 구간(길 9). dry도 같다
   ./run.sh measure <이름>
   ```
   녹화 브라우저는 구간 사이에도 떠 있어 같은 페이지 · 열린 폴더 · 터미널 · Codex 대화가 남고, 실행(`prep` · `reset` · `dry` · `rec`)은 `page.mjs`로 붙었다 떨어진다. 같은 브라우저에 붙은 다른 실행이 돌고 있으면 `run.sh`가 「BUSY」로 시작하지 않으므로 리허설과 녹화는 차례로 돌린다. 첫 페이지가 웹 VS Code이고, 새 구조 랩의 결과 화면(`output/result.html`)은 둘째 페이지에서 `PAGE=1`로 찍는다. 구간 모듈이 `resultView`로 `file:///D:/HYD-Practice/<폴더>/<랩>/output/result.html`을 열고, 화면 값이 `config.json`의 `viewport` 그대로라 웹 VS Code와 같은 프레임이 된다. 다른 화면 값이 필요한 구간에만 `VP='{width:..,height:..,dsf:..}'`를 준다. 터미널 명령은 학생과 같은 글자로 치고 `--no-open`을 붙이지 않는다(영상 V-3). 길 1대로 켠 서버의 터미널에서 `python run.py`는 결과 화면을 어디에도 띄우지 않았다(녹화 브라우저의 페이지 수와 이 PC의 브라우저 프로세스 수가 그대로였다). 구간 사이의 녹화 밖 상태 맞춤은 그 편의 `segs/<편>-reset.mjs`(본보기 `i206-reset.mjs`)로 한다. 사용자가 넣은 결과는 실습 폴더의 파일로 읽는다.
   - 결과 화면이 저절로 열리는 장면 — 학생 PC에서는 `output/result.html`이 없을 때의 첫 `python run.py`만 브라우저를 앞에 띄우고, 그 뒤 실행은 터미널에 「열린 화면에서 F5로 새로 고침합니다」만 찍는다(랩 `run.py`). 그래서 첫 실행은 두 구간으로 나눠 찍는다. 앞 구간(첫 페이지)은 명령을 치고 터미널에 `결과: output/result.html`이 뜬 직후(실측: Enter 뒤 0.2~0.4초)에 0.7초쯤 두고 끝낸다. 뒤 구간(`PAGE=1`, 앞 구간 이름을 준다)은 녹화 전에 `resultView`로 결과 화면을 열어 두고 그 화면에서 시작한다. 합성하면 터미널 출력에서 결과 화면으로 바로 넘어가, 브라우저가 앞에 뜬 것처럼 이어진다(시험 합성 `작업/촬영/vscode/t1125b-결과화면합성/`). 뒤 구간의 화살표는 앞 구간이 끝난 자리에서 시작하게 `installPointer(ctx.prev ? null : …)`로 둔다. 그 뒤의 실행은 첫 페이지에서 명령을 치는 구간과 둘째 페이지에서 F5를 하는 구간을 번갈아 찍는다. 학생의 F5는 `ctx.p.reload()`로 한다(CDP로 보낸 F5 키는 `file://` 문서를 다시 읽지 않았다). 새로 읽은 문서에는 표시 포인터가 없으므로 같은 자리에 `installPointer`로 다시 놓고, 굴린 자리는 새로 고친 뒤에도 그대로 남으므로(실측) 그 화면에 보이는 대상부터 짚는다.
   - 그림 한 장 위에 그리는 장면(06-1 여는 장) — 웹 VS Code 밖의 화면 위에 펜 그림과 글상자를 그릴 때는 그 화면의 그림 파일(1920×1080, 16:9가 아니면 멈춘다)을 `imageView(c, ctx, '<그림 절대 경로>')`로 둘째 페이지에 가득 띄운 뒤 `c.pen` · `c.note`로 그리고 `PAGE=1`로 찍는다. 06-1의 그림은 사용자 녹화의 첫 프레임을 `작업/촬영/vscode/사용자녹화/`에 뽑아 두고 그 경로를 준다(`ffmpeg -i <사용자 녹화> -frames:v 1 <첫프레임.png>`). 그림을 바꿔도 모듈은 경로만 바꾸면 된다(임시 그림으로 찍은 시험 `작업/촬영/vscode/t1125b-pen-a/`).
   - Codex 패널 — 채팅은 웹뷰 iframe 안이지만 녹화 브라우저는 그 안의 요소까지 잰다. 이름이나 글이 있는 단추와 입력칸은 `lab-common.mjs`의 `codexEl(c, ctx, {label | text | input})`로 재어 누르고(예: `{label: 'New chat'}`), 이름도 글도 없는 자리만 `codexPoint`의 비율 좌표로 짚는다.
7. 합성과 검사 — `FFMPEG=<ffmpeg> PYTHONUTF8=1 python encode.py <출력> <구간[:ms]> …`로 합성한다(문장이 겹치거나 교체 음성이 원래 길이를 넘으면 멈춘다). 검사는 영상 길 17대로 한다.
8. 조각 고침 — 그 구간만 새 take 이름으로(`p22-2` → `p22-2b`) 앞 구간 끝의 포인터 위치에서 찍고, `encode.py` 인자에서 그 이름만 바꾼다.
9. Codex 요청 구간 — 「새 대화 → 입력 · 전송 → `task_complete` 기다리기 → 답 굴리기 → 터미널 `python check.py`」를 한 흐름으로 하고, 녹화 전에 `run.sh dry`로 끝까지 돌린다. 다음 순서로 한다.
   - 요청 입력과 전송 → 응답 진행을 한 흐름으로 찍는다. `lab-common.mjs`의 네 함수를 차례로 쓴다. `codexFocus`는 입력칸을 재어 누르고 초점이 Codex에 왔는지 확인한다(실측: 한 번 눌러 초점이 왔다). `codexType`은 부탁 글을 넣고, `codexSubmit`은 Enter로 보낸 뒤 보낸 시각을 돌려준다. 초점이 Codex에 없으면 글도 Enter도 보내지 않고 멈춘다. 보내면 패널에 「Thinking」이 뜨고, 끝나면 「Worked for N s」 줄 아래에 답이 선다. 답은 패널 위에서 마우스 휠로 굴린다. 「Default permissions」에서는 작업 폴더 안의 쓰기에 승인 창이 뜨지 않고 Codex가 바로 쓴다. 그래서 쓰기를 맡기는 요청에는 그 랩의 구현 파일 경로(코딩랩 K-7)를 명시한다.
   - 응답이 끝났는지는 화면이 아니라 `<CODEX_HOME>/sessions/<날짜>/rollout-*.jsonl`의 `task_complete`로 판정한다. `codexWait(ctx, <보낸 시각>)`이 이 기록을 읽어 끝난 답(`message`), 계정 한도 사용률(`used`, %), 걸린 시간을 돌려주고, 기록에 오류 사건이 있으면 그 글로 멈춘다. 이 함수는 환경변수 `CODEX_HOME`(길 1에 둔 값)을 읽으므로 요청 구간은 `CODEX_HOME=… ./run.sh rec|dry …`로 부른다. 리허설(`dry`)도 실제 요청을 보내 한도를 쓴다. 한도 오류나 로그인 풀림으로 멈추면 다른 계정으로 돌리지 않고 사용자에게 알린다. 같은 대화에 이어 보낸 부탁은 같은 기록 파일에 붙는데, Windows는 Codex가 열어 둔 파일의 수정 시각을 바로 바꾸지 않으므로 기록은 수정 시각이 보낸 시각보다 6시간 안쪽인 파일까지 읽는다.
   - 답이 늦을 때 하는 기다림 말(영상 V-14)은 `waitLines(ctx, <보낸 시각>, ['큐id', …])`로 넣는다. 앞 말이 끝나고 쉼이 지나면 `codexDone`으로 기록을 한 번 보고, 아직 안 끝났을 때만 다음 기다림 말을 한다. 그래서 답이 빨리 오면 말이 줄고, 늦게 오면 남은 시간은 말 없이 기다린다(본보기 `segs/wv-06a.mjs`).
   - 시험이나 리허설이 남긴 대화는 녹화 전에 보관한다. 대화 목록에서 그 행에 커서를 올리면 `Archive chat` 단추(aria-label)가 나오고, 누른 뒤 `Confirm`을 누른다(길 4).
   - 끝난 응답, 바뀐 파일, 실행 출력을 읽고 「결과 확인」 큐를 쓴 뒤 그 음성을 만든다.
   - 결과 확인 구간에서는 Codex를 다시 부르지 않는다. 이미 있는 응답을 굴려 보며 결과 파일과 원자료를 연다.
   - ZIP 받기 · 풀기 · 폴더 열기 · 신뢰 장면을 어디서 무엇으로 보이는지는 영상 V-13이 정한다. 웹 VS Code 구간은 3의 폴더가 열린 화면에서 시작한다. 영상에는 가이드 문서를 띄우지 않는다. 가이드는 영상을 보고도 더 필요한 학생이 따로 여는 자료다.
10. 가이드 사진(영상 밖) — 어느 사진을 웹 VS Code로, 어느 장면을 실제 PC에서 찍는지는 가이드 P-8이 정한다. 웹 VS Code 사진은 녹화 프레임(`<take>/frames/`)에서 고르거나 녹화 브라우저의 screencast 프레임으로 받는다.

## 함정

- 네이티브 VS Code에서는 computer use가 `click` 등급뿐이라 입력할 수 없다. CDP로 입력하는 것은 같은 제한을 우회하는 일이라 쓰지 않는다. 그래서 serve-web을 녹화 브라우저에서 찍는다.
- ego lite 0.6.3.17부터 SDK가 `page.cdp('Page.screencastFrameAck', {sessionId})`를 「does not take sessionId in params」로 거부한다. ACK가 없으면 프레임이 3초에 3장만 오고, ego는 창이 앞에 있어야 프레임을 주는데 서비스 모드에는 창이 없으며, `Page.captureScreenshot`을 되풀이하면 7.8 fps라 커서가 끊긴다. 그래서 이 도구는 ego를 쓰지 않는다. ego로 찍는 다른 도구를 다시 찍는 작업자는 먼저 짧은 녹화로 프레임 수를 잰다.
- 웹 VS Code 서버는 브라우저가 떨어져도 그 폴더의 터미널을 살려 둔다. 터미널 칸이 닫힌 창(새 프로필)에서는 되살아난 터미널이 화면에 보이지 않다가, 녹화 구간이 새 터미널을 열 때 목록에 경고 표시와 함께 두 개로 나타난다. 그래서 `resetLab`은 보이는 터미널이 없어도 `Terminal: Kill All Terminals`를 한 번 보낸다. 터미널을 여는 구간의 프레임에서 터미널이 하나인지 본다.
- Git Bash에서 서버를 띄우면 Codex가 `CODEX_HOME ... does not exist`로 실패한다. PowerShell에서 띄운다.
- 토큰 파일을 상대 경로로 주면 서버가 읽지 못한다. 절대 경로로 준다.
- 확장 폴더를 복사해서는 확장이 등록되지 않는다. `--install-extension`으로 설치한다.
- Codex 탭이 `The extension could not start its user interface`로 끝나거나 대화가 막히면, 2의 화면 확장과 엔진 조합, 사용자 설정을 확인한다.
- 세션 파일을 직접 보관 폴더로 옮긴 뒤 패널이 비면 최신 `Codex.log`의 `stale rollout path`와 옮긴 파일을 대조한다. 직접 옮긴 시험 파일이 원래 경로에서 없어진 경우에만 그 파일을 원래 자리로 복원하고 F1 → `Developer: Reload Window`로 연다. 패널이 돌아오면 길 4의 보관 버튼을 쓴다. 재설치나 AI 요청으로 상태를 시험하지 않는다.
- 사용자 설정에 새 엔진 경로가 있어도 이미 떠 있던 구형 프로세스는 그대로일 수 있다. 로그인 후 모델이 `5.5`만 보이고 학생 프로필 `logs_2.sqlite`의 모델 목록 오류에 `unknown variant max`가 있으면, 현재 프로세스의 실행 경로를 확인한다. 같은 웹 VS Code를 새로고침한 뒤 `app-server-26.1021.22027/codex.exe`에서 실행되는지, 오른쪽 모델이 `6-Luna Medium`인지 확인한다. 모델 표시만으로 계정 연결을 판정하지 않고 4의 짧은 응답 확인까지 마친다.
- `D:/...`를 그대로 넣으면 `C:\work\...`가 열린다. `encodeURIComponent('/D:/...')`로 넣는다.
- 신뢰 단추를 선택자로 누르면 눌리지 않는다(가려진 같은 이름 단추, Ctrl+Enter, Machine 설정은 모두 효과가 없었다). 3대로 단추 중심을 좌표로 누른다. 그 폴더에 지난 터미널이 살아 있으면 「Do you trust the authors of the files in this folder?」 창이 Workspace Trust 편집기 위에 늦게 떠서 편집기의 Trust 단추가 눌리지 않는다. `trustFolder`는 그 창이 보이면 그 창의 `Trust Folder & Continue`를 누른다. 본문의 「Restricted Mode」 글자에 신뢰 판정이 속으므로 `.statusbar-item`만 본다.
- Codex 답에 「2~4행」처럼 범위가 둘 나오면, 두 `~` 사이가 마크다운 취소선으로 그려져 글자에 줄이 그어진다. 녹화에 쓸 답은 그 화면을 먼저 본다. 랩의 `AGENTS.md`가 범위를 다른 꼴로 쓰게 할지는 코딩 랩 담당이 정한다.
- 터미널 패널이 세 줄 높이면 새 출력이 옛 줄 위에 겹쳐 그려진다. 터미널 장면을 찍기 전에 패널 높이를 키우고 이전 출력을 지운 뒤, 그 화면을 프레임으로 먼저 본다. 화면 크기(metrics)를 다시 걸면 터미널 가운데에 「125 x 22」 같은 크기 표시가 잠깐 뜨므로, 터미널이 열린 구간의 첫 프레임에서 사라졌는지 본다.
- 탐색기 행의 이름 위에 커서를 오래 두면 전체 경로 툴팁이 떠서 아래 행을 가린다. 행을 짚을 때는 이름 왼쪽의 접기 화살표 쪽에 둔다.
- PowerShell 시작 시 `PSReadLine`을 불러오지 못했다는 경고가 뜨고, 해당 모듈을 불러온 출력에 `PSSecurityException`이 있으면 입력 보조 모듈이 스크립트 실행 정책에 막힌 것이다. PC의 정책을 낮추지 않고, 길 1대로 `PSExecutionPolicyPreference`를 준 서버를 다시 켠다(터미널에서 `Get-ExecutionPolicy -List`의 `Process`가 `Bypass`로 나온다). 경고를 지운 화면만으로 해결됐다고 판정하지 않고, 새 터미널에서 실습 명령이 실행되는지 확인한다.
- 학생 역 Codex 계정은 무료 계정이라 새 대화 화면 오른쪽 아래에 「Get Plus」 단추가 늘 보인다. 끌 수 없으므로 말로 짚지 않고 둔다.
- 프레임과 같은 실제 픽셀 1920×1080으로 찍으면 화면이 좁아 패널이 답답하다. 실제 픽셀 2304×1296(`config.json`의 `viewport`)으로 찍어 프레임 1920×1080으로 받는다.
- 한국어 팩은 1.131이 마켓플레이스의 마지막 판이고 1.143에 맞는 판이 없다. 웹 VS Code는 화면 글자를 팩에서 번호 차례로 받아 오므로, 판이 다른 팩을 켜면 글자가 엉뚱하게 바뀐다(「Welcome」이 「새 터미널(&&N)」로 바뀌었다). 그래서 녹화 화면은 영어로 두고, 1.143에 맞는 팩이 나오면 다시 시험한다. F1에서 `Configure Display Language`를 찾아 `English`를 고른 뒤 새로고침한다. 메뉴 글자가 틀려도 명령의 영어 이름으로 찾을 수 있다. localStorage의 nls 키만 지우면 브라우저 언어에 따라 같은 팩을 다시 불러오므로 그것만으로 복구됐다고 판단하지 않는다.
- 랩 DB 명령(`python run.py db`)은 Docker Desktop이 떠 있어야 하고, 출력이 길어 터미널 칸(13줄쯤)의 첫 줄들이 위로 밀린다. 랩 DB 컨테이너(`hyd-student-<id>`, 라벨 `hyd.practice.id`)는 그 폴더의 `.lab_connection.json`과 짝이고, 시험으로 만든 것은 `docker rm -f -v`로 익명 볼륨 둘까지 지운다. 촬영 폴더 경로가 길면 프롬프트가 터미널 한 줄의 절반을 차지하므로 LABS 표의 짧은 꼴(`D:/HYD-Practice/<접두>p-<해시>/`)에 푼다.
- 녹화 브라우저는 하나라서, 리허설이 화면에 남긴 것(열린 터미널, 탭, Codex 대화)이 다음 녹화의 첫 화면이 된다. 녹화 전에 그 편의 `reset`을 돌리고 첫 프레임을 본다.
- `run.sh dry`의 통과는 모듈이 `ctx.report`에 남긴 기록으로만 판정되므로, 기록을 남기지 않는 모듈은 예외 없이 끝나기만 해도 「DRY OK」가 된다(`dry.json`의 `cues` · `ops`가 0이다). dry 결과는 `cues`가 그 구간 큐 수와 같은지까지 본다.
- 폴더를 연 직후에는 Codex 웹뷰가 늦게 떠서 입력 초점을 가져간다. 그때 F1이나 명령 글자를 보내면 Codex 입력칸으로 간다. 그래서 되돌리기는 「Ask Codex anything」이 뜬 뒤에 첫 명령을 보내고, 글을 보내기 전마다 초점이 있는 자리를 확인한다. 새로 푼 폴더에 신뢰를 준 그 창에서는 Codex 패널에 웹뷰가 아예 생기지 않으므로, 되돌리기는 신뢰를 준 뒤 창을 한 번 새로 고친다.
- 여유 메모리가 3 GB 아래면 이 도구의 `run.sh`는 경고만 하고(Notion `run.sh`는 멈춘다), 녹화가 괜찮은지는 `measure.py`의 이동 중 공백으로 판정한다.
- 메뉴 클릭이 대사 끝까지 밀린다. `{at:'구절'}`로 클릭 시점을 대사 속 구절에 맞춘다. 두 번째 클릭이 앞 문장 끝에 함께 일어나면 큐를 나눈다. 포털의 「다시 계산」 클릭이 빗나가면 「화면 안」을 본문의 실제 높이 비율로 판단하고(`segs/p31-common.mjs`의 `p.show`), 화면을 굴릴 때 화살표를 옮기지 않는다.
