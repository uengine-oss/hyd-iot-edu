# 웹 VS Code 촬영준비

코딩 랩과 VS Code 장면은, 공식 `code serve-web`으로 띄운 웹 VS Code를 이 PC의 ego 탭에서 찍는다(클라우드에서는 찍을 수 없다). 서버는 저장소 루트의 PowerShell에서 띄우고, 음성, 녹화, 합성은 Git Bash에서 [촬영도구/](촬영도구/)를 현재 위치로 두고 한다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md)에 있다.

## 길

1. 서버 — 포트 8793에 다른 서버가 떠 있으면 멈춘다. 비어 있을 때만 같은 판본, 포트, 데이터로 켠다(PowerShell). Codex가 학생 역 계정과 모델(testmiken 로그인 · `gpt-6-luna` medium)을 쓰도록, 켜기 전에 `$env:CODEX_HOME = 'D:\HYD-Practice\_codex_luna'`를 둔다. 이 값이 없으면 기본 `~/.codex` 설정으로 떠서 모델이 「Custom High」로 보인다. 서버를 다시 켤 때는 `code-tunnel.exe`만 끄면 자식 `node.exe`가 8793을 계속 쥐므로, 명령줄에 `v143`이 든 프로세스를 모두 끈 뒤 포트가 비었는지 본다.
   ```powershell
   $r = (Resolve-Path '작업/촬영/vscode/v143').Path
   $commit = 'e646868227c3e3a9e3f24277c8c7220be42c0be7'
   $listener = Get-NetTCPConnection -LocalPort 8793 -State Listen -ErrorAction SilentlyContinue
   if ($listener) {
       $server = Get-CimInstance Win32_Process -Filter "ProcessId=$($listener.OwningProcess)"
       if ($server.Name -ne 'code-tunnel.exe' -or !$server.CommandLine.Contains($r) -or !$server.CommandLine.Contains($commit)) { throw '8793을 다른 서버가 사용 중' }
   } else {
       if (!(Test-Path "$r/access.txt" -PathType Leaf) -or !(Test-Path "$r/data/extensions/extensions.json" -PathType Leaf)) { throw '접속 파일 · 확장 프로필 확인' }
       $env:CODEX_HOME = 'D:\HYD-Practice\_codex_luna'
       $exe = Join-Path $env:LOCALAPPDATA 'Programs/Microsoft VS Code/bin/code-tunnel.exe'
       Start-Process -FilePath $exe -WindowStyle Hidden -ArgumentList "serve-web --commit-id $commit --host 127.0.0.1 --port 8793 --connection-token-file `"$r\access.txt`" --cli-data-dir `"$r\cli`" --server-data-dir `"$r\data`" --disable-telemetry --accept-server-license-terms"
   }
   ```
2. Codex 확장(확장이 사라졌을 때만) — 맞는 조합은 웹 VS Code 1.143.1, 화면 확장 26.422.71525, 실행 엔진 26.1021.22027(Windows)이다.
   - 확장은 `& "$r/cli/serve-web/$commit/bin/code-server.cmd" --server-data-dir "$r/data" --install-extension openai.chatgpt@26.422.71525 --force`로 설치한다.
   - 사용자 설정(JSON)의 `chatgpt.cliExecutable`에 `$r/app-server-26.1021.22027/codex.exe`의 절대 경로를 `/` 구분자로 넣는다. 이 설정은 서버가 아니라 ego 프로필의 브라우저 저장소에 있다. 그래서 `v143` 폴더를 옮기면 옛 경로가 남아 Codex 패널이 로고만 띄운 채 멈추고, 서버 로그 `data/data/logs/<시각>/exthost*/remoteexthost.log`에 `spawn … codex.exe ENOENT`가 찍힌다. 고칠 때는 F1 → `Preferences: Open User Settings (JSON)`을 연다. 편집기가 `{`를 자동으로 닫으므로, 내용을 넣은 뒤 JSON으로 읽히는지 확인하고 저장한다.
   - 엔진 폴더를 잃었으면 VSIX의 `extension/bin/windows-x86_64/` 전체를 그 자리에 둔다(VSIX는 `작업/_로컬/VSCode웹복구/`에 있다). VSIX도 없으면 같은 `code-server.cmd`에 `--server-data-dir "$r/engine-download-data" --extensions-dir "$r/engine-download" --install-extension openai.chatgpt@26.1021.22027 --force`를 주어 별도 폴더에 받는다. 그 안의 `openai.chatgpt-26.1021.22027-win32-x64/bin/windows-x86_64/` 전체를 `$r/app-server-26.1021.22027/`로 복사한다. 화면 확장은 26.422.71525로 유지하고, 고친 뒤 같은 탭을 새로고침한다.
3. 폴더 열기 — 학생처럼 ZIP을 `D:/HYD-Practice/<id>-<uuid8>`에 풀고, `http://127.0.0.1:8793/?tkn=<access.txt 값>&folder=` 뒤에 `encodeURIComponent('/D:/...')`를 붙인 주소로 연다. 토큰 값은 로그나 화면에 남기지 않는다. 새로 푼 폴더는 Restricted Mode로 열리고, 그동안은 Codex 확장이 꺼져 확장 목록에서 흐리게 보이며 오른쪽 패널에는 Copilot Chat만 있다. 그러니 폴더 신뢰를 먼저 준다. F1 → `Workspaces: Manage Workspace Trust`로 Workspace Trust 편집기를 연다(상태 표시줄의 Restricted Mode 클릭은 편집기를 열지 못할 때가 있다). 그 안의 `Trust` 단추(`.monaco-button`)를 단추 중심 좌표로 누른다. 신뢰됐는지는 `.statusbar-item`에서 「Restricted Mode」가 사라질 때까지 기다려 판정한다(불러온 직후에 한 번 읽은 값은 아직 바뀌기 전일 수 있다). 상태 표시줄에 「Screen Reader Optimized」가 보이면 F1 → `Toggle Screen Reader Accessibility Mode`로 끈다. 켜진 채로 두면 편집기 줄바꿈이 달라지고 그 표시가 화면에 남는다. Welcome 탭은 `.tab .tab-actions .action-label`로 닫는다. 미리보기 탭을 고정하려면 dblclick 이벤트를 보낸다(ego에는 `mouse.dblclick`이 없다).
4. Codex와 터미널 — Codex는 오른쪽 Codex 탭에서 쓴다(새 프로필 안내가 뜨면 Next → Continue with current model). 녹화 전에 이 촬영의 시험 대화만 확장 화면에서 보관한다. 해당 대화 행에 커서를 올려 `Archive chat` → `Confirm`을 누르고, 목록에서 사라졌는지와 새 대화 입력칸이 비었는지 확인한다. 다른 대화는 건드리지 않는다. 세션 파일을 직접 옮기면 대화 목록의 경로와 어긋나므로 옮기지 않는다. 기존 연결 확인이 없을 때만 짧은 질문 하나로 답이 오는지 본다. 탐색기의 파일은 그 행을 누른 뒤 Enter로 연다(한 번 누르기는 선택만 한다). 새 터미널은 왼쪽 위 `Application Menu` → `Terminal` → `New Terminal`로 열고, 명령은 `typeKeys`(키 입력)로 친다. 터미널은 `insertText`로 넣은 글자를 받지 않는다. 웹판의 표시 언어는 영어이므로, 대사는 「왼쪽 탐색기(Explorer)」처럼 한글과 영어를 함께 말한다.
   - 통합반 2회차의 색상은 `Dark Modern`으로 고정한다. F1에서 `Preferences: Color Theme`를 찾아 그 이름의 명령을 정확히 누른 뒤 `Dark Modern`을 고른다. 검색 결과 첫 줄의 Marketplace 명령을 Enter로 선택하지 않는다. 배율은 아래 「공간 · 화면」의 125%를 유지한다.
   - 이 촬영용 웹 VS Code의 터미널은 `Command Prompt`를 쓴다. F1 → `Preferences: Open User Settings (JSON)`에서 기존 설정을 보존하며 아래 세 항목을 추가한다. 이미 있는 터미널 프로필은 덮어쓰지 않는다. 준비 중 열었던 PowerShell이 유휴 상태인지 확인해 `Kill Terminal`로 닫고 새 터미널을 열어, 제목이 `cmd`이며 시작 경고가 없는지 확인한다. 이 설정은 학생 랩 파일에 넣지 않는다.
     ```json
     "terminal.integrated.profiles.windows": {
       "Command Prompt": { "path": "C:\\Windows\\System32\\cmd.exe", "args": ["/d"] }
     },
     "terminal.integrated.defaultProfile.windows": "Command Prompt",
     "terminal.integrated.gpuAcceleration": "off"
     ```
     마지막 항목은 터미널을 캔버스가 아니라 DOM으로 그리게 한다. 그래야 구간 모듈이 `.xterm-rows`에서 프롬프트 줄과 출력 줄의 위치를 읽어 짚을 수 있다(F1 → `Preferences: Open Settings (UI)`에서 `terminal.integrated.gpuAcceleration`을 찾아 `off`를 골라도 된다).
   - 새 프로필에서 Codex 탭이 숨겨져 있으면 오른쪽 `Additional Views`에서 Codex를 연다. `Sign in with ChatGPT`를 누르면 OpenAI 로그인 탭이 열린다. 로그인과 본인 인증은 촬영 공통의 `handOff` 순서로 사용자에게 넘기고, 사용자가 완료했다고 알린 뒤 같은 공간을 되찾는다. 확장의 웹뷰는 snapshot에 버튼이 보여도 새 ref나 텍스트 선택자가 실패할 수 있으므로, 이때는 실제 프레임과 `.part.auxiliarybar`의 현재 위치를 기준으로 누른다.
   - 새 학생 프로필에 `Set up Agent sandbox to continue`가 뜨면 `Set up`으로 준비한다. 관리자 방식이 실패해 `Use backup sandbox`를 제공하면 그 경로로 준비하고 `Sandbox is ready`를 확인한다. 설정 뒤 로고만 남고 확장 호스트가 다시 연결되지 않으면 편집기를 먼저 클릭해 F1 → `Developer: Reload Window`로 다시 연다. 준비 완료 문구만으로 응답까지 확인됐다고 쓰지 않고, 짧은 질문의 화면 응답과 `task_complete`를 확인한다.
5. 음성 — `PYTHONUTF8=1 python voice.py [<큐 파일>]`. 큐 파일을 주지 않으면 `voice-jobs.json`을 읽는데, 지금은 없으니 만들어 쓴다(동시 3개씩 만든다). 큐 파일 `*_큐.json`의 항목은 `id` · `segment` · `text`를 가진다. 음성이 없는 큐가 있으면 녹화가 「Voice cue missing」으로 멈춘다.
6. 찍기 — 구간 모듈은 `segs/<이름>.mjs`이고, `vscode(ctx)`로 조작 층을 받아 `ctx.say(큐id, 조작, {at:'대사 속 구절'})`로 큐와 조작을 잇는다. 새 구조 랩(통합 3 · 4회차, 실전 2 · 3회차)의 모듈은 `segs/lab-common.mjs`의 `labUi(ctx)`를 쓴다. 이 층은 조작마다 `ctx.report`에 기록을 남겨 dry가 큐와 조작을 재게 한다. 대상이 없거나 화면 밖이면 실패로 멈추고, 글을 칠 자리에 입력 초점이 없으면(Codex 입력칸에 가 있으면) 글을 보내지 않고 멈춘다. 한 큐에서 여럿을 차례로 짚을 때는 고정 대기 대신 `atPhrase`로 그 대상을 말하는 구절에 맞추고, 쉼 값은 영상 V-14의 2회차 값을 `PAUSE`로 준다. 촬영 폴더 · ZIP · 큐 파일은 `LABS` 표 한 곳에 있고, 되돌리기 `resetLab`은 폴더 이름의 해시가 지금 ZIP과 다르면 멈춘다(ZIP을 다시 만들면 촬영 폴더를 새로 푼다).
   ```bash
   ./run.sh rec <이름> <모듈> [앞 구간 | '{x:..,y:..}']
   SPACE=<녹화 공간> VP='{width:1920,height:1080,dsf:1}' HYD_AUDIO=../../포털/음성 ./run.sh rec …   # 포털 구간(앞 구간 URL로 되돌아가지 않음, 길은 포털 촬영준비 「로컬 ego」)
   ./run.sh dry <이름> <모듈>                 # 리허설: 녹화 없이 조작만 해 보고 큐마다 검사(dry.json), 실패면 종료 코드 1
   ./run.sh measure <이름>
   ```
   VS Code 구간과 포털 구간은 서로 다른 ego 공간에서 찍고, 녹화 공간은 리허설 공간과 겹치지 않게 한다. 새 구조 랩의 결과 화면(`output/result.html`)도 따로 둔 결과 화면 공간에서 찍는다. 그 공간의 p1을 `file:///D:/HYD-Practice/<폴더>/<랩>/output/result.html`로 열고 `VP='{width:1843,height:1037,dsf:1.25}'`를 주면 웹 VS Code(125%)와 같은 프레임이 된다. 웹판에서는 명령에 `--no-open`을 붙여 이 PC의 기본 브라우저가 뜨지 않게 하고, 학생 PC에서는 브라우저가 저절로 열린다는 차이를 대사에서 말한다. 학생의 F5는 `ctx.p.reload()`로 한다(CDP로 보낸 F5 키는 `file://` 문서를 다시 읽지 않았다). 새로 읽은 문서에는 표시 포인터가 없으므로 같은 자리에 `installPointer`로 다시 놓는다. 구간 사이의 녹화 밖 상태 맞춤은 그 편의 `segs/<편>-reset.mjs`(본보기 `i206-reset.mjs`)로 한다. Codex 채팅은 웹뷰 iframe이므로 `.part.auxiliarybar` 영역 안의 비율 좌표로 누른다. 사용자가 넣은 결과는 실습 폴더의 파일로 읽는다.
7. 합성과 검사 — `FFMPEG=<ffmpeg> PYTHONUTF8=1 python encode.py <출력> <구간[:ms]> …`로 합성한다(문장이 겹치거나 교체 음성이 원래 길이를 넘으면 멈춘다). 검사는 영상 길 17대로 한다.
8. 조각 고침 — 그 구간만 새 take 이름으로(`p22-2` → `p22-2b`) 앞 구간 끝의 포인터 위치에서 찍고, `encode.py` 인자에서 그 이름만 바꾼다.
9. Codex 요청 구간 — 「새 대화 → 입력 · 전송 → `task_complete` 기다리기 → 답 굴리기 → 터미널 `python check.py`」를 한 흐름으로 하고, 녹화 전에 `run.sh dry`로 끝까지 돌린다. 다음 순서로 한다.
   - 요청 입력과 전송 → 응답 진행을 한 흐름으로 찍는다. 입력칸은 `codexInput`으로 누른다. 이 함수는 새 대화 화면에서 `.part.auxiliarybar`의 비율 좌표 (0.45, 0.855)를 두 번 누른다. 웹뷰가 첫 클릭에는 패널만 활성화하고, 둘째 클릭에서 입력칸 포커스를 받기 때문이다. 그다음 `type` 또는 `typeFast`로 넣고 Enter로 보낸다. 답은 패널 위에서 마우스 휠로 굴린다. 「Default permissions」에서는 작업 폴더 안의 쓰기에 승인 창이 뜨지 않고 Codex가 바로 쓴다. 그래서 쓰기를 맡기는 요청에는 그 랩의 구현 파일 경로(코딩랩 K-7)를 명시한다.
   - 응답이 끝났는지는 화면이 아니라 `D:/HYD-Practice/_codex_luna/sessions/<날짜>/rollout-*.jsonl`의 `task_complete`로 판정한다(`last_agent_message`에 끝난 답이 있다).
   - 끝난 응답, 바뀐 파일, 실행 출력을 읽고 「결과 확인」 큐를 쓴 뒤 그 음성을 만든다.
   - 결과 확인 구간에서는 Codex를 다시 부르지 않는다. 이미 있는 응답을 굴려 보며 결과 파일과 원자료를 연다.
   - ZIP 받기와 풀기는 영상 V-13대로 찍지 않고, 3의 폴더가 열린 화면에서 시작한다. 영상에는 가이드 문서를 띄우지 않는다. 가이드는 영상을 보고도 더 필요한 학생이 따로 여는 자료다.
10. 가이드 사진(영상 밖) — VS Code 안의 화면은 영상과 같은 ego의 웹 VS Code에서 screencast 프레임으로 찍는다. 웹판 메뉴는 영어이므로, 가이드 문장은 「왼쪽 탐색기(Explorer)」처럼 한글과 영어를 함께 적는다. ZIP 받기 · 압축 풀기 · 폴더 열기 · 신뢰 창 네 장면은 ego로 찍을 수 없으므로 가이드 P-8대로 실제 PC 화면에서 따로 찍는다.

## 함정

- 네이티브 VS Code에서는 computer use가 `click` 등급뿐이라 입력할 수 없다. CDP로 입력하는 것은 같은 제한을 우회하는 일이라 쓰지 않는다. 그래서 serve-web과 ego로 찍는다.
- Git Bash에서 서버를 띄우면 Codex가 `CODEX_HOME ... does not exist`로 실패한다. PowerShell에서 띄운다.
- 토큰 파일을 상대 경로로 주면 서버가 읽지 못한다. 절대 경로로 준다.
- 확장 폴더를 복사해서는 확장이 등록되지 않는다. `--install-extension`으로 설치한다.
- Codex 탭이 `The extension could not start its user interface`로 끝나거나 대화가 막히면, 2의 화면 확장과 엔진 조합, 사용자 설정을 확인한다.
- 세션 파일을 직접 보관 폴더로 옮긴 뒤 패널이 비면 최신 `Codex.log`의 `stale rollout path`와 옮긴 파일을 대조한다. 직접 옮긴 시험 파일이 원래 경로에서 없어진 경우에만 그 파일을 원래 자리로 복원하고 F1 → `Developer: Reload Window`로 연다. 패널이 돌아오면 길 4의 보관 버튼을 쓴다. 재설치나 AI 요청으로 상태를 시험하지 않는다.
- 사용자 설정에 새 엔진 경로가 있어도 이미 떠 있던 구형 프로세스는 그대로일 수 있다. 로그인 후 모델이 `5.5`만 보이고 학생 프로필 `logs_2.sqlite`의 모델 목록 오류에 `unknown variant max`가 있으면, 현재 프로세스의 실행 경로를 확인한다. 같은 웹 VS Code를 새로고침한 뒤 `app-server-26.1021.22027/codex.exe`에서 실행되는지, 오른쪽 모델이 `6-Luna Medium`인지 확인한다. 모델 표시만으로 계정 연결을 판정하지 않고 4의 짧은 응답 확인까지 마친다.
- `D:/...`를 그대로 넣으면 `C:\work\...`가 열린다. `encodeURIComponent('/D:/...')`로 넣는다.
- 신뢰 단추를 선택자로 누르면 눌리지 않는다(가려진 같은 이름 단추, Ctrl+Enter, Machine 설정은 모두 효과가 없었다). 3대로 단추 중심을 좌표로 누른다. 신뢰 창이 떠 있는 동안은 캡처가 되지 않는다. 본문의 「Restricted Mode」 글자에 신뢰 판정이 속으므로 `.statusbar-item`만 본다.
- Codex 답에 「2~4행」처럼 범위가 둘 나오면, 두 `~` 사이가 마크다운 취소선으로 그려져 글자에 줄이 그어진다. 녹화에 쓸 답은 그 화면을 먼저 본다. 랩의 `AGENTS.md`가 범위를 다른 꼴로 쓰게 할지는 코딩 랩 담당이 정한다.
- 터미널 패널이 세 줄 높이면 새 출력이 옛 줄 위에 겹쳐 그려진다. 터미널 장면을 찍기 전에 패널 높이를 키우고 이전 출력을 지운 뒤, 그 화면을 프레임으로 먼저 본다. 화면 크기(metrics)를 다시 걸면 터미널 가운데에 「125 x 22」 같은 크기 표시가 잠깐 뜨므로, 터미널이 열린 구간의 첫 프레임에서 사라졌는지 본다.
- 탐색기 행의 이름 위에 커서를 오래 두면 전체 경로 툴팁이 떠서 아래 행을 가린다. 행을 짚을 때는 이름 왼쪽의 접기 화살표 쪽에 둔다.
- PowerShell 시작 시 `PSReadLine`을 불러오지 못했다는 경고가 뜨고, 해당 모듈을 불러온 출력에 `PSSecurityException`이 있으면 입력 보조 모듈이 스크립트 실행 정책에 막힌 것이다. 정책을 낮추지 않고 길 4의 명령 프롬프트로 준비한다. 경고를 지운 화면만으로 해결됐다고 판정하지 않고, 새 터미널에서 실습 명령이 실행되는지 확인한다.
- Codex 무료 계정(testmiken)이라 새 대화 화면 오른쪽 아래에 「Get Plus」 단추가 늘 보인다. 끌 수 없으므로 말로 짚지 않고 둔다.
- 1920×1080 metrics는 CSS 1280×720이라 패널이 답답하다. 2304×1296을 쓴다.
- 웹판 한국어 팩(1.131)이 1.143과 맞지 않아 글자가 엉뚱하게 바뀐다(「Welcome」이 「새 터미널(&&N)」로 바뀌었다). 웹판은 영어로 쓴다. F1에서 `Configure Display Language`를 찾아 `English`를 고른 뒤 새로고침한다. 메뉴 글자가 틀려도 명령의 영어 이름으로 찾을 수 있다. localStorage의 nls 키만 지우면 브라우저 언어에 따라 같은 팩을 다시 불러오므로 그것만으로 복구됐다고 판단하지 않는다.
- 한 공간을 리허설과 함께 쓰면 탭의 앞뒤가 바뀌어 캡처가 빈다. 녹화 공간을 따로 둔다.
- `run.sh dry`의 통과는 모듈이 `ctx.report`에 남긴 기록으로만 판정되므로, 기록을 남기지 않는 모듈은 예외 없이 끝나기만 해도 「DRY OK」가 된다(`dry.json`의 `cues` · `ops`가 0이다). dry 결과는 `cues`가 그 구간 큐 수와 같은지까지 본다.
- 폴더를 연 직후에는 Codex 웹뷰가 늦게 떠서 입력 초점을 가져간다. 그때 F1이나 명령 글자를 보내면 Codex 입력칸으로 간다. 그래서 되돌리기는 「Ask Codex anything」이 뜬 뒤에 첫 명령을 보내고, 글을 보내기 전마다 초점이 있는 자리를 확인한다.
- 여유 메모리가 3 GB 아래면 이 도구의 `run.sh`는 경고만 하고(Notion `run.sh`는 멈춘다), 녹화가 괜찮은지는 `measure.py`의 프레임 간격으로 판정한다.
- 메뉴 클릭이 대사 끝까지 밀린다. `{at:'구절'}`로 클릭 시점을 대사 속 구절에 맞춘다. 두 번째 클릭이 앞 문장 끝에 함께 일어나면 큐를 나눈다. 포털의 「다시 계산」 클릭이 빗나가면 「화면 안」을 본문의 실제 높이 비율로 판단하고(`segs/p31-common.mjs`의 `p.show`), 화면을 굴릴 때 화살표를 옮기지 않는다.
