# 실습 환경을 시작하고 HYD 포털 둘러보기

내 컴퓨터에 도구를 설치하고 시스템을 시작한 뒤, 포털의 각 화면에서 무엇을 하는지 둘러봅니다.

| 항목 | 이번 실습에서 할 일 |
|---|---|
| 순서 | 도구 여섯 개 설치 → VS Code에서 프로젝트 받기 → Codex 연결 → 시스템 시작 → 포털 둘러보기 |
| 준비물 | 프로젝트 README, 본인의 ChatGPT 계정 |
| 끝나면 | 브라우저에 HYD 포털이 열리고, 메뉴 일곱 갈래에서 할 일을 찾을 수 있습니다. |

## README에서 시스템과 준비할 도구 확인하기

[프로젝트 README](https://github.com/uengine-oss/hyd-iot-edu#readme)를 엽니다. README는 프로젝트 소개와 실행 방법을 담은 첫 안내문입니다. **실행 환경** 표에서 여섯 도구의 설치 기준과 공식 설치 링크를 찾으세요.

이미 설치한 도구는 버전이 기준 이상이면 그대로 쓰고, 없거나 낮은 것만 설치합니다. Mac은 같은 README의 macOS 안내를 따릅니다.

| 도구 | 어디에 쓰나 |
|---|---|
| Python | 프로젝트의 준비 코드와 직접 만들 프로그램을 실행합니다. |
| Node.js | 업무 데이터베이스를 준비하는 도구 등을 실행합니다. |
| Git | 프로젝트를 내 컴퓨터로 받고 이후 새 판을 받습니다. Windows에서는 Git Bash도 함께 사용합니다. |
| VS Code | 파일을 열고, AI와 대화하고, 터미널에서 명령을 실행합니다. |
| WSL | Windows에서 Docker가 Linux 프로그램을 실행할 기반을 제공합니다. |
| Docker Desktop | 여러 서비스를 준비된 구성대로 함께 실행합니다. |

## WSL 준비하기

PowerShell에서 실행합니다.

```powershell
wsl --version
```

아무 키나 누르라는 안내가 나오면 60초 안에 Enter를 누르고 설치가 끝날 때까지 기다리세요.

<!-- PHOTO:wsl-enter -->

WSL이 없다는 오류만 나오면 관리자 PowerShell에서 실행합니다.

```powershell
wsl --install --no-distribution
```

버전이 README 기준보다 낮으면 실행합니다.

```powershell
wsl --update
```

<!-- PHOTO:wsl-version -->

재부팅을 요청하면 재부팅한 뒤 `wsl --version`을 다시 실행해 README 기준 이상인지 봅니다. Ubuntu는 설치하지 않습니다. Docker가 자기 Linux 환경을 쓰기 때문입니다.

<!-- PHOTO:project-open-folder -->

학교 인터넷에서 `schannel: server closed abruptly`로 끊기면 아래 명령을 한 번 실행하고 `git clone` 명령을 다시 실행하세요. 그래도 끊기면 휴대폰 핫스팟으로 받습니다.


## 명령 한 번으로 시스템 시작하기

Docker Desktop을 엽니다. **Docker Subscription Service Agreement**가 나오면 읽어 보고 **Accept**를 누르세요.

<!-- PHOTO:docker-terms -->

**Welcome to Docker**에서 오른쪽 위 **Skip**을 누릅니다.

<!-- PHOTO:docker-skip -->

왼쪽 아래에 **Engine running**이 나올 때까지 기다립니다. **Settings → General**에서 `Choose Virtual Machine Manager (VMM)`가 **WSL 2**인지 보세요.

<!-- PHOTO:docker-wsl -->

VS Code의 Git Bash에서 프로젝트 폴더로 들어갑니다.

```bash
cd hyd-iot-edu
```

입력 줄 위치가 `hyd-iot-edu`로 바뀌면 시작 명령을 실행하세요. `setup` 폴더의 `시작.bat`을 더블클릭해도 같습니다.

```bash
bash scripts/start_all.sh
```

<!-- PHOTO:system-start -->

처음에는 이미지를 받느라 오래 걸립니다. **Pulling**의 받은 양이 변하거나 다음 단계 번호가 나오면 그대로 기다리세요. 3/8 단계의 빨간 `WARN: config section [inbucket] is deprecated` 줄은 멈춘 것이 아닙니다.

<!-- PHOTO:system-progress -->

**완료. 포털** 줄의 주소를 **Ctrl**을 누른 채 클릭하세요.

<!-- PHOTO:system-ready -->

브라우저에 제목 **홈**과 위쪽 네 칸이 보이면 포털이 열린 것입니다. 앞으로 설비 상황을 보고 승인하는 일은 이 화면에서 합니다.

<!-- PHOTO:portal-arrival -->

터미널에 **포털은 열 수 있습니다** 줄이 나오면 AI 단계만 실패한 것입니다. 그 위 **실패** 줄의 까닭을 고치고 안내된 명령을 다시 실행하세요.

## 홈에서 전체 연결 보기

위쪽 네 칸은 설비 수, 열린 사건, 지식 항목, 시간 배율입니다. 시간 배율 20배는 설비가 실제보다 스무 배 빠르게 돈다는 뜻입니다. 숫자는 사진과 달라도 됩니다.

맨 위 막대의 **진행 중 사건**과 **서비스** 수를 봅니다. 서비스가 다 켜져 있어야(사진에서는 13/13) 포털이 제대로 돕니다. 시스템을 켠 뒤에는 이 숫자부터 보세요.

**설비 · 데이터 · AI 연결** 그림은 왼쪽 현장 설비에서 생긴 값이 가운데 데이터 길을 지나 오른쪽 AI에게 가고, 사람이 승인한 조치가 위쪽 화살표를 따라 설비로 돌아가는 흐름입니다. 왼쪽 메뉴도 이 흐름의 차례로 둘러봅니다.

## 설비 메뉴 둘러보기 — 값이 생기는 곳

**설비 → 결함 시뮬레이션**을 엽니다. 카드 세 장이 공장의 유압 설비 세 대이고, 컴퓨터 안에서 도는 가상 설비입니다. 큰 숫자는 기름 온도인 유온이고, 아래 **보호 정지 기준**을 넘으면 설비가 스스로 멈춥니다. 주황 표시는 정기 점검 · 재고 보충 같은 업무 알림이고 고장 표시가 아닙니다.

<!-- PHOTO:portal-equipment -->

카드 아래쪽의 **쿨러 열화 주입** 같은 버튼은 누르는 순간 그 일이 시작됩니다. 오늘은 보기만 하고 아무것도 누르지 마세요.

**실시간 모니터링**은 같은 값을 시간에 따라 그래프로 보는 곳이고, **오일 분석 입력**은 기름 검사 결과를 사람이 넣는 곳, **이상 확인 · 조치**는 설비 상태와 사건이 처리되는 과정을 보는 곳입니다.

## 지식 메뉴 둘러보기 — AI가 아는 것

**작업 → 내 작업함**은 회사 결재함과 같습니다. 맨 위 **나**에서 고른 사람 앞으로 온 승인할 일과 알림이 모입니다. 고른 사람은 브라우저가 기억해 승인 기록에 그 이름과 역할로 남으니, **지금은 고르지 말고 비워 두세요**. 실제로 승인할 때 고릅니다.

**처리 건**은 일 하나가 생겼을 때 처음부터 끝까지를 한 줄로 이어 기록하는 곳입니다. 지금은 비어 있어도 됩니다.

<!-- PHOTO:portal-instances -->

## 성과 · 시스템 메뉴 둘러보기

**성과 → 성과 지표**는 승인해서 실행한 조치가 회사에 좋았는지 재는 숫자입니다. AI가 조치를 고를 때도 이 값들을 따집니다. **목표 없음 · 기록 없음 · 계산 불가**는 아직 자료나 목표가 없다는 뜻입니다.

<!-- PHOTO:portal-performance -->

**시스템 → 시스템 구성**은 켜 둔 서비스들이 모여 있는 곳이고, **관리**는 업무 흐름을 올리고 배포하는 화면이라 오늘은 열지 않습니다.

<!-- PHOTO:portal-system -->

메뉴를 다 둘러봤으면 끝입니다. 화면 아래 **다음**을 누르면 메뉴 차례대로 하나씩 넘어가니, 혼자 다시 둘러볼 때 쓰세요. 시스템은 켜 둔 채 다음으로 갑니다. 다음에 켤 때는 Docker Desktop을 먼저 열고, 받은 폴더에서 `bash scripts/start_all.sh`만 다시 실행하면 됩니다. 끄거나 새 판을 받는 법은 README의 **실행 파일**에 있습니다.
