# 실습 환경을 설치하고 시작하기

수업 내내 쓸 도구를 내 컴퓨터에 설치하고, 명령 한 번으로 수업 시스템을 켭니다.

| 항목 | 이번 실습에서 할 일 |
|---|---|
| 순서 | 도구 여섯 개 설치 → VS Code에서 프로젝트 받기 → Codex 연결 → 시스템 시작 |
| 준비물 | 프로젝트 README, 본인의 ChatGPT 계정 |
| 끝나면 | 터미널에 완료 줄과 주소가 나오고, 그 주소로 브라우저에 수업 시스템이 열립니다. |

## README에서 시스템과 준비할 도구 확인하기

[프로젝트 README](https://github.com/uengine-oss/hyd-iot-edu#readme)를 엽니다. 이 사이트가 GitHub이고, 이 페이지가 수업 시스템의 저장소입니다. 저장소는 프로젝트의 파일과 그 파일이 바뀐 기록을 한데 모아 둔 곳입니다. 아래로 내리면 나오는 README는 「나를 먼저 읽어 주세요」라는 뜻의 안내문으로, 무엇으로 되어 있고 어떻게 설치해서 켜는지가 적혀 있습니다. **실행 환경** 표에서 여섯 도구의 설치 기준과 공식 설치 링크를 찾으세요.

이미 설치한 도구는 버전이 기준 이상이면 그대로 쓰고, 없거나 낮은 것만 설치합니다. Mac은 같은 README의 macOS 안내를 따릅니다.

| 도구 | 어디에 쓰나 |
|---|---|
| 도구 | 무엇이고, 여기서 어디에 쓰나 |
|---|---|
| Python | 컴퓨터에게 일을 시키는 프로그래밍 언어입니다. 시스템을 켤 때와 나중에 코드를 만들 때 씁니다. |
| Node.js | 자바스크립트 프로그램을 웹 브라우저 밖에서도 돌려 주는 도구입니다. 시스템이 켜질 때 씁니다. |
| Git | 파일이 바뀐 기록을 남기는 도구입니다. GitHub에 있는 저장소를 내 컴퓨터로 받을 때 씁니다. 함께 설치되는 Git Bash로 README의 명령을 칩니다. |
| VS Code | 코드를 쓰고 고치는 프로그램(코드 편집기)입니다. 안에 터미널도 있어 명령도 여기서 칩니다. |
| WSL | Windows에서 리눅스를 돌릴 수 있게 해 주는 도구입니다. Docker가 리눅스 위에서 돌아가서 먼저 있어야 합니다. |
| Docker Desktop | 프로그램을 이미지와 컨테이너로 돌리는 도구입니다. 수업 시스템의 프로그램 여러 개를 한 번에 켭니다. |

## Python 설치하고 실행 확인하기

README의 Python 링크에서 Windows 설치 파일을 받아 엽니다. **Add python.exe to PATH**를 선택하고 **Install Now**를 누르세요. PATH는 컴퓨터가 프로그램을 찾을 때 보는 폴더 목록입니다. 여기에 Python 폴더를 넣어 두면 터미널에서 `python`이라고만 쳐도 찾아 줍니다.

<!-- PHOTO:python-install -->

설치가 끝나면 설치 창을 닫고, **시작**에서 PowerShell을 검색해 **Windows PowerShell**을 엽니다. 글자로 명령을 치는 창을 터미널이라고 하고, PowerShell은 Windows에 처음부터 들어 있는 터미널입니다. 설치 전에 열어 둔 창은 바뀐 PATH를 모르니 꼭 새로 여세요.

<!-- PHOTO:node-shell -->

열린 창에서 아래 명령을 실행합니다. 명령은 손으로 치면 틀리기 쉬우니 복사해 붙여넣으세요.

```powershell
python --version
```

<!-- PHOTO:python-version -->

README 기준 이상의 버전이 나오면 됩니다. 명령을 찾지 못하면 PATH를 선택했는지 보고 PowerShell을 새로 여세요.

## WSL 준비하기

WSL은 Windows에서 리눅스를 돌릴 수 있게 해 주는 도구입니다. 마지막에 설치할 Docker가 리눅스 위에서 돌아가기 때문에 먼저 준비합니다. 설치만 해 두면 되고, 직접 열어서 쓸 일은 없습니다. Mac은 이 단계를 건너뜁니다.

README의 WSL 설치 링크로 열리는 Microsoft 안내 페이지의 명령은 Ubuntu까지 함께 설치하므로 쓰지 않습니다. 시작 메뉴에서 PowerShell을 찾아 오른쪽 버튼 → **관리자 권한으로 실행**으로 열고, 허락을 묻는 창에서 **예**를 누른 뒤 실행합니다.

```powershell
wsl --version
```

아무 키나 누르라는 안내가 나오면 60초 안에 Enter를 누르고 설치가 끝날 때까지 기다리세요.

<!-- PHOTO:wsl-enter -->

WSL이 없다는 오류만 나오면 관리자 PowerShell에서 실행합니다.

```powershell
wsl --install --no-distribution
```

버전이 README 기준보다 낮으면 실행합니다.

```powershell
wsl --update
```

<!-- PHOTO:wsl-version -->

재부팅을 요청하면 재부팅한 뒤 `wsl --version`을 다시 실행해 README 기준 이상인지 봅니다. Ubuntu는 설치하지 않습니다. Docker가 자기 Linux 환경을 쓰기 때문입니다.

## Docker Desktop 설치하고 저장소 주소 복사하기

Docker는 프로그램을 이미지와 컨테이너로 돌리는 도구입니다. 이미지는 프로그램과 그 프로그램이 돌아가는 데 필요한 것을 통째로 싸 둔 묶음이고, 컨테이너는 그 이미지를 꺼내 실제로 돌리고 있는 것입니다. 이미지에 필요한 것이 다 들어 있어서 어느 컴퓨터에서든 똑같이 돌아갑니다.

README의 Docker Desktop 링크로 열린 페이지에서 맨 위 **Docker Desktop for Windows** 버튼으로 설치 파일을 받아 엽니다(그 아래 Microsoft Store 버튼이 아닙니다). 설정 창에서 **WSL 2** 선택을 그대로 두고 **OK**를 누르세요.

<!-- PHOTO:docker-install -->

**Installation succeeded**가 나오면 **Close**를 누릅니다.

<!-- PHOTO:docker-install-complete -->

프로젝트 GitHub 페이지에서 **Code → HTTPS**의 주소 오른쪽 복사 버튼을 누르면 저장소 주소가 복사됩니다. 뒤에서 쓰는 README의 `git clone` 명령에는 이 주소가 이미 들어 있습니다.

## 작업 폴더에서 프로젝트 받기

VS Code는 폴더 하나를 열어 두고 그 안에서 일합니다. 이 폴더를 작업 공간이라고 합니다. **파일 → 폴더 열기**를 누릅니다. 시작 화면이나 왼쪽 탐색기의 **폴더 열기**를 눌러도 같습니다.

<!-- PHOTO:project-open-folder -->

내 파일을 둘 위치에 작업 폴더를 만들고 **폴더 선택**을 누르세요. 사진은 C 드라이브의 study 폴더입니다.

<!-- PHOTO:project-workfolder -->

폴더를 신뢰할지 묻는 창이 나오면 **Yes, I trust the authors**를 누릅니다. 창이 안 나오면 다음으로 갑니다.

<!-- PHOTO:project-trust-dialog -->

왼쪽 아래에 **Restricted Mode**가 보이면 제한 모드라 AI가 동작하지 않습니다. **Restricted Mode**를 누르세요.

<!-- PHOTO:project-trust-restricted -->

**Workspace Trust** 화면에서 **Trust**를 누르면 풀립니다.

<!-- PHOTO:project-trust-manage -->

**터미널 → 새 터미널**을 누릅니다. 메뉴가 접혀 있으면 위쪽 **…** 안에 있습니다.

<!-- PHOTO:project-new-terminal -->

터미널 위쪽 **새 터미널 옆 화살표 → Git Bash**를 고릅니다.

<!-- PHOTO:project-terminal -->

저장소를 내 컴퓨터로 받아 오는 것을 clone이라고 합니다. Git Bash에 아래 명령을 넣고 Enter를 누르세요. `--depth 1`은 지난 기록은 빼고 지금 파일만 받아서 금방 끝나게 합니다.

```bash

```

<!-- PHOTO:project-clone -->

학교 인터넷에서 `schannel: server closed abruptly`로 끊기면 아래 명령을 한 번 실행하고 `git clone` 명령을 다시 실행하세요. 그래도 끊기면 휴대폰 핫스팟으로 받습니다.

```bash
git config --global http.sslBackend openssl
```

## 명령 한 번으로 시스템 시작하기

수업 시스템의 프로그램들은 Docker 이미지로 준비돼 있어서, Docker가 켜져 있어야 컨테이너를 띄울 수 있습니다. 그래서 시작 명령보다 Docker Desktop을 먼저 엽니다. 처음 열 때는 창이 뜨는 데 시간이 좀 걸립니다. **Docker Subscription Service Agreement**가 나오면 읽어 보고 **Accept**를 누르세요.

<!-- PHOTO:docker-terms -->

**Welcome to Docker**에서 오른쪽 위 **Skip**을 누릅니다.

<!-- PHOTO:docker-skip -->

왼쪽 아래에 **Engine running**이 나오면 Docker가 다 켜진 것입니다. **Settings → General**에서 `Choose Virtual Machine Manager (VMM)`가 **WSL 2**이면 Docker가 앞에서 설치한 WSL 위에서 돌고 있는 것입니다.

<!-- PHOTO:docker-wsl -->

VS Code의 Git Bash에서 프로젝트 폴더로 들어갑니다. `cd`는 그 폴더 안으로 들어가는 명령입니다.

```bash
cd hyd-iot-edu
```

입력 줄 위치가 `hyd-iot-edu`로 바뀌면 시작 명령을 실행하세요. `scripts` 폴더에 있는 시스템을 켜는 파일 `start_all.sh`를 실행하라는 명령입니다. `setup` 폴더의 `시작.bat`을 더블클릭해도 같습니다.

```bash
bash scripts/start_all.sh
```

<!-- PHOTO:system-start -->

올라가는 글자들은 필요한 이미지를 내려받고 그 이미지로 컨테이너를 띄우는 과정입니다. 수업 시스템은 일을 나눠 맡은 프로그램(서비스) 여러 개로 되어 있어서 컨테이너도 여러 개 뜹니다. 줄 앞의 1/8, 2/8 같은 숫자가 지금 몇 번째 단계인지 알려 줍니다. 처음에는 4/8 단계에서 이미지를 받느라 10분 넘게 걸릴 수 있습니다. 같은 명령을 다시 치지 말고, **Pulling**의 받은 양이 변하거나 다음 단계 번호가 나오면 그대로 기다리세요. 3/8 단계의 빨간 `WARN: config section [inbucket] is deprecated` 줄은 멈춘 것이 아닙니다.

<!-- PHOTO:system-progress -->

**완료. 포털** 줄의 주소를 **Ctrl**을 누른 채 클릭하세요.

<!-- PHOTO:system-ready -->

브라우저에 수업 시스템이 열리면 이번 실습은 끝입니다.

<!-- PHOTO:portal-arrival -->

터미널에 **포털은 열 수 있습니다** 줄이 나오면 AI 단계만 실패한 것입니다. 그 위 **실패** 줄의 까닭을 고치고 안내된 명령을 다시 실행하세요.

시스템은 켜 둔 채 다음으로 갑니다. 다음에 켤 때는 Docker Desktop을 먼저 열고, 받은 폴더에서 `bash scripts/start_all.sh`만 다시 실행하면 됩니다. 이미지는 한 번 받아 두면 다시 받지 않아서 보통 훨씬 빨리 켜집니다. 끄거나 새 판을 받는 법은 README의 **실행 파일**에 있습니다.
