# 실습 환경을 시작하고 HYD 포털 둘러보기

내 컴퓨터에 도구를 설치하고 시스템을 시작한 뒤, 포털의 각 화면에서 무엇을 하는지 둘러봅니다.

| 항목 | 이번 실습에서 할 일 |
|---|---|
| 순서 | 도구 여섯 개 설치 → VS Code에서 프로젝트 받기 → Codex 연결 → 시스템 시작 → 포털 둘러보기 |
| 준비물 | 프로젝트 README, 본인의 ChatGPT 계정 |
| 끝나면 | 브라우저에 HYD 포털이 열리고, 일곱 메뉴 묶음에서 할 일을 찾을 수 있습니다. |

## README에서 시스템과 준비할 도구 확인하기

[프로젝트 README](https://github.com/uengine-oss/hyd-iot-edu#readme)를 엽니다. README는 프로젝트 소개와 실행 방법을 담은 첫 안내문입니다. **실행 환경** 표에서 여섯 도구의 설치 기준과 공식 설치 링크를 찾으세요.

이미 설치한 도구는 버전이 기준 이상이면 그대로 쓰고, 없거나 낮은 것만 설치합니다. Mac은 같은 README의 macOS 안내를 따릅니다.

| 도구 | 어디에 쓰나 |
|---|---|
| Python | 프로젝트의 준비 코드와 직접 만들 프로그램을 실행합니다. |
| Node.js | 업무 데이터베이스를 준비하는 도구 등을 실행합니다. |
| Git | 프로젝트를 내 컴퓨터로 받고 이후 새 판을 받습니다. Windows에서는 Git Bash도 함께 사용합니다. |
| VS Code | 파일을 열고, AI와 대화하고, 터미널에서 명령을 실행합니다. |
| WSL | Windows에서 Docker가 Linux 프로그램을 실행할 기반을 제공합니다. |
| Docker Desktop | 여러 서비스를 준비된 구성대로 함께 실행합니다. |

## Python 설치하고 실행 확인하기

README의 Python 링크에서 Windows 설치 파일을 받아 엽니다. **Add python.exe to PATH**를 선택하고 **Install Now**를 누르세요. PATH를 켜 두면 터미널에서 이름만으로 프로그램을 부를 수 있습니다.

<!-- PHOTO:python-install -->

설치가 끝나면 새 **PowerShell** 창을 열고 아래 명령을 실행합니다. 명령은 손으로 치면 틀리기 쉬우니 복사해 붙여넣으세요.

```powershell
python --version
```

<!-- PHOTO:python-version -->

README 기준 이상의 버전이 나오면 됩니다. 명령을 찾지 못하면 PATH를 선택했는지 보고 PowerShell을 새로 여세요.

## WSL 준비하기

PowerShell에서 실행합니다.

```powershell
wsl --version
```

아무 키나 누르라는 안내가 나오면 60초 안에 Enter를 누르고 설치가 끝날 때까지 기다리세요.

<!-- PHOTO:wsl-enter -->

WSL이 없다는 오류만 나오면 관리자 PowerShell에서 실행합니다.

```powershell
wsl --install --no-distribution
```

버전이 README 기준보다 낮으면 실행합니다.

```powershell
wsl --update
```

<!-- PHOTO:wsl-version -->

재부팅을 요청하면 재부팅한 뒤 `wsl --version`을 다시 실행해 README 기준 이상인지 봅니다. Ubuntu는 설치하지 않습니다. Docker가 자기 Linux 환경을 쓰기 때문입니다.

## 작업 폴더에서 프로젝트 받기

**파일 → 폴더 열기**를 누릅니다.

<!-- PHOTO:project-open-folder -->

내 파일을 둘 위치에 작업 폴더를 만들고 **폴더 선택**을 누르세요. 사진은 C 드라이브의 study 폴더입니다.

<!-- PHOTO:project-workfolder -->

폴더를 신뢰할지 묻는 창이 나오면 **Yes, I trust the authors**를 누릅니다. 창이 안 나오면 다음으로 갑니다.

<!-- PHOTO:project-trust-dialog -->

<!-- PHOTO:project-trust-restricted -->

**Workspace Trust** 화면에서 **Trust**를 누르면 풀립니다.

<!-- PHOTO:project-trust-manage -->

**터미널 → 새 터미널**을 누릅니다. 메뉴가 접혀 있으면 위쪽 **…** 안에 있습니다.

<!-- PHOTO:project-new-terminal -->

<!-- PHOTO:project-terminal -->

Git Bash에 아래 명령을 넣고 Enter를 누르세요.

```bash
git clone --depth 1 https://github.com/uengine-oss/hyd-iot-edu.git
```

<!-- PHOTO:project-clone -->

**Receiving objects** 비율이 올라가면 받는 중입니다. 사진은 `--depth 1` 없이 받아 더 오래 걸렸습니다. 기다리는 동안 Codex를 연결합니다.

학교 인터넷에서 `schannel: server closed abruptly`로 끊기면 아래 명령을 한 번 실행하고 `git clone` 명령을 다시 실행하세요. 그래도 끊기면 휴대폰 핫스팟으로 받습니다.

```bash
git config --global http.sslBackend openssl
```

## 명령 한 번으로 시스템 시작하기

Docker Desktop을 엽니다. **Docker Subscription Service Agreement**가 나오면 읽어 보고 **Accept**를 누르세요.

<!-- PHOTO:docker-terms -->

**Welcome to Docker**에서 오른쪽 위 **Skip**을 누릅니다.

<!-- PHOTO:docker-skip -->

왼쪽 아래에 **Engine running**이 나올 때까지 기다립니다. **Settings → General**에서 `Choose Virtual Machine Manager (VMM)`가 **WSL 2**인지 보세요.

<!-- PHOTO:docker-wsl -->

VS Code의 Git Bash에서 프로젝트 폴더로 들어갑니다.

```bash
cd hyd-iot-edu
```

입력 줄 위치가 `hyd-iot-edu`로 바뀌면 시작 명령을 실행하세요. `setup` 폴더의 `시작.bat`을 더블클릭해도 같습니다.

```bash
bash scripts/start_all.sh
```

<!-- PHOTO:system-start -->

처음에는 이미지를 받느라 오래 걸립니다. **Pulling**의 받은 양이 변하거나 다음 단계 번호가 나오면 그대로 기다리세요. 3/8 단계의 빨간 `WARN: config section [inbucket] is deprecated` 줄은 멈춘 것이 아닙니다.

<!-- PHOTO:system-progress -->

**완료. 포털** 줄의 주소를 **Ctrl**을 누른 채 클릭하세요.

<!-- PHOTO:system-ready -->

브라우저에 제목 **홈**과 왼쪽 **작업**, **설비** 메뉴가 보이면 포털이 열린 것입니다. 앞으로 실습은 대부분 이 화면에서 합니다.

<!-- PHOTO:portal-arrival -->

터미널에 **포털은 열 수 있습니다** 줄이 나오면 AI 단계만 실패한 것입니다. 그 위 **실패** 줄의 까닭을 고치고 안내된 명령을 다시 실행하세요.

## 홈에서 전체 연결 확인하기

왼쪽 **시스템 → 홈**을 엽니다. 지금 다 이해하지 않아도 뒤에서 직접 써 보며 익힙니다.

위쪽 네 칸은 설비, 열린 사건, 지식 항목, 시간 배율입니다. 시간 배율 20배는 설비가 실제보다 스무 배 빠르게 돈다는 뜻입니다. 숫자는 사진과 달라도 됩니다.

**설비 · 데이터 · AI 연결** 그림은 왼쪽 현장 설비 → 가운데 데이터 길 → 오른쪽 지식 지도와 AI 에이전트 순으로 값이 흐르고, 승인된 조치는 위쪽 화살표로 설비에 돌아갑니다.

**작업 → 내 작업함**을 엽니다. 나에게 온 승인과 확인이 모이는 곳입니다. **나**에서 **최운전 · 운전원**을 고르세요. 오른쪽 위 이름이 바뀌고, 나중에 승인하면 이 사람이 승인한 것으로 남습니다.

## 판단 화면 둘러보기

**판단 → 조치 판단 규칙**에서 설비와 이상 상황을 고르고 **판단 실행**을 누르면 규칙대로 조치 후보가 나옵니다. **조건별 손익**은 조건에 따라 어떤 조치가 이득인지 비교하는 곳입니다. 쓰는 법은 뒤 회차에서 배웁니다.

<!-- PHOTO:portal-rules -->
<!-- PHOTO:portal-tradeoff -->

**승인과 실행**은 AI의 판단을 사람이 승인하고 실행 결과를 보는 곳입니다. 사람이 승인하기 전에는 설비에 손대지 않습니다. 아래 **기업 시스템 현황**에서 생산 오더의 납기를 볼 수 있습니다.

<!-- PHOTO:portal-flow -->

**흐름 가져오기**는 업무 흐름을 포털에 등록하는 곳입니다. 위치만 봐 두세요.
