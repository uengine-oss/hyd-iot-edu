# 환경세팅 촬영준비

1회차 실습 04 「실행 환경」 설치 구간(두 과정 공통). 설치 화면은 **사용자가 직접 찍은 원본**을 쓰고, 에이전트는 잇기 · 음성 · 합성만 한다(ego는 설치 창 · 관리자 승인 · Windows 터미널을 다루지 못한다). 이 PC에서만. 규칙은 [영상](../../../지침/영상.md), 공통은 [README](../README.md).

## 길

1. 원본 — `작업/촬영/환경세팅/환경세팅 설치.mp4`(이 PC에만 있음). 진행 순서: README → Python → Node.js → Git → VS Code → WSL → Docker → VS Code 한국어 · Codex 확장 → 작업 폴더 · clone → 로그인 → clone 완료 → Git Bash `bash scripts/start_all.sh` → 완료 주소 Ctrl+클릭 → 포털 홈.
2. 원고 — 실제 설치 화면에 맞춰 [실행환경_촬영큐.json](실행환경_촬영큐.json)을 고친다. 행동 설명이 시작되면 바로 조작해도 되고(말과 겹침), 익숙한 동작(「창을 닫고」)은 짧게, 중요한 옵션 · 개념만 그 순간에 까닭을 말한다.
   - VS Code = 파일을 열고 고치고 실행하는 작업 공간, Git = 프로젝트를 내려받고 이력을 관리하는 도구, GitHub Copilot · Codex = 요구를 전하고 코드 작성 · 수정 · 확인을 함께 하는 AI 코딩 도구로 말한다.
   - Docker는 필요성부터(서비스를 하나하나 설치 · 설정하는 부담을 줄이고 준비된 환경을 실행) 말하고 이미지 · 컨테이너 · 포트 · 데이터 보관은 화면에 나오는 만큼만. 「전부 Docker 안에 있다」고 단정하지 않는다.
   - Git 선택 화면은 기본값으로 갈 곳과 확인할 옵션을 가른다. Python · Node.js는 버전과 실행 경로를 확인한다. Git 이름 · 이메일 설정과 커밋 장면은 넣지 않는다. 점검.bat은 넣지 않는다.
   - Node 설치 직후 기존 터미널에서 명령이 실패하면 원인을 짚고 새 PowerShell에서 같은 명령으로 성공하는 데까지 원본을 그대로 쓴다.
3. 대본 — 저장소 루트에서 `python workspace/강의제작/제작도구/촬영/환경세팅/대본_만들기.py`(실행환경 큐 + [포털소개_큐.json](../포털/포털소개_큐.json) → 두 과정 `실습/01회차/대본/04_실습_실행환경.md`).
4. 음성 · 편집 — 바뀐 문장만 음성을 만들어 원본의 행동에 맞춰 놓는다. 원본 시간축에서 뺄 곳만 표시한다: 녹화에 검게 찍힌 관리자 승인 창(말과 가이드로 안내), 같은 로그만 오래 흐르는 가운데(`start_all`은 첫 실행이 오래 걸리는 까닭 · 명령 입력 · 실제 출력 · 완료 주소를 남김). 로그인 화면은 자르지 않고 이메일 @ 뒤 · 주소창 토큰만 그 시각 · 그 자리를 가린다.
5. 합본 — 설치 원본 뒤에 포털 소개(포털 촬영준비)를 잇는다. 파일 `workspace/강의제작/산출물/영상/통합반/통합반_01회차_04_실습_실행환경.mp4` 하나를 두 과정이 쓴다.
6. 조각 고침 — 새 이음매의 앞뒤 프레임 · 말 연결 · 음량 · 자막 시간만 다시 본다. 말만 고치면 그 문장 음성만. clone 화면을 README의 `--depth 1`에 맞추려면 12:12~14:05를 사용자가 다시 찍는다. 포털 소개는 포털 촬영준비 「조각 고침」.

## 함정

- 설치 뒤 새 터미널에서 `python` · `docker`를 못 찾음 → 설치기의 PATH 항목(Python `Add python.exe to PATH`)을 확인, `where python`.
- 기본 `wsl --install`은 Ubuntu 사용자 이름 · 암호 화면을 연다 → 이 수업은 `wsl --install --no-distribution`(기존 설치는 `wsl --update`). 이 장면은 찍은 적 없다. WSL 목록의 `docker-desktop`은 정상.
- `docker compose up`만으로는 Docker · 설정 · 포트 · Supabase · MCP · 응답 확인이 빠진다 → `bash scripts/start_all.sh`.
- 설치 완료와 엔진 준비는 다르다 → Docker Desktop에서 Engine running을 본 뒤 진행.
- 옛 합본이 로그인 7.6초를 자르고 화면을 단색으로 덮었다 → 조작이 보이는 구간은 자르지 않고 글자만 가린다. 문장별 장면만으로는 놓치니 프레임을 더 뽑아 본다.
- 녹화가 끊김(여유 메모리 약 0.5 GiB) → 촬영 직전 사용자가 앱을 정리한다(다른 세션을 임의로 끄지 않는다).
