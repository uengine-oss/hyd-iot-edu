## 1. 바로 가는 길

### 1. 말하는 법 (대본에서 설명하는 법 — 1회차 환경 준비, 두 과정 공통)

- VS Code는 파일을 열고 고치고 실행하는 작업 공간, Git은 프로젝트를 내려받고 변경 이력을 관리하는 도구로 쉽게 말한다. IDE처럼 처음 보는 용어를 설명 없이 쓰지 않는다. GitHub Copilot · Codex는 요구를 전달하고 코드 작성 · 수정 · 결과 확인을 함께 하는 AI 코딩 도구로 소개한다(「확장 프로그램」 같은 분류 중심 소개 X).
- Docker는 다른 도구보다 필요성을 충분히 설명한다: 필요한 서비스를 하나하나 설치 · 설정하는 부담을 줄이고 준비된 환경을 실행한다는 이유에서 출발한다. 이미지 · 컨테이너 · 접속 포트 · 데이터 보관은 실제 화면과 설정에서 필요한 만큼만 잇고, 개념을 먼저 길게 강의하거나 옵션을 다 풀지 않는다. 실제 설치 목록을 확인해 「전부 Docker 안에 있다」고 단정하지 않고, 근거 없는 「나머지 실행 도구」 항목을 만들지 않는다.
- 공식 다운로드 위치를 보여 주고 설치 완료 상태에서 진행한다. 설치 대기 · 계정 로그인은 늘리지 않는다. 설치 중에는 중요한 옵션의 이유만 짧게 짚는다.
- README에는 수업·강사·촬영 진행을 쓰지 않는다. 역할 설명·화면 전환·말의 순서는 이 대본과 큐표에서만 다룬다.

### 2. 설치 구간의 말과 행동 — 최신 사용자 확정

설치 구간에서는 해당 행동의 설명이 먼저 시작됐다면 바로 조작해도 된다. 문장 전체가 끝날 때까지 기다리지 않으며 말은 다음 동작 안내까지 자연스럽게 이어질 수 있다. “창을 닫고”처럼 익숙한 동작은 짧게 말하며 진행한다. 중요한 옵션·개념만 필요한 순간에 이유를 설명하고 실제 원본 영상에 맞춰 유연하게 음성을 편집한다. 이 예외의 범위는 V-181이다. 프로그램별 분할 촬영과 다운로드·재부팅 대기 축약은 이번 사용자 허용 범위다.

설치·다운로드·재부팅·응답은 실제 완료 신호로 확인한다. Python·Node.js는 버전과 실행 경로를 확인하고, 다른 프로그램의 버전 명령 화면은 설치 영상에 의무적으로 넣지 않는다. 중요한 선택과 실제 완료는 보존한다. 인증 정보는 녹화하지 않는다.

### 4. 편집 · 음성 · 합성 (원본 수령 후)

원본 수령 후: 실제 설치 화면에 맞춰 원고 수정 → 음성 생성·길이 측정 → 행동 설명이 시작되면 조작되도록 편집(말과 겹쳐도 됨) → 실제 움직임·가독성·전체 음성 재생 확인. 완성 판정은 V-185다. 점검.bat은 영상에 넣지 않는다.

- 안치윤 음성은 중요한 선택의 이유를 짧게 연결하고, 해당 행동의 안내를 시작한 뒤 실제 행동과 자연스럽게 겹칠 수 있게 배치한다.
- **음성:** ElevenLabs만 쓴다. 모델 `eleven_v4`, 목소리 「안치윤」 `1PdAOcPlPTz12RwMyFVp`(편집기록.json의 `voice_id` · `model_id`와 같다). stability 0.5 · similarity 0.75는 공통 기본값이고 바꾸지 않는다 — 이 편집본을 만들 때의 값은 편집기록.json에 적혀 있지 않아 미확인이다. OpenAI 음성은 쓰지 않는다.
- 파트마다 원본의 쓴 구간(`cuts`)만 이어 붙이고 파트 끝 정지(`hold`)를 둔다. 자른 곳은 설치 · 다운로드 · 재부팅 대기뿐이다(V-181 · V-182). 커서 움직임과 정상 조작은 원래 속도로 보존한다. 하나의 세션처럼 이어도 분할 촬영본임을 숨기지 않는다(V-233).
- 인증 화면의 주소 표시줄 · 계정 영역은 가린 편집본을 쓰고, 가리기 전 원본 인증 화면을 다시 넣지 않는다.
- take · 원본은 매번 새 이름으로 보존하고, 실패 · 잘못된 상태 조각은 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.
- 결과: 1920×1080 · 30 fps 출력, 688.633초. 화면 마스터 `환경준비_화면마스터.mp4`와 무손실 음성 `환경준비_안치윤_음성.flac`(WAV에서 변환)은 합성 MP4와 시간축이 같다 — 이음매를 다시 만들 때 이 둘에서 시작한다.

**WSL 도입·조작 대본 — 실제 영상에 맞춰 적용**

“여기서는 우분투를 별도로 설치하지 않겠습니다. 프로젝트 명령은 윈도우의 깃 배시에서 실행하고, 도커가 필요한 리눅스 실행 환경은 직접 관리하기 때문입니다. 지금 준비할 더블유에스엘 투는 도커가 사용할 실행 기반입니다.”

“먼저 버전 확인 명령을 입력해 보겠습니다.” → `wsl --version`. 이번 PC에서는 이 호출 후 Ubuntu 없이 WSL 설치가 진행됐다고 사용자가 확인했다. 실제 영상이 이 흐름이면 설치 안내와 결과에 맞춰 설명한다. 다른 PC에서도 무조건 자동 설치된다고 말하지 않는다.

미설치 오류만 나오는 경우의 안내는 “이 환경에서는 설치 명령으로 기반만 준비하겠습니다.” → `wsl --install --no-distribution`. 기존 설치 업데이트는 `wsl --update`. 기본 `wsl --install`만 입력하거나 Ubuntu 사용자 이름·암호를 만드는 장면은 제외한다. Docker가 만드는 `docker-desktop`은 정상 구성이다.
