## 1. 바로 가는 길

### 1. 말하는 법 (대본에서 설명하는 법 — 1회차 환경 준비, 두 과정 공통)

- VS Code는 파일을 열고 고치고 실행하는 작업 공간, Git은 프로젝트를 내려받고 변경 이력을 관리하는 도구로 쉽게 말한다. IDE처럼 처음 보는 용어를 설명 없이 쓰지 않는다. GitHub Copilot · Codex는 요구를 전달하고 코드 작성 · 수정 · 결과 확인을 함께 하는 AI 코딩 도구로 소개한다(「확장 프로그램」 같은 분류 중심 소개 X).
- Docker는 다른 도구보다 필요성을 충분히 설명한다: 필요한 서비스를 하나하나 설치 · 설정하는 부담을 줄이고 준비된 환경을 실행한다는 이유에서 출발한다. 이미지 · 컨테이너 · 접속 포트 · 데이터 보관은 실제 화면과 설정에서 필요한 만큼만 잇고, 개념을 먼저 길게 강의하거나 옵션을 다 풀지 않는다. 실제 설치 목록을 확인해 「전부 Docker 안에 있다」고 단정하지 않고, 근거 없는 「나머지 실행 도구」 항목을 만들지 않는다.
- README의 해당 도구 링크에서 공식 다운로드, 설치 옵션, 설치 중 화면, 완료와 버전 확인까지 실제 순서대로 보여 준다. Git의 여러 선택 화면에서는 기본값으로 진행할 부분과 확인할 옵션을 구분해 설명한다.
- README에는 수업·강사·촬영 진행을 쓰지 않는다. 역할 설명·화면 전환·말의 순서는 대본과 큐에서만 다룬다. Git 이름 · 이메일 설정과 커밋 장면은 찍지 않는다.

### 2. 설치 구간의 말과 행동 — 최신 사용자 확정

설치 구간에서는 해당 행동의 설명이 먼저 시작됐다면 바로 조작해도 된다. 문장 전체가 끝날 때까지 기다리지 않으며 말은 다음 동작 안내까지 자연스럽게 이어질 수 있다. “창을 닫고”처럼 익숙한 동작은 짧게 말하며 진행한다. 중요한 옵션·개념만 필요한 순간에 이유를 설명하고 실제 원본 영상에 맞춰 유연하게 음성을 편집한다. 이 범위는 V-148이다(대기 생략은 V-181). Node 설치 직후 기존 터미널에서 명령이 실패하면 원인을 짚고, 시작 메뉴에서 새 PowerShell을 열어 같은 명령으로 성공하는 데까지 실제 원본을 이어 쓴다. 사소한 실수의 수습은 V요-24를 따른다.

설치·다운로드·재부팅·응답은 실제 완료 신호로 확인한다. Python·Node.js는 버전과 실행 경로를 확인하고, 다른 프로그램의 버전 명령 화면은 설치 영상에 의무적으로 넣지 않는다. 시작 명령이 완료되면 VS Code 통합 터미널의 주소에 커서를 놓고 Ctrl+클릭한 뒤 열린 브라우저에서 포털 홈 제목과 왼쪽 메뉴를 확인하는 흐름을 보인다. 전환을 검수할 때 클릭 전·실제 클릭·열린 홈의 근거를 구분한다. 인증 정보는 녹화하지 않는다.

### 3. 현재 촬영 순서

**현재 설치 원본의 진행 순서**는 README → Python → Node.js → Git → VS Code 설치 → WSL → Docker 설치 → VS Code 한국어와 Codex 확장 → 작업 폴더와 clone 시작 → 인증 화면 제외 → clone 완료 → Git Bash 시작 명령 → 완료 주소다. 원본의 8/8에서는 저장한 응답 재생 안내와 루프백 포트 8088을 확인했다. 원본에는 주소 위의 링크 안내까지 남아 있다. 2026-11-02 보충 촬영에서는 VS Code가 복원한 당시 Git Bash 세션의 8/8 완료 출력에서 주소를 Ctrl+클릭했다. 12.200초 조각에서 4.850초에 누르고 5.392초에 새 탭의 정상 배율 포털 홈을 확인했다. 이후 왼쪽 메뉴가 보이도록 스크롤했다. 보충 촬영에서는 시작 명령을 다시 실행하지 않았다.

**시작 구간:** 프로젝트 루트의 VS Code Git Bash 터미널에서 `bash scripts/start_all.sh`를 입력한다. 시작 BAT 없이 같은 스크립트를 실행하는 경로다. Docker·설정·포트·Supabase·이미지 다운로드/빌드·Compose·MCP·응답 확인을 포함한다. 준비 중 이미지·명령 설명은 실제 진행 단계에 맞춘다. Python 보조 코드는 프로젝트 코드다. 시작 경로·권한·포트·데이터 영향 검증 전에는 시스템을 실행하지 않는다.

```bash
cd /c/<작업 폴더>/<프로젝트 폴더>
bash scripts/start_all.sh
```

### 4. 편집 · 음성 · 합성

원본 수령 후: 실제 설치 화면에 맞춰 원고 수정 → 음성 생성·길이 측정 → 행동 설명이 시작되면 조작되도록 편집(말과 겹쳐도 됨) → 실제 움직임·가독성·전체 음성 재생 확인. 완성 판정은 V-185다. 점검.bat은 영상에 넣지 않는다.

- 안치윤 음성은 중요한 선택의 이유를 짧게 연결하고, 해당 행동의 안내를 시작한 뒤 실제 행동과 자연스럽게 겹칠 수 있게 배치한다.
- **음성:** ElevenLabs만 쓴다. 모델 `eleven_v4`, 목소리 「안치윤」 `1PdAOcPlPTz12RwMyFVp`, stability 0.5 · similarity 0.75(바꾸지 않는다). OpenAI 음성은 쓰지 않는다.
- 원본의 연속 시간축에서 V-181 · V-182에 해당하는 제외 구간만 표시한다. 특히 `start_all`은 첫 실행이 오래 걸리는 이유를 설명하고 명령 입력, 내려받기·기동 중의 실제 출력, 완료 주소를 남긴다. 같은 로그만 오래 흐르는 부분을 줄이더라도 조작을 정지 화면으로 대신하지 않는다. 하나의 세션처럼 이어도 분할 촬영본임을 숨기지 않는다(V-233).
- 인증 화면의 주소 표시줄 · 계정 영역은 가린 편집본을 쓰고, 가리기 전 원본 인증 화면을 다시 넣지 않는다.
- take · 원본은 매번 새 이름으로 보존하고, 실패 · 잘못된 상태 조각은 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.

## 4. 아직 안 뚫린 길

- **WSL 신규 설치 장면:** `wsl --install --no-distribution`을 실제로 찍은 적 없다(이번 PC는 `wsl --version` 뒤 설치 안내로 진행). 신규 설치를 촬영했다고 말하지 않는다.
- **ZIP · 시작 BAT 경로(2026-10-24 이전 기록, 그 뒤 미확인):** 현재 공개 ZIP과 로컬 미커밋 시작 코드가 달라 BAT 없는 실행은 준비 완료로 표시하지 않는다. 시작 BAT 차단도 해결된 것으로 보지 않는다. 영상은 git clone + `bash scripts/start_all.sh` 경로로 찍었다.
