# 환경세팅 촬영준비

1회차 실습 04 「실행 환경」(두 과정 공통)이다. 영상은 설치 → 시작 명령 → 완료 줄의 주소를 Ctrl을 누른 채 클릭하는 데서 끝나고, 포털을 처음 여는 것은 06 「전체 과정 관찰」이다. 설치 화면은 사용자가 직접 찍은 원본을 쓰고, 에이전트는 잇기, 음성, 합성만 한다. ego가 설치 창, 관리자 승인, Windows 터미널을 다루지 못하기 때문이다. 이 PC에서만 한다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md)에 있다.

## 길

1. 원본 — `작업/촬영/환경세팅/환경세팅 설치.mp4`(이 PC에만 있음). 진행 순서는 README → Python → Node.js → Git → VS Code → WSL → Docker → VS Code 한국어와 Codex 확장 → 작업 폴더와 clone → 로그인 → clone 완료 → Git Bash에서 `bash scripts/start_all.sh` → 완료 주소를 Ctrl+클릭이다.
2. 원고 — 실제 설치 화면에 맞춰 [실행환경_촬영큐.json](실행환경_촬영큐.json)을 고친다. 행동 설명이 시작되면 바로 조작해도 된다(말과 조작이 겹쳐도 된다). 익숙한 동작(「창을 닫고」)은 짧게 말하고, 중요한 옵션과 개념만 그 순간에 까닭을 말한다.
   - 도구 소개는 영상 V-15의 차례(원래 무엇 → 여기서의 쓰임)를 따른다. Node.js를 「데이터베이스 준비용」처럼 이 수업의 쓰임으로만 소개하지 않는다. 이 구간의 도구 뜻은 이렇다. VS Code는 코드를 쓰고 고치는 코드 편집기이고 안에 터미널이 있다. Git은 파일이 바뀐 기록을 남기는 도구이고, GitHub는 그 기록째 저장소를 인터넷에 올려 두는 곳이다(게임 세이브와 클라우드 세이브). Git이 있으면 GitHub의 저장소를 받아 올 수 있다. Git Bash는 Git과 함께 들어오는 터미널이고, README 명령이 그 꼴로 적혀 있어 README 명령을 칠 때 쓴다 — 「시스템을 켜는 건 Git Bash」처럼 그 일에만 쓰는 도구로 말하지 않는다. WSL은 Windows에서 리눅스를 돌리게 해 주는 도구이고, Docker가 리눅스 위에서 돌아서 필요하다(이 관계를 WSL을 소개하는 자리에서 말한다). Codex는 요구를 전하면 코드 작성, 수정, 확인을 함께 하는 AI 코딩 도구다. 화면에 보이는 GitHub Copilot 채팅 탭은 수업에서 쓰지 않으므로 설명하지 않는다. Codex를 쓰는 까닭은 구글 계정으로 ChatGPT에 무료로 가입하면 Codex에서 `gpt-6-luna`를 쓸 수 있기 때문이다.
   - Docker는 이미지(프로그램과 필요한 것을 통째로 싼 묶음)와 컨테이너(그 이미지를 꺼내 돌리고 있는 것)가 설명의 중심이다(게임 팩과 꽂아서 돌아가는 게임). 그다음 여기서는 여러 서비스를 하나하나 설치하지 않고 한 번에 띄운다고 잇고, 시작 명령 전에 Docker를 켜는 까닭(프로그램들이 이미지로 준비돼 있어 Docker가 켜져 있어야 컨테이너를 띄운다)을 그 자리에서 말한다. 켜는 동안은 「이미지를 받고 컨테이너를 띄우는 과정」과 단계 숫자 · 오래 걸리는 4단계 · 정상 표시만 말하고, 식당 비유 · 데이터베이스 · 엔진 풀이는 하지 않는다. 「전부 Docker 안에 있다」고 단정하지 않는다(시작 파일은 Python과 Node.js도 직접 쓴다).
   - Git 선택 화면에서는 기본값으로 둘 곳과 확인할 옵션을 나눠 말한다. Python과 Node.js는 버전과 실행 경로를 확인한다. Git 이름과 이메일 설정, 커밋 장면은 넣지 않는다. 점검.bat도 넣지 않는다.
   - Node 설치 직후 기존 터미널에서 명령이 실패하는 장면은 원본을 그대로 쓴다. 원인을 짚고, 새 PowerShell에서 같은 명령이 성공하는 데까지 보여 준다.
3. 대본 — 저장소 루트에서 `python workspace/강의제작/제작도구/촬영/환경세팅/대본_만들기.py`를 돌린다. 실행환경 큐와 [포털 둘러보기 큐](../포털/통합_01_04_포털둘러보기_큐.json)로 두 과정의 `실습/01회차/대본/04_실습_실행환경.md`를 만든다.
4. 음성과 편집 — 바뀐 문장만 음성을 만들어 원본의 행동에 맞춰 놓는다. 원본 시간축에서는 뺄 곳만 표시한다.
   - 녹화에 검게 찍힌 관리자 승인 창은 뺀다(말과 가이드로 안내한다).
   - 같은 로그만 오래 흐르는 가운데 부분은 뺀다. `start_all`에서는 첫 실행이 오래 걸리는 까닭, 명령 입력, 실제 출력, 완료 주소를 남긴다.
   - 로그인 화면은 자르지 않는다. 이메일의 @ 뒷부분과 주소창의 토큰만, 그것이 보이는 시각에 그 자리를 가린다.
5. 끝 — 영상은 C100(완료 줄의 주소를 Ctrl을 누른 채 클릭)에서 끝난다. 포털 둘러보기는 잇지 않는다(06이 맡는다). 영상 하나(`통합반_01회차_04_실습_실행환경.mp4`, Release `영상`의 `int-01-04-lab.mp4`)를 두 과정이 함께 쓴다.
6. 조각 고침 — 새 이음매의 앞뒤 프레임, 말의 이어짐, 음량, 말 시각 기록만 다시 본다. 말만 고치면 그 큐의 음성만 다시 사서 쉼넣기로 끼운다(자료 「지금 판의 편집」 ②). clone 화면의 명령에는 `--depth 1`이 없지만 다시 찍지 않는다. 결과는 같고(그냥 clone해도 main을 받는다), 그 장면에 README 명령 글상자를 띄우고 가이드의 복사 블록이 지금 명령을 준다. 포털 소개 부분은 포털 촬영준비의 「조각 고침」을 따른다.

## 함정

- 설치 뒤 새 터미널에서 `python`이나 `docker`를 찾지 못하면, 설치기의 PATH 항목(Python은 `Add python.exe to PATH`)을 확인하고 `where python`으로 본다.
- 기본 `wsl --install`은 Ubuntu 사용자 이름과 암호 화면을 연다. 이 수업은 `wsl --install --no-distribution`을 쓴다(이미 설치돼 있으면 `wsl --update`). 이 장면은 찍은 적이 없다. WSL 목록에 `docker-desktop`이 보이는 것은 정상이다.
- `docker compose up`만으로는 Docker, 설정, 포트, Supabase, MCP, 응답 확인이 빠진다. `bash scripts/start_all.sh`를 쓴다.
- 설치 완료와 엔진 준비는 다르다. Docker Desktop에서 Engine running을 본 뒤 진행한다.
- 옛 합본이 로그인 장면 7.6초를 자르고 화면을 단색으로 덮었다. 조작이 보이는 구간은 자르지 않고 글자만 가린다. 문장별 장면만 보면 놓치므로 프레임을 더 뽑아 본다.
- 녹화가 끊긴 적이 있다(여유 메모리 약 0.5 GiB). 촬영 직전에 사용자가 앱을 정리한다. 다른 세션을 임의로 끄지 않는다.
- Windows 검색 창(작업 표시줄의 검색)을 열면 왼쪽에 최근 항목이, 오른쪽에 그날의 뉴스 「인기 검색어」와 그림이 뜬다. 지금 판의 2:52 · 4:48 · 10:07(첫 합본의 1:57 · 3:01 · 7:06)에 「이태원 참사」 같은 검색어가 찍혔다. 사용자는 녹화 전에 「설정 → 개인 정보 및 보안 → 검색 권한 → 검색 하이라이트 표시」를 끄고 시작 메뉴의 최근 항목을 지운 뒤 찍는다. 이미 찍힌 원본은 그 칸이 열린 동안만 흐리게 가린다(자료 「지금 판의 편집」 ③의 `--흐림`).
