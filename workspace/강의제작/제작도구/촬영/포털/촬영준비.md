## 1. 바로 가는 길

한 갈래를 처음부터 끝까지 따라간다. 한 단계가 실패하면 다음으로 넘어가지 않는다.

### 클라우드 길(정본 — Playwright 헤드리스, bash · `python3`)

명령은 [촬영도구](촬영도구/)에서 돌린다. 녹화 원본 · 끝 상태는 config `work` = `작업/촬영/포털/`(이 PC 전용), 스택 기동 로그는 `stack.sh`의 `ev` 자리. 환경값은 3절 「클라우드 환경」.

1. **스택(학생과 같은 시작 상태)** — 학생 시작 파일 `scripts/start_all.sh`로 띄우고 워커만 호스트에서 재생으로 돌린다(2026-11-03 실측 약 8분). 저장소의 `.sh`는 실행 권한이 없으니 `bash <파일>`로 부른다. 체크아웃은 origin/main을 포함해야 한다.
   ```bash
   (setsid nohup dockerd >/tmp/dockerd.log 2>&1 < /dev/null &)    # docker info가 답할 때까지 기다린다
   grep -q host.docker.internal /etc/hosts || echo "127.0.0.1 host.docker.internal" >> /etc/hosts   # 워커가 업무 DB를 찾는 이름
   # 이미지: 3절 「베이스 이미지」 · 「Supabase 이미지」대로 받아 원래 이름으로 tag, compose.override.yaml(3절 「워커」)을 저장소 루트에
   bash scripts/start_all.sh            # 4단계가 새 코드로 빌드. 워커가 없으면 5단계 「agent-worker: 응답 확인 실패」로 멈춘다 — 정상, 아래로
   python3 -m venv .venv && .venv/bin/pip install -r it/agent-worker/requirements.txt
   git archive refs/heads/workspace workspace/개발/scripts/run_worker_host.sh workspace/개발/scripts/host_libpq.sh | tar -x
   docker compose stop agent-worker      # 중계가 켜져 있으면 워커 시작이 거절한다(워커는 하나)
   (HEALTH_PORT=8097 AI_MODE=replay PYTHON=.venv/bin/python setsid nohup bash workspace/개발/scripts/run_worker_host.sh > <로그> 2>&1 < /dev/null &)
   docker compose up -d --no-deps agent-worker   # 중계(워커 :8097/health 가 replay로 답한 뒤)
   bash scripts/start_all.sh            # 다시: 5단계 통과 → 6 수업 흐름 배포 · 7 기본 지식(HM-8 · PM-02 · PR-07). 8단계 점검만 실패 — 정상(점검이 이 PC 포트 값으로 워커를 찾는다)
   ```
   확인 넷: `curl :8097/health`의 `ai_mode` replay · `:8080/api/instances` 처리 건 0 · `:8080/api/kg/manuals/sources` 보관 원문 3 · 지식 관리 「등록할 문서」에 `HM-8_cooler-fan-manual.md · 문서 개정`. 포털 위 막대 「서비스 13/13」. `stack.sh`는 실제 AI 호스트 워커(CLI 로그인)와 「보관 원문 0」을 전제해 지금 시작 파일과 맞지 않는다 — 쓰지 않는다.
2. **데이터 초기화(사용자 허락 필요)** — 매뉴얼을 적재하고 판단이 한 번이라도 돌면 적재 되돌리기가 거절된다(DIAGNOSED_AS 이력). 볼륨 3개 삭제 + 업무 DB 재설정이라 자동 승인이 막는다. 사용자에게 「데이터 볼륨 neo4j · detector · process 삭제와 Supabase db reset」을 실제 동작 이름으로 묻고 허락을 받은 뒤:
   ```bash
   kill <워커 PID>   # 8097 응답 없어진 것 확인
   docker compose -p hyd-iot-edu stop && docker compose -p hyd-iot-edu rm -f neo4j detector process
   docker volume rm hyd-iot-edu_neo4j-data hyd-iot-edu_detector-data hyd-iot-edu_process-data
   (cd it/supabase && npx -y supabase@2.119.0 db reset)
   # 그다음 1번을 다시(start_all.sh가 흐름 · 기본 지식을 다시 넣는다)
   ```
   녹화 브라우저의 「나」(localStorage `hyd.me`)는 포털 소개 구간 1이 지우고 실습3 구간 1은 최운전이어야 한다(구간 모듈이 확인). 새 마이그레이션만이면 `supabase migration up`(데이터 유지)으로 충분하다.
3. **길뚫기(녹화 없이)** — 녹화할 화면을 먼저 본다. 상태를 바꾸지 않는 보기만 한다.
   - `node look.mjs <메뉴> [선택자 …]`: 다른 메뉴를 열어 한 화면씩 PNG로 저장하고 요소 글 · 위치를 출력한 뒤 원래 메뉴 · 스크롤로 되돌린다.
   - `node dry.mjs <segs 모듈> <구간>`: 큐의 point · scroll · wait · 메뉴 누르기를 실제로 하고 대상이 하나로 찾아지는지 본다. 되돌릴 수 없는 조작(아래)은 건너뛴다.
   - **되돌릴 수 없는 조작**: 매뉴얼 미리보기(원문이 서버에 보관됨) · 에이전트 추출 요청 · 결과 적재 · 결함 주입 · 승인 · 거절 · 「나」 바꾸기. 이것 뒤의 화면은 dry로 볼 수 없다 → 그 화면을 만드는 코드(`it/portal/www/*.js`)를 읽고, 서버 데이터는 API로 읽는다(예: 추출 결과 `GET /api/kg/manuals/sources/<id>/extractions/<실행>`, 처리 건 `GET :8080/api/instances`). 또는 그 조작 직후에서 구간을 끊고, 다음 구간을 쓰기 전에 그 화면을 look으로 본다.
4. **대본(큐 JSON)** — 형식 `{"cues":[{"id","segment","text","ops":[[조작, 대상, 시점 0~1, …]]}]}`. 조작: point · click · scroll(대상을 위에서 top px로) · select(대상, 값) · file(대상, 경로) · wait(대상이 나타날 때까지) · waittext(글이 나타날 때까지, 150초). 대상 이름 → 화면 요소는 구간 모듈의 표(`portal_tour.mjs` FIXED/target, `manual.mjs` MORE). 큐 파일 머리에 `voice_id` · `model_id`(3절 「음성」)를 둔다.
   - 행동 문장 안에서 누른다(시점 0.6~0.9). 서버 응답 뒤 그려지는 결과는 다음 문장 첫 조작을 `wait`/`waittext`로 둔다.
   - 말 규칙은 공통.md C-7 · 영상 V-57 · V-229 — 승인 구간 대사는 「추천안을 보고 승인」처럼 이름 없이 쓰고, 이름과 순위는 승인 뒤 구간에서 화면을 읽고 쓴다. 시나리오 기호(A · B · C)는 화면 글자에는 보인다. 촬영 사정을 설명하는 대사는 쓰지 않는다(06에서 10개를 고쳤다). 04 · 06 독립 검토에서 되풀이된 불통과를 쓸 때 막는다: 말과 다른 화면, 경보 · 남은 기한처럼 화면에서 짚을 것을 말로 안 짚음, 커서가 목록 항목 · 대상을 안 짚음(V-162), 출처가 없거나 사실표 말과 다른 문장, 이번 촬영 값과 다른 대본 값.
   - 길이는 `python3 ../../시간계산.py estimate <큐>`로 잰다.
5. **음성** — `ELEVENLABS_API_KEY="$(tr -d '\r\n ' < <키 파일>)" python3 voice.py <큐> [구간 …]`. 같은 글은 다시 사지 않는다. 키 파일은 사용자 업로드(`/root/.claude/uploads/<세션>/…-env.txt`), 값을 출력하지 않는다(키 다루기는 영상 V요-48). 견적을 먼저 알린다(V요-42). 결과는 음성 캐시 `<큐id>.mp3` · `.json`(3절 「클라우드 환경」 config).
6. **녹화** — 정본은 끊지 않는 한 번 녹화(`take.sh`, 구간 여러 개를 녹화 한 번으로, 2026-11-03 06 실측 초당 약 50장 · 분당 약 0.5 GB — 녹화 전 `df`):
   ```bash
   bash run.sh up                                                        # 녹화 브라우저(기본 문맥)
   bash take.sh record <이름> <큐.json> <모듈> <구간,…>                     # 리허설 표시 <work>/rehearsal-<이름 앞부분>.json의 조작 표시가 큐와 같아야 시작
   RESUME=<앞 take>:<실패 큐> bash take.sh record <새 이름> <큐.json> <모듈> <구간,…>   # 실패한 큐부터 잇기
   python3 이음새검수.py <새 이름>                                          # 잘린 화면과 첫 화면이 같은가(0.5 % 이하)
   ```
   리허설은 말을 기다리지 않아 말 시점 · 화면이 따라 내려가는 결함이 드러나지 않으니(2절) 본녹화 첫 몇 큐를 지켜본다. 이어 찍기 전에는 잘린 지점의 화면(메뉴 · 스크롤 · 「나」)을 녹화 밖에서 되돌린다 — 학습 조작은 하지 않는다. 조작을 고친 큐는 `bash take.sh rehearse …`(같은 `RESUME`)로 그 큐만 리허설한 뒤 다시 되돌리고 찍는다. 검토 뒤 뒤쪽 걸음만 다시 찍을 때: 화면만 보는 걸음이면 초기화 없이 앞 걸음 끝 화면과 「나」를 되돌려 `RESUME=<앞 take>:<그 걸음 첫 큐>`로 찍고(04), 되돌릴 수 없는 조작이 앞에 있으면 초기화(2번) → `take.sh rehearse`로 앞 걸음을 녹화 없이 돌려 같은 상태로 → 같은 `RESUME`으로 찍고 `encode.py <출력> <앞 take>:<잘린ms> <새 take>`로 합성한다(06). 구간별 녹화는 `bash run.sh up`(녹화 브라우저) → 구간 1 `bash run.sh rec <이름> <모듈>` → 나머지 `bash chain.sh <앞 이름> <이름:모듈> …`(실패하면 멈춤). 구간 모듈의 BEFORE(녹화 전 준비)가 기다릴 조건을 맞춘다: 구간 시작 화면 · 「나」 확인 · 승인 요청이 뜰 때까지 기다림. 추출 요청·판단 진행·완료 표시는 같은 요청의 흐름으로 촬영한다. 앞 파일을 닫고 다음 파일을 여는 동안 학생이 볼 동작·진행 신호를 놓치지 않는다. 대기 생략 여부는 실제 기록으로 영상 V-181을 판정한다.
   ```bash
   ./run.sh up                                  # 녹화 브라우저(이미 떠 있으면 그대로)
   ./run.sh rec <이름> <구간 파일(segs/ 기준)> [앞 구간 이름]
   ./chain.sh <앞 이름> <이름:모듈> …
   ./run.sh measure <이름>                      # 녹화 하나 다시 실측
   ./run.sh down                                # 끄기(끈 뒤 포트가 내려갔는지 확인)
   ```
   구간마다 시작 상태 확인 → 녹화 → 끝 상태(`end-state.json`) · 프레임 · 행동 시각(`timing.json`) 저장. 한 구간씩 찍고 바로 실측한다(이동별 최대 프레임 공백, 클릭 좌표 오차, 문장보다 늦은 조작, 마지막 프레임). take는 매번 새 이름으로 보존하고, 실패 · 잘못된 상태 take는 이름을 붙여 남기되 합성에 쓰지 않는다. 기존 MP4를 덮어쓰지 않는다.
7. **합성** — `python3 encode.py <이름> <take…>`(take 뒤 `:<여기까지 쓸 ms>`, 음성 없는 시험 구간은 `--silent`, 사용 줄 전부는 `encode.py` 머리말 「사용」). 이어 찍었으면 `<앞 take>:<잘린ms> <새 take>`(이음새검수가 명령을 알려 준다). take는 큐 구간(segment)마다 조각으로 나뉘어 `작업/촬영/포털/조각_저장/`(이 PC 전용)에 남고, 같은 조각은 다시 인코딩하지 않는다 — 대사만 고치면 영상 인코딩 0. 조각 경계마다 프레임 간격 · 소리 튐 · 다른 녹화가 만나는 화면을 자동으로 검사해 하나라도 어긋나면 멈춘다 — `<출력>/이음새_NN.jpg`를 보고 이어짐이 맞으면(앱 전환 등) `--이음새허용 <번호>`로 다시 낸다. 통과하면 이 폴더의 `합성기록/<이름>.json`(커밋한다)을 쓰고, 한 구간만 바꿀 때는 `python3 encode.py --교체 <합성기록.json> <번호>=<take>`로 바꾼 조각만 새로 만든다. 녹화 뒤 대사만 고쳐 다시 만든 음성(화면과 맞추는 정정)은 원래 말이 끝나던 자리에 끝나도록 맞추고 고친 글 · 길이로 자막을 쓰며, 조각 끝을 넘으면 멈춘다. 같은 큐 id가 합성 안에 두 번 나오는데 음성이 바뀌었으면 `--음성교체 <json>`으로 자리마다 정한다. 행동별 장면은 `python3 행동검수.py <take[:여기까지 쓸 ms]> <합본.mp4>` — 이어 찍은 take는 합본 시각으로 맞춰 뽑는다.
8. **검증(게시 전 모두)** — 셋 다 하고 결과를 `작업/촬영/포털/`에 남긴다.
   - `python3 verify.py <영상> <자막> <폴더>`: 길이 · 자막 겹침 · 무음 · 최고점 · 검은 화면, 문장마다 한 장면 그림.
   - `python3 scenes.py <영상> 2`: 끝까지 2~3초 간격 장면 그림을 **모두** 본다(튐 · 로딩 · 오류 창 · 엉뚱한 화면). 의심 구간은 0.5초 간격으로 다시 뽑는다.
   - `ELEVENLABS_API_KEY=… python3 listen.py <영상> <자막> <폴더>`: 소리를 받아써 자막과 대조(크레딧 사용). 「확인할 것」 목록은 매번 눈으로 본다 — 긴 문장 속 짧은 구절이 바뀌면 일치율이 0.9 언저리라 종료 코드로는 안 잡힌다.
9. **여러 영상 잇기(필요할 때)** — `python3 join.py <출력.mp4> <조각1.mp4>:<조각1.srt> …`. 조각마다 소리 크기를 재서 −16 LUFS로 맞추고, 자막 시간을 밀어 합치고, 이음매 앞뒤 장면을 남긴다. 장(chapter)은 조각의 장을 밀어 옮기고, 장이 없는 조각은 `<조각.mp4>:<자막>:<장 이름>`으로 이름을 준다(자막이 없으면 `<조각.mp4>::<장 이름>`). 100 MiB가 넘으면 `CRF=20`으로 다시. 이은 뒤 8단계를 합본에 다시 한다. 게시본 앞부분을 재사용할 때는 `cut.py`가 말이 든 구간을 자르지 않으니 ffmpeg 복사로 떼어 잇고 소리만 영상 길이에 맞춘다(3절 04 실측).
   같은 단계의 긴 대기를 영상 V-181의 범위에서 줄일 때만 `python3 cut.py <입력.mp4> <입력.srt> <출력.mp4> <시작초>-<끝초> …` — 자막 · 장을 당겨 맞추고, 자막이 걸치면 멈춘다. 자른 자리 앞뒤를 0.5초 간격으로 본다.
10. **게시** — 이름 `<과정>_<NN>회차_<대본 번호>_실습_<이름>.mp4`(대본 파일 이름과 같게, 두 과정 공통이면 통합반 이름의 파일 하나를 두 과정 노션이 함께 가리킨다), 자막은 `workspace/강의제작/산출물/영상/_작업/영상_자막_기록/` 같은 이름, `workspace/강의제작/산출물/영상/README.md` 표에 행. `PYTHONUTF8=1 .venv314/Scripts/python.exe workspace/동기화.py commit "메시지" [main 경로 …] [--만 workspace 경로 …]`로 커밋한다(영상 V요-50). push는 CLAUDE.md 2절대로. 클라우드는 `python3`. 영상 한 편은 100 MiB 아래. 올린 뒤 raw 링크가 200이고 크기가 같은지 확인.
11. **노션** — 회차 페이지를 fetch해 그 칸의 「⏳ 영상 준비 중」 블록을 다른 영상과 같은 모양(길이 · 실습 종류 · 한 문단 설명 · `[영상 열기](blob 링크) · [MP4 내려받기](raw 링크)` · 「페이지 안에서 재생」 토글 안 `<video source="raw 링크">`)으로 바꾼다(`update_content`, 통합반 · 실전반 두 페이지). 다시 fetch해 남은 「영상 준비 중」이 없는지 본다(검색 색인은 늦게 바뀐다). 링크는 그 workspace 커밋에 고정한다. Notion 파일 업로드는 한 번에 20 MiB라 영상은 링크로 건다. 유튜브는 쓰지 않는다.
12. **기록** — 영상 V요-33대로: `workspace/강의제작/산출물/영상/README.md` 표, 이 문서 0절 표(새 함정은 2절에 한 줄), 진행 기록은 그 작업 폴더의 `기록.md`.

### 로컬 ego 길(지식 지도 구간 — 2026-10-28 실전 2-2 실측, Git Bash)

클라우드 Playwright가 아니라 로컬 ego 공간 「portal rec 20261028」에서 VS Code 녹화 도구([../vscode/촬영도구/](../vscode/촬영도구/))로 찍는다. 같은 길로 실전 3-1 · 3-3, 통합 2-2 · 3-1의 포털 구간도 찍었다. 값은 3절 「로컬 ego」.

1. **Docker · 스택** — Docker Desktop이 꺼져 있으면 켜고 `docker info` 응답을 기다린다. 스택은 compose 프로젝트 `hyd-system-audit-20261026`을 재빌드 · 데이터 변경 없이 켠다. 켠 직후 「조건별 손익」 기준은 「근거 조회가 불완전」으로 보류되고 몇 분 뒤 데이터가 쌓이면 계산된다.
   ```bash
   docker compose -p hyd-system-audit-20261026 start
   ```
2. **포털 확인** — 포털 127.0.0.1:8088, 위 막대 「서비스 13/13」(서비스를 끄면 화면에 드러남).
3. **ego 준비** — ego lite 설치 · 로그인은 사용자가 한다. 설치된 `ego-browser skill` 출력도 끝까지 읽는다(API는 설치 버전이 우선). 녹화 공간은 「portal rec 20261028」 — 작업 공간은 `taskSpace(<번호 또는 이름>)`로 쥐고(VS Code 촬영도구 `ctrl.mjs`가 `SPACE` 값으로) 같은 작업은 같은 공간을 쓴다. 리허설 에이전트 공간과 겹치지 않게 하고, 다른 세션과 같은 공간 · 페이지를 동시에 조작하지 않는다. ego 창은 최소화하지 않는다(앞에 보이는 탭에서만 프레임이 온다).
4. **시작 상태** — 「알림 50」 배지: 녹화 전 `localStorage.removeItem('hyd.me')`(「나」 비움, 화면 쪽만). 이전 시연 흔적을 정리한 뒤 첫 프레임을 실제 녹화 프레임으로 본다.
5. **길뚫기** — 대상은 3절 「로컬 ego」 선택자로 찾고 클릭 직전 위치를 다시 읽는다. 상태를 바꾸지 않는 보기만 한다(되돌릴 수 없는 조작은 클라우드 길 3번 목록).
6. **큐 · 음성** — 구간 모듈 `segs/<이름>.mjs`(ctx를 받아 `ctx.say(큐id, 조작, {at|pointFrac})`), 음성은 `voice-jobs.json`의 새 큐를 만든다(같은 문장은 다시 만들지 않음). 키는 VS Code 촬영도구와 같이 환경변수 `HYD_ELEVENLABS_KEY_FILE`이 가리키는 파일에서만 읽고 출력하지 않는다. 결과는 음성 캐시(`config.json` `audio`)의 `<id>.mp3` · `<id>.json`. 음성이 없는 큐는 녹화가 「Voice cue missing」으로 멈춘다(생성 후 촬영).
   ```bash
   cd workspace/강의제작/제작도구/촬영/vscode/촬영도구
   PYTHONUTF8=1 python voice.py            # voice-jobs.json
   ```
7. **녹화** — 포털은 `SPACE` · `VP`를 넘긴다. `run.sh`는 문법 검사(`node --check`) · 다른 ego 명령 실행 중이면 시작 안 함 · 화상회의가 돌면 녹화 안 함 · 여유 메모리 3 GB 미만 경고를 한 뒤 ego로 구간을 돌리고 끝나면 `measure.py`로 실측한다(이동별 최대 프레임 공백 · 클릭 오차 · 늦은 조작 · 마지막 프레임). 연속은 `chain.sh`(앞 구간이 실패하면 멈춤).
   ```bash
   SPACE="portal rec 20261028" VP='{width:1536,height:864,dsf:1.5}' ./run.sh rec <이름> <구간 파일(segs/ 기준)> [앞 구간 이름[:자른ms]]
   SPACE="portal rec 20261028" VP='{width:1536,height:864,dsf:1.5}' ./chain.sh <앞 구간 이름> <이름:모듈> …
   ./run.sh measure <이름>
   ```
   진행 리듬(도구가 한다): 모든 ego 호출은 하나의 직렬 큐로 보낸다. 표시 포인터는 페이지에 그린 SVG 화살표를 `element.animate`로 움직이고, 실제 입력은 같은 경로를 단계별 `mouse.move`로 보내며, 실제 입력이 다 끝날 때까지 화살표를 목표에 고정한다. 위치가 바뀌는 대상은 150ms 간격 두 번 같은 위치일 때 출발한다. 조작은 행동 문장이 끝나기 약 250ms 전에 실행하고 다음 음성은 행동 종료 + 250ms에 시작한다. 녹화 시작 전에 조작 큐가 돌면 즉시 실패시키고, 긴 이동 · 긴 문자열 입력을 큐 한 항목에 넣지 않는다. 녹화 전에 서비스 상태와 PC 부하를 보되 수치만으로 중단하지 않고 실제 반응 · 프레임 간격(`measure.py` 최대 0.8초 이하)으로 판정한다. 구간 기록 · take 보존은 클라우드 길 6번과 같다.
   사용자가 직접 배치 · 입력할 때: 녹화를 멈추고 `task.handOff()`로 넘긴 뒤 `takeOverTaskSpace(<번호>)`로 되찾는다. 그 결과는 화면 캡처가 아니라 앱 저장 데이터로 읽는다. 사용자가 ego 공간을 잡고 있으면 우회하지 않고 「계속」을 받은 뒤 되찾는다.
8. **합성** — `FFMPEG` 경로는 3절.
   ```bash
   FFMPEG=<ffmpeg 경로> PYTHONUTF8=1 python encode.py <출력이름> <구간[:여기까지 쓸 ms]> …
   ```
