# 포털 촬영준비

포털(`http://127.0.0.1:8088`) 화면을 찍는다. 정본은 클라우드 세션(리눅스)의 Playwright 헤드리스 Chromium으로 찍고, 화면 상태만 바꾸는 구간(지식 지도 등)은 이 PC의 ego로도 찍는다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md)에 있다.

## 길

### 클라우드(정본) — bash와 `python3`, 1 · 2는 저장소 루트에서, 3부터 [촬영도구/](촬영도구/)에서 실행한다

1. 스택 — 학생과 같은 시작 상태로 띄운다(실측 약 8분). 체크아웃이 origin/main을 포함해야 한다. 저장소의 `.sh`는 실행 권한이 없으므로 `bash <파일>`로 부른다.
   ```bash
   (setsid nohup dockerd >/tmp/dockerd.log 2>&1 < /dev/null &)    # docker info가 답할 때까지
   grep -q host.docker.internal /etc/hosts || echo "127.0.0.1 host.docker.internal" >> /etc/hosts
   # 이미지: 자료 「Supabase 이미지」 · 「베이스 이미지」대로, 저장소 루트에 compose.override.yaml(아래 「워커 중계」)
   bash scripts/start_all.sh            # 5단계 「agent-worker: 응답 확인 실패」에서 멈춤 — 정상
   python3 -m venv .venv && .venv/bin/pip install -r it/agent-worker/requirements.txt
   git archive refs/heads/workspace workspace/개발/scripts/run_worker_host.sh workspace/개발/scripts/host_libpq.sh | tar -x
   docker compose stop agent-worker      # 워커는 하나
   (HEALTH_PORT=8097 AI_MODE=replay PYTHON=.venv/bin/python setsid nohup bash workspace/개발/scripts/run_worker_host.sh > <로그> 2>&1 < /dev/null &)
   docker compose up -d --no-deps agent-worker   # 중계(워커 :8097/health가 replay로 답한 뒤)
   bash scripts/start_all.sh            # 다시: 6 흐름 배포 · 7 기본 지식. 8단계 점검만 실패 — 정상
   ```
   띄운 뒤 넷을 확인한다. ① `curl :8097/health`의 `ai_mode`가 replay다. ② `:8080/api/instances`의 처리 건이 0건이다. ③ `:8080/api/kg/manuals/sources`의 보관 원문이 3건이다. ④ 지식 관리의 「등록할 문서」에 `HM-8_cooler-fan-manual.md`가 있다. 그리고 위 막대가 「서비스 13/13」이어야 한다.
2. 초기화(처리 건이 있을 때만, 사용자의 허락을 받고) — 「데이터 볼륨 neo4j · detector · process 삭제와 Supabase db reset」을 그 이름 그대로 묻는다. 매뉴얼을 적재하고 판단이 한 번 돌면 적재 되돌리기가 거절되기 때문에 초기화가 필요하다.
   ```bash
   kill <워커 PID>   # 8097 응답이 없어졌는지 확인
   docker compose -p hyd-iot-edu stop && docker compose -p hyd-iot-edu rm -f neo4j detector process
   docker volume rm hyd-iot-edu_neo4j-data hyd-iot-edu_detector-data hyd-iot-edu_process-data
   (cd it/supabase && npx -y supabase@2.119.0 db reset)    # 그다음 1을 다시
   ```
   새 마이그레이션만 넣으면 될 때는 `supabase migration up`을 쓴다(데이터가 유지된다).
3. 길뚫기(녹화 없이, 상태를 바꾸지 않고) — `node look.mjs <메뉴> [선택자 …]`는 다른 메뉴를 열어 PNG, 요소 글, 위치를 낸 뒤 원래대로 되돌린다. `node dry.mjs <segs 모듈> <구간>`은 point, scroll, wait, 메뉴 누르기를 실제로 해 보고 대상이 하나로 찾아지는지 본다. 되돌릴 수 없는 조작은 매뉴얼 미리보기, 추출 요청, 적재, 결함 주입, 승인, 거절, 「나」 바꾸기다. 이 조작 뒤의 화면은 `it/portal/www/*.js`를 읽고 API로 본다(`GET /api/kg/manuals/sources/<id>/extractions/<실행>`, `GET :8080/api/instances`).
4. 큐 JSON — 꼴은 `{"cues":[{"id","segment","text","ops":[[조작, 대상, 시점 0~1, …]]}]}`이고, 머리에 `voice_id`와 `model_id`를 둔다.
   - 조작: point, click, scroll(대상을 위에서 top px 자리로), select(대상, 값), file(대상, 경로), wait(대상이 나타날 때까지), waittext(글이 나타날 때까지, 최대 150초), settle(본문 스크롤 자리 · 높이가 1.2초 동안 그대로일 때까지, 최대 b초 — 펼치기 · 적재 · 승인 뒤 칸이 늘어나는 화면), textin(대상 글 안 구절 바로 뒤를 가리킴 — 원문 칸 · 긴 줄의 한 값).
   - 큐마다 `gap`(앞 말이 끝나고 이 말을 시작할 때까지의 ms)을 두고, 그 값은 영상 V-14의 쉼이다. 큐 생성기가 대본의 ‖ · ▸ · 단계 경계에서 정한다(06은 `통합_01_06_전체과정관찰_큐만들기.py`).
   - 대상 이름을 실제 요소로 바꾸는 표는 구간 모듈에 있다(`portal_tour.mjs`의 FIXED/target, `manual.mjs`의 MORE).
   - 말이 화면 대상을 이름으로 부르거나 「이 그림 · 이 숫자 · 밑으로 내려 보시면」으로 받는 자리마다 그 대상을 짚거나 굴리는 조작을 둔다. 1회차 04 화면대조에서 메뉴 묶음 이름, 「이 그림」, 두 카드의 승인 역할, 「밑으로 내려 보시면」이 커서 없이 지나가 걸렸다. 그 편의 큐 생성기는 이런 짚기를 대사 구절에 붙인다(`통합_01_04_포털둘러보기_큐만들기.py`의 EXTRA). 짚는 기본 자리(글 끝 오른쪽)는 맨 위 막대의 숫자 · 「나」 · 종처럼 옆에 다른 요소가 붙은 칸에서 옆 단추를 가리키고, 단추 위에 올라가면 마우스 올림 색으로 단추가 바래 누르기 직전처럼 보인다(1회차 04 「서비스 13/13」 · 「쿨러 열화 주입」). 그런 칸은 `anchor:'center'`에 `dy`를 주어 바로 밑 빈자리를 짚는다.
   - 누르는 시점은 행동 문장 안의 0.6~0.9 지점으로 둔다. 서버 응답 뒤에 그려지는 결과는, 다음 문장의 첫 조작을 `wait`이나 `waittext`로 두어 기다린다.
   - 길이는 `python3 ../../시간계산.py estimate <큐>`로 잰다.
5. 음성 — `ELEVENLABS_API_KEY="$(tr -d '\r\n ' < <키 파일>)" python3 voice.py <큐> [구간 …]`. 키 파일은 사용자가 업로드한 것(`/root/.claude/uploads/<세션>/…`)을 쓴다.
6. 녹화 — 정본은 끊지 않고 한 번에 녹화한다. 녹화 전에 `df`로 디스크 여유를 본다.
   ```bash
   bash run.sh up                                                        # 녹화 브라우저
   bash take.sh record <이름> <큐.json> <모듈> <구간,…>                     # 리허설 표시가 큐와 같아야 시작
   RESUME=<앞 take>:<실패 큐> bash take.sh record <새 이름> <큐.json> <모듈> <구간,…>
   python3 이음새검수.py <새 이름>                                          # 잘린 화면과 첫 화면 차이 0.5 % 이하
   ```
   큐 JSON을 구간마다 나눠 찍을 때(`segs/map.mjs`를 쓰는 모듈, 예: 1회차 04 `segs/tour04.mjs`)는 `AFTER=<앞 take> bash take.sh record <이름> <큐.json> <모듈> <구간>`으로 찍는다. 새 take는 앞 take의 끝 화면과 마지막 커서 자리(움직임 없이 끝난 take면 그 시작 커서 자리)에서 시작하고, `python3 measure.py <이름>`과 `python3 이음새검수.py <이름>`을 통과해야 다음 구간을 찍는다. 한 구간만 다시 찍을 때는 `take.sh rehearse`로 1구간부터 바로 앞 구간까지 돌려 화면을 그 끝 상태로 되돌린 뒤 찍는다(구간 1이 홈을 새로 연다). `ui.mjs`를 쓰는 옛 모듈은 `bash run.sh rec <이름> <모듈> [앞 이름]` → `bash chain.sh <앞 이름> <이름:모듈> …` → `bash run.sh measure <이름>` → `bash run.sh down`(포트가 내려갔는지 확인) 순서로 찍고, 구간 모듈의 BEFORE 단계가 시작 화면, 「나」, 승인 요청이 준비될 때까지 기다린다.
7. 합성 — `python3 encode.py <출력> <take[:여기까지 ms]> …`로 한다. 음성 없는 시험 구간은 `--silent`를 주고, 자세한 쓰는 법은 파일 머리말에 있다. take는 큐 구간마다 조각으로 나뉘어 `작업/촬영/포털/조각_저장/`에 남고, 같은 조각은 다시 인코딩하지 않는다. 조각 경계의 프레임 간격, 소리 튐, 화면을 자동으로 검사해 어긋나면 멈춘다. 그러면 `<출력>/이음새_NN.jpg`를 보고, 이어짐이 맞으면 `--이음새허용 <번호>`를 준다. 통과하면 `합성기록/<출력>.json`이 생기고, 이 파일은 커밋한다. 행동별 장면은 `python3 행동검수.py <take[:ms]> <합본.mp4>`로 본다.
8. 검사 — `python3 verify.py <영상> <자막> <폴더>`, `python3 scenes.py <영상> 2`, `ELEVENLABS_API_KEY=… python3 listen.py <영상> <자막> <폴더>`를 돌린다(어디에 돌리는지는 영상 지침 길 17). 여러 편은 `python3 join.py <출력.mp4> <조각.mp4>:<조각.srt>[:<장 이름>] …`로 잇는다. 자막이 없는 조각은 `<조각.mp4>::<장 이름>`으로 준다. 잇기는 소리를 −16 LUFS로 맞추고, 결과가 100 MiB를 넘으면 실패하니 `CRF=20`을 주어 다시 만든다. 같은 단계의 긴 대기는 `python3 cut.py <입력.mp4> <입력.srt> <출력.mp4> <시작초>-<끝초> …`로 자른다(자를 곳에 자막이 걸쳐 있으면 멈춘다).

### 로컬 ego(포털 화면) — Git Bash, `workspace/강의제작/제작도구/촬영/vscode/촬영도구/`에서

0. 찍을 곳 — 대본과 큐를 쓰기 전에 어느 PC · 도구로 찍을지 정한다. 큐 JSON은 클라우드 정본과 같은 꼴(길 4) 하나이고, 이 PC에서는 `segs/map-common.mjs`가 그 큐를 그대로 읽어 찍는다. 구간 모듈은 `mapSeg(ctx, <큐 파일>, <구간>)` 한 줄이다(통합 05 `segs/m05-N.mjs`, 실전 06 `segs/r06-N.mjs`). map-common이 다루는 조작은 point · click · scroll · select · type · key · wait이고, 대상은 `{css, contains}`다. 대상 이름표(`tab:` · `{text, within}`)와 file · waittext · waitjs · open · step · phrase · download는 다루지 않으므로, 그런 조작이나 되돌릴 수 없는 조작(적재 · 주입 · 승인 · 「나」 바꾸기)이 든 구간은 클라우드 정본으로 찍는다. 가리키는 자리 규칙은 지식 지도(`#ontoNode` · `#ontoMap`)에서 맞춘 것이고 다른 화면은 기본 규칙(글 끝 오른쪽)을 쓰므로, 리허설(길 4)의 덮음 검사로 확인한다. 시점 규칙은 그 파일 머리말에 있다.
1. 스택 — Docker Desktop을 켜고 `docker info`가 답하면 `docker compose -p <.hyd-runtime/project.json의 compose 값> start`로 스택을 켠다(다시 빌드하거나 데이터를 바꾸지 않는다). 포털 위 막대가 「서비스 13/13」이어야 한다. 첫 구간은 모듈이 포털 홈을 새로 열고 「나」를 비운다.
2. 음성 — 이 폴더 `음성/`을 `HYD_AUDIO=../../포털/음성`으로 고른다(사본을 만들지 않는다). 음성이 없는 큐가 있으면 녹화가 「Voice cue missing」으로 멈춘다.
3. 화면 크기 — `VP='{width:1920,height:1080,dsf:1}'`(CSS 1280×720)을 리허설과 녹화에 똑같이 건다. 모듈은 구간 시작과 큐마다 CSS 크기를 보고, 1280×720이 아니면 멈춘다.
4. 리허설(녹화 전, 녹화 공간과 다른 공간) — `SPACE=<리허설 공간> VP=… HYD_AUDIO=… ./run.sh dry <이름> <모듈>`을 구간 순서대로 돌린다. 녹화 · 프레임 저장 · 음성 대기 없이 조작만 실제로 하고(screencast는 녹화처럼 돌린다), 큐마다 네 가지를 `<work>/<이름>/dry.json`에 숫자로 남긴다. ① 대상이 하나로 찾아지고 화면 안에 들어오는가(못 하면 그 큐에서 멈춘다) ② 가리킨 화살표 몸통이 덮는 글자 수(0이어야 한다) ③ 입력에 걸린 시간(2.5초 이하) ④ 결과가 그려질 때까지 기다린 시간(6초 이하). 하나라도 어기면 `DRY FAIL`과 종료 코드 1을 낸다. 녹화는 전 구간 리허설이 통과한 큐와 모듈로만 한다. 리허설도 화면 상태만 바꾸는 조작뿐이고, 녹화 첫 구간이 홈을 새로 연다.
5. 녹화 — `SPACE=<녹화 공간> VP=… HYD_AUDIO=… ./run.sh rec <이름> <모듈> [앞 이름]`. 구간마다 따로 부른다. 다음 구간은 앞 take가 돌려준 굴린 자리로 되돌린 뒤 찍는다(다르면 멈춘다). 실패한 take 뒤에 다시 찍을 때는 앞 take 끝 화면(검색어 · 고른 노드 · 설비 · 층 단추 · 굴린 자리 · 포커스)을 녹화 밖에서 맞춘다. 구간마다 `measure.py`의 0.5초 넘는 끊김이 3회 미만이고 프레임 간격이 최대 0.8초 이하여야 한다.
6. 합성과 검사 — `FFMPEG=<ffmpeg> PYTHONUTF8=1 python encode.py <출력> <구간[:ms]> …`로 합성하고, 검사는 영상 길 17대로 한다. 끝나면 ego 공간을 닫고, `docker desktop stop`으로 끄고, 남은 프로세스가 없는지 확인한다.

### 조각 고침 — 합성기록이 있는 영상은 그 걸음만

걸음은 구간 하나(조작에서 그 결과까지)를 말한다.

- 말만 바꿀 때: 그 큐의 음성만 새로 만든 뒤 같은 조각으로 합성한다(새 음성은 원래 말이 끝나던 자리에 맞추고, 조각 끝을 넘으면 멈춘다). 새 음성이 옛 말보다 길면 그만큼 앞 쉼을 먹고, 앞 말 끝을 넘으면 앞 말 바로 뒤에 붙으며, 뒤 말과 겹치면 「말이 겹친다」로 멈춘다. 구간 첫 큐는 구간 사이 쉼을 먹고, 짧으면 앞 쉼이 그만큼 길어진다. 그래서 바꾼 글은 옛 말 길이 ±0.5초 안으로 쓰고, 합성 뒤 자막에서 말 사이를 재어 V-14 쉼 근처인지 본다(1회차 04: 07-09 겹침, 08-01 구간 사이 쉼 0.4초 → 2.9초). 같은 큐 id가 두 번 나오는데 음성이 바뀌었으면 `--음성교체 <json>`을 준다.
- 한 걸음을 바꿀 때: `python3 encode.py --교체 <합성기록.json> <번호>=<take>`.
- 실패한 큐부터 다시 찍을 때: 잘린 지점의 화면(메뉴, 스크롤, 「나」)을 녹화 밖에서 되돌림 → 조작을 고친 큐는 `bash take.sh rehearse …`(같은 `RESUME`)로 리허설 → `RESUME=…`로 녹화 → `이음새검수.py`, 이 순서로 한다.
- 뒤쪽 걸음이고 화면만 보는 걸음일 때: 초기화 없이 앞 걸음 끝 화면과 「나」를 되돌린 뒤 `RESUME`으로 찍는다. 실제로 통한 명령(04): `RESUME=04-t1:pt301` → `encode.py 04-포털소개2 04-t1:181841 04-t2`.
- 뒤쪽 걸음이고 앞에 되돌릴 수 없는 조작이 있을 때: 초기화(허락을 받고) → `take.sh rehearse`로 앞 걸음을 녹화 없이 돌림 → 추출 처리 건이 COMPLETED가 될 때까지 API로 기다림 → `RESUME`으로 찍고 `encode.py <출력> <앞 take>:<잘린ms> <새 take>`로 합성. 실제로 통한 명령(06): `RESUME=06-t6:C034` → `encode.py 06-합본4 06-t6:626059 06-t8`.
- 게시본 앞부분을 다시 쓸 때: `cut.py`는 말이 든 구간을 자르지 않으므로, ffmpeg 복사로 앞부분을 떼어 `join.py`로 잇고 소리만 영상 길이에 맞춘다(04: 옛 게시본 0~1031.9초 뒤에 포털 소개).

## 함정

- 클라우드 VM이 쉬었다가 다시 켜지면 dockerd, hosts 줄, 워커, 녹화 브라우저가 사라진다(볼륨과 이미지는 남는다). 길 1을 처음부터 다시 한다.
- 위 막대가 「서비스 12/13」이고 process가 워커를 찾지 못한다. 이름 `agent-worker:8097`로 중계를 띄운다(`compose.override.yaml`). `.env`의 `WORKER_URL`은 process에 넘어가지 않는다.
- 스택을 몇 시간 띄워 두면 위 막대가 「서비스 12/13 — 응답 없음: detector」로 바뀌어 구간 1이 「13/13 · 나 선택 안 함이 아님」으로 멈춘다(detector `/healthz` 503, 로그의 다른 요청은 200). `docker compose -p hyd-iot-edu restart detector` 뒤 healthy가 되면 다시 찍는다.
- 시작 파일이 8088과 7474가 쓰이고 있다고 보고 18088과 17474로 옮긴다(`.hyd-runtime/ports.json`). 이때는 8088 → 18088 중계를 띄운다. 워커는 `HEALTH_PORT=8097`로 띄운다.
- Supabase 시작이 `public.ecr.aws … Forbidden`으로 실패하고, 빌드가 `deb.debian.org`에서 막힌다. 미러 이미지와 호스트 워커로 해결한다(정책을 우회하지 않는다).
- 녹화 원본이 분당 약 0.5 GB씩 쌓인다(멈춘 화면에서도 홈 그림의 흐르는 점선 같은 움직임 때문에 초당 20~40장이 온다). 이미지와 저장소가 세션 허용량의 대부분을 써서 여유가 5 GB 남짓이고, 차면 녹화가 오류로 멈춘다. 녹화 전에 `df`를 보고, 구간마다 검사를 마친 뒤 `python3 프레임정리.py <take> --실행`으로 합성에 쓰지 않는 프레임(약 35 %)을 지운다(조각 키와 출력은 같다). 구간이 여럿이라 그래도 모자라면, 그 구간을 `encode.py`로 합성해 조각을 남긴 뒤 `--비움`으로 남은 프레임을 같은 크기의 빈 파일로 바꾼다(06 다시 찍기에서 구간마다 1.3~1.7 GB). 비운 take는 커서 경로를 바꾸는 합성을 할 수 없어 그 구간을 다시 찍어야 한다. 다시 찍기로 한 옛 take와 실패한 take의 프레임은 지우고 `timing.json`은 남긴다.
- `pkill -f`가 한글 경로를 잡지 못하거나 자기 셸을 죽인다. PID 파일로 끈다(`run.sh down`).
- 헤드리스 녹화가 1280×720으로 찍힌다. `--force-device-scale-factor=1.5`와 문맥 배율 1.5(`browser.mjs`)를 함께 건다. 사이트를 옮기면 크기 설정이 풀리므로 녹화마다 다시 건다.
- 4코어 VM에서는 커서 이동 중 프레임 공백이 100~190ms 생긴다. 커서 표시는 보정한다(`pointer: overlay`). 화면 내용의 멈춤은 보정되지 않는다.
- 메뉴(`.rail`)와 본문(`main#content`)이 따로 굴러간다. 굴릴 영역 위로 화살표를 옮긴 뒤 굴린다(`ui.mjs`). 처리 건 오른쪽 칸처럼 스크롤 칸이 겹치면, 바깥 칸 · 화면에 잘린 안쪽 칸의 보이는 범위로 「화면 안」을 판정한다. 06에서 sticky 칸을 화면 고정으로 보아 화살표가 화면 밖(y 1041)을 가리켰다.
- 진행 중인 처리 건은 새 줄이 생기면서 화면을 따라 내린다. 처리 기록의 다음 단계는 칸을 누르지 말고, `scroll`(제목을 위로)과 가리키기로 아래로만 따라간다. 기록을 읽어 설명하는 구간은 처리 건이 끝난 뒤(`GET :8080/api/instances`에서 그 건이 COMPLETED)에 시작한다. 06에서 재관측 중에 읽다가 그 건이 끝나며 위에 줄이 생기자, 굴릴 자리가 밀려 화면이 「운전원 승인」 · 「점수 구성」 칸에 약 7초 머물렀고 말과 화면이 어긋났다(13:17~13:26, 사용자 결정으로 그대로 둠).
- 리허설은 말을 기다리지 않아 빠르다. 대상이 늦게 그려지는 곳은 `wait`를 넣고, 본녹화의 첫 몇 큐를 지켜본다. 추출은 두 번(제출, 보정)에 끝나므로, 녹화 없이 앞 걸음을 돌릴 때는 COMPLETED를 API로 기다린다.
- 이어 찍은 첫 화면이 같은데 이음새검수가 1.1 %를 낸다. 소수점 글자 차이 때문이다. `앞뒤보기.py`로 0.5초 간격 프레임을 보고 판정한다.
- 승인이 「승인 권한 없음 … 생산관리자 이상」으로 거절된다. 카드마다 승인 역할이 다르다. 승인 구간의 BEFORE에서 역할을 읽고, 「나」를 녹화 전에 그 역할로 맞춘다(운전원은 최운전 · 김운전, 생산관리자는 이생산).
- 승인 기한(PT10M)은 벽시계 시간이다. 승인 요청과 남은 기한을 확인하고 녹화한다.
- 추천안이 길뚫기 때와 달라진다(실행할 때 다시 계산한다). 대본에 추천안 이름을 미리 쓰지 않는다.
- 매뉴얼을 적재하지 않고 쿨러 열화를 주입하면 원인 진단이 보류된다. 매뉴얼을 먼저 적재한다. 미리보기만으로는 지식이 생기지 않으니 「에이전트 추출 요청」을 한다.
- 클라우드 VM 이미지의 `/etc/fonts/conf.d/56-prefer-inter.conf`가 `-apple-system` · `BlinkMacSystemFont` · `Segoe UI` · `system-ui` · `sans-serif`를 Inter로 바꾸고, 맑은 고딕이 없으면 한글은 중국어 글꼴(WenQuanYi Zen Hei)로 그려진다. 포털 글꼴 목록 맨 앞이 `-apple-system`이라 영문 · 숫자가 Inter로 찍혀 학생 화면(전부 맑은 고딕)과 달랐다. 녹화 브라우저는 시스템 conf.d를 읽지 않는 `촬영도구/fonts.conf`로 띄운다(자료 「글꼴」). 그 파일의 XML 주석에 빼기 두 개를 쓰면 fontconfig가 파일을 통째로 버리고 시스템 설정으로 조용히 돌아가므로, `browser.mjs`가 띄우기 전에 확인한다. 글꼴은 브라우저를 띄울 때 정해지므로 구간을 이어 찍는 도중에는 `run.sh up`을 새로 하지 않는다
- Playwright가 직접 띄운 브라우저에서는 한글이 든 경로의 파일이 파일 선택 칸에 들어가지 않고 오류도 나지 않는다(CDP로 붙은 녹화 브라우저에서는 들어간다). 녹화 폴더 `작업/촬영/포털`이 한글이므로 `segs/one06.mjs`의 `file` 조작은 영문 임시 폴더로 복사해 넣고, 파일 칸에 들어갔는지 확인해 아니면 멈춘다. 길뚫기 스크립트도 영문 경로를 쓴다.

- 로컬: 메뉴 클릭이 대사 끝까지 밀린다. `ctx.say(id, fn, {at:'대사 속 구절'})`로 시점을 맞춘다. 한 큐의 두 클릭이 함께 일어나면 큐를 나눈다. 「빈 자리」의 x 1240이 CSS 폭 1024 밖에 있으니, 굴릴 때 화살표를 옮기지 않는다. 「화면 안」은 본문의 실제 높이 비율로 판단한다(`segs/p31-common.mjs`의 `p.show`).
- 로컬 지식 지도: CSS 폭이 1100 미만(1024)이면 상세 칸이 한 단으로 내려가 관계 묶음이 속성 아래에 온다. 「오른쪽의 관계」를 말하는 대사와 맞으려면 CSS 1280으로 찍는다. dpr 2.25(`dsf:1.5`)에서는 지도를 다시 그린 뒤 화살표 이동 중 프레임이 0.5초 넘게 비었다. 지도 화면에서 실제 마우스를 8단계로 움직이면 한 번에 수백 ms씩 직렬 큐를 붙잡아 프레임이 비므로, 표시 화살표만 움직이고 실제 입력은 도착 때 한 번 보낸다(`segs/map-common.mjs`). 그래도 이동 · 굴리기를 시작하고 약 50ms 뒤 200~550ms 공백이 되풀이된다(그 시각에 페이지의 긴 작업은 없었다). 검색 칸은 글자마다 지도 전체를 다시 그려 한 글자에 0.5~1초가 걸리므로 두 덩이로 나눠 넣는다. 글 끝 오른쪽에 둔 화살표는 몸통이 아랫줄 글을 덮으므로, 상세 칸과 지도 머리글은 그 줄 왼쪽 여백을 가리킨다. 두 줄로 접힌 링크는 첫 줄 상자에서 누른다. `page.screenshot`은 화면 배율 설정을 풀 수 있으므로 화면 확인은 screencast 프레임으로 한다. 녹화를 시작하면 녹화 밖에서 화면을 되돌리기 전에 만들어진 프레임도 함께 오므로, `encode.py`는 녹화 시계 0 이전 프레임 가운데 마지막 하나만 쓴다(버린 수는 합성 기록 `dropped_prestart`).
