# 포털 촬영준비

포털(`http://127.0.0.1:8088`) 화면. 정본은 클라우드 세션(리눅스) Playwright 헤드리스 Chromium, 지식 지도 구간은 이 PC ego로도 찍는다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md).

## 길

### 클라우드(정본) — bash · `python3`, 명령은 [촬영도구/](촬영도구/)에서

1. 스택(학생과 같은 시작 상태, 실측 약 8분) — 체크아웃이 origin/main을 포함해야 한다. 저장소의 `.sh`는 실행 권한이 없어 `bash <파일>`로 부른다.
   ```bash
   (setsid nohup dockerd >/tmp/dockerd.log 2>&1 < /dev/null &)    # docker info가 답할 때까지
   grep -q host.docker.internal /etc/hosts || echo "127.0.0.1 host.docker.internal" >> /etc/hosts
   # 이미지: 자료 「Supabase 이미지」 · 「베이스 이미지」대로, 저장소 루트에 compose.override.yaml(아래 「워커 중계」)
   bash scripts/start_all.sh            # 5단계 「agent-worker: 응답 확인 실패」에서 멈춤 — 정상
   python3 -m venv .venv && .venv/bin/pip install -r it/agent-worker/requirements.txt
   git archive refs/heads/workspace workspace/개발/scripts/run_worker_host.sh workspace/개발/scripts/host_libpq.sh | tar -x
   docker compose stop agent-worker      # 워커는 하나
   (HEALTH_PORT=8097 AI_MODE=replay PYTHON=.venv/bin/python setsid nohup bash workspace/개발/scripts/run_worker_host.sh > <로그> 2>&1 < /dev/null &)
   docker compose up -d --no-deps agent-worker   # 중계(워커 :8097/health가 replay로 답한 뒤)
   bash scripts/start_all.sh            # 다시: 6 흐름 배포 · 7 기본 지식. 8단계 점검만 실패 — 정상
   ```
   확인 넷: `curl :8097/health`의 `ai_mode` replay · `:8080/api/instances` 처리 건 0 · `:8080/api/kg/manuals/sources` 보관 원문 3 · 지식 관리 「등록할 문서」에 `HM-8_cooler-fan-manual.md`. 위 막대 「서비스 13/13」.
2. 초기화(처리 건이 있을 때, **사용자 허락**) — 「데이터 볼륨 neo4j · detector · process 삭제와 Supabase db reset」을 그 이름으로 묻는다. 매뉴얼을 적재하고 판단이 한 번 돌면 적재 되돌리기가 거절되기 때문이다.
   ```bash
   kill <워커 PID>   # 8097 응답이 없어졌는지 확인
   docker compose -p hyd-iot-edu stop && docker compose -p hyd-iot-edu rm -f neo4j detector process
   docker volume rm hyd-iot-edu_neo4j-data hyd-iot-edu_detector-data hyd-iot-edu_process-data
   (cd it/supabase && npx -y supabase@2.119.0 db reset)    # 그다음 1을 다시
   ```
   새 마이그레이션만이면 `supabase migration up`(데이터 유지).
3. 길뚫기(녹화 없이, 상태를 바꾸지 않음) — `node look.mjs <메뉴> [선택자 …]`(다른 메뉴를 열어 PNG · 요소 글 · 위치를 내고 되돌림), `node dry.mjs <segs 모듈> <구간>`(point · scroll · wait · 메뉴 누르기를 실제로 하고 대상이 하나로 찾아지는지). **되돌릴 수 없는 조작**: 매뉴얼 미리보기 · 추출 요청 · 적재 · 결함 주입 · 승인 · 거절 · 「나」 바꾸기 — 그 뒤 화면은 `it/portal/www/*.js`를 읽고 API로 본다(`GET /api/kg/manuals/sources/<id>/extractions/<실행>`, `GET :8080/api/instances`).
4. 큐 JSON — `{"cues":[{"id","segment","text","ops":[[조작, 대상, 시점 0~1, …]]}]}`, 머리에 `voice_id` · `model_id`. 조작: point · click · scroll(대상을 위에서 top px로) · select(대상, 값) · file(대상, 경로) · wait(대상이 나타날 때까지) · waittext(글이 나타날 때까지, 150초). 대상 이름 → 요소는 구간 모듈 표(`portal_tour.mjs` FIXED/target, `manual.mjs` MORE). 누르기는 행동 문장 안 시점 0.6~0.9, 서버 응답 뒤 그려지는 결과는 다음 문장 첫 조작을 `wait` · `waittext`로. 길이 `python3 ../../시간계산.py estimate <큐>`.
5. 음성 — `ELEVENLABS_API_KEY="$(tr -d '\r\n ' < <키 파일>)" python3 voice.py <큐> [구간 …]`. 키 파일은 사용자 업로드(`/root/.claude/uploads/<세션>/…`).
6. 녹화(정본은 끊지 않는 한 번 녹화 — 녹화 전 `df`):
   ```bash
   bash run.sh up                                                        # 녹화 브라우저
   bash take.sh record <이름> <큐.json> <모듈> <구간,…>                     # 리허설 표시가 큐와 같아야 시작
   RESUME=<앞 take>:<실패 큐> bash take.sh record <새 이름> <큐.json> <모듈> <구간,…>
   python3 이음새검수.py <새 이름>                                          # 잘린 화면과 첫 화면 차이 0.5 % 이하
   ```
   구간별로 찍을 때는 `bash run.sh rec <이름> <모듈> [앞 이름]` → `bash chain.sh <앞 이름> <이름:모듈> …` → `bash run.sh measure <이름>` → `bash run.sh down`(포트가 내려갔는지 확인). 구간 모듈의 BEFORE가 시작 화면 · 「나」 · 승인 요청을 기다린다.
7. 합성 — `python3 encode.py <출력> <take[:여기까지 ms]> …`(음성 없는 시험 구간 `--silent`, 사용은 머리말). take는 큐 구간마다 조각으로 `작업/촬영/포털/조각_저장/`에 남아 같은 조각은 다시 인코딩하지 않는다. 조각 경계의 프레임 간격 · 소리 튐 · 화면을 자동 검사해 어긋나면 멈춘다 — `<출력>/이음새_NN.jpg`를 보고 이어짐이 맞으면 `--이음새허용 <번호>`. 통과하면 `합성기록/<출력>.json`(커밋). 행동별 장면 `python3 행동검수.py <take[:ms]> <합본.mp4>`.
8. 검사 — `python3 verify.py <영상> <자막> <폴더>` · `python3 scenes.py <영상> 2` · `ELEVENLABS_API_KEY=… python3 listen.py <영상> <자막> <폴더>`(범위는 영상 길 17). 여러 편 잇기 `python3 join.py <출력.mp4> <조각.mp4>:<조각.srt>[:<장 이름>] …`(자막이 없으면 `<조각.mp4>::<장 이름>`)(−16 LUFS, 100 MiB 넘으면 `CRF=20`), 같은 단계의 긴 대기 `python3 cut.py <입력.mp4> <입력.srt> <출력.mp4> <시작초>-<끝초> …`(자막이 걸치면 멈춤).

### 로컬 ego(지식 지도 구간) — Git Bash, `workspace/강의제작/제작도구/촬영/vscode/촬영도구/`에서

1. Docker Desktop을 켜고 `docker info` → `docker compose -p hyd-system-audit-20261026 start`(재빌드 · 데이터 변경 없이). 포털 위 막대 「서비스 13/13」.
2. 녹화 전 `localStorage.removeItem('hyd.me')`(「나」 비움), 첫 프레임 확인.
3. 큐 · 음성 — 구간 모듈 `segs/<이름>.mjs`(`ctx.say(큐id, 조작, {at|pointFrac})`), 새 문장은 `voice-jobs.json`(지금 없음 — 돌리기 전에 만든다) → `PYTHONUTF8=1 python voice.py`. 음성이 없는 큐는 녹화가 「Voice cue missing」으로 멈춘다.
4. 녹화 — `SPACE="portal rec 20261028" VP='{width:1536,height:864,dsf:1.5}' ./run.sh rec <이름> <모듈> [앞 이름[:자른ms]]`, 연속은 `./chain.sh`. `measure.py` 프레임 간격 최대 0.8초 이하.
5. 합성 · 검사 — `FFMPEG=<ffmpeg> PYTHONUTF8=1 python encode.py <출력> <구간[:ms]> …`, `python ../../포털/촬영도구/verify.py <영상> <자막> <폴더>` · `scenes.py <영상> 3`. 끝나면 `docker desktop stop`, 프로세스 0.

### 조각 고침 — 합성기록이 있는 영상은 그 걸음만

- 말만: 그 큐 음성만 새로 → 같은 조각으로 합성(원래 말이 끝나던 자리에 맞추고 조각 끝을 넘으면 멈춤). 같은 큐 id가 두 번 나오는데 음성이 바뀌면 `--음성교체 <json>`.
- 한 걸음: `python3 encode.py --교체 <합성기록.json> <번호>=<take>`.
- 실패한 큐부터: 잘린 지점의 화면(메뉴 · 스크롤 · 「나」)을 녹화 밖에서 되돌림 → 조작을 고친 큐는 `bash take.sh rehearse …`(같은 `RESUME`) → `RESUME=…` 녹화 → `이음새검수.py`.
- 뒤쪽 걸음, 화면만 보는 걸음: 초기화 없이 앞 걸음 끝 화면과 「나」를 되돌려 `RESUME`. 통한 명령(04): `RESUME=04-t1:pt301` → `encode.py 04-포털소개2 04-t1:181841 04-t2`.
- 뒤쪽 걸음, 앞에 되돌릴 수 없는 조작: 초기화(허락) → `take.sh rehearse`로 앞 걸음을 녹화 없이 → 추출 처리 건 COMPLETED를 API로 기다림 → `RESUME`으로 찍고 `encode.py <출력> <앞 take>:<잘린ms> <새 take>`. 통한 명령(06): `RESUME=06-t6:C034` → `encode.py 06-합본4 06-t6:626059 06-t8`.
- 게시본 앞부분을 재사용: `cut.py`는 말이 든 구간을 자르지 않으니 ffmpeg 복사로 떼어 `join.py`로 잇고 소리만 영상 길이에 맞춘다(04: 옛 게시본 0~1031.9초 + 포털 소개).

## 함정

- 클라우드 VM이 쉬었다 다시 켜지면 dockerd · hosts 줄 · 워커 · 녹화 브라우저가 사라진다(볼륨 · 이미지는 남음) → 길 1을 처음부터.
- 위 막대 「서비스 12/13」 · process가 워커를 못 찾음 → 이름 `agent-worker:8097` 중계(`compose.override.yaml`). `.env`의 `WORKER_URL`은 process에 안 넘어간다.
- 시작 파일이 8088 · 7474가 쓰인다고 보고 18088 · 17474로 옮김(`.hyd-runtime/ports.json`) → 8088 → 18088 중계를 띄운다. 워커는 `HEALTH_PORT=8097`.
- Supabase 시작이 `public.ecr.aws … Forbidden`, 빌드가 `deb.debian.org`에서 막힘 → 미러 이미지 · 호스트 워커(우회하지 않는다).
- 녹화 원본이 분당 약 0.5 GB(세션 허용 30 GB 중 이미지 약 10 GB) → 녹화 전 `df`, 실패 take의 프레임은 저해상도 영상으로 남기고 비운다.
- `pkill -f`가 한글 경로를 못 잡거나 자기 셸을 죽인다 → PID 파일로(`run.sh down`).
- 헤드리스 녹화가 1280×720 → `--force-device-scale-factor=1.5` + 문맥 배율 1.5(`browser.mjs`). 사이트를 옮기면 크기 설정이 풀린다 → 녹화마다 다시.
- 4코어에서 이동 중 프레임 공백 100~190ms → 커서 표시 보정(`pointer: overlay`). 화면 내용의 멈춤은 보정되지 않는다.
- 메뉴(`.rail`)와 본문(`main#content`)이 따로 굴러간다 → 굴릴 영역 위로 화살표를 옮긴 뒤 굴린다(`ui.mjs`).
- 진행 중인 처리 건은 새 줄로 화면을 따라 내린다 → 처리 기록의 다음 단계는 칸을 누르지 말고 `scroll`(제목을 위로) + 가리키기로 아래로만.
- 리허설은 말을 기다리지 않아 빠르다 → 대상이 늦게 그려지는 곳은 `wait`, 본녹화 첫 몇 큐를 지켜본다. 추출은 두 번(제출 · 보정)에 끝나니 녹화 없이 앞 걸음을 돌릴 때는 COMPLETED를 API로 기다린다.
- 이어 찍은 첫 화면이 같은데 이음새검수 1.1 % → 소수점 글자 차이, `앞뒤보기.py`로 0.5초 간격을 보고 판정.
- 승인이 「승인 권한 없음 … 생산관리자 이상」 → 카드마다 승인 역할이 다르다. 승인 구간 BEFORE에서 역할을 읽고 「나」를 녹화 전에 맞춘다(운전원 최운전 · 김운전, 생산관리자 이생산).
- 승인 기한(PT10M)은 벽시계다 → 승인 요청 · 남은 기한을 확인하고 녹화한다.
- 추천안이 길뚫기 때와 다르다(실행 때 다시 계산) → 대본에 이름을 미리 쓰지 않는다.
- 적재 없이 쿨러 열화를 주입하면 원인 진단이 보류된다 → 매뉴얼을 먼저 적재. 미리보기만으로는 지식이 안 생긴다 → 「에이전트 추출 요청」.
- 「미리보기」 버튼이 둘 → `#manualPreview`(매뉴얼) · `#ddlPreview`(데이터 연결). 파일 선택 창은 헤드리스에 안 찍힌다 → 대사는 창 없이 맞게.
- 홈 도식은 고정 그림 → 「구조 설명 그림」으로 말한다. 실시간 모니터링 첫 3초 빈 틀은 실제 동작이라 둔다.
- ffmpeg가 메시지 없이 끝나고 `moov atom not found`(같은 입력을 trim 두 갈래 → OOM) → `cut.py`처럼 조각마다 만들어 `-c copy`. 합본 장이 엉뚱함 → `-map_metadata -1` 쓰지 않고 `-map_chapters`.
- 키 값이 로그에 찍힘(키 파일을 `sed`로 봄) → 실행 프로세스 안에서만 `tr -d '\r\n '`.
- 로컬: 메뉴 클릭이 대사 끝까지 밀림 → `ctx.say(id, fn, {at:'대사 속 구절'})`. 한 큐의 두 클릭이 같이 일어남 → 큐를 나눈다. 「빈 자리」 x 1240이 CSS 폭 1024 밖 → 굴릴 때 화살표를 옮기지 않는다. 「화면 안」은 본문 실제 높이 비율로(`segs/p31-common.mjs` `p.show`).
- 로컬: 스택을 켠 직후 「조건별 손익」이 「근거 조회가 불완전」 → 몇 분 기다린다.
- 로컬 스냅샷 되돌리기가 약 55분(볼륨 8개) → `스냅샷.sh`는 수업 상태 볼륨 4개만(고친 판의 되돌리기는 미검증).
