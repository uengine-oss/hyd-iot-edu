## 2. Python

*(표의 Python 줄을 짚는다)*

첫 번째는 Python이에요. 컴퓨터는 사람 말을 그대로 알아듣지 못하죠. 그래서 「이 파일을 열어서, 숫자를 더하고, 결과를 저장해」 같은 일을 컴퓨터가 알아듣는 말로 적어 줘야 하는데, 이런 말을 프로그래밍 언어라고 합니다. Python은 그중에서도 읽기 쉽고 쓰기 편해서, 전 세계에서 가장 많이 쓰는 언어 중 하나예요. 우리 수업에서는 시스템을 켤 때 필요한 준비를 Python이 대신 해 주고, 나중에 코드를 직접 만들 때도 이 Python으로 씁니다.

## 3. Node.js

*(Node.js 줄)*

다음은 Node.js예요. 웹 사이트를 떠올리면 쉬운데요, 버튼을 누르면 메뉴가 펼쳐지고 글자가 바뀌잖아요. 이렇게 웹 페이지를 움직이는 언어가 자바스크립트입니다. 원래 자바스크립트는 인터넷 브라우저 안에서만 돌아갔는데, Node.js를 깔면 브라우저 없이도 자바스크립트로 만든 프로그램을 돌릴 수 있어요. 그래서 많은 개발 도구가 Node.js 위에서 돌아가고, 우리는 시스템을 켤 때 데이터베이스를 띄우는 데 씁니다.

## 4. Git

*(Git 줄)*

세 번째는 Git이에요. 과제 파일을 고치다 보면 「최종」, 「진짜 최종」, 「진짜진짜 최종」처럼 파일이 자꾸 늘어나죠. 그러다 보면 어느 게 언제 바뀐 건지 헷갈립니다. Git을 쓰면 파일은 하나만 두고, 「여기까지 남겨 둘래」 할 때마다 그 시점을 기록해 둬요. 게임에서 세이브해 두면 언제든 그 시점으로 다시 불러올 수 있는 것처럼, 필요하면 예전 시점으로 되돌릴 수도 있고요. 아까 본 GitHub가 바로 이 Git으로 기록을 관리하는 저장소를 올려 두는 곳입니다. 우리는 그 저장소를 내 컴퓨터로 받아 올 때 Git을 써요.

## 5. VS Code

*(VS Code 줄)*

네 번째는 VS Code예요. 보고서를 쓸 때는 한글이나 워드를 켜잖아요. 코드를 쓰고 고칠 때도 그런 프로그램이 따로 있는데, 이걸 코드 편집기라고 합니다. VS Code는 개발자들이 가장 많이 쓰는 코드 편집기 중 하나예요. 앞으로 코드를 열어 보고 고치는 일은 VS Code에서 할 거고요.

## 6. WSL

*(WSL 줄)*

다섯 번째는 WSL이에요. Windows 안에서 리눅스를 돌릴 수 있게 해 주는 기능입니다. 리눅스가 왜 필요하냐면, 바로 다음에 볼 Docker가 리눅스 위에서 돌아가거든요. 그래서 Windows에서 Docker를 쓰려면 WSL이 먼저 있어야 해요. WSL 안에 들어가서 직접 할 일은 없고, 뒤에서 Docker를 받쳐 주기만 합니다.

## 7. Docker

*(Docker 줄)*

마지막은 Docker예요. 같은 프로그램이라도 컴퓨터마다 깔린 것도, 설정도 조금씩 달라서, 내 컴퓨터에선 되는데 옆 컴퓨터에선 안 되는 일이 자주 생기죠. 이걸 컴퓨터마다 하나하나 맞추려면 시간이 한참 걸립니다.

Docker는 그 대신 프로그램을, 돌아가는 데 필요한 환경까지 통째로 상자 하나에 싸 버려요. 배로 물건 나를 때 쓰는 컨테이너처럼요. 그래서 이 상자를 컨테이너라고 부르고, 어느 컴퓨터에 가져가든 그 상자를 열면 똑같이 돌아갑니다. 똑같은 컨테이너를 몇 번이고 찍어 낼 수 있게 무엇을 담을지 정해 둔 본은 이미지라고 해요. 우리 수업 시스템도 이렇게 Docker로 한 번에 켜니까, 여러분 컴퓨터가 달라도 모두 똑같은 시스템을 쓰게 됩니다.

## 8. 켜기 — Docker Desktop과 시작.bat

자, 필요한 것들은 다 봤으니 이제 시스템을 켜 볼게요.

*(Docker Desktop을 연다 → 왼쪽 아래 Engine running)*

먼저 Docker Desktop을 켭니다. 아까 말씀드린 Docker를 켜고 잘 돌고 있는지 보여 주는 앱이에요. 왼쪽 아래에 Engine running이 떠야 Docker가 컨테이너를 돌릴 준비가 된 겁니다.

*(파일 탐색기 → 로컬 디스크(C:) → hyd-iot-edu → setup → 시작.bat 두 번 누르기)*

저장소는 여기 PC에 이미 받아 두었어요. 로컬 디스크 C에 들어가 보시면 hyd-iot-edu라는 폴더가 있죠. 아까 GitHub에서 본 그 저장소 이름 그대로예요. 그 안의 setup 폴더에서 시작.bat을 두 번 누르시면 돼요. 이게 시스템을 켜는 명령을 대신 실행해 주는 파일이에요. 처음 켤 때는 이것저것 내려받느라 시간이 좀 걸리니까, 같은 파일을 또 누르지 마시고 창을 닫지 말고 그대로 두세요.

## 9. 로그 — 크게 세 덩어리만

*(검은 창에 글자가 올라온다 — 줄마다 읽지 않고 지금 어느 덩어리인지만 짚는다)*

글자가 쭉 올라오죠. 하나하나 보실 필요는 없고, 크게 세 가지를 하고 있다고 보시면 됩니다.

첫째, 이 컴퓨터에서 쓸 설정이랑 실행에 필요한 키 같은 걸 준비해요.

둘째, Docker로 시스템을 띄웁니다. 아까 말한 이미지, 그러니까 컨테이너를 찍어 낼 본을 내려받아서 서비스마다 컨테이너를 하나씩 띄우는 거예요. 수업 시스템은 프로그램 하나가 아니라 여러 프로그램이 일을 나눠서 하거든요. 식당에 주문 받는 직원, 요리하는 직원, 계산하는 직원이 따로 있는 것처럼요. 이렇게 일을 나눠 맡은 프로그램 하나하나를 서비스라고 합니다. 처음엔 받을 게 많아서 여기가 제일 오래 걸려요.

셋째, 마지막에 서비스마다 「준비됐어요?」 하고 물어서, 전부 제대로 돌아가는지 시험해 봅니다. 켜지기만 한 것과 일할 준비가 된 건 다르니까요.

## 10. 포털 열기와 둘러보기

*(마지막 줄 「완료. 포털: http://…」 주소를 Ctrl을 누른 채 클릭 → 포털 홈)*

다 끝나면 마지막 줄에 포털 주소가 나옵니다. Ctrl을 누른 채 클릭하면 포털이 열려요. 앞으로 설비 상황을 보고, 할 일을 고르고, 승인하는 건 다 여기서 합니다.

메뉴가 많은데, 지금은 어디에 뭐가 있는지만 한 바퀴 보고, 자세한 건 바로 이어서 실제로 한 바퀴 돌리면서 보겠습니다. 둘러보는 동안은 버튼을 누르지 마세요.

### 홈

*(위쪽 네 칸 → 맨 위 막대 → 아래 연결 그림)*

위의 네 칸은 공장 상황 요약이에요. 설비 대수, 지금 열린 사건 수, AI가 가진 지식 수, 그리고 시간 배율 20배는 설비 안의 시간이 스무 배 빨리 간다는 뜻이라 수업 시간 안에 고장부터 회복까지 다 볼 수 있습니다. 맨 위 막대의 서비스 수는 켜고 나면 늘 먼저 보세요. 다 켜져 있어야 포털이 제대로 돕니다.

아래 그림이 시스템 전체예요. 설비에서 값이 생기고, AI가 지식을 보고 판단을 올리면 사람이 승인하고, 그 조치가 위쪽 화살표를 따라 다시 설비로 돌아갑니다. 왼쪽 메뉴도 이 차례로 묶여 있어요.

### 설비 — 값이 생기는 곳

- **결함 시뮬레이션** — 컴퓨터 안의 가상 설비 세 대예요. 여기서 일부러 고장을 내면 한 바퀴가 시작됩니다. 조금 뒤에 같이 누를게요.
- **실시간 모니터링** — 유온 같은 값을 그래프로 봅니다. 조치가 먹혀서 온도가 내려오는지도 여기서 확인해요.
- **오일 분석 입력** — 센서로 못 재는 기름 상태를 사람이 검사해서 넣는 곳이에요. 기준을 벗어났다고 넣으면 경보처럼 처리가 시작됩니다.
- **이상 확인 · 조치** — 경보로 열린 사건을 설비별로 따라가는 곳이고요.

### 지식 — AI가 아는 것

- **지식 지도** — 이 공장의 고장 · 원인 · 조치가 선으로 이어진 지도예요. AI는 이 선을 따라 원인과 조치를 찾아갑니다.
- **조치 방법** — 고장마다 쓸 조치와 그 작업 순서, 누가 승인하는지가 정리돼 있어요.
- **지식 관리** — 매뉴얼을 올려서 AI 지식으로 만드는 곳이에요. 조금 뒤에 직접 해 봅니다.
- **데이터 연결** — AI가 읽는 회사 기록과 센서 기록이 어디서 오는지 보는 곳이에요. AI는 읽기만 하고 고치지는 못합니다.

### 인공지능 설정 — 일하는 AI

- **에이전트에게 질문** — 궁금한 걸 물으면 에이전트가 매뉴얼과 데이터를 찾아보고 답해 줘요.
- **에이전트** — 냉각 긴급 대응, 예비품 구매처럼 일마다 따로 둔 AI들이고, 나중에 나만의 에이전트도 여기서 만들어요.
- **도구 연결 · 시험 비교 · 판단 채점** — 에이전트가 쓰는 도구, 에이전트끼리 견줘 보기, 판단에 점수 매기기예요. 에이전트를 만들고 고칠 때 씁니다.

### 판단 — 무엇을 할지 정하는 곳

- **조치 판단 규칙** — 「이런 상황이면 이런 조치」로 정해 둔 규칙이에요.
- **조건별 손익** — 조건이 바뀌면 어떤 조치가 돈으로 더 이득인지 계산해 봅니다.
- **흐름 가져오기** — 업무 흐름을 올리는 곳이고, 뒤 회차에서 배워요.
- **승인과 실행** — AI가 올린 판단과 실행 결과가 모이는 곳이에요. 아래에는 생산 · 정비 · 구매를 관리하는 회사 시스템, MES · CMMS · ERP 상태도 보입니다.

### 작업 — 사람이 승인하는 곳

- **내 작업함** — 회사 결재함이에요. 나한테 온 승인할 일이 모입니다.
- **처리 건** — 일 하나가 생겨서 끝날 때까지, AI가 뭘 추천했고 누가 승인했는지가 한 줄로 남는 곳이에요.

### 성과 · 시스템

- **성과 지표** — 조치 결과가 회사 숫자, 비용이나 가동률에 어떻게 나타났는지 보는 곳이에요.
- **시스템 구성** — 켠 서비스들이 모여 있어서, 멈춘 게 있으면 여기서 찾습니다.
- **관리** — 관리자용 화면이라 열지 않습니다.

*(홈으로 돌아온다)*

정리하면, 설비에서 값이 생기고, AI가 지식을 보고 판단을 올리고, 사람이 승인하면 조치가 다시 설비로 돌아가는 이 흐름 하나예요. 이제 이 흐름을 실제로 한 바퀴 돌려 보겠습니다.

## 11. 실제 흐름 한 바퀴 — 문서가 지식이 되고, 그 지식으로 에이전트가 일하기

*(진행 메모 — 낭독하지 않음: 화면 글자를 하나하나 읽지 않는다. 단계마다 「지금 뭘 하는지」만 한두 문장. 되돌릴 수 없는 조작(적재 · 쿨러 열화 주입 · 「나」 고르기 · 승인)은 학생들이 따라오는지 보고 같이 누른다. AI가 그 자리에서 정리하면 화면 문장이 영상과 조금 달라도 된다. 재관측 값 · 시각 · 번호는 읽지 않는다.)*

### 11-1. 문서 넣기 — 문서가 어떻게 AI 지식이 되나

*(지식 관리)*

AI가 고장을 판단하려면 설비 매뉴얼을 알고 있어야겠죠. 쿨러 매뉴얼은 처음부터 지식으로 들어 있는데, 문서가 어떤 과정을 거쳐 지식이 되는지 보려고 같은 문서를 한 번 새로 넣어 보겠습니다.

*(제공 문서의 쿨러 팬 매뉴얼 받기 → 파일 선택 → 등록할 문서 「… · 문서 개정」 → 미리보기)*

제공 문서에서 쿨러 팬 매뉴얼을 받아서 파일 선택으로 고르시고, 오른쪽 등록할 문서는 「문서 개정」으로 골라 주세요. 이미 있는 문서를 새 판으로 바꿔 넣는다는 뜻이에요. 그리고 미리보기를 누르면 파일이 올라갑니다. 아래에 이것저것 뜨는데 지금은 넘어가셔도 돼요.

*(추출 원문 전체 보기 → 훑어만 보기)*

원문을 열어 보면 쿨러가 고장 났다고 보는 기준, 원인 세 가지, 당장 온도를 낮추는 조치와 원인을 없애는 정비가 적혀 있어요. 이걸 AI가 정리하게 하겠습니다.

*(추출 제안 준비 → 추출 진행 · 결과 확인)*

추출 제안 준비, 그다음 추출 진행 · 결과 확인을 누르세요.

*(아래 AI 정리 결과 — 위에서 아래로 한 번 훑는다)*

AI가 매뉴얼을 읽고 이렇게 정리했습니다. 어떤 조치가 있고, 그게 어느 고장에 쓰이고, 원인은 뭐고, 언제 꺼내 쓰는지까지요. 이건 아직 AI의 제안이에요. AI도 틀릴 수 있어서, 사람이 보고 잘못된 게 있으면 빼고, 없으면 그대로 넣습니다. 오늘은 잘못된 게 없네요.

*(맨 아래 「검토했습니다」 체크 → 검토한 내용 적재 → 적재 완료)*

「검토했습니다」에 체크하고 적재를 누르면, 적재 완료. 이제 이게 AI가 쓰는 지식이 됐습니다.

정리하면, 문서를 올리고 → AI가 정리하고 → 사람이 확인하고 → 적재하면 지식이 되는 거예요. 그럼 이 지식으로 에이전트가 실제로 일하는 걸 보겠습니다.

### 11-2. 고장 내기

*(결함 시뮬레이션 → 첫 번째 설비 → 쿨러 열화 주입 — 다 같이 한 번)*

결함 시뮬레이션에서 첫 번째 설비를 보면 지금 유온 48도쯤, 정상이죠. 아래 쿨러 열화 주입을 한 번 눌러 주세요.

쿨러가 나빠지니까 기름이 덜 식고, 유온이 천천히 올라갑니다. 55도를 넘어 조금 지나면 「경보 발생」이 떠요.

### 11-3. 에이전트가 판단한 것 보기

*(처리 건 → 냉각 긴급 대응 → 진행 상황 그림)*

처리 건을 보면 「냉각 긴급 대응」이 새로 생겼죠. 경보가 오자마자 에이전트가 방금 넣은 매뉴얼 지식으로 원인을 짚고, 할 조치를 골라 뒀어요. 지금은 사람 승인을 기다리는 중이고, 승인 전에는 설비에 아무것도 안 갑니다.

*(위 승인 요청 카드)*

승인 카드에는 에이전트가 고른 조치, 하면 온도가 얼마나 내려갈지, 대신 감수할 것, 근거가 된 매뉴얼이 같이 나와요.

### 11-4. 사람이 승인하기

*(내 작업함 「나」에서 최운전 · 운전원 → 처리 건으로 돌아와 승인)*

승인 버튼이 흐린 건 누가 승인하는지가 아직 안 정해져서예요. 내 작업함에서 최운전 · 운전원을 고르고, 처리 건으로 돌아와 승인을 누르세요.

### 11-5. 조치 → 다시 재기 → 끝

*(아래 처리 과정 → 「끝」이 뜰 때까지)*

승인하자 조치가 설비로 갔고, 이제 정말 식는지 다시 재 보는 중이에요. 1분쯤 지나 온도가 내려오고 경보가 풀리면 「끝」이 뜹니다.

*(처리 기록 탭 → 위에서 아래로 훑기)*

처리 기록을 보면 이 한 건이 처음부터 끝까지 남아 있어요. 경보 → 에이전트의 판단 → 사람의 승인 → 설비 조치 → 다시 재서 확인 → 정비 요청까지요. 누가 언제 뭘 했는지 다 남아서, 나중에 다시 따라가 볼 수 있습니다.

*(홈 그림으로 돌아온다)*

오늘 본 걸 한 줄로 하면, 문서를 지식으로 넣고, 그 지식으로 에이전트가 판단하고, 사람이 승인한 것만 설비로 가는 한 바퀴예요.
