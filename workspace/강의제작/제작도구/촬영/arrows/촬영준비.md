# ARROWS 촬영준비

arrows.app 캔버스를 이 PC의 ego로 찍는다(클라우드에서는 찍을 수 없다). 명령은 Git Bash에서, 이 폴더를 현재 위치로 두고 `PYTHONUTF8=1 python`으로 실행한다. 규칙은 [영상](../../../지침/영상.md), 여러 도구 공통은 [README](../README.md)에 있다.

## 길

1. 환경 — 환경변수는 `HYD_ELEVENLABS_KEY_FILE`과 `FFMPEG` 둘만 맞추면 된다. `work`와 `space` 값은 [촬영도구/config.json](촬영도구/config.json)에 있다.
2. 큐, 시간, 배치 순서(녹화 전에) — 큐의 원본은 [build_ontology.py](build_ontology.py)의 `CUES`다(조작 이름은 「자료」 아래 설명에 있다).
   ```bash
   python build_ontology.py cues ../../../../../작업/촬영/arrows/cues.json
   python ../시간계산.py estimate ../../../../../작업/촬영/arrows/cues.json
   python 촬영도구/plan_order.py <시작 구간>     # 배치가 바뀌었을 때: 겹침 · 그림 범위 축소가 없는 순서
   ./촬영도구/run.sh coords                       # 사용자가 ego에서 잡은 배치를 저장 좌표로 읽는다(화면 캡처 X)
   ```
3. 음성(바뀐 문장만) — `python 촬영도구/voice.py <구간번호 …>`.
4. 시작 상태(이어 찍을 때만, 녹화 밖에서) — `./촬영도구/run.sh restore <앞 구간> [출발원 도착원]`이 다음 순서로 맞춘다. 끝 상태 데이터를 새 그림으로 가져오기 → radius를 70으로 → 원들의 상대 위치 확인 → 마지막 화살표 선택. 하나라도 다르면 멈춘다. 가져오면 그림 주소가 바뀌므로, 이어 찍는 첫 구간은 `run.sh rec`의 다섯째 인자로 `relax`를 준다. 가져오기는 그림을 화면에 다시 맞추므로, 앞 판 화면과 같은 배율 · 위치로 이으려면 `VIEW='{"scale":…,"dx":…,"dy":…}'`를 `run.sh rec` 앞에 준다(녹화기가 녹화 직전에 넣고 0.8초 그대로인지 본다). 값은 앞 take 끝 상태의 `view`이고, 원본 take가 없는 게시본에서 이을 때는 그 프레임에서 원 테두리에 원을 맞춰 잰 중심(그림 좌표 = 프레임 좌표 ÷ 1.029, 테두리 두께 몫)으로 그림을 만들고 배율 = 1.029 ÷ 1.25, 위치는 한 번 넣어 찍은 프레임과의 어긋남으로 고쳐 정한다.
5. 구간 녹화 — 한 번에 한 구간씩 찍고, 이름은 매번 새로 짓는다. 같은 이름에 프레임이 이미 있으면 멈춘다.
   ```bash
   TMO=<초> ./촬영도구/run.sh rec <이름> <구간> [시작큐] [앞 구간] [relax]
   python 촬영도구/measure.py <이름>
   ```
   run.sh의 끝줄이 비어 있을 수 있으므로, 실행 결과는 `<take>.log`에 `"error":null`이 있는지로 판정한다. 구간을 이어 찍을 때는 한 구간씩 찍고, 다음 구간 전에 ① 앞 take 끝 프레임과 이 take 첫 프레임의 화소 차 ② `measure.py`의 `over_500ms`(0.5초 넘는 이동 공백)와 `unexplained_jumps`(조작 없이 그림 전체가 한 번에 바뀐 자리)가 0인지 ③ 끝 상태의 `view` · 그림 ④ 고르게 뽑은 장면에서 원과 글자가 그림 영역 밖으로 잘리지 않았는지를 확인한다. 검토자도 이 숫자부터 본다. 녹화 직전에는 녹화 탭에서 3초 동안 screencast 프레임 간격을 재어 100 ms를 넘는 간격이 없을 때만 찍는다.
6. 합성 — `FFMPEG=<ffmpeg.exe> python 촬영도구/encode.py <출력> <조각[:자를ms]> …`. 오류로 끝난 take에는 자를 ms를 반드시 준다. 녹음한 뒤에 큐 문장이 바뀌었으면 합성이 멈춘다. 결과는 `<work>/<출력>/<출력>_안치윤_1080p.mp4`, `자막.srt`, `verification.json`이다.
7. 연결 산출물 — `python build_ontology.py sync`가 대본, 수업원고, 예상시간, 두 과정의 대상_목록, ZIP을 만든다(해시는 [동기화판본.json](동기화판본.json)). 가이드 사진과 문구는 `python build_student_guide.py [--video <mp4>] [--captures <폴더>]`로 만든다.
8. 조각 고침 — 다시 합칠 조각이 없으면, 앞부분은 게시본을 잘라 `../포털/촬영도구/join.py`로 잇는다(지금 판의 앞부분 끝은 624.95초, 자르는 자리는 말과 조작이 끝나 화면이 멈춘 큐 사이로 고른다). 음성 캐시가 없으면 게시본 소리를 자막 시각대로 잘라 큐마다 `audio/<id>.mp3`와 `.json`으로 두고(크레딧이 들지 않는다), 새 문장만 `voice.py`로 만든다. 화면이 조금 틀어진 정도면 되돌리지 말고, 수습 큐(번호를 따로 준다, 예 `o091b`)로 그 화면에서 이어 찍는다.

큐 조작(`CUES`)의 이름과 뜻은 다음과 같다.
- `at 비율`: 그 문장의 이 비율 지점까지 다음 조작을 미룬다. `point 대상`: 대상을 가리킨다(`look:원` · `props:원` · `node:원` · 패널).
- `click` / `ctrlclick 대상`: 대상은 `blank` · `node:이름` · `caption` · `type` · `labelPlus` · `labelInput` · `propPlus` · `propKey` · `propVal` · `customize` · `style:radius` · `style:node-color` · `reverse` · `export` · `tab:JSON|PNG|Cypher` · `done` · `logo` · `menu:New|newLocal|Import` · `importButton` · `panelToggle`.
- `type 글자` · `key 키` · `grow 원 각도`(테두리를 빈 곳으로 끌어 새 원과 화살표를 만든다) · `edge` / `connect 출발 도착` · `layoutNorm [[이름, x비율, y비율]…] 기준원2` · `download 종류 이름` · `choose 종류` · `verify`(다시 연 그림의 원, 관계, 조건 수를 대조한다) · `openLink` · `move 원 dx dy`.
- 쓰지 않는 것: `spread`(그림이 끝없이 축소된다), `manual`(녹화 중 사용자 조작은 페이지에 들어가지 않는다), `place`, `arrange`.

## 함정

- 커서 이동이 0.5~1.3초씩 끊긴다. ego 창이 다른 창(Claude 앱 등)에 덮였거나, 같은 창에서 다른 탭(확장 설치 탭 등)이 앞에 있으면 screencast 프레임이 띄엄띄엄 온다. 녹화기는 녹화 탭을 앞으로 올리지만 창 순서는 못 바꾸므로, ego 창을 최대화해 맨 앞에 두고 프레임 시험(길 5)을 통과한 뒤 찍는다.
- arrows에는 확대 · 축소 조작이 없다(휠 · Ctrl+휠 · Alt+휠 · 가장자리 끌기 모두 그대로). 보기(확대율 · 위치)는 창 크기가 바뀔 때만 그림 맞춤으로 바뀌고, 그 순간 화면 전체가 한 번에 줄며 옮겨 간다. 옛 판의 「튐」(08 10:32 · 10:40 · 11:37 · 12:18 · 13:41)은 녹화 도구가 원을 다시 그리게 하려고 보낸 창 크기 신호 탓이었다. 그래서 `ui.mjs`는 창 크기 신호 대신 지금 보기 값을 그대로 다시 넣어 그린다(`__redraw`). 그러면 보기는 녹화 시작 때 그대로이므로, 그 확대율로 모든 원이 그림 영역 안에 들어가도록 배치를 정한다(새 원은 테두리까지 영역 안 — 반지름 1.25배 여유). 옛 확정판 10:24.95의 확대율로 이으면 8구간에서 새 원 자리가 모자랐다.
- 화면 크기가 바뀌면(ego는 호출마다 크기가 풀리고, 녹화기도 녹화 전에 1px 바꿨다 되돌린다) 약 0.3초 뒤 그림 맞춤이 다시 된다. 이어 찍을 때 보기를 맞추려면 `VIEW`를 준다(길 4). 보기 값을 녹화 밖 스크립트로 읽으면 크기가 풀린 뒤의 값(0.017 같은 작은 값)을 읽으므로, 앞 take 끝 상태의 `view`만 쓴다.
- arrows는 바뀐 그림을 늦게 저장한다(「Saving to Web Browser storage...」). 녹화기는 마지막 큐 뒤 「Saved」가 될 때까지 녹화를 이어 가므로 끝 프레임과 끝 상태가 같은 그림이다. 저장 전에 끝내면 끝 상태에 입력 전 그림이 남아 다음 구간이 빈 이름으로 시작했다.
- 프레임에서 원 중심을 잴 때 원 아래 조건 글자를 테두리로 잡으면 중심이 20px 넘게 틀린다. 테두리 점 수가 다른 원(약 1,700개)보다 크게 적거나 잔차가 1px을 넘으면 처음 짐작을 바꿔 다시 잰다.
- 스타일 칸이나 Label 칸에서 엔터를 누르면 원이 하나 더 생긴다. Tab으로 확정한다.
- 테두리 끌기가 빈 곳 클릭으로 처리된다. 끌기 시작점은 반지름 × 1.09 지점으로 하고, 화살표에서 16px 안이면 피한다. 새 원과 조건을 단 원은 위치를 150ms 간격으로 두 번 읽고, 글자에서 22px 안이면 피한다.
- 화살표를 눌렀는데 옆 화살표가 선택된다. 출발 원 쪽 35% 지점을 누른다. 관계 이름이 잘리면 원 중심 사이 거리를 반지름의 6.6배로 둔다.
- 빈 곳을 눌러도 선택이 풀리지 않는다. 원, 화살표, 글자에서 가장 먼 지점을 한 번의 페이지 평가로 고른다(원을 하나씩 찾으면 프레임이 400ms 끊긴다).
- 축소된 화면에서 원을 찾지 못한다. 가장 큰 반지름의 75% 이상인 것만 원으로 본다.
- 녹화 밖에서 Ctrl+Z를 누르면 입력 칸에 적용되고 원 스타일은 되돌아가지 않는다. `run.sh restore`(가져오기)로 되돌린다. Ctrl+Y는 동작하지 않는다.
- 다운로드 대기를 직렬 큐에 넣으면 클릭이 막힌다. `waitForEvent`와 `waitForFileChooser`는 큐 밖에서 기다린다. 내보내기 창의 Download 버튼은 둘이며 첫 번째를 누른다. `choose`는 같은 녹화 실행에서 받은 파일만 고르므로, 내려받기와 가져오기는 한 구간에 넣는다.
- New로 만든 그림에는 빈 원이 1개 있다. 영상에서 그 원을 선택해 Delete한다. Import는 radius를 50으로 넣고 새 주소를 만든다. radius를 70으로 되돌리고 `relax`를 준다.
- 여러 원을 함께 선택할 때는 Ctrl+클릭을 쓴다(Shift는 하나만 선택된다). 색은 STYLE의 node-color에 값을 입력한 뒤 Tab을 누른다.
- `build_ontology.py`의 `VIDEO`는 끝 7초가 잘린 옛 판(`ARROWS-온톨로지-최종배치`)의 `verification.json`을 읽는다. 그러니 sync가 표시하는 길이는 실행해서 확인한다.
