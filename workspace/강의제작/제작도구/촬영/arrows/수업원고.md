# ARROWS 실습 — 쿨러 고장의 지식 그래프 그리기

2026-10-23 촬영판. 교재 SLIDE 64(지식 그래프 지도) · 70 · 71(핀 오염 기본도 → 팬 구동 불량 가지 → 비교 · 저장 · 다시 열기)의 실습이다. HM-8.4의 세 번째 원인(주변 온도 상승), 고장이 다른 고장으로 이어지는 팬 베어링 열화, 화살표의 절차 번호까지 그린 뒤 정리 · 색칠하고, 완성 그림으로 판단해 보고, 저장 · 다시 열기와 Cypher 내보내기로 마친다. 두 과정 공통.

## 진행 메모 — 낭독하지 않음

- 실제 촬영한 큐 그대로다. 표 왼쪽 발화로 대상과 행동을 먼저 알리고, 행동 문장이 끝나기 약 0.25초 전에 오른쪽 조작을 실행한 뒤 결과가 보이면 다음 발화로 간다.
- 원 위치는 고정 좌표가 아니다. 테두리 끌기로 원을 만들 때 빈 곳을 찾아 놓고, 10구간에서 흐름이 보이게 정리한다. arrows.app은 그림 전체를 화면에 자동으로 맞춘다.
- 첫 원만 Add Node로 만들고 나머지는 원 테두리를 빈 곳으로 끌어 원과 화살표를 함께 만든다. 원인 → 고장(CAUSES)과 증상 → 센서(OBSERVED_BY)는 만든 뒤 Reverse로 방향을 뒤집는다.
- 입력값 출처: 클래스 · 관계 이름은 `workspace/개발/문서/ontology/schema-v2.md` · `it/neo4j/v2/instances.cypher`, 판별 기준은 랩 `매뉴얼_발췌.md` HM-8.4, 조치 근거는 HM-8.1 · 8.5 · 8.7.
- 영상: `workspace/강의제작/산출물/영상/통합반/통합반_01회차_08_실습_관계그림.mp4`(로컬 근거, Git 미포함). 구간 · 시간 · 측정은 제작용 [예상시간](예상시간.md).

# 촬영 본문 끝

## 제작 확인용 — 낭독하지 않음

- 판별 조건은 HM-8.4 원문 기준이다(핀 오염: CE 30초 평균 < 70 % 이고 VS1 2분 평균 < 0.9 mm/s, 팬 구동 불량: VS1 2분 평균 ≥ 0.9 mm/s, 주변 온도 상승: TS4 2분 평균 ≥ 35 ℃). 캐비닛 환기 보강은 랩 발췌 HM-8.7의 SOP-COOL-15다. 이번 그림은 판별 기준을 담은 지식 구조이며 새 진단 실행 결과가 아니다.
- REFERS_TO는 실제 데이터에서 Skill → Step → ManualSection 두 단계(HAS_STEP · REFERS_TO)다. 교재 지도처럼 한 번에 이었다고 영상에서 말한다.
- 10구간 배치는 사용자가 ego에서 직접 잡은 15개 배치를 비율대로 따랐다(원 크기 70 → 47). 그 배치에 없던 팬 베어링 열화 · 진동 증가는 비어 있는 왼쪽 위에 두었다.
