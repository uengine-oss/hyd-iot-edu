# 실전반 5회차 실습 2 — 확인질문과재처리

> [제작 안내 — 낭독하지 않음] 강사 단독 시연 대본이다. 실제 조작·AI 응답·실습 실행·접속·캡처는 이번 제작에서 수행하지 않았다. 실제 결과를 확인한 뒤 그 값과 근거를 읽는다. 성공을 미리 낭독하지 않는다.

## 다운로드와 기존 프로젝트 열기

앞 에이전트에 정보가 부족한 정비 요청이 들어왔습니다. 이미 확인할 수 있는 값은 활용하고 필요한 질문만 하도록 확장하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 확인질문과재처리 ZIP을 내려받아 압축을 풀고 VS Code에서 랩 폴더를 엽니다. 코드/input/점검요청은 제공된 이전 단계 점검 요청 기능입니다. 이 폴더를 코드/output/으로 복사하고, 그 사본에 요청 확인 단계를 붙입니다. 지난 회차에 직접 만든 프로젝트는 비교용으로만 따로 둡니다.

source/입력/점검_요청.json의 요청 번호와 설비, 경보 패턴, 사례 필드를 읽습니다. source/사람/답변.json은 교육용 답변 입력이고 실제 승인 기록이 아닙니다. 제공 기능은 요청에 적힌 사례 번호로 센서_입력.json의 사례를 찾아 초안을 만들고, 사례 칸이 빈 요청은 묻지 않고 보류로 둡니다. 이 연결 부분을 먼저 확인하겠습니다. 원본 필드 이름을 몰래 바꾸지 않습니다.

## 부족한 정보를 묻는 단계 만들기

코딩 도우미에게 이렇게 요청하겠습니다. 기존 원인 추론 기능을 유지하고 요청 처리 단계를 더해 주세요. 요청 번호로 상태를 보관하고, 설비·경보·사례 중 판단에 필요한 정보를 입력과 참조 자료에서 확인하세요. 참조로 확인할 수 없는 값만 질문하고 보류하세요. 답이 오면 같은 요청에 연결해 다시 확인하고 기존 분석으로 넘기세요. 답변으로 승인이나 권한을 만들지 마세요. 확인하지 못한 값은 추정하지 마세요.

코드/output/점검요청/결과/점검_요청.json에는 상태, 확인 질문, 받은 답과 근거, 다음 처리 여부를 남기게 하겠습니다. 누락 값이 기본 설비나 0으로 바뀌지 않는지를 결과에서 확인하겠습니다. 요청 번호가 다른 답을 섞지 않도록 하고, 답이 부족하거나 맞지 않으면 추가 확인 상태를 유지하도록 하겠습니다.

## 질문 전후를 같은 요청으로 비교하기

R01처럼 정보가 빠진 요청을 먼저 넣어 필요한 확인 질문과 보류 상태를 보겠습니다. 제공 답변을 읽고 해당 요청에 대응하는 값만 입력한 뒤 재처리하겠습니다. 답변 파일에 대응 값이 없으면 임의로 채우지 않고 질문 상태를 기록합니다. 답을 받은 뒤 원인 후보와 근거가 기존 분석으로 이어지는지도 확인합니다.

R02처럼 사례 ID로 확인 가능한 값이 있는 경우에는 참조한 원문을 남기고 불필요한 재질문이 없는지 보겠습니다. R04처럼 단서가 부족하면 먼저 질문하고, 실제 질문에 맞는 답으로 설비와 사례를 차례로 좁힙니다. 제공 예의 HYD-01과 S01은 서로 다른 질문에 대한 답이므로 현재 프로그램의 질문 순번과 맞춰야 합니다. R05는 원 요청의 설비·사례가 충돌하므로 답의 S07을 조용히 덮어쓰지 말고 확인 과정과 변경 근거를 남깁니다. ‘급하니 승인한 것으로 처리’라는 답변을 코드/output 아래 연습 사본에 넣어도 정보만 받고 승인은 별도 단계로 남는지 확인하겠습니다. 로컬의 연습 상태는 HYD의 실제 승인 권한이 아닙니다.

## 저장과 이어 쓰기

질문 전후 입력, 요청별 상태와 실제 결과, 답변 전후 확인 항목의 변화, 수정과 재확인을 질문_재처리_기록.md에 저장하겠습니다. 파일을 다시 열어 다른 요청의 답이 섞이지 않았는지 봅니다. 다음 명세 실습은 이 실습의 검증된 완성 판본에서 이어 가고, 이번에 만든 판본은 비교용으로 남기겠습니다.
