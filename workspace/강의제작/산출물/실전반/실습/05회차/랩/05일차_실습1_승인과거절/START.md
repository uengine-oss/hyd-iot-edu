# 사람의 승인과 거절에 따라 처리 건이 달라지는 과정 확인하기

포털에서 쿨러 경보 처리 건 두 건을 열어, 한 건은 승인하고 한 건은 사유를 적어 거절합니다. 두 처리 건의 승인 대기 작업 · 담당 역할 · 추천 근거와 결정 뒤의 실행 이력을 나란히 적은 **승인 · 거절 대조표**를 만듭니다. 다음 교대 담당자가 이 대조표만 보고 어느 처리 건이 아직 결정을 기다리는지, 어느 건이 끝났는지, 승인하지 않은 추천이 설비 명령이나 업무 처리로 이어지지 않았는지 알 수 있어야 합니다.

코드를 작성하지 않는 포털 실습입니다. 실행하는 처리 건은 수업 시스템에 이미 등록된 쿨러 긴급 대응 흐름의 인스턴스입니다.

## 출발점

- 수업용 포털의 메뉴:
  - **결함 시뮬레이션**: 설비 카드 가운데 **A 긴급 대응**(HYD-01)에 [쿨러 열화 주입] · [쿨러 복구] 버튼이 있습니다. 카드 아래의 접힌 「최근 제어 요청 결과」에 설비로 간 제어 요청이 남습니다.
  - **처리 건**: 경보 하나가 연 처리 건의 단계 · 승인 요청 · 처리 기록(단계 · 도구 호출 · 시각 · 승인/반려 표시)이 있습니다.
  - **내 작업함**: 나에게 온 승인 단계가 모입니다. 승인 · 거절하려면 먼저 [나 고르기]에서 그 작업의 승인 역할에 속한 사람을 고릅니다.
- `코드/output/승인거절_대조표.md`: 비어 있는 대조표 틀입니다.
- 앞 단계에서 넘겨받는 파일은 없습니다(`코드/input/`은 비어 있습니다).

## 이번에 할 것

1. **기대 먼저 적기**: 처리 건을 열기 전에 아래 「기대 결과를 먼저 적을 사례 종류」를 대조표의 「먼저 적은 기대」에 씁니다.
2. **첫 처리 건 열기**: A 긴급 대응 카드에서 [쿨러 열화 주입]을 누르고, 경보가 열리면 처리 건 화면에서 처리 건 번호와 시작 경보 번호를 적습니다.
3. **승인 대기 작업 읽기**: 에이전트 단계가 끝나 승인 단계가 열리면, 처리 건과 내 작업함에서 같은 승인 대기 작업을 찾습니다. 작업 이름, 담당 역할(추천안마다의 승인 역할), 추천안과 그 근거(값 · 출처), 결정 전 상태를 적습니다.
4. **결정 전 실행 이력 보기**: 아직 결정하지 않은 동안 처리 기록에 설비 명령 · 작업지시 단계가 있는지, 「최근 제어 요청 결과」에 새 제어 요청이 생겼는지 적습니다. 승인 기한이 지나 지연 알림이 나오면 그 뒤의 상태도 적습니다.
5. **승인**: [나 고르기]에서 고를 추천안의 승인 역할에 속한 사람을 고르고, 근거를 확인한 뒤 승인합니다. 승인한 사람 · 역할 · 고른 안이 처리 기록에 어떻게 남는지 적습니다.
6. **승인 뒤 이력 대조**: 같은 처리 건 번호로 설비 명령, 재관측 · 경보 해제, 작업지시 번호, 결과 보고와 끝 상태를 하나씩 찾아 적습니다.
7. **둘째 처리 건 열기**: [쿨러 복구]를 눌러 쿨러를 되돌리고 경보가 닫힌 것을 확인한 뒤, [쿨러 열화 주입]으로 새 처리 건을 엽니다. 앞 처리 건과 번호가 다르니 기록을 섞지 않습니다.
8. **거절**: 새 처리 건의 추천 근거를 읽고 거절할 사유를 적어 거절합니다. 거절 사유와 끝 상태, 그 뒤에 설비 명령 · 작업지시가 생겼는지를 처리 기록과 「최근 제어 요청 결과」에서 확인해 적습니다. 끝나면 [쿨러 복구]로 쿨러를 되돌립니다.
9. **대기와 완료 구분**: 두 처리 건마다 「결정을 기다리는 상태」와 「끝난 상태」를 다른 칸에 적고, 처리 건이 끝난 것과 현장 업무(정비)가 끝난 것도 구분합니다.

## 기대 결과를 먼저 적을 사례 종류

처리 건을 열기 전에 아래 경우마다 생겨야 할 기록과 생기면 안 되는 기록을 적습니다. 실행한 뒤 실제와 대조하고, 결과에 맞추려고 먼저 적은 기대를 고치지 않습니다.

- 승인 단계가 열린 뒤 아직 결정하지 않은 동안: 설비 명령 · 작업지시가 있어야 하는지
- 승인 기한이 지나도록 결정하지 않은 경우: 승인 단계가 어떻게 되는지
- 추천안을 승인한 경우: 어떤 기록이 어떤 차례로 생기고, 처리 건이 어떤 상태로 끝나는지
- 사유를 적어 거절한 경우: 무엇이 생기지 않아야 하고, 처리 건이 어떤 상태로 끝나는지

## 학생이 정할 것

- 첫 처리 건에서 어느 추천안을 승인할지, 그 근거 값과 승인 역할을 보고 정합니다. 추천안이 아닌 다른 안을 골랐다면 그 까닭도 적습니다.
- 둘째 처리 건의 거절 사유를 정합니다. 사유는 그 처리 건의 근거 가운데 어느 값 · 조건 때문인지가 드러나게 씁니다.

> 판단 지점: 같은 쿨러 경보라도 승인과 거절은 처리 건에 남는 기록이 다릅니다. 「거절했으니 아무 일도 없었다」로 끝내지 말고, 생기지 않은 기록을 실행 이력으로 확인해 적습니다.

## 완료 조건

- 대조표에 두 처리 건의 번호 · 경보 번호가 있고 기록이 섞이지 않았습니다.
- 처리 건마다 승인 대기 작업 · 담당 역할 · 추천 근거 · 내 결정과 사유가 있습니다.
- 결정 전과 거절 뒤에 설비 명령 · 작업지시가 있었는지 실행 이력으로 확인한 결과가 있습니다.
- 대기 상태와 끝난 상태, 처리 건 완료와 업무 완료가 다른 칸에 있습니다.
- 화면에서 찾지 못한 것은 「찾지 못함」, 직접 보지 않은 것은 「확인하지 않음」으로 남아 있습니다.
