외부 MCP와 내 도구로 다음 협의 안건 만들기

VS Code에서 이 폴더(이 안내 파일이 있는 폴더)를 열고 START.md를 함께 읽으세요. 이 안내는 START.md와 같은 내용입니다.

출발점직접 구현할 것작업 순서진행할 때실행기대 결과를 먼저 적을 사례 종류학생이 정할 것이번 범위 밖완료 조건저장과 다음 실습

내가 정리한 Notion 회의 · 학습 기록을 읽기로 연결하고, 파일 · Git · 시간 MCP 서버와 직접 구현한 점검 메모 조회 도구를 함께 써서 다음 협의 안건을 만듭니다. 안건마다 결정할 질문 · 확인된 사실 · 남은 확인과 그 근거(Notion 페이지 · 파일 · 커밋)가 있어야, 다음 협의에 들어가는 사람이 무엇이 끝났고 무엇을 정해야 하는지 바로 압니다. 모든 서버는 내 PC의 VS Code에서 연결하며 포털에 등록하지 않습니다.

출발점

  • 코드/서버/: 제공 MCP 서버 셋(파일시스템_서버.py 허용 폴더 읽기, 깃_서버.py 변경 이력 읽기, 시간_서버.py 현재 시각)과 공통 뼈대 mcp_기본.py. 각 파일 머리에 실행 방법과 인자가 있습니다.
  • 코드/서버/점검메모_서버.py: 점검 메모 조회 서버의 골격입니다. 서버는 뜨고 도구 목록에 도구 하나가 보이지만, 도구 함수의 본문은 비어 있어 부르면 「아직 구현하지 않은 도구」 오류를 돌려줍니다.
  • 코드/도구/자료_준비.py: 설비보전팀 공유 폴더 코드/업무자료/를 만들고 커밋 다섯 건의 Git 이력을 쌓습니다. 마지막 커밋 뒤에 고친 파일과 새 파일이 커밋되지 않은 채 남습니다. 회의록 두 건, 점검 메모 · 점검 기록, 기준 문서가 들어갑니다.
  • 코드/도구/연결_점검.py: .vscode/mcp.json에 적힌 stdio 서버를 AI 없이 직접 띄워 도구 목록을 보고 도구를 불러 봅니다.
  • 코드/구매팀_자료/: 파일 서버의 허용 범위 밖에 두는 연습 자료입니다.
  • 코드/input/meeting-actions/SKILL.md: 앞 실습의 완성 시작본 회의 스킬입니다. 앞 실습에서 직접 만든 스킬을 써도 됩니다.
  • 코드/source/Notion_내보내기_표본/: 교육용 가상 Notion 내보내기 표본입니다. 자기 Notion 기록이 없으면 이 파일을 자기 Notion에 가져와 연결 대상으로 쓰고, Notion에 연결할 수 없으면 같은 자료의 내보내기로 씁니다.
  • 코드/설정_작성.md: .vscode/mcp.json 형식 예시.
  • 빈 틀: 코드/output/config-notes.md(연결 기록), 코드/output/expected.md(실행 전 기대), 코드/output/다음_협의_안건.md(안건), 코드/output/review.md(호출 · 변경 대조).

직접 구현할 것

무엇내용
연결 설정랩 폴더의 .vscode/mcp.json에 Notion(읽기) · 파일 · Git · 시간 · 내 점검 메모 서버를 적고, 서버마다 도구 목록의 입력 · 반환을 확인합니다
점검 메모 조회 도구점검메모_서버.py의 도구 함수를 구현합니다. 설비 하나의 점검 내용을 근거(파일 · 줄)와 함께 돌려주고, 찾은 것이 없을 때와 읽지 못했을 때를 다른 결과로 돌려줍니다. 이름 · 설명 · 입력 스키마는 바꿔도 되며 바꾼 이유를 기록합니다
다음 협의 안건회의 스킬을 다시 써서 회의록 · Notion 기록의 미결을 모으고, 다른 서버의 결과로 확인된 사실과 남은 확인을 가른 안건을 코드/output/다음_협의_안건.md에 냅니다

안건의 칸마다 어느 서버의 어느 도구 결과에서 왔는지 근거를 남깁니다. 접근에 실패한 자료는 「확인하지 못함」과 사유로 적고, 그 자료에 기대는 내용은 남은 확인으로 둡니다.

작업 순서

  1. 자료 준비: 터미널에서 python 코드/도구/자료_준비.py를 실행하고 출력의 커밋 다섯 건과 커밋하지 않은 변경을 확인합니다.
  2. 탐색만 요청: AI에게 파일을 바꾸지 말고 코드/서버/의 서버들과 점검메모_서버.py 골격, 코드/업무자료/의 자료가 무엇이고 어떤 도구로 무엇을 읽을 수 있는지 설명하게 합니다. 설명을 실제 파일과 대조합니다.
  3. 연결 설정: 설정_작성.md를 보고 .vscode/mcp.json을 직접 만듭니다. Notion은 직접 로그인해 연결하고 쓰기 도구를 끕니다. python 코드/도구/연결_점검.py와 채팅의 도구 목록으로 서버마다 연결 결과 · 도구 이름 · 필수 입력을 config-notes.md에 적습니다. 한 서버가 실패했다고 다른 서버까지 성공이나 실패로 묶지 않습니다.
  4. Notion 기록 읽기: 읽을 자기 회의 · 학습 기록 페이지를 고르고 Notion 도구로 읽습니다. 연결이 안 되면 같은 페이지를 Markdown으로 내보내 코드/source/ 아래 폴더에 두고(또는 제공 표본 폴더를 쓰고), 그 폴더를 파일 서버의 허용 폴더에 하나 더 적어 읽습니다. 이때 config-notes.md에는 MCP 연결 실패와 사유를 그대로 적고 연결 성공으로 적지 않습니다.
  5. 내 도구 구현: 점검 메모 도구가 돌려줄 것을 먼저 자기 말로 정한 뒤 구현합니다. python 코드/도구/연결_점검.py --호출 <서버 이름> <도구 이름> 이름=값으로 AI 없이 직접 불러, 찾은 경우 · 찾은 것이 없는 경우 · 읽지 못한 경우의 결과를 config-notes.md에 적습니다.
  6. 기대 적기: 회의 스킬을 랩 폴더의 .github/skills/ 아래에 복사합니다. 안건을 만들게 하기 전에 아래 사례 종류마다 원자료를 직접 열어 기대를 expected.md에 적고 「기대 칸을 쓴 시각」을 적습니다.
  7. 안건 만들기: 회의 스킬로 미결을 모으고, 파일 · Git · 시간 · 내 도구의 결과를 엮어 다음 협의 안건을 만들게 합니다. 안건의 기준 시각은 시간 서버의 결과로, 회의록의 상대 날짜는 회의 날짜로 해석합니다.
  8. 호출로 거슬러 대조: 안건 문장마다 그 값을 준 호출의 도구 · 입력 · 결과를 review.md에 적습니다. 서로 다른 회의와 후속 변경을 대조해 결정이 사라지거나 같은 일이 두 번 들어가지 않았는지 봅니다. 범위 밖 자료(구매팀_자료) 요청이 거부되고 안건에 「확인하지 못함」으로 남는지도 봅니다.
  9. 수정 · 저장: 다르면 입력 · 기대 · 실제를 함께 주고 고치게 합니다. 저장한 안건을 다시 열어 근거와 맞는지 확인합니다.

진행할 때

  • 채팅에 파일 이름을 쓸 때는 백틱()으로 감쌉니다. 예: 코드/업무자료/점검/쿨러_점검_메모.md`. 채팅 입력이 밑줄(_)을 서식으로 바꿔 이름이 달라질 수 있습니다.
  • AI가 완료를 알리면 부른 서버 · 도구와 실제 결과 원문을 붙여 달라고 요청합니다. 진행 설명은 근거가 아닙니다.
  • AI가 질문 카드(선택지와 「(권장)」 표시)로 물으면, 「(권장)」은 AI의 추천일 뿐입니다. 근거가 되는 원문 · 페이지 · 커밋을 열어 확인한 뒤 고르거나 직접 입력 칸에 결정과 근거를 적습니다.
  • 도구 호출 승인 창이 뜨면 어느 서버의 어느 도구가 무엇을 하려는지 보고, 읽기 도구만 허용합니다. Notion 쓰기 도구 호출은 거절합니다.
  • 파일 편집 승인 창이 뜨면 바뀔 파일이 .vscode/, .github/skills/, 코드/서버/점검메모_서버.py, 코드/output/ 아래인지 보고 허용하고, 아니면 거절합니다.

실행

python 코드/도구/자료_준비.py
python 코드/도구/연결_점검.py
python 코드/도구/연결_점검.py --호출 time get_current_time timezone=Asia/Seoul
python 코드/도구/연결_점검.py --호출 inspection-notes find_inspection_notes equipment=3호기

마지막 명령의 서버 · 도구 이름과 인수는 내가 정한 이름에 맞춰 바꿉니다.

기대 결과를 먼저 적을 사례 종류

  • 앞 회의의 결정이 뒤 회의에서 전달 · 진행으로 이어진 일(전달함 ≠ 발주 완료)
  • 회의록 · Notion 기록과 Git 이력 · 점검 메모의 상태가 다른 일(앞 기록 뒤에 바뀐 것)
  • 마지막 커밋 뒤 커밋되지 않은 변경이 상태를 바꾸는 일
  • 담당이나 기한이 정해지지 않아 다음 협의에서 정해야 하는 일
  • 설비마다 상태가 다른 점검
  • 범위 밖 자료나 연결 실패 때문에 확인하지 못한 일

학생이 정할 것

원자료만으로 하나로 정해지지 않아 학생이 근거를 찾아 정하는 지점입니다. 정한 내용 · 근거 · 바뀌는 안건을 expected.md 「정한 것」 표에 적습니다. AI는 이 지점을 정하기 전에 학생에게 묻습니다.

Notion 기록 · 회의록과 Git 이력 · 점검 메모가 서로 다를 때, 그리고 커밋되지 않은 변경만 다른 내용을 말할 때, 어느 것을 「확인된 사실」로 두고 어느 것을 「남은 확인」으로 둘지 정합니다.

내 점검 메모 도구가 무엇을 어떤 모양으로 돌려줄지(줄 · 표의 행 · 남은 일 같은 절, 근거 표시) 정합니다. 이 결정에 따라 안건의 「남은 확인」이 달라집니다.

이번 범위 밖

Notion · 파일 쓰기(안건을 Notion에 올리기 포함), 커밋 · 되돌리기, 구매팀 자료 읽기 허용, 서버를 HYD 포털에 등록하기, 메시지 · 알림 보내기, 회의록 원문 수정. 개인 GitHub 계정 · push는 필요하지 않습니다.

완료 조건

  • config-notes.md에 서버 다섯 개 각각의 연결 결과(성공 / 실패 / 확인 안 함)와 도구 목록, Notion을 읽은 경로가 있습니다. 내보내기로 이어 갔다면 MCP 연결은 실패로 적혀 있습니다.
  • 내 점검 메모 도구가 구현되어 도구 목록에 보이고, 찾은 경우 · 없는 경우 · 읽지 못한 경우를 직접 불러 본 결과가 있습니다.
  • 다음_협의_안건.md의 안건마다 결정할 질문 · 확인된 사실 · 남은 확인 · 근거(페이지 · 파일 · 커밋 · 호출)가 있고, 기준 시각이 시간 서버의 결과입니다.
  • review.md에 서로 다른 회의와 후속 변경의 대조가 있고, 결정이 사라지거나 중복된 곳이 없습니다.
  • 접근 실패를 업무 없음으로 적은 곳이 없습니다.

저장과 다음 실습

.vscode/mcp.json, 스킬 폴더, 점검메모_서버.py, 코드/output/을 저장하고 다시 열어 확인하세요. Notion 로그인 정보는 어디에도 적지 않습니다. 보관할 파일은 재부팅 전에 USB 또는 개인 클라우드에 복사하세요. 다음에는 에이전트 · 스킬 · MCP의 역할을 함께 정리하고, 다음 회차에서 사람의 승인과 확인 질문으로 이어 갑니다.
