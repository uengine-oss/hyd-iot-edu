# 점검 요청 초안의 입출력 계약

이 문서는 입력과 결과의 형식·뜻만 정합니다. 원인을 가리는 기준은 `source/ontology/`의 증거와 `source/manuals/`의 원문에 있습니다.

## 입력

- `source/ontology/graph.json`, `schema.json`: 설비·구성 요소·이상 패턴·증상·고장 유형·원인·증거·조치 방법의 노드와 관계. 읽는 법은 `source/ontology/README.md`.
- `source/cases/cases.json`: 경보 사례 S01~S11. 칸의 뜻은 `source/cases/README.md`. 제공된 과거 입력이며 지금 설비의 값이 아닙니다.
- `source/manuals/`: HM-8 · PM-02 · PR-07 원문과 `문서_목록.csv`.
- `.env`와 `llm_client.py`: 모델 접속. `llm_client.chat(messages, tools)`가 대화와 도구 목록을 보내고 모델의 답 한 건을 돌려줍니다.

## 출력 output/점검요청_초안.json

```
{
  "모델": ".env의 LLM_MODEL 값",
  "실행_시각": "2026-..T..:..",
  "사례": [
    {"id": "S01", "설비": "HYD-01", "경보": "COOLER_DEGRADATION", "판단_시각": "cases.json의 time",
     "상태": "요청 초안 | 보류",
     "원인_후보": [
       {"cause": "cause:...", "근거_상태": "SUPPORTED | UNKNOWN | UNSUPPORTED",
        "증거": [{"evd": "evd:...", "tag": "CE", "aggregate": "avg", "windowSeconds": 30,
                 "값": 숫자 또는 null, "기준": "lt 70", "결과": "맞음 | 안 맞음 | 확인 못함",
                 "확인_못한_이유": "결과가 확인 못함일 때", "출처": "HM-8.4 또는 없음", "호출": [3]}]}
     ],
     "점검_요청": {
       "대상_설비": "HYD-01", "구성_요소": "comp:...",
       "부품": [{"이름": "...", "번호": "원문의 부품 번호 또는 null", "출처": "문서 · 절", "호출": [5]}],
       "관측_시각": "값을 읽은 시각", 
       "관측값": [{"tag": "CE", "aggregate": "avg", "windowSeconds": 30, "값": 숫자 또는 null, "호출": [3]}],
       "확인_항목": [{"항목": "현장에서 확인할 것", "이유": "어느 근거 때문인가", "출처": "...", "호출": [3, 4]}],
       "다른_후보": ["cause:..."],
       "표시": "점검 요청 초안이며 확정 원인도 작업지시도 아니라는 문장"
     } 또는 null,
     "보류": {"이유": "...", "빠진_것": ["..."]} 또는 null,
     "calls": [{"번호": 1, "도구": "...", "입력": {...}, "결과": ..., "오류": null 또는 "오류 문장"}],
     "멈춘_까닭": "답을 냄 | 반복 한도 | 같은 호출 반복 | 오류"}
  ]
}
```

- `사례`의 순서와 구성은 `cases.json`과 같습니다. 사례 한 건마다 에이전트를 한 번 돌립니다.
- `calls`는 에이전트가 실제로 부른 도구를 부른 순서대로 적은 호출 기록입니다. 프로그램이 대신 실행한 결과를 그대로 적습니다. 실패한 호출은 `오류`에 적고 지우지 않습니다.
- 결과의 `호출`은 그 값을 돌려준 `calls`의 `번호`입니다. 오류가 난 호출을 근거로 쓰지 않습니다.
- `상태`가 `요청 초안`이면 `점검_요청`을 채우고 `보류`는 `null`, `보류`이면 그 반대입니다. 둘을 함께 내지 않습니다.
- 값을 읽지 못했거나 묵었거나 표본이 모자란 증거는 `값`을 지어내지 않고 `null` 또는 읽은 값 그대로 두고 `결과`를 `확인 못함`으로, 이유를 `확인_못한_이유`에 적습니다.
- `cause:`·`evd:`·`comp:` 식별자는 graph.json에 있는 것만 씁니다. 부품 번호는 원문에 있는 것만 씁니다.
- `output/점검요청_초안.md`는 같은 내용을 사례마다 절로 나눠 점검 담당자가 읽게 씁니다. 각 절 제목에 사례 id를 넣습니다.
