# 실전반 4회차 실습 4 — MCP도구연결

> [제작 안내 — 낭독하지 않음] 강사 단독 시연 대본이다. 조작·AI 응답·접속·실행·캡처는 이번 제작에서 수행하지 않았다. 실제 결과가 나온 뒤 그 값과 근거를 읽고, 다르면 원인을 고쳐 다시 확인한다. 성공을 미리 낭독하지 않는다.

## 다운로드와 출발 자료 확인

내 Notion 회의 기록과 파일·Git·시간 서버, 직접 만든 점검 메모 조회 도구를 엮어 다음 협의 안건을 만들겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] MCP도구연결 ZIP을 내려받아 압축을 풀고 VS Code에서 그 폴더를 열겠습니다. START.md에서 과제와 완료 조건을 읽습니다. 모든 서버는 이 PC의 VS Code에서 연결하고 HYD 포털에는 등록하지 않습니다. 연결 결과는 코드/output/config-notes.md에 서버마다 나눠 적겠습니다.

출발 자료를 보겠습니다. 코드/서버에는 제공 서버 셋과 직접 구현할 점검메모_서버.py 골격이 있습니다. 골격은 도구 목록에는 보이지만 부르면 아직 구현하지 않았다는 오류를 돌려줍니다. 코드/input에는 앞 실습의 회의 스킬 시작본이, 코드/source에는 Notion에 연결하지 못할 때 쓰는 교육용 내보내기 표본이 있습니다.

## 로컬 작업 자료와 서버 설정

코드/도구의 자료_준비.py를 열어 어떤 폴더와 Git 이력을 만드는지 읽겠습니다. 터미널에서 python 코드/도구/자료_준비.py를 실행하면 코드/업무자료가 준비됩니다. 이미 업무자료가 있으면 그대로 두는 기본 실행만 사용하겠습니다. 다시 만들기 옵션은 쓰지 않습니다. 업무자료와 제공된 구매팀_자료는 연습용 자료이며 실제 업무 저장소가 아닙니다.

> [조작] 이번 제작에서는 자료 준비도 실행하지 않는다. 수업에서 Python·Git과 도우미의 MCP 지원을 확인하고 오류를 기록한다. 서버 시작 전에 실제 절대경로와 실행 주체를 확인한다.

연 랩 폴더 아래에 .vscode/mcp.json을 만들겠습니다. 최상위 servers 아래 notion, filesystem, git, time과 내 점검 메모 서버를 각각 둡니다. Notion은 원격 서버 주소를 적고 처음 연결할 때 직접 로그인합니다. 연결 뒤 쓰기 도구는 도구 선택에서 끕니다. 각 항목의 type은 stdio, command는 교육 환경의 Python 실행 파일로 정하고 args에 해당 서버 스크립트의 절대경로를 넣습니다. 파일 서버에는 --read-only와 업무자료 절대경로, Git 서버에는 --repository와 같은 업무자료 경로를 추가합니다. 시간 서버에는 서버/시간_서버.py 경로와 시간대를, 점검 메모 서버에는 --folder와 업무자료의 점검 폴더를 넣습니다. 제공 설정_작성.md의 형식과 실제 경로를 대조하며 적겠습니다.

이 로컬 설정은 이론의 HYD mcpServers 설정을 그대로 붙여 넣는 것이 아닙니다. VS Code는 이 파일의 servers를 읽습니다. 로컬 경로는 포털 서버에서 보이지 않으므로 포털에 등록하지 않겠습니다.

## 연결하고 내 도구 구현하기

서버를 각각 시작하고 도구 목록을 확인하겠습니다. stdio 서버는 python 코드/도구/연결_점검.py로 AI 없이 직접 확인하고, Notion은 채팅의 도구 목록으로 확인합니다. 파일 서버의 허용 폴더와 읽기 전용 모드, Git 서버의 대상 저장소, 시간 서버의 시간대 입력을 기록합니다. 실패하면 실행 파일·스크립트 경로·대상 폴더·서버 오류를 순서대로 확인합니다. 한 서버가 실패했다고 다른 서버까지 성공이나 실패로 묶지 않겠습니다. Notion에 연결하지 못하면 같은 페이지의 내보내기 파일로 이어 가되, config-notes.md에는 연결 실패와 사유를 그대로 적고 연결 성공으로 쓰지 않겠습니다.

이제 점검메모_서버.py의 도구 함수를 구현하겠습니다. 무엇을 어떤 모양으로 돌려줄지 먼저 정하고, 결과마다 파일과 줄을 근거로 붙입니다. 찾은 것이 없을 때와 읽지 못했을 때는 다른 결과로 돌려줍니다. 연결_점검.py의 --호출로 세 경우를 직접 불러 보고 결과를 기록하겠습니다.

## 다음 협의 안건 만들기

회의 스킬 시작본을 .github/skills 아래로 복사하고, 안건을 만들게 하기 전에 expected.md에 기대를 먼저 적겠습니다. 그다음 ‘회의 스킬로 회의록과 내 Notion 기록의 미결을 모으고, 업무자료의 점검 메모와 내 점검 메모 도구, Git의 최근 변경과 아직 커밋하지 않은 변경을 확인해, 시간 도구의 Asia/Seoul 현재 시각을 기준으로 다음 협의 안건을 만들어 주세요. 안건마다 결정할 질문·확인된 사실·남은 확인과 페이지·파일·커밋 근거를 남기고, 과거 회의록의 상대 날짜는 회의 날짜를 기준으로 해석해 주세요’라고 요청하겠습니다. 도구가 실제로 호출됐는지 기록을 펼쳐 보고 코드/output/다음_협의_안건.md의 각 문장을 원문과 이력으로 대조합니다. 서로 다른 회의와 후속 변경을 맞춰 보아 결정이 사라지거나 같은 일이 두 번 들어가지 않았는지도 review.md에 적겠습니다. 현재 시간과 문서 작성 날짜를 섞어 옛 기한을 새 기한으로 바꾸지 않겠습니다.

## 실패와 권한 경계 확인

연습용 구매팀_자료는 파일 서버 허용 범위 밖에 두었습니다. 그 파일을 요청했을 때 접근이 거부되고 미확인으로 남는지 보겠습니다. 범위를 몰래 넓히는 대신 이 요청에서 필요하지 않은 자료라고 기록합니다. 결과가 일부만 보이면 읽은 범위를 적고 필요한 구간을 다시 확인합니다. 조회 실패나 시간 초과는 값 없음이나 업무 완료로 바꾸지 않겠습니다.

설정 파일, 스킬 폴더, 점검메모_서버.py, 서버별 목록과 호출 기록, 다음 협의 안건, 오류와 수정 내역을 저장하겠습니다. 다시 열어 안건의 페이지·파일 근거와 Git 변경, 기준 시각이 서로 맞는지 봅니다. 서버 연결 성공과 답변의 정확성은 별개입니다. 네 실습에서 남긴 근거를 기준으로 이제 에이전트·스킬·MCP의 역할을 함께 정리하겠습니다.
