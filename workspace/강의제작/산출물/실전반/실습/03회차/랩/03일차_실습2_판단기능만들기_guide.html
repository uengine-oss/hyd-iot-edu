원천 기록에서 판단 입력을 만들고 조건표로 판정 · 비교하는 제공 흐름에, 방향이 갈리는 판단 두 자리를 내가 구현해 끼우고 결과 화면에서 기대 · 원천 줄과 대조합니다. 결과는 담당자가 읽는 조치 검토 결과로 나옵니다. 단계마다 「요청에 담을 것」 다섯 칸을 내 말로 채워 AI에게 요청하고(그대로 보내는 글이 아니며, 값은 원자료에서 찾습니다), 「증거」를 확인한 뒤 다음 단계로 갑니다. 막히면 「정답 보기」를 펼칩니다.

01 폴더와 출발점 확인 · 결과 화면 열기

포털에서 순위가 높아도 금지 조건에 걸리면 고를 수 없는 이유를 결과에서 찾았습니다. 이번에는 조치 조건표로 사건과 지난 30일 경보를 원천 기록에서 직접 판정하고, 담당자가 읽고 바로 결정할 수 있는 조치 검토 결과로 완성합니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건, 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보 ALT-hyd02-0172-54a5입니다(경보 ID로 자료 · 결과 화면에서 찾습니다).

판정 기능은 조건표를 읽어 후보마다 경고 · 감점 · 제외와, 입력이 없어 맞는지 알 수 없는 정보 부족을 이유와 함께 내고, 허용 후보만 주어진 비교 산식으로 견줍니다 — 조치 검토 결과는 후보마다 그 판정과 이유 · 원문 출처 · 추가로 확인할 값 · 승인 역할을 담습니다. 판단 입력은 원천 네 곳(경보 · PLC 상태 · 팬 카운터 · 예측)에 흩어져 있고, 경보 60건마다 후보가 넷이라 손으로 다 맞출 수 없습니다.

원천 읽기 · 시각 · 단위 · 판정 · 산식 · 결과 쓰기는 제공 코드가 하고, 끊긴 기록을 어떻게 볼지와 어느 후보를 견줄지 — 쓰는 사람에 따라 방향이 갈리는 판단 — 는 내가 정할 자리에 AI와 구현합니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 판단 지식 — 조건표로 조치를 판정하고 견주는 일 — 를 맡습니다.

받기 노션 「가이드문서」에서 이 실습의 ZIP을 받아 압축을 풀면, 풀린 폴더 안에 실습 폴더와 이 가이드가 나란히 있습니다. 가이드는 브라우저로, 실습 폴더는 VS Code의 파일 → 폴더 열기(File → Open Folder)로 엽니다 — 그 위 폴더를 열면 AI가 정답이 든 가이드까지 읽습니다. 이어서 할 때는 같은 실습 폴더를 다시 엽니다. 필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot.

처음 열 때 폴더를 신뢰할지 물으면 신뢰합니다 — 제한 모드(Restricted Mode)에서는 AI 채팅이 동작하지 않습니다. 왼쪽 탐색기(Explorer)에서 폴더 이름을 확인하고 START.md를 엽니다. AI 계정이 없거나 정답을 보고도 막히면 따로 받는 학생용 완성본으로 결과를 봅니다.

왜 무엇이 주어졌고 이 답을 누가 쓰는지 알아야 AI에게 같은 출발점을 말할 수 있습니다.

할 일 VS Code 탐색기에서 입력/ · 자료/ · 결과/ · START.md를 열어 각 자리의 역할과 이번 질문을 확인하고, 터미널에서 python show_result.py를 실행해 결과 화면을 엽니다.

해결할 질문 이 답은 야간 운전원과 설비보전팀장이 이 검토 결과만 읽고 어느 후보를 승인 요청할지, 무엇을 먼저 확인할지 정할 때 씁니다.

  1. 사건의 네 후보 — 판단 입력(원천 네 개, 판정을 요청한 시각 기준) · 판정(유지 · 제외 · 보류와 이유) · 비교값과 순위는 무엇인가?
  2. 같은 기능이 지난 경보의 경계값 · 제외 사유와 누락이 겹친 입력 · 모두 제외된 입력에서 기대와 같은가?
  3. 사건에서 승인 요청을 검토할 후보와 그 까닭은 무엇인가? 후보마다 이유 · 원문 출처 · 추가로 확인할 값 · 승인 역할은 무엇이고, 비교 순위는 실행 승인과 어떻게 다른가?

말 풀이 경고는 그 조치에 주의할 점이 있다는 사유, 감점은 비교할 때 금액으로 깎는 사유, 제외는 그 조치를 쓸 수 없는 사유입니다. 판정은 그 사유를 모아 유지 · 제외 · 보류로 나뉩니다 — 보류는 제외 사유는 없지만 입력이 없어 맞는지 알 수 없는 규칙이 있는 후보이고, 세 말의 뜻은 자료/작업기준.md 4절에 있습니다. 판단 입력은 규칙이 견주는 값(예측 유온 · 운전 모드 · 팬 연속 시간 등)이고 원천은 그 값이 기록된 곳, 비교 합계는 주어진 산식의 네 손실과 감점을 더한 값입니다. 검토 의견은 사례마다 승인 요청을 검토할 후보와 그 까닭, 먼저 확인할 값입니다. 제공 코드는 누가 해도 같은 일(파일 읽기 · 원문 인용 · 조건표 적용 · 계약 꼴 쓰기 · 검사)을 하는 받은 코드이고, 정할 자리는 결과/의 「제공 빈 틀」 파일 — 방향이 갈리는 판단을 내가 AI와 채우는 곳입니다. python show_result.py가 채운 자리까지 제공 코드를 돌려 결과/보기.html에 단계마다 결과를 보입니다. 계약은 결과 파일의 모양(열 · 키와 그 뜻)을 정해 둔 입출력_계약.md입니다 — 다음 실습의 기능이 이 모양 그대로 읽습니다.

내 조건표를 쓸 때: 제공 입력은 그대로 두고 내 조건표.csv를 결과/내_입력/에 복사해, 열 이름 · 규칙이 거는 후보가 입출력_계약.md와 같은지 먼저 견준 뒤 씁니다. 제공 코드와 구조 검사는 결과/내_입력/에 있는 파일을 기준으로 봅니다. 내 조건표가 없어도 제공된 조건표로 끝까지 할 수 있습니다.

터미널 → 새 터미널(Terminal → New Terminal)로 이 실습 폴더에서 터미널을 엽니다. 명령은 직접 치지 말고 블록의 복사로 붙여 넣습니다(손으로 옮기면 오타가 납니다). 오류로 멈추면 명령과 출력 전문을 AI 채팅에 보내 까닭부터 묻습니다. 명령은 AI 채팅이 아니라 이 터미널에서 내가 실행합니다.

결과 화면 여는 법 python show_result.py가 결과/보기.html을 새로 쓰고 처음 한 번 브라우저로 엽니다(안 열리면 탐색기에서 그 파일을 오른쪽 클릭 → Reveal in File Explorer → 두 번 클릭). 단계 띠의 「비어 있음 · 채움 · 오류」를 보고, 다시 실행한 뒤 F5를 누릅니다.

정할 것 이번 질문과, 이 답을 쓰는 사람이 누구인지 확인합니다.

터미널(PowerShell · 이 실습 폴더)

증거 탐색기에서 네 자리를 찾았고, 입력/조건표.csv가 규칙을, 자료/의 원천 기록이 판단 입력을 담는다는 것을 파일에서 확인했습니다. 결과 화면 1단계에 경보마다 판정 요청 직전 원천 기록이 보입니다. 결과 화면 맨 위 단계 띠에 이 실습의 단계가 보이고, 정할 자리가 있는 단계는 「비어 있음」입니다.
다를 때 보일 자리가 없으면 다른 실습이거나 덜 풀린 것이니 노션 「가이드문서」에서 ZIP을 다시 받아 풉니다.

02 파일을 바꾸지 않고 자료 파악

왜 원천마다 기록 주기 · 단위 · 시각 표기와 값이 비는 까닭이 다르고, 판정을 요청한 시각까지의 기록만 써야 결과를 다시 만들 수 있습니다. 그 일반 처리(시각 맞추기 · 단위 · 하트비트 · 유효 시간)는 제공 코드가 자료/수집_설명.md대로 하고, 끊긴 기록을 어떻게 볼지만 내가 정합니다.

할 일 AI에게 파일을 바꾸지 말고, 원천 네 개(경보 · PLC 상태 · 팬 카운터 · 예측)와 조건표 · 계약이 각각 무엇을 어떤 모양으로 담는지 파일:줄로 짚어 달라고 합니다. 결과 화면 1단계 표에서 판정 요청 직전 기록이 그 원천의 주기보다 오래된 경보 하나를 골라 원천 줄을 직접 엽니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘으로, GitHub Copilot은 같은 채팅 창의 Chat 탭으로 엽니다. 답에 나온 줄은 편집기에서 직접 열어 읽고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit the following file?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누릅니다.

정할 것 원천마다 값이 비는 까닭이 몇 가지인지 묻습니다 — 칸이 빈 것뿐 아니라, 정해진 주기로 와야 할 기록이 오지 않은 곳(마지막 기록에서 판정 요청까지도)과 유효 시간이 지나 쓸 수 없는 값까지.

다를 때 짚은 줄이 없거나 다르면 근거로 쓰지 않고 다시 찾게 합니다. 편집 승인 창이 뜨면 Deny를 누릅니다.

03 기대 판정 먼저 적기

왜 실행하기 전에 기대를 먼저 적어 두어야, 결과가 다를 때 판단 입력 · 판정 · 기대 가운데 어디가 틀렸는지 근거로 가릴 수 있습니다. AI가 낸 결과를 기대로 옮기면 틀린 결과도 맞아 보입니다.

할 일 결과/기대결과.md에 목표 · 쓰는 사람 · 지킬 조건을 적고, 사건의 네 후보와 카운터 기록이 끊긴 경보 하나, 모든 후보가 제외될 것 같은 경보 하나, 예측 값이 조건표 기준값과 같거나 가장 가까운 경계 경보 하나의 기대 판정을 원천 줄 · 조건표 · 원문으로 손으로 구해 결과/기대_판정.csv에 근거 줄과 함께 적습니다. 다 쓰면 「기대 칸을 쓴 시각」을 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.

아래 지점은 지금 적지 않고 5 · 6단계에서 원문을 열어 정한 뒤 결과/정한_것.csv에 적습니다. 여기서는 어떤 지점이 있는지만 봐 둡니다.

고친 파일은 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 결과/정한_것.csv에 한 줄씩 적습니다.

  • 빈 값의 뜻 — 정해진 주기로 남아야 할 기록이 빠져 판정을 요청한 때의 값을 기록에서 바로 읽을 수 없을 때, 끊긴 구간을 이어 판단 입력을 만들지 — 어느 원천의 어느 경보에 그런 구간이 있는지, 이을 근거가 원천에 있는지는 원천에서 찾습니다
  • 쓰는 사람에 따라 갈리는 답 — 경고가 붙은 후보를 비교 산식으로 견주는 후보에 넣을지
  • 비교 기준 문장 — 이 비교 합계가 무엇을 견주는 값인지, 포털 성과 지표의 점수 · 실행 승인과 어떻게 다른지 내 말로

질문 카드의 「(권장)」은 AI의 추천일 뿐이니, 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정할 것 경보는 결과 화면 1단계의 사실과 AI에게 판정 · 순위를 빼고 위치만 찾게 한 목록으로 고르고, 기대 판정은 그 줄을 열어 내가 구합니다.

04 계획 검토

왜 판단 입력 · 판정 · 비교를 한 번에 만들면 결과가 다를 때 어느 부분이 틀렸는지 찾기 어렵습니다. 갈리는 판단을 자리 하나씩 정하고 결과 화면에서 확인해야 다른 줄의 원인을 한 곳으로 좁힐 수 있습니다.

할 일 제공 코드(judge_tools.py)가 판단 입력 → 판정 → 비교 → 결과 쓰기 가운데 어디서 두 정할 자리를 부르는지 AI에게 짚게 하고, 5 · 6단계 순서를 검토하고 동의합니다. 아직 파일을 만들지 않습니다.

정할 것 판정에서 정보 부족(보류)을 어떤 경우에 내는지가 내 기대와 같은지 묻습니다. 고른 것은 의견처럼 말하지 않고, 무엇으로 정했는지와 그 근거 줄을 단정해서 말합니다 — 의견으로 말하면 AI가 결정으로 받지 않고 다시 묻습니다.

05 빈 값의 뜻 — 끊긴 카운터 기록

왜 판단 입력은 원천마다 기록 방식이 달라, 값이 없는 입력은 0이나 앞 값으로 채우지 않고 까닭과 함께 남겨야 규칙이 무엇을 근거로 판정했는지 따라갈 수 있습니다. 입력이 없어 확인할 수 없는 조건은 거짓과 달라 보류로 남기고, 이미 확인된 제외 사유는 다른 입력이 빠져도 그대로입니다.

할 일 결과/gap_rule.py의 함수를 AI와 채워, 카운터 기록이 판정 요청 전에 끊긴 경보의 팬 100 % 연속 시간을 내 결정대로 냅니다. 고른 것 · 근거를 결과/정한_것.csv에 한 줄 적고, 결과 화면에서 끊긴 경보의 값과 판정을 3단계 기대와 견줍니다. 실행은 내가 터미널에서 하고, AI가 답에 옮겨 적은 출력이 아니라 터미널에 나온 출력과 결과 화면으로 확인합니다 — 옮겨 적은 글은 실제 출력과 다를 수 있습니다.

정할 것 끊긴 구간을 이을지, 잇는다면 원천의 무엇을 근거로 할지 내가 정합니다. AI가 결정을 대신 정하려 하면 돌려보내고 내 선택과 근거를 다시 말합니다.
