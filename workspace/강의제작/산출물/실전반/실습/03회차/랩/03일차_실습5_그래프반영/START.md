# 검토 지식으로 작업 확인 카드 만들기

## 목표

포털 데이터 연결에서 현재 값을 문서의 기준값과 나란히 놓고 구분했습니다. 이번에는 검토한 문서 지식을 별도 랩 DB의 기존 ID에 잇고 핀 세척의 작업 확인 카드를 만듭니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건인 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보이고, 그 판정 뒤에 남은 근본 조치가 핀 세척(`SOP-COOL-14`)입니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 온톨로지 단계의 마지막 — 검토한 문서 지식을 그래프에 잇고 질문으로 확인하는 일 — 을 맡습니다.

만들 것: 정할 자리(그래프 모양 · 연결 규칙 · 별칭 · 다른 문서의 조건 · 역할 · 질문 값 · 현재 값 원천 · 기대 답 · 고른 것)와, 결과 화면이 그 자리로 만드는 스키마 확장 `결과/schema_ext.json` · 적재 파일 `결과/load.cypher` · 조회문 `결과/query.cypher` · 작업 확인 카드 둘(`결과/작업확인카드_<SOP ID>.md`) · 남은 질문 `결과/남은_질문.json` · 내보내기 `결과/지식_내보내기.json`, `결과/구축_기록.md`.

## 출발점

- `입력/모델/` — 설비 모델(schema.json · graph.json). `입력/조건표.csv` · `입력/sop.json` — 냉각 계통 조치의 조건표와 SOP 구조. `입력/조치검토결과.json` — 그 조건표로 지난 30일 경보를 판정 · 비교한 조치 검토 결과.
- `입력/검토결과/` — 문서마다 후보와 결정(채택 · 수정 · 제외 · 보류) · 근거를 적은 검토 결과 · 이 사건의 작업의 조건(`선택작업_조건.json`). 문서에서 지식을 추출 · 검토하는 실습의 결과와 같은 꼴로 검증해 제공하는 판입니다.
- 내 앞 결과를 쓸 때: 제공 입력은 그대로 두고 내 검토 결과 · 모델 등을 `결과/내_입력/`에 `입력/`과 같은 이름 · 같은 자리로 복사해, 형식이 `입출력_계약.md` 「입력」과 같은지 먼저 견준 뒤 씁니다. 제공 코드와 `check.py`는 `결과/내_입력/`에 있는 파일을 씁니다. 내 결과가 없어도 제공된 입력으로 끝까지 할 수 있습니다.
- `자료/` — 검토한 문서의 원문과 `자료/문서_목록.csv`(문서마다 판 · 상태 · 시행일 · 파일 · SHA-256).
- `python show_result.py` · `lab_steps.py` — 결과 화면(`결과/보기.html`)을 쓰는 제공 파일. `doc_graph.py` — 정할 자리대로 적재 · 조회 · 카드 · 내보내기를 하는 제공 코드. `lab_db.py` — 이 폴더 전용 랩 DB(그래프 DB)를 켜는 도구. `lab_cypher.py` — 랩 DB에 Cypher를 실행하는 공용 도구.
- `입출력_계약.md` — 입력 · 정할 자리 · 결과 파일의 형식. `check.py` — 결과의 구조 검사.
- `결과/` — 정할 자리(「제공 빈 틀」 파일)와 `구축_기록.md`.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.

## 처음 쓰는 도구

- `python lab_db.py` — 이 폴더 전용 랩 DB를 켭니다(Docker Desktop이 켜져 있어야 함).
- `python show_result.py` — 채운 정할 자리까지 적재 · 조회를 돌려 `결과/보기.html`을 다시 씁니다. 처음 한 번은 브라우저로 엽니다.

## 해결할 질문

이 답은 보전 야간조가 핀 세척 전에 카드로 준비 · 금지 · 완료를 원문으로 되짚고, 설비보전팀장이 승인할 때 씁니다.

1. HYD-02 핀 세척 카드의 항목마다 내용과 원문 절 · 인용은?
2. 다른 작업의 카드도 만들어지고, 원문이 없는 작업 · 절은 「결과 없음」으로 구별되는가?
3. 다시 적재해도 수가 같은가? 공급 정보 · 작업 조건을 어디까지 답하고, 현재 값 · 승인 없이 정할 수 없는 것은?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **다른 문서의 조건** — 다른 문서의 조건 · 시간 · 승인을 핀 세척(`SOP-COOL-14`)에 이을지
- **그래프 모양과 연결** — 어떤 종류 · 관계 · ID로 담고 어느 기존 ID에 이을지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 문서에서 후보를 다시 뽑거나 검토 결정을 바꾸는 일 — 바꿀 것은 남은 질문으로 남깁니다
- 포털 DB에 접속하거나 포털 자료를 랩 DB에 넣는 일
- 현재 값(재고 · 작업지시 상태 · 센서 값)을 그래프에 넣는 일
- 설비 모델의 기존 ID · 기존 종류 · 관계의 뜻을 바꾸는 일

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

파일의 모양은 `입출력_계약.md`에 있습니다. 무엇을 어떤 종류 · 관계로 담을지, 새 대상의 ID를 어떻게 지을지, 무엇을 어느 기존 ID에 이을지는 정할 자리에 내가 정합니다.

- 정할 자리 — `결과/기대_답.csv` · `결과/그래프_모양.json` · `결과/연결_규칙.csv` · `결과/별칭.csv` · `결과/다른문서_조건.csv` · `결과/역할.csv` · `결과/질문_값.csv` · `결과/현재값_원천.csv` · `결과/정한_것.csv`(계약 「정할 자리」).
- 결과 화면이 쓰는 것 — `결과/schema_ext.json` · `결과/load.cypher` · `결과/query.cypher` · `결과/남은_질문.json` · `결과/지식_내보내기.json` · `결과/작업확인카드_<SOP ID>.md` · `결과/보기.html`.
- `결과/구축_기록.md` — 「제공 빈 틀」의 칸대로 채웁니다.

## 지킬 조건

- `입력/` · `자료/`는 읽기만 합니다. 제공 파일(`show_result.py` · `lab_steps.py` · `doc_graph.py` · `lab_cypher.py` · `lab_db.py` · `check.py`)은 고치지 않습니다.
- 승인(`approved`) 후보만 적재합니다.
- 기존 ID를 바꾸지 않고, 모델에 없는 기존 ID를 지어내지 않습니다.
- 현재 값(재고 · 작업지시 상태 · 센서 값)은 그래프에 넣지 않고 읽을 원천을 가리킵니다.
- 전체를 지우는 문장을 쓰지 않습니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(ZIP을 풀면 이 폴더 옆에 있는 `_guide.html` 파일)의 같은 번호에 있습니다.

1. **새 폴더 · 랩 DB 준비** — `python lab_db.py`로 랩 DB를 켜고 `python show_result.py`를 실행해 설비 모델 · 조치 기준의 종류별 수를 `결과/구축_기록.md` 「적재 수」 첫 줄에 적습니다.
2. **기대 카드 먼저** — `결과/기대_답.csv`에 카드 항목마다 기대를 원문 · 검토 결과의 파일:줄로, `결과/구축_기록.md`에 목표 · 쓰는 사람 · 기대 칸을 쓴 시각을 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
3. **판단① 그래프 모양 — 종류 · 관계 · ID** — `결과/그래프_모양.json`에 문서 · 판 · 절 · 지식과 관계의 이름 · 뜻 · ID 꼴을 정하고 까닭을 `결과/정한_것.csv`에 적은 뒤 `python show_result.py`로 적재 없이 센 수를 봅니다.
4. **판단② 연결 규칙 · 별칭 · 역할** — `결과/연결_규칙.csv`에 카드에 닿는 문서(와 절)의 승인 후보를 어느 기존 ID에 이을지, 필요하면 `결과/별칭.csv` · `결과/역할.csv`를 적고 `python show_result.py`로 적재합니다.
5. **판단③ 다른 문서의 조건 · 반복 적재** — 핀 세척에 걸 다른 문서의 조건(시간 · 승인 · 준비)을 `결과/다른문서_조건.csv`에 잇는다 · 잇지 않는다로, 고른 것을 `결과/정한_것.csv`에 적고 `python show_result.py`를 두 번 실행해 수가 늘지 않는지 봅니다.
6. **판단④ 작업 확인 카드 — 현재 값을 읽을 원천** — `결과/질문_값.csv`에 물을 작업 · 절을, `결과/현재값_원천.csv`에 확인할 현재 값과 원천을 적고 `python show_result.py`로 `결과/작업확인카드_SOP-COOL-14.md`를 기대와 견줘 `결과/구축_기록.md`에 적습니다.
7. **다른 작업 카드와 답할 수 있는 범위** — `python show_result.py`로 다른 작업의 카드 · 제공되지 않은 작업과 절 · 남은 질문을 보고 `결과/구축_기록.md` 「다른 작업 · 제공되지 않은 것」과 「답할 수 있는 것과 없는 것」에 적습니다.
8. **내보내기 · 저장하고 다시 열기** — `python show_result.py`의 마지막 단계가 내보내기와 `python check.py`를 돌립니다. 저장 뒤 폴더를 닫았다 다시 열어 `python lab_db.py` · `python show_result.py`를 다시 실행하고 `결과/구축_기록.md` 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/연결_규칙.csv`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 보류 · 제외 후보가 그래프와 카드에 들어가지 않았는지
- 같은 적재를 두 번 했을 때의 수
- 절차 밖 절 · 다른 절차 · 다른 문서에 있는 작업 조건
- 설비 별칭 · 제조사 품번으로 적힌 대상
- 다른 작업의 카드
- 제공되지 않은 작업 · 절을 묻는 질문
- 공급 조건(설비 모델)과 그날의 재고 · 승인의 경계

실행 명령:

```
python lab_db.py
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/` · `자료/`가 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 카드 항목마다 먼저 적은 기대와 실제 카드가 원문 줄로 맞고, 다른 작업 카드와 「결과 없음」이 구별되며, 같은 적재를 다시 해도 수가 같고, `결과/정한_것.csv`의 근거와 그 선택으로 바뀌는 답을 설명할 수 있으면 완료입니다. 답하지 못한 것은 남은 질문으로 남깁니다.
