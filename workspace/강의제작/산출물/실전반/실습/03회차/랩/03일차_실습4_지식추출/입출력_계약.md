# 입출력 계약

입력과 결과 파일의 형식과 뜻만 정한다. 어떤 문장을 어떤 후보로 만들지, 문서를 어떤 단위로 나눌지는 정하지 않는다. 다음 실습은 같은 모양의 검토 결과를 입력으로 읽는다. `check.py`가 이 계약의 구조와 인용을 검사한다.

## 1. 입력(읽기만)

- `입력/조건표.csv` — 조건표. 열 `rule_id,action,condition_index,logic,input,operator,value,unit,boundary_included,result,penalty_manwon,reason,source_section`. 비교 하나가 한 행이고, 같은 `rule_id` · `action`의 행이 한 규칙 묶음이다. `action`은 그 규칙이 걸리는 조치(SOP ID), `input` · `operator` · `value` · `unit`은 비교, `result`는 `WARN`(경고) · `PENALTY`(감점) · `EXCLUDE`(제외), `reason`은 규칙의 이유, `source_section`은 그 규칙을 가져온 곳이다.
- `입력/sop.json` — SOP 구조. `document`가 가리키는 문서(식별자 · 판 · 파일)의 조치 절차를 구조로 옮긴 것이다. sop.json 키의 뜻: `document` 원문 문서, `failure_modes` 고장 유형, `causes` 원인, `sops` 조치 절차(`id` · `name` 이름 · `kind` 조치 종류(없으면 null) · `codes` 실행 코드 · `source` 출처 · `failure_mode` 고장 유형 · `model_refs` 모델 참조 · `apply_conditions` 적용 조건 · `prohibitions` 금지 조건 · `steps` 수행 단계 · `completion` 완료 기준 · `approval` 승인(`role` 역할)), `relations` 관계 목록. 항목마다 `text`는 원문 문장, `rules`는 그 조건을 옮긴 조건표의 `rule_id`다.
- `입력/조치검토결과.json` — 조건표로 경보마다 조치 후보를 판정 · 비교한 조치 검토 결과. `events`의 경보마다 `id` · `asset` 설비 · `decision_time` 판정을 요청한 시각(UTC) · `candidates` 후보(`sop` · `status` 유지 · 제외 · 보류 · `inputs` 판단 입력 · `reasons` 이유 — 맞은 규칙의 `rule_id` · `result` · `actual_inputs` 실제 입력 · `comparison` 비교값 · `rank` 순위 · `approval` 승인) · `review` 검토 의견(`top` 승인 요청을 검토할 후보 · `reason` · `checks`).
- `자료/문서_목록.csv` — 첫 줄은 내보내기 머리, 둘째 줄이 열 이름이다. 열: 문서 식별자 · 제목 · 판 · 상태 · 시행일 · 소유 부서 · 대체 관계 · 파일 · SHA-256 · 비고. 파일 칸이 빈 행은 목록에만 있고 받은 파일이 없는 문서다.
- `결과/내_입력/` — 내 앞 결과를 쓸 때 위 `입력/`의 파일과 같은 이름으로 둔다. 있으면 `check.py`는 그 파일을 기준으로 본다.

## 2. 응답 기록 (`결과/응답_기록/<요청 해시>.json` — `llm_client.py`가 쓴다)

- 키: `request_hash` 요청 해시, `model` `.env`의 모델 이름, `response_model` 응답의 model, `system_fingerprint`, `finish_reason` 답이 끝난 까닭, `method` 보낸 방법(`강의 중계` · `채팅으로 받음`), `attempt` 같은 요청을 보낸 차례, `received_at` 받은 시각, `folder_mark` 이 폴더의 표지(`결과/폴더_표지.txt`), `request` 보낸 요청, `response_text` 받은 답 글, `response_raw` 받은 응답 원문, `usage` 토큰 수.
- 응답 기록은 고치지 않는다. 다른 폴더의 응답 기록을 옮겨 쓰면 그 기록의 `folder_mark`가 이 폴더와 다르다.

## 3. 후보 파일 (`결과/후보/<문서 식별자>_<판>.json` — 판이 빈 문서는 식별자만)

```json
{
  "doc_id": "문서 목록의 문서 식별자",
  "rev": "문서 목록의 판",
  "doc_status": "문서 목록의 상태",
  "source_file": "자료/ 안의 파일 이름",
  "source_sha256": "실제로 읽은 파일의 SHA-256",
  "encoding": "그 파일을 읽은 글자 방식(Python이 쓰는 이름)",
  "extractor": "이 결과를 만든 실행(코드 파일과 옵션)",
  "generated_at": "실행 시각(ISO 8601)",
  "model_run": [ {"record": "결과/응답_기록/….json", "request_hash": "…", "model": "…", "method": "…", "reused_from": null} ],
  "candidates": [ { 후보 }, ... ],
  "unlocated": [ { 후보와 같은 모양, "note": "인용을 찾지 못한 까닭" } ],
  "warnings": ["추출 중 판단하지 못한 것"]
}
```

- `model_run`은 이 후보를 만든 응답 기록마다 한 항목이다. `request_hash` · `model` · `method`는 그 기록의 값이고, 다른 폴더의 기록이면 `reused_from`에 그 기록의 `folder_mark`를 적는다(이 폴더 기록이면 `null`).
- 원문 어디에서도 인용을 찾지 못한 것은 후보(`candidates`)로 쓰지 않고 `unlocated`에 둔다.

## 4. 후보 하나

| 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 파일 안에서 고유한 문자열 |
| `section` | 예 | 그 내용이 있는 절 — 그 문서의 절 표기 그대로(문서마다 다르다: `HM-8.7` · `PM-2.4` · `3` · `제1조` · `HM-9.1`). 첫 절 앞의 글은 `머리말` |
| `procedure` | 예 | 그 내용이 절차 안이면 절차 표기(`SOP-COOL-14` 등), 절차 밖이면 `null` |
| `kind` | 예 | `step` · `precondition` · `prohibition` · `completion` · `unit_value` 중 하나 |
| `text` | 예 | 후보의 내용을 사람이 읽을 수 있게 적은 것 |
| `quote` | 예 | 근거가 되는 원문 문자열. 원문 글자를 고치거나 옮겨 쓰지 않은 연속 문자열이다 |
| `quote_match` | 예 | 인용을 찾은 방법 — `exact`(그 줄에 글자 그대로 있음) · `normalized`(글자 · 숫자만 남겨 소문자로 비교하면 그 줄에 있음). 원문 여러 곳에 맞는 인용은 찾지 못한 것으로 본다 |
| `line_start` · `line_end` | 예 | 인용이 있는 원문 파일의 줄 번호(1부터, `encoding`으로 읽은 줄) |
| `page` | 문서 목록 상태가 참고(스캔본)이면 예 | 인용이 있는 쪽 — 그 쪽 꼬리의 쪽 번호 표기 그대로 |
| `lang` | 영문 원본과 번역이 함께 있는 문서면 예 | 인용한 줄의 말 — `en` · `ko` |
| `refs` | 예 | `quote`가 가리키는 다른 절 · 절차의 표기 목록(원문의 표기). 없으면 `[]` |
| `status` | 예 | 추출 직후에는 `pending` |
| `order` | `step`이면 예 | 절차 안 번호(1부터) |
| `value` | `unit_value`이면 예 | 숫자. 범위면 작은 값 |
| `value_max` | 범위이면 예 | 범위의 큰 값 |
| `unit` | `unit_value`이면 예 | 원문에 적힌 단위 |
| `comparator` | `unit_value`이면 예 | `>=` `>` `<=` `<` `=` `range` `±` 중 하나, 원문에 비교 표현이 없으면 `null` |
| `value_text` | `unit_value`이면 예 | 값 · 단위 · 비교 표현이 적힌 원문 조각 그대로. `quote` 안에 있어야 한다 |

종류의 뜻:

- `step`: 절차의 번호 단계.
- `precondition`: 작업을 하기 전에 충족 · 확인해야 하는 조건과 승인.
- `prohibition`: 금지와 제한.
- `completion`: 끝났다고 보는 기준과 끝나지 않았을 때의 처리.
- `unit_value`: 숫자와 단위가 있는 기준값.

## 5. 검토 결과 파일 (`결과/검토/<문서 식별자>_<판>_검토.json`)

후보 파일을 복사해 아래를 더한 별도 파일이다. 후보 파일 원본은 그대로 둔다.

```json
{
  ...후보 파일의 최상위 필드...,
  "review": {"reviewer": "검토자", "reviewed_at": "시각", "candidates_file": "결과/후보/….json", "candidates_sha256": "검토를 시작할 때 후보 파일의 SHA-256",
             "selected_task": "선택한 작업 ID 또는 null", "decisions": ["검토 전체에 적용한 결정과 근거"]},
  "candidates": [ {후보 필드 + 아래 검토 필드} ],
  "missing": [ {"section": "…", "procedure": null, "kind": "…", "quote": "원문 그대로", "line_start": 1, "line_end": 1, "note": "왜 빠졌는지", "added": false} ],
  "rule_links": [ {"rule_id": "…", "candidates": ["후보 id"], "match": "일치 | 불일치 | 원문 없음 | 보류", "note": "까닭"} ]
}
```

| 검토 필드 | 뜻 |
|---|---|
| `decision` | `채택` · `수정` · `제외` · `보류` |
| `status` | 채택 · 수정 → `approved`, 제외 → `excluded`, 보류 → `pending` |
| `reason` | 원문 근거를 든 결정 이유 |
| `before` | `수정`일 때 바꾸기 전 필드 값 |
| `origin` | 모델 답에서 온 후보는 `extractor`, 검토자가 원문 문장으로 더한 후보는 `reviewer` |

- `missing`은 원문에 있는데 후보가 없는 것이다. 검토자가 근거 문장으로 후보를 더했으면 `added: true`로 두고 그 후보의 `origin`을 `reviewer`로 둔다.
- `rule_links`는 조건표의 조건과 이 문서 후보의 근거 대조다. `rule_id`는 기준 조건표의 `rule_id`(기준 조건표에 없는 규칙이면 그 규칙을 가져온 곳에 적힌 규칙 id), `candidates`는 근거로 본 이 파일의 후보 id, `match`는 원문과 조건이 맞는 정도, `note`는 그렇게 본 까닭(원문이 말하는 대상 · 때와 조건이 거는 대상 · 때)이다. 근거 원문을 찾지 못하면 `match`를 `원문 없음`으로 두고 `candidates`를 비운다.
- 다음 단계에는 `approved` 후보만 쓴다.

## 6. 선택한 작업의 조건 (`결과/선택작업_조건.json`)

```json
{
  "task": "고른 작업의 SOP ID",
  "basis": "고른 근거 — 파일 · 줄",
  "preparation": [ {항목} ], "prohibitions": [ {항목} ], "completion": [ {항목} ],
  "remaining_questions": [ {"item": "…", "kind": "보류 | 원문 미확인 | 제공되지 않은 절", "source": "…", "note": "…"} ]
}
```

- 항목: `{"candidate": "결과/검토/…_검토.json#후보 id", "doc_id": "…", "rev": "…", "section": "…", "quote": "…", "decision": "…"}` — 검토 결과의 `approved` 후보를 가리키고, `doc_id` · `rev` · `section` · `quote`는 그 후보의 값이다.
- 승인 후보가 아닌 것(보류 · 원문을 확인하지 못한 것 · 제공되지 않은 절)은 `remaining_questions`에 둔다.
