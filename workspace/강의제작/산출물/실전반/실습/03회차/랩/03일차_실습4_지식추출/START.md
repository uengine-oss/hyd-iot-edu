# 문서에서 작업 조건과 근거를 추출하는 기능 만들기

## 목표

포털에서 매뉴얼을 추출 · 대조 · 적재해 본 일을 직접 만듭니다. 포털에서 본 경보와 같은 종류의 다른 경보 한 건인 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보의 판정 뒤에 남은 근본 조치 쿨러 핀 세척(`SOP-COOL-14`)의 준비 · 금지 · 완료 조건을 문서 묶음 전체에서 모읍니다.

문서 10개는 판 · 상태 · 언어 · 형식이 다르고, 모델의 답은 같은 요청에도 달라 원문 줄과 대조해야 씁니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 문서 지식 — 원문에서 근거 있는 후보를 뽑아 사람이 검토하는 일 — 을 맡습니다.

만들 것: 정할 자리(나누는 단위 `결과/나누기.json` · 요청 글 `결과/prompt.md` · 기대 항목 · 검토 결정 · 조건 근거 · 역할 · 고른 것)와, 결과 화면이 그 자리로 만드는 후보 파일(`결과/후보/`) · 검토 결과(`결과/검토/`) · `결과/선택작업_조건.json`, `결과/검토_기록.md`.

## 출발점

- `입력/조건표.csv` · `입력/sop.json` · `입력/조치검토결과.json` — 냉각 계통 조치의 조건표 · SOP 구조와, 그 조건표로 지난 30일 경보를 판정한 결과. 조치를 판정하는 실습의 결과와 같은 꼴로 검증해 제공하는 판입니다.
- 내 앞 결과를 쓸 때: 제공 입력은 그대로 두고 내 `조건표.csv` · `sop.json` · `조치검토결과.json`을 `결과/내_입력/`에 복사해, 열 이름 · 키가 `입출력_계약.md` 「입력」과 같은지 먼저 견준 뒤 씁니다. 제공 코드와 구조 검사는 `결과/내_입력/`에 있는 파일을 기준으로 봅니다. 내 결과가 없어도 제공된 입력으로 끝까지 할 수 있습니다.
- `자료/` — 문서 10개와 `자료/문서_목록.csv`(문서마다 판 · 상태 · 시행일 · 소유 부서 · 파일 · SHA-256 — 파일 내용으로 계산한 지문 같은 값이라 한 글자만 달라도 바뀝니다). 문서 목록은 10월 28일 07:30에 내보낸 것입니다.
- `python show_result.py` · `lab_steps.py` — 결과 화면(`결과/보기.html`)을 쓰는 제공 파일. `doc_extract.py` — 정할 자리대로 문서를 읽고 나누어 모델에 보내고, 답을 후보로 바꾸고 인용 줄을 찾고, 검토 결과를 쓰는 제공 코드.
- `.env.example` · `llm_client.py` — 수업 모델 연결 값의 틀과 연결 도구. 보낸 요청과 받은 답은 `결과/응답_기록/`에 남습니다.
- `입출력_계약.md` — 입력 · 정할 자리 · 결과 파일의 형식. `check.py` — 결과의 구조 검사.
- `결과/` — 정할 자리(「제공 빈 틀」 파일)와 `검토_기록.md`.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.

## 처음 쓰는 도구

- `python llm_client.py` — 수업 모델에 짧은 질문 하나를 보내 연결을 확인합니다. `--count`는 보내지 않고 응답 기록 수와 이 폴더의 안내용 상한까지 남은 수를 보입니다.
- `python show_result.py` — 채운 정할 자리까지 제공 코드를 돌려 `결과/보기.html`을 다시 씁니다(처음 한 번은 브라우저로 엽니다). 모델을 부르는 단계가 있으므로 이 명령은 내 터미널에서 실행합니다. 같은 요청은 다시 보내지 않고 남은 응답 기록을 씁니다.
- 키가 없으면 `llm_client.py`는 요청을 보내지 않고, 보낼 글을 `결과/요청/`에 남긴 뒤 무엇을 했는지 알리고 멈춥니다.

## 해결할 질문

이 답은 보전 야간조가 핀 세척 전에 준비 · 금지 · 완료를 원문으로 되짚고, 설비보전팀장이 작업지시를 승인할 때 씁니다.

1. 핀 세척 후보의 결정(채택 · 수정 · 제외 · 보류)과 근거(문서 · 판 · 절 · 인용)는?
2. 핀 세척의 준비 · 금지 · 완료 조건과, 이 작업에 걸린 조건마다의 근거 원문은?
3. 같은 기능을 다른 문서에 적용하면 누락 · 근거 없는 생성은 몇 건이고, 무엇을 고쳐 다시 셌나?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **조건의 근거** — 이 작업에 걸린 조건마다 근거 원문과 그에 따른 조건의 자리
- **사내 문서와 제조사 지침** — 제조사 지침이 말하는 것을 작업 조건에 어떻게 둘지
- **나누는 단위와 요청 글** — 어떤 단위로 나누고 무엇을 뽑게 할지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 그래프 DB에 적재하는 일(다음 실습)
- 조건표 · SOP 구조 · 판정 결과를 고치는 일 — 바꿀 것은 요청으로 남깁니다
- 포털에 문서를 올리거나 포털의 추출 기능을 부르는 일
- 문서를 고쳐 쓰거나 번역하는 일

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

파일의 모양은 `입출력_계약.md`에 있습니다. 문서를 어떤 단위로 나눌지, 무엇을 뽑게 할지, 어떤 후보를 채택할지, 어느 원문을 조건의 근거로 둘지는 정할 자리에 내가 정합니다.

- 정할 자리 — `결과/나누기.json` · `결과/prompt.md` · `결과/기대_항목.csv` · `결과/검토_결정.csv` · `결과/조건_대조.csv` · `결과/역할.csv` · `결과/정한_것.csv`(계약 「정할 자리」).
- 결과 화면이 쓰는 것 — `결과/후보/<문서 식별자>_<판>.json` · `결과/검토/<문서 식별자>_<판>_검토.json` · `결과/선택작업_조건.json` · `결과/시험_조각.json` · `결과/보기.html`. `결과/응답_기록/`은 `llm_client.py`가 씁니다(고치지 않습니다).
- `결과/검토_기록.md` — 「제공 빈 틀」의 칸대로 채웁니다.

## 지킬 조건

- `입력/` · `자료/`는 읽기만 합니다. 제공 파일(`show_result.py` · `lab_steps.py` · `doc_extract.py` · `llm_client.py` · `check.py`)은 고치지 않습니다.
- 후보는 모델의 답에서 만듭니다 — `입력/`의 SOP 구조 · 조건표를 후보로 옮기지 않습니다.
- 후보 파일 원본은 남기고, 검토는 별도 파일에 씁니다. 원문과 대조하지 않은 후보는 보류로 둡니다.
- 조건표 · 판정 결과는 바꾸지 않고, 바꿀 것은 요청으로 남깁니다.
- 키 · 접속 값을 채팅 · 파일 · 기록에 붙이지 않습니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(ZIP을 풀면 이 폴더 옆에 있는 `_guide.html` 파일)의 같은 번호에 있습니다.

1. **폴더 · 사건 · 문서 묶음 파악** — `python show_result.py`로 결과 화면을 열어 사건 경보의 조치 후보 · 핀 세척이 걸린 관계 · 문서 표를 보고, AI에게 파일을 바꾸지 말고 핀 세척 원문의 절 · 줄을 물어 직접 연 뒤 `결과/검토_기록.md` 「이 사건의 작업」에 적습니다.
2. **수업 모델 연결 확인** — `.env.example`을 `.env`로 복사해 받은 세 줄을 붙여 넣고 저장한 뒤 `python llm_client.py`를 실행합니다.
3. **기대 항목 먼저** — `결과/기대_항목.csv`에 핀 세척 작업의 원문 줄을 파일 · 줄 · 종류로, `결과/검토_기록.md`에 목표 · 쓰는 사람 · 기대 칸을 쓴 시각을 적고 `python show_result.py`로 그 줄의 원문을 봅니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **판단① 나누는 단위와 요청 글 — 한 조각으로 시험** — `결과/나누기.json`에 단위 · 글자 상한 · 「시험_조각」(핀 세척 줄 「파일:줄」)을, `결과/prompt.md`에 요청 글을 쓰고 단위의 까닭을 `결과/정한_것.csv`에 적은 뒤 `python show_result.py`를 실행합니다.
5. **문서 묶음에 실행하고 기대 · 다른 문서와 대조** — 「보낼_문서」에 핀 세척 · 조건 근거 문서와 다른 문서(정기 점검표 · 예비품 기준 · 보충 매뉴얼)를 적고 `python show_result.py`를 실행해, 기대와 다른 줄의 차이 종류와 다른 문서의 실제 누락 · 근거 없는 생성 수를 `결과/검토_기록.md`에 적습니다.
6. **판단③ 검토 — 사내 문서와 제조사 지침** — `결과/검토_결정.csv`에 기대 줄의 결정 · 근거 · 까닭을(같은 결정은 줄 칸을 비운 규칙 한 행으로), 제조사 항목을 어떻게 둘지 `결과/정한_것.csv`에 적고 `python show_result.py`로 봅니다.
7. **판단④ 이 작업에 걸린 조건의 근거** — `결과/조건_대조.csv`에 이 작업에 걸린 조건마다 근거 · 맞는 정도 · 까닭 · 요청할 것을 적고 고른 것을 `결과/정한_것.csv`에 적은 뒤 `python show_result.py`로 봅니다. 조건표는 고치지 않습니다.
8. **판단⑤ 이 작업의 준비 · 금지 · 완료 모으기** — `결과/역할.csv`에 계약 기본과 다르게 둘 종류 · 글자만 적고 `python show_result.py`로 `결과/선택작업_조건.json`의 항목과 sop_diff를 원문 줄로 확인합니다.
9. **고침 · 저장하고 다시 열기** — 적어 둔 누락 하나를 판단 자리에서 고쳐 그 문서를 「다시_보낼_문서」에 적고 다시 실행해 센 수를 `결과/검토_기록.md`에 적고, 저장 뒤 폴더를 닫았다 다시 열어 `python show_result.py`를 실행하고 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/prompt.md`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 판이 다른 같은 문서에서 같은 작업의 조건이 달라지는 곳
- 같은 작업을 사내 문서와 제조사 지침이 함께 말하는 곳
- 영문 원본과 번역이 함께 있는 줄
- 부정 조건(「~하지 않는다」)과 범위 참조(「~부터 ~까지」)
- 경계 낱말(초과 · 이상 · 미만 · 이내)이 문서마다 다른 곳
- 글자 그대로는 찾히지 않는 인용과 원문 여러 곳에 맞는 인용
- 이 작업에 걸린 조건표 조건마다 근거 원문 — 원문이 말하는 대상 · 때가 조건과 같은 곳, 다른 곳, 근거 원문을 찾지 못하는 조건
- 같은 요청을 한 번 더 보낸 응답
- 받은 SOP 구조가 이미 구조로 옮긴 문서에 같은 기능을 적용한 결과
- 정기 점검표 · 예비품 기준 · 보충 매뉴얼에 같은 기능을 적용한 결과
- 이 작업의 조건이 절차 밖 절 · 다른 문서에 있는 곳

실행 명령:

```
python llm_client.py
python llm_client.py --count
python show_result.py
python check.py
python check.py 결과/후보/<파일 이름>.json
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/` · `자료/`가 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 실행 전에 원문에서 적은 기대 항목과 실제 후보를 줄마다 견준 기록이 있고, 핀 세척의 준비 · 금지 · 완료 후보의 결정과 이 작업에 걸린 조건마다의 근거 대조가 원문 줄로 설명되며, 다른 문서의 누락 · 근거 없는 생성 수와 고친 뒤 다시 센 수가 있고, `결과/정한_것.csv`의 근거와 그 선택으로 바뀌는 답을 설명할 수 있으면 완료입니다. 키가 없어 모델을 부르지 못한 단계는 그렇다고 적습니다.
