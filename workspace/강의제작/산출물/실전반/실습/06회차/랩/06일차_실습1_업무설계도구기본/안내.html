웹 BPMN 편집기로 첫 업무 흐름 파일 만들기

VS Code에서 이 폴더(이 안내 파일이 있는 폴더)를 열고 START.md를 함께 읽으세요. 이 안내는 START.md와 같은 내용입니다.

출발점이번에 할 것작업 순서기대 결과를 먼저 적을 사례 종류학생이 정할 것이번 범위 밖완료 조건저장과 다음 실습

정비 요청이 접수돼 담당자에게 넘어가는 작은 흐름을 웹 BPMN 편집기(bpmn.io)에서 직접 그리고 .bpmn 파일로 저장합니다. 이 파일은 다음 실습에서 승인 업무와 설비 이상 대응으로 넓혀 갈 출발점이고, 다른 사람이 같은 파일을 열어도 같은 그림과 연결을 읽을 수 있어야 합니다.

출발점

  • 이번 실습은 빈 그림에서 시작합니다. 앞 단계 결과는 필요하지 않습니다.
  • 코드/output/: 직접 만든 파일을 저장할 자리입니다. 지금은 비어 있습니다.
  • 코드/review.md: 저장 전후에 확인한 것을 적는 제공 빈 틀입니다.
  • 편집기: 브라우저에서 demo.bpmn.io를 엽니다. 설치는 필요하지 않습니다.

bpmn.io는 업무 흐름을 BPMN 표준 기호로 그리는 웹 편집기입니다. 왼쪽 팔레트에서 요소를 골라 놓고, 요소를 선택했을 때 나오는 작은 메뉴로 다음 요소를 잇거나 종류를 바꿉니다. 저장하면 그림이 BPMN XML 파일(.bpmn)로 내려받아집니다.

이번에 할 것

  • 시작 이벤트, 작업 하나, 끝 이벤트를 놓고 시퀀스 흐름으로 잇습니다.
  • 작업 이름을 정비 요청의 설비·증상·요청자를 확인하는 일로 적고, 작업 종류를 사용자 작업으로 바꿉니다.
  • 요소를 옮기거나 이름을 고친 뒤에도 선이 따라오는지, 선택한 요소의 이름·종류·들어오고 나가는 선을 확인합니다.
  • 코드/output/basics.bpmn으로 저장하고 편집기에서 다시 열어 같은 구조인지 확인합니다.

작업 순서

  1. demo.bpmn.io에서 새 그림을 시작합니다.
  2. 시작 이벤트 → 작업 → 끝 이벤트를 놓고 순서대로 잇습니다.
  3. 작업 이름을 고치고, 작업 종류를 사용자 작업으로 바꿔 사람 표식이 붙는지 봅니다.
  4. 요소 위치를 옮겨 선이 따라오는지 확인합니다. 잘못 이은 선은 지우고 다시 잇습니다.
  5. 그림을 내려받아 코드/output/basics.bpmn으로 옮깁니다.
  6. VS Code에서 basics.bpmn을 열어 startEvent·userTask·endEvent와 sequenceFlow의 sourceRef·targetRef가 그림의 요소 ID를 가리키는지 확인합니다.
  7. 편집기의 파일 열기로 basics.bpmn을 다시 열어 요소 수·이름·연결 방향을 저장 전과 견주고, 확인한 것을 코드/review.md에 적습니다.

기대 결과를 먼저 적을 사례 종류

저장하기 전에 코드/review.md의 「예상」 칸을 먼저 적습니다.

  • 요소 수: 다시 열었을 때 이벤트·작업·선이 각각 몇 개여야 하는지
  • 이름과 ID: 작업 이름을 바꾼 뒤 XML에서 요소 ID가 어떻게 보일지
  • 연결 방향: 각 선의 출발 요소와 도착 요소

학생이 정할 것

요소 ID를 편집기가 붙인 값 그대로 둘지, 읽기 쉬운 이름으로 바꿀지 정합니다. 뒤의 실습에서 같은 요소를 ID로 찾아 대조하므로, 고른 방식과 이유를 코드/review.md에 적습니다.

이번 범위 밖

승인·반려 갈림(다음 실습), 설비 이상 대응과 역할 레인, 실행 조건·담당자·실행 기능 지정, 포털로 흐름을 보내는 일.

완료 조건

  • 코드/output/basics.bpmn이 있고 편집기에서 다시 열면 시작·사용자 작업·끝과 두 선이 그대로 보입니다.
  • XML의 선이 가리키는 ID가 그림의 요소와 맞습니다.
  • 코드/review.md에 예상과 실제, 표시 이름과 요소 ID를 구별한 기록이 있습니다.

저장과 다음 실습

코드/output/basics.bpmn과 코드/review.md를 저장하고 다시 열어 확인하세요. 보관할 결과는 재부팅 전에 USB 또는 개인 클라우드에 복사하세요. 다음 실습에서는 이 파일에 승인과 반려 갈림을 붙입니다.
