01 폴더와 출발점 확인 · 결과 화면 열기

포털 판단 규칙 화면에서 허용 · 제외된 후보를 SOP의 금지 조건과 대조했습니다. 이번에는 그 근거를 제공 SOP(HM-8 매뉴얼)에서 직접 뽑아 조치 조건표로 만들고, 판단 시스템에 등록된 결정표와 행마다 출처를 견줍니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건, 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보 ALT-hyd02-0172-54a5입니다(경보 ID로 자료 · 결과 화면에서 찾습니다).

조건표는 어떤 입력이 어떤 값일 때 조치를 경고 · 감점 · 제외하는지를 한 행씩 적은 판단 규칙이고, DMN(판단을 표준 모양으로 적는 방식)의 결정표 — 입력 조건과 판단 결과를 한 행씩 적은 표 — 를 이 실습에서 부르는 이름입니다. 무엇을 규칙으로 옮기고 근거 없는 옛 규칙을 어떻게 둘지는 내가 정하고, 조건표를 사례에 대는 일은 제공 코드가 합니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 판단 지식 — 작업 기준의 조건을 판단 규칙으로 옮기는 일 — 를 맡습니다.

받기 「실습 시작」 도구에서 과정 → 회차 → 실습을 고르고 새로 시작(이어서 할 때는 이전 작업 열기)을 누르면 이 폴더와, 폴더 옆에 놓인 이 가이드가 열립니다(가이드는 AI가 읽는 폴더 밖에 둡니다). 받기에 실패하면 다시 시도하고, 안 되면 수동 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 열고 가이드는 노션 「가이드문서」에서 엽니다. 필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot.

처음 열 때 폴더를 신뢰할지 물으면 신뢰합니다 — 제한 모드(Restricted Mode)에서는 AI 채팅이 동작하지 않습니다. 왼쪽 탐색기(Explorer)에서 폴더 이름을 확인하고 START.md를 엽니다. AI 계정이 없거나 정답을 보고도 막히면 따로 받는 학생용 완성본으로 결과를 봅니다.

왜 무엇이 주어졌고 이 답을 누가 쓰는지 알아야 AI에게 같은 출발점을 말할 수 있습니다. 이번에는 절차(SOP)가 아니라 어떤 조건에서 조치를 쓸 수 있는지를 정하는 판단 규칙 쪽을 표로 만듭니다.

할 일 VS Code 탐색기에서 자료/ · 결과/ · START.md를 열어 각 자리의 역할과 이번 질문을 확인하고, 터미널에서 python show_result.py를 실행해 결과 화면을 엽니다.

해결할 질문 이 답은 야간 운전원이 경보가 났을 때 어느 조치가 남고 어느 조치가 빠지는지, 남은 조치를 누가 승인하는지 볼 때 씁니다.

  1. 네 조치의 경고 · 감점 · 제외 조건(입력 · 단위 · 연산자 · 경계 · 결과 · 출처)은 무엇인가?
  2. 사건과 확인 사례에서 각 후보는 남는가, 빠지는가, 무엇이 아직 모르는 값인가?
  3. 남은 후보와 실행 승인은 어떻게 다른가 — 남은 후보마다 누가 승인하는가?

말 풀이 SOP는 표준 작업 절차입니다. 경고는 그 조치에 주의할 점이 있다는 사유, 감점은 비교할 때 금액으로 깎는 사유, 제외는 그 조치를 쓸 수 없는 사유입니다. 판정은 그 사유를 모아 유지 · 제외 · 보류로 나뉩니다 — 보류는 제외 사유는 없지만 입력이 없어 맞는지 알 수 없는 규칙이 있는 후보이고, 세 말의 뜻은 자료/작업기준.md 4절에 있습니다. 미확인은 입력이 없어 조건이 맞는지 알 수 없는 상태입니다. 판단 시스템은 경보가 나면 조치 후보를 판정해 보여 주는 회사 시스템이고, 그 결정표를 내보낸 파일이 자료/판단시스템_결정표_내보내기.txt입니다. 제공 코드는 누가 해도 같은 일(파일 읽기 · 원문 인용 · 조건표 적용 · 계약 꼴 쓰기 · 검사)을 하는 받은 코드이고, 정할 자리는 결과/의 「제공 빈 틀」 파일 — 방향이 갈리는 판단을 내가 AI와 채우는 곳입니다. python show_result.py가 채운 자리까지 제공 코드를 돌려 결과/보기.html에 단계마다 결과를 보입니다. 계약은 결과 파일의 모양(열 · 키와 그 뜻)을 정해 둔 입출력_계약.md입니다 — 다음 실습의 기능이 이 모양 그대로 읽습니다.

터미널 → 새 터미널(Terminal → New Terminal)로 이 실습 폴더에서 터미널을 엽니다. 명령은 직접 치지 말고 블록의 복사로 붙여 넣습니다(손으로 옮기면 오타가 납니다). 오류로 멈추면 명령과 출력 전문을 AI 채팅에 보내 까닭부터 묻습니다. 명령은 AI 채팅이 아니라 이 터미널에서 내가 실행합니다.

결과 화면 여는 법 python show_result.py가 결과/보기.html을 새로 쓰고 처음 한 번 브라우저로 엽니다(안 열리면 탐색기에서 그 파일을 오른쪽 클릭 → Reveal in File Explorer → 두 번 클릭). 단계 띠의 「비어 있음 · 채움 · 오류」를 보고, 다시 실행한 뒤 F5를 누릅니다.

정할 것 이번 질문과, 이 답을 쓰는 사람이 누구인지 확인합니다.

터미널(PowerShell · 이 실습 폴더)

python show_result.py

증거 탐색기에서 세 자리를 찾았고, 결과/조건표.csv에 열 이름만 있다는 것을 확인했습니다. 결과 화면 맨 위 단계 띠에 이 실습의 단계가 보이고, 정할 자리가 있는 단계는 「비어 있음」입니다.
다를 때 보일 자리가 없으면 다른 실습이거나 덜 풀린 것이니 「실습 시작」에서 다시 받습니다.

02 파일을 바꾸지 않고 자료 파악

왜 조건표에는 원문에 있는 조건만 담아야 합니다. 원문 · 시스템 내보내기 · 기록은 만든 때와 사람이 달라 같은 조건도 다르게 적혀 있을 수 있으므로, 자료마다 어느 판 · 시점인지 먼저 압니다.

할 일 AI에게 파일을 바꾸지 말고, 원문의 조건 문장 · 판단 시스템 결정표의 행 · 사건 기록 · 확인 사례가 각각 무엇을 담고 있는지 파일:줄로 짚어 달라고 합니다. 짚은 줄을 직접 열고 결과 화면 2단계 표와 견줍니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘으로, GitHub Copilot은 같은 채팅 창의 Chat 탭으로 엽니다. 답에 나온 줄은 편집기에서 직접 열어 읽고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit the following file?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누릅니다.

정할 것 자료끼리 말이 달라 보이는 곳이 있는지, 확인 사례의 값이 비는 까닭이 몇 가지인지 묻습니다.

요청에 담을 것

목적조건과 판단 입력이 어디서 오는지 파악한다. 아직 아무것도 만들지 않는다.
입력자료/ 전체, START.md 「해결할 질문」
지킬 것파일을 바꾸지 않는다. 해석보다 파일:줄을 먼저 받는다.
결과의 꼴원문 근거 목록, 자료끼리 말이 달라 보이는 곳 목록, 값이 비는 까닭 표
확인 방법짚은 줄 가운데 몇 개를 내가 직접 열어 같은 내용인지 본다

명령 없음

증거 짚은 줄을 열면 그 내용이 있고, AI가 바꾼 파일이 없습니다. 질문에 쓸 자료가 무엇인지 내 말로 말할 수 있습니다.
다를 때 짚은 줄이 없거나 다르면 근거로 쓰지 않고 다시 찾게 합니다. 편집 승인 창이 뜨면 Deny를 누릅니다.

03 요구와 기대 판정 정하기

왜 기대 답을 원자료에서 먼저 적어야 결과를 견줄 기준이 생깁니다. AI의 답을 옮기면 틀린 결과도 맞아 보입니다.

할 일 결과/판단기록.md에 목표 · 쓰는 사람 · 지킬 조건을 적고, 사건과 확인 사례 두세 개의 네 후보가 유지 · 제외 · 보류 가운데 무엇이 될지 원문에서 먼저 찾아 결과/기대_판정.csv에 근거 줄과 함께 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.

아래 지점은 지금 적지 않고 6 · 7단계에서 원문을 열어 정한 뒤 결과/정한_것.csv에 적습니다. 여기서는 어떤 지점이 있는지만 봐 둡니다.

고친 파일은 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 결과/정한_것.csv에 한 줄씩 적습니다.

  • 출처가 확인되지 않는 기준 — 판단 시스템 결정표에 있는데 제공 SOP에서 근거 문장을 찾을 수 없는 규칙을 조건표에 어떻게 둘지 — 그런 규칙이 여럿이면 규칙마다 정하고 근거를 적습니다
  • 승인 역할 — 원문의 승인 줄이 하나로 읽히지 않는 후보의 승인을 무엇으로 적을지

질문 카드의 「(권장)」은 AI의 추천일 뿐이니, 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정할 것 경계값과 같은 사례, 입력이 빠졌는데 제외 사유도 있는 사례를 고릅니다(AI에게는 판정을 빼고 위치만 찾게 합니다).

요청에 담을 것

목적내가 적은 요구를 AI가 같은 뜻으로 이해했는지 되짚게 한다
입력내가 채운 결과/판단기록.md · 결과/정한_것.csv, 2단계에서 연 근거 줄
지킬 것파일을 바꾸지 않는다 — 결과/판단기록.md와 결과/정한_것.csv는 내가 편집기에서 채운다. 기대 답은 내가 원자료에서 찾은 값이다(AI의 답을 옮기지 않는다). 「학생이 정할 것」은 내가 고른다. 기대_판정.csv 칸: 한 줄에 사례 하나의 후보 하나, 실행 전에 원자료로 구한 값 · 사례 = 자료/확인_사례.csv의 사례 ID(사건 메모의 경보도 그 ID) · 후보 = 자료/targets.csv의 SOP ID · 기대_판정 = 유지 · 제외 · 보류 가운데 하나 · 근거 = 파일:줄(여러 개는 ;).
결과의 꼴내가 채운 칸(목표와 질문 · 쓰는 사람 · 자료와 기준일 · 지킬 조건, 기대_판정.csv)을 AI가 자기 말로 다시 말한 것과, 근거 줄이 맞지 않거나 두 갈래로 읽히는 문장의 목록
확인 방법되짚기가 내 뜻과 다른 곳과 짚인 문장을 내가 편집기에서 고친다

05 조건표 규칙 — 복합 조건과 경계

왜 DMN의 결정표는 함께 맞아야 하는 비교 여러 개를 한 규칙으로 묶고, 「이상 · 이하」는 기준값을 포함하지만 「초과 · 미만」은 포함하지 않아 기준값과 같은 값에서 결과가 갈립니다. 여러 규칙이 함께 맞을 때 무엇을 낼지 정한 것이 Hit Policy이고, 이 판정은 맞은 경고 · 감점 · 제외를 모두 모읍니다.

할 일 원문의 경고 · 감점 · 제외 조건을 결과/조건표.csv에 계약 모양으로 한 묶음씩 옮기며 결과 화면에서 출처의 원문과 사건 · 확인 사례의 판정을 3단계 기대와 견줍니다. 실행은 내가 터미널에서 하고, AI가 답에 옮겨 적은 출력이 아니라 터미널에 나온 출력과 결과 화면으로 확인합니다 — 옮겨 적은 글은 실제 출력과 다를 수 있습니다.

정할 것 여러 조건을 한 묶음(AND)으로 둘지 나눌지, 「이상 · 초과 · 미만」이 원문끼리 다른 곳을 무엇으로 정할지, 규칙을 어느 조치에 걸지 원문 낱말로 정합니다.

06 출처가 확인되지 않는 규칙

왜 판단 규칙이 후보를 남겼다는 것은 쓸 수 있다는 뜻일 뿐 실행해도 된다는 허락이 아닙니다. 실행은 정해진 사람이 한 번 승인한 뒤에 하므로, 누가 승인하는지를 원문에서 따로 확인합니다.

08 검사 · 저장하고 다시 열기

왜 구조 검사는 ID · 열 · 짝처럼 모양만 보고, 결과가 원문과 맞는지는 원문에서 먼저 적은 기대 판정과 견주어 판단합니다. 학교 PC는 재부팅하면 초기화될 수 있어, 다시 열어 같은 결과가 나와야 저장된 것입니다.

할 일 터미널에서 구조 검사를 실행해 짚은 문제를 고치고, 결과 파일을 모두 저장한 뒤 VS Code에서 폴더를 닫았다 다시 열어 python show_result.py와 구조 검사를 다시 실행합니다. 결과/판단기록.md 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

정할 것 검사가 짚은 문제가 결과 파일 · 정할 자리의 어느 항목인지 묻습니다. 확인하지 못한 점으로 무엇을 남길지 정합니다.
