01 폴더와 출발점 확인

포털 판단 규칙 화면에서 허용 · 제외된 후보를 SOP의 금지 조건과 대조했습니다. 이번에는 그 근거를 제공 SOP(HM-8 매뉴얼)에서 직접 뽑아 조치 조건표로 만들고, 판단 시스템에 등록된 결정표와 행마다 출처를 견줍니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건, 10월 27일 01:59 HYD-02 쿨러 성능 저하 경보입니다.

조건표는 어떤 입력이 어떤 값일 때 조치를 경고 · 감점 · 제외하는지를 한 행씩 적은 판단 규칙이고, DMN(판단을 표준 모양으로 적는 방식)의 결정표 — 입력 조건과 판단 결과를 한 행씩 적은 표 — 를 이 실습에서 부르는 이름입니다. 원문은 사람이 읽는 문장이라 한 문장에 조건 여러 개와 예외가 섞여 있고, 판단 시스템에 등록된 표는 옛 판으로 만들어져 번호와 낱말이 다릅니다. 행마다 원문으로 돌아갈 수 있어야 판단 결과를 믿고 쓸 수 있습니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 판단 지식 — 작업 기준의 조건을 판단 규칙으로 옮기는 일 — 를 맡습니다.

받기 「실습 시작」 도구에서 과정 → 회차 → 실습을 고르고 새로 시작(이어서 할 때는 이전 작업 열기)을 누르면 이 폴더와 가이드가 열립니다. 받기에 실패하면 다시 시도하고, 안 되면 수동 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 엽니다.

필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot.

받은 폴더 VS Code 왼쪽 탐색기에 이렇게 보입니다.

해결할 질문 이 답은 야간 운전원이 경보가 났을 때 어느 조치가 남고 어느 조치가 빠지는지, 남은 조치를 누가 승인하는지 볼 때 씁니다.

  1. 네 조치의 경고 · 감점 · 제외 조건(입력 · 단위 · 연산자 · 경계 · 결과 · 출처)은 무엇인가?
  2. 사건과 확인 사례에서 각 후보는 남는가, 빠지는가, 무엇이 아직 모르는 값인가?
  3. 남은 후보와 실행 승인은 어떻게 다른가 — 남은 후보마다 누가 승인하는가?

말 풀이 SOP는 표준 작업 절차입니다. 경고는 그 조치에 주의할 점이 있다는 사유, 감점은 비교할 때 금액으로 깎는 사유, 제외는 그 조치를 쓸 수 없는 사유입니다. 미확인은 입력이 없어 조건이 맞는지 알 수 없는 상태입니다. 판단 시스템은 경보가 나면 조치 후보를 판정해 보여 주는 회사 시스템이고, 그 결정표를 내보낸 파일이 자료/판단시스템_결정표_내보내기.txt입니다. 계약은 결과 파일의 모양(열 · 키와 그 뜻)을 정해 둔 입출력_계약.md입니다 — 다음 실습의 기능이 이 모양 그대로 읽습니다.

왜 하는가 만들기 전에 무엇이 주어졌고 무엇을 만들어야 하는지 알아야 AI에게도 같은 출발점을 말할 수 있습니다. 이 답을 누가 어디에 쓰는지에 따라 무엇을 하나로 보고 무엇을 따로 둘지가 달라지므로, 쓰는 사람도 여기서 확인합니다. 절차(SOP)는 사람이 차례대로 하는 일을, 판단 규칙은 어떤 조건에서 조치를 쓸 수 있는지를 정합니다. 이번에는 판단 규칙 쪽을 표로 만듭니다.

할 일 VS Code 탐색기에서 이 폴더의 자료/ · 결과/ · START.md를 열어 각 자리의 역할과 이번 질문을 확인합니다.

정하거나 물을 것 이번 질문 세 개와, 이 답을 쓰는 사람이 누구인지 확인합니다.

명령 없음 — 이 단계는 탐색기 · 편집기 · AI 채팅에서 합니다.

판단할 증거 탐색기에서 세 자리를 찾았고, 결과/조건표.csv에 열 이름만 있다는 것을 확인했습니다.
다를 때 보여야 할 자리 가운데 없는 것이 있으면 다른 실습을 받았거나 압축이 덜 풀린 것입니다. 「실습 시작」 도구에서 이 실습을 다시 받습니다.

02 파일을 바꾸지 않고 자료 파악

왜 하는가 조건표에는 원문에 있는 조건만 담아야 합니다. 원문 · 시스템 내보내기 · 기록은 만든 때와 만든 사람이 달라 같은 조건도 다르게 적혀 있을 수 있으므로, 자료마다 어느 판 · 시점인지 먼저 압니다. 이 단계에서 파일을 바꾸지 않는 것은 무엇을 옮길지 합의하기 전에 AI가 조건표를 만들기 시작하지 않게 하려는 것입니다.

할 일 AI에게 파일을 바꾸지 말고, 원문의 조건 문장 · 판단 시스템 결정표의 행 · 사건 기록 · 확인 사례가 각각 무엇을 담고 있는지 파일 · 줄로 짚어 달라고 합니다. 짚은 줄을 직접 엽니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘으로, GitHub Copilot은 같은 채팅 창의 Chat 탭으로 엽니다. 답에 나온 줄은 편집기에서 직접 열어 읽고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit the following file?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누릅니다.

정하거나 물을 것 자료끼리 말이 달라 보이는 곳이 있는지, 확인 사례의 값이 비는 까닭이 몇 가지인지 묻습니다.

03 요구와 기대 판단 정하기

왜 하는가 기대 답을 내가 원자료에서 먼저 찾아 적어 두어야, 뒤에서 AI가 만든 결과가 맞는지 견줄 기준이 생깁니다. AI가 낸 답을 기대 답으로 옮기면 틀린 결과도 맞아 보입니다. 원자료만으로 하나로 정해지지 않는 지점은 이 답을 쓰는 사람의 일을 보고 내가 정해야 같은 질문에 늘 같은 답이 나옵니다. 기대 판단을 경고 · 감점 · 제외로 나눠 적어 두어야 뒤에서 조건표 행의 결과 칸과 하나씩 견줄 수 있습니다.

할 일 결과/판단기록.md 첫머리에 목표 · 쓰는 사람 · 지킬 조건을 적고, 사건과 확인 사례 두세 개의 네 후보가 남는지 · 빠지는지 · 무엇이 아직 모르는 값인지를 원문에서 먼저 찾아 기대 판단으로 적습니다. 「학생이 정할 것」의 지점에 고른 것과 근거 줄을 적습니다.

고친 파일은 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로는 하나로 정해지지 않아, 근거를 찾아 내가 정해야 결과를 업무에 쓸 수 있는 지점이 있습니다. 이번 자료에는 아래 종류의 지점이 있습니다. 어느 행 · 어느 절이 해당하는지는 탐색에서 직접 찾고, 지점마다 고른 것 · 근거(파일 · 줄) · 그 선택으로 바뀌는 답을 결과/판단기록.md 「정한 것」 표에 적습니다.

  • 출처가 확인되지 않는 기준 — 판단 시스템 결정표에 있는데 제공 SOP에서 근거 문장을 찾을 수 없는 규칙을 조건표에 어떻게 둘지

질문 카드의 「(권장)」은 AI의 추천일 뿐이니, 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정하거나 물을 것 지점마다 내 선택과 근거를 말합니다. AI가 고를 것을 내놓거나 「권장」을 붙이면 따르지 말고 원문 줄을 다시 열어 내 말로 정합니다. 못 정한 지점은 미결로 적습니다.

04 계획 검토

왜 하는가 한 문장에 조건 여러 개와 예외가 섞인 원문을 바로 표로 옮기면 빠지거나 겹치는 행이 생깁니다. 무엇을 몇 행으로 옮길지 먼저 합의해야 행마다 원문으로 돌아갈 수 있습니다.

할 일 조건표에 넣을 규칙과 옮길 순서를 AI의 계획으로 받아 검토하고 동의합니다. 아직 파일을 만들지 않습니다.

정하거나 물을 것 조건표에 옮기지 않을 원문 조건과 그 까닭을 정합니다.
