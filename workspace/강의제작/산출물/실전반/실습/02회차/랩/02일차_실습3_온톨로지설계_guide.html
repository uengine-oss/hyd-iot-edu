HYD · 실습 가이드

설비·부품·공급 정보를 연결하는 온톨로지 설계하기

제공 모델에 공급 조건을 더하되, 어느 견적을 쓰고 승인을 어떻게 담을지만 내가 정하고 결과 화면에서 원자료와 대조합니다. 단계마다 「요청에 담을 것」 다섯 칸을 내 말로 채워 AI에게 요청하고(그대로 보내는 글이 아니며, 값은 원자료에서 찾습니다), 「증거」를 확인한 뒤 다음 단계로 갑니다. 막히면 「정답 보기」를 펼칩니다.

01 폴더와 출발점 확인

포털 지식 지도에서 부품을 쓰는 설비를 찾을 때, 연결이 있다는 것과 살 수 있는 조건이 확보됐다는 것은 달랐습니다. 이번에는 제공된 설비 · 부품 모델에 견적 · 승인 · 품번 자료를 이어, 부품마다 쓰는 설비와 공급사별 조건을 답하게 합니다. 단위 · 출처 · 계약 꼴은 제공 코드가 하고, 나는 어느 견적을 쓰고 승인을 어떻게 담고 무엇을 함께 남길지 정합니다. 공급사를 고르는 것은 구매 담당입니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 설계를 맡습니다.

받기 「실습 시작」 도구에서 과정 → 회차 → 실습을 고르고 새로 시작(이어서 할 때는 이전 작업 열기)을 누르면 이 폴더와, 폴더 옆에 놓인 이 가이드가 열립니다(가이드는 AI가 읽는 폴더 밖에 둡니다). 받기에 실패하면 다시 시도하고, 안 되면 수동 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 열고 가이드는 노션 「가이드문서」에서 엽니다. 필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot, 다음 실습의 랩 DB를 켤 Docker Desktop.

처음 열 때 폴더를 신뢰할지 물으면 신뢰합니다 — 제한 모드(Restricted Mode)에서는 AI 채팅이 동작하지 않습니다. 왼쪽 탐색기(Explorer)에서 폴더 이름을 확인하고 START.md를 엽니다. AI 계정이 없거나 정답을 보고도 막히면 따로 받는 학생용 완성본으로 결과를 봅니다.

왜 제공 모델에 무엇이 없는지 알아야 공급 정보를 더할 자리를 정합니다. 다음 실습의 랩 DB는 처음 켜는 데 오래 걸립니다.

할 일 탐색기에서 입력/ · 자료/ · 결과/ · START.md를 열고 python show_result.py로 결과 화면을 엽니다. 다음 실습 폴더도 받아 그 폴더에서 python lab_db.py를 먼저 켜 둡니다.

해결할 질문 아래 질문의 답은 구매 담당이 다음 발주에서 공급사를 비교할 때 씁니다. 고르는 것은 구매 담당입니다.

  1. 펌프 축 씰 키트를 쓰는 설비는 어디인가?
  2. 기준일(2026-10-15)에 펌프 축 씰 키트를 어느 공급사에서 어떤 조건(승인 여부 · 단가 · 불량률 · 납기)으로 살 수 있고, 각 값은 어느 파일 · 어느 줄에서 왔는가?
  3. 이름이 비슷한 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물으면 결과가 서로 구별되는가?

말 풀이 승인 공급사는 구매팀이 사도 된다고 등록한 공급사, 불량률은 입고 물량 가운데 불량 비율, 납기는 주문부터 받기까지 날수, 기준일은 자료를 뽑은 날, 정할 자리는 결과/에서 첫 줄에 「제공 빈 틀」이 있는 파일입니다.

터미널 → 새 터미널(Terminal → New Terminal)로 이 실습 폴더에서 터미널을 엽니다. 명령은 직접 치지 말고 블록의 복사로 붙여 넣습니다(손으로 옮기면 오타가 납니다). 오류로 멈추면 명령과 출력 전문을 AI 채팅에 보내 까닭부터 묻습니다. 명령은 AI 채팅이 아니라 이 터미널에서 내가 실행합니다.

결과 화면 여는 법 python show_result.py가 결과/보기.html을 새로 쓰고 처음 한 번 브라우저로 엽니다(안 열리면 탐색기에서 그 파일을 오른쪽 클릭 → Reveal in File Explorer → 두 번 클릭). 단계 띠의 「비어 있음 · 채움 · 오류」를 보고, 다시 실행한 뒤 F5를 누릅니다.

정할 것 질문 셋과 이 답을 쓰는 사람(구매 담당)을 확인합니다.

터미널(PowerShell · 이 실습 폴더)

python show_result.py

증거 1단계 칸에 제공 모델의 종류별 개수(공급사 종류는 아직 없음)와 원자료 행 수가 보이고, 3단계부터 「비어 있음」입니다.
다를 때 보일 자리가 없으면 다른 실습이거나 덜 풀린 것이니 「실습 시작」에서 다시 받습니다.

02 파일을 바꾸지 않고 자료 파악

왜 공급 조건이 견적표 · 승인 목록 · 기준서에 흩어져 있어, 한 자료만 보면 어긋난 곳을 놓칩니다.

할 일 AI에게 파일을 바꾸지 말고 펌프 축 씰 키트에 관한 줄을 자료마다 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘으로, GitHub Copilot은 같은 채팅 창의 Chat 탭으로 엽니다. 답에 나온 줄은 편집기에서 직접 열어 읽고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit the following file?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누릅니다.

정할 것 공급 조건 · 승인 · 비교 기준이 어느 자료에 있는지, 자료끼리 다르게 말하는 곳, 구매 기준서 7.4가 더 보게 하는 것을 묻습니다.

다를 때 짚은 줄이 없거나 다르면 근거로 쓰지 않고 다시 찾게 합니다. 편집 승인 창이 뜨면 Deny를 누릅니다.

03 요구와 기대 답 정하기

왜 기대 답을 원자료에서 먼저 적어야 결과를 견줄 기준이 생깁니다. AI의 답을 옮기면 틀린 결과도 맞아 보입니다.

할 일 결과/요구사항.md에 질문 · 쓰는 사람 · 기준일 · 지킬 조건을, 결과/기대_답.csv에 질문 1(사용 설비) · 질문 2(기준일의 세 공급 조건) · 질문 3(다른 표기 · 없는 품번)의 기대 답을 원자료에서 찾아 적고, 결정 지점 셋을 결과/정한_것.csv에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.

고친 파일은 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 결과/정한_것.csv에 한 줄씩 적습니다.

  • 조건이 붙은 승인 — 승인 목록에 조건을 달아 등록된 쌍을 승인 여부(참 · 거짓)에 어떻게 담고, 그 조건을 구매 담당에게 어떻게 보여 줄지
  • 빈 값의 뜻 — 비어 있는 칸을 「없음」으로 읽을지 「적지 않음」으로 읽을지
  • 쓰는 사람에 따라 갈리는 답 — 구매 담당이 공급사를 비교할 때 함께 봐야 할 것이 자료에 있으면, 그것을 모델에 어떻게 남길지

질문 카드의 「(권장)」은 AI의 추천일 뿐이니, 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정할 것 지점마다 내 선택과 근거를 정합니다. AI의 「권장」은 따르지 않고 원문 줄로 정하며, 못 정하면 미결로 적습니다.

요청에 담을 것

목적질문 1 ~ 3의 기대 답을 원자료에서 먼저 찾아 적는다(결과 화면이 이 표와 실제 답을 견준다)
입력자료/ 원문 줄, START.md 질문, 2단계 근거 줄
지킬 것AI의 답을 옮기지 않는다. 열(질문, 물을_값, 항목, 기대_답, 근거)은 그대로, 근거는 파일:줄. 값의 꼴: 한 줄 = (질문 · 물을_값 · 항목) 하나. 질문 = 1(사용 설비) · 2(공급 조건) — 질문 3은 질문 1 · 2 줄에 다른 표기 · 없는 품번을 물을_값으로 씀. 물을_값 = 모델에 물을 품번이나 표기 하나. 항목 = 질문 1은 찾을 사내 품번, 질문 2는 사내 품번/공급사. 기대_답 = 질문 1은 쓰는 설비 코드들, 질문 2는 「승인 여부 · 단가(만원) · 불량률(0~1) · 납기(일)」를 한 칸에. 근거 = 파일:줄. 여러 값은 「 · 」로 잇고, 값이 없으면(원자료에 없는 품번 · 빈 값) 「없음」.

# 제공 빈 틀 — 기준일에 쓸 견적을 고르는 내 판단. 함수 머리와 설명은 그대로 두고 본문만 채웁니다.


def use_quote(quotes, as_of):
    """근거: 자료/현장_메모.md 6절(견적을 쌓아 둔 표), 공급_조건.csv 유효기한 칸 — 기준일에 기한이 지난 견적은 쓰지 않고, 남은 것 가운데 견적일이 가장 늦은 줄."""
    live = [q for q in quotes if q['유효기한'] >= as_of]
    return max(live, key=lambda q: q['견적일']) if live else None

터미널(PowerShell · 이 실습 폴더)

막히면 「아직 검사할 결과가 없습니다」는 오류가 아니라 결과 파일이 아직 그 자리에 없다는 뜻입니다 — 결과 화면에서 비어 있는 단계를 먼저 채웁니다.

증거 6단계 줄이 모두 「같음」이거나 다른 까닭을 요구사항.md에 적었고, 「구조 검사 통과」가 있습니다.
다를 때 입력 · 기대 · 실제를 AI에게 전해 고친 뒤 다시 확인합니다.
