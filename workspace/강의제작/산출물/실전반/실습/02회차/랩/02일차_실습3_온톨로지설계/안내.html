01 폴더와 출발점 확인

포털 지식 지도에서 한 부품을 쓰는 설비를 찾아보며, 연결이 있다는 것과 그 부품을 실제로 살 수 있는 조건이 확보됐다는 것은 다르다는 것을 확인했습니다. 이번에는 그 공급 조건을 직접 모델에 넣습니다. 제공된 설비 · 부품 모델에 구매팀의 견적 · 승인 · 품번 자료를 연결해, 부품마다 쓰는 설비와 공급사별 조건을 함께 답하는 모델로 확장합니다.

같은 부품이라도 어느 공급사에서 어떤 조건으로 살 수 있는지는 시점과 출처에 따라 달라집니다. 그래서 값마다 어느 자료의 언제 값인지 남겨야 고르는 사람이 믿고 쓸 수 있습니다. 이 모델은 공급사를 골라 주지 않습니다. 고르는 사람이 고를 때 필요한 정보를 찾아 주는 구조입니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 설계 — 질문으로 범위를 정하고, 종류 · 속성 · 관계를 정의해 원자료로 모델을 만드는 일 — 를 맡습니다.

이 답은 구매 담당이 다음 발주에서 공급사를 비교할 때 씁니다. 고르는 것은 구매 담당입니다.

받기 「실습 시작」 도구에서 과정 → 회차 → 실습을 고르고 새로 시작(이어서 할 때는 이전 작업 열기)을 누르면 이 폴더와 가이드가 열립니다. 받기에 실패하면 다시 시도하고, 안 되면 수동 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 엽니다.

필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot.

받은 폴더 VS Code 왼쪽 탐색기에 이렇게 보입니다.

AI 계정이 없으면 실습 폴더와 따로 받는 학생용 완성본 묶음(계정이 없는 학생이 결과를 확인하는 용도)으로 결과를 확인하세요.

해결할 질문

  1. 펌프 축 씰 키트를 쓰는 설비와 구성 요소는 어디인가?
  2. 기준일(2026-10-15)에 펌프 축 씰 키트를 어느 공급사에서 어떤 조건(승인 여부 · 단가 · 불량률 · 납기)으로 살 수 있고, 각 값은 어느 파일 · 어느 날짜 자료에서 왔는가?
  3. 이름이 비슷한 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물으면 결과가 서로 구별되는가?

말 풀이 승인 공급사는 구매팀이 그 부품을 사도 된다고 등록해 둔 공급사이고, 불량률은 들어온 물량 가운데 불량의 비율, 납기는 주문해서 받기까지 걸리는 날수입니다. 기준일은 자료를 뽑은 날입니다.

왜 하는가 제공된 설비 · 부품 모델에 무엇이 있고 무엇이 없는지 알아야 이번에 더할 공급 정보의 자리를 정할 수 있습니다. 이 답을 쓰는 사람이 고르는 사람이라는 것도 여기서 확인합니다 — 모델은 고를 정보를 찾아 줄 뿐입니다.

할 일 VS Code 탐색기에서 이 폴더의 입력/ · 자료/ · 결과/ · START.md를 열어 각 자리의 역할과 이번 질문을 확인합니다.

정하거나 물을 것 이번 질문 세 개와, 이 답을 쓰는 사람이 누구인지 확인합니다.

명령 없음 — 이 단계는 탐색기 · 편집기 · AI 채팅에서 합니다.

판단할 증거 탐색기에서 네 자리를 찾았고, 입력/schema.json의 관계 목록에 공급사와 이어지는 관계가 아직 없다는 것을 파일에서 확인했습니다.
다를 때 보여야 할 자리 가운데 없는 것이 있으면 다른 실습을 받았거나 압축이 덜 풀린 것입니다. 「실습 시작」 도구에서 이 실습을 다시 받습니다.
증거를 확인한 뒤 다음 단계로 갑니다.

02 파일을 바꾸지 않고 자료 파악

왜 하는가 공급 조건은 견적표 · 승인 목록 · 구매 기준서처럼 여러 자료에 흩어져 있어, 한 자료만 보면 다른 자료가 다르게 말하는 곳을 놓칩니다. 파일을 바꾸지 않게 하는 것은 아직 합의하지 않은 해석으로 AI가 결과를 만들기 시작하지 않게 하려는 것입니다.

할 일 AI에게 파일을 바꾸지 말고, 펌프 축 씰 키트에 관한 줄을 자료마다 찾아 파일 · 줄로 짚어 달라고 합니다. 짚은 줄을 직접 엽니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘으로, GitHub Copilot은 같은 채팅 창의 Chat 탭으로 엽니다. 답에 나온 줄은 편집기에서 직접 열어 읽고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit the following file?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누릅니다.

정하거나 물을 것 어느 자료가 공급 조건 · 승인 · 비교 기준을 말하는지, 같은 대상을 두고 자료끼리 다르게 말하는 곳이 있는지 묻습니다.

03 요구와 기대 답 정하기

왜 하는가 기대 답을 내가 원자료에서 먼저 찾아 적어 두어야, 뒤에서 AI가 만든 결과가 맞는지 견줄 기준이 생깁니다. AI가 낸 답을 기대 답으로 옮기면 틀린 결과도 맞아 보입니다. 원자료만으로 하나로 정해지지 않는 지점은 이 답을 쓰는 사람의 일을 보고 내가 정해야 같은 질문에 늘 같은 답이 나옵니다.

할 일 질문 · 이 답을 쓰는 사람 · 기준일 · 지킬 조건과, 질문 1 · 2의 기대 답을 원자료에서 직접 찾아 결과/요구사항.md에 내 말로 적습니다. 「학생이 정할 것」의 지점마다 고른 것과 근거 줄을 적습니다.

고친 파일은 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로는 하나로 정해지지 않아, 근거를 찾아 내가 정해야 결과를 업무에 쓸 수 있는 지점이 있습니다. 이번 자료에는 아래 종류의 지점이 있습니다. 어느 행 · 어느 절이 해당하는지는 탐색에서 직접 찾고, 지점마다 고른 것 · 근거(파일 · 줄) · 그 선택으로 바뀌는 답을 결과/요구사항.md 「정한 것」 표에 적습니다.

  • 출처끼리 부딪치는 권위 — 같은 공급사 · 부품을 두 자료가 다르게 말할 때 무엇을 따르고, 구매 담당에게 어떻게 보여 줄지
  • 빈 값의 뜻 — 비어 있는 칸을 「없음」으로 읽을지 「적지 않음」으로 읽을지
  • 쓰는 사람에 따라 갈리는 답 — 구매 담당이 공급사를 비교할 때 함께 봐야 할 것이 자료에 있으면, 그것을 모델에 어떻게 남길지

질문 카드의 「(권장)」은 AI의 추천일 뿐이니, 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정하거나 물을 것 지점마다 내 선택과 근거를 말합니다. AI가 고를 것을 내놓거나 「권장」을 붙이면 따르지 말고 원문 줄을 다시 열어 내 말로 정합니다. 못 정한 지점은 미결로 적습니다.

아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

04 설계 계획 검토

왜 하는가 공급 조건은 공급사 하나나 부품 하나의 성질이 아니라 그 둘의 짝에 붙는 값이라 관계의 속성으로 둡니다 — 관계도 속성을 가질 수 있다는 점이 대상의 속성과 다릅니다(「공급 조건 형식」). 제공된 모델의 ID를 그대로 써야 새로 더한 공급 정보가 이미 있는 부품에 이어집니다. 계획이 틀린 채 만들면 만든 것을 다시 고쳐야 합니다.

할 일 공급 정보를 모델의 어느 종류 · 속성 · 관계로 둘지 AI의 계획을 받아 검토하고, 5 ~ 10단계의 구현 순서에 동의합니다. 아직 파일을 만들지 않습니다.

정하거나 물을 것 「결과 형식」이 정해 둔 것과 내가 정할 것을 나눕니다. 「정한 것」 표의 결정(승인 정보 · 출처 등)을 어느 속성에 둘지 정합니다.

왜 하는가 구조 검사는 ID가 겹치지 않는지, 관계의 양 끝이 있는지, 스키마에 없는 종류 · 속성이 없는지처럼 모양만 봅니다. 값과 답이 맞는지는 모르므로, 질문의 답은 10단계에서 내가 원자료와 대조한 기록으로 판단합니다.

할 일 터미널에서 구조 검사를 실행하고, 나온 문제를 고친 뒤 10단계 확인을 다시 합니다.

정하거나 물을 것 검사가 짚은 문제가 결과 파일의 어느 대상 · 관계인지 묻습니다.

아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적구조 문제를 찾아 고친다

명령

터미널 명령 · PowerShell · 이 실습 폴더에서

python check.py

막히면 「아직 검사할 결과가 없습니다」는 오류가 아니라 결과 두 파일이 아직 그 자리에 없다는 뜻입니다.

판단할 증거 「구조 검사 통과」 줄이 나옵니다. 「참고」 줄의 관계 개수를 원자료의 줄 수와 견주어 설명할 수 있습니다. 고친 뒤에도 10단계 결과가 같습니다.
다를 때 「구조 확인 필요」로 시작하면 아래 줄마다 문제가 하나씩 적혀 있습니다. 줄마다 결과 파일의 어느 대상 · 관계인지 AI에게 짚게 해 고친 뒤 다시 실행합니다.
증거를 확인한 뒤 다음 단계로 갑니다.

12 저장하고 다시 열기

왜 하는가 학교 PC는 재부팅하면 초기화될 수 있고, 다음 실습은 이 결과를 이어 쓸 수 있습니다. 폴더를 닫았다 다시 연 뒤에도 같은 결과가 나와야 저장된 것입니다.

할 일 결과 파일을 모두 저장하고 VS Code에서 폴더를 닫았다 다시 연 뒤 10단계 명령을 다시 실행합니다. 요구사항.md 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

정하거나 물을 것 확인하지 못한 점으로 무엇을 남길지 정합니다.
