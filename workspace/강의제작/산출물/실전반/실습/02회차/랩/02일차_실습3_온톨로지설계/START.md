# 설비·부품·공급 정보를 연결하는 온톨로지 설계하기

## 목표

포털 지식 지도에서 부품을 쓰는 설비를 찾을 때, 연결이 있다는 것과 살 수 있는 조건이 확보됐다는 것은 달랐습니다. 이번에는 제공된 설비 · 부품 모델에 견적 · 승인 · 품번 자료를 이어, 부품마다 쓰는 설비와 공급사별 조건을 답하게 합니다. 단위 · 출처 · 계약 꼴은 제공 코드가 하고, 나는 어느 견적을 쓰고 승인을 어떻게 담고 무엇을 함께 남길지 정합니다. 공급사를 고르는 것은 구매 담당입니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 설계를 맡습니다.

만들 것: `결과/`의 판단 함수 두 파일과 그것으로 제공 코드가 확장하는 모델(`결과/schema.json` · `결과/graph.json`), `결과/기대_답.csv` · `결과/정한_것.csv` · `결과/요구사항.md`.

## 출발점

- `입력/schema.json` · `입력/graph.json` — 제공된 설비 · 부품 모델. 설비 7대 · 구성 요소 · 센서 · 부품과 그 연결이 들어 있고, 공급 정보는 아직 없습니다.
- `자료/` — 원자료. CSV 8개(설비 대장 · 구성 요소 · 센서 · 예비품 · 품번 교차표 · 공급 조건 · 승인 공급사 · 입고 이력), 현장 메모, 구매 기준서 발췌. 기준일은 2026-10-15입니다.
- `결과/` — 정할 자리(첫 줄에 「제공 빈 틀」이 있는 함수 · 표 파일)와 기록.
- `supply_tool.py` — 공급 정보를 모델에 더하고 물어보는 제공 코드(바꾸지 않습니다). `check.py` — 구조 검사.
- `show_result.py` · `lab_steps.py` — 결과 화면을 만드는 제공 코드. `python show_result.py`가 단계마다 `결과/보기.html`을 다시 씁니다. 바꾸지 않습니다.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.

## 해결할 질문

아래 질문의 답은 구매 담당이 다음 발주에서 공급사를 비교할 때 씁니다. 고르는 것은 구매 담당입니다.

1. 펌프 축 씰 키트를 쓰는 설비는 어디인가?
2. 기준일(2026-10-15)에 펌프 축 씰 키트를 어느 공급사에서 어떤 조건(승인 여부 · 단가 · 불량률 · 납기)으로 살 수 있고, 각 값은 어느 파일 · 어느 줄에서 왔는가?
3. 이름이 비슷한 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물으면 결과가 서로 구별되는가?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **조건이 붙은 승인** — 승인 목록에 조건을 달아 등록된 쌍을 승인 여부(참 · 거짓)에 어떻게 담고, 그 조건을 구매 담당에게 어떻게 보여 줄지
- **빈 값의 뜻** — 비어 있는 칸을 「없음」으로 읽을지 「적지 않음」으로 읽을지
- **쓰는 사람에 따라 갈리는 답** — 구매 담당이 공급사를 비교할 때 함께 봐야 할 것이 자료에 있으면, 그것을 모델에 어떻게 남길지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 공급사를 고르거나 점수 · 순위를 매기는 일
- 입고 이력으로 실측 납기를 계산하는 일
- 그래프 DB에 적재하고 조회하는 일(다음 실습)
- 제공된 설비 · 부품 모델의 설비 · 구성 요소 · 센서 · 부품 부분을 고치는 일(이상한 곳은 `결과/요구사항.md`에 적습니다)

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

`check.py`와 다음 실습이 읽는 모양입니다. 무엇을 종류·속성·관계로 둘지는 직접 정합니다.

- `결과/schema.json`: `{"classes": {종류: {"meaning": 뜻, "required": {속성: 자료형}, "optional": {속성: 자료형}}}, "relations": {관계: {"from": 종류 또는 [종류…], "to": 종류, "cardinality": "1:N" 등, "properties": {속성: 자료형}}}}`
- 자료형은 `string`·`number`·`integer`·`boolean`·`list` 중 하나이거나, 허용 값 목록(예: `["upper", "lower"]`)입니다.
- `결과/graph.json`: `{"nodes": [{"labels": [종류], "props": {"id": 고유 ID, …}}], "rels": [{"type": 관계, "a": 시작 id, "b": 끝 id, "props": {…}}]}`
- 같은 두 대상 사이에 같은 관계를 여러 개 두려면 그 관계의 props에 `id`를 붙입니다.

### 공급 조건 형식(다음 실습의 조회가 읽는 모양)

- 공급사에서 부품으로 가는 관계 `SUPPLIES` 하나가 그 공급사 · 부품 쌍의 기준일 견적 조건 하나와 그 공급사의 승인 여부입니다. 같은 쌍에 `SUPPLIES`를 둘 이상 두지 않습니다. 기준일에 쓸 조건이 없는 쌍은 이 관계를 두지 않고, 그 사정을 `결과/자료_검토.md`에 남깁니다.
- `SUPPLIES`에 반드시 둘 속성: `approved`(boolean, 승인 공급사인지), `price_manwon`(number, 만원), `defect_rate`(number, 0~1 비율), `lead_days`(integer, 일), `quote_date`(string, 견적일). 그 밖의 속성(출처 · 조건 · 원래 표기 등)은 직접 정합니다.
- 견적 · 승인 이력을 함께 남기려면 다른 종류나 관계로 둡니다(선택).

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(「실습 시작」 도구가 이 폴더 옆에 내려 둔 파일, 노션 「가이드문서」)의 같은 번호에 있습니다.

1. **폴더와 출발점 확인** — 탐색기에서 `입력/` · `자료/` · `결과/` · START.md를 열고 `python show_result.py`로 결과 화면을 엽니다. 다음 실습 폴더도 받아 그 폴더에서 `python lab_db.py`를 먼저 켜 둡니다.
2. **파일을 바꾸지 않고 자료 파악** — AI에게 파일을 바꾸지 말고 펌프 축 씰 키트에 관한 줄을 자료마다 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.
3. **요구와 기대 답 정하기** — `결과/요구사항.md`에 질문 · 쓰는 사람 · 기준일 · 지킬 조건을, `결과/기대_답.csv`에 질문 1(사용 설비) · 질문 2(기준일의 세 공급 조건) · 질문 3(다른 표기 · 없는 품번)의 기대 답을 원자료에서 찾아 적고, 결정 지점 셋을 `결과/정한_것.csv`에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **판단① 기준일에 쓸 견적 정하기** — `결과/quote_rule.py`의 `use_quote`를 AI와 채우고 `python show_result.py`를 실행합니다. 공급사 이름 · 품번 · 단위 맞추기와 출처는 제공 코드가 합니다.
5. **판단② 승인과 함께 볼 것 정하기** — `결과/approval_rule.py`의 `approval` · `buyer_info`를 `결과/정한_것.csv`의 세 결정대로 AI와 채우고 `python show_result.py`를 실행합니다.
6. **물어보고 대조 · 구조 검사** — `python show_result.py`로 6단계 칸의 기대 답 ↔ 모델의 답과 구조 검사 출력을 봅니다.
7. **저장하고 다시 열기** — 모두 저장하고 폴더를 닫았다 다시 연 뒤 `python show_result.py`를 다시 실행하고, `요구사항.md` 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적은 뒤 다음 실습 폴더로 갑니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 같은 공급사 · 부품의 견적이 여러 줄인 경우
- 기준일에 기한이 지난 기록(견적 · 승인 등록)
- 같은 공급사를 다르게 적은 이름
- 출처마다 다른 승인 정보
- 기준서에 나오는 기준값과 같거나 가까운 값
- 단위 · 표기가 줄마다 다른 값
- 품번 칸의 표기가 줄마다 다른 경우
- 이름이 비슷한 다른 품번 · 예전 품번 · 다른 표기 · 원자료에 없는 품번
- 같은 정할 자리로 다시 실행한 결과

실행 명령:

```
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/` · `자료/` · 제공 파일(`show_result.py` · `lab_steps.py` · `supply_tool.py` · `check.py`)이 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 결과 화면 6단계에서 질문마다 원자료에서 먼저 적은 기대 답과 모델의 답이 맞고, `결과/정한_것.csv`의 지점마다 근거 줄과 그 선택으로 바뀌는 답을 설명할 수 있으면 완료입니다. 고친 점과 확인하지 못한 점은 `결과/요구사항.md`에 짧게 남깁니다.
