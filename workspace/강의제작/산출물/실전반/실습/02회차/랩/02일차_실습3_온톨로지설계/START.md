# 부품의 사용 설비와 공급 정보를 연결하기

> 자료는 교육용 가상 사례(실제 HYD 시스템 구조 기반). 회사·사람·일련번호·금액은 수업용으로 만든 값이다.

앞 단계에서 만든 설비·부품 모델에 구매팀의 견적·승인·품번 자료를 연결해, 부품별 사용 설비와 공급 조건을 함께 답하는 모델로 확장합니다. 공급사를 고르거나 점수화하지는 않습니다.

## 출발점

`입력/schema.json`·`graph.json`은 설비 7대·구성요소·센서·부품까지 정리된 앞 단계 완성 모델입니다. 공급 정보는 아직 연결되어 있지 않습니다. `자료/`에 원자료 전체(견적·승인 공급사·품번 교차표·입고 이력 포함)가 있습니다.

## 이번에 해결할 질문

1. 선택한 부품을 쓰는 설비와 구성 요소는 무엇인가?
2. 그 부품의 공급사별 승인 여부·단가·불량률·납기는 무엇이고, 각 값은 어느 파일·어느 날짜 자료에서 왔는가?
3. 비슷한 이름의 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물었을 때 결과가 서로 구별되는가?

## 작업

공급 자료를 모델의 어디에 어떤 종류·속성·관계로 둘지 정하고, 기존 설비·부품 연결과 ID를 유지하면서 모델을 확장합니다. 값마다 단위와 출처(파일·날짜)를 남기고, 원자료에서 공급 정보를 만드는 코드를 `결과/`에 둡니다. 자료를 정리하며 내린 처리는 `결과/자료_검토.md`에 남깁니다.

## 확인할 사례의 종류

같은 대상의 여러 기록(같은 쌍·같은 품목이 여러 줄이나 여러 파일에 나오는 경우) / 출처마다 다른 값이나 표기 / 비슷한 이름의 다른 품번과 원자료에 없는 품번

어느 행이 해당하는지는 원자료에서 직접 찾습니다.

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 학생이 근거를 찾아 정하는 지점입니다. 어느 행이 해당하는지는 탐색에서 직접 찾고, 정한 내용·근거 줄·바뀌는 답을 `결과/요구사항.md` 결정 표에 적습니다. AI는 이 지점을 정하기 전에 학생에게 묻습니다.

- 공급사·부품 쌍마다 기준일에 유효한 견적 조건을 무엇으로 볼지(같은 쌍의 견적이 여러 줄일 때 포함)
- `approved`를 무엇으로 정할지: 출처마다 승인 표시가 다르거나, 승인에 조건·기한이 붙은 경우
- 그 밖에 탐색에서 찾은, 자료를 읽는 방식에 따라 답이 갈리는 곳

## 이번 범위 밖

입고 이력과 실측 납기(다음 실습), 공급사 선정·점수화, 그래프 DB 적재와 조회. 자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

`check.py`와 다음 실습이 읽는 모양입니다. 무엇을 종류·속성·관계로 둘지는 직접 정합니다.

- `결과/schema.json`: `{"classes": {종류: {"meaning": 뜻, "required": {속성: 자료형}, "optional": {속성: 자료형}}}, "relations": {관계: {"from": 종류 또는 [종류…], "to": 종류, "cardinality": "1:N" 등, "properties": {속성: 자료형}}}}`
- 자료형은 `string`·`number`·`integer`·`boolean`·`list` 중 하나이거나, 허용 값 목록(예: `["upper", "lower"]`)입니다.
- `결과/graph.json`: `{"nodes": [{"labels": [종류], "props": {"id": 고유 ID, …}}], "rels": [{"type": 관계, "a": 시작 id, "b": 끝 id, "props": {…}}]}`
- 같은 두 대상 사이에 같은 관계를 여러 개 두려면 그 관계의 props에 `id`를 붙입니다.

### 공급 조건 형식(다음 실습의 조회가 읽는 계약)

- 공급사에서 부품으로 가는 관계 `SUPPLIES` 하나가 그 공급사·부품 쌍의 **기준일에 유효한 견적 조건 하나와 그 공급사의 승인 여부**입니다. 같은 쌍에 `SUPPLIES`를 둘 이상 두지 않고, 기준일에 유효한 조건이 없는 쌍은 이 관계를 두지 않습니다. 그 사정은 `결과/자료_검토.md`에 남깁니다.
- `SUPPLIES`의 속성 중 다음은 반드시 둡니다: `approved`(boolean, 승인 공급사인지), `price_manwon`(number, 만원), `defect_rate`(number, 0~1 비율), `lead_days`(integer, 일), `quote_date`(string, 견적일). 출처·조건 같은 다른 속성은 직접 정합니다.
- 견적·승인 이력을 함께 보존하려면 다른 종류나 관계로 둡니다(선택).

## 처음 쓰는 도구

VS Code 탐색기에서 파일을 열고 `Ctrl+S`로 저장합니다. 터미널(「터미널 → 새 터미널」)에서 명령을 실행하고, Codex 채팅(위쪽 탭이 Codex인지 확인)에서 AI에게 요청합니다. AI의 완료 보고는 실제 파일·실행 출력으로 확인합니다.
파일 편집 승인 창(「Allow ChatGPT to edit …」)은 경로가 `결과/` 아래일 때만 「Allow once」, 아니면 「Deny」를 누릅니다. AI가 질문 카드로 물으면 「(권장)」은 추천일 뿐이므로 근거 줄을 확인하고 고르거나 직접 적습니다.

## 진행 방법

1. AI에게 파일은 바꾸지 말고 자료를 읽어 과제와 확인할 점을 파일·줄로 짚어 달라고 요청하세요. 짚어 준 근거는 원자료에서 직접 확인합니다.
2. 목표·입력·지킬 조건과 내가 정한 결정을 자기 말로 `결과/요구사항.md`에 적으세요. 자료를 읽는 방식에 따라 답이 달라지는 지점을 하나 이상 찾아, 무엇으로 정했고 근거가 어느 파일·줄인지 함께 적습니다. 구현 전에 질문별 기대 답을 원자료에서 몇 개 직접 찾아 둡니다.
3. AI에게 계획을 먼저 받아 검토한 뒤 구현을 맡기세요. 한 번에 다 맡기지 말고 확인할 수 있는 단위로 나눕니다.
4. 완료 보고에는 실행한 명령과 출력 원문을 붙여 달라고 요청하세요. 바뀐 파일도 확인합니다. 입력/·자료/는 바뀌지 않아야 합니다.
5. 적어 둔 기대 답과 실제 결과를 대조하고, 다르면 입력·기대·실제를 함께 전달해 고치세요. 고친 뒤에는 내가 예로 든 행만 맞았는지가 아니라 같은 종류의 다른 행에도 통하는지 다시 세어 달라고 합니다.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 저장할 결과

`결과/schema.json`, `결과/graph.json`, `결과/요구사항.md`, `결과/자료_검토.md`, 공급 정보를 만든 코드

## 확인

```
python check.py
```

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 질문마다 원자료의 행과 실제 답을 대조하고, 내가 정한 결정에 따라 답이 어떻게 달라지는지 설명할 수 있어야 합니다. 수정한 점과 확인하지 못한 점을 짧게 남깁니다.
