# AI 작업 경계

- `data/`, `app/ui/`, `app/utils/`, `run.py`는 제공 파일이다. 원자료와 제공 코드를 보존한다.
- 요청받은 핵심 기능과 판단 기준은 `app/features/`에서 구현한다. 실행 결과는 `output/`에만 쓴다.
- 먼저 자료와 현재 코드를 파악하고, 요청한 기능 범위에서 작게 구현한다. 무관한 기능이나 문서를 추가하지 않는다.
- 사람이 자료를 물으면 구조·특징·어긋난 곳을 실제 예 줄(파일:줄)과 개수와 함께 보여, 사람이 몇 줄 열어 확인할 수 있게 한다.
- 원자료만으로 정해지지 않는 판단은 사람이 정한다. 그 자리에 이르면 무엇을 정해야 하는지와 선택지 · 각 선택의 결과를 쉬운 말로 풀어 먼저 묻는다. 사람이 물으면 근거 줄을 보이고 추천안도 낼 수 있다. 사람이 고르고 이유를 말하기 전에는 그 판단에 걸린 결과를 만들지 않는다. 「알아서 해 줘」 「잘 만들어 줘」처럼 이유 없이 넘기면 무엇을 정해야 하는지 되묻는다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인, 값 없음, 0을 구별한다.
- 실제 실행한 명령·결과·변경 파일을 보고한다. 실행하지 않은 것을 성공했다고 말하지 않는다.
- 키와 비밀번호를 코드·결과·기록에 적지 않는다. 열어 둔 프로젝트 폴더 밖의 파일은 읽지 않는다.

- `app/features/decisions.csv`의 고른_것 · 근거와 `app/features/expected.csv`의 기대 답에는 학생이 대화에서 정한 것만 적는다(학생이 보고 받아들인 근거 줄과 기대 답 후보도 된다). 학생이 정하지 않았으면 적지 않고, 정할 것을 선택지와 그 결과로 보여 묻는다.
- 한 번에 요청받은 기능 파일 하나만 고친 뒤 멈춘다. 랩 DB를 쓰는 명령(`python run.py` 기능)은 학생이 자기 터미널에서 실행하고, AI는 학생이 붙여 준 터미널 출력과 결과 화면으로 확인한다. AI가 그 명령을 직접 실행하지 않는다.
- `app/features/update.cypher`에서 불용 설비와 수정본의 「삭제」 줄(목록에서 빠진 센서)을 어떻게 할지는 `decisions.csv`의 「불용 결정 설비」 · 「목록에서 빠진 센서」 줄을 학생이 정한 뒤에만 쓴다. 정하기 전에는 수정본의 다른 줄만 반영하고 그 처리는 쓰지 않으며, 무엇을 정해야 하는지 선택지와 결과로 묻는다.
- 「다 해 줘」처럼 여러 기능을 한꺼번에 부탁받아도 기능 파일 하나를 고친 뒤 멈추고, 다음 기능을 할지 묻는다.
- `app/features/load.cypher`에는 그 파일 첫머리에 적힌 쿼리만 쓴다(처음에는 셋이고, 공급사와 견적 · 견적과 부품을 잇는 관계 쿼리 둘은 학생이 구매팀 질문 단계에서 요청했을 때 더한다). 나머지 종류 · 관계는 제공 코드가 넣는다(`output/load_provided.cypher`는 실행할 때마다 다시 쓰이는 기록이라 고치지 않는다).
- `app/features/schema_additions.csv`에는 스키마에 없던 속성을 그래프에 남기기로 학생이 정했을 때, 학생과 정한 속성만 적는다. `data/model/`의 모델 파일은 고치지 않는다.
- `expected.csv`의 기대 답은 원자료와 모델 파일에서 찾아 적고, 쿼리 결과를 옮겨 적지 않는다. 결과가 기대 답과 다르면 기대 답을 고치기 전에 원인을 먼저 설명한다.
- 「권장안대로」 · 「알아서」 · 「다 해 줘」처럼 갈래를 고르지 않거나 이유를 말하지 않은 부탁은 결정이 아니다. 학생이 고를 갈래와 그렇게 고른 자기 이유를 말하기 전에는 `decisions.csv`의 그 줄을 쓰지 않고, 그 결정이 걸린 `update.cypher`의 불용 설비 처리와 「삭제」 줄 처리, `schema_additions.csv`도 만들거나 고치지 않는다. 추천안을 냈더라도 학생이 그 추천을 받아들인다고 말하고 이유를 대야 결정이고, `decisions.csv`의 근거 칸에는 그 이유를 학생의 말로 적는다. 그때까지는 무엇을 정해야 하는지와 선택지 · 각 선택의 결과를 쉬운 말로 다시 묻는다.
- 파일은 모두 UTF-8(BOM 없음)이다. 읽고 쓸 때 글자표를 UTF-8로 밝힌다 — PowerShell로 읽을 때는 `Get-Content -Encoding utf8 <파일>`, 한글이 든 파일을 `>` · `Out-File` · `Set-Content`로 쓰지 않는다. 읽은 글의 한글이 깨져 보이면 그 내용으로 답하지 말고 UTF-8로 다시 읽는다.
- DB는 이 폴더에 배정된 랩 DB만 사용한다. 포털 DB나 전체 삭제 명령을 쓰지 않는다. Docker와 랩 DB를 켜고 끄는 명령(`python run.py db` 등)은 사람이 자기 터미널에서 실행한다.
