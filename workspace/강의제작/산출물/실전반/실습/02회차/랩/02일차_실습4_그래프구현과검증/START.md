# 부품의 사용 설비와 공급 정보를 조회하는 그래프 구현하기

## 목표

「설비·부품·공급 정보를 연결하는 온톨로지 설계하기」에서는 부품마다 쓰는 설비와 공급사별 조건을 모델에 넣었습니다. 이번에는 제공된 설비 · 부품 · 공급 모델(또는 내 모델)을 이 폴더 전용 랩 DB(그래프 DB)에 적재하고, 질문마다 Cypher 쿼리를 만들어 원자료와 대조합니다. 파일 읽기 · 실행 · 개수 세기 · 전후 비교는 제공 코드가 하고, 나는 같은 대상을 알아보는 열쇠와 조회가 돌려줄 것을 정해 문장으로 씁니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 구현과 검증를 맡습니다.

만들 것: 적재 쿼리(`결과/load.cypher`), 질문별 조회 쿼리(`결과/query.cypher`), `결과/기대_답.csv` · `결과/정한_것.csv` · `결과/검증_기록.md`.

## 출발점

- `입력/schema.json` · `입력/graph.json` — 제공된 설비 · 부품 · 공급 모델. 설비 7대 · 구성 요소 · 센서 · 부품 · 공급사와 그 연결이 들어 있고, 공급 조건마다 승인 여부 · 단가 · 불량률 · 납기와 값마다 출처가 붙어 있습니다. 그 밖에 붙은 속성은 `입력/schema.json`에서 봅니다.
- `입력/자료/` — 그 모델의 원자료(기준일 2026-10-15).
- `입력/요구사항.md` · `입력/자료_검토.md` — 제공된 모델이 답하는 질문과 자료 처리 근거.
- `lab_db.py` — 이 폴더 전용 랩 DB를 켜는 도구. `lab_cypher.py` — 적재 · 조회 문장을 랩 DB에 실행하고 세는 제공 도구. `check.py` — 제공 파일 · 기록 검사.
- `show_result.py` · `lab_steps.py` — 결과 화면을 만드는 제공 코드. `python show_result.py`가 단계마다 `결과/보기.html`을 다시 씁니다. 바꾸지 않습니다.
- `결과/` — 정할 자리(첫 줄에 「제공 빈 틀」이 있는 문장 · 표 파일)와 기록.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.
- 내 모델은 고를 때만 `결과/내_모델/`에 복사해 씁니다(형식 · ID가 맞는지 먼저 보고, 다르면 내 정의로 조회). 없어도 제공 모델로 끝까지 합니다.

## 해결할 질문

아래 질문의 답은 보전 · 구매 담당이 예비품을 쓰는 설비와 공급사별 조건을 함께 볼 때 씁니다. 고르는 것은 구매 담당입니다.

1. 세 설비가 함께 쓰는 펌프 축 씰 키트를 어느 설비 · 구성 요소에서 쓰고, 기준일의 세 공급 조건(승인 여부 · 단가 · 불량률 · 납기)은 무엇이며 각 값은 어느 파일 · 어느 줄에서 왔는가?
2. 이름이 비슷한 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물으면 결과가 서로 구별되는가? 비승인 공급사는 승인 상태와 함께 구별되는가?
3. 같은 적재를 다시 실행해도 대상과 관계가 늘지 않는가?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **쓰는 사람에 따라 갈리는 답** — 구매 담당이 공급사를 비교할 때 승인 여부 · 단가 · 불량률 · 납기 말고도 함께 봐야 할 것이 모델에 있으면, 그것을 조회 결과에 함께 돌려줄지와 어떻게 보일지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 공급사를 고르거나 점수 · 순위를 매기는 일
- 입고 이력으로 실측 납기를 세는 일
- 모델의 종류 · 속성 · 관계 정의를 새로 바꾸는 일(이상한 곳은 `결과/검증_기록.md`에 적습니다)
- 포털 DB에 접속하거나 포털 자료를 랩 DB에 넣는 일

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

`결과/`에 아래 파일을 둡니다. 파일 안에서 무엇을 어떤 문장으로 쓸지는 직접 정합니다.

- `결과/load.cypher`(또는 적재 코드): 모델 파일의 대상과 관계를 랩 DB에 넣습니다. 같은 파일을 다시 실행해도 됩니다.
- `결과/query.cypher`: 질문마다 Cypher 쿼리 하나. 쿼리 위에 어느 질문의 쿼리인지 주석(`// 질문 1`)으로 적습니다.
- `결과/검증_기록.md`: 「제공 빈 틀」의 칸대로 채웁니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(ZIP을 풀면 이 폴더 옆에 있는 `_guide.html` 파일)의 같은 번호에 있습니다.

1. **폴더와 출발점 · 랩 DB 켜기** — 탐색기에서 `입력/` · `결과/` · START.md를 열고 `python lab_db.py`로 이 폴더 전용 랩 DB를 켠 뒤 `python show_result.py`로 결과 화면을 엽니다. 「설비·부품·공급 정보를 연결하는 온톨로지 설계하기」 1단계에서 이미 켰으면 `python show_result.py`부터 합니다.
2. **파일을 바꾸지 않고 자료 파악** — AI에게 파일을 바꾸지 말고 `입력/graph.json`의 종류별 대상 · 관계 수와 펌프 축 씰 키트에 닿는 관계와 그 값의 원자료 줄을 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.
3. **요구와 기대 답 정하기** — `결과/검증_기록.md`에 질문 · 쓰는 사람 · 지킬 조건을, `결과/기대_답.csv`에 질문마다 물을 값 · 볼 열 · 원자료에서 찾은 기대 답(펌프 축 씰 키트의 사용 설비와 세 공급 조건, 다른 표기 · 없는 품번)을 적고, 결정 지점을 `결과/정한_것.csv`에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **판단① 적재 쿼리 쓰기** — `결과/load.cypher`에 종류 · 관계마다 문장 하나(위에 `// 넣을 것: <종류 또는 관계>`, 행은 `$rows`)를 AI와 쓰고 `python show_result.py`를 실행합니다. 행을 넘겨 실행하고 개수를 세는 것은 제공 코드가 합니다. 같은 적재를 한 번 더 해 늘지 않는지도 봅니다.
5. **판단② 사용 설비와 공급 조건 조회** — `결과/query.cypher`에 `// 질문 1` 조회(품번 하나 → 사용 설비 · 구성 요소와 공급사별 공급 조건, 승인 상태 · 출처 포함)를 AI와 쓰고 `python show_result.py`를 실행합니다.
6. **판단③ 다른 표기와 없는 품번 구별** — `결과/query.cypher`에 `// 질문 2` 조회(정식 · 예전 품번 · 다른 표기로 같은 부품을 찾고, 비슷한 다른 품번 · 없는 품번을 구별)를 더하고 `python show_result.py`를 실행합니다.
7. **저장하고 다시 열기** — 적재 · 조회 파일과 기록을 저장하고 폴더를 닫았다 다시 연 뒤 `python lab_db.py` · `python show_result.py`를 실행하고, 기록 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 세 설비가 함께 쓰는 부품
- 비슷한 이름의 다른 품번
- 예전 품번 · 다른 표기
- 원자료에 없는 품번
- 비승인 · 조건이 붙은 공급사
- 공급사 이름 표기(견적표 · 승인 목록)
- 같은 적재 두 번

실행 명령:

```
python lab_db.py
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/`(원자료 포함) · 제공 파일(`show_result.py` · `lab_steps.py` · `lab_cypher.py` · `lab_db.py` · `check.py`)이 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 결과 화면에서 질문마다 원자료에서 먼저 적은 기대 답과 실제 조회 결과가 맞고, 같은 적재를 다시 해도 개수가 같으며, `결과/정한_것.csv`의 지점마다 근거 줄과 그 선택으로 바뀌는 답을 설명할 수 있으면 완료입니다. 고친 점과 확인하지 못한 점은 `결과/검증_기록.md`에 짧게 남깁니다.

## 저장과 다음 실습

적재 · 조회 파일과 `검증_기록.md` · `정한_것.csv` · `기대_답.csv`를 함께 보관합니다. 기록에는 반영한 자료의 기준일을 적습니다. 다음 실습 「작업 기준의 복합 조건과 예외를 조치 조건표로 표현하기」는 제공된 자료로 시작하므로 이 결과는 참고로 보관합니다. 재부팅 전에 이 폴더를 USB나 개인 클라우드에 복사합니다(자동으로 되살리지 않음).
