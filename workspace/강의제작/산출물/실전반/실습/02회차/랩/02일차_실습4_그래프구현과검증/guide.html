01 폴더와 출발점 확인

「설비·부품·공급 정보를 연결하는 온톨로지 설계하기」에서는 부품마다 쓰는 설비와 공급사별 조건을 모델에 넣었습니다. 이번에는 제공된 설비 · 부품 · 공급 모델(또는 내가 만든 모델)을 이 폴더 전용 랩 DB(그래프 DB)에 적재하고, 질문마다 조회문을 만들어 원자료와 대조합니다. 스키마의 ID와 관계 방향이 그래프의 노드 · 관계로 어떻게 옮겨지는지 직접 봅니다.

조회가 돌려준 공급 조건을 구매 담당이 믿고 쓰려면 승인되지 않은 공급사가 승인된 것처럼 섞이지 않고 값마다 출처가 따라와야 합니다. 이 조회는 공급사를 골라 주지 않습니다. 고르는 사람이 볼 정보를 돌려줍니다. 그래프에 넣은 자료는 한 번으로 끝나지 않습니다. 수정본이 들어오면 전체를 지우고 다시 넣지 않고 필요한 대상만 고쳐야 다른 곳에서 쓰던 ID와 연결이 그대로 남고, 같은 적재를 다시 실행해도 대상이 늘지 않아야 믿고 다시 돌릴 수 있습니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 구현과 검증 — 설계한 모델을 그래프 DB에 옮기고, 질문에 실제로 답하는지 원자료와 대조하는 일 — 를 맡습니다.

이 답은 보전 · 구매 담당이 지금 가동하는 설비의 예비품 수요와 공급사별 조건을 볼 때 씁니다. 고르는 것은 구매 담당입니다.

02 랩 DB 켜기

할 일 터미널에서 python lab_db.py를 실행해 이 폴더 전용 랩 DB를 켜고, 열린 Neo4j Browser에 연결합니다.

메뉴에서 터미널 → 새 터미널(Terminal → New Terminal)을 선택하세요. 아래쪽 터미널에 이번 실습 폴더의 경로와 입력 커서가 보이면 다음 명령을 쓰고 Enter를 누릅니다. 출력 마지막 줄을 읽고 질문에 대한 실제 답은 원자료 행과 따로 대조하세요.

「랩 DB 준비 완료」가 나오면 열린 Browser의 Protocol에서 bolt://를 선택하고 Connection URL에는 출력 주소의 127.0.0.1:포트 부분만 넣습니다. Database user는 neo4j, Password는 비워 두고 Connect를 누릅니다. 연결 정보는 랩_연결.json에도 저장됩니다. AI가 명령 실행 승인을 요청하면 이 폴더의 적재 · 조회 명령이고 주소가 랩_연결.json의 주소와 같은지 먼저 확인하세요.

개수 조회 Browser 위쪽 입력 칸에 붙여 넣고 실행합니다.

MATCH (n) RETURN labels(n)[0] AS 종류, count(*) AS 개수 ORDER BY 종류

정하거나 물을 것 출력된 주소가 127.0.0.1의 이 폴더 전용 주소인지 확인합니다.

명령

python lab_db.py

판단할 증거 「랩 DB 준비 완료」와 주소가 나왔고, Browser에서 개수 조회가 빈 결과(이 폴더 전용 DB가 아직 비어 있음)를 보입니다. 확인한 뒤 다음 단계로 갑니다.

활동 표시줄에서 사용하는 AI의 아이콘을 열고 패널 제목에서 Codex 또는 GitHub Copilot을 확인하세요. 패널 아래 입력칸에 이번 질문을 자기 말로 적고 보냅니다. 첫 요청에서는 파일을 바꾸지 말고 근거 행을 찾아 달라고 하세요. 답변에 나온 파일을 왼쪽 탐색기에서 열어 가운데 편집기의 실제 행을 읽습니다.

정하거나 물을 것 수정본에서 무엇이 바뀌는지(이름 · 상태 · 값 · 줄 삭제), 제공된 모델의 ID가 무엇으로 지어졌는지 묻습니다. 입고 이력에서 한 발주가 여러 줄인 곳이 있는지도 묻습니다.

04 요구와 기대 답 정하기

할 일 질문 · 이 답을 쓰는 사람 · 지킬 조건과, 펌프 축 씰 키트의 사용 설비와 세 공급 조건, 공급사 하나의 지난 발주별 납기, 수정본 반영 뒤 달라져야 할 것을 원자료에서 직접 찾아 기대 답으로 결과/검증_기록.md에 적습니다. 「학생이 정할 것」의 지점마다 고른 것과 근거 줄을 적습니다.

파일을 고친 뒤에는 Ctrl+S로 저장합니다. 탭 이름 옆 점(●)이 사라지면 저장된 것입니다.

학생이 정할 것 — 지점의 종류 원자료만으로는 하나로 정해지지 않아, 근거를 찾아 내가 정해야 결과를 업무에 쓸 수 있는 지점이 있습니다. 이번 자료에는 아래 종류의 지점이 있습니다. 어느 행 · 어느 절이 해당하는지는 탐색에서 직접 찾고, 지점마다 고른 것 · 근거(파일 · 줄) · 그 선택으로 바뀌는 답을 결과/검증_기록.md 「정한 것」 표에 적습니다.

  • 시점과 상태 — 수정본에서 상태가 바뀐 설비를 그래프에 어떻게 반영하고, 「지금 가동하는 설비」를 묻는 답에 어떻게 드러낼지(답에서 빠지는지, 상태와 함께 보이는지)
  • 세는 법 — 나눠 들어온 발주의 실측 납기를 어느 입고로 셀지, 아직 다 들어오지 않은 발주를 어떻게 둘지

AI에게 이 지점을 대신 정하게 하지 않습니다. AI가 고를 것을 내놓거나 「권장」을 붙여도 그대로 따르지 말고, 원문 줄을 열어 내 선택과 근거를 말합니다. 못 정한 지점은 미결로 남깁니다.

정하거나 물을 것 지점마다 내 선택과 근거를 말합니다. AI가 고를 것을 내놓거나 「권장」을 붙이면 따르지 말고 원문 줄을 다시 열어 내 말로 정합니다. 못 정한 지점은 미결로 적습니다.

요청에 담을 것 아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적내가 정한 요구를 AI가 같은 뜻으로 이해하게 한다
입력3단계에서 연 근거 줄, 결과/검증_기록.md(제공 빈 틀)
지킬 것기대 답은 내가 원자료에서 찾은 값으로 적는다(AI의 답을 옮기지 않는다). 「학생이 정할 것」은 내가 고른다.
결과의 꼴검증_기록.md의 칸 — 목표와 질문, 이 답을 쓰는 사람, 사용한 입력, 지킬 조건, 「정한 것」 표, 「기대 답과 실제 결과」 표
확인 방법AI에게 검증_기록.md를 자기 말로 되짚게 하고, 내 뜻과 다른 곳을 고친다

판단할 증거 기대 답마다 파일 · 줄이 붙어 있습니다. 「정한 것」 표의 지점마다 고른 것 · 근거 · 바뀌는 답이 채워져 있거나 미결로 적혀 있습니다. AI의 되짚기가 내 요구와 같습니다. 확인한 뒤 다음 단계로 갑니다.

05 적재 계획 검토

할 일 대상과 관계를 어떤 문장으로 어떤 순서로 넣을지 AI의 계획을 받아 검토합니다. 스키마의 ID와 관계 방향이 그래프의 노드 · 관계로 어떻게 옮겨지는지 짚습니다. 아직 파일을 만들지 않습니다.

정하거나 물을 것 스키마의 ID가 노드의 무엇이 되고, 관계의 시작 · 끝이 어느 쪽이 되는지 내 말로 설명합니다. 같은 적재를 다시 실행해도 대상이 늘지 않으려면 무엇이 필요한지 묻습니다.

요청에 담을 것 아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적만들기 전에 적재 방법과 순서를 합의한다
입력입력/schema.json, 3단계의 개수 표, START.md 「결과 형식」

06 구현 ① 적재하기

할 일 모델 파일의 대상과 관계를 랩 DB에 넣는 적재문(또는 적재 코드)을 결과/에 만들고 실행합니다.

편집 승인을 묻는 경우 경로와 변경 내용을 확인합니다. 결과/ 안에서 요청한 변경만 허용하세요. AI가 선택을 물으면 자료의 행을 확인하고 판단 이유를 답합니다.

정하거나 물을 것 종류별 노드 수와 관계 수를 입력 파일과 견줍니다.

요청에 담을 것 아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적모델 파일의 대상과 관계를 랩 DB에 그대로 옮긴다
입력입력/schema.json · 입력/graph.json(또는 내 모델), 5단계 계획, 랩_연결.json의 주소
지킬 것이 폴더의 랩 DB에만 넣는다. 전체 삭제문을 쓰지 않는다. 대상 수백 개를 손으로 옮기지 않고 파일에서 만든다.
결과의 꼴결과/load.cypher 또는 적재 코드와 실행 출력
확인 방법종류별 노드 수 · 관계 수를 모델 파일에서 센 수와 나란히 보여 달라고 한다

명령

Browser에서 결과/load.cypher 실행, 또는 python 결과/<적재 코드 이름>.py

판단할 증거 종류별 노드 수와 관계 수가 모델 파일에서 센 수와 같습니다. 바뀐 파일이 결과/(와 랩 DB를 켤 때 생긴 랩_연결.json)뿐입니다. 다르면 입력 · 기대 · 실제를 함께 전해 고친 뒤 같은 확인을 다시 합니다. 확인한 뒤 다음 단계로 갑니다.

지킬 것개수를 맞추려고 전체를 지우고 다시 넣지 않는다
결과의 꼴첫 적재 · 다시 적재의 노드 · 관계 수 표(검증_기록.md)
확인 방법두 번째 실행 뒤 종류별 개수를 첫 실행과 나란히 놓는다

08 구현 ② 사용 설비와 공급 조건 조회

정하거나 물을 것 비승인 공급사를 결과에서 어떻게 구별해 보일지, 어떤 속성을 함께 돌려줄지 정합니다.

목적부품 하나의 사용 설비와 공급 조건을 한 번에 돌려준다
입력랩 DB의 그래프, 입력/schema.json의 관계 방향, 「기대 답과 실제 결과」 표
지킬 것조회만 한다(그래프를 바꾸지 않는다). 공급사를 고르거나 순위를 매기지 않는다.
결과의 꼴조회문과 Table 결과(설비 · 구성 요소, 공급사마다 승인 상태 · 단가 · 불량률 · 납기 · 출처)
확인 방법펌프 축 씰 키트의 결과를 기대 답과 줄마다 나란히 놓는다

명령

Browser에서 결과/query.cypher의 조회 실행

판단할 증거 펌프 축 씰 키트의 사용 설비와 세 공급 조건이 내가 먼저 적은 기대 답과 같고, 비승인 공급사가 승인 상태와 함께 구별됩니다. 다르면 입력 · 기대 · 실제를 함께 전해 고친 뒤 같은 확인을 다시 합니다. 확인한 뒤 다음 단계로 갑니다.

09 구현 ③ 다른 표기와 없는 품번 구별

할 일 예전 품번 · 다른 표기로 물어도 같은 부품을 찾고, 이름이 비슷한 다른 품번과 원자료에 없는 품번을 구별해 돌려주게 조회를 고치고 실행합니다.

정하거나 물을 것 원자료에 없는 품번으로 물었을 때 무엇을 돌려줄지(빈 결과와 미확인을 어떻게 구별할지) 정합니다.

요청에 담을 것 아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적품번을 어떻게 적어 물어도 같은 부품을 찾고, 없는 것은 없다고 돌려준다
입력8단계 조회문, 입력/graph.json의 부품 속성, 입력/자료/품번_교차표.csv
지킬 것없는 품번에 값을 지어내지 않는다. 비슷한 이름의 다른 품번을 같은 부품으로 합치지 않는다.
결과의 꼴고친 조회문과 네 가지 물음(정식 품번 · 예전 품번이나 다른 표기 · 비슷한 다른 품번 · 없는 품번)의 결과
확인 방법네 가지 물음을 실행해 결과를 서로 견주고, 기대 답과 나란히 놓는다

명령

Browser에서 결과/query.cypher의 조회 실행

판단할 증거 예전 품번 · 다른 표기로 물은 결과가 정식 품번과 같고, 이름이 비슷한 다른 품번과 없는 품번의 결과가 서로 구별됩니다. 다르면 입력 · 기대 · 실제를 함께 전해 고친 뒤 같은 확인을 다시 합니다. 확인한 뒤 다음 단계로 갑니다.

10 구현 ④ 실측 납기 세기

정하거나 물을 것 이 단계의 결과는 내 결정에 따라 달라집니다. 나눠 들어온 발주와 아직 다 들어오지 않은 발주에 「정한 것」 표의 결정이 그대로 적용됐는지 묻습니다.

목적지난 입고로 공급사별 실측 납기를 세어 견적 납기와 견준다
입력입력/자료/입고_이력.csv · 입력/자료/품번_교차표.csv, 「정한 것」 표, 8단계 조회의 견적 납기
지킬 것「정한 것」 표의 결정대로 센다. 입고일이 없는 줄에 날짜를 지어내지 않는다. 공급사를 고르지 않는다.
결과의 꼴공급사마다 「견적 납기 · 센 발주 수 · 실측 납기(평균 · 최대) · 근거 줄」 표
확인 방법공급사 하나의 발주를 내가 손으로 센 값과 코드 결과를 나란히 놓고, 결정을 바꾸면 무엇이 바뀌는지 본다

11 구현 ⑤ 수정본 반영하기

할 일 수정본의 줄마다 필요한 대상 · 관계만 고치는 수정문(또는 수정 코드)을 결과/에 만들고 실행합니다.

정하거나 물을 것 이 단계의 결과는 내 결정에 따라 달라집니다. 상태가 바뀐 설비를 「정한 것」 표의 결정대로 반영했는지, 「삭제」 줄이 그래프에서 무엇을 바꿨는지 묻습니다. AI가 결정을 대신 정하려 하면 돌려보내고 내 선택과 근거를 다시 말합니다.

요청에 담을 것 아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

목적전체를 지우지 않고 수정본이 고친 것만 그래프에 반영한다
입력입력/자료_변경분/2026-10-20_수정본/, 「정한 것」 표, 6단계 이후의 조회문
지킬 것전체 삭제문을 쓰지 않는다. ID를 바꾸지 않는다. 「정한 것」 표의 결정대로 한다.
결과의 꼴결과/update.cypher 또는 수정 코드, 반영 전후의 노드 · 관계 수와 바뀐 대상 목록
확인 방법반영 전후 개수 변화를 수정본의 줄로 설명하게 하고, 같은 수정을 한 번 더 실행해 개수를 비교한다

명령

Browser에서 결과/update.cypher 실행, 또는 python 결과/<수정 코드 이름>.py

판단할 증거 반영 전후 개수 변화를 수정본의 줄 하나하나로 설명할 수 있습니다. 「삭제」 줄이 걸린 설비의 센서 수를 원자료 행과 다시 세어, 실제로 있는 센서가 사라지지 않았는지 확인했습니다. 이름이 바뀐 설비의 ID가 그대로입니다. 같은 수정문을 다시 실행해도 개수가 같습니다. 조회를 다시 실행한 「지금 가동하는 설비」 답이 「정한 것」과 맞습니다. 확인한 뒤 다음 단계로 갑니다.
