# 실전반 2회차 실습 3 — 설비·부품·공급 정보를 연결하는 온톨로지 설계하기

> 촬영용 원고. 아래 요청은 실제 응답을 보고 구체화한다. 참조 모델의 DB 검증은 완료했으며 AI 작업·본 촬영 결과는 아직 아니다.

## 업무 문제에서 시작하기

앞에서는 준비된 그래프를 조회하고 포털의 기준 지도를 살펴봤습니다. 이번에는 부품이 어느 설비에서 쓰이고 어떤 공급 조건이 있는지 함께 찾을 수 있도록 모델을 확장하겠습니다. 설비·부품 자료와 공급 조건을 연결해 스키마와 데이터를 만들고, 원자료의 품번과 조건이 그대로 구별되는지 확인하겠습니다. 먼저 실습 시작 안내를 열어 볼게요. 「실습 시작 도구 다운로드」를 누르면 ZIP 파일을 받습니다. 다운로드한 파일에서 압축을 풀고, 풀린 폴더를 열어 실습시작.cmd를 실행하세요.

> [조작] 학생용 가이드의 링크에서 시작한다. 다운로드 완료 → 압축 해제 → 실행 파일 순서로 실제 동작과 결과를 잇는다. 시작 도구에 과정·회차·실습 선택 칸이 나타난 뒤 다음으로 간다.

실전반을 고르고 온라인 02회차에서 「설비·부품·공급 정보를 연결하는 온톨로지 설계하기」를 선택하겠습니다. 「새로 시작」을 눌러 보세요. 브라우저에 방금 고른 과제의 가이드가 열리고, VS Code에는 이 실습을 위한 새 작업 폴더가 열립니다. 왼쪽 탐색기 맨 위에서 폴더 이름을 읽어 보세요. 그 아래 START.md를 누르면 가운데 편집기에 같은 이름의 탭이 뜹니다. 파일을 누르는 곳과 내용을 읽는 곳이 이렇게 나뉩니다.

> [조작] 선택한 실습과 자동으로 열린 폴더·가이드 제목을 대조한다. 제한 모드가 보일 때만 해당 폴더의 신뢰 화면을 따라간다. 촬영 편의상 미리 열린 창을 자동 열기의 증거로 쓰지 않는다.

기존 모델부터 살펴보겠습니다. 설비와 센서, 교체 부품은 연결되어 있습니다. 여기에 공급 자료를 어떻게 연결해야 같은 부품의 여러 선택지를 비교해서 볼 수 있을지 정할 겁니다. 지금은 어느 공급사를 고를지 결정하는 기능은 만들지 않습니다.

VS Code의 Codex 버튼을 누르면 채팅 패널이 열립니다. 패널 제목이 Codex인지 보고 아래 입력칸을 눌러 볼게요. 여기에 궁금한 것을 적으면 답이 같은 패널에 나타납니다. 어느 파일의 어느 행을 봤는지도 같이 물어보겠습니다.

> [탐색 요청] 이번 업무와 준비된 자료를 읽고, 현재 모델로 답할 수 있는 것과 추가로 결정해야 할 것을 근거 위치와 함께 알려 주세요. 아직 파일은 바꾸지 마세요.
> [확인] 실제 답변을 입력 모델·공급_조건.csv와 대조한다. 부품의 품번, 공급사별 조건, 승인 여부의 의미를 확인한다.

## 연결할 조건을 정하기

같은 공급사여도 부품에 따라 단가와 납기가 다릅니다. 이 값을 공급사에 하나만 저장하면 다른 부품의 조건과 섞이겠죠. 어떤 대상 사이의 조건인지 설명할 수 있게 모델을 정하겠습니다.

> [판단] 학생의 업무 질문과 원자료의 두 기록을 나란히 연다. 학생이 정한 기준으로 서로 다른 설계가 어떤 답을 돌려줄지 비교하고, 선택한 표현과 판단 근거를 기록한다. 파일 작성 전 합의한 날짜·단위·확인 사례를 되짚는다.

요구를 짧게 정리하겠습니다. 부품으로 사용 설비와 공급 선택지를 찾고, 승인 여부와 가격·불량률·납기를 함께 확인해야 합니다. 비승인 행을 몰래 없애거나 가격만 보고 추천을 만들지는 않겠습니다.

> [구현 요청 구성] 앞에서 확인한 입력, 선택한 표현, 기존 연결 보존, 질문별 확인 방법을 자기 말로 묶어 요청한다. 예상 AI 답변을 원고에 채우지 않는다. 결과/schema.json·graph.json으로 저장한다.

## 다른 부품으로 확인하기

펌프 축 씰 키트부터 보겠습니다. 사용 설비와 공급 조건이 원자료와 맞는지 하나씩 확인합니다. 이어서 팬 베어링으로 바꿔 보겠습니다. 품번만 바뀌고 앞의 가격이 그대로 남아 있으면 안 됩니다.

위쪽 터미널 메뉴에서 새 터미널을 열겠습니다. 아래에 이번 실습 폴더의 경로와 커서가 보이죠. 여기에 python check.py를 입력하고 엔터를 누르면 바로 아래 줄에 검사 결과가 나옵니다.

> [조작] python check.py 실행. 구조 검사와 별도로 P-PMP-SEAL·P-FAN-BRG의 원자료 행과 모델 연결을 대조한다. 없는 품번도 구별할 수 있는지 확인한다. 실제 차이가 발견되면 입력·기대·실제 결과를 붙여 수정 요청한다.

검사가 통과했다는 말은 파일 구조가 맞다는 뜻입니다. 조건이 올바른 부품에 연결되었는지는 방금 한 자료 대조로 확인합니다. 선택한 이유와 아직 확인하지 못한 점을 결과에 남기겠습니다.

## 모델 저장과 공급 조건 확인

모델과 검토 기록을 저장하고 다시 열어 보겠습니다. 품번과 견적일, 승인 상태가 함께 남아 있어야 나중에 같은 조건으로 비교할 수 있습니다.

> [조작] 직접 만든 결과에서 펌프 씰 품번의 사용 설비와 기준일의 공급 조건을 확인한다.

AI 계정 없이 결과를 확인하려면 별도로 제공되는 완성본을 사용하세요. 같은 품번을 넣고 어느 설비에 쓰이는지, 유효한 견적 중 어느 공급사가 비승인인지 비교해 보겠습니다.

> [조작] 학생용 완성본을 빈 폴더에 풀어 완성본_안내.md가 있는 폴더에서 터미널을 연다. `python -B -X utf8 결과/모델실행.py`를 실행한 뒤 결과/질문별_결과.json을 연다. 직접 만든 결과와 완성본에서 해당 품번의 사용 설비, 견적 행과 승인 상태를 대조한 화면으로 마친다.
