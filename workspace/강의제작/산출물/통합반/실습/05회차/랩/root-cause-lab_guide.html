01 자료와 질문 파악

온톨로지에서 찾은 원인 후보는 이번 사건의 확정 원인이 아닙니다. 문서 조건과 현재 관측을 따로 찾는 에이전트 단계에서, 정비 담당자가 검토할 후보·다음 점검·추가 자료가 필요한 질문을 만듭니다. 자료 파악 → 내 요구와 기대 → 계획 → 기능별 구현·실행 → 원문과 견주기 → 다른 입력 확인 → 저장 순서로 진행합니다.

클래스룸 🧪 05회차 실습 자료에서 ZIP을 내려받아 압축 풀기를 합니다. VS Code의 파일 → 폴더 열기에서 root-cause-lab 폴더만 엽니다. 가이드는 옆의 root-cause-lab_guide.html을 브라우저로 엽니다. 위 폴더까지 열면 Codex가 답이 든 가이드를 읽을 수 있습니다. 직접 받은 폴더인지 확인한 뒤 신뢰 창에서 신뢰합니다.

탐색기 모양

root-cause-lab/
├ README.md
├ AGENTS.md
├ data/
├ app/
│  ├ features/
│  ├ ui/
│  └ utils/

탐색기에서 README.md로 목적과 첫 명령을 봅니다. AGENTS.md는 Codex가 지킬 공통 작업 원칙입니다. VS Code의 Codex 채팅을 열고 로그인이 필요한 경우 개인 GPT 계정으로 로그인합니다. 터미널 → 새 터미널에서 현재 위치가 root-cause-lab인지 봅니다. 명령과 글은 오타로 다른 파일을 다루지 않도록 복사 단추로 가져옵니다.

터미널(PowerShell · 이 실습 폴더)

python run.py --inspect

터미널에는 제공 지식의 노드·관계 수, 요청 수와 읽기 도구가 나옵니다. data/requests.csv에서 기본 요청의 설비와 기준시각을 찾고, data/source_manifest.json과 data/field_notes.md에서 문서 판본·수집 범위를 연결합니다. 10초 자료는 개별 관측 표본이며 평균이 아닙니다. 질문에 필요한 값이 어느 출처에 있는지 알아야 다음에 기대 답을 정할 수 있습니다.

Codex에게 기본 요청의 질문을 받는 역할과 문서·그래프·관측의 위치를 물어봅니다. 파일을 바꾸지 말고 근거를 찾게 한 뒤, 답에 나온 문서의 판본과 줄을 직접 열어 확인합니다. 찾지 못한 항목은 모르는 것으로 남깁니다.

02 요구와 기대 답 정하기

누가 이 결과로 무엇을 할지 먼저 정합니다. app/features/requirements.md에 받을 역할·질문·지킬 조건을 내 말로 적고, choices.csv에 선택·원문 근거·그 선택으로 달라질 다음 행동을 적습니다. 증거 대조는 원인 후보의 조건과 현재 관측을 비교해 충족·해당 없음·보류를 구분하는 일입니다.

하나는 근거 묶음입니다. 숫자 한 줄로 충분한지, 표머리·적용 조건·인접절이나 같은 운전 조건의 다른 기간이 필요한지 정합니다. 다른 하나는 점검 전달입니다. 근거가 일부 비었을 때 확인한 범위부터 나눠 보낼지, 요청 전체의 근거를 모아 전달할지 대상과 받을 역할에 맞춰 정합니다. 문서의 안전 조건을 바꾸는 선택은 아닙니다. AI가 권장안을 붙이면 원문을 열어 내 선택과 이유를 다시 말합니다.

터미널(PowerShell · 이 실습 폴더)

python run.py --source data/documents/hm_8_1_1.md --start 25 --end 43

원문 도구는 줄 번호와 글을 그대로 보여 줍니다. 목록의 원래 파일 이름은 source_manifest.json의 catalog_file에서 실제 file로 연결합니다. expected.csv에는 세 후보의 적용 조건, 관측을 쓸 수 있는 기준, 작업 전제 등 이번 요청에서 확인할 질문과 기대·출처를 먼저 적습니다. 관측을 아직 조회하지 않았다면 수치나 상태를 짐작하지 말고 미확인으로 둡니다. 그래야 이후 실제 반환을 원문과 견줄 수 있습니다.

내가 찾은 원문과 수집 조건을 Codex에게 설명하고, 선택에 따라 달라질 조회 범위와 다음 행동을 함께 짚습니다. data/field_notes.md의 업무 범위에는 수신 역할이 아직 정하지 않은 전달 요구가 있습니다. 문서 조건과 사람의 업무 선택을 구분하고 내 요구와 이유를 말합니다. choices.csv의 decision에는 적용 기능인 query 또는 deliver를, 나머지 칸에는 내 선택·출처·달라질 행동을 적습니다. 전달 요구가 비어 있으면 수집·판정은 볼 수 있어도 다음 점검을 정한 것으로 보지 않습니다.

Codex에게 내 요구·선택·기대와 세 파일의 함수 설명을 읽게 합니다. 어떤 입력을 받아 무엇을 반환하고 어느 원문으로 확인할지 기능별로 제안받습니다. 모델의 도구 선택이 고정 순서의 답 조회로 바뀌지 않는지 계획에서 확인합니다.

API 키가 없으면 터미널에 output/model_requests/의 요청 글과 붙여넣기 명령이 나옵니다. 이 폴더를 모르는 별도 Codex 채팅에 요청 글을 보내 JSON 답을 받습니다. 터미널에 나온 python run.py --paste … --model …을 그대로 실행해 답을 붙여 넣고, 새 줄에서 Ctrl+Z → Enter로 끝냅니다. 같은 수집 명령을 다시 실행하면 그 반환부터 이어집니다. 필요한 조회가 남으면 이 동선을 반복합니다. 모델이 독립 조회를 묶으면 한 답에서 여러 도구가 실행됩니다.

결과 화면의 조회 근거에서 실제 도구·출처·시각을 보고 입력·반환 원문 펼치기로 모델 인수와 실제 인수·반환을 견줍니다. 수집이 끝나면 모델이 쓴 요약도 보입니다. 그 요약은 검토 대상입니다. 도구 오류가 있으면 실제 오류와 빠진 근거를 확인합니다. 필요한 근거가 없으면 조회 기능을 고쳐 수집하며, 기준이나 자료가 바뀌면 이전 반환은 이전판으로 구분됩니다.

끝낼 조건은 실제 도구 선택과 반환, 원문에 근거한 후보 상태, 내 선택이 바꾼 조회 범위·다음 행동, 다른 요청의 결과를 원문과 견준 기록이 모두 남는 것입니다. 충족을 현장 원인 확정·작업 완료로 쓰지 않습니다. 계정이 없거나 정답을 보고도 막히면 실습 폴더와 따로 받는 학생용 완성본으로 결과를 봅니다.
