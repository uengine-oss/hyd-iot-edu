# 통합반 8회차 — 행동기준작성

> [제작 — 낭독하지 않음] 문서 작성 완료. 실제 실습·학생 코드·테스트·AI·HYD·DB·브라우저·캡처는 미수행이다. 아래는 강사가 수업에서 수행할 흐름이며 결과는 직접 확인한 뒤 기록한다.

## 다운로드와 앞 회차 결과 열기

앞 명세를 실행 결과로 판정할 수 있는 행동 기준으로 옮기겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 행동기준작성 ZIP을 다운로드하고 압축을 풀겠습니다. VS Code에서 7회차 명세에따른변경 실습의 프로젝트 사본을 열고, 받은 코드 폴더의 source와 작성 양식을 가져오겠습니다. 기존 spec.md와 에이전트, 입력·조회 자료, 변경 전후 기록을 보존합니다. input/previous-work.md에 그 위치와 판본을 적겠습니다. 앞에서 만든 결과가 없으면 source의 참조 사례로 문서 작성은 할 수 있지만, 내가 만든 에이전트를 이어 검증했다는 기록은 남기지 않습니다.

## 다섯 경우의 행동 기준 직접 쓰기

scenarios.md에 일반 정비, 긴급 정비, 필수 정보 누락, 승인 거절, 도구 오류를 나눠 쓰겠습니다. 경우마다 Given에는 실제로 사용할 요청과 조회 자료, 설정과 시작 상태를 적습니다. When에는 확인할 행동 하나를 적고 Then에는 상태·필수 출력 항목·금지 행동의 발생 여부처럼 결과로 가릴 조건을 적겠습니다. 긴급 여부를 가르는 값과 경계는 앞 명세에서 가져오고, 답변을 받았다는 사실과 승인을 받았다는 사실은 구분합니다.

코딩 도우미에는 앞 명세와 입력 파일을 지정하고 이 다섯 경우의 초안을 요청하겠습니다. 도구 오류는 오류 응답을 받았을 때의 약속을 적되 서버를 끄거나 값을 망가뜨려 실패를 만들지는 않습니다. 기존 기록이나 준비된 대역이 해당 조건을 표현하는지 먼저 확인합니다. 근거가 없으면 그 경우의 실행 준비가 미완료라고 남깁니다.

## 기대와 관찰 위치 맞추기

각 Then 옆에 어느 출력 필드나 로그에서 확인할지 적겠습니다. 승인 거절은 확정이나 외부 실행이 생기지 않는지, 누락은 확인 질문 또는 보류가 명세대로 나오는지 연결합니다. 요청 처리 예제의 확정 상태가 실제 정비나 설비 명령 완료를 뜻하지 않는 점도 구별하겠습니다. 참조 시나리오는 이전 예제용이므로 현재 프로젝트의 필드와 요청 번호를 대조해 옮깁니다.

모호한 기대가 있으면 실행 결과로 판정할 수 있게 고치고, 원래 명세의 근거를 함께 남깁니다. 비교 대상이 문장 전체인지, 필수값인지, 허용 목록인지도 가르겠습니다. 원래 요구와 어긋난 기대는 지금 바로잡되, 아직 실행하지 않은 결과를 통과로 채우지는 않습니다.

## 저장과 다음 실습으로 넘기기

명세와 다섯 시나리오, 입력 파일 목록, 판정할 필드와 근거를 저장하겠습니다. 파일을 닫았다가 다시 열어 각 경우에 전제·행동·기대가 모두 있고 자료가 실제로 열리는지 확인합니다. 이 프로젝트를 다음 반복 검증의 입력으로 그대로 이어 쓰겠습니다.
