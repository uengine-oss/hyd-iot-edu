# 통합반 9회차 실습 3 — 시스템연결

> [진행 — 낭독하지 않음] 강사 단독 진행용이다. 아래는 수업에서 수행할 절차이며 이번 문서 제작에서는 실제 실습·학생 코드/테스트·AI 시연·HYD/DB·브라우저·캡처를 실행하지 않았다. 실제 결과는 수업에서 작성한다.

## 그림과 비교 자료 준비하기

앞에서 그린 흐름을 포털에 등록된 기준 흐름과 견주고, 내가 그린 작업마다 어떤 실행 기능에 대응하는지 표시하겠습니다. 여기서 기준 흐름은 수업용으로 미리 등록해 둔 시나리오 A 흐름 「냉각 긴급 대응」과 그 제공 매핑입니다. 아무 수업 흐름도 쓰지 않을 때 경보를 받는 원래 흐름과는 다른 것입니다. 이번에는 내 그림을 새로 등록하거나 포털에 올리지 않습니다.

> [준비 · 비낭독] 시스템연결 ZIP을 내려받아 압축을 풀고 VS Code에서 랩 폴더를 열어 START.md를 읽겠습니다. 앞 실습의 cooling.bpmn, 조건표, 요소 대응표를 코드/input에 가져옵니다. 랩 폴더의 reference에 있는 cooling-emergency.bpmn과 mapping.json은 제공 기준 BPMN과 매핑이며 고치지 않습니다. 결과는 코드/output/실행연결_대응표.md에 적겠습니다.

내 그림의 요소 id와 이름, 종류, 레인을 대응표 왼쪽에 먼저 옮기겠습니다. 매핑을 열기 전에 작업마다 어떤 실행 기능이 붙을지 예상 칸에 적어 둡니다.

## 등록된 기준 흐름 보기

제공 기준 BPMN을 편집기에서 열고, 포털의 승인과 실행 화면에서 업무 흐름 그림을 보겠습니다. 처리 건 화면에 냉각 긴급 대응 처리 건이 있으면 흐름 이름과 판본, 단계도 확인해 비교한 대상 칸에 적습니다. 그림 파일의 프로세스 id와 포털에서 보이는 흐름 이름은 따로 적습니다.

내 그림과 기준 흐름의 레인, 작업, 갈림, 끝을 나란히 놓겠습니다. 이름은 같아도 레인이나 종류가 다른 작업, 한쪽에만 있는 작업이나 갈림을 그대로 적습니다.

## 제공 매핑에서 다섯 연결 찾기

mapping.json에서 다섯 연결을 찾겠습니다. 시작 이벤트는 start의 경보 패턴 COOLER_DEGRADATION입니다. 원인 진단·제안 작업은 판단·제안 부품과 냉각 대응 에이전트, 운전원 승인은 조치 카드 승인·거절 부품과 운전원 역할입니다. 냉각 명령은 PLC 명령 발행, 재관측은 재관측 부품입니다. 키와 값을 대응표에 적고 내 그림에서 해당 요소 id를 찾아 옆에 둡니다.

레인 이름이 담당자라고 해서 그 작업의 승인 역할이 정해지는 것은 아닙니다. 승인 역할은 매핑의 role에 있습니다. 그림의 레인과 실행 정의의 담당을 따로 적겠습니다.

## 그림 파일과 실행 정의 구분하기

내 작업마다 대응하는 기준 요소와 실행 기능, 담당을 채우겠습니다. 내 작업 하나가 기준 작업 둘에 걸치거나 맞는 작업이 없으면 대응함, 다르게 대응, 대응 없음 중 무엇으로 표시할지 근거를 보고 정합니다.

승인 선에 승인이라고 이름을 붙였지만 실행 조건 approval 같음 승인은 매핑의 flows에 있습니다. 회복 조건 recovered 같음 true도 flows에, 승인 지연 기한 PT10M은 timers에 있습니다. 선에 이름을 붙이는 것과 실행 정의에 조건이 있는 것은 다릅니다. 그림 파일과 실행 정의 표를 채우겠습니다.

## 저장과 다음 실습으로 연결하기

대응표를 저장하고 다시 열어 근거 칸이 비지 않았는지 확인하겠습니다. 다음 실습에서는 포털의 준비된 시나리오 A로 처리 건 하나를 실행하고, 이 대응표를 옆에 두고 실제 기록을 내 그림과 잇겠습니다.
