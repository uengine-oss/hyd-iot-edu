# 통합반 9회차 실습 1 — 승인절차작도

> [진행 — 낭독하지 않음] 강사 단독 진행용이다. 아래는 수업에서 수행할 절차이며 이번 문서 제작에서는 실제 실습·학생 코드/테스트·AI 시연·HYD/DB·브라우저·캡처를 실행하지 않았다. 실제 결과는 수업에서 작성한다.

## 자료를 내려받고 작업 공간 열기

정비 요청의 담당 확인과 승인·반려를 업무 흐름으로 만들고, 뒤의 냉각 대응에 이어 쓰겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 승인절차작도 ZIP을 내려받아 압축을 풀겠습니다. VS Code에서 랩 폴더를 열어 START.md와 코드/source/request.md를 읽겠습니다. 이번에 그릴 작은 업무는 정비 요청을 받아 담당자가 확인하고, 승인 또는 반려로 닫는 절차입니다. 이 파일은 작도할 업무의 입력 설명이지, 승인된 결과가 아닙니다. 이번 실습은 앞 단계 결과 없이 빈 그림에서 시작합니다.

## 시작·작업·갈림·끝을 직접 그리기

수업에서 사용할 bpmn.io 편집기를 열고 새 다이어그램을 만들겠습니다. 시작 원을 선택해 이름을 정비 요청으로 바꿉니다. 팔레트의 작업을 놓거나 선택한 요소의 연결 메뉴로 작업을 추가하고 담당자 확인이라고 적겠습니다. 이 작업은 사람이 판단하므로 사용자 작업으로 종류를 바꾸겠습니다. 단순히 글자에 담당자라고 쓰는 것과 작업 종류를 고르는 것은 다릅니다.

담당자 확인 뒤에는 배타 게이트웨이를 놓고 승인 여부라고 이름을 붙이겠습니다. 여기서 선 두 개를 각각 다른 끝 이벤트로 연결합니다. 하나는 승인 종료, 다른 하나는 반려 종료입니다. 선을 선택해 승인과 반려라는 이름을 붙이겠습니다. 승인으로 가는 선과 반려로 가는 선이 같은 끝으로 잘못 이어지지 않았는지 출발점부터 따라가겠습니다.

이 단계에서는 업무의 두 결말을 읽을 수 있는 그림을 만드는 것이 목적입니다. 선에 승인이라고 써 놓았다는 사실만으로 실제 입력값을 검사하는 조건이 생기지는 않습니다. 실행할 변수와 조건은 그림이 아니라 실행 정의의 연결 값에 있고, 뒤의 비교 실습에서 포털에 등록된 흐름의 제공 매핑으로 확인합니다. 시작에서 담당자 확인으로, 거기서 갈림을 거쳐 두 끝으로 가는 순서를 먼저 완성하겠습니다.

## 파일의 구조와 그림 대조하기

그림을 output/approval.bpmn으로 저장하고 VS Code에서 XML도 열겠습니다. 화면의 작업과 게이트웨이, 두 끝 이벤트에 각각 어떤 id가 붙었는지 element-map.md에 적습니다. sequenceFlow의 sourceRef와 targetRef가 실제 요소를 가리키는지 그림의 선과 맞춰 보겠습니다. 식별자는 외워 읽기 위한 것이 아니라 다음 연결에서 같은 요소를 찾기 위한 값입니다.

코딩 도구에는 이 파일에서 끊긴 참조나 이름 없는 분기가 있는지 검토하도록 요청하겠습니다. 답변만 보고 완료하지 않고 지적한 요소를 편집기에서 직접 찾습니다. 잘못 연결된 선이나 빠진 이름이 있으면 고치고 두 경로를 다시 따라갑니다. 문제가 없으면 시연을 위해 일부러 선을 끊지는 않겠습니다.

## 저장한 파일 다시 열기

수정한 파일을 다시 내려받아 같은 output 위치에 판본을 구분해 저장하겠습니다. 편집기에서 저장한 파일을 다시 열어 요청, 담당자 확인, 승인 여부와 두 끝이 남아 있는지 확인합니다. review.md에 확인한 파일과 남은 항목을 적고 작업 공간도 닫았다 다시 열겠습니다. 다음 실습에서는 이 작은 승인 절차를 출발점으로 역할과 다른 업무 단계를 더하겠습니다.
