웹 BPMN 편집기로 정비 요청 승인 절차 그리기

VS Code에서 이 폴더(이 안내 파일이 있는 폴더)를 열고 START.md를 함께 읽으세요. 이 안내는 START.md와 같은 내용입니다.

출발점이번에 할 것작업 순서기대 결과를 먼저 적을 사례 종류학생이 정할 것이번 범위 밖완료 조건저장과 다음 실습

웹 BPMN 편집기(bpmn.io)의 기본 조작을 익히면서, 정비 요청을 담당자가 확인하고 승인 여부에 따라 승인 종료 또는 반려 종료로 닫는 승인 절차를 직접 그려 .bpmn 파일로 만듭니다. 이 그림을 처음 보는 사람이 누가 무엇을 결정하고 어디서 끝나는지 읽을 수 있어야 하고, 다음 실습에서 긴급 대응 흐름의 출발점으로 씁니다.

출발점

  • 코드/source/request.md: 그릴 업무의 입력 설명입니다. 실제 요청 번호·담당자·승인 결과는 없습니다.
  • 코드/input/: 이번 실습은 앞 단계 결과 없이 시작합니다.
  • 코드/output/: 이번 결과를 저장할 자리입니다. 지금은 비어 있습니다.
  • 코드/element-map.md, 코드/review.md: 요소 ID 대응과 확인 기록의 제공 빈 틀입니다.
  • 편집기: 브라우저에서 demo.bpmn.io를 엽니다. 설치는 필요하지 않습니다.

bpmn.io는 업무 흐름을 BPMN 표준 기호로 그리는 웹 편집기입니다. 왼쪽 팔레트에서 요소를 놓고, 요소를 선택하면 나오는 작은 메뉴로 다음 요소를 잇거나 종류를 바꿉니다. 오른쪽 속성 칸이 보이면 이름과 ID를 읽을 수 있고, 저장하면 BPMN XML 파일(.bpmn)이 내려받아집니다.

이번에 할 것

  • 팔레트·요소 배치·연결·속성 확인·저장·열기를 직접 해 봅니다.
  • 정비 요청(시작) → 담당자 확인(사용자 작업) → 승인 여부(배타 게이트웨이) → 승인 종료·반려 종료를 그립니다.
  • 게이트웨이의 두 갈래가 각자의 끝 이벤트에 닿는지 확인합니다.
  • 코드/output/approval.bpmn으로 저장하고 다시 엽니다.

작업 순서

  1. 코드/source/request.md를 읽고 그릴 요소를 자기 말로 정리합니다.
  2. 새 그림에서 시작 이벤트 이름을 「정비 요청」으로 하고, 「담당자 확인」 작업을 놓아 사용자 작업으로 바꿉니다.
  3. 배타 게이트웨이 「승인 여부」를 놓고 두 선을 각각 승인 종료·반려 종료로 잇고 이름을 붙입니다.
  4. 시작에서 각 끝까지 따라가며 끊긴 선이나 같은 끝으로 잘못 이어진 갈래가 없는지 봅니다.
  5. 코드/output/approval.bpmn으로 저장하고 VS Code에서 XML을 열어 sequenceFlow의 sourceRef·targetRef가 그림의 요소를 가리키는지 확인합니다. 요소 ID를 코드/element-map.md에 적습니다.
  6. AI 코딩 도구에 끊긴 참조나 이름 없는 갈래가 있는지 검토를 요청했다면, 답만 보고 끝내지 말고 지적한 요소를 편집기에서 직접 찾아 확인합니다.
  7. 편집기에서 파일을 다시 열어 같은 그림인지 확인하고 코드/review.md에 적습니다.

기대 결과를 먼저 적을 사례 종류

그리기 전에 코드/review.md의 「입력과 기대」에 먼저 적습니다.

  • 승인 경로와 반려 경로가 각각 지나는 요소와 닿는 끝
  • 다시 열었을 때 이벤트·작업·게이트웨이·선의 개수
  • 표시 이름과 요소 ID가 XML에서 어떻게 다르게 보일지

학생이 정할 것

담당자가 결정을 내리는 작업과 흐름이 갈라지는 게이트웨이에 어떤 이름을 붙일지 정합니다. 게이트웨이 이름을 질문(예: 승인했는가?)으로 쓸지 결정 이름으로 쓸지 고르고, 처음 보는 사람이 결정 주체를 헷갈리지 않는 쪽을 택한 이유를 코드/review.md에 적습니다.

이번 범위 밖

설비 이상 대응·역할 레인·타이머(다음 실습), 선의 실행 조건 값, 에이전트·역할 연결, 포털로 흐름을 보내는 일. 선에 「승인」이라고 이름을 붙인 것만으로 실행 조건이 생기지는 않습니다.

완료 조건

  • 코드/output/approval.bpmn을 다시 열면 시작·사용자 작업·배타 게이트웨이·끝 둘이 있고, 두 갈래가 각자의 끝에 닿습니다.
  • 끊긴 선과 이름 없는 갈래가 없습니다.
  • 코드/element-map.md에 요소 ID가, 코드/review.md에 기대와 실제가 있습니다.

저장과 다음 실습

결과 파일을 저장하고 다시 열어 확인하세요. 보관할 결과는 재부팅 전에 USB 또는 개인 클라우드에 복사하세요. 다음 실습에서는 이 승인 절차를 출발점으로 설비 이상 대응의 역할 레인과 승인 지연 알림을 그립니다.
