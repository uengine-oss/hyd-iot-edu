01 폴더와 출발점 확인

포털 지식 관리에서 매뉴얼을 올려 추출을 요청하고, 후보를 원문과 나란히 놓고 고쳐 적재하는 것을 봤습니다. 이번에는 그 일을 직접 합니다 — 수업 모델에 보낼 요청 글을 내가 짜고, 받은 후보가 원문 어디에 있는지 코드로 찾고, 판정에 쓴 조건이 어느 문서의 어느 문장에서 왔는지 확인합니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건인 10월 27일 01:59 HYD-02 쿨러 성능 저하 경보이고, 그 판정 뒤에 남은 근본 조치 — 쿨러 핀 세척(SOP-COOL-14) — 의 작업지시를 내기 전입니다.

문서 묶음은 10개입니다 — 같은 매뉴얼의 판이 여럿이고, 판 · 상태 · 언어 · 형식이 문서마다 다릅니다. 모델의 답은 같은 요청에도 매번 다를 수 있어서, 받은 후보를 원문 줄과 코드로 대조해야 업무에 쓸 수 있습니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 문서 지식 — 원문에서 근거 있는 후보를 뽑아 사람이 검토하는 일 — 을 맡습니다.

받기 이 폴더는 「실습 시작」 도구로 받습니다. 도구에서 과정 → 회차 → 실습을 고르고 새로 시작을 누르면 이 판본만 새 폴더에 받아 풀고, VS Code에 이 폴더와 START.md를, 브라우저에 이 가이드를 엽니다. 이어서 할 때는 이전 작업 열기를 누릅니다 — 새로 시작은 늘 새 폴더에 받으므로 고친 파일을 덮지 않습니다. 받기에 실패하면 한 번 더 시도하고, 그래도 안 되면 수동 ZIP으로 받은 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 그 폴더를 엽니다.

필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot, 강의에서 받은 수업 모델 접속 세 줄(없으면 4단계의 안내).

말 풀이 수업 모델은 강의에서 쓰는 언어 모델이고, 이 폴더의 llm_client.py가 .env의 접속 세 줄(접속 주소 · 키 · 모델 이름)로 모델 서버에 요청을 보내 부릅니다. 요청 글(프롬프트)은 모델에게 보내는 작업 지시입니다. 후보는 모델의 답에서 뽑아 계약 꼴로 적은 조건 · 단계 하나이고, 사람이 원문과 대조해 결정하기 전에는 지식으로 쓰지 않습니다. 인용은 후보의 근거가 되는 원문 부분을 글자 그대로 옮긴 것, 응답 기록은 보낸 요청과 받은 답을 결과/응답_기록/에 남긴 파일입니다. 조건표는 조치마다 어떤 입력이 어떤 값일 때 경고 · 감점 · 제외하는지 적은 판단 조건의 표, SOP 구조는 조치의 작업 절차를 구조로 옮긴 것, 판정 결과는 그 조건표로 지난 경보마다 조치 후보를 판정한 결과입니다. 계약은 결과 파일의 모양(열 · 키와 그 뜻)을 정해 둔 입출력_계약.md입니다 — 다음 실습의 기능이 이 모양 그대로 읽습니다.

내 앞 결과를 쓸 때: 제공 입력은 그대로 두고 내 조건표.csv · sop.json · result.json을 결과/내_입력/에 복사해, 열 이름 · 키가 입출력_계약.md 「입력」과 같은지 먼저 견준 뒤 씁니다. 구조 검사는 결과/내_입력/에 있는 파일을 기준으로 보고, 어느 파일을 봤는지 첫 줄에 찍습니다. 내 결과가 없어도 제공된 입력으로 끝까지 할 수 있습니다.

수업 모델 접속 세 줄이 없을 때도 같은 학생용 완성본 묶음으로 결과를 확인할 수 있고, 키 없이 한 조각만 채팅으로 받아 보는 길은 4단계와 10단계에 있습니다.

02 사건 경보와 이 작업 확인

왜 하는가 판정은 지금 바로 할 조치를 고르지만, 원인을 없애는 근본 조치는 따로 남습니다. 어느 경보의 어느 판정 뒤에 무엇이 남았는지 알아야 문서 묶음에서 어느 작업의 조건을 찾을지 정해집니다. 판정 결과의 시각은 UTC라 한국 시각보다 9시간 이릅니다.

할 일 AI에게 파일을 바꾸지 말고 입력/result.json에서 사건 경보(10월 27일 01:59 HYD-02 쿨러 성능 저하 경보)를 찾아 달라고 해, 그 경보의 1위 조치와 함께 순위에 오른 핀 세척(SOP-COOL-14)을 보고, 핀 세척이 즉시 완화가 아니라 원인을 없애는 근본 조치라는 것을 입력/sop.json과 원문 줄로 확인합니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘을 누르면 채팅 창이 열립니다. 입력하기 전에 창 위쪽 탭이 Codex인지 확인합니다. GitHub Copilot을 쓰면 같은 창의 Chat 탭을 엽니다(처음 열면 GitHub 로그인 창이 뜹니다). 창 아래 입력 칸에 요청을 내 말로 적어 보내고, 답에 나온 파일을 왼쪽 탐색기에서 열어 가운데 편집기의 실제 줄을 읽습니다. AI가 「완료」라고 해도 실제 파일과 실행 출력으로 확인합니다.

AI가 파일을 만들거나 고치려 하면 편집 승인 창(Allow ChatGPT to edit the following file?)이 뜹니다. 창에 적힌 경로가 결과/ 아래이고 내가 요청한 변경이면 Allow once(이번 한 번 허용)를 누르고, 입력/ · 자료/의 파일이거나 요청하지 않은 파일이면 Deny(거부)를 누른 뒤 까닭을 채팅으로 알립니다. GitHub Copilot을 쓰면 바뀐 파일의 경로를 같은 기준으로 보고, 요청하지 않은 변경은 되돌립니다.

정하거나 물을 것 사건 경보가 판정 결과의 어느 경보이고, 핀 세척이 근본 조치라는 근거가 어느 파일의 어느 줄인지 묻습니다.

03 파일을 바꾸지 않고 자료 파악
