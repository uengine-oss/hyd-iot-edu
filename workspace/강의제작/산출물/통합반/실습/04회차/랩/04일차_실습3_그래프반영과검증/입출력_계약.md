# 입출력 계약

입력과 결과 파일의 형식과 뜻만 정한다. 무엇을 어떤 종류 · 관계로 담을지, 새 대상의 ID를 어떻게 지을지는 정하지 않는다. `check.py`가 이 계약의 구조를 검사한다.

## 1. 입력(읽기만)

- `입력/모델/schema.json` · `입력/모델/graph.json` — 설비 모델. 형식은 schema.json 그대로다: `classes`(종류마다 뜻 · 필수 · 선택 속성) · `relations`(관계마다 시작 · 끝 종류) · `constraints`. graph.json은 `nodes`(`labels` · `props`)와 `rels`(`type` · `a` 시작 ID · `b` 끝 ID · `props`)이고, ID는 그래프 전체에서 고유하다.
- `입력/조건표.csv` — 냉각 계통 조치의 조건표. 열 `rule_id,action,condition_index,logic,input,operator,value,unit,boundary_included,result,penalty_manwon,reason,source_section`. 비교 하나가 한 행이고, 같은 `rule_id` · `action`의 행이 한 규칙 묶음이다. `action`은 그 규칙이 걸리는 조치(SOP ID), `input` · `operator` · `value` · `unit`은 비교, `result`는 `WARN`(경고) · `PENALTY`(감점) · `EXCLUDE`(제외), `reason`은 규칙의 이유, `source_section`은 그 규칙을 가져온 곳이다.
- `입력/sop.json` — SOP 구조. `document`가 가리키는 문서(식별자 · 판 · 파일)의 조치 절차를 구조로 옮긴 것이다. sop.json 키의 뜻: `document` 원문 문서, `failure_modes` 고장 유형, `causes` 원인, `sops` 조치 절차(`id` · `name` 이름 · `kind` 조치 종류(없으면 null) · `codes` 실행 코드 · `source` 출처 · `failure_mode` 고장 유형 · `model_refs` 모델 참조 · `apply_conditions` 적용 조건 · `prohibitions` 금지 조건 · `steps` 수행 단계 · `completion` 완료 기준 · `approval` 승인(`role` 역할)), `relations` 관계 목록. 항목마다 `text`는 원문 문장, `rules`는 그 조건을 옮긴 조건표의 `rule_id`다.
- `입력/검토결과/<문서 식별자>_<판>_검토.json` — 문서에서 뽑은 후보를 원문과 대조해 결정을 적은 검토 결과. 최상위에 `doc_id` · `rev` · `doc_status` · `source_file` · `source_sha256`(읽은 파일의 SHA-256)과 `review`(검토자 · 시각 · 검토 전체에 적용한 결정 `decisions`)가 있다. `candidates`의 후보 하나는 `id`(파일 안에서 고유) · `section`(그 문서의 절 표기 그대로) · `procedure`(절차 안이면 절차 표기, 아니면 `null`) · `kind`(`step` 단계 · `precondition` 시작 조건과 승인 · `prohibition` 금지와 제한 · `completion` 완료 기준 · `unit_value` 숫자와 단위가 있는 기준값) · `text` · `quote`(원문 그대로) · `line_start` · `line_end`(원문 파일의 줄) · `refs`(인용이 가리키는 다른 절 · 절차) · `decision`(`채택` · `수정` · `제외` · `보류`) · `status`(채택 · 수정 → `approved`, 제외 → `excluded`, 보류 → `pending`) · `reason`(결정 이유)이다. 스캔본은 `page`, 영문 원본과 번역이 함께 있는 문서는 `lang`이 더 있고, 기준값은 `value` · `unit` · `comparator` · `value_text`가 더 있다. `missing`은 원문에 있는데 후보가 없던 것, `rule_links`는 조건표의 조건(`rule_id`)마다 근거로 본 후보 id(`candidates`) · 맞는 정도(`match`: 일치 · 불일치 · 원문 없음 · 보류) · 까닭(`note`)이다.
- `자료/` — 검토한 문서의 원문과 `자료/문서_목록.csv`(첫 줄은 내보내기 머리, 둘째 줄이 열 이름: 문서 식별자 · 제목 · 판 · 상태 · 시행일 · 소유 부서 · 대체 관계 · 파일 · SHA-256 · 비고 — 파일 칸이 빈 행은 목록에만 있고 받은 파일이 없는 문서).
- `결과/내_입력/` — 내 앞 결과를 쓸 때 위 `입력/`의 파일과 같은 이름 · 같은 자리(`결과/내_입력/검토결과/` 등)로 둔다. 있으면 `lab_cypher.py model`과 `check.py`는 그 파일을 쓴다.

## 2. 설비 모델과 조치 기준의 그래프 (`python lab_cypher.py model`이 랩 DB에 올리는 것)

설비 모델의 노드 · 관계를 그대로 올리고, SOP 구조와 조건표를 아래 이름으로 더한다. 다시 실행해도 늘지 않는다(ID로 찾고 없으면 만든다).

| 종류 | ID | 속성 |
|---|---|---|
| `FailureMode` 고장 유형 | sop.json의 `failure_modes[].id` | `name` · `source` |
| `Cause` 원인 | `causes[].id` | `name` · `source` |
| `Skill` 조치 방법(SOP 하나) | `sops[].id` | `name` · `kind` · `codes` · `source` · `apply_conditions` · `prohibitions` · `completion`(각 항목의 문장 목록) · `approval_role` · `approval_source` |
| `Step` SOP 단계 | `<SOP ID>:<단계 번호>` | `order` · `text` · `source` |
| `Rule` 조건표의 규칙 | 조건표의 `rule_id` | `effect`(`WARN` · `PENALTY` · `EXCLUDE`) · `when`(비교를 사람이 읽게 이은 글) · `penalty_manwon` |

| 관계 | 시작 → 끝 | 뜻 · 속성 |
|---|---|---|
| `HAS_STEP` | Skill → Step | SOP의 단계 |
| `MITIGATED_BY` · `REMEDIED_BY` | FailureMode → Skill | 즉시 완화 · 근본 조치(`source`) |
| `ADDRESSES` | Skill → Cause | 근본 조치가 없애는 원인(`source`) |
| `ACTS_ON` | Skill → Component | 조치가 다루는 구성 요소(sop.json `model_refs.components`) |
| `CHECKS` | Skill → Sensor | 조치의 판정 · 완료 확인에 쓰는 센서(`model_refs.sensors`) |
| `OUTPUTS` | Rule → Skill | 그 규칙이 걸리는 조치(`reason` · `source_section` — 조건표 그 행의 값) |

## 3. 결과

- `결과/schema_ext.json` — 문서 근거를 담으려고 더한 종류 · 관계. 꼴은 `입력/모델/schema.json`과 같다(`classes` · `relations`). 기존 종류 · 관계 이름은 그 뜻 그대로 다시 쓰고, 새 이름에는 뜻을 적는다.
- `결과/` 아래 적재 파일(`.cypher`, 또는 적재 문장을 만드는 코드와 그 출력) — 같은 파일을 다시 실행해도 노드 · 관계 수가 늘지 않는다. 전체를 지우는 문장은 쓰지 않는다.
- `결과/query.cypher` — 질문마다의 조회문(읽기만).
- `결과/지식_내보내기.json` — `python lab_cypher.py export 결과/지식_내보내기.json`이 쓴다. 꼴은 `입력/모델/graph.json`과 같고(`nodes` · `rels`), `remaining_questions`가 더 있다.
- `결과/남은_질문.json` — 그래프에 넣지 않은 것 가운데 답하려면 더 알아야 하는 것. `[{"item": "…", "kind": "보류 | 원문 미확인 | 제공되지 않은 절 | 제공되지 않은 문서 | 현재 값 필요", "source": "…", "note": "…"}]`. 내보내기가 이 목록을 `remaining_questions`에 넣는다.
- `결과/구축_기록.md` — 「제공 빈 틀」의 칸대로 채운다.
