검토한 문서 지식을 그래프 DB에 반영하고 관계 확인하기

검토해 승인한 문서 지식을 랩 DB의 설비 모델과 조치 기준에 기존 ID로 잇습니다. 가이드의 다섯 질문으로 조회한 답을 원문과 견주고 하나의 온톨로지 구축 결과로 저장합니다. 과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라가며, 이 실습은 온톨로지 단계의 문서 지식을 맡습니다. 단계마다 지금 할 일과 확인할 결과를 보고 진행하고, 막히면 「정답 보기」의 요청을 앞 단계에서 확인한 내용에 이어 보냅니다.

01 폴더 열고 검토 결과 확인하기

클래스룸의 4회차 실습 자료에서 ZIP을 받아 압축 풀기를 선택합니다. VS Code의 파일 → 폴더 열기에서 knowledge-graph-lab 폴더를 엽니다. 함께 풀린 가이드는 브라우저로 엽니다.

신뢰 여부를 물으면 예, 작성자를 신뢰합니다(Yes, I trust the authors)를 선택합니다. 제한 모드에서는 Codex를 사용할 수 없습니다.

README.md에서 폴더 역할을 봅니다. data/reviews/는 문서에서 뽑은 지식 후보를 원문과 견줘 결정을 적은 검토 결과로, 문서 지식을 추출 · 검토하는 실습의 결과와 같은 꼴입니다. data/model/은 설비 모델, data/sop.json · data/conditions.csv는 조치 기준, data/documents/는 원문입니다. 적재 · 조회 · 내보내기는 제공 코드가 하고, app/features/에는 무엇을 어디에 이을지 내가 정해 채우는 빈 틀이 있습니다. AGENTS.md는 Codex의 공통 작업 원칙입니다.

사건은 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보이고, 그 판정 뒤에 남은 근본 조치가 쿨러 핀 세척(SOP-COOL-14)입니다. 이 답은 설비보전팀장이 핀 세척과 냉각 조치의 조건 · 근거를 그래프로 찾을 때 씁니다.

내 앞 결과를 쓰는 것은 선택입니다. 쓸 때는 형식이 data/contract.md 「입력」과 같은지 먼저 견주고, app/features/my_inputs/에 data/와 같은 이름 · 같은 자리로 복사합니다(검토 결과는 my_inputs/reviews/). 넣은 검토 결과는 제공 검토 결과를 통째로 대신하므로, 내 결과에 없는 문서의 행은 연결 규칙에서 뺍니다. 제공 입력은 그대로 둡니다.

터미널 → 새 터미널을 엽니다. 오타를 줄이도록 명령은 직접 치지 말고 블록의 복사로 붙여 넣습니다.

터미널(PowerShell · 이 실습 폴더)

python run.py

검토 결과마다 승인 · 보류 · 제외 수와 조건 근거 견주기, 기존 ID 수, 승인 후보 찾아보기 표가 보입니다. 결과는 output/result.html에 저장됩니다. 브라우저가 열리지 않으면 Windows 파일 탐색기로 이 실습 폴더의 output 폴더를 열고 result.html을 두 번 누릅니다(VS Code 탐색기에서 누르면 화면이 아니라 HTML 글이 열립니다). 이후에는 명령을 실행한 뒤 열린 화면에서 F5를 누릅니다.

02 Codex와 기존 ID 찾기

문서 속 대상은 모델의 ID와 다른 이름 · 번호로 적혀 있을 수 있어, 어느 기존 ID를 가리키는지 먼저 봅니다. Codex 확장 아이콘을 눌러 채팅을 열고 로그인합니다. 계정이 없거나 막히면 클래스룸에서 따로 받는 knowledge-graph-lab-completed.zip을 실행해 볼 수 있습니다.

파일을 바꾸지 말고, 승인 후보가 가리키는 대상(설비 · 구성 요소 · 부품 · SOP · 단계 · 규칙)이 설비 모델 · SOP 구조 · 조건표의 어느 ID인지 물어봅니다. 짚은 ID와 줄은 data/model/graph.json · data/sop.json · 원문에서 직접 엽니다.

후보 대상과 기존 ID의 짝 몇 개를 말할 수 있으면 이어 갑니다. 짚은 ID나 줄이 파일에 없으면 근거로 쓰지 않습니다.

03 질문과 기대 답 먼저 적기

질문이 모델의 범위를 정합니다. 조회 결과를 본 뒤에 기대를 적으면 빠진 연결이 기대에 맞춰 사라지므로, 원문과 검토 결과로 먼저 적어 둡니다.

물을 질문은 다섯입니다. ① HYD-02 냉각 성능 상실에서 쓸 수 있는 조치마다 수행 단계 · 준비 · 금지 · 완료 기준 · 승인과 근거 문서 · 판본 · 절 · 인용은? ② 판정에 쓴 규칙마다 근거 원문이 있고 조건과 무엇이 다른가? ③ 핀 세척 전에 확인할 현재값은 무엇이고 어디서 읽는가? ④ 다른 문서를 더 반영하면 그 문서의 작업은 어느 대상에 걸리고 앞의 연결은 그대로인가? ⑤ 제공되지 않은 작업이나 절을 물으면 그래프는 무엇을 돌려주는가?

app/features/expected.csv에 질문 1 · 2의 기대 답을 문서 · 절로, 질문 3은 읽을 원천 이름으로 적고(근거는 파일:줄), app/features/build_record.md에 목표 · 쓰는 사람 · 기대 칸을 쓴 시각을 적습니다. 같은 번호를 쓰는 다른 문서의 절, 판본이 다른 같은 문서, 근거 원문이 있는 규칙 · 범위가 다른 원문 · 원문이 없는 규칙, 설비 별칭 · 제조사 품번으로 적힌 대상도 찾아 둡니다. 원문 글자가 깨져 보이면 VS Code 오른쪽 아래 UTF-8을 눌러 Reopen with Encoding → Korean (EUC-KR)으로 다시 엽니다.

파일을 손으로 고친 뒤에는 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨). 저장하지 않으면 명령이 고치기 전 내용을 읽어 0행으로 보입니다.

Codex가 파일을 바꾸려 하면 편집 승인 창이 뜹니다. app/features/ 아래 요청한 파일이면 Allow once, 그 밖의 경로면 Deny를 누릅니다. 요청에 파일 이름을 쓸 때는 백틱()으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다. python run.py` 명령은 내 터미널에서 실행하고, 터미널 출력과 결과 화면으로 확인합니다.

06 승인 지식을 기존 ID에 잇고 적재하기

문서 속 대상은 모델과 다른 이름(설비 모델명 · 제조사 품번)으로 적혀 있어, 어느 기존 ID를 가리키는지 정해야 새 대상을 지어내지 않고 잇습니다. 승인한 것만 이어야 이 지식을 쓰는 쪽이 근거 있는 지식만 씁니다.

app/features/link_rules.csv에 검토 결과의 문서마다(필요하면 절마다) 승인 후보를 어느 기존 ID에 어떤 관계로 이을지, aliases.csv에 원문의 이름 · 품번이 가리키는 기존 ID, roles.csv에 조치에 잇는 지식의 항목을 적습니다. 제조사 지침과 예비품 기준의 행은 다른 문서 추가 단계에서 채웁니다.

검토 결과의 결정(채택 · 수정 · 제외 · 보류)과 기존 ID · 종류 · 관계의 뜻은 바꾸지 않습니다. 바꿀 것은 추가 자료가 필요한 질문으로 남깁니다.

07 다른 문서의 조건 정하고 다시 적재하기

핀 세척(SOP-COOL-14)에 걸 다른 문서의 조건(시간 · 승인 · 준비)을 찾아, 그 문서의 적용 범위 절과 이 작업을 말하는 사내 문장을 원문으로 열어 이을지 정합니다. Codex가 고를 것을 내놓거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말합니다. 못 정하면 미결로 둡니다.

09 다른 문서 추가 반영하기

여러 문서가 같은 대상을 말할 때, 뒤에 넣은 문서가 앞의 연결을 덮거나 같은 번호의 다른 절을 같은 대상으로 합치면 앞에서 맞던 답이 바뀝니다. 더한 뒤 기존 노드 · 관계를 견주어야 반영 범위를 압니다.

10 답할 수 있는 범위 나누기

문서의 판단 기준은 그래프에 있지만, 작업 직전의 센서 값 · 작업지시 상태 · 재고는 시계열 · CMMS · ERP · MES 같은 원천 시스템에서 읽어야 합니다. 그래프가 무엇에 답하고 무엇에 답하지 못하는지 밝혀 두어야 이 지식을 쓰는 쪽이 읽을 곳을 압니다.

app/features/current_value_sources.csv에 핀 세척 전에 확인할 현재값과 읽을 원천을 적고(값 자체는 적지 않습니다) 실행합니다. 질문마다 그래프로 답하는지 · 현재값 필요 · 추가 자료 필요 · 원문에 없음인지를 app/features/build_record.md 「답할 수 있는 것과 없는 것」에 적습니다.

11 내보내고 저장해 다시 열기

내보내기는 지금 랩 DB의 그래프와 추가 자료가 필요한 질문을 한 파일로 남깁니다. 짚은 문제를 고친 뒤 아래 차례로 실행합니다: 내보내기 → 구조 검사 → 파일 → 모두 저장 → 폴더를 닫았다 다시 열기 → 랩 DB 다시 켜기 → 결과 다시 보기.
