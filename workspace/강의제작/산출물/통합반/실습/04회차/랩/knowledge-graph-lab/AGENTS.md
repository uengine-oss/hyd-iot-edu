# AI 작업 경계

- `data/`, `app/ui/`, `app/utils/`, `run.py`는 제공 파일이다. 원자료와 제공 코드를 보존한다.
- 요청받은 핵심 기능과 판단 기준은 `app/features/`에서 구현한다. 실행 결과는 `output/`에만 쓴다.
- 먼저 자료와 현재 코드를 파악하고, 요청한 기능 범위에서 작게 구현한다. 무관한 기능이나 문서를 추가하지 않는다.
- 사람이 자료를 물으면 구조·특징·어긋난 곳을 실제 예 줄(파일:줄)과 개수와 함께 보여, 사람이 몇 줄 열어 확인할 수 있게 한다.
- 원자료만으로 정해지지 않는 판단은 사람이 정한다. 사람이 물으면 선택지와 각 선택의 결과, 근거 줄을 보이고 추천안도 낼 수 있다. 사람이 고르고 이유를 말하기 전에는 그 판단에 걸린 결과를 만들지 않는다. 「알아서 해 줘」 「잘 만들어 줘」처럼 이유 없이 넘기면 무엇을 정해야 하는지 되묻는다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인, 값 없음, 0을 구별한다.
- 실제 실행한 명령·결과·변경 파일을 보고한다. 실행하지 않은 것을 성공했다고 말하지 않는다.
- 키와 비밀번호를 코드·결과·기록에 적지 않는다. 열어 둔 프로젝트 폴더 밖의 파일은 읽지 않는다.

- 빈 틀은 `app/features/`의 파일이다. 적재 · 조회 · 내보내기는 제공 코드가 하고 그 결과를 `output/`에 쓴다.
- 승인(`approved`) 후보만 적재한다. 기존 ID를 바꾸거나 모델에 없는 ID를 지어내지 않는다.
- 현재값(재고 · 작업지시 상태 · 센서 값)은 그래프에 넣지 않고 읽을 원천을 가리킨다.
- 그래프 모양, 다른 문서의 조건을 이을지, 무엇을 어느 기존 ID에 이을지는 사람이 정한다. 사람이 물으면 선택지와 각 선택으로 바뀌는 답, 근거가 되는 원문 줄을 보이고 추천안도 낼 수 있다. 사람이 고르고 이유를 말하기 전에는 그 결정의 `decisions.csv` 줄과 그 결정에 걸린 빈 틀을 채우지 않는다.
- `decisions.csv`와 `expected.csv`에는 사람이 대화에서 정한 것만 적는다. 사람이 보고 받아들인 근거 줄과 기대 답 후보도 사람이 정한 것이다. 기대 답 후보는 원문과 검토 결과에서 찾아 줄 번호와 함께 내고, 조회 결과나 `python run.py`가 낸 결과를 기대로 옮기지 않는다.
- DB는 이 폴더에 배정된 랩 DB만 사용한다. 포털 DB나 전체 삭제 명령을 쓰지 않는다. Docker와 랩 DB를 켜고 끄는 명령(`python run.py db` 등)은 사람이 자기 터미널에서 실행한다.
