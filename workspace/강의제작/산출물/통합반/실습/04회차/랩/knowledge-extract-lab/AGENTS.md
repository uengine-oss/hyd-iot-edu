# AI 작업 경계

- `data/`, `app/ui/`, `app/utils/`, `run.py`는 제공 파일이다. 원자료와 제공 코드를 보존한다.
- 요청받은 핵심 기능과 판단 기준은 `app/features/`에서 구현한다. 실행 결과는 `output/`에만 쓴다.
- 먼저 자료와 현재 코드를 파악하고, 요청한 기능 범위에서 작게 구현한다. 무관한 기능이나 문서를 추가하지 않는다.
- 사람이 자료를 물으면 구조·특징·어긋난 곳을 실제 예 줄(파일:줄)과 개수와 함께 보여, 사람이 몇 줄 열어 확인할 수 있게 한다.
- 원자료만으로 정해지지 않는 판단은 사람이 정한다. 사람이 물으면 선택지와 각 선택의 결과, 근거 줄을 보이고 추천안도 낼 수 있다. 사람이 고르고 이유를 말하기 전에는 그 판단에 걸린 결과를 만들지 않는다. 「알아서 해 줘」 「잘 만들어 줘」처럼 이유 없이 넘기면 무엇을 정해야 하는지 되묻는다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인, 값 없음, 0을 구별한다.
- 실제 실행한 명령·결과·변경 파일을 보고한다. 실행하지 않은 것을 성공했다고 말하지 않는다.
- 키와 비밀번호를 코드·결과·기록에 적지 않는다. 열어 둔 프로젝트 폴더 밖의 파일은 읽지 않는다.

- 빈 틀은 `app/features/`의 파일이다. 후보 · 검토 결과 · 응답 기록 · 요청 글은 제공 코드가 `output/`에 쓴다. 응답 기록(`output/model_responses/`)은 고치지 않는다.
- 수업 모델을 부르는 실행(`python run.py connect` · `trial` · `extract` · `other`)은 사람이 자기 터미널에서 한다. 키 · 접속 값을 채팅 · 파일 · 기록에 적지 않는다.
- 지식 후보는 모델의 답에서 만든다. `data/`의 SOP 구조 · 조건표를 후보로 옮기지 않고, 조건표 · 판정 결과는 바꾸지 않는다.
- 나누는 단위, 어느 문서를 따를지, 어느 원문을 조건의 근거로 둘지는 사람이 정한다. 사람이 물으면 선택지와 각 선택으로 바뀌는 답, 근거가 되는 원문 줄을 보이고 추천안도 낼 수 있다. 사람이 고르고 이유를 말하기 전에는 그 결정의 `decisions.csv` 줄과 그 결정에 걸린 빈 틀을 채우지 않는다.
- `decisions.csv`와 `expected.csv`에는 사람이 대화에서 정한 것만 적는다. 사람이 보고 받아들인 근거 줄과 기대 항목 후보도 사람이 정한 것이다. 기대 항목 후보는 원문에서 찾아 줄 번호와 함께 내고, 모델의 답이나 `python run.py`가 낸 결과를 기대로 옮기지 않는다.
