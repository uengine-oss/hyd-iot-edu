# 통합반 4회차 실습 3 — 검토한 문서 지식을 그래프 DB에 반영하고 관계 확인하기

## 그래프에서 찾을 답을 먼저 적기

핀 세척 작업지시를 내기 전에, 어떤 조건을 확인해야 하고 그 조건은 어느 판의 어느 절에서 왔을까요? 먼저 원문에서 기대하는 답을 적어 두겠습니다. 그래프에 자료를 넣은 다음 같은 질문으로 돌아오면 서로 다른 작업의 조건이 섞였는지도 알아볼 수 있습니다.

> [화면] 실습3 폴더의 입력/검토결과/에서 문서별 검토 파일 하나를 연다. 내 결과를 쓸 때는 계약을 확인한 파일만 결과/내_입력/검토결과/에 둔다. 입력/모델/, 입력/sop.json, 입력/조건표.csv에서 연결할 기존 ID를 찾고, 결과/기대_답.csv에 문서·절·기대 답을 적는다.

## 승인한 조건을 기존 작업에 연결하기

검토 파일에서 채택한 후보와 수정해서 승인한 후보를 찾아보세요. 제외하거나 보류한 후보도 검토 기록에는 남아 있습니다. 어느 상태가 적재 대상으로 선택되는지 비교해 보겠습니다. 다음으로 핀 세척 작업의 식별자를 찾아 승인한 조건과 원문 출처를 어디에 연결할지 정하겠습니다.

> [화면] 이 폴더에서 python lab_db.py로 랩 전용 DB를 열고 python show_result.py로 설비 모델과 조치 기준을 확인한다. 결과/그래프_모양.json, 결과/연결_규칙.csv, 결과/역할.csv와 필요한 별칭을 채운다. 결과/정한_것.csv에 고른 기준과 근거 줄을 적는다. 다른 문서의 조건을 같은 작업에 연결할 때에는 문장의 대상과 작업이 일치하는지 원문 줄을 연다.

## 같은 자료를 다시 넣고, 다른 문서도 더하기

같은 자료를 다시 넣으면 같은 조건이 두 번 생길까요? 두 번째 실행 뒤의 수를 첫 번째 실행과 견주겠습니다. 수가 같으면 질문으로도 확인해 보겠습니다. 핀 세척에 걸린 조건과 그 근거 절이 처음 기대한 답과 맞는지, 보류한 후보가 섞이지 않았는지 살펴보세요.

> [화면] 결과/다른문서_조건.csv에 적용 여부와 근거를 적은 뒤 python show_result.py를 두 번 실행한다. 결과/질문_값.csv에 대상과 보류 후보 둘을 지정해 조회한다. 제조사 지침이나 예비품 기준을 추가한 뒤에는 기존 노드의 속성 변화, 사라진 관계, 원문 출처를 각각 비교한다. 실제 차이는 결과/구축_기록.md에 기록한다.

## 그래프로 답할 질문과 원천에서 읽을 값

핀 세척 전에 어떤 조건을 확인해야 하는지는 작업과 문서를 따라가면 찾을 수 있습니다. 지금 현장에서 그 조건이 충족됐는지는 어디서 확인해야 할까요? 어떤 값은 원천을 조회해야 하고 어떤 확인은 사람이 맡습니다. 질문마다 찾은 근거와 아직 확인해야 할 일을 구분해 보겠습니다.

> [화면] 결과/현재값_원천.csv와 결과/남은_질문.json을 대조한다. 적재 단계에서 생긴 결과/schema_ext.json과 결과/load.cypher, 질문 단계에서 생긴 결과/query.cypher를 실제 조회 결과와 함께 확인한다. 마지막 단계에서 결과/지식_내보내기.json을 연다. 구조 검사 뒤 폴더를 다시 열어 같은 질문을 재현한다. 다음 실습에 넘길 파일은 결과/지식_내보내기.json, 결과/query.cypher, 결과/구축_기록.md다.
