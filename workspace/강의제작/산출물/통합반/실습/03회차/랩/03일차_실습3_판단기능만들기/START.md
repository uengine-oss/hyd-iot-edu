# 설비 조건별 최적의 조치를 비교하는 판단 기능 만들기

## 목표

포털에서 운전 모드와 설비 상태를 바꿔 판단을 다시 돌리고, 조건별 손익에서 순위가 바뀌는 것을 봤습니다. 포털은 사실을 자동으로 모아 한 건씩 판단했습니다. 이번에는 같은 일을 원천 기록에서 직접 하고, 지난 30일 경보 전체로 기능을 검증합니다. 사건은 포털에서 본 경보와 같은 종류의 다른 경보 한 건, 10월 27일 01:59(한국 시각) HYD-02 쿨러 성능 저하 경보 `ALT-hyd02-0172-54a5`입니다(경보 ID로 자료 · 결과 화면에서 찾습니다).

판정 기능은 조건표를 읽어 후보마다 경고 · 감점 · 제외와, 입력이 없어 맞는지 알 수 없는 정보 부족을 이유와 함께 내고, 허용 후보만 주어진 비교 산식으로 견줍니다. 판단 입력은 원천 네 곳(경보 · PLC 상태 · 팬 카운터 · 예측)에 흩어져 있고, 경보 60건마다 후보가 넷이라 손으로 다 맞출 수 없습니다.

원천 읽기 · 시각 · 단위 · 판정 · 산식 · 결과 쓰기는 제공 코드가 하고, 끊긴 기록을 어떻게 볼지와 어느 후보를 견줄지 — 쓰는 사람에 따라 방향이 갈리는 판단 — 는 내가 정할 자리에 AI와 구현합니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 판단 지식 — 조건표로 조치를 판정하고 견주는 일 — 를 맡습니다.

만들 것: 정할 자리 둘(`결과/gap_rule.py` · `결과/compare_rule.py`), `결과/정한_것.csv` · `결과/기대_판정.csv` · `결과/기대결과.md`(내가 AI와 채움), `결과/result.json`(제공 코드가 씀).

## 출발점

- `입력/조건표.csv` · `입력/sop.json` — 냉각 계통 조치의 조건표와 SOP 구조. 조치 기준 만들기 실습의 결과와 같은 꼴로 검증해 제공하는 판입니다.
- 내 조치 기준을 쓸 때: 제공 입력은 그대로 두고 내 `조건표.csv` · `sop.json`을 `결과/내_입력/`에 복사해, 열 이름 · ID가 `입출력_계약.md`와 같은지 먼저 견준 뒤 씁니다. 제공 코드와 구조 검사는 `결과/내_입력/`에 있는 파일을 기준으로 봅니다. 내 조치 기준이 없어도 제공된 입력으로 끝까지 할 수 있습니다.
- `자료/경보_목록.csv` · `자료/PLC_상태_수신.csv` · `자료/팬_운전_카운터.csv` · `자료/예측_결과.csv` — 판단 입력의 원천 네 개(HYD-01 ~ 03, 2026-09-28 ~ 10-27). 기록 방식은 `자료/수집_설명.md`에 있습니다.
- `자료/오더_현황.csv` · `자료/metrics/` — 주어진 비교 산식(`지표_정의.md`)과 그 값.
- `자료/HM-8_매뉴얼.md` · `자료/HI-01_보충매뉴얼.md` · `자료/작업기준.md` — 조치 원문 · 보충 기준 · 회사 작업 기준. `자료/targets.csv` — 경보마다 검토하는 조치 후보 넷.
- `입출력_계약.md` — 입력 · 정할 자리 · 결과 파일의 형식. `check.py` — 구조 검사. `judge_tools.py` · `condition_tools.py` — 제공 코드(고치지 않습니다).
- `show_result.py` · `lab_steps.py` — 결과 화면(`python show_result.py`가 채운 단계까지 제공 흐름을 돌려 `결과/보기.html`을 다시 씀). 고치지 않습니다.
- `결과/` — 정할 자리(「제공 빈 틀」)와 README.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.

## 해결할 질문

이 답은 야간 운전원이 경보가 났을 때 네 후보를 쓸 수 있는지, 견준 후보 가운데 무엇이 1위이고 왜인지, 아직 무엇을 확인해야 하는지 볼 때 씁니다.

1. 사건의 네 후보 — 판단 입력(원천 네 개, 판정을 요청한 시각 기준) · 판정(유지 · 제외 · 보류와 이유) · 비교값과 순위는 무엇인가?
2. 같은 기능이 지난 경보의 정상 · 경계 · 복수 조건 · 모두 제외 · 필수값 누락 사례에서 기대와 같은가?
3. 사건에서 1위는 무엇이고 그 까닭과 추가로 확인할 사항은 무엇인가? 이 비교값은 포털 성과 지표의 점수와 어떻게 다른가?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **빈 값의 뜻** — 정해진 주기로 남아야 할 기록이 빠져 판정을 요청한 때의 값을 기록에서 바로 읽을 수 없을 때, 끊긴 구간을 이어 판단 입력을 만들지 — 어느 원천의 어느 경보에 그런 구간이 있는지, 이을 근거가 원천에 있는지는 원천에서 찾습니다
- **쓰는 사람에 따라 갈리는 답** — 경고가 붙은 후보를 비교 산식으로 견주는 후보에 넣을지
- **비교 기준 문장** — 이 비교 합계가 무엇을 견주는 값인지, 포털 성과 지표의 점수 · 실행 승인과 어떻게 다른지 내 말로

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 조건표 · SOP 구조를 고치는 일(입력은 읽기만 합니다)
- 원문에서 작업 조건을 뽑거나 조건의 원문 근거를 다시 검토하는 일(다음 실습)
- 비교 산식을 바꾸는 일
- 실제 설비 조작과 실행 승인

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

파일의 모양은 `입출력_계약.md`에 있습니다. 끊긴 기록을 어떻게 볼지와 어느 후보를 견줄지는 원천과 원문을 읽고 직접 정합니다.

- 정할 자리(「제공 빈 틀」): `결과/gap_rule.py` · `결과/compare_rule.py`(빈 함수), `결과/정한_것.csv`, `결과/기대_판정.csv`, `결과/기대결과.md`.
- `결과/result.json` — 제공 코드 `judge_tools.py`가 정할 자리를 불러 씁니다(`python show_result.py`).

## 지킬 조건

- `입력/`은 읽기만 합니다.
- 규칙은 `입력/조건표.csv`에서 읽습니다(제공 코드가 읽습니다 — 정할 자리에 규칙을 다시 적지 않습니다).
- 비교 순위와 선택 이유를 실행 승인처럼 적지 않습니다.
- 제공 코드(`show_result.py` · `lab_steps.py` · `judge_tools.py` · `condition_tools.py` · `check.py`)는 고치지 않습니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(ZIP을 풀면 이 폴더 옆에 있는 `_guide.html` 파일)의 같은 번호에 있습니다.

1. **폴더와 출발점 확인 · 결과 화면 열기** — VS Code 탐색기에서 `입력/` · `자료/` · `결과/` · START.md를 열어 각 자리의 역할과 이번 질문을 확인하고, 터미널에서 `python show_result.py`를 실행해 결과 화면을 엽니다.
2. **파일을 바꾸지 않고 자료 파악** — AI에게 파일을 바꾸지 말고, 원천 네 개(경보 · PLC 상태 · 팬 카운터 · 예측)와 조건표 · 계약이 각각 무엇을 어떤 모양으로 담는지 파일:줄로 짚어 달라고 합니다. 결과 화면 1단계 표에서 판정 요청 직전 기록이 그 원천의 주기보다 오래된 경보 하나를 골라 원천 줄을 직접 엽니다.
3. **기대 판정 먼저 적기** — `결과/기대결과.md`에 목표 · 쓰는 사람 · 지킬 조건을 적고, 사건의 네 후보와 카운터 기록이 끊긴 경보 하나, 모든 후보가 제외될 것 같은 경보 하나, 예측 값이 조건표 기준값과 같거나 가장 가까운 경계 경보 하나의 기대 판정을 원천 줄 · 조건표 · 원문으로 손으로 구해 `결과/기대_판정.csv`에 근거 줄과 함께 적습니다. 다 쓰면 「기대 칸을 쓴 시각」을 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **계획 검토** — 제공 코드(`judge_tools.py`)가 판단 입력 → 판정 → 비교 → 결과 쓰기 가운데 어디서 두 정할 자리를 부르는지 AI에게 짚게 하고, 5 · 6단계 순서를 검토하고 동의합니다. 아직 파일을 만들지 않습니다.
5. **빈 값의 뜻 — 끊긴 카운터 기록** — `결과/gap_rule.py`의 함수를 AI와 채워, 카운터 기록이 판정 요청 전에 끊긴 경보의 팬 100 % 연속 시간을 내 결정대로 냅니다. 고른 것 · 근거를 `결과/정한_것.csv`에 한 줄 적고, 결과 화면에서 끊긴 경보의 값과 판정을 3단계 기대와 견줍니다. 실행은 내가 터미널에서 하고, AI가 답에 옮겨 적은 출력이 아니라 터미널에 나온 출력과 결과 화면으로 확인합니다 — 옮겨 적은 글은 실제 출력과 다를 수 있습니다.
6. **쓰는 사람에 따라 갈리는 답 — 견줄 후보** — `결과/compare_rule.py`의 함수를 AI와 채워, 유지 후보 가운데 비교 산식으로 견주지 않을 후보와 그 까닭을 내 결정대로 냅니다. 고른 것 · 근거를 `결과/정한_것.csv`에 적고, 결과 화면에서 순위와 손계산 예를 봅니다.
7. **비교 기준 문장과 결과 쓰기** — 이 비교 합계가 무엇을 견주는 값인지, 포털 성과 지표의 점수와 어떻게 다르고 1위가 실행 승인이 아닌 까닭을 `결과/정한_것.csv`의 「비교 기준 문장」 줄에 내 말로 적고, 결과 화면이 `결과/result.json`을 쓰는지 봅니다.
8. **사례 대조** — 3단계에서 `결과/기대_판정.csv`에 먼저 적은 기대(사건 · 끊긴 경보 · 모두 제외 · 경계)를 8단계 대조와 견주고, 「후보마다 판정 내용」 표를 걸러 다른 사례 종류(정상 · 복수 조건 · 필수값 누락)를 더 고르면 원천 줄로 기대를 먼저 적어 더한 뒤 견줍니다. 기대와 다른 줄은 원인이 판단 입력 · 판정 · 산식 가운데 어디인지 `결과/기대결과.md`에 적습니다.
9. **검사 · 저장하고 다시 열기** — 터미널에서 구조 검사를 실행해 짚은 문제를 고치고, 결과 파일을 모두 저장한 뒤 VS Code에서 폴더를 닫았다 다시 열어 `python show_result.py`와 구조 검사를 다시 실행합니다. `결과/기대결과.md` 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `자료/수집_설명.md`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 규칙이 하나도 맞지 않는 후보(정상)
- 조건표의 숫자 기준값마다(예측 유온 · 팬 연속 시간 등) 그 값과 같은 후보와, 그 값의 바로 위 · 아래에서 가장 가까운 후보(경계 — 단위가 다른 원천 포함)
- 경고 · 감점 · 제외가 한 후보에 함께 맞는 경우(복수 조건 — 감점이 규칙마다 한 번인지)
- 모든 후보가 제외된 경보
- 원천에서 값이 비는 까닭이 서로 다른 경보(필수값 누락 — 그 값이 필요한 규칙에만 영향이 가는지)
- 「정할 것」의 결정에 따라 판단 입력 · 순위가 바뀌는 경보
- `자료/metrics/지표_정의.md`의 손계산 예
- 같은 명령을 다시 실행한 결과

실행 명령:

```
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/` · `자료/` · 제공 코드가 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 사례 종류마다 실행 전에 적은 기대와 실행 결과가 같거나 다른 까닭을 찾아 적은 기록이 있고, 손계산 예의 네 손실이 프로그램 값과 같으며, 「정한 것」의 근거와 그 선택으로 바뀌는 판단 입력 · 순위를 설명할 수 있으면 완료입니다.
