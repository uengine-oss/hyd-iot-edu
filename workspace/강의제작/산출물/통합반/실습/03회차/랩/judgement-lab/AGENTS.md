# AI 작업 경계

- `data/`, `app/ui/`, `app/utils/`, `run.py`는 제공 파일이다. 원자료와 제공 코드를 보존한다.
- 요청받은 핵심 기능과 판단 기준은 `app/features/`에서 구현한다. 실행 결과는 `output/`에만 쓴다.
- 먼저 자료와 현재 코드를 파악하고, 요청한 기능 범위에서 작게 구현한다. 무관한 기능이나 문서를 추가하지 않는다.
- 원자료만으로 정해지지 않는 판단은 사람에게 근거와 선택을 확인한다. AI가 대신 선택하거나 추천한 갈래로 완성하지 않는다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인, 값 없음, 0을 구별한다.
- 실제 실행한 명령·결과·변경 파일을 보고한다. 실행하지 않은 것을 성공했다고 말하지 않는다.
- 키와 비밀번호를 코드·결과·기록에 적지 않는다. 열어 둔 프로젝트 폴더 밖의 파일은 읽지 않는다.

- 학생이 AI와 채우는 파일: `app/features/`의 `gap_rule.py` · `compare_rule.py`(빈 함수), `decisions.csv` · `expected.csv` · `review.md`. 「제공 빈 틀」 표시가 있는 파일은 바로 고쳐 채운다. 규칙은 조건표에서 읽으므로 함수에 다시 적지 않는다.
- `output/judgement.json`과 결과 화면은 `python run.py <기능>`이 쓴다. 직접 쓰지 않는다. 파일의 모양은 `data/contract.md`에 있다.
- 정할 지점: 「빈 값의 뜻」 · 「쓰는 사람에 따라 갈리는 답」 · 「비교 기준 문장」. `app/features/decisions.csv`의 지점 칸에 이 이름을 그대로 쓴다. 이 지점은 학생에게 근거와 선택을 먼저 묻고, 다 해 달라는 요청에도 대신 정하지 않는다. 학생이 근거와 선택을 말하기 전에는 그 지점에 걸린 결과를 만들지 않는다.
- 이번 범위 밖: 조건표 · SOP 구조를 고치는 일, 비교 산식을 바꾸는 일, 원문에서 작업 조건을 뽑는 일, 실제 설비 조작과 실행 승인.
