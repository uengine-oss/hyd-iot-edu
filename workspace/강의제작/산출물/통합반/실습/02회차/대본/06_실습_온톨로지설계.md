# 통합반 2회차 실습 3 — 현장 정보를 체계화하는 온톨로지 직접 설계하기

> 강사 단독 진행. AI 요청과 파일 조작은 비낭독 표시를 따른다. 응답은 실제 내용을 확인한 뒤 설명한다. 실제 실습·AI 대화·캡처 미수행.

## 자료 다운로드와 작업 폴더 열기

앞에서는 준비된 그래프를 사이퍼로 조회하고, 포털의 지식 지도에서도 연결을 살펴봤습니다. 이제는 우리가 답하고 싶은 질문에 맞춰 지식 구조를 직접 만들겠습니다. 설비·센서·부품 자료에서 대상과 연결 기준을 정하고, 스키마와 예시 데이터를 만든 뒤 원자료와 대조하겠습니다. 먼저 실습 시작 안내를 열어 볼게요. 「실습 시작 도구 다운로드」를 누르면 ZIP 파일을 받습니다. 다운로드한 파일에서 압축을 풀고, 풀린 폴더를 열어 실습시작.cmd를 실행하세요.

> [조작] 학생용 가이드의 링크에서 시작한다. 다운로드 완료 → 압축 해제 → 실행 파일 순서로 실제 동작과 결과를 잇는다. 시작 도구에 과정·회차·실습 선택 칸이 나타난 뒤 다음으로 간다.

통합반을 고르고 온라인 02회차에서 「현장 정보를 체계화하는 온톨로지 직접 설계하기」를 선택하겠습니다. 「새로 시작」을 눌러 보세요. 브라우저에 방금 고른 과제의 가이드가 열리고, VS Code에는 이 실습을 위한 새 작업 폴더가 열립니다. 왼쪽 탐색기 맨 위에서 폴더 이름을 읽어 보세요. 그 아래 START.md를 누르면 가운데 편집기에 같은 이름의 탭이 뜹니다. 파일을 누르는 곳과 내용을 읽는 곳이 이렇게 나뉩니다.

> [조작] 선택한 실습과 자동으로 열린 폴더·가이드 제목을 대조한다. 제한 모드가 보일 때만 해당 폴더의 신뢰 화면을 따라간다. 촬영 편의상 미리 열린 창을 자동 열기의 증거로 쓰지 않는다.

탐색기에서 입력 폴더를 펼치고 관계그림.json을 열겠습니다. 앞에서 그린 지도를 파일로 저장한 모습이에요. 노드 목록에서 HYD-01 유압 파워팩과 오일 쿨러를 찾아보세요. 설비와 구성 요소를 구별해 둔 출발점입니다. 이번에는 설비와 센서 부분에 식별자와 속성, 연결 조건을 정하겠습니다. 증상과 원인, 조치로 이어지는 가지는 그대로 보존하고, 지금 답할 세 질문에 필요한 범위부터 구체화하겠습니다.

이제 AI에게 자료를 읽어 달라고 요청할게요. AI 채팅은 자료를 함께 살펴보고 작성이나 수정을 요청하는 곳입니다. 채팅을 열고 현재 작업 폴더가 이번 설계 실습인지 확인하겠습니다. 먼저 자료를 읽고 근거를 알려 달라고 요청할게요. 아직 파일을 바꾸라는 요청은 하지 않겠습니다.

> [조작] 설치된 Codex의 실제 채팅 버튼 위치·이름을 확인해 가리키고 클릭한다. 화면을 확인하지 않은 버튼명·위치를 낭독하지 않는다. 아래 탐색 요청을 실제 입력하고 전송한다. 응답에서 제시한 파일을 탐색기로 열어 근거를 대조하는 장면까지 보여 준다. 두 제품을 한 화면의 기능처럼 섞지 않는다.

현장 자료와 준비된 양식을 먼저 도우미와 살펴보겠습니다. 아직 열 이름이나 식별자 규칙을 정하지 않았으니, 자료에서 확인할 수 있는 범위부터 보겠습니다.

> [탐색 요청 · 응답 확인 뒤 다음 단계] 프로젝트의 설명과 현장 자료를 읽고 설비·센서·부품을 연결할 근거, 중복이나 단위가 모호한 부분, 현재 준비된 양식을 알려 주세요. 파일을 바꾸지 말고 원문 위치를 함께 제시해 주세요.
> [확인] 답변의 자료 위치와 현재 기능을 실제 파일에 대조한다. 아래 경로·필드 설명은 그 확인 후 진행하며 응답을 미리 받은 것처럼 읽지 않는다.

> [조작] 열어 둔 작업 폴더에서 자료/현장_메모.md와 CSV를 확인한다. 입력/관계그림.json의 nodes에서 두 대상의 caption과 labels를 가리킨다. 개인 결과를 쓸 때만 별도 보관한 뒤 가져온다. 결과/요구사항.md에 이번 모델의 질문 세 개와 이전 그림에서 가져온 범위를 적는다. 이전 개인 결과가 없어도 제공된 관계 그림으로 진행한다.

제가 정할 질문은 설비의 구성 요소에 어떤 센서가 붙는지, 그 센서가 읽는 물리량의 한계가 무엇인지, 어떤 교체 부품을 쓰는지입니다. 공급 조건도 자료에는 있지만, 이번 세 질문에 필요한 범위부터 만들겠습니다.

## 같은 대상과 서로 다른 대상을 가리기

센서 목록을 보면 같은 설비의 TS1이 두 줄이고, 다른 설비에도 TS1이라는 태그가 있습니다. 같은 줄의 반복과 다른 설비의 계측 채널을 한꺼번에 합치면 안 됩니다. 현장 메모의 설명과 설비 코드를 같이 읽겠습니다.

> [조작] 중복 TS1의 근거, 쿨러·열교환기의 별칭, HYD-02 압력 한계의 단위 혼입, HYD-03 진동 단위 누락을 원문 위치와 함께 자료_검토.md에 기록한다. 교체 부품 누락은 메모의 대응 근거와 대조한다. 근거 없는 값은 생성하지 않는다.

이번 모델은 설비별 계측 채널을 구별하도록 하겠습니다. 구성 요소와 센서는 설비 코드가 포함된 식별자로 나누고, 공용 교체 부품은 품번 하나로 묶겠습니다. 부품을 공용으로 쓴다는 말은 같은 실물 부품을 동시에 장착한다는 뜻이 아닙니다. 공통으로 주문하는 품목이라는 뜻입니다.

## 정의와 예시 데이터를 만들기

이 결정을 요구사항에 적겠습니다. 클래스마다 무엇을 뜻하는지, 어떤 속성을 갖는지, 관계가 어디서 시작해서 어디로 가는지를 정합니다. 한계가 없는 항목과 반드시 필요한데 누락된 항목도 구별하겠습니다.

먼저 설계 계획만 받아 볼게요. 쿨러 하나와 센서 하나를 골라 어떤 종류로 두고 어느 방향으로 이을지 설명해 달라고 하겠습니다. 같은 태그가 다른 설비에도 있을 때 구별하는 기준은 제가 적은 요구사항을 따르도록 할게요.

> [조작] Codex에 읽기 전용으로 계획을 요청한다. 원자료에서 한 설비의 구성요소와 센서 행을 열어 제안한 식별자와 관계 방향을 확인한다. 학생이 채택한 기준과 근거를 요구사항에 저장한 후 다음 요청을 보낸다.

이 기준으로 우선 스키마 파일만 만들겠습니다. 설비와 센서의 필수 속성과 연결 방향을 열어 보고, 조금 전 읽은 두 행을 이 정의로 표현할 수 있는지 확인해 보세요.

> [조작] 결과/schema.json 한 파일을 요청하고 변경 내역을 연다. 맞지 않는 정의가 있으면 해당 행을 근거로 고친다. 이어 원자료를 읽는 생성 코드를 결과/에 요청하고 실행해 graph.json을 만든다. 생성된 노드와 관계에서 앞서 정한 ID를 찾고 실제 출력과 함께 설명한다.

## 원자료와 생성 결과 대조하기

이제 나온 파일을 원자료와 맞추겠습니다. 이름이 같다는 이유로 다른 설비의 센서가 합쳐졌는지, 같은 품번의 부품이 설비마다 중복됐는지 봅니다. 관계를 문장으로 읽어서 센서가 맞는 물리량에 이어졌는지도 확인하겠습니다.

> [조작] schema.json의 정의와 graph.json의 각 노드·관계 대응을 검토한다. 중복 ID·필수값·자료형·관계 끝점·연결 수를 대조한다. 원자료 세 질문의 예상 답을 검토표에 기록한다. 오류가 있으면 원문 위치와 실제 잘못된 부분을 짚어 수정 요청하고 해당 부분을 다시 확인한다.

위쪽의 터미널 메뉴에서 새 터미널을 열어 보세요. 아래에 뜬 경로가 이번 실습 폴더인지 보고 python check.py를 입력한 뒤 엔터를 누릅니다. 검사 메시지가 나온 줄을 함께 읽어 볼게요.

> [조작] 학생 작업 폴더에서 실제 검사를 실행한다. 지적이 있으면 해당 파일을 열고 수정 후 재실행한다. 통과를 화면보다 먼저 말하지 않는다.

JSON 형식이 맞는 것만으로 설계가 맞는 것은 아닙니다. 유온 센서가 팬 진동을 읽도록 연결돼도 두 대상의 클래스는 맞을 수 있죠. 그래서 질문의 예상 답과 실제 연결을 함께 봅니다. 단위가 빠진 값은 영이나 빈 문자열로 덮지 않고, 원자료에서 확인할 수 있는지 남기겠습니다.

## 설계 결과 저장과 다시 확인

설계한 스키마와 그래프, 자료를 해석한 근거를 저장하겠습니다. 다음 실습에서 같은 설비와 센서를 찾아가려면 식별자와 관계 방향이 그대로 남아 있어야 합니다.

> [조작] 작업 폴더의 결과를 다시 열고 세 질문에 사용한 설비·센서·부품 경로를 보여 준다. 확인하지 못한 값은 검토표에 표시한다.

AI 계정을 사용할 수 없다면 따로 제공되는 완성본으로 같은 질문을 따라가 보세요. 이번에는 그 묶음을 새 폴더에서 열겠습니다.

> [조작] 학생용 완성본을 빈 폴더에 풀어 완성본_안내.md가 있는 폴더에서 터미널을 연다. `python -B -X utf8 결과/모델실행.py`를 실행한 뒤 결과/질문별_결과.json을 연다. 앞에서 선택한 설비와 공용 부품으로 다시 조회하고 두 결과의 식별자와 연결 경로를 나란히 확인한다. 실제 확인된 결과로 마친다.
