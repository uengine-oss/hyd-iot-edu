HYD · 실습 가이드

설계한 온톨로지를 그래프 DB에 구현하고 검증하기

설비 · 센서 · 부품 모델을 이 폴더 전용 그래프 DB에 적재하고 질문마다 쿼리 결과를 원자료와 대조하며, 수정본 반영 뒤 ID와 개수를 확인하고 포털 기준 지도와 견줍니다. 단계마다 「요청에 담을 것」 다섯 칸을 내 말로 채워 AI에게 요청하고(그대로 보내는 글이 아니며, 값은 원자료에서 찾습니다), 「증거」를 확인한 뒤 다음 단계로 갑니다. 막히면 「정답 보기」를 펼칩니다.

01 폴더와 출발점 · 랩 DB 켜기

「현장 정보를 체계화하는 온톨로지 직접 설계하기」에서는 설비 · 센서 · 부품을 종류(이론의 클래스 — 대상의 갈래) · 속성 · 관계로 정의해 모델을 만들었습니다. 이번에는 제공된 설비 · 센서 · 부품 모델(또는 내 모델)을 이 폴더 전용 랩 DB(그래프 DB)에 적재하고, 질문마다 Cypher 쿼리를 만들어 원자료와 대조합니다. 파일 읽기 · 실행 · 개수 세기 · 전후 비교는 제공 코드가 하고, 나는 같은 대상을 알아보는 열쇠와 조회가 돌려줄 것, 수정본 반영을 정해 문장으로 씁니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 구현과 검증를 맡습니다.

받기 「실습 시작」 도구에서 과정 → 회차 → 실습을 고르고 새로 시작(이어서 할 때는 이전 작업 열기)을 누르면 이 폴더와, 폴더 옆(AI가 읽는 폴더 밖)에 놓인 이 가이드가 열립니다. 받기가 안 되면 수동 ZIP을 풀어 파일 → 폴더 열기(File → Open Folder)로 열고 가이드는 노션 「가이드문서」에서 엽니다. 필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot, 랩 DB를 켤 Docker Desktop.

처음 열 때 폴더를 신뢰할지 물으면 Yes, I trust the authors를 누릅니다 — 제한 모드(Restricted Mode)에서는 AI 채팅이 동작하지 않습니다. 왼쪽 탐색기(Explorer)에서 폴더 이름을 보고 START.md를 엽니다(CSV는 누르면 표 글자가 보입니다). AI 계정이 없거나 정답을 보고도 막히면 따로 받는 학생용 완성본으로 결과를 봅니다.

왜 처음에 비어 있어야 뒤에서 센 개수가 모두 이번에 넣은 것입니다.

할 일 탐색기에서 입력/ · 결과/ · START.md를 열고 python lab_db.py로 이 폴더 전용 랩 DB를 켠 뒤 python show_result.py로 결과 화면을 엽니다.

해결할 질문 아래 질문의 답은 보전팀이 지금 가동하는 설비의 예비품 준비를 정할 때 씁니다.

  1. 설비별로 어떤 구성 요소에 어떤 센서 · 계산값 · 설정값이 붙어 있고, 각 센서의 물리량 · 단위 · 한계는 무엇인가?
  2. 설비별로 구성 요소마다 어떤 교체 부품이 들어가고, 여러 설비가 함께 쓰는 부품은 어느 설비 · 구성 요소에서 쓰는가? 다른 표기로 적힌 품번이나 원자료에 없는 품번으로 물으면 결과가 어떻게 구별되는가?
  3. 수정본을 반영한 뒤에도 같은 ID가 유지되고, 같은 적재를 다시 실행해도 대상과 관계가 늘지 않는가?
  4. 포털 실습에서 본 기준 지도와 견주면 내 그래프의 식별자 · 관계 방향이 어디서 같고 어디서 다른가?

말 풀이 적재는 모델 파일의 대상과 관계를 그래프 DB에 넣는 일, 수정본은 기준일 뒤 고친 줄만 모은 자료, 정할 자리는 결과/에서 첫 줄에 「제공 빈 틀」이 있는 파일입니다.

내 모델은 고를 때만 결과/내_모델/에 복사해 씁니다(형식 · ID가 맞는지 먼저 보고, 다르면 내 정의로 조회). 없어도 제공 모델로 끝까지 합니다.

터미널 → 새 터미널(Terminal → New Terminal)로 이 실습 폴더에서 터미널을 엽니다. 명령은 직접 치지 말고 블록의 복사로 붙여 넣은 뒤 Enter를 누릅니다(손으로 치면 오타가 납니다). 오류로 멈추면 명령과 출력 전문을 AI 채팅에 보내 까닭부터 묻습니다. 명령은 AI가 아니라 이 터미널에서 내가 실행합니다.

랩 DB는 Docker로 켜므로 Docker Desktop을 먼저 켭니다. 처음 한 번은 DB 이미지를 받느라 오래 걸립니다.

결과 화면 python show_result.py가 결과/보기.html을 새로 쓰고 처음 한 번 브라우저로 엽니다(안 열리면 탐색기에서 그 파일을 오른쪽 클릭 → Reveal in File Explorer → 두 번 클릭). 단계 띠의 「비어 있음 · 채움 · 오류」를 보고, 다시 실행한 뒤 F5를 누릅니다. 빨간 칸에는 멈춘 파일:줄과 까닭이 있습니다.

정할 것 주소가 127.0.0.1의 이 폴더 전용인지 보고, 내 모델과 제공 모델 가운데 무엇을 쓸지 정합니다.

터미널(PowerShell · 이 실습 폴더)

python lab_db.py
python show_result.py

「랩 DB 준비 완료」 뒤 열린 Neo4j Browser 연결 창에서 Connection URL이 출력의 127.0.0.1:포트인지 보고, Database user neo4j · Password는 비운 채(이 PC 안에서만 열리는 DB) Connect를 누릅니다. 안내 풍선은 Esc로 닫고, 입력 칸에 Cypher를 붙여 넣어 Run, 표는 Table로 봅니다.

그래프 모양 적재 뒤 Neo4j Browser에 MATCH (n)-[r]->(m) RETURN n, r, m LIMIT 50을 붙여 넣고 Run을 누릅니다.

막히면 「랩 DB 준비 확인 필요:」는 Docker Desktop을 켜고 다시 실행합니다. 「이 PC의 Docker에 없습니다」 뒤 「랩 DB 준비 완료」는 이 폴더 전용 랩 DB를 새로(빈 채로) 만든 것입니다.

증거 「랩 DB 준비 완료」가 나오고, 1단계 칸에 모델 파일 개수와 랩 DB 개수(처음 0)가 나란히 보입니다.
다를 때 「랩 DB 꺼짐」이면 python lab_db.py를 다시 실행합니다(이전 작업이면 전에 넣은 개수가 맞음).

02 파일을 바꾸지 않고 자료 파악

왜 적재가 맞았는지는 모델 파일에 무엇이 몇 개 있는지 먼저 알아야 셀 수 있습니다.

할 일 AI에게 파일을 바꾸지 말고 입력/graph.json의 종류별 대상 · 관계 수와 수정본 줄마다 가리키는 대상과 원자료(입력/자료/)의 같은 행을 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.

AI 채팅은 왼쪽 활동 표시줄의 Codex 아이콘(GitHub Copilot은 같은 창의 Chat 탭)으로 엽니다. 답에 나온 파일 · 줄은 편집기에서 직접 열어 보고, 「완료」라는 말 대신 실제 파일과 출력으로 확인합니다.

편집 승인 창(Allow ChatGPT to edit…?)에서는 경로가 결과/ 아래인 요청한 변경만 Allow once, 그 밖은 Deny를 누르고 까닭을 알립니다.

AI가 Docker · 랩 DB 명령을 실행하려 하면 폴더 밖 실행 승인 창이 뜹니다. Deny를 누르고 그 명령을 내 터미널에서 실행합니다.

정할 것 수정본이 무엇을 바꾸는지(이름 · 상태 · 값 · 줄 삭제)와 제공 모델의 ID가 무엇으로 지어졌는지 묻습니다.

요청에 담을 것

목적적재할 모델과 수정본을 파악한다
입력입력/schema.json · graph.json · 자료_검토.md, 입력/자료_변경분/2026-10-20_수정본/
지킬 것파일을 바꾸지 않는다. 파일 · 줄과 개수를 먼저.
결과의 꼴종류별 개수 표, 수정본 줄마다 「대상 · 바뀌는 것 · 원자료 행」
확인 방법개수를 1단계 표와 견주고 수정본 줄 몇 개를 연다

명령 없음

증거 짚은 줄을 열면 그 내용이 있고, AI가 바꾼 파일이 없습니다. 종류별 대상 수와 수정본 줄 수를 내 말로 댈 수 있습니다.
다를 때 짚은 줄이 없거나 다르면 근거로 쓰지 않고 다시 찾게 합니다. 편집 승인 창이 뜨면 Deny를 누릅니다.

03 요구와 기대 답 정하기

왜 기대 답을 원자료에서 먼저 적어야 결과를 견줄 기준이 생깁니다. AI의 답을 옮기면 틀린 결과도 맞아 보입니다.

할 일 결과/검증_기록.md에 질문 · 쓰는 사람 · 지킬 조건을, 결과/기대_답.csv에 질문마다 물을 값 · 볼 열 · 원자료에서 찾은 기대 답(설비 하나의 센서 · 교체 부품, 공용 부품 하나의 사용 설비)을 적고, 결정 지점을 결과/정한_것.csv에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.

편집기에서 고친 뒤 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨).

학생이 정할 것 — 지점의 종류 원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 결과/정한_것.csv에 한 줄씩 적습니다.

  • 시점과 상태 — 설비 대장의 상태와 수정본에서 바뀐 상태를 그래프에 어떻게 반영하고, 「지금 가동하는 설비」를 묻는 부품의 사용 설비 조회에 어떻게 드러낼지(답에서 빠지는지, 상태와 함께 보이는지)
  • 불용 결정 설비 — 수정본이 불용으로 바꾼 설비를 상태만 바꿔 남길지, 그 설비에만 딸린 구성 요소 · 센서와 함께 그래프에서 지울지

AI가 이 지점을 물으며 「(권장)」을 붙인 선택지 카드를 내도 추천일 뿐입니다. 근거 줄을 연 뒤 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다.

정할 것 지점마다 내 선택과 근거를 정합니다. AI의 「권장」은 따르지 않고 원문 줄로 정하며, 못 정하면 미결로 적습니다.

요청에 담을 것

목적질문의 기대 답을 원자료에서 먼저 찾아 적는다(결과 화면이 이 표와 실제 답을 견준다)
입력자료/ 원문 줄, START.md 질문, 2단계 근거 줄
지킬 것AI의 답을 옮기지 않는다. 열(질문, 물을_값, 볼_열, 기대_답, 근거)은 그대로, 근거는 파일:줄. 값의 꼴: 한 줄 = (질문 · 물을_값) 하나에 볼_열 하나. 질문 = query.cypher의 「// 질문 N」 번호. 물을_값 = $ 자리에 넣을 값 하나(질문 1 · 2는 설비 코드, 질문 3은 품번이나 표기). 볼_열 = 그 조회 결과에서 견줄 열 이름 하나. 기대_답 = 그 열의 값들(결과 줄마다 하나). 근거 = 파일:줄. 여러 값은 「 · 」로 잇고, 값이 없으면(원자료에 없는 품번 · 빈 값) 「없음」.
결과의 꼴결과/기대_답.csv의 행, 결정 지점마다 결과/정한_것.csv 한 줄
확인 방법AI가 파일을 바꾸지 않고 근거 줄을 되짚고, 3단계 칸에 내 표가 보인다
정답 보기

볼_열은 내 조회가 돌려줄 열 이름입니다(정답 보기의 쿼리를 쓰면 아래 이름). 결정 지점은 갈래마다 바뀌는 답을 보고 고릅니다.

04 판단① 적재 쿼리 쓰기

왜 스키마의 종류(이론의 클래스) 이름은 그래프의 레이블이 되고, 대상 하나(이론의 인스턴스)를 저장한 것이 노드입니다. ID는 노드의 속성, 관계 정의의 시작 · 끝은 관계의 방향이 됩니다. CREATE는 실행할 때마다 새로 만들고, MERGE는 같은 것이 있으면 찾고 없으면 만듭니다. 그래서 다시 실행해도 늘지 않으려면 무엇으로 「같은 것」을 알아볼지 먼저 정해야 합니다. 다시 넣을 때 값을 덮어쓰면 수정본으로 고친 값이 되돌아가고, 처음 만들 때만 넣으면 그대로 남습니다.

할 일 결과/load.cypher에 종류 · 관계마다 문장 하나(위에 // 넣을 것: <종류 또는 관계>, 행은 $rows)를 AI와 쓰고 python show_result.py를 실행합니다. 행을 넘겨 실행하고 개수를 세는 것은 제공 코드가 합니다.

정할 것 같은 대상을 무엇으로 알아볼지(MERGE의 열쇠)와, 다시 적재할 때 이미 있는 대상의 값을 어떻게 할지 고릅니다 — 수정본으로 바뀐 값을 지킬지, 모델 파일(원자료) 값으로 통째로 되돌릴지. 고른 것을 내 말로 AI에게 말하면 AI가 문장으로 옮깁니다. ID와 관계의 시작 · 끝이 그래프의 무엇이 되는지도 내 말로 설명합니다.

요청에 담을 것

목적모델의 대상과 관계를 랩 DB에 옮기는 적재 문장을 종류 · 관계마다 쓴다
입력입력/schema.json(종류 · 관계 · 방향), 결과/load.cypher 첫 줄, 2단계 개수 표
지킬 것이 랩 DB에만. 전체 삭제문 금지. 행은 $rows(노드는 속성 묶음, 관계는 a · b · props). 다시 실행해도 늘지 않게. 다시 적재 때 값: 수정본 값을 지키면 9단계에서 고친 값이 그대로 남고, 원자료 값으로 통째로 되돌리면 결과 화면이 매번 적재 → 수정 순서로 돌아 9단계에서 다시 고쳐진다 — 어느 쪽이든 다시 열어도(11단계) 9단계 바뀐 노드 · 관계 수가 같아야 하고, 일부만 덮어써 수정본이 더한 값이 남으면 그 수가 줄어든다.

노드는 id로 MERGE하고 값은 처음 만들 때만 넣습니다(ON CREATE SET — 다시 적재해도 수정본이 고친 값을 되돌리지 않게). 관계는 양 끝 id로 찾은 뒤 같은 방식으로 MERGE합니다.

붙여 넣는 내용 · VS Code 편집기에서 — 결과/load.cypher

// 적재 — 노드는 id로 같은 대상을 알아보고(MERGE), 값은 처음 만들 때만 넣는다(ON CREATE SET — 다시 적재해도 수정본이 고친 값을 되돌리지 않음). 관계는 양 끝 id와 관계 이름으로 알아본다.
// 넣을 것: Asset
UNWIND $rows AS row MERGE (n:Asset {id: row.id}) ON CREATE SET n = row;

// 넣을 것: Component
UNWIND $rows AS row MERGE (n:Component {id: row.id}) ON CREATE SET n = row;

// 넣을 것: Part
UNWIND $rows AS row MERGE (n:Part {id: row.id}) ON CREATE SET n = row;

// 넣을 것: Quantity
UNWIND $rows AS row MERGE (n:Quantity {id: row.id}) ON CREATE SET n = row;

// 넣을 것: Sensor
UNWIND $rows AS row MERGE (n:Sensor {id: row.id}) ON CREATE SET n = row;

// 넣을 것: HAS_COMPONENT
UNWIND $rows AS row MATCH (a {id: row.a}), (b {id: row.b}) MERGE (a)-[r:HAS_COMPONENT]->(b) ON CREATE SET r = row.props;

// 넣을 것: MONITORED_BY
UNWIND $rows AS row MATCH (a {id: row.a}), (b {id: row.b}) MERGE (a)-[r:MONITORED_BY]->(b) ON CREATE SET r = row.props;

// 넣을 것: OBSERVES
UNWIND $rows AS row MATCH (a {id: row.a}), (b {id: row.b}) MERGE (a)-[r:OBSERVES]->(b) ON CREATE SET r = row.props;

// 넣을 것: USES_PART
UNWIND $rows AS row MATCH (a {id: row.a}), (b {id: row.b}) MERGE (a)-[r:USES_PART]->(b) ON CREATE SET r = row.props;

// 질문 1 — 설비 하나의 구성 요소별 센서(설비에 바로 붙은 센서는 「(설비 전체)」)

RETURN CASE WHEN x = a THEN '(설비 전체)' ELSE x.id END AS attached_to, s.id AS sensor, s.tag AS tag, s.kind AS kind,
       q.name AS quantity, s.unit AS unit, s.normal AS normal, s.limit AS limit, s.limit_direction AS direction
ORDER BY attached_to, tag;

// 질문 2 — 설비 하나의 구성 요소마다 교체 부품(없으면 빈 칸으로 남김)
MATCH (a:Asset {id: $asset})-[:HAS_COMPONENT]->(c:Component)
OPTIONAL MATCH (c)-[:USES_PART]->(p:Part)
RETURN c.id AS component, c.name AS component_name, p.id AS part, p.name AS part_name
ORDER BY component;

// 질문 1 — 설비 하나의 구성 요소별 센서(설비에 바로 붙은 센서는 「(설비 전체)」)
MATCH (a:Asset {id: $asset})-[:HAS_COMPONENT*0..1]->(x)-[:MONITORED_BY]->(s:Sensor)-[:OBSERVES]->(q:Quantity)
RETURN CASE WHEN x = a THEN '(설비 전체)' ELSE x.id END AS attached_to, s.id AS sensor, s.tag AS tag, s.kind AS kind,
       q.name AS quantity, s.unit AS unit, s.normal AS normal, s.limit AS limit, s.limit_direction AS direction
ORDER BY attached_to, tag;

// 질문 2 — 설비 하나의 구성 요소마다 교체 부품(없으면 빈 칸으로 남김)
MATCH (a:Asset {id: $asset})-[:HAS_COMPONENT]->(c:Component)
OPTIONAL MATCH (c)-[:USES_PART]->(p:Part)
RETURN c.id AS component, c.name AS component_name, p.id AS part, p.name AS part_name
ORDER BY component;

// 질문 3 — 품번이나 다른 표기로 부품을 찾고 쓰는 설비 · 구성 요소와 설비 상태(가동이 아닌 설비도 상태와 함께)
OPTIONAL MATCH (p:Part) WHERE p.id = $part OR $part IN coalesce(p.other_codes, [])
OPTIONAL MATCH (a:Asset)-[:HAS_COMPONENT]->(c:Component)-[:USES_PART]->(p)
RETURN p.id AS part, a.id AS asset, a.status AS status, c.id AS component,
       CASE WHEN p IS NULL THEN '원자료에 없는 품번' WHEN a IS NULL THEN '쓰는 설비 없음' END AS note
ORDER BY part, asset, component;

// 수정본 반영 — 불용 결정 설비는 그 설비에만 딸린 구성 요소 · 센서와 함께 지운다(공용 부품 · 물리량은 남김). 나머지는 남김 갈래와 같다.
