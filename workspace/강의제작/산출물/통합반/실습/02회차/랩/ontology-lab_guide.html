01 폴더 열고 자료 확인하기

목표 받은 랩 폴더를 VS Code로 열고 첫 명령을 실행한다. 이 폴더 하나로 실습 전체가 돌아간다.

상황

  • ZIP 안에 랩 폴더와 이 가이드가 들어 있다
  • 할 일은 터미널에 명령을 넣는 것과 Codex에게 말하는 것, 두 가지뿐이다
  • 폴더 안에 있는 것
    • data/ — 원자료. 설비 · 구성 요소 · 센서 · 예비품 · 품번 표, 현장 메모, 설비 · 구성 요소 · 센서가 어떻게 이어지는지 그린 출발 그림(relationships.json)이 있고, 읽기만 한다
    • AGENTS.md — AI가 지킬 공통 규칙
    • app/features/ — Codex와 함께 채울 빈 파일들. 단계를 따라 하나씩 채운다
    • app/ui/ · app/utils/ — 미리 만들어 둔 화면 · 처리 코드
    • run.py — 실행 파일. 명령은 모두 python run.py …로 시작한다
    • output/ — 실행하면 생기는 결과. 결과 화면 result.html도 여기에 생긴다

뭐부터 해야 할까?

  1. ZIP을 풀고, VS Code에서 파일 → 폴더 열기로 안쪽 ontology-lab 폴더(run.py가 있는 폴더)를 연다
  2. 폴더를 신뢰하겠느냐고 물으면 예, 작성자를 신뢰합니다를 누른다
  3. 터미널 → 새 터미널을 열고 아래 명령을 실행한다

터미널(PowerShell · 이 실습 폴더)

python run.py

확인 원자료 줄 수가 나오고 결과 화면이 열리면 됩니다. 결과 화면이 안 열리면 탐색기에서 output/result.html을 직접 엽니다. 다음 명령부터는 실행한 뒤 결과 화면에서 F5(새로 고침)를 누릅니다.

02 Codex에게 물어 자료 파악하기

목표 설계하기 전에 원자료에 무엇이 들어 있는지 알아 둔다. 온톨로지에는 이 자료에 있는 것만 담을 수 있어서, 무엇이 있고 어디가 다르게 적혔는지부터 알아야 한다.

상황

  • data/에 표 다섯 개, 현장 메모, 출발 그림이 있다

뭐부터 해야 할까?

  1. Codex에게 표마다 무엇이 들어 있고 몇 줄인지 물어보자
  2. 표와 표가 어떤 칸으로 이어지는지도 물어보자
  3. 같은 것을 서로 다르게 적어 둔 곳이 있는지, 실제 줄(파일:줄)과 개수로 알려 달라고 하자
  4. 알려 준 줄을 한두 곳 직접 열어서 맞는지 확인하자

Codex에게 파일 이름을 말할 때는 백틱 기호(키보드 숫자 1 왼쪽)로 감쌉니다.

03 역량 질문과 기대 답 정하기

목표 온톨로지를 만들기 전에, 세 역량 질문에 어떤 답이 나와야 하는지 먼저 정한다. 만든 뒤에는 이 기대 답과 견줘 맞는지 확인하는데, 결과를 본 뒤에 정하면 틀린 결과도 맞아 보인다.

상황

  • 자료가 어떻게 생겼는지, 어디가 다르게 적혔는지 알았다
  • expected.csv(미리 정해 두는 기대 답 표)는 아직 비어 있다
  • 역량 질문(스키마가 답해야 할 질문) 세 가지
    • ① 설비의 구성 요소마다 어떤 센서가 붙고, 그 자리에 어떤 장치(일련번호)가 달렸는가?
    • ② 같은 물리량을 재는 센서는 어느 것이고, 각각의 단위 · 정상값 · 한계는 무엇인가?
    • ③ 부품을 어느 설비가 함께 쓰며, 예전 품번이나 다른 표기로 물어도 찾을 수 있는가?

뭐부터 해야 할까?

  1. 질문마다 「무엇을 물으면 무엇이 나와야 하는지」를 근거 줄과 함께 표로 받아 보자
  2. 내가 골라야 답이 정해지는 줄이 어느 것인지도 물어보자. 그 줄은 05 · 06단계에서 고른 뒤에 넣는다
  3. 표에서 맞는 줄만 expected.csv에 적어 달라고 하고, 파일을 열어 확인하자

승인 창이 뜨면 Codex가 app/features/ 안의 파일을 고치려는 것일 때만 Allow once, 그 밖이면 Deny를 누릅니다.

Codex 채팅에 붙여 넣는 글

「같은 물리량의 범위」 지점은 「○○」로 정했어. 이유는 ○○이고, 열어 본 근거 줄은 ○○야. 그래서 달라지는 답은 ○○야. `decisions.csv`의 이 지점 줄에 적어 줘. 다른 파일은 바꾸지 마.

Codex 채팅에 붙여 넣는 글

방금 갈래마다 보여 준 질문 2의 답 가운데 `decisions.csv`에 적은 내 선택(같은 물리량의 범위)에 맞는 묶음 줄과 센서 값 줄을 `expected.csv`에 더해 줘. 물을 값의 물리량 이름은 내가 말한 이름으로 적어 줘. 다른 파일은 바꾸지 마.

Codex 채팅에 붙여 넣는 글

`decisions.csv`에 적은 내 선택(같은 물리량의 범위)을 `quantity_rules.py`의 두 함수에 규칙으로 구현해 줘. 센서를 한 줄씩 이름표로 옮기지 말고 태그 · 재는것 · 붙은곳 입력으로 가르게 해 줘. 서로 다른 묶음에는 다른 이름을 주고, 내가 `expected.csv` 질문 2에 적은 물리량 이름을 써 줘. 다른 파일은 바꾸지 마.

07 식별자와 다른 이름 잇기: 부품과 품번 표기

목표 여러 가지로 적힌 품번을 사내 품번 하나에 잇고, 모델 파일을 만든다. 표기마다 부품을 따로 만들면 「이 부품을 어느 설비가 쓰나」의 답이 흩어진다.

상황

  • 정할 곳 두 군데를 다 정했다
  • 교체부품 칸에 예전 품번, 줄여 쓴 품번, 제조사 품번이 섞여 있다

뭐부터 해야 할까?

  1. 잇는 일은 미리 만들어 둔 코드가 한다. 아래 명령만 실행하자
  2. 다르게 적힌 품번이 사내 품번의 다른 이름으로 남았는지 보자
  3. 모델 파일 output/schema.json(클래스와 관계)과 graph.json(인스턴스)이 생겼는지 보자

08 역량 질문으로 모델 검증하기

상황

  • 모델 파일과 기대 답이 다 있다

뭐부터 해야 할까?

  1. 처음에 고르지 않은 설비, 예전 품번, 원자료에 없는 품번도 기대 답에 먼저 더해 달라고 하자
  2. 아래 명령으로 맞춰 보고, 「같음」이 아닌 줄이 있으면 무엇을 물었는지 · 기대 답 · 실제 답을 함께 보여 주며 이유부터 물어보자
  3. 이유가 나오면 그 파일만 고쳐 달라고 하자
  4. 두 번 고쳐도 안 되면 새 대화를 열고, 알게 된 것을 담아 다시 부탁하자
  5. 마지막으로 구조 검사(식별자가 겹치거나 끝이 빠진 관계가 없는지)도 돌려 보자
