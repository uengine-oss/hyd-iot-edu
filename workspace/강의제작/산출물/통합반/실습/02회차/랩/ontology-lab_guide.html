01 폴더 열고 자료 확인하기

클래스룸의 2회차 실습 자료에서 ZIP을 받아 압축 풀기를 선택합니다. VS Code의 파일 → 폴더 열기에서 ontology-lab 폴더를 엽니다. 함께 풀린 가이드는 브라우저로 엽니다.

신뢰 여부를 물으면 예, 작성자를 신뢰합니다(Yes, I trust the authors)를 선택합니다. 제한 모드에서는 Codex를 사용할 수 없습니다.

왼쪽 탐색기는 파일을 고르는 곳, 가운데 편집기는 내용을 보는 곳입니다. README.md를 열어 폴더 역할을 봅니다. data/는 자료, app/features/는 AI와 구현할 기능입니다. 화면 표시와 공통 처리는 제공됩니다.

AGENTS.md는 README 표에 적힌 대로 AI가 지킬 공통 규칙이고, Codex가 따로 읽습니다. 코드를 직접 외울 필요는 없습니다. 무엇을 만들지 정해 설명하고 결과를 확인하는 일을 맡습니다.

터미널 → 새 터미널을 엽니다. 오타를 줄이도록 명령 블록의 복사를 눌러 붙여 넣고 Enter를 누릅니다.

터미널(PowerShell · 이 실습 폴더)

python run.py

원자료 파일마다 행 수가 보이는지 봅니다. 결과는 output/result.html에 저장됩니다. 브라우저가 열리지 않으면 Windows 파일 탐색기로 이 실습 폴더의 output 폴더를 열고 result.html을 두 번 누릅니다(VS Code 탐색기에서 누르면 화면이 아니라 HTML 글이 열립니다). 이후에는 명령을 실행한 뒤 열린 화면에서 F5를 누릅니다.

02 Codex에게 물어 자료 파악하기

온톨로지에는 원자료에 있는 것만 담으므로, 무엇이 들어 있는지 알아야 설계를 시작할 수 있습니다. 왼쪽 활동 표시줄의 Codex 아이콘을 눌러 채팅을 열고 계정에 로그인합니다. 계정이 없거나 구현 중 막히면 클래스룸에서 실습 폴더와 따로 받는 완성본 ZIP(ontology-lab-completed.zip)으로 결과를 실행해 볼 수 있습니다.

무엇을 만들지 이미 분명하면 요구부터 말하고 필요한 자료만 물어도 됩니다. 그렇지 않으면 원자료를 처음부터 다 읽지 않고 Codex에게 물어 먼저 파악합니다. 파일을 바꾸지 말고 data/의 표마다 한 줄이 무엇을 뜻하는지, 줄이 몇 개인지, 표끼리 어느 열로 이어지는지 설명해 달라고 요청합니다. 설비가 어떤 모델로 나뉘고 모델마다 구성 요소와 센서가 어떻게 다른지, 같은 구성 요소나 같은 부품을 다르게 적은 곳, 철거처럼 다른 줄과 사정이 다른 곳, 단위가 다른 줄도 실제 예 줄(파일:줄)과 개수로 짚어 달라고 합니다. 요약만 받으면 맞는지 가릴 길이 없지만, 예 줄과 개수가 있으면 한두 곳만 열어 봐도 설명을 믿을지 알 수 있습니다.

짚어 준 줄 가운데 한두 곳을 열어 설명과 같은지 봅니다. 자료를 보낸 담당자의 설명은 data/field_notes.md에 있습니다.

방금 연 결과 화면의 「출발 그림(data/relationships.json)의 연결 — 시작 → 끝」 표는 1회차 관계 그림 실습에서 그린 것과 같은 그림입니다. 그 그림에서 원 하나씩이던 설비 → 구성 요소 → 센서가 이번 원자료에서는 설비 다섯 대의 구성 요소와 센서 여러 줄로 늘어납니다. 그림의 증상 · 원인 · 조치 쪽 연결은 이번 범위 밖입니다.

설비 · 구성 요소 · 센서 · 부품이 어느 표에 있고 무엇으로 이어지는지, 모델마다 무엇이 다른지 내 말로 설명할 수 있으면 이어갑니다. Codex가 파일을 바꾸려 하면 편집 승인 창에서 Deny를 누르고 설명만 요청합니다.

03 역량 질문과 기대 답 정하기

만들 모델이 맞는지 가릴 기준부터 정합니다. 이론에서 본 역량 질문(Competency Question)은 스키마가 답해야 할 질문이고, 정의는 여기서 시작해 이 질문으로 확인합니다. 아래 셋을 이번 모델의 역량 질문으로 씁니다.

① 설비의 구성 요소마다 어떤 센서가 붙고, 그 자리에 어떤 장치(일련번호)가 달렸는가? ② 같은 물리량을 재는 센서는 어느 것이고, 각각의 단위 · 정상값 · 한계는 무엇인가? ③ 부품을 어느 설비가 함께 쓰며, 예전 품번이나 다른 표기로 물어도 찾을 수 있는가?

app/features/requirements.md에 목적과 답을 쓸 사람(보전팀 · 운전), 역량 질문과 기준일, 지킬 조건과 범위 밖을 내 말로 짧게 적습니다.

app/features/expected.csv에는 모델을 만들기 전에 기대 답을 먼저 정합니다. 모델이 낸 결과를 기대 답으로 옮기면 틀린 결과도 맞아 보입니다. Codex에게 원자료에서 후보를 찾아 달라고 하고, 근거 줄을 몇 군데 열어 본 뒤 받아들입니다. 받아들인 줄은 Codex에게 적게 해도 됩니다. 질문 1은 설비 하나의 구성 요소 두셋과 펌프를 교체한 설비의 펌프 자리, 질문 2는 물리량 한 묶음과 센서 셋의 값(같은 값을 다른 단위로 적은 줄과 손으로 읽는 현장 지시계를 하나씩 포함), 질문 3은 사내 품번 · 예전 품번 · 줄여 쓴 표기 · 원자료에 없는 품번으로 정합니다. 물을 값은 설비 코드와 품번처럼 원자료에 적힌 값을 씁니다. 칸마다 뜻은 파일 첫 줄에 있습니다.

app/features/decisions.csv에는 원자료만으로 하나로 정해지지 않는 지점 둘이 미리 적혀 있습니다. 지금은 비워 두고 05 · 06단계에서 정합니다. 고른 것에 따라 질문 1의 펌프 자리 줄과 질문 2의 줄(물을 값이 내가 정할 물리량 이름입니다)이 달라집니다. 그 줄들은 지금 갈래마다의 후보만 받아 두고, 05 · 06단계에서 고른 직후 모델을 만들기 전에 적습니다.

파일을 손으로 고친 뒤에는 Ctrl+S로 저장합니다(탭 이름 옆 ●가 사라지면 저장됨). 저장하지 않으면 명령이 고치기 전 내용을 읽어 0행으로 보입니다.

04 클래스와 식별자, 관계 방향과 카디널리티 정하기

온톨로지 스키마는 클래스 · 속성 · 관계 · 제약을 실제로 적어 둔 공통 정의입니다. 이번 자료의 클래스(같은 성질의 대상을 묶은 갈래)는 이론에서 본 설비 · 구성 요소 · 센서 · 부품에 물리량을 더한 다섯입니다. 역량 질문 ②처럼 같은 것을 재는 센서를 설비끼리 모아 견주려면 센서가 재는 것을 따로 가리켜야 해서, 이론에서 본 대로 다루려는 일이 넓어진 만큼 클래스를 하나 더합니다.

인스턴스는 클래스에 속하는 실제 개별 대상이고, 그래프의 노드 하나가 인스턴스 하나입니다. HYD-01 한 대, 그 설비의 오일 쿨러, 거기 붙은 유온 센서 하나가 각각 인스턴스입니다. 표의 줄과 인스턴스가 늘 하나씩 맞지는 않습니다. HYD-02의 펌프 자리는 두 줄로 적혀 있고, 물리량은 따로 적힌 표 없이 센서 목록의 재는것 칸에서 모아 만듭니다. 무엇을 인스턴스 하나로 셀지는 답할 질문이 정하고, 05 · 06단계에서 그것을 정합니다.

식별자는 인스턴스 하나만 가리키는 값입니다. 태그 TS1은 HPP-45A · 45B 네 대에 모두 있어서 태그만으로는 센서 하나를 가리키지 못합니다. Codex에게 대상마다 어느 열로 식별자를 지으면 겹치지 않는지, 관계를 어느 쪽에서 시작하는지 추천안과 그 까닭을 받아 따져 봅니다. 겹치지 않고 바뀌지 않으면 꼴은 내가 정해도 됩니다. 설비 코드와 사내 품번은 식별자와 따로 모델에 남아, 뒤에서 역량 질문을 원자료에 적힌 값으로 묻습니다.

관계마다 카디널리티도 정합니다. 대상 하나에 반대쪽이 많아야 몇 개 이어지는지를 「시작 쪽 수:끝 쪽 수」로 적고, 1은 많아야 하나입니다. 설비 하나에 구성 요소가 몇 개 붙는지, 센서 하나가 물리량을 몇 개 재는지 Codex에게 개수로 물어 정합니다.

정한 것을 app/features/design.csv와 relations.csv에 반영하도록 요청합니다. 부탁할 때는 목적(세 역량 질문에 답하는 모델), 쓸 자료, 지킬 조건(같은 이름의 다른 대상이 합쳐지지 않게), 확인 사례(TS1이 설비마다 따로인지)를 함께 말합니다. 빠진 것은 AI가 짐작으로 채우기 때문입니다. 식별자에 쓸 열은 {열 이름}으로 적습니다.

Codex가 파일을 바꾸려 하면 편집 승인 창이 뜹니다. app/features/ 아래 요청한 파일이면 Allow once, 그 밖의 경로면 Deny를 누릅니다. 요청에 파일 이름을 쓸 때는 키보드 숫자 1 왼쪽의 백틱 기호로 앞뒤를 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다. python run.py 명령은 내 터미널에서 실행하고, 터미널 출력과 결과 화면으로 확인합니다.

Codex 채팅에 붙여 넣는 글

세 역량 질문에 답하는 모델을 만들려고 해. 지금 정한 식별자와 관계 방향 · 카디널리티를 `app/features/design.csv`와 `relations.csv`에 반영해 줘. 같은 이름의 다른 대상이 한 식별자로 합쳐지면 안 돼. 반영한 뒤 TS1이 설비마다 다른 식별자가 되는지 원자료 열로 확인해 줘. 실물 행과 구성 요소-실물 행은 내가 정할 때까지 넣지 말고, 다른 파일은 바꾸지 마.

python run.py design

05 새 클래스를 만들지 정하기: 구성 요소 자리와 실물

구성 요소 자리와 그 실물을 정합니다. HYD-02의 펌프 자리에는 떼어 낸 펌프와 지금 달린 펌프, 두 줄이 있습니다. 일련번호를 구성 요소의 속성으로만 두면 모델이 단순하고 지금 달린 펌프만 남습니다. 실물을 클래스로 따로 두면 그 자리를 거쳐 간 펌프를 모두 물을 수 있고 클래스와 관계가 하나씩 늘어납니다. 이론에서 본 「따로 가리켜 물을 대상은 클래스와 인스턴스로, 대상을 설명하는 값은 속성으로」를 펌프 실물에 대어 보는 판단입니다.

Codex에게 두 선택지마다 질문 1의 답과 보전팀이 하게 될 일이 어떻게 달라지는지, 추천안은 무엇인지 묻습니다. 추천안을 따져 본 뒤 고치거나 받아들여 내 이유로 고릅니다. 어느 쪽을 고르느냐에 따라 결과가 달라지고, 그 결과를 책임지는 것은 고른 사람이기 때문입니다. 「잘 모르겠으니 알아서 해 줘」처럼 이유 없이 넘기면 Codex가 무엇을 정해야 하는지 되묻습니다. app/features/decisions.csv의 이 지점 줄에 고른 것과 내 이유, 결정을 좌우해 열어 본 근거 줄(파일:줄), 바뀌는 답을 남깁니다(내가 말한 대로 Codex에게 적게 해도 됩니다). 이 줄이 비어 있으면 아래 명령이 그 줄을 짚고 멈춥니다.

고른 뒤에는 모델을 만들기 전에 기대 답부터 적습니다. 03단계에서 받은 갈래별 후보 가운데 내가 고른 갈래의 펌프 자리 줄을 expected.csv 질문 1에 더합니다. 결과 화면을 본 뒤에 적으면 화면의 값을 옮겨 적게 되어, 판단이 틀려도 맞아 보입니다.

그다음 고른 대로 표를 맞추도록 요청합니다. 떼어 낸 펌프 줄은 row_rules.csv에 적습니다(실물을 따로 두면 「지난 실물」, 아니면 「빼기」). 실물을 따로 두기로 했으면 design.csv에 실물 행을, relations.csv에 「구성 요소-실물」 행을 더합니다. 기대 답을 적는 일과 표를 맞추는 일은 요청을 나눕니다. 여러 기능을 한꺼번에 맡기면 결과가 틀렸을 때 어디서 틀렸는지 가리기 어렵습니다.

구성 요소 이름은 제공 코드가 맞춥니다. 같은 모델(HPP-45A) 세 대에서 담당자마다 다르게 적은 이름(오일 쿨러 · 쿨러 · 열교환기)을 구성 요소 목록에 먼저 나온 이름 하나로 맞추고, 원자료 이름은 이론에서 본 다른 이름(같은 대상을 달리 부르는 이름)으로 그 구성 요소에 남깁니다. 이름을 맞춰도 HYD-01의 오일 쿨러와 HYD-02의 오일 쿨러는 서로 다른 인스턴스입니다. 모델이 다른 HYD-04 · HYD-07의 구성 요소는 원자료 이름 그대로 둡니다.

06 같은 대상으로 볼 범위 정하기: 같은 물리량

태그는 센서를 부르는 이름이고, 그 센서가 재는 것이 물리량입니다. 04단계에서 물리량을 클래스로 두었으므로, 재는 것의 이름이 설비마다 달라도 같은 것을 재는 센서를 물리량 하나에 모을 수 있습니다. 태그가 같아도 재는 것이 다르면 같은 물리량이 아닙니다(HYD-04의 FS2는 냉각수 유량).

같은 물리량의 범위를 정합니다. 온도 센서를 보면 탱크 유온은 탱크에, 유온과 쿨러 출구 유온은 둘 다 쿨러에 붙어 있습니다. 압력과 유량도 재는 지점마다 이름이 다릅니다(토출 압력과 시스템 압력, 유량과 냉각 회로 유량). 재는 값의 종류가 같으면 물리량 하나로 묶을 수도 있고, 재는 지점이 다르면 다른 물리량으로 둘 수도 있습니다.

물리량 클래스 안에서 어디까지를 인스턴스 하나로 볼지 정하는 판단입니다. 이론에서 본 「무엇을 인스턴스 하나로 셀지는 그래프가 답할 질문이 정한다」가 이 자리입니다. Codex에게 선택지마다 질문 2의 묶음에 어떤 센서가 들어가는지, 한 묶음에 든 쿨러의 두 온도 센서를 무엇으로 가려 읽게 되는지, SCADA 태그가 없는 HYD-07의 현장 지시계 두 줄은 어느 물리량에 들어가는지 예 줄(파일:줄)과 함께 묻습니다. 운전 담당이 정상값을 견주는 방법이 어떻게 달라지는지도 묻고, 추천안을 따져 내 이유로 고릅니다. app/features/decisions.csv의 이 지점 줄에 고른 것과 내 이유, 결정을 좌우해 열어 본 근거 줄(파일:줄), 바뀌는 답을 남깁니다(내가 말한 대로 Codex에게 적게 해도 됩니다). 이 줄이 비어 있으면 아래 명령이 그 줄을 짚고 멈춥니다.

고른 뒤에는 expected.csv 질문 2의 줄부터 적습니다. 03단계에서 받은 갈래별 후보 가운데 내가 고른 갈래의 묶음 줄과 센서 값 줄이고, 물을 값에는 그 묶음을 부를 물리량 이름을 내가 정해 적습니다.
