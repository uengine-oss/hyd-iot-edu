01 폴더와 출발점 확인

포털 지식 지도에서 오일 쿨러와 거기 붙은 센서가 어떻게 이어지는지 따라가 봤습니다. 이번에는 그 연결을 직접 만듭니다. 창원1공장 유압 설비 7대의 대장 · 구성 요소 · SCADA 태그 · 예비품 자료를 종류(이론의 클래스 — 공통 특성을 가진 대상의 유형) · 속성 · 관계로 짠 하나의 설비 지식 모델로 정리해, 설비별 센서와 여러 설비가 함께 쓰는 부품을 답하게 합니다.

자료는 시스템마다 따로 내보낸 것이라 같은 센서 이름이 여러 설비에 쓰이고, 같은 장치를 사람마다 다르게 부르며, 줄이 겹치거나 칸이 비어 있습니다. 손으로 다 맞춰 볼 수 없는 양이므로 AI와 코드로 처리하고 결과는 원자료와 대조합니다. 대상마다 겹치지 않는 ID를 주고 단위와 관계 방향을 정해 두어야, 누가 같은 질문을 해도 같은 답이 나옵니다.

과정은 온톨로지 → 에이전트 → 프로세스 순서로 올라갑니다. 이 실습은 첫 단계인 온톨로지의 설계 — 질문으로 범위를 정하고, 종류 · 속성 · 관계를 정의해 원자료로 모델을 만드는 일 — 를 맡습니다.

받기 이 폴더는 「실습 시작」 도구로 받습니다. 도구에서 과정 → 회차 → 실습을 고르고 새로 시작을 누르면 이 판본만 새 폴더에 받아 풀고, VS Code에 이 폴더와 START.md를, 브라우저에 이 가이드를 엽니다. 이어서 할 때는 이전 작업 열기를 누릅니다 — 새로 시작은 늘 새 폴더에 받으므로 고친 파일을 덮지 않습니다. 받기에 실패하면 한 번 더 시도하고, 그래도 안 되면 수동 ZIP으로 받은 ZIP을 풀어 VS Code의 파일 → 폴더 열기(File → Open Folder)로 그 폴더를 엽니다.

필요한 것 VS Code와 Python, 로그인해 둔 Codex 또는 GitHub Copilot.

받은 폴더 VS Code 왼쪽 탐색기에 이렇게 보입니다.

탐색기에 보이는 모양 · 읽기만

VS Code가 이 폴더를 처음 열 때 폴더를 신뢰할지 묻는 창(Do you trust the authors of the files in this folder?)이 뜨면 신뢰하는 쪽(Yes, I trust the authors)을 누릅니다. 신뢰하지 않으면 제한 모드(Restricted Mode)로 열려 AI 채팅이 동작하지 않습니다. 아래쪽 상태 표시줄에 제한 모드가 보이면 그 표시를 눌러 이 폴더를 신뢰합니다.

왼쪽 탐색기(Explorer) 맨 위에서 이 실습의 폴더 이름을 확인합니다. 가운데 편집기에 START.md 탭이 열려 있으면 이번 질문을 읽고, 탭이 보이지 않으면 탐색기에서 START.md를 누릅니다. CSV를 누르면 표의 글자가 그대로 보입니다.

AI 계정이 없으면 실습 폴더와 따로 받는 학생용 완성본 묶음(계정이 없는 학생이 결과를 확인하는 용도)으로 결과를 확인하세요.

해결할 질문 아래 질문의 답은 보전팀이 설비별 센서를 찾고, 교체할 부품을 어느 설비와 함께 준비할지 정할 때 씁니다. 같은 부품을 구매팀은 호환 후보를 찾을 때, 창고는 품목별 재고를 셀 때 조회합니다.

  1. 설비별로 어떤 구성 요소에 어떤 센서 · 계산값 · 설정값이 붙어 있는가?
  2. 각 센서가 재는 물리량과 단위 · 정상값 · 한계(위로 넘는지, 아래로 떨어지는지)는 무엇인가? 설비마다 태그 이름이 달라도 같은 물리량을 재는 센서를 함께 찾을 수 있는가?
  3. 교체 부품별로 그 부품을 쓰는 설비와 구성 요소는 무엇인가? 다른 표기로 적힌 품번, 제조사 규격 번호, 원자료에 없는 품번으로 물으면 결과가 어떻게 구별되는가?

말 풀이 계산값은 계기 없이 다른 값으로 계산해 내는 값이고, 설정값은 사람이 정해 넣는 목표 값입니다. 사내 품번은 우리 회사가 부품에 붙인 번호이고, 제조사 규격 번호(제조사 품번)는 부품을 만든 회사가 붙인 번호입니다. 기준일은 자료를 뽑은 날입니다.

왜 하는가 만들기 전에 무엇이 주어졌고 무엇을 만들어야 하는지 알아야 AI에게도 같은 출발점을 말할 수 있습니다. 이 답을 누가 어디에 쓰는지에 따라 무엇을 하나로 보고 무엇을 따로 둘지가 달라지므로, 쓰는 사람도 여기서 확인합니다.

할 일 VS Code 탐색기에서 이 폴더의 입력/ · 자료/ · 결과/ · START.md를 열어 각 자리의 역할과 이번 질문을 확인합니다.

정하거나 물을 것 이번 질문 세 개와, 이 답을 쓰는 사람이 누구인지 확인합니다.

명령 없음 — 이 단계는 탐색기 · 편집기 · AI 채팅에서 합니다.

판단할 증거 탐색기에서 네 자리를 찾았고, 결과/에 아직 schema.json · graph.json이 없다는 것을 확인했습니다. 관계 그림에 있는 종류 몇 개와 그 사이 관계를 말할 수 있습니다.
다를 때 보여야 할 자리 가운데 없는 것이 있으면 다른 실습을 받았거나 압축이 덜 풀린 것입니다. 「실습 시작」 도구에서 이 실습을 다시 받습니다.
증거를 확인한 뒤 다음 단계로 갑니다.

02 파일을 바꾸지 않고 자료 파악

왜 하는가 모델에는 원자료에 있는 것만 담아야 하므로, 만들기 전에 자료가 실제로 무엇을 말하는지부터 봅니다. 자료끼리 말이 다른 곳을 먼저 찾아 두어야 뒤에서 대상이 두 번 생기거나 섞이지 않습니다. 파일을 바꾸지 않게 하는 것은 아직 합의하지 않은 해석으로 AI가 결과를 만들기 시작하지 않게 하려는 것입니다.

할 일 AI에게 파일을 바꾸지 말고, 내가 고른 설비 하나의 구성 요소 · 센서 · 교체 부품에 관한 줄을 자료마다 찾아 파일 · 줄로 짚어 달라고 합니다. 짚은 줄을 직접 엽니다.

Codex는 왼쪽 활동 표시줄의 Codex 아이콘을 누르면 채팅 창이 열립니다. 입력하기 전에 창 위쪽 탭이 Codex인지 확인합니다. GitHub Copilot을 쓰면 같은 창의 Chat 탭을 엽니다(처음 열면 GitHub 로그인 창이 뜹니다). 창 아래 입력 칸에 요청을 내 말로 적어 보내고, 답에 나온 파일을 왼쪽 탐색기에서 열어 가운데 편집기의 실제 줄을 읽습니다. AI가 「완료」라고 해도 실제 파일과 실행 출력으로 확인합니다.

AI가 파일을 만들거나 고치려 하면 편집 승인 창(Allow ChatGPT to edit the following file?)이 뜹니다. 창에 적힌 경로가 결과/ 아래이고 내가 요청한 변경이면 Allow once(이번 한 번 허용)를 누르고, 입력/ · 자료/의 파일이거나 요청하지 않은 파일이면 Deny(거부)를 누른 뒤 까닭을 채팅으로 알립니다. GitHub Copilot을 쓰면 바뀐 파일의 경로를 같은 기준으로 보고, 요청하지 않은 변경은 되돌립니다.

정하거나 물을 것 같은 장치나 센서를 자료마다 다르게 적은 곳, 칸이 비었거나 표기가 다른 곳처럼 자료끼리 말이 달라 보이는 곳이 있는지 묻습니다.

아래 다섯 가지를 내 말로 채워 요청을 짭니다. 값은 원자료에서 내가 찾습니다.

다를 때 짚은 줄을 열었는데 그 내용이 없거나 다르면 그 줄은 근거로 쓰지 않고, 같은 파일에서 다시 찾아 달라고 합니다. 편집 승인 창이 떴다면 Deny를 누르고, 이 단계는 파일을 바꾸지 않는 단계라고 다시 알립니다.

03 요구와 기대 답 정하기

왜 하는가 기대 답을 내가 원자료에서 먼저 찾아 적어 두어야, 뒤에서 AI가 만든 결과가 맞는지 견줄 기준이 생깁니다. AI가 낸 답을 기대 답으로 옮기면 틀린 결과도 맞아 보입니다. 원자료만으로 하나로 정해지지 않는 지점은 이 답을 쓰는 사람의 일을 보고 내가 정해야 같은 질문에 늘 같은 답이 나옵니다.

할 일 질문 · 이 답을 쓰는 사람 · 기준일 · 지킬 조건과, 고른 설비의 구성 요소별 센서와 여러 설비가 함께 쓰는 부품 하나의 사용 설비를 원자료에서 직접 찾아 기대 답으로 결과/요구사항.md에 내 말로 적습니다. 「학생이 정할 것」의 지점마다 고른 것과 근거 줄을 적습니다.

가운데 편집기에서 파일을 열어 고친 뒤 Ctrl+S로 저장합니다. 탭 이름 옆 점(●)이 사라지면 저장된 것입니다.

학생이 정할 것 — 지점의 종류 원자료만으로는 하나로 정해지지 않아, 근거를 찾아 내가 정해야 결과를 업무에 쓸 수 있는 지점이 있습니다. 이번 자료에는 아래 종류의 지점이 있습니다. 어느 행 · 어느 절이 해당하는지는 탐색에서 직접 찾고, 지점마다 고른 것 · 근거(파일 · 줄) · 그 선택으로 바뀌는 답을 결과/요구사항.md 「정한 것」 표에 적습니다.

  • 쓰는 사람에 따라 갈리는 답 — 같은 규격(제조사 품번)으로 등록된 서로 다른 사내 품번을 한 물품으로 볼지 — 그 규격이나 한쪽 품번으로 물었을 때 나와야 할 답이 호환 후보를 찾는 사람과 품목별 재고를 세는 사람에게 같은지

AI가 이 지점을 물을 때 채팅에 선택지와 직접 입력 칸이 있는 질문 카드가 뜰 수 있습니다. 선택지에 「(권장)」이 붙어 있어도 AI의 추천일 뿐이므로, 원자료의 근거 줄을 열어 본 뒤 직접 입력 칸에 내 결정과 근거 줄을 적어 보냅니다. 선택지를 고르더라도 근거 줄을 함께 적습니다.

정하거나 물을 것 지점마다 내 선택과 근거를 말합니다. AI가 고를 것을 내놓거나 「권장」을 붙이면 따르지 말고 원문 줄을 다시 열어 내 말로 정합니다. 못 정한 지점은 미결로 적습니다.

04 설계 계획 검토

왜 하는가 모델은 종류 · 대상(이론의 인스턴스 — 그 종류에 속하는 실제 대상 하나) · 속성(대상 하나에 붙은 값) · 관계(두 대상 사이의 연결)로 짭니다. 다른 대상과 이어지거나 스스로 값을 가지면 대상으로, 대상 하나에 붙은 값 하나면 속성으로 둡니다. 관계에는 방향(어느 쪽에서 어느 쪽으로)과 연결 수(한쪽 하나에 다른 쪽이 몇 개까지 — 1:1 · 1:N · N:M)가 있고, ID는 전체 모델에서 대상 하나만 가리켜야 합니다. 이 틀을 먼저 합의해야 기능을 하나씩 더해도 앞에서 만든 것과 어긋나지 않습니다. 계획이 틀린 채 파일을 만들면 만든 것을 모두 다시 고쳐야 합니다.

할 일 설비 · 구성 요소 · 센서 · 물리량 · 부품을 어떤 종류 · 속성 · 관계로 둘지, ID를 무엇으로 지을지 AI의 계획을 받아 검토하고, 5 ~ 10단계의 구현 순서에 동의합니다. 아직 파일을 만들지 않습니다.

정하거나 물을 것 같은 태그 이름이 여러 설비에 있을 때 ID가 겹치지 않게 짓는 법, 관계의 방향과 연결 수, 단위를 맞출 기준을 정합니다. 「정한 것」 표의 결정을 어느 종류 · 관계에 반영할지 정합니다.

05 구현 ① 설비와 구성 요소 만들기

왜 하는가 설비 대장은 설비를, 구성 요소 목록은 설비 안에서 정비하는 부분을 적은 자료입니다. 구성 요소에는 뒤에서 센서와 부품을 이어야 하므로, 구성 요소를 속성으로 둘지 대상으로 둘지는 4단계의 기준(다른 대상과 이어지면 대상)으로 정합니다. 같은 장치를 다르게 적은 행과 다른 장치를 비슷하게 적은 행을 가려내야 대상이 두 번 생기거나 섞이지 않고, 가려내는 근거는 자료 안에서 찾습니다.

할 일 설비 대장과 구성 요소 목록에서 설비 · 구성 요소 대상과 그 사이 관계를 만드는 코드를 결과/에 만들고 실행합니다. 이 단계에서 처리한 문제 행은 결과/자료_검토.md에 한 줄씩 적습니다.

메뉴에서 터미널 → 새 터미널(Terminal → New Terminal)을 누릅니다. 아래쪽에 열린 터미널의 맨 앞 경로가 이 실습 폴더인지 봅니다. 명령은 직접 치지 말고 블록의 복사를 눌러 붙여 넣은 뒤 Enter를 누릅니다 — 손으로 옮기면 오타가 나기 쉽습니다. 명령이 오류로 멈추면 실행한 명령과 출력 전문을 복사해 AI 채팅에 보내고, 무엇이 왜 멈췄는지 먼저 설명해 달라고 합니다.

정하거나 물을 것 대장에 남은 옛 기록, 같은 장치를 다른 이름으로 적은 행을 어떻게 처리했는지와 그렇게 본 근거 줄을 묻습니다.

06 구현 ② 센서와 물리량 잇기

할 일 센서 목록의 줄마다 센서 대상을 만들어 붙은 곳(구성 요소 또는 설비)과 재는 물리량에 잇는 기능을 더하고 실행합니다. 이 단계에서 처리한 문제 행은 결과/자료_검토.md에 한 줄씩 적습니다.

정하거나 물을 것 같은 태그 이름이 다른 설비에 있을 때, 같은 설비 · 태그가 여러 줄일 때, 붙은 곳 이름이 대장 이름과 다를 때 각각 어떻게 처리됐는지 묻습니다.

08 구현 ④ 교체 부품 잇기

왜 하는가 같은 부품을 설비마다 따로 만들면 「이 부품을 어느 설비가 쓰나」의 답이 흩어집니다. 그래서 부품은 전체에서 하나인 번호로 한 번만 만들고 여러 구성 요소가 그것을 가리키게 합니다. 어떤 두 번호를 같은 부품으로 볼지는 답을 쓰는 사람의 일에 따라 달라질 수 있어, 3단계에서 내가 정한 대로 합니다.
