# 현장 정보를 체계화하는 온톨로지 직접 설계하기

## 목표

포털 지식 지도에서 오일 쿨러와 거기 붙은 센서가 어떻게 이어지는지 따라가 봤습니다. 이번에는 그 연결을 직접 만듭니다. 유압 설비 7대의 대장 · 구성 요소 · SCADA 태그 · 예비품 자료를 종류(이론의 클래스 — 대상의 갈래) · 속성 · 관계로 짠 온톨로지에 맞춰 지식 그래프로 정리해, 설비별 센서와 여러 설비가 함께 쓰는 부품을 답하게 합니다. 자료는 같은 센서 이름이 여러 설비에 쓰이고, 같은 장치를 다르게 부르며, 줄이 겹치거나 칸이 비어 있습니다. 읽기 · 환산 · 계약 꼴 · 물어보기는 제공 코드가 하고, 나는 결과가 갈리는 판단(ID와 관계 방향, 같은 장치 · 물리량으로 볼 근거, 빈 칸의 뜻, 같은 규격을 한 물품으로 볼지)을 정합니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 설계를 맡습니다.

만들 것: `결과/`의 정할 자리(판단 표 · 판단 함수)와 그것으로 제공 코드가 만드는 스키마와 지식 그래프(`결과/schema.json` · `결과/graph.json`), `결과/기대_답.csv` · `결과/정한_것.csv` · `결과/요구사항.md`.

## 출발점

- `자료/` — 원자료. CSV 8개(설비 대장 · 구성 요소 · 센서 · 예비품 · 품번 교차표 · 공급 조건 · 승인 공급사 · 입고 이력), 현장 메모. 기준일은 2026-10-15입니다. 이번 질문에 쓰는 것은 설비 · 구성 요소 · 센서 · 예비품 · 품번 자료이고, 공급 · 입고 자료는 이번 질문 밖입니다.
- `입력/관계그림.json` — 1회차에 ARROWS로 그린 관계 그림(설비 · 구성 요소 · 센서와 증상 · 원인 · 조치). 이번에는 그 가운데 설비 · 센서 · 부품 쪽을 원자료 전체로 구체화합니다.
- `결과/` — 정할 자리(첫 줄에 「제공 빈 틀」이 있는 표 · 함수 파일)와 기록. 모델(스키마 · 인스턴스)은 정할 자리를 채운 뒤 제공 코드가 씁니다.
- `model_tool.py` — 원자료와 정할 자리를 읽어 모델을 쓰고 모델에 물어보는 제공 코드(바꾸지 않습니다). `check.py` — 구조 검사.
- `show_result.py` · `lab_steps.py` — 결과 화면을 만드는 제공 코드. `python show_result.py`가 단계마다 `결과/보기.html`을 다시 씁니다. 바꾸지 않습니다.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.

## 해결할 질문

아래 질문의 답은 보전팀이 설비별 센서를 찾고, 교체할 부품을 어느 설비와 함께 준비할지 정할 때 씁니다. 같은 부품을 구매팀은 호환 후보를 찾을 때, 창고는 품목별 재고를 셀 때 조회합니다.

1. 설비별로 어떤 구성 요소에 어떤 센서 · 계산값 · 설정값이 붙어 있는가?
2. 각 센서가 재는 물리량과 단위 · 정상값 · 한계(위로 넘는지, 아래로 떨어지는지)는 무엇인가? 설비마다 태그 이름이 달라도 같은 물리량을 재는 센서를 함께 찾을 수 있는가?
3. 교체 부품별로 그 부품을 쓰는 설비와 구성 요소는 무엇인가? 다른 표기로 적힌 품번, 제조사 규격 번호, 원자료에 없는 품번으로 물으면 결과가 어떻게 구별되는가?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **쓰는 사람에 따라 갈리는 답** — 같은 규격(제조사 품번)으로 등록된 서로 다른 사내 품번을 한 물품으로 볼지 — 그 규격이나 한쪽 품번으로 물었을 때 나와야 할 답이 호환 후보를 찾는 사람과 품목별 재고를 세는 사람에게 같은지
- **빈 칸의 뜻** — 교체부품 칸이 비었거나 품명만 적힌 행을 예비품 목록(적용모델 · 쓰는곳)으로 이어 그 부품을 쓰는 설비로 볼지, 원자료가 품번을 말하지 않았으니 잇지 않을지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 공급 조건 · 입고 이력을 모델에 넣는 일
- 그래프 DB에 적재하고 조회하는 일(다음 실습)
- 부품 재고 수량을 세거나 발주를 정하는 일

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

`check.py`와 다음 실습이 읽는 모양입니다. 무엇을 종류·속성·관계로 둘지는 직접 정합니다.

- `결과/schema.json`: `{"classes": {종류: {"meaning": 뜻, "required": {속성: 자료형}, "optional": {속성: 자료형}}}, "relations": {관계: {"from": 종류 또는 [종류…], "to": 종류, "cardinality": "1:N" 등, "properties": {속성: 자료형}}}}`
- 자료형은 `string`·`number`·`integer`·`boolean`·`list` 중 하나이거나, 허용 값 목록(예: `["upper", "lower"]`)입니다.
- `결과/graph.json`: `{"nodes": [{"labels": [종류], "props": {"id": 고유 ID, …}}], "rels": [{"type": 관계, "a": 시작 id, "b": 끝 id, "props": {…}}]}`
- 같은 두 대상 사이에 같은 관계를 여러 개 두려면 그 관계의 props에 `id`를 붙입니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(「실습 시작」 도구가 이 폴더 옆에 내려 둔 파일, 노션 「가이드문서」)의 같은 번호에 있습니다.

1. **폴더와 출발점 확인** — 탐색기에서 `입력/` · `자료/` · `결과/` · START.md를 열고, 터미널에서 `python show_result.py`로 결과 화면을 처음 엽니다.
2. **파일을 바꾸지 않고 자료 파악** — AI에게 파일을 바꾸지 말고, 내가 고른 설비 하나의 구성 요소 · 센서 · 교체 부품에 관한 줄을 자료마다 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.
3. **요구와 기대 답 정하기** — `결과/요구사항.md`에 질문 · 쓰는 사람 · 기준일 · 지킬 조건을, `결과/기대_답.csv`에 고른 설비에서 센서가 붙은 구성 요소 셋의 센서(질문 1), 같은 물리량을 재는 센서 한 묶음(질문 2), 함께 쓰는 부품 · 다른 표기 · 없는 품번 하나씩의 사용 설비(질문 3)를 원자료에서 찾아 적습니다. 질문 1 항목은 지금은 원자료 이름으로 적고 5단계에서 고칩니다. 결정 지점은 `결과/정한_것.csv`에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **판단① ID와 관계 방향 정하기** — `결과/설계.csv`에 대상(설비 · 구성 요소 · 센서 · 물리량 · 부품)마다 ID를 지을 원자료 열을, `결과/관계.csv`에 연결마다 관계 이름과 시작 쪽을 적고 `python show_result.py`를 실행합니다.
5. **판단② 같은 장치 이름과 겹친 행 정하기** — `결과/name_rules.py`의 `same_device` · `group_name`에 같은 장치로 볼 내 기준을 AI와 쓰고, `결과/행_처리.csv`에 겹치거나 기준일에 살아 있지 않은 행의 처리를 적은 뒤 `python show_result.py`를 실행합니다. 제공 코드가 모든 구성 요소 행 짝에 내 기준을 물어 묶고 묶음마다 이름 하나를 씁니다. 기준이 묶지 못한 같은 장치만 `결과/이름.csv`에 적습니다.
6. **판단③ 같은 물리량 묶기** — `결과/quantity_rules.py`의 `same_quantity` · `quantity_name` · `kind_of`에 같은 물리량으로 볼 기준과 종류(실측 · 계산값 · 설정값)를 가르는 기준을 AI와 쓰고 `python show_result.py`를 실행합니다. 기준과 다르게 둘 재는것만 `결과/물리량.csv`에 적습니다.
7. **판단④ 단위와 빈 칸 정하기** — `결과/unit_rules.py`의 `base_unit` · `blank_unit`에 기준 단위를 고르는 기준과 빈 단위 칸을 채우는 기준을 AI와 쓰고 `python show_result.py`를 실행합니다. 기준과 다르게 둘 것만 `결과/단위.csv`에 적습니다.
8. **판단⑤ 교체 부품과 같은 규격 정하기** — `결과/part_rules.py`의 `find_part` · `same_item`을 AI와 채우고 `python show_result.py`를 실행합니다. 괄호 속 품번 · 사내 품번 · 교차표로 풀리는 칸은 제공 코드가 먼저 풀고, 못 푼 행에서만 내 함수를 부릅니다.
9. **물어보고 기대 답과 대조** — `python show_result.py`로 9단계 칸에서 내 기대 답과 모델에 물은 답을 줄마다 견줍니다.
10. **구조 검사** — 10단계 칸의 구조 검사(`python check.py`) 출력을 봅니다.
11. **저장하고 다시 열기** — 모두 저장하고 폴더를 닫았다 다시 연 뒤 `python show_result.py`를 다시 실행하고, `결과/요구사항.md` 끝에 기준일 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 같은 태그 이름이 여러 설비에 있는 경우
- 이름이 다른데 같은 것을 재는 태그
- 같은 장치를 다르게 부른 이름
- 같은 대상이 두 번 나온 행
- 기준일(2026-10-15)에 살아 있지 않은 기록(옛 코드 · 철거된 실물)
- 비어 있는 칸(단위 · 교체부품 · 정상값)
- 단위 표기가 다른 값
- 계기 없는 계산값과 설정값
- 여러 설비가 함께 쓰는 부품과 한 설비만 쓰는 부품
- 품번 대신 품명 · 다른 표기로 적힌 칸
- 같은 규격(제조사 품번)으로 등록된 다른 사내 품번
- 원자료에 없는 품번
- 같은 정할 자리로 다시 실행한 결과

실행 명령:

```
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/` · `자료/` · 제공 파일(`show_result.py` · `lab_steps.py` · `model_tool.py` · `check.py`)이 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.
