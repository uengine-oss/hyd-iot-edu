01 시작하기

앞 단계 완성 모델을 별도 랩 DB에 적재하고, 질문마다 조회를 만들어 원자료와 대조합니다. 수정본을 반영하고 다시 적재해도 같은 ID가 유지되고 중복이 생기지 않는지 확인합니다.

입력/schema.json·graph.json은 앞 단계 완성 모델이고, 입력/자료/는 그 원자료, 입력/자료_변경분/은 기준일 뒤 들어온 수정본입니다. 이전 개인 결과 없이 시작할 수 있습니다. 개인 모델을 쓰려면 제공 입력을 보존하고 별도 폴더에 복사하세요.

VS Code에서 START.md를 열고 이번 요구를 확인하세요.

입력/   앞 단계 결과·완성 모델
입력/자료/   원자료 · 입력/자료_변경분/   수정본
결과/   이번에 만들 결과
AGENTS.md   AI 작업 규칙

터미널에서 아래 명령을 실행하세요. Docker가 실행 중이어야 합니다.

python lab_db.py

「랩 DB 준비 완료」가 나오면 열린 Browser의 Protocol에서 bolt://를 선택하고 Connection URL에는 출력 주소의 127.0.0.1:포트 부분만 넣으세요. Database user는 neo4j, Password는 비워 두고 Connect를 누릅니다. 연결 정보는 랩_연결.json에도 저장됩니다.

02 요구 정하기

  1. 설비별로 어떤 구성 요소에 어떤 센서·계산값·설정값이 붙어 있는가?
  2. 각 센서가 재는 물리량과 단위·정상값·한계(위로 넘는지, 아래로 떨어지는지)는 무엇인가? 설비마다 태그 이름이 달라도 같은 물리량을 재는 센서를 함께 찾을 수 있는가?
  3. 교체 부품별로 그 부품을 쓰는 설비와 구성 요소는 무엇인가? 보전팀은 이 답으로 지금 가동하는 설비의 예비품 준비를 정한다. 다른 표기로 적힌 품번이나 원자료에 없는 품번으로 물으면 결과가 어떻게 구별되는가?
  4. 수정본을 반영한 뒤에도 같은 ID가 유지되고, 다시 적재해도 대상과 관계가 늘지 않는가?

자료에서 답의 근거를 찾고, AI에 전달할 목표·제약·내가 정한 결정을 정리하세요. 확인할 사례의 종류: 설비별 구성 요소·센서 개수 / 태그 이름이 달라도 같은 물리량 / 한계 방향과 한계 없음 / 공용 부품과 전용 부품 / 다른 표기·없는 품번 / 수정본의 이름 변경·상태 변경·값 보완 / 같은 적재 두 번.

03 AI와 만들기

적재(모델 → DB)와 조회를 작성합니다. 같은 입력을 두 번 적재해도 대상과 관계가 늘지 않아야 하고, 이름이 바뀌어도 같은 ID의 대상은 유지되어야 합니다. 전체 삭제문은 쓰지 않고, 수정본은 필요한 대상만 고쳐 반영합니다. 공용 부품의 사용 설비를 원자료와 대조하고, 다른 품번과 원자료에 없는 품번도 조회해 결과를 구별합니다.

먼저 파일을 바꾸지 말고 자료를 읽게 하고, 계획을 받아 검토한 뒤 확인할 수 있는 단위로 나눠 맡기세요. 완료 보고에는 실행 출력 원문을 붙여 달라고 요청합니다. 파일 이름은 백틱(`)으로 감싸 입력하세요.

요청을 정리할 때 볼 항목

만들 결과 / 참고할 자료 / 내가 정한 결정 / 바꾸지 않을 범위 / 성공을 확인할 사례

04 결과 확인하기

python lab_db.py
Neo4j Browser에서 적재 → 개수 확인 → 같은 적재 다시 실행 → 개수 비교 → 조회 → 수정본 반영 → 조회 다시 실행
  • 질문마다 원자료에서 먼저 찾은 기대 답과 실제 결과를 나란히 적습니다.
  • 자료를 읽는 방식에 따라 답이 갈리는 지점은 내가 정한 결정과 근거 행을 함께 남깁니다.
  • 값이 없음·미확인·0을 구별합니다.
  • 같은 입력을 다시 적재해도 노드·관계 수가 늘지 않습니다. 수정본 반영 뒤의 개수 변화는 수정본의 행으로 설명할 수 있어야 합니다.
  • 수정본의 「삭제」 줄을 반영한 뒤에는 그 설비의 센서 수를 원자료의 행과 다시 세어, 실제로 있는 센서가 사라지지 않았는지 확인합니다.
  • 상태가 바뀐 설비가 질문의 답에 어떻게 나오는지(빠지는지, 상태와 함께 나오는지)를 결정 표의 결정과 대조합니다.

원자료와 실제 결과를 대조하세요. AI의 완료 메시지는 실행 결과를 대신하지 않습니다.

개수 확인 예: MATCH (n) RETURN labels(n)[0] AS 종류, count(*) ORDER BY 종류. 조회 결과는 Browser의 Table 보기로 원자료의 행과 대조합니다.
