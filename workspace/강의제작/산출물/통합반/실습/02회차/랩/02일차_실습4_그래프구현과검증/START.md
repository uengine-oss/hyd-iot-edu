# 설계한 온톨로지를 그래프 DB에 구현하고 검증하기

## 목표

「현장 정보를 체계화하는 온톨로지 직접 설계하기」에서는 설비 · 센서 · 부품을 종류(이론의 클래스 — 대상의 갈래) · 속성 · 관계로 정의해 모델을 만들었습니다. 이번에는 제공된 설비 · 센서 · 부품 모델(또는 내 모델)을 이 폴더 전용 랩 DB(그래프 DB)에 적재하고, 질문마다 Cypher 쿼리를 만들어 원자료와 대조합니다. 파일 읽기 · 실행 · 개수 세기 · 전후 비교는 제공 코드가 하고, 나는 같은 대상을 알아보는 열쇠와 조회가 돌려줄 것, 수정본 반영을 정해 문장으로 씁니다.

줄기(온톨로지 → 에이전트 → 프로세스)에서 이 실습은 첫 단계 온톨로지의 구현과 검증를 맡습니다.

만들 것: 적재 쿼리(`결과/load.cypher`), 질문별 조회 쿼리(`결과/query.cypher`), 수정본을 반영하는 수정 쿼리(`결과/update.cypher`), `결과/기대_답.csv` · `결과/정한_것.csv` · `결과/검증_기록.md`.

## 출발점

- `입력/schema.json` · `입력/graph.json` — 제공된 설비 · 센서 · 부품 모델. 설비 7대 · 구성 요소 · 센서 · 물리량 · 부품과 그 연결이 들어 있습니다.
- `입력/자료/` — 그 모델의 원자료(기준일 2026-10-15). `입력/자료_변경분/2026-10-20_수정본/` — 기준일 뒤 담당자들이 고친 줄만 모은 수정본.
- `입력/요구사항.md` · `입력/자료_검토.md` — 제공된 모델이 답하는 질문과 자료 처리 근거.
- `lab_db.py` — 이 폴더 전용 랩 DB를 켜는 도구. `lab_cypher.py` — 적재 · 조회 문장을 랩 DB에 실행하고 세는 제공 도구. `check.py` — 제공 파일 · 기록 검사.
- `show_result.py` · `lab_steps.py` — 결과 화면을 만드는 제공 코드. `python show_result.py`가 단계마다 `결과/보기.html`을 다시 씁니다. 바꾸지 않습니다.
- `결과/` — 정할 자리(첫 줄에 「제공 빈 틀」이 있는 문장 · 표 파일)와 기록.
- `AGENTS.md` · `.github/copilot-instructions.md` · `CLAUDE.md` — Codex와 GitHub Copilot이 지키는 작업 규칙(세 파일이 같은 내용). 학생도 함께 읽습니다.
- 내 모델은 고를 때만 `결과/내_모델/`에 복사해 씁니다(형식 · ID가 맞는지 먼저 보고, 다르면 내 정의로 조회). 없어도 제공 모델로 끝까지 합니다.

## 해결할 질문

아래 질문의 답은 보전팀이 지금 가동하는 설비의 예비품 준비를 정할 때 씁니다.

1. 설비별로 어떤 구성 요소에 어떤 센서 · 계산값 · 설정값이 붙어 있고, 각 센서의 물리량 · 단위 · 한계는 무엇인가?
2. 설비별로 구성 요소마다 어떤 교체 부품이 들어가고, 여러 설비가 함께 쓰는 부품은 어느 설비 · 구성 요소에서 쓰는가? 다른 표기로 적힌 품번이나 원자료에 없는 품번으로 물으면 결과가 어떻게 구별되는가?
3. 수정본을 반영한 뒤에도 같은 ID가 유지되고, 같은 적재를 다시 실행해도 대상과 관계가 늘지 않는가?
4. 포털 실습에서 본 기준 지도와 견주면 내 그래프의 식별자 · 관계 방향이 어디서 같고 어디서 다른가?

## 학생이 정할 것

원자료만으로 하나로 정해지지 않아 내가 근거를 찾아 정할 지점입니다. 해당하는 행 · 절은 직접 찾고, 지점마다 고른 것 · 근거(파일:줄) · 바뀌는 답을 `결과/정한_것.csv`에 한 줄씩 적습니다.

- **시점과 상태** — 설비 대장의 상태와 수정본에서 바뀐 상태를 그래프에 어떻게 반영하고, 「지금 가동하는 설비」를 묻는 부품의 사용 설비 조회에 어떻게 드러낼지(답에서 빠지는지, 상태와 함께 보이는지)
- **불용 결정 설비** — 수정본이 불용으로 바꾼 설비를 상태만 바꿔 남길지, 그 설비에만 딸린 구성 요소 · 센서와 함께 그래프에서 지울지

AI에게 이 지점을 정하게 하지 않습니다. AI가 고르거나 「권장」을 붙여도 따르지 말고 원문 줄을 열어 내 선택과 근거를 말하며, 못 정하면 미결로 둡니다.

## 이번 범위 밖

- 공급 조건 · 입고 이력의 적재와 조회
- 모델의 종류 · 속성 · 관계 정의를 새로 바꾸는 일(이상한 곳은 `결과/검증_기록.md`에 적습니다)
- 포털 DB에 접속하거나 포털 자료를 랩 DB에 넣는 일

자료에 있어도 이번 결과에 만들지 않습니다.

## 결과 형식

`결과/`에 아래 파일을 둡니다. 파일 안에서 무엇을 어떤 문장으로 쓸지는 직접 정합니다.

- `결과/load.cypher`(또는 적재 코드): 모델 파일의 대상과 관계를 랩 DB에 넣습니다. 같은 파일을 다시 실행해도 됩니다.
- `결과/update.cypher`(또는 수정 코드): 수정본의 줄을 이미 넣은 그래프에 반영합니다.
- `결과/query.cypher`: 질문마다 Cypher 쿼리 하나. 쿼리 위에 어느 질문의 쿼리인지 주석(`// 질문 1`)으로 적습니다.
- `결과/검증_기록.md`: 「제공 빈 틀」의 칸대로 채웁니다.

## 진행 단계

한 번에 한 단계씩 갑니다. 단계마다 결과를 확인한 뒤 다음 단계로 갑니다. 단계마다 정하거나 물을 것, 요청에 담을 것, 판단할 증거는 가이드(「실습 시작」 도구가 이 폴더 옆에 내려 둔 파일, 노션 「가이드문서」)의 같은 번호에 있습니다.

1. **폴더와 출발점 · 랩 DB 켜기** — 탐색기에서 `입력/` · `결과/` · START.md를 열고 `python lab_db.py`로 이 폴더 전용 랩 DB를 켠 뒤 `python show_result.py`로 결과 화면을 엽니다.
2. **파일을 바꾸지 않고 자료 파악** — AI에게 파일을 바꾸지 말고 `입력/graph.json`의 종류별 대상 · 관계 수와 수정본 줄마다 가리키는 대상과 원자료(`입력/자료/`)의 같은 행을 파일 · 줄로 짚게 하고, 그 줄을 직접 엽니다.
3. **요구와 기대 답 정하기** — `결과/검증_기록.md`에 질문 · 쓰는 사람 · 지킬 조건을, `결과/기대_답.csv`에 질문마다 물을 값 · 볼 열 · 원자료에서 찾은 기대 답(설비 하나의 센서 · 교체 부품, 공용 부품 하나의 사용 설비)을 적고, 결정 지점을 `결과/정한_것.csv`에 적습니다. 다 적으면 AI에게 파일을 바꾸지 말고 되짚게만 합니다.
4. **판단① 적재 쿼리 쓰기** — `결과/load.cypher`에 종류 · 관계마다 문장 하나(위에 `// 넣을 것: <종류 또는 관계>`, 행은 `$rows`)를 AI와 쓰고 `python show_result.py`를 실행합니다. 행을 넘겨 실행하고 개수를 세는 것은 제공 코드가 합니다.
5. **같은 적재 다시 실행** — `python show_result.py`를 한 번 더 실행해 5단계 칸에서 같은 적재 전후의 개수를 봅니다.
6. **판단② 설비별 센서 조회** — `결과/query.cypher`에 `// 질문 1` 조회(설비 하나 → 구성 요소별 센서와 물리량 · 단위 · 한계, 구성 요소 · 센서 id 포함)를 AI와 쓰고 `python show_result.py`를 실행합니다.
7. **판단③ 설비별 교체 부품 조회** — `결과/query.cypher`에 `// 질문 2` 조회(설비 하나 → 구성 요소마다 교체 부품)를 더하고 `python show_result.py`를 실행합니다.
8. **판단④ 부품의 사용 설비 조회** — `결과/query.cypher`에 `// 질문 3` 조회(품번이나 표기 하나 → 쓰는 설비 · 구성 요소)를 더하고 `python show_result.py`를 실행합니다. 설비 상태는 `결과/정한_것.csv`의 결정대로 반영합니다.
9. **판단⑤ 수정본 반영하기** — `결과/update.cypher`에 수정본 줄마다 필요한 대상 · 관계만 고치는 문장을 AI와 쓰고 `python show_result.py`를 실행합니다. 전후 비교와 같은 수정 한 번 더는 제공 코드가 합니다.
10. **포털 기준 지도와 비교** — 10단계 칸의 「내 그래프 — HYD-01에서 시작하는 관계」와 아래 포털 기준 지도 표를 나란히 보고, 식별자와 관계의 시작 · 끝을 `결과/검증_기록.md`에 적습니다. 포털은 다시 열지 않습니다.
11. **저장하고 다시 열기** — 적재 · 수정 · 조회 파일과 기록을 저장하고 폴더를 닫았다 다시 연 뒤 `python lab_db.py` · `python show_result.py`를 실행하고, 기록 끝에 기준일 · 수정본 날짜 · 저장 시점 · 확인하지 못한 점을 적습니다.

이 순서는 바이브 코딩 일곱 단계 — 파일을 바꾸지 않고 파악 → 요구와 기대 답을 내 말로 → 계획 검토 → 작게 구현 → 원자료와 대조 → 고침 → 저장하고 다시 열기 — 를 따릅니다.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 확인

확인할 사례의 종류(어느 행이 해당하는지는 원자료에서 직접 찾습니다):

- 설비별 구성 요소 · 센서 개수
- 한계 방향과 한계 없음
- 설비에 바로 붙은 센서
- 설비별 교체 부품과 교체 부품이 없는 구성 요소
- 공용 부품과 전용 부품
- 상태가 가동이 아닌 설비도 쓰는 공용 부품
- 다른 표기 · 없는 품번
- 수정본의 이름 변경 · 상태 변경 · 값 보완 · 줄 삭제가 바꾸는 그래프의 대상 · 관계
- 반영 뒤 원자료와 다시 센 개수 · 값(「삭제」 줄이 걸린 설비 포함)
- 같은 적재 두 번 · 같은 수정 두 번

실행 명령:

```
python lab_db.py
python show_result.py
python check.py
```

바뀐 파일 확인: AI가 단계를 마칠 때마다 바뀐 파일 목록을 봅니다. `입력/`(원자료 · 수정본 포함) · 제공 파일(`show_result.py` · `lab_steps.py` · `lab_cypher.py` · `lab_db.py` · `check.py`)이 바뀌지 않았는지, 요청하지 않은 파일이 생기지 않았는지 확인합니다. 편집 승인 창에서는 경로가 `결과/` 아래일 때만 허용합니다.

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 결과 화면에서 질문마다 원자료에서 먼저 적은 기대 답과 실제 조회 결과가 맞고, 같은 적재 · 같은 수정을 다시 해도 개수가 같으며, `결과/정한_것.csv`의 지점마다 근거 줄과 그 선택으로 바뀌는 답을 설명할 수 있으면 완료입니다. 고친 점과 확인하지 못한 점은 `결과/검증_기록.md`에 짧게 남깁니다.

## 저장과 다음 실습

적재 · 수정 · 조회 파일과 `검증_기록.md` · `정한_것.csv` · `기대_답.csv`를 함께 보관합니다. 기록에는 반영한 자료의 기준일과 수정본 날짜를 적습니다. 다음 실습 「작업 절차와 판단 조건을 연결해 조치 기준 만들기」는 이 설비 모델의 ID에 작업 절차와 판단 조건을 잇습니다. 그 실습도 제공된 모델로 시작할 수 있으므로 이 결과는 골라서 가져갑니다. 재부팅 전에 이 폴더를 USB나 개인 클라우드에 복사합니다(자동으로 되살리지 않음).
