HYD · 실습 가이드

설계한 온톨로지를 그래프 DB에 구현하고 검증하기

설계 실습에서 다룬 클래스 · 식별자 · 관계를 Neo4j 실습에서 써 본 MERGE로 이 폴더 전용 그래프 DB(랩 DB)에 옮깁니다. 과정의 첫 단계인 온톨로지를 그래프 DB에서 실제로 묻고 고쳐 보며, 역량 질문마다 쿼리를 돌린 결과와 수정본을 반영한 결과를 원자료와 대조합니다. 결과는 사람마다 조금씩 달라도 되고, 내가 먼저 정한 기대 답과 맞으면 됩니다.

01 폴더 열고 자료 확인하기

ZIP을 풀고 VS Code 파일 → 폴더 열기로 안쪽 graph-lab 폴더(run.py가 든 폴더)를 엽니다(바깥 폴더를 열면 Codex가 정답이 든 이 가이드까지 읽습니다). 신뢰를 물으면 예, 작성자를 신뢰합니다를 누르고, 터미널 → 새 터미널에 아래 명령을 복사해 붙여 넣습니다(손으로 치면 오타가 납니다). 랩 DB를 쓰는 명령은 터미널에서만 실행합니다(02단계).

06 스키마를 그래프로 옮기기: 적재와 다시 적재

힌트

다시 적재해도 늘지 않으려면, 무엇을 정해 말할까?

  • MERGE 패턴 — 바뀌지 않는 식별자만
  • 이름 같은 값 — SET
  • 행 — $rows(실행할 때 값을 넣는 자리)
  • 종류 · 관계마다 쿼리 하나
정답 보기

Codex 채팅에 붙여 넣는 글

MERGE의 패턴에는 바뀌지 않는 식별자(`schema.json`의 식별자)만 적고 이름 같은 값은 SET으로 넣어 `load.cypher`를 구현해 줘. `schema.json`의 종류와 관계 방향을 따르고 행은 $rows로 받아 줘. 종류 · 관계마다 쿼리를 나누고 바로 위에 `// 넣을 것: <종류 또는 관계>`를 적어 줘. 같은 대상을 중복 생성하거나 전체를 지우지 마. 조회 쿼리와 수정 쿼리는 아직 작성하지 마.

11 포털 기준 지도와 견주기

아래 명령으로 「내 그래프」 표를 띄워, 그 아래 포털 지식 지도(기준 지도) 표와 쿨러를 어떻게 셌는지 견줍니다. 기준 지도의 상태 변수 줄은 내 모델의 물리량 자리이고, CE 센서는 이 원자료 밖입니다.

터미널(PowerShell · 이 실습 폴더)

python run.py compare

결과 화면에 「내 그래프」 표가 보이면 아래 기준 지도 표와 견줍니다.

포털 기준 지도 포털 실습에서 HYD-01의 오일 쿨러를 펼쳐 본 지식 지도 가운데 설비 → 쿨러 → 센서 → 상태 변수 길의 식별자 · 관계입니다. 「 」는 화면의 관계 이름, 괄호는 저장된 이름, →는 방향(시작 → 끝)입니다.

종류식별자(id)알아볼 값관계와 방향
설비asset:hyd-01code HYD-01나가는 「구성 요소」(HAS_COMPONENT): 이것 → comp:cooler
구성 요소comp:coolername 오일 쿨러들어오는 「구성 요소」(HAS_COMPONENT): asset:hyd-01 → 이것
나가는 「관측 센서」(MONITORED_BY): 이것 → sen:ce · 이것 → sen:ts1
센서sen:ts1tag TS1들어오는 「관측 센서」(MONITORED_BY): comp:cooler → 이것
나가는 「읽는 상태 변수」(OBSERVES): 이것 → sv:ts1
센서sen:cetag CE들어오는 「관측 센서」(MONITORED_BY): comp:cooler → 이것
나가는 「읽는 상태 변수」(OBSERVES): 이것 → sv:ce
상태 변수sv:ts1name 유온들어오는 「읽는 상태 변수」(OBSERVES): sen:ts1 → 이것
상태 변수sv:cename 냉각 효율들어오는 「읽는 상태 변수」(OBSERVES): sen:ce → 이것

포털 실습에서 본 것처럼 설비 칸을 HYD-02로 바꾸면 asset:hyd-02에서 같은 comp:cooler로 「구성 요소」 관계가 이어지고, 그 아래 센서 · 상태 변수도 이 표와 같은 노드입니다.

확인 두 표의 차이와 그 까닭을 실제 줄로 말할 수 있으면 됩니다. 모델은 바꾸지 않습니다.

12 저장하고 다시 확인하기

폴더를 닫았다 다시 열고 아래 명령으로 랩 DB를 켭니다. 학교 PC는 재부팅하면 초기화될 수 있으니 폴더를 USB나 개인 클라우드에 보관합니다.

터미널(PowerShell · 이 실습 폴더)

python run.py db

확인 같은 랩 DB가 열리면 됩니다. 새 랩 DB를 만들었다고 나오면 접힌 안내의 적재 · 수정을 먼저 실행합니다.

새 랩 DB가 만들어졌다는 안내가 나왔을 때 — 먼저 실행

터미널(PowerShell · 이 실습 폴더)

python run.py load

넣은 개수가 모델과 같은지 봅니다.

터미널(PowerShell · 이 실습 폴더)

python run.py update

수정본과 내 선택이 반영됐는지 봅니다.

터미널(PowerShell · 이 실습 폴더)

python run.py usage

F5를 눌러 결과가 그대로인지 봅니다.

터미널(PowerShell · 이 실습 폴더)

python run.py export

랩 DB의 그래프를 output/schema.json · graph.json으로 저장합니다.

터미널(PowerShell · 이 실습 폴더)

python run.py check

「구조 검사 통과」가 보이면 됩니다.

내 말로 불용 설비를 왜 그렇게 처리했고 질문 ③이 어떻게 나왔는지, 다시 적재해도 늘지 않은 까닭을 말해 봅니다.
