01

README에서 시스템과 준비할 도구 확인하기

프로젝트 README를 엽니다. README는 프로젝트 소개와 실행 방법을 담은 첫 안내문입니다. 실행 환경 표에서 여섯 도구의 설치 기준과 공식 설치 링크를 찾으세요.

이미 설치한 도구는 버전이 기준 이상이면 그대로 쓰고, 없거나 낮은 것만 설치합니다. Mac은 같은 README의 macOS 안내를 따릅니다.

도구 어디에 쓰나
Python 프로젝트의 준비 코드와 직접 만들 프로그램을 실행합니다.
Node.js 업무 데이터베이스를 준비하는 도구 등을 실행합니다.
Git 프로젝트를 내 컴퓨터로 받고 이후 새 판을 받습니다. Windows에서는 Git Bash도 함께 사용합니다.
VS Code 파일을 열고, AI와 대화하고, 터미널에서 명령을 실행합니다.
WSL Windows에서 Docker가 Linux 프로그램을 실행할 기반을 제공합니다.
Docker Desktop 여러 서비스를 준비된 구성대로 함께 실행합니다.
02

Python 설치하고 실행 확인하기

README의 Python 링크에서 Windows 설치 파일을 받아 엽니다. Add python.exe to PATH를 선택하고 Install Now를 누르세요. PATH를 켜 두면 터미널에서 이름만으로 프로그램을 부를 수 있습니다.

설치가 끝나면 새 PowerShell 창을 열고 아래 명령을 실행합니다. 명령은 손으로 치면 틀리기 쉬우니 복사해 붙여넣으세요.

python --version

README 기준 이상의 버전이 나오면 됩니다. 명령을 찾지 못하면 PATH를 선택했는지 보고 PowerShell을 새로 여세요.

03

Node.js 설치하고 실행 확인하기

README의 Node.js 링크에서 Windows 설치 파일을 받아 엽니다. 기본값으로 진행하다 Tools for Native Modules에서 자동 설치 항목을 비워 두고 Next, 다음 화면에서 Install을 누르세요. Windows가 권한을 물으면 예를 누릅니다(사진에는 찍히지 않습니다). 뒤의 설치에서도 같습니다.

시작에서 PowerShell을 검색해 Windows PowerShell을 새로 엽니다.

node --version

README 기준 이상의 버전이 나오면 됩니다.

04

Git 설치하고 Git Bash 열기

README의 Git 링크에서 Windows 설치 파일을 받아 엽니다. PATH 화면은 권장 선택 그대로 Next를 누릅니다. 마지막 창에서 Launch Git Bash를 선택하고 Finish를 누르세요.

열린 Git Bash에서 실행합니다.

git --version

Git 버전이 나오면 됩니다.

VS Code 설치하기

README의 VS Code 링크에서 Windows User Installer를 받아 엽니다. PATH에 추가를 유지하고 설치를 마칩니다. VS Code는 WSL과 Docker를 설치한 뒤에 엽니다.

06

WSL 준비하기

PowerShell에서 실행합니다.

wsl --version

아무 키나 누르라는 안내가 나오면 60초 안에 Enter를 누르고 설치가 끝날 때까지 기다리세요.

WSL이 없다는 오류만 나오면 관리자 PowerShell에서 실행합니다.

wsl --install --no-distribution

버전이 README 기준보다 낮으면 실행합니다.

wsl --update

재부팅을 요청하면 재부팅한 뒤 wsl --version을 다시 실행해 README 기준 이상인지 봅니다. Ubuntu는 설치하지 않습니다. Docker가 자기 Linux 환경을 쓰기 때문입니다.

Docker Desktop 설치하고 저장소 주소 복사하기

README의 Docker Desktop 링크에서 Windows 설치 파일을 받아 엽니다. WSL 2 선택을 유지하고 OK를 누르세요.

Installation succeeded가 나오면 Close를 누릅니다.

프로젝트 GitHub 페이지에서 Code → HTTPS의 주소 오른쪽 복사 버튼을 누르세요. 뒤의 git clone 명령에 들어가는 주소입니다.

08

VS Code에 한국어 팩과 Codex 설치하기

VS Code를 엽니다. 로그인 창에서 Continue without Signing In을 누르세요.

테마 창에서 Get Started를 누릅니다.

왼쪽 확장 아이콘(Extensions)에서 Korean Language Pack for Visual Studio Code를 검색해, 게시자 Microsoft인 것을 설치합니다.

같은 검색칸에서 Codex를 찾아 게시자 OpenAI인 것을 설치합니다. Codex는 VS Code 안에서 대화하며 코드를 함께 만드는 AI이고, 이 과정의 실습에서 씁니다. 설치되면 오른쪽 패널에 Codex 탭이 생깁니다.

오른쪽 아래 Change Language and Restart를 누르고, 다시 시작을 묻는 창에서 Restart를 누르세요.

메뉴가 파일, 터미널처럼 한국어로 보이면 됩니다.

09

작업 폴더에서 프로젝트 받기

파일 → 폴더 열기를 누릅니다.

내 파일을 둘 위치에 작업 폴더를 만들고 폴더 선택을 누르세요. 사진은 C 드라이브의 study 폴더입니다.

폴더를 신뢰할지 묻는 창이 나오면 Yes, I trust the authors를 누릅니다. 창이 안 나오면 다음으로 갑니다.

왼쪽 아래에 Restricted Mode가 보이면 제한 모드라 AI가 동작하지 않습니다. Restricted Mode를 누르세요.

Workspace Trust 화면에서 Trust를 누르면 풀립니다.

터미널 → 새 터미널을 누릅니다. 메뉴가 접혀 있으면 위쪽 … 안에 있습니다.

터미널 위쪽 새 터미널 옆 화살표 → Git Bash를 고릅니다.

Git Bash에 아래 명령을 넣고 Enter를 누르세요.

git clone --depth 1 https://github.com/uengine-oss/hyd-iot-edu.git

Receiving objects 비율이 올라가면 받는 중입니다. 사진은 --depth 1 없이 받아 더 오래 걸렸습니다. 기다리는 동안 Codex를 연결합니다.

학교 인터넷에서 schannel: server closed abruptly로 끊기면 아래 명령을 한 번 실행하고 git clone 명령을 다시 실행하세요. 그래도 끊기면 휴대폰 핫스팟으로 받습니다.

git config --global http.sslBackend openssl

Codex 연결과 저장소 수신 결과 확인하기

오른쪽 Codex 탭을 열고 다음을 누릅니다.

현재 모델로 계속 진행을 누르세요.

ChatGPT로 로그인을 누르면 브라우저가 열립니다. 본인 계정을 누르세요(처음이면 계정 정보를 넣는 화면이 먼저 나옵니다).

Select a workspace에서 Continue를 누릅니다.

Signed in to Codex가 나오면 VS Code로 돌아갑니다. 전화번호 확인이 나오면 먼저 마칩니다.

Codex 입력칸에 인사를 넣고 보내세요.

안녕

Codex 패널에 답이 나오고, 왼쪽 탐색기에 hyd-iot-edu 폴더가, 아래 터미널에 Receiving objects: 100%와 Resolving deltas: 100%가 보이면 됩니다.

11

명령 한 번으로 시스템 시작하기

Docker Desktop을 엽니다. Docker Subscription Service Agreement가 나오면 읽어 보고 Accept를 누르세요.

Welcome to Docker에서 오른쪽 위 Skip을 누릅니다.

왼쪽 아래에 Engine running이 나올 때까지 기다립니다. Settings → General에서 Choose Virtual Machine Manager (VMM)가 WSL 2인지 보세요.

VS Code의 Git Bash에서 프로젝트 폴더로 들어갑니다.

cd hyd-iot-edu

입력 줄 위치가 hyd-iot-edu로 바뀌면 시작 명령을 실행하세요. setup 폴더의 시작.bat을 더블클릭해도 같습니다.

bash scripts/start_all.sh

처음에는 이미지를 받느라 오래 걸립니다. Pulling의 받은 양이 변하거나 다음 단계 번호가 나오면 그대로 기다리세요. 3/8 단계의 빨간 WARN: config section [inbucket] is deprecated 줄은 멈춘 것이 아닙니다.

완료. 포털 줄의 주소를 Ctrl을 누른 채 클릭하세요.

브라우저에 제목 홈과 위쪽 네 칸이 보이면 포털이 열린 것입니다. 앞으로 설비 상황을 보고 승인하는 일은 이 화면에서 합니다.

터미널에 포털은 열 수 있습니다 줄이 나오면 AI 단계만 실패한 것입니다. 그 위 실패 줄의 까닭을 고치고 안내된 명령을 다시 실행하세요.

12

홈에서 전체 연결 보기

위쪽 네 칸은 설비 수, 열린 사건, 지식 항목, 시간 배율입니다. 시간 배율 20배는 설비가 실제보다 스무 배 빠르게 돈다는 뜻입니다. 숫자는 사진과 달라도 됩니다.

맨 위 막대의 진행 중 사건과 서비스 수를 봅니다. 서비스가 다 켜져 있어야(사진에서는 13/13) 포털이 제대로 돕니다. 시스템을 켠 뒤에는 이 숫자부터 보세요.

설비 · 데이터 · AI 연결 그림은 왼쪽 현장 설비에서 생긴 값이 가운데 데이터 길을 지나 오른쪽 AI에게 가고, 사람이 승인한 조치가 위쪽 화살표를 따라 설비로 돌아가는 흐름입니다. 왼쪽 메뉴도 이 흐름의 차례로 둘러봅니다.

13

설비 메뉴 둘러보기 — 값이 생기는 곳

설비 → 결함 시뮬레이션을 엽니다. 카드 세 장이 공장의 유압 설비 세 대이고, 컴퓨터 안에서 도는 가상 설비입니다. 큰 숫자는 기름 온도인 유온이고, 아래 보호 정지 기준을 넘으면 설비가 스스로 멈춥니다. 주황 표시는 정기 점검 · 재고 보충 같은 업무 알림이고 고장 표시가 아닙니다.

카드 아래쪽의 쿨러 열화 주입 같은 버튼은 누르는 순간 그 일이 시작됩니다. 오늘은 보기만 하고 아무것도 누르지 마세요.

실시간 모니터링은 같은 값을 시간에 따라 그래프로 보는 곳이고, 오일 분석 입력은 기름 검사 결과를 사람이 넣는 곳, 이상 확인 · 조치는 설비 상태와 사건이 처리되는 과정을 보는 곳입니다.

14

지식 메뉴 둘러보기 — AI가 아는 것

지식 → 지식 지도를 엽니다. 이 공장에 대해 아는 것들이 갈래별 칸에 나뉘어 있고, 관련 있는 것끼리 선으로 이어져 있습니다. 위쪽에서 설비와 지식 묶음을 고릅니다. 지식 지도는 뒤에서 자세히 배웁니다.

조치 방법은 매뉴얼에서 뽑은 조치 목록입니다. 괄호의 즉시 완화는 당장 막는 조치, 근본 조치는 원인을 없애는 조치입니다. 지식 관리는 매뉴얼을 넣어 AI가 정리하고 사람이 확인해 지식으로 넣는 곳, 데이터 연결은 AI가 읽는 회사 데이터와 센서 기록의 연결을 보는 곳입니다.

15

인공지능 설정 메뉴 둘러보기 — 지식을 꺼내 쓰는 에이전트

인공지능 설정 → 에이전트에게 질문은 칸에 궁금한 것을 적어 에이전트에게 묻는 곳입니다. 칸 밑의 질문을 누르면 칸에 채워집니다. 오늘은 보내지 않습니다.

에이전트는 맡은 일이 다른 에이전트 목록, 도구 연결은 에이전트가 쓰는 도구, 시험 비교는 두 에이전트의 판단 비교, 판단 채점은 AI 판단의 점수입니다. 이 화면들은 뒤 회차에서 씁니다.

16

판단 메뉴 둘러보기 — 무엇을 할지 정하는 곳

판단 → 조치 판단 규칙은 「이런 상황이면 이런 조치」로 정해 둔 규칙을 사람이 직접 돌려 보는 곳입니다. 조건별 손익은 조건에 따라 어떤 조치가 이득인지 비교하고, 흐름 가져오기는 업무 흐름을 포털에 등록하는 곳입니다.

승인과 실행은 에이전트가 올린 판단과 그 판단이 승인돼 실행된 결과가 모이는 곳입니다. 아래 기업 시스템 현황에서 생산 주문의 납기를 볼 수 있습니다. 사람이 승인하기 전에는 설비에 손대지 않습니다.

17

작업 메뉴 둘러보기 — 사람이 승인하는 곳

작업 → 내 작업함은 회사 결재함과 같습니다. 맨 위 나에서 고른 사람 앞으로 온 승인할 일과 알림이 모입니다. 고른 사람은 브라우저가 기억해 승인 기록에 그 이름과 역할로 남으니, 지금은 고르지 말고 비워 두세요. 실제로 승인할 때 고릅니다.

처리 건은 일 하나가 생겼을 때 처음부터 끝까지를 한 줄로 이어 기록하는 곳입니다. 지금은 비어 있어도 됩니다.

18

성과 · 시스템 메뉴 둘러보기

성과 → 성과 지표는 승인해서 실행한 조치가 회사에 좋았는지 재는 숫자입니다. AI가 조치를 고를 때도 이 값들을 따집니다. 목표 없음 · 기록 없음 · 계산 불가는 아직 자료나 목표가 없다는 뜻입니다.

시스템 → 시스템 구성은 켜 둔 서비스들이 모여 있는 곳이고, 관리는 기록 재처리와 초기화 화면이라 오늘은 열지 않습니다.

메뉴를 다 둘러봤으면 끝입니다. 화면 아래 다음을 누르면 메뉴 차례대로 하나씩 넘어가니, 혼자 다시 둘러볼 때 쓰세요. 시스템은 켜 둔 채 다음으로 갑니다. 다음에 켤 때는 Docker Desktop을 먼저 열고, 받은 폴더에서 bash scripts/start_all.sh만 다시 실행하면 됩니다. 끄거나 새 판을 받는 법은 README의 실행 파일에 있습니다.
