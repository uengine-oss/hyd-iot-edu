# 코딩 랩

## 반드시
1. **K-1. 랩의 범위는 실라버스 그 행의 VS Code 구간 하나다.** — 판정: 대조표(행 문장 원문 | 다루는 곳: `START.md` 절 · 자료 · 확인 사례 · 가이드 단계 | 확인 방법 | 예상 분)의 빈칸 0, 행에 없는 과제 0.
   코딩 랩은 구분 칸에 VS Code가 있는 행뿐이다. 프로세스 · 종합 회차(온라인 통합 9~11 · 실전 6~8, 오프라인 통합 8~10회 · 실전 7~9회)에는 없다 — bpmn.io · 포털 도구 실습이다.
   시간은 온라인 랩만 행 단위로 잰다: 계획 · 실측 ≥ 배정 − 10분(상한 없음), 채운 것은 행의 내용뿐(대기 · 억지 실패 · 가상 학생 0). 오프라인 랩은 분으로 판정하지 않는다.
2. **K-2. 이론 → 포털 실습 → 코딩 랩 순서로, 앞을 이름으로 받아 열고 포털 없이 돈다.** — 판정: `START.md` 첫머리 · 가이드 첫 화면이 앞 포털 실습(대응 기능이 없으면 바로 앞 이론)을 이름으로 받고 줄기 단계(온톨로지 · 에이전트 · 프로세스)를 말한다. `grep -rn -E '다음|포털에서|앞 실습의' <랩 폴더>`에 걸린 문장 중 실라버스 순서상 바로 다음 랩이 아닌 예고 · 포털 화면 설명 · 학생이 만든 적 없는 결과의 전제 0.
3. **K-3. 문제는 현업 규모로 어렵고, 바이브 코딩 일곱 단계로만 풀린다.** — 판정: 장난감 시험 네 번(Codex · Claude × `two_turn` · `one_turn`) 어느 것도 강사 참조 답과 같은 결과를 내지 않는다.
   자료는 공장 단위 다출처(자산 대장 · 태그 수백 줄 · 정비 이력 · 품번 변형 부품 마스터 · 판본 다른 점검표)라 눈으로 못 맞춘다. 주 질문 경로 위에 원자료만으로 하나로 정해지지 않는 결정 지점이 1개 이상, 갈래에 따라 역할(정비 · 구매 · 운전 · 품질)의 다음 행동이 바뀐다. 억지 함정 · 고의 오류 · 파일 수로 꾸민 난도 · 해피패스 · 구세주 데이터 0.
   일곱 단계: ① 파일을 바꾸지 않고 AI와 파악 ② 요구와 기대 답을 내 말로 ③ 계획 검토 ④ 작게 구현 ⑤ 실행 결과를 원자료와 대조 ⑥ 고침 ⑦ 저장하고 다시 열어 확인. 랩마다 전면 기법 하나: 설계(탐색으로 함정을 찾고 사람이 결정) · 구현(한 기능씩 실제 DB로 확인) · 판정(기대 결과를 원문에서 먼저 적고 대조, AI 출력을 기대값으로 쓰지 않음).
4. **K-4. 학생 폴더에 답이 없다 — 학생의 AI는 폴더 전체를 읽는다.** — 판정: `grep -rn -E 'reference|제작용|강사|정답|해결 로직' <랩 폴더>`에 걸린 문장 중 답 · 강사 자료 위치를 주는 것 0(「막히면 강사에게」 · 「정답이 하나로 정해져 있지 않다」는 해당 없음), 학생 폴더 전문을 강사 참조와 견줘 풀어 쓴 답 0.
   없어야 하는 것: 해결 로직 · 정답 값 · 기대 결과 표 · 판정 절차 · 정답 방향 · 그대로 붙이면 끝나는 완성 프롬프트 · 강사 대본 · 결정 지점의 답을 적은 현장 메모 · README(출처 · 시점 · 맥락까지만). 작업 규칙은 보안 장치가 아니다.
   강사 참조(갈래별 답 · 기대 결과)는 `실습시작/reference/`에만, 학생용 완성본은 실습 ZIP 밖 별도 묶음이고 「계정이 없는 학생이 결과를 확인하는 묶음」으로만 안내한다.
5. **K-5. `START.md`는 열 칸이다.** — 판정: `grep -n '^## ' <랩 폴더>/START.md`에 열 칸이 다 있다.
   ① 목표 ② 출발 상태 ③ 학생이 구현할 범위 ④ 학생이 정할 것(K-3 결정 지점, 갈래 2개 이상마다 실제로 돌린 강사 참조 답이 `reference/`에 있음) ⑤ 이번 범위 밖 ⑥ 확인할 사례의 종류 ⑦ 실행 명령 ⑧ 완료 판정 원칙 ⑨ 바뀐 파일 확인(원자료 보존 · 요청 밖 파일) ⑩ 저장 · 다음 실습.
   힌트는 완성 프롬프트가 아니라 단계마다 다섯 요소(목적 · 입력 · 지킬 것 · 결과의 꼴 · 확인 방법, 값은 학생이 원자료에서 정함)다.
6. **K-6. 작업 규칙 열 줄을 두 도구 자리에 같게 둔다.** — 판정: `AGENTS.md` · `.github/copilot-instructions.md`(있으면 `CLAUDE.md`) 본문 diff 0, 장난감 시험에서 Codex의 답이 ⑩ 꼴.
   ① 원자료 보존 ② 새 결과는 `결과/` ③ 원자료에 없는 값 만들지 않기 ④ 미확인 · 값 없음 · 0 구별 ⑤ 무관한 기능 0 ⑥ 별도 랩 DB만 ⑦ 키 기록 0 ⑧ 「정할 것」은 추천 · 권장 없이 묻고, 학생이 선택과 근거를 말할 때까지 그 결과를 만들지 않음(「권장안대로」 「알아서」는 선택이 아님, 끝까지 못 들으면 미결) ⑨ 「제공 빈 틀」 표시 ⑩ 한 번에 가이드 한 단계 — 통째 요청에는 결과 · 바뀐 파일 0으로 「안 만든 까닭 한 줄 + 지금 단계 번호 · 이름 + 빠진 힌트 요소마다 질문 한 줄」만 돌려보내고, 예시 답 · 대신 쓴 프롬프트 0.
7. **K-7. 제공물은 실제 업무 자료 꼴이고 결과 자리는 빈 틀이다.** — 판정: `verify_packages.py` 통과, `grep -c -E '^(OPENAI_BASE_URL|LLM_API_KEY|LLM_MODEL)=$' <랩 폴더>/.env.example` = 3(모델을 부르는 랩), `ls <랩 폴더>/결과/`에 README와 빈 틀뿐.
   `입력/` = 앞 단계 강사 검증 판(연결 랩만, 이번 답 0) · `자료/` = 원문 · CSV · 현장 메모 그대로(함정 유지, 정답에 맞춘 값 · 정리본 0, 출처 · 시점 표기, 생성한 가상 자료는 파일 첫머리 한 곳에만 가상 사례 표시) · `결과/` = README + 열 이름 틀(계약은 형식 · 의미만, 정답 행 · 판정 절차 0) · 검사기(`check.py`) = ID · 끝점 · 중복 구조 검사만 하고 「의미와 질문별 답은 원자료와 따로 대조」를 출력.
   계약이 사실표 「두 설계 원칙」을 어기지 않는다(계속 바뀌는 값을 그래프에 두기 · 설비 · 납기 결정을 에이전트가 하기 0). 새 코드 이름은 `STRUCTURE.md`(영어 `snake_case`, 하는 일로 짓기, 설명 글은 한국어).
8. **K-8. 실제로 격리하고, 모델은 실제로 부른다.** — 판정: `grep -rln -E 'recorded/|replay|재생 모드' <랩 폴더>` · `find <랩 폴더> -name 'replies*.json'` 0(학생 실행이 남긴 자기 호출 기록은 해당 없음).
   그래프 DB는 `lab_db.py`(폴더마다 새 컨테이너 `neo4j:5.26-community`, 127.0.0.1 자동 포트, `랩_연결.json` ID와 라벨 `hyd.practice.id`가 같을 때만 재사용) — 포털 DB 주소 · 계정 0. 가드레일이 막는 것은 포털 DB · 전체 삭제 · 키 · 원자료 덮어쓰기뿐이고 외부 MCP · 자기 Notion은 막지 않는다. 랩 결과가 포털 에이전트에 자동 연동된다고 쓰지 않는다.
9. **K-9. 랩 하나만 받아 앞 랩 없이 시작하고, 저장 · 다시 열기로 다음 랩에 잇는다.** — 판정: 새 시험 폴더에서 그 ZIP만 받아 시작되고, `test_launcher.py` 통과 + 학생 파일을 고친 뒤 「이전 작업 열기」가 덮지 않고 「새 시작」이 새 폴더를 쓴다.
   자기 앞 결과 가져오기는 선택이다(판본 · 계약 확인, 별도 보관, 덮어쓰기 0). 다음 랩의 `입력/`이 이 랩 `결과/` 계약을 받는다. 자동 복구 약속 · 학생 Git 설정 · commit 요구 0. 수정본을 반영하는 랩은 반영 뒤 개수 · 값을 원자료와 다시 세는 확인 사례가 `START.md` ⑥과 가이드에 있다.
10. **K-10. 두 과정의 차이는 아래 영역의 결과물 모양에만 있다.** — 판정: 두 과정 랩의 `결과/` 계약 · 완료 조건을 아래 칸과 견준다, `diff -rq workspace/강의제작/산출물/통합반/실습/01회차/랩 workspace/강의제작/산출물/실전반/실습/01회차/랩` 0(1회차 공통).
    온라인 회차 통합/실전 — 모델 설계 · 적재 · 조회(2/2): 설비 · 센서 · 공용 부품 모델 + 별도 랩 DB 조회 / + 공급 조건 포함 부품 활용 조회(사용 설비 · 공급 근거). 절차 · 판단(3/2~3): 절차 · 금지 · 완료 조건과 결정표, 후보 비교 / + 후보별 이유 · 출처 · 추가 확인의 조치 검토 결과. 문서 지식화(4/3): 추출 → 출처 포함 후보 → 사람 검토 → 별도 DB 적재 / + 준비 · 금지 · 완료 조건의 작업 확인 카드.
    기본 에이전트(5/4): 원인 · 점검 계획 에이전트 / + 대상 · 관측 시각 · 이유 · 확인 항목의 점검 요청. 스킬 · 자기 자료(6/4): 회의 후속 작업, 자기 노트 퀴즈 / + 회의 · 점검 · 변경 근거의 다음 협의 안건. 외부 · 직접 만든 도구(6/4): 공통 한 랩(외부 MCP 연결 + 서버 골격에 조회 함수). 질문 · 재개 · 명세 · 검증(7~8/5): 부족한 정보만 묻고 재개, 작성 · 검토 역할, 긴급 표시 명세 · 구현, 회귀 검사 / + 같은 점검 요청으로 명세 · 검증. 통합반만: 다른 활용(5 — 품질 접수, 센서 도표), 자료 통합(8 — 로컬 인수인계).
11. **K-11. 오프라인은 온라인 랩 묶음을 그대로 받는다.** — 판정: 오프라인 회 가이드 · 묶음 목록을 대응 온라인 회차 랩과 견줘 새 과제 · 전용 묶음 0(예외: 1회 `01일차_오프라인_모델과질문` · `오프라인_가이드.html` · `오프라인1_가이드.zip`).
    대응: 통합 1~6회 = 온라인 1~6, 7회 = 7 + 8, 8 · 9 · 10회 = 9 · 10 · 11 / 실전 1~3회 = 1~3, 4 · 5회 = 4회차 스킬 앞 · 뒤, 6~9회 = 5~8. 한 회에 다 안 들어가면 뒤 랩부터 「빨리 끝나면 해 볼 것」.
    Notion 학습노트(학습노트 하나 → 주제 카드 → 자유 내용, 분류 · 별도 DB 강제 0): 1회 준비 → 통합 6회 퀴즈 · 10회 정리, 실전 5회 협의 안건 · 9회 기록. 접속 · MCP가 안 되면 같은 노트를 파일로 두고 파일 · Git · 시간 MCP로 같은 단계.
12. **K-12. 코드를 몰라도, 개인 GPT 무료 계정으로 끝까지 간다.** — 판정: 가이드 단계 · 리허설 기록에 코드 해설이 있어야 넘어가는 단계 · 유료 기능 단계 0, 학생용 완성본을 새 폴더에서 실행하면 영상 끝과 같은 결과.
    학생이 판단하는 곳은 요구를 내 말로 정하기 · 결과를 원자료와 대조 · 다른 입력으로 검증이다. 만드는 데 필요한 이론은 그 단계에서 다시 푼다.
13. **K-13. 학생 문장은 한 대상 한 이름, 회는 과정의 말로.** — 판정: 온라인 랩 `grep -rn -E '[0-9]+회([^차]|$)|[0-9]+일차|첫날' <랩 폴더>`, 오프라인 랩 `grep -rn -E '[0-9]+회차|[0-9]+일차' <랩 폴더>` — 폴더 이름 말고 0. `grep -rn -E 'SDD|BDD|명세 주도|행동 주도' <앞 회차 랩>` 0(통합 7회차 · 실전 5회차 / 오프라인 통합 7회 · 실전 6회부터).
    한 대상을 두 이름(「실습용 예제 DB」/「별도 랩 DB」), 한 이름에 두 대상 0. 식별자 · 속성 키는 문장에서 뜻으로, 그대로는 자료 · 명령 · 복사 블록에만. 줄인 랩 이름 대신 하는 일로.
14. **K-14. 랩 완성은 네 실행 기록이 모두 `확인됨`일 때다.** — 판정: 작업 폴더 `기록.md`에 넷 각각의 명령 · 출력 위치 · 판본 해시.
    ① 학생 경로 리허설 1회(학생과 같은 입력 · 폴더 · 명령, Codex + 강의 중계 `coding`) ② 검사기가 일부러 망가뜨린 입력(ID 중복 · 끝점 없음 · 관계 방향)을 잡음 ③ 강사 참조 갈래별 실행 ④ 받기 시험(시작 도구 → 다운로드 → 새 폴더에 풀기 → VS Code 열기 · 신뢰 → 가이드대로 실행 → 저장 → 다시 열기, 학교 PC 초기화 뒤와 개인 환경 구별). 넷 중 하나라도 `미확인`이면 완료가 아니다.
15. **K-15. 본 것만 쓰고, 영상 · 가이드에 실제로 돌린 것을 넘긴다.** — 판정: `grep -rn '예상과 다르면' <랩 폴더>` 0, `START.md` · 결과 README의 결과 문장마다 리허설 · 실행 기록이 있다.
    아직 안 나온 AI 응답 · 실행 결과(추천안 이름 · 점수 · 순위) 0 — 관찰 항목과 판단 조건만. AI가 처음에 맞혔으면 고의 오류 · 재시도 0, 막혀 참조본으로 바꾼 곳은 짧게 밝힌다. 이미 만든 영상이 있으면 랩 · `START.md`가 그 영상의 실제 입력 · 순서 · 결과와 같다.
    넘길 것 — 영상: 돌려 본 시작본, 단계마다 AI에게 묻고 정하는 순서, 결과 화면, 결정 지점과 확인 사례, 그 자리에서 다시 풀 이론, 학생용 완성본. 가이드: 단계 · 단계마다 정하거나 물을 것 · 힌트 · 명령 · 확인 조건 · 저장 위치(학생 폴더에 있는 것만, 키 · 접속값 0) · 네이티브 VS Code 캡처 목록(다운로드 · 압축 해제 · 폴더 열기 · 신뢰 창).

## 길
1. 행 뽑기 — 공통 「행 뽑기」로 그 회차와 앞뒤를 뽑아 대조표(K-1)를 작업 폴더 `스펙.md`에 쓴다.
2. 앞과 잇기 — 앞 이론 덱의 실습 설명 장 · 앞 포털 실습 가이드에서 연결점 한 줄을 정해 `START.md` 첫머리 · 가이드 첫 화면 · 영상 여는 말에 같게 쓴다.
3. 과제 설계 → 구성안 사용자 확인 1회 — 보여 줄 것: 배정 · 계획 분, 흐름, 대조표, `START.md` 첫머리 · 「학생이 정할 것」 · 끝 발췌, 결정 지점과 갈래.
4. 생성 — 생성기를 고치고 그 랩 하나만 만든다: `python workspace/강의제작/제작도구/실습시작/<생성기>`(어느 랩이 어느 생성기인지는 `실습시작/README.md` 「생성」 표). 폴더만 고쳤으면 `python …/실습시작/lab_package.py <랩 폴더> --version <새 판>`, `START.md` 랩은 `python workspace/강의제작/제작도구/온라인/labs/online/start_guides/build.py <랩 폴더>`. 산출물 HTML · ZIP을 손으로 고치지 않는다.
5. 강사 참조 — 2회차 실습3 · 4 `python …/실습시작/verify_reference.py`, 조치 판단 네 랩 `HYD_MAIN_ROOT=<main> python …/실습시작/reference/session3/run_reference.py`, 문서 지식 네 랩 `python …/실습시작/reference/session3_docs/run_reference.py`. 「불일치」로 멈추면 결과를 맞추지 말고 원인을 고친다. 검사기 고의 손상도 이 실행이 기록한다(2회차는 `reference/session2_check_trials.py`).
6. 장난감 시험(유료) — `python …/실습시작/reference/ai_toy_test.py <학생 ZIP> --tool codex|claude --scenario two_turn|one_turn --out 작업/검사/<새 폴더>` 네 번, 모델을 부르는 랩은 `--lab-env <파일>`. 뚫리면 결정 지점 · 자료 · 작업 규칙을 고친 새 판으로만 다시 돈다.
7. 학생 경로 리허설 — 웹 VS Code(`code serve-web`) + ego 탭, Codex + 중계 `coding`(값 · 길은 `촬영/vscode/촬영준비.md` 「길」 1~4). 준비 · 설명 · AI 대기 · 구현 · 확인 · 막힘 시간을 나눠 기록한다.
8. 묶고 검사 — `python …/실습시작/build_launcher.py` → `python …/실습시작/verify_packages.py` → `python …/실습시작/test_launcher.py`.
9. 받기 시험(K-14 ④) — 기본 주소 `http://127.0.0.1:8765`. 공개 배포는 패키지 커밋을 먼저 올리고 그 커밋 raw 주소로 `build_launcher.py --base-url <주소>`, 커밋 · ZIP 해시를 함께 고정한다.
10. 넘기기 — K-15 목록을 영상 · 가이드 작업에 넘기고, 커밋은 `CLAUDE.md` 2절.
11. 고칠 때 — 바뀐 랩의 생성기 하나 → 바뀐 곳과 그 연결만 4~9를 다시(승인된 덱 화면 문구가 바뀌었으면 그 랩 `참고_교재_발췌.md`와 ZIP도). 같은 판본에서 통과한 리허설 · 강사 참조 · 장난감 시험은 다시 돌리지 않는다.

## 함정
- 작업 규칙이 「묻고 멈추기」만 하면 「START.md대로 다 해 줘」 → 「권장안대로 다 해 줘」 두 마디로 강사 참조 답이 값까지 나왔다 — ⑧ · ⑩의 돌려보내기가 있어야 한다.
- 현장 메모 · 자료 설명이 결정 지점의 답을 적어 두거나 결정 지점이 주 질문 밖에 있으면 장난감 시험이 뚫렸다.
- 수정본을 반영하던 학생 AI가 실제 센서 TS1을 지웠다(실전 2-4) — 반영 뒤 다시 세는 사례가 그래서 있다.
- 학생 AI는 실습 폴더 위 폴더의 `AGENTS.md` · `CLAUDE.md`(저장소 제작 규칙)도 읽는다 — 리허설 · 장난감 시험 폴더는 저장소 밖에 둔다.
- AI가 「정할 것」에 권장을 붙여 낸다 — 학생이 원문을 열어 자기 선택과 근거를 말하는 자리가 랩 흐름에 있어야 한다.
- 학교 PC가 초기화되면 폴더 신뢰가 풀려 VS Code가 제한 모드로 열리고 AI 채팅이 동작하지 않는다.
- `lab_db.py`의 「새로 만든 랩 DB라 비어 있습니다」는 오류가 아니라 컨테이너가 없어 새로 만든 것이다 — 적재부터 다시 실행한다.
- 생성기 중 일부는 돌리면 다른 랩까지 옛 판으로 되돌린다 — 돌리기 전에 `실습시작/README.md` 「생성」 표의 「지금」 칸을 본다.
