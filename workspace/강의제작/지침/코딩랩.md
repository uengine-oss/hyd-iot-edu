# 코딩 랩

새로 만들거나 다시 만드는 랩은 K-5~K-7의 새 구조(`README.md` · `data/` · `app/` · `output/` · `.lab_connection.json`)를 쓴다. 옛 구조(`START.md` · `입력/` · `결과/` · `랩_연결.json`) 랩의 목록은 `workspace/강의제작/제작도구/실습시작/README.md` 「생성」 표에 있고, 그 랩은 그 회차를 다시 만드는 작업에서 새 구조로 옮긴다. 옮기기 전까지 생성기와 검사기는 옛 구조도 받고, 옛 구조 랩의 가이드와 ZIP은 `python workspace/강의제작/제작도구/온라인/labs/online/start_guides/build.py <랩 폴더>`로 만든다(검사만 할 때는 `--check`). 이 문서의 이름은 모두 새 구조의 것이다. 같은 작업트리의 다른 담당 랩을 일괄 재생성하지 않는다.

## 반드시
1. **K-1. 랩의 범위는 실라버스 그 행의 VS Code 구간 하나다.** — 판정: 대조표를 읽는다. 대조표는 행 문장 원문마다 다루는 곳(가이드 단계, 자료, 확인 사례, 구현 파일), 확인 방법, 예상 분을 적은 표다. 빈칸이 없고 행에 없는 과제가 없어야 통과다.
   코딩 랩은 실라버스 구분 칸에 VS Code가 있는 행에만 있다. 프로세스 · 종합 회차(온라인 통합 9~11 · 실전 6~8회차, 오프라인 통합 8~10회 · 실전 7~9회)에는 코딩 랩이 없고, bpmn.io와 포털 도구 실습을 한다.
   기준은 실라버스의 칸(오프라인 50분, 온라인 배정 분)이고 같은 ZIP을 쓴다(K-11). 강사는 멈춰 설명하지 않고 행위와 함께 설명하며, 학생은 가이드를 훑어 읽으며 실습을 이어 간다. 그래서 사람 분은 「가이드 읽기(분당 500자, 300자 값은 참고)와 AI 대기 가운데 긴 쪽 + 손으로 쓰는 행 0.3분 + 근거 줄을 열어 보는 행 0.1분 + 명령 0.5분」으로 추정하고, 50분 칸의 설계에서는 추정 60분까지(포털과 한 칸이면 같은 비율) 받는다. 이 값은 계획에 쓰는 추정치다. K-14 ①에서 잰 시간은 AI 학생 역의 수행 시간으로 기록하고, 실제 학생이 참여한 수업에서 잰 경우에만 현장 실측으로 기록한다.
   랩을 설계할 때는 같은 회차의 VS Code 행 안에서 남는 시간을 다른 랩에 배분하고(랩 하나는 70분까지), 「배정 분 − 10분」 하한도 그 회차 VS Code 행의 합으로 본다(판단 자리마다 판단 시간 3분을 더한 값). 60분을 넘는 랩은 먼저 가치 없는 글과 손 몫을 덜고, 짧아진 랩은 일반 로직 제공 때문이면 그대로 둔다. 모자란 시간을 대기나 억지로 만든 실패, 꾸며 낸 학생 활동으로 채우지 않는다.
2. **K-2. 공통 C-8의 회차 안 순서대로 앞을 장부의 이름으로 받아 열고, 포털 없이 돈다.** — 판정: `README.md`의 목적과 가이드 첫 화면을 읽는다. 이번 랩이 받는 앞 활동은 `앞회차.py <과정> <NN>`이 찍는 앞 회차의 마친 활동, 「행 뽑기」로 뽑은 같은 회차의 앞 실습 행, 그 직전 실습이 실제로 남기는 결과(그 랩의 출력 계약, 도구 실습이면 그 가이드의 마지막 단계)에서 확인한다. 첫머리는 그렇게 확인한 실제 앞 활동과 이번 랩이 이어받는 개념을 장부의 이름으로 짚고, 이 랩이 줄기 단계(온톨로지 → 에이전트 → 프로세스) 가운데 어디인지 말해야 한다. 그리고 `grep -rn -E '다음|포털에서|앞 실습의' <랩 폴더>`로 후보를 모아 걸린 곳을 읽어 가른다. 실라버스 순서상 바로 다음 랩이 아닌 것의 예고, 포털 화면 설명, 학생이 하지 않은 조작이나 만들지 않은 결과를 전제한 문장(공통 C-8의 불통과)이 없어야 통과다.
3. **K-3. 문제는 현업 규모로 어렵고, 바이브 코딩 일곱 단계를 밟아야만 풀린다.** — 판정: 장난감 시험(학생 ZIP을 학생 역 AI — 학생처럼 ChatGPT 계정으로 로그인한 Codex와 `gpt-6-luna` — 에 주고 통째로 풀어 달라고 하는 유료 시험, 길 6)을 `two_turn`과 `one_turn`으로 두 번 돌린다. 어느 번에도 학생이 선택과 근거를 말하지 않았는데 AI가 결정 지점을 스스로 정해 끝까지 결과를 낸 적이 없어야 통과다(낸 결과가 어느 갈래의 참조 답과 같은지는 따지지 않는다).
   자료는 공장 단위의 여러 출처(자산 대장, 수백 줄의 태그, 정비 이력, 품번이 변형된 부품 마스터, 판본이 다른 점검표)라서 눈으로는 맞출 수 없다. 주 질문의 경로 위에 원자료만으로는 하나로 정해지지 않는 결정 지점이 1개 이상 있고, 고른 갈래에 따라 역할(정비 · 구매 · 운전 · 품질)의 다음 행동이 바뀐다. 억지 함정, 고의 오류, 파일 수로 꾸민 난도, 해피패스, 구세주 데이터가 없어야 한다.
   일곱 단계: ① 파일을 바꾸지 않고 AI와 파악 ② 요구와 기대 답을 내 말로 정리 ③ 계획 검토 ④ 작게 구현 ⑤ 실행 결과를 원자료와 대조 ⑥ 고침 ⑦ 저장하고 다시 열어 확인.
   랩마다 아래 셋 중 기법 하나를 전면에 둔다. 설계는 탐색으로 함정을 찾고 사람이 결정한다. 구현은 한 기능씩 실제 DB로 확인한다. 판정은 기대 결과를 원문에서 먼저 적고 대조하며, AI 출력을 기대값으로 쓰지 않는다.
   난도는 내리지 않는다. 다만 AI가 일반 로직까지 만들면 그 시간이 칸을 넘기므로(「함정」), 학생이 AI와 구현하는 것은 어떻게 잡느냐에 따라 결과의 방향이 갈리는 판단뿐이다(예: 큰 문서를 나눌 단위, 무엇을 조건으로 뽑을지, 사내 기준과 제조사 지침 중 무엇을 따를지, 지식을 그래프에 어떤 모양으로 이을지 — 사람마다 결과가 달라도 되고 고른 것과 원문 근거를 적는다). 누가 해도 같은 결과가 나오는 일반 로직(공백 정리, 글자 방식, 파일 읽기, 모델 호출, 인용 줄 찾기, 계약 꼴 쓰기, 적재 실행, 내보내기, 검사)은 제공 코드로 준다. 가이드의 구현 · 판단 단계를 하나 깰 때마다 제공 도구가 다시 쓰는 정적 HTML 결과 화면(`output/result.html` — 순수 HTML, CSS, 작은 바닐라 JS, 파이썬 표준 라이브러리만, 서버 · 설치 · 인터넷 없음)에 방금 실행한 기능의 실제 결과가 보인다. 화면과 터미널에 전체 학습 단계, 완료율, 아직 하지 않은 단계의 상태를 나열하지 않는다. 실행에 필요한 입력 확인과 실제 오류·결과 검증은 유지한다.
4. **K-4. 학생 폴더에 답이 없다 — 학생의 AI는 폴더 전체를 읽는다.** — 판정: `grep -rn -E 'reference|제작용|강사|정답|해결 로직' <랩 폴더>`로 후보를 모아 걸린 곳을 읽어 가른다. 답이나 강사 자료의 위치를 알려 주는 문장이 없어야 한다(「막히면 강사에게」와 「정답이 하나로 정해져 있지 않다」는 해당 없음). 그리고 학생 폴더 전문을 강사 참조와 견줘 읽어, 답을 풀어 쓴 문장이 없어야 통과다.
   학생 폴더에 없어야 하는 것: 해결 로직(결정 지점의 갈래를 정하거나 판단 결과를 내는 로직 — K-3의 일반 로직은 해당 없음), 정답 값, 기대 결과 표, 판정 절차, 정답 방향, 그대로 붙여 넣으면 끝나는 완성 프롬프트, 강사 대본, 결정 지점의 답을 적은 현장 메모. 학생용 안내는 루트 README 하나이며 내용은 K-5를 따른다. 원자료의 출처·시점·맥락은 원자료의 메타데이터나 현장 메모에 둔다. 작업 규칙(K-6)은 답을 지키는 보안 장치가 아니다.
   강사 참조(갈래별 답과 기대 결과)는 `실습시작/reference/`에만 둔다. 학생이 막혔을 때 볼 단계별 정답은 가이드 P-3대로 랩 폴더 밖에만 둔다. 학생용 완성본은 실습 ZIP 밖의 별도 묶음이고, 계정이 없는 학생과 정답을 보고도 막힌 학생이 결과를 확인하는 묶음으로 안내한다.
5. **K-5. 학생용 안내는 루트 `README.md` 하나로 짧게 쓴다.** — 판정: README에 목적 한두 문장, K-7의 주요 폴더와 역할, 처음 실행할 명령만 있는지 읽는다. `START.md`, 별도 준비 안내, 폴더별 설명 README를 중복 배포하지 않는다. AI 작업 지시, 단계별 과제, 채점 절차, 긴 용어 해설은 README에 쓰지 않는다.
   목표·질문·구현 범위·결정 지점·범위 밖·확인 사례·완료 조건·저장은 생성기의 랩 정의와 바깥 가이드에 둔다. 단계 순서의 정본도 그 랩 정의와 가이드이며, 학생 코드가 학습 단계 번호나 완료 상태를 관리하지 않는다.
   결정 지점마다 결과가 달라지는 갈래를 둘 이상 설계하고, 갈래별 실행 근거를 학생 폴더 밖 `reference/`에 둔다. 학생이 새로 찾은 갈래는 K-14로 판단한다. 가이드 힌트는 목적, 입력, 지킬 것, 결과의 꼴, 확인 방법 다섯 요소를 담되 값과 선택은 원자료에서 정하게 한다.
6. **K-6. AI 지침은 학생 안내와 분리하고 필요한 작업 경계만 둔다.** — 판정: 이 과정에서 사용하는 Codex의 `AGENTS.md`만 두고, 학생용 README와 가이드가 긴 규칙 본문 읽기를 요구하지 않아야 한다. 처음 쓰는 자리에서는 AGENTS.md가 AI의 공통 작업 원칙임을 짧게 소개한다. CLAUDE.md·.claude/·Copilot 전용 설정은 새 구조에 넣지 않는다. AGENTS.md는 탐색기에 보이게 두고, VS Code 자체 설정과 실행 캐시만 숨길 수 있다. 숨김을 보안이나 정답 보호로 보지 않는다(K-4).
   AI에 필요한 경계는 원자료·제공 코드 보존, 요청한 기능만 구현, 원자료에 없는 값·관계·실행 결과를 만들지 않기, 미확인·값 없음·0 구별, 실제 실행과 변경 파일 보고, 별도 랩 DB만 사용, 키를 기록하지 않기다. 학생이 구현하는 파일과 자동 생성 결과의 경로를 구체적으로 적는다.
   결과가 갈리는 판단은 학생에게 근거와 선택을 물어 확인하며 AI가 대신 결정하지 않는다. 한 번에 요청받은 기능 범위에서 작업한다. 단계 번호, 진척률, 정해진 세 문장 응답 같은 형식을 강제하지 않는다. AI에게 전체 과제를 맡긴 시험에서도 사람의 판단이 필요한 곳을 임의로 결정해 완주하지 않는지 K-3으로 확인한다. 정답이 든 바깥 가이드는 AI의 입력으로 삼지 않는다.
7. **K-7. 프로젝트는 `data`, `app`, `output`의 역할로 정돈한다.** — 판정: `verify_packages.py`가 통과하고, 코드·원자료·생성 결과가 아래 역할에 맞게 분리되어야 한다. 폴더·데이터·코드 파일은 영어 이름으로, 화면과 설명은 한국어로 쓴다. 이름의 세부 규칙은 `STRUCTURE.md`를 따른다.
   `data/`: 읽기만 하는 원자료와 제공 입력이다. 앞 결과를 제공하는 랩은 `data/model/`처럼 실제 역할이 필요한 곳만 나눈다. 원자료의 함정과 출처·시점은 보존하고 정답에 맞춘 값이나 정리본을 넣지 않는다.
   `app/features/`: 학생이 AI와 구현할 핵심 기능과 판단 기준의 빈 틀이다. 코드, 기준 표, 학생이 적는 기대 답·선택 근거는 자동 생성 결과와 섞지 않는다. 별도 빈 폴더나 설명 파일로 분류 수를 늘리지 않는다.
   `app/ui/`: 실제 결과를 화면에 표시하는 제공 코드다. `app/utils/`: 파일 읽기·변환·DB 실행·구조 검사 등 일반 처리의 제공 코드다. 일반 코드를 핵심 구현 과제로 돌리지 않는다(K-3).
   루트 `run.py`는 학생의 실행 진입점이고 `README.md`는 K-5의 짧은 안내다. `output/`은 실행 때 생기는 결과만 받으며 처음 ZIP에는 완성 결과나 결과 화면을 넣지 않는다. AI 규칙과 도구 설정은 K-6에 따라 학생 설명과 분리한다.
   검사기는 ID, 끝점, 중복 같은 구조를 확인하고 의미와 질문별 답은 원자료와 따로 대조해야 함을 알린다. 계약은 사실표의 「두 설계 원칙」을 지킨다. 모델 호출 랩은 `.env.example`의 OPENAI_BASE_URL·LLM_API_KEY·LLM_MODEL 값을 비워 제공한다. 실제 `.env`와 DB 연결 파일은 배포하지 않는다.
8. **K-8. 격리는 실제로 하고, 모델은 실제로 부른다.** — 판정: `grep -rln -E 'recorded/|replay|재생 모드' <랩 폴더>`와 `find <랩 폴더> -name 'replies*.json'`로 찾은 미리 넣은 응답이 0곳이어야 한다. 학생 실행이 남긴 자기 호출 기록은 세지 않는다. 모델을 쓰는 랩은 같은 판본의 승인된 실행 기록에서 실제 호출의 입력과 응답 또는 그 응답이 반영된 결과를 확인해야 통과다. 저장 응답으로 실제 호출을 대신했으면 불통과다. 승인된 실행이나 확인할 기록이 없으면 미확인으로 둔다.
   그래프 DB는 `lab_db.py`가 만든다. 폴더마다 `neo4j:5.26-community` 컨테이너를 새로 띄우고 127.0.0.1의 포트를 자동으로 고르며, `.lab_connection.json`의 ID와 컨테이너 라벨 `hyd.practice.id`가 같을 때만 재사용한다. 포털 DB의 주소와 계정은 쓰지 않는다.
   가드레일이 막는 것은 포털 DB, 전체 삭제, 키를 코드 · 결과 · 기록에 적는 것, 원자료 덮어쓰기뿐이다. 외부 MCP와 학생 자신의 Notion은 막지 않는다. 랩 결과가 포털 에이전트에 자동으로 연동된다고 쓰지 않는다.
9. **K-9. 랩 하나만 받아 앞 랩 없이 시작하고, 저장하고 다시 열어 다음 랩으로 잇는다.** — 판정: 새 시험 폴더에 그 ZIP 하나만 풀어 시작되고, `verify_packages.py`가 통과해야 한다. 그리고 학생 파일을 고친 뒤 같은 랩 폴더를 VS Code로 다시 열었을 때 고친 파일이 그대로 있어야 통과다.
   자기 앞 랩의 결과를 가져오는 것은 선택이다. 가져올 때는 판본과 계약을 확인하고 별도로 보관하며 덮어쓰지 않는다. 다음 랩의 제공 입력은 이 랩 `output/`의 계약을 받는다.
   자동 복구를 약속하지 않고, 학생에게 Git 설정이나 commit을 요구하지 않는다. 수정본을 반영하는 랩에는 반영한 뒤 개수와 값을 원자료와 다시 세는 확인 사례가 랩 정의의 확인 사례와 가이드에 있어야 한다.
10. **K-10. 두 과정은 같은 랩을 하고, 실전반은 아래 영역에서 실제 역할이 쓰는 결과물을 하나 더 만든다(공통 C-4).** — 판정: 두 과정 랩의 출력 계약과 완료 조건을 아래 목록과 견줘 목록 밖 차이가 없어야 한다. 1회차 공통 랩을 두 과정에 반영하는 단계에서는 `diff -rq workspace/강의제작/산출물/통합반/실습/01회차/랩 workspace/강의제작/산출물/실전반/실습/01회차/랩`의 결과가 0줄이어야 통과다.
    읽는 법: 괄호 안은 온라인 회차(통합/실전)이고, 「/」 앞은 두 과정의 결과, 「/ +」 뒤는 실전반이 그 위에 더 만드는 결과다. 한 과정만 맡으면 다른 과정의 계약은 읽어서 대조하고, 그 과정의 보강과 ZIP 갱신은 인계한다.
    모델 설계 · 적재 · 조회(2/2): 설비 · 센서 · 공용 부품 모델과 별도 랩 DB 조회 / + 공급 조건을 포함한 부품 활용 조회(사용 설비, 공급 근거). 절차 · 판단(3/2~3): 절차, 금지, 완료 조건과 결정표, 후보 비교 / + 후보별 이유, 출처, 추가 확인을 담은 조치 검토 결과. 문서 지식화(4/3): 추출 → 출처를 포함한 후보 → 사람 검토 → 별도 DB 적재 / + 준비, 금지, 완료 조건을 담은 작업 확인 카드.
    기본 에이전트(5/4): 원인 · 점검 계획 에이전트 / + 대상, 관측 시각, 이유, 확인 항목을 담은 점검 요청. 스킬 · 자기 자료(6/4): 설비 점검 기록의 후속 정비 작업, 자기 노트 퀴즈 / + 틀린 문항을 원문 근거와 함께 자기 Notion 오답노트에 쓰기(학생이 승인한 항목만 쓰인다. 이 영역의 실전반 결과물은 실제 역할의 결과물이 아니라 사용자가 정한 자기 학습 결과물이다). 외부 · 직접 만든 도구(6/4): 두 과정 공통 한 랩(외부 MCP 연결, 그리고 서버 골격에 조회 함수 추가). 질문 · 재개 · 명세 · 검증(7~8/5): 부족한 정보만 묻고 재개, 작성 · 검토 역할, 긴급 표시의 명세와 구현, 회귀 검사 / + 같은 점검 요청으로 명세와 검증. 통합반에만 있는 것: 다른 활용(5회차 — 품질 접수, 센서 도표), 자료 통합(8회차 — 로컬 인수인계).
11. **K-11. 오프라인은 온라인 랩 묶음을 그대로 받는다.** — 판정: 오프라인 회의 가이드와 묶음 목록을 대응하는 온라인 회차 랩과 견줘, 새 과제와 오프라인 전용 묶음이 없어야 통과다. 예외는 1회의 `01일차_오프라인_모델과질문`, `오프라인_가이드.html`, `오프라인1_가이드.zip`이다.
    오프라인 회와 온라인 회차의 대응은 실라버스 L-11을 따른다. 한 회에 다 들어가지 않아 오프라인 칸을 받지 못한 뒤 랩은 「빨리 끝나면 해 볼 것」으로 돌린다.
    Notion 학습노트는 학습노트 하나 아래에 주제 카드를 두고 자유롭게 쓰며, 분류나 별도 DB를 강제하지 않는다. 쓰는 회는 실라버스 L-11이다. Notion 접속이나 MCP가 안 되면 같은 노트를 파일로 두고 파일 · Git · 시간 MCP로 같은 단계를 한다.
12. **K-12. 코드를 몰라도 개인 GPT 무료 계정으로 끝까지 간다.** — 판정: 가이드 단계와 리허설 기록을 읽어, 코드 해설이 있어야 넘어가는 단계와 유료 기능이 필요한 단계가 없어야 한다. 그리고 학생용 완성본을 새 폴더에서 실행한 결과가 영상 끝의 결과와 같아야 통과다.
    학생이 판단하는 곳은 K-3의 방향이 갈리는 판단과, 요구를 내 말로 정하기, 결과를 원자료와 대조하기, 다른 입력으로 검증하기다. 만드는 데 필요한 이론은 그 단계에서 앞 이론의 같은 이름과 같은 정의 한 줄로 다시 건다(공통 C-9).
13. **K-13. 학생이 읽는 문장은 이론과 같은 장부의 이름을 한 대상에 하나만 쓰고, 회는 그 과정의 말로 부른다.** — 판정: `앞회차.py <과정> <NN> --검사 <README.md · AI 지침 · 가이드 생성 원본>`가 낸 후보 줄을 공통 C-2 · C-9의 판정대로 읽어 가른다. 온라인 랩은 `grep -rn -E '[0-9]+회([^차]|$)|[0-9]+일차|첫날' <랩 폴더>`, 오프라인 랩은 `grep -rn -E '[0-9]+회차|[0-9]+일차' <랩 폴더>`를 돌려 걸린 곳 가운데 폴더 이름이 아닌 것이 없어야 한다. 그리고 배운 회차(실라버스 L-8)보다 앞 회차 랩에서 `grep -rn -E 'SDD|BDD|명세 주도|행동 주도' <앞 회차 랩>`의 결과가 0줄이어야 통과다.
    이름은 이론 덱과 같은 과정 용어 장부(공통 C-9)를 따르고, 랩에서 자주 갈리는 「실습용 예제 DB」와 「별도 랩 DB」처럼 장부에 없는 이름도 한 대상에 하나만 쓴다. 학생이 정할 것의 갈래 이름과 결과 칸 이름도 장부의 이름으로 짓는다. 식별자와 속성 키는 문장에서 뜻으로 풀어 쓰고, 그대로 쓰는 것은 자료, 명령, 복사 블록에서만 한다. 줄인 랩 이름 대신 그 랩이 하는 일로 부른다.
14. **K-14. 랩 완성은 네 실행 기록이 모두 `확인됨`일 때다.** — 판정: 작업 폴더 `기록.md`에 넷 각각의 명령, 출력 위치, 판본 해시가 있어야 한다. 넷 중 하나라도 `미확인`이면 완료가 아니다.
    ① 학생 경로 리허설 1회: 학생과 같은 입력, 폴더, 명령으로 K-3의 학생 역 AI를 써서 돈다. 결정 지점에서 원자료를 근거로 고른 값이 실행 결과에 실제로 반영되는지 확인한다. 구조 검사만 통과하거나 결과 화면이 열렸다는 기록으로 이 확인을 대신하지 않는다.
    ② 검사기가 일부러 망가뜨린 입력(ID 중복, 끝점 없음, 관계 방향)을 잡는지 본다. ③ 강사 참조를 갈래마다 실행한다. 학생의 선택이 참조와 다르면 공통 C-7에 따라 원자료, 입출력 계약, 그 선택으로 달라져야 할 실행 결과를 대조한다. 셋을 모두 충족하는 풀이도 인정한다.
    ④ 받기 시험(가이드 P-12).
15. **K-15. 본 것만 쓰고, 영상과 가이드 작업에는 실제로 돌린 것을 넘긴다.** — 판정: `grep -rn '예상과 다르면' <랩 폴더>`로 찾은 안내가 재현된 증상과 확인할 근거를 가리키는지 읽는다. 가이드와 결과 화면에 쓴 관측 결과는 리허설이나 실행 기록에서 확인되고, 학생이 확인할 조건과 구별되어야 통과다.
    아직 나오지 않은 AI 응답과 실행 결과(추천안 이름, 점수, 순위)는 쓰지 않고 관찰할 항목과 판단 조건만 쓴다. AI가 처음에 맞혔으면 고의 오류를 넣거나 다시 시도하지 않는다. 막혀서 참조본으로 바꾼 곳은 그렇다고 짧게 밝힌다. 이미 만든 영상이 있으면 랩과 가이드가 그 영상의 실제 입력, 순서, 결과와 같아야 한다.
    영상 작업에 넘길 것: 돌려 본 시작본, 단계마다 AI에게 묻고 정하는 순서, 결과 화면, 결정 지점과 확인 사례, 그 자리에서 다시 걸 이론의 이름과 정의 한 줄, 학생용 완성본.
    가이드 작업에 넘길 것: 단계, 단계마다 정하거나 물을 것, 힌트, 명령, 확인 조건, 리허설로 돌려 본 단계별 정답, 결과 화면에 보이는 것, 저장 위치(학생 폴더 안의 것, 키와 접속값은 빼고), 네이티브 VS Code 캡처 목록(다운로드, 압축 해제, 폴더 열기, 신뢰 창).

## 길
1. 행 뽑기 — 공통 「행 뽑기」 명령으로 그 회차 행과 앞뒤 행을 뽑고, 대조표(K-1)를 작업 폴더 `스펙.md`에 쓴다.
2. 앞과 잇기 — K-2의 세 자리에서 학생이 실제로 마친 앞 활동을 확인하고, 앞 이론의 실습 설명 장을 본 뒤 hyd-task 3-1의 이름표를 세운다. 직전 활동의 결과를 실제로 쓸 때만 그 결과와 이번 랩을 잇는다. 독립해서 시작하는 랩이면 이미 배운 개념과 제공 입력으로 풀 물음을 한 줄로 정한다. 연속 랩은 K-9의 기본 입력과 앞 랩 결과를 가져오는 선택 경로를 구분한다. 그 한 줄을 `README.md`의 목적, 가이드 첫 화면, 영상 여는 말에 똑같이 쓴다.
3. 과제 설계 → 구성안 사용자 확인 1회 — 사용자에게 보여 줄 것은 배정 분과 계획 분, 흐름, 대조표, 프로젝트 구조, 짧은 README, 가이드의 목표 · 판단 · 저장 부분, 결정 지점과 갈래다.
4. 생성 — 생성기를 고치고 그 랩 하나만 만든다: `python workspace/강의제작/제작도구/실습시작/<생성기>`. 어느 랩이 어느 생성기인지는 `실습시작/README.md` 「생성」 표에 있다. 폴더만 고쳤으면 `python …/실습시작/lab_package.py <랩 폴더> --version <새 판>`을 돌린다. 옛 구조 랩은 머리말의 명령으로 만든다. 산출물 HTML과 ZIP은 손으로 고치지 않는다.
5. 강사 참조 — 2회차 실습3 · 4는 `python …/실습시작/verify_reference.py`, 조치 판단 네 랩은 `HYD_MAIN_ROOT=<저장소 루트> python …/실습시작/reference/session3/run_reference.py`, 문서 지식 네 랩은 `python …/실습시작/reference/session3_docs/run_reference.py`를 돌린다. 「불일치」로 멈추면 결과를 맞추지 말고 원인을 고친다. 검사기 고의 손상(K-14 ②)도 이 실행이 기록한다(2회차는 `reference/session2_check_trials.py`).
6. 장난감 시험(유료) — `python …/실습시작/reference/ai_toy_test.py <학생 ZIP> --tool codex --codex-home <로그인해 둔 CODEX_HOME> --scenario two_turn|one_turn --out 작업/검사/<새 폴더>`를 두 번 돌린다(이 PC의 CODEX_HOME은 `D:/HYD-Practice/_codex_luna` — 그 폴더의 `config.toml`이 모델을 정하고, 로그인은 사용자가 `codex login`으로 한다, `--codex-bin`은 절대 경로). 모델을 부르는 랩은 `--lab-env <파일>`을 더한다. 뚫리면 결정 지점, 자료, 작업 규칙을 고친 새 판으로만 다시 돌린다. AI 지침과 핵심 판단의 입력·빈 틀이 바뀌지 않은 판에서는 다시 돌리지 않는다.
7. 학생 경로 리허설 — 리허설 전에 그 랩의 사람 분(K-1 식)과 칸 뜻 · 틀 꼴 멈춤 · 결과 화면을 먼저 점검해 넘는 곳을 고친다. 리허설은 강사 참조를 읽지 않은 새 학생 역에게 의뢰 틀 `제작도구/검사/의뢰/의뢰_학생역리허설.md`로 맡긴다(랩을 고친 작업자는 하지 않는다). 폴더는 `reference/prepare_rehearsal.py`가 풀고 가이드를 토글 뺀 본문과 단계별 토글로 나누며, AI 턴은 `reference/rehearsal_turn.sh`(K-3의 학생 역 AI), 모델 랩의 `.env`는 `reference/fill_lab_env.sh`로 채운다. 결과는 「같아야 함 · 달라도 맞음 · 틀림」으로 가르고, 지적은 원인만 고치고 리허설은 다시 돌리지 않는다. 폴더를 닫고 다시 여는 VS Code 화면은 이 길로 보지 못하므로 받기 시험(길 9)에서 본다.
8. 묶고 검사 — 생성기가 묶은 ZIP의 해시를 `package-index.json`에 등록하고(`lab_package.register`, 폴더만 고쳤으면 `lab_package.py <랩 폴더> --version <새 판>`) `python …/실습시작/verify_packages.py`를 돌린다.
9. 받기 시험(K-14 ④) — 패키지 커밋을 올린 뒤, 커밋 고정 raw 링크로 ZIP을 받아 새 시험 폴더에 풀고 가이드 P-12의 길대로 한다.
10. 검토와 넘기기 — 랩 하나를 다 만들 때마다 hyd-task 3대로 검토를 받고, 닫힌 랩의 K-15 목록을 영상 작업과 가이드 작업에 넘긴다.
11. 고칠 때 — `build_labs.py --lab`도 다른 과정의 강사 자료를 쓸 수 있으므로 hyd-task 5절의 출력 범위를 먼저 확인한다. 바뀐 랩의 생성기 하나만 고치고, 바뀐 곳과 그 연결에 대해서만 4~10을 다시 한다. 승인된 덱 화면 문구가 바뀌었으면 그 랩의 `참고_교재_발췌.md`와 ZIP도 다시 만든다. 같은 판본에서 통과한 리허설, 강사 참조, 장난감 시험은 다시 돌리지 않는다.

## 함정
- 과거에는 전체 수행 요청과 「권장안대로」에 AI가 사람의 판단을 대신해 답까지 만들었다. 단계 응답 형식을 강제하는 대신 K-6의 판단 확인과 K-3의 실제 시험으로 이 경계를 확인한다.
- 현장 메모나 자료 설명이 결정 지점의 답을 적어 두었거나 결정 지점이 주 질문 밖에 있으면, 장난감 시험이 뚫렸다.
- 수정본을 반영하던 학생 AI가 실제 센서 TS1을 지웠다(실전 2-4). 반영 뒤 다시 세는 확인 사례는 그래서 있다.
- 학생 AI는 실습 폴더 위 폴더의 `AGENTS.md`와 `CLAUDE.md`(저장소 제작 규칙)도 읽는다. 그래서 리허설과 장난감 시험 폴더는 저장소 밖에 둔다.
- AI가 「정할 것」에 권장을 붙여 낸다. 그래서 학생이 원문을 열어 자기 선택과 근거를 말하는 자리가 랩 흐름에 있어야 한다.
- `lab_db.py`가 내는 「새로 만든 랩 DB라 비어 있습니다」는 오류가 아니다. 컨테이너가 없어서 새로 만든 것이므로 적재부터 다시 실행한다.
- 학생이 일반 로직까지 AI와 만들게 했더니, AI가 코드를 만들고 돌리고 고치는 반복으로 랩 하나가 AI 학생 기준 86~100분 걸려 오프라인 칸을 넘었다(판단 자체는 시간을 거의 쓰지 않았다). 그래서 일반 로직은 제공하고 판단만 남긴다(K-3). 판단만 남겨도 학생이 손으로 채우는 행이 많으면 AI 실측은 10분대인데 사람 분은 칸을 넘었다(통합 2회 설계 랩 149행 → 70분). 그래서 학생은 판단 규칙과 규칙으로 정해지지 않는 행만 적고, 나머지 행은 제공 코드가 그 규칙대로 채운다.
- 틀의 칸 뜻이 틀 머리와 그 단계 「지킬 것」에 없으면 학생이 꼴을 짐작해 결과 화면 대조가 전부 「실제 없음」이 됐고, 같은 짝을 두 줄 쓰면 제공 코드가 조용히 뒤 줄만 남겼다. 그래서 칸마다 뜻 한 줄(값은 넣지 않음)을 두고, 틀 꼴이 어긋나면 실제 파일:줄을 짚고 멈춘다.
- Windows PowerShell 5.1은 BOM 없는 UTF-8 파일의 한글을 깨뜨려, 학생 AI가 START.md를 읽고 단계 이름을 지어냈다. 그래서 학생이 읽는 안내 문서(START.md · README · 입출력_계약)는 BOM을 붙여 쓰고(`lab_frame.write`), 원문 · CSV · JSON · 코드는 그대로 둔다. 같은 PowerShell은 명령 인자의 큰따옴표를 지워 JSON 목록을 넘길 수 없으므로, 값 여럿은 빈칸으로 이은 한 값으로 넘긴다.
- 강사 참조를 읽은 작업자가 학생 역 리허설을 하면 기대 답을 옮겨 적어 6분 만에 끝나 시간도, 가이드만으로 되는지도 판정하지 못했다. 그래서 리허설은 새 학생 역에게 맡긴다(길 7).
- 생성기 가운데 일부는 돌리면 다른 랩까지 옛 판으로 되돌린다. 돌리기 전에 `실습시작/README.md` 「생성」 표의 「지금」 칸을 본다.
