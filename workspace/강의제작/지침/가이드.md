# 가이드

## 반드시
1. **P-1. 가이드의 범위는 실라버스 그 실습 행이고, 종류부터 정한다.** — 판정: 대조표(행 문장 원문 | 가이드 단계 | 사진 · 화면 | 확인 방법 | 영상 구간 · 분)의 빈칸 0, 행에 없는 단계 0, 조작 없는 「정리 · 예상」 단계 0.
   종류는 둘이다: 도구 실습(포털 · ARROWS · Notion · Neo4j Browser · bpmn.io — 그 화면에서 보고 판단하며 조작)과 코딩 랩(VS Code에서 받은 폴더로 학생이 AI와 만듦). 서로의 장면 · 예고 · 제공물을 섞지 않는다.
2. **P-2. 도구 실습은 그 도구 화면에서 시작해 그 화면에서 끝난다.** — 판정: `grep -n -E 'VS Code|START\.md|결과/|다음 실습' <가이드>` 걸린 곳 0, `unzip -l <ZIP>`에 `START.md` · `결과/` · 학생 코드 파일 0.
   이론 재설명 · 끝의 정리 절 · 학생 코드 과제 · 다른 도구로 넘어가는 장면 0(그 도구 안의 내보내기 · 가져오기 · 다시 열기는 허용). 학생이 읽지 않아도 되는 칸은 「이 칸은 몰라도 됩니다, 볼 곳은 여기」로 짚는다.
   bpmn.io에서 그린 흐름은 기준 흐름과 비교하고, 포털에서는 등록된 흐름을 실행해 이력과 대조한다(「내 흐름 등록」으로 보이지 않음).
3. **P-3. 코딩 랩 가이드는 학생 폴더에 있는 것만 쓰고, 답을 주지 않는다 — 학생의 AI는 폴더 전체를 읽는다.** — 판정: `grep -n -E '정답|해결 로직|완성 프롬프트|강사|reference|자동 복구' <가이드>`에 걸린 문장 중 답 · 강사 자료 위치를 주는 것 0(「막히면 강사에게」는 해당 없음), 가이드를 강사 참조(`실습시작/reference/`)와 견줘 풀어 쓴 답 0.
   쓰는 것은 `START.md` · 입력 · 원자료 · 확인 사례 · 저장 위치뿐이다. 접속값 · 코드 해설 문단 0, 만드는 데 필요한 이론은 그 단계에서 다시 푼다. 학생용 완성본은 「실습 폴더와 따로 받는 묶음(계정이 없는 학생이 결과를 확인하는 용도)」으로만 안내한다.
4. **P-4. 코딩 랩 단계는 한 가지 일씩, 구현은 기능 하나씩, AI에게 보낼 글은 힌트다.** — 판정: 단계마다 할 일 하나 · 학생이 정하거나 물을 것 · 명령 · 성공 증거가 있고, 단계 번호 · 이름이 작업 규칙 ⑩이 부르는 것과 같다.
   힌트 = 다섯 요소(목적 · 입력 · 지킬 것 · 결과의 꼴 · 확인 방법, 값은 학생이 원자료에서) — 그대로 보내면 결과가 나오는 프롬프트 0, 기본 화면에 보이고 토글로 숨기지 않는다.
   첫 화면은 받은 폴더를 VS Code 탐색기 구조로, 끝은 저장 위치 · 다시 열어 볼 것 · 다음 랩에 넘길 판. GitHub Copilot · Codex 두 채팅 위치를 함께 보인다. `.env`는 `.env.example`을 복사해 강의에서 받은 세 줄을 붙여 넣을 뿐(손으로 정할 값 0)이고, 코드 받기 · Docker/DB · AI 로그인 · 접속 준비는 단계를 나눈다. 받기는 시작 도구가 하고, 노션 · HTML 링크로 PC 명령이 실행된다고 쓰지 않는다.
   있어야 하는 장면: 만든 결과를 다른 입력으로 검증, AI가 「정할 것」에 권장을 붙이면 원문을 열어 자기 선택과 근거를 말하기, 수정본 반영 뒤 개수를 원자료와 다시 세기, 앞 결과 가져오기는 선택(판본 확인 · 별도 보관).
5. **P-5. 여는 단락은 앞 단계를 이름으로 받고, 단계마다 다섯 칸이다.** — 판정: 단계마다 목적 · 행동(위치는 첫 문장에) · 입력 · 실제 화면 · 결과 확인(눈으로 판단할 성공 조건 한 문장)을 세고, 같은 조작의 앞 회차 짝보다 사진 · 확인 문장이 적은 뒤 회차 단계 0.
   여는 단락: 포털 실습은 앞 이론을, 코딩 랩은 앞 포털 실습(대응 기능이 없으면 바로 앞 이론)을 받고 줄기 단계(온톨로지 · 에이전트 · 프로세스)를 말한다. 첫 화면은 만들 결과와 순서(파일 나열 0).
   단계는 기능 · 결과 단위(결과 없는 클릭 하나짜리 0), 명령마다 확인할 출력과 다음 행동. 마지막 단계는 그 실습의 결과 확인으로 닫는다. 절 구조는 그 종류 본보기 그대로, 실습 하나에 HTML 하나.
6. **P-6. 본 것만 쓴다.** — 판정: 결과 문장 · 값 · 에러 문구마다 본 촬영 · 받기 시험 기록이 있고, `grep -n -E '예상과 다르면|다시 시도' <가이드>` 걸린 꾸민 분기 0, 포털 실습 가이드 `grep -n -E '재생|저장된 응답|캐시' <가이드>` 0.
   아직 안 나온 AI 응답 · 실행 결과(추천안 이름 · 점수 · 순위) 0 — 관찰 항목과 판단 조건만. AI 결과 화면은 「강사 화면의 예」, 성공은 원자료 대조 조건으로(AI 출력과 같아야 통과 0). 결과 단계마다 기대값과 관측값을 나누고 「다를 때」 길을 둔다.
   오류 안내는 재현된 증상과 조치만 그 단계 자리에, 막히면 AI에게 명령 · 오류 전문 · 화면을 보내게 잇는다. 막혀 참조본으로 바꾼 단계는 그렇다고 밝힌다. UI 이름은 사진 속 실제 글자(메뉴 · 버튼 굵게, 영어 화면과 다르면 괄호에 영어).
7. **P-7. 복사할 것은 글 블록으로 준다.** — 판정: 블록마다 복사 단추를 눌러 붙여 넣은 글 = 블록 본문, `grep -c '직접 치지 말고' <가이드>` = 1.
   프롬프트 · 질의 · 명령을 사진 속 글자로만 주지 않는다. 블록 종류(읽는 지침 · AI 힌트 · 터미널 명령 · 코드 수정 위치 · 붙여넣는 코드)를 색과 글자로 함께 표시하고, 복사는 본문만(줄 번호 · 셸 기호 0), 완료 메시지는 목적지에 맞게(「PowerShell에 붙여넣으세요」). 터미널 블록에 셸과 실행 폴더, 미리보기와 실제 적용은 블록을 나눈다.
   따라 하는 Cypher 질의는 `graph_guide.py`가 촬영 큐에서 블록으로 만든다 — 손으로 옮기지 않는다.
8. **P-8. 학생이 하는 조작마다 본 촬영 화면의 사진이 있다.** — 판정: 조작 동사(누르다 · 열다 · 붙여넣다 · 입력하다 · 저장하다) 수 = 사진 수, 사진마다 본 촬영 영상 프레임 또는 사진 근거 기록(`capture-provenance.json` · `학생가이드_사진근거.json`)과 대조된다.
   없는 화면 · 그린 터미널 출력 · 실패 화면을 정상으로 쓴 곳 0. 못 찍은 단계가 남으면 게시하지 않고 `기록.md`에 `미촬영`으로 적는다. 코딩 랩의 네이티브 장면(다운로드 · 압축 해제 · 폴더 열기 · 신뢰 창)은 네이티브 한국어 VS Code에서 따로 캡처한다(웹판 화면으로 대신 0).
   표시: 클릭 · 입력 · 확인할 요소마다 같은 색 · 두께의 빨간 사각형, 관찰 화면에도 볼 곳 하나, 겹친 상자 · 글자를 가린 표시 · 합성 0, 표시는 원본에서 다시 그린다. 사진 글자가 원래 크기에서 읽히고, 같은 화면 전체 · 확대 두 번 0. 그래프 사진은 연결 · 레이블 · 속성이 보이는 구도.
   가림은 키 · 토큰 · 글자로 보이는 비밀번호 · 전화번호 · 이메일(@부터 뒤)의 글자 자리만 — 이름 · PC 경로 · 대화 목록 · 프로필은 가리지 않는다.
9. **P-9. 학생이 읽는 말로, 진행에 필요한 것만 쓴다.** — 판정: `grep -n -E '일차|첫날' <가이드>`(폴더 이름 말고) 0, `grep -n -E '확인하세요|다르면' <가이드>`에 걸린 막연한 말 0, 이모지 0.
   회는 온라인 「N회차」 · 오프라인 「N회」. 문단은 행동 · 명령 · 화면 · 확인 · 오류 대처 · 그 단계의 상황과 까닭뿐(제작 이야기 · 다른 실습 소개 0). 식별자 · 속성 키는 뜻으로(그대로는 복사 블록 · 화면 값 자리만). 부정 지시에는 까닭 한 문장.
   통합반은 처음 쓰는 비전공자 기준으로 풀고, 실전반은 기본 조작을 한두 문장으로 줄이고 결과 해석 · 선택 이유를 쓴다. 처음 나오는 용어 · VS Code 조작(폴더 열기 · 탐색기 · 편집 · 저장 · 터미널 · AI 채팅)은 처음 단계에서 풀고(조작은 사진과), 앞당기기 · 뒤에서 되풀이 0. 「명세 주도 개발 · 행동 주도 개발」은 배운 회차부터(온라인 통합 7 · 실전 5회차, 오프라인 통합 7 · 실전 6회).
10. **P-10. 두 과정 · 오프라인은 온라인 실습을 같은 모양으로 받는다.** — 판정: 두 과정 1회차 가이드 · ZIP 내용 같음, 오프라인 회 가이드 목록 = 대응 온라인 회차 실습 목록.
    1회차는 두 과정 공통, 도구 실습은 두 과정이 같은 안내 · 캡처를 쓴다. 코딩 랩의 결과 확인 · 완료 기준은 그 과정 랩 `START.md` ⑧에서 온다.
    오프라인 대응: 통합 1~6회 = 온라인 1~6, 7회 = 7 + 8, 8 · 9 · 10회 = 9 · 10 · 11 / 실전 1~3회 = 1~3, 4 · 5회 = 4회차 스킬 앞 · 뒤, 6~9회 = 5~8. 흐름은 앞 학습 → 오늘의 목적 → 수행 · 결과 확인이고, 오프라인용 대본 · 영상 전제 · 복습 · 행정 절 0, 이론 없는 회(통합 9 · 10, 실전 8 · 9)는 설명을 실습 안에. 다 안 들어가는 랩만 「빨리 끝나면 해 볼 것」.
    첫 오프라인 회는 전체 구조 → 포털 경보 → 판단 → 승인 → 조치 → 결과 → 관계 모델 순서, 첫 그래프 실습에 Cypher 생성 · 조회 · 조건 · 수정 · 삭제 · 재조회 · 노드 속성이 다 있다. Notion: 1회 준비 → 통합 6회 퀴즈 · 10회 정리, 실전 5회 협의 안건 · 9회 기록, 접속 · MCP가 안 되면 같은 노트를 파일로 두고 파일 · Git · 시간 MCP. ProcessGPT 시연은 따라 하는 단계가 아니다.
11. **P-11. 마지막 종합 실습은 교대 인수인계 한 시나리오를 학생이 직접 한다.** — 판정: 그 회 가이드 단계를 아래 목록과 견줘 빠진 것 · 목록 밖 0(온라인 통합 11 · 실전 8회차, 오프라인 통합 10 · 실전 9회).
    보충 매뉴얼을 기존 스키마로 추출 · 원문 검토 · 추가 적재(검토 · 적재는 학생이 직접), 설비 · 정비 · ERP 조회로 미완료 · 주의 · 기록 불일치를 정리하는 에이전트 · 스킬 편집, 제공 교대 BPMN의 표시 이름 · 배치 · 에이전트 배정 · 별도 판본 등록, 조회 → 인계안 → 인계자 검토 → 인수자 확인/보완 → 완료를 포털 정의 · 시작 폼 · 역할에 연결해 실행(보완 분기 유지).
    인계 확인을 정비 완료 · 발주로 쓰지 않는다. 실전반은 인수자가 받아들일 근거와 보완 질문까지.
12. **P-12. 받기 시험은 실제 학생 경로로 한다.** — 판정: 작업 폴더 `기록.md`에 명령 · 화면 · 폴더 기록, 못 한 항목은 `미확인` = 불통과.
    코딩 랩: 노션 회차 페이지 또는 시작 도구 → 다운로드 → 새 시험 폴더에 풀기 → VS Code 열기 · 신뢰 → 가이드의 위치 · 명령대로 실행 → 저장 → 다시 열기(고친 학생 파일이 남고, 새로 시작은 다른 폴더). 도구 실습: 가이드의 조작대로 그 화면에서 결과까지.
    정상 · 경계 · 오류와 복구를 보고, GUI는 실제 화면 상태로 본다(CLI 로그로 대신 0). 복사 · 붙여넣기 일치, 단계 이동 · 직접 링크, 좁은 화면 가로 넘침 0. 학교 PC 초기화 뒤(폴더 신뢰 · `D:/HYD-Practice` 쓰기 권한)와 개인 환경을 나눠 적는다.
13. **P-13. ZIP은 랩 폴더와 바이트까지 같고, 학생이 읽을 것만 든다.** — 판정: `python workspace/강의제작/제작도구/실습시작/verify_packages.py` 통과(경로 집합 + 파일별 바이트), `unzip -l <ZIP> | grep -i -E '\.pdf|대본|예상시간|채울_화면'` 0, ZIP · 가이드에서 `grep -n -E 'localhost|C:/Users|확정|미수행|튜닝 가능|인계|요청문'` 0(교대 인수인계 실습의 「인계」는 해당 없음).
    한 실습 한 묶음(저장소 전체 · 여러 회차 0), 이전 ZIP의 루트 폴더 이름 유지. 가이드 HTML은 생성 원본을 고쳐 다시 만든다 — 손으로 고친 HTML 0. 새 가이드 이름은 `guide.html`, 기존 `가이드.html` · `안내.html`은 이름 유지.
14. **P-14. 게시는 커밋 고정 링크를 실제로 눌러 확인하고, 바꾼 것은 잇는 곳까지 같은 판이다.** — 판정: 두 과정 노션 회차 페이지를 열어 링크를 눌러 응답 200 · 크기 = 원본(API 응답만으로 대신 0), 바뀐 행 · 문구로 `git grep`해 옛 문장 0.
    가이드 · ZIP은 「가이드문서」 탭, 영상은 「🎬 강의 영상」 탭에 workspace 커밋 고정 raw 링크로(노션에 영상 업로드 0). 실라버스 행이 바뀌면 가이드 첫 화면 · 제목 · 단계 · 대조표 · `START.md` · ZIP을, 승인된 덱 화면 문구가 바뀌면 그 랩 `참고_교재_발췌.md` · ZIP을 함께, 두 과정이 함께 쓰는 내용이면 다른 과정도. 영상이 있으면 그 실제 진행이 기준이고 사소한 발화 차이로 가이드를 고치지 않는다. 사진 원본은 지우거나 덮지 않는다.

## 길
1. 행 뽑기 — 공통 「행 뽑기」로 그 회차 · 앞뒤를 뽑고, 종류를 정해 대조표(P-1)를 작업 폴더 `스펙.md`에 쓴다.
2. 본보기 통독 — 도구 실습은 자료의 본보기 둘. 코딩 랩은 사용자 확정 본보기가 없으니 P-4 · P-5가 기준이다.
3. 준비 — 단계 · 자료 링크 · 판정 조건만 쓴다. AI 응답 · 실행 결과 · 사진은 본 촬영 뒤에 넣는다(리허설 전에 사진 가이드를 완성하지 않는다).
4. 사진 — 본 촬영 영상에서 그 조작의 순간을 뽑는다. 같은 판의 기존 사진은 재사용, 모자란 장면만 같은 판으로 보충하고 원본 · 좌표 · 해시를 사진 근거 파일에 남긴다.
5. 생성 — 자료 「생성 원본」 그 도구의 명령. 코딩 랩은 그 랩 생성기 하나 → `build_launcher.py`.
6. 자동 검사 — `python workspace/강의제작/제작도구/실습시작/verify_packages.py <ZIP>`, `START.md` 랩은 `python workspace/강의제작/제작도구/온라인/labs/online/start_guides/build.py --check <랩 폴더>`, P-2 · P-3 · P-6 · P-7 · P-9 · P-13 판정 grep을 생성 원본과 HTML 둘 다에.
7. 통독 — 가이드를 브라우저에서 처음부터 이어 읽으며 앞 문장에 없는 대상을 받는 지시어 · 맞지 않는 접속사 · 같은 뜻 되풀이 · 답 없는 질문을 고친다.
8. 받기 시험(P-12) — Docker를 쓴 뒤에는 끄고 꺼졌는지 본다.
9. 커밋 → 게시 — `CLAUDE.md` 2절로 커밋하고, 사용자에게 물은 뒤 노션 두 과정 회차 페이지에 그 커밋 고정 링크를 넣고 눌러 본다(P-14).
10. 고칠 때 — 바뀐 실습의 생성 원본 하나를 고쳐 다시 만들고, 바뀐 단계 · 사진과 그 ZIP만 6 · 8을 다시. 같은 판에서 통과한 검사는 다시 돌리지 않는다.

## 함정
- 웹판 VS Code는 한국어 팩이 글자를 엉뚱하게 바꿔 영어로 둔다 — 학생 가이드 사진은 같은 결과 파일을 네이티브 한국어 VS Code에서 따로 찍는다.
- 학교 PC가 초기화되면 폴더 신뢰가 풀려 VS Code가 제한 모드로 열리고 AI 채팅이 동작하지 않는다 — 가이드의 그 단계 자리에 신뢰 · 재다운로드 길을 둔다.
- 리허설 화면 · 비슷한 다른 화면으로 만든 사진은 단계 · 버튼 위치 · 결과 값이 본 촬영과 어긋났다.
- 1회차 영상 04 · 06과 다른 판의 「ZIP · compose 확인표」 · 「근거 연결표」가 가이드에 남았다 — 가이드는 영상이 실제로 한 판을 따른다.
- 행이 바뀌었는데 그 행을 가리키는 가이드를 함께 고치지 않아 첫 화면이 지금 수업과 다른 말을 했다(옛 문장 예: 「포털에 문서를 새로 등록하거나 적재하지 않습니다」).
- `pack_arrows.py`는 폴더의 `채울_화면.md` · `예상시간.md` 때문에 늘 멈춘다(1회차 실습4 ZIP은 보관 — 다시 묶지 않음).
