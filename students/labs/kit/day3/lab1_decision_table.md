# 3-1 · 조치를 허용·경고·제외하는 결정표 만들기

## 만들 것

판단 기준을 표로 옮긴 `work/decision_table.json`과, 그 표로 입력 세 값을 평가하는 프로그램 `work/evaluate.py`.

## 왜 만드나

"어떻게 하는가"(작업 절차)와 "지금 해도 되는가"(판단 조건)는 다른 지식입니다. 판단 조건을 글로만 두면 사람마다 다르게 읽지만, 표와 함수로 만들면 같은 입력에는 언제나 같은 결과가 나옵니다. 이 랩에서는 글로 된 기준을 표로 옮기고 실행해 봅니다.

## 주어지는 자료

- `day3/decision_rules.md` — 입력 세 가지(출구 온도 · 팬 상태 · 부하), 조치 세 가지, 규칙 11개(F1~F4 · L1~L4 · C1~C3), 규칙이 겹칠 때의 순서
- `day3/inputs/normal.json` — 정상값 입력 하나

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: 판단 기준의 규칙을 결정표 파일로 옮기고, 그 표를 읽어 조치마다 허용 · 경고 · 제외를 내는 평가 프로그램을 만든다.
- **입력 자료**: `day3/decision_rules.md`.
- **결정표의 모양**: 규칙 하나가 한 줄이다. 규칙 번호는 기준 문서의 것을 그대로 쓴다.

```json
{
  "inputs": {"temp_c": {"label": "출구 온도", "type": "number"}, "fan_state": {"label": "팬 상태", "type": "enum", "values": ["정상", "약함", "정지"]}, "load_pct": {"label": "부하", "type": "number", "min": 0, "max": 100}},
  "priority": ["제외", "경고", "허용"],
  "actions": {"ACT-FAN-UP": "팬 속도 올리기"},
  "rules": [{"id": "F1", "action": "ACT-FAN-UP", "when": [{"input": "fan_state", "op": "==", "value": "정지"}], "result": "제외", "reason": "…"}]
}
```

- **꼭 지킬 것**
  - 규칙은 프로그램 안에 쓰지 않고 결정표 파일에서 읽는다(표를 고치면 결과가 바뀐다).
  - 한 조치에 규칙이 여러 개 맞으면 `priority` 순서로 더 조심스러운 결과를 따른다.
  - 맞는 규칙이 없거나 기준에 없는 값이 들어오면 결과를 지어내지 않고 오류로 끝낸다(종료 코드가 0이 아니다).
- **출력 모양**: `python work/evaluate.py --input <입력 파일>`이 화면에 JSON을 낸다.

```json
{"input": {"temp_c": 38, "fan_state": "정상", "load_pct": 50}, "actions": {"ACT-FAN-UP": {"result": "제외", "applied_rule": "F4", "matched_rules": ["F4"], "reason": "…"}}}
```

- **완료 기준**: 정상값 입력을 넣으면 조치 세 가지의 결과와 적용된 규칙이 나온다.

"보다 높다"와 "이하"를 Claude Code가 어떤 기호로 옮겼는지 결정표에서 직접 읽어 봅니다. 여기가 다음 랩에서 드러나는 자리입니다.

## 무엇이 나오면 성공

```
python -m labcheck 3-1
```

- 결정표에 규칙 11개가 모두 있고 조치 · 결과가 기준과 같다
- 조치 세 가지마다 결과 · 적용된 규칙 · 맞은 규칙 목록이 나온다
- 같은 입력을 두 번 넣으면 같은 결과가 나온다
