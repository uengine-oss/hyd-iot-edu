# 3-2 · 조건을 바꿔 규칙 결과가 달라지는지 확인하기

## 만들 것

새 파일은 없습니다. 앞 랩의 평가 프로그램에 준비된 입력 세 가지를 넣어 결과가 바뀌는 지점을 찾고, 결정표에 틀린 곳이 있으면 고칩니다.

## 왜 만드나

규칙을 눈으로 읽을 때는 맞아 보여도, 값을 넣어 돌려 보면 경계에서 어긋나는 일이 흔합니다. "45 ℃보다 높다"를 "45 ℃ 이상"으로 옮기면 45 ℃ 한 점에서만 결과가 달라지고, 눈으로는 찾기 어렵습니다. 규칙 두 개가 동시에 맞는 입력도 실행해 봐야 어느 쪽이 이기는지 드러납니다.

## 주어지는 자료

| 파일 | 어떤 경우 | 값 |
|---|---|---|
| `day3/inputs/normal.json` | 정상값 | 38 ℃ · 팬 정상 · 부하 50 % |
| `day3/inputs/just_above.json` | 임계값 바로 위 | 45.1 ℃ · 팬 정상 · 부하 50 % |
| `day3/inputs/overlap.json` | 서로 다른 두 조건이 겹침 | 62 ℃ · 팬 약함 · 부하 85 % |

## Claude Code에 전달할 요구사항의 뼈대

먼저 세 입력을 직접 넣어 봅니다.

```
python work/evaluate.py --input day3/inputs/just_above.json
```

돌리기 전에 `day3/decision_rules.md`를 보고 조치마다 결과를 손으로 먼저 적어 둡니다. 실행 결과와 다르면 그때 Claude Code에게 묻습니다.

- **목표**: 세 입력의 결과가 판단 기준과 같아지게 결정표(필요하면 평가 프로그램)를 고친다.
- **입력 자료**: 내가 손으로 적은 기대 결과와 실제 출력의 차이.
- **꼭 지킬 것**
  - 고치기 전에 어느 규칙이 왜 적용됐는지부터 설명하게 한다. 이유를 모르고 결과만 맞추지 않는다.
  - 프로그램에 "이 입력이면 이 결과"를 따로 써넣지 않는다. 고칠 곳은 규칙의 조건이다.
- **완료 기준**: 겹침 입력에서 핀 세척에 맞은 규칙이 두 개(C1 · C2) 보이고, 더 조심스러운 쪽이 적용된다.

같은 입력을 되풀이해 돌리는 것이 목적이 아닙니다. "왜 이 규칙이 적용됐는가"를 내 말로 설명할 수 있으면 됩니다.

## 무엇이 나오면 성공

```
python -m labcheck 3-2
```

- 준비된 세 입력의 결과와 적용된 규칙이 판단 기준과 같다
- 45 · 60 ℃, 30 · 80 %의 바로 아래와 위 값이 모두 기준대로 갈린다
- 기준에 없는 팬 상태나 빠진 입력은 결과를 내지 않고 오류로 끝난다

## 다음 랩에서 어떻게 쓰이나

여기서 확인한 결정표가 6일차 판단 MCP의 결과와 같아야 합니다. 경계가 어긋난 표를 그대로 두면, 뒤의 에이전트가 "해도 된다"고 잘못 답하게 됩니다.
