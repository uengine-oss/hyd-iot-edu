# 4-4 · 질문을 바꿔 답변 근거가 유지되는지 확인하기

## 만들 것

앞 랩의 `work/lookup.py`에 고장 이름으로 묻는 기능을 더하고, 근거가 없는 질문에는 "근거 없음"으로 답하게 만듭니다.

## 왜 만드나

같은 지식 구조라도 묻는 대상, 현재 값, 이어진 관계가 달라지면 답이 달라져야 합니다. 그리고 등록되지 않은 것을 물었을 때 그럴듯한 조치를 만들어 내면 안 됩니다. 조회 기능이 "모른다"를 정직하게 돌려줘야, 그 위에 올라가는 에이전트도 지어내지 않습니다.

## 주어지는 자료

- 앞 랩의 `work/lookup.py`, 연습용 그래프와 DB
- 넣어 볼 질문 세 가지
  - 과열 증상의 가능한 원인과 조치는?
  - 현재 냉각장치 온도에 해당하는 조치 기준은?
  - 소음의 원인은? (매뉴얼에 없는 고장)

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: 고장 이름으로 원인 · 조치를 찾는 명령을 더하고, 찾지 못한 경우의 답 모양을 정한다.
- **출력 모양**: `python work/lookup.py failure --asset-id CL-01 --name 과열`

```json
{"found": true, "asset_id": "CL-01", "failure_mode": "과열", "symptoms": [{"name": "…", "source": {}}], "causes": [{"name": "…", "source": {}}], "actions": [{"id": "…", "name": "…", "source": {}}]}
```

- **찾지 못했을 때**(두 명령 모두 같은 모양): 원인 · 조치 · 현재 값 칸을 채우지 않는다.

```json
{"found": false, "asset_id": "CL-01", "missing": ["무엇이 없는지"], "reason": "근거 없음: …"}
```

- **꼭 지킬 것**: 다음 세 경우를 구분해서 `missing`에 적는다.
  - 그래프에 없는 설비
  - 설비는 있지만 등록되지 않은 고장
  - 센서는 있지만 DB에 측정값이 없음
- **완료 기준**: 세 질문을 넣었을 때 앞의 둘은 그래프 관계 · 원문 위치 · DB 값이 맞게 나오고, 셋째는 근거 없음이 나온다.

질문을 바꿔 가며 넣어 봅니다. CL-01과 CL-02에 같은 질문을 하면 무엇이 달라지는지, `--kind "팬 회전수"`로 CL-02를 물으면 무엇이 나오는지 봅니다.

## 무엇이 나오면 성공

```
python -m labcheck 4-4
```

- 고장 이름으로 물은 원인과 조치가 그래프에 등록된 것과 같고 원문 위치가 있다
- 등록되지 않은 고장은 근거 없음으로 답한다
- 측정값이 없는 센서는 값이 없다고 답한다
- 없는 설비는 설비가 없다고 답한다
- 설비가 바뀌면 현재 값과 답이 달라진다
