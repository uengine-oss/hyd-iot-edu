# 6-3 · 지식 조회와 조치 판단을 두 MCP 도구로 잇기

## 만들 것

Neo4j MCP로 조치 후보를 찾고 판단 MCP로 그 조치를 지금 해도 되는지 판정받은 과정의 기록 `work/mcp/chain.json`.

## 왜 만드나

"과열에는 어떤 조치가 있는가"는 지식을 찾는 일이고, "그 조치를 지금 해도 되는가"는 조건을 계산하는 일입니다. 두 일은 서로 다른 도구가 맡습니다. 에이전트가 할 일은 첫 도구에서 읽은 결과를 둘째 도구의 입력에 **빠짐없이, 바꾸지 않고** 넘기는 것입니다. 하나라도 빠지거나 값이 달라지면 판정은 엉뚱한 것에 대한 판정이 됩니다.

## 주어지는 자료

- 앞 랩의 `.mcp.json`(서버 `lab-neo4j` · `lab-judge`)
- 판단 MCP의 도구
  - `describe_decision_table`: 받는 입력, 판정하는 조치, 규칙 전체
  - `evaluate_actions(temp_c, fan_state, load_pct, action_ids)`: 조치마다 허용 · 경고 · 제외와 적용된 규칙
- 질문: "CL-01이 지금 출구 온도 63 ℃, 팬 상태 약함, 부하 85 %다. 과열을 푸는 조치 가운데 지금 해도 되는 것은 무엇인가?"

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: 위 질문에 두 MCP 도구를 이어 써서 답한다.
- **순서**
  1. Neo4j MCP로 CL-01의 과열에 등록된 조치를 찾는다. 반환값에 조치 번호(`ACT-…`)와 원문 위치가 있어야 한다.
  2. 찾은 조치 번호 전부와 질문의 운전 조건 세 값을 판단 MCP의 `evaluate_actions`에 보낸다.
  3. 판정을 허용 · 경고 · 제외로 나눠 근거와 함께 답한다.
- **꼭 지킬 것**
  - 조치 번호를 기억으로 쓰지 않는다. 첫 도구의 반환값에서 가져온다.
  - 판정을 스스로 하지 않는다. 둘째 도구가 돌려준 결과만 쓴다.
- **기록**(`work/mcp/chain.json`): 입력과 반환값을 고치지 않고 적게 한다.

```json
{"question": "…",
 "condition": {"temp_c": 63, "fan_state": "약함", "load_pct": 85},
 "neo4j": {"query": "MATCH …", "rows": [{"action_id": "…"}]},
 "judge": {"input": {"temp_c": 63, "fan_state": "약함", "load_pct": 85, "action_ids": ["…"]}, "output": {}},
 "answer": {"allowed": ["ACT-…"], "warned": ["ACT-…"], "excluded": ["ACT-…"], "text": "사람이 읽는 답"}}
```

- **완료 기준**: 조치 세 개가 허용 · 경고 · 제외로 나뉘고, 각 판정의 규칙 번호와 매뉴얼 위치가 답에 있다.

콘솔 로그에서 두 도구의 입력과 출력을 찾아, 첫 도구의 `action_id`가 둘째 도구의 `action_ids`에 그대로 들어갔는지 눈으로 맞춰 봅니다. 판단 MCP가 받은 호출은 `docker compose logs lab-judge-mcp`에서도 볼 수 있습니다.

## 무엇이 나오면 성공

```
python -m labcheck 6-3
```

- 조치 후보 질의의 반환값이 그래프에 직접 돌린 결과, MCP로 다시 부른 결과와 같다
- 첫 도구가 찾은 조치 번호가 둘째 도구의 입력에 그대로 전달됐다
- 질문의 운전 조건이 둘째 도구의 입력에 그대로 전달됐다
- 기록된 판정이 판단 MCP를 같은 입력으로 다시 부른 결과와 같다
- 최종 답의 허용 · 경고 · 제외가 판정과 같다
