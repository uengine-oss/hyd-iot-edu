# 6-1 · 회의 메모를 정리하는 Skill 만들기

## 만들 것

회의 메모를 결정사항 · 담당자 · 할 일로 정리하는 Skill `.claude/skills/meeting-notes/SKILL.md`, 그 Skill로 정리한 결과 `work/meeting/memo1.result.json` · `memo2.result.json`.

## 왜 만드나

매번 같은 형식으로 정리해야 하는 일을 그때마다 길게 설명하면, 설명이 조금씩 달라지고 결과도 흔들립니다. 목표 · 순서 · 출력 칸을 한 번 적어 둔 작업 지침이 Skill입니다. 도구가 "실제로 찾아 주는 기능"이라면 Skill은 "일을 하는 방법"입니다. 한 번 만든 Skill이 형식이 다른 두 번째 문서에도 통하는지 확인합니다. 이 랩은 냉각장치와 관계없는 문서 업무입니다.

## 주어지는 자료

- `day6/memos/memo1.md` — 주간 품질 회의 메모(항목으로 적힘)
- `day6/memos/memo2.md` — 신입 교육 준비 회의 메모(줄글로 적힘)

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: 회의 메모를 언제나 같은 칸으로 정리하는 Skill을 만든다.
- **Skill에 적을 것**
  - 머리말: `name`(폴더 이름과 같게 `meeting-notes`)과 `description`(언제 이 Skill을 쓰는지)
  - 정리 순서: 무엇을 결정사항으로 보고 무엇을 할 일로 보는지, 담당자와 기한을 어떻게 찾는지
  - 필수 출력 칸
- **필수 출력 칸**(`work/meeting/<메모 이름>.result.json`)

```json
{"title": "…", "date": "YYYY-MM-DD", "decisions": ["…"], "todos": [{"task": "…", "owner": "…", "due": "YYYY-MM-DD"}]}
```

- **꼭 지킬 것**
  - 메모에 없는 내용은 만들지 않는다.
  - 정해진 것만 결정사항이다. 미룬 것은 결정사항이 아니다.
  - 기한에 해가 없으면 회의 날짜의 해를 쓴다.
- **완료 기준**: memo1에 적용한 결과를 내가 메모와 대조해 맞고, 같은 Skill을 고치지 않고 memo2에 적용해도 결정사항 · 담당자 · 할 일이 구분된다.

memo1 결과를 먼저 보고, 틀린 곳이 있으면 결과를 고치지 말고 Skill의 순서를 고칩니다. 그다음 memo2에 "이 메모도 정리해 줘"라고만 말해 봅니다. Skill이 스스로 선택되는지 봅니다.

## 무엇이 나오면 성공

```
python -m labcheck 6-1
```

- Skill 머리말의 이름과 설명이 있고, 필수 출력 칸이 적혀 있다
- memo1 · memo2: 날짜가 맞고, 결정사항이 빠짐없이 다른 것과 섞이지 않았다
- memo1 · memo2: 할 일마다 담당자와 기한이 메모와 같다

## 다음 랩에서 어떻게 쓰이나

네 번째 랩(6-4)에서 이 Skill에 "담당자가 없는 할 일은 따로 표시한다"는 새 요구를 넣습니다. 그때 오늘의 결과가 "예전 동작"의 기준이 되므로 결과 파일을 지우지 않습니다.
