# 5-2 · 조회 도구를 연결해 근거로 답하는 에이전트 만들기

## 만들 것

2일차와 4일차에 만든 조회 기능을 에이전트의 도구로 감싼 `work/agent/tools.py`, 도구를 쓰도록 고친 `work/agent/agent.py`, 그리고 도구를 써서 낸 답 `work/agent/answers/q1.json` · `q2.json`.

## 왜 만드나

AI가 기억으로 쓴 답과, 실제 조회 결과를 받아 쓴 답은 겉으로는 비슷해 보여도 믿을 수 있는 정도가 다릅니다. 도구를 붙이면 에이전트는 "질문 → 도구 호출 → 결과 반환 → 근거 있는 답"의 순서로 움직입니다. 이 과정에서 무엇을 보내고 무엇을 받았는지를 콘솔에서 읽을 수 있어야 답을 검증할 수 있습니다.

## 주어지는 자료

- `work/find_related.py`(2일차), `work/lookup.py`(4일차)
- `day5/questions.json`의 q1 · q2
- 앞 랩의 지침과 프로그램

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: 조회 기능 세 가지를 도구로 등록하고, 에이전트가 필요할 때 불러 그 결과로 답하게 한다.
- **도구 세 개**(이름은 이대로)

| 도구 | 입력 | 하는 일 |
|---|---|---|
| `get_related` | `asset_id` | 설비의 센서 · 부품 목록 |
| `get_current_value` | `asset_id`, `kind` | 현재 값과 그 값에 해당하는 기준 · 원인 · 조치 |
| `get_failure_knowledge` | `asset_id`, `failure_name` | 고장 하나의 증상 · 원인 · 조치 |

- **`tools.py`의 약속**
  - `TOOLS`: 도구마다 `name` · `description` · `input_schema`(필수 입력 포함)가 있는 목록.
  - `call_tool(name, arguments)`: 도구를 실행해 결과를 돌려준다. 성공하면 조회 결과에 `"ok": true`를 더한 값.
  - 부를 때마다 도구 이름 · 입력 · 반환값을 콘솔에 찍고, `work/agent/tool_calls.jsonl`에 `{"name", "input", "output"}` 한 줄을 남긴다.
- **에이전트**: `python work/agent/agent.py --question-id q1`이 도구를 써서 답하고 `work/agent/answers/q1.json`에 저장한다. 부른 도구와 반환값을 답의 `tool_calls`에 그대로 적는다.
- **꼭 지킬 것**
  - 답의 원인 · 조치 · 근거는 도구 반환값에 있는 것만 쓴다. 반환값을 고쳐 적지 않는다.
  - 설명(`description`)은 "언제 이 도구를 부르는가"가 드러나게 쓴다. 에이전트는 이 글을 보고 도구를 고른다.
- **완료 기준**: q1 · q2를 실행하면 콘솔에 도구 호출과 반환값이 보이고, 답의 근거가 그 반환값과 같다.

호출이 실패하거나 빈 결과가 나오면 코드를 직접 고치지 말고, 입력 형식과 기대 결과를 말로 다시 정해 주고 재실행합니다. 콘솔에서 "어떤 도구에 무엇을 보냈고 무엇을 받았는가"를 한 건 골라 소리 내어 읽어 봅니다.

## 무엇이 나오면 성공

```
python -m labcheck 5-2
```

- 도구 세 개가 설명 · 필수 입력과 함께 등록돼 있다
- 도구가 2일차 · 4일차 조회 기능, 연습용 DB의 값과 같은 결과를 돌려준다
- 부를 때마다 기록이 남는다
- q1 · q2: 도구를 불렀고, 기록된 반환값이 실제로 다시 불러 나온 값과 같다
- q1 · q2: 근거 · 원인 · 조치가 모두 도구 반환값에 있다

확인은 AI를 다시 부르지 않습니다. 저장된 답 파일을 도구의 실제 반환값과 대조합니다.

## 다음 랩에서 어떻게 쓰이나

다음 랩에서는 답이 없는 질문을 던집니다. 없는 부품, 값이 없는 센서, 없는 설비입니다. 도구가 "없다"고 돌려줄 때 에이전트가 지어내지 않고 보류하는지 봅니다.
