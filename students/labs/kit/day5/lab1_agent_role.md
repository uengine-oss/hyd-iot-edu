# 5-1 · 작은 에이전트의 역할·입력·출력 정의하기

## 만들 것

냉각장치 질문에 답하는 에이전트의 지침 `work/agent/system_prompt.md`, 그 지침으로 AI에게 질문을 보내는 프로그램 `work/agent/agent.py`, 그리고 도구 없이 낸 초안 답 `work/agent/answers/draft_q1.json`.

## 왜 만드나

답할 범위를 먼저 정하지 않으면 에이전트는 근거 없는 조치까지 자신 있게 제안합니다. 그래서 만들기 전에 네 가지를 글로 정합니다. 무엇을 위해 답하는가(목표), 무엇을 받는가(입력), 언제 무엇을 찾아보는가(도구 사용 조건), 답에 무엇을 담는가(출력 항목). 이 랩에서는 아직 도구를 붙이지 않고, 지침만 가진 에이전트가 어떤 초안을 내는지 봅니다.

## 주어지는 자료

- `day5/questions.json` — 테스트 질문 다섯 개(q1~q5). 이 랩에서는 q1만 씁니다
- `.env`의 `ANTHROPIC_API_KEY`(강사가 알려 준 값을 넣습니다)와 `LAB_AGENT_MODEL`
- 답의 출력 항목(아래)

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: "온도가 높을 때 관련 고장 원인과 근거를 설명하되 실제 제어는 하지 않는다"는 에이전트를 만든다.
- **지침에 적을 것**: 목표, 입력(질문 문장과 설비 번호), 도구를 쓰는 조건, 하지 않는 것(설비 제어, 근거 없는 추천), 출력 항목.
- **출력 항목**(답 하나가 JSON 파일 하나)

| 항목 | 뜻 |
|---|---|
| status | `답변` 또는 `보류` |
| answer | 사람이 읽는 답 |
| causes · actions | 원인 이름 목록 · 조치 이름 목록 |
| evidence | 근거 목록. 문서 근거는 `doc` · `section` · `line` · `quote`, 현재 값 근거는 `sensor_id` · `value` · `unit` · `measured_at` |
| missing | 부족한 정보 목록 |
| control | 언제나 `없음` |
| tool_calls | 부른 도구의 이름 · 입력 · 반환값 목록 |

- **프로그램**: `python work/agent/agent.py --question-id q1 --no-tools`가 질문 파일에서 q1을 읽어 AI에게 보내고, 답을 `work/agent/answers/draft_q1.json`에 저장한다. 키와 모델은 `labkit.settings`로 `.env`에서 읽는다. `question_id`와 `question`도 답 파일에 함께 적는다.
- **꼭 지킬 것**: 답은 자유로운 글이 아니라 위 항목이 모두 있는 JSON이어야 한다. `--no-tools`일 때 `tool_calls`는 빈 목록이다.
- **완료 기준**: q1의 초안 답 파일이 생긴다.

초안을 열어 `evidence`를 봅니다. 도구가 없는 에이전트가 근거 칸을 어떻게 채웠는지(비웠는지, 그럴듯하게 지어냈는지)를 적어 둡니다. 다음 랩의 답과 비교할 것입니다.

## 무엇이 나오면 성공

```
python -m labcheck 5-1
```

- 지침에 목표 · 입력 · 도구 사용 조건 · 출력 항목이 적혀 있고 출력 항목 이름이 모두 나온다
- 초안 답에 출력 항목이 모두 있고 `control`이 `없음`이다
- 초안은 도구 없이 낸 답이다

자동 확인은 지침과 답의 **모양**만 봅니다. 초안의 내용이 믿을 만한지는 내가 읽고 판단합니다.
