# 2-2 · 설비·부품·센서 자료를 그래프에 등록하기

## 만들 것

CSV 세 개를 읽어 연습용 그래프에 노드와 관계로 넣는 프로그램 `work/load_csv.py`.

## 왜 만드나

스키마는 틀이고, 틀에 실제 대상이 들어가면 인스턴스가 됩니다. 자료는 한 번만 들어오지 않습니다. 내일 같은 파일이 다시 오거나 한 줄만 고쳐져 올 수 있습니다. 넣을 때마다 무조건 새로 만들면(CREATE) 같은 설비가 둘, 셋으로 늘어나고, 이미 있으면 다시 쓰게 하면(MERGE) 하나로 유지됩니다. 이 차이를 직접 봅니다.

## 주어지는 자료

- `day2/data/assets.csv` — 설비 2줄
- `day2/data/components.csv` — 부품 7줄(어느 설비의 부품인지 포함)
- `day2/data/sensors.csv` — 센서 5줄(어느 설비에 붙었고 어느 부품을 지켜보는지 포함)
- 앞 랩의 `work/schema.json`

## Claude Code에 전달할 요구사항의 뼈대

- **목표**: CSV 세 개를 스키마대로 연습용 그래프에 넣는다.
- **입력 자료**: 위 CSV와 스키마 파일. CSV의 `asset_id` · `component_id` · `sensor_id`가 각 노드의 `id`가 되고, 나머지 열은 같은 이름의 속성이 된다.
- **꼭 지킬 것**
  - 관계 세 가지를 스키마의 방향대로 만든다(설비 → 부품, 설비 → 센서, 부품 → 센서).
  - 같은 자료를 다시 넣어도 노드와 관계가 늘어나지 않는다.
- **완료 기준**: `python work/load_csv.py`를 두 번 실행해도 설비 2 · 부품 7 · 센서 5 그대로다.

실행하기 전에 Claude Code가 만든 Cypher에서 CREATE와 MERGE가 어디에 쓰였는지 찾아보고, 왜 그렇게 썼는지 물어봅니다.

## 무엇이 나오면 성공

```
python -m labcheck 2-2
```

- 노드의 `id` · `name` · `tag`가 CSV와 같다
- 관계 세 가지가 CSV와 같고 방향이 맞다
- 같은 `id`의 노드, 같은 쌍의 관계가 두 번 없다
- 확인이 적재 프로그램을 한 번 더 실행해도 노드 · 관계 수가 그대로다

Neo4j Browser에서 `MATCH (n) RETURN n`을 실행해 설비 두 대와 그 부품 · 센서가 이어진 그림도 봅니다.
