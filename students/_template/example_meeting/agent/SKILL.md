# 분기 리뷰 회의 준비 (D2 절차)

회의 요청 한 건(request_id)에서 자료 · 안건 · 시간 후보를 준비한다. 추천 1개와 지는 안을 이유와 함께 낸다.
**승인 전에는 조회 · 계산 · 요약만 한다.** 일정 만들기 · 초대 · 메일은 하지 않는다 — 주관자가 승인한 뒤 시스템 task 가 한다.

## 절차
1. **지식 그래프 읽기** — `neo4j` 서버로 이 고객의 미결 안건(AgendaItem, status open)과 운영 규칙(Decision "시간 후보 고르기"의 Rule, 근거 절)을 읽는다. (D2 1 · 3)
2. **드라이브에서 자료 찾기** — `gdrive` 서버의 검색 · 읽기 도구로 지난 회의록과 계약 자료를 찾아 읽고 한 쪽으로 요약한다. (D2 1 · 2)
3. **업무 표 읽기** — `my-biz` 서버 `read_rows`로 `meeting_request`(마감 due_by), `attendee`(required = true 인 필수 참석자), `room`(좌석 수)을 읽는다. (D2 4)
4. **빈 시간 조회** — `gcal` 서버의 빈 시간(free/busy) 조회 도구로 필수 참석자 · 회의실의 빈 시간을 본다. (D2 4)
5. **규칙으로 빼고 순위 매기기** — 후보마다 아래 규칙을 적용한다. 뺀 안은 `losers` 에 규칙 번호와 수치로 이유를 쓴다. 남은 안에 점수를 매겨 `options` 를 순위대로 3개까지, 1위를 `recommended` 로 낸다. (D2 4)

`gdrive` · `gcal` 의 도구 이름은 강사가 등록한 구글 서버의 도구 목록(포털 도구(MCP) 화면)에서 확인해 이 문서에 적는다: 검색 ____ · 읽기 ____ · 빈 시간 ____.

## 규칙으로 빼기 (D1)
| 규칙 | 값 | 결과 |
|---|---|---|
| D1 1 필수 참석 | 필수 참석 가능 비율 < 1 | 제외 |
| D1 2 자료 공유 | 회의까지 남은 시간 < 48시간 | 제외 |
| D1 3 근무시간 | 09:00~18:00 밖 | 제외 |
| D1 4 회의실 | 고객 회의인데 좌석 < 6 | 제외 |
| D1 5 점심 | 12:00~13:00 에 걸침 | 제외 |
| D1 6 요청 마감 | due_by 를 넘김 | 감점 10 |

규칙을 지키는 안이 하나도 없으면 지어내지 말고 `options` 를 빈 목록으로, `losers` 에 모든 안과 이유를 내고 마지막 메시지에 "규칙을 지키는 시간이 없습니다"라고 쓴다.

## 결과 (output/result.json)
```json
{"proposal": {
  "options":   [{"slot": "…", "room": "…", "attendees_ok": "6/6", "prep_hours": 97, "score": 90, "reason": "…"}],
  "recommended": "<options[0].slot>",
  "losers":    [{"slot": "…", "why": "D1 2 위반: 자료 공유 25시간 전"}],
  "docs":      [{"title": "…", "link": "…"}],
  "agenda":    ["…"]
}}
```
칸 이름(`options[].slot · reason · score`, `losers`, `docs`)은 승인 카드가 읽는 약속이다. 바꾸지 않는다. 예: `proposal.example.json`.
