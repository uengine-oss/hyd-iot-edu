# (요령 이름) — T6 출발본

> 복사해서 `my-skill-name` 을 내 스킬 이름(영문 소문자 · 숫자 · 하이픈)으로 바꾼다. 포털 에이전트 화면 → 스킬 만들기에 이 글을 그대로 붙인다.
> 머리의 name 은 스킬 이름과 같아야 저장된다. 완성 예: `students/_template/example_meeting/agent/SKILL.md`.

(요청 한 건)에서 (무엇)을 준비한다. 추천 1개와 지는 안을 이유와 함께 낸다.
**승인 전에는 조회 · 계산 · 요약만 한다.** (쓰기 일: 일정 · 메일 · 표 기록)은 하지 않는다 — 승인 뒤 시스템 task 가 한다.

## 절차 (내 SOP 문서의 단계 5개)
1. **지식 그래프 읽기** — (서버) 로 ( 무엇 ) 을 읽는다. (근거: 내 문서 ___ 절)
2. **자료 찾기** — (서버 · 읽기 도구) 로 ( 무엇 ) 을 찾아 요약한다. (근거: ___)
3. **업무 표 읽기** — (내 표 서버) `read_rows` 로 (표 · 칸) 을 읽는다. (근거: ___)
4. **바뀌는 값 조회** — (서버 · 읽기 도구) 로 ( 무엇 ) 을 본다. (근거: ___)
5. **규칙으로 빼고 순위 매기기** — 아래 규칙을 후보마다 적용한다. 뺀 안은 `losers` 에, 남은 안은 점수 순으로 `options` 에, 1위를 `recommended` 에 낸다.

도구 이름은 포털 도구(MCP) 화면의 도구 목록에서 그대로 옮겨 적는다(지어내지 않는다).

## 규칙으로 빼기 (내 규칙 문서)
| 규칙(문서 · 절) | 값 | 결과(제외 · 감점 몇 점 · 경고) |
|---|---|---|
| | | |
| | | |
| | | |

남는 안이 없으면 지어내지 말고 `options` 를 빈 목록으로, `losers` 에 모든 안과 이유를 낸다.

## 결과 (output/result.json)
```json
{"proposal": {
  "options":   [{"slot": "후보 이름 또는 시각", "score": 0, "reason": "왜 이 점수인가(규칙 · 수치)"}],
  "recommended": "<options[0].slot>",
  "losers":    [{"slot": "뺀 후보", "why": "어느 규칙의 어떤 수치로 졌나"}],
  "docs":      [{"title": "근거 문서", "link": "주소"}]
}}
```
`options[].slot · reason · score`, `recommended`, `losers[].slot · why`, `docs[].title · link` 는 승인 카드가 읽는 칸 이름이다 — 이름을 바꾸지 않는다.
내 업무에 필요한 칸(예: room · prep_hours)은 options 항목에 더해도 된다.
