# T6 에이전트 만들기 — 포털 칸에 넣을 것

포털 → 에이전트 → 만들기. 아래 칸을 채운다. 완성 예: `example_meeting/agent/agent.json`.

| 포털 칸 | 넣을 것 | 예 (회의 준비) |
|---|---|---|
| 이름 | 하는 일이 보이는 이름 | 회의 준비 에이전트 |
| 목표 | 아래 목표 문장 틀 | (아래) |
| 역할 | 한 줄 | 고객사 분기 리뷰 회의 준비 담당 |
| 성격 · 말투 | 근거를 먼저 말한다, 모르면 지어내지 않는다 | (예시 파일) |
| 도구 | 포털에 **등록하고 검사 통과한** 서버 이름. 읽기 도구만 에이전트에 붙는다 | neo4j, my-biz, gdrive, gcal |
| 스킬 | T6 SKILL.md 로 만든 스킬 이름 | qbr-prep |

## 목표 문장 틀

> **(요청 한 건)** 에 대해 **(찾을 근거)** 를 찾아 정리하고, **(규칙 문서)** 를 지키는 **(후보)** **(몇)** 개를 순위와 함께 제안한다. 승인 전에는 조회 · 계산 · 요약만 한다.

예: 회의 요청 한 건에 대해 필요한 자료를 찾아 요약하고, 운영 규칙을 지키는 시간 후보 3개를 순위와 함께 제안한다. 승인 전에는 조회 · 계산 · 요약만 한다.

## 확인할 결과
- 포털 "에이전트에게 질문하기"로 질문 하나(예: "QBR-2026-Q4-01 시간 후보를 제안해 줘") → 도구 호출 기록과 규칙 번호 · 문서 절이 붙은 답.
- 스킬을 붙이기 전 · 후로 첫 도구 호출이 달라진다(붙인 뒤에는 절차 1단계 도구부터).
- 답에 지는 안과 그 이유(규칙 · 수치)가 있다.

## 막혔을 때
| 증상 | 할 일 |
|---|---|
| "등록되지 않은 도구 서버입니다" | 도구 칸의 이름이 포털 도구(MCP) 화면의 서버 이름과 같은지 본다 |
| "붙일 수 없는 도구 서버가 있습니다" | 그 서버의 연결 검사를 다시 누른다. 읽기 표시 없는 도구는 강사가 "읽기로 확인"해야 붙는다(T5) |
| "문서 머리의 name … 이 스킬 폴더 이름과 다릅니다" | SKILL.md 맨 위 `name:` 을 스킬 이름과 같게 |
| 답에 근거가 없다 · 지는 안이 없다 | SKILL.md 5단계와 결과 칸(losers)을 다시 본다 |
| 에이전트가 일정을 만들려 한다 | 쓰기 도구는 에이전트에 붙지 않는다. 목표 문장에 "승인 전에는 조회 · 계산 · 요약만"이 있는지 본다 |
