# T0 사례 카드 — 내 업무 하나 고르기

복사해서 7칸을 채우고 강사에게 보여 준다. 판정 5개에 모두 체크가 되면 단계 1로 간다.
아래쪽에 채운 예(고객사 분기 리뷰 회의 준비)가 있다. 사람 · 회사 이름은 가상으로 쓴다.

## 빈 카드

| # | 칸 | 내 답 |
|---|---|---|
| 1 | 무엇이 시작을 알리나 (요청 한 건 · 기한 도래 한 건) | |
| 2 | 에이전트가 답할 질문 | |
| 3 | 승인하는 사람 1명 (역할) | |
| 4 | 승인 뒤 시스템이 하는 쓰기 (일정 · 메일 · 표 한 줄) | |
| 5 | 시스템이 다시 읽어 확인할 것 | |
| 6 | 지는 대안 2개와 지는 이유 (규칙 · 비용 · 시간) | ① <br> ② |
| 7 | 미달 가지 1개 (응답 없음 · 마감 초과 · 기준 미달) | |

### 강사 판정
- [ ] 시작이 사건 하나다 — 한 건 = 처리 건 하나
- [ ] 대안이 둘 이상이고, 지는 안이 실제 이유(규칙 · 비용 · 시간)로 진다 (그냥 옮겨 적기 업무가 아니다)
- [ ] 승인 뒤 쓰기가 실제 시스템에 남고, 시스템이 그 결과를 다시 읽어 확인할 수 있다
- [ ] 미달 가지를 수업 중에 실제로 밟을 수 있다
- [ ] 개인정보 · 회사 기밀 문서를 쓰지 않는다 (필요하면 출발본 예시 문서로)

## 채운 예 — 고객사 분기 리뷰 회의 준비 (가상 회사 "가온상사")

| # | 칸 | 답 |
|---|---|---|
| 1 | 시작 | 회의 요청 한 건 접수 — 시작 폼 `request_id = QBR-2026-Q4-01` |
| 2 | 에이전트가 답할 질문 | "이 회의에 어떤 자료가 필요하고, 운영 규칙을 지키는 시간 · 회의실 후보 중 무엇을 추천하나?" |
| 3 | 승인하는 사람 | 회의 주관자(영업 담당) — 후보 중 하나를 골라 승인 |
| 4 | 승인 뒤 쓰기 | 구글 캘린더에 일정 만들기(참석자 · 회의실 · 자료 링크) |
| 5 | 시스템 확인 | 응답 마감 뒤 그 일정을 다시 읽어 필수 참석자 2명이 모두 수락했는지 |
| 6 | 지는 대안 | ① 내일 10시 — 가장 빠르지만 자료 공유 48시간 규칙(D1 2) 위반으로 제외 <br> ② 목 14시 — 6명 중 5명 가능하나 필수 참석자(고객 담당 임원) 불가(D1 1)로 제외 <br> (추천: 금 10시 6인실 B. 다음 주 화 15시는 모두 가능하지만 요청 마감을 넘겨 감점) |
| 7 | 미달 가지 | 필수 참석자가 초대를 거절하거나 응답하지 않음 → "미확정" 보고. 승인을 4시간 미루면 "승인 지연" 알림만 오고 일정은 만들어지지 않는다 |

### 강사 판정
- [x] 시작이 사건 하나다 — 회의 요청 한 건
- [x] 대안이 둘 이상이고 지는 안이 규칙 · 시간 이유로 진다
- [x] 승인 뒤 캘린더 일정이 남고, 시스템이 그 일정을 다시 읽어 응답을 확인한다
- [x] 미달 가지(거절 · 무응답)를 시험 계정으로 실제로 밟을 수 있다
- [x] 개인정보 없음 — 가상 회사 · 가상 인물 · example.com 메일
