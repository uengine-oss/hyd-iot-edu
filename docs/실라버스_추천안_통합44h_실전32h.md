## ① 과정 소개

유압 설비 세 대가 도는 가상 공장에서, 쿨러 · 펌프 · 팬 세 가지 고장이 났을 때 AI와 사람이 함께 원인을 찾고 조치를 골라 설비를 되살리기까지를 직접 해 보는 과정이다. 같은 흐름을 세 번 돌되 첫 바퀴는 전체를 따라가며 단계마다 무슨 일이 일어나는지 보고, 둘째 바퀴는 결과를 먼저 예측하고 맞춰 보고, 셋째 바퀴는 일부러 틀린 선택을 해서 공장이 어떻게 스스로를 지키는지 확인한다. 기술(메시지 통로, 지식 그래프, AI 도구 연결, 업무 흐름 그림 등)은 그 일을 하다 필요해지는 순간에 짧게 다룬다.

끝나면 수강생은 이렇게 할 수 있다.

1. 설비 경보 하나가 원인 찾기 → 조치 고르기 → 설비 명령 → 회복 확인 → 정비 요청으로 이어지는 한 바퀴를 화면으로 따라가며, 지금 누구(AI · 사람 · 시스템) 손에 있는지 말할 수 있다.
2. 매뉴얼과 회사 데이터 구조를 넣어 우리 공장 지식으로 만들고, 그 지식에서 "왜 이 조치인가"의 길을 직접 걸어 설명할 수 있다.
3. 내 PC의 AI 일꾼에게 공장 일을 맡기고, AI가 무엇을 읽고 판단했는지 기록으로 확인하며, AI가 묻는 질문에 사람으로서 답할 수 있다.
4. 원인과 1등 조치를 돌리기 전에 예측하고, 납기 · 품질 · 공급사 같은 회사 사정이 판단을 어떻게 뒤집는지 값을 바꿔 보여 줄 수 있다.
5. 틀린 선택(위험한 조작, 경보만 끄는 조치, 권한 없는 승인)이 어느 겹에서 막히는지 보이고, "경보가 꺼진 것"과 "설비가 나은 것"을 데이터로 구별할 수 있다.

### 단원 4. 지식 지도에서 "기름이 뜨겁다 → 왜 → 무엇을 할까 → 회사에 어떤 영향"의 길을 직접 걸어 보기

### 단원 5. AI가 원인을 찾고 조치 카드를 만들기까지 무엇을 읽었는지 확인하고, 1등 카드의 이유를 내 말로 설명해 보기

- 갈래: 에이전트
- 해 보는 것
  1. 쿨러 경보 하나의 AI 실행 기록을 단계별로 읽고 "단계 · 도구 · 출처 · 읽은 값" 표를 만든다(원인 진단 → 조치 후보 → 규정 검토 → 순위 · 카드).
  2. 경보가 열려 있을 때 조치 판단 규칙 화면의 순위와 AI 카드의 순위를 비교한다.
  3. 끝난 처리 건의 기록 화면에서 카드 점수표(회사 목표 지표 득실 · 예측 온도 · 감점 · 과거 같은 선택 비율)를 읽고 "왜 1등인가"를 두세 문장으로 쓴다.
  4. 후보 모으기 → 안 되는 후보 빼기 → 점수 매기기 → 1등 추천 → 사람 선택의 다섯 단계를 단원 1의 카드에 대어 본다.
- 알게 되는 것: 에이전트 = AI 모델 + 도구 + 정해진 절차. 좋은 조치는 설비 하나가 아니라 회사 목표까지 따져 정해진다.
- 쓰는 시나리오: 쿨러
- 이 안에서 자연스럽게 다루는 것: (LLM과 에이전트의 차이) (도구 호출 기록) (선행 · 후행 지표 21개) (AI가 설비에 직접 쓰지 못하는 이유)
- 대표 화면: [조치 판단 카드 — 추천 1등](../.evidence/a151-capture/05-조치판단카드-추천1등.png) · [근거 보기 — 왜 1등인지](../.evidence/a151-capture/06-근거보기-왜1등인지_표시-영문·내부기록.png)
- 필요 시간 근거: 시스템 안 기본 AI로 네 일 약 15~18초(**실측**). 선택 기한이 20배속에서 30초라 카드는 처리 건이 끝난 뒤 기록 화면에서 천천히 읽는다.

### 단원 6. 권한 있는 사람이 카드를 골라 설비를 움직이고, 정말 나았는지 확인한 뒤 정비 요청으로 끝내 보기

- 갈래: 처리 흐름·사람
- 해 보는 것

### 단원 12. 일부러 틀린 선택을 해 보며 공장이 여러 겹으로 스스로를 지키는 모습 확인하기

- 갈래: 시나리오(팬 바퀴 마무리, 안전)
- 해 보는 것

  2. 팬 경보 중 수동 조작으로 팬을 100 %로 쓴다(화면에 100 % 버튼이 없어 명령 한 줄로). 1초 만에 설비 제어기가 스스로 멈추는 것을 보고 예상과 비교한다. 이 처리 건의 선택은 두어 30초 뒤 상급자 확인으로 넘어가는 것도 본다.
  3. 펌프 누설에 "부하 70 %"를 고르기 전에 "새 예측 검토"의 예측 압력과 회복 기준 165를 비교해 결과를 예상하고, 골라서 경보는 꺼지지만 다시 지켜보기에서 실패해 책임자에게 넘어가는 것을 확인한다.
  4. 설비를 원격 수동으로 둔 채 쿨러 고장을 넣어, 쓸 수 있는 조치 카드가 규정상 모두 빠지고 과열로 설비가 멈추는 것을 본다.
  5. 세 장면을 "어느 겹이 막았나(설비 제어기 안전장치 / 다시 지켜보기 / 규정 · 운전 모드 검사)" 표로 정리하고, 단원 6의 권한 거절 · 시간 초과와 합친다. 설비는 결함 복구 → 보호 정지 해제 → 원격 자동으로 되돌린다.
- 알게 되는 것: 안전은 한 곳이 아니라 여러 층이 나눠 지킨다. 경보가 꺼져도 실패일 수 있다.
- 쓰는 시나리오: 팬 함정(HYD-03), 펌프 가림(HYD-02), 쿨러 원격 수동 과열 정지(HYD-01)
- 이 안에서 자연스럽게 다루는 것: (인터록) (가림과 회복의 차이) (운전 모드: 원격 자동 · 원격 수동 · 현장) (예측과 실측 비교)
- 대표 화면: [결함 시뮬레이션 — 수동 조작 · 보호 정지 해제 · 운전 모드](../.evidence/a141/scenario-1440.png)(팬 함정 · 가림 전용 장면은 어느 세트에도 없어 별도 촬영 필요)
- 필요 시간 근거: 팬 함정 1초 만에 정지, 가림은 명령 뒤 약 40초에 실패 판정, 원격 수동 과열 정지는 경보 뒤 약 56초(모두 **실측**). 펌프는 첫 판단 2분 대기가 생길 수 있다(**실측**, 단원 9). 원격 수동 장면 뒤에는 책임자 확인 일이 남아 정리가 필요하다.
- 기존 회차 문서: 21 · 22 · 02

### 단원 13. 납기 · 품질 · 공급사 사정을 바꿔 1등 조치가 뒤집히는 순간을 찾아보기

- 갈래: 시나리오(회사 사정 — 쿨러 · 펌프 다시 보기)
- 해 보는 것
  1. 쿨러 패턴으로 판단을 돌려 카드 순위 "전" 열을 적는다. 회사 DB에서 납기를 30시간 뒤로 미루고 다시 판단해 납기 점수가 0이 되며 순위가 바뀌는 것을 "후" 열에 적는다.
  2. 쿨러 경보가 열려 있는 동안 품질(고온 로트 · 클레임) 값을 바꿔 경고가 붙는 카드를 찾는다.
  3. 펌프 누설 중 공급사 승인을 끄면 "펌프 축 씰 교체"가 빠지고, 다시 켜면 돌아오는 것을 본다.
  4. 카드를 받은 뒤 납기를 바꾸고 옛 카드를 골라 거절 사유(바뀐 입력 이름)를 읽는다. 바꾼 값은 모두 되돌린다.
  5. (통합반) 계약 손실 · 재고 값만 바꿔 "계획 정지" 카드의 순위가 오르는지 직접 찾아본다(제작자 실측 예: 4위 → 2위).
- 알게 되는 것: 설비 값만 보면 틀리는 판단이 있다. 순위를 정하는 식도 데이터라서 프로그램 수정 없이 바뀐다. 승인은 "그때의 사실"에 묶여 있다.
- 쓰는 시나리오: 쿨러(납기 · 품질), 펌프(공급사)
- 이 안에서 자연스럽게 다루는 것: (MES · ERP · QMS · SCM 회사 시스템) (점수 식의 납기 · 품질 항과 상한) (승인 직전 재검사)
- 대표 화면: [승인과 실행 — 기업 시스템 현황](../.evidence/a141/process-1440.png)(기존 캡처) · [조치 판단 카드 — 점수와 순위](../.evidence/a151-capture/05-조치판단카드-추천1등.png)
- 필요 시간 근거: 값 바꾸고 다시 판단은 바로(**예상**). 옛 승인 거절 장면은 30초 선택 기한 안에 납기 변경과 선택을 이어서 해야 한다. "이 값이 바뀌면 순위가 뒤집힌다"를 화면이 미리 알려 주지 않으므로 값을 바꿔 보며 찾는 시간이 필요하다.
- 기존 회차 문서: 23

### 단원 14. 이 구조를 실제 회사 규모로 넓히면 무엇이 더 필요한지 그려 보고, 내 시나리오로 발표하기

- 갈래: 확장(설명 · 발표, 실행 실습 없음)
- 해 보는 것
  1. 수업에서 쓴 부품(처리 건 · 일꾼 · 도구 연결 · 규칙 · 지식 지도 · 화면)이 실제 제품(ProcessGPT)의 어느 부품에 해당하는지 대응표 1장을 만든다.
  2. "다음으로 가면" 설명을 듣고 확장 그림 1장을 그린다: 회사 DB가 여러 종류로 갈리면 필요한 데이터 패브릭(여러 DB를 하나처럼 묻게 하는 중간층), 설비 · 데이터 층을 실제 공장 제품(소프트 PLC · 경보 처리 · 스트림 탐지 · 구역 분리 등)으로 바꾸는 방향. 둘 다 이번 시스템에는 없고 방향만 정해 보류된 것이다.
  3. 세 시나리오 중 하나를 골라 ④의 기록지로 5분 발표하고 자가 평가를 한다.
- 알게 되는 것: 이 과정의 구조가 제품과 더 큰 회사 환경으로 어떻게 커지는지 말로 설명한다.
- 쓰는 시나리오: 쿨러 · 펌프 · 팬 중 하나(발표)
- 이 안에서 자연스럽게 다루는 것: (데이터 패브릭) (IoT · 설비층 제품 교체의 방향과 보안 구역) (제품과 같은 일 목록 모양)
- 대표 화면: [처리 건 — 흐름 전 단계 완료](../.evidence/a151-capture/13-처리건-흐름도전단계완료_표시-영문목록.png) · [정비 요청 발행](../.evidence/a151-capture/11-작업지시발행-정비요청WO.png)
- 필요 시간 근거: 해당 없음(설명 · 발표). 발표 시간은 수강생 수에 따라 달라진다(⑤). 자가 평가 문항은 저장소 밖 교재에 있다.
- 기존 회차 문서: 24 · 25

## ④ 시나리오별 진행 틀

세 바퀴는 같은 흐름을 탄다. 다른 것은 **이번 바퀴에서 얻는 가치**와 수강생이 기록하는 것이다.

### 쿨러 바퀴 — 한 바퀴 전체를 따라가며 단계마다 "누가, 무엇을 보고, 무엇을 남기나"를 안다

- 목표 가치: 처음 보는 공장에서 경보 하나가 정비 요청으로 끝나기까지 각 단계가 무엇이고 누구 손에 있는지 말할 수 있게 된다.
- 진행 순서: 단원 1(한 바퀴 지켜보기) → 2(감지) → 3(처리 건) → 4(AI가 읽을 지식을 사람이 먼저 걷기) → 5(AI 네 일과 1등 이유) → 6(사람 선택 · 명령 · 다시 지켜보기 · 정비 요청). 단원 1에서 적은 "누구 일인가" 표를 단원마다 채워 간다.
- 수강생이 기록할 것
  - 단계별 시각표: 주입 → 경보 → 처리 건 열림 → AI 네 일 → 카드 → 선택 → 설비 응답 → 경보 해제 → 다시 지켜보기 → 정비 요청 → 종결
  - 단계마다 담당(AI · 운전원 · 생산관리자 · 설비 제어 · 처리 시스템 · 정비 시스템)과 읽은 출처
  - "왜 1등인가" 두세 문장, 회복 기준표 쿨러 줄(유온 55 ℃ 아래)
- 대표 화면: [홈](../.evidence/a151-capture/01-홈-설비3기정상.png) · [조치 판단 카드](../.evidence/a151-capture/05-조치판단카드-추천1등.png) · [종결 결과](../.evidence/a151-capture/12-처리건-종결결과_표시-영문목록.png) — a151 세트 14장 전체가 이 바퀴의 장면이다(`README.md` 장별 설명)

### 펌프 바퀴 — 돌리기 전에 예측하고, 지식 지도와 규칙으로 근거를 대며 맞춰 본다

- 목표 가치: 시스템이 무엇을 할지 미리 말하고 맞히는 경험으로, 지식 지도 · 규칙을 "읽을 줄 아는" 단계에서 "써서 설명하는" 단계로 넘어간다.
- 진행 순서: 단원 7(지식을 채워 넣고 예비 펌프 준비 상태 연결) → 8(규칙으로 규정 제외 미리 보기) → 9(예측표 → 펌프 누설 주입 → 보류와 다시 평가 → 예비 펌프 전환 → 대조).
- 수강생이 기록할 것
  - 예측표: 원인 / 빠질 조치와 이유 / 1등 조치 / 승인 역할 / 회복 기준 / 첫 판단이 멈출지
  - 실제 결과와 한 줄씩 대조, 틀린 곳마다 "지도 · 규칙 중 어디를 못 봤나"
  - 회복 기준표 펌프 줄(압력 165 이상), 쿨러와 달랐던 곳(패턴 · 카드 · 명령 · 회복 기준) 4행
- 대표 화면: [조치 판단 규칙 — 설비 · 패턴 · 예비 펌프](../.evidence/a141/decision-1440.png) · [지식 관리](../.evidence/a141/knowledge-1440.png) — 펌프 전용 장면은 별도 촬영 필요

### 팬 바퀴 — 일을 AI 일꾼에게 맡겨 본 뒤, 일부러 틀린 선택으로 여러 겹의 안전을 확인한다

- 목표 가치: 정상 경로는 내 PC AI 일꾼에게 맡기고 사람은 질문에 답하는 역할을 해 본 뒤, 사람이 틀렸을 때 공장이 어디서 어떻게 막는지 안다.
- 진행 순서: 단원 10(내 일꾼이 팬 경보의 네 일 처리 · 질문에 답 · 정상 종결) → 11(AI에게 진동 · 납기 · 규칙을 물어 근거 확인) → 12(팬 100 % 함정, 펌프 가림, 원격 수동 과열 정지). 단원 12는 시스템 기본 AI 상태로 한다(일꾼과 함정을 같이 돌린 제작자 검증은 없음).
- 수강생이 기록할 것
  - 일 → 다음 일로 넘어간 입력 표, AI 질문과 내 답, 일꾼이 쓴 도구 · 출처
  - 함정마다 예상 → 실제 → 막은 겹(설비 제어기 안전장치 / 다시 지켜보기 / 규정 · 운전 모드 검사 / 권한 · 기한)
  - 회복 기준표 팬 줄(진동 1.2 아래), 예측 압력 · 실측 압력 · 기준 165 비교
- 대표 화면: [에이전트의 질문 카드](../.evidence/a148/52/screen-question-card-1440.png) · [결함 시뮬레이션 — 수동 조작 · 보호 정지 해제](../.evidence/a141/scenario-1440.png) — 팬 함정 · 가림 장면은 별도 촬영 필요

### 마무리 — 세 바퀴 비교표

단원 13(회사 사정)과 14(발표) 전에, 세 시나리오 × (감지 조건 · 원인 · 1등 조치 · 빠진 조치와 이유 · 승인자 · 설비 명령 · 회복 기준 · 실패하면 어디로)를 한 표로 채운다. 발표는 이 표와 바퀴별 기록지를 쓴다.
