# 실습 가이드의 형식

이 문서는 실습 가이드의 원고를 쓰거나 HTML로 바꿀 때, 어떤 블록이 있고 언제 무엇을 쓰는지 알고 싶을 때 읽는다.

틀은 같은 폴더의 `실습가이드_틀.html`이다. 사용자가 준 본보기(다른 과정의 실습 가이드)의 **형식만** 옮긴 것이다: 스타일과 스크립트는 본보기의 것이고, 본문은 모두 〔 〕로 싼 자리표시 글이며 그림 자리는 빈 상자다. 본보기 파일과 그 본문 · 그림은 저장소에 없다. 무엇이 정해졌는지의 전체는 `docs/교재/인계/06_실습가이드_착수.md` 2절에 있고, 여기에는 형식에 관한 것만 적는다.

## 1. 형식에 관해 정해진 것

| 정해진 것 | 내용 |
|---|---|
| 원고와 배포 | 원고는 MD 하나가 원본이고 그림은 같은 폴더의 이미지 파일이다. HTML로 변환해 배포한다. 변환 스크립트는 아직 없다 |
| 디자인 | 본보기의 형식을 그대로 따른다. 새 디자인을 만들지 않는다. 블록이 더 필요하면 아래의 블록을 조합하고, 그래도 안 되면 사용자에게 묻는다 |
| VS Code 화면은 찍지 않는다 | Copilot 채팅에 보내는 요청과 명령어는 복사 상자로, 출력은 터미널 재현 상자에 글자로 싣는다 |
| 사진은 브라우저 화면에만 | HYD 포털, Neo4j Browser, bpmn.io, arrows.app의 결과 화면 |
| 예외로 받는 사진 | VS Code 확장을 열고 로그인하는 처음 한 번, Windows 설치 화면 — 수업 PC에서 찍은 것을 받아 넣는다 |
| 표기 | 학생의 도구는 VS Code의 GitHub Copilot 채팅이다. 본보기의 「Copilot Agent 채팅」 자리는 「Copilot 채팅」으로 적는다. 붙여넣는 곳은 「Copilot 채팅 입력 칸」, 「VS Code 터미널의 실습 폴더」, 「브라우저 화면의 입력 칸」 가운데 하나로 적는다 |
| 요청 상자마다 「왜 이렇게 시키는가」 | 한두 줄. 풀이 상자(`check-explanation`)에 쓴다 |
| 출력 예 아래에 「확인할 것」 | 두세 줄. 「글자가 똑같아야 한다」가 아니라 「이 항목들이 들어 있으면 된다」로 읽히게 쓴다 |
| 나쁜 요청과 좋은 요청 | 실제 출력으로 나란히 보인다 |
| 빈칸 늘리기 | 앞 실습은 요청을 그대로 주고(요청 복사 상자), 뒤는 틀만 주고(직접 쓰는 칸과 접어 둔 예), 마지막은 목표만 준다(직접 쓰는 칸만) |
| 흔히 막히는 곳 | 실습마다 한두 개. 주의 상자(`route-recovery`)나 접어 두는 도움말(`details`)에 쓴다 |
| 싣는 내용 | 명령어, 출력, 좋은 예와 나쁜 예, 막히는 곳은 **실제로 돌려 얻은 것만** 쓴다 |

## 2. 한 가이드의 뼈대

```
header                         가이드 이름
div.layout > main
  nav.step-menu                단계 메뉴(버튼마다 data-step)
  article.task#S00             시작 전에
  article.task#H01 …           단계마다 하나(H01, H02, …)
div#notice                     복사했을 때 뜨는 알림(스크립트가 채운다)
script
```

- 단계의 id는 `S00`(시작 전에)과 `H01`, `H02` …(두 자리 숫자)다. 메뉴 버튼의 `data-step`, 「다음」 버튼의 `data-step`, `data-route-stage`가 이 id와 같아야 한다.
- 한 번에 한 단계만 보인다. 주소 끝에 `#H03`을 붙이면 그 단계가 열린다.
- `body`의 `data-guide="…"`는 이 가이드의 이름표다. 체크 상태와 직접 쓴 글이 이 이름으로 브라우저에 저장되므로 **가이드마다 다른 값**을 준다.
- 다섯 걸음(파악시키기 → 끝난 모습 정하기 → 계획 받기 → 작게 만들고 확인 → 되돌려 주기)과 단계가 꼭 일대일일 필요는 없다. 짧은 실습은 걸음을 한 단계에 합친다. 틀은 걸음 2와 3을 한 단계(H02)에 합쳐 보였다.

## 3. 블록 종류

틀의 HTML에는 블록마다 `<!-- [블록] … -->` 주석이 달려 있다.

### 3.1 단계의 틀

| 블록 | 클래스 · 요소 | 언제 쓰는가 | 틀에서 보는 곳 |
|---|---|---|---|
| 단계 메뉴 | `nav.step-menu` > `button.step-link[data-step]` > `span`(번호) | 가이드 맨 위에 한 번. 그 단계의 기준을 모두 체크하면 버튼에 ✓가 붙는다 | 맨 위 |
| 단계 머리 | `p.eyebrow` + `h2[tabindex=-1]` (+ `p.goal`) | 단계마다 맨 위. eyebrow는 걸음의 이름, h2는 그 단계에서 하는 일 | 모든 단계 |
| 읽을거리 카드 | `div.read-card` (+ `span.role-label`, 또는 `h3.action-title` + `strong`으로 「상황」 「할 일」) | 손을 대기 전에 읽을 글. 단계마다 하나 | S00, H01~H05 |
| 작은 제목 | `h3.action-title` > `span`(어디에서 하는가: Copilot 채팅 · 터미널 · 브라우저 · 결과 확인) | 단계 안에서 일의 자리가 바뀔 때 | 모든 단계 |
| 구획 | `section` | 단계 안의 덩어리. 구획 사이에 가는 선이 그어진다 | 모든 단계 |
| 다음으로 가는 기준 | `section.route-checkpoint[data-route-stage]` > `label` > `input[type=checkbox][data-route-check]` + `p.route-status` + `button[data-route-next][data-step]` | 단계의 맨 끝. 체크를 모두 해야 「다음」 버튼이 켜진다. 기준은 **직접 본 것**으로 쓴다(「읽었다」가 아니라 「이 줄이 내 출력에도 있다」) | 모든 단계의 끝 |
| 끝 알림 | `p.route-finish[hidden]` | 마지막 단계의 기준 안에. 모든 단계의 기준이 체크되면 보인다 | H05 |

### 3.2 시작 전에(S00)

| 블록 | 클래스 · 요소 | 언제 쓰는가 |
|---|---|---|
| 자리 지도 | `div.place-map` > `div` 셋(`b` + 설명) | 이 실습에서 오가는 곳(Copilot 채팅, 터미널, 브라우저)을 처음에 한 번 보인다 |
| 준비 걸음 | `section.setup-step` > `h3` > `span.step-number` | 준비물을 하나씩. 번호, 제목, 설명, 명령어 복사 상자, 결과 한 줄의 순서 |
| 표 | `table.service-table` | 이름 · 쓰임 · 확인할 것처럼 대응을 보일 때만 |
| 접어 두는 도움말 | `details` > `summary` | 막혔을 때만 볼 것. 평소에는 접혀 있다 |

### 3.3 복사 상자

세 가지 모두 **머리(`div.block-head`: 무엇을 어디에 넣는가 + 복사 버튼) → 글(`pre[id]`) → 붙여넣는 곳 안내(`div.paste-destination`)**의 꼴이다. 복사 버튼은 `button[data-copy="<pre의 id>"][data-destination]`이고 안에 복사 아이콘(`svg.copy-icon`)이 든다.

| 블록 | 클래스 | `data-destination` | 언제 쓰는가 |
|---|---|---|---|
| 명령어 복사 상자 | `div.block.terminal` | `terminal` | 터미널에 넣는 명령. 한 상자에 명령 하나 |
| AI에게 줄 요청 복사 상자 | `div.block.prompt` | `agent` | Copilot 채팅에 보내는 요청. 좋은 예와 나쁜 예도 이 상자로 싣는다(머리에 「좋은 예」 「나쁜 예」) |
| 브라우저에 넣는 질의 | `div.block.terminal` | `browser` | Neo4j Browser의 질의처럼 브라우저의 입력 칸에 넣는 것 |
| 파일 경로 | 위와 같은 꼴 | `file` | VS Code에서 열 파일의 경로(본보기의 스크립트에 있는 쓰임. 틀에는 보이지 않았다) |

복사하면 화면 아래에 「복사했습니다. (붙여넣는 곳)」 알림이 뜬다. 브라우저가 복사를 막으면 글을 선택해 주고 직접 복사하라고 알린다.

### 3.4 직접 쓰는 칸

| 블록 | 클래스 · 요소 | 언제 쓰는가 |
|---|---|---|
| 직접 쓰는 칸 | `div.writing-studio` > `aside.writing-hints`(`h4` + `p` > `span.comment-label` + `span`) + `div.block.write-card`(`div.block-head` > `label` + 복사 버튼, `textarea[id][data-draft]`, `div.paste-destination`, `div.actions` > `span.draft-status` + `button[data-download]`) | 학생이 요청을 **자기 말로** 쓰게 할 때. 왼쪽에 넣을 거리, 오른쪽에 글 칸. 쓴 글은 그 브라우저에 저장되고, 복사와 텍스트 파일로 내려받기가 된다 |
| 접어 둔 예 | `details.example.answer-help` > `summary` + 요청 복사 상자 | 직접 쓴 뒤에 견주어 볼 예. 뒤 실습으로 갈수록 뺀다 |
| 쓰는 순서 안내 | `p.conversation-order` | 직접 쓰는 칸 위의 한 줄 |

### 3.5 출력과 결과

| 블록 | 클래스 · 요소 | 언제 쓰는가 |
|---|---|---|
| 터미널 재현 상자 | `div.h01-output-sample` > `div.h01-output-label`(`strong` 「출력 예」 + `span` 「발췌」 등) + `pre.output-example[aria-label]` | 터미널과 Copilot 채팅의 출력을 **글자로** 싣는다. 실제 출력에서 옮기고, 줄였으면 「발췌」라고 적는다 |
| 확인할 줄 표시 | `mark.output-hit` + `hit-success` · `hit-id` · `hit-state` | 출력 안에서 학생이 찾아야 하는 줄에 빨간 테두리를 친다. 세 클래스의 모양은 같고 뜻(끝났다는 표시, 식별자, 상태)만 다르다 |
| 결과 확인 한 줄 | `p.result` > `strong` | 「이것이 보이면 된다」. 출력 상자와 사진 바로 아래에 둔다 |
| 풀이 상자 | `div.check-explanation` > `h4` | 「왜 이렇게 시키는가」, 출력의 낱말 풀이 |
| 결과 묶음 | `section.route-results` > `h3` + 터미널 재현 상자 + 읽는 법 | 한 단계의 마지막 실행 결과를 상자 하나로 묶어 보일 때 |
| 주의 상자 | `p.route-recovery` | 흔히 막히는 곳과 되돌리는 법 |

### 3.6 사진

| 블록 | 클래스 · 요소 | 언제 쓰는가 |
|---|---|---|
| 화면 사진과 확대 | `figure.screen-example` > `figcaption`(`strong` 화면 이름) + `button.screen-zoom[aria-label]` > `img[width][height][alt][loading=lazy]` | 브라우저 화면의 결과. 누르면 크게 열리고(`dialog#screen-dialog`는 스크립트가 만든다) 「원본 크기로 보기」와 「닫기」가 있다 |
| 볼 곳 표시 | `span.photo-mark[style="left:…%;top:…%;width:…%;height:…%"]` (`button.screen-zoom` 안, `img` 뒤) | 사진에서 볼 곳에 빨간 테두리를 친다. 자리와 크기는 사진에 대한 %다. 사진에 직접 그려 넣지 않는다 |
| 사진 확인 구획 | `section.photo-check` > `h3.action-title` + `p.screen-purpose` + 사진 + `p.result` | 「화면에서 무엇을 보는가」를 사진과 함께 물을 때 |
| 받은 사진(예외) | `figure.screen-example.terminal-example` | 수업 PC에서 찍어 받은 설치 · 로그인 화면 |
| 화면에서 따라가는 순서 | `section.decision-route` > `ol` | 브라우저에서 누르는 순서. 메뉴와 버튼 이름은 `strong`으로 |

사진의 규칙: 원본 사진은 MD와 같은 폴더에 둔다. `img`의 `width`와 `height`에는 사진의 실제 크기를 적는다(본보기의 브라우저 사진은 1440 × 1000이었다). `alt`에는 화면에 무엇이 보이는지를 적는다. 배포용 HTML에서 사진을 파일 안에 넣을지(data URI) 따로 둘지는 정해지지 않았다(`docs/교재/인계/06_실습가이드_착수.md` 5절).

### 3.7 본보기에 없던 쓰임

| 쓰임 | 어떻게 했나 | 상태 |
|---|---|---|
| 나쁜 요청과 좋은 요청의 출력을 나란히 | 두 칸 그리드(`div.writing-studio`)에 터미널 재현 상자 둘을 넣었다. 새 스타일은 만들지 않았다(틀의 H03) | 본보기 실습을 만들 때 사용자에게 보이고 확정한다 |
| 브라우저에 넣는 질의의 알림 문구 | 스크립트의 `data-destination`에 `browser`를 더했다 | 같다 |

### 3.8 스타일에는 있으나 본보기 본문에 쓰이지 않은 것

`reading-key`(읽는 법 꼬리표), `task-brief` · `compose-brief`(할 일 요약 상자), `result-criteria`, `route-entry`, `observed`, `reply-example`, `footnote`, `extension`. 틀의 스타일에 그대로 남아 있다. 쓰려면 실제 모양을 먼저 확인한다.

## 4. 스크립트가 하는 일

| 기능 | 걸리는 곳 | 메모 |
|---|---|---|
| 단계 바꾸기 | `[data-step]`, 주소의 `#` | id가 `S00` · `H\d\d`이고 그 id의 `article`이 있을 때만 |
| 복사 | `[data-copy]` + `[data-destination]` | 대상이 비어 있으면(직접 쓰는 칸) 먼저 쓰라고 알린다 |
| 직접 쓴 글의 저장과 내려받기 | `textarea[data-draft]`, `[data-download]` | 브라우저의 저장소(localStorage)에 둔다. 다른 PC로 옮겨지지 않는다 |
| 사진 확대 | `.screen-zoom` | 볼 곳 표시도 함께 옮겨 보인다. Esc나 바깥을 누르면 닫힌다 |
| 다음으로 가는 기준 | `[data-route-check]`, `[data-route-next]`, `.route-status`, `.route-finish` | 체크 상태도 브라우저에 저장된다 |

본보기의 스크립트에서 바꾼 곳은 다섯이다: 단계 id의 범위(`H01`~`H06` → 두 자리 숫자면 모두), 저장 이름(`body`의 `data-guide` 값을 앞에 붙인다), 붙여넣는 곳 문구(「Copilot 채팅 입력 칸」, `browser` 추가), 빈 칸을 복사하려 할 때의 알림 문구, 내려받는 파일 이름. 스타일은 한 글자도 바꾸지 않았다.

## 5. 틀이 혼자 열리는가

외부 자원(글꼴, 스타일 파일, 스크립트 파일, 그림 주소)을 쓰지 않는다. 글꼴은 그 PC의 것(Segoe UI, 맑은 고딕, Consolas)을 쓴다. 2026-10-12에 네트워크를 막은 헤드리스 Chrome에서 파일로 열어 단계 바꾸기, 기준 체크와 「다음」 버튼, 사진 확대와 닫기, 복사 알림, 직접 쓴 글의 저장이 동작하고 스크립트 오류가 없음을 확인했다. Windows의 브라우저와 맑은 고딕으로는 열어 보지 않았다.

## 6. MD 원고와의 대응(정해지지 않았다)

MD의 어떤 표기가 어느 블록이 되는지는 아직 정하지 않았다. 본보기 실습 하나를 MD로 쓰면서 정하고, 그때 이 절을 채운 뒤 변환 스크립트를 만든다. 조건은 둘이다: MD만 읽어도 실습을 따라갈 수 있을 것, 변환 결과가 이 틀의 블록 구조와 같을 것.
