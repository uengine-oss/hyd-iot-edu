# 외부 서비스 연결 — 운영자와 학생의 역할

학생은 포털에 로그인하지 않는다. `도구 연결`에서 서비스를 선택해 `연결`을 누르고, 필요한 경우 외부 서비스 창에서 본인 계정 로그인과 권한 동의를 한다. 동의 뒤에는 포털이 실제 도구 검사를 하고 등록한다. 무인증 서버는 로그인 창 없이 검사하며, 접속키 방식 서버는 제공자가 안내한 키와 방식을 입력한다. 연결 검사 실패를 사용 가능으로 바꾸지 않는다.

현재 수업 공간에서 함께 사용하는 공용 연결이다. 다른 학생의 개인 계정을 자동으로 섞지 않는다. 계정별 격리를 보장하는 학생 로그인 시스템을 만들었다는 뜻은 아니다. 연결 해제는 HYD의 자격증명과 해당 연결이 만든 등록을 제거한다. Google 등의 계정 보안 화면에서 동의까지 철회했다고 표시하지 않는다.

## 운영자가 한 번 준비하는 것

1. `scripts/setup_mcp_oauth_keys.py`를 실행한다. 기본 Windows 위치는 `%LOCALAPPDATA%/HYD/mcp/`, Linux는 `$XDG_STATE_HOME/hyd/mcp/` 또는 `~/.local/state/hyd/mcp/`다. 암호화 키와 실행기 인증 키는 별개이며 기존 파일을 다시 만들지 않는다. Git 안의 경로는 거절한다.
2. process의 기존 영속 볼륨 `/data/mcp/`에 `oauth.key`와 `worker-runtime.key`를 설치하고 디렉터리 권한 700, 파일 권한 600을 적용한다. 호스트 워커는 같은 실행기 인증 키를 사용하고 암호화 키를 받지 않는다. 이번 PC에는 설치·실제 배포를 완료했다. 키 값은 보고서에 없다.
3. `HYD_MCP_OAUTH_CALLBACK_URL`은 실제 포털 주소의 `/api/mcp/connections/callback`으로 고정한다. 이번 로컬 주소는 `http://localhost:8088/api/mcp/connections/callback`이다. 다른 PC가 접근하는 배포에서는 실제 HTTPS 주소와 외부 앱의 등록 반환 주소를 일치시킨다.
4. 서비스가 앱 자동 등록을 제공하면 discovery 후 자동 등록한다. 사전 등록을 요구하면 운영자가 OAuth 앱을 등록하고 `HYD_MCP_OAUTH_CLIENTS`의 issuer별 JSON 설정을 Git 밖에서 제공한다. 항목은 `client_id`, 선택 `client_secret`, 지원하는 `token_endpoint_auth_method`다. provider의 공식 설정과 일치해야 하며 임의 인증서를 꺼서 통과시키지 않는다. compose는 이 선택 환경변수를 process에 전달한다. 값을 진단·화면·커밋에 출력하지 않는다.
5. 교육용 사설 서버를 연결하려면 운영자가 필요한 정확한 origin만 `HYD_MCP_OAUTH_PRIVATE_ORIGINS`에 지정한다. 공용 서버와 임의 로컬·클라우드 메타데이터 주소를 같은 정책으로 허용하지 않는다.

## 공식 Google MCP의 현재 상태

구글 드라이브·구글 캘린더 공식 MCP 주소를 선택 목록에 넣었다. 실제 Google 공개 보호 자원 metadata와 OAuth issuer의 S256 지원도 인증 없이 확인했다. 서비스 제공자가 요구하는 미리보기 API 사용 권한, OAuth 앱 사전 등록, 소유 계정의 동의는 따로 필요하다. [Google 공식 설정 문서](https://developers.google.com/workspace/guides/configure-mcp-servers)에서 서버 주소·미리보기·앱 등록 및 각 서비스 읽기 권한을 대조했다. ChatGPT Google 앱에 연결한 권한은 HYD로 자동 이전되지 않는다.

현재 Google client 정보와 HYD 계정 동의는 없다. 기존 서버 5개는 유지했고 Google 서버를 사용 가능으로 등록하지 않았다. 이 제한을 ‘로그인이 이미 끝났음’이나 ‘모든 MCP가 자동 연결됨’으로 바꾸지 않는다. 학생에게 GCP 설정을 반복시키는 것이 아니라, 운영자 준비 후 학생이 로그인·동의만 하는 경로를 제공한다.

## 지원 범위와 실패 표시

새 간편 연결은 HTTP MCP의 무인증·명시 헤더 접속키·표준 OAuth 발견/PKCE를 지원한다. 기존 명령형 서버 직접 등록은 접힌 운영자 영역에서 유지한다. 임의 서비스 전용 인증, 모든 등록 방식, 모든 MCP 전송 방식을 지원한다고 약속하지 않는다. 새 OAuth 실행 중계는 Streamable HTTP의 JSON/POST 응답 스트림을 지원하며 선택 GET 스트림과 옛 OAuth SSE 방식은 명시적으로 거절한다.

읽기 도구는 실제 검사와 현재 설정 해시가 맞아야 에이전트에 제공된다. 승인 전 쓰기 도구는 허용하지 않는다. 승인 후 시스템 쓰기는 기존 승인 경로를 사용하고 외부 계정 권한도 있어야 한다. 처리 중 만료는 요청마다 갱신하며 실제 401 뒤 요청을 몰래 재실행하지 않는다. 계정 연결 만료, 준비 파일 부재, 권한 부족은 사용자가 조치할 수 있는 한국어 안내로 표시한다.
