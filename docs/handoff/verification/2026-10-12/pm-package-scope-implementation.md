# PM 원문 정비 묶음과 자산 범위 구현

PM-02의 누적 정비 차례와 경보 세대 `cycle`을 분리했다. 검토된 `maintenance_policy`는 원문 모델 범위·주기·허용 편차·세 정비 묶음·필수 품목·출처를 보존한다. 실제 누적 11,950 h / 정비 후 1,950 h는 다음 누적 12,000 h의 4,000 h 묶음이다. 조기 정비로 차례가 불명확하면 실제 완료 이력 없이 경보 세대로 추측하지 않는다.

단일/동종 두 자산 범위는 실제 카운터, 동종 원문 적용 범위, 1,800 h 하한, 공통 창, 허용 기한, 전체 품목과 인력을 재검증한다. 두 자산의 원문 묶음이 다르면 각 묶음의 필수 품목을 합산한다. 인력 부족은 원문 감점·추가 확보 필요로 남기며 확보 완료를 만들지 않는다. 승인 계획과 실제 오더 영수증은 별도 기록한다.

PM11의 `reserve`, PM12의 `issue`, PM13의 `preserve`를 구분했다. 출고는 실제 보유량을 차감하고 입고 예정량으로 대신하지 않는다. 시간 변경은 기존 오더의 실제 소유 예약량을 유지하며 새 예약을 만들지 않는다. 묶음 생성과 예약은 PostgreSQL 한 트랜잭션으로 처리하고 실패 시 두 자산을 모두 되돌린다. 예약 묶음 취소는 모든 오더·포인터·예약을 함께 검증하고 함께 해제한다. 진행된 오더 또는 반품 확인 없는 출고는 보상 불가를 명시하며 일부 취소 성공으로 표시하지 않는다. 정비 오더 발행은 실제 현장 정비 완료가 아니다.

현재 실제 ERP에는 리턴 필터 품목/재고와 작동유 매핑/수량이 없다. `F/PM-full-business-source-read.json`과 `F/PM-actual-policy-scope-validation.json`의 F 정본 경로는 `D:/work/study/hyd-iot-edu/.evidence/delegated-review-20261012`이다. 후자는 12,000 h / 4,000 h 문맥을 유지한 채 리턴 필터 미상으로 실행 불가를 확인했다. 원문 적용 자산 목록은 검토된 원문 근거이며 실제 자산 마스터의 미상 모델 코드를 채운 것이 아니다. 메인 데이터에 품목·재고·오더를 추가하지 않았다.

최신 순수/메모리 PM 회귀 43개와 보상·오더 영수증 포함 backend 묶음 64개 통과. 신규 migration56의 최초 독립 PostgreSQL 실행은 기존 시간 변경 6개 통과, 신규 10개 설정 단계에서 CASE 식 문법 실패였다. 최초 `F/pytest-pm-scoped-pg-first.log/xml`을 보존하고 생산 SQL을 수정한 재실행은 16개 통과했다. 추가 stock 모드 시험의 최초 실행은 기존 16개 통과, 새 3개의 입력에서 공통 창·시간 하한 계약 위반으로 실패했다(`F/pytest-pm-scoped-pg-stock.log/xml`). 입력을 정상 계약으로 교정하고 기존 두 자산 출고량 2/ledger 4 검사는 그대로 유지했다. PM12 단일 즉시 출고량 1/ledger 2 검사를 별도로 추가했다. 실제 PostgreSQL 추가 재실행 및 전역 검증 결과는 루트 최종 원장으로 확정한다. 시험 데이터는 독립 트랜잭션 또는 명시적인 가상 단위 fixture이며 실제 교실 재고 증거가 아니다.

추가 20개 실행은 원천 facts를 소비하는 신규 시험에 생산자의 `pm_limit_hours` projection이 빠져 18개 통과/2개 입력 실패했다(`F/pytest-pm-scoped-pg-final.log/xml`). 실제 관측 주기·허용 편차로 계산하는 생산자 projection을 시험 입력에도 적용했으며 상한 기본값이나 기대 완화는 사용하지 않았다. 최종 실제 독립 PostgreSQL 재실행 `F/pytest-pm-scoped-pg-final2.log/xml`은 **20개 통과, 3.69초**이다. 양 자산 예약/출고, 원자적 실패, 전 범위 보상, 단일 취소 우회 거부, 자유 재고 0인 실제 소유 예약 보존, 승인 후 예약량 변동 거부를 포함한다. 메인 적재·배포·실제 B 실행의 성공을 의미하지 않는다.
