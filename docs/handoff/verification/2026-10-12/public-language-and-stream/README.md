# 일반 화면 용어와 MCP 준비 상태 — 실제 화면 확인

10월 12일 시작한 후속 작업을 10월 13일 KST에 배포·확인했다. 최종 제품/검사 소스 819개를 고정했다. 이번 변경은 알려진 화면 용어와 가져오기 준비 상태 안내이며 색상/CSS·모델·승인 흐름을 바꾸지 않는다.

- 메뉴를 조건별 손익·성과 지표·도구 연결·인공지능 설정으로, 알려진 시스템과 기본 에이전트 설명을 한국어로 표시한다. 사용자 지정 이름·원문 접기·모델/문서번호·기술 설정은 보존한다. 생성 사전에도 표시 정책을 적용했다. 실제 B PNG가 발견한 대기/기한 확인/담당자 알림/종료의 하드코드4개도 공통 업무 수행자 투영으로 고쳤다. 실제 소비자4개를 호출하는 Node 계약과 원문 불변을 확인했고 첫 의미 실패를 보존했다. 홈 그림도 한국어 이름 설정을 우회하던 SVG의 AI/Agent 하드코드를 제거해 설정된 이름을 사용한다. 첫 홈 실패와 실제 SVG 소비자 검사도 남겼다.
- MCP 단계의 저장된 등록/검사 결과를 사용해 서버 미등록·검사 실패/재검사·도구 누락·읽기 미확인을 구분한다. 구조 유효성, 등록/시작 정책과 호출 시 실제 스키마·인증 검사는 그대로다. 저장된 검사 통과를 현재 Google 인증 성공이라고 표시하지 않는다.
- 실제 회의 초안을 import → mapping → check 순서로 확인했다. 구조 문제 0과 미등록 서버 2개를 동시에 확인했고 판본 등록·실행·Google 호출은 0이다. 캡처 뒤 본인 초안만 정식 DELETE로 삭제했고 기존 흐름 목록은 전후 정확히 같다.

집중 검사: 화면 정책/관련 회귀 6개, 에이전트 원문 편집 1개, MCP 준비 상태 4개 및 Node 화면 검사 통과. 정책 제거 역실험 9개는 예상 실패다. 전체 회귀·새 LLM·A/B/C 업무 재완주는 0이다. 첫 MCP tenant fixture 키 오류, 화면 검사기의 실제 도구 이름 오류, 프로필 없는 첫 build 오류, 서비스 기동 전 첫 GET 오류도 보존/설명했다. 실제 B의 수행자 의미 실패는 제품 소비자를 수정했다. 에이전트 제목을 단순 ‘에이전트’로 가정한 수집기는 이미 구현된 정확한 ‘인공지능 에이전트’ 표시와 옛 CLI 명칭 미노출 계약으로 교정했다. 이미 통과한 B/C3장은 재촬영하지 않았고 남은4장만 이어갔다. 업무 기대값을 낮춰 제품 실패를 통과시키지 않았다.

실제 화면 8장과 비교 1장: GET 전용 캡처의 write/page/console 오류 0, 기존 B/C 업무와 기본 에이전트 원문 불변. [B 상세 1440](native-public/B-record-1440.png), [B 상세 1024](native-public/B-record-1024.png), [기본 에이전트](native-public/agents-sys-agent-1440.png), [흐름 준비 안내](native-public/owned-draft/dependency-warning-1440.png), [참고 나란히 비교](native-public/comparison.png). 참고는 보존된 ProcessGPT/Dify 이미지이며 최신 앱 실구동·픽셀 동등성을 주장하지 않는다. 세부 판정은 native result와 SHA 기록에 있다.

첫 화면 대기·최소 진단의 시간 초과도 보존했다. 당시 호스트 여유 메모리 약500MB와 DB IO 대기를 관찰했으나 인과는 확정하지 않았다. 이후 15:17Z에 포털 등 기존 서비스 여러 개가 종료된 상태를 확인했다(포털 exit137/OOMfalse·정상 종료 신호 로그, 종료 주체 미확인). 본인 캡처 프로세스만 정리하고 기존 서비스 컨테이너를 다시 시작했으며 source/data를 재생성하지 않았다. 포털 정적 GET200을 확인했다. 캡처 전후 확인은 이번 변경19파일로 좁히고 최종819파일 고정 판정은 별도로 남긴다.

캡처는 수정 단계별로 합친 증거다. 초안 안내는 수행자 소비자 수정 전, B/C·에이전트는 수행자 수정 후, 홈은 SVG 수정 후다. 변하지 않은 화면을 재촬영해 같은 판본처럼 꾸미지 않았다. 홈은 이름·그림 확인 시점의 센서값 초기 로딩 상태이며 센서 조회 완료의 증거가 아니다. 빈 조건별 손익 화면도 계산 완료의 증거가 아니다.

실시간 증거 감사는 [audit.md](audit.md)에 있다. 실제 B/C 공개 설명과 MCP 프레임, 최신 원문 읽기를 확인했지만 추천 카드 생성·승인/거절·시스템 처리·종료의 모든 순간을 실시간 화면으로 관찰한 증거는 없다. 현재 구독 결함으로 확정할 근거도 발견하지 못했다. 저장 화면을 전체 실시간 증거로 바꾸어 부르지 않는다.

처리 서비스만 한 번 계획 재생성했고 건강 상태와 재시작 0을 확인했다. 그 뒤 로컬 API 시간 초과·호스트 메모리 압박·DB117초 IO 대기를 관찰했으나 느린 쿼리의 정체나 인과는 확정하지 못했다. 현재 IPv4 DB접속25.6ms와 GET3종200이 확인됐고 전역 네트워크/SQL 인덱스/사용자 앱을 바꾸지 않았다. `/healthz`200이 업무 DB조회 준비를 보장하지 않는 간극은 F13의 운영 잔여로 남긴다. [연결 진단](db-connectivity-readonly/findings.md)과 operational-observations/response-health에 범위를 구분한다. 데이터 볼륨·보호 폴더·다른 세션은 보존했다. U16/U20/F13·K3 전체는 열림이다. 실제 Google 계정 접근/주관자 배정/회의 실행, 수업 리허설과 사용자 최종 시각 인수는 이 증거로 대체하지 않는다.
