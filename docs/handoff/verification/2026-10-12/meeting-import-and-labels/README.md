# 회의 가져오기 구성과 정비 표시 수정 — 2026-10-12

사용자에게 없는 재고 자료나 MCP 서버 URI를 찾아 달라고 요구하지 않는다. B 교육 ERP 초기값 누락은 직전 작업에서 공식057로 해결해 실제 완료까지 확인했다. 이번에는 우리가 구성할 수 있는 회의 등록·사본 준비와 발견된 표시 결함을 처리했다.

## 실제로 준비한 것

- 정식 API로 `회의 주관자` 역할과 `Google 회의 준비 에이전트`를 생성했다. 실제 응답 ID와 후속 GET catalog를 보존했다. 기존 에이전트는 바꾸지 않았다. 모델 설정은 비워 실행기 기본을 상속하며 개발용 Sol6.1 선택으로 제품 실행 모델을 덮지 않았다. 이번에 GPU 접속을 시험했다는 뜻은 아니다.
- [가져오기 사본](prepared/mapping.json)과 [BPMN](prepared/flow.bpmn), [미확인 전제](prepared/preconditions.json)를 실제 등록 에이전트/역할로 생성했다. 현재 catalog를 사용하는 production importer의 offline 구조 검사는 문제0으로 통과했다. 미등록 에이전트 및 기존 출력 덮어쓰기는 거절됐고 원본 예제 SHA는 그대로다. [검증 원본](prepared-bundle-proof.json), [사용 범위](prepared-usage.md).
- 두 Google 서버는 명시 계획 이름만 있다. 아직 미등록·미인증이며 새 에이전트에도 도구를 붙이지 않았다. 주관자 회원도 미배정이다. 구조 검사를 Google 연결이나 실행 성공으로 바꾸지 않는다. 실제 계정의 앱 등록·동의 후 서버 연결, 실자료 입력, 주관자 승인, 일정 생성·참석 응답 확인을 한 번 검증해야 K3가 끝난다. 학생 포털 로그인은 요구하지 않는다.

## 화면 수정과 확인 범위

기존 B 보고 상세에 `작업지시`가 남아 있었고 UIUX.md 인수 조건1에 어긋났다. 처리 기록·조치 코드·이름 사전을 기존 `정비 오더` 표현으로 맞췄다. 이름 사전 생성기의 화면용 투영에도 정책을 적용해 재생성 때 되살아나지 않게 했다. DB, 내부 분류 키, 자유문, 접은 원문은 바꾸지 않았다. 이미 일반어인 A의 `정비 요청` 별칭은 그대로다. 브라우저 캐시 버전만 갱신했고 색상·CSS 변경은 없다.

[최종 집중 검사](labels-fix/result.json)는 생성 정책1개와 Node 명칭 검사 통과 및 투영 제거 시7개 예상실패를 기록한다. 앞선 관련 보고 의미/기록 검사도 별도 [첫 묶음](labels-fix/first-batch-result.json)에 보존한다. 처음 Node VM 접근 실패는 제품/기대값 변경 없이 lexical binding 접근을 고쳐 확인했다. 새 전체 회귀·LLM·업무 완주는0이다. 실제 영향 화면 [1440](native-labels/B-report-detail-1440.png)·[1024](native-labels/B-report-detail-1024.png)를 확인했다. [현재 검사](native-labels/result.json)는 정확한 `남긴 번호 정비 오더` 문장, 금지 표현 없음, 접힌 저장 원문 동일, 쓰기·오류0을 기록한다. [참고 화면과 나란히](native-labels/comparison.png) 보는 자료도 보존했다.

수집기는 최초 DOM 분리와 요구된 `정비 오더`까지 금지하는 잘못된 검사로 실패했다. 각 실패 결과/수집기 파일을 보존했고, 기존 요구대로 정확한 표시 문장 존재·`작업지시` 부재를 검사하도록 바로잡았다. 마지막 교정은 이미 캡처한 실제 DOM에 적용했으며 재캡처나 제품/업무/원문 수정은 하지 않았다. 이 실패를 숨기거나 정상 업무 성공으로 대체하지 않는다.

## 전체 수용 범위

[대응표](course-ui-acceptance.md)는 최종 실라버스 요구, 학생 화면, 기존 구현·시험·업무 증거, 남은 조건을 연결한다. 과거173쌍 원장·F27 96체크·문서 선택18체크·학생 흐름18체크·B 최종8PNG는 서로 다른 범위로 합산하지 않는다. 전체2673개는 당시 판본이다. 이번 표시는 그중 영향 부분만 확인한다.

실제 교육 업무의 A 부정 종결·B/C 완료와 공식3문서 적재는 유효한 별도 근거다. Google 외부 업무, 강사 수업 리허설, 사용자 최종 시각 인수까지 모두 완료했다고 표시하지 않는다. 최초 B live 캡처 실패도 직전 기록 그대로이며 이번 정적 상세 화면으로 실시간 공개/도구 두 구간 성공을 대신하지 않는다.

## 실행 이력과 환경

등록 준비 첫 시도는 `utf8-sig` 인코딩 별칭 오류로 POST 전에 멈췄다. 최초 스크립트와 실패 기록을 보존하고 `utf-8-sig`로 고쳐 실제 role/agent POST2건을 했다. 사본 준비 agent의 `live_POST=0`은 그 작업 범위이며 root 구성2건과 구분한다. 원복은 소유한 생성 ID의 정식 DELETE만 사용하며 전역 초기화를 하지 않는다.

[루트 최종 증거](root-final-proof.json)와 [원본 SHA 목록](copied-evidence-sha.json)은 source815개 중 이번 코드/검사/픽스처8경로, 서빙 바이트, 기존 에이전트/B 업무 원문, process 재시작0, supabase backend, 가동29컨테이너 및 본인 잠금 해제를 확인한다. 검증 원본45파일의 바이트를 그대로 복사했다. 보호 폴더·프로젝트 데이터 볼륨은 건드리지 않았다. 참고 비교는 보존된 ProcessGPT·Dify 원본과 현재 실제 화면을 구분하며 현재 참고 제품 실행 화면이나 픽셀 동등성을 주장하지 않는다.
