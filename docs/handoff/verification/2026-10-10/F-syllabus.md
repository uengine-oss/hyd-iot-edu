### DECISIONS 112 를 대체하는 결정 (→ DECISIONS 113 후보)
- **정기 정비 · 예비품 구매는 실라버스(10-10, `슬라이드/실라버스_통합반.md` 109~114행) 모양으로 되돌린다.** DECISIONS 112 의 "B · C 는 설비까지 가지 않는다(처리되면 끝)"는 폐기한다. 근거: 최신 실라버스가 예약 시각 대기 → 정비 → 시운전(정상 = 다음 정비 시점 갱신 / 미달 = 별도 결과), ERP 발주 → 공급사 메일 → 입고 대기(일치하는 입고 확인 / 기한 안 미입고 = 지연)를 각각 실행하라고 요구하고, 사용자가 "실라버스가 이긴다"고 지시했다.
- 112 에서 **그대로 남는 것**: 시나리오 3개, 에이전트 추천 1개 → 사람 승인 1회 → 시스템 처리 → 자동 확인 → 결과 보고, 블랙박스 없음, 업무 감시 기본 끔, 시각 기준점 규칙, A 누름 ↔ 처리 건 연결, CMMS/ERP 화면은 enterprise-sim.
- **실라버스가 요구하지 않는 것은 덧붙이지 않았다**: 정비 단계는 PLC 설비 명령을 내지 않는다(실습 시뮬레이터의 정비 모사 — 작업지시 완료 · 대상 부품 복구 — 만, 기존 `svc:maintenance` 그대로).
- **설비 결함 인지 · 조치(A)에 승인 거절 경로**(실라버스 92 · 102 · 104행): 조치 카드 승인 단계에서 담당자가 거절하면 설비 명령 없이 결과 보고(반려) → 사건 `REJECTED_BY_OPERATOR`(운전원 거부)로 닫힌다. 상급자 확인으로 넘기지 않는다(가장 좁은 해석 — 아래 "사용자 확인 필요").
- **화면 이름은 실라버스 표기**: 설비 결함 인지 · 조치 / 정기 정비 / 예비품 구매. 버튼 [정기 점검] → [정기 정비], [재고 보충] → [예비품 구매](process 쪽 값. 포털 글자는 포털 작업자 몫 — 아래).
- **수업용 비정상 입력은 원인 쪽**: 결과 값을 넣지 않는다. plant-sim(팬 구동부 고장 · 정비 불량)과 enterprise-sim(공급사 납기 지연 통보)에 원인을 주고 흐름이 실제 판정으로 그 결말에 이른다.
