# 실라버스가 포털을 덜 쓰는 곳 — 실라버스 수정 참고 (2026-10-10 밤)

사용자 지적: "포털에서 똑같이 따라 만들면 되는데 그걸 안 하고 그냥 본다. 주어진 것에 비해 너무 안 하고 있다(체험처럼 되어 있다)."
기준 실라버스: 사용자가 준 `피지컬ai_실라버스_최종.xlsx`(통합반 온라인 44H 시트). 포털 메뉴는 `it/portal/www/index.html:28-60`의 실제 문구(7묶음 24개).
이 문서는 코드 조사와 10-10 작업 기록에 근거한다. **화면에서 직접 눌러 확인한 것이 아니다** — 표의 "확인" 칸을 본다.

## 1. 전체 패턴

- 이론 시간은 HYD 포털 화면을 "보여 주고 읽는다", 랩 시간은 HYD와 분리된 작은 예제를 Claude Code로 만든다.
- 그 결과 학생이 HYD 본 시스템을 자기 손으로 다루는 것은 9~10일차의 「흐름 가져오기」와 「내 작업함 · 처리 건」뿐이고, 그것도 정답과 같은 흐름을 한 번 올려 실행하는 데 그친다.

## 3. 흐름을 따라 만들면 실제로 그 흐름이 도는 이유 (9일차의 근거)

- 경보가 오면 `flow_deploy.route_definition`이 그 패턴을 받는 **배포된 학생 흐름**을 먼저 찾고(여럿이면 가장 최근에 배포한 것), 없으면 기준 흐름을 연다(`it/process/procsvc/flow_deploy.py:3-9, 57-64`).
- 수업용 A · B · C 흐름도 같은 가져오기 → 등록 → 배포 경로로 올라간다(`scripts/c3_flows.py deploy`). 학생이 같은 흐름을 같은 연결로 배포하면 버튼 → 경보 → 그 학생 흐름의 처리 건 → 에이전트 → 승인 → 설비 명령 → 재확인까지 같다.
- "기준 흐름으로 되돌리기"는 학생 흐름을 경보 경로에서 내린다(등록본은 남음). 경보 패턴별로 지금 어느 흐름이 여는지 보는 표가 있다(`routes`).
- 주의: 한 시스템을 여럿이 같이 쓰면 마지막에 배포한 사람의 흐름이 경보를 가져간다. 손으로 그린 사본으로 A를 끝까지 돌린 기록은 아직 없다. 포털 가져오기 화면에 시스템 부품 설정 칸이 없어 포털만으로는 연결을 끝내지 못한다(NOW 3.2).
- 설비와 무관한 개인 흐름은 경보가 아니라 **직접 시작**(시작 폼)으로 연다.

## 4. 같은 식으로 올릴 수 있는 자리 (시나리오는 0.2의 단순한 흐름 그대로)

- 3 · 7일차: 조치 판단 규칙과 손익 · What-if에서 값을 직접 바꿔 추천이 달라지는 것 확인
- 4일차: 기준 매뉴얼을 지식 관리에 똑같이 등록해 추출 · 검토 · 적재까지 직접
- 5일차: 기준 에이전트와 같은 에이전트를 포털에서 직접 만들어 질문하고 시험 비교로 기준과 대조
- 6일차: 기준 MCP 서버를 도구 메뉴에 직접 등록해 써 보고 내 에이전트에 붙이기
- 8~10일차: 따라 만들기는 짧게, 흐름을 바꿔 배포 → 기준과 비교 → 되돌리기, 사전 검사에 걸리는 흐름을 일부러 올려 고치기
- 이렇게 하면 9일차에 "내가 만든 에이전트 · 내가 등록한 도구 · 내가 넣은 지식"을 붙여 돌리게 된다.

실라버스에 넣기 전에 「시험 비교」「판단 채점」「손익 · What-if」「데이터 연결」「오일 분석 입력」이 학생 손으로 어디까지 되는지 화면에서 확인한다. 같은 폴더의 `syllabus-gap.md`는 "실라버스가 요구하는데 시스템에 없는 것" 조사(반대 방향)이며, 그 묶음 2(정비 · 구매를 실라버스 모양으로)는 NOW 0.2의 결정으로 폐기됐다.
