## 4. 업무 프로세스 흐름도 — 실제 정의에서 그리기 (B6)

### 4.1 입력과 레인
- 입력: 처리 건 상세 API가 돌려주는 `definition`(`/api/instances/{id}` → `view.definition`; `instances.js:299-305`가 이미 `activities·sequences·events·gateways`를 받음) + `workitems`. 정의 v2.2(`it/process/definitions/anomaly_response_v22.json`): 활동 9, 이벤트 4(`ev:alert` 시작 · `ev:select-timeout` 경계 타이머 · `ev:closed`·`ev:escalated` 종료), 게이트웨이 2(`gw:control`, `gw:recovered`), 흐름 15.
- 레인 결정 규칙(역할 endpoint 접두로): `sys:agent` → **에이전트**; `role:*` → **담당자**; `sys:scada`·`sys:process`·`sys:cmms` → **시스템**. 시작 이벤트(경보 수신)는 시스템 레인 칸 이름 "설비 경보", `task:command`는 "설비에 명령", `task:reobserve`는 "효과 확인". 온톨로지는 레인 아님(정의에 노드 없음 → 아무것도 안 그림). 층 번호 없음.
- 노드 표시 이름(정의 `name`은 바꾸지 않고 UI 표에서 번역): `원인 진단 / 조치 후보 조회 / 규정 검토 / 우선순위 · 카드 작성`(→`조치 후보 정리`) / `조치 카드 선택 (HITL)`(→`조치 선택`) / `상급자 호출`(→`책임자 확인`) / `PLC 명령 발행`(→`설비에 명령`) / `재관측 (15분)`(→`효과 확인 (15분)`) / `정비 작업지시`(→`정비 요청`) / `경보 수신`(→`설비 경보`) / `선택 시간 초과` / `종결` / `에스컬레이션 종료`(→`책임자 확인으로 종료`). 게이트웨이 라벨 `즉시 제어 포함?`→`설비 제어가 있나?`, `회복?`→`회복됐나?`. 흐름 라벨 `선택 스킬 kind == control`→`설비 제어`, `== work_order`→`정비 요청만`, `TS1 < 55 and 경보 해제`→`회복`, `미회복`.
- 상태 덧칠: `workitems`의 최신 세대 상태 → `hydSteps.stepStateOf`(`instanceSteps.js:10-15`)로 done/current/skipped; 색은 R4(완료 초록·진행 중 파랑·건너뜀 회색·실패 빨강).
