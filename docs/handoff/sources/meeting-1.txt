데이터패브릭이 뭐야?


데이터 패브릭(Data Fabric)은 여러 시스템에 흩어진 데이터를 찾아서 연결하고, 권한과 품질을 관리하면서 함께 사용할 수 있게 만드는 데이터 통합·관리 체계입니다. 특정 데이터베이스나 프로그램 하나를 뜻하는 것이 아니라, 여러 기술을 조합하는 아키텍처, 즉 설계 방식입니다. [IBM](https://www.ibm.com/think/topics/data-fabric)
쉽게 비유하면, 여러 도서관의 책을 한 건물로 옮기는 대신, 통합 목록·대출 창구·이용 규칙을 마련해서 함께 이용할 수 있게 만드는 것과 비슷합니다.
예를 들어 다음처럼 자료가 나뉘어 있다고 하겠습니다.
담당자가 이렇게 묻습니다.
“부대별 정원과 현원을 비교해서 인원이 부족한 부대를 보여줘.”
각 시스템이 따로 운영된다면, 담당자나 개발자가 시스템별로 자료를 가져오고, 부대 코드를 맞추고, 기준일이 같은지 확인한 뒤 결합해야 합니다.
데이터 패브릭은 이런 작업에 필요한 연결과 관리 기능을 공통 기반으로 마련하는 것입니다. 새로운 보고서나 AI 에이전트를 만들 때마다 데이터 연결부터 제각각 다시 만들지 않도록 하는 것이죠. 단순히 연결만 하는 것이 아니라, 데이터 목록·접근 권한·품질 관리까지 함께 다룹니다. [IBM](https://www.ibm.com/think/topics/data-fabric)
대표적으로 다음 기능들을 갖춥니다. 핵심은 데이터 자체뿐 아니라, 데이터를 설명하는 정보인 ‘메타데이터’를 활용해서 관리한다는 것입니다. [SAP](https://www.sap.com/resources/what-is-data-fabric)
이런 정보를 한 번 문서로 작성하고 끝내는 것이 아니라, 데이터 구조나 사용 상황의 변화에 맞춰 갱신하고 연결·통제·품질 관리에 활용하는 것이 중요합니다. [IBM](https://www.ibm.com/think/topics/data-fabric)
원문에 나온 **“있는 자리에 둔 채 연결해서 하나의 창구로 조회한다”**는 설명은 데이터 패브릭의 구성 기술인 데이터 가상화에 더 가깝습니다. 데이터 가상화는 원본을 모두 별도 저장소로 복제하지 않고도, 여러 데이터 소스를 통합된 모습으로 조회하게 해주는 방식입니다. [IBM](https://www.ibm.com/think/topics/data-fabric)
데이터 패브릭이 데이터 이동이나 복제를 금지하는 것은 아닙니다. 필요에 따라 원본을 직접 조회할 수도 있고, 일부 데이터를 분석용 저장소로 가져오거나 변경분을 동기화할 수도 있습니다. 실제 데이터 패브릭 구현은 가상화뿐 아니라 배치 처리, 스트리밍, 변경 데이터 캡처 같은 방식을 함께 사용합니다. [IBM](https://www.ibm.com/solutions/data-fabric?utm_source=chatgpt.com)
따라서 이렇게 이해하는 것이 정확합니다.
“데이터를 절대 옮기지 않는다”가 아니라, “모든 데이터를 한곳으로 옮기는 것을 전제로 하지 않고, 목적에 맞는 방식으로 연결하고 관리한다.”
또한 “모든 것을 SQL 하나로 조회한다”가 필수 조건도 아닙니다. 데이터 제공 방식은 SQL일 수도 있고 API일 수도 있습니다. 공통된 접근·관리 체계를 갖추는 것이 핵심이지, 모든 인터페이스를 SQL로 통일하는 것이 핵심은 아닙니다. [IBM](https://www.ibm.com/think/insights/data-fabric-architecture)
역할을 나누어 이해하면, 카탈로그는 ‘어떤 데이터가 어디에 있는지 알려주는 목록’, **온톨로지는 ‘업무 개념과 그 관계를 명시한 지식 모델’**입니다. 데이터 패브릭은 이런 기능을 데이터 연결·보안·품질 관리와 결합해 활용하는 더 넓은 체계입니다. 그래서 넓은 의미의 데이터 패브릭에는 시맨틱 모델이나 지식 그래프도 포함될 수 있습니다. [SAP](https://www.sap.com/resources/what-is-data-fabric)
올려주신 설명에서는 이해를 돕기 위해 ‘데이터 연결’과 ‘온톨로지’를 별도 층으로 나누어 설명한 것으로 보면 됩니다. 다만 데이터 패브릭을 단순한 DB 연결 창구로만 이해하면 범위를 너무 좁게 잡게 됩니다.
결국 이 사업에서 데이터 패브릭을 구축한다는 것은, “DB를 하나 더 만드는 일”이라기보다 “기존 DB·문서·API의 데이터를 업무와 AI가 함께 찾아서, 권한에 맞게, 출처를 확인하며 쓸 수 있도록 기반을 만드는 일”입니다. [IBM](https://www.ibm.com/think/topics/data-fabric)
