# UI/UX 재설계 계약 — 2026-10-07 사용자 지시 (다음 세션의 주 작업)

## 사용자 지시 원문 요지(10-07 19:10)

- UI/UX는 **process-gpt를 따라가되 최신 레포 기준**으로 한다.
- "작업지시", "HITL" 같은 말은 화면에서 뺀다. 화면에는 **사용자에게 보여 줘야 하는 내용만** 있어야 한다.
- 지금 추가된 UI는 **조잡하고 정렬되어 있지 않고 카드 형식도 아니다**. 특히 **조치 판단 규칙**. 쓸데없는 것은 표시하지 말고 진짜 있어야 하는 것만 넣는다.
- **폼**도 예쁘게. **설비 이상 조치**(이상 확인·조치)도 정렬된 느낌이 없다.
- 기준은 "너의 기준"이 아니라 **너의 기준 + process-gpt 실제 레포 + 다른 서비스·홈페이지 디자인 조사**다.

## 추가 지시(10-07 19:30)

- **핵심만 깔끔하게.** 많은 것을 보여 주려 하지 않는다. 한 화면에 사용자가 지금 결정·확인해야 하는 것만 두고, 나머지는 펼침이나 다음 화면으로 보낸다.
- **폼은 섹션으로.** 입력을 의미 단위(예: 사건 정보 / 선택 / 사유·담당)로 나누어 제목을 붙이고, 라벨·입력·버튼의 세로 정렬을 맞춘다. 섹션 사이 간격은 일정하게.
- **참고 1순위는 Dify**(사용자: "Dify가 좀 이쁘긴 하더라"). 그렇다고 다른 것을 참고하지 말라는 뜻은 아니다 — process-gpt 최신 레포와 아래 프로세스·에이전트 서비스도 본다.

## 명칭 기준(10-07 19:40 사용자)

- **모든 기준은 일반인이다.** 백엔드의 이름(작업지시·todolist·HITL·인스턴스·에스컬레이션·재관측·generation·task:·ev:·L1~L9·cliagents)을 화면에 그대로 내보내지 않는다.
- 설명을 덧붙여 풀지 말고 **처음부터 명확한 표현**을 쓴다. 한 가지를 두 이름으로 부르지 않는다(todolist/할일 목록 같은 중복 제거).
- 명칭표는 새 세션이 화면별 제거·정렬 목록과 함께 만들어 사용자에게 보인다. 코드·API·DB의 이름은 바꾸지 않고 화면 문구만 바꾼다.

## 판정 기준(인수 조건)

1. 화면에 내부 용어가 없다: 작업지시·HITL·todolist·L1~L9·ev:*·task:*·cliagents·generation·lease 같은 말은 사용자 말로 바꾸거나 숨긴다(설명 문단·"실습 안내"·"실습 홈" 문구도 포함).
2. 모든 정보 단위가 **카드**(제목·핵심 값·상태 칩·한 줄 보조)로 정렬되고, 같은 화면 안의 카드는 같은 폭·같은 간격·같은 위계다.
3. 폼은 process-gpt의 폼(라벨 위·입력 아래·필수 표시·도움말 1줄·버튼 우하단)을 따른다. 입력이 2개 이하인 폼은 카드 안 인라인으로 줄인다.
4. 조치 판단 규칙 화면: 입력(설비·이상 패턴·조건 3개)과 결과(카드 순위)가 한 화면에 카드로 나오고, 설명 문단·"실제 값" 같은 내부 표현이 없다.
5. 이상 확인·조치 화면: 설비 3기 카드가 같은 높이로 정렬되고, 선택한 설비의 조치 과정이 시간순 카드 목록으로 보인다. 빈 상태 문구는 한 줄.
6. 사용자가 캡처를 보고 "됐다"고 해야 완료다. 기계 검사(콘솔 오류 0·overflow 0)는 전제 조건일 뿐 완료가 아니다.
