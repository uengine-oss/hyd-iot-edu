## SLIDE 06 — 남은 일을 맡는 쪽과 순서
### 화면 내용
- 유형: 흐름
- 아이콘: user-check, send, eye, tool, file-text
- 메시지: 남은 일은 운전원, SCADA, CMMS처럼 서로 다른 쪽이 맡으며, 저마다 앞의 결과를 받아야 시작할 수 있다.
- 요소:
  1. 승인 | 운전원 / 추천안을 검토해 / 승인하거나 거절한다
  2. 냉각 명령 | SCADA / 승인된 조치대로 / PLC에 명령을 보낸다
  3. 재관측 | process 서비스 / 유온이 55 ℃ 미만으로 / 회복했는지 판정한다
  4. 작업지시 등록 | CMMS / Computerized Maintenance / Management System / 정비를 작업지시로 등록한다
  5. 결과 보고 | process 서비스 / 처리한 내용과 / 결과를 정리해 알린다
- 노트: 남은 다섯 가지를 누가 하는지 보겠습니다. 승인은 운전원이, 냉각 명령은 SCADA가, 재관측과 결과 보고는 process 서비스가, 작업지시 등록은 CMMS가 맡습니다. CMMS는 Computerized Maintenance Management System, 곧 설비 보전 관리 시스템입니다. 다섯 가지는 맡는 쪽이 서로 다르고, 앞의 일이 끝나야 다음 일을 시작할 수 있습니다.
### 화면 구성
다섯 칸 흐름. 칸의 첫 줄이 맡는 쪽이다.
### 제작 기준
[기록] 단계별 담당(`role:operator` · `sys:scada` · `sys:process` · `sys:cmms`): 사실표 3.2 「같은 처리 건의 단계 표」. 회복 판정 기준 `TS1 < 55.0`: 사실표 4.6. [일반] CMMS의 정식 명칭(점검 뒤 풀네임을 화면의 칸에도 붙였다). 새 용어: CMMS.

## SLIDE 43 — 실행 상태: 처리 건의 상태와 단계의 상태

- 요소:

## SLIDE 44 — COMPLETED는 성공을 뜻하지 않는다
### 화면 내용
- 유형: 비교
- 아이콘: circle-check, ban
- 메시지: 거절로 닫힌 처리 건도 상태는 COMPLETED이므로, 업무의 결과는 닿은 끝 이벤트와 결과 보고의 내용으로 판단한다.
- 요소:
  1. 승인된 처리 건 | status: COMPLETED / end_event: E_end / 결과 보고: 정상 / 설비 명령: CMD-1010-0001-01d1 / 회복에 미달해도 end_event는 E_end이고 결과 보고가 미달로 달라진다 | 끝
  2. **거절된 처리 건** | status: COMPLETED / end_event: E_rejected / 결과 보고: 거절(기록의 값은 반려) / 설비 명령: 없음 / 냉각 명령, 재관측, 작업지시 등록은 CANCELLED | 거절 종결
- 노트: 같은 정의에서 나온 두 처리 건입니다. 왼쪽은 승인되어 설비 명령이 나갔고, 오른쪽은 거절되어 설비 명령이 없으며 결과 보고의 값은 거절을 뜻하는 반려로 적혔습니다. 그런데 두 건의 상태는 똑같이 COMPLETED입니다. COMPLETED는 실행이 끝났다는 뜻일 뿐이어서, 업무가 어떻게 끝났는지는 닿은 끝 이벤트와 결과 보고로 읽어야 합니다. 승인된 뒤 회복에 미달한 경우도 끝 이벤트는 같으므로 결과 보고가 정상인지 미달인지를 봅니다.
### 제작 기준
[기록] 승인 경우(`COMPLETED` · `E_end` · 정상 · `CMD-1010-0001-01d1` · `WO-1010-1198`)와 거절 경우(`COMPLETED` · `E_rejected` · 단계 이름 「결과 보고: 거절」, 결과 값 반려 · 설비 명령 0건 · `T_cmd` · `T_reobs` · `T_wo` `CANCELLED`): 사실표 2.2 표와 「함정」 항목. 정상과 미달이 같은 끝 이벤트 `E_end`로 간다: 같은 항목(화면에는 01단원의 완료 조건 표에 미달의 닫힘이 있다).

승인 지연은 비중단형 타이머이고 발생 뒤에도 승인 단계는 `IN_PROGRESS`, 자동 취소 · 자동 거절 없음: 사실표 2.2 · 3.2. 본문의 「승인을 받는 자리의 그림」 · 「토큰이 둘이 되는 순간」 장으로 풀린다.

## SLIDE 64 — Quiz 2. 설비 명령이 나갔는지를 판단하는 근거
### 화면 내용
- 유형: 문답
- 메시지: 어느 긴급 대응 처리 건의 기록에 status는 COMPLETED, end_event는 E_rejected로 적혀 있다.
- 문장: 이 처리 건에서 냉각 명령이 설비에 나갔는지를 판단한 것으로 옳은 것은?
- 요소:
  1. 끝 이벤트가 E_rejected이고 냉각 명령 단계가 CANCELLED이므로 나가지 않았다
  2. status가 COMPLETED이므로 명령이 나가 유온이 회복되었다
  3. 에이전트 단계가 DONE이므로 추천대로 명령이 나갔다
  4. 기록으로는 알 수 없으므로 에이전트에게 다시 판단을 맡긴다
- 노트: 어떤 기록을 근거로 삼아야 하는지를 구분하는 문항입니다. 처리 건의 상태가 말해 주는 것과 끝 이벤트와 단계의 상태가 말해 주는 것을 나누어 생각해 보시기 바랍니다.
### 제작 기준
거절 경우: `COMPLETED` · `E_rejected` · 설비 명령 0건 · `T_cmd` `CANCELLED`: 사실표 2.2. 본문의 「COMPLETED는 성공을 뜻하지 않는다」 · 「실행 상태」 장으로 풀린다.

## SLIDE 65 — Quiz 3. 냉각 명령을 시작시키는 쪽
### 화면 내용
- 유형: 문답
- 메시지: 에이전트가 팬 최대 운전을 권하는 추천안을 제출했고, 처리 건은 운전원 승인에서 기다리고 있다.
- 문장: 운전원이 승인했을 때 냉각 명령 작업을 여는 것은?
- 요소:
  1. 추천안을 제출한 에이전트
  2. 명령을 받아 PLC에 전하는 SCADA
  3. 승인한 운전원
  4. 프로세스 엔진
- 노트: 누가 무엇을 맡는지, 책임의 경계를 묻는 문항입니다. 추천하는 쪽, 결정하는 쪽, 다음 작업을 여는 쪽이 각각 누구였는지를 떠올려 보시기 바랍니다.
### 제작 기준
명령 단계는 승인 단계가 승인으로 끝난 뒤에만 열리고(조건 선 `approval == '승인'`), 다음 단계를 여는 것은 엔진이다: 사실표 2.2 · 4.4. 본문의 「프로세스가 에이전트 밖에서 보장하는 것」 · 「프로세스 엔진과 오케스트레이션」 장으로 풀린다.
