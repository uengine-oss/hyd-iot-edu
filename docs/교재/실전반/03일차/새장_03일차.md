## SLIDE [N4] — 예시 인스턴스의 적재와 문서 인제스천의 차이
### 화면 내용
- 유형: 비교
- 아이콘: database-import, file-import
- 메시지: 직접 넣은 인스턴스와 달리 문서에서 들여온 지식은 근거 원문과 검토 기록이 남아야 판단의 근거로 쓰인다.
- 요소:
  1. 2일차의 예시 인스턴스 적재 | 넣는 것: 설계한 스키마에 맞춰 사람이 정리한 예시 인스턴스와 관계 / 넣는 방법: Cypher 문으로 그래프 DB에 직접 적재한다 / 확인: 저장된 노드와 관계가 설계한 것과 같은지 조회해 본다 / 내용이 어디에서 왔는지는 넣은 사람이 안다 | 직접 정해 넣는다
  2. **문서 인제스천** | 넣는 것: 매뉴얼 원문에서 추출한 지식 후보 / 넣는 방법: 스키마와 식별자에 맞추고 원문 대조, 사람 검토, 승인을 거친 것만 적재한다 / 확인: 지식마다 근거가 된 원문 구간과 검토한 사람이 기록된다 / 손으로 옮기면 느리고 빠뜨리며 개정 때마다 되풀이되므로 정해진 과정으로 둔다 | 검토해 출처와 함께
- 노트: 그래프 DB에 넣는다는 점은 같지만 넣는 것과 남는 것이 다릅니다. 왼쪽은 2일차에 한 일로, 설계한 스키마에 맞춰 직접 정리한 예시 인스턴스를 Cypher로 넣고 저장된 결과가 설계와 같은지를 조회해 확인했습니다. 오른쪽은 사람이 정리한 목록이 아니라 매뉴얼 원문이 입력이며, 추출한 후보를 원문과 대조하고 사람이 검토해 승인한 것만 넣습니다. 맨 아래 줄을 견주면 왼쪽은 내용의 출처를 넣은 사람만 알고, 오른쪽은 근거가 된 원문과 검토한 사람이 지식과 함께 남습니다. 이 차이를 만드는 것이 이어서 볼 일곱 단계입니다.
### 화면 구성
두 칸 비교. 칸마다 넣는 것, 넣는 방법, 확인의 세 줄을 같은 순서로 두고 넷째 줄에 출처와 과정에 관한 한 줄. 오른쪽 강조.
### 제작 기준
실전반 3일차 실라버스의 「2일차 샘플 인스턴스 적재와 본격 문서 인제스천의 차이를 구분한다」. 왼쪽의 사실은 실전반 2일차 실라버스의 실습 두 항목(「schema.json, 인스턴스 노드/관계 목록을 작성」「생성한 스키마 · 인스턴스에서 Cypher를 작성하여 교육용 Neo4j에 적재 · 조회, 수동 모델링 결과와 저장된 노드 · 관계가 일치하는지 확인」)의 범위 안에서만 썼다. 오른쪽은 통합반 4일차 덱의 일곱 단계(추출 → 매핑 → 대조와 사람 검토 → 승인된 지식 적재)와 사실표 4.1 · 4.3(인용, 검토자 기록)이다. 넷째 줄은 통합반 4일차 「문서를 지식으로 옮기는 일을 과정으로 정해 두는 이유」 장(느리다 · 빠뜨린다 · 되풀이된다)을 한 줄로 받았다. 「인용」「적재 기록」은 뒤 장에서 처음 세우는 용어이므로 이 장에서는 풀어 썼다. 수치는 싣지 않았다. 「출처가 없다」는 단정은 쓰지 않았다.
