## SLIDE 53 — 결합한 두 가지: 표준의 예측 가능성과 에이전트의 자율성
### 화면 내용
- 유형: 비교
- 아이콘: sitemap, robot
- 메시지: BPMN만으로는 상황에 맞춘 판단이 어렵고 에이전트만으로는 순서와 책임이 보장되지 않아 둘을 함께 쓴다.
- 요소:
  1. BPMN 표준 | 순서, 책임, 갈림이 그림으로 정해진다 / 실행한 대로 기록이 남는다 / 정해 두지 않은 상황은 판단하지 못한다 | 예측 가능성
  2. AI 에이전트 | 지식과 값을 읽어 상황에 맞게 판단한다 / 같은 입력에도 과정이 달라질 수 있다 / 순서와 승인을 스스로 보장하지 않는다 | 자율성
- 노트: 제품이 결합했다는 두 가지를 견주어 보겠습니다. BPMN은 순서와 책임과 갈림을 그림으로 정해 두므로 예측할 수 있고 기록이 남지만, 정해 두지 않은 상황은 판단하지 못합니다. 에이전트는 상황에 맞게 판단하지만 순서와 승인을 스스로 보장하지 않습니다. 이 과정에서 쿨러 사건으로 본 것과 같은 이야기입니다. 그래서 판단은 에이전트 단계에 두고, 그 단계를 BPMN 프로세스 안에 놓습니다.

## SLIDE 57 — 실행 기록도 그래프의 일부: 실행 계층
### 화면 내용
- 유형: 관계도
- 메시지: 제품의 스키마는 프로세스 인스턴스와 워크아이템도 그래프의 노드로 두어, 실행된 일을 이름 붙은 관계로 적는다.
- 요소:
  1. 담당 | 사람 또는 / 에이전트 | 0,0
  2. **워크아이템** | WorkItem | 42,0
  3. 인스턴스 | Process / Instance | 86,0
  4. 작업 | 정의의 요소 | 42,100
  5. 프로세스 정의 | 설계도 | 86,100
- 연결: 워크아이템 > 담당 : ASSIGNED_TO ; 워크아이템 > 인스턴스 : IN_INSTANCE ; 워크아이템 > 작업 : EXECUTES ; 인스턴스 > 프로세스 정의 : INSTANCE_OF
