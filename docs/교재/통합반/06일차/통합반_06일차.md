## SLIDE 09 — 스킬이 놓이는 자리: 작업 폴더의 스킬 폴더
### 화면 내용
- 유형: 코드
- 메시지: 스킬은 이름과 같은 폴더에 든 SKILL.md 한 파일이며, 실행이 시작될 때 에이전트의 작업 폴더에 놓인다.
- 코드: 작업 폴더 /   context/ /     task.json /   .claude/skills/ /     cooling-emergency-response/ /       SKILL.md /   output/ /     result.json
- 요소:
  1. 작업 폴더 | 에이전트가 한 번의 실행 동안 쓰는 전용 폴더이다.

  3. **스킬 폴더** | 배정된 스킬이 폴더째 놓인다. 폴더 이름이 곧 스킬 이름이다.
  4. output/result.json | 에이전트가 결과를 써 넣는 파일이다.
- 노트: 스킬이 실제로 놓이는 자리입니다. 에이전트는 실행마다 작업 폴더 하나를 받고, 그 안에 이번 일의 입력과 배정된 스킬과 결과를 쓸 자리가 있습니다. 쿨러 경보의 실행 기록은 「배정된 스킬 1개를 작업 폴더에 넣고 실행합니다」라는 줄로 시작합니다.
### 화면 구성
왼쪽 폴더 구조, 오른쪽 짚을 점 넷. 스킬 폴더를 강조한다.
### 제작 기준
[기록] 작업 폴더의 구성(`context/task.json` · `.claude/skills/cooling-emergency-response/SKILL.md` · `output/result.json`): 사실표 5.1.2 기록 ②, 6.1.1 (나). 실행 기록의 첫 줄 「배정된 스킬 1개를 작업 폴더에 넣고 실행합니다: cooling-emergency-response」: 사실표 5.1.2 기록 ①(11:13:09). 작업 폴더의 다른 파일과 스킬 본문의 보관 위치는 싣지 않았다. 새 용어: 작업 폴더.

## SLIDE 10 — SKILL.md 원문 ①: 머리말과 요약
### 화면 내용
- 유형: 코드
- 메시지: SKILL.md는 이름과 쓰임을 적은 머리말로 시작해, 맡는 일과 그 범위의 한계를 밝히는 요약으로 이어진다.
- 코드: --- / name: cooling-emergency-response / description: 쿨러 과열 경보 — /   원인 진단 · 냉각 조치 카드 / --- /  / # 냉각 긴급 대응 /  / 쿨러 과열 경보(COOLER_DEGRADATION) 한 건에서 / 원인을 진단하고, 냉각 조치 후보를 비교해 / 추천 카드 한 장과 지는 대안을 올린다. / 승인 전에는 조회 · 계산만 한다. / 설비 명령은 사람 승인 뒤 시스템이 낸다.
- 요소:
  1. name | 스킬의 이름이다. 폴더 이름과 같다.
  2. **description** | 어떤 경우에 쓰는 스킬인지를 한 줄로 적는다.

  3. **시간이 넘었다** | 정해진 시간 안에 응답하지 못해 / 오류로 돌아온다 | 실패로 적는다
  4. 응답이 잘렸다 | 본문의 일부만 오거나 / 본문이 전달되지 않는다 | 읽지 못한 범위를 밝힌다
- 노트: 값이 없는 것과 조회에 실패한 것은 에이전트의 멈춤 조건에서 이미 구분했고, 위의 두 줄이 그것입니다. 도구를 연결해 쓰면 경우가 둘 더 생깁니다. 정해진 시간 안에 응답하지 못한 호출은 오류로 돌아오므로 실패로 적고, 응답이 잘렸을 때는 읽지 못한 범위를 밝힙니다. 어느 경우에도 0이나 빈 값으로 바꾸어 적지 않습니다.
### 화면 구성
표 한 장. 셋째 행을 강조한다.
### 제작 기준
[저장소] 응답 봉투 `{"result": "ok", "document": …}` / `{"result": "error", "error_kind": …, "message": …}`, 지시 「조회 실패와 값 없음을 구분합니다」 「실패를 0이나 빈 값으로 바꿔 성공처럼 제출하지 않습니다」: 사실표 5.2.3 「도구 호출이 실패한다」 · 6.2.2. 호출과 조회에 시간 제한이 있고 넘으면 실패로 돌아온다, 큰 결과는 잘리거나 본문이 전달되지 않는다: 사실표 6.3.4(한도의 수치와 포털 쪽 표기는 깊이의 상한을 넘어 싣지 않았다). 멈춤 조건 자체는 5일차가 가르쳤고 여기서는 응답의 구분만 다룬다.
