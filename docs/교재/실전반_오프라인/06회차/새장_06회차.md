## SLIDE [N7] — 실습에서 살펴보는 실패와 보완하는 명세
### 화면 내용
- 유형: 흐름
- 아이콘: bug, file-text, tool, player-play
- 메시지: 계약이 바뀌어 생긴 실패를 먼저 보고 명세를 보완하면, 긴급 조건을 더한 뒤에도 기존 출력과 승인 기준이 그대로 남는다.
- 요소:
  1. 실패를 살펴본다 | 출력 계약이 바뀐 예에서 / 뒤 단계가 결과를 / 읽지 못하는 것을 본다
  2. **명세를 보완한다** | spec.md에 긴급 조건과 / 지킬 출력, 승인 기준을 / 적는다
  3. 명세대로 고친다 | 기존 일반 정비 요청에 / 긴급 요청 조건을 / 더한다
  4. 다시 실행한다 | 일반 요청과 긴급 요청을 / 실행하고 입력과 / 기대 결과를 남긴다
- 노트: 셋째 실습에서는 기존의 일반 정비 요청에 긴급 요청 조건을 더합니다. 먼저 출력 계약이 바뀌었을 때 뒤 단계가 결과를 읽지 못하는 예를 살펴봅니다. 그런 다음 spec.md에 긴급 조건과 함께 지킬 출력과 승인 기준을 적고, 그 명세를 기준으로 고칩니다. 끝으로 일반 요청과 긴급 요청을 다시 실행하고, 그 입력과 기대 결과를 다음 실습의 검증에 쓰도록 남깁니다.
### 제작 기준
오프라인 6회차 실라버스의 실습 「새로운 요구사항을 추가해도 기존 기능 유지하기」(기존 일반 정비 요청에 긴급 요청 조건 추가, 계약 변화 예제로 실패를 살펴본 뒤 spec.md 보완, 기존 출력 · 승인 기준의 보존)다. 통합반 7일차의 넷째 · 다섯째 실습을 한 실습으로 합친 내용이어서 설명 장을 새로 썼다. 한쪽 계약만 바꾸면 맞은편이 읽지 못한다는 사실은 본문의 「계약」 장이 세운다.
