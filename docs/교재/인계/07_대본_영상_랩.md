## 2. 사용자가 정한 것

### 대본
- 강사는 화면을 보지 않고 대본만 읽는다. 그래서 화면의 요소(이름, 정의, 값, 예)가 모두 말에 들어 있다.
- 시간의 기준은 **회차(일차)의 합이 4시간**이다. 실라버스의 행마다 분을 맞추지 않는다. 도입 · 핵심 정리 · 퀴즈 · 실습 연결 멘트는 실라버스에 자리가 없어 이론 대본을 줄여 흡수했다(지침의 「분량」 절).
- 영문 · 숫자 이름은 그대로 읽고 앞에 무엇인지 붙여 말한다(「유압 설비 HYD-01」).
- 덱과 대본에서 실습 도구의 이름을 되풀이하지 않는다. 「바이브 코딩으로 …」라고 말하고, 도구 이름은 통합반 1일차의 도구 소개 한 곳에만 있다(`04_결정_기록.md`).

### 윤문
- 1차: 글로 쓴 티를 벗기고 사람이 말하는 투로. 내용 · 숫자 · 이름은 그대로, 길이는 비슷하게.
- 2차: **내용을 더하지 않고** 이미 있는 말과 말 사이가 자연스럽게 이어지게. 그만큼 4~5%쯤 길어져도 된다. 억지로 늘리지 않는다(이을 데가 없는 장은 그대로여도 된다). 모자라는 시간은 실습 영상에서 채운다.
- 모델은 gpt-6-astra. **윤문은 1차 · 2차 모두 OpenAI API 키로 부른다.** 11일치의 2차 윤문본은 Codex(ChatGPT 계정)로 만들었으나, 그 뒤로 Codex는 쓰지 않기로 했다. 도구는 API 키를 쓰도록 고쳤고, 고친 뒤로 API를 실제로 불러 보지는 않았다(윤문이 끝나 부를 일이 없었다).
- **윤문할 때 영상의 경계를 알려 준다.** 영상은 실라버스 행마다 따로 재생된다. 처음에는 장마다 「앞 장의 끝」만 주고 이어 달라고 했더니, 영상의 첫 장이 앞 영상의 말을 받아 「그럼 첫 번째 단원은…」으로 시작했다. 지금은 장마다 그날의 영상 목록, 이 장이 어느 영상의 몇 번째 장인지, 같은 영상 안의 앞뒤 장을 주고, 영상의 첫 장에는 앞 장의 글을 주지 않는다. 영상의 첫 문장이 「그럼 · 그러면 · 그래서 · 자 · 이제 · 이어서」로 시작하면 검사에서 떨어진다(`윤문2.py`의 `day_frame` · `frame_text`).
- 책임자는 영상을 끝까지 다 볼 수 없다. 영상을 만들기 전에 글에서 잡을 수 있는 것은 글에서 잡는다(모든 영상의 첫 문장과 마지막 문장을 뽑아 읽기 등).

### 음성과 영상
- 음성 합성은 ElevenLabs만 쓴다. **모델은 `eleven_v4`로 고정**한다. 구형 모델(`eleven_multilingual_v2`)에 빠르기 설정을 건 음성은 목소리가 무너져 버렸다.
- 목소리는 강사의 복제 음성이다. 음성 ID는 `강의영상.py`의 기본값에 있다.
- `eleven_v4`에는 빠르기 설정이 없다. 모델이 읽은 음성을 그대로 두고, **쉼만 자연스럽게 보탠다**: 문장 사이마다 이어 말할지 쉴지를 정해(잇는다 · 짧게 · 한 호흡 · 크게) `video_lecture/쉼_저장/`에 적어 두고, 그 자리에 0.15 · 0.45 · 0.8초를 더한다. 물음표 뒤는 적어도 0.5초, 문단 사이는 적어도 0.4초, 장이 넘어갈 때는 1.2초.
- 쉼을 늘려 배정 시간에 억지로 맞추지 않는다(2~4초짜리 쉼이 생겨 어색했다).
- **절대 규칙: gpt-6-astra(OpenAI)는 윤문에만, OpenAI API 키로만 쓴다(Codex 계정으로 부르지 않는다).** 영상 제작, 쉼 판단, 검증, 정리 등 나머지는 모두 작업하는 세션(Claude)이 한다. 비용이 많이 나와서 정한 규칙이다. 1일차의 쉼 단계는 gpt-6-astra가 정했지만, 그 뒤로 영상 도구는 OpenAI를 부르지 않는다. 2일차부터 쉼 단계는 작업하는 세션(Claude)이 대본을 읽고 정해 적는다. 윤문은 11일치가 끝났으므로 지금은 OpenAI를 부를 일이 없다.
- 영상은 사용자가 범위를 정해 준 만큼만 만든다. 음성 생성에는 크레딧이 든다.

### 랩
- 학생의 도구는 VS Code의 GitHub Copilot 채팅이다. 세팅은 따로 있는 세팅 가이드가 맡는다.
- 핸즈온 가이드는 오프라인 수업 전용이다. 온라인은 강사 시연과 완성본으로 한다.
- 그 밖의 기준은 `lab/만드는_법.md`에 있다.
- **2026-10-13에 더해진 기준.** 오프라인 실습은 학생마다 모델 접속 정보를 받는다. 랩의 에이전트는 그 모델(사내 서버, OpenAI 호환)을 실제로 부른다. 핸즈온 가이드는 학생이 길을 잃지 않게 길잡이가 분명해야 하고, 실습을 진행하는 데 필요한 내용만 담는다(설계의 까닭을 길게 풀거나 만드는 사람에게 하는 말을 넣지 않는다).
- **일하는 순서.** 방식은 먼저 제안하고 승인받은 뒤에 한다. 하나를 만들어 확인받고, 30%쯤으로 넓혀 다시 확인받고, 그다음 전체로 간다. 여러 묶음을 한꺼번에 고치지 않는다. 완성본은 만드는 쪽이 끝까지 도는 것을 확인하면 되고, 모델 호출과 작업자는 필요한 만큼만 쓴다.

## 3. 도구를 쓰는 법

모두 저장소 루트에서 실행한다. 키는 저장소 밖의 파일에 두고 `--env`로 넘긴다(`OPENAI_API_KEY`, `ELEVENLABS_API_KEY`). 저장소의 `.env`는 쓰지 않는다.

```
# 1차 윤문 (OpenAI API)
python3 video_lecture/윤문.py docs/교재/통합반/02일차/통합반_02일차_대본.md --env <키 파일>

# 2차 윤문 (OpenAI API)
python3 video_lecture/윤문2.py --env <키 파일> docs/교재/통합반/02일차/통합반_02일차_대본_윤문.md [--slides 첫장 끝장]

# 강의 영상: <일차> <첫 장> <끝 장> <목표 초, 0이면 맞추지 않음> <출력 폴더>
python3 video_lecture/강의영상.py 01 4 14 0 <출력 폴더> --polished2 --breath \
  --pause-short 0.15 --pause-mid 0.45 --pause-long 0.8 --pause-question 0.5 --pause-para 0.4 --gap 1.2 --env <키 파일>
```

- `윤문2.py`는 `--env` 파일의 키로 OpenAI API(gpt-6-astra)를 부른다. 통과하지 못한 장은 1차 윤문본을 그대로 두고 보고 파일에 까닭을 남긴다.
- `강의영상.py`는 PPTX를 LibreOffice로 PDF, `pdftoppm`으로 그림으로 바꾸고, 장마다 음성을 뽑아 `video_lecture/음성_저장/`에 둔다(글 · 음성 · 모델이 같으면 다시 뽑지 않는다). 쉼의 자리는 `video_lecture/쉼_저장/`에서 읽는다(장마다 파일 하나, `"쉼"`에 사이 자리마다 0~3). 적히지 않은 장이 있으면 `"쉼": null`인 파일을 만들어 두고 멈추니, 그 파일을 채운 뒤 다시 돌린다. 출력 폴더에는 영상(mp4)만 두고, 자막과 길이 기록은 출력 폴더 옆의 `_작업/영상_자막_기록/`에 넣는다.
- 쉼의 길이만 바꿔 다시 만드는 것은 크레딧이 들지 않는다.

- **학생의 도구(Copilot)로는 한 번도 돌리지 않았다.** 완성본과 기록은 Claude Code로 대신 돌린 것이다. 규칙에 어긋나는 요청을 그 모델이 막는지도 모른다.
- 가이드의 사진 자리는 비어 있다(모두 197곳). 찍을 화면은 묶음마다 `찍어_주실_화면.md`에 있다.
- 시간은 추정이다. Windows에서 돌려 보지 않았다. 가이드의 단추 동작과 좁은 화면을 사람이 확인하지 않았다.
- 그래프 DB를 쓰는 두 묶음은 Neo4j 브라우저 화면에서 돌려 보지 않았다(cypher-shell과 HTTP로 확인했다).

## 5. 다음에 할 일

1. **1일차 영상은 만들었다.** 아홉 편, 합계 112.6분(이론 배정 110분). 2차 윤문본과 3절의 설정이다. 사용자가 듣고 확인하는 중이다. 영문 식별자(`REMOTE_AUTO`, `fan_pct`, `plant/hyd01/tag/TS1`, `ALT-hyd01-0014…`, `MITIGATED_BY`)를 음성이 어떻게 읽는지는 아무도 확인하지 못했다.
2. **2일차부터의 영상은 사용자가 범위를 말한 뒤에만 만든다.** 실라버스 행 하나가 영상 하나다. 행과 장의 대응은 각 대본 맨 위의 「이 일차의 구성」 표에 있다. 하루에 5,000 크레딧 안팎이 든다.
3. 영상을 만든 날은 실제 길이를 재어 4시간에서 넘치거나 모자라는 분을 실습 영상에 배분한다(1일차는 2.6분 넘친다).
4. 대본을 다 읽지 못하는 책임자를 위해 일차마다 핵심 내용을 한 장으로 정리한 페이지를 만들어 두었다(사용자에게 있다). 정리하면서 드러난 덱 · 대본 안의 어긋남은 그 페이지의 일차별 「알아 둘 것」과 각 대본 끝의 「제작 확인용」 절에 있다. 퀴즈는 11일 모두 대본이 보기를 읽지 않는다.
5. 실습 구간의 영상은 사용자가 직접 찍는다.
6. **랩: 새 기준의 첫 묶음(5회차 실습 2)을 사용자가 보고 있다.** OK가 나면 에이전트가 든 묶음(5회차 실습 3 · 4, 7회차 실습 2 · 3 · 4)부터 같은 식으로 고치고, 가이드 정리를 나머지로 넓힌다. OK 전에는 다른 묶음을 고치지 않는다. 5회차 실습 3 · 4는 실습 2의 이전 판에서 출발해 있어 지금은 이어지지 않는다.
6-1. 랩: 사진을 받아 가이드에 넣는다. 사용자가 Copilot으로 돌려 본 결과를 받아 가이드와 규칙 파일을 고친다.
7. 랩: 포털에서 하는 실습의 틀과 실전반 오프라인 랩을 만든다(4절의 「남은 것」).
8. 실전반: 통합반의 장을 가져온 덱이라 음성을 다시 쓸 수 있다. 통합반이 끝난 뒤에 계획한다.

## 6. 정해 주어야 하는 것

| 무엇 | 왜 열려 있나 |
|---|---|
| 학생이 쓸 「실습용으로 분리된 그래프 DB」의 주소 | 덱은 분리된 DB라고만 한다. 수업 스택의 그래프 DB에는 기준 지식이 들어 있고 학생이 넣는 것과 식별자가 겹친다. 두 묶음은 DB가 비어 있지 않으면 준비 단계에서 멈추게 해 두었다. 권고는 랩 전용 DB를 다른 포트(7475 · 7688)로 하나 더 띄우고 가이드의 주소를 그쪽으로 바꾸는 것이다 |
| 랩의 스키마 이름이 덱과 다르다 | 2회차 랩은 1회차 랩에서 이어받은 이름(`MEASURES`, `MOUNTED_ON`)을 쓰고 덱은 `OBSERVES`, `MONITORED_BY`로 설명한다 |
| 4회차 실습 3의 「판단 규칙」 | 덱은 판단 규칙까지 조회한다고 하나, 이어받은 후보에 규칙이 없어 랩에서 뺐다 |
| 6회차 랩의 중복 처리 | 덱은 「합치지 않고 표시」, 랩은 합친다 |
| 4회차 실습 4의 개정 값 | 덱은 「24시간이라는 기준이 바뀐다고 해 봅니다」까지만 말하고 새 값이 없다. 랩은 48시간으로 했는데 HYD나 덱의 값이 아니다 |
| 2회차 랩 스키마의 `USES_PART` 카디널리티 | 이어받은 스키마는 `1:N`, 저장소의 확정 스키마는 `N:M`이다. 2회차 실습 3의 완성본에 이 때문에 어긋남 한 건이 남고, 랩은 그것을 「스키마를 고쳐 달라는 요청이 막히는 것」을 보는 소재로 썼다 |
| 6회차의 MCP 서버 | 덱은 공개 서버 셋(파일시스템 · Git · 시간)이라고 하나 설치 방법이 저장소에 없다. 랩은 네트워크 없이 되도록 묶음 안에 파이썬으로 새로 쓴 서버를 쓴다 |
| 7회차 실습 4의 「오류를 수정」 | 실습 3의 완성본에 시나리오를 돌리니 프로그램의 어긋남이 한 곳도 나오지 않았다. 실패를 심지 않았고, 대신 사람의 승인 한 줄을 써 넣어 회귀 편이 실패하는 것을 보고 원인을 가리게 했다. 이것으로 충분한지 |
| 덱의 「모호한 한 문장이 기존 동작을 깨뜨린다」 | 7회차 랩에서 그 문장을 보내면 AI가 고치지 않고 되묻는 일이 잦았다. 학생의 도구에서도 그럴 수 있다 |
| 랩의 에이전트가 모델을 부르지 않는다 | **정해졌다: 모델을 부른다.** 5회차 실습 2는 고쳤다. 5회차 실습 3 · 4와 7회차 실습 2 · 3 · 4는 아직 모델 없이 도는 파이썬 프로그램이다 |
| 수업 문서 원문의 「교육용」 문구 | 매뉴얼 HM-8 원문에 그런 문구가 있다. 포털에 올리는 문서와 같아야 해서 랩에서도 고치지 않았다 |

## 7. 확인하지 못한 것

- 대본 본문은 대부분 작업자에게 나눠 써서, 전 장을 한 사람이 읽은 적이 없다. 자동 검사(숫자 · 이름 · 길이)와 일부 장의 확인만 했다. 덱 안의 어긋남은 각 대본 끝의 「제작 확인용」 절에 있다.
- 윤문본도 자동 검사만 거쳤다. 지어낸 설명이 끼어든 곳은 자동으로 잡지 못한다.
- 영상은 만든 세션이 들어 보지 못한다. 쉼의 분포를 `ffmpeg`의 `silencedetect`로 재어 견줬을 뿐이다.
- 음성 모델이 읽는 빠르기는 구간마다 다르다. 영문 이름과 숫자가 많은 장은 더 느리다.
