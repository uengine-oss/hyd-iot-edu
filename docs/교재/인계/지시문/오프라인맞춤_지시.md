# 오프라인 과정 덱: 과정 전체 맞춤 (회차 사이의 어긋남 고치기)

> 자리표시: `<저장소>`는 저장소 루트, `<작업 폴더>`는 저장소 밖의 임시 작업 폴더(본문의 「scratchpad」)다. 이 지시문이 쓰이는 단계는 같은 폴더의 `README.md`에 있다.

오프라인 과정의 회차 덱은 세 작업자가 회차 묶음을 나눠 **동시에** 만들었다. 그래서 묶음 사이에 서로 보지 못한 채 생긴 어긋남이 있다. 한 과정의 전 회차를 순서대로 보고 그것을 고친다. 모든 작업은 Opus로 한다(서브에이전트를 쓰지 않는다).

저장소: `<저장소>`. 덱: `docs/교재/<과정>_오프라인/NN회차/`(`조립.py`, `새장_NN회차.md`, `<과정>_오프라인_NN회차.md`, `.pptx`). 덱 MD는 `조립.py`가 통합반 덱(`docs/교재/통합반/0N일차/`)과 새장 원고에서 만든다 — **덱 MD를 직접 고치지 않는다.** 고칠 곳은 `조립.py`(가져올 장의 목록, 손질 목록)와 `새장_NN회차.md`뿐이다. 통합반 덱, 실전반 온라인 덱, 도구, 스킬 문서, 제작 기준은 고치지 않는다.

먼저 읽을 것: `docs/교재/기준/제작기준.md`(3 · 8절), scratchpad의 `오프라인쓰기_지시.md`, 그리고 각 묶음의 `조립.py` 하나씩(손질을 적는 방식이 묶음마다 조금 다르다).

## 할 일
1. **약어 풀네임**: 풀네임은 과정에서 처음 나오는 화면에 한 번 붙는다(AI · PC · DB · URL · ID 제외). 스크립트로 전 회차 덱 MD의 화면 글(제목 · 메시지 · 요소 · 코드. 노트와 제작 기준 칸은 빼고)에서 영문 대문자 약어를 회차 순서대로 뽑아 「처음 나오는 회차와 장」 표를 만들고, 그 자리에 풀네임이 붙어 있는지 본다. 없으면 그 장에 손질로 붙인다 — 원칙은 통합반 덱이 그 약어에 풀네임을 붙인 장의 표기를 그대로 따르는 것이다(통합반 덱에서 `약어(` 꼴을 찾아 표기를 확인한다). 처음 나오는 자리가 그림 라벨 · 코드 · 표의 좁은 칸이어서 붙이면 넘치는 경우에는 그 장의 메시지나 설명 줄, 그것도 안 되면 그 회차의 용어 정리 표에 싣는다. 뒤 회차에 풀네임이 다시 붙어 있는 것(통합반 원문에 붙어 있던 것)은 그대로 둔다. 식별자 · 도구 이름 · 표준 번호(ISO/IEC 19510)는 약어로 보지 않는다.
2. **뒤 회차가 전제하는 것**: 정리(Wrap-up) 단원과 뒤 회차의 장이 「앞 회차에서 다뤘다」고 전제하는 용어 · 규칙 · 그림 · 실습 산출물 · 도구 이름이 앞 회차 덱에 실제로 실려 있는지 대조한다(프롬프트가 묶음 작업자들의 보고에서 나온 의심 목록을 준다 — 그것부터, 그리고 정리 단원 전 장을 통독해 더 찾는다). 실려 있지 않으면 (가) 전제하는 문장을 손질해 그 회차 안에서 서게 하거나, (나) 앞 회차에 통합반의 해당 장을 하나 더 가져온다(단원 본문이 범위 상한을 한두 장 넘는 것은 된다). 회차 번호 대응이 틀린 곳(「2회차에 본」이 실제로는 3회차)도 고친다.
3. **용어의 통일**: 과정 전체에서 산출물은 「추천안」(스킬 원문 인용 속의 「조치 카드 · 추천 카드」는 원문이라 그대로), 사람의 결정은 「승인 · 거절」(끝 이벤트 이름 「거절 종결」, 코드 속 실제 값 「반려」는 그대로), 「재관측」, 「처리 건」, 「쿨러 성능 저하 경보」. 새장 원고(새로 쓴 장)에서 어긋난 곳을 고친다. 가져온 장의 본문은 통합반 원문이므로 고치지 않는다.
4. **회차 사이의 겹침과 이음**: 같은 장이 두 회차에 그대로 실린 곳을 스크립트로 찾아(제목이 같은 장), 의도한 이어받기(앞 회차 끝의 예고와 다음 회차의 여는 장)가 아니면 한쪽을 뺀다(빼서 단원이 범위 아래로 내려가면 두고 보고에 적는다). 같은 퀴즈 문항이 두 회차에 있으면 뒤 회차 것을 그 회차의 다른 장으로 풀리는 문항으로 바꾼다(통합반의 다른 퀴즈를 가져오거나 새로 쓴다. 정답 번호가 몰리지 않게).
5. **틀의 통일**: 과정 전체에서 표지 · 학습목표 · 목차 · 간지 · 용어 정리 · 퀴즈 간지 · 정답의 모양과 고정 문구가 같은지 훑어, 묶음마다 다른 곳(목차의 실습 표기 방식, 단원 간지의 「구분」 값, 실습 간지 부제의 말투)을 다수 쪽에 맞춘다. 사소한 차이는 두고 눈에 띄는 것만.

## 빌드와 확인
고친 회차마다: `cd <저장소> && python3 docs/교재/<과정>_오프라인/NN회차/조립.py && uv run --no-project --with python-pptx --with pymupdf python .claude/skills/lecture-deck/scripts/deck2pptx.py <md> <pptx> --render <scratchpad/오프라인맞춤_<과정>/NN>`. 화면이 바뀐 장은 렌더를 눈으로 본다(`docs/교재/도구/시트.py`). 고치지 않은 회차는 다시 빌드하지 않는다. 덱 폴더에 렌더 · `__pycache__`를 남기지 않는다. 커밋 · push는 하지 않는다.
