# 06. 실습 가이드 착수 — 새 세션의 본 작업

이 문서는 실습 가이드(핸즈온 가이드)를 쓰기 시작할 때 읽는다. 무엇이 정해졌고, 실습이 몇 건이고, 무엇부터 하고, 시작 전에 무엇을 받아야 하는지를 적었다.

상태: 실습 가이드는 **아직 없다.** 사용자는 「아직 보류」라고 했고 새 세션에서 착수한다. 저장소에 있는 것은 형식만 옮긴 빈 틀(`docs/실습가이드/틀/실습가이드_틀.html`), 형식 문서(`docs/실습가이드/틀/형식.md`), 스킬 둘뿐이다.

스킬: `.claude/skills/hyd-lab-guide/SKILL.md`가 이 문서와 형식 문서의 요약이고(원칙, 작업 순서, 지킬 것), 실습 자료의 일반 절차는 `.claude/skills/lecture-lab/SKILL.md`에 있다. 스킬과 이 문서가 다르면 이 문서가 맞다. 둘 가운데서는 `hyd-lab-guide`가 우선한다.

## 1. 왜 필요한가, 덱과의 관계

- 덱은 실습마다 간지와 「무엇을 하고 무엇이 만들어지는지」 한 장만 싣는다(제작 기준 9절). **절차 · 명령어 · 화면은 덱 어디에도 없다.** 그것을 담는 것이 실습 가이드다.
- 가이드의 단위는 **덱의 실습 간지 하나 = 실라버스의 실습 행 하나**다.
- 강사가 제품을 보여 주는 시연(ProcessGPT)은 학생이 따라 하는 가이드의 대상이 아니다. 강사용 시연 순서가 필요하면 따로 정한다.
- 가이드는 덱과 같은 사건, 같은 용어, 같은 값을 쓴다. 용어는 제작 기준 8절 「덱 사이의 용어」와 10절을 따른다.

## 2. 실습 가이드에 대해 정해진 것

사용자와의 대화에서 정해진 것이다. 그대로 따른다. 형식에 관한 것의 세부(블록 종류와 클래스 이름)는 `docs/실습가이드/틀/형식.md`에 있다.

### 2.1 형식

| 정해진 것 | 내용 |
|---|---|
| 원고는 MD, 배포는 HTML | MD 하나가 원본이고, 그림은 같은 폴더의 이미지 파일이다. MD를 HTML로 변환해 배포한다 |
| HTML은 사용자가 준 본보기의 형식을 그대로 따른다 | 새 디자인을 만들지 않는다. 본보기는 다른 과정의 실습 가이드이며 그 파일과 본문 · 그림은 저장소에 넣지 않았다. 형식(CSS · 스크립트 · 블록 구성)만 옮긴 빈 틀이 `docs/실습가이드/틀/실습가이드_틀.html`이다 |
| VS Code 화면은 찍지 않는다 | VS Code에서 하는 일은 GitHub Copilot 채팅에 말로 시키고 결과를 보는 것(바이브 코딩)이다. 입력할 말(프롬프트)과 명령어는 **복사 상자**로, 출력은 **터미널 재현 상자에 글자로** 싣는다 |
| 사진은 결과를 보는 브라우저 화면에만 쓴다 | HYD 포털의 지식 지도 · 에이전트 실행 기록 · 처리 건, Neo4j Browser의 그래프, bpmn.io의 그림, arrows.app |
| 예외로 받는 사진 | VS Code 화면이 필요한 곳(확장을 열고 로그인하는 처음 한 번)과 Windows 설치 화면은 **수업 PC에서 찍은 사진을 받아** 넣는다 |

MD를 HTML로 바꾸는 변환 스크립트는 아직 없다. 본보기 실습 하나를 확정한 뒤 만든다(4.2절). 그 전의 본보기 HTML은 틀을 복사해 자리표시 글을 원고의 글로 바꿔 만든다.

### 2.2 AI에게 일을 시키는 순서를 실습하게 짠다

사용자가 준 본보기는 프롬프트 유도가 너무 간략하다(「이 요청을 복사해 붙여 넣으세요」 한 번). HYD 가이드는 **AI에게 일을 시키는 순서 자체를 실습하게** 짠다. 실습마다 같은 다섯 걸음이다.

| 걸음 | 무엇을 하는가 | 요청의 예 |
|---|---|---|
| ① 파악시키기 | 만들기 전에 먼저 읽게 한다 | 「이 폴더의 자료를 읽고 무엇이 있고 어떻게 이어지는지 정리해 줘. 아직 아무것도 만들지 마.」 |
| ② 할 일과 끝난 모습 정하기 | 목표, 결과물의 항목, 건드리면 안 되는 것, 값이 없을 때의 처리를 정한다. 7일차의 명세를 실제로 써 보는 자리다 | (실습마다 쓴다) |
| ③ 계획부터 받기 | 바로 만들게 하지 않는다 | 「어떻게 할지 단계로 먼저 말해 줘. 내가 확인한 다음에 시작해.」 |
| ④ 작게 만들고 확인하기 | 덩어리마다 「이것이 보이면 된다」는 기준을 둔다 | (실습마다 쓴다) |
| ⑤ 틀렸을 때 되돌려 주기 | 무엇이 왜 틀렸고 어떻게 해야 하는지를 말한다 | 나쁜 예 「다시 해 줘」 / 좋은 예 「셋째 항목의 담당자가 회의록에 없는 이름이야. 회의록에 적힌 사람만 쓰고 없으면 미정으로 둬.」 |

### 2.3 싣는 모양

| 정해진 것 | 내용 |
|---|---|
| 요청 상자마다 「왜 이렇게 시키는가」 | 한두 줄 |
| 나쁜 요청과 좋은 요청 | 실제 출력으로 나란히 보인다 |
| 뒤 실습으로 갈수록 빈칸을 늘린다 | 앞 실습은 요청을 그대로 주고, 뒤는 틀만 주고, 마지막은 목표만 준다 |
| 흔히 막히는 곳 | 실습마다 한두 개(AI가 없는 값을 지어냈을 때, 시키지 않은 파일까지 고쳤을 때) |
| 출력 예를 읽는 법 | 바이브 코딩은 실행마다 출력이 다르다. 출력 예는 「글자가 똑같아야 한다」가 아니라 「이 항목들이 들어 있으면 된다」로 읽히게 쓰고, 출력 상자 아래에 확인할 것 두세 줄을 둔다 |
| 분량 | 다섯 걸음이면 실습 하나가 네댓 번의 주고받기가 된다. 실라버스의 실습 시간(대개 30~50분) 안에 들어가는지 실습마다 따지고, 짧은 실습은 걸음을 합친다 |

### 2.4 실제로 돌려 본 것만 쓴다

- 명령어와 출력, 「좋은 예 · 나쁜 예」, 「막히는 곳」은 가이드를 쓰는 세션이 실습을 **그 순서대로 실제로 돌려** 얻는다. 지어내서 쓰지 않는다.
- 그러려면 실습 스택을 띄우고 쓰기(에이전트 만들기, 흐름 배포, 승인)까지 해야 한다. 교재를 만든 세션은 그것을 하지 않았다(검증은 그 세션에서 하지 않기로 했다).
- 덱의 값은 저장소 코드와 실행 기록에 근거하며, 실행 중인 시스템으로 다시 확인한 것이 아니다(`01_현황.md` 6절). 돌려 본 값이 덱과 다르면 6절을 따른다.
- 스택을 올리고 확인하는 방법은 `docs/handoff/NOW.md` 2절, Windows 기준의 기동 절차는 `docs/RUNBOOK.md`다. 저장소 루트 `CLAUDE.md` 3절의 시스템 규칙(배속, 검사 중 compose 금지, 워커, 정리)을 지킨다.

### 2.5 진행 방식

실습 하나를 먼저 이 틀로 만들어 사용자에게 보여 확정한 뒤 나머지를 만든다. 덱에서 샘플을 먼저 컨펌받은 것과 같은 방식이다.

## 3. 실습 전체 목록

실라버스(`docs/교재/기준/피지컬AI_실라버스_최종본.xlsx`) 네 시트의 실습 행 160건이다. 스크립트로 뽑았다(2026-10-12). 덱의 실습 간지도 160개이며 행과 순서대로 하나씩 대응한다.

| 과정 | 실습 행 | 분 합계 | 20분 이하 | 25~35분 | 40~50분 | 50분 초과 |
|---|---|---|---|---|---|---|
| 통합반 온라인 | 45(시연 1 포함) | 1,735 | 5 | 13 | 26 | 1 |
| 실전반 온라인 | 39(시연 1 포함) | 1,285 | 9 | 14 | 16 | 0 |
| 통합반 오프라인 | 40 | 1,645 | 3 | 6 | 31 | 0 |
| 실전반 오프라인 | 36 | 1,475 | 3 | 6 | 27 | 0 |

- 통합반 온라인에서 학생이 따라 하는 실습은 시연을 뺀 44건, 실전반 온라인은 38건이다. ProcessGPT 시연(통합반 11일차, 실전반 8일차)은 가이드의 대상이 아니다(1절).
- 덱의 실습 간지 제목으로 세면 서로 다른 것이 89개이고, 그 가운데 35개가 두 과정 이상에 나온다. **제목이 같아도 실라버스의 상세 내용과 시간은 과정마다 다르다**(예: 「그래프 DB에서 관계를 따라 조회하기」는 통합반 25분, 실전반 15분, 통합반 오프라인 45분). 가이드를 함께 쓸 수 있는지는 실습마다 실라버스 문구로 가린다.
- 오프라인 과정에는 온라인에 없는 실습이 따로 있다(직접 설계 · 구현 중심).

표를 읽는 법:

| 열 | 뜻 |
|---|---|
| 쓰는 도구 | 실라버스의 제목과 상세 교육 내용에 **이름이 적힌 것만** 뽑았다. 「(덱 기준)」은 실라버스에는 없고 덱의 실습 간지 · 설명 장에 적힌 것, 「(화면 이름으로 추정)」은 실라버스가 포털의 화면 · 버튼 이름만 적은 것이다. 「표기 없음(확인 필요)」은 실라버스가 도구를 적지 않은 행이다(에이전트 · 명세 · 검증을 만드는 실습에 많다). 추측해 채우지 않았다. 실라버스가 학생 도구로 적은 「Claude Code」는 수업 도구인 「GitHub Copilot」으로 옮겨 적었다(2026-10-12 결정, `04_결정_기록.md` 2절) |
| 덱의 실습 간지 | 그 과정 덱의 간지 제목이다(`실습: ` 뒤의 글. ` / `는 화면의 줄바꿈). 설명 장은 간지 바로 다음 한 장이다. **장 번호는 싣지 않는다** — 덱을 고치면 바뀌므로 제목으로 찾거나 아래 명령으로 뽑는다 |
| 제공 자료가 저장소에 있는가 | 사실표 기준. 사실표는 통합반 온라인의 실습 행만 다루므로 나머지 세 과정은 모두 「확인 필요」다. 같은 주제의 통합반 실습 줄을 참고한다 |

간지와 설명 장의 지금 번호 · 제목을 뽑는 명령(저장소 루트에서):

```bash
python3 .claude/skills/hyd-lab-guide/scripts/실습목록.py                 # 38개 덱 전부
python3 .claude/skills/hyd-lab-guide/scripts/실습목록.py 통합반 --day 6   # 통합반 6일차만
```

## 4. 착수 순서의 제안

### 4.1 먼저 본보기 하나

실습 하나를 골라 2절의 형식으로 끝까지 만들고(실제로 돌려서) 사용자 확인을 받는다. 본보기로 알맞은 후보는 다음 셋이다. 어느 것도 아직 돌려 보지 않았다.

| 후보 | 왜 알맞은가 | 걸리는 것 |

### 4.2 그다음: 과정과 도구로 묶어 진행

1. 본보기를 확정하면 MD → HTML 변환 스크립트를 만든다(틀의 블록과 일대일로). 본보기의 MD를 변환한 결과가 확정본과 같아야 한다.
2. 통합반 온라인 44건을 먼저 한다. 일차 순서대로 가되, 같은 도구의 실습을 묶어 돌리면 스택을 올리고 내리는 품이 준다(지식 영역의 VS Code 실습 → 포털 실습 → 에이전트 영역 → 프로세스 영역).
3. 「빈칸을 늘린다」는 규칙은 과정 전체의 순서로 건다. 앞 일차의 실습은 요청을 그대로 주고, 에이전트 영역부터는 틀만, 11일차의 개인 주제 실습은 목표만 준다.
4. 실전반 온라인과 오프라인 과정은 통합반 가이드에서 가져올 수 있는 것과 따로 써야 하는 것을 먼저 가른다(3절의 표에서 간지 제목이 같은 것부터 실라버스 문구를 대조한다).
5. 실습마다 시간을 잰다. 다섯 걸음이 실습 시간을 넘으면 걸음을 합친다. 20분 이하의 실습(통합반 온라인 5건)은 처음부터 걸음을 합쳐 짠다.
6. 실습마다 기록한다: 돌린 날, 환경(PC · OS · 배속), 걸린 시간, 출력의 출처. 지어낸 출력이 섞이지 않게 하는 장치다.

### 4.3 파일을 두는 곳(제안)

정해진 것은 「MD 하나가 원본, 그림은 같은 폴더」뿐이다. 아래는 제안이며 본보기를 만들 때 사용자에게 확인한다.

```
docs/실습가이드/
  README.md
  틀/                         형식.md, 실습가이드_틀.html, (만들면) 변환 스크립트
  <과정>/<NN일차>/            실습N_<짧은 제목>.md, 그림 파일, 변환한 .html
```

## 6. 가이드를 쓰다 덱과 어긋나는 사실을 찾으면

실습을 실제로 돌리면 덱의 값 · 이름 · 순서와 다른 것이 나올 수 있다. 가이드만 맞추고 덱을 두지 않는다. **덱도 함께 고친다.**

1. 무엇이 다른지 적는다: 덱의 어느 장, 덱의 값, 실제로 본 값, 돌린 환경.
2. 다름의 종류를 가린다. 덱이 틀린 것인가, 실행 회차가 달라 값이 다른 것인가(덱은 두 실행 회차의 값을 쓴다 — `04_결정_기록.md` 2절), 시스템이 그 뒤 바뀐 것인가. 판단이 서지 않으면 사용자에게 묻는다.
3. 덱이 틀렸으면 통합반 원 덱을 고치고, 조립 덱과 배포 묶음까지 다시 만든다. 순서는 `02_덱_고치는_법.md` (나)다(스킬 `hyd-course-deck`).
4. 근거가 되는 사실표의 절도 함께 고치거나 「확인 못 한 것」에서 지운다.
5. 실습 설명 장(덱의 「무엇을 하고 무엇이 만들어지는지」 한 장)이 가이드의 실제 산출물과 맞는지 실습마다 대조한다.
6. `05_남은_일.md`에서 닫힌 줄을 지운다.
