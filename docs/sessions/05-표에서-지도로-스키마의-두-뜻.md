# 5. 표에서 지도로, 스키마의 두 뜻 (2부, 180분: 설명 70 / 실습 80 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
시계열 표에는 숫자만 있고 "왜"가 없다. 지식 그래프(Neo4j)에서 설비 구조와 "경보 → 증상 → 고장 유형 → 원인" 경로를 걷고, DB 스키마와 온톨로지 스키마가 어떻게 다른지 표로 적는다.
끝나면 원인 후보가 prior 순으로 나온 질의 결과와 "두 스키마 차이" 표 1장이 남는다.

## 준비
- Neo4j Browser http://127.0.0.1:7474 (Connect URL `neo4j://127.0.0.1:7687`, neo4j / hydpass123).
- 파일: `it/neo4j/v2/schema.json`(온톨로지 스키마 원본, 클래스 46개), `it/neo4j/v2/queries.cypher`(정답 질의 예시), `it/timescaledb/init.sql`(DB 스키마).
- 포털 **온톨로지 지식 지도** 탭(설비 HYD-01, "이상 패턴 경로" 선택).
- 그래프의 설비 id는 `asset:hyd-01`처럼 접두사가 붙는다(`HYD-01`은 설비 코드 `code` 속성).

## 실행 장면
1. [화면] Neo4j Browser → `CALL db.schema.visualization()` → [관찰] 클래스(노드 라벨)와 관계가 그림으로 → [확인] 라벨 수를 센다(`schema.json`의 클래스 46개와 비교; 그래프에는 실행 투영 라벨 `ProcessInstance`·`WorkItem` 등 스키마 밖 라벨도 섞여 있다).
2. [화면] `MATCH (a:Asset {id:'asset:hyd-01'})-[:HAS_COMPONENT]->(c)-[r:MONITORED_BY|ACTUATED_BY]->(x) RETURN a,c,x` → [관찰] 부품·센서·구동기 → [확인] 부품 6(쿨러·팬·모터·펌프 A·펌프 B·탱크) · 센서 5(CE·FS1·PS1·TS1·VS1) · 구동기 3인지. 설비 태그는 19개(`docs/hyd01-status-lookup.md` L1 행)지만 그래프에는 판단에 쓰는 센서만 있다 — 그 차이가 "표"와 "지도"의 차이다.
3. [화면] `queries.cypher`의 `q2-diagnosis-path`를 붙여 넣고 `:param symptom => 'sym:ts1-rise'` → [관찰] 고장 유형·원인(prior)·증거·조치 방법(SOP)·매뉴얼이 한 표로 → [확인] 원인 후보 수를 세고(현재 그래프에서 유온 상승은 원인 2개 · 행 7개 — 원인 × 조치 방법 조합), prior 내림차순인지.
4. [명령] `.venv314/Scripts/python.exe scripts/ontology_v2.py queries --only q2-diagnosis-path --uri bolt://127.0.0.1:7687` → [관찰] 같은 질의를 터미널에서 실행한 결과(기본 `--limit 8`) → [확인] 3단계와 같은 행.
5. [화면] 포털 **온톨로지 지식 지도** → 이상 패턴 경로 `COOLER_DEGRADATION` → [관찰] 증상 → 고장 유형 → 원인 · 증거 → 조치 방법(SOP) → 규칙 · 성과 지표 경로가 강조 → [확인] 3단계 결과의 id와 화면 노드 id가 같다.
6. [파일] `init.sql`의 `tag_1s`와 `schema.json`의 `Sensor`/`InputData` 정의를 나란히 → [확인] 표 1장: 열 이름/타입(값을 담는 스키마) vs 클래스/관계/속성(뜻과 연결을 담는 스키마), 각각 "값은 어디에"·"뜻은 어디에".

## 막혔을 때
- Browser 접속이 안 된다: `docker ps`에 neo4j (healthy)인지, 포트 7474/7687.
- 질의가 0행: id 접두사(`asset:hyd-01`)를 확인한다. kg-seed가 끝났는지 `docker compose logs kg-seed`(멱등, 다시 돌리려면 `docker compose run --rm --no-deps kg-seed`).
- `ontology_v2.py`가 bolt 연결 실패: 기본값이 검증용 7688이므로 `--uri bolt://127.0.0.1:7687`를 명시.
