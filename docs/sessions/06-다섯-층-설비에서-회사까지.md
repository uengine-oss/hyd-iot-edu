# 6. 다섯 층: 설비에서 회사까지 (2부, 180분: 설명 70 / 실습 80 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
조치 하나가 설비 값을 바꾸고, 그 값이 생산량·납기 같은 회사 지표에 닿는 영향 사슬을 그래프에서 걷는다.
끝나면 영향 사슬 3개의 Cypher 결과와 BSC(성과 지표) · 역할 노드 목록이 남는다.

## 준비
- Neo4j Browser http://127.0.0.1:7474, 포털 **온톨로지 지식 지도** 탭(층 칩: BSC · 프로세스 · 리소스 · 스킬 · 규칙).
- 파일: `it/neo4j/v2/instances.cypher`(인스턴스 적재 원본; 317~345행 근처에 스킬 → 상태변수 AFFECTS 값), `it/neo4j/templates/t3_tradeoffs.cypher`, `t3_roles.cypher`.

## 실행 장면
1. [화면] 포털 온톨로지 지식 지도 → 층 칩에서 **BSC**만 켠다 → [관찰] 관점 · 전략 목표 · 성과 지표 노드 → [확인] 성과 지표 이름 3개를 적는다.
2. [화면] Neo4j Browser → `MATCH p=(s:Skill)-[:AFFECTS]->(v)-[:INFLUENCES*1..3]->(m) WHERE s.id='skill:fan-slow-derate' RETURN p` → [관찰] "팬 40 % + 부하 80 %" → 팬 속도·부하 상태변수 → 영향 받는 지표 → [확인] 사슬 1(팬 속도 ↓ → 진동 ↓ …).
3. [화면] `MATCH p=(v {id:'sv:ps1'})-[:INFLUENCES*1..2]->(m) RETURN p` → [관찰] 토출 압력이 어느 지표(`msr:throughput` "PS1 < 165 bar에서 사이클 지연", `definition.py` 31~34행 주석)에 닿는지 → [확인] 사슬 2.
4. [화면] `MATCH p=(s:Skill {id:'skill:switch-standby-pump'})-[:AFFECTS]->(v)-[:INFLUENCES*1..3]->(m) RETURN p` → [확인] 사슬 3(예비 펌프 전환이 `sv:leak`·`msr:mtbf`에 주는 영향, `instances.cypher` 339~340행).
5. [화면] 포털 온톨로지 탭 하단 **판단 근거를 직접 조회하기** → **BSC 득실 (성과 지표 · 부서)** 버튼 → [관찰] `t3_tradeoffs.cypher` 본문이 표시 → Neo4j Browser에 붙여 넣고 `:param ids => ['skill:fan-max-derate']`(매개변수 이름은 `$ids`) → [확인] 득실 행(열 `skill · measure · name · direction · owners · dir · weight …`)에 지표·부서가 붙어 있다.
6. [화면] **승인 역할과 직급** 버튼 → `t3_roles.cypher` 실행 → [관찰] 운전원 · 생산관리자 · 정비관리자와 직급 → [확인] 16회차에서 쓸 역할 표 1장.

## 막혔을 때
- 관계 이름이 틀려 0행: `CALL db.schema.visualization()`으로 실제 관계 이름(AFFECTS, INFLUENCES, OUTPUTS …)을 확인한다. 선언된 관계 전체는 `it/neo4j/v2/schema_prompt.md` "## 관계".
- 경로 길이가 너무 길어 느리다: `*1..3`을 `*1..2`로 줄인다.
