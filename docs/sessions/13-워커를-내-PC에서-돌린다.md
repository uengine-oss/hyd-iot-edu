# 13. 워커를 내 PC에서 돌린다 (3부, 180분: 설명 50 / 실습 100 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
작업을 "집어 가는" 쪽을 자기 PC에서 띄운다. 경보가 나면 내 워커가 네 개의 에이전트 작업을 차례로 집어 Claude Code로 수행하고, 사람 선택 작업이 열리는 것까지 로그와 화면으로 본다.
끝나면 네 작업의 `task_started · tool_usage_* · task_completed` 이벤트, 세션 4개와 변수 전달 기록이 남는다.

## 준비
- 스택 + Supabase + MCP 2개. 로그인된 `claude` CLI.
- `.env`: `AGENT_BRIDGE=off`, `WORKER_URL=http://host.docker.internal:8097`, 시간 배율은 **낮게**(`TIME_SCALE=2` — 커리큘럼 §4: 20배속에서는 에이전트 지연 중 과열 트립이 났고 실제 완주는 2배속에서 확인) → `docker compose up -d plant-sim detector process agent` (배율은 세 서비스에 함께 적용해야 한다; 포털의 시간 배율 셀렉트는 plant-sim만 바꾼다).
- 스크립트: `scripts/run_worker_host.sh`(Git Bash) 또는 `scripts/run_worker_host.ps1`(PowerShell, 기본 Codex, `-Provider claude-code`). 종료: `scripts/stop_worker_host.ps1`.

## 실행 장면
1. [명령] `bash scripts/run_worker_host.sh` (새 터미널) → [관찰] `child-process environment: removed …`, polls 증가 → [확인] `curl -s 127.0.0.1:8097/health` → `"status":"ok"`, 포털 **프로세스 인스턴스**의 에이전트 현황 배너에 워커가 보인다.
2. [화면] 결함 시뮬레이션 → HYD-01 **쿨러 열화 주입** → [관찰] 경보 → 인스턴스 1건, 첫 에이전트 작업(원인 진단, 화면 표기: task:diagnose)이 IN_PROGRESS → 워커 터미널에 claim·run 로그 → [확인] 실시간 스트림에 MCP 도구 호출이 흐른다.
3. [관찰] 네 작업(원인 진단 → 조치 후보 → 규정 검토 → 우선순위)이 차례로 SUBMITTED → DONE → [확인] 각 작업 행의 이벤트에 `task_started`와 `task_completed`, 도구 호출 `tool_usage_started/finished`가 있다. 세션 id가 작업마다 다른지(독립 세션 4개) 이벤트 `run_start`에서 확인.
4. [화면] 인스턴스 상세 "시작 입력과 현재 결과" → [관찰] 앞 작업의 결과(원인 · 후보 · 규정)가 다음 작업의 입력 변수로 들어간다(`variable_sources`에 작업 UUID) → [확인] 변수 전달 표.
5. [화면] **내 할일**에 "조치 카드 선택"이 나타난다 → 생산관리자로 선택 → [확인] 이후는 1회차와 같다(명령 → ACK → 재관측 → 종결). 1배속 실측에서 네 작업은 수 분(제작자 증거 참조).
6. [정리] `AGENT_BRIDGE=legacy`, `TIME_SCALE=20`으로 되돌리고 워커를 끈다(`stop_worker_host.ps1`).

## 막혔을 때
- 워커가 바로 죽는다: psycopg libpq 차단 → 스크립트가 `host_libpq.sh`를 부르지만 LibreOffice가 없으면 `LIBPQ_DIR`를 서명된 libpq 위치로 지정(RUNBOOK §3).
- 워커는 떴는데 작업을 안 집는다: `AGENT_BRIDGE`가 `legacy`면 서버가 먼저 채운다. process `healthz`와 `.env` 확인 뒤 재기동.
- 에이전트 작업이 끝나기 전에 설비가 트립: 배율이 높다. 2배속으로.
- 플랜 한도·로그인 만료: `claude` 단독 실행으로 상태 확인. 워커는 API 키 없이 로그인 세션을 쓴다(`.env.example` 주석).
