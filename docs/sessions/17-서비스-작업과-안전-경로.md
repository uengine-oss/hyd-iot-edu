# 17. 서비스 작업과 안전 경로 (4부, 180분: 설명 60 / 실습 90 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
에이전트가 설비에 직접 쓰지 않는 이유를 구조로 본다. 명령 · 재관측 · 정비 요청 세 서비스 작업이 사건 상태기계(승인 → 명령 → ACK → 재관측 → 종결)와 어떻게 맞물리는지 추적하고, 재관측 판정 기준이 패턴마다 다른 것을 확인한다.
끝나면 감사 기록의 재관측 판정(criterion)이 패턴별로 다른 값으로 적힌 표가 남는다.

## 준비
- 파일: `it/process/procsvc/machine.py`(상태기계), `definition.py` 27~37행(`REOBSERVE_SIM_S = 15*60`, `RECOVERY = {COOLER_DEGRADATION: TS1 < 55, PUMP_LEAKAGE: PS1 >= 165, FAN_VIBRATION: VS1 < 1.2}`), `instances.py`(서비스 작업 `incident:command`·`incident:reobserve`·`enterprise:WO_CREATE`).
- API: `GET /api/incidents/{id}`, `GET /api/audit`, `GET /api/instances/{id}`.
- 절대 규칙(HANDOFF §3): PLC 명령은 process의 사건 경로(action.cmd → cmd-gateway)로만, 에이전트·워커·MCP는 직접 쓰지 않는다.

## 실행 장면
1. [파일] `machine.py` → [관찰] 상태 AWAITING_APPROVAL → CMD_ISSUED → AWAITING_ACK → ACKED → RE_OBSERVING → RESOLVED → WORK_ORDER_CREATED → CLOSED, 실패 가지 ESCALATED(ACK_TIMEOUT 233행 · MITIGATION_FAILED 256행), 사람이 거부한 가지 REJECTED_BY_OPERATOR · 조치 없이 끝난 RESOLVED_WITHOUT_ACTION(`grep -n "_go(inc" machine.py`) → [확인] 상태 그림 1장.
2. [화면] 쿨러 실행 1건을 끝까지(1회차) → 인스턴스 상세에서 서비스 작업 3개(명령 · 재관측 · 정비 요청; 수행자 SCADA · 프로세스 · CMMS) → [관찰] 각 작업의 `service_result`(명령은 cmdId, 재관측은 판정, 정비 요청은 WO 번호) → [확인] 작업 ↔ 사건 상태 대응표.
3. [명령] `curl -s 127.0.0.1:8080/api/audit | python -m json.tool | grep -B2 -A6 REOBSERVATION` → [관찰] `criterion`에 `TS1 < 55` → [확인] 쿨러 행.
4. [화면] HYD-02 펌프 누설 실행(20회차 절차) 뒤 같은 명령 → [확인] `criterion`이 `PS1 >= 165`; HYD-03 팬(21회차) 뒤 `VS1 < 1.2` → 표 완성.
5. [관찰] 재관측은 15 시뮬레이션-분(20배속 45초), 값이 이미 기준 안인데 CLEAR가 늦으면 최대 3회 연장(`REOBSERVE_MAX_EXTENSIONS`, 감사 `REOBSERVATION_EXTENDED`) → [확인] 연장이 있었는지.
6. [정리] 에이전트 쪽 코드에 PLC 쓰기가 없음을 확인: `it/agent-worker/worker/`와 `it/dmn-mcp/`에서 `action.cmd`·`cmd/auto`를 검색하면 없고, `submit_decision` 도구는 process API에 판단을 제출할 뿐이다 → [확인] "유일한 쓰기" 두 곳(에이전트의 카드 제출, process의 명령 발행).

## 막혔을 때
- 감사에 REOBSERVATION이 없음: 아직 재관측 중이거나 ACK_TIMEOUT으로 끝났다(`/api/incidents/{id}`의 state·reason).
- 정비 요청이 실패(CMMS): enterprise-sim `healthz`와 `ENTERPRISE_BACKEND=supabase`에서 ent 스키마. 재시도 API `POST /api/incidents/{id}/work-order-retry`.
