# 15. 프로세스가 주인공, 에이전트는 작업 (4부, 180분: 설명 60 / 실습 90 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
경보 하나가 실행(인스턴스) 하나를 열고, 그 안의 작업 행들이 상태를 바꾸며 끝까지 가는 것을 한 실행에서 전부 본다. 안 간 가지는 취소된다.
끝나면 상태 전이 표(TODO → IN_PROGRESS → SUBMITTED → DONE, CANCELLED)와 모니터링 배너 설명이 남는다.

## 준비
- 포털 **프로세스 인스턴스** 탭, Supabase Studio http://127.0.0.1:54323 (테이블 `bpm_proc_inst`, `todolist`, `events`).
- 파일: `it/process/procsvc/engine.py`, `it/supabase/migrations/20261003000001_process_engine.sql`, 정의 `it/process/definitions/anomaly_response_v22.json`(현재 기본 2.2).
- API: `GET /api/instances?limit=50`, `GET /api/instances/{id}`, `GET /api/todolist?status=IN_PROGRESS`, `GET /api/process/definitions`.

## 실행 장면
1. [화면] 결함 시뮬레이션 → HYD-01 쿨러 열화 주입 → **프로세스 인스턴스** 목록 → [관찰] 경보 직후 인스턴스 1건, 상세에 작업 행이 **미리 전부** 생겨 있다(에이전트 4 · 사람 1 · 책임자 호출 1 · 명령 · 재관측 · 정비 요청 …) → [확인] 행 수를 세고 수행자(AI 에이전트 · 운전원 · 생산관리자 · SCADA · 프로세스 · CMMS)를 적는다.
2. [관찰] 첫 작업만 IN_PROGRESS, 나머지 TODO → 네 에이전트 작업이 차례로 SUBMITTED → DONE → [확인] 전이 표에 시각을 적는다(상세 타임라인).
3. [화면] 사람 작업 "조치 카드 선택"이 IN_PROGRESS가 되면 경계 타이머 행(선택 시간초과 → 책임자 호출, 정의의 `ev:select-timeout` PT10M)이 함께 보인다 → [확인] 타이머 행의 기한.
4. [화면] 생산관리자로 선택 → [관찰] 선택 작업 DONE, 타이머 짝 **CANCELLED**, 명령 작업 SUBMITTED → … → 종결 → [확인] 한 실행 안에서 DONE·CANCELLED·TODO→DONE을 모두 본다. 회복 분기에서 안 간 가지(`ev:escalated` 쪽)도 CANCELLED.
5. [화면] Supabase Studio `todolist`에서 같은 `proc_inst_id`로 필터 → [관찰] 열 `status · consumer · agent_orch · output · start_date/end_date` → [확인] 화면의 행과 DB 행이 같다(이 표·RPC `fetch_pending_task`·`save_task_result`가 ProcessGPT의 것과 같은 모양, 화면 안내문).
6. [화면] 인스턴스 탭 상단 배너(화면 표기: 에이전트 현황 · 실시간 스트림) → [확인] 워커 상태와 스트림 연결 표시의 뜻을 한 줄씩.

## 막혔을 때
- 인스턴스가 안 열림: process `healthz`의 `"mode":"instance","supabase":true`가 아니면 `.env PROCESS_MODE`와 Supabase 확인.
- 목록이 "최근 50건"에 안 보임: 상태 필터를 "실행 중"으로.
- 실행 중 인스턴스가 쌓여 헷갈림: 수업 전에 RUNBOOK §3 잔재 정리.
