# 3. 메시지의 길과 저장 (1부, 180분: 설명 50 / 실습 100 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
센서 값 하나가 MQTT → Kafka → 시계열 DB를 거쳐 표에 쌓이는 길을 세 곳에서 같은 값으로 확인한다.
끝나면 TS1 · PS1 · VS1 최근값을 MQTT 구독, Kafka 토픽, SQL 세 곳에서 읽은 결과가 한 표에 남는다.

## 준비
- 스택 켜짐(RUNBOOK). `.venv314`에 `paho-mqtt`가 있어야 `scripts/mqtt_tail.py`가 돈다(없으면 `.venv314/Scripts/python.exe -m pip install paho-mqtt`).
- 열 화면: EMQX http://127.0.0.1:18083 (admin / public123, 첫 로그인 때 비밀번호 변경을 요구할 수 있음), Grafana http://127.0.0.1:3000.
- 토픽 정의: `common/hydcommon/topics.py`, `it/redpanda/topics.sh`(Kafka 토픽 7개와 보존 기간).

## 실행 장면
1. [명령] `.venv314/Scripts/python.exe scripts/mqtt_tail.py 'plant/hyd01/tag/TS1' 3` → [관찰] `plant/hyd01/tag/TS1 {"t":…,"v":48.0,"q":"good"}`가 초당 1건 → [확인] 마지막 줄 `-- N messages in 3s`에서 N≈3.
2. [화면] EMQX → **Monitoring › Clients** → [관찰] `plant-sim-edge`, `connect-ingest`, `cmd-gateway` 클라이언트(FUXA가 떠 있으면 `mqttjs_*`도) → [확인] 누가 발행하고 누가 구독하는지 표에 적는다. **Diagnose › WebSocket Client**에서 `plant/hyd01/#` 구독해 같은 값 확인. (같은 목록을 API로: `POST /api/v5/login` 뒤 `GET /api/v5/clients`.)
3. [명령] `docker compose exec redpanda rpk topic list` → [관찰] `plant.tag plant.wave plant.status feat.1s alerts action.cmd audit` 7개 → [확인] `topics.sh`의 보존 기간과 대조. 검사 스크립트가 남긴 `a0NN-…` 접두사 토픽이 섞여 있으면 무시한다(수업 토픽이 아니다).
4. [명령] `docker compose exec redpanda rpk topic consume plant.tag -n 60 -f '%k %v\n' -o end | grep '^hyd01 ' | grep -E 'TS1|PS1|VS1'` → [관찰] 키 `hyd01`, 값 JSON에 `name`·`v` → [확인] 1단계와 같은 값.
5. [명령] `docker compose exec timescaledb psql -U hyd -d hyd -c "SELECT name, value, time FROM tag_1s WHERE asset='HYD-01' AND name IN ('TS1','PS1','VS1') ORDER BY time DESC LIMIT 6"` → [관찰] 최근 6행 → [확인] 세 곳의 값이 같은 시각에 같은 숫자.
6. [파일] `ot/plant-sim/plantsim/daq.py` 머리말(1~8행) → [관찰] `lite` 프로파일은 "탐지 입력 6종(TS1, CE, PS1, FS1, VS1, LoadSP)은 매초, 나머지 핵심 태그는 데드밴드를 넘을 때 + 10초 하트비트" → [확인] 4단계 출력에서 TS1·PS1·VS1은 매초 오고, 예를 들어 `TS2`는 드문드문 오는 것을 센다. (커리큘럼의 "FS1이 변화 때만" 표현은 코드와 다르다 — FS1은 lite에서도 매초 온다.)
7. [화면] Grafana → 대시보드 `hyd-trend`(제목 "HYD 설비 추세 · 경보 · 조치") → 설비 HYD-01 → [확인] 패널 "유온 TS1 (현재)" 값이 5단계 값과 같다.

## 막혔을 때
- `mqtt_tail.py`가 연결 거부: EMQX가 아직 healthy가 아니다(`docker ps`). 포트 1883.
- rpk가 "no such topic": `topic-init`가 끝나지 않았다. `docker compose logs topic-init`.
- SQL이 0행: `curl -s 127.0.0.1:8094/healthz`의 `rows`·`errors`로 적재기(connect-sink) 상태 확인.
- Redpanda Console(8085)은 `tools` 프로필이라 기본으로 뜨지 않는다. 필요하면 `docker compose --profile tools up -d redpanda-console`.
