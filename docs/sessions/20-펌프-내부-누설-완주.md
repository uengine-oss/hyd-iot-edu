# 20. 펌프 내부 누설 완주 (5부, 180분: 설명 30 / 실습 120 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
HYD-02에 누설을 넣어 압력 · 유량이 떨어지는 경보를 내고, "압력 상향"이 규정상 제외된 이유를 카드에서 읽은 뒤 예비 펌프 전환을 골라 PS1이 회복되는 것으로 종결한다.
끝나면 `PS1 >= 165`로 RESOLVED된 실행 1건과, 카드의 규정 인용(`rule:no-pressure-raise`)이 남는다.

## 준비
- 스택 healthy, 전체 초기화. 포털 네 탭.
- 지식: `it/neo4j/v2/instances.cypher` 203행(`pattern:pump-leakage`), 281행(`skill:switch-standby-pump`, SOP-PMP-01), 285행(`skill:raise-pressure` "구 절차"), 436행(`rule:no-pressure-raise`, `dt:compliance`), 재관측 기준 `definition.py` 33행(`PUMP_LEAKAGE: PS1 >= 165`).
- 자동 검사(강사 시연용): `scripts/scenario_pump_fan_test.py --only pump`(머리말: pump_leakage → 카드(압력 상향 제외, 예비 펌프 전환 권장) → 생산관리자 선택 → PUMP_SELECT → PLC 펌프 B → PS1 ≥ 165 → 재관측 → 작업지시 → ev:closed).

## 막혔을 때
- 경보가 안 난다: HYD-02 부하가 80 % 미만이면 조건 불성립(4회차). 전체 초기화 뒤 다시.
- 카드에서 예비 펌프 전환이 제외(`rule:standby`)되고 부하 70 %가 1위다: CMMS `ent.maintenance_profiles`의 HYD-02 `standby_ready`가 비어 있으면(NULL = 미확인) 예비 펌프를 쓸 수 없다고 본다. 2026-10-07 제작자 DB 값이 NULL이다(마이그레이션 이전 행; 새로 `supabase start`한 PC는 seed로 true). Studio에서 true로 바꾼 뒤 주입하고 수업 뒤 원래 값으로 돌린다(검사 스크립트도 흐름 동안만 true로 둔다).
- 첫 진단이 보류되지 않고 바로 카드가 나온다: 직전 2분 안에 같은 설비에 누설이 있었으면 그 기록이 근거로 쓰인 것으로 보인다(22회차 제작자 실행에서 보류 없이 바로 카드가 나옴). 그대로 진행한다.
- 카드에 예비 펌프 전환이 없다: 예비 펌프가 "정비 중"(CMMS standby_ready)이거나 공급사 AVL 철회(23회차 주제). **조치 판단 규칙** 탭에서 예비 펌프 "가용"으로 바꿔 판단 실행해 비교.
- PUMP_SELECT가 거절: 설비 모드(2회차)와 PLC 인터록 `PS1 < 130 LOW_PRESSURE` 트립 여부(`/api/state`).
