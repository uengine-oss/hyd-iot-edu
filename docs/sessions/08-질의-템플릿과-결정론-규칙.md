# 8. 질의 템플릿과 결정론 규칙 (2부, 180분: 설명 70 / 실습 80 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
같은 질문에 매번 같은 답을 내야 하는 부분(원인 순위 · 규정 검사 · 조치 순위)은 고정 질의와 규칙표로 돌아간다. 템플릿과 규칙을 읽고, 사실값과 임계값을 바꿔 결과가 어떻게 달라지는지 비교한다.
끝나면 "바꾸기 전 예상 → 실행 결과" 비교 1건이 남는다.

## 준비
- 포털 **조치 판단 규칙** 탭, Neo4j Browser.
- 파일: `it/neo4j/templates/t0_*.cypher`~`t3_*.cypher`(T0 그래프, T1 원인, T2 스킬, T3 규칙·입력·득실·예측·선례·역할·공급사), `it/neo4j/v2/instances.cypher` 404~440행(결정표 `dt:diagnose-cause`·`dt:action-candidates`·`dt:compliance`·`dt:rank-actions`와 규칙), `it/agent/agentsvc/cards.py`(순위 식, 280~286행에 납기 `delivery`·품질 `quality` 항).
- 규칙 엔진을 도구로 내놓은 서버: dmn-mcp http://127.0.0.1:8198 (`it/dmn-mcp/dmn_mcp/server.py` 도구 `dmn_rules`, `inputs`, `evaluate_cards`, `tradeoffs`…).

## 실행 장면
1. [파일] `t1_causes.cypher`·`t2_skills.cypher`·`t3_dmn.cypher` → [관찰] 매개변수(`$pattern`, `$asset` …)만 바뀌고 본문은 고정 → [확인] "왜 고정 질의인가"를 한 줄로.
2. [화면] 포털 **온톨로지 지식 지도 → 판단 근거를 직접 조회하기 → DMN 규칙 · 임계값** → [관찰] `t3_dmn.cypher` 본문 → Neo4j Browser에서 실행 → [확인] `rule:no-pressure-raise`(`dt:compliance`, 압력 상향 금지)·`rule:cand-pump` 등 규칙과 TESTS 임계값이 보인다.
3. [화면] **조치 판단 규칙** → 설비 HYD-01, 이상 패턴 COOLER_DEGRADATION, 나머지 "실제 값" → **판단 실행** → [관찰] 어느 규칙이 후보를 고르고(SELECT) 제외·감점·경고했는지, 카드 순위와 순위 식 항 → [확인] 1위 카드 이름을 적는다.
4. [입력] 같은 화면에서 **팬 100 % 누적 (h)** = 30, **예비 펌프** = 정비 중 → 예상(어느 규칙이 걸릴지) 먼저 적기 → **판단 실행** → [확인] 예상과 결과 비교(카드 제외·감점 사유가 바뀌는지).
5. [화면] 임계값 바꾸기(그래프 직접 수정, 수업 끝에 되돌림): Neo4j Browser에서 `MATCH (r:Rule {id:'rule:fan-24h'})-[t:TESTS]->(i:InputData) RETURN r.id, i.variable, t.operator, t.value`로 현재 값(`fan100_hours > 24`)을 적어 두고, `SET t.value = 48`로 바꾼다 → **조치 판단 규칙**에서 HYD-01 / COOLER_DEGRADATION, 팬 100 % 누적 30 h 재실행 → [확인] 4단계에서 걸리던 감점이 사라지는지 → 원래 값 24로 `SET` 복원 → 재실행해 원상 확인. (`rule:cand-pump`의 TESTS는 고장 유형 일치뿐이라 임계값 실습에 맞지 않고, HYD-02 / PUMP_LEAKAGE 판단은 실제 누설 근거가 없으면 "근거 없음 — 보류"로 끝난다.)
6. [파일] `cards.py` 280~286행 → [관찰] 납기(`delivery`)·품질(`quality`) 점수 항이 카드 설명에 붙는 자리 → [확인] 23회차에서 이 항이 바뀌는 입력(MES 납기·QMS 로트)을 미리 표시.

## 막혔을 때
- 판단 실행이 "에이전트 연결을 확인하세요": agent 서비스(8091) healthz.
- 규칙 수정 뒤 결과가 안 바뀐다: dmn-mcp·agent는 그래프를 매번 읽지만 포털은 이전 결과를 캐시하지 않는다 — 패턴·설비를 다시 고르고 실행. 그래도 같으면 바꾼 규칙이 그 패턴의 결정표에 속하는지(`dt:…`) 확인.
- 되돌리기를 잊으면 다음 회차 카드가 달라진다. 되돌린 뒤 `scripts/ontology_v2.py validate`로 스키마 검증.
