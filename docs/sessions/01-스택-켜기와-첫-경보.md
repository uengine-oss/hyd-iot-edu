# 1. 아홉 층 한 장, 스택 켜기 (1부, 180분: 설명 50 / 실습 100 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
공장 시뮬레이터부터 승인 화면까지 전부 켜고, 쿨러가 나빠지는 상황을 한 번 만들어 경보가 조치와 종결까지 가는 것을 끝까지 지켜본다.
끝나면 포털 홈의 상태 점이 전부 초록이고, "이상 확인 · 조치"에 종결된 사건 1건, "프로세스 인스턴스"에 완료된 실행 1건이 남는다.

## 준비
- 저장소 `/d/work/study/hyd-iot-edu`, `.env`(없으면 `cp .env.example .env`), Docker Desktop 실행.
- 기동·확인·종료 절차는 `docs/RUNBOOK.md` 한 장을 그대로 따른다.
- 열 화면: 포털 http://127.0.0.1:8088, 터미널(Git Bash) 하나.

## 실행 장면
1. [명령] `( cd it/supabase && supabase start )` → [관찰] 마지막에 API URL·DB URL(54321·54322)이 출력된다 → [확인] `docker ps`에 `supabase_db_hyd-iot-edu … (healthy)`.
2. [명령] `docker compose up -d --build` → [관찰] 이미지 빌드 뒤 컨테이너 18개가 생성된다(그중 fuxa-init·topic-init·kg-seed 3개는 끝나면 Exited 0) → [확인] `docker ps`에 hyd-iot-edu-* 15개 "Up".
3. [명령] `docker compose --profile cliagents up -d enterprise-mcp dmn-mcp` → [확인] `curl -s 127.0.0.1:8198/healthz` → `{"ok":true,"neo4j":true,…}`.
4. [화면] 포털 → **실습 홈**/상단 상태 점 → [관찰] 점이 하나씩 초록으로 바뀐다 → [확인] 전부 초록, 상단 "진행 중 0".
5. [화면] 포털 → **결함 시뮬레이션** → HYD-01 카드 → **쿨러 열화 주입** (같은 일: `curl -X POST 127.0.0.1:8000/api/fault -H 'Content-Type: application/json' -d '{"asset":"HYD-01","type":"cooler_degradation"}'`) → [관찰] 카드에 "결함 진행 중: 쿨러 성능 저하", TS1(유온)이 오르고 CE(냉각 효율)가 떨어진다 → [확인] 카드의 탐지 단계가 IDLE → CANDIDATE → **RAISED**(20배속에서 주입 후 약 30~40초, `docs/scenario-walkthrough.md`).
6. [화면] **이상 확인 · 조치** → 붉은 테두리 HYD-01 도식 클릭 → [관찰] 에이전트가 만든 원인 후보·증거·권장 조치 카드가 보인다 → [확인] 사건 상태가 "승인 대기"(화면 표기: AWAITING_APPROVAL).
7. [화면] **프로세스 인스턴스** → **내 할일** → "조치 카드 선택" → 역할 **생산관리자** 선택 → 카드 하나 고르고 **새 예측 검토** → 바로 제출(검토 없이 제출하면 "현재 조건에서 승인을 보류합니다 … 새 카드 검토가 필요합니다"로 거절된다; 선택 작업은 20배속에서 30초 안에 끝내야 한다 — 16회차) → [관찰] 결함 시뮬레이션 탭 "최근 제어 요청 결과"에 `PASS`, HYD-01 카드 팬·부하 값이 바뀌고 마지막 ACK `DONE` → [확인] 사건 상태 "재관측 중"(화면 표기: RE_OBSERVING).
8. [화면] 같은 인스턴스를 1~2분 지켜본다 → [관찰] 경보 해제(CLEAR) → 재관측 통과 → 정비 요청(작업지시, 화면 표기: task:work-order) → 종결 → [확인] 인스턴스 상태 **완료**(COMPLETED), 사건 **CLOSED**, 상단 "진행 중 0".
9. [화면] 결함 시뮬레이션 → HYD-01 **결함 복구** 또는 **전체 초기화 (정상 운전점)** → [확인] TS1이 48 ℃ 부근으로 돌아온다.

## 막혔을 때
- 상태 점이 하나라도 빨강: 그 서비스의 `/healthz`를 RUNBOOK §2 명령으로 본다. process가 503이면 `docker restart hyd-iot-edu-process-1`.
- 경보가 안 뜸: `curl -s 127.0.0.1:8092/api/detector/state` → `assets.HYD-01.phase`. CANDIDATE가 60 시뮬레이션-초(3초) 유지돼야 RAISED.
- "내 할일"이 비어 있음: 에이전트 네 작업이 아직 끝나지 않았다(인스턴스 상세에서 작업 상태 확인). 현재 배포는 `AGENT_BRIDGE=legacy`라 서버 안 에이전트가 수 초 안에 채운다.
- 제출이 403: 역할을 운전원으로 골랐다. 생산관리자로 바꾼다(16회차 주제).
- 제출은 됐는데 명령 작업이 멈춤(화면 표기: 새 판단 · 승인 필요, 작업 상태 PENDING): 명령 직전 재검사에서 예측 유온이 검토 때보다 0.5 ℃ 넘게 나빠졌다(`it/agent/agentsvc/forecasting.py` 11·100~103행). 20배속 쿨러는 TS1이 빨리 올라 검토와 제출 사이가 길면 생긴다. 이 실행은 명령 없이 끝나고 설비는 곧 과열 트립(OVERTEMP)되므로 **결함 복구 → 전체 초기화** 뒤 5단계부터 다시, 검토 직후 바로 제출한다.
