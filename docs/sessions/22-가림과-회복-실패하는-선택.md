# 22. 가림과 회복: 실패하는 선택 (5부, 180분: 설명 40 / 실습 110 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
펌프 누설에 "부하 70 %"를 고르면 경보는 꺼지지만 압력은 돌아오지 않는다. 재관측이 실패해 책임자에게 넘어가는(ESCALATED) 것을 보고, 예측값과 비교해 "가림 ≠ 회복"을 데이터로 설명한다.
끝나면 ESCALATED 1건과 예측 · 실측 비교표가 남는다.

## 준비
- 스택 healthy, 전체 초기화.
- 지식: 탐지 clear 조건 `LoadSP < 80`이면 경보 종료(`cep.py` 머리말 "the leak is masked, not gone"), 재관측 기준 `PS1 >= 165`(`definition.py`), 실패 전이 `machine.py` 256~257행(`MITIGATION_FAILED` → ESCALATED), 예측 노드 `fc:*-derate70`(`instances.cypher` 569행 근처; 펌프는 `fc:pump-derate70`로 적혀 있는지 Neo4j에서 `MATCH (f:Forecast) RETURN f.id`로 확인).
- 자동 검사(강사): `scripts/scenario_pump_fan_test.py --only mask`(HYD-01에 pump_leakage → derate-70 → CLEAR but PS1 < 165 → MITIGATION_FAILED → ev:escalated).

## 실행 장면
1. [화면] HYD-02(또는 검사와 같은 HYD-01) → **펌프 누설 주입** → RAISED → [확인] 경보.
2. [화면] 카드에서 **새 예측 검토**로 "부하 70 %" 카드의 예측(정상 상태 PS1 예측값)을 본다 → [확인] 예측값을 적는다(검사 스크립트 설명 기준 160 bar 안팎 — 실제 화면 값 사용).
3. [화면] 생산관리자로 **부하 70 %** 선택 → [관찰] PASS · ACK, 부하 70 % → 60 시뮬레이션-초 뒤 경보 **CLEAR**(LoadSP < 80) → [확인] 탐지 단계 IDLE인데 PS1은 165 미만.
4. [관찰] 재관측 종료 → 감사 `REOBSERVATION`에 `cleared=true PS1=<값> (criterion PS1 >= 165)` → `MITIGATION_FAILED` → 사건 ESCALATED, 인스턴스는 `ev:escalated`로 끝남 → [확인] ESCALATED 1건.
5. [표] 예측(2단계) · 실측(4단계 PS1) · 기준 165 → [확인] "경보 조건과 회복 조건이 다른 변수"임을 한 줄로.
6. [정리] 결함 복구, 원격 자동.

## 막혔을 때
- CLEAR가 안 온다: clear는 `(PS1 >= 168 and FS1 >= 8) or LoadSP < 80`이다. 부하가 70으로 실제 내려갔는지 `/api/state`.
- ESCALATED 대신 RESOLVED: PS1이 165를 넘었다(누설 target이 작게 들어감). 주입을 기본값으로 다시.
- 재관측이 길다: 15 시뮬레이션-분 + 연장 최대 3회(17회차).
