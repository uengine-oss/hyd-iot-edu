회차마다 학생·강사가 그대로 따라 하는 1쪽 절차다. 커리큘럼(`docs/curriculum-75h.md`, 전부 예상치)의 회차 내용을 **지금 실제로 있는 기능·API·스크립트·화면**에 연결했다. 2026-10-07 제작자 배포본 기준(`.env`: `PROCESS_MODE=instance`, `AGENT_BRIDGE=legacy`, `TIME_SCALE=20`, `ENTERPRISE_BACKEND=supabase`, 정의 2.2). 기동·확인·종료는 `docs/RUNBOOK.md`.

## 작성 원칙

- 형식 고정: 제목(번호 · 제목 · 부 · 분) → 이번에 할 것 / 끝나면 보이는 것 → 준비 → 실행 장면([화면/명령] → [입력] → [관찰] → [확인]) → 막혔을 때 → 증거.
- 사실만: 주소·파일·행 번호·옵션은 열어 확인한 것만. 없는 기능은 만들어 넣지 않고 "현재 시스템에 없음 — 설명으로 대체".
- 학생 자료 원칙: 제작 로그·내부 판정·강사 정답을 넣지 않는다. 내부 용어는 쉬운 말로 쓰고 화면에 아직 보이면 "(화면 표기: …)".
- 증거 구분: `.evidence/sessions/<NN>/`만 학생 절차 증거다. 검사 스크립트 증거는 "제작자 증거"로 따로 적고 학생 완주 증거로 세지 않는다. 상태는 검증됨 / 미검증 / 해당 없음.
- 시간은 커리큘럼의 예상치(설명/실습/정리)를 그대로 옮겼고 실측이 아니다.
