# 12. 지식과 현황값을 함께 읽는다 (3부, 180분: 설명 60 / 실습 90 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
그래프만으로는 "지금 값"을 모른다. 범용 에이전트에 세 서버(그래프 neo4j · 업무 DB enterprise · 규칙·시계열 hyd-dmn)를 붙여 "HYD-02 펌프 누설, 지금 PS1과 납기는?" 같은 질문을 시키고, 어느 도구가 어느 출처를 언제 읽었는지 기록한다.
끝나면 도구별 출처·시각·응답값 표가 남는다.

## 준비
- 스택 + MCP 2개(enterprise-mcp 8199, dmn-mcp 8198) + 호스트 워커 1개. process·agent는 `AGENT_BRIDGE=off`(`.env` 수정 → `docker compose up -d process agent`), 그래야 워커가 작업을 집는다.
- 도구 목록: `it/dmn-mcp/dmn_mcp/server.py`(`diagnose · dmn_rules · inputs · gather_facts · timeseries_schema · timeseries_query · prometheus_* · evaluate_cards · forecast_actions · submit_decision · precedents · tradeoffs`), `it/enterprise-mcp/enterprise_mcp/server.py`(`mes_orders · erp_contract · erp_inventory · cmms_history · qms_lots · scm_suppliers · ems_demand · describe_schema · describe_catalog · query`).
- 수업용 질문 정의 3개(`docs/examples/`): `timeseries-question-v1.json`(시계열·PromQL), `business-question-v1.json`(업무 DB), `rule-question-v1.json`(규칙 → 질의). 각 정의는 시작 변수 `question` 하나를 받아 에이전트 작업 1개(`answer`, cliagents · Claude Code)가 폼(`answer · values · query/sql · tool · note …`)을 채운다. 정의의 `description`에 예시 질문이 있다.
- 기대값을 자동으로 대조하는 검사 스크립트(같은 정의 모양): `scripts/probe_timeseries_questions.py`, `probe_business_questions.py`, `probe_rule_questions.py` — 각 머리말에 실행 명령.

## 실행 장면
1. [화면] 포털 **프로세스 인스턴스 → 고급 → 프로세스 정의 등록** → `timeseries-question-v1.json` 선택 → **이 정의 버전 등록** → `timeseries_question @ 1` 선택, 시작 이벤트 ID 새 값, 시작 변수 `{"question": "HYD-01 설비의 2026-10-06T14:00:00Z부터 2026-10-06T14:10:00Z까지(UTC) 팬 진동 센서 VS1 값의 최대값은? 소수 셋째 자리까지."}` → **선택한 정의 버전으로 실행** → [관찰] 작업 `answer`가 IN_PROGRESS가 되고 워커가 집는다(실시간 스트림에 도구 호출이 흐른다) → [확인] 작업 행의 "에이전트 도구 기록"에서 `timeseries_schema` → `timeseries_query`(SQL 본문) 순서와 응답값, 폼의 `answer`.
2. [화면] 같은 방법으로 `business-question-v1.json`, 질문 `"HYD-02 설비의 현재 생산오더는 납기까지 몇 시간 남았고, 그 설비 판매 계약의 고객 등급은?"` → [관찰] `describe_catalog`/`describe_schema` → `query`(ent 스키마 SELECT) → [확인] 에이전트가 폼 `sql`에 적은 SELECT가 도구 기록의 실제 실행 SQL과 같은지.
3. [화면] `rule-question-v1.json`, 질문 `"규칙 rule:standby 의 조건이 설비 HYD-03에서 지금 성립하는가?"` → [관찰] 규칙 id만 주면 `dmn_rules`로 TESTS를 읽고 → `inputs`로 출처를 찾고 → 그 출처(CMMS · 시계열 · 최신 PS1)를 읽어 "지금 성립/불성립/모름"을 답한다 → [확인] "데이터 없음"이 "거짓"과 구분돼 있는지.
4. [표] 세 실행에서 도구 이름 · 출처(Neo4j / TimescaleDB / Supabase ent / Prometheus) · 호출 시각 · 응답값을 한 표로 → [확인] 정해진 호출 순서가 아니라 "실제 호출과 응답값"으로 판정한다.
5. [정리] 질문을 바꿔 보기: 같은 정의를 새 시작 이벤트 ID와 다른 `question`으로 다시 실행한다(정의 재등록 불필요). 기대값까지 자동 대조하려면 검사 스크립트(`--out .evidence/sessions/12/<이름>`)를 쓴다 — 스크립트가 기대값을 현재 DB에서 다시 계산한다.

## 막혔을 때
- 작업이 TODO/IN_PROGRESS로 멈춤: `AGENT_BRIDGE`가 아직 `legacy`이거나 워커가 없다. `curl 127.0.0.1:8080/healthz`와 8097 `/health`.
- 정의 등록이 400: 파일의 `forms`·`activities` 구조가 바뀌었다. 등록 API가 `validate_definition`(`it/process/procsvc/definition_registry.py` 14행)으로 검사한다.
- enterprise `query`가 거절: ent 스키마 밖 표·쓰기·다중 문장은 실행 전 거절된다(`definition-authoring.md` "업무 SQL의 실행 계약"). 거절은 0행이 아니다.
- 질의 시간 초과(`UNKNOWN`): 시계열 읽기 계정은 5초 statement timeout(`docs/sensor-queries.md`).
- 수업 뒤 `AGENT_BRIDGE=legacy`로 되돌린다.

## 증거
- `.evidence/sessions/12/`(2026-10-07 제작자, `run.py`·`commands.md`): 수업용 정의 3개를 검사 스크립트의 `definition()`에서 분리해 `docs/examples/`에 만들고(`01_made_definitions.json`), process 컨테이너 안의 실제 `validate_definition`으로 3개 모두 OK · 대조용 `inspection-review-v1.json` OK · 폼을 뺀 깨진 입력은 FAIL(`02_validate_definition.json`) — **검증됨**. **1~5단계 실행(워커가 질문을 집어 세 MCP를 호출)은 호스트 워커와 `AGENT_BRIDGE=off`가 필요해 하지 않음 — 미검증.**
- 제작자 증거(호스트 Claude Code 워커 실제 실행, 같은 정의 모양): 시계열 질문 `.evidence/reaudit/a083-timeseries-2/`, 업무 질문 `.evidence/reaudit/a081-questions-2/`, 규칙 질문 `.evidence/reaudit/a086-rules-2/`, 없는 열을 현재 스키마로 고쳐 재질의 `.evidence/reaudit/codex-sql-repair-aac86b9d/`(Codex). 학생 완주 증거 아님.
