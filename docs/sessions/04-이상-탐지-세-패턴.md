# 4. 이상 탐지: 세 패턴 (1부, 180분: 설명 60 / 실습 90 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
경보를 올리는 조건(쿨러 · 펌프 · 팬) 세 가지를 코드에서 읽고, 세 결함을 각각 주입해 탐지 단계가 바뀌는 것을 본다. 부하를 낮추면 펌프 경보가 꺼지는 이유를 데이터로 설명한다.
끝나면 세 패턴의 RAISE 기록 각 1건과 "가림과 회복의 차이" 한 문장이 남는다.

## 준비
- 스택 켜짐. 포털 http://127.0.0.1:8088, 탐지기 http://127.0.0.1:8092/docs.
- 읽을 파일: `it/detector/det/cep.py` 머리말(1~15행).
- 이 회차의 주입은 현재 배포에서 모두 사건·인스턴스를 연다(에이전트가 자동으로 카드를 만든다). 수업 뒤 RUNBOOK §3 잔재 정리를 한다.

## 실행 장면
1. [파일] `cep.py` 머리말 → [관찰] `COOLER_DEGRADATION raise: TS1 > 55 and CE < 70 and slope(TS1) > 0 / clear: TS1 < 52 and slope(TS1) <= 0`, `PUMP_LEAKAGE raise: PS1 < 165 and FS1 < 8.0 and LoadSP >= 80 / clear: (PS1 >= 168 and FS1 >= 8.0) or LoadSP < 80`, `FAN_VIBRATION raise: VS1 > 1.2 and slope(VS1) > 0 / clear: VS1 < 1.1`, 유지 시간 `HOLD_S = 60.0`(시뮬레이션 초, 머리말 아래 26행) → [확인] 세 패턴의 raise·clear 선이 왜 다른지(히스테리시스) 한 줄.
2. [화면] 포털 → **결함 시뮬레이션** → HYD-02 → **펌프 누설 주입** → [명령] `curl -s 127.0.0.1:8092/api/detector/state | python -m json.tool | grep -A12 '"HYD-02"'` → [관찰] `ps1`·`fs1`가 내려가고 `patterns`의 PUMP_LEAKAGE 단계가 IDLE → CANDIDATE → RAISED → [확인] `phase: RAISED`, `alert_id`가 생김.
3. [화면] HYD-03 → **팬 베어링 마모 주입** → [관찰] 같은 명령에서 `vs1`·`vs1_slope` 상승, FAN_VIBRATION RAISED → [확인] RAISE 1건.
4. [화면] HYD-01 → **쿨러 열화 주입** → [확인] COOLER_DEGRADATION RAISED(1회차와 같다).
5. [화면] HYD-02 카드에서 부하를 70 %로 낮춘다(수동 조작: `curl -X POST 127.0.0.1:8000/api/manual -H 'Content-Type: application/json' -d '{"asset":"HYD-02","writes":{"LoadSP":70}}'`; 수동 쓰기는 PLC를 REMOTE_MANUAL로 바꾼다) → [관찰] 60 시뮬레이션-초 뒤 PUMP_LEAKAGE가 CLEAR(조건 `LoadSP < 80`) → 그런데 `ps1`은 여전히 165 미만 → [확인] "경보가 꺼진 것(가림)과 설비가 회복한 것(PS1 ≥ 165)은 다르다"를 한 문장으로.
6. [명령] `docker compose exec timescaledb psql -U hyd -d hyd -c "SELECT asset, pattern, state, raised_at, cleared_at FROM alerts ORDER BY coalesce(raised_at, cleared_at) DESC LIMIT 8"` (raised_at이 빈 옛 행이 있어 `ORDER BY raised_at DESC`면 그 행들이 맨 앞에 온다) → [확인] 세 패턴 행. 경보 하나가 한 행이고, 해제되면 state가 CLEAR로 바뀌고 cleared_at이 채워진다.
7. [화면] 결함 시뮬레이션 → **전체 초기화 (정상 운전점)** → [확인] 세 설비 모두 IDLE·REMOTE_AUTO.

## 막혔을 때
- 펌프 경보가 안 난다: raise 조건에 `LoadSP >= 80`이 있다. HYD-02 부하가 80 % 이상인지 `/api/state`에서 확인.
- 팬 경보가 안 난다: `slope(VS1) > 0`이 필요하다. 주입 직후 진동이 올라가는 동안에만 조건이 성립한다.
- 주입 뒤 트립(OVERHEAT_TRIP 등)이 먼저 났다: 조치를 안 하면 약 80초 뒤 65 ℃ 트립(`scenario-walkthrough.md`). **결함 복구** → TS1 < 55 ℃ 뒤 RESET.
