# 21. 팬 베어링 마모 완주와 함정 (5부, 180분: 설명 30 / 실습 120 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
HYD-03에 베어링 마모를 넣어 진동 경보를 내고, "팬 감속 + 부하 저감"을 골라 VS1 < 1.2로 종결한다. 함정 실험으로 팬을 100 %로 올리면 진동 인터록이 걸리는 이유를 영향 관계로 설명한다.
끝나면 종결 1건, 인터록 1건, 설명 한 단락이 남는다.

## 준비
- 스택 healthy, 전체 초기화.
- 지식: `instances.cypher` 204행(`pattern:fan-vibration`, VS1 > 1.2 and slope(VS1) > 0), 289행(`skill:fan-slow-derate` "팬 40 % + 부하 80 %", SOP-FAN-01), 344~345행(AFFECTS: 팬 속도 −20 %, 부하 −10 %); 인터록 `thermal.py` 33행 `TRIP_VS1 = 2.0`, `plc.py` 머리말 `VS1 >= 2.0 HIGH_VIBRATION`; 진동 식 `thermal.vibration`(83행: 베어링 마모가 팬 속도에 비례해 증폭).
- 자동 검사(강사): `scripts/scenario_pump_fan_test.py --only fan`.

## 실행 장면
1. [화면] 결함 시뮬레이션 → HYD-03 → **팬 베어링 마모 주입** → [관찰] VS1 상승, 탐지 단계 RAISED(FAN_VIBRATION) → [확인] 경보 1건.
2. [화면] 이상 확인 · 조치 → HYD-03 카드 → 내 할일 → 생산관리자 → **팬 40 % + 부하 80 %** 선택 → [관찰] PASS · ACK DONE, 팬 40 % · 부하 80 % → [확인] ACK 1건.
3. [관찰] VS1이 1.1 아래로 내려가 CLEAR → 재관측 `VS1 < 1.2` → 정비 요청 → 종결 → [확인] 인스턴스 COMPLETED.
4. [함정] 새 실행: HYD-03에 다시 마모 주입(1~3단계 뒤 결함 복구를 했으면 그냥 주입) → 경보 → 이번에는 수동 조작으로 팬 100 %: `curl -X POST 127.0.0.1:8000/api/manual -H 'Content-Type: application/json' -d '{"asset":"HYD-03","writes":{"FanSpeedSP":100}}'` → [관찰] 약 1초 만에 VS1이 2.0을 넘어 PLC 상태 TRIP(`status.trip: HIGH_VIBRATION`), 모드는 REMOTE_MANUAL, 트립 경보(`alerts` 표의 `HIGH_VIBRATION_TRIP`) → [확인] 인터록 1건. 이 실행의 "조치 카드 선택"은 고르지 않고 둔다(30초 뒤 책임자 호출로 넘어간다 — 16회차).
5. [설명] Neo4j Browser → `MATCH p=(s {id:'sv:fan-speed'})-[:INFLUENCES*1..2]->(m) RETURN p`와 `thermal.vibration` 식 → [확인] "팬 속도 ↑ → 진동 ↑(마모 × 팬 속도) → 2.0 인터록"을 한 단락으로.
6. [정리] HYD-03 **결함 복구** → VS1 < 1.2 뒤 **RESET**(수동 쓰기 `{"Reset":1}`) → **원격 자동** → [확인] 정상 운전점.

## 막혔을 때
- 경보가 안 난다: `slope(VS1) > 0`이 필요하다. 주입 뒤 기다리되, 이미 포화됐으면 복구 후 다시 주입.
- 수동 조작 뒤 자동 조치가 거절: 수동 쓰기는 PLC를 REMOTE_MANUAL로 바꾼다(2회차). 원격 자동으로 복귀.
- RESET 거절 `RESET_TOO_HOT`: TS1이 55 ℃ 넘으면 안 된다(`plc.py` 113행).
