# 11. 범용 코딩 에이전트를 서버가 부른다 (3부, 180분: 설명 60 / 실습 90 / 정리 30)

## 이번에 할 것 / 끝나면 보이는 것
Claude Code · Codex 같은 범용 에이전트를 서버가 하위 프로세스로 실행하는 구조를 본다. 워커가 작업을 집어 CLI를 호출하고, CLI의 이벤트 스트림이 DB의 이벤트 행과 화면의 "에이전트 도구 기록"으로 이어지는 것을 대응시킨다.
끝나면 원시 스트림(JSONL)의 세션 id · 도구 호출 · 최종 결과와 DB `events` 행을 짝지은 표가 남는다.

## 준비
- 스택 + Supabase. 호스트 워커 1개(RUNBOOK §1 ⑤) — 이 회차는 읽기 위주라 워커 없이 과거 스트림 파일로도 진행할 수 있다.
- 파일: `it/agent-worker/worker/main.py`(머리말: poll → fetch_pending_task → Runner → save_task_result), `runner.py`, `bridge.py`, `events.py` 18행(`ROW_TYPE`: run_start→task_working, tool_start→tool_usage_started, tool_end→tool_usage_finished …), `codex_provider.py`.
- 과거 원시 스트림 예: `.evidence/reaudit/a086-rules-2/r1-run-*.events.jsonl`, Codex: `.evidence/reaudit/codex-registry-df9b60d2/events-1.json`.

## 실행 장면
1. [명령] `curl -s 127.0.0.1:8097/health` 와 `curl -s "127.0.0.1:8097/agents?check_auth=1"` → [관찰] `status: ok`, `agent_type: cliagents`, `max_concurrent_runs: 1`, `/agents`는 이 PC에 설치된 CLI 목록(`claude-code` 기본 · `codex`)과 설치 여부(`installed`). 로그인 상태는 응답에 없다 — `check_auth=1`을 붙여도 같은 목록이다(`it/agent-worker/worker/main.py` 39~45행). 로그인은 `claude` 단독 실행으로 확인 → [확인] 워커가 "ProcessGPT의 cliagents 에이전트 유형"임을 머리말에서 확인.
2. [파일] 호출 인자는 고정 버전 `cliagents` 패키지가 만든다: `.venv314/Lib/site-packages/cliagents/providers/claude_code.py` 82~98행(`--print … --output-format stream-json … --resume <세션>`)과 `providers/codex.py` 82~88행(`codex exec --json`, 재개는 `exec resume <세션>`). 저장소 쪽은 `runner.py`(382행 주석에 같은 인자)와 Codex 어댑터 `codex_provider.py`(재개 플래그 순서) → [확인] 두 CLI의 호출 방식 차이 표(인자 · 세션 재개 방법 · MCP 설정 파일 `.mcp.json` vs `codex-mcp.toml`).
3. [파일] JSONL 한 줄씩 읽기(한 줄 = `{"kind": …, "session_id": …, "tool": …, "tool_input": …, "tool_output": …, "raw": {…}}`) → [관찰] `kind`가 `run_start`(session id) → `tool_start`/`tool_end`(MCP 도구 이름·입력·출력) → `result`; `thinking`·`assistant_text`·`usage`·`unknown`(원시 상태 이벤트)이 사이에 섞인다 → [확인] 세션 id, 도구 호출 수, 최종 결과 문단을 적는다.
4. [화면] Supabase Studio http://127.0.0.1:54323 → 테이블 `events` → 같은 `todo_id`로 필터 → [관찰] `event_type`이 `task_started · tool_usage_started · tool_usage_finished · task_completed` → [확인] 3단계의 스트림 이벤트와 1:1로 짝짓는다(스트림에만 있고 행이 없는 것: `permission_request`, `events.py` 17행).
5. [화면] 포털 **프로세스 인스턴스** → 해당 인스턴스 → 에이전트 작업 행 펼침 → [관찰] "에이전트 도구 기록"(화면 표기: events)과 실시간 스트림 패널 → [확인] 4단계와 같은 행.
6. [정리] 비밀이 자식 프로세스로 가지 않게 막는 코드 `env_guard.py`, 실행 뒤 MCP 설정 정리 `bridge.cleanup` → [확인] "서버가 에이전트에게 주는 것과 안 주는 것" 두 줄.
