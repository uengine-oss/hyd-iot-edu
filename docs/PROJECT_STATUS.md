## 목표

우리가 만들고 있는 것은 강의용 축소 샘플이 아니라 **ProcessGPT의 핵심 업무 기능을 HYD 유압설비 사례에 구현하는 시스템**이다. 수강생은 실제 기능을 함께 만들어 가며 온톨로지·인제스천·에이전트·프로세스가 업무에서 어떻게 연결되는지 배운다. 회의 원문과 실제 ProcessGPT 관련 레포를 기준으로 개발한다. 교재·슬라이드 제작과 강의 리허설은 이 시스템 개발 범위에 포함하지 않는다.

완성하려는 한 흐름은 다음과 같다.

**설비 경보 → Start Event → 프로세스 인스턴스 생성 → 인스턴스 안의 AI·사람·서비스 Task 수행 → 사람 승인 → 안전한 조치 실행 → 실제 상태 재확인 → 완료 또는 복구**

인스턴스는 경보 한 건을 처리하는 업무 한 건이고, Task는 그 업무에 속한 개별 작업이다. 에이전트는 배정된 Task에서 온톨로지와 실제 업무 데이터를 조회해 결과를 내며, 정의된 조건과 사람의 결정에 따라 다음 작업이 진행된다.

## 만들어야 하는 기능과 당시 상태(2026-10-06, 이력)

회의 요구 R01–R14를 기준으로, 필요한 기능과 현재 확인된 상태를 나눠 적었다. ‘일부 구현’은 그 기능의 전체 완료를 뜻하지 않는다.

| 요구 | 쉽게 말한 기능 | 현재 상태와 남은 개발 |
|---|---|---|
| R01 온톨로지 | 설비, 고장, 원인, 조치, 규칙, 업무, 데이터가 서로 어떻게 연결되는지 시스템이 알게 한다. | 기본 스키마와 일부 실행 연결은 있다. 지식과 실제 업무 판단·실행 전체를 잇는 의미 관계는 더 연결하고 확인해야 한다. |
| R02 인제스천 | DDL·매뉴얼·SOP를 넣고, 출처를 보존하며, 검토 후 지식으로 반영·수정·되돌린다. | DDL과 SOP 적재, 문서 보관·추출 작업·사람 검토 경로가 있다. 일반 문서를 실제 Codex가 읽어 정확히 추출하고 지식 변경까지 이어지는 기능은 미완료다. |
| R03 온톨로지 질의 | AI가 필요한 지식 구조를 찾아 관계를 따라 원인·조치 근거를 얻는다. | Neo4j MCP 실제 호출 경로는 확인했다. 새 관계나 질문에도 필요한 정보를 제대로 찾아 판단하는 범위를 넓혀야 한다. |
| R04 업무 데이터 조회 | 주문·납기·재고 등 회사 업무 DB의 현재 사실을 찾아온다. | 실제 DB/MCP 조회와 납기 변화에 따른 권고 변경을 확인한 사례가 있다. 다양한 업무 데이터 변경을 AI 판단까지 연결하는 종합 경로가 남았다. |
| R05 최신 상태 조회 | 그래프에 오래된 숫자를 고정하지 않고 센서·업무 원천에서 현재값을 조회하며, 누락·오래된 값을 구분한다. | 출처·신선도·미확인 방어 일부와 실제 값 변경 확인이 있다. 모든 원천과 동적 예측까지 포괄하지는 않는다. |
| R06 데이터 기반 질의 | 구조와 조건을 보고 필요한 SQL·시계열 질의를 만들고 실제 결과를 읽는다. | 일부 SQL 생성·실행 및 PromQL 경로가 있다. 새 조건·컬럼·규칙을 폭넓게 처리하는 일반화는 미완료다. |
| R07 실제 에이전트 도구 사용 | 에이전트가 모의 응답이 아니라 실제 MCP·명령 도구를 쓰고 결과와 실패를 남긴다. | 실제 Codex와 도구 실행을 확인한 과거 경로가 있다. 최신 변경 지식·재작업을 반영한 Codex 실행은 아직 확인되지 않았다. |
| R08 이벤트부터 화면까지 | 실제 경보가 서버 처리를 시작하고, 에이전트 작업과 결과가 통합 화면까지 이어진다. | 경보→에이전트→제어 경로를 확인한 기록이 있다. 지연·중복·최신 통합 화면까지 포함한 전체 범위를 더 확인해야 한다. |
| R09 대안 비교 | 설비 상태와 납기·품질 등 조건이 충돌할 때 대안을 비교하고, 조건 변화에 따라 권고를 바꾼다. | 실제 업무 데이터 변화에 따라 권고가 바뀐 사례가 있다. 계약·품질 등 다양한 조건 변화는 더 연결해야 한다. |
| R10 사람 승인과 제어 | 담당자가 근거를 보고 선택·승인·거절하고, 권한 확인 뒤 승인된 조치만 실행한다. | 승인, 변경 조건 재확인, 포털·제어 일부 경로가 있다. 최신 AI 및 실제 고장까지 포함한 승인·실패 경계를 더 연결해야 한다. |

| R12 운영 모니터링 | 화면에서 인스턴스·Task·에이전트가 무엇을 했고 어디서 대기·실패했는지 확인한다. | 실행 이력과 일부 상태 화면을 확인했다. 전체 상태·복구 경로가 실제 원천 상태와 일치하는지 더 연결해야 한다. |
| R13 ProcessGPT 확장 기능 대조 | 기본 흐름을 넘어서 참고 제품의 지식·데이터 패브릭 등 필요한 기능을 선별해 확장한다. | 관련 레포 47개의 지도를 만들었다. 어떤 기능을 실제로 채택하고 구현할지 깊이 대조하는 작업은 미완료다. |
| R14 여러 설비·변경 시나리오 | 설비와 조건, 자료가 달라져도 같은 구조로 업무를 처리하고 변경 결과를 설명한다. | 설비 시나리오와 정의 변경 일부를 구현·확인했다. 여러 입력·경로에서 실제 시스템 변경이 끝까지 이어지는 범위는 더 넓혀야 한다. |

## 당시 어디까지 왔나(2026-10-06, 이력)

기본 인스턴스·Task 처리, 지식과 업무 데이터 조회, 사람 승인과 조치, 실행 기록·화면, 일부 조건 변경 및 복구 경로까지 개발했다. 최신 근거가 기록된 단계는 **A071**이다. A071은 별도 분기 조건의 대기와 타이머 도달을 실제 연결한 작업이며, 새 Codex가 변경 지식으로 판단한 결과는 아니다. 최신으로 기록된 전체 평가는 **62.5/100의 요구별 단계 점수**다. 작업량이나 완료율 62.5%라는 뜻은 아니다.

현재 보고서 기준으로는 A071까지 기록된 근거만 완료·확인 사실로 반영했다. 이후 작성 중인 보상·복구 변경은 구현 범위와 상태를 대조하기 전까지 완료 기능으로 세지 않는다.

## 당시 다음 개발 우선순위(2026-10-06, 이력 — 1~3은 이후 A072·A073·A077~A134에서 진행됐다. 현재 남은 일은 위 "현재 상태" 표)

1. 이미 실행된 조치의 효과를 어떻게 확인하고, 실패·취소 때 어떤 보상 조치를 할지 참고 ProcessGPT 계약과 HYD 승인·명령·업무 영수증에 맞춰 구현한다.
2. DDL·매뉴얼 등 원천 변경이 온톨로지 의미 관계와 AI의 새 조회·판단까지 전파되는 경로를 완성한다. 일반문서 실제 추출도 확인한다.
3. 새 Codex가 변경된 지식·업무 조건으로 실제 판단하는 경로와 이벤트 시작부터 승인·제어·화면까지 연결한다.
4. R01–R14와 참고 레포 대조에서 남은 조건·복구·모니터링·다중 시나리오 범위를 닫고 전체 요구를 다시 평가한다.
