# HYD 시스템 개발 현황

2026-10-05

## 1. 목표와 방향

**온톨로지와 AI 에이전트 중심의 강의 내용을 확충하기 위해, ProcessGPT의 핵심 구조를 유압설비 사례로 직접 구현하고 있다.** 지식을 준비하고, 업무를 시작하고, AI와 사람이 각자의 작업을 수행하는 개발 과정 자체를 강의의 재료로 활용하는 것이 목적이다.

최종 목표는 다음 흐름을 실제로 동작하게 만드는 것이다.

**설비 이상 감지 → Start Event로 업무 시작 → 프로세스 인스턴스 생성 → Task 안에서 AI 판단 → 사람 승인 → 조치 실행 → 결과 확인·종결**

프로세스 인스턴스는 ‘이번 경보를 처리하는 업무 한 건’, Task는 그 안의 개별 작업이다. AI는 자신에게 배정된 Task에서 필요한 자료를 조회하고 판단 결과를 제출한다. 업무 전체는 미리 정한 순서와 조건에 따라 진행된다.

이 구조를 만들어 가면서 각 기능의 필요성을 이해하고, 강의 후반에는 직접 구현한 구조와 실제 ProcessGPT를 연결해 보여 주는 방향이다. 개발은 회의 내용과 ProcessGPT 관련 실제 코드를 참고해 진행한다.

## 2. 해야 하는 일

1. **AI가 사용할 지식 준비하기**

   매뉴얼·작업 절차·DB 구조를 읽어 설비, 고장, 조치 방법, 필요한 데이터의 위치를 연결한다. 이 연결된 지식이 ‘온톨로지’이고, 자료를 읽어 넣는 과정이 ‘인제스천’이다.

2. **경보가 나면 처리할 업무 만들기**

   어떤 이벤트로 시작하고 어떤 작업을 거쳐 끝낼지 정한다. 경보가 들어오면 그 정의에 따라 업무 한 건과 필요한 Task를 만든다.

3. **Task 안에서 AI가 조회하고 판단하게 하기**

   AI가 온톨로지에서 관련 지식을 찾고, 현재 센서 값과 주문·납기·품질 데이터를 조회한다. 이를 바탕으로 원인과 조치 후보를 정리하고 규정과 우선순위를 검토한다.

4. **사람의 선택을 실제 조치로 연결하기**

   담당자가 근거와 대안을 보고 선택·승인하면 정해진 경로로 설비 명령이나 정비 업무를 실행한다. 실행 후에는 상태를 다시 확인해 회복 여부를 판단한다.

5. **업무 진행 상황을 화면에 보여 주기**

   어떤 Task가 진행 중인지, 누구의 승인을 기다리는지, AI가 무엇을 조회하고 판단했는지, 어디서 실패했는지를 확인할 수 있게 한다.

6. **조건이 바뀌거나 중단돼도 올바르게 처리하기**

   매뉴얼·납기·규칙이 바뀌면 판단에도 반영하고, 재시작이나 재요청으로 조치가 중복되지 않게 한다. 이미 실행한 조치를 다시 검토해야 할 때의 처리도 마련한다.

## 3. 지금까지 한 일

**기본 업무 흐름을 연결해 실행했고, 조건 변경과 중단 후 복구를 보강하는 단계다.** 현재 확인한 실행은 모의 설비와 로컬 업무 DB를 사용한 결과다.

- **경보에서 업무 시작까지 연결했다.** 경보를 받아 프로세스 인스턴스와 소속 Task를 만들고, 정의된 순서에 따라 작업을 진행하는 구조를 구현했다.
- **지식·데이터 조회 경로를 만들었다.** 문서와 DB 구조를 지식으로 넣고 수정하는 기능, 센서와 업무 데이터를 조회하는 기능을 구현하고 일부 변경 상황까지 확인했다.
- **AI 작업과 사람 승인·실행을 연결했다.** 실제 AI가 조회 도구를 사용해 작업한 실행 이력이 있다. 별도 규칙 실행 시험에서는 납기·업무 값이 바뀔 때 권고가 달라지는 것도 확인했다.
- **승인 이후 처리 결과를 확인했다.** 모의 설비에 명령을 전달하고 상태를 다시 확인한 뒤 정비 작업지시를 만들고 종결하는 흐름을 검증했다. 최신 전체 흐름 시험은 기존 규칙 엔진을 사용했으며, 최신 코드의 실제 AI 검증은 남아 있다.
- **진행 화면과 복구 기능을 보강했다.** 업무·AI 작업·실행 이력을 보여 주는 화면을 마련했다. 재시작, 중복 요청, 늦은 제출, 승인 시간초과, 조건 변경에 따른 재검토도 검증했다.

## 4. 남은 일

- **새 자료가 실제 AI 판단에 이어지는지 확인:** 새 매뉴얼·DB 항목·규칙을 넣었을 때 AI가 바뀐 내용을 정확히 찾고 조회·판단·조치안에 반영하는지 검증해야 한다.
- **이미 실행한 조치의 후속 처리 완성:** 정비 지시나 설비 명령을 실행한 뒤 판단이 바뀌면 실제 상태를 확인하고, 취소 가능한 업무와 별도 후속 조치가 필요한 경우를 처리해야 한다.
- **최신 AI와 화면을 포함한 전체 흐름 검증:** 쿨러·펌프·팬 사례에서 실제 AI 작업, 사람 승인, 실행 결과와 화면 표시가 함께 맞는지 확인해야 한다. 거부·시간초과·데이터 누락·재시작도 포함한다.
- **참고 코드와 남은 기능 대조:** ProcessGPT 관련 코드에서 필요한 구조와 기능을 더 확인하고, 현재 구현에 빠진 부분을 보완해야 한다.
