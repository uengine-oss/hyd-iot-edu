# HYD 시스템 개발 현황 — 2026-10-05

**최종 방향은 설비 경보부터 근거 조회·대안 판단·사람 승인·실행·결과 확인까지 연결하고, 정의·지식·규칙·업무 데이터가 바뀌어도 그 변화에 맞게 동작하는 시스템을 만드는 것이다.** 현재 A071까지 구현·부분 실동 검증을 마쳤으며 전체 목표는 진행 중이다.

## 1. 최종적으로 만들 시스템

회의에서 제시한 유압설비 사례를 중심으로 다음 흐름을 구현한다. 지원 범위와 판단 근거는 명시하며, 시나리오 이름에 따른 고정 정답 반환으로 대체하지 않는다.

```text
설비·센서의 실제 상태와 경보
  → 프로세스 인스턴스와 에이전트 작업 생성
  → 온톨로지에서 매뉴얼·SOP·규칙·데이터 위치 탐색
  → MCP로 현재 센서·기업 DB 조회
  → 원인과 조치 후보, 설비·납기·품질의 득실 제시
  → 담당자의 검토·선택·승인
  → PLC 명령 또는 기업 업무 실행
  → 응답·재관측·작업지시·종결 및 실행 이력 확인
```

판단 중 조건이 바뀌면 이전 동의를 재사용하지 않고 새 검토로 이어져야 한다. 실패·누락·중복·재시작·시간초과도 실제 상태와 일치해야 한다. 기준은 [회의 원문](handoff/sources/meeting-2.txt), [전체 요구 R01~R14](handoff/AUDIT.md), [현재 목표와 수용조건](handoff/GOAL.md)이다. 참고 레포는 고정 버전의 실제 코드를 대조해 채택하며 제품 전체를 복제했다고 주장하지 않는다. 현재 작업은 시스템 개발·검증·운영 문서이고 교재·슬라이드·수업 리허설은 제외한다.

## 4. 남은 일과 다음 우선순위

| 순서 | 수행할 일 | 완료를 판단할 결과 |
|---|---|---|
| 1 | 이미 실행된 효과의 확인·보상 계약 | 실제 명령/기업 영수증을 근거로 사람 검토·처리·복구를 수행. 상태만 초기화하거나 물리 효과가 취소됐다고 가정하지 않음 |
| 2 | 원천→확정/미확정 의미→지식/규칙→새 판단 연결 | 새 문서·컬럼·조건을 넣고 원문·불확실성을 보존하면서 실제 질의·대안·승인 결과가 달라짐 |
| 3 | 남은 참고 레포의 깊은 채택 대응 | 각 요구에 실제 코드·채택/비채택 이유·HYD 구현·수용 검증이 연결됨. 확보/열람 건수로 완료 판정하지 않음 |
| 4 | 최신 Codex·직접 UI와 변경 시나리오 종합 검증 | 최신 코드에서 실제 모델의 추출/질의/재작업과 화면·실행 결과가 일치. 실패·중복·재시작도 확인 |

현재 새 Codex 워커는 Windows 스크립트 정책, 직접 UI는 Device Guard/브라우저 가용성 때문에 미검증이다. 차단을 우회하거나 이전 성공을 최신 검증으로 대체하지 않는다. 독립적으로 진행 가능한 구현은 계속한다. 보고 준비를 시작할 때 후속 보상 검토는 코드 열람 단계였다. 이후 최종 Git 비교에서 `state.py`, `supabase_backend.py`, `test_entsim.py`, `20261005000015_enterprise_compensation.sql`의 **A072 미커밋 변경**이 추가된 것을 확인했다. 이 보고에서 해당 변경의 구현·배포·검증을 확인하지 않았으므로 로컬 WIP로 보존하고 이번 A071 전달 범위에서는 제외했다.

## 5. 진척과 보고 기준

[현재 평가](handoff/PROGRESS.md)는 **62.5/100**이다. R01~R14를 동일 가중치로 평가한 단계 점수이며 실제 공수 완료율이나 납기 예측이 아니다. 핵심 정상 경로와 여러 변경·복구 경로는 작동하지만 위 미결 때문에 전체 완료를 선언할 수 없다.

완료 기준은 모든 요구의 실제 수용 증거, 지원 범위 내 변경 실행, 최신 Codex/MCP/사람 승인/제어/화면 검증, 정확한 운영 문서다. 작업은 실제 API·입력·시간 계약을 먼저 확인하고 관련 검사→안정된 단계의 전체 검사 순으로 진행한다. 재개 정보는 [HANDOFF §0·§9 G·§10](handoff/HANDOFF.md), 참고 코드 대응은 [REFERENCE_ADOPTION](handoff/REFERENCE_ADOPTION.md)에 유지한다.
