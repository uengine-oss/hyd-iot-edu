# hyd-iot-edu

HYD 제조 AI 교육과정(경남대학교 피지컬AI 사관학교)의 시스템과 교재다. 유압 설비의 값이 올라와 저장되고, 이상이 감지되면 에이전트가 근거를 모아 조치를 추천하고, 사람이 승인하면 시스템이 실행한다. 이 시스템으로 온톨로지, 에이전트, 업무 흐름을 가르친다.

## 어디부터 읽는가

운영 기준은 `문서/`에 있고, 현장에서 따라 할 설치 안내는 `산출물/설치/`에 있다.

| 하려는 일 | 읽을 곳 |

| 시스템(포털, 설비)을 켜거나 고친다 | [`문서/시스템/1_목적과_방향.md`](문서/시스템/1_목적과_방향.md) |

기본 문서는 다음 순서이며 교재 상세 기준은 덱·실습·검증으로 나뉜다: 1 목적과 방향, 2 기준, 3 현황, 4 만드는 법(켜고 돌리는 법), 5 결정 기록, 6 남은 일.

## 수업: 같은 환경을 준비하고 포털 열기

이 README를 화면에 열어 두고 **도구 소개 → 프로젝트 ZIP 받기 → 운영체제별 설치 파일 → VS Code 설정 → 시작 파일 → 포털 접속** 순서로 진행한다. Windows는 `.bat`, Mac은 `.command`를 사용한다. 설치 코드 하나하나보다 시작을 기다리는 동안 주요 명령과 실제 진행 상황을 연결해서 본다.

### 1. 무엇을 왜 준비하는가

| 도구 | 이번 수업에서 하는 일 |
|---|---|
| [VS Code](https://code.visualstudio.com/) | 프로젝트 폴더와 자료를 열고, 코드를 수정하고, 명령을 실행하는 작업 공간이다. |
| [Git](https://git-scm.com/) / GitHub | Git은 변경 이력을 관리하는 도구, GitHub는 프로젝트를 공유하는 웹사이트다. 처음에는 ZIP으로 받는다. Windows는 Git Bash, Mac은 기본 Bash로 시작 스크립트를 실행한다. |
| [WSL](https://learn.microsoft.com/ko-kr/windows/wsl/install) | Windows에서 Linux 프로그램을 실행하는 기반이다. Docker의 WSL 2 실행 방식에서 사용한다. Mac에는 필요 없다. |
| [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) | 여러 프로그램을 준비된 구성으로 실행·관리한다. 학생마다 데이터베이스 등을 하나씩 설치하고 설정하는 부담을 줄인다. |
| [Node.js](https://nodejs.org/) | JavaScript 도구를 실행한다. 업무 DB 준비 도구를 필요할 때 받아 실행하는 데도 쓴다. |
| [Python](https://www.python.org/downloads/) | 시작할 때 다른 프로그램과 접속 포트가 겹치지 않도록 준비하는 스크립트를 실행한다. 두 운영체제 모두 설치 파일에서 3.14.7 이상을 확인하고 없거나 낮으면 설치한다. |
| Codex | VS Code에서 요청을 전달하고 코드 작성·수정·확인을 함께 진행하는 AI 도구다. 설치 뒤 자신의 ChatGPT 계정으로 연결한다. |

Docker의 **이미지**는 프로그램과 실행에 필요한 파일을 담은 묶음이다. **컨테이너**는 그 이미지를 바탕으로 만든 실행 환경이다. 같은 프로젝트 구성으로 여러 컨테이너를 실행하므로 같은 실습 환경을 준비하기 쉽다. 컴퓨터의 운영체제·CPU·메모리까지 저절로 같아지는 것은 아니므로 마지막 실행 확인이 필요하다.

### 2. 프로젝트 ZIP 받기와 설치

자동 설치 최소 기준은 두 운영체제 모두 **Docker Desktop 4.87.0 / VS Code 1.143.0 / Node.js 24.16.0 / Git 2.54.0 / Python 3.14.7**이다(2026-10-22 강사 Windows PC 기준). **같거나 높으면 유지하고, 없거나 낮으면 설치·업데이트 후 기준 이상인지 다시 확인한다.** 설치되는 판은 기준보다 높을 수 있다. Windows의 WSL 기준은 **2.7.12.0**이다. 기존 버전을 읽지 못하면 덮어쓰지 않고 실패로 표시한다. 배포처 버전이 기준에 못 미치거나 설치 후에도 예전 실행 파일이 선택되면 완료로 처리하지 않는다.

#### Windows

1. [수업 저장소 develop](https://github.com/uengine-oss/hyd-iot-edu/tree/develop)을 열고 **Code → Download ZIP**으로 프로젝트 전체를 받는다.
2. 탐색기에서 **모두 압축 풀기**를 선택한다. 압축을 푼 폴더 안에 `설치.bat`, `시작.bat`, `scripts` 폴더가 함께 있는지 확인한다. ZIP 안에서 바로 실행하거나 배치 파일만 따로 옮기지 않는다. 기존 프로젝트 폴더에 덮어쓰지 않는다.
3. **`설치.bat`을 더블클릭**하고 관리자 승인 창의 내용을 확인한 뒤 승인한다. 앞에서 소개한 Docker Desktop·VS Code·Node.js·Git·Python과 WSL 실행 기능을 준비한다. 개별 설치 옵션을 하나씩 설정하는 대신 배치가 설치를 진행한다.
4. 결과 표에서 설치·업데이트·유지 여부를 확인한다. 실패 항목은 비고를 확인하고, 재부팅 안내가 나오면 재부팅한다.

Windows에서는 설치·업데이트가 필요한 항목에 `winget`을 사용한다. 실행 경로에서 찾지 못하면 Windows에 등록된 앱 설치 관리자(App Installer)의 위치를 자동 확인한다. 사용자 이름·드라이브·패키지 버전 경로를 직접 입력할 필요는 없다. 이미 기준을 만족하는 항목은 `winget` 없이도 유지 여부를 확인한다.

강사 PC에서도 같은 배치를 실행한다. 기준을 만족하는 도구는 빠르게 건너뛰고, 처음 설치하는 PC는 다운로드 때문에 더 오래 걸린다. 배치는 학교 공용 PC용 Docker 사용 권한과 프로젝트 폴더 접근 권한도 준비한다.

**Windows 준비도 설치 파일에 포함:** Python·WSL과 필요한 Windows 기능까지 설치·확인한다. WSL 설치에는 별도 Ubuntu 배포판이 필요하지 않다. 재부팅 요청이 나오면 재부팅 후 `설치.bat`을 다시 실행해 결과를 확인한다. BIOS 가상화, 관리자 승인, Docker 약관 동의는 화면 안내에 따라 처리한다. `winget`이 없으면 Microsoft Store의 앱 설치 관리자(App Installer)를 먼저 준비한다.

#### Mac

1. 같은 저장소에서 **Code → Download ZIP**으로 받고 Finder에서 ZIP을 열어 압축을 푼다. `설치.command`, `시작.command`, `scripts` 폴더를 함께 둔다. 기존 프로젝트에 덮어쓰지 않는다.
2. **`설치.command`를 더블클릭**한다. [Homebrew](https://brew.sh/)가 없으면 공식 설치 스크립트로 먼저 준비한다. 터미널의 설치 내용·Enter·관리자 암호 요청을 확인한다. 암호 입력 중 글자가 보이지 않는 것은 정상이다. 전체 파일을 `sudo`로 실행하지 않는다.
3. Docker Desktop·VS Code·Node.js·Git·Python의 `[유지]`·`[완료]`·`[실패]` 결과를 확인한다. 기준 미달인 항목만 [Homebrew 설치·업데이트](https://docs.brew.sh/Manpage)를 수행한다. 의존 패키지도 함께 설치될 수 있다. Docker·VS Code는 업데이트 전에 작업을 저장하고 종료한다. `/Applications`와 `~/Applications`의 앱을 확인하며 두 곳에 중복된 앱은 자동 교체하지 않는다.
4. **Python도 설치 파일이 준비한다.** 3.14.7 이상이 있으면 유지하며 기존 Python·Anaconda는 삭제하지 않는다. Mac에는 WSL·Git Bash가 필요 없다.
5. Docker Desktop을 열어 초기 설정과 약관 동의를 완료하고 **Engine running**을 확인한다. 현재 macOS가 [Docker Desktop 지원 조건](https://docs.docker.com/desktop/setup/install/mac-install/)과 Homebrew 지원 조건을 만족해야 한다.

ZIP 다운로드 후 실행 권한 오류가 나면 터미널에서 `cd ` 뒤에 압축을 푼 폴더를 끌어다 놓고 Enter를 누른 다음 아래를 한 번 실행한다. 이후 더블클릭할 수 있다.

```bash
chmod +x 설치.command 시작.command
./설치.command
```

보안 경고가 나오면 출처와 파일을 확인한 뒤 **시스템 설정 → 개인정보 보호 및 보안**에서 해당 파일의 실행 허용을 확인한다. 보안 기능 전체를 끄지 않는다. 더블클릭 대신 프로젝트 폴더에서 `bash 설치.command`, `bash 시작.command`로 실행할 수도 있다.

**Mac 검증 범위:** 설치 정책과 쉘 구문은 자동 검사 대상이다. 실제 Intel·Apple Silicon Mac에서 설치, Docker 이미지 실행, 포털 접속까지의 검증은 아직 완료하지 않았다.

### 3. VS Code 한국어 설정과 첫 채팅

1. **File → Open Folder**로 압축을 푼 프로젝트 폴더를 연다. 탐색기는 파일을 찾는 곳, 터미널은 명령을 입력하는 곳, Codex 패널은 AI에게 요청하는 곳이다.
2. 왼쪽 **Extensions**(확장, Windows `Ctrl+Shift+X` / Mac `Cmd+Shift+X`)에서 **Korean Language Pack for Visual Studio Code**를 찾아 Microsoft 게시 확장을 설치한다.
3. Windows `Ctrl+Shift+P` / Mac `Cmd+Shift+P`로 명령 팔레트를 열고 **Configure Display Language → 한국어(ko)**를 선택한다. 안내에 따라 다시 시작하고 한국어 메뉴를 확인한다. [공식 표시 언어 안내](https://code.visualstudio.com/docs/configure/locales)
4. 확장 화면에서 **Codex**를 찾아 OpenAI 게시 확장을 설치한다. Codex 패널에서 **ChatGPT로 로그인**해 자신의 계정을 연결한다. [공식 Codex 확장 안내](https://learn.chatgpt.com/docs/codex/ide)
5. 모델 목록에 **GPT-6 Luna**가 표시되면 선택하고 `안녕하세요`를 입력해 답변을 확인한다. 답변 문장은 매번 달라도 된다.

Codex는 Free 플랜에도 제공되지만 사용량과 모델 제공 범위는 계정·제품에 따라 다르다. 공식 무료 GPT-6 Luna 안내는 데스크톱 앱 기준이므로 VS Code 확장에서도 표시되는지는 수업 전에 확인한다. 목록에 없으면 다른 모델을 같은 모델이라고 설명하지 않는다. [플랜 안내](https://learn.chatgpt.com/docs/pricing) · [모델 안내](https://learn.chatgpt.com/docs/models)

### 4. 운영체제별 시작 파일 실행

Docker Desktop에서 **Engine running**을 확인하고 프로젝트 폴더에서 **Windows는 `시작.bat`, Mac은 `시작.command`를 더블클릭**한다. 실행 창은 닫지 않는다. 두 파일은 같은 `scripts/start_all.sh`를 실행한다. Mac에서 Docker가 꺼져 있으면 앱을 열고 최대 3분 기다린다. 초기 설정이 끝나지 않았으면 설정 후 다시 시작한다. 아래 명령들은 **시작 파일 안에서 하는 일을 읽기 위한 것**이다. 실행 중에 같은 명령을 다시 입력하지 않는다.

### 5. 시작을 기다리는 동안: 어떤 일이 일어나는가

| 실제 진행 표시 | 주요 명령·동작 | 쉽게 읽는 의미 |
|---|---|---|
| `1/6 Docker 확인` | `docker info`, `docker compose version` | Docker가 준비됐는지 확인한다. Compose는 프로젝트의 여러 프로그램을 함께 실행하는 도구다. |
| `2/6 .env 준비` | 실행 설정 준비, `scripts/prepare_ports.py` | 수업용 실행 모드와 업무 DB 설정을 준비하고 사용 가능한 접속 포트를 찾는다. 포트는 같은 PC의 프로그램들을 구별하는 접속 번호다. 설정 파일의 비밀값을 열 필요는 없다. |
| `3/6 업무 DB(Supabase) 켜기` | `it/supabase`에서 `npx -y supabase@2.119.0 start` | 설치 파일에서 준비한 CLI로 업무 DB를 켠다. 처음에는 여기에 필요한 이미지도 내려받는다. |
| `4/6 시스템 빌드 · 기동` | `docker compose up -d --build` | `compose.yaml`에 적힌 구성으로 이미지를 준비하고 프로그램을 실행한다. `--build`는 프로젝트 코드로 이미지를 만들고, `-d`는 실행한 프로그램이 뒤에서 계속 동작하게 한다. |
| `5/6 에이전트용 MCP 서버 둘` | `docker compose up -d --build --no-deps enterprise-mcp dmn-mcp` | 업무 자료 조회와 규칙 판단 도구를 준비한다. `--no-deps`는 연결 대상들을 다시 시작하지 않고 지정한 두 서비스만 다룬다는 뜻이다. MCP의 상세 원리는 이후 수업에서 다룬다. |
| `6/6 상태 확인` | `curl`로 응답 확인, `docker ps`로 실행 목록 확인 | 실행 명령이 끝난 것과 사용할 준비가 된 것은 다르다. 각 프로그램과 포털의 응답을 확인한 뒤 접속 주소를 보여 준다. |

**지금 내려받는 것은 포털 설치 파일 하나가 아니라, 역할이 다른 프로그램 묶음들이다.** 실제 `compose.yaml`의 구성은 다음과 같다. 선택 기능과 실행 설정에 따라 켜지는 범위는 달라진다.

| 내려받거나 만드는 구성 | 하는 일 |
|---|---|
| EMQX / Redpanda | 설비에서 보낸 값과 사건을 전달하고 이어서 처리할 수 있게 한다. |
| TimescaleDB / Supabase | 시간에 따라 바뀌는 측정값과 업무 기록을 각각 저장한다. |
| Neo4j | 설비·부품 등 대상 사이의 관계를 저장한다. 이후 지식 연결 수업에서 사용한다. |
| FUXA / Grafana | 설비 화면과 값의 변화를 보여 준다. |
| Nginx (`portal`) | 브라우저에 포털 화면을 제공하고 필요한 요청을 연결한다. |
| `plant-sim`, `detector`, `agent`, `process` 등 | 설비 모사·이상 감지·판단 지원·처리 흐름을 담당한다. 받은 프로젝트 코드로 실행 이미지를 만드는 단계도 있다. |

`Pulling`·`Downloading`은 파일 받기, `Extracting`은 압축 풀기다. 빌드의 `CACHED`는 앞서 만든 부분을 재사용했다는 뜻이다. `Started` 뒤에도 준비 확인이 이어질 수 있다. 받은 이미지와 빌드 결과가 있으면 다음 시작은 더 빨라질 수 있고, 매번 긴 다운로드가 발생하는 것은 아니다.

현재 진행 중인 단계에 맞춰 설명한다. 시작이 빨리 끝나면 완료된 상태에서 주요 명령의 의미를 짚고 포털로 이동한다. 시간을 만들려고 이미지·데이터를 지우지 않는다. 오류로 멈춘 경우에는 대기 중이라고 설명하지 않고 마지막 오류와 해당 단계를 확인한다.

### 6. 포털 접속과 마무리

완료 메시지에 표시된 **포털 주소**를 브라우저에서 연다. 포트가 다른 프로그램과 겹치면 바뀔 수 있으므로 이번 출력값을 사용한다. 포털과 홈의 상태 표시를 확인한다. 포털이 열리는 것과 모든 후속 AI·시나리오 준비가 끝난 것은 구별한다. 별도로 받은 접속 설정과 전체 점검은 아래 학교 PC 안내를 따른다.

문제가 있을 때 프로젝트 폴더의 터미널에서 `docker compose ps`는 서비스 상태를, `docker compose logs portal`은 포털 실행 기록을 보여 준다. 모든 로그를 낭독하지 않고 오류가 난 서비스의 기록을 확인할 때 쓴다. 실습을 마치면 **Windows는 `끄기.bat`, Mac은 프로젝트 폴더의 터미널에서 `bash scripts/stop_all.sh`**로 종료한다.

## 학교 PC에 설치하고 켜기

이 절은 **Windows 학교 PC** 안내다. Mac은 위의 Mac 설치·시작 절을 따른다.

**전체 설치는 아래 순서대로 진행한다.** 상세 화면·수동 설치는 [학교 PC 설치·실행 확인](산출물/설치/학교PC_설치확인/학교PC_설치확인.md)을 보고, WSL·Docker에서 막힌 경우에만 [사진·명령어로 보는 오류 해결](문서/시스템/참조/Windows_Docker_설치.md)을 연다.

**준비:** 재부팅하면 초기화되는 PC는 강의실 관리자와 복원 기능 해제·변경 유지 방법부터 확인한다. C 드라이브 여유는 40 GB 이상을 권한다.

**저장소 받기 — PowerShell:** Git이 없는 경우에만 먼저 `winget install -e --id Git.Git`을 실행하고 PowerShell을 새로 연다. 처음 받는 PC에서는 아래를 실행한다.

```powershell
git clone -b develop https://github.com/uengine-oss/hyd-iot-edu.git C:\hyd-iot-edu
Set-Location -LiteralPath 'C:\hyd-iot-edu'
```

이미 저장소가 있으면 해당 폴더에서 `git branch --show-current`로 `develop`인지 확인한 뒤 `git pull --ff-only origin develop`으로 갱신한다. 로컬 수정 때문에 거부되면 강제 덮어쓰기 전에 변경 내용을 확인한다.

| 순서 | 실행할 것 | 확인할 것 |
|---|---|---|
| 1 | 저장소 폴더의 **`설치.bat`** 더블클릭 | 관리자 승인 후 없거나 최소 기준보다 낮은 프로그램 설치·업데이트. 결과 표의 실패 항목 확인 |
| 2 | 안내에 따라 재부팅 후 **Docker Desktop** 열기 | 약관 동의 후 **Engine running** 확인. 오류 시 아래 안내로 복구 |
| 3 | **루트 `.env` 접속 설정** | Google Drive에 보관한 주소·중계키·모델 복사·저장. 이미 설정했다면 생략 |
| 4 | **`시작.bat`** 더블클릭 | 완료 메시지와 이 PC의 포털 주소 확인 |
| 5 | **`점검.bat`** 더블클릭 | 실패 항목이 없는지 확인하고, 중계 서버가 **「연결됨」**인지 확인 |
| 종료 | **`끄기.bat`** 더블클릭 | 실습 스택 종료 |

**설치 정책:** Docker 4.87.0·VS Code 1.143.0·Node.js 24.16.0·Git 2.54.0·Python 3.14.7·WSL 2.7.12.0을 기준으로, 같거나 높으면 유지하고 낮거나 없으면 설치·업데이트한다. WSL용 Windows 기능도 준비한다. 기존 Python·Anaconda와 데이터는 삭제하지 않는다. 재부팅 후 확인이 필요한 항목은 완료로 표시하지 않는다. 이 범위는 포털 실행 환경이며 별도 PLC 실습용 XG5000은 기존 개별 설치 안내를 따른다.

**중계 설정(3번):** Google Drive에 보관한 `.env`의 `OPENAI_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` 세 값을 **저장소 루트 `.env`**에 복사·저장한다. 루트 `.env`가 없으면 `.env.example`을 복사해 만든다. `OPENAI_API_KEY`는 비워도 된다. `점검.bat`을 더블클릭하면 루트 설정을 자동 사용한다. 루트에 중계키가 없을 때만 기존 실습 폴더 설정을 사용하며, 명시적인 `-LlmEnvFile` 지정은 우선한다. 이미 발급한 중계키이므로 **gcloud 조회·재발급은 필요 없다.** 값이 있으면 점검 때 다시 묻지 않는다. 중계 서버 「건너뜀」은 연결 확인 완료가 아니다. 실제 키를 넣은 파일은 커밋·푸시하지 않는다.

**WSL·Docker에서 막히면(2번):** [오류 해결 가이드](문서/시스템/참조/Windows_Docker_설치.md)에서 Hyper-V 지원 여부 확인 → 가능하면 Docker를 Hyper-V로 실행 → 불가능하면 WSL 오류 복구 순서로 진행한다. Docker가 정상 실행되면 위 3번으로 돌아온다. 이미 WSL 설치에 실패한 학교 PC는 이 단계부터 이어가며, 정상화한 뒤 전체 `설치.bat`을 반복해 WSL을 다시 설치할 필요는 없다. 나머지 도구의 실패 항목은 별도로 해결한다.

**복제 PC:** 메인 PC에서 점검을 마친 뒤 학교의 이미지 복제를 진행한다. 복제 후에는 `시작.bat` → `점검.bat`으로 해당 PC 상태를 확인한다. 시작 시 포트 충돌을 확인해 빈 포트로 옮기며(업무 DB·메일 포함), 포털과 점검은 같은 포트 표(`.hyd-runtime/ports.json`)를 사용한다. 포털 주소는 시작 완료 메시지에 표시된다. 학교 PC의 복원·계정·Docker 데이터 복제 여부는 현장에서 확인해야 한다.

## 지키는 것

- 공개 저장소다. 키, 사람 이름, 메일, 절대 경로, 내부 주소를 올리지 않는다. 강의 영상·음성은 main · develop에 올리지 않고 `other-pc` 브랜치에만 둔다(문서/교재/2_기준.md 76번).
- `.env`는 열지 않는다.
- 브랜치는 `main`과 `develop` 둘만 쓴다. 커밋은 경로를 지정한다.
- 문서를 새로 늘리지 않는다. 옛 지침과 쓰이지 않는 파일을 남기지 않는다.
