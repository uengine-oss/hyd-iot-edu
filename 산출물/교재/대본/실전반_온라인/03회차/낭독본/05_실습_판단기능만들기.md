# 실전반 3회차 실습 2 — 판단기능만들기


## 자료 다운로드와 조건표 연결

앞에서 검토한 조건표를 읽어 후보별 판단과 이유를 내는 기능을 만들겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.


앞 조건표가 이번 프로그램의 기준입니다. 기존 실행 틀과 입력 형식을 도우미와 확인한 뒤, 필요한 처리 순서를 정하겠습니다.


cases.csv의 입력을 읽고 expected.md에 예상 판단을 먼저 적겠습니다. 결과를 본 뒤 기대값을 맞추지 않도록 경계와 적용 대상을 먼저 적습니다. 지난 회차 조건표는 팬 최대 운전 후보를 중심으로 만들었습니다. targets.csv의 다른 후보도 비교하려면 원문의 적용 대상에 맞게 행을 확장하고, 추가한 행과 근거를 기록하겠습니다. targets.csv의 후보 ID와 우리 조건표의 ID가 다르면 id-map.csv에서 명시적으로 대응시키겠습니다. 서로 다른 체계의 ID를 이름만 보고 섞지 않겠습니다.

입출력 계약에서 조건 행을 묶는 방법과 입력 이름의 대응을 확인하겠습니다. 같은 규칙의 조건이 둘이라고 감점도 두 번 더하면 안 됩니다. 원문이 정한 적용 대상부터 가리고, 관련 조건의 누락만 판정에 반영하겠습니다.

## 평가 함수 만들기

원문과 입력의 약속을 기준으로 구현을 요청하겠습니다. 결과에서는 조건과 출처가 빠지지 않았는지 확인하겠습니다.


도우미가 설명한 처리 순서를 조건표와 맞추겠습니다. 해당 조치에만 규칙이 적용되는지, 겹친 사유가 모두 남는지, 빠진 값이 정상으로 바뀌지 않는지를 결과에서 확인할 기준으로 적겠습니다. 수업에서는 이 검토 뒤 터미널에서 생성된 실행 방법을 확인하고 cases.csv를 넣어 결과를 만들겠습니다.


## 정상·경계·복수 조건 확인

정상 입력부터 예상과 실제를 비교하겠습니다. 23.9, 24, 24.1시간을 넣었을 때 초과 규칙의 경계가 맞는지 확인합니다. 예측 유온 55도에서는 경고가, 팬 30시간에서는 해당 팬 조치의 감점이 함께 남는지도 보겠습니다. 온도와 압력 경고, 수동과 트립 제외가 겹친 입력에서는 일치 사유를 하나만 남기지 않아야 합니다. 값을 하나 비운 사례는 보류와 누락 항목이 남는지 확인하겠습니다.

원격 제어 후보만 넣고 운전 모드를 수동으로 둔 사례에서는 추천이 없어야 합니다. 작업지시 후보가 있던 경우와 입력 후보 목록 자체가 다르므로 두 사례를 혼동하지 않겠습니다.

## 적용 대상 대조와 필요한 수정

팬 연속 운전 시간이 30시간인 사례에서 팬 최대 운전과 부하 감소 후보를 나란히 보겠습니다. 팬 감점은 해당 팬 조치에만 적용돼야 합니다. 앞 조건표에 적은 대상과 실제 결과의 규칙 ID·감점·출처를 맞추겠습니다.


규칙을 적용한 결과와 후보의 성과 비교가 분리돼 있는지도 확인하겠습니다. 감점 이유가 설명에만 있고 합계에서 빠졌다면 그 차이를 고쳐야 합니다. 결과를 맞추기 위해 조건표나 기대를 바꾸지는 않겠습니다.

## 남은 후보의 성과 비교와 마무리

허용된 후보에 한해 metrics 폴더의 제공 업무 값과 지표 정의로 비용·생산·품질·에너지 손실을 계산하도록 기능을 잇겠습니다. 계산식은 교육용 비교 모형입니다. 정지와 감산을 단순히 더하고 정비 시점을 따로 계산하지 않는다는 가정을 결과에 남기겠습니다. 단위는 만 원이고, 이 네 지표의 합과 감점 금액을 비교용 합계로 두되 항목별 값과 경고는 그대로 남기겠습니다. 이 비교용 합계는 이론에서 본 HYD의 일곱 성분 점수와 다른 교육용 기준입니다. 값이 빠진 지표가 있으면 합계 순위도 보류합니다. 같은 합계는 동순위로 두겠습니다.

지표 정의의 손계산 예 하나를 먼저 계산한 뒤 프로그램 결과와 대조하겠습니다. 낮은 온도 하나만 보고 조치를 고르지 않고 생산 감소와 에너지 비용까지 확인합니다. output/result.json과 비교 기록을 저장하고 다시 열겠습니다. 어떤 입력이 어떤 규칙에 걸렸고, 남은 후보를 어떤 기준으로 비교했는지 근거를 따라 설명할 수 있어야 마무리입니다.
