# 실전반 8회차 — 흐름실행


## 앞 에이전트를 업무 흐름으로 연결하기

앞 명세와 에이전트 정의·ID·출력 계약을 이번 작업 공간에 가져오겠습니다. 요청을 받아 자료를 비교하고 담당자가 검토한 뒤 결과를 남기는 흐름을 만들겠습니다. 회의 준비의 결과와 실제 정비 실행은 구별합니다.

## 추천 가능 여부와 사람 검토 나누기

bpmn.io에서 요청 시작, 자료 검토 에이전트, 추천 가능 여부 확인, 담당자 검토, 결과 보고를 연결하겠습니다. 필요한 정보가 없으면 추가 확인을 보고하고, 적합 후보가 있을 때 사람의 계획 검토로 보냅니다. 사람의 거절은 거절 이유를 보고하는 경로로 닫겠습니다. 보류 보고가 끝나도 정비 계획이 확정됐다는 뜻은 아닙니다.


그림을 저장하고 다시 열어 보류·검토·거절의 길을 확인하겠습니다. 다음으로 포털에서 앞 에이전트와 담당 역할, 보고 부품을 실제 요소 ID에 연결합니다. 기존 냉각 대응 흐름을 그대로 덮어쓰지 않고 별도 정의로 관리하겠습니다.

## 검사와 두 입력 판본의 처리 확인

사전 검사에서 나온 위치와 사유를 읽고 현재 그림과 매핑을 고치겠습니다. 검사한 판본을 등록하고 수업 환경에서 요청을 시작합니다. 첫 자료와 후속 자료의 처리 기록은 같은 업무 요청에 속하더라도 별도 실행 기록으로 보존하겠습니다.

최초 자료에서 확인이 남는다면 보고에 그 이유가 있어야 합니다. 후속 자료로 추천이 가능해졌다면 실제 후보와 근거를 확인한 뒤 담당자가 검토합니다. 승인·거절 뒤 보고에 전달된 값이 앞 에이전트의 어떤 판본인지 확인하겠습니다. 요청 번호만 같고 서로 다른 자료를 섞지 않아야 합니다.


마지막으로 보고에서 일정 등록·메일 발송·정비 오더·현장 작업이 실행된 것처럼 표현되지 않았는지 확인하겠습니다. BPMN과 매핑, 명세·에이전트 정의, 두 자료 판본의 기록을 저장하고 다시 열겠습니다. 다음 제품 비교에서도 이름보다 이 역할과 기록의 연결을 보겠습니다.
