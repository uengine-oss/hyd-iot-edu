# 실전반 8회차 — 흐름실행


## 다운로드와 앞 에이전트 연결 확인

흐름실행 ZIP을 내려받아 압축을 풀고 VS Code에서 앞 실습의 같은 프로젝트를 열겠습니다. 에이전트 ID와 출력 계약을 input에 가져옵니다. reference/example_meeting의 BPMN과 매핑은 일정 생성까지 포함한 더 큰 예제이며, 실제 도구 이름과 결과 경로를 채우지 않은 자리도 있습니다. 이번에는 명세에 정한 읽기·제안·확인·보고 범위의 흐름을 직접 그립니다.

## 작은 흐름 직접 그리기

bpmn.io에서 새 그림을 열고 시작, 에이전트 작업, 필요한 사람 확인, 결과 보고, 종료를 잇겠습니다. 사람이 거절하거나 근거가 부족하면 그 사유를 보고하는 경로도 둡니다. 각 요소의 ID를 element-map.md에 기록하고 flow.bpmn으로 저장한 뒤 다시 열어 선과 담당이 유지되는지 확인합니다.

포털의 흐름 가져오기에서 직접 시작 입력을 정하고 에이전트 작업에는 앞에서 등록한 ID를 연결합니다. 각 단계의 입력·출력 이름은 실제 계약과 맞춥니다. 사람 확인 부품이 요구하는 추천 옵션 형식과 앞 에이전트 결과가 다르면 그 차이를 먼저 명세와 결과 계약에 반영합니다. 단순 검토 의견을 승인으로 바꾸어 연결하지 않습니다.

## 검사와 실행 결과 확인하기

연결 표를 저장하고 사전 검사를 수행하겠습니다. 오류가 있으면 해당 요소 ID와 필드, 지원 부품을 확인해 수정하고 다시 검사합니다. 실제 연결을 확보하지 못하면 BPMN 작성과 등록·실행 미확인을 구분해 남깁니다. 검사 통과만으로 실행 성공이라고 쓰지는 않습니다.

수업 환경에서 확인된 연결로 판본을 등록하고 요청 한 건을 시작하겠습니다. 시작 입력, 에이전트의 제출 결과, 필요한 사람 확인 기록, 다음 단계에 전달된 값과 최종 보고를 차례로 확인합니다. 끝 이벤트에 닿았는지와 어떤 결과로 닫혔는지를 따로 봅니다. 이번 흐름에 없는 일정 등록과 메일 발송은 하지 못한 일로 보고에 남기고 실제로 실행했다고 말하지 않습니다. 거절이나 보류가 발생했다면 명세가 정한 경로와 기록을 대조하겠습니다.

## 저장과 다시 열기

BPMN과 매핑, 명세, 에이전트 정의, 등록 판본과 처리 건 기록을 저장합니다. 다시 열어 같은 판본과 입력에서 어떤 경로를 확인했는지 찾아갑니다. 수정 뒤에는 새 판본과 기존 처리 건을 구분해 재확인합니다. 이 기록을 제품 시연에서 정의·인스턴스·담당·결과를 비교할 기준으로 쓰겠습니다.
