# 실전반 2회차 실습 3 — 현장 자료로 온톨로지 설계하기

> 강사 단독 진행. AI 요청과 파일 조작은 비낭독 표시를 따른다. 응답은 실제 내용을 확인한 뒤 설명한다. 실제 실습·AI 대화·캡처 미수행.

## 자료 다운로드와 작업 폴더 열기

현장 자료를 바탕으로 설비별 센서와 교체 부품을 구별해서 찾을 수 있는 지식 구조를 만들겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 설계 자료를 내려받고 압축을 풀겠습니다. VS Code에서 작업 폴더를 열면 설비 대장과 센서 목록, 구성 요소와 예비품 목록이 있습니다. 먼저 현장 메모를 읽고 자료가 어떤 범위를 나타내는지 확인하겠습니다.

현장 자료와 준비된 양식을 먼저 도우미와 살펴보겠습니다. 아직 열 이름이나 식별자 규칙을 정하지 않았으니, 자료에서 확인할 수 있는 범위부터 보겠습니다.

> [탐색 요청 · 응답 확인 뒤 다음 단계] 프로젝트의 설명과 현장 자료를 읽고 설비·센서·부품을 연결할 근거, 중복이나 단위가 모호한 부분, 현재 준비된 양식을 알려 주세요. 파일을 바꾸지 말고 원문 위치를 함께 제시해 주세요.
> [확인] 답변의 자료 위치와 현재 기능을 실제 파일에 대조한다. 아래 경로·필드 설명은 그 확인 후 진행하며 응답을 미리 받은 것처럼 읽지 않는다.

> [조작] 실습3 ZIP 다운로드 → 압축 해제 → VS Code 폴더 열기. 자료/현장_메모.md와 CSV들을 연다. 결과/요구사항.md를 열고 이번 모델이 답할 질문 세 개를 적는다.

제가 정할 질문은 설비의 구성 요소에 어떤 센서가 붙는지, 그 센서가 읽는 물리량의 한계가 무엇인지, 어떤 교체 부품을 쓰는지입니다. 공급 조건도 자료에는 있지만, 이번 세 질문에 필요한 범위부터 만들겠습니다.

## 같은 대상과 서로 다른 대상을 가리기

센서 목록을 보면 같은 설비의 TS1이 두 줄이고, 다른 설비에도 TS1이라는 태그가 있습니다. 같은 줄의 반복과 다른 설비의 계측 채널을 한꺼번에 합치면 안 됩니다. 현장 메모의 설명과 설비 코드를 같이 읽겠습니다.

> [조작] 중복 TS1의 근거, 쿨러·열교환기의 별칭, HYD-02 압력 한계의 단위 혼입, HYD-03 진동 단위 누락을 원문 위치와 함께 자료_검토.md에 기록한다. 교체 부품 누락은 메모의 대응 근거와 대조한다. 근거 없는 값은 생성하지 않는다.

이번 모델은 설비별 계측 채널을 구별하도록 하겠습니다. 구성 요소와 센서는 설비 코드가 포함된 식별자로 나누고, 공용 교체 부품은 품번 하나로 묶겠습니다. 부품을 공용으로 쓴다는 말은 같은 실물 부품을 동시에 장착한다는 뜻이 아닙니다. 공통으로 주문하는 품목이라는 뜻입니다.

## 정의와 예시 데이터를 만들기

이 결정을 요구사항에 적겠습니다. 클래스마다 무엇을 뜻하는지, 어떤 속성을 갖는지, 관계가 어디서 시작해서 어디로 가는지를 정합니다. 한계가 없는 항목과 반드시 필요한데 누락된 항목도 구별하겠습니다.

> [입력 — Copilot] 자료 폴더와 요구사항.md를 읽고 schema.json과 graph.json을 결과 폴더에 작성해 주세요. 클래스·속성의 자료형·필수 여부·관계 시작과 끝·카디널리티를 정의하고, graph.json은 nodes와 rels로 나누세요. 각 노드는 labels와 props(id 포함), 관계는 type·a·b·props로 적어 주세요. 원문 근거가 없는 값은 채우지 말고 미확인 목록에 남기세요. 먼저 모델의 범위와 식별자 선택을 설명한 뒤 파일을 작성해 주세요.

> [조작] 응답의 모델 범위와 변경 파일을 먼저 읽는다. 임의 실행이나 패키지 설치 요청은 이 작업에 필요하지 않다. 실제 생성 내용에 따라 확인 발화를 이어 간다.

## 원자료와 생성 결과 대조하기

이제 나온 파일을 원자료와 맞추겠습니다. 이름이 같다는 이유로 다른 설비의 센서가 합쳐졌는지, 같은 품번의 부품이 설비마다 중복됐는지 봅니다. 관계를 문장으로 읽어서 센서가 맞는 물리량에 이어졌는지도 확인하겠습니다.

> [조작] schema.json의 정의와 graph.json의 각 노드·관계 대응을 검토한다. 중복 ID·필수값·자료형·관계 끝점·연결 수를 대조한다. 원자료 세 질문의 예상 답을 검토표에 기록한다. 오류가 있으면 원문 위치와 실제 잘못된 부분을 짚어 수정 요청하고 해당 부분을 다시 확인한다.

JSON 형식이 맞는 것만으로 설계가 맞는 것은 아닙니다. 유온 센서가 팬 진동을 읽도록 연결돼도 두 대상의 클래스는 맞을 수 있죠. 그래서 질문의 예상 답과 실제 연결을 함께 봅니다. 단위가 빠진 값은 영이나 빈 문자열로 덮지 않고, 원자료에서 확인할 수 있는지 남기겠습니다.

## 저장하고 다음 작업으로 넘기기

스키마와 데이터, 원자료 검토표를 저장하겠습니다. 두 JSON 파일을 다시 열어 같은 내용이 남았는지 보고, 세 질문의 경로를 한 번 더 확인합니다. 다음 실습에서는 이 파일들을 그래프로 옮깁니다. 수정한 근거도 같이 가져가야 적재한 뒤의 결과를 비교할 수 있습니다.

> [조작] 결과 폴더의 요구사항·schema.json·graph.json·자료_검토.md를 함께 보존한다. 미확인 필수값이 있으면 적재 전 보완 대상으로 표시한다. 완성됐다고 미리 단정하지 않는다.
