# 실전반 1회차 — 학습노트 실습 대본

> [운영 · 비낭독] 강사가 혼자 자료를 읽고 조작·판단·요청·검토를 시범 보이는 발화다. 학생 응답이나 조작을 기다리지 않는다. 이번 문서 제작에서는 실습·화면 조작·캡처를 하지 않는다. 화면은 가이드의 동일 ID 자리에 나중에 넣는다. 아래 조작 안내와 미래형 발화는 수행 완료 기록이 아니다. 운영 시간은 미확정이다. 이전 고정 견적은 철회했다. 실제 화면에 맞는 조작을 확인한 뒤 해당 발화를 사용한다. 접이식 요청 예시는 실제 AI 대화가 아니며, 실제 응답은 관측한 내용에 따라 검토한다. 설치·가입·권한 복구는 별도 준비 시간이다.

> [진행 원칙 · 비낭독] 조작하면서 해당 판단을 설명한다. 힌트와 AI 요청 예시는 필요한 경우에만 사용하며 모두 순서대로 소진하지 않는다. 이미 확인한 결론을 모르는 척하거나 질문 횟수를 채우지 않는다. 오류 분기는 실제 오류가 있을 때만 사용한다.

## 시작. 자료를 받아 작업 폴더 열기

> [화면 01-START] 실습 자료 다운로드 → 압축 해제 → VS Code 폴더 열기 → 탐색기. 화면은 후속 삽입 자리다. 다운로드 링크는 배포한 01일차_실습1_학습노트.zip을 연결한다. 실제 실습·캡처는 이번 문서 제작에서 수행하지 않는다.
> [조작] 이전 실습 파일을 닫는다. 수업 자료의 해당 ZIP을 내려받고 파일 탐색기에서 압축을 푼다. VS Code를 열어 파일 → 폴더 열기로 `01일차_실습1_학습노트`를 선택한다. 출처를 확인한 자료만 작업 공간 신뢰 여부를 판단한다. 파일 하나만 열거나 ZIP 내부에서 편집하지 않는다.

이번 실습 자료부터 받겠습니다. 같은 회차에도 실습이 여러 개 있으니까 파일 이름을 먼저 확인하겠습니다. 다운로드한 파일을 열어 보면 압축된 묶음입니다. 이 안에서 바로 수정하지 않고, 작업할 위치에 압축을 풀겠습니다.

이제 VS Code를 열겠습니다. 파일에서 폴더 열기를 선택하고, 방금 압축을 푼 폴더로 이동합니다. 이번 실습 폴더를 선택하겠습니다. 이전 실습 폴더와 섞이지 않도록 이름을 확인합니다.

왼쪽 탐색기에 파일 목록이 보입니다. 이 폴더가 지금 작업할 공간입니다. 파일 하나만 열었을 때와 달리, 자료와 결과를 같은 위치에서 관리할 수 있습니다. 학습노트_입력틀.md부터 열겠습니다. 이 양식을 따라 오늘 남길 결과와 확인할 항목을 먼저 보겠습니다.

> [조작] 읽기 전용 입력과 수정할 파일, 결과가 저장될 위치를 차례로 짚는다. 전체 경로에 개인 사용자 이름이 보이면 화면에서 제외한다.

이 양식에는 설명과 출처, 검토 내용을 넣을 자리가 마련되어 있습니다. 우선 항목을 읽고 왜 필요한지 생각해 보겠습니다. 설명만 남겨도 될 것 같은데 출처와 수정 이유까지 필요한 이유는 무엇일까요? 다시 찾아보고 고치려면 처음 생각과 확인한 근거가 남아 있어야겠네요. 이 틀 안에 어떤 내용을 넣을지는 제가 판단하겠습니다.

## 1. 결과와 준비 확인

> [화면 01-01] 수업용 작업 공간과 과정 홈의 세 영역. 개인 페이지·계정 정보는 제외한다.
> [조작] 편집할 수 있는 작업 공간을 준비하고 과정 홈에서 개념·참고 자료·실습 결과로 이동할 구성을 먼저 적는다. 설치·가입·권한 복구가 필요하면 별도 준비 시간으로 기록한다.

> [조작 · 비낭독] Notion을 열어 수업용 작업 공간을 선택한다. 새 빈 페이지를 만들고 제목을 입력한다. 기성 완성 노트를 복제하지 않는다. VS Code의 입력틀은 옆에 두고 필요한 항목만 차례로 옮긴다.

이제 Notion을 열겠습니다. 수업 기록을 둘 작업 공간에서 빈 페이지를 만들고, 과정 이름을 제목으로 적겠습니다. 아직 내용이 없는 상태입니다. 왼쪽에 둔 입력틀을 통째로 복사하기보다, 기록을 어디에서 찾고 어떻게 확인할지 생각하면서 필요한 부분부터 만들겠습니다.

이번에는 방금 배운 내용을 다시 찾고 고칠 수 있는 노트를 만들겠습니다. 첫 주제는 메모와 지식 자산의 차이입니다. 제가 이해한 것을 제 말로 적고, 그 설명을 확인할 자료를 연결하는 것이 목표입니다.

기록 제목을 정하면서 생각해 보겠습니다. 다음 주에 이 내용을 잊었다면 어떤 말로 검색할까요? 저는 개념 이름부터 찾을 것 같습니다. 수업 이름만 적으면 그 안의 어떤 내용을 찾는지 알기 어렵습니다. 과정 홈은 전체 기록으로 들어가는 입구로 두고, 각 기록에는 찾으려는 개념의 이름을 붙이겠습니다.

기록을 다시 쓸 때 하는 일을 떠올려 보겠습니다. 개념 설명을 읽고, 근거 자료를 열고, 실제로 적용한 결과를 찾겠죠. 그래서 개념, 참고 자료, 실습 결과의 세 영역을 두겠습니다. 틀에 적혀 있어서 옮기는 것이 아니라 이 세 가지 일을 연결하기 위한 구성입니다. 제출할 때 누가 읽을 수 있어야 하는지도 수업에서 정한 범위로 확인하겠습니다.

## 2. 과정 홈과 기록 틀 만들기

> [화면 01-02] 과정 홈, 학습노트 속성, 같은 기록의 표·이해도별 보기.
> [조작] 홈과 하위 영역을 만들고 제목·본문 블록·목차·링크로 연결한다. 학습노트 데이터베이스에 제목·분야·이해도·작성일을 둔다. 같은 기록을 표와 이해도별 보기에서 확인한다.

과정 홈 아래에 학습노트 목록을 만들겠습니다. 기록마다 제목, 분야, 이해도, 작성일을 붙입니다. 이해도는 잘 보이게 꾸미는 항목이 아니라, 무엇을 다시 공부해야 하는지 찾는 기준입니다. 아직 설명하기 어렵다면 그 상태를 표시해 두겠습니다.

목차와 링크도 넣겠습니다. 목차는 이 페이지 안의 대목을 찾는 데, 링크는 연결한 다른 기록이나 자료로 가는 데 쓰겠습니다. 개념을 설명하다가 참고 자료로 이동하고, 실습 결과에서 그때 사용한 개념을 다시 찾아올 수 있게 연결하겠습니다.

같은 기록을 표로도 보고 이해도에 따라 모아서도 볼 겁니다. 보기마다 내용을 복사하면 수정한 내용이 서로 달라질 수 있겠죠. 같은 기록을 다른 기준으로 보여 주도록 구성하겠습니다. 한 보기에서 기록을 열고 다른 보기에서도 같은 기록인지 확인하겠습니다.

## 3. 자기 말로 첫 기록 쓰기

> [화면 01-03] 첫 설명, 교재 출처, 수정했다면 전후 문장과 이유.
> [조작] 교재를 잠깐 덮고 첫 설명을 쓴 뒤 교재 4~9장과 대조한다. 강사 설명→Copilot 질문→강사 자기 답변→응답 검토→필요한 문장 수정 순으로 진행한다. 실제 응답이 없는 상태에서 답변을 만들어 읽지 않는다.

첫 제목은 메모와 지식 자산의 차이로 하겠습니다. 자료를 잠깐 덮고 두세 문장으로 적겠습니다. 문장을 길게 쓰는 것보다 내가 다시 사용하려면 무엇이 필요하다고 이해했는지가 중요합니다. 아직 배우지 않은 기술을 미리 설명할 필요는 없습니다.

제가 처음 적을 설명은 이렇습니다. 메모는 그때 본 내용을 남기는 기록이고, 지식 자산은 나중에 찾아 다시 쓰고 고칠 수 있도록 설명과 근거를 연결한 기록이라고 정리하겠습니다. 이 설명이 교재의 뜻과 맞는지 검토하겠습니다.

이제 교재를 열어 비교하겠습니다. 제가 단정한 표현이 원문에도 있는지, 중요한 조건을 빠뜨리지 않았는지 확인하겠습니다. 문장이 술술 읽혀도 근거와 다를 수 있습니다. 고칠 부분이 있다면 첫 설명을 남겨 두고, 무엇을 왜 바꿨는지 기록하겠습니다.

설명은 이 Notion 기록에 남기겠습니다. 제가 쓴 문장과 교재의 근거 대목만 Copilot 채팅에 붙여, 다시 사용할 때 빠진 조건이 없는지 검토하겠습니다. 입력틀은 항목을 확인하는 참고로 두고 같은 기록을 두 군데 관리하지 않겠습니다.

> [조작 · 비낭독] Notion의 첫 설명과 근거 위치를 필요한 범위만 채팅에 붙인다. 교재 발췌는 실제 원문을 사용한다. 입력틀에 같은 내용을 다시 작성하지 않는다.
> [입력 · 비낭독] `제가 적은 설명과 교재 대목을 비교하려 합니다. 먼저 제가 어떤 상황에서 이 기록을 다시 쓰려는지 질문 하나를 해 주세요. 제 답을 들은 뒤 원문과 다른 주장이나 빠진 조건이 있다면 그 문장만 검토해 주세요. 전체 노트는 만들지 마세요.`
> [응답 분기 · 비낭독] 실제 질문을 읽고 강사가 답한다. 재사용 상황을 묻는다면 아래 자기 답변을 사용한다. 질문의 내용이 다르면 그 내용에 맞춰 사실대로 답한다. 질문 없이 수정안을 내놓으면 적용 전에 자신의 사용 목적을 설명한다.

저는 다음 회차에서 앞 개념을 다시 확인할 때 이 기록을 쓰려 합니다. 제목으로 찾고, 제 설명을 읽은 뒤 근거 대목까지 돌아갈 수 있어야 합니다. 그래서 단순히 파일이 남아 있는 것보다 찾을 이름과 출처가 연결되어 있는지를 보겠습니다.

> [입력 · 비낭독] 강사의 실제 답변을 채팅에 입력한다. 이어 받은 검토에서 원문에 없는 주장, 빠진 조건, 단순 표현 제안을 구분한다. 수정이 필요하면 해당 문장만 요청·검토하고 Notion의 해당 기록에 반영한다. 오류가 없으면 억지로 고치지 말고 대조한 근거를 남긴다.

받은 제안을 원문과 나란히 보겠습니다. 문장이 매끄러워졌더라도 교재의 뜻이 달라지면 채택하지 않겠습니다. 필요한 문장만 고치고 처음 설명과 수정 이유를 함께 남기겠습니다. 마지막 단계에서 이 기록을 다시 찾아 출처가 열리는지 확인하겠습니다.

## 4. 출처와 실습 기록 연결하기

> [화면 01-04] 근거 위치가 적힌 참고 자료와 아직 수행하지 않은 실습의 결과 양식.
> [조작] 교재 이름·장·판본과 확인한 대목을 기록한다. 실습 결과에 입력·기대·관측·문제·다음 확인 항목을 만든다. 수행하지 않은 항목은 미수행으로 둔다.

참고 자료를 연결할 때 링크만 남기면 긴 문서 안에서 근거를 다시 찾기 어려울 수 있습니다. 교재 이름과 판본, 장 번호, 어떤 대목을 확인했는지도 적겠습니다. 내가 쓴 설명에서 출처로 돌아갈 수 있어야 나중에 이해가 바뀌었을 때 고칠 수 있습니다.

실습 결과를 담을 자리도 마련하겠습니다. 무엇을 넣었는지, 무엇을 기대했는지, 실제로 무엇이 나왔는지 나누어 적는 겁니다. 기대와 관측이 다르면 문제와 다음 확인을 남깁니다. 아직 하지 않은 뒤 실습은 결과를 비워 두고 미수행이라고 표시하겠습니다.

실패를 겪지 않았다면 실패한 것처럼 채울 필요는 없습니다. 반대로 원인을 찾지 못했는데 해결했다고 적어서도 안 됩니다. 다음에 이어서 볼 사람이 어디까지 확인했는지 알 수 있게 남기겠습니다.

## 5. 찾기·보완·제출하기

> [화면 01-05] 검색 결과, 낮은 이해도 보기, 출처 재열기와 제출 범위.
> [조작] 과정 홈에서 제목으로 첫 기록을 찾고, 이해도가 낮은 기록을 골라 출처를 연 뒤 돌아온다. 수업에서 정한 열람 범위로 제출 링크를 확인한다. 확인하지 못한 항목은 결과를 채우지 않는다.

과정 홈으로 돌아가 방금 쓴 기록을 다시 찾아보겠습니다. 제목으로 찾고, 이해도가 낮은 항목만 모아 볼 수 있는지도 확인하겠습니다. 출처를 열었을 때 내 설명의 근거가 있는 대목으로 갈 수 있어야 합니다.

다른 페이지가 열리거나 권한이 없다면 기록을 쓴 것과 검토할 수 있는 것을 구분해야 합니다. 링크가 있다는 사실만으로 제출 준비가 끝난 것은 아니에요. 정해진 검토자가 읽을 수 있는지 확인하고, 확인할 수 없다면 열람 미확인으로 남기겠습니다.

제출할 것은 첫 설명, 확인한 출처, 고친 문장과 그 이유입니다. 고칠 문장이 없었다면 남은 질문이나 검토한 근거를 적겠습니다. 이어지는 실습 결과도 이 노트에 쌓겠습니다. 노트의 틀을 마련했으니, 다음 시간에는 설비 데이터가 판단으로 이어지는 시스템의 구조를 살펴보겠습니다.

> [연결 · 비낭독] 이론 12장에서 재개한다. 화면과 관측 결과는 후속 촬영 때 같은 ID 자리에 삽입한다.
