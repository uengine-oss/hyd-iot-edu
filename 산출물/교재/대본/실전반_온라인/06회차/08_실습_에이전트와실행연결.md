# 실전반 6회차 실습 5 — 에이전트와실행연결

> [진행 — 낭독하지 않음] 강사 단독 진행용 대본이다. 아래 조작은 수업에서 수행할 절차이며 이번 제작에서 실행·접속·캡처하지 않았다. 예상 결과를 실제 결과처럼 읽지 않는다. 오류가 나면 실제 사유와 수정·재확인을 남긴다.

## 다운로드와 그림·매핑 대응

에이전트와실행연결 ZIP을 내려받아 압축을 풀고 코드 폴더를 VS Code에서 열겠습니다. 앞 실습의 cooling.bpmn과 condition-plan.md를 input에 복사합니다. source/reference의 mapping.json은 참조 그림의 ID를 사용하므로 그대로 내 그림에 적용하지 않겠습니다. element-map.md에 참조 ID와 직접 만든 ID, 작업 이름을 한 줄씩 대응시키겠습니다.

## HYD에 가져와 시작과 담당 연결

포털의 흐름 가져오기에서 내 BPMN을 선택하고 내 교육 환경에서 구분할 흐름 ID를 입력하겠습니다. 기준 흐름의 ID는 사용하지 않습니다. 시작 조건을 경보로 정하고 쿨러 성능 저하 하나만 선택합니다. 내부 값은 COOLER_DEGRADATION입니다.

진단·제안 작업은 판단·제안 부품과 앞 회차에서 만든 냉각 대응 에이전트에 연결하겠습니다. 기본 예의 agent:cooling을 무조건 복사하지 않고 내 에이전트의 실제 ID와 지침·도구 구성을 확인합니다. 승인 작업은 조치 카드 승인·거절 부품과 운전원 역할로 연결합니다. 그림의 레인 이름만으로 권한이 정해졌다고 보지 않겠습니다.

## 시스템·분기·타이머 설정

냉각 명령은 PLC 명령 발행, 재관측은 재관측, 작업지시 등록은 정비 작업지시 부품으로 연결하겠습니다. 정상·미달·거절·지연 작업은 각각 결과 보고에 연결하고 참조 파일의 결과 값, 제목, 내용을 읽으며 입력합니다. 보고 문장에 들어가는 변수 이름은 그대로 맞춥니다. 보고 내용만으로 실제 명령 실행을 입증하지는 않습니다.

승인 선에는 승인 결과가 승인과 같다는 조건, 회복 선에는 설비 회복 여부가 예라는 조건을 넣습니다. 반대 선은 각각 그 밖의 경우로 둡니다. 승인 지연 기한은 10분으로 정합니다. 참조 mapping.json과 내 요소 ID를 맞춘 output/mapping.json에도 같은 값을 정리하겠습니다.

현재 저장소의 포털은 이런 설정 폼을 제공합니다. 교육 환경에 해당 항목이 없다면 제공된 API_연결절차.md에서 요청 경로와 본문을 확인해 같은 초안의 매핑을 저장하고 다시 읽겠습니다. API가 없는 환경에서는 성공했다고 넘기지 않고 미확인 항목을 남깁니다. 참조 파일의 ID가 내 그림에 존재하는지와 필요한 연결이 빠지지 않았는지 확인한 뒤 검사 단계로 넘어가겠습니다.
