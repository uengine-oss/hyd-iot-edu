# 실전반 6회차 실습 7 — 이벤트와처리결과


## 다운로드와 배포 대상 확인

배포한 판본으로 열린 사건을 따라 승인·명령·회복·작업지시의 실제 기록을 대조하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.


## 이벤트와 승인 대기 읽기

교육용 설비 화면에서 쿨러 열화 버튼을 누르고 새 경보의 사건 ID와 시각을 확인하겠습니다. 그 경보로 열린 프로세스 인스턴스의 정의와 판본을 deployment-record와 맞춥니다. 새 처리 건이 보이지 않으면 같은 이벤트를 무작정 반복하지 않고 경보·배포·중복 판정 기록을 보겠습니다.

에이전트 단계가 낸 원인과 추천안, 근거와 판단 기록 번호를 확인하겠습니다. 다음 승인 작업이 열리면 전체는 진행 중이고 명령은 아직 나가지 않았는지 보겠습니다. 지연 알림이 발생할 때까지 기다릴 경우에는 수업 배속에 맞춘 시간을 기록합니다. 알림 뒤에도 승인 작업이 열려 있고 명령이 없다는 근거를 단계와 명령 기록에서 확인합니다. 사람이 기다리는 정상 상태와 오류는 구별하겠습니다.

## 승인 뒤의 명령과 효과 확인

승인 권한이 있는 교육용 계정으로 추천안과 현재 조건을 검토하겠습니다. 근거와 조건이 충족된 경우에 조치를 선택해 승인하고, 부족하면 보류와 이유를 남깁니다. 승인한 경우에는 다음 기록을 확인하겠습니다. 승인 접수와 다음 단계 전달, PLC 명령 처리 기록을 각각 확인합니다. 명령을 보냈다는 사실과 설비가 처리했다는 사실도 구분합니다.

재관측에서는 유온과 회복 기준, 경보 해제 여부를 확인하겠습니다. 유온이 기준에 도달하지 않았다면 정상으로 읽지 않습니다. 최종 상태가 끝남이어도 결과 보고가 정상인지 미달인지, 작업지시가 등록됐는지를 따로 확인합니다. 작업지시 등록을 핀 세척 완료로 말하지 않겠습니다.

## 기준 흐름과 비교하고 기록 저장

제공된 기준 흐름 설명과 수업 흐름을 대조하겠습니다. 기준 흐름은 여러 에이전트 단계와 중단형 타이머, 수업 흐름은 에이전트 한 단계와 비중단형 지연 알림을 사용합니다. 단순히 새 버전과 옛 버전으로 구분하지 않고, 지연 시 담당자 작업을 유지하는지부터 비교합니다.

기대한 흐름과 다르면 사건 입력, 매핑, 실제 호출·승인 기록 중 어디에서 달라졌는지 보겠습니다. 원인을 확인해 고칠 때는 이전 정의 판본과 결과를 보존하고 새 판본의 재검사를 거쳐 별도 사건으로 재확인합니다. 다시 실행하지 못한 범위는 미확인으로 남깁니다. review.md에 사건·처리 건·정의·판본, 실제 확인한 승인 대기와 종료 시각, 명령·재관측·보고의 근거를 적겠습니다. 승인 거절 경로를 이번에 실행하지 않았다면 설계에서 확인한 것과 실행 미확인을 구분합니다. 저장한 기록을 다시 열어 각 결론의 출처를 확인하고 복습으로 돌아가겠습니다.
