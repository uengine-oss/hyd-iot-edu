# 통합반 1회차 실습 2 — 실행 환경과 서비스 연결 확인

> 제작용 · 비낭독: 이론② 45장 뒤 첫 실습. 실제 시스템 실행은 이번 문서 작업에서 하지 않았다. 준비된 수업용 HYD 프로젝트·설정·인증이 필요하다. 실습 ZIP은 확인표와 안내 자료이며 시스템 전체가 아니다. 기동 판본·프로필·워커 연결은 안내의 사전 조건을 확인한다. 아래 명령은 강의 때의 조작 지시이며 지금 실행한 기록이 아니다.

## 자료 다운로드와 프로젝트 열기

> 조작: 실습 2 ZIP을 내려받아 압축 해제하고 VS Code로 폴더를 연다. `환경_준비_안내.md`와 `환경_확인표.md`를 읽는다. 준비된 HYD 프로젝트를 별도 VS Code 창에서 폴더로 연다. 프로젝트 루트의 compose.yaml과 ot·dmz·it 폴더를 확인한다. 설정의 비밀값은 화면에 노출하지 않는다.

앞에서 본 데이터와 명령의 경로를 이제 실행 환경에서 확인하겠습니다. 자료를 내려받아 폴더를 열고, 확인표를 준비할게요. 이 자료 폴더에는 기록할 틀이 있고, 실행할 프로그램은 별도로 준비한 HYD 프로젝트에 있습니다.

프로젝트를 열면 현장 쪽, 중간 연결 쪽, 업무 쪽 폴더가 보입니다. 서비스가 어떻게 연결되는지는 Compose 파일에 정의돼 있습니다. 오늘은 이 구성을 실행하고, 켜졌다는 표시와 실제 연결을 차례로 확인하겠습니다.

## 도구와 배포 설정 확인

> 조작: 프로젝트 루트에서 Git Bash 터미널을 연다. Docker Desktop 엔진 상태를 확인한다. `docker --version`, `docker compose version`, `python --version`을 차례로 확인하고 `docker info`로 엔진에 닿는지 확인한다. 환경 안내에 적힌 프로필과 수업용 설정을 대조한다.

터미널에서 도구가 준비됐는지 확인합니다. 버전이 나온다는 것은 명령을 찾았다는 뜻입니다. Docker는 엔진에도 연결돼야 컨테이너를 실행할 수 있으니 여기까지 확인하겠습니다.

Python은 자체 서비스와 랩 코드에 쓰입니다. 브로커와 데이터베이스는 각자의 프로그램이고, Docker가 실행 환경을 묶어 줍니다. 도구 역할은 여기서 구분하고, 이제 실제 서비스를 켜겠습니다.

## 업무 저장소와 서비스 기동

> 입력 · Git Bash, 프로젝트 루트: `( cd it/supabase && supabase start )`

업무 저장소부터 켜겠습니다. 사건과 승인, 작업지시를 남기는 서비스가 이 저장소에 연결됩니다. 준비 상태가 확인되면 나머지 서비스를 올립니다.

> 입력 · Git Bash: `COMPOSE_PROFILES=ot,backbone,detect,knowledge,agent,enterprise,process,cliagents docker compose up -d --scale agent-worker=0`

> 조작: 준비 안내와 compose.yaml에서 해당 판본의 프로필·호스트 워커 사용을 확인한 뒤 위 명령을 적용한다. 처음 빌드가 필요한 배포본은 해당 배포 안내를 따른다. 호스트 워커는 이미 동작 중인지 먼저 확인하고 없을 때만 별도 Git Bash에서 `bash scripts/run_worker_host.sh`를 실행한다. 한 개만 유지한다.

여러 서비스가 올라오는 동안 상태를 보겠습니다. 실행 순서를 외우기보다는 어느 의존 서비스가 준비됐는지를 확인합니다. 한 번 자료를 넣고 끝나는 준비 작업도 있으니 종료됐다는 표시를 모두 실패로 읽지는 않겠습니다. 종료 코드와 그 작업의 역할을 함께 보겠습니다.

에이전트 작업을 처리할 워커도 확인합니다. 포털이 열려도 워커가 연결되지 않으면 다음 실습의 진단 단계가 진행되지 않을 수 있습니다. 이미 실행 중인 워커가 있으면 하나를 더 띄우지 않고 그 상태를 확인하겠습니다.

## 상태와 접속 결과를 확인표에 남기기

> 입력 · Git Bash: `docker compose ps -a`; `( cd it/supabase && supabase status )`; `curl -s http://127.0.0.1:8080/healthz`; `curl -s http://127.0.0.1:8097/health`

> 조작: 상시 서비스는 실행 상태와 제공되는 healthcheck를, 초기화 작업은 종료 코드와 로그를 확인한다. 포털 `http://127.0.0.1:8088`을 열어 연결 상태와 HYD-01 계측 갱신을 확인한다. 실제 주소가 다른 배포본은 안내의 주소를 쓴다. 확인표에는 실제로 본 서비스·상태·확인 시각·연결 결과를 적는다.

이제 목록을 확인표와 대조하겠습니다. 개수가 맞아도 필요한 서비스 하나가 빠졌을 수 있습니다. 계속 떠 있어야 하는 서비스와 한 번 실행하고 끝나는 작업을 나눠 확인합니다.

프로세스의 응답과 워커 상태를 보고 포털을 열겠습니다. 화면이 열리는 것까지 확인한 뒤, 설비 값이 갱신되는지도 봅니다. 단순히 페이지가 보이는 것과 설비에서 값이 올라오는 것은 다른 확인입니다.

확인표에는 지금 화면에서 확인한 결과를 적습니다. 접속이 안 되는 곳은 정상이라고 채우지 않고, 오류 내용과 마지막으로 확인된 지점을 남기겠습니다.

> 오류 분기 · 해당할 때만: 엔진 연결 실패는 Docker Desktop 상태부터, 업무 DB 연결 실패는 Supabase 상태와 포트부터, 진단 대기는 워커 연결과 배포 설정부터 확인한다. 필요한 서비스의 로그만 읽고 원인을 좁힌다. 볼륨 삭제나 전체 초기화로 해결하려 하지 않는다. 해결되지 않으면 다음 사건 실습의 선행 조건 미충족으로 기록한다.
