# 통합반 2회차 실습 3 — 현장 자료로 온톨로지 설계하기


## 자료 다운로드와 작업 폴더 열기

현장 자료를 바탕으로 설비별 센서와 교체 부품을 구별해서 찾을 수 있는 지식 구조를 만들겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.


현장 자료와 준비된 양식을 먼저 도우미와 살펴보겠습니다. 아직 열 이름이나 식별자 규칙을 정하지 않았으니, 자료에서 확인할 수 있는 범위부터 보겠습니다.



제가 정할 질문은 설비의 구성 요소에 어떤 센서가 붙는지, 그 센서가 읽는 물리량의 한계가 무엇인지, 어떤 교체 부품을 쓰는지입니다. 공급 조건도 자료에는 있지만, 이번 세 질문에 필요한 범위부터 만들겠습니다.

## 같은 대상과 서로 다른 대상을 가리기

센서 목록을 보면 같은 설비의 TS1이 두 줄이고, 다른 설비에도 TS1이라는 태그가 있습니다. 같은 줄의 반복과 다른 설비의 계측 채널을 한꺼번에 합치면 안 됩니다. 현장 메모의 설명과 설비 코드를 같이 읽겠습니다.


이번 모델은 설비별 계측 채널을 구별하도록 하겠습니다. 구성 요소와 센서는 설비 코드가 포함된 식별자로 나누고, 공용 교체 부품은 품번 하나로 묶겠습니다. 부품을 공용으로 쓴다는 말은 같은 실물 부품을 동시에 장착한다는 뜻이 아닙니다. 공통으로 주문하는 품목이라는 뜻입니다.

## 정의와 예시 데이터를 만들기

이 결정을 요구사항에 적겠습니다. 클래스마다 무엇을 뜻하는지, 어떤 속성을 갖는지, 관계가 어디서 시작해서 어디로 가는지를 정합니다. 한계가 없는 항목과 반드시 필요한데 누락된 항목도 구별하겠습니다.



## 원자료와 생성 결과 대조하기

이제 나온 파일을 원자료와 맞추겠습니다. 이름이 같다는 이유로 다른 설비의 센서가 합쳐졌는지, 같은 품번의 부품이 설비마다 중복됐는지 봅니다. 관계를 문장으로 읽어서 센서가 맞는 물리량에 이어졌는지도 확인하겠습니다.


JSON 형식이 맞는 것만으로 설계가 맞는 것은 아닙니다. 유온 센서가 팬 진동을 읽도록 연결돼도 두 대상의 클래스는 맞을 수 있죠. 그래서 질문의 예상 답과 실제 연결을 함께 봅니다. 단위가 빠진 값은 영이나 빈 문자열로 덮지 않고, 원자료에서 확인할 수 있는지 남기겠습니다.

## 저장하고 다음 작업으로 넘기기

스키마와 데이터, 원자료 검토표를 저장하겠습니다. 두 JSON 파일을 다시 열어 같은 내용이 남았는지 보고, 세 질문의 경로를 한 번 더 확인합니다. 다음 실습에서는 이 파일들을 그래프로 옮깁니다. 수정한 근거도 같이 가져가야 적재한 뒤의 결과를 비교할 수 있습니다.
