# 통합반 9회차 실습 3 — 시스템연결 — 낭독 대본

시스템연결 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. 앞 실습의 cooling.bpmn, 요소 대응표와 조건표를 input에 가져옵니다. reference의 mapping.json은 제공 참조 그림에 맞춘 설정입니다. 내 그림의 id와 맞춘 사본을 output/mapping.json으로 작성하겠습니다. 앞 회차에서 만든 냉각 대응 에이전트의 실제 id와 연결 자료도 input/previous-work.md에 기록합니다.

배정된 교육용 HYD 포털에서 흐름 가져오기를 열고 직접 만든 BPMN을 선택하겠습니다. 기존 기준 흐름을 덮어쓰지 않도록 내 교육 작업을 구분할 새 정의 id를 정합니다. 시작 종류는 경보, 패턴은 쿨러 성능 저하인 COOLER_DEGRADATION 하나로 맞추겠습니다. 수업 환경에서 실제 제공되는 부품·역할·에이전트 목록도 확인합니다.

원인 진단·제안 작업은 판단·제안 부품에 연결하고 앞에서 만든 에이전트의 실제 id를 고르겠습니다. 참조의 agent:cooling을 내 결과의 id로 가정하지 않습니다. 운전원 승인은 조치 카드 승인·거절 부품과 운전원 역할에 연결합니다. 레인 이름이 맞는 것과 로그인 계정에 승인 권한이 있는 것은 따로 확인하겠습니다.

냉각 명령은 PLC 명령 발행, 재관측은 재관측, 작업지시 등록은 정비 작업지시 부품에 연결하겠습니다. 정상·미달·거절·지연 작업은 각각 결과 보고 부품에 연결합니다. 참조의 outcome, title, summary가 각 경로의 뜻과 맞는지 읽고, 보고 문장이 사용하는 변수 이름도 맞춥니다. 문장에 명령을 내지 않았다고 썼다는 이유만으로 실제 명령 기록이 없다고 판정하지는 않습니다.

승인 갈래에는 approval이 승인과 같다는 조건을, 회복 갈래에는 recovered가 true라는 조건을 넣겠습니다. 반대편은 각각 기본 흐름으로 둡니다. 비중단형 승인 지연 타이머는 PT10M으로 맞춥니다. tasks, flows, timers의 키가 내 BPMN의 요소 id와 같은지 하나씩 대조하겠습니다. 내 그림과 설정을 함께 저장해 두어야 어느 선의 조건을 고쳤는지 찾을 수 있습니다.

현재 화면에 설정란이 없다면 source/api-contract.md의 요청 경로와 본문 구조를 읽고 같은 초안의 매핑을 저장·다시 읽는 절차로 보완하겠습니다. 파일 경로를 JSON 객체 대신 보내지 않고, 교육 환경의 실제 인증과 계약을 확인합니다. 연결이 준비되지 않았으면 설정 파일 작성과 접속 미확인을 구분해 남기겠습니다.

사전 검사를 요청하겠습니다. 문제가 있으면 표시된 요소와 field, reason을 inspection.md에 옮기고 원래 그림·설정의 같은 위치를 찾아 고칩니다. 누락된 부품인지, 다른 id를 가리키는지, 조건의 변수나 값이 맞지 않는지 근거로 구분하겠습니다. 고친 뒤 같은 초안을 다시 검사합니다. 문제가 없는데 오류 장면을 만들려고 정상 설정을 비우지는 않습니다.

정적 검사 통과와 실제 호출 성공은 다릅니다. 등록할 정의의 연결이 준비됐는지 확인한 뒤 판본으로 등록하고 반환된 정의 id와 version을 deployment-record.md에 적겠습니다. 등록 응답의 deployed가 false이면 아직 배포한 것이 아닙니다. 업무 프로세스 화면에서 그 판본을 선택하고 배정된 환경의 배포 상태를 확인합니다. 같은 경보를 받을 흐름이 여럿이면 마지막 배포가 선택되므로 실제 경보 경로가 내 정의·판본을 가리키는지 다시 읽겠습니다.

내보낸 BPMN, 최종 매핑, 실제 검사 응답과 배포 정보를 저장하겠습니다. VS Code에서 파일을 다시 열고 포털에서도 같은 정의·판본을 다시 확인합니다. 원래 열려 있던 처리 건은 시작할 때의 판본을 유지하므로 새 판본의 실행 증거로 쓰지 않겠습니다. 다음 실습에서는 새 경보로 열린 한 건을 추적하겠습니다.
