## 다섯 경우의 행동 기준 직접 쓰기

scenarios.md에 일반 정비, 긴급 정비, 필수 정보 누락, 승인 거절, 도구 오류를 나눠 쓰겠습니다. 경우마다 Given에는 실제로 사용할 요청과 조회 자료, 설정과 시작 상태를 적습니다. When에는 확인할 행동 하나를 적고 Then에는 상태·필수 출력 항목·금지 행동의 발생 여부처럼 결과로 가릴 조건을 적겠습니다. 긴급 여부를 가르는 값과 경계는 앞 명세에서 가져오고, 답변을 받았다는 사실과 승인을 받았다는 사실은 구분합니다.

코딩 도우미에는 앞 명세와 입력 파일을 지정하고 이 다섯 경우의 초안을 요청하겠습니다. 도구 오류는 오류 응답을 받았을 때의 약속을 적되 서버를 끄거나 값을 망가뜨려 실패를 만들지는 않습니다. 기존 기록이나 준비된 대역이 해당 조건을 표현하는지 먼저 확인합니다. 근거가 없으면 그 경우의 실행 준비가 미완료라고 남깁니다.

## 기대와 관찰 위치 맞추기

각 Then 옆에 어느 출력 필드나 로그에서 확인할지 적겠습니다. 승인 거절은 확정이나 외부 실행이 생기지 않는지, 누락은 확인 질문 또는 보류가 명세대로 나오는지 연결합니다. 요청 처리 예제의 확정 상태가 실제 정비나 설비 명령 완료를 뜻하지 않는 점도 구별하겠습니다. 참조 시나리오는 이전 예제용이므로 현재 프로젝트의 필드와 요청 번호를 대조해 옮깁니다.

모호한 기대가 있으면 실행 결과로 판정할 수 있게 고치고, 원래 명세의 근거를 함께 남깁니다. 비교 대상이 문장 전체인지, 필수값인지, 허용 목록인지도 가르겠습니다. 원래 요구와 어긋난 기대는 지금 바로잡되, 아직 실행하지 않은 결과를 통과로 채우지는 않습니다.

## 저장과 다음 실습으로 넘기기

명세와 다섯 시나리오, 입력 파일 목록, 판정할 필드와 근거를 저장하겠습니다. 파일을 닫았다가 다시 열어 각 경우에 전제·행동·기대가 모두 있고 자료가 실제로 열리는지 확인합니다. 이 프로젝트를 다음 반복 검증의 입력으로 그대로 이어 쓰겠습니다.

## 다운로드와 시나리오 이어 받기

앞에서 쓴 행동 기준을 실제 입력과 출력에 연결하고, 같은 조건의 결과를 반복해서 비교하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.


## 시나리오를 실행 경로에 연결하기

execution-plan.md에 실제 에이전트의 시작 명령, 입력 전달 방식, 결과 저장 위치, 사용할 설정과 조회 자료의 판본을 적겠습니다. 코딩 도우미에 현재 프로젝트의 실행 진입점과 출력 계약을 보여 주고, 시나리오 번호별 입력을 전달하고 원출력·오류·설정·시각을 별도 폴더에 저장하는 반복 실행 코드를 작성하도록 요청합니다. 실제 연결을 읽어 확인한 다음 사용할 명령을 기록하겠습니다. 제공된 예시 이름을 현재 명령인 것처럼 실행하지 않습니다.

판정 코드는 필수 항목의 유무뿐 아니라 자료형과 뜻, 허용 상태와 금지 행동을 확인하도록 연결합니다. 새로 생기는 실행 번호는 과거 번호와 같아야 하는 값이 아니라 해당 기록으로 연결되는 값입니다. 모델의 설명은 글자 전체의 일치 대신 근거와 결론을 검토하겠습니다. 기존 결과를 복사해 새 실행의 실제값 칸에 넣지 않습니다.

## 실행 기록으로 차이 판정하기

준비된 교육용 환경에서 다섯 경우를 같은 입력·조회 자료·설정으로 실행하고, 모델 경로의 반복 횟수를 정해 기록하겠습니다. 횟수는 신뢰성을 보장하는 수가 아니라 이번 관찰 범위입니다. 오류 상황을 준비하지 못한 경우는 건너뜀과 이유로 남기며, 정상 입력을 일부러 망가뜨려 실패를 채우지 않습니다.

실행마다 나온 원출력을 output에 보존하고 result-review.md에 시나리오·기대·실제·근거 파일·판정을 적겠습니다. 표현 차이, 계약 위반, 실행 실패, 아직 판정할 수 없는 경우를 구분합니다. 위반이 한 번이라도 있으면 다른 실행의 높은 점수로 덮지 않겠습니다. 자료가 바뀐 실행은 같은 조건의 반복으로 합산하지 않습니다.

## 연결 오류를 고치고 저장하기

로그가 없거나 잘못된 파일을 읽었다면 입력 경로와 실행 연결부터 고치고 같은 경우를 다시 확인합니다. 이 수정과 에이전트의 행동 오류는 구별해 남기겠습니다. 실행 코드와 명령, 원출력, 판정표를 저장하고 다시 열어 시나리오 번호에서 근거까지 찾아갑니다. 다음 실습에는 이 기록 전체와 실제 위반 목록을 넘기겠습니다.

## 다운로드와 실패 기록 열기

앞 검증에서 남긴 차이의 원인을 좁히고, 수정한 기능과 기존 기능을 함께 재확인하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.


## 근거로 수정 위치 정하기

change-review.md에 증상과 입력, 기대의 근거, 실제 기록을 나란히 적겠습니다. 지침을 안 따랐다면 호출 기록과 지침을, 기준값이 다르면 자료의 판본과 단위를, 항목이 없으면 명세와 출력 구현을 대조합니다. 도구가 실패한 경우에는 읽지 못한 값을 만든 것인지 오류 처리는 맞았는지도 가릅니다.

원인이 확인된 파일과 수정 목적을 코딩 도우미에게 지정하겠습니다. 현재 출력에 맞춰 기대값을 낮추지 않고, 요구 자체가 바뀐 경우에만 근거와 함께 명세·시나리오를 갱신합니다. 실제 실패가 없으면 수정은 하지 않습니다. 대신 확인한 경우와 실행하지 못한 경우를 남기고 전체 재확인으로 넘어가겠습니다.

## 수정한 경우와 전체를 다시 확인하기

변경 내용을 읽어 관련 없는 기능을 건드리지 않았는지 확인한 다음, 실패했던 경우를 같은 조건에서 다시 실행하겠습니다. 결과가 기대를 충족하는지 기록으로 판정합니다. 이어서 일반 요청, 긴급 요청, 누락에 대한 질문·보류, 거절, 준비된 도구 오류 경우까지 전체 시나리오를 다시 확인합니다. 실패가 고쳐졌다는 것과 다른 기능이 유지됐다는 것은 서로 다른 기록으로 남깁니다.

실행되지 않은 항목은 미확인으로 유지합니다. 새 실행의 번호나 설명 차이는 계약이 허용하는 범위에서 읽고, 금지된 확정이나 외부 쓰기 흔적은 별도로 확인합니다. 다시 실패하면 원출력과 변경 파일을 대조해 원인을 좁히고 같은 순서로 재확인하겠습니다.

## 저장과 인수인계에 반영하기

수정 전후 파일, 변경 이유, 전체 결과와 미확인 항목을 저장하겠습니다. 다시 열어 변경 한 건에서 해당 시나리오와 실행 근거까지 찾아갑니다. 다음 교대 인수인계 실습에서는 이번에 남긴 미완료 요청과 주의 사항도 함께 넘기겠습니다.

앞 검증 결과를 가져오되 이번에는 출처마다 다른 대상 식별자와 기준 시점을 맞추는 데 집중하겠습니다.


## 같은 대상과 시각으로 연결하기

source의 세 자료를 열고 설비 식별자, 작업·요청 번호, 관측 또는 갱신 시각, 조회 시각을 확인하겠습니다. 같은 설비라고 모든 행을 곧바로 붙이지 않고, 어떤 요청과 기간을 인수인계할지 handover-plan.md에 적습니다. 정비 완료 표시는 정비 기록에서 확인하고, 경보 해제나 작업지시 등록만으로 세척 완료라고 적지 않습니다.

코딩 도우미에는 원래 필드 이름과 자료형을 유지해 세 출처를 읽고, 대상별 완료 작업·미완료 요청·주의 사항·근거 위치를 정리하는 코드를 요청하겠습니다. 앞 실습의 미확인 항목도 별도 출처로 붙입니다. 부품 재고가 0인 행과 자료를 읽지 못해 수량을 모르는 경우는 다른 상태로 둡니다. 사건 시각이 없는 자료는 임의 시각을 채우지 않고 그 한계를 적겠습니다.

## 인수인계 초안과 원문 대조하기

준비된 자료를 읽어 초안을 만들고, 각 항목이 어느 파일의 어느 행에서 왔는지 원문과 대조하겠습니다. 출처끼리 상태가 다르면 갱신 시각과 적용 기간을 확인하고 해결되지 않은 차이는 주의 사항으로 남깁니다. 자료에 없는 담당자·기한·완료 결과는 만들어 넣지 않습니다.

잘못 연결된 행이나 빠진 출처가 있으면 연결 조건을 수정하고 다시 생성해 같은 항목을 대조합니다. 하나의 출처를 읽지 못했을 때는 관련 업무가 없다고 쓰지 않고 해당 출처와 범위를 미확인으로 남깁니다. 데이터 패브릭의 관점은 이처럼 여러 출처를 연결하고 추적하는 데 적용합니다.

## 저장하고 다시 읽기

input의 원자료와 판본, 연결 코드, output/handover.md, 대조표를 함께 저장하겠습니다. 작업 공간을 다시 열고 인수인계 항목에서 근거 파일로 돌아갈 수 있는지 확인합니다. 읽은 자료의 범위와 남은 요청을 표시한 뒤 다음 이론에서 제작부터 검증까지의 과정을 정리하겠습니다.
