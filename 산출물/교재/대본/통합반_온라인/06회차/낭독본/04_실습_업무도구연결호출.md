# 통합반 6회차 실습 1 — 업무도구연결호출 — 낭독 대본

업무도구연결호출 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. connection-record.md에는 서버 설정과 검사 결과를, review.md에는 실제 호출과 원문 대조를 남깁니다. 수업에서 제공받은 교육용 포털 주소와 계정, 읽기 서버 주소를 확인하겠습니다. 인증값은 기록 파일에 쓰지 않습니다.

포털의 도구 MCP 메뉴에서 기본 업무 DB와 판단 엔진 서버를 열겠습니다. 이름, 연결 방식, 검사 상태와 도구 목록을 보겠습니다. 읽기 표시가 있는 조회 도구 하나를 골라 이름과 설명, 필수 입력을 적습니다. 판단 제출처럼 쓰기인 도구는 이번 조회 시험의 대상에서 제외합니다.

이제 제공받은 읽기 서버를 제 이름으로 등록하겠습니다. HTTP 서버라면 포털 실행 환경에서 닿을 주소와 연결 방식을 입력합니다. 제 PC의 로컬 경로를 포털 서버에서도 쓸 수 있다고 가정하지 않겠습니다. 인증이 필요하면 포털이 제공하는 비밀값 설정에 입력하고 설정 파일에는 실제 값을 남기지 않습니다.

연결 검사를 누르고 도구 목록이 돌아왔는지 보겠습니다. 실패하면 표시된 분류에 따라 주소·서버 상태·인증·실행 위치를 확인합니다. 설정을 고친 뒤에는 검사를 다시 합니다. 읽기 표시와 허용된 도구 이름을 대조하겠습니다. 목록에 보이는 것과 에이전트가 사용할 수 있는 것은 다릅니다.

허용된 조회 도구의 입력 스키마를 보며 수업 대상의 실제 식별자를 채우겠습니다. 입력과 결과의 대상을 대조하고 호출을 요청합니다. 반환된 행과 기준 시각, 호출 기록의 서버·도구·입력을 나란히 확인하겠습니다. 정상적으로 0행이면 해당 조건의 행을 못 찾은 것이고, 실패나 시간 초과라면 값을 확인하지 못한 것입니다. 서로 바꾸어 적지 않겠습니다.

앞 회차에 만든 에이전트를 열고 검사한 서버와 필요한 읽기 도구를 연결하겠습니다. 기존 도구와 지침을 보존한 채 이번 조회에 필요한 항목만 더합니다. 같은 업무 요청을 한 번 전달한 뒤 실제로 사용한 도구와 입력, 반환 값을 호출 기록에서 확인합니다. 도구를 쓰지 않았다면 성공으로 기록하지 않고 요청과 지침, 연결·허용 목록을 살펴보겠습니다.

검사 시각, 허용 도구, 조회 대상과 반환 행, 에이전트 연결 변경점과 호출 기록을 저장하겠습니다. 파일을 다시 열어 설정 검사와 업무 호출의 결과를 구분해 읽습니다. 이제 로컬 작업 공간에서 세 서버를 함께 연결하겠습니다.
