# 통합반 4회차 실습 1 — 매뉴얼등록과검토


## 다운로드와 원문 준비

이제 문서의 문장을 검토한 지식으로 등록하겠습니다. 회차 안내에서 매뉴얼등록과검토 ZIP을 내려받아 압축을 풀고 VS Code에서 폴더를 열겠습니다. 코드/source의 HM-8 매뉴얼과 documents.csv, review.md를 엽니다. 문서 식별자와 파일을 확인하고 원본은 그대로 두겠습니다. 수업용 포털을 열어 구조 지식이 준비된 교육 환경인지, 같은 문서가 이미 등록됐는지 확인하겠습니다.


## 등록과 추출 요청

매뉴얼 등록 화면에서 원문 파일을 선택하고 제목과 식별자를 확인하겠습니다. 보관된 원문을 열어 절 번호와 표, 단위가 읽히는지 봅니다. 텍스트가 누락됐다면 추출 전에 원문 분석부터 바로잡겠습니다. 추출을 요청하고 처리 상태를 확인하겠습니다. 결과가 나오면 아직 그래프에 들어간 지식이 아니라 검토할 후보로 읽겠습니다.

## 원문과 후보 대조

팬 최대 운전 후보에서 적용 조건과 단계, 제한, 완료 기준을 따라가겠습니다. 인용을 열어 원격 자동 조건, 24시간 이내 제한, 15분 재관측이 빠지지 않았는지 확인합니다. 핀 세척은 정지·LOCAL·잠금, 고압수 금지, 재가동 후 냉각 효율 기준과 승인을 함께 보겠습니다. 인용 문장만 보지 않고 앞뒤 절과 표 머리글까지 대조하겠습니다.

틀린 수치나 단위, 순서, 대상 연결은 수정하고 review.md에 수정 전후와 원문 근거를 적겠습니다. 맞는 기존 식별자가 없는 후보는 임의로 연결하지 않고 보류하겠습니다. 형식 검사를 통과해도 내용 누락은 남을 수 있으므로, 절차와 제한을 모두 답할 수 있는지 원문 전체를 다시 보겠습니다.

## 승인 적재와 조회 확인

검토가 끝난 제안만 남기고 검토자와 검토 완료 상태를 확인한 뒤 교육 환경에 적재하겠습니다. 추출 완료와 적재 완료는 다른 단계입니다. 실패했다면 오류를 기록하고 일부만 들어갔다고 가정하지 않겠습니다.

지식 지도에서 조치의 단계, 근거 절, 문서와 판본으로 이어지는 경로를 확인하겠습니다. 팬 최대 운전의 절차와 제한이 무엇이며 근거는 어디인지 조회하고, 앞에서 원문으로 정한 답과 비교합니다. 빠진 답이 있으면 구조·추출·매핑·조회 중 원인을 찾아 고친 뒤 같은 질문을 다시 확인하겠습니다.

데이터 연결에서는 24시간 기준과 지금의 연속 운전 시간이 각각 어디에 있는지 구별하겠습니다. 기준은 문서 지식이고 현재 값은 판단할 때 원천에서 읽습니다. review.md에 확인한 문서·판본·경로와 남은 미확인을 저장하고 다시 열겠습니다. 다음에는 이 추출과 대조 과정을 직접 만드는 쪽으로 이어갑니다.


# 통합반 4회차 실습 2 — 문서지식추출


## 자료 다운로드와 작업 폴더 열기

문서지식추출 ZIP을 내려받아 압축을 풀고 VS Code에서 폴더를 열겠습니다. 코드/source에는 매뉴얼 HM-8, 정기 점검표 PM-02, 예비품 기준 PR-07과 문서 목록이 있습니다. 2회차의 schema.json과 graph.json, 3회차에서 검토한 SOP·규칙 구조은 input에 복사하겠습니다. 기존 대상의 식별자를 찾을 때 쓸 입력입니다. 출력은 output에 따로 두겠습니다.

문서 목록의 ID와 실제 파일을 맞춰 보겠습니다. 매뉴얼의 표와 단계, 정기 점검의 준비·안전 조건, 예비품 기준의 공급사 선택 순서가 어떤 형태인지 먼저 읽겠습니다. 이 자료는 Markdown이므로 없는 PDF 쪽 번호를 만들어 붙이지 않고 절과 행 구간을 위치로 쓰겠습니다.

## 구조화 출력의 약속 작성

prompt.md를 열고 추출할 항목과 금지할 일을 직접 적겠습니다. 문서는 분석할 데이터이고 지시가 아니라고 적고, 원문 밖의 단계나 조건을 보태지 않도록 하겠습니다. 후보마다 문서 ID, 판본 지문, 절, 행 범위와 그대로의 인용문을 붙이겠습니다. 숫자와 단위, 부정 조건, 순서, 예외를 보존하고 기존 대상은 input의 ID로 가리키도록 합니다. 못 찾은 대상은 경고로 남깁니다.

코딩 도우미에게 이 계약을 읽는 추출·형식 검사 기능을 만들도록 요청하겠습니다. source를 읽어 output/candidates.json을 만들되, 기존 그래프를 수정하거나 적재하지 않게 하겠습니다. 후보에는 종류·내용·기존 대상 참조·근거·경고를 분리하고 검토 상태는 pending으로 시작합니다. 서비스 접속 정보가 필요하면 수업 환경의 설정으로 읽고 파일에 인증값을 쓰지 않겠습니다.

## 추출하고 원문으로 되짚기

생성된 코드를 열어 읽는 폴더와 출력 경로, 스키마 검사, 오류 처리를 확인하겠습니다. 수업에서는 이 검토 후 추출을 실행하고 처리 실패와 경고를 먼저 읽겠습니다. 인용 대조 기능은 후보가 가리킨 원문 구간에 인용문이 실제로 있는지 검사하도록 만들겠습니다. 같은 문장이 여러 곳에 있으면 임의로 하나를 고르지 않고 위치를 보완합니다.

이제 원문과 후보를 나란히 놓겠습니다. 24시간이 24분으로 바뀌지 않았는지, 원격 자동이 아니면 쓰지 않는다는 부정 조건이 남았는지, 정기 점검의 안전 조건이 준비물과 섞이지 않았는지 확인합니다. 예비품 긴급 발주에서는 가장 빠른 공급사를 먼저 고르고 승인 여부를 확인하는 순서를 보겠습니다. 승인된 공급사 중 가장 빠른 곳을 고른 것으로 바뀌었다면 원문의 판단 순서가 달라진 것이므로 고치겠습니다.

검토 기록에는 인용이 있는지뿐 아니라 뜻이 맞는지, 필요한 내용이 통째로 빠지지 않았는지를 적습니다. candidates.json 원본은 남기고 수정한 reviewed.json을 별도로 만들겠습니다. 채택·수정·제외와 근거를 후보마다 기록합니다. 미해결 후보는 승인하지 않겠습니다.

## 저장과 다음 단계 연결

reviewed.json과 review.md를 저장하고 다시 열겠습니다. 후보마다 원문의 어느 위치로 돌아가야 하는지, 기존 대상과 연결할 ID가 무엇인지 확인하겠습니다. 이 파일은 다음 실습의 입력입니다. JSON이 만들어졌다는 사실만으로 그래프가 갱신됐다고 말하지 않겠습니다.


# 통합반 4회차 실습 3 — 그래프반영과검증


## 다운로드와 검토 결과 연결

그래프반영과검증 ZIP을 내려받아 압축을 풀고 VS Code에서 폴더를 열겠습니다. input에 앞 실습의 reviewed.json과 review.md, 2회차의 schema.json과 graph.json, 3회차의 SOP·규칙 구조을 복사하겠습니다. source의 원문과 문서 목록도 함께 열어 근거를 다시 확인하겠습니다. 강사가 제공한 별도 교육용 Neo4j 주소와 DB를 사용하고 기존 HYD 기준 DB와 구별하겠습니다.

## 매핑과 적재 범위 정하기

채택되거나 수정 후 승인된 후보만 골라 approved.json으로 저장하겠습니다. pending과 제외 후보는 넣지 않겠습니다. 기존 설비와 부품, 상태 변수는 앞서 검토한 모델의 실제 ID로 연결합니다. 없는 관계 종류나 ID는 이름이 비슷하다고 대신 쓰지 않고 mapping.md에 미해결로 남기겠습니다. 필요한 스키마 확장은 정의와 방향을 검토해 별도로 기록합니다.

문서·판본·절·인용을 보관할 구조를 함께 정하겠습니다. 같은 문서의 식별자와 판본은 구별하고, 원인에서 고장 유형으로, 조치에서 단계와 근거 절로 이어지는 관계를 스키마에 맞춥니다. 원인과 증상 사이에 원래 없는 직결 관계를 만들지 않고 고장 유형을 거쳐 조회하겠습니다.

## 적재와 조회 기능 만들기

코딩 도우미에게 input의 스키마와 승인 후보를 읽는 load.py와 query.cypher를 만들도록 요청하겠습니다. 기존 대상은 ID로 찾고 새 후보는 ID와 판본 기준으로 중복 없이 저장하게 합니다. 관계 끝점이 없거나 미승인 후보가 섞이면 적재를 멈추고, 문서와 판본·검토자·처리 시각을 기록하도록 하겠습니다. 이번 입력 범위만 한 트랜잭션으로 반영하고 전체 DB 삭제나 다른 문서 덮어쓰기는 하지 않게 하겠습니다.

생성된 코드에서 레이블과 관계를 스키마 허용 목록으로 제한했는지, 값은 매개변수로 넘기는지 확인하겠습니다. 접속할 DB명과 입력 파일을 확인한 뒤 수업용 DB에 적재합니다. 실패하면 오류와 입력을 남기고 원인을 고친 뒤 다시 확인하겠습니다.

## 개수가 아닌 답과 근거 검증

조회문은 세 가지로 만들겠습니다. 첫째, 고장 유형에서 증상과 원인·증거로 가는 경로. 둘째, 조치와 단계·제한·규칙을 찾는 경로. 셋째, 각 지식에서 원문 절과 문서 판본으로 가는 경로입니다. 팬 최대 운전의 절차와 제한을 원문에서 기대한 답과 비교하고, 원격 자동 조건과 시간 제한이 빠지지 않았는지 봅니다.

승인한 후보가 모두 있는지, 제외·보류 후보가 없는지도 확인합니다. 같은 approved.json을 한 번 더 넣었을 때 같은 대상의 노드와 관계가 늘지 않는지 수를 비교하겠습니다. 개수는 같아도 잘못된 관계가 있을 수 있으므로 답과 출처까지 함께 봅니다. 누락을 찾으면 스키마·매핑·적재·조회 가운데 원인을 고쳐 같은 질문으로 다시 확인하겠습니다.

## 저장과 전체 흐름 정리

load.py와 query.cypher, mapping.md, 실제 조회 결과와 검토 기록을 저장하고 다시 열겠습니다. 문서에서 뽑은 후보가 사람의 검토를 거쳐 어떤 근거와 함께 반영됐는지 확인합니다. 원문 개정과 되돌리기 전체 기능을 이 실습에서 구현했다고 확대하지 않겠습니다. 이제 지금까지 만든 구조와 규칙, 성과 기준, 문서 지식이 하나의 판단에서 어떻게 쓰이는지 정리하겠습니다.
