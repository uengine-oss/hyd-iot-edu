# 통합반 11회차 — 제안에이전트 — 낭독 대본

제안에이전트 ZIP을 다운로드해 압축을 풀고 VS Code에서 이번 코드 폴더를 열고 앞 단계의 명세·스키마·인스턴스·조회 기록을 input에 복사하겠습니다. 앞에서 완성한 파일은 보존하고 이번 빈 양식으로 덮어쓰지 않습니다. reference의 에이전트 정의와 제안 예시는 구조를 읽는 자료입니다. 실제 에이전트 식별자나 도구 연결의 완료 증거는 아닙니다.

agent/goal.md에 명세의 요청과 산출물·보류 조건을 적고 SKILL.md에 문서 확인, 지식 조회, 근거 대조, 제안 또는 보류의 순서를 작성하겠습니다. 원문에서 확인한 안건과 미확인 일정을 구분하고, 권한 밖의 일정 등록이나 메일 발송은 하지 않도록 범위를 적습니다.

코딩 도우미에는 앞 지식을 읽을 수 있는 실제 도구와 입력·출력 계약을 제공해 연결 구성을 작성하게 하겠습니다. 포털에서 현재 등록돼 있고 읽기 권한이 확인된 MCP 서버 이름만 tools에 넣습니다. 참조의 gdrive나 gcal은 이름 예시이므로 등록 여부를 확인하지 않고 복사하지 않습니다. 지식 조회에 사용하는 이름 공간과 실제 반환 필드도 맞추겠습니다.

명세의 요청을 넣고 실제 도구 호출과 응답, 제안 결과를 저장하겠습니다. 출처가 붙은 안건과 규칙을 원문에 대조합니다. 후보를 제외했다면 어떤 규칙과 값 때문에 제외했는지 확인합니다. 연결되지 않은 달력의 빈 시간을 지어내지 않고 보류와 이유가 남는지도 봅니다. 이미 근거가 부족한 상태를 확인하면 그 결과를 쓰며, 정상 연결을 일부러 끊어 실패 장면을 만들지는 않습니다.

설명은 맞아 보여도 도구를 실제로 읽지 않았거나 결과 형식이 다음 단계와 다르면 완료로 보지 않습니다. 지침·연결·출력 중 잘못된 곳을 고치고 같은 요청으로 재확인합니다. AI 검토 의견이나 추천안에 적힌 승인 역할을 사람의 승인 기록으로 취급하지 않겠습니다.

정의와 스킬, 등록된 에이전트 ID, 사용한 도구 계약, 원출력과 미확인을 저장합니다. 다시 열어 결과의 근거를 찾아보고 출력 항목 이름과 뜻을 명세에 대조합니다. 이 에이전트와 결과 계약을 다음 흐름의 작업에 그대로 연결하겠습니다.
