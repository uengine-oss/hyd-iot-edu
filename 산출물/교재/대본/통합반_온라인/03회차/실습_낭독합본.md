# 통합반 3회차 실습 1 — 조치결과비교


## 자료 다운로드와 작업 공간 열기

같은 후보라도 운전 조건과 비교 기준이 달라지면 판단이 어떻게 달라지는지 확인하겠습니다. 회차 실습 안내에서 조치결과비교 ZIP을 내려받아 압축을 풀겠습니다. VS Code에서 압축을 푼 폴더를 열고, 코드 폴더의 comparison.md와 kpi.csv를 나란히 열겠습니다. comparison.md에는 기준 입력과 바꾼 입력, 결과와 근거를 분리해서 적겠습니다.

수업용 HYD 포털 주소를 열고 대상 설비와 사건을 선택하겠습니다. 사건 식별자와 판단 시각, 운전 모드, 후보 목록을 먼저 기록합니다. 자료의 과거 사례 값과 지금 화면의 값은 같다고 가정하지 않겠습니다. 후보가 없다면 필요한 사건과 기준 지식이 준비됐는지부터 확인하겠습니다.


## 가능 여부와 비교 결과 구별하기

판단 규칙 화면에서 후보마다 제외 사유, 경고, 감점을 보겠습니다. 성과 점수와 손익 금액도 각각 기록하겠습니다. 점수가 높다는 것과 돈을 덜 잃는다는 것은 같은 말이 아니어서 열을 나눕니다. 적용 규칙에서 근거 문서까지 따라가 어떤 조건이 결과를 만들었는지 적겠습니다.

What-if의 시험 사본을 열고 원래 입력을 기록하겠습니다. 먼저 팬 최대 연속 운전 시간만 24시간과 24.1시간으로 바꿔 비교합니다. 초과 조건이면 정확히 24시간에는 걸리지 않아야 합니다. 화면에서 누적이라고 표시되더라도 이 입력의 정의는 연속 운전 시간인지 확인하겠습니다. 감점이 적용되는 후보와 규칙 식별자까지 같이 봅니다.

기준값으로 돌린 뒤 운전 모드만 수동으로 바꾸겠습니다. 원격 제어 후보의 제외와 작업지시 후보의 유지를 따로 봅니다. 작업지시가 남아도 현장 정지·잠금·승인 조건이 사라지는 것은 아닙니다. 다음에는 기준으로 되돌려 설비 상태 한 항목을 바꾸고, 상태 규칙이 적용되는 후보와 이유를 기록하겠습니다.


## 가중치와 목표 비교

이어서 납기까지 남은 시간 하나를 바꾸겠습니다. 후보의 납기 성분과 손익이 어떻게 달라졌는지 보고, 순위가 그대로라면 그대로 기록합니다. 이번에는 값을 복원한 뒤 순위 가중치 또는 관점 중요도 하나만 바꿉니다. 감점 금액 시험도 별도로 해 보겠습니다. 여러 항목을 한꺼번에 바꾸면 원인을 구별하기 어려우니 한 번에 하나씩 비교하겠습니다.

KPI 목표 비교는 제공된 kpi.csv에서 직접 하겠습니다. 인터록 여유 2.53, 16.72, 14.55도를 같은 기간의 자료로 놓고 평균과 최솟값을 계산해 기록합니다. 평균은 약 11.27도이지만 최솟값은 2.53도입니다. 목표 10도와 견주면 두 집계가 서로 다른 판단을 주죠. 한 설비가 한계에 가까운지를 보려면 최솟값이 필요한 이유입니다. 목표를 5도로 둔 별도 비교 열도 적겠습니다. 측정값은 그대로이고 판정 기준만 달라진 것입니다. 포털에 목표 편집 기능이 있다고 가정하지 않겠습니다.

## 저장과 재확인

원본 불변 표시와 기준 입력을 다시 확인하고 comparison.md에 기록하겠습니다. 자료에 값이 없는 지표는 0으로 채우지 않고 계산 불가와 그 이유를 적습니다. 저장한 뒤 파일을 닫았다 열어 시험마다 한 항목만 달라졌는지, 규칙·점수·손익·KPI의 근거가 각각 남았는지 확인하겠습니다. 이제 이 판단을 표에서 읽어 처리하는 기능으로 이어갈 수 있습니다.


# 통합반 3회차 실습 2 — 조치기준만들기


## 자료 다운로드와 앞 회차 결과 연결

이번에는 절차 자료를 조치의 단계와 판단 조건으로 나누겠습니다. 실습 안내에서 조치기준만들기 ZIP을 내려받아 압축을 풀고, VS Code에서 그 폴더를 열겠습니다. 코드의 source 폴더에 작업 매뉴얼과 구조화 규칙 발췌가 있고, input 폴더는 앞 회차 결과를 넣을 자리입니다. 2회차에서 만든 schema.json과 graph.json을 이곳에 복사하고 원본은 보존하겠습니다.

고장 유형은 failuremodes.csv, 조치 목록은 targets.csv에서 확인합니다. 기존 모델에서 이 대상의 식별자를 찾고 id-map.csv에 대응을 적겠습니다. 이름이 같다는 이유로 새 노드를 만들지 않고, 설비와 종류를 함께 확인합니다. 아직 없는 대상은 제공 목록과 근거를 보고 필요한 확장으로 표시하겠습니다.

## 절차를 직접 구조화하기

HM-8 매뉴얼의 적용 대상과 전제 조건, 안전 조건, 준비사항, 수행 단계, 금지, 역할, 완료 기준을 나누겠습니다. 원문에 없는 준비사항은 지어내지 않고 미기재로 남깁니다. 팬 최대 운전의 순서와 24시간 제한, 회복 확인을 따로 읽고, 핀 세척의 정지·LOCAL·잠금과 승인도 확인하겠습니다.

코딩 도우미에 이렇게 요청하겠습니다. 이 폴더의 원문과 식별자 대응을 읽고 output/sop.json을 작성해 주세요. 여덟 구성요소를 구별하고, 각 항목에 문서 식별자·절·원문 문장을 남겨 주세요. 기존 대상은 그 식별자를 쓰고 없는 값은 미기재로 표시해 주세요. 단계 순서를 바꾸거나 원문에 없는 작업을 추가하지 마세요. 이번에는 문서를 자동 추출하는 프로그램을 만들지 말고 제공된 구조를 검토할 JSON으로 정리해 주세요.


## 결정표 만들기

이제 rules.csv의 열을 채우겠습니다. 규칙 ID, 적용 조치, 입력, 연산자, 기준값, 단위, 출력, 이유, 출처를 적습니다. 원격 자동이 아닌 제어 조치는 제외, 예측 유온과 압력 기준은 경고, 팬 최대 연속 운전 24시간 초과는 해당 조치에 감점으로 구별합니다. 한 행의 여러 조건은 모두 맞아야 하고, 여러 행이 맞으면 경고·감점·제외 사유를 모두 남기겠습니다.

구조화 규칙 발췌의 출처 절 번호와 첨부 매뉴얼 번호가 다르면 같은 번호로 덮어쓰지 않겠습니다. 압력과 트립 규칙처럼 매뉴얼에 직접 없는 문장은 규칙 발췌를 근거로 표시합니다. 감점이 있다고 24시간 수행 제한이 없어지는 것도 아닙니다. 후보 비교와 실제 작업 승인은 구별하겠습니다.

cases.csv에서 온도와 압력의 경계, 정확히 24시간과 초과, 수동과 트립이 겹친 입력, 누락 입력을 하나씩 읽겠습니다. 함수를 만들기 전에 각 사례가 어느 행에 맞을지 expected.md에 직접 적겠습니다. 제외 사유가 있으면 제외하면서 누락도 기록하고, 제외가 없더라도 필요한 입력이 없으면 보류하겠습니다.

## 저장과 다음 입력 확인

sop.json과 rules.csv를 저장하고 다시 열겠습니다. 원문에서 구조로, 구조에서 적용 조치와 근거로 되짚어 보겠습니다. 규칙에 적힌 대상이 식별자 대응표와 일치하는지도 확인합니다. 이 파일들이 다음 실습의 입력입니다. 문서를 추출해 적재하는 기능은 뒤에서 별도로 다룹니다.


# 통합반 3회차 실습 3 — 판단기능만들기


## 자료 다운로드와 조건표 연결

이제 조건표를 읽어서 후보별 판단과 근거를 남기는 기능을 만들겠습니다. 실습 안내에서 판단기능만들기 ZIP을 내려받아 압축을 풀고, VS Code에서 그 폴더를 열겠습니다. 코드 폴더의 input에 앞 실습에서 직접 만든 rules.csv와 sop.json을 복사하겠습니다. 완성 판정 결과를 입력으로 쓰지 않고, 원문에서 검토한 조건표를 읽도록 만들겠습니다.

cases.csv의 입력을 읽고 앞 실습에서 적은 예상 판단을 expected.md에 옮겨 먼저 대조하겠습니다. 결과를 본 뒤 기대값을 맞추지 않도록 경계와 적용 대상을 먼저 적습니다. targets.csv의 후보 ID와 우리 조건표의 ID가 다르면 id-map.csv에서 명시적으로 대응시키겠습니다. 서로 다른 체계의 ID를 이름만 보고 섞지 않겠습니다.

## 평가 함수 만들기

코딩 도우미에게 이렇게 요청하겠습니다. input의 조건표와 SOP를 읽어 evaluate.py를 만들어 주세요. 규칙을 코드 안에 다시 고정하지 말고 표에서 읽으세요. 후보별 적용 대상을 먼저 가리고 한 행의 조건은 AND로 검사하세요. 일치한 모든 규칙의 ID·실제 입력·비교식·출력·출처를 결과에 남기세요. 경고와 감점, 제외를 서로 다른 배열로 모으고, 제외가 있으면 추천에서 빼세요. 값이 없으면 0이나 정상으로 채우지 말고 unknown에 남기세요. 제외가 없더라도 필요한 입력이 누락되면 보류하세요. 모든 후보가 제외되면 추천은 빈값과 사유로 반환하세요. output/result.json에 저장하고, 실제 설비나 업무 시스템을 호출하지 마세요.

생성된 코드를 열어 파일 경로와 비교 연산자부터 확인하겠습니다. 적용 대상 검사가 조건 검사보다 먼저 있는지, 첫 번째 일치에서 멈추지 않는지, 빠진 값을 0으로 만드는 부분이 없는지 읽겠습니다. 수업에서는 이 검토 뒤 터미널에서 생성된 실행 방법을 확인하고 cases.csv를 넣어 결과를 만들겠습니다.


## 정상·경계·복수 조건 확인

정상 입력부터 예상과 실제를 비교하겠습니다. 23.9, 24, 24.1시간을 넣었을 때 초과 규칙의 경계가 맞는지 확인합니다. 예측 유온 55도에서는 경고가, 팬 30시간에서는 해당 팬 조치의 감점이 함께 남는지도 보겠습니다. 온도와 압력 경고, 수동과 트립 제외가 겹친 입력에서는 일치 사유를 하나만 남기지 않아야 합니다. 값을 하나 비운 사례는 보류와 누락 항목이 남는지 확인하겠습니다.

원격 제어 후보만 넣고 운전 모드를 수동으로 둔 사례에서는 추천이 없어야 합니다. 작업지시 후보가 있던 경우와 입력 후보 목록 자체가 다르므로 두 사례를 혼동하지 않겠습니다.

## 적용 대상 오류를 발견하고 고치기

정상 코드를 별도로 보존하고 error-copy.py라는 검토용 사본을 만들겠습니다. 사본에서 팬 감점을 모든 후보에 적용하도록 한 곳만 바꿉니다. 30시간 입력으로 팬 최대 운전과 팬을 건드리지 않는 부하 감소 후보를 비교하는 시험을 먼저 쓰겠습니다. 기대는 팬 후보에만 20만 원 감점입니다. 같은 시험이 오류 사본을 실패로 잡는지 본 뒤, 적용 대상 조건을 복구하고 다시 확인하겠습니다. 실패를 숨기거나 기대값을 결과에 맞추지 않겠습니다.

## 남은 후보의 성과 비교와 마무리

허용된 후보에 한해 metrics 폴더의 제공 업무 값과 지표 정의로 비용·생산·품질·에너지 손실을 계산하도록 기능을 잇겠습니다. 단위는 만 원이고, 이 네 지표의 합과 감점 금액을 비교용 합계로 두되 항목별 값과 경고는 그대로 남기겠습니다. 이 비교용 합계는 이론에서 본 HYD의 일곱 성분 점수와 다른 교육용 기준입니다. 값이 빠진 지표가 있으면 합계 순위도 보류합니다. 같은 합계는 동순위로 두겠습니다.

지표 정의의 손계산 예 하나를 먼저 계산한 뒤 프로그램 결과와 대조하겠습니다. 낮은 온도 하나만 보고 조치를 고르지 않고 생산 감소와 에너지 비용까지 확인합니다. output/result.json과 비교 기록을 저장하고 다시 열겠습니다. 어떤 입력이 어떤 규칙에 걸렸고, 남은 후보를 어떤 기준으로 비교했는지 근거를 따라 설명할 수 있어야 마무리입니다.
