HYD · 실습 가이드

매뉴얼에서 작업 지식 후보를 추출하고 검토하기

원문 Markdown에서 작업 순서·조건·금지·완료 기준·기준값을 문서 ID·절·인용과 함께 뽑는 추출 기능을 만들고, 사람이 후보를 검토합니다.

01 시작하기

압축을 푼 폴더를 VS Code에서 열고 START.md와 입력/출력_계약.md를 읽으세요.

자료/원문/        HM-8·PM-02·PR-07 원문
입력/출력_계약.md   후보·검토 JSON 모양
입력/비교용_추출결과/  포털 승인 추출(비교용, 실제 실행 아님)
check_candidates.py  계약·인용 검사기
결과/            이번에 만들 것

AI에게 먼저 이 자료를 읽고 무엇이 있고 무엇이 비었는지 설명하게 하세요. 이때는 파일을 만들거나 바꾸지 말라고 함께 말합니다.

02 요구 정하기

목표(원문에서 다섯 종류의 후보를 문서 ID·절·인용과 함께 추출), 입력(자료/원문), 제약(원문 그대로의 인용, LLM 호출 없음, 비교용 결과 사용 금지), 확인할 사례(START의 사례 종류)를 자기 말로 정리해 전달하세요.

AI가 계획을 내면 계약의 필수 필드와 확인 사례가 빠지지 않았는지 보고 고칠 점을 말한 뒤 진행합니다.

03 AI와 만들기

작은 단위로 구현하고 실행합니다. 예: 절·절차 인식 → 번호 단계 → 표 칸 → 문장의 조건·금지·완료 → 값과 단위. 단계마다 HM-8로 실행해 출력을 원문과 비교한 뒤 다음으로 넘어갑니다.

수정 요청에는 어떤 원문 문장에서, 무엇을 기대했고, 실제로 무엇이 나왔는지를 함께 주세요.

요청을 정리할 때 볼 항목

만들 결과 / 읽을 자료 / 바꾸지 않을 범위 / 지켜야 할 출력 계약 / 성공을 확인할 사례 / 확인하지 못하면 어떻게 표시할지

04 결과 확인하기

python 결과/extract.py 자료/원문/HM-8_cooler-fan-manual.md --doc HM-8 --out 결과/후보/HM-8.json
python check_candidates.py 결과/후보/HM-8.json
python 결과/extract.py 자료/원문/PM-02_powerpack-pm-checklist.md --doc PM-02 --out 결과/후보/PM-02.json
python check_candidates.py 결과/후보/PM-02.json
python check_candidates.py 결과/검토/HM-8_검토.json

판단 원칙: 검사기는 인용이 원문 절 안에 그대로 있는지와 계약 구조만 확인합니다. 지식이 맞는지, 빠졌는지는 원문과 직접 대조해 판단합니다.

  • 인용 검사에서 실패한 후보는 원문을 바꾸지 말고 추출 함수를 고칩니다.
  • 한 문장에 단계와 제한이 함께 있으면 두 후보가 모두 있는지 봅니다.
  • 표의 칸 값에 행·열 머리글이 text로 남았는지 봅니다.
  • 「이상」과 「초과」가 같은 비교 기호로 바뀌지 않았는지 봅니다.
  • PM-02에 다시 실행했을 때 HM-8에는 없던 표현(쉼표 숫자, 여러 값이 든 표 칸, 「~보다 적으면」, 「~려면」)이 어떻게 나오는지 봅니다.
  • 이름 속 숫자를 기준값으로 만든 후보는 근거 없는 생성으로 제외하거나 규칙을 고칩니다.

비교용 추출 결과와 차이가 나면 어느 쪽이 원문과 맞는지 원문으로 판단합니다. 비교용 결과가 정답 목록은 아닙니다.

05 저장하기

결과/extract.py, 결과/후보/, 결과/검토/, 결과/검토_기록.md를 저장하고 다시 열어 확인하세요. 검토 결과에 대해 check_candidates.py를 한 번 더 실행합니다.

보관할 결과는 USB 또는 개인 클라우드에 복사하세요. 다음 실습은 강사가 검토한 HM-8 검토 결과로 시작하므로 이번 결과가 없어도 진행할 수 있습니다.
