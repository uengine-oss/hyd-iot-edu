검토한 지식을 랩 그래프에 연결하고 작업 확인 카드 만들기

검토를 마친 HM-8 지식을 2회차 모델의 기존 ID에 연결해 별도 랩 DB에 적재하고, 선택한 작업의 준비·금지·완료 조건과 원문 출처를 모은 작업 확인 카드를 조회 결과로 만듭니다.

01 시작하기

압축을 푼 폴더를 VS Code에서 열고 START.md를 읽으세요. Docker Desktop이 실행 중이어야 합니다.

python lab_db.py
python lab_cypher.py model
python lab_cypher.py count

「랩 DB 준비 완료」가 나온 뒤 앞 단계 모델을 적재하고 노드·관계 수를 구축 기록에 적어 두세요. 이 수가 기존 모델을 보존했는지 판단하는 기준입니다.

AI에게 먼저 입력/의 모델·검토 결과와 출력 계약을 읽고 무엇이 있는지 설명하게 하세요. 이때는 파일을 만들거나 바꾸지 말라고 함께 말합니다.

02 요구 정하기

목표(검토한 지식을 기존 ID에 연결해 적재하고 작업 확인 카드 만들기), 입력, 제약(approved만, 기존 ID 보존, 반복 적재 무중복, 전체 삭제 금지), 확인할 사례(다른 작업, 미제공 절, 재적재, 제외·보류)를 자기 말로 정리해 전달하세요.

AI의 계획에서 새 종류·관계와 기존 ID 연결의 근거가 원문·자료에 있는지 보고 고칠 점을 말한 뒤 진행합니다.

03 AI와 만들기

작은 단위로 진행합니다. 예: 문서·절·절차 적재 → 지식 후보 적재와 출처 연결 → 기존 ID 연결 → 조회 → 카드. 단계마다 count와 조회 결과를 확인합니다.

수정 요청에는 실행한 문장, 기대한 결과, 실제 결과(오류 메시지·수치)를 함께 주세요.

요청을 정리할 때 볼 항목

만들 결과 / 읽을 자료 / 바꾸지 않을 범위 / 지켜야 할 출력 계약 / 성공을 확인할 사례 / 확인하지 못하면 어떻게 표시할지

04 결과 확인하기

python lab_db.py
python lab_cypher.py model
python lab_cypher.py count
python lab_cypher.py run 결과/load.cypher
python lab_cypher.py count
python lab_cypher.py run 결과/load.cypher
python lab_cypher.py count
python lab_cypher.py run 결과/query.cypher

판단 원칙: 수치는 기존 모델 보존과 무중복을, 카드의 출처와 원문 대조는 내용을 판정합니다. 둘 중 하나만으로는 완료가 아닙니다.

  • 같은 load.cypher를 두 번 실행한 뒤 count가 같아야 합니다.
  • 모델 적재 직후의 종류별 수(Asset·Sensor·Part 등)가 이번 적재 뒤에도 같아야 합니다.
  • 카드의 각 항목에서 원문 절을 열어 인용을 찾을 수 있어야 합니다.
  • 절차 밖의 절에 적힌 조건과 다른 절을 가리키는 완료 기준이 카드에 이어졌는지 원문 HM-8과 대조합니다.
  • 보류·제외 후보 id로 조회하면 결과가 없어야 합니다.
  • 원문에 없는 작업을 조회하면 결과 없음이 나오고, 카드에 그렇게 적혀야 합니다.

현재 운전 상태·누적 운전 시간처럼 작업 직전에 읽어야 하는 값과 승인은 카드가 정하지 않습니다. 「현재 값 필요」·「승인 필요」로 남깁니다.

05 저장하기

결과 파일을 저장하고 다시 열어 확인하세요. 랩 DB의 내용은 컨테이너 안에 있으므로 적재문·조회문·카드·구축 기록 파일이 결과입니다. 보관할 결과는 USB 또는 개인 클라우드에 복사하세요.

다음 회차는 이 지식으로 점검 요청을 만듭니다. 다음 실습도 독립 시작본을 제공합니다.
