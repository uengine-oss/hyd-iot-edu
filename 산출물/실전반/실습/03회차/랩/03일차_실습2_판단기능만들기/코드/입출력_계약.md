# 조건표와 판단 결과의 계약

## 앞 결과를 보존해 연결하기
앞 실습에서 작성한 파일은 input/에 원래 이름으로 보존하고 파일명·SHA-256·출처 판본을 검토 기록에 적는다. rules.csv는 빈 작성 틀이며 앞 결과를 덮는 완성본이 아니다. 앞 조건표의 열은 같은 뜻의 열로 옮기고 변경한 행과 이유를 기록한다. 후보 식별자는 targets.csv의 SOP ID를 사용한다. 시드의 skill ID는 동일 ID가 아니며 id-map.csv에서 근거를 확인한 대응만 사용한다. reference_skill_id 빈칸은 없어도 SOP별 평가를 할 수 있으며 이름만 보고 채우지 않는다.

## 규칙 한 개와 CSV 행
- 같은 rule_id·action의 여러 행은 condition_index 순으로 묶고 logic=AND로 평가한다. action은 SOP ID 하나다. 여러 적용 대상은 action을 달리하여 같은 규칙의 조건 전체를 각각 적는다.
- 단일 조건도 condition_index=1, logic=AND다. OR는 다른 rule_id로 나눈다. 조건·출력·단위·출처가 모순되는 중복 행은 입력 오류로 보고 먼저 고친다.
- 한 묶음의 조건이 모두 참일 때 출력은 한 번만 낸다. PENALTY를 조건 수만큼 더하지 않는다. 다른 규칙은 모두 평가하여 WARN·PENALTY·EXCLUDE를 각각 모은다.
- 적용 대상 밖은 평가하지 않는다. AND에서 알려진 거짓이 있으면 그 규칙은 불일치다. 나머지 경우 필요한 값이 없으면 unknown이다. 알려진 제외는 유지하며, 제외 없이 미해결 unknown이 남은 후보는 보류한다. 이는 이 랩의 보수적 검토 계약이며 HYD의 효과별 누락 처리와 구별한다.

## 입력 이름과 판본
cases.csv의 forecast_ts1_C → forecast_ts1(℃), forecast_ps1_bar → forecast_ps1(bar)로 명시 변환한다. fan100_hours·plc_mode·plc_state는 그대로 쓴다. skill_kind와 skill_code는 targets.csv에서 후보별로 읽으며 kind의 workorder를 work_order로 명시 변환해 작업지시로 해석한다. 코드의 세미콜론 목록은 분리한다. RESET 외 코드 조건은 목록에서 RESET이 아닌 실행 코드가 있는지를 검사한다. 비어 있는 숫자나 모드는 0·정상으로 채우지 않는다.

시드 작업기준의 R1은 팬 최대 운전·팬 감속용이다. HM-8.6의 모든 후보 예측 유온 경고로 확장할 때는 별도 규칙 ID와 HM-8.6 출처를 사용하고 기존 R1을 중복 집계하지 않는다. R3은 control 후보, R5는 SOP-COOL-11·12에 적용한다. 압력·TRIP 규칙은 source/규칙_원문.txt를 근거로 하며 HM-8에 없는 문장을 원문 인용으로 만들지 않는다.

## 결과와 확인
output/result.json에는 입력 사례 ID, 후보 SOP ID, 판정(유지/제외/보류), 규칙별 실제 입력·비교식·적용 여부·unknown·출처, warnings·penalties·violations, 누락 항목을 남긴다. 추천 대상이 없으면 빈 추천과 사유를 남긴다. 규칙 묶음당 감점은 한 번만 합산한다.

cases.csv의 A~M는 적용 대상과 경계 검사용이다. 후보별 예측값을 갖는 metrics/판정_요청.json의 C01~C14와 별도로 평가한다. 비교 대상 요청을 전부 처리하고, 빠진 값은 계산 불가로 남긴다. 네 손실+감점은 이 랩의 비교 합계이며 HYD 정책 점수가 아니다. 제외·보류 후보는 순위에서 빼고 동점은 동순위로 둔다. 원문에서 기대 결과를 먼저 적고 실제 결과와 대조한다. 오류를 일부러 만들지 않는다.

L은 원격 제어 후보의 모드 누락을, M은 작업지시 후보에서 원격 모드·팬 시간이 적용 대상 밖인 경우를 확인한다. 관련 없는 빈값까지 모든 후보를 보류하는 결함을 이 둘로 구분한다.
