# 부품별 사용 설비와 공급 조건 조회하기

> 자료는 교육용 가상 사례(실제 HYD 시스템 구조 기반). 회사·사람·일련번호·금액은 수업용으로 만든 값이다.

앞 단계 완성 모델(설비·부품·공급)을 별도 랩 DB에 적재하고, 부품별 사용 설비와 공급 조건을 반환하는 조회를 만듭니다. 수정본 반영과 반복 적재에서 중복이 생기지 않는지 확인합니다.

## 출발점

`입력/schema.json`·`graph.json`은 앞 단계 완성 모델이고, `입력/자료/`는 그 원자료, `입력/자료_변경분/`은 기준일 뒤 들어온 수정본입니다. 이전 개인 결과 없이 시작할 수 있습니다. 개인 모델을 쓰려면 제공 입력을 보존하고 별도 폴더에 복사하세요.

## 이번에 해결할 질문

1. 선택한 부품을 쓰는 설비와 구성 요소는 무엇인가?
2. 그 부품의 공급사별 승인 여부·단가·불량률·납기는 무엇이고, 각 값은 어느 파일·어느 날짜 자료에서 왔는가?
3. 비슷한 이름의 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물었을 때 결과가 서로 구별되는가?
4. 견적 납기와 지난 입고의 실측 납기는 공급사별로 얼마나 다른가?
5. 수정본을 반영한 뒤에도 같은 ID가 유지되고, 다시 적재해도 대상과 관계가 늘지 않는가?

## 작업

적재(모델 → DB)와 조회를 작성합니다. 같은 입력을 두 번 적재해도 대상과 관계가 늘지 않아야 하고, 이름이 바뀌어도 같은 ID의 대상은 유지되어야 합니다. 전체 삭제문은 쓰지 않고, 수정본은 필요한 대상만 고쳐 반영합니다. P-PMP-SEAL을 확인 사례로 사용 설비와 공급 조건을 원자료와 대조하고, 다른 품번·없는 품번도 조회합니다. 비승인 공급사는 승인 상태와 함께 구별해 보여 줍니다. 실측 납기는 `입력/자료/입고_이력.csv`에서 계산합니다.

## 확인할 사례의 종류

공용 부품 / 비슷한 이름의 다른 품번 / 예전 품번·다른 표기 / 원자료에 없는 품번 / 비승인·조건이 붙은 공급사 / 나눠 들어온 입고 / 수정본의 이름 변경·상태 변경·값 보완 / 같은 적재 두 번

어느 행이 해당하는지는 원자료에서 직접 찾습니다.


## 처음 쓰는 도구

`python lab_db.py`가 이 폴더 전용 Neo4j(랩 DB)를 Docker로 켜고 Browser를 엽니다. 포털 DB와 분리돼 있습니다. Browser 입력 칸에 Cypher를 넣어 실행하고 표(Table)로 원자료와 대조합니다. 수백 개 대상은 AI가 `입력/graph.json`에서 적재문을 만들게 합니다.

## 진행 방법

1. AI에게 파일은 바꾸지 말고 자료를 읽어 과제와 확인할 점을 파일·줄로 짚어 달라고 요청하세요. 짚어 준 근거는 원자료에서 직접 확인합니다.
2. 목표·입력·지킬 조건과 내가 정한 결정을 자기 말로 `결과/검증_기록.md`에 적으세요. 자료를 읽는 방식에 따라 답이 달라지는 지점을 하나 이상 찾아, 무엇으로 정했고 근거가 어느 파일·줄인지 함께 적습니다. 구현 전에 질문별 기대 답을 원자료에서 몇 개 직접 찾아 둡니다.
3. AI에게 계획을 먼저 받아 검토한 뒤 구현을 맡기세요. 한 번에 다 맡기지 말고 확인할 수 있는 단위로 나눕니다.
4. 완료 보고에는 실행한 명령과 출력 원문을 붙여 달라고 요청하세요. 바뀐 파일도 확인합니다. 입력/·자료/는 바뀌지 않아야 합니다.
5. 적어 둔 기대 답과 실제 결과를 대조하고, 다르면 입력·기대·실제를 함께 전달해 고치세요.

요청에 파일 이름을 쓸 때는 `결과/schema.json`처럼 백틱(`)으로 감쌉니다. 채팅 입력이 밑줄(_)을 서식으로 바꾸기 때문입니다.

## 저장할 결과

`결과/load.cypher`(또는 적재 코드), `결과/query.cypher`, `결과/검증_기록.md`

## 확인

```
python lab_db.py
Neo4j Browser에서 적재 → 개수 확인 → 같은 적재 다시 실행 → 개수 비교 → 조회 → 수정본 반영 → 조회 다시 실행
```

## 완료 판정

형식 검사나 실행 성공만으로 완료하지 않습니다. 질문마다 원자료의 행과 실제 답을 대조하고, 내가 정한 결정에 따라 답이 어떻게 달라지는지 설명할 수 있어야 합니다. 수정한 점과 확인하지 못한 점을 짧게 남깁니다.
