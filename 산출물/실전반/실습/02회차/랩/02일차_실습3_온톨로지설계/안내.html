01 시작하기

앞 단계에서 만든 설비·부품 모델에 구매팀의 견적·승인·품번 자료를 연결해, 부품별 사용 설비와 공급 조건을 함께 답하는 모델로 확장합니다. 공급사를 고르거나 점수화하지는 않습니다.

입력/schema.json·graph.json은 설비 7대·구성요소·센서·부품까지 정리된 앞 단계 완성 모델입니다. 공급 정보는 아직 연결되어 있지 않습니다. 자료/에 원자료 전체(견적·승인 공급사·품번 교차표·입고 이력 포함)가 있습니다.

VS Code에서 START.md를 열고 이번 요구를 확인하세요.

입력/   앞 단계 결과·완성 모델
자료/   현장 원자료(CSV 8개·현장 메모)
결과/   이번에 만들 결과
AGENTS.md   AI 작업 규칙

02 요구 정하기

  1. 선택한 부품을 쓰는 설비와 구성 요소는 무엇인가?
  2. 그 부품의 공급사별 승인 여부·단가·불량률·납기는 무엇이고, 각 값은 어느 파일·어느 날짜 자료에서 왔는가?
  3. 비슷한 이름의 다른 품번, 예전 품번이나 다른 표기, 원자료에 없는 품번으로 물었을 때 결과가 서로 구별되는가?

자료에서 답의 근거를 찾고, AI에 전달할 목표·제약·내가 정한 결정을 정리하세요. 확인할 사례의 종류: 같은 대상의 여러 기록(같은 쌍·같은 품목이 여러 줄이나 여러 파일에 나오는 경우) / 출처마다 다른 값이나 표기 / 비슷한 이름의 다른 품번과 원자료에 없는 품번.

03 AI와 만들기

공급 자료를 모델의 어디에 어떤 종류·속성·관계로 둘지 정하고, 기존 설비·부품 연결과 ID를 유지하면서 모델을 확장합니다. 값마다 단위와 출처(파일·날짜)를 남기고, 원자료에서 공급 정보를 만드는 코드를 `결과/`에 둡니다. 자료를 정리하며 내린 처리는 `결과/자료_검토.md`에 남깁니다.

먼저 파일을 바꾸지 말고 자료를 읽게 하고, 계획을 받아 검토한 뒤 확인할 수 있는 단위로 나눠 맡기세요. 완료 보고에는 실행 출력 원문을 붙여 달라고 요청합니다. 파일 이름은 백틱(`)으로 감싸 입력하세요.

요청을 정리할 때 볼 항목

만들 결과 / 참고할 자료 / 내가 정한 결정 / 바꾸지 않을 범위 / 성공을 확인할 사례

Codex 채팅 창 위쪽 탭이 Codex인지 확인하고 입력합니다(Chat 탭은 GitHub Copilot). AI가 파일을 고치려 하면 「Allow ChatGPT to edit the following file?」 창이 뜹니다. 경로가 결과/ 아래이면 「Allow once」, 입력/·자료/이거나 요청하지 않은 파일이면 「Deny」를 누릅니다. START.md 「학생이 정할 것」 지점에서는 AI가 질문 카드로 묻습니다. 「(권장)」은 AI의 추천일 뿐이니 원자료의 근거 줄을 열어 확인하고 고르거나 직접 적습니다.

04 결과 확인하기

python check.py
  • 질문마다 원자료에서 먼저 찾은 기대 답과 실제 결과를 나란히 적습니다.
  • 자료를 읽는 방식에 따라 답이 갈리는 지점은 내가 정한 결정과 근거 행을 함께 남깁니다.
  • 값이 없음·미확인·0을 구별합니다.
  • 공급사·부품 쌍마다 기준일에 유효한 조건 하나와 approved(참/거짓)를 정했는지, 그 근거 행(견적표·승인 공급사 목록)을 자료_검토.md에 적었는지 확인합니다. 모든 견적을 남기고 표시만 붙이면 질문 2의 답이 하나로 정해지지 않습니다.
  • 가격·납기로 공급사를 자동 선정하지 않습니다.

원자료와 실제 결과를 대조하세요. AI의 완료 메시지는 실행 결과를 대신하지 않습니다.
