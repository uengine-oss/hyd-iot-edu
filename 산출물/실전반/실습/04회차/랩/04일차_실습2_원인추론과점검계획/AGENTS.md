# 실습 작업 규칙

- START.md의 이번 과제와 자료를 먼저 확인한다. 요구가 모호하면 필요한 질문을 한다.
- 코드/source·코드/input의 파일과 코드/check.py, 코드/llm_client.py는 보존한다. 새 코드와 산출물은 코드/output에 작성한다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인과 값 없음, 0을 구별한다.
- 학생이 정한 요구와 제약 안에서 구현한다. 무관한 서비스·대시보드·선정 규칙을 추가하지 않는다.
- 실행한 명령, 실제 결과, 남은 미확인을 구별한다. 검사 통과를 위해 검사 기준이나 원자료를 바꾸지 않는다.
- 완료를 알릴 때는 실행한 명령과 실제 출력, 바뀐 파일 목록을 함께 보여 준다. 실행하지 않은 것은 실행하지 않았다고 쓴다.
- 실제 설비·포털·업무 시스템을 호출하지 않는다. 이번 실습은 제공 파일과 수업 모델 접속만 쓴다.
- 접속 키·비밀번호를 코드나 결과 기록에 넣지 않는다. 코드/.env는 열거나 출력하지 않고 llm_client.py만 읽게 한다. 개인 GitHub·commit·push는 요구하지 않는다.
- 학생이 작성한 결과를 바꿀 때만 보관한다. 제공된 빈 틀(첫머리에 「제공 빈 틀」 표시가 있는 파일)은 보관 없이 채운다.
- START.md의 「정할 것」 절(「학생이 정할 것」 포함)에 해당하는 지점은 정하기 전에 학생에게 묻는다. 학생이 이미 정해 준 결정은 그대로 따르고, 묻지 못했으면 정하지 말고 미결로 표시한다. 정한 결정은 누가 어떤 근거로 정했는지 결과 기록에 남긴다.
- START.md 「이번 범위 밖」의 일(다음 실습에서 할 일 포함)은 만들지 않는다.
- 원인·증거·기준값·부품 번호를 코드에 옮겨 적어 고정하지 않는다. 도구가 그래프·사례·원문에서 읽는다. 특정 사례 번호나 값에만 맞춘 분기를 넣지 않는다.
- 도구를 고르는 것은 모델이다. 프로그램은 모델이 부른 도구를 실행해 그대로 돌려주고, 부른 순서대로 호출 기록에 남긴다. 실패한 호출도 지우지 않는다.
- 원인 후보를 확정 원인으로, 점검 요청 초안을 작업지시로 쓰지 않는다. 작업지시 번호를 만들지 않는다.
