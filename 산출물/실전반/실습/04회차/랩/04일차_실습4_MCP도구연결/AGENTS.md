# 실습 작업 규칙

- START.md의 이번 과제와 자료를 먼저 확인한다. 요구가 모호하면 필요한 질문을 한다.
- 코드/source·코드/input의 파일과 제공 서버(코드/서버의 점검메모_서버.py 밖의 파일), 코드/도구는 보존한다. 새 결과는 코드/output에, 직접 구현하는 서버 코드는 코드/서버/점검메모_서버.py에 작성한다.
- 원자료에 없는 값·관계·실행 결과를 만들지 않는다. 미확인과 값 없음, 0을 구별한다.
- 학생이 정한 요구와 제약 안에서 구현한다. 무관한 서비스·대시보드·선정 규칙을 추가하지 않는다.
- 실행한 명령, 실제 결과, 남은 미확인을 구별한다. 검사 통과를 위해 검사 기준이나 원자료를 바꾸지 않는다.
- 완료를 알릴 때는 부른 서버·도구와 실제 결과, 바뀐 파일 목록을 함께 보여 준다. 실행하지 않은 것은 실행하지 않았다고 쓴다.
- 실제 설비·포털·업무 시스템을 호출하지 않는다. 이번 실습은 제공 파일·로컬 MCP 서버와 학생 자신의 Notion 읽기만 쓴다.
- 접속 키·비밀번호·토큰을 코드나 결과 기록에 넣지 않는다. Notion 로그인은 학생이 직접 한다. 개인 GitHub·commit·push는 요구하지 않는다.
- 학생이 작성한 결과를 바꿀 때만 보관한다. 제공된 빈 틀(첫머리에 「제공 빈 틀」 표시가 있는 파일)은 보관 없이 채운다.
- START.md의 「정할 것」 절(「학생이 정할 것」 포함)에 해당하는 지점은 정하기 전에 학생에게 묻는다. 학생이 이미 정해 준 결정은 그대로 따르고, 묻지 못했으면 정하지 말고 미결로 표시한다. 정한 결정은 누가 어떤 근거로 정했는지 결과 기록에 남긴다.
- START.md 「이번 범위 밖」의 일(다음 실습에서 할 일 포함)은 만들지 않는다.
- 모든 서버는 읽기로만 쓴다. Notion·파일 쓰기 도구, Git 커밋·되돌리기를 부르지 않는다. 허용 범위 밖 자료를 읽으려고 서버 인자나 허용 폴더를 몰래 넓히지 않는다.
- 접근 실패·연결 실패·시간 초과를 업무 없음이나 0행으로 바꾸지 않는다. 「확인하지 못함」과 사유로 적고 그 자료에 기대는 내용은 남은 확인으로 둔다.
- Notion에 연결하지 못해 내보내기 파일로 이어 갔으면 MCP 연결 성공으로 적지 않는다.
