# 점검 요청 기능 — 이전 단계 판본

지난 회차 「원인 추론과 점검 계획」 실습의 결과를 점검 요청 단위로 묶은 판본입니다. 수업 준비 때 실행해 결과를 확인했습니다. AI 모델을 부르지 않고 같은 입력이면 같은 결과를 내는 프로그램입니다.

## 하는 일

1. `source/입력/점검_요청.json`의 요청마다 요청에 적힌 `사례` 번호로 `source/입력/센서_입력.json`의 사례 한 건을 찾습니다.
2. 그 사례의 경보 패턴으로 온톨로지(`source/온톨로지/graph.json`)에서 원인 후보 · 증거 기준 · 조치 방법 · 승인 역할을 읽고, 센서 값을 증거 기준에 대어 원인마다 확인됨 · 가설 · 해당_없음으로 나눕니다. 관련 부품은 `source/매뉴얼/`의 원문에서 찾습니다.
3. **점검 요청 초안**(대상 설비 · 구성 요소 · 부품 · 관측 시각 · 근거 상태 · 확인 항목 · 이유 · 승인 대상 조치)을 만듭니다. 초안은 작업지시가 아닙니다.
4. 근거 상태가 SUPPORTED이면 `승인 대기`, 아니면 `보류`로 둡니다. 요청에 사례가 적혀 있지 않거나 센서 입력에 없는 사례이면 `보류`로 둡니다.
5. `source/사람/승인.json`에서 그 요청 번호의 결정만 읽어 반영합니다. 승인은 초안의 조치 가운데 하나를, 그 조치의 승인 역할이거나 더 높은 등급의 역할이 고를 때만 반영합니다. 거절은 사유가 있고 그 요청의 조치를 결정할 수 있는 역할일 때만 반영합니다. 반영하지 않은 결정도 까닭과 함께 상태 기록에 남습니다.

이 프로그램은 설비 명령 · 작업지시를 만들지 않습니다. 역할 · 이름은 로컬 연습 입력이며 실제 HYD의 인증 · 권한 검사를 대신하지 않습니다.

## 실행

VS Code 터미널에서 랩 폴더(START.md가 있는 폴더)를 기준으로 실행합니다.

```
python 코드/input/점검요청/점검_요청.py
python 코드/input/점검요청/점검_요청.py R03
```

- 결과는 프로그램 폴더 아래 `결과/점검_요청.json`(다음 단계가 읽는 것)과 `결과/점검_요청.md`(사람이 읽는 것)에 씁니다. 터미널에는 요청마다 번호 · 상태 · 사례 · 보류 사유가 한 줄씩 나옵니다.
- `--원자료 <source 폴더>`, `--입력 <폴더>`(점검_요청.json · 센서_입력.json), `--사람 <폴더>`(답변.json · 승인.json), `--결과 <폴더>`로 읽을 곳과 쓸 곳을 바꿀 수 있습니다.
- 이 폴더의 `결과/`는 이 판본을 그대로 실행한 결과입니다.

## 결과 한 건의 칸

| 칸 | 뜻 |
|---|---|
| `요청` | 요청 번호 |
| `상태` | `접수` · `보류` · `승인 대기` · `승인됨` · `거절` 가운데 지금 상태 |
| `보류_사유` | 보류일 때 그 까닭. 아니면 `null` |
| `사례` | 초안을 만든 사례 번호. 정하지 못했으면 `null` |
| `초안` | 점검 요청 초안. 사례가 없으면 `null` |
| `승인` | 반영한 결정(결정 · 절차_번호 · 역할 · 이름 · 사유). 없으면 `null` |
| `후속_업무` | 승인된 조치의 실행 요청 대상. 승인되지 않았으면 빈 목록 |
| `상태_기록` | 순번 · 상태 · 까닭의 목록. 반영하지 않은 결정도 남는다 |

함수: `처리한다(요청, 자료)`가 요청 한 건의 결과를 돌려주고, `초안을_만든다(사례, 자료)`가 사례 한 건의 초안을 돌려줍니다. 원자료를 읽는 일은 `도구.py`가 맡고 판정하지 않습니다.
