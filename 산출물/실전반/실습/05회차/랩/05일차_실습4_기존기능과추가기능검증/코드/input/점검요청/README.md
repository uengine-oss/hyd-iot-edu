# 점검 요청 기능 — 「명세에 따른 요구사항 추가」 완성 판본

앞 실습(명세에 따른 요구사항 추가)의 완성 판본입니다. 명세는 `코드/input/spec.md`입니다. 수업 준비 때 실행해 결과를 확인했습니다. AI 모델을 부르지 않고 같은 입력이면 같은 결과를 내는 프로그램입니다.

## 하는 일

1. `source/입력/점검_요청.json`의 요청마다 설비 · 경보 · 사례를 `source/입력/센서_입력.json`으로 먼저 확인해 사례 한 건을 정합니다. 기존 자료로 정할 수 없거나(맞는 사례가 여럿) 요청과 사례가 어긋날 때만 질문을 내고 `질문 대기`로 둡니다. 맞는 사례가 없으면 묻지 않고 `보류`로 둡니다.
1. `source/사람/답변.json`에서 같은 요청 번호 · 같은 질문 순번의 답만 읽어 이어서 다시 판단합니다(`재개`). 선택지에 없는 답, 내지 않은 순번의 답은 반영하지 않고 상태 기록에 남깁니다. 답변은 정보이며 승인이 아닙니다.
1. 그 사례의 경보 패턴으로 온톨로지(`source/온톨로지/graph.json`)에서 원인 후보 · 증거 기준 · 조치 방법 · 승인 역할을 읽고, 센서 값을 증거 기준에 대어 원인마다 확인됨 · 가설 · 해당_없음으로 나눕니다. 관련 부품은 `source/매뉴얼/`의 원문에서 찾습니다.
1. **점검 요청 초안**(대상 설비 · 구성 요소 · 부품 · 관측 시각 · 근거 상태 · 확인 항목 · 이유 · 승인 대상 조치)을 만듭니다. 초안은 작업지시가 아닙니다.
1. 근거 상태가 SUPPORTED이면 `승인 대기`, 아니면 `보류`로 둡니다. 센서 입력에 없는 사례이면 `보류`로 둡니다.
1. `source/사람/승인.json`에서 그 요청 번호의 결정만 읽어 반영합니다. 승인은 초안의 조치 가운데 하나를, 그 조치의 승인 역할이거나 더 높은 등급의 역할이 고를 때만 반영합니다. 거절은 사유가 있고 그 요청의 조치를 결정할 수 있는 역할일 때만 반영합니다. 반영하지 않은 결정도 까닭과 함께 상태 기록에 남습니다.
1. 요청마다 긴급 확인 표시(`urgent`: true · false · null)와 그 근거를 붙입니다(교육용 조건, `코드/input/spec.md`). 긴급 표시는 상태 · 질문 · 승인 조건을 바꾸지 않습니다.

이 프로그램은 설비 명령 · 작업지시를 만들지 않습니다. 역할 · 이름은 로컬 연습 입력이며 실제 HYD의 인증 · 권한 검사를 대신하지 않습니다.

## 실행

VS Code 터미널에서 랩 폴더(START.md가 있는 폴더)를 기준으로 실행합니다.

```
python 코드/input/점검요청/점검_요청.py
python 코드/input/점검요청/점검_요청.py R03
```

- 결과는 프로그램 폴더 아래 `결과/점검_요청.json`(다음 단계가 읽는 것)과 `결과/점검_요청.md`(사람이 읽는 것)에 씁니다. 터미널에는 요청마다 번호 · 상태 · 사례 · 보류 사유가 한 줄씩 나옵니다.
- `--원자료 <source 폴더>`, `--입력 <폴더>`(점검_요청.json · 센서_입력.json), `--사람 <폴더>`(답변.json · 승인.json), `--결과 <폴더>`로 읽을 곳과 쓸 곳을 바꿀 수 있습니다.
- 이 폴더의 `결과/`는 이 판본을 그대로 실행한 결과입니다.

## 결과 한 건의 칸

| 칸 | 뜻 |
|---|---|
| `요청` | 요청 번호 |
| `상태` | `접수` · `질문 대기` · `재개` · `보류` · `승인 대기` · `승인됨` · `거절` 가운데 지금 상태 |
| `보류_사유` | 보류 · 질문 대기일 때 그 까닭. 아니면 `null` |
| `사례` | 초안을 만든 사례 번호. 정하지 못했으면 `null` |
| `사례_확인` | 사례를 어떻게 정했는지(요청에 적힌 사례 · 기존 자료로 확인 · 질문의 답) |
| `질문` | 낸 질문(순번 · 물음 · 선택지 · 답 · 답한_사람 · 반영) |
| `초안` | 점검 요청 초안. 사례가 없으면 `null` |
| `확인_항목_변화` | 질문이 있었던 요청에서 답변 전 · 뒤의 확인 항목 |
| `urgent` | 긴급 확인 표시. `null`은 「긴급 아님」이 아니다 |
| `긴급_근거` | 구분 · 기준 · 판정_값 · 신선도_ok · 표본_covered · 이유 |
| `승인` | 반영한 결정(결정 · 절차_번호 · 역할 · 이름 · 사유). 없으면 `null` |
| `후속_업무` | 승인된 조치의 실행 요청 대상. 승인되지 않았으면 빈 목록 |
| `상태_기록` | 순번 · 상태 · 까닭의 목록. 반영하지 않은 결정도 남는다 |

함수: `처리한다(요청, 자료)`가 요청 한 건의 결과를 돌려주고, `초안을_만든다(사례, 자료)`가 사례 한 건의 초안을 돌려줍니다. 원자료를 읽는 일은 `도구.py`가 맡고 판정하지 않습니다.
