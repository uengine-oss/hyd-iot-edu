# 실전반 5회차 실습 3 — 명세에따른요구사항추가

> [제작 안내 — 낭독하지 않음] 강사 단독 시연 대본이다. 실제 조작·AI 응답·실습 실행·접속·캡처는 이번 제작에서 수행하지 않았다. 실제 결과를 확인한 뒤 그 값과 근거를 읽는다. 성공을 미리 낭독하지 않는다.

## 다운로드와 변경 전 상태 보존

기존 정비 요청을 유지하면서 긴급 판단을 추가하겠습니다. 먼저 무엇을 바꾸고 무엇을 유지할지 명세로 정합니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 명세에따른요구사항추가 ZIP을 내려받아 압축을 풀고 앞 실습의 프로젝트를 VS Code에서 열겠습니다. 변경 전 파일과 입력, 실제 확인 기록을 별도 보존하겠습니다. 이번 자료의 source/기존_비교기록은 모호한 요청을 세 사본에 보냈던 제공 기록입니다. 이번에 실행한 결과와 구별해서 읽습니다.

요청.txt와 변경 전 요청_처리.json, 각 사본의 출력과 바뀐 파일 목록을 비교하겠습니다. 출력 항목, 일반 요청의 상태, 승인 조건이 달라진 부분을 review.md에 적습니다. 일부만 바뀐 파일이므로 없는 파일을 삭제된 것으로 읽지 않습니다. 이 기록의 확인됨은 등록된 증거 기준이 지지했다는 뜻이며 현장 원인을 입증한 것은 아닙니다. 기존 코드의 역할 문자열 비교는 실제 역할 구성원·등급 검사를 대신하지 않고, 거절 권한 검사도 불완전합니다. 이 한계를 현재 실습 명세의 정답으로 가져오지 않습니다. 모호한 요청이 항상 실패한다거나 세 결과가 모든 경우를 대표한다고 결론 내리지 않겠습니다.

## 명세를 먼저 작성하기

현재 프로젝트의 입력과 출력 구조를 읽고 spec.md를 작성하겠습니다. 목표, 입력, 출력, 금지 조건과 수용 기준을 나눕니다. 기존 일반 요청의 결과 항목과 뜻, 정보 누락 시 보류, 승인 없이 업무를 확정하지 않는 조건을 먼저 적겠습니다.

추가 요구는 COOLER_DEGRADATION, 즉 쿨러 성능 저하 경보에서 유효한 TS1의 120초 평균이 섭씨 60도 이상이면 urgent를 참으로 표시하는 교육용 조건입니다. 같은 경보에서 유효한 값이 60도 미만이면 거짓입니다. 다른 경보 종류에는 이 조건을 적용하지 않고 기존 처리를 유지합니다. 제공 자료의 freshness.ok와 해당 집계의 coverage.covered가 모두 참인지 확인합니다. 값이 없거나 유효하지 않으면 false로 대신 채우지 않고 urgent를 null로 두어 미판정과 보류 사유를 기록합니다. 실제 운전 화면의 60도 초과 경고와 이 예의 60도 이상 조건은 경계에서 다릅니다. 실제 설비 기준을 바꾸는 것이 아닙니다. 긴급 표시가 생겨도 승인 절차와 일반 요청의 출력 계약은 유지합니다.

수용 기준에는 같은 입력과 자료에서 일반 요청의 기존 결과가 유지되는지, 긴급 입력에 표시가 추가되는지, 누락이면 보류하는지, 거절이면 후속 업무가 없는지를 적겠습니다. 실행 번호와 시각은 값 자체의 동일성 대신 형식·연결 관계를 검사하도록 정합니다. 출력에 필드를 더할 때 기존 소비자가 이를 받아들일 수 있는지도 확인하겠습니다.

## 명세에 맞춰 구현하고 비교하기

코딩 도우미에게 spec.md를 읽고 필요한 부분만 고치도록 요청하겠습니다. 기존 일반 요청 처리와 질문 단계, 승인 조건을 보존하고 긴급 여부와 그 근거를 추가해 주세요. 임계값과 입력 검사를 명세와 맞추고, 기존 출력 이름과 뜻은 유지해 주세요.

수정된 파일을 비교해 관련 없는 변경이 없는지 읽고, 수업 환경에서 일반·긴급·누락 입력을 같은 조건으로 확인하겠습니다. 새 기능만 보지 않고 변경 전 일반 요청의 결과와 대조합니다. 기대와 다르면 차이를 먼저 기록한 뒤 코드와 명세 중 실제 원인이 있는 곳을 확인합니다. 검사에 맞추려고 기존 기대값을 바꾸지 않겠습니다.

## 다음 검증의 재료 저장

spec.md와 구현 판본, 입력, 조회 자료, expected.json에 직접 적은 기대 결과, 실제 결과를 저장하겠습니다. 가상 경계 입력은 복사본에만 만들고 원본과 구별합니다. 다시 열어 각 수용 기준에 대응하는 입력과 기대가 있는지 확인하겠습니다. 이어서 이 프로젝트를 시나리오와 반복 검증으로 확인하겠습니다.
