# 실전반 6회차 실습 5 — 에이전트와실행연결

> [진행 — 낭독하지 않음] 강사 단독 진행용 대본이다. 아래 조작은 수업에서 수행할 절차이며 이번 제작에서 실행·접속·캡처하지 않았다. 예상 결과를 실제 결과처럼 읽지 않는다. 오류가 나면 실제 사유와 수정·재확인을 남긴다.

## 다운로드와 비교 대상 준비

직접 그린 흐름을 포털에 등록된 기준 흐름과 견주고, 내가 그린 작업마다 어떤 실행 기능에 대응하는지 표시하겠습니다. 여기서 기준 흐름은 수업용으로 미리 등록해 둔 시나리오 A 흐름 「냉각 긴급 대응」과 그 제공 매핑입니다. 아무 수업 흐름도 쓰지 않을 때 경보를 받는 원래 흐름과는 다른 것입니다. 이번에는 내 그림을 포털에 올리지 않습니다.

> [준비 · 비낭독] 에이전트와실행연결 ZIP을 내려받아 압축을 풀고 VS Code에서 랩 폴더를 열어 START.md를 읽겠습니다. 앞 실습의 cooling.bpmn, condition-plan.md, element-map.md를 코드/input에 복사합니다. 코드/source/reference의 cooling-emergency.bpmn과 mapping.json은 제공 기준 BPMN과 매핑이며 고치지 않습니다. 결과는 코드/output/실행연결_대응표.md에 적겠습니다.

내 그림의 요소 ID와 이름, 종류, 레인을 대응표 왼쪽에 먼저 옮기겠습니다. 매핑을 열기 전에 작업마다 어떤 실행 기능이 붙을지 예상 칸에 적어 둡니다.

## 기준 흐름 확인과 다섯 연결 찾기

제공 기준 BPMN을 편집기에서 열고, 포털의 승인과 실행 화면에서 업무 흐름 그림을 보겠습니다. 처리 건 화면에 냉각 긴급 대응 처리 건이 있으면 흐름 이름과 판본, 단계도 확인해 비교한 대상 칸에 적습니다. 그림 파일의 프로세스 ID와 포털에서 보이는 흐름 이름은 따로 적겠습니다.

이제 mapping.json에서 실라버스가 꼽은 다섯 연결을 찾겠습니다. 시작 이벤트는 start의 경보 패턴, 에이전트 단계는 판단·제안 부품과 냉각 대응 에이전트, 운전원 승인은 조치 카드 승인·거절 부품과 운전원 역할입니다. 설비 명령은 PLC 명령 발행, 재관측은 재관측 부품입니다. 키와 값을 대응표에 적고, 내 그림에서 해당 요소 ID를 찾아 옆에 둡니다.

## 내 작업과 실행 기능 대응 표시

내 작업마다 대응하는 기준 요소 ID와 실행 기능, 담당을 채우겠습니다. 이름이 같아도 레인이나 종류가 다르면 그대로 적습니다. 내 작업 하나가 기준 작업 둘에 걸치거나 맞는 작업이 없으면 대응함, 다르게 대응, 대응 없음 중 무엇으로 표시할지 근거를 보고 정합니다. 예를 들어 앞 실습에서 회복 여부 갈림을 그리지 않았다면, 기준 흐름에만 있는 갈림으로 적습니다.

마지막으로 그림 파일과 실행 정의를 구분하겠습니다. 승인 선에 승인이라고 이름을 붙였지만, 실행 조건 approval 같음 승인은 매핑의 flows에 있습니다. 승인 지연 기한 PT10M은 timers에, 에이전트와 운전원 역할은 tasks에 있습니다. 그림의 레인 이름만으로 담당과 권한이 정해지지 않습니다. 대응표를 저장하고 다시 열어 근거 칸이 비지 않았는지 확인한 뒤, 다음 실습에서 이 표로 내 그림을 검사하겠습니다.
