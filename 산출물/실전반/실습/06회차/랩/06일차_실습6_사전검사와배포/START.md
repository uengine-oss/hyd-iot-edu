# 내 BPMN의 역할·분기·종료 연결 검사하고 수정하기

내가 그린 설비 대응 BPMN에서 승인·반려 경로와 종료 연결을 직접 따라가며 빠진 연결을 찾아 고치고, 제공 기준 BPMN·매핑과 견주어 작업마다 담당 역할과 실행 기능이 빠지지 않았는지 확인합니다. 결과는 고친 그림과 **연결 검사 기록**이며, 다음 실습에서 실제 처리 건의 기록과 내 그림을 맞춰 볼 때 이 그림을 씁니다.

## 출발점

- `코드/input/`: 실습4에서 저장한 `cooling.bpmn`과 실습5의 `실행연결_대응표.md`를 복사해 둡니다. 원본은 고치지 않습니다.
- [코드/source/reference/cooling-emergency.bpmn](코드/source/reference/cooling-emergency.bpmn), [코드/source/reference/mapping.json](코드/source/reference/mapping.json): 제공 기준 BPMN과 매핑입니다(대조용, 고치지 않습니다). 설명은 [코드/source/reference/README.md](코드/source/reference/README.md).
- [코드/output/연결검사_기록.md](코드/output/연결검사_기록.md): 검사와 수정을 적는 제공 빈 틀입니다.
- 편집기: demo.bpmn.io

## 이번에 할 것

- 시작에서 승인 경로, 거절(반려) 경로, 승인 지연 알림 갈래를 하나씩 따라가 각 갈래가 끝 이벤트에 닿는지, 끊긴 선·건너뛴 작업·끝 없는 갈래가 없는지 찾습니다.
- 제공 기준 BPMN·매핑과 비교해 내 작업마다 담당 역할(레인)과 실행 기능이 빠지지 않았는지 확인합니다.
- 실제로 찾은 문제만 고쳐 `코드/output/cooling.bpmn`으로 저장하고, 다시 열어 연결을 확인합니다.

## 작업 순서

1. `코드/input/cooling.bpmn`을 편집기에서 열고, 고친 결과는 `코드/output/cooling.bpmn`으로 저장할 준비를 합니다.
2. 고치기 전에 경로마다 지나야 할 요소와 닿아야 할 끝을 기록의 「따라간 경로」에 먼저 적습니다.
3. 그림에서 경로를 하나씩 따라가며 실제로 닿는 끝과 찾은 문제의 위치(요소 ID)를 적습니다.
4. 실습5의 대응표와 제공 기준 BPMN·매핑을 옆에 두고 「기준 BPMN·매핑과 대조」 표를 채웁니다.
5. 차이마다 누락인지 의도한 차이인지 판정하고, 누락만 고칩니다. 정상인 연결을 일부러 지워 문제를 만들지 않습니다.
6. 저장하고 편집기에서 다시 열어 각 경로를 다시 따라갑니다. XML에서 선의 `sourceRef`·`targetRef`와 경계 타이머의 `attachedToRef`·`cancelActivity`도 확인합니다.

## 기대 결과를 먼저 적을 사례 종류

- 거절 경로: 냉각 명령을 지나지 않고 반려 종료에 닿는지
- 승인 지연 알림 갈래: 운전원 승인을 끝내지 않고 자기 끝에 닿는지
- 기준 흐름에 있지만 내 그림에 없는 갈림이나 작업(예: 재관측 뒤 갈림, 거절 결과 보고)
- 레인은 맞지만 매핑의 담당 역할과 다르게 읽힐 수 있는 작업

## 학생이 정할 것

> 기준 BPMN과 다른 곳마다 고칠 누락인지, 내 업무 설계에서 의도한 차이로 남길지 정합니다. 예를 들어 앞 실습에서 그리지 않은 갈림을 이번에 더할지, 레인 이름이 기준과 달라도 그대로 둘지를 정하고, 판정과 근거를 기록의 「판정」 칸에 적습니다. 판정에 따라 고친 그림이 달라집니다.

## 이번 범위 밖

포털로 그림을 가져오거나 검사·저장하는 일, 포털 흐름의 판본을 바꾸는 일, 매핑 파일을 고치는 일, 처리 건 실행(다음 실습).

## 완료 조건

- `코드/output/cooling.bpmn`을 다시 열면 승인·거절·지연 알림 갈래가 모두 끝 이벤트에 닿고, 거절 갈래에 냉각 명령이 없습니다.
- `코드/output/연결검사_기록.md`에 경로별 예상·실제, 기준과의 차이마다 판정과 조치, 저장·다시 열기 확인이 있습니다.
- 고친 곳마다 무엇을 보고 고쳤는지 근거가 있고, 찾지 않은 문제를 만들어 고치지 않았습니다.
