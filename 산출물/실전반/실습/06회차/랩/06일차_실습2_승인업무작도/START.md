# 정비 요청의 승인·반려 흐름 그리기

실습1의 정비 요청 흐름에 승인 여부 갈림을 붙여, 요청 확인 뒤 승인 종료와 반려 종료로 나뉘는 승인 업무 흐름을 그립니다. 이 흐름을 읽는 사람이 누가 무엇을 결정하고 각 결정이 어느 끝으로 가는지 그림만 보고 알 수 있어야 합니다.

## 출발점

- `코드/input/`: 실습1에서 저장한 `basics.bpmn`을 복사해 둡니다. 실습1 결과가 없으면 실습1의 작업 순서대로 시작·요청 확인·끝을 먼저 그립니다.
- `코드/output/`: 이번 결과를 저장할 자리입니다. 지금은 비어 있습니다.
- [코드/review.md](코드/review.md): 경로별 확인 기록의 제공 빈 틀입니다.
- 편집기: demo.bpmn.io

## 이번에 할 것

- 시작 이벤트 이름을 「정비 요청」으로 하고, 「요청 확인」 사용자 작업 뒤에 배타 게이트웨이 「승인 여부」를 놓습니다.
- 게이트웨이에서 나가는 두 선에 「승인」·「반려」 이름을 붙이고 각각 별도의 끝 이벤트(승인 종료·반려 종료)로 잇습니다.
- 시작에서 각 끝까지 경로를 하나씩 따라가며 Event·Task·Gateway와 각 경로의 연결을 확인합니다.
- `코드/output/approval.bpmn`으로 저장하고 다시 엽니다.

## 작업 순서

1. `코드/input/basics.bpmn`을 편집기에서 엽니다. 원본은 고치지 않고 결과는 새 파일로 저장합니다.
2. 요청 확인 뒤에 배타 게이트웨이를 놓습니다. 가위표 표식(배타)인지, 더하기 표식(병렬)이 아닌지 봅니다.
3. 두 갈래를 각자의 끝 이벤트로 잇고 선과 끝에 이름을 붙입니다.
4. 시작 → 요청 확인 → 승인 여부 → 승인 종료, 같은 방식으로 반려 종료까지 따라가며 `코드/review.md`에 경로마다 시작·결정·끝을 적습니다.
5. 끊긴 선, 작업을 건너뛰는 선, 끝에 닿지 않는 갈래가 있으면 고칩니다.
6. `코드/output/approval.bpmn`으로 저장하고 편집기에서 다시 열어 두 경로가 그대로인지 확인합니다.

## 기대 결과를 먼저 적을 사례 종류

그리기 전에 `코드/review.md`의 「예상」 칸을 경로마다 먼저 적습니다.

- 승인 경로: 지나는 요소와 닿는 끝
- 반려 경로: 지나는 요소와 닿는 끝
- 저장한 XML에서 게이트웨이가 나가는 선 몇 개를 갖는지

## 학생이 정할 것

> 요청을 확인하는 사람이 결정을 내리는 곳(사용자 작업)과 흐름이 갈라지는 곳(게이트웨이)을 어떻게 이름 붙일지 정합니다. 게이트웨이 이름을 질문으로 쓸지(예: 승인했는가?) 결정 이름으로 쓸지 고르고, 그림을 처음 보는 사람이 결정 주체를 헷갈리지 않는 쪽을 택한 이유를 `코드/review.md`에 적습니다.

## 이번 범위 밖

설비 이상 대응·역할 레인(다음 실습), 선의 실행 조건과 기한 값, 포털로 흐름을 보내는 일. 선에 「승인」이라고 이름을 붙인 것만으로 실행 조건이 생기지는 않습니다.

## 완료 조건

- `코드/output/approval.bpmn`을 다시 열면 배타 게이트웨이 하나와 끝 이벤트 둘이 있고, 두 갈래가 각자의 끝에 닿습니다.
- 끊긴 선이나 이름 없는 갈래가 없습니다.
- `코드/review.md`에 두 경로의 예상과 실제가 있습니다.

## 저장과 다음 실습

`코드/output/approval.bpmn`과 `코드/review.md`를 저장하고 다시 열어 확인하세요. 보관할 결과는 재부팅 전에 USB 또는 개인 클라우드에 복사하세요. 다음 실습에서는 이 승인 구조를 설비 이상 대응의 역할 레인에 배치합니다.
