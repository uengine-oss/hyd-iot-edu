# 내 BPMN과 포털에 등록된 기준 흐름의 실행 연결 비교하기

bpmn.io에서 직접 그린 설비 대응 흐름을 포털에 등록된 기준 흐름과 견주고, 내가 그린 작업마다 어떤 실행 기능에 대응하는지 표시한 **실행 연결 대응표**를 만듭니다. 이 표를 읽는 사람이 그림 파일에 있는 것과 실행 정의에만 있는 것(조건·기한·담당)을 구분해 말할 수 있어야 합니다.

여기서 「포털에 등록된 기준 흐름」은 수업용으로 미리 등록해 둔 시나리오 A 흐름 「냉각 긴급 대응」과 그 제공 매핑입니다. 포털의 다른 화면에서 「기준 흐름」이라고 부르는 것(아무 수업 흐름도 쓰지 않을 때 경보를 받는 원래 흐름)과는 다른 것입니다. 이번 실습에서는 내 그림을 포털에 올리지 않습니다.

## 출발점

- `코드/input/`: 실습4에서 저장한 `cooling.bpmn`, `condition-plan.md`, `element-map.md`를 복사해 둡니다. 비교 대상은 내 그림이므로 제공 기준 BPMN을 내 그림 대신 쓰지 않습니다.
- [코드/source/reference/cooling-emergency.bpmn](코드/source/reference/cooling-emergency.bpmn): 제공 기준 BPMN입니다(그림 파일).
- [코드/source/reference/mapping.json](코드/source/reference/mapping.json): 제공 매핑입니다. 시작 조건(`start`), 작업마다 붙는 실행 기능·담당(`tasks`), 갈림 조건(`flows`), 기한(`timers`)이 있습니다. 두 파일의 설명은 [코드/source/reference/README.md](코드/source/reference/README.md)에 있습니다.
- 포털: 「승인과 실행」 화면의 「업무 흐름」 그림, 「처리 건」 화면에서 「냉각 긴급 대응」 처리 건을 열었을 때 보이는 흐름 이름·판본·단계. 보이는 화면에서만 적습니다.
- [코드/output/실행연결_대응표.md](코드/output/실행연결_대응표.md): 결과를 적는 제공 빈 틀입니다.

제공 매핑의 실행 기능은 부품 값으로 적혀 있습니다. 포털에서 보이는 이름은 다음과 같습니다(저장소 `students/flows/README.md`).

| 부품 값 | 포털에서 보이는 이름 |
|---|---|
| `task:decide` | 판단 · 제안 (에이전트 한 번) |
| `task:select-or-reject` | 조치 카드 승인 · 거절 |
| `task:command` | PLC 명령 발행 |
| `task:reobserve` | 재관측 |
| `task:work-order` | 정비 작업지시 |
| `svc:report` | 결과 보고 |

## 이번에 할 것

- 내 그림과 기준 흐름의 작업·갈림·끝·레인을 나란히 놓고 같은 것, 다른 것, 한쪽에만 있는 것을 찾습니다.
- 제공 매핑에서 시작 이벤트·에이전트 단계·운전원 승인·설비 명령·재관측 작업의 연결을 찾아 키와 값을 적습니다.
- 내가 그린 작업마다 대응하는 실행 기능(부품)과 담당을 표시합니다. 대응하지 않거나 다르게 대응하는 것도 그대로 적습니다.
- 갈림 조건·승인 지연 기한·담당이 그림 파일에 있는지, 실행 정의(매핑)에만 있는지 구분합니다.

## 작업 순서

1. `코드/input/cooling.bpmn`을 편집기에서 열고, 내 요소 ID·이름·종류·레인을 대응표의 「작업별 대응」 왼쪽 칸에 옮깁니다.
2. 매핑을 열기 전에 작업마다 어떤 실행 기능이 붙을지 「예상」 칸에 적습니다.
3. 제공 기준 BPMN을 편집기에서 열고, 포털에서 기준 흐름의 이름·판본·단계를 확인해 「비교한 대상」에 적습니다.
4. 제공 매핑에서 다섯 연결을 찾아 적고, 내 작업마다 대응하는 기준 요소 ID·실행 기능·담당을 채웁니다.
5. 예상과 다른 곳은 근거(파일·키·화면)를 적고 「대응 판정」을 정합니다.
6. 그림 파일과 실행 정의를 구분하는 표를 채운 뒤 저장하고 다시 열어 확인합니다.

## 기대 결과를 먼저 적을 사례 종류

- 이름은 같지만 레인이나 종류가 다른 작업
- 내 그림에만 있는 작업 또는 갈림, 기준 흐름에만 있는 작업 또는 갈림
- 선에 「승인」이라고 이름을 붙인 갈림: 그 조건이 어디에 있는지
- 운전원 승인: 그림의 레인 이름과 매핑의 역할이 각각 무엇을 정하는지

## 학생이 정할 것

> 내 작업 하나가 기준 흐름의 작업 둘에 걸치거나 딱 맞는 작업이 없을 때 「대응함 · 다르게 대응 · 대응 없음」 중 무엇으로 표시할지 정합니다. 고른 표시와 근거(어느 키·어느 요소를 보고 판단했는지)를 대응표에 적습니다. 표시에 따라 다음 실습에서 고칠 곳이 달라집니다.

- 다섯 연결(시작 이벤트·에이전트·운전원 승인·설비 명령·재관측)의 매핑 키와 값이 있습니다.
