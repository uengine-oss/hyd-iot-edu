# 실전반 7회차 실습 3 — 재고보충작도

> [진행 — 낭독하지 않음] 문서 작성 완료. 실제 실습·학생 코드·AI·HYD 실행과 캡처는 미수행. 수업에서 직접 확인한 결과만 기록한다.

## 다운로드와 정비 그림 이어 쓰기

정기 점검에서 사용한 승인 구조를 재고 보충에 적용하겠습니다. 발주와 입고는 서로 다른 작업으로 남깁니다. 실습 자료를 받아 압축을 풀고 START.md를 열어 과제를 확인하겠습니다.

> [준비 · 비낭독] 재고보충작도 ZIP을 내려받아 압축을 풀고 START.md를 열겠습니다. input의 정기 점검 완성 그림 pm-planning.bpmn을 demo.bpmn.io에서 엽니다. 앞 실습에서 직접 그린 그림이 있으면 그것으로 시작해도 됩니다. source/spare-purchase.bpmn은 내 그림을 저장한 뒤 견줄 수업 흐름의 그림입니다. 그리기 전에 승인·거절·무응답·발주 뒤 입고 전의 경로를 output/element-map.md에 먼저 적습니다.

## 구매 업무의 앞뒤 작업 구성

시작을 재고 부족 메시지 이벤트로, 제안을 발주안 제안으로, 사용자 작업을 구매 담당 승인으로 바꾸겠습니다. 승인 블록과 비중단형 지연 알림은 유지하되 이 업무에도 같은 승인 정책이 맞는지 확인합니다.

승인 뒤에는 ERP 발주·공급사 통지, 입고·재고 반영, 입고 완료 보고를 차례로 놓겠습니다. 거절은 발주로 이어지지 않고 반려 보고와 거절 종료로 보냅니다. 발주 등록과 실제 입고는 별개이므로 작업도 나누겠습니다. 이 수업 시스템은 즉시 입고 기능을 쓰지만 실제 공급사 거래나 배송을 수행하는 것은 아닙니다. ERP와 재고 기능이 HYD 시뮬레이션이라는 범위를 그림에 텍스트 주석으로 적고, 주석을 찾지 못하면 element-map.md의 범위 메모에 적겠습니다.

## 조건·역할·저장 확인

먼저 내 그림을 output/spare-purchase.bpmn으로 저장하고 다시 열어 연결과 종류를 확인합니다. 그다음 수업 흐름 그림의 작업7개, 승인 게이트웨이1개, 정상·거절·알림 끝 이벤트3개와 대조합니다. 승인 대기가 알림으로 취소되지 않는지, 거절에서 발주로 가는 길이 없는지, 발주 다음 입고와 보고까지 연결됐는지 선을 따라 보겠습니다. 구매 담당자 레인과 에이전트·시스템 레인의 책임도 읽습니다.

실제 누락이나 잘못된 선이 있으면 고치고 승인·거절·지연의 세 경로를 다시 확인한 뒤 같은 파일로 다시 저장합니다. output/element-map.md에 내 요소 ID와 수업 흐름의 요소, 발주와 통지를 묶을지 나눌지 정한 이유를 적겠습니다. 다음 실습에서는 준비된 재고 보충 시나리오 C를 실행해 이 그림의 작업과 실제 발주·입고 기록을 짝지어 보겠습니다.
