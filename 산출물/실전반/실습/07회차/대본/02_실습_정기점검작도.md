# 실전반 7회차 실습 1 — 정기점검작도

> [진행 — 낭독하지 않음] 문서 작성 완료. 실제 실습·학생 코드·AI·HYD 실행과 캡처는 미수행. 수업에서 직접 확인한 결과만 기록한다.

## 다운로드와 앞 흐름 열기

앞 승인 구조를 정기 점검 업무에 적용하겠습니다. 설비 명령 대신 정비 오더와 생산팀 공지로 이어지는 차이를 반영합니다. 실습 자료를 받아 압축을 풀고 START.md를 열어 과제를 확인하겠습니다.

> [준비 · 비낭독] 정기점검작도 ZIP을 내려받아 압축을 풀고 START.md를 열겠습니다. input의 냉각 대응 완성 그림 cooling-emergency.bpmn을 브라우저의 demo.bpmn.io에서 엽니다. 앞 회차에 직접 그린 그림이 있으면 그것으로 시작해도 됩니다. source/pm-planning.bpmn은 내 그림을 저장한 뒤 견줄 수업 흐름의 그림입니다. 완성본을 결과로 복사하지 않고 앞 그림에서 정비 업무를 직접 만들겠습니다. 그리기 전에 승인·거절·무응답·알림 뒤 승인의 경로가 어느 끝에 닿아야 하는지 output/element-map.md에 먼저 적습니다.

## 승인 블록을 새 업무에 맞추기

담당자·에이전트·시스템 레인을 유지하고 메시지 시작 이벤트를 정기 점검 도래로, 제안 작업을 정비 계획 제안으로, 사용자 작업을 설비보전팀장 승인으로 바꾸겠습니다. 냉각 명령과 재관측·유온 갈림은 정비 오더 등록·생산팀 공지와 결과 보고 흐름으로 바꿉니다. 오더 등록과 공지를 한 작업으로 묶을지 두 작업으로 나눌지는 제가 정하고 그 이유를 element-map.md에 남기겠습니다. 수업 흐름은 한 서비스 작업으로 묶었습니다.

승인 작업 뒤에는 승인 여부 게이트웨이를 두겠습니다. 승인은 정비 오더와 공지, 정상 보고와 종료로 잇고, 거절은 반려 보고와 별도 종료로 연결합니다. 승인 작업의 경계 타이머는 비중단형으로 두고 지연 알림과 알림 종료로 연결하겠습니다. 알림이 끝나도 사람의 승인 작업은 남아 있어야 합니다. 기한 10분과 분기 조건 값은 그림이 아니라 연결 값에 있습니다. 수업 흐름의 값은 source의 매핑 파일에서 읽기만 합니다.

## 그림과 저장 파일 확인

먼저 내 그림을 output/pm-planning.bpmn으로 저장하고 편집기에서 다시 열어 레인·종류·선이 유지되는지 보겠습니다. 그다음 수업 흐름의 그림을 열어 작업6개, 승인 게이트웨이1개, 정상·거절·알림 끝 이벤트3개와 대조합니다. 요소 수만 맞추지 않고 각 선의 방향과 끝, 타이머가 붙은 작업도 읽겠습니다. 거절 경로에서 오더로 가는 선이 없는지 확인합니다. 단순 표시 이름을 바꿔도 ID가 자동으로 바뀐다고 가정하지 않고, output/element-map.md에 직접 만든 요소 ID와 수업 흐름의 요소, 같음·의도한 차이·빠짐을 적겠습니다.

어긋난 연결이나 종류가 있으면 해당 항목을 고친 뒤 승인·거절·지연 경로를 다시 따라가고, 같은 파일로 다시 저장해 열어 보겠습니다. 없는 속성 패널을 찾느라 진행을 멈추지 않고, 편집기가 제공하는 기능과 XML의 종류·참조를 함께 확인합니다. 다음 실습에서는 준비된 정기 점검 시나리오 B를 실행해 이 그림의 작업과 실제 기록을 짝지어 보겠습니다.
