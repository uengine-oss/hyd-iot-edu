실전반 8회차 · 교대 인수인계

여러 출처를 대조한 인계안을 만들고 두 사람이 검토하여 다음 교대가 이어 확인할 일을 남깁니다.

학생 시작본 · 화면 사진은 포함하지 않습니다. 실제 결과는 자기 처리 건에서 확인하고 저장합니다.

보충 문서 · 제공 BPMN · 연결 기준 · 저장 항목

1. 시작과 업무 범위

교대 담당자의 미완료 업무·재고와 입고 예정·모순을 구분하고 다음 확인 행동을 정합니다. 대상 설비, 인계할 교대, 실제 기준시각, 전달받은 작업 메모를 자기 말로 정리합니다. 수업 중 실제 대상과 시각을 사용하며 예시 시각을 현재 값으로 복사하지 않습니다. 앞 실습 결과가 없어도 제공 보충 문서와 기존 시스템으로 시작할 수 있습니다. 포털 왼쪽 「수업 기능」이 「교대 실습」 상태인지 확인합니다. 코드가 없거나 거절되면 강사에게 확인하고 잠금을 우회하지 않습니다.

2. 보충 문서 추가 적재

「매뉴얼 → 지식화」에서 source/inspection-manual.md를 선택합니다. 기존 쿨러·정비·구매 매뉴얼 목록과 배치를 먼저 기록합니다. 같은 보충 문서가 이미 적재되어 있으면 해당 판본과 원문을 확인해 재사용하고 재추출하지 않습니다. 새 문서라면 미리보기→에이전트 추출→원문과 절·단계·근거 대조→검토한 항목만 적재합니다. HI-01의 세 절차는 참고용이며 설비를 직접 실행하는 조치가 아닙니다. 불완전하거나 실패한 제안을 적재하지 않고 같은 처리 건의 오류·응답을 보존해 보완합니다. 추가 뒤 기존 세 문서의 배치가 그대로인지 확인합니다.

3. 자기 에이전트와 스킬

「에이전트」에서 교대에 필요한 짧은 검토 스킬과 에이전트를 만듭니다. 목표와 확인할 출처·완료 기준을 먼저 설명하고 코딩 도우미의 제안은 원자료에 대조합니다. 업무 규칙은 「교대 인수인계」, 모델은 수업 기본값, 도구는 설비 지식·업무 자료·설비 이력의 조회 범위에서 선택합니다. 설비, 열린 작업지시, 현재 재고/입고 예정, 작업 메모의 네 영역을 확인해야 합니다. 메모의 완료 주장과 열린 작업지시의 모순, 조회 결과 없음과 출처 오류를 구별하는 기준을 직접 작성합니다. 수업 에이전트에게 질문할 수 있습니다. 도구 서버 관리·다른 모델 선택·임의 쓰기 기능은 열리지 않습니다.

4. BPMN과 포털 연결

source/handover.bpmn을 bpmn.io에서 열어 초안→인계자 검토→인수자 확인/보완→완료와 세 번의 초안 범위를 확인합니다. 표시 이름과 그림 배치는 바꿀 수 있으며 작업·연결·승인 조건을 추가하거나 제거하지 않습니다. 포털 「흐름」에서 이 파일을 가져옵니다. 흐름 ID는 제공 파일의 ShiftHandover를 유지합니다. source/mapping.json을 대조해 시작 입력 네 개와 각 작업의 부품·사람 역할·분기 조건을 연결합니다. 인계안 작성·보완 1·보완 2의 세 에이전트 칸에는 3단계에서 만든 자기 에이전트를 모두 배정합니다. 「검사」의 누락을 고친 뒤 「판본 등록」을 합니다. 기본 A/B/C의 매핑이나 배포는 바꾸지 않습니다. 임의 코드가 자동으로 포털 작업에 연결되는 것은 아닙니다.

5. 같은 처리 건에서 검토와 보완

등록한 교대 판본을 시작하고 네 입력을 채웁니다. 포털의 「나」를 인계자 김운전으로 선택해 실제 초안·조회 근거를 검토합니다. 자료가 없거나 모순이면 미확인과 다음 확인 행동을 남깁니다. 승인 후 「나」를 인수자 최운전으로 바꾸어 근거와 남은 요청을 대조합니다. 보완할 사실이 있으면 사유를 적어 같은 건을 돌려보내고 보완된 초안과 인계자 재검토를 확인합니다. 처음부터 맞은 결과에 고의 오류를 넣지 않습니다. 인수 확인은 인계 기록만 남긴다는 확인을 한 뒤 제출합니다. 처리 건의 종료 상태와 미확인 항목을 확인하며 인수 확인을 정비 완료로 바꾸지 않습니다.

6. 실패 복구와 저장

AI가 질문/권한 요청/실패로 멈추면 처리 건 ID·작업 ID·질문·호출 기록·원천 응답을 보존합니다. 새 건을 반복 시작하거나 DB/컨테이너를 지우지 말고 원인을 강사와 확인해 같은 건의 보완/재시도를 사용합니다. 통신 실패를 업무 없음으로 쓰지 않습니다. 완료 후 output에 적재 판본, 에이전트, 흐름 판본과 처리 건 ID, 조회 기준시각/근거, 사람 검토, 보완 사유, 완료·미확인 구분을 저장합니다. 다시 열어 각 주장으로부터 원문·조회 결과로 돌아갈 수 있어야 합니다.
