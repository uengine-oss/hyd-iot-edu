## 실습별로 늘어지는 위치와 편집 판단

### 학습노트

- §1에서 빈 페이지를 이미 만든 뒤 “빈 페이지를 만들기 전에”라고 돌아가므로 순서가 어색하다.
- Notion에 쓴 설명을 VS Code 입력틀에도 옮기고, 수정 후 다시 양쪽에 반영한다. 이중 기록 자체는 학습 목표가 아니다. 제출 원본을 한 곳으로 두고 필요한 대목만 AI에 전달하면 된다.
- 첫 기록은 두세 문장이다. ‘자기 설명15분’은 자료 대조와 질문을 포함하더라도 근거 없이 넓게 잡았다. 초안·근거 비교·필요한 수정은 유지하고 문답을 위한 문답은 빼야 한다.
- 출처 연결과 마지막 재검색은 서로 다른 검증이므로 유지한다. 다만 링크가 있다는 것과 검토 가능한 것의 차이를 매번 새 강의처럼 반복하지 않는다.

### 실행환경

- 서비스 역할을 읽을 때 AI가 “무엇부터 읽을지” 질문하도록 하고, 상태 확인 뒤 다시 이미 적은 근거를 묻게 한다. 필요한 질문일 수 있으나 두 번 모두 필수인 것은 아니다. 이해가 막힌 한 항목이나 실제 관측의 불일치에서 대화한다.
- 도구·엔진·서비스 구분은 핵심이다. 역할 읽기→기대 상태→관측→판정 한 흐름으로 연결하고, 매 단계 ‘아직 전체 성공은 아니다’를 길게 되풀이하지 않는다.
- 설치·복구·이미지 다운로드는 기존 견적에서도 별도였다. 이것으로45분을 사후 정당화할 수 없다.
- 해당 판본의 실제 기동 명령·프로필이 대본에 구체화되지 않고 문서 참조로 남아 있다. 이 실습은 시간 과다뿐 아니라 강사가 즉시 수행할 수 있는 구체성도 부족하다. 오래 배정했다고 완성도가 높아지는 것은 아니다.

## 적용할 운영 원칙

1. 다운로드·압축 해제·VS Code 열기는 매 실습 실제 절차로 유지한다. 처음에는 의미를 설명하고 이후에는 해당 자료와 위치를 확인하며 자연스럽게 진행한다. 매번5분을 채우지 않는다.

3. 힌트는 관찰·비교 질문으로 유지한다. 질문을 추가했다는 이유만으로 시간을 일괄 증액하지 않는다.
4. 강사의 기본 진행, 필요할 때의 오류 분기, 학생의 별도 반복 연습 시간을 구분한다.
5. 설명하면서 클릭·입력하는 구간은 둘 중 하나의 실제 구간으로 센다. 발화 시간에 모든 조작 시간을 그대로 더하지 않는다.
6. 먼저 해야 할 일의 수와 중복을 정리한다. 근거가 부족한205분을 근거로 과제 이관이나 회차 분할부터 결정하지 않는다.

시간과 흐름에 대한 판정을 바로잡고 최신 인계에 남겼다. 기존 대본·PDF·가이드의205분 표기는 이전 견적으로 취급한다. 이번 검토에서는 강의 본문을 임의로 삭제하거나 PPTX를 재조립하지 않았다. 위 반복·역순·기동 구체성 문제는 발견 사항이며, 수정 완료로 보고하지 않는다. 직접 실습 금지 조건을 유지한다.
