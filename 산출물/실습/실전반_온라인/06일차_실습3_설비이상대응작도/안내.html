실전반 6회차 실습 3 — 설비이상대응작도

[진행 — 낭독하지 않음] 강사 단독 진행용 대본이다. 아래 조작은 수업에서 수행할 절차이며 이번 제작에서 실행·접속·캡처하지 않았다. 예상 결과를 실제 결과처럼 읽지 않는다. 오류가 나면 실제 사유와 수정·재확인을 남긴다.

자료와 참조 흐름 준비

앞 승인 흐름에 냉각 경보의 진단·명령·재관측을 연결하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

[준비 · 비낭독] 설비이상대응작도 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. source/reference의 흐름은 제공된 참조이며 이번에 만든 결과가 아닙니다. 앞 실습의 approval.bpmn을 input에 복사하고 편집기에서 열겠습니다. 원본을 보존하고 cooling-draft.bpmn으로 따로 저장한 뒤 기존 승인 구조에 역할과 작업을 보태겠습니다.

역할별 Lane과 주요 작업 작성

풀 하나를 만들고 담당자, 에이전트, 시스템의 세 레인으로 나누겠습니다. 풀을 세 개 만드는 것이 아닙니다. 에이전트 레인에 메시지 시작 이벤트 ‘쿨러 성능 저하 경보’와 표식 없는 작업 ‘원인 진단·냉각 조치 제안’을 놓겠습니다. 담당자 레인에는 ‘운전원 승인’ 사용자 작업을 놓습니다. 에이전트라는 별도 BPMN 표준 작업이 있는 것은 아니며 실제 에이전트는 나중에 연결합니다.

시스템 레인에는 냉각 명령, 재관측, 작업지시 등록, 정상 보고를 서비스 작업으로 놓겠습니다. 경보에서 진단과 제안, 승인, 명령, 재관측, 작업지시, 보고, 끝 순서로 연결하겠습니다. 레인을 가로지르더라도 같은 풀 안의 순서는 시퀀스 흐름입니다.

이 기본 경로에서 추천안만으로 명령으로 가지 않고 승인 작업을 거치는지 보겠습니다. 재관측을 두는 것은 명령 처리와 실제 회복이 서로 다른 확인이기 때문입니다. 작업지시 등록은 핀 세척의 실제 완료를 뜻하지 않으므로 보고와 구별하겠습니다.

저장과 다음 설계 준비

output/cooling-draft.bpmn으로 저장하고 다시 열겠습니다. 참조 파일의 작업 이름과 책임을 대조하되 완성본으로 바꿔치기하지 않겠습니다. 직접 만든 요소 ID와 역할을 element-map.md에 적습니다. 지금 파일은 기본 경로 초안입니다. 다음 실습에서 거절·미달·지연을 추가한 뒤 실행 연결로 넘기겠습니다.
