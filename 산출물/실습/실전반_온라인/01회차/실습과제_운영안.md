## 고정 범위와 변경 이유

- 실전반 응용은 성공 기록에 더해 실패·누락·미확인, 관찰 근거, 다음 확인 담당을 남기는 데 둔다. 실패를 만들려고 실제 서비스를 임의로 망가뜨리지 않는다. 실패 자료를 의도적으로 구성하면 교육용 변형 자료라고 표시하고 실제 실행과 구별한다.
- 코드가 필요하지 않은 Notion·관계 그림 활동에 코드 작성을 억지로 추가하지 않는다. 바이브 코딩은 기록 검토·구조화·오류 수정이 필요한 단계에 사용하며, AI에게 완성본 전체를 한 번에 맡기지 않는다.

## 공통 입력과 완료 조건

강사가 먼저 동일한 판본의 시작 자료·완성 자료·실행 기록을 묶는다. 자료별로 원본 위치, 판본 또는 해시, 대상 설비, 관측 구간, 준비 확인자를 적는다. 동일 사건임을 원본 참조로 증명할 수 없는 기록들을 한 사건으로 합치지 않는다.

온라인 학생에게 모델 키를 주지 않는다. AI 호출이 필요한 구간은 저장된 실제 요청·응답·도구 결과를 사용한다. 아직 그 실행의 원본이 확보되지 않았다면 해당 구간은 **준비 대기**다. 사실표에 적힌 값이나 교재 캡처만으로 실행 기록 묶음이 완성됐다고 간주하지 않는다. 학생의 추가 대화는 선택 가능한 학습 보조로 두고, 키 없이도 제공된 실제 기록과 로컬 자료로 필수 결과를 검토할 수 있어야 한다.

결과 상태는 다음과 같이 쓴다.

| 상태 | 판단 기준 |
|---|---|
| 성공 | 요구한 결과가 존재하고 원본·실행·참조로 검증했으며 필수 검사가 모두 통과함 |
| 실패 | 수행했고, 확인 가능한 결과가 명시된 성공 기준을 충족하지 못함 |
| 미확인 | 수행 여부나 판정에 필요한 기록·권한·관측이 부족해 결론을 낼 수 없음 |
| 준비 대기 | 시작 자료·환경·실행 원본·완성본 중 필수 준비가 아직 끝나지 않음 |

학습 활동을 충실히 수행했다는 평가와 시스템 실행의 성공은 따로 기록한다. 증거 누락을 정확히 찾아 미확인으로 남긴 제출물은 검토 활동을 잘 수행한 것일 수 있다. 확인하지 못한 시스템을 성공으로 바꾸지는 않는다.

## 실습 시간 견적

아래는 강사가 조작·설명하며 온라인 학생이 완성 결과를 확인하는 수업 구간의 **설계 견적**이다. 학생 개별 따라 하기, 신규 설치·가입·복구, 제작자의 개발·촬영 작업 시간은 별도다. 실제 측정값이 아니며 실행·리허설 뒤 다시 기록한다. 앞 이론에 포함한 실습 간지·설명은 중복 계산하지 않는다. 실습의 설명 단계는 실제 입력·시작 상태·성공 기준을 확인하는 데 쓴다.

최신 구간 분류와 시간표는 [1회차 시간견적](../01회차_시간견적.md)을 따른다. 학습노트50분·실행환경45분·전체과정55분·관계그림55분, 합205분이다. 아래 단계 설명의 기존 세부 분량은 활동 내용 참고이며 최신 시간표와 중복 합산하지 않는다.

Notion 50분은 기준서 60-1의 고정 조건이다. 나머지 초과 견적은 최신 근거 추적·두 원인 확장·오류 리뷰를 포함한 결과다. 이론이 초과하거나 남는 시간을 자동으로 실습에서 빼거나 더하지 않는다. 개발 완료 전 이 수치를 실행 보장 시간으로 안내하지 않는다.

**응용 과제:** 같은 형식으로 이번 회차의 낯선 개념 하나를 추가하되, 자신이 틀리거나 모호하게 쓴 문장 하나의 수정 이유를 남긴다. 이는 수업 뒤 과제이며 위 50분에 합산하지 않는다.

**리뷰 8분:** 하나라도 다른 결과가 있으면 로그의 해당 서비스·시각을 확인해 원인 후보를 좁힌다. 버전 번호만 출력된 것을 엔진 실행 성공으로 보거나, 종료된 준비 작업을 무조건 실패로 보지 않는다. 아직 재현하지 않은 오류는 오류 예시라고 꾸미지 않는다.

**완성본 확인 6분:** 검증된 완성 환경에서 같은 체크 항목을 다시 확인하고 시작 환경과의 차이를 설명한다. 외부 호스트 작업자 등 Compose 밖의 의존성도 다음 실습의 요구 조건에 맞춰 확인한다.

**성공:** 해당 판본·프로필의 필수 서비스와 준비 작업이 각자의 기대 상태를 만족하고 주요 서비스·포털에 접속할 수 있음. **실패:** 기동·접속을 시도한 뒤 필수 항목의 실패를 확인함. **미확인:** 로그 또는 대상 환경에 접근하지 못했거나 실행 구성이 불명확함. 「전부 Up」이나 특정 서비스 개수만으로 성공 처리하지 않는다.

**응용 과제:** 제공된 실제 실패 로그가 있다면 실패 지점을 한 곳 고르고, 근거·가설·추가로 확인할 항목을 적는다. 실물이 없으면 제작 준비 대기로 남기며 임의로 실패를 주입하지 않는다.

## 10행 · 설비 이상 발생부터 판단·승인·조치까지 전체 과정 경험하기

**준비물:** 동일 쿨러 사건의 저장된 실제 실행, 승인 전후 상태·명령·응답·재관측·작업지시 원문, 판단의 원인 증거, 참조가 보이는 발췌 묶음, 빈 연결표와 검증된 완성표. 고정 교재의 숫자와 다른 실행을 쓰면 서로 다른 실행임을 명시하고 한 사건처럼 섞지 않는다.

**설명 4분:** 사건을 앞에서 뒤로 관찰한 뒤 작업지시에서 거꾸로 근거를 찾는 두 활동을 안내한다. 온라인 필수 경로는 키 없는 저장 실행 확인이다. 강사의 새 실행은 준비 환경에서 먼저 검증하고 기록한 뒤 사용한다.

**행위 12분:** 경보→추천→승인→명령→ACK→재관측→작업지시를 관찰한다. 이어 작업지시의 판단 참조, 판단의 사건 참조, 사건의 경보 참조를 각각 열어 연결표에 적는다. 기록 이름만 옮기지 않고 실제 참조 필드·값과 도착 기록의 식별자를 대조한다. 판단의 구간 평균과 경보 당시 순간값을 따로 적는다.

**리뷰 8분:** 승인 전 명령 없음은 제공 기록의 범위와 시각을 확인해 판단한다. 팬 속도가 그대로라는 사실만으로 결론 내리지 않는다. ACK 완료, 유온 완화, 핀 세척 완료는 서로 다른 판정이다. 작업지시가 등록된 상태를 정비 완료로 바꾸지 않는다. 참조가 없으면 미확인으로 남긴다.

**완성본 확인 6분:** 저장된 완료 기록과 완성 연결표를 같은 참조로 다시 따라가며 조치의 이유를 설명한다. 기록 재열기·대조가 이 구간의 결과 확인이며 새 설비 명령 실행이라고 부르지 않는다.

**성공:** 필수 세 참조가 같은 사건 안에서 확인되고 경보값·진단 증거·명령 처리·완화·정비 잔여 상태를 구분함. **실패:** 다른 사건을 이어 붙였거나 기록과 다른 판정을 씀. **미확인:** 필요한 참조나 관측이 원본에 없거나 발췌 묶음이 불완전함.

**응용 과제:** 완성 연결표에서 근거가 되는 참조 한 곳을 가렸을 때 어디까지 말할 수 있는지 비교한다. 이는 의도적으로 일부를 가린 학습 자료임을 표시한다. 실제 시스템이 참조를 누락했다고 주장하지 않는다. 확인할 원본과 다음 확인 담당을 적는다.

## 12행 · 설비 이상과 원인·조치의 관계를 시각화하기

**준비물:** 대상 목록, HM-8.1·8.4·8.5·8.7의 읽을 수 있는 원문, 기본 그림 편집 파일, 두 원인 확장 완성 파일, 관계의 의미·방향 확인표. 현재 arrows.app 화면과 저장·다시 열기는 제작 단계에서 실제 확인한다.

**설명 5분:** 처음에는 핀 오염 관계도를 만들고, 같은 고장 유형을 유지한 채 팬 구동 불량 가지를 더한다고 안내한다. 관계 그림은 스키마 검증이나 새 진단 실행의 완료본이 아니다.

**행위 23분:** 설비·구성 요소·센서·증상·고장 유형·원인·증거·조치를 연결한다. 이름과 방향을 붙이고 원문 절을 남긴다. 핀 오염에는 CE 최근 30초 평균 < 70 %, VS1 최근 2분 평균 < 0.9 mm/s를, 팬 구동 불량에는 VS1 최근 2분 평균 ≥ 0.9 mm/s를 대조한다. 핀 세척과 팬 점검의 문서 근거를 구별한다. HM-8.1의 순간값 문장과 HM-8.4의 진단용 구간 평균 기준을 섞지 않는다.

**리뷰 10분:** 각 화살표를 문장으로 읽고 양 끝 대상의 종류와 원문까지 확인한다. 문장이 자연스럽다는 것만으로 통과시키지 않는다. 저장 방향과 거슬러 찾는 방향도 구별한다. 팬 구동 불량 가지는 다른 실제 고장 실행을 뜻하지 않는다. 앞 사건의 낮은 진동 평균을 그 가지의 발생 증거로 쓰지 않는다.

**완성본 확인 7분:** 편집 가능한 파일과 이미지로 저장하고 다시 열어 두 원인의 증거와 조치를 각각 찾는다. 다음 회차의 스키마 입력으로 넘길 대상·관계·출처가 보존됐는지 확인한다. 화면 캡처만 남겨 편집 결과를 잃지 않게 한다.

**성공:** 공통 고장 유형, 두 원인, 각 증거·조치·출처가 구별되고 이름·방향·사실이 일치하며 파일을 다시 열 수 있음. **실패:** 팬 구동 불량을 핀 세척으로 직접 연결하거나 화살표 뜻을 뒤집음. **미확인:** 원문이나 편집 파일을 열 수 없어 비교하지 못함.

**응용 과제:** 자신의 그림에서 한 관계의 이름·방향·종류·출처를 설명하고, 잘못된 연결 하나를 수정한 전후와 이유를 남긴다. 실제로 처음부터 맞았다면 오류를 겪었다고 꾸미지 말고 명시적인 오류 예제를 검토한다.
