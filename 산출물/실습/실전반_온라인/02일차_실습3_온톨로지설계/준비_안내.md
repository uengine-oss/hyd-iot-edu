# 온톨로지 설계 입력

자료 폴더의 현장 원자료에서 출발한다. 완성 스키마나 그래프는 제공하지 않는다. 결과/schema.json과 결과/graph.json을 직접 만든다. 예제 그래프의 공통 구성 모델과 달리 이번 질문은 실제 개별 설비의 센서를 구별하므로 구성 요소·센서 ID에 설비 코드를 포함한다. 예비품은 SKU로 공유한다.

질문: 설비별 구성 요소의 센서는 무엇인가? 센서가 읽는 물리량·단위·한계는 무엇인가? 여러 설비가 공유하는 교체 부품은 무엇인가? 공급 조건은 별도 확장을 위한 원자료로 보존하며 이번 세 질문의 필수 산출물은 아니다.

graph.json은 nodes:[{labels:[종류],props:{id:고유값,...}}], rels:[{type:관계,a:출발id,b:도착id,props:{...}}]로 작성한다. HAS_COMPONENT, MONITORED_BY, OBSERVES, USES_PART의 방향과 끝점은 스키마에 명시한다. 종류·필수 속성·형·단위·허용값·카디널리티를 정의한다.

TS1 중복, 별칭, 숫자·단위가 섞인 값, 누락 단위는 현장 메모와 대조하고 처리 근거를 기록한다. 근거 없는 값을 채우지 않는다.
