실전반 6회차 실습 6 — 사전검사와배포

[진행 — 낭독하지 않음] 강사 단독 진행용 대본이다. 아래 조작은 수업에서 수행할 절차이며 이번 제작에서 실행·접속·캡처하지 않았다. 예상 결과를 실제 결과처럼 읽지 않는다. 오류가 나면 실제 사유와 수정·재확인을 남긴다.

자료와 정상 초안 보존

사전검사와배포 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. 앞 실습의 BPMN과 mapping.json을 input에 복사합니다. 포털에서도 같은 흐름 ID의 초안을 열고 현재 연결을 저장하겠습니다. 오류 사례는 배포하지 않은 별도 연습 초안에서 확인합니다.

누락 검사와 수정

먼저 연습 초안에서 냉각 명령 작업의 부품 선택을 비우고 사전 검사를 요청하겠습니다. 검사 결과에서 해당 작업과 part 항목, 부품을 고르라는 사유가 잡히는지 보겠습니다. 실제로 표시된 문구를 review.md에 적고 PLC 명령 부품을 복원해 다시 검사합니다. 예상한 오류가 나오지 않으면 성공한 실패 시연으로 처리하지 않고 현재 설정과 검사의 범위를 확인합니다.

다음에는 승인 분기의 조건을 비우고 기본 경로 표시도 없는 상태로 검사하겠습니다. 해당 선의 condition 누락 사유를 확인하고 승인 결과가 승인과 같다는 조건을 복원합니다. 선의 표시 이름을 ‘승인’으로 쓴 것만으로 조건이 생기지 않는다는 점을 여기서 확인합니다. 한 항목씩 바꾸고 복원해야 어떤 수정으로 문제가 사라졌는지 알 수 있습니다.

정상 초안으로 돌아와 모든 작업·조건·타이머와 담당을 검사하겠습니다. 경고나 오류가 남으면 위치와 사유를 읽고 고칩니다. 정적 검사 통과는 실제 서비스 호출 성공을 보장하지 않으므로 다음 실습의 확인을 남겨 둡니다.

판본 등록과 배포 확인

검사한 정상 초안을 판본 등록하겠습니다. 반환된 정의 ID와 판본을 deployment-record.md에 적고 등록만으로 경보 경로가 바뀌지 않았는지 확인합니다. 업무 프로세스 화면에서 그 정의와 판본을 선택해 배포하겠습니다. 공용 환경이라면 다른 작업자의 경보 경로를 바꾸지 않도록 수업의 전용 환경과 배포 순서를 확인한 뒤 진행합니다.

경보와 흐름 대응 화면에서 쿨러 경보가 내 정의와 판본을 가리키는지 다시 보겠습니다. 내보낸 BPMN·매핑, 검사 결과와 배포 기록을 저장합니다. 이미 진행 중인 처리 건은 열릴 때의 판본을 사용하므로 새 배포와 섞어 읽지 않겠습니다. 다음에는 새 이벤트로 열린 처리 건의 기록을 확인합니다.
