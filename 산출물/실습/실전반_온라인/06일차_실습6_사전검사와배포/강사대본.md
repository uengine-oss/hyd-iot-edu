# 실전반 6회차 실습 6 — 사전검사와배포

> [진행 — 낭독하지 않음] 강사 단독 진행용 대본이다. 아래 조작은 수업에서 수행할 절차이며 이번 제작에서 실행·접속·캡처하지 않았다. 예상 결과를 실제 결과처럼 읽지 않는다. 오류가 나면 실제 사유와 수정·재확인을 남긴다.

## 자료와 정상 초안 보존

앞에서 연결한 흐름을 검사하고, 수정한 판본이 경보를 받을 대상으로 배포됐는지 확인하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 사전검사와배포 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. 앞 실습의 BPMN과 mapping.json을 input에 복사합니다. 포털에서도 같은 흐름 ID의 초안을 열고 현재 연결을 저장하겠습니다. 지금 작성한 초안을 검사하며 실제로 발견한 문제만 수정하겠습니다.

## 누락 검사와 수정

사전 검사를 요청하고 반환된 작업·선의 위치와 field, reason을 현재 BPMN과 매핑에 대조하겠습니다. 부품 관련 문제가 실제로 있으면 그 작업의 ID와 part 값, 교육 환경의 부품 목록을 확인합니다. 냉각 명령 작업에는 PLC 명령 부품이 맞는지 보고 잘못된 연결이나 누락을 고친 뒤 저장하고 다시 검사합니다. 실제 문구와 수정 이유는 review.md에 적겠습니다.

분기 조건에 관한 문제가 있으면 해당 선의 condition과 기본 경로 표시를 읽겠습니다. 승인 선은 승인 결과가 승인과 같다는 조건인지, 반대 선은 기본 경로인지 확인합니다. 선의 표시 이름을 ‘승인’으로 쓴 것만으로 조건이 생기지는 않습니다. 실제로 잘못된 항목을 하나씩 고쳐 재검사하고 어느 수정으로 문제가 해소됐는지 기록하겠습니다.

현재 초안의 모든 작업·조건·타이머와 담당을 검사하겠습니다. 경고나 오류가 남으면 위치와 사유를 읽고 고칩니다. 문제가 없으면 정상 설정을 비우지 않고 확인한 검사 범위와 응답을 남깁니다. 정적 검사 통과는 실제 서비스 호출 성공을 보장하지 않으므로 다음 실습의 확인을 남겨 둡니다.

## 판본 등록과 배포 확인

검사한 정상 초안을 판본 등록하겠습니다. 반환된 정의 ID와 판본을 deployment-record.md에 적고 등록만으로 경보 경로가 바뀌지 않았는지 확인합니다. 업무 프로세스 화면에서 그 정의와 판본을 선택해 배포하겠습니다. 공용 환경이라면 다른 작업자의 경보 경로를 바꾸지 않도록 수업의 전용 환경과 배포 순서를 확인한 뒤 진행합니다.

경보와 흐름 대응 화면에서 쿨러 경보가 내 정의와 판본을 가리키는지 다시 보겠습니다. 내보낸 BPMN·매핑, 검사 결과와 배포 기록을 저장하고 VS Code와 포털에서 다시 열어 정의 ID와 판본·경보 경로를 대조하겠습니다. 이미 진행 중인 처리 건은 열릴 때의 판본을 사용하므로 새 배포와 섞어 읽지 않겠습니다. 다음에는 새 이벤트로 열린 처리 건의 기록을 확인합니다.
