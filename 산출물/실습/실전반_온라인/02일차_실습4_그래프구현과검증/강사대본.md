# 실전반 2회차 실습 4 — 그래프 구현과 검증

> 강사 단독 진행. 전용 랩 DB만 사용한다. 명령 결과를 보기 전 성공 발화를 하지 않는다. 이번 제작에서는 코드·DB·실습·캡처를 실행하지 않았다.

## 구현 자료와 설계 결과 열기

앞에서 설계한 모델을 그래프에 옮기고, 현장 자료로 정한 질문에 같은 답이 나오는지 확인하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

> [준비 · 비낭독] 구현 자료를 내려받아 압축을 풀고 VS Code에서 폴더를 열겠습니다. 앞 실습에서 만든 스키마와 예시 데이터를 입력 폴더에 복사합니다. 요구사항과 검토표도 함께 열어 두겠습니다. 저장할 내용과 확인할 기준을 같은 자리에서 보려는 겁니다.

> [조작] 실습4 ZIP 다운로드 → 압축 해제 → VS Code 폴더 열기. 실습3의 결과를 입력/에 복사한다. 제공된 랩 DB 주소와 대상 DB를 확인한다. 예제 조회 DB 또는 HYD 기준 DB에 덮어쓰지 않고, 준비된 별도 실습 DB를 사용한다. 전체 노드 삭제 명령은 사용하지 않는다.

## Cypher를 만들고 읽기

먼저 각 클래스의 식별자에 유일 제약을 두고, 식별자로 노드를 찾거나 만들도록 하겠습니다. 바뀔 수 있는 이름과 값은 SET으로 넣습니다. 관계는 양 끝 노드를 먼저 찾고 스키마의 방향으로 잇겠습니다.

> [입력 — Copilot] 입력의 schema.json과 graph.json을 읽고 적재.cypher와 조회.cypher를 작성해 주세요. 현재 설계에 있는 레이블·관계만 사용하고 식별자로 MERGE, 속성은 SET으로 나눠 주세요. 관계는 양 끝 ID를 먼저 MATCH하세요. 삭제문과 HYD 기준 DB 변경은 넣지 마세요. 노드·관계 누락, 중복 ID, 필수값, 자료형, 허용값, 관계 끝점과 카디널리티를 확인할 검토 방법도 작성해 주세요. 원자료 세 질문의 조회를 포함해 주세요.

생성된 질의를 실행하기 전에 읽겠습니다. 식별자와 이름을 함께 MERGE 조건에 넣지는 않았는지, 없는 끝점을 찾는 관계는 없는지 확인합니다. 무엇을 만들지 설명할 수 있는 상태에서 실행하겠습니다.

## 적재 뒤 질문의 답을 확인하기

> [조작] 대상 DB를 다시 확인하고 제약·노드·관계 순서로 적재한다. 각 단계의 오류와 생성 개수를 기록한다. 조회.cypher로 질문 세 개에 답하고 원자료 예상 답과 대조한다. 실패하면 해당 문장과 원인을 확인해 수정한 뒤 필요한 부분만 다시 실행한다.

실행 완료 표시는 요청이 끝났다는 뜻입니다. 찾을 노드가 없어서 관계가 하나도 만들어지지 않았을 수도 있습니다. 그래서 센서 목록과 교체 부품 목록을 직접 조회하고, 원자료에서 기대한 식별자와 비교하겠습니다.

같은 적재를 다시 적용했을 때에도 서로 다른 대상 수와 연결 수가 늘지 않는지 확인하겠습니다. 이름만 같은 노드를 세지 않고, 식별자와 관계의 양 끝을 기준으로 대조합니다.

## 형태는 맞지만 뜻이 틀린 연결 찾기

센서가 연결됐다는 사실만으로 맞는 모델이라고 판단할 수는 없습니다. 앞에서 남긴 원자료 검토표로 돌아가 설비별 센서 태그, 계측 대상, 단위를 실제 조회 결과와 대조하겠습니다. 다른 설비에도 같은 태그가 있으므로 설비 식별자를 함께 보겠습니다.

> [조작] 기존 graph.json과 원자료를 보존한다. 설비별 센서·상태 변수·교체 부품의 예상 답과 실제 조회를 검증_기록.md에 대응시킨다. 실제 잘못된 끝점이 있으면 근거를 찾아 수정하고 해당 질의와 기존 세 질문을 다시 확인한다. 정상 관계를 일부러 바꾸는 오류 사본은 만들지 않는다.

뜻이 다른 연결을 찾았다면 어디에서 섞였는지 원자료의 대상 구분과 적재 매핑을 확인하겠습니다. 차이가 없다면 대조한 범위를 기록하고 저장하겠습니다.

## 결과와 남은 점 저장하기

정의와 실제 저장 결과를 맞췄는지 검토표를 읽겠습니다. 자료형이나 카디널리티는 DB가 모두 대신 검사해 주는 것이 아니므로 따로 확인한 근거를 남깁니다. 미확인 항목이 있다면 완료로 바꾸지 않겠습니다.

> [조작] 적재·조회 질의, 원자료 대비 결과, 반복 적재 비교, 오류 수정 전후, 미확인 사항을 저장한다. 파일을 다시 열어 확인한다. 접속 인증값은 산출물에 넣지 않는다.

이제 설계 파일에서 저장된 그래프까지 같은 대상과 연결을 따라갈 수 있습니다. 조회 결과와 검토 기록이 있어야 다른 사람이 이 모델을 이어서 확인할 수 있습니다.
