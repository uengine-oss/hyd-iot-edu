# 1회차 제공 틀과 직접 만드는 범위

강사가 혼자 진행하는 실습이다. 자료 다운로드부터 시작하되 매번 도구·프로젝트를 전부 새로 만드는 활동으로 확대하지 않는다. 목표·입력·수정 범위·판정 기준을 고정하고, 의미 있는 판단과 작은 구현을 직접 보여 준다. 직접 실습은 하지 않고 이 문서와 대본으로 설계한다.

## 제공과 직접 작성의 경계

| 실습 | 처음 제공하는 틀 | 강사가 직접 결정·작성할 것 | 처음부터 주지 않을 것 | 끝날 때 확인할 것 |
|---|---|---|---|---|
| 학습노트 | 영역3개·속성4개·빈 기록 양식·참고 교재 범위 | 자기 설명1건, 출처, 이해도 판단, 수정 이유, 보기 구성 | 완성된 개념 설명·AI가 채운 전체 노트 | 같은 기록 다시 찾기, 출처 연결, 설명의 근거 |
| 실행환경 | 판본·기대/관측/근거/판정 확인표와 역할 구분 | 해당 구성에 맞는 기대 상태, 관측 근거, 미확인 범위 | 전부 정상이라는 결론·환경을 통째로 고치는 요청 | 설치/엔진/서비스/접속의 구별, 일회성 작업 판정 |
| 전체과정·기록 추적 | 실제 발췌1개·가림 자료1개, 입출력 코드, 빈 함수1개, 반환 계약, 검사4개 | 비교할 필드 선정, 값 없음/다름/같음 기준, 함수 구현·변경 검토, 결과 해석 | 함수 완성 코드·가짜 AI 응답·없는 직접 참조 | 동일 사건 근거, 누락/불일치 구별, 수정 범위 유지 |
| 관계그림 | 대상 종류·두 원인 범위·출처 위치·빈 관계표 | 실제 이름·관계 뜻과 방향·증거 구간·조치·수정 이유 | 완성된 관계도·원인별 관계 정답 전부 | 대상 종류/방향/출처, 두 원인 차이, 편집 결과 보존 |

## 기록 추적 랩의 구체적인 크기

- 시작 작업 공간: `시작코드/` 하나. 완성 `코드/` 폴더를 함께 열거나 AI에 첨부하지 않는다.
- 수정 대상: `trace_records.py`의 `check_link` 함수 **1개**. 읽기·저장·전체 흐름 집계는 제공한다.
- 설계할 분기: **3개**. 실제 참조가 없는 경우, 값이 다른 경우, 값이 같은 경우. 빈 문자열을 어떤 범주로 볼지도 설명한다.
- 입력: **2개**. 실제 기록 발췌와 참조를 하나 가린 교육용 자료. 수정하지 않는다.
- 확인: 기존 **4개 검사**와 두 입력 결과 비교. 테스트를 고쳐 통과시키거나 전체 사건 성공으로 확대 해석하지 않는다.
- 대화 횟수는 고정하지 않는다. 필요한 판단 단계는 다음과 같다: 입력 구조 탐색 질문 → 찾은 항목과 첫 가설 검토 → 가림 자료에서 첫 기준의 빈틈 질문 → 정리한 기준으로 함수 하나 구현 요청. 실제 오류가 있을 때만 해당 조건을 고치는 대화를 더한다.

이 규모는 파일 입출력과 서버 설정으로 주제가 벗어나는 것을 막으면서, 판단 기준을 코드로 옮기는 경험은 남기기 위한 설계다. 제공 비율을 임의의 퍼센트로 제시하지 않고 수정 파일·함수·입력·검사의 수로 통제한다.

## 도움을 여는 순서

1. **목표와 완료 조건:** 무엇을 만들고 무엇으로 확인하는지 공개한다. 정답 구현은 공개하지 않는다.
2. **입력 탐색 질문:** 어느 필드가 다음 기록을 가리키는지 강사가 자료를 읽으며 답한다.
3. **부분 힌트:** 관찰할 위치나 비교 관점을 질문으로 좁힌다. 정답 필드·분기 순서·판정 규칙을 알려 주지 않는다. 토글에도 자기 관찰을 채우는 요청 예시만 둔다.
4. **상황별 요청 예시:** 현재 자료·강사의 판단·이번 수정 범위를 함께 AI에 전달한다.
5. **완성본 비교:** 구현·결과 검토 뒤 별도로 연다. AI가 시작부터 완성본을 읽고 복제하도록 하지 않는다.

강사 단독 진행이므로 각 단계에서 수강생 답을 기다리지 않는다. 강사가 스스로 질문을 말하고, 자료를 찾아 판단 근거를 설명한다. AI가 해 준 말을 그대로 낭독하는 것으로 판단 과정을 대신하지 않는다.

## 이탈했을 때 돌아오는 기준

| 이탈 | 강사가 할 판단과 다음 요청 |
|---|---|
| AI가 서버·웹 화면·DB까지 만들려 함 | 이번 목표는 로컬 참조 비교 함수 하나라고 다시 한정한다. |
| 입력 식별자를 바꾸려 함 | 기록을 고쳐 맞추는 것은 검증이 아니므로 해당 변경을 제외한다. |
| 테스트 기대값을 바꾸려 함 | 성공 기준을 바꾸지 않고 구현에서 어긋난 조건을 찾는다. |
| 전체 파일을 재작성함 | 변경 비교에서 함수 밖 변경을 확인하고 필요한 부분만 다시 요청한다. |
| 참조가 없는 곳을 추정함 | 미확인으로 남기고 다음에 필요한 원문을 명시한다. |
| 실제 오류가 없는데 실패 시연을 요구함 | 오류 장면을 만들지 않고 준비된 가림 자료의 조건 비교로 진행한다. |

## 시간에 미치는 영향

기록 추적은 다운로드·시작본 열기5분, 사건 흐름7분, 자료 탐색·가설·질문·기준11분, AI와 함수 구현·변경 검토10분, 저장·실행·해석8분, 응용 비교8분, 정리6분으로 **55분 설계**다. AI 응답 지연은 미측정이므로 별도다. 이 견적을 검증하려고 이번에 실제 실습을 수행하지 않는다.

전체는 학습노트50·환경45·기록추적55·관계그림55분으로 **205분**이다. 설명을 줄여 맞추지 않는다. 범위를 더 줄여야 한다면 설명 삭제보다 실습3의 추가 오류 수정이나 관계도 응용을 별도 과제로 분리할지 먼저 검토한다. 현재는 위 범위를 유지한다.


## 2026-10-18 최종 힌트 기준

위 분기 수·범위는 제작 견적용이다. 학생 힌트로 읽지 않는다. 힌트는 관찰→비교→가설의 질문이며 정답이나 알고리즘을 제공하지 않는다. 강사 해설은 탐색과 근거 확인 뒤에 이어진다. 기존 결과 비교는 구현 이후의 검증 자료로 별도 표시한다.
