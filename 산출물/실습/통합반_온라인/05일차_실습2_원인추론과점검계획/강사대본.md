# 통합반 5회차 실습 2 — 원인추론과점검계획

> [제작 안내 — 낭독하지 않음] 강사 단독 시연 대본이다. 실제 조작·AI 응답·실습 실행·접속·캡처는 이번 제작에서 수행하지 않았다. 실제 결과를 확인한 뒤 그 값과 근거를 읽는다. 성공을 미리 낭독하지 않는다.

## 다운로드와 입력 확인

원인추론과점검계획 ZIP을 내려받아 압축을 풀고 VS Code에서 폴더를 열겠습니다. 코드/source에는 공통 온톨로지와 사례 입력, 매뉴얼이 있습니다. 완성 에이전트를 실행하는 대신 이 입력을 읽는 기능을 만들겠습니다. README의 입력 구조를 읽고 graph.json에서 원인·고장 유형·증상·증거의 ID와 관계 방향을 확인합니다. cases.json의 센서 값은 제공된 과거 입력이며 현재 설비 값이 아닙니다.

expected.md에 첫 사례에서 확인할 근거를 먼저 적겠습니다. 원인 후보에 연결된 증거 조건, 필요한 태그, 집계와 시간 창을 찾습니다. 평균과 최댓값·최솟값 차이는 다른 집계입니다. 입력의 신선도와 표본 누락을 확인하지 않고 숫자 하나만 비교하지 않겠습니다.

## 근거를 읽는 기능과 출력 약속 만들기

코딩 도우미에게 이렇게 요청하겠습니다. source의 스키마·그래프·사례를 읽어 원인 후보를 찾고 증거를 평가하는 agent.py를 만들어 주세요. 입력의 실제 필드와 관계 이름을 먼저 확인하세요. 기준은 그래프에서 읽고 코드에 임의 수치를 넣지 마세요. 확인됨·확인 못함·지지 근거 없음의 상태를 구별하고, 근거마다 태그·집계·시간 창·실제 값·기준·출처를 남겨 주세요. 누락·묵은 값·불충분한 표본은 0이나 정상으로 바꾸지 마세요. 여러 후보가 남으면 함께 제시하고 확정 원인이라고 쓰지 마세요.

출력은 output/result.json과 output/inspection.md로 정하겠습니다. 점검 계획에는 원인 후보, 확인할 근거, 확인 순서와 이유, 필요한 사람의 확인을 적게 합니다. 순서는 제공 SOP의 선행 조건과 안전 조건을 먼저 따르고, 자료가 순서를 정하지 않으면 ‘제안’이라고 표시하도록 하겠습니다. 실제 제어나 작업지시는 호출하지 않습니다.

> [조작] 학생 기능은 수업에서 작성한다. 생성 코드의 파일 경로·출력 구조·누락 처리·종료 조건을 읽은 뒤에만 수업 환경에서 실행한다. API가 필요하면 교육용 설정으로 읽고 인증값은 산출물에 남기지 않는다.

## 실행 고리와 결과 대조

기능이 원인 후보 조회, 필요한 증거 읽기, 관찰, 다음 확인의 순서를 기록하도록 요청하겠습니다. 모델을 쓰는 부분과 수치·조건을 계산하는 부분을 나누고, 최대 반복 횟수와 확인 불가 시 종료 조건도 설정합니다. 수업에서는 생성된 실제 인자에 맞춰 사례 하나를 실행하고 expected.md의 근거와 대조하겠습니다. 결과가 다르면 그래프 해석, 센서 집계, 신선도, 문장화 중 어디에서 달라졌는지 확인합니다.

정상 입력 사본에서 필요한 태그 하나를 제거한 경우, 관측 시각이 오래된 경우, 여러 원인에 맞는 증거가 함께 있는 경우를 차례로 만들겠습니다. 한 번에 한 조건을 바꾸고 원본 사례는 보존합니다. 빠진 태그가 보류와 추가 점검으로 이어지는지, 복수 근거에서 하나를 임의로 확정하지 않는지 확인합니다. 점검 순서를 고칠 때도 원문에 없는 조작 단계를 덧붙이지 않겠습니다.

## 저장과 다시 열기

작성한 기능과 입력 사본, 예상 근거, 실제 결과와 수정 기록을 저장하고 다시 열겠습니다. 어느 근거로 후보가 남았고 무엇을 추가로 확인해야 하는지 설명할 수 있는지 보겠습니다. 지금 만든 기능이 실제 고장 원인을 확정하거나 현장 작업을 승인한 것은 아닙니다. 다음에는 품질 접수를 후속 업무로 연결하겠습니다.
