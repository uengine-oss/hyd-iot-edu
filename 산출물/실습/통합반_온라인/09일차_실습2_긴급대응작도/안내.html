통합반 9회차 실습 2 — 긴급대응작도

[진행 — 낭독하지 않음] 강사 단독 진행용이다. 아래는 수업에서 수행할 절차이며 이번 문서 제작에서는 실제 실습·학생 코드/테스트·AI 시연·HYD/DB·브라우저·캡처를 실행하지 않았다. 실제 결과는 수업에서 작성한다.

앞 승인 절차 이어 열기

앞 승인 구조를 냉각 경보 대응으로 확장해 담당 역할과 회복·거절·지연 경로를 구분하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

[준비 · 비낭독] 긴급대응작도 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. 앞에서 만든 approval.bpmn과 요소 대응표를 input에 가져옵니다. 앞 파일을 편집기에서 열고 다른 이름 cooling.bpmn으로 저장해 승인과 반려의 기본 구조를 이어 쓰겠습니다. 코드 폴더 밖 reference의 BPMN과 그림은 저장소의 제공 참조입니다. 이것을 내려받았다는 사실을 제가 작도한 결과로 기록하지 않겠습니다.

역할을 나누고 경보에서 보고까지 잇기

풀 하나를 놓고 담당자, 에이전트, 시스템의 세 레인으로 나누겠습니다. 기존의 사용자 작업은 담당자 레인의 운전원 승인으로 옮기고 승인 여부 게이트웨이를 뒤에 둡니다. 시작 이벤트는 에이전트 레인에 놓고 메시지 시작 이벤트로 바꿔 쿨러 성능 저하 경보라고 이름을 붙이겠습니다. 그다음 표식 없는 작업 하나를 두고 원인 진단·냉각 조치 제안이라고 적어 운전원 승인으로 잇습니다.

승인 갈래는 시스템 레인의 냉각 명령으로 보냅니다. 서비스 작업으로 바꾸고, 이어 재관측과 유온 정상 여부 게이트웨이를 놓겠습니다. 회복된 갈래에는 작업지시 등록과 정상 보고를 차례로 두고 끝에 연결합니다. 회복하지 못한 갈래는 미달 보고를 거쳐 같은 끝으로 보냅니다. 운전원 승인의 거절 갈래는 거절 보고를 거쳐 별도의 거절 종결로 닫겠습니다. 정상, 미달, 거절 보고는 각각 서비스 작업으로 구분하고 이름을 붙입니다.

처음의 승인 절차에는 없던 실행과 효과 확인이 이제 승인 뒤에 들어갔습니다. 반려로 끝나는 선이 냉각 명령 쪽으로 섞이지 않았는지, 작업지시 등록을 실제 정비 완료로 이름 붙이지 않았는지 확인하겠습니다.

승인을 끊지 않는 타이머 붙이기

운전원 승인 테두리에 경계 이벤트를 붙이고 타이머로 바꾸겠습니다. 종류는 비중단형으로 정해 점선 겹테두리인지 봅니다. 타이머에서 승인 지연 알림 서비스 작업으로 선을 잇고, 알림이라는 별도 끝 이벤트로 닫겠습니다. 알림의 끝을 승인 작업의 끝으로 연결하지 않습니다. 알림이 끝나도 사람의 결정은 계속 기다려야 하기 때문입니다.

기한은 업무 시간 10분, 기간 표기로 PT10M입니다. 편집기에 기간 입력이 있으면 같은 값을 넣고, 그림과 별도로 condition-plan.md에도 적겠습니다. HYD 연결에서 이 기간을 다시 확인합니다. 저장한 XML의 경계 이벤트가 운전원 승인 id에 붙어 있고 cancelActivity가 false인지 대조하겠습니다. 실선으로 남았다면 비중단형으로 고치고 다시 저장합니다.

참조와 견주고 다음 입력 저장하기

제공 참조 그림과 나란히 보며 세 레인, 두 갈림, 정상·미달·거절·알림의 경로를 하나씩 따라가겠습니다. 내 요소의 id를 참조 id와 대응표에 적습니다. 이름이 같아도 id는 다를 수 있으므로 참조 매핑을 그대로 붙이지 않겠습니다. 조건표에는 approval이 승인인 선과 recovered가 true인 선, 각각 반대쪽 기본 흐름을 나눠 적습니다. 값 누락을 정상이나 거절로 단정하는 검증 결과는 쓰지 않습니다.

각 선이 실제 요소에 닿고, 알림 뒤에도 승인 작업이 남도록 그려졌는지 확인하겠습니다. 오류를 발견하면 해당 연결만 고치고 네 경로를 다시 봅니다. output/cooling.bpmn과 조건표·요소 대응표를 저장한 뒤 파일을 다시 열어 레인·작업 종류·타이머가 유지되는지 확인합니다. 이 파일들을 다음 실습의 입력으로 넘기겠습니다.
