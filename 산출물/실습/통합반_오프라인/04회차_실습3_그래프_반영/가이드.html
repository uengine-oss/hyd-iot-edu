앞 실습에서 문서의 문장을 출처가 붙은 후보로 뽑았다. 후보는 아직 지식이 아니다. 이번에는 그 후보를 사람이 원문과 대조해 승인하고, 승인한 것만 지난 시간의 그래프에 이어 넣는다. 넣은 뒤에는 고장 유형에서 원인, 조치, 작업 단계를 거쳐 매뉴얼의 절과 문서까지 관계를 따라가 본다. 넣는 문장은 AI가 만들지만, 무엇을 넣을지 정하는 것과 그래프 DB에 넣는 것은 내가 한다.

끝나면 남는 것검토가 적힌 후보.json, 반영.py, 출처까지 이어진 그래프

오늘 하는 일의 순서

손으로 코드를 쓰는 일은 없다. 요청은 대부분 이 가이드에 준비되어 있어 복사해 보낸다. 내가 할 일은 원문과 후보를 나란히 읽어 승인할 것을 정하고, AI가 만든 문장을 읽고, 넣은 결과를 그래프에서 조회하는 것이다.

1읽게 한다후보가 그래프의 무엇에 이어지고 무엇이 남는지 가르게 한다
2검토를 적는다원문과 대조한 것만 승인으로 적는다
3정하고 계획 받기출처를 그래프의 어디에 남길지 내가 정한다
4만들고, 읽고, 넣는다문장을 파일로 받아 읽은 뒤 내가 넣는다
5조회하고 되돌려 준다관계를 따라가 보고, 아쉬운 곳을 말해 고친다

1~5단계와 8단계가 이 다섯 걸음이다. 그 사이에 두 가지를 더 해 본다. 승인하지 않은 후보를 넣어 달라고, 그래프를 비워 달라고 일부러 요청해 보고(6단계), 후보 하나를 더 승인해 다시 넣어도 이미 넣은 것이 둘이 되지 않는지 본다(7단계).

새 노드를 만드는 문장은 이렇게 생겼다. 팬 최대 운전의 2단계다.

MERGE (n:Step {id: 'step:fan-maximum-run/2'}) SET n.order = 2, n.text = '팬 속도를 100 %로 올린다. 100 % 연속 운전은 24시간 이내로 한다.', n.citation = '2. 팬 속도를 100 %로 올린다. 100 % 연속 운전은 24시간 이내로 한다.', n._manual_document = 'HM-8'; MATCH (a:Skill {id: 'skill:fan-maximum-run'}), (b:Step {id: 'step:fan-maximum-run/2'}) MERGE (a)-[r:HAS_STEP]->(b) SET r._manual_document = 'HM-8'; MATCH (a:Step {id: 'step:fan-maximum-run/2'}), (b:ManualSection {id: 'HM-8.5'}) MERGE (a)-[r:REFERS_TO]->(b) SET r._manual_document = 'HM-8';

그래프에 이미 있는 노드는 이렇게 다룬다. 팬 최대 운전 자신이다.

팬 최대 운전 // 그래프에 이미 있는 노드다. 새로 만들지 않고 출처와 단계만 덧붙인다. MATCH (a:Skill {id: 'skill:fan-maximum-run'}), (b:ManualSection {id: 'HM-8.5'}) MERGE (a)-[r:REFERS_TO {citation: '### SOP-COOL-11 팬 최대 운전'}]->(b) SET r._manual_document = 'HM-8';
①

MERGE의 괄호 안에 id만 있는가MERGE (n:Step {id: …})처럼 레이블과 id만 있고 나머지 속성은 SET에 있다. 이래야 같은 문장을 두 번 넣어도 노드가 하나다. CREATE는 파일에 없어야 한다.

②

이미 있는 노드를 새로 만들지 않는가skill:fan-maximum-run과 cause:cooler-fin-fouling을 찾는다. MERGE (n:Skill {id: …})가 아니라 MATCH로만 나오고, name을 SET하는 줄이 없어야 한다.

넣지 않기로 한 것이 없는가cooler-fin-cleaning(쿨러 핀 세척)과 cabinet-ventilation(캐비닛 환기 보강)을 찾는다. 나오지 않아야 한다. DELETE도 찾아본다.
