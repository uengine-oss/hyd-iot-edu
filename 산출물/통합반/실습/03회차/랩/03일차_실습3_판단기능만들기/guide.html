HYD · 실습 가이드

조건표를 읽는 조치 판정·비교 기능 만들기

완성 조건표로 후보별 경고·감점·제외·정보 부족을 판정하고, 허용 후보만 교육용 손실로 비교합니다.

01 시작하기

VS Code에서 이 폴더를 열고 START.md와 입출력_계약.md를 읽으세요.

입력/   이전 단계 완성 조건표(rules.csv)와 SOP 구조(sop.json)
자료/   사례 A~M, 대상 후보, 원문, metrics/의 비교 요청 C01~C14와 손실 식
결과/   이번에 만들 judge.py, result.json, 기대결과.md
check.py   결과 구조 검사

입력/의 조건표가 이번 프로그램의 기준입니다. 고치지 말고 읽기만 합니다.

먼저 AI에게 파일을 바꾸지 말고 입력 형식·조건표의 묶음 방식·결과 형식을 설명하게 하고, 그 설명을 실제 파일과 대조하세요.

02 요구 정하기

이번 실습의 판단 지점: 기대 결과를 원문에서 먼저 적습니다. 코드를 만들기 전에 결과/기대결과.md에 사례 종류마다 하나 이상, 조건표와 원문으로 손으로 구한 판정과 근거를 적으세요. 프로그램 출력을 보고 기대 칸을 채우면 검증이 되지 않습니다.

그다음 AI에게 전달할 요구를 자기 말로 정리합니다.

  • 입력 이름 변환: forecast_ts1_C → forecast_ts1, RUN → RUNNING, workorder → work_order
  • 판정 순서: 적용 대상 → AND 묶음 → 결과 모으기 → 제외·보류·유지
  • 비교: 유지 후보만, 네 손실 + 감점, 동순위, 계산 불가

03 AI와 만들기

구현 전에 계획만 받아 검토하세요. 규칙을 코드에 다시 적는 계획, 첫 일치에서 멈추는 계획, 빈 값을 0으로 바꾸는 계획, 감점을 행마다 더하는 계획이 있으면 계획 단계에서 고칩니다.

  1. 사례 A~M의 판정부터 만들고 실행합니다.
  2. 판정이 기대와 맞으면 C01~C14 비교를 붙이고 C01 손계산과 대조합니다.
  3. 마지막으로 결과 형식과 저장을 맞춥니다.
요청을 정리할 때 볼 항목

만들 결과 / 참고할 자료 / 바꾸지 않을 범위 / 이번 단계의 범위 / 성공을 확인할 사례

04 결과 확인하기

python 결과/judge.py
python check.py

구조 검사는 형식과 계약의 불변식만 봅니다. 판정이 맞는지는 다음 기준으로 원문과 대조하세요.

  • 경계: C03처럼 팬이 정확히 24시간이면 감점이 없고, C04의 24.1시간이면 팬 최대 운전 후보(SOP-COOL-11·12)에만 20만 원 감점이 붙습니다. 부하 감소 후보에는 붙지 않습니다.
  • 복수 조건: 사례 F는 경고·감점·제외가 함께 남습니다. 감점은 조건 행 수와 관계없이 규칙당 한 번입니다.
  • 누락: C13처럼 팬 운전 시간을 모르면 그 값이 필요한 후보만 보류되고, 관련 없는 후보까지 보류되지 않습니다.
  • 모두 제외: 유지 후보가 없는 요청에서는 추천이 비고 이유가 남습니다.
  • 비교: C01 SOP-COOL-12는 지표_정의.md의 손계산(비용 3.86, 생산 33.33, 품질 0, 에너지 0.54)과 같아야 합니다.

기대결과.md의 기대 칸과 실제 출력을 한 줄씩 대조하세요. 다르면 입력(사례·후보), 기대(원문 근거), 실제(출력)를 함께 AI에 주고 원인을 찾게 한 뒤 필요한 부분만 고칩니다. 같은 사례와 이미 맞았던 사례를 다시 실행합니다.

05 저장하기

결과/judge.py, 결과/result.json, 결과/기대결과.md를 저장하고 다시 열어 확인하세요. 보관할 결과는 재부팅 전에 USB 또는 개인 클라우드에 복사합니다.

비교 합계는 교육용 비교값입니다. 실제 HYD 성과 점수와 다르며 순위가 실행 승인을 뜻하지 않습니다.
