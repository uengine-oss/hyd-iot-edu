SOP 구조와 조치 결정표 만들기

조치 원문을 적용 조건·금지 조건·수행 단계·완료 기준으로 나누고, 판단 규칙을 결정표로 만듭니다. 사례 A~M로 경계·복수 조건·누락을 확인합니다.

01 시작하기

VS Code에서 이 폴더를 열고 START.md와 입출력_계약.md를 읽으세요.

입력/   이전 단계 완성 설비 모델(schema.json, graph.json)
자료/   HM-8 매뉴얼, 규칙 발췌, 작업기준, 적용범위, 대상·고장 유형·사례
결과/   이번에 만들 sop.json, rules.csv, 요구사항.md, 사례대조.md
check.py   구조 검사

이전 개인 결과가 없어도 됩니다. 제공 모델의 ID를 그대로 재사용합니다.

02 요구 정하기

먼저 AI에게 파일을 바꾸지 말고 자료/와 입력/을 읽어 SOP 네 개, 규칙 발췌, 두 자료의 절 번호 차이를 설명하게 하세요. 설명은 실제 파일과 대조합니다.

그다음 결과/요구사항.md에 자기 말로 적습니다.

  • 무엇을 만드는가: SOP 네 개의 구조와 판단 규칙의 결정표
  • 어떤 자료를 쓰는가: HM-8 원문과 규칙 발췌
  • 지킬 조건: 원문에 없는 단계·값을 만들지 않는다, 기존 모델 ID를 재사용한다, 자동 추출 프로그램은 만들지 않는다
  • 확인할 사례: 정상·경계·복수 조건·모두 제외·필수값 누락·적용 대상 밖

이번 실습의 판단 지점: "55 ℃ 이상"이 55.0을 포함하는지, 팬 감점이 어느 후보에 붙는지처럼 모호한 경계와 적용 대상은 AI가 아니라 사람이 원문을 읽고 정해 근거 절과 함께 요구사항.md에 적습니다. AI에게는 그 결정을 전달합니다.

03 AI와 만들기

먼저 만들 순서를 계획으로만 받아 검토하세요. 원문에 없는 단계를 넣거나 기존 ID 대신 새 ID를 만들려는 부분이 있으면 계획 단계에서 고칩니다.

  1. SOP-COOL-11 하나의 구조를 먼저 만들고 원문 단계와 한 줄씩 대조합니다. 맞으면 나머지 SOP로 넓힙니다.
  2. 결정표는 규칙 하나씩 만듭니다. 같은 규칙의 비교 두 개는 한 묶음으로 둡니다.
  3. 모든 항목과 행에 원문 근거 칸(출처)을 채우게 요구합니다. 근거를 못 대는 항목은 지우거나 미기재로 둡니다.
요청을 정리할 때 볼 항목

만들 결과 / 참고할 자료 / 사람이 정한 경계·적용 대상 / 바꾸지 않을 범위 / 출처 칸 요구 / 성공을 확인할 사례

04 결과 확인하기

python check.py

구조 검사가 통과한 뒤 사례 A~M를 결정표에 대입해 결과/사례대조.md를 채웁니다. 판단 기준은 다음과 같습니다.

  • 원문이 "55 ℃ 이상"이면 55.0은 포함, "165 bar 미만"이면 165.0은 포함하지 않습니다. "24시간을 넘으면"은 24.0을 포함하지 않습니다.
  • 사례 F처럼 여러 규칙이 함께 맞으면 경고·감점·제외를 모두 남깁니다. 제외됐다고 경고를 지우지 않습니다.
  • 사례 K처럼 값이 빠졌어도 이미 확인된 제외 사유가 있으면 제외하면서 빠진 값을 함께 적습니다. 제외 사유 없이 값이 빠진 사례 H·L은 보류입니다.
  • 사례 M의 작업지시 후보는 원격 모드·팬 시간 규칙의 대상이 아니므로 그 칸이 비어 있어도 보류하지 않습니다.

결과가 예상과 다르면 결정표가 원문과 다른지, 손으로 대입한 예상이 틀렸는지 원문으로 돌아가 확인하세요. 고칠 때는 해당 항목, 원문 문장(기대), 지금 결과(실제)를 함께 AI에 전달하고 그 부분만 고치게 합니다. AI의 완료 메시지는 대조를 대신하지 않습니다.

05 저장하기

결과/sop.json, 결과/rules.csv, 결과/요구사항.md, 결과/사례대조.md를 저장하고 다시 열어 확인하세요. 보관할 결과는 재부팅 전에 USB 또는 개인 클라우드에 복사합니다.
