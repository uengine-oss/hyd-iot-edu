통합반 10회차 실습 4 — 재고보충실행

[진행 — 낭독하지 않음] 문서 작성 완료. 실제 실습·학생 코드·AI·HYD 실행과 캡처는 미수행. 수업에서 직접 확인한 결과만 기록한다.

다운로드와 시작 상태 기록

구매 흐름을 연결하고, 승인 수량과 발주·입고·재고 변화를 같은 처리 건에서 대조하겠습니다. 실습 자료를 받아 압축을 풀고 VS Code에서 작업 공간을 열겠습니다.

[준비 · 비낭독] 재고보충실행 ZIP을 내려받아 압축을 풀고 VS Code에서 코드 폴더를 열겠습니다. 앞 실습의 BPMN과 요소 대응표를 input에 복사합니다. 수업용 포털에서 대상 부품의 현재고·예약·발주 중 수량과 기준 시각을 기록하고, 이미 열린 같은 업무의 처리 건이 있는지도 확인하겠습니다.

구매·입고 기능 연결

작성한 흐름을 가져와 시작 조건을 SPARE_BELOW_MIN으로 정하겠습니다. 제안에는 기존 예비품 구매 에이전트, 승인에는 구매 담당 역할을 연결합니다. source/spare-purchase.mapping.json을 대조하면서 ERP 발주 부품의 공급사 통지 설정과 입고 확인 부품의 바로 입고 처리를 입력하겠습니다. 승인된 부품·수량·공급사가 발주에 전달되는지 설정을 읽습니다.

승인은 approval이 승인인 조건, 거절은 기본 경로로 연결하고 타이머는 비중단형10분으로 둡니다. 정상 보고는 입고 완료, 반려 보고는 발주하지 않음, 지연 보고는 승인 대기로 구분합니다. 내 요소 ID에 맞춘 설정을 output/spare-purchase.mapping.json과 포털에 저장하고 검사 사유를 고친 뒤 정상 정의를 판본 등록·배포하겠습니다.

발주와 입고를 따로 확인

재고 보충 이벤트로 열린 건이 내 정의·판본인지 확인하고 추천 수량·공급사·경고와 현재 재고를 읽겠습니다. 공급사 승인 여부와 금액별 전결 범위, 품질 경고까지 확인하겠습니다. 현재 역할의 권한과 업무 조건이 충족될 때 승인하고, 전결 범위를 넘거나 근거가 부족하면 필요한 승인 절차 또는 보류를 기록합니다. 승인한 경우에는 발주 번호와 수량, 공급사 통지, 입고 번호·수량·검수 기록, 재고 반영과 결과 보고를 각각 확인합니다.

처음의 현재고3개·예약2개·발주 중0개에6개가 입고됐다면 현재고9개, 예약2개, 발주 중0개이므로 보충 판단 수량은7개입니다. 이 숫자를 무조건 기대 결과로 쓰지 않고 실제 시작 값과 승인 수량으로 계산하겠습니다. 발주 중 수량이 먼저 반영되어 보충 필요 표시가 꺼졌더라도 입고가 끝난 것으로 읽지 않습니다. 발주 뒤 입고가 실패했다면 기록을 확인하고 전체를 무조건 다시 실행해 중복 발주하지 않겠습니다.

거절 건과 결과 저장

거절 경로를 확인할 별도 교육용 건은 앞 건의 발주·입고로 바뀐 재고와 섞이지 않도록 시작 상태와 대상을 먼저 확인합니다. 업무상 거절 사유가 있는 건에서 그 근거를 남기겠습니다. 조건을 마련하지 못하면 해당 경로는 미확인으로 두겠습니다. 해당 건에서 발주·통지·입고가 생성되지 않았는지, 반려 종료와 미해결 업무가 기록에 남는지 확인합니다. 다른 건의 재고 변화가 섞였다면 이번 거절의 효과로 단정하지 않고 구분합니다.

기대와 다른 기록은 실제 입력·매핑·승인 내용과 연결해 원인을 찾겠습니다. 고칠 항목이 있으면 이전 결과를 보존하고 설정 수정·저장·재검사를 거쳐 새 판본과 별도 사건으로 재확인합니다. 이미 생성된 발주를 다시 만드는 방식으로 입고 실패를 고치지 않겠습니다.

BPMN·매핑·요소 대응표를 저장한 뒤 다시 열어 포털 설정과 맞추겠습니다. 시작 값, 승인 내용, 발주·입고·처리 건 ID와 판본, 실제 결과와 미확인을 result-review.md에 저장하겠습니다. 파일을 다시 열어 완료 상태와 실제 입고 근거가 연결되는지 봅니다. 공용 환경의 배포 복구는 정해진 범위와 시점에 따르고 임의로 전체 흐름을 내리지 않겠습니다. 이 기록과 교재의 기존 예시를 구별해 전체 업무 흐름 복습으로 돌아갑니다.
