# 준비된 냉각 대응 시나리오 A를 실행하고 처리 이력 확인하기

포털에 준비된 냉각 대응 시나리오 A를 실행해 쿨러 경보로 열린 처리 건 하나를 판단 → 운전원 승인 → 명령 → 재관측 → 보고까지 따라가고, 실제 정의·판본·처리 건·단계 결과를 내가 그린 BPMN의 작업과 이은 **처리 이력 기록표**를 만듭니다. 이 표만 읽고도 처리 건이 어디까지 갔고 무엇이 실제로 이뤄졌는지 구별해 말할 수 있어야 합니다.

## 출발점

- 포털에 시나리오 A 흐름 「냉각 긴급 대응」이 미리 등록돼 있어, 쿨러 경보가 오면 이 흐름으로 처리 건이 열립니다. 내가 흐름을 올리거나 바꾸지 않습니다.
- `코드/input/`: 실습2에서 저장한 `cooling.bpmn`과 실습3의 `실행연결_대응표.md`를 복사해 둡니다. 처리 건의 단계마다 내 그림에서 해당 작업을 찾을 때 씁니다.
- [reference/](reference/README.md): 제공 기준 BPMN과 매핑(요소 ID 대조용).
- [코드/source/제공사례_거절과무응답.md](코드/source/제공사례_거절과무응답.md): 시스템 검증 때 남은 거절·무응답 기록의 요약입니다. 이번 실행 결과가 아닙니다.
- [코드/output/evidence-index.md](코드/output/evidence-index.md): 결과를 적는 제공 빈 틀입니다.

포털에서 쓰는 화면:

| 화면 | 이번에 보는 것 |
|---|---|
| 결함 시뮬레이션 | HYD-01 카드 「A 긴급 대응」의 [쿨러 열화 주입]·[쿨러 복구], 감지기 상태와 명령 결과 |
| 처리 건 | 처리 건 목록과 상세(정의·판본·단계 상태·시각·결과 보고), 「내 차례」의 승인 단계 |
| 이상 확인 · 조치 / 실시간 모니터링 | 경보와 유온 변화, 경보 해제 |
| 승인과 실행 | 업무 흐름 그림, 「기업 시스템 현황」의 작업지시 |

## 이번에 할 것

- [쿨러 열화 주입]을 한 번 눌러 새 경보와 그 경보로 열린 처리 건의 번호·정의·판본을 적습니다.
- 같은 처리 건에서 판단 → 운전원 승인 → 명령 → 재관측 → 보고를 단계 상태와 기록으로 따라갑니다.
- 승인 단계에서 추천안과 근거를 읽고 승인할지 거절할지 직접 결정합니다.
- 명령 처리와 온도 회복, 작업지시 등록과 정비 완료를 각각 다른 근거로 확인합니다.
- 승인 대기·거절·보류를 이번 실제 기록과 제공 사례로 나눠 비교합니다.
- 내가 그린 BPMN에서 각 단계에 해당하는 작업을 찾아 실제 결과와 잇습니다.

## 작업 순서

1. 결함 시뮬레이션 화면에서 HYD-01 감지기가 다음 경보를 기다리는 상태인지 보고 [쿨러 열화 주입]을 한 번 누릅니다. 처리 건이 보이지 않으면 여러 번 누르지 말고 경보와 처리 건 목록을 다시 읽습니다.
2. 처리 건 화면에서 새 처리 건을 열어 경보 번호·처리 건 번호·정의 이름·판본을 기록표에 적습니다.
3. 에이전트 단계가 낸 원인·추천안·판단 번호를 읽고, 승인 단계가 열린 동안 처리 건 상태와 냉각 명령 단계 상태를 적습니다.
4. 「내 차례」에서 [나 고르기]로 운전원 역할의 사람을 고른 뒤, 추천안과 근거를 검토해 [승인] 또는 [거절](사유를 적습니다)을 누릅니다. 결정과 이유를 기록표에 적습니다.
5. 승인했다면 명령 단계와 명령 결과, 재관측의 유온·회복 기준·경보 해제, 작업지시 번호와 상태, 결과 보고를 각각 확인합니다. 거절했다면 명령 단계와 명령 기록이 어떻게 남았는지 확인합니다.
6. 처리 건이 닿은 끝 이벤트와 결과 보고를 적고, 단계마다 내 BPMN의 해당 요소 ID를 찾아 적습니다.
7. 이번에 겪지 않은 상황(거절·보류·승인 지연 알림)은 제공 사례에서 읽어 「제공 사례」 칸에 적습니다.
8. 저장하고 다시 열어 각 결론의 출처를 확인합니다. 거절로 끝났거나 다시 실행할 때는 [쿨러 복구]를 누르고 감지기가 대기 상태가 된 뒤 주입합니다.

## 기대 결과를 먼저 적을 사례 종류

실행 전에 기록표의 각 칸 옆에 예상을 먼저 적습니다.

- 승인 단계가 열린 동안 처리 건 전체와 냉각 명령 단계의 상태
- 승인했을 때: 명령 처리 기록과 유온 회복이 각각 어디에 남는지
- 거절했을 때: 닿는 끝과 명령 기록
- 처리 건이 끝난 뒤 작업지시의 상태
- 승인 지연 알림이 나간 뒤 운전원 승인 단계의 상태(제공 사례와 비교)

## 학생이 정할 것

> 승인 단계에서 추천안을 승인할지 거절할지 정합니다. 추천안의 근거와 지금 설비 조건을 읽고 판단하며, 결정에 따라 이번 처리 건이 지나는 경로와 남는 기록이 달라집니다. 결정과 이유를 기록표에 적습니다.

## 이번 범위 밖

흐름을 포털에 올리거나 판본을 바꾸는 일, 매핑을 고치는 일, 같은 경보를 여러 번 만들어 결과를 맞추는 일, 실제 정비 수행.

## 완료 조건

- 기록표에 처리 건 하나의 경보 번호·처리 건 번호·정의·판본과 판단 → 승인 → 명령 → 재관측 → 보고의 단계 상태·시각·결과가 있습니다(거절했다면 거절 경로의 기록).
- 승인 대기와 끝남을 단계 상태로 구별했고, 명령 처리와 온도 회복, 작업지시 등록과 정비 완료를 서로 다른 근거로 적었습니다.
- 승인 대기·거절·보류가 이번 실제 기록인지 제공 사례인지 구분돼 있습니다.
- 단계마다 내 BPMN의 해당 요소 ID가 있습니다.
