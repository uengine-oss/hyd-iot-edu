> 강사 단독 진행. 조작 메모는 낭독하지 않는다. 이 원고는 실습 DB 준비 이후 자동 연결 창부터 Browser 저장까지의 본편이다. 자료 다운로드·VS Code 준비 화면은 별도 촬영 의존성이며 본편에서 수행했다고 말하지 않는다.

## 앞 이론에서 전체 설비 지도로

앞 이론에서는 노드와 관계를 사이퍼로 표현하는 방법을 배웠습니다. 이번에는 설비의 전체 지도를 먼저 보고, 쿨러가 무엇과 연결돼 있는지 직접 찾아보겠습니다. 그림의 노드와 화살표를 눌러 정보를 읽고, 궁금한 부분을 쿼리로 좁혀 볼 거예요. 마지막에는 전체 연결로 돌아와 확인한 내용과 질의를 저장하겠습니다.

> [forest001 · 조작] 학생 실습 DB 링크의 자동 연결 창. 이전 결과·열린 메뉴 없음.

실습 데이터베이스의 링크를 열면 이렇게 연결 창이 나옵니다. 지금 보고 있는 도구가 네오포제이 브라우저입니다. 프로토콜은 볼트, 연결 주소는 이번 실습에서 안내된 주소입니다. 아래 사용자 이름은 네오포제이이고, 이 실습 데이터베이스는 비밀번호가 없는 상태로 준비했습니다. 값이 맞는지 확인하면서 아래 커넥트를 누르겠습니다.

> [full002 · 조작] 자동 입력된 접속값을 설명하며 가리키고 Connect 클릭. 실제 연결 완료를 기다린다.

왼쪽 위에 연결 주소와 데이터베이스 이름이 나타났습니다. 이제 준비된 데이터를 조회할 수 있습니다. 여기서는 조회 문장을 연습합니다. 새 노드나 관계를 만드는 작업은 뒤의 그래프 구현 실습에서 이어 가겠습니다.

> [full003 · 조작] 실제 연결 주소·DB 이름을 짚는다.

아래에는 도구 소개와 접속 결과가 보입니다. 먼저 화면을 정리할게요. 위쪽 입력칸에 콜론 클리어를 넣고 엔터를 누르겠습니다. 데이터베이스의 내용을 지우는 것이 아니라 화면에 쌓인 카드만 비우는 명령입니다.

> [full004 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

위쪽 스트림 왼편의 패널 버튼으로 도구 목록을 접거나 펼칠 수 있습니다. 한 번 접었다가 다시 열어 볼게요. 왼쪽 맨 위 원통 모양의 데이터베이스 오버뷰를 눌러 준비된 데이터의 종류를 보겠습니다.

> [full005 · 조작] Collapse Sidebar → Open Sidebar → Database overview. 전환을 설명하며 수행한다.

노드는 스무 개, 관계는 열아홉 개가 준비돼 있습니다. 노드 아래의 에셋, 컴포넌트, 센서는 대상의 종류를 구분하는 레이블입니다. 그 아래는 구성 요소를 포함한다, 센서로 계측한다 같은 관계 유형이에요. 오늘 쓸 문장에도 이 이름들이 들어갑니다.

> [full006 · 조작] 실제 노드20·관계19와 레이블·관계 유형을 짚는다.

오른쪽 위 달러 표시 옆이 쿼리 입력칸입니다. 여기에 문장을 넣고 오른쪽 런을 누르면 아래에 결과 카드가 생깁니다. 줄을 바꿀 때는 시프트와 엔터를 함께 누릅니다. 먼저 설비의 전체 연결을 펼쳐 보겠습니다.

> [forest007 · 조작] 입력칸·Run·결과 영역을 짚는다.

## 전체 연결과 노드 속성 읽기

먼저 이번 예제의 전체 연결을 펼치겠습니다. 설비에서 출발해 세 단계까지 이어지는 경로를 피라는 이름으로 받아 그림으로 보는 문장입니다. 별표 뒤의 일 점점 삼이 한 단계부터 세 단계까지라는 뜻이에요. 오늘은 이 지도를 바탕으로 필요한 부분을 하나씩 찾아보겠습니다.

```cypher
MATCH p=(a:Asset {code:'HYD-01'})-[*1..3]->(n)
RETURN p;
```

> [forest008 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

런을 눌러 설비의 전체 연결을 보겠습니다.

> [forest009 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

연결을 넓게 볼 수 있도록 왼쪽 패널과 오른쪽 상세 창을 잠시 접겠습니다. 그래프 아래 배치 메뉴에서 계층형 배치를 고르고, 화면에 맞춤을 누를게요. 데이터는 그대로 두고 위에서 아래로 관계를 읽기 편하게 정리하는 것입니다.

> [forest010 · 조작] 패널 접기 → Select layout → Hierarchical layout → Zoom to fit. 모두 실제 UI로 수행.

맨 위의 에이치와이디 영일이 설비 한 대입니다. 그 아래 쿨러와 팬, 펌프 같은 구성 요소가 있고, 구성 요소에서 센서나 교체 부품으로 갈라집니다. 센서 아래에는 그 센서가 관측하는 물리량이 있네요. 모든 원이 같은 종류의 물건은 아닙니다. 이제 원 하나를 눌러 무엇으로 구분하는지 보겠습니다.

> [forest011 · 조작] 설명하는 노드로 커서를 연속 이동하며 전체 구조를 짚는다.

오른쪽 상세 창을 열고 맨 위 설비 노드를 눌러 보겠습니다. 선택한 대상의 정보는 오른쪽에서 읽습니다.

> [선택 대상] HYD-01 · 실제 확인: asset:hyd-01

> [forest012 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.

애셋은 이 노드의 종류를 나타내는 레이블입니다. 코드에는 에이치와이디 영일, 이름에는 유압 파워팩이 들어 있습니다. 그림의 짧은 이름만 보는 것보다 속성을 함께 확인하면 정확히 어느 설비인지 알 수 있습니다.

> [forest013 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

이번에는 설비에 연결된 오일 쿨러를 눌러 보겠습니다. 같은 원 모양이어도 설비와 쿨러는 역할이 다릅니다.

> [선택 대상] 오일 쿨러 · 실제 확인: comp:cooler

> [forest014 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.

쿨러의 레이블은 컴포넌트이고, 식별자는 컴프 콜론 쿨러입니다. 설비 전체를 뜻하는 애셋과 그 안의 구성 요소를 구분했네요. 지금 확인한 이 식별자를 조건으로 써서 쿨러 하나만 찾아보겠습니다.

> [forest015 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

## 한 노드에서 센서 관계로

전체 지도는 잠시 정리하고 쿨러 한 개부터 직접 조회하겠습니다. 콜론 클리어는 결과 카드를 비우는 명령입니다. 데이터베이스의 노드나 관계를 지우는 것은 아닙니다.

> [forest016 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

매치에는 컴포넌트 중 식별자가 쿨러인 노드를 찾도록 적겠습니다. 씨는 찾은 노드에 붙인 변수이고, 리턴 씨는 그 노드 자체를 보여 달라는 뜻입니다.

```cypher
MATCH (c:Component {id:'comp:cooler'})
RETURN c;
```

> [forest017 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

실행해서 전체 지도에서 보았던 쿨러가 맞는지 확인하겠습니다.

> [forest018 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

쿨러 노드를 눌러 식별자와 이름을 다시 보겠습니다. 결과가 하나라는 것뿐 아니라 찾으려던 대상인지도 확인해야 합니다.

> [선택 대상] 오일 쿨러 · 실제 확인: comp:cooler

> [forest019 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.

식별자와 이름이 앞에서 확인한 값과 같습니다. 화면에 쿨러 하나만 보인다고 실제 연결이 없어진 것은 아닙니다. 이번 문장에서 쿨러 노드만 돌려받았기 때문입니다. 이제 이 쿨러가 어떤 센서로 관측되는지 연결을 포함해 보겠습니다.

> [forest020 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

앞 카드를 비우고 쿨러에서 센서로 이어지는 경로에 집중하겠습니다.

> [forest021 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

왼쪽 씨는 쿨러, 오른쪽 에스는 센서입니다. 가운데 대괄호 안의 모니터드 바이가 관계 유형이고 화살표는 저장된 방향입니다. 리턴에 씨, 알, 에스를 함께 넣어 노드와 관계를 모두 받겠습니다.

```cypher
MATCH (c:Component {id:'comp:cooler'})-[r:MONITORED_BY]->(s:Sensor)
RETURN c,r,s;
```

> [forest022 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

런을 눌러 센서까지 연결해 보겠습니다.

> [forest023 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

쿨러 하나에서 유온 센서와 냉각 효율로 두 갈래가 나옵니다. 오른쪽 개요의 노드 세 개, 관계 두 개와 그림을 비교해 보세요. 같은 쿨러를 두 번 만든 것이 아니라 한 노드가 두 센서와 연결된 모습입니다.

> [forest024 · 조작] 화면에 나온 경로를 짚으며 해석한다.

유온 센서를 눌러 태그와 단위를 확인하겠습니다. 노드를 고르면 오른쪽 내용도 그 대상의 속성으로 바뀝니다.

> [선택 대상] 유온 센서 · 실제 확인: TS1

> [forest025 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.

태그는 티에스원이고 단위는 섭씨입니다. 아이디는 노드를 구별하는 값, 태그는 이 예제에서 센서 채널을 구별하는 값입니다. 버추얼은 거짓으로 표시돼 있습니다. 다음에는 다른 센서와 비교해 볼게요.

> [forest026 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

냉각 효율 노드를 눌러 같은 센서 종류 안에서 속성이 어떻게 다른지 보겠습니다.

> [선택 대상] 냉각 효율 · 실제 확인: sen:ce

> [forest027 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.

이번 태그는 씨이이고 버추얼은 참입니다. 이름에도 가상이라고 적혀 있죠. 이 예제는 계산해서 얻는 항목도 센서 종류로 표현했습니다. 같은 색의 노드라고 측정 방식과 속성값까지 같은 것은 아닙니다.

> [forest028 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

이번에는 노드 사이의 모니터드 바이 화살표를 눌러 보겠습니다. 원의 정보와 선의 정보를 구분해서 읽어 보세요.

> [선택 대상] MONITORED_BY · 실제 확인: Relationship details

> [forest029 · 조작] 관계 화살표를 클릭 → Relationship details 확인.

오른쪽에 관계 정보가 나타났습니다. 모니터드 바이는 쿨러가 센서로 관측된다는 연결입니다. 화살표는 저장된 관계의 방향이고, 데이터가 흐르는 배관 방향을 그린 것은 아닙니다. 노드의 이름, 관계의 유형, 화살표 방향을 함께 읽어야 뜻이 분명해집니다.

> [forest030 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

## 물리량과 조건 탐색

이제 이 센서들이 무엇을 관측하는지 보겠습니다. 앞 카드를 정리하고 설비에서 물리량까지 이어지는 경로로 넓히겠습니다.

> [forest031 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

설비에서 구성 요소로, 구성 요소에서 센서로, 센서에서 물리량으로 이어지는 패턴입니다. 앞에서 읽은 관계를 문장으로 옮긴 셈이죠. 경로 전체를 피에 담아 리턴하면 어떤 물리량이 어느 장치에 속하는지도 함께 볼 수 있습니다.

```cypher
MATCH p=(a:Asset {code:'HYD-01'})-[:HAS_COMPONENT]->(c:Component)
        -[:MONITORED_BY]->(s:Sensor)-[:OBSERVES]->(v:StateVariable)
RETURN p;
```

> [forest032 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

실행해서 센서 아래에 물리량이 어떻게 연결되는지 보겠습니다.

> [forest033 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

센서가 붙은 구성 요소 세 개에서 다섯 개의 관측 경로가 이어집니다. 쿨러의 유온 센서 아래에는 유온, 팬 진동 센서 아래에는 팬 진동이 있습니다. 센서는 관측하는 대상이고 물리량은 무엇을 관측하는지 나타내는 대상입니다.

> [forest034 · 조작] 화면에 나온 경로를 짚으며 해석한다.

유온 노드를 눌러 센서의 속성과 물리량의 속성을 비교하겠습니다. 이번에는 유온 센서가 아니라 그 아래의 유온입니다.

> [선택 대상] 유온 · 실제 확인: sv:ts1

> [forest035 · 조작] 대상 노드로 이동·클릭 → 실제 속성 표시 확인. 결과 설명은 확인 뒤.
