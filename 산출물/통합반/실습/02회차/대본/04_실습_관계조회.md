## 앞 이론에서 전체 설비 지도로

앞 이론에서는 노드와 관계를 사이퍼로 표현하는 방법을 배웠습니다. 이번에는 설비의 전체 지도를 먼저 보고, 쿨러가 무엇과 연결돼 있는지 직접 찾아보겠습니다. 그림의 노드와 화살표를 눌러 정보를 읽고, 궁금한 부분을 쿼리로 좁혀 볼 거예요. 마지막에는 전체 연결로 돌아와 확인한 내용과 질의를 저장하겠습니다.

## 전체 연결과 노드 속성 읽기

위 입력칸에 전체 연결을 찾는 문장을 넣겠습니다. 괄호 안의 에셋은 설비 종류를 고르는 레이블이고, 그 앞의 에이는 찾은 노드를 이 문장에서 가리킬 변수입니다. 코드는 에이치와이디 영일인 설비를 찾습니다. 여기서 한 단계부터 세 단계까지 이어지는 경로를 피에 담아 돌려받겠습니다. 먼저 전체 지도를 보고, 이어서 짧은 문장으로 하나씩 조회해 볼게요.

```cypher
MATCH p=(a:Asset {code:'HYD-01'})-[*1..3]->(n)
RETURN p;
```

런을 눌러 설비의 전체 연결을 보겠습니다.

> [forest009 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

연결을 넓게 볼 수 있도록 왼쪽 패널과 오른쪽 상세 창을 잠시 접겠습니다. 그래프 아래 배치 메뉴에서 계층형 배치를 고르고, 화면에 맞춤을 누를게요. 데이터는 그대로 두고 위에서 아래로 관계를 읽기 편하게 정리하는 것입니다.

> [forest010 · 조작] 패널 접기 → Select layout → Hierarchical layout → Zoom to fit. 모두 실제 UI로 수행.

맨 위의 에이치와이디 영일이 설비 한 대입니다. 그 아래 쿨러와 팬, 펌프 같은 구성 요소가 있고, 구성 요소에서 센서나 교체 부품으로 갈라집니다. 센서 아래에는 그 센서가 관측하는 물리량이 있네요. 모든 원이 같은 종류의 물건은 아닙니다. 이제 원 하나를 눌러 무엇으로 구분하는지 보겠습니다.

> [forest011 · 조작] 설명하는 노드로 커서를 연속 이동하며 전체 구조를 짚는다.

오른쪽 상세 창부터 열겠습니다. 그래프의 빈 곳을 누르고 아래 화면 맞춤을 눌러 전체 위치를 잡을게요. 빈 배경을 끌면 그림 전체를 옮길 수 있고, 노드 위에서 휠을 올리면 확대됩니다. 설비가 잘 보이도록 위치와 크기를 맞춘 다음, 맨 위 설비 노드를 누르겠습니다.

> [선택 대상] HYD-01 · 실제 확인: asset:hyd-01

> [forest012 · 조작] 선택 해제·전체 맞춤 → 대상이 읽히도록 실제 줌·이동 → 노드 클릭·속성 확인. 결과 설명은 확인 뒤.

오른쪽 위에 에셋이라고 표시돼 있죠. 이 노드를 설비 종류로 분류하는 레이블입니다. 그 아래 코드와 이름은 속성 이름이고, 오른쪽의 에이치와이디 영일과 유압 파워팩은 속성값입니다. 그림 안에 보이는 이름과 종류를 구분하는 레이블을 이렇게 상세 창에서 따로 확인할 수 있습니다.

빈 곳을 눌러 설비 선택을 풀겠습니다. 화면 맞춤으로 전체 위치를 다시 보고, 쿨러가 읽기 편하도록 그림을 옮기고 확대할게요. 이제 오일 쿨러를 눌러 설비와 어떤 점이 다른지 보겠습니다.

> [선택 대상] 오일 쿨러 · 실제 확인: comp:cooler

> [forest014 · 조작] 선택 해제·전체 맞춤 → 대상이 읽히도록 실제 줌·이동 → 노드 클릭·속성 확인. 결과 설명은 확인 뒤.

이번 노드의 레이블은 컴포넌트입니다. 구성 요소 종류라는 뜻이고, 이름 속성에는 오일 쿨러가 들어 있습니다. 아이디 속성값은 컴프 콜론 쿨러네요. 이 값을 조회 조건으로 사용해 같은 쿨러를 찾아보겠습니다.

## 한 노드에서 센서 관계로

전체 지도는 잠시 정리하고 쿨러 한 개부터 직접 조회하겠습니다. 콜론 클리어는 결과 카드를 비우는 명령입니다. 데이터베이스의 노드나 관계를 지우는 것은 아닙니다.

> [forest016 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

위 입력칸에 쿨러 한 개를 찾는 문장을 넣겠습니다. 매치 뒤 괄호에서 씨는 찾은 노드를 가리킬 변수, 콜론 뒤 컴포넌트는 찾을 노드의 레이블입니다. 중괄호 안에는 아이디 속성값이 컴프 콜론 쿨러라는 조건을 적었습니다. 리턴 씨는 찾은 노드 자체를 결과로 보여 달라는 뜻입니다.

```cypher
MATCH (c:Component {id:'comp:cooler'})
RETURN c;
```

> [forest017 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

실행해서 전체 지도에서 보았던 쿨러가 맞는지 확인하겠습니다.

> [forest018 · 조작] Run 클릭 → 새 결과 렌더 확인. 다음 발화는 결과 확인 후 시작.

그래프의 빈 곳을 누르고 화면 맞춤으로 위치를 잡겠습니다. 쿨러가 잘 보이도록 크기를 맞춘 뒤 노드를 눌러 볼게요. 오른쪽에서 앞서 본 식별자와 이름을 비교하겠습니다.

> [선택 대상] 오일 쿨러 · 실제 확인: comp:cooler

> [forest019 · 조작] 선택 해제·전체 맞춤 → 대상이 읽히도록 실제 줌·이동 → 노드 클릭·속성 확인. 결과 설명은 확인 뒤.

식별자와 이름이 앞에서 확인한 값과 같습니다. 화면에 쿨러 하나만 보인다고 실제 연결이 없어진 것은 아닙니다. 이번 문장에서 쿨러 노드만 돌려받았기 때문입니다. 이제 이 쿨러가 어떤 센서로 관측되는지 연결을 포함해 보겠습니다.

> [forest020 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

앞 카드를 비우고 쿨러에서 센서로 이어지는 경로에 집중하겠습니다.

> [forest021 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

위 입력칸에 센서까지 이어지는 문장을 넣겠습니다. 왼쪽 괄호의 씨와 오른쪽 괄호의 에스는 각각 노드를 가리키는 변수입니다. 콜론 뒤 컴포넌트와 센서가 노드의 레이블이에요. 가운데 대괄호에서는 알이 관계를 가리키는 변수이고, 모니터드 바이는 관계 유형입니다. 리턴에 씨, 알, 에스를 함께 적으면 양쪽 노드와 그 사이 관계를 모두 볼 수 있습니다.

```cypher
MATCH (c:Component {id:'comp:cooler'})-[r:MONITORED_BY]->(s:Sensor)
RETURN c,r,s;
```

> [forest022 · 조작] 입력할 위치와 작업이 전달된 뒤 문장을 넣는다. 한 글자씩 느리게 입력하지 않는다.

쿨러 하나에서 유온 센서와 냉각 효율로 두 갈래가 나옵니다. 오른쪽 개요의 노드 세 개, 관계 두 개와 그림을 비교해 보세요. 같은 쿨러를 두 번 만든 것이 아니라 한 노드가 두 센서와 연결된 모습입니다.

> [선택 대상] 유온 센서 · 실제 확인: TS1

> [forest025 · 조작] 선택 해제·전체 맞춤 → 대상이 읽히도록 실제 줌·이동 → 노드 클릭·속성 확인. 결과 설명은 확인 뒤.

> [forest028 · 조작] 선택한 노드/관계의 실제 속성을 읽는다.

## 물리량과 조건 탐색

> [forest043 · 조작] 입력칸 선택 → :clear → Enter → 카드 정리 완료 확인 → 입력 비움. DB 데이터는 보존한다.

태그 조건 대신 물리량의 한계가 이즈 낫 널이라는 조건을 넣겠습니다. 널은 영이 아니라 값이 없다는 뜻입니다. 한계가 등록된 센서의 태그와 물리량, 단위, 한계를 받아 보겠습니다.

제목은 설비 연결 탐색으로 적고, 실행한 문장 앞에 확인한 연결과 개수를 주석으로 남기겠습니다. 두 빗금으로 시작하는 줄은 설명용 주석입니다. 그림에서 무엇을 확인했는지도 함께 적어 두면 나중에 다시 읽기 편합니다.

> [forest068 · 조작] 실제로 실행한 문장과 확인 기록을 주석과 함께 입력한다. Ctrl+Home으로 첫 주석 제목을 확인한다.

왼쪽 목록에 설비 연결 탐색이 저장됐습니다. 탭을 닫고 목록에서 다시 열어 문장과 확인 기록이 남아 있는지 보겠습니다.

> [forest069 · 조작] 자동 저장 목록 확인 → 탭 닫기 → 목록에서 다시 열기 → 문장·기록 보존 확인.

문장과 확인 기록이 다시 열렸습니다. 다만 이 목록은 지금 브라우저에 저장된 상태입니다. 학교 컴퓨터는 초기화되므로 파일도 따로 받아야 합니다. 쿼리즈 제목 오른쪽의 내려받기 버튼을 눌러 저장된 문장을 파일로 받겠습니다.

> [full046 · 조작] Download all → 실제 CSV 내려받기 완료 확인.

내려받은 파일은 브라우저의 쿼리 목록을 담은 씨에스브이 파일입니다. 오늘 작성한 문장과 주석이 함께 들어 있습니다. 수업이 끝나면 받은 파일을 개인 저장 공간이나 유에스비로 옮겨 보관합니다. 다음날 이 컴퓨터에 그대로 남아 있다고 생각하면 안 되겠죠.

> [full047 · 조작] CSV의 실제 문장·주석과 원본 일치를 확인. 학교 초기화 후 로컬 보존을 약속하지 않는다.

그림과 질의를 함께 보관하면 연결의 의미와 확인 방법이 남습니다. 학교 컴퓨터가 초기화되기 전에 개인 저장 공간으로 옮겨 두세요. 다음에는 포털의 지식 지도에서 연결을 직접 탐색합니다. 오늘의 파일이 없어도 다음 실습은 제공된 시작 자료로 시작할 수 있습니다.

> [forest072 · 조작] 이번 수행과 다음 포털 탐색의 연결을 마무리한다.
