# .astra — 아스트라 전용 공간

아스트라(gpt-6-astra, Codex)가 이 레포에서 일을 잘 이어 가도록 스스로 세팅하는 곳이다. 무엇을 둘지(기억 노트, 점검 목록, 자기 도구, 요청 틀 등)는 아스트라가 정한다.

- 사용자 지시(2026-10-14): 「스킬이랑 도구를 최대한 활용하게 하고, 아스트라가 알아서 최적화하게. 공간을 하나 지어 주고 거기서 알아서 세팅해 그 세션을 최적화해라. 앞으로 그 세션에서 계속 쓸 거니까 컨텍스트가 요약되어도 상관없다.」
- 공개 저장소다. 키, 사람 이름, 메일, 절대 경로는 두지 않는다.
- 부르는 법은 `만들기/tools/deck/아스트라세션.sh`, 규칙은 `문서/교재/2_기준.md` 45-1번.

## 작업 계약(사용자 확정 — 요약돼도 지킨다)

- 아스트라는 맡은 회차의 덱 원본(MD) · 대본 원본(· 그 회차 figures)을 직접 고친다. 세션은 그것을 받아 빌드(PPTX · 낭독본)하고 검사 · 커밋한다. 다른 회차 · 기준 · 스킬 · 도구 · PPTX는 고치지 않는다. 아스트라에게 회차를 맡길 때는 한 번에 끝까지: 기준대로 덱 · 대본 검증(사실 · 기준 · 흐름) → 원본 직접 수정 → 대본 윤문을 처음부터 끝까지 끊김 없이(새로 넣은 곳과 앞뒤가 매끄럽게) 마친다. 세션은 그대로 받아 빌드한다(사용자 2026-10-16). 4~9회차의 아스트라 윤문 · 검증 · 기준 점검은 지금 하지 않는다. 1~3회차가 확정된 뒤 회차 차례대로 한다(한꺼번에 하면 앞 회차가 바뀔 때 다시 고쳐야 하므로). 견적만 물으면 파일을 고치지 않는다. (`문서/교재/2_기준.md` 45-2번)

- 인제스천(문서 → 지식 추출 · 검토 · 그래프 적재)은 4회차 주제다. 1~3회차 실습 · 설명에 앞당기지 않는다. 실습을 풍부하게 할 때도 억지로 늘리지 않고 어색하지 않은 선에서만 한다(사용자 2026-10-16, 실습 풍부화는 보류 — `문서/교재/6_남은_일.md` 0절).

## 다시 들어왔을 때

1. 최신 사용자 요청과 `state.json`을 읽는다. 사용자 확정, 위임받아 조율한 기준, 아직 검토하지 않은 견적을 구분한다. 여기는 작업 위치를 찾는 안내이며 규칙·사실의 정본은 아니다. 지금 요청이 이전 상태보다 우선한다.
2. `python3 .astra/context.py status --day 1 --kind deck`을 실행한다. 회차는 1~11, 작업은 `design`(압축 설계), `deck`(덱), `polish`(윤문), `script`(대본) 중 고른다. 다음 회차를 임의로 시작하지 않는다.
3. 기준·결정·대상 원고·사실표 중 바뀐 곳과 기억이 불분명한 곳을 원문에서 확인한다. 처음 맡는 회차의 원고·실라버스 상세 내용·관련 사실은 충분히 읽는다. 앞서 확인한 범위가 그대로이고 이해가 유지된 경우 반복해서 전부 출력하지 않는다. 원문 전체 읽기를 명시적으로 요청받으면 그대로 따른다.
4. 적용 스킬을 읽거나, 같은 버전을 이미 읽었으면 필요한 절로 돌아간다. 사용자에게 적용 스킬을 알린다. 여기의 간단한 표로 스킬 본문을 대신하지 않는다.

요약 후에는 해시가 같아도 이해가 사라질 수 있다. `reading.json`은 **어느 버전의 어느 줄을 출력/검토했는지**만 기록한다. 의미를 기억한다고 보증하지 않는다. 잊은 판단은 원문과 코드로 다시 세운다. 바뀐 파일은 기존 범위 기록을 새 버전에 자동 승계하지 않는다. 기준을 해시만 보고 건너뛰지 않는다.

## 최소 작업 도구

```bash
# 재개 상태와 해당 회차의 경로; 파일 본문이나 전체 diff는 자동으로 쏟지 않는다
python3 .astra/context.py status --day 2 --kind design

# 현재/압축 전 장 목록. 제목이 같다고 내용 보존을 판정하지 않는다
python3 .astra/context.py outline --day 1
python3 .astra/context.py outline --day 1 --rev e0311fe

# 필요한 장의 화면·노트·제작 기준을 함께 읽기
python3 .astra/context.py slides --day 1 --numbers 18-21,26
python3 .astra/context.py slides --day 1 --rev e0311fe --numbers 20-23

# 줄 번호가 있는 원문. 한도 뒤의 줄은 읽기 기록에 포함되지 않는다
python3 .astra/context.py read 문서/교재/2_기준.md --start 81 --end 116

# 기존 빌더를 실제 실행하고 입력 지문·결과를 기록한다. PPTX는 쓰지 않는다
python3 .astra/context.py check --day 1
```

`read`·`slides`의 기본 출력 한도는 16,000자다. 제한에 닿으면 다음 줄 번호를 알려 준다. 이어 읽거나 `--limit`를 늘린다. 이것은 토큰 목표가 아니라 출력 잘림을 피하는 장치다. 요약만 읽고 전 문장 검토를 했다고 하지 않는다.

직접 실행도 가능하다:

```bash
.venv-deck/bin/python .claude/skills/lecture-deck/scripts/deck2pptx.py --check 만들기/decks/integrated/day01/통합반_01일차.md
```

`check`는 검사 생략 캐시가 아니다. 항상 위 빌더를 실행한다. `checks.json`은 덱·참조 그림·빌더·아이콘/로고·파이썬 및 패키지 버전의 지문과 결과만 둔다. 이 중 하나가 바뀌거나 검사 도중 수정되면 이전 성공은 유효하지 않다. 자동 검사는 사실·누락·시각 검토를 증명하지 않는다. 렌더 도구와 글꼴의 검증은 별도로 한다. 다른 환경으로 옮기면 명령을 다시 실행한다.

위 경로는 저장소 기준이다. 스킬의 예전 경로나 절 번호가 현재 문서와 어긋나면 실제 파일과 최신 결정으로 해결하고, 필요한 수정만 한다. 새 스킬·패키지·서비스를 습관적으로 늘리지 않는다. 이 공간의 도구는 표준 라이브러리로 움직인다.

네트워크 자료가 도움이 되면 사용한다. 강의에 들어갈 사실은 45-1번·11절의 근거 조건을 따르고, 외부 자료는 공식 출처·확인 날짜·저장소와의 일치 여부를 검토한 뒤 필요한 근거를 남긴다. 외부 검색 결과로 시스템의 실제 값을 추정하지 않는다.

제작 순서의 정본은 `문서/교재/4_만드는_법.md` 2부 0절이다. 상태 파일이나 이전 견적의 단계·장 수를 새 규칙으로 만들지 않는다. 읽은 범위와 이해·실행·청취 검증은 서로 다른 증거다.

제작 파일의 쓰기 권한은 최신 사용자 요청과 `문서/교재/2_기준.md` 45-2번에서 확인한다. 과거 직접 쓰기 GOAL을 지속 권한으로 보지 않는다. 견적은 사용자 결정과 구별하며, `.astra/` 갱신 허용은 제작 파일 수정 허용이 아니다.

## 한 작업을 이어 가는 방식

- 시작: 범위, 수정 전 기준 커밋, 고정 장/승인 그림, 관련 미결을 `state.json`에 적는다. 번호가 바뀌므로 장 번호만 쓰지 않고 제목·경로·버전도 남긴다.
- 압축: 옛 장/정의/용어/값 → 새 화면 또는 노트의 대응을 만든다. 삭제와 의도적인 제외는 이유를 적는다. 실라버스 상세 항목과 사실표의 미반영 내용도 따로 찾는다. 최종 대응은 장의 제작 기준과 `문서/교재/3_현황.md`에 남긴다.
- 작업 중: 독립적인 조회는 묶되, 수정·빌드·렌더·승인은 순서대로 한다. 같은 파일의 작성자는 하나다. 검토 결과는 새 결함과 근거 중심으로 받고, 반복해서 같은 원문 전체를 넘기지 않는다.
- 중단 전: `state.json`에 정확한 다음 행동·바뀐 파일·검사 유효성·남은 불확실성을 적는다. 임시 기록은 `.astra/local/` 또는 `.evidence/`에 둔다. 임시 파일 경로에만 복구를 의존하지 않는다.
- 완료: 필요한 검사와 시각 검토를 하고, 현황/남은 일 및 산출물을 맞춘다. `state.json`은 다음 작업이 오기 전까지 완료 상태로 둔다. 사용자 결정·한계·결과를 보고하고 커밋/push는 하지 않는다.

## 파일과 유지 원칙

- `state.json`: 현재 작업 한 건, 최근 확정 결과의 근거, 다음 행동과 미결. 누적 일지로 만들지 않는다.
- `reading.json`: 출력/이전 검토 범위의 해시. 원문 사본은 없다. 이전 1회차 작업에서 실제로 읽은 자료만 기준 커밋과 함께 초기화했다. 새 회차를 읽은 것으로 미리 표시하지 않는다.
- `checks.json`: 회차별 마지막 자동 검사 한 건. 실패도 성공을 덮어써 낡은 성공이 보이지 않게 한다.
- `context.py`, `test_context.py`: 도구와 회귀 검사. `python3 -m unittest discover -s .astra -p 'test_*.py'`로 검사한다.
- `local/`: Git 제외 임시 공간. 요청문·도구 로그·민감 자료를 공개 파일에 복사하지 않는다.

부르는 세션은 **대상 회차·원하는 결과·바뀐 제약·새 증거**를 주면 된다. 같은 세션 ID를 이어 쓰고, 요약되었다는 이유만으로 새 세션을 만들거나 모든 자료를 재첨부할 필요는 없다. 새 세션이 필요하면 이 README와 상태/원문을 읽어 재개한다. 기존 호출 스크립트는 이 진입점만 짧게 덧붙이고 요청문 자체는 그대로 전달한다. 계정 설정이나 저장소 밖의 Codex 설정은 바꾸지 않는다.
