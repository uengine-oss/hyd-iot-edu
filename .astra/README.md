# .astra — 아스트라 재개 진입점

최신 사용자 요청 → 이 안내와 `state.json` → 필요한 원문 순서로 복구한다. 여기는 현재 작업의 위치를 찾는 곳이며, 기준과 사실의 정본을 대신하지 않는다. 이미 이해한 같은 버전의 자료는 반복 출력하지 않는다.

## 현재 세션과 범위

2026-10-16 새 컨테이너의 세션 `01a142fe-de8a-7282-a2a0-59c7f515a6a7`으로 복구했다. 이전 세션 `01a142cf`의 실행 상태를 이어받지 않는다. ID는 `.evidence/이음매_1회차/로그.txt:10`의 `session id:`와 환경의 세션·스레드 ID로 확인했다.

현재 요청은 **1회차 이음매 재수정 — 제목 없이 본문만 들어도 이어지는 강의 흐름**이다. 직전 반영본(1회차 대본 커밋 `93d5a09`)에서 출발해 기준 5·5-1·7·49·97-1번과 14절에 따라 01~78장을 처음부터 끝까지 다시 읽고 원본을 직접 고쳤다. 수정 뒤 전체 통독과 새 문장·앞뒤의 추가 윤문을 마쳤다.

수정은 대본 **33개 장 묶음**이다. 학습목표·목차, 다섯 단원과 네 실습, 복습·용어 정리·퀴즈·정답 확인의 자리를 본문에서 알린다. 41장은 단원의 첫 물음에 답하며 닫는 말을 복원했고, 53·59장은 단원 이름을 다시 말한다. 새 이음말의 반복과 모호한 지시어도 다듬었다. 덱 MD·figures는 바뀌지 않았다. 시간 채우기·장 추가·다른 회차는 제외했다. 커밋·push하지 않는다.

1회차는 78장이다. 인사·강사 소개와 마지막의 짧은 맺음 → 다음 회차 → 끝인사는 유지했다. **호출 세션의 낭독본 재생성과 현황·운영 기록 동기화가 남았다.** 대본의 비낭독 구성표는 이번 추정으로 동기화했다. 전체 낭독 96.4분, 이론 합 88.7분, 학습 대기 65초, 운영 238.3분과 미배정 1.7분이다. 실습 배분 50·30·28·38분은 그대로다. 이는 도구 추정이며 실제 음성·실습 실측이 아니다. 이번 덱 검사도 통과했으며 구체적인 결과와 변경 장은 `state.json`에 있다.

## 작업 계약

- 회차를 맡으면 아스트라가 그 회차의 덱 MD·대본 원본·필요한 figures를 직접 고친다. **사실·기준·흐름 검증 → 원본 수정 → 대본 전체의 끊김 없는 윤문**까지 한 번에 마친다. 새로 넣은 부분과 앞뒤도 매끄럽게 잇는다. 부분 수정 요청은 그 범위가 우선한다.
- 호출 세션은 원본을 그대로 받아 PPTX·낭독본을 빌드하고 검사·커밋한다. 아스트라는 다른 회차·기준·스킬·도구·PPTX를 고치지 않고 커밋·push하지 않는다. 범위 밖 문제는 근거와 함께 보고한다.
- 견적만 요청받으면 제작 파일을 수정하지 않는다. 과거의 수정안 전달 방식과 임시 직접 쓰기 권한을 현행 계약으로 오인하지 않는다(기준 45-2번의 2026-10-16 개정과 최신 사용자 요청 우선).
- **4~9회차 아스트라 윤문·검증·기준 점검은 1~3회차 확정 뒤 4회차부터 순서대로** 한다. 호출 세션의 4~6회차 초안 준비와 아스트라의 점검은 별개다.
- 추가 실습 풍부화는 보류다. 이미 반영한 보강과 새 견적을 구별한다. 인제스천은 4회차 주제이며 1~3회차로 앞당기지 않는다. 시간은 억지로 채우지 않는다. 세부 기준은 `2_기준.md` 39~42·60-1번과 `6_남은_일.md` 0절을 따른다.

## 원문으로 복구하기

1. 최신 요청의 허용 범위와 `state.json`의 다음 행동·미결을 확인한다. `git status --short`와 `git log --oneline -30`으로 읽은 뒤 바뀐 파일·커밋을 대조한다. 다른 세션의 변경은 보존한다.
2. 처음이거나 맥락이 흐리면 `CLAUDE.md`, `문서/교재/` 여섯 문서(특히 `2_기준.md` 전체와 `6_남은_일.md` 0절), 적용 스킬, 대상 회차 원고·실라버스·사실 근거를 읽는다. 전체 읽기를 요청받으면 그대로 따른다.
3. 사용자 결정은 `.evidence/대화_원문_2026-10-15.md`의 사용자 발화와 최신 요청으로 확인한다. 과거 세션 답변·자동 작업 통지·견적은 사용자 승인과 구별한다. 이 대화 파일의 끝 이후 결정은 최신 기준·요청문·git에서 확인하고, 직접 대화 원문을 못 본 사실은 남긴다.
4. `.evidence/`는 다음 컨테이너에 없을 수 있다. 재개를 거기에만 의존하지 않는다. 없으면 `2_기준.md`, `5_결정_기록.md` 7절, `6_남은_일.md` 0절과 git을 읽고 부족한 근거를 명시한다.
5. `문서/교재/근거/이야기_흐름_본보기.txt`는 전개 방식의 본보기다. 실제 시스템의 사실·수치·기능은 관련 사실표와 코드·실행 기록으로 확인한다.

## 작업별 안내

| 작업 | 원문·스킬 |
|---|---|
| 덱 | `.claude/skills/hyd-course-deck/SKILL.md` → `lecture-deck/SKILL.md`, 해당 회차 원고·figures·사실표 |
| 대본·윤문 | `2_기준.md` 14·15절, `4_만드는_법.md` 3부, 확정 덱과 노트 |
| 실습 | `.claude/skills/hyd-lab-guide/SKILL.md` → `lecture-lab/SKILL.md` |
| 영상 | `.claude/skills/hyd-lecture-video/SKILL.md` — 별도 요청 때만 제작 |
| 설계·검증·배포 | `.claude/skills/lecture-plan/SKILL.md`, `lecture-verify/SKILL.md`, `lecture-deliver/SKILL.md`; 조립·배포 보류는 `6_남은_일.md` 먼저 확인 |

공통 제작 절차는 `4_만드는_법.md` 2부 0절에 있다. 스킬·도구를 읽었다는 이유로 요청 범위를 넓히지 않는다. 적용할 때는 스킬을 사용자에게 알린다.

## 필요한 만큼 읽는 도구

```bash
python3 .astra/context.py status --day 1 --kind script
python3 .astra/context.py outline --day 1
python3 .astra/context.py slides --day 1 --numbers 72-78
python3 .astra/context.py read 문서/교재/2_기준.md --start 1 --end 80
```

`read`·`slides`의 출력 한도에 닿으면 다음 줄부터 이어 읽는다. `--rev`로 옛 판을 대조할 수 있다. 검색·장 목록·해시는 원문 이해와 전 문장 검토를 대신하지 않는다.

제작이 허용된 작업에서는 `python3 .astra/context.py check --day 1`로 기존 빌더를 실행할 수 있다. 검사 성공은 사실 검증·전 장 렌더·청취·학생 완주를 증명하지 않는다. PPTX·낭독본 빌드는 호출 세션의 일이다. 이번 작업은 1회차만 검사한다. 새 컨테이너에는 `.venv-deck`가 없으므로 기존 빌더를 임시 의존성 환경에서 직접 실행한다. 구체적인 실행 결과는 `state.json`에 기록한다. 덱·그림을 고치지 않아 새 렌더는 하지 않았으며 대본 시간은 기존 도구로 다시 측정했다.

## 기록 유지

- `state.json`은 **현재 상태로 고쳐 쓴다.** 지난 진행 일지를 덧붙이지 않는다. 추적은 git과 결정 기록을 이용하며, 이 세션이 범위 밖 문서를 고치지는 않는다.
- `reading.json`은 이전에 출력한 버전과 범위, `checks.json`은 이전 자동 검사 결과다. 이번 작업에서 둘을 갱신하지 않으며, 이번 검사 결과는 `state.json`에 기록한다. 읽기 기록이 있어도 이해가 흐리면 원문으로 돌아가며, 입력·도구·환경이 바뀌면 옛 검사 성공을 승계하지 않는다.
- 기존 `context.py`·`test_context.py`·임시 자료는 지우거나 초기화하지 않았다. 세션 교체는 저장소 기록과 제작 파일의 삭제가 아니다.
- 공개 기록에는 키·메일·사람 이름·절대 경로를 복사하지 않는다. 계정 설정과 저장소 밖 설정은 바꾸지 않는다.

호출 시 대상 회차·원하는 결과·수정 범위·새 제약을 받는다. 새 세션 ID는 호출 로그의 `session id:`로 확인한다. 같은 세션에 두 요청을 동시에 보내지 않는다. 작업 완료 뒤에는 최신 요청을 받아 다음 작업을 시작한다.
